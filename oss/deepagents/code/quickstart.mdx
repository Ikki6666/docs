Deep Agents Code（`dcode`）是一个构建在 [Deep Agents SDK](/oss/python/deepagents/quickstart) 之上的终端 coding agent。本指南涵盖安装、你的第一个任务、日常交互式使用、通过管道进行自动化，以及 LangSmith tracing。功能概览请参见 [Deep Agents Code overview](/oss/deepagents/code/overview)。`config.toml` 与 provider 设置请参见 [Configuration](/oss/deepagents/code/configuration)。

## 安装并运行你的第一个任务

<Steps>

    <Step title="安装并启动" icon="terminal">
        ```bash
        curl -LsSf https://langch.in/dcode | bash
        ```
    </Step>

    <Step title="添加 provider 凭据" icon="key">
        Deep Agents Code 可以搭配任何支持 tool calling 的 LLM 使用。OpenAI、Anthropic 和 Google 开箱即用。

        使用 `/auth` 命令连接 provider。完整列表和凭据详情请参见 [Providers](/oss/deepagents/code/providers)。

        <Note>
            Web search 使用 [Tavily](https://tavily.com)。通过 `/auth` 添加 key。请参见 [Enable web search](/oss/deepagents/code/credentials#enable-web-search-with-tavily)。
        </Note>
    </Step>

    <Step title="给 agent 一个任务" icon="message">
        ```txt
        Create a Python script that prints "Hello, World!"
        ```

        agent 会理解查询，并以 diff 形式提出修改供你批准，然后才会修改文件。如有需要，它可以运行 shell 命令来测试代码、查看文档，或在网上搜索最新信息。
    </Step>

    <Step title="启用 tracing（可选）" icon="chart-dots">
        要在 LangSmith 中记录 agent 操作、tool calls 和决策，请运行 `/auth` 并添加你的 LangSmith API key。tracing 会在下次启动时启用。

        项目命名、高级选项以及 CI 或 headless 设置请参见 [Trace with LangSmith](#trace-with-langsmith)。
    </Step>
</Steps>

<Note>
    Deep Agents Code 未在 Windows 上提供官方支持。Windows 用户可以尝试在 [Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/en-us/windows/wsl/install) 下运行。
</Note>

## 交互式模式

像在聊天界面中一样自然地输入。
agent 会使用其内置的 tools、skills 和 memory 来协助你完成任务。

<AccordionGroup>
    <Accordion title="斜杠命令" icon="slash">
        在 Deep Agents Code 会话中可以使用以下命令：

        - `/model`：切换模型或打开交互式模型选择器。
        - `/effort`：设置当前模型的 reasoning effort。
        - `/agents`：无需重新启动即可在预配置的 agent 之间热切换。相关 flag 请参见 [Command reference](/oss/deepagents/code/cli-reference#command-line-options)。
        - `/auth`：管理模型 provider 和服务（例如 Tavily web search）的已存储 API key。详情请参见 [Provider credentials](/oss/deepagents/code/credentials)。
        - `/goal <objective>`：根据可度量的目标起草验收标准。请参见 [Goals and rubrics](/oss/deepagents/code/goals-and-rubrics)。
        - `/rubric`：为评分设置明确的验收标准。请参见 [Goals and rubrics](/oss/deepagents/code/goals-and-rubrics)。
        - `/remember [context]`：回顾对话并更新 memory 和 skills。可选传入额外的上下文。
        - `/skill:<name> [args]`：按名称直接调用一个 skill。该 skill 的 `SKILL.md` 指令会连同你提供的参数一起注入 prompt。
        - `/skill-creator [task]`：创建高效 agent skills 的指南。
        - `/offload`（别名 `/compact`）- 通过将消息卸载到存储并留下摘要占位符来释放上下文窗口空间。如有需要，agent 可以从卸载的文件中恢复完整历史。
        - `/context`：打开一份按颜色编码的上下文窗口用量报告，包含模型容量、用量类别和剩余空间。
        - `/context-doctor`：审计注入会话的上下文及其估算 token 成本。请参见 [Audit injected context](/oss/deepagents/code/cli-reference#audit-injected-context)。
        - `/tools`：列出当前 agent 可用的内置工具和 MCP 工具。请参见 [List available tools](/oss/deepagents/code/cli-reference#list-available-tools)。
        - `/extensions`：列出已加载的 [Python extensions](/oss/deepagents/code/extensions)、它们的注册项和源路径。需要 `DEEPAGENTS_CODE_EXPERIMENTAL=1`。
        - `/cost`：显示该 thread 的估算成本。请参见 [Track thread cost](/oss/deepagents/code/cli-reference#track-thread-cost)。
        - `/btw`：在不打断主任务的情况下就对话提出附带问题。请参见 [Ask a side question](/oss/deepagents/code/cli-reference#ask-a-side-question)。
        - `/tokens`：显示当前上下文窗口 token 用量明细。
        - `/clear`：开始一个全新 thread。
        - `/force-clear`：通过全新 thread 恢复卡住的会话。
        - `/copy`：将最新的 assistant 消息复制到剪贴板。
        - `/prompts`：搜索、预览、复制并复用之前提交的 prompts。
        - `/threads`：浏览并恢复之前的对话 thread。
        - `/mcp [login <server> | reconnect]`：显示活跃的 MCP server 和工具。`login <server>` 为某个 server 运行 OAuth 流程；`reconnect` 加载延迟登录。
        - `/plugins`：管理 [plugins and marketplaces](/oss/deepagents/code/plugins)。
        - `/notifications`：配置启动警告偏好。
        - `/reload`：在不重启的情况下重新读取 `.env` 文件、刷新配置并重新发现 skills。这也会重新加载 plugin skills 和 MCP 配置。会话状态会保留。覆盖行为请参见 [`DEEPAGENTS_CODE_` prefix](/oss/deepagents/code/configuration#deepagents_code_-prefix)。
        - `/theme`：打开交互式主题选择器以切换配色主题。除内置主题外，还可以使用[用户自定义主题](/oss/deepagents/code/configuration#themes)。
        - `/scrollbar`：显示或隐藏聊天滚动条。
        - `/line-numbers`：在新 diff 中显示或隐藏相对于文件的行号。请参见 [Diff line numbers](/oss/deepagents/code/config-file#diff-line-numbers)。
        - `/update`：在内联检查并安装 Deep Agents Code 更新。会检测你的安装方式（uv、Homebrew、pip）并运行相应的升级命令。
        - `/auto-update`：开启或关闭自动更新。
        - `/install`：安装可选集成。
        - `/trace`：在 LangSmith 中打开当前 thread。
        - `/editor`：在外部编辑器（`$VISUAL` / `$EDITOR`）中打开当前 prompt。请参见 [External editor](#external-editor)。
        - `/restart`：重启 agent server。
        - `/timestamps`：开关消息时间戳页脚。
        - `/changelog`：在浏览器中打开 Deep Agents Code changelog。
        - `/docs`：在浏览器中打开文档。
        - `/feedback`：发送反馈或报告问题。
        - `/version`（别名 `/about`）- 显示已安装的 `deepagents-code` 和 SDK 版本。
        - `/help`：显示帮助和可用命令。
        - `/quit`：退出应用程序。
    </Accordion>

    <Accordion title="Shell 命令" icon="prompt">
        输入 `!` 进入 shell 模式，然后输入你的命令。

        ```bash
        git status
        npm test
        ls -la
        ```
    </Accordion>

    <Accordion title="键盘快捷键" icon="keyboard">
        **通用**

        | 快捷键 | 操作 |
        |-|-|
        | `Enter` | 提交 prompt |
        | `Shift+Enter`、`Ctrl+J`、`Alt+Enter` 或 `Ctrl+Enter` | 插入换行符 |
        | `@filename` | 自动补全文件并注入内容 |
        | `@@query` | 搜索最近的 thread 并插入 thread 引用 |
        | `Shift+Tab` | 循环切换 [approval modes](/oss/deepagents/code/approval-modes) |
        | `Ctrl+G` | 在外部编辑器中打开 prompt |
        | `Ctrl+T` | 在存在 subagent 面板时展开或折叠它 |
        | `Ctrl+N` | 在面板打开时查看待处理的通知 |
        | `Ctrl+O` | 展开/折叠最近的工具输出 |
        | `Escape` | 中断当前操作 |
        | `Ctrl+C` | 中断或退出 |
        | `Ctrl+D` | 退出 |

        **prompt 中的文本编辑**

        聊天输入框使用标准的 readline 风格绑定：

        | 快捷键 | 操作 |
        |-|-|
        | `Ctrl+A` 或 `Home` | 将光标移动到行首 |
        | `Ctrl+E` 或 `End` | 将光标移动到行尾 |
        | `Ctrl+U` | 从光标删除到行首 |
        | `Ctrl+K` | 从光标删除到行尾 |
        | `Ctrl+W` 或 `Ctrl+Backspace` | 删除左侧单词 |
        | `Ctrl+Left` / `Ctrl+Right` | 将光标左移/右移一个单词 |

        **搜索 prompt 历史**

        prompt 历史搜索让你可以在不离开聊天输入框的情况下找到并复用之前提交的 prompts。按 `Ctrl+R` 打开对存储在本机的 prompts 的内联搜索。

        **引用之前的 thread**

        在聊天输入框中输入 `@@`，可以按初始 prompt、thread ID、agent、分支或工作目录搜索最近的 thread。选择一个结果即可插入 `@@(thread:<thread-id>)` 引用。当被引用的对话与你的请求相关时，Deep Agents Code 可以查看该对话。

        在 `@@` 后面添加文本可以过滤结果。在建议列表打开时，按 `Ctrl+R` 可以用相同的搜索浏览所有 thread。在完整的 thread 选择器中，按 `Ctrl+C` 可以复制选中的 thread ID。

        <Note>
            **macOS `Cmd+Left` / `Cmd+Right` / `Cmd+Delete`**

            终端模拟器会在 `Cmd` 修饰键到达运行中的应用之前拦截它们，因此 Deep Agents Code 从不直接接收这些按键。终端会将它们转换为上面的 readline 快捷键。

            - **Ghostty：** 开箱即用。`Cmd+Left`、`Cmd+Right` 和 `Cmd+Delete` 默认会被转换为 `Ctrl+A`、`Ctrl+E` 和 `Ctrl+U`。
            - **iTerm2：** 默认未绑定。在 **Settings > Profiles > Keys > Key Mappings** 下添加以下映射，动作选择 `Send Text with vim special chars`：
                - `Cmd+Left` → `\x01` (Ctrl+A)
                - `Cmd+Right` → `\x05` (Ctrl+E)
                - `Cmd+Delete` → `\x15` (Ctrl+U)
            - **Terminal.app：** 没有用于此重映射的原生 UI。直接使用基于 `Ctrl` 的快捷键。

            按单词移动（`Option+Left` / `Option+Right`）的处理方式相同：终端发送 `Esc+b` / `Esc+f`，Deep Agents Code 会将其解释为左移/右移一个单词。
        </Note>
    </Accordion>
</AccordionGroup>

### 查看上下文窗口用量

运行 `/context` 打开当前模型上下文窗口用量的彩色报告。报告会显示模型的上下文限制、已用 token、剩余容量，以及（在这些值可用时）对话与 system prompt 加 tools 之间的用量拆分。

provider 上报的总量与本地对话估算值是相互独立的。当 provider 总量不可用时，报告会将对话计数标记为估算值，并将总用量标记为不可用。如果你想在对话记录中获得文本形式的摘要，请使用 `/tokens`。

当用量增长快于预期时，运行 `/context-doctor` 将 token 归因到每个注入的组件：基础 system prompt、memory 文件、skills 索引、内置工具 schema 和 MCP 工具 schema。要确认 agent 当前可以调用哪些工具，请运行 `/tools`。要查看 thread 的运行成本估算，请运行 `/cost`；同一数字也会显示在状态栏中。请参见 [Diagnose and audit a session](/oss/deepagents/code/cli-reference#diagnose-and-audit-a-session)。

### 外部编辑器

按 `Ctrl+G` 或输入 `/editor` 可以在外部编辑器中撰写 prompts。Deep Agents Code 会依次检查 `$VISUAL`、`$EDITOR`，然后回退到 `vi`（macOS/Linux）或 `notepad`（Windows）。GUI 编辑器（VS Code、Cursor、Zed 等）会自动附加 `--wait` 标志，因此 Deep Agents Code 会阻塞到你关闭文件为止。

```bash
# Set in your shell profile (~/.zshrc, ~/.bashrc, etc.)
export VISUAL="code"    # GUI editor (--wait auto-injected)
export EDITOR="nvim"    # Terminal fallback
```

## 非交互式模式与管道

使用 `-n` 可以在不启动交互式 UI 的情况下运行单个任务：

```bash
dcode -n "Write a Python script that prints hello world"
```

每次非交互式运行都会开始一个全新的 thread—对话历史不会在多次调用之间保留。基于文件的状态（memory、skills、配置）会持久保存。

你也可以通过 stdin 管道传入输入。当输入通过管道传入时，Deep Agents Code 会自动以非交互方式运行：

```bash
echo "Explain this code" | dcode
cat error.log | dcode -n "What's causing this error?"
git diff | dcode -n "Review these changes"
git diff | dcode --skill code-review -n 'summarize changes'
```

当你把管道输入与 `-n` 或 `-m` 结合使用时，管道内容会排在最前面，之后是传给该 flag 的文本。

<Note>
    管道输入的最大大小为 10 MiB。
</Note>

在非交互式模式下，shell 执行默认是禁用的。使用 `-S`/`--shell-allow-list` 启用特定命令（例如 `-S "pytest,git,make"`），使用 `recommended` 作为安全默认值，或使用 `all` 允许任何命令。

<AccordionGroup>
    <Accordion title="限制回合数" icon="gauge">
        CI/CD 流水线中长时间运行或行为异常的 agent 可能无限循环。`--max-turns N` 为操作者提供了硬性上限，而无需触及 SDK 内部：

        ```bash
        dcode -n "fix the failing tests" --max-turns 10
        ```

        `N` 必须是正整数，会覆盖原本用于限制失控循环的内部安全默认值。超出预算时以退出码 124 退出（与 GNU `timeout` 一致），因此 CI 可以区分预算用尽与一般性失败。需要 `-n` 或管道 stdin；否则以退出码 2 退出。

        如果想要基于时间的限制来替代（或叠加）回合数限制，请参见 [Cap wall-clock time with `--timeout`](#non-interactive-mode-and-piping)。
    </Accordion>

    <Accordion title="限制实际运行时间" icon="clock">
        `--timeout SECONDS` 为非交互式运行强制执行硬性的实际时间限制。它用基于时间的预算补充 `--max-turns`（回合数）—先到达哪个限制就取消 agent。

        ```bash
        # Fail fast in CI if the task takes more than 2 minutes
        dcode -n "run the test suite and summarise failures" --timeout 120

        # Combine with --max-turns—whichever limit is hit first stops the agent
        dcode -n "refactor auth module" --timeout 300 --max-turns 20
        ```

        到期时 agent 会被取消，进程以退出码 124 退出，与 `--max-turns` 使用的退出码相同，因此 CI 可以统一处理这两种预算用尽的情况。需要 `-n` 或管道 stdin；否则以退出码 2 退出。
    </Accordion>

    <Accordion title="干净的输出与缓冲" icon="buffer">
        使用 `-q` 获得适合管道传输给其他命令的干净输出，使用 `--no-stream` 缓冲完整响应（而不是流式输出）后再写入 stdout：

        ```bash
        dcode -n "Generate a .gitignore for Python" -q > .gitignore
        dcode -n "List dependencies" -q --no-stream | sort
        ```

        在非交互式模式下，agent 会被要求做出合理假设并自主推进，而不是提出澄清性问题。它还会优先使用非交互式命令变体（例如 `npm init -y`、`apt-get install -y`）。
    </Accordion>

    <Accordion title="Shell 执行示例" icon="shield-check">
        ```bash
        # Allow specific commands (validated against the list)
        dcode -n "Run the tests and fix failures" -S "pytest,git,make"

        # Use the curated safe-command list
        dcode -n "Build the project" -S recommended

        # Allow any shell command
        dcode -n "Fix the build" -S all
        ```
    </Accordion>
</AccordionGroup>

<Warning>
    **请谨慎使用。**

    `-S all`（或 `--shell-allow-list all`）允许 agent 在没有人工确认的情况下执行任意 shell 命令。
</Warning>

## Trace with LangSmith

启用 [LangSmith](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=oss-deepagents-code-quickstart) tracing，以便在 LangSmith 项目中查看 agent 操作、tool calls 和决策。

运行 `/auth` 并添加你的 LangSmith API key。tracing 会在下次启动时启用并跨会话保持。凭据管理器的详情请参见 [Provider credentials](/oss/deepagents/code/credentials#use-%2Fauth-recommended)。

要自定义项目名称，或在不使用 TUI 的情况下配置 tracing，请把 key 添加到 `~/.deepagents/.env`，这样每次会话都会启用 tracing，而无需在每个 shell 中导出：

```bash title="~/.deepagents/.env"
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=lsv2_...
DEEPAGENTS_CODE_LANGSMITH_PROJECT=deepagents-code  # Project for Deep Agents Code's own traces; defaults to "deepagents-code"
```

`DEEPAGENTS_CODE_LANGSMITH_PROJECT` 用于为接收 Deep Agents Code 自身 traces 的项目命名。它的作用域限定在 Deep Agents Code，因此不受项目 `.env` 中设置的 `LANGSMITH_PROJECT` 影响（后者用于路由该项目的应用 traces；参见下文**将 agent traces 与应用 traces 分开**）。

要为特定工作目录覆盖项目，请在该目录的 `.env` 中添加 `DEEPAGENTS_CODE_LANGSMITH_PROJECT`。完整的加载顺序请参见 [environment variables](/oss/deepagents/code/configuration#environment-variables)。

<Accordion title="禁用 agent tracing">
    启动 `dcode --no-tracing` 可以为单个会话禁用 LangSmith agent tracing。对于之后的启动，请在 shell 或 `~/.deepagents/.env` 中设置 `DEEPAGENTS_CODE_LANGSMITH_TRACING=false`。

    该 flag 会覆盖环境设置。`DEEPAGENTS_CODE_LANGSMITH_TRACING` 中显式设置的 `false` 会覆盖其他启用 tracing 的 flag，包括 `LANGSMITH_TRACING=true`。对于同一个变量，shell 导出优先于 `.env` 值。

    禁用 agent tracing 不会禁用本地对话历史或对模型 provider 的请求。它与 trace 脱敏以及 shell 命令中运行的应用发出的 tracing 相互独立。
</Accordion>

<Accordion title="将 agent traces 与应用 traces 分开">
    Deep Agents Code 可以产生两类 LangSmith traces：

    - `Agent traces` 是 Deep Agents Code 自身的模型调用、tool calls、编排和 middleware。
    - `Shell-command traces` 是 Deep Agents Code 在 shell 中为你运行的代码（例如测试、脚本或本地 LangGraph 应用）发出的 traces。

    要将 Deep Agents Code 自身的 traces 发送到专用项目，请设置 `DEEPAGENTS_CODE_LANGSMITH_PROJECT`：

    ```bash title="~/.deepagents/.env"
    # Example value; use any LangSmith project name you want.
    DEEPAGENTS_CODE_LANGSMITH_PROJECT=deepagents-code
    ```

    然后为你的应用 traces 配置 `LANGSMITH_PROJECT`：

    ```bash title=".env"
    LANGSMITH_PROJECT=customer-support-agent
    ```

    例如，假设你让 Deep Agents Code 调试一个失败的 LangGraph 测试：

    ```bash
    uv run pytest tests/test_escalation_flow.py
    ```

    如果该测试在启用 LangSmith tracing 的情况下运行你的应用，这些应用 traces 由 shell 进程创建并进入 `customer-support-agent`。Deep Agents Code 自身的推理和工具使用 traces 则进入 `deepagents-code`。

    你还可以使用 [`DEEPAGENTS_CODE_` prefix](/oss/deepagents/code/configuration#deepagents_code_-prefix) 将 LangSmith 凭据限定到 Deep Agents Code（例如 `DEEPAGENTS_CODE_LANGSMITH_API_KEY`）。
</Accordion>

<Accordion title="将 traces 双写到第二个项目">
    要将 agent traces 镜像到第二个 LangSmith 项目，请设置 `DEEPAGENTS_CODE_LANGSMITH_REPLICA_PROJECTS`。这适用于把相同的 traces 同时发送到个人项目和共享的团队项目。

    ```bash title="~/.deepagents/.env"
    DEEPAGENTS_CODE_LANGSMITH_REPLICA_PROJECTS=team-shared
    ```

    设置该变量且 tracing 处于活动状态时，每次 agent 运行都会同时写入主项目（`DEEPAGENTS_CODE_LANGSMITH_PROJECT`，默认为 `deepagents-code`）和你在该变量中命名的项目。保持该变量未设置即可像往常一样只写入单个项目。
</Accordion>

配置完成后，Deep Agents Code 会显示一条带有 LangSmith 项目链接的状态行。在受支持的终端中，点击该链接可以直接打开。你也可以使用 `/trace` 打印 URL 并在浏览器中打开。

```sh
✓ LangSmith tracing: 'my-project'
```

<Tip>
    建议你同时设置 [LangSmith Engine](/langsmith/engine)，它可以监控你的 traces、检测问题并提出修复建议。
</Tip>
