**文本分割器**会把大型文档拆成更小的块，让这些块既能单独被检索，也能放进模型的上下文窗口限制内。

文档分割有多种策略，每种都有各自的优点。

<Tip>
    对大多数场景，先从 [`RecursiveCharacterTextSplitter`](/oss/javascript/integrations/splitters/recursive_text_splitter) 开始。它在保留上下文完整性和控制块大小之间提供了良好的平衡。这个默认策略开箱即用，只有当你需要针对具体应用微调性能时，才需要考虑调整。
</Tip>

## 基于文本结构

文本天然会组织成层级单元，例如段落、句子和单词。你可以利用这种固有结构来指导分割策略，从而得到既保留自然语言流动性、维持语义连贯性，又能适应不同文本粒度的切分结果。LangChain 的 `RecursiveCharacterTextSplitter` 就实现了这一思路：

- [`RecursiveCharacterTextSplitter`](/oss/javascript/integrations/splitters/recursive_text_splitter) 会尽量保留更大的单元（例如段落）不被拆开。
- 如果某个单元超过块大小限制，它会继续下探到下一层级（例如句子）。
- 如有需要，这个过程会一直继续到单词级别。

示例用法：


```ts
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";

const splitter = new RecursiveCharacterTextSplitter({ chunkSize: 100, chunkOverlap: 0 })
const texts = splitter.splitText(document)
```

## 基于长度

一种直观的策略是按长度来分割文档。这种简单却有效的方法可以确保每个块都不超过指定的大小限制。按长度分割的主要优势包括：

- 实现简单
- 块大小一致
- 易于适配不同模型的要求

基于长度的分割类型包括：

- 按 token 分割：按 token 数量切分文本，适用于与语言模型配合使用。
- 按字符分割：按字符数切分文本，在不同文本类型之间往往更稳定。

下面是使用 LangChain `CharacterTextSplitter` 进行基于 token 分割的示例：


```ts
import { TokenTextSplitter } from "@langchain/textsplitters";

const splitter = new TokenTextSplitter({ encodingName: "cl100k_base", chunkSize: 100, chunkOverlap: 0 })
const texts = splitter.splitText(document)
```

- [按 token 分割](/oss/javascript/integrations/splitters/split_by_token)
- [按字符分割](/oss/javascript/integrations/splitters/character_text_splitter)

## 基于文档结构

有些文档本身带有固有结构，例如 HTML、Markdown 或 JSON 文件。在这些场景下，最好按文档结构来分割，因为它通常天然会把语义相关的文本组织在一起。基于结构分割的主要优势包括：

- 保留文档的逻辑组织
- 保持每个块内部的上下文完整
- 对检索或摘要等下游任务通常更有效
