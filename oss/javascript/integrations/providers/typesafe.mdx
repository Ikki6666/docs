[Jev](https://docs.typesafe.ai/models) 是一个 [System One model](https://docs.typesafe.ai/concepts/system-one)，它读取自然语言，但返回带类型的答案和经过校准的概率，而不是生成的文本。

`TypeSafeClassifier` 通过 `@langchain/core/decisions` 中的 `BaseDecisionModel` 实现 LangChain Decisions API。它是一个 `Runnable`，因此你可以调用、批处理，或将它与其他 runnable 组合。它接受字符串、结构化 JSON 和 [LangChain 消息对象](/oss/javascript/langchain/messages)，并在 LangSmith 中记录 trace 和 token usage。可以用它处理聚焦的决策，例如路由请求、选择模型，或检查某个工具调用是否可以安全运行。

在 LangChain middleware 中使用 TypeSafe 决策，可在特定生命周期节点控制 `createAgent` 的行为，包括使用对 agent state 进行分类的自定义 middleware。示例见 [Agent middleware](#agent-middleware)。

## 设置

<Note>
这些示例要求 `@langchain/typesafe` 0.1.0 或更高版本，以及 `@langchain/core` 1.4.0 或更高版本。此版本使用 `@langchain/core/decisions` 中的共享决策类型。
</Note>

<CodeGroup>
```bash npm
npm install @langchain/typesafe @langchain/core
```

```bash yarn
yarn add @langchain/typesafe @langchain/core
```

```bash pnpm
pnpm add @langchain/typesafe @langchain/core
```
</CodeGroup>

请把 API key 保存在服务端。不要在浏览器代码中暴露它。设置 `dangerouslyAllowBrowser: false` 以拒绝浏览器使用。

在 [TypeSafe console](https://console.typesafe.ai/settings/keys) 中创建 API key 并导出：

```bash
export TYPESAFE_API_KEY=...
```

<Note>
可选：设置 `TYPESAFE_BASE_URL` 以使用兼容的 gateway、测试服务器或私有部署。默认值为 `https://api.typesafe.ai`。

```bash
export TYPESAFE_BASE_URL=https://gateway.example.com
```
</Note>

## 快速开始

创建一个 `TypeSafeClassifier`，然后在每次调用时一起传入 state 和命名问题。共享同一个 state 的问题会在一次请求中独立并行地评估：

<Note>
早期版本在 `TypeSafeClassifier` 上配置 `questions`，并且只把 state 传给 `invoke`。现在请把 `state` 和 `questions` 都传给 `invoke`。每个问题都需要 `instructions`。
</Note>

```typescript
import { TypeSafeClassifier } from "@langchain/typesafe";

const classifier = new TypeSafeClassifier();

const response = await classifier.invoke({
  state:
    "The deploy failed twice and customers are seeing 500s. Can someone look now?",
  questions: {
    urgent: {
      type: "noul",
      instructions: "Does this need attention right now?",
    },
    team: {
      type: "choice",
      instructions: "Which team should pick this up?",
      criteria: {
        infra: "Deploys, availability, and on-call incidents.",
        billing: "Payments, invoices, and subscriptions.",
      },
    },
    severity: {
      type: "score",
      instructions: "How severe is the impact?",
      criteria: ["Cosmetic.", "Degraded for some users.", "Full outage."],
    },
  },
});

console.log(response.nouls.urgent.noul);
console.log(response.choices.team.choice, response.choices.team.confidence);
console.log(response.scores.severity.score);
```

答案以你提供的问题 ID 为键，存放在 `response.answers` 中，并在 `nouls`、`choices`、`scores` 和 `boxes` 上按类型分组。答案会根据你传入的问题推导类型：`response.choices.team.choice` 的类型为 `"infra" | "billing"`，而未知的问题 ID 会导致类型错误。响应还会带上作答的 `model`、可选的 `usage_metadata`，以及 TypeSafe 的 `requestId`。

在 0.1 版本中，token usage 为 `usage_metadata`，包含 `input_tokens`、`output_tokens` 和 `total_tokens`。它取代了早期的 `usage` 对象。读取前请先检查它是否已定义：

```typescript
if (response.usage_metadata !== undefined) {
  console.log(response.usage_metadata.input_tokens);
  console.log(response.usage_metadata.output_tokens);
  console.log(response.usage_metadata.total_tokens);
}
```

请求的 `state` 可以是字符串、JSON 对象或数组，也可以是 LangChain 消息。消息会被转换为 transcript 文本，包括嵌套在更大对象中的情况。

## 配置请求

构造函数选项控制模型、认证和请求行为：

- **`model`**：设置模型或别名。默认值为 `jev-latest`。
- **`apiKey`**：覆盖 `TYPESAFE_API_KEY`。
- **`baseUrl`**：覆盖 `TYPESAFE_BASE_URL`。
- **`timeout`**：设置每个请求的超时时间（毫秒）。默认值为 `30000`。
- **`maxRetries`**：设置最大重试次数。默认值为 `2`；设为 `0` 可禁用重试。
- **`fetch`**：为代理或测试提供自定义 transport。

请求级配置（例如 `signal`、`tags` 和 `metadata`）作为 `invoke` 的第二个参数传入。

## 处理错误

该包导出 `TypeSafeError`、`TypeSafeAPIError`、`TypeSafeAuthenticationError` 和 `TypeSafeRateLimitError`。使用它们的 `isInstance(error)` 方法识别失败。避免不加区分地记录 API 错误 body：它们可能包含提交的 state。

TypeSafe 会接收你提交的 state，包括消息内容和工具调用参数。在调用分类器之前，请移除密钥或敏感数据。

## 决策类型

将问题定义为 `type` 为 `"noul"`、`"choice"`、`"score"` 或 `"box"` 的对象。从 `@langchain/core/decisions` 导入问题和答案类型，例如 `Noul`、`Choice` 和 `ChoiceAnswer`。为保持兼容性，`@langchain/typesafe` 的类型 re-export 仍然可用。每个问题属于四种原语之一：

| Primitive | 提问 | 返回 | 何时使用 |
|---|---|---|---|
| [`noul`](https://docs.typesafe.ai/primitives/noul) | 这是否为真？ | `noul`，即回答为 yes 的概率 | 你的代码基于 `if` 分支 |
| [`choice`](https://docs.typesafe.ai/primitives/choice) | 这些选项中的哪一个？ | `choice`，外加 `probabilities` 和 `confidence` | 选项对应不同的代码路径 |
| [`score`](https://docs.typesafe.ai/primitives/score) | 哪个级别？ | `score`，外加 `legend`、`probabilities` 和 `confidence` | 答案是一个需要与阈值比较的连续谱 |
| `box` | 它在图像中的哪个位置？ | `box`，带有归一化的边缘，以及可选的 `confidence` | 答案用于定位一个对象或区域 |

`noul` 答案没有 `confidence`，因为概率本身就是答案。对于连续谱请使用 `score` 而不是 `noul`：`noul` 为 `0.5` 表示 yes 和 no 均势对半，而不是“中等”。

TypeSafe 接受 PNG 和 JPEG 图像，形式为包含 base64 数据或 base64 `data:` URL 的 LangChain 图像内容块。图像可以出现在 state、问题 instructions 或 criteria 中。远程图像 URL 不会被下载。对于 `box` 问题，读取 `response.boxes[questionId].box`；它的 `top`、`bottom`、`left` 和 `right` 边缘范围为 `0` 到 `1`。

## Agent middleware

LangChain 提供两个由决策驱动的 [middleware](/oss/javascript/langchain/middleware/overview)，它们通过 `classifier` 接受 `TypeSafeClassifier`。

<Note>
这些 middleware 处于 beta 阶段，要求 `langchain` 1.6.5 或更高版本。自 `@langchain/typesafe` 0.1.0 起，`@langchain/typesafe/middleware` 的导出已弃用，并计划在 0.2.0 中移除。请改为从 `langchain` 导入，并传入 `classifier: new TypeSafeClassifier()`。
</Note>

下面的示例使用 OpenAI 模型。使用前请安装 LangChain 和 OpenAI 集成：

<CodeGroup>
```bash npm
npm install langchain @langchain/typesafe @langchain/openai
```

```bash yarn
yarn add langchain @langchain/typesafe @langchain/openai
```

```bash pnpm
pnpm add langchain @langchain/typesafe @langchain/openai
```
</CodeGroup>

| Middleware | Hook | 决策 |
|---|---|---|
| [`modelRouterMiddleware`](#model-routing) | `beforeAgent`、`wrapModelCall` | 由哪个模型处理本次运行 |
| [`autoModeMiddleware`](#tool-risk-gating) | `wrapToolCall` | 某个工具调用是否风险过高而不应运行 |

### 模型路由

对最新的人类消息在你命名的一组模型之间进行分类，并为本次运行中的每次模型调用使用选中的模型。每个选项都把一个模型与选择它的标准配对：

```typescript
import { createAgent, modelRouterMiddleware } from "langchain";
import { TypeSafeClassifier } from "@langchain/typesafe";

const router = modelRouterMiddleware({
  classifier: new TypeSafeClassifier(),
  choices: {
    fast: {
      model: "openai:gpt-5.6-terra",
      criteria:
        "Direct lookups, extraction, and localized changes with explicit targets.",
    },
    powerful: {
      model: "openai:gpt-6-astra",
      criteria:
        "Architecture, novel root-cause reasoning, and high-stakes decisions.",
    },
  },
  instructions: "Choose the least costly model that can complete the task safely.",
});

const agent = createAgent({
  model: "openai:gpt-5.6-terra",
  middleware: [router],
});

const result = await agent.invoke({
  messages: [
    { role: "user", content: "Prove that there are infinitely many prime numbers." },
  ],
});
console.log(result.modelRoute?.choice);
```

### 工具风险门控

询问某个工具调用存在风险或授权不足的概率。被判定为有风险的调用会返回错误 `ToolMessage`，而不是运行该工具。只有你列出的工具会被分类。可以传入它们的名称或工具对象：

```typescript
import { autoModeMiddleware, createAgent, tool } from "langchain";
import { TypeSafeClassifier } from "@langchain/typesafe";
import * as z from "zod";

const deleteAllBackups = tool(async () => "Backups deleted.", {
  name: "delete_all_backups",
  description: "Delete every backup. This action cannot be undone.",
  schema: z.object({}),
});

const agent = createAgent({
  model: "openai:gpt-6-astra",
  tools: [deleteAllBackups],
  middleware: [
    autoModeMiddleware({
      tools: [deleteAllBackups],
      classifier: new TypeSafeClassifier(),
    }),
  ],
});

const result = await agent.invoke({
  messages: [{ role: "user", content: "Delete all backups." }],
});
console.log(result.messages.at(-1)?.contentBlocks);
```

覆盖 `instructions`，或传入 `criteria: { true: ..., false: ... }`，来描述你自己工具的风险。

<Warning>
除非可以接受把密钥发送给 TypeSafe，否则不要把它们放进工具参数或对话 state 中。这个 middleware 会拒绝有风险的调用，但不会请求批准。当你希望由人工批准这些调用时，请将它和 [human-in-the-loop middleware](/oss/javascript/langchain/middleware/built-in) 搭配使用。
</Warning>

### 自定义 middleware

`TypeSafeClassifier` 直接接受 LangChain 消息对象，因此自定义 middleware hook 无需先做转换就能对 agent 的对话 state 进行分类。下面的示例在每次运行开始时对对话分类一次，并把完整的 `ChoiceAnswer` 存入 agent state：

```typescript
import { createAgent, createMiddleware } from "langchain";
import type { ChoiceAnswer } from "@langchain/core/decisions";
import { TypeSafeClassifier } from "@langchain/typesafe";
import * as z from "zod";

const classifier = new TypeSafeClassifier();

const triageMiddleware = createMiddleware({
  name: "TriageMiddleware",
  stateSchema: z.object({ triage: z.custom<ChoiceAnswer>().optional() }),
  async beforeAgent(state) {
    const response = await classifier.invoke({
      state: state.messages,
      questions: {
        triage: {
          type: "choice",
          instructions: "Which team should handle this conversation?",
          criteria: {
            billing: "Payments, invoices, and subscriptions.",
            infra: "Deploys, availability, and incidents.",
            other: "Requests that belong to another team.",
          },
        },
      },
    });
    return { triage: response.choices.triage };
  },
});

const agent = createAgent({
  model: "openai:gpt-5.6-terra",
  middleware: [triageMiddleware],
});

const result = await agent.invoke({
  messages: [{ role: "user", content: "Customers are seeing 500 errors." }],
});
console.log(result.triage?.choice, result.triage?.confidence);
```

使用任何与你的决策点匹配的生命周期 hook。例如，用 `beforeModel` 在每个工具结果之后重新分类，或用 `wrapToolCall` 对提议的动作分类。所有 hook 和 state 模式见 [自定义 middleware](/oss/javascript/langchain/middleware/custom)。

## Tracing

TypeSafe 分类会在 [LangSmith](/langsmith/home) 中被追踪，因此你可以检查决策和 token usage，以及 agent 的其余部分。
