LangChain 和 [Deep Agents](/oss/javascript/deepagents/overview) 提供了一组适用于常见场景的预构建 middleware。每个 middleware 都可以直接用于生产，并且可按你的具体需求进行配置。

## 与模型无关的 middleware

下面这些 middleware 适用于任何 LLM 提供商：



| Middleware | 描述 |
|------------|-------------|
| [Tool retry](#tool-retry) | 使用指数退避自动重试失败的 tool call。 |
| [Model retry](#model-retry) | 使用指数退避自动重试失败的模型调用。 |
| [Model fallback](#model-fallback) | 主模型失败时自动切换到备用模型。 |
| [Summarization](#summarization) | 在接近 token 上限时自动总结对话历史。 |
| [Human-in-the-loop](#human-in-the-loop) | 在执行 tool call 前暂停，等待人工批准。 |
| [Model call limit](#model-call-limit) | 通过限制模型调用次数来防止成本过高。 |
| [Tool call limit](#tool-call-limit) | 通过限制调用次数来控制工具执行。 |
| [PII detection](#pii-detection) | 检测并处理个人可识别信息（PII）。 |
| [To-do list](#to-do-list) | 为 agent 提供任务规划和跟踪能力。 |
| [LLM tool selector](#llm-tool-selector) | 在调用主模型之前，用 LLM 选择相关工具。 |
| [Provider tool search](#provider-tool-search) | 把工具隐藏在 provider 的服务端工具搜索后面，按需展示。 |

### Tool retry

通过可配置的指数退避自动重试失败的 tool call。Tool retry 适用于以下情况：

- 处理外部 API 调用中的瞬时失败。
- 提高依赖网络的工具的可靠性。
- 构建能优雅处理临时错误的 resilient agent。



**API reference:** [`toolRetryMiddleware`](https://reference.langchain.com/javascript/langchain/index/toolRetryMiddleware)

```typescript
import { createAgent, toolRetryMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [searchTool, databaseTool],
  middleware: [
    toolRetryMiddleware({
      maxRetries: 3,
      backoffFactor: 2.0,
      initialDelayMs: 1000,
    }),
  ],
});
```


<Accordion title="Configuration options">



<ParamField body="maxRetries" type="number" default="2">
    初始调用后的最大重试次数（默认总共 3 次尝试）。必须大于等于 0。
</ParamField>

<ParamField body="tools" type="(ClientTool | ServerTool | string)[]">
    可选：要应用重试逻辑的工具或工具名数组。可以是 `BaseTool` 实例或工具名字符串列表。如果为 `undefined`，则应用于所有工具。
</ParamField>

<ParamField body="retryOn" type="((error: Error) => boolean) | (new (...args: any[]) => Error)[]" default="(error) => getRetryable(error) ?? true">
    要么是错误构造函数数组，要么是接收错误并返回 `true` 的函数。使用 `langchain>=1.5.9` 时，默认值不再重试被标记为不可重试的错误，其余所有错误都会被重试。
</ParamField>

<ParamField body="onFailure" type="'error' | 'continue' | ((error: Error) => string)" default="continue">
    重试耗尽后的行为。可选：
    - `'continue'`（默认）- 返回包含错误详情的 `ToolMessage`
    - `'error'` - 重新抛出异常
    - 自定义函数 - 接收异常并返回 `ToolMessage` 内容字符串

    **Deprecated values:** `'raise'`（改用 `'error'`）和 `'return_message'`（改用 `'continue'`）。
</ParamField>

<ParamField body="backoffFactor" type="number" default="2.0">
    指数退避的乘数。每次重试等待 `initialDelayMs * (backoffFactor ** retryNumber)` 毫秒。设为 `0.0` 则为固定延迟。必须大于等于 0。
</ParamField>

<ParamField body="initialDelayMs" type="number" default="1000">
    第一次重试前的初始延迟（毫秒）。必须大于等于 0。
</ParamField>

<ParamField body="maxDelayMs" type="number" default="60000">
    重试之间的最大延迟（毫秒），用于限制指数退避增长。必须大于等于 0。
</ParamField>

<ParamField body="jitter" type="boolean" default="true">
    是否加入随机抖动（`±25%`）以避免惊群
</ParamField>


</Accordion>

<Accordion title="Full example">

这个 middleware 会使用指数退避自动重试失败的 tool call。


**Key configuration:**
- `maxRetries` - 重试次数（默认：2）
- `backoffFactor` - 指数退避乘数（默认：2.0）
- `initialDelayMs` - 初始延迟（默认：1000ms）
- `maxDelayMs` - 延迟上限（默认：60000ms）
- `jitter` - 是否加入随机变化（默认：true）

**Failure handling:**
- `onFailure: "continue"`（默认）- 返回错误消息
- `onFailure: "error"` - 重新抛出异常
- Custom function - 返回错误消息的函数




```typescript
import { createAgent, toolRetryMiddleware } from "langchain";

import { z } from "zod";

  model: "gpt-5.5",

  middleware: [toolRetryMiddleware()],

// Retry specific exceptions only

  retryOn: [TimeoutError, NetworkError],
  backoffFactor: 1.5,
});

// Custom exception filtering

  // Only retry on 5xx errors
  if (error.name === "HTTPError" && "statusCode" in error) {
    const statusCode = (error as any).statusCode;
    return 500 <= statusCode && statusCode < 600;
  }
  return false;
}

const retryWithFilter = toolRetryMiddleware({
  maxRetries: 3,
  retryOn: shouldRetry,
});

// Apply to specific tools with custom error handling
const formatError = (error: Error) =>
  "Database temporarily unavailable. Please try again later.";

const retrySpecificTools = toolRetryMiddleware({
  maxRetries: 4,
  tools: ["search_database"],
  onFailure: formatError,
});

// Apply to specific tools using BaseTool instances
const searchDatabase = tool(
  async ({ query }) => {
    // Search implementation
    return results;
  },
  {
    name: "search_database",
    description: "Search the database",
    schema: z.object({ query: z.string() }),
  }
);

const retryWithToolInstance = toolRetryMiddleware({
  maxRetries: 4,
  tools: [searchDatabase], // Pass BaseTool instance
});

// Constant backoff (no exponential growth)
const constantBackoff = toolRetryMiddleware({
  maxRetries: 5,
  backoffFactor: 0.0, // No exponential growth
  initialDelayMs: 2000, // Always wait 2 seconds
});

// Raise exception on failure
const strictRetry = toolRetryMiddleware({
  maxRetries: 2,
  onFailure: "error", // Re-raise exception instead of returning message
});
```

#### 将错误标记为可重试

<Note>
需要 `@langchain/core>=1.2.8` 和 `langchain>=1.5.9`。
</Note>

在抛出错误前将其标记，重试中间件就会遵循该判定。这样可以避免在会以完全相同方式重复出现的失败上浪费重试次数，例如无效输入或被拒绝的凭证。

使用 `@langchain/core/errors` 中的 `stampRetryable`：

```typescript
import { stampRetryable } from "@langchain/core/errors";
import { tool } from "@langchain/core/tools";
import { z } from "zod";

const lookupRecord = tool(
  async ({ id }) => {
    const response = await fetch(`https://api.example.com/records/${id}`);

    if (response.status === 422) {
      // Retrying the same identifier fails the same way
      throw stampRetryable(new Error("Malformed record identifier"), false);
    }
    if (response.status === 503) {
      throw stampRetryable(new Error("Record service unavailable"), true);
    }

    return response.json();
  },
  {
    name: "lookup_record",
    description: "Look up a record by identifier",
    schema: z.object({ id: z.string() }),
  }
);
```

对于另一次尝试也无法成功的失败，传入 `false`；对于瞬时失败传入 `true`。你未标记的错误会被重试，因此现有工具会保持其当前行为。

标记错误并不会改变其类型或形态，因此针对它的 `instanceof` 检查仍可正常使用。若要读取标记，可调用 `getRetryable(error)`，对于从未被标记的错误，它会返回 `true`、`false` 或 `undefined`。

聊天模型集成已经会标记它们能识别的失败，因此你无需手动标记这些错误。以下失败会在第一次尝试时就发生，而非消耗重试次数：

- **身份验证失败**：API 密钥缺失、无效或已过期。
- **权限被拒绝**：凭证有效，但无权访问所请求的资源。
- **未知模型**：提供方无法识别的模型标识符。
- **上下文窗口溢出**：输入超过模型可接受的长度。
- **无效的工具结果**：格式错误的工具结果块。
- **载荷过大**：请求体因体积过大而被提供方拒绝。
- **配额耗尽**：达到计费或用量限制，而非速率限制。
- **调用被取消**：通过中止信号停止的请求。

速率限制、超时和服务器错误仍然保持可重试。任何提供方无法识别的错误都不会被标记，并照常重试。


### Model retry

通过可配置的指数退避自动重试失败的模型调用。Model retry 适用于以下情况：

- 处理模型 API 调用中的瞬时失败。
- 提高依赖网络的模型请求的可靠性。
- 构建能优雅处理临时模型错误的 resilient agent。



**API reference:** [`modelRetryMiddleware`](https://reference.langchain.com/javascript/langchain/index/modelRetryMiddleware)

```typescript
import { createAgent, modelRetryMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [searchTool, databaseTool],
  middleware: [
    modelRetryMiddleware({
      maxRetries: 3,
      backoffFactor: 2.0,
```

```typescript
const agent = createAgent({
  model: "gpt-5.5",
  tools: [searchTool],
  middleware: [modelRetryMiddleware()],
});

class TimeoutError extends Error {
    // ...
}
class NetworkError extends Error {
    // ...
}

  maxRetries: 4,
  retryOn: [TimeoutError, NetworkError],
  backoffFactor: 1.5,
});

// Custom exception filtering
function shouldRetry(error: Error): boolean {
  // Only retry on rate limit errors
  if (error.name === "RateLimitError") {
    return true;
  }
  // Or check for specific HTTP status codes
  if (error.name === "HTTPError" && "statusCode" in error) {
    const statusCode = (error as any).statusCode;
    return statusCode === 429 || statusCode === 503;
  }
  return false;
}

const retryWithFilter = modelRetryMiddleware({
  maxRetries: 3,
  retryOn: shouldRetry,
});

// Return error message instead of raising
const retryContinue = modelRetryMiddleware({
  maxRetries: 4,

});

// Custom error message formatting

const retryWithFormatter = modelRetryMiddleware({
  maxRetries: 4,
```

### Model fallback

当主模型失败时，自动切换到备用模型。Model fallback 适用于以下情况：

- 构建能够应对模型宕机的 resilient agent。
- 通过回退到更便宜的模型来优化成本。
- 在 OpenAI、Anthropic 等 provider 之间做冗余备份。



```typescript
import { createAgent, modelFallbackMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [],
  middleware: [
    modelFallbackMiddleware(
      "gpt-5.4-mini",
      "claude-3-5-sonnet-20241022"
    ),
  ],
});
```




<Accordion title="Configuration options">



这个 middleware 接收任意数量的字符串参数，表示按顺序尝试的备用模型：

<ParamField body="...models" type="string[]" required>
  一个或多个备用模型字符串。

  ```typescript
  modelFallbackMiddleware(
    "first-fallback-model",
    "second-fallback-model",
    // ... more models
  )
  ```
</ParamField>


</Accordion>

### Summarization

在接近 token 上限时自动总结对话历史，保留最近消息，同时压缩更早的上下文。Summarization 适用于以下场景：
- 长时间运行、历史很长的对话。
- 具有大量历史记录的多轮对话。
- 需要保留完整对话脉络的应用。

<Note>
Summarization 是面向文本的上下文压缩。它不会对图像、音频或视频 payload 进行缩放、降采样或其他压缩。`keep` 保留的最近消息仍然保留原始多模态 blocks，而被总结掉的旧多模态消息只会以生成的文本摘要形式存在。对于图片很多的应用，请把媒体存到文件系统或对象存储中，并通过 URL 或文件引用放进消息历史。
</Note>



```typescript
import { createAgent, summarizationMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [weatherTool, calculatorTool],
  middleware: [
    summarizationMiddleware({
      model: "gpt-5.4-mini",
      trigger: { tokens: 4000 },
      keep: { messages: 20 },
    }),
  ],
});
```


<Accordion title="Configuration options">



<Tip>
    下文中 `trigger` 和 `keep` 的 `fraction` 条件依赖 chat model 的 [profile data](/oss/javascript/langchain/models#model-profiles)，前提是使用 `langchain@1.1.0`。如果没有这些数据，请使用其他条件或手动指定：
    ```typescript
    const customProfile: ModelProfile = {
        maxInputTokens: 100_000,
        // ...
    }
    model = await initChatModel("...", {
        profile: customProfile,
    });
    ```
</Tip>

<ParamField body="model" type="string | BaseChatModel" required>
    用于生成摘要的模型。可以是模型标识字符串（例如 `'openai:gpt-5.4-mini'`），也可以是 `BaseChatModel` 实例。
</ParamField>

<ParamField body="trigger" type="object | object[]">
    触发摘要的条件。可以是：

    - **单一条件（AND 逻辑）：** 一个条件对象，其中所有属性必须同时满足。

        ```typescript
        // 当 tokens >= 4000 且 messages >= 10 时触发
        trigger: { tokens: 4000, messages: 10 }
        ```

    - **多个条件（OR 逻辑）：** 条件对象数组。只要任意一个对象的条件满足，就会触发摘要。

        ```typescript
        // 当 tokens >= 3000 或 messages >= 6 时触发
        trigger: [{ tokens: 3000 }, { messages: 6 }]
        ```

    每个条件可以包含：
    - `fraction`（number）：模型上下文大小的比例（0-1）
    - `tokens`（number）：绝对 token 数
    - `messages`（number）：消息数量

    每个条件至少要指定一个属性。如果不提供，则不会自动触发摘要。
</ParamField>

<ParamField body="keep" type="object" default="{messages: 20}">
    摘要后要保留多少上下文。只需指定以下之一：

    - `fraction`（number）：保留的模型上下文比例（0-1）
    - `tokens`（number）：保留的绝对 token 数
    - `messages`（number）：保留的最近消息数量
</ParamField>

<ParamField body="tokenCounter" type="function">
    自定义 token 计数函数。默认使用基于字符的计数。
</ParamField>

<ParamField body="summaryPrompt" type="string">
    用于摘要的自定义 prompt 模板。如果未指定，则使用内置模板。模板应包含 `{messages}` 占位符，供插入对话历史。
</ParamField>

<ParamField body="trimTokensToSummarize" type="number" default="4000">
    生成摘要时可包含的最大 token 数。会先裁剪消息，使其符合该限制。
</ParamField>

<ParamField body="summaryPrefix" type="string">
    添加到摘要消息前面的前缀。如果未提供，则使用默认前缀。
</ParamField>

<ParamField body="maxTokensBeforeSummary" type="number" deprecated>
    **已弃用：** 请改用 `trigger: { tokens: value }`。
</ParamField>

<ParamField body="messagesToKeep" type="number" deprecated>
    **已弃用：** 请改用 `keep: { messages: value }`。
</ParamField>


</Accordion>

<Accordion title="Full example">

summarization middleware 会监控消息 token 数量，并在达到阈值时自动总结较早的消息。

**Trigger conditions** 控制何时运行摘要：
- 单个阈值会在满足该阈值时触发
- 包含多个阈值的 trigger clause 只有在所有阈值都满足时才会触发（AND 逻辑）
- trigger 条件列表只要命中其中一项就会触发（OR 逻辑）
- 每个阈值可以使用 `fraction`（模型上下文大小的比例）、`tokens`（绝对数）或 `messages`（消息数量）

**Keep condition** 控制要保留多少上下文（只需指定一个）：
- `fraction` - 保留的模型上下文比例
- `tokens` - 保留的绝对 token 数
- `messages` - 保留的最近消息数量



```typescript
import { createAgent, summarizationMiddleware } from "langchain";

// 单条条件（AND 逻辑）：当 tokens >= 4000 且 messages >= 10 时触发
const agent = createAgent({
  model: "gpt-5.5",
  tools: [weatherTool, calculatorTool],
  middleware: [
    summarizationMiddleware({
      model: "gpt-5.4-mini",
      trigger: { tokens: 4000, messages: 10 },
      keep: { messages: 20 },
    }),
  ],
});

// 多条条件（OR 逻辑）：当 tokens >= 3000 或 messages >= 6 时触发
const agent2 = createAgent({
  model: "gpt-5.5",
  tools: [weatherTool, calculatorTool],
  middleware: [
    summarizationMiddleware({
      model: "gpt-5.4-mini",
      trigger: [
        { tokens: 3000 },
        { messages: 6 },
      ],
      keep: { messages: 20 },
    }),
  ],
});

// Using fractional limits
const agent3 = createAgent({
  model: "gpt-5.5",
  tools: [weatherTool, calculatorTool],
  middleware: [
    summarizationMiddleware({
      model: "gpt-5.4-mini",
      trigger: { fraction: 0.8 },
      keep: { fraction: 0.3 },
    }),
  ],
});
```


</Accordion>

### Human-in-the-loop

在工具执行前暂停 agent，让人工审批、编辑或拒绝 tool call。[Human-in-the-loop](/oss/javascript/langchain/human-in-the-loop) 适用于以下情况：

- 需要人工批准的高风险操作，例如数据库写入或金融交易。
- 需要人工监督的合规工作流。
- 人工反馈会指导 agent 的长对话场景。



<Warning>
    Human-in-the-loop middleware 需要一个 [checkpointer](/oss/javascript/langgraph/checkpointers#checkpoints)，以便在中断之间保留 state。

### Tool call limit

通过限制 tool call 的数量来控制 agent 执行，可以是全局限制，也可以是针对特定工具的限制。Tool call limits 适用于以下情况：

- 防止对昂贵的外部 API 进行过多调用。
- 限制 web search 或数据库查询。
- 对特定 tool 的使用施加速率限制。
- 防止 agent runaway loop。



```typescript
import { createAgent, toolCallLimitMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [searchTool, databaseTool],
  middleware: [
    toolCallLimitMiddleware({ threadLimit: 20, runLimit: 10 }),
    toolCallLimitMiddleware({
      toolName: "search",
      threadLimit: 5,
      runLimit: 3,
    }),
  ],
});
```

    观看这个 [video guide](https://www.youtube.com/watch?v=oL6am5UqODY)，了解 Tool Call Limit middleware 的行为。
</Callout>


<Accordion title="Configuration options">



<ParamField body="toolName" type="string">
    特定工具的名称。如果不提供，则限制适用于**所有工具**。
</ParamField>

<ParamField body="threadLimit" type="number">
    单个 thread 中的 tool call 上限（跨多次调用持续生效）。需要 checkpointer 来维护 state。`undefined` 表示不限制。
</ParamField>

<ParamField body="runLimit" type="number">
    单次调用中的 tool call 上限（单次用户消息 → 响应周期）。每次新的用户消息都会重置。`undefined` 表示不限制。

    **注意：** `threadLimit` 和 `runLimit` 至少要设置一个。
</ParamField>

<ParamField body="exitBehavior" type="string" default="continue">
    达到限制时的行为：

    - `'continue'`（默认）- 用错误消息阻止超额的 tool call，但继续让其他工具和模型执行。模型会根据错误消息决定何时结束。
    - `'error'` - 直接抛出 `ToolCallLimitExceededError` 异常并停止执行。
    - `'end'` - 立即停止执行，并为超额的 tool call 返回 `ToolMessage` 和 AI message。仅在限制单个工具时可用；如果还有其他待执行调用，则会抛出错误。
</ParamField>


</Accordion>

<Accordion title="Full example">

限制通常可以这样理解：
- **Thread limit** - 单个 conversation 中跨所有运行的最大调用数，需要 checkpointer。
- **Run limit** - 单次 invocation 的最大调用数，每轮都会重置。

退出行为：
- `'continue'`（默认）- 用错误消息阻止超额调用，agent 继续执行。
- `'error'` - 立即抛出异常。
- `'end'` - 以 `ToolMessage + AI message` 的形式结束，仅适用于单工具场景。



```typescript
import { createAgent, toolCallLimitMiddleware } from "langchain";

const globalLimiter = toolCallLimitMiddleware({ threadLimit: 20, runLimit: 10 });
const searchLimiter = toolCallLimitMiddleware({ toolName: "search", threadLimit: 5, runLimit: 3 });
const databaseLimiter = toolCallLimitMiddleware({ toolName: "query_database", threadLimit: 10 });
const strictLimiter = toolCallLimitMiddleware({ toolName: "scrape_webpage", runLimit: 2, exitBehavior: "error" });

const agent = createAgent({
  model: "gpt-5.5",
  tools: [searchTool, databaseTool, scraperTool],
  middleware: [globalLimiter, searchLimiter, databaseLimiter, strictLimiter],
});
```


</Accordion>

### PII detection

使用可配置策略检测并处理对话中的 Personally Identifiable Information (PII)。PII detection 适用于以下情况：

- 需要合规控制的医疗和金融应用。
- 需要清理日志的客服 agent。
- 任何处理敏感用户数据的应用。



```typescript
import { createAgent, piiMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [],
  middleware: [
    piiMiddleware("email", { strategy: "redact", applyToInput: true }),
    piiMiddleware("credit_card", { strategy: "mask", applyToInput: true }),
  ],
});
```


#### Custom PII types

你可以通过 `detector` 参数创建自定义 PII 类型，这样就能检测超出内置类型范围的模式。

**创建自定义 detector 的三种方式：**

1. **Regex pattern string** - 简单的模式匹配
2. **RegExp object** - 需要 regex flags 时更灵活
3. **Custom function** - 带验证逻辑的复杂检测



```typescript
import { createAgent, piiMiddleware, type PIIMatch } from "langchain";

// Method 1: Regex pattern string
const agent1 = createAgent({
  model: "gpt-5.5",
  tools: [],
  middleware: [
    piiMiddleware("api_key", {
      detector: "sk-[a-zA-Z0-9]{32}",
      strategy: "block",
    }),
  ],
});

// Method 2: RegExp object
const agent2 = createAgent({
  model: "gpt-5.5",
  tools: [],
  middleware: [
    piiMiddleware("phone_number", {
      detector: /\+?\d{1,3}[\s.-]?\d{3,4}[\s.-]?\d{4}/,
      strategy: "mask",
    }),
  ],
});

// Method 3: Custom detector function
function detectSSN(content: string): PIIMatch[] {
  const matches: PIIMatch[] = [];
  const pattern = /\d{3}-\d{2}-\d{4}/g;
  let match: RegExpExecArray | null;

  while ((match = pattern.exec(content)) !== null) {
    const ssn = match[0];
    // Validate: first 3 digits shouldn't be 000, 666, or 900-999
    const firstThree = parseInt(ssn.substring(0, 3), 10);
    if (firstThree !== 0 && firstThree !== 666 && !(firstThree >= 900 && firstThree <= 999)) {
      matches.push({
        text: ssn,
        start: match.index ?? 0,
        end: (match.index ?? 0) + ssn.length,
      });
    }
  }
  return matches;
}

const agent3 = createAgent({
  model: "gpt-5.5",
  tools: [],
  middleware: [
    piiMiddleware("ssn", {
      detector: detectSSN,
      strategy: "hash",
    }),
  ],
});
```


**自定义 detector 函数签名：**

detector 函数需要接收一个字符串并返回匹配项：


返回一个 `PIIMatch` 对象数组：
```typescript
interface PIIMatch {
  text: string;
  start: number;
  end: number;
}

function detector(content: string): PIIMatch[] {
  return [
    { text: "matched_text", start: 0, end: 12 },
    // ... more matches
  ];
}
```


<Tip>
    对于自定义 detector：

    - 简单模式用 regex string
    - 需要 flags 时用 RegExp object
    - 需要更复杂验证逻辑时用 custom function
    - custom function 给你完整的检测控制权
</Tip>

<Accordion title="Configuration options">



<ParamField body="piiType" type="string" required>
    要检测的 PII 类型。可以是内置类型（`email`、`credit_card`、`ip`、`mac_address`、`url`）或自定义类型名。
</ParamField>

<ParamField body="strategy" type="string" default="redact">
    处理检测到的 PII 的方式：

    - `'block'` - 检测到就抛异常
    - `'redact'` - 替换为 `[REDACTED_TYPE]`
    - `'mask'` - 部分遮蔽
    - `'hash'` - 替换为确定性 hash
</ParamField>

<ParamField body="detector" type="RegExp | string | function">
    自定义 detector。可以是：

    - `RegExp`
    - `string`
    - `function`

    如果不提供，则使用内置 detector。
</ParamField>

<ParamField body="applyToInput" type="boolean" default="true">
    在模型调用前检查用户消息
</ParamField>

<ParamField body="applyToOutput" type="boolean" default="false">
    在模型调用后检查 AI 消息
</ParamField>

<ParamField body="applyToToolResults" type="boolean" default="false">
    在工具执行后检查 tool result 消息
</ParamField>


</Accordion>

### LLM tool selector

在调用主模型之前，用 LLM 智能选择相关工具。LLM tool selector 适用于以下情况：

- 工具很多（10 个以上）且大多数与当前问题无关的 agent。

```typescript
import { createAgent, llmToolSelectorMiddleware } from "langchain";

const agent = createAgent({

      model: "gpt-5.4-mini",

});
```

### Provider tool search

把选定工具延后到模型 provider 的 server-side tool search，让模型按需发现这些工具，而不是一开始就收到所有 tool schema。Provider tool search 适用于以下情况：

- 在使用很多工具时减少 context 膨胀。
- 通过只展示相关工具来提高工具选择准确性。

<Note>
    需要支持 server-side tool search 的模型：Anthropic（Claude Sonnet 4+/Opus 4+/Haiku 4.5+）或 OpenAI（gpt-5.5+）。其他 provider 会抛出错误。
</Note>

**API reference:** [`providerToolSearchMiddleware`](https://reference.langchain.com/javascript/langchain/index/providerToolSearchMiddleware)

```typescript
import { createAgent, providerToolSearchMiddleware } from "langchain";
import { tool } from "@langchain/core/tools";
import { z } from "zod";

const getWeather = tool(async () => "Sunny, 22C", {
  name: "get_weather",
  description: "Get the current weather for a city",
  schema: z.object({ city: z.string() }),
});

const lookupOrderStatus = tool(async () => "OUT_FOR_DELIVERY", {
  name: "lookup_order_status",
  description: "Look up the current delivery status of a customer order by ID",
  schema: z.object({ orderId: z.string() }),
});

const nicheTools = [lookupOrderStatus];

const agent = createAgent({
  model: "anthropic:claude-opus-4-8",
  tools: [getWeather, ...nicheTools],
  middleware: [
    providerToolSearchMiddleware({ searchableTools: nicheTools }),
  ],
});
```

<Accordion title="Configuration options">

<ParamField body="searchableTools" type="(string | StructuredToolInterface)[]">
    要通过 provider tool search 延后的工具，可以按名称或实例指定。被延后的工具会在搜索结果显现前对模型隐藏。构造时设置 `extras.defer_loading: true` 的工具无论如何都会被延后；如果省略 `searchableTools`，则只延后这些预标记工具。
</ParamField>

</Accordion>

<Accordion title="Full example">

这个 middleware 会把 `searchableTools` 中的工具都加入延后与搜索流程。工具也可以在构造时通过 `extras.defer_loading: true` 自己进入延后模式。

```typescript
import { createAgent, providerToolSearchMiddleware } from "langchain";
import { tool } from "@langchain/core/tools";
import { z } from "zod";

// Marked `defer_loading` at construction, so it's deferred on its own —
// no need to list it in `searchableTools`.
const sendEmail = tool(async () => "sent", {
  name: "send_email",
  description: "Send an email",
  schema: z.object({ to: z.string() }),
  extras: { defer_loading: true },
});

const agent = createAgent({
  model: "anthropic:claude-opus-4-8",
  tools: [sendEmail],
  middleware: [providerToolSearchMiddleware()],
});
```

</Accordion>




### Filesystem middleware

Context engineering 是构建有效 agent 的核心挑战之一。使用返回可变长度结果的工具时尤其困难，例如 `web_search` 和 RAG，因为过长的 tool result 很快就会填满 context window。

来自 [Deep Agents](/oss/javascript/deepagents/overview) 的 `FilesystemMiddleware` 为 interacting with short-term and long-term memory 提供四个工具：

- `ls`：列出 filesystem 中的文件
- `read_file`：读取整个文件或文件的若干行
- `write_file`：向 filesystem 写入新文件
- `edit_file`：编辑 filesystem 中的已有文件



```typescript
import { createAgent } from "langchain";
import { createFilesystemMiddleware } from "deepagents";

// FilesystemMiddleware is included by default in createDeepAgent
// You can customize it if building a custom agent
const agent = createAgent({
  model: "claude-sonnet-4-6",
  middleware: [
    createFilesystemMiddleware({
      backend: undefined,  // Optional: custom backend (defaults to StateBackend)
      systemPrompt: "Write to the filesystem when...",  // Optional custom system prompt override
      customToolDescriptions: {
        ls: "Use the ls tool when...",
        read_file: "Use the read_file tool to...",
      },  // Optional: Custom descriptions for filesystem tools
    }),
  ],
});
```


#### Short-term vs. long-term filesystem

默认情况下，这些工具会写入 graph state 里的本地“filesystem”。如果要在 thread 之间持久化存储，可以配置一个 `CompositeBackend`，把特定路径（如 `/memories/`）路由到 `StoreBackend`。



```typescript
import { createAgent } from "langchain";
import { createFilesystemMiddleware, CompositeBackend, StateBackend, StoreBackend } from "deepagents";
import { InMemoryStore } from "@langchain/langgraph-checkpoint";

const store = new InMemoryStore();

const agent = createAgent({
  model: "claude-sonnet-4-6",
  store,
  middleware: [
    createFilesystemMiddleware({
      backend: new CompositeBackend(
        new StateBackend(),
        { "/memories/": new StoreBackend() }
      ),
      systemPrompt: "Write to the filesystem when...", // Optional custom system prompt override
      customToolDescriptions: {
        ls: "Use the ls tool when...",
        read_file: "Use the read_file tool to...",
      }, // Optional: Custom descriptions for filesystem tools
    }),
  ],
});
```


当你为 `/memories/` 配置了 `StoreBackend` 的 `CompositeBackend` 时，任何以 **/memories/** 为前缀的文件都会保存到持久化存储中，并跨不同 thread 保留。没有这个前缀的文件仍然保存在 ephemeral state storage 中。

### Subagent

把任务交给 subagent 可以隔离 context，让主（supervisor）agent 的 context window 保持干净，同时仍能深入处理任务。

来自 [Deep Agents](/oss/javascript/deepagents/overview) 的 subagents middleware 允许你通过 `task` tool 提供 subagent。



```typescript
import { tool } from "langchain";
import { createAgent } from "langchain";
import { createSubAgentMiddleware } from "deepagents";
import { z } from "zod";

const getWeather = tool(
  async ({ city }: { city: string }) => {
    return `The weather in ${city} is sunny.`;
  },
  {
    name: "get_weather",
    description: "Get the weather in a city.",
    schema: z.object({
      city: z.string(),
    }),
  },
);

const agent = createAgent({
  model: "claude-sonnet-4-6",
  middleware: [
    createSubAgentMiddleware({
      defaultModel: "claude-sonnet-4-6",
      defaultTools: [],
      subagents: [
        {
          name: "weather",
          description: "This subagent can get weather in cities.",
          systemPrompt: "Use the get_weather tool to get the weather in a city.",
          tools: [getWeather],
          model: "gpt-5.5",
          middleware: [],
        },
      ],
    }),
  ],
});
```


一个 subagent 由 **name**、**description**、**system prompt** 和 **tools** 定义。你也可以为 subagent 提供自定义 **model**，或者提供额外的 **middleware**。当你想让 subagent 额外共享一个 state key 时，这会特别有用。

对于更复杂的场景，你还可以把自己预构建的 LangGraph graph 作为 subagent。



```typescript
import { tool, createAgent } from "langchain";
import { createSubAgentMiddleware, type SubAgent } from "deepagents";
import { z } from "zod";

const getWeather = tool(
  async ({ city }: { city: string }) => {
    return `The weather in ${city} is sunny.`;
  },
  {
    name: "get_weather",
    description: "Get the weather in a city.",
    schema: z.object({
      city: z.string(),
    }),
  },
);

const weatherSubagent: SubAgent = {
  name: "weather",
  description: "This subagent can get weather in cities.",
  systemPrompt: "Use the get_weather tool to get the weather in a city.",
  tools: [getWeather],
  model: "gpt-5.5",
  middleware: [],
};

const agent = createAgent({
  model: "claude-sonnet-4-6",
  middleware: [
    createSubAgentMiddleware({
      defaultModel: "claude-sonnet-4-6",
      defaultTools: [],
      subagents: [weatherSubagent],
    }),
  ],
});
```


除了用户定义的 subagent 之外，主 agent 会一直拥有一个 `general-purpose` subagent。这个 subagent 使用和主 agent 相同的指令，以及它可以访问的所有工具。`general-purpose` subagent 的主要作用是 context isolation：主 agent 可以把复杂任务交给它，从而在不被中间 tool call 细节膨胀的情况下获得一个简洁答案。





### Context editing

管理 conversation context，在达到 token 上限时清理较早的 tool call 输出，同时保留最近的结果。这有助于在包含大量 tool call 的长对话中维持可控的上下文窗口。Context editing 适用于以下情况：

- tool call 很多、容易超过 token 上限的长对话。
- 通过移除不再相关的旧 tool output 来降低 token 成本。
- 只保留最近 N 个 tool result 在上下文中。



```typescript
import { createAgent, contextEditingMiddleware, ClearToolUsesEdit } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [],
  middleware: [
    contextEditingMiddleware({
      edits: [
        new ClearToolUsesEdit({
          triggerTokens: 100000,
          keep: 3,
        }),
      ],
    }),
  ],
});
```


<Accordion title="Configuration options">



<ParamField body="edits" type="ContextEdit[]" default="[new ClearToolUsesEdit()]">
    要应用的 [`ContextEdit`](https://reference.langchain.com/javascript/langchain/index/ContextEdit) 策略数组
</ParamField>

**[`ClearToolUsesEdit`](https://reference.langchain.com/javascript/langchain/index/ClearToolUsesEdit) options:**

<ParamField body="triggerTokens" type="number" default="100000">
    触发编辑的 token 数。超过后会清理较早的 tool output。
</ParamField>

<ParamField body="clearAtLeast" type="number" default="0">
    编辑执行时至少要回收的 token 数。设为 0 时，尽可能清理更多。
</ParamField>

<ParamField body="keep" type="number" default="3">
    必须保留的最近 tool result 数量。
</ParamField>

<ParamField body="clearToolInputs" type="boolean" default="false">
    是否清理 AI message 上对应的 tool call 参数。设为 `true` 时，tool call args 会被替换成空对象。
</ParamField>

<ParamField body="excludeTools" type="string[]" default="[]">
    不允许清理的工具名列表。这些工具的输出永远不会被清理。
</ParamField>

<ParamField body="placeholder" type="string" default="[cleared]">
    插入到已清理 tool output 中的占位文本。
</ParamField>


</Accordion>

<Accordion title="Full example">

当 token 上限达到时，这个 middleware 会应用 context editing 策略。最常见的策略是 `ClearToolUsesEdit`，它会清理较早的 tool result，同时保留最近的结果。

**How it works:**
1. 监控对话中的 token 数
2. 达到阈值时，清理较早的 tool output
3. 保留最近 N 个 tool result
4. 可选地保留 tool call 参数以维持上下文



```typescript
import { createAgent, contextEditingMiddleware, ClearToolUsesEdit } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [searchTool, calculatorTool, databaseTool],
  middleware: [
    contextEditingMiddleware({
      edits: [
        new ClearToolUsesEdit({
          triggerTokens: 2000,
          keep: 3,
          clearToolInputs: false,
          excludeTools: [],
          placeholder: "[cleared]",
        }),
      ],
    }),
  ],
});
```


</Accordion>

### LLM tool emulator

使用 LLM 来模拟工具执行，适合测试场景，用 AI 生成的响应替代真实 tool call。LLM tool emulator 适用于以下情况：

- 不执行真实工具就测试 agent 行为。
- 在外部工具不可用或成本较高时开发 agent。
- 在实现真实工具前先原型化 agent workflow。



```typescript
import { createAgent, toolEmulatorMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [getWeather, searchDatabase, sendEmail],
  middleware: [
    toolEmulatorMiddleware(), // Emulate all tools
  ],
});
```


<Accordion title="Configuration options">



<ParamField body="tools" type="(string | ClientTool | ServerTool)[]">
    要模拟的工具名称（字符串）或工具实例列表。如果是 `undefined`（默认），则模拟所有工具。如果是空数组 `[]`，则不模拟任何工具。如果是 name/instance 数组，则只模拟这些工具。
</ParamField>

<ParamField body="model" type="string | BaseChatModel">
    用于生成模拟工具响应的模型。可以是模型标识字符串，也可以是 `BaseChatModel` 实例。未指定时默认使用 agent 的模型。
</ParamField>


</Accordion>

<Accordion title="Full example">

这个 middleware 使用 LLM 生成 tool call 的合理响应，而不是执行真实工具。



```typescript
import { createAgent, toolEmulatorMiddleware, tool } from "langchain";
import * as z from "zod";

const getWeather = tool(
  async ({ location }) => `Weather in ${location}`,
  {
    name: "get_weather",
    description: "Get the current weather for a location",
    schema: z.object({ location: z.string() }),
  }
);

const sendEmail = tool(
  async ({ to, subject, body }) => "Email sent",
  {
    name: "send_email",
    description: "Send an email",
    schema: z.object({
      to: z.string(),
      subject: z.string(),
      body: z.string(),
    }),
  }
);

// Emulate all tools (default behavior)
const agent = createAgent({
  model: "gpt-5.5",
  tools: [getWeather, sendEmail],
  middleware: [toolEmulatorMiddleware()],
});

// Emulate specific tools by name
const agent2 = createAgent({
  model: "gpt-5.5",
  tools: [getWeather, sendEmail],
  middleware: [
    toolEmulatorMiddleware({
      tools: ["get_weather"],
    }),
  ],
});

// Emulate specific tools by passing tool instances
const agent3 = createAgent({
  model: "gpt-5.5",
  tools: [getWeather, sendEmail],
  middleware: [
    toolEmulatorMiddleware({
      tools: [getWeather],
    }),
  ],
});

// Use custom model for emulation
const agent5 = createAgent({
  model: "gpt-5.5",
  tools: [getWeather, sendEmail],
  middleware: [
    toolEmulatorMiddleware({
      model: "claude-sonnet-4-6",
    }),
  ],
});
```


</Accordion>
