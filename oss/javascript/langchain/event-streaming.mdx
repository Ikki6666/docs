---
title: 事件流
description: 从 LangChain 智能体运行中实时流式获取更新
---

LangChain 智能体构建在 LangGraph 之上，因此它们支持同样的流式传输栈，并针对消息、工具调用、状态和自定义更新提供了智能体视角的投影。

对于大多数应用和前端场景，请使用 `stream_events(..., version="v3")` 进行 **事件流式传输**。事件流会返回一个带类型投影的运行对象，因此每个投影都能独立消费，而不需要解析 stream-mode 元组。



```ts
import { createAgent, tool } from "langchain";
import * as z from "zod";

const getWeather = tool(
  async ({ city }) => `It's always sunny in ${city}!`,
  {
    name: "get_weather",
    description: "查询某个城市的天气。",
    schema: z.object({ city: z.string() }),
  }
);

const agent = createAgent({
  model: "gpt-5-nano",
  tools: [getWeather],
});

const stream = await agent.streamEvents(
  { messages: [{ role: "user", content: "What is the weather in SF?" }] },
  { version: "v3" }
);

for await (const message of stream.messages) {
  for await (const delta of message.text) {
    process.stdout.write(delta);
  }
}

const finalState = await stream.output;
```


## 可以流式获取什么



| 投影 | 用途 |
| ---------- | --- |
| `for event in stream` | 原始协议事件，包含完整封装和所有通道的访问权限。 |
| `stream.messages` | 模型消息流，每次 LLM 调用对应一个。 |
| `message.text` | 某条消息的文本增量和最终文本。 |
| `message.reasoning` | 对暴露推理内容的模型提供推理增量。 |
| `message.toolCalls` | 工具调用参数块和最终完成的工具调用。 |
| `message.output` | 模型调用完成后的最终消息对象。 |
| `message.usage` | 当提供商返回时，提供 token 使用量元数据。 |
| `stream.values` | 智能体状态快照。 |
| `stream.output` | 最终智能体状态。 |
| `stream.subgraphs` | 嵌套图运行，包括子智能体和普通子图。 |
| `stream.extensions` | 自定义转换器投影。 |
| `stream.toolCalls` | 工具执行生命周期，包括输入、输出增量、最终输出和错误。 |




`stream.messages` 会返回消息流对象。每个消息流都暴露 `.text`、`.reasoning`、`.toolCalls`、`.output` 和 `.usage`。异步投影可以迭代实时增量，也可以 `await` 获取最终值。


## 智能体消息

当你想要获取每次 LLM 调用的模型输出时，就使用 `stream.messages`。



```ts
const stream = await agent.streamEvents(input, { version: "v3" });

for await (const message of stream.messages) {
  process.stdout.write(`[${message.node}] `);
  for await (const delta of message.text) {
    process.stdout.write(delta);
  }

  const fullMessage = await message.output;
  console.log(fullMessage.content);

  const usage = await message.usage;
  if (usage) {
    console.log(usage);
  }
}
```


`message.output` 会给出最终的 AI 消息，包括提供商特定的内容块。在 TypeScript 中，如果你只需要 token 计数或其他使用量元数据，请使用 `message.usage`；在 Python 中，请从 `message.output.usage_metadata` 读取使用量。

## 推理内容

推理内容和文本内容的形状相同，但只有在所选模型输出 reasoning blocks 时才可用。



```ts
const stream = await agent.streamEvents(input, { version: "v3" });

for await (const message of stream.messages) {
  for await (const delta of message.reasoning) {
    process.stdout.write(`[thinking] ${delta}`);
  }

  for await (const delta of message.text) {
    process.stdout.write(delta);
  }
}
```


有关模型配置细节，请参见 [推理指南](/oss/javascript/langchain/models#reasoning) 和你所用提供商的集成页面。

## 工具调用

有两个很有用的工具调用投影：

- `message.tool_calls` 会在模型生成工具调用时，流式输出工具调用参数块。
- `stream.tool_calls` 会在工具调用开始后，流式输出工具执行生命周期。



```ts
const stream = await agent.streamEvents(input, { version: "v3" });

await Promise.all([
  (async () => {
    for await (const message of stream.messages) {
      for await (const chunk of message.toolCalls) {
        console.log("tool call chunk", chunk);
      }
    }
  })(),
  (async () => {
    for await (const call of stream.toolCalls) {
      console.log(call.name, call.input);
      console.log(await call.output, await call.error);
    }
  })(),
]);
```


## 流式子智能体

当某个 `create_agent` 调用通过一个包装工具调用另一个命名的 `create_agent` 时，内部智能体的事件会流到一个嵌套命名空间中。你传给 `create_agent` 的 `name=` 会在流里标识那个内部智能体，因此你可以按智能体过滤和标注。



命名子智能体会作为句柄出现在 `stream.subgraphs` 上，并与普通子图并列。每个句柄都暴露内部智能体的 `.messages`、`.values`、`.toolCalls` 和 `.output`；通过检查 `subagent.name`（也就是你传入的 `name=`）来筛选特定智能体。

```ts
import { createAgent, tool } from "langchain";
import { z } from "zod";

const getWeather = tool(
  async ({ city }) => `It's always sunny in ${city}!`,
  { name: "get_weather", schema: z.object({ city: z.string() }) }
);

const weatherAgent = createAgent({
  model: "openai:gpt-5.5",
  tools: [getWeather],
  name: "weather_agent",
});

const callWeather = tool(
  async ({ query }) => {
    const result = await weatherAgent.invoke({
      messages: [{ role: "user", content: query }],
    });
    return result.messages.at(-1)?.text ?? "";
  },
  { name: "call_weather", schema: z.object({ query: z.string() }) }
);

const supervisor = createAgent({
  model: "openai:gpt-5.5",
  tools: [callWeather],
  name: "supervisor",
});

const stream = await supervisor.streamEvents(
  { messages: [{ role: "user", content: "What's the weather in Boston?" }] },
  { version: "v3" }
);

for await (const subagent of stream.subgraphs) {
  if (subagent.name !== "weather_agent") continue;
  process.stdout.write(`${subagent.name}: `);
  for await (const message of subagent.messages) {
    for await (const token of message.text) {
      process.stdout.write(token);
    }
  }
  process.stdout.write("\n");
}
```


普通的 `StateGraph` 子图如果是从工具中调用的，也会出现在 `stream.subgraphs` 中。要想在 `subagent.graph_name` 里看到标签，请在 `.compile(name=...)` 上设置 `name=`。



命名子智能体和普通子图共用 `stream.subgraphs` 投影；由你写在循环里的筛选条件来区分它们。


## 状态和最终输出

使用 `stream.values` 获取状态快照，使用 `stream.output` 获取最终智能体状态。



```ts
const stream = await agent.streamEvents(input, { version: "v3" });

for await (const snapshot of stream.values) {
  console.log(snapshot);
}

const finalState = await stream.output;
```


## 多个投影同时消费



如果你想在 JavaScript 中同时消费多个投影，可以这样写：

```ts
const stream = await agent.streamEvents(input, { version: "v3" });

await Promise.all([
  (async () => {
    for await (const message of stream.messages) {
      console.log(await message.text);
    }
  })(),
  (async () => {
    for await (const call of stream.toolCalls) {
      console.log(call.name, call.input);
    }
  })(),
]);
```


如果你想访问那些没有暴露为类型化投影的通道，或者检查完整事件封装，就直接迭代原始协议事件：



```ts
for await (const event of stream) {
  console.log(event.method, event.params.namespace, event.params.data);
}
```


## 自定义更新

当你的应用需要一个内置投影之外的视图时，就用自定义流转换器，例如检索进度、工件，或者领域特定事件。



```ts
const stream = await agent.streamEvents(input, {
  version: "v3",
  transformers: [toolActivityTransformer],
});

for await (const activity of stream.extensions.toolActivity) {
  console.log(activity);
}
```


### 在中间件上注册转换器



<Note>通过中间件注册的转换器需要 `langchain@1.4.3` 或更高版本。</Note>


中间件可以连同钩子和工具一起声明流转换器工厂。不同语言中的工厂形状不一样：



把 `streamTransformers` 传给 `createMiddleware`，作为一个工厂元组。每个工厂的形状都是 `() => StreamTransformer<any>`（无参数），并且每个作用域只调用一次。每次调用都返回一个新的转换器，能让每个子图彼此隔离。

```ts
import { createAgent, createMiddleware } from "langchain";

const toolActivityMiddleware = createMiddleware({
  name: "ToolActivityMiddleware",
  streamTransformers: [toolActivityTransformer],
});

const agent = createAgent({
  model: "gpt-5-nano",
  tools: [getWeather],
  middleware: [toolActivityMiddleware],
});
```




在编译时，`createAgent` 会把中间件注册的工厂和传给自身 `streamTransformers` 选项的内容合并起来。编译后图上的最终顺序是：

1. 内置的 `ToolCallTransformer`。
2. 中间件注册的工厂，按中间件顺序排列。
3. 来自 `createAgent` 的调用方自定义 `streamTransformers`。

这样可以保证内置工具调用投影始终排在消费者转换器前面，同时把最终解释权留给调用方传入的条目。


有关转换器契约，请参见 [构建你自己的投影](/oss/javascript/langgraph/event-streaming#build-your-own-projection)。
