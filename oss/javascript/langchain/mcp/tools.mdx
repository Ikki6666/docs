[`MCPAdapter`](https://reference.langchain.com/javascript/langchain-mcp-adapters/MCPAdapter) 在 MCP 服务器和 LangChain 智能体之间架起桥梁：它发现服务器宣告的工具，并将其适配成标准的 LangChain 工具。像使用任何其他 LangChain 工具一样，把 `listTools()` 返回的工具传给 [`createAgent`](https://reference.langchain.com/javascript/langchain/index/createAgent)。


本页介绍该桥梁特有的内容：识别 MCP 工具、控制它们的执行、处理它们的输出，以及在调用期间服务器需要输入时进行响应。关于可运行的发现与智能体示例，参见 [MCP 快速开始](/oss/javascript/langchain/mcp)。

## 在智能体中使用 MCP 工具



用 [`MCPAdapter.listTools`](https://reference.langchain.com/javascript/langchain-mcp-adapters/MCPAdapter/listTools) 发现服务器的目录，然后将返回的工具交给 [`createAgent`](https://reference.langchain.com/javascript/langchain/index/createAgent)。从智能体的角度看，它们表现得像 LangChain 工具：模型选择一个工具，LangChain 调用它，生成的 [`ToolMessage`](https://reference.langchain.com/javascript/langchain-core/messages/ToolMessage) 返回给模型。

<McpUseInAgentJs />

在智能体可以调用这些工具期间保持 adapter 打开，包括恢复被中断的运行时。用完智能体后调用 `await adapter.close()`。


关于定义、绑定和使用 LangChain 工具的一般指导，参见 [Tools](/oss/javascript/langchain/tools)。关于多个 MCP 服务器及其带命名空间的工具目录，参见 [Connections](/oss/javascript/langchain/mcp/connections#multiple-servers)。

## 处理工具输出

MCP 工具结果会变成 [`ToolMessage`](https://reference.langchain.com/javascript/langchain-core/messages/ToolMessage) 对象，其中包含模型可读的内容、用于应用数据的 artifact，以及指示成功或失败的状态。

### 多模态内容

adapter 将模型可见的 MCP 内容转换为 LangChain [content blocks](/oss/javascript/langchain/messages#standard-content-blocks)。例如，返回带有截图的 MCP 图像 block 的工具，会以 `image` block 的形式到达模型。



<McpMultimodalToolContentJs />


### 结构化内容

当工具返回结构化内容时，adapter 会将其作为 artifact 附加到 [`ToolMessage`](https://reference.langchain.com/javascript/langchain-core/messages/ToolMessage) 上，而不是并入模型可见的文本中。运行智能体，然后从结果中的 [`ToolMessage`](https://reference.langchain.com/javascript/langchain-core/messages/ToolMessage) 实例读取 `artifact`：



`artifact` 是一个由 MCP 结果条目组成的数组。结构化内容出现在 `type: "mcp_structured_content"` 的条目中，其 `data` 字段保存工具结果的 `structuredContent`。


### 错误



当服务器在智能体工具调用期间返回 `isError: true` 时，adapter 返回一个 `status: "error"` 的 [`ToolMessage`](https://reference.langchain.com/javascript/langchain-core/messages/ToolMessage)，并附带服务器的消息。模型可以读取该错误并重试。

adapter 会抛出传输失败。当工具在 `createAgent` 内运行时，智能体的默认错误处理也会把这些失败转换为错误工具消息。仅凭消息的 `status` 无法区分原因：

<McpToolErrorsJs />

如果你用普通参数直接调用一个适配后的工具，带有 `isError: true` 的服务器结果会改为抛出 `ToolException`，MCP 结果位于 `error.result` 中。


## 工具元数据



adapter 将 MCP 工具注解存储在 `tool.metadata.annotations` 中：

```typescript
tool.metadata;
// {
//   annotations: {
//     destructiveHint: true,
//     readOnlyHint: false,
//   },
// }
```




`annotations` 保存服务器的 MCP 工具注解，例如 `readOnlyHint` 和 `destructiveHint`。服务器可能省略它们，因此该字段可能是 `undefined`。

## Human-in-the-loop

读取注解让你可以基于服务器对工具的声明来控制工具，而不是硬编码工具名称。MCP 注解对工具进行分类，LangChain 的 human-in-the-loop 中间件执行审批策略。

在工具发现期间从 metadata 中读取一次 destructive 提示。然后为 human-in-the-loop 配置提供一个 `when` 谓词，该谓词接收每个待处理的工具调用，并返回该调用是否需要审批：



<McpDestructiveGateJs />

<Warning>
`interruptOn` 的键必须是 adapter 的工具名称，其中包含服务器前缀（`crm_delete_file`）。不带前缀的键永远不会匹配，因此工具会在未经审批的情况下运行。
</Warning>


当智能体调用被谓词控制的工具时，运行会暂停。批准该调用以执行它，或拒绝它以跳过该工具并告知模型：



```typescript
import { Command } from "@langchain/langgraph";

// Approve the pending destructive call and resume.
const resumed = await agent.invoke(
  new Command({ resume: { decisions: [{ type: "approve" }] } }),
  config
);
```


谓词还可以检查调用的参数。这让工具对安全的输入自由运行，只对有风险的输入暂停，例如针对受保护路径的 `delete_file` 调用。



通过 `request.toolCall.args` 访问参数。


结合 metadata 分类和参数检查，只在工具的类型和输入需要审批时才控制它。关于完整的审批工作流，参见 [Human-in-the-loop](/oss/javascript/langchain/human-in-the-loop)。

## 工具执行期间的服务器请求

大多数工具在调用中途不需要向客户端请求任何东西就能完成。当服务器需要输入时，[`MCPAdapter`](https://reference.langchain.com/javascript/langchain-mcp-adapters/MCPAdapter) 将 [elicitation](https://modelcontextprotocol.io/specification/draft/client/elicitation) 呈现为 LangGraph [`interrupt`](https://reference.langchain.com/javascript/langchain-langgraph/index/interrupt)。

### Elicitation

[Elicitation](https://modelcontextprotocol.io/specification/draft/client/elicitation) 让 MCP 服务器在工具调用期间请求输入。adapter 使用 LangGraph interrupt 暂停运行。你的应用程序将请求呈现给用户，并用用户的答案恢复运行。

为智能体附加一个 [checkpointer](/oss/javascript/langchain/short-term-memory)，并在调用和恢复时使用相同的 `thread_id`。

此示例假设预订工具请求一个日期并暂停一次。将示例日期替换为用户的答案。



基于 interrupt 的 elicitation 需要现代 MCP 服务器，并且默认开启。在服务器上设置 `elicitation: false` 以选择退出。对于旧式服务器，改为在 `mode: "legacy"` 下配置 `onElicitation` 处理器。没有 checkpointer 时，请求输入的工具会以错误 `ToolMessage` 失败，而不是暂停。

<McpElicitationJs />

`createMCPElicitationResume` 将答案寻址到请求它的 interrupt。响应使用服务器的请求键。请始终用 `createMCPElicitationResume` 构建每个 resume 值，而不要使用不带服务器信息的 `{ responses }` 对象，后者没有说明它回答的是哪个 interrupt。

每个 interrupt 的 `value` 是一个 `MCPElicitationInterrupt`：`type: "mcp_elicitation"`、`server`、`tool`（服务器自己的工具名称，不带前缀）、`arguments`（生效的工具参数）和 `requests`。当同一个智能体还可能引发 human-in-the-loop interrupt 时，请检查 `type`。

当多个调用同时暂停时，要回答每个 interrupt。将 `createMCPElicitationResume` 返回的对象合并为一个 `Command({ resume })`，例如 `Object.assign({}, ...paused.__interrupt__!.map((q) => createMCPElicitationResume(q, answers)))`，或者持续恢复直到 `__interrupt__` 为空。只回答第一个 interrupt 的 resume 会让其余的保持暂停。


<Note>
恢复会从头重新运行工具。在服务器请求输入之前执行的任何工作都可能重复。请确保这些工作可以安全地重复，而不会产生重复的副作用。
</Note>

每个答案使用以下操作之一：

- **`accept`**：提供与请求 schema 匹配的表单 `content`，或者在不带 `content` 的情况下确认 URL 交互已完成。
- **`decline`**：拒绝提供所请求的信息。
- **`cancel`**：表示用户取消了该交互。

adapter 将答案转发给服务器，由服务器决定工具调用如何结束。



只有 elicitation 是通过这种方式回答的。adapter 在每次调用中只宣告 elicitation 能力，因此需要 [sampling](https://modelcontextprotocol.io/specification/2025-06-18/client/sampling) 或 [roots](https://modelcontextprotocol.io/specification/2025-06-18/client/roots) 的工具会以 `ToolException` 失败，`createAgent` 会将其作为错误 `ToolMessage` 返回给模型。参见 [Sampling and roots](/oss/javascript/migrate/langchain-mcp-adapters#sampling-and-roots)。


<Note>
基于 interrupt 的 elicitation 回答的是将其请求作为 `InputRequiredResult` 返回的服务器。只在旧式握手会话上推送 elicitation 的服务器无法通过这种方式回答。
</Note>
