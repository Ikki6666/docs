Generative UI 是指智能体的输出呈现文本之外的用户界面的任何模式。智能体不再把一段话流式输出到聊天气泡里，而是驱动表单、卡片、仪表盘和交互控件。这样，你的 UI 可以像应用程序那样传达结果，同时由智能体决定展示什么以及何时展示。

Generative UI 不是单一技术。它跨越一个由一个问题定义的范围：**谁来编写界面？** 在一端，你编写每个组件，智能体只在其中选择；在另一端，界面完全在你的应用程序之外创建。沿着这个范围推进，是以可预测性换取表达空间。

## Generative UI 范围

这个范围从对每个像素的完全控制延伸到智能体的完全自主，包含三种主要方式：

从左到右，可预测性和每项能力的工程成本都在下降，而智能体的表达空间在增长。无障碍性和视觉一致性在最左端最容易保证，在最右端最难保证。

### 受控

由你编写组件，智能体选择渲染哪一个以及传入什么数据。这提供了最高的可预测性，以及对品牌和无障碍性最严格的控制，代价是要为想要暴露的每项能力编写一个组件。它是 generative UI 的主力，最适合高流量、品牌关键、布局必须精确的界面，例如机票和预订确认页。你的组件库就是边界：智能体只能渲染你发布的内容。受控 generative UI 涵盖组件作为工具、工具调用渲染、状态渲染和推理。

详情参见 [受控 generative UI](/oss/javascript/langchain/frontend/controlled-generative-ui)。

### 声明式

智能体发出一个结构化的规格，前端从你预先注册的组件目录中组合出界面。这个目录既是护栏也是边界：智能体可以自由排列和组合你的组件，但不能超出你批准的集合。长尾需求就落在这里。它以像素级精确换取覆盖面，适合次要交互、内部工具和仪表盘，在这些场景下展示有用的内容比精确控制更重要。[声明式 generative UI](/oss/javascript/langchain/frontend/declarative-generative-ui) 通过 [json-render](https://json-render.dev) 实现这一点；Google 的 A2UI 通过 CopilotKit 集成，以动态和固定 schema 两种变体提供同样的形态。

### 开放式

智能体拥有画布。界面在你的应用程序之外创建，例如由 MCP 服务器创建，并在沙盒中渲染。这提供了最宽的表达空间，可以在你这边不写任何前端代码的情况下添加新的界面能力，适合一次性的可视化和定制化回答，在这些场景下，一个令人惊喜且足够好的结果胜过可预测的结果。它也是最具实验性的方式：确定性最低，最难保证无障碍性、一致性和安全性，因此必须将 UI 隔离。沙盒和你的提示词就是边界。

详情参见 [开放式 generative UI](/oss/javascript/langchain/frontend/open-ended-generative-ui)。

## 选择一种方式

从你需要多大程度地约束界面开始：

| 如果你需要... | 选择 |
| --- | --- |
| 为一组已知的输出保证品牌、布局和无障碍性 | [受控](/oss/javascript/langchain/frontend/controlled-generative-ui) |
| 让智能体只使用已批准的组件来组合新布局 | [声明式](/oss/javascript/langchain/frontend/declarative-generative-ui) |
| 呈现第三方编写的界面，而无需自己构建 | [开放式](/oss/javascript/langchain/frontend/open-ended-generative-ui) |

为整个产品只选择一种方式是最常见的错误。真实的应用程序会混合使用各种方式，并让每个界面匹配其用途：高流量、品牌关键的核心使用受控组件，长尾的次要交互使用声明式组合，第三方能力使用开放式嵌入。一次会话可以在三种方式之间移动。

这个范围也适用于聊天之外。同样的三种方式描述了移动端以及 Slack 或电子邮件等界面上的生成式界面，而不仅限于聊天记录。
