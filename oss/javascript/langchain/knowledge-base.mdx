## 概览

本教程会帮助你熟悉 LangChain 的 [embedding](/oss/javascript/integrations/embeddings) 和 [vector store](/oss/javascript/integrations/vectorstores) 抽象。这些抽象是为了支持从（向量）数据库和其他来源检索数据而设计的，可把它们接入 LLM 工作流。它们对需要把数据检索出来再交给模型推理的应用非常重要，例如检索增强生成，也就是 [RAG](/oss/javascript/langchain/retrieval)。

这里我们会围绕一个 PDF 文档构建搜索引擎。这样就能检索出与输入查询相似的 PDF 段落。这个指南还会在搜索引擎上再实现一个最小版 RAG。

### 概念

本指南聚焦于文本数据检索。会覆盖以下概念：

- [Documents](https://reference.langchain.com/python/langchain-core/documents);
- [Text splitters](/oss/javascript/integrations/splitters);
- [Embeddings](/oss/javascript/integrations/embeddings);
- [Vector stores](/oss/javascript/integrations/vectorstores) 和 [retrievers](/oss/javascript/integrations/retrievers)。

## 1. 文档

LangChain 实现了 [Document](https://reference.langchain.com/javascript/langchain-core/documents/Document) 抽象，用来表示一段文本及其相关元数据。它有三个属性：


- `pageContent`：表示内容的字符串；
- `metadata`：包含任意元数据的 dict；
- `id`：（可选）文档的字符串标识。


`metadata` 属性可以保存文档来源、与其他文档的关系以及其他信息。注意，一条单独的 [`Document`](https://reference.langchain.com/javascript/langchain-core/documents/Document) 往往代表更大文档的一个 chunk。

当需要时，我们可以生成示例文档：


```typescript
import { Document } from "@langchain/core/documents";

const documents = [
  new Document({
    pageContent:
      "Dogs are great companions, known for their loyalty and friendliness.",
    metadata: { source: "mammal-pets-doc" },
  }),
  new Document({
    pageContent: "Cats are independent pets that often enjoy their own space.",
    metadata: { source: "mammal-pets-doc" },
  }),
];
```


## 2. Embeddings

向量搜索是一种存储和搜索非结构化数据（例如非结构化文本）的常见方式。核心思路是存储与文本相关联的数值向量。给定查询后，我们可以把它 [embed](/oss/javascript/integrations/embeddings) 成同维度向量，并用向量相似度指标（如余弦相似度）找出相关文本。

LangChain 支持来自 [数十个提供方](/oss/javascript/integrations/embeddings/) 的 embeddings。这些模型规定了文本如何转换成数值向量。我们先选一个模型：


<EmbeddingsTabsJS />

```typescript
const vector1 = await embeddings.embedQuery(documents[0].pageContent);
const vector2 = await embeddings.embedQuery(documents[1].pageContent);

assert vector1.length === vector2.length;
console.log(`Generated vectors of length ${vector1.length}\n`);
console.log(vector1.slice(0, 10));
```


```text
Generated vectors of length 1536

[-0.008586574345827103, -0.03341241180896759, -0.008936782367527485, -0.0036674530711025, 0.010564599186182022, 0.009598285891115665, -0.028587326407432556, -0.015824200585484505, 0.0030416189692914486, -0.012899317778646946]
```
有了文本 embedding 生成模型之后，我们接下来可以把它们存进一种专门支持高效相似度搜索的数据结构。

## 3. Vector stores

LangChain 的 [VectorStore](https://reference.langchain.com/javascript/langchain-core/vectorstores/VectorStore) 对象包含向存储中添加文本和 [`Document`](https://reference.langchain.com/javascript/langchain-core/documents/Document) 以及用各种相似度指标查询的接口。它们通常会和 [embedding](/oss/javascript/integrations/embeddings) 模型一起初始化，后者决定文本如何被翻译成数值向量。

LangChain 提供了一整套不同向量存储技术的 [integration](/oss/javascript/integrations/vectorstores)。有些 vector store 由提供方托管，需要特定凭据；有些运行在独立基础设施中，可以本地运行或通过第三方运行；还有一些可以以内存方式运行，适合轻量工作负载。我们先选一个 vector store：

### 为 vector store 填充数据

我们先用 PDF 内容为存储填充数据。[这里有一个样例 PDF](https://github.com/langchain-ai/langchain/blob/v0.3/docs/docs/example_data/nke-10k-2023.pdf)——Nike 2023 年的 10-K 文件。我们会用一个小 helper 直接读取 PDF，并在索引前把它拆成更小的 chunk。


```typescript
import { readFileSync } from "node:fs";
import { Document } from "@langchain/core/documents";
import { PDFParse } from "pdf-parse";

// 下面是一个用于演示的最小 helper。
async function loadPdfPages(filePath: string): Promise<Document[]> {
  const parser = new PDFParse({
    data: new Uint8Array(readFileSync(filePath)),
  });
  try {
    const { pages } = await parser.getText();
    return pages.map(
      (page) =>
        new Document({
          pageContent: page.text,
          metadata: { source: filePath, page: page.num - 1 },
        })
    );
  } finally {
    await parser.destroy();
  }
}

const filePath = "../../data/nke-10k-2023.pdf";
const docs = await loadPdfPages(filePath);
console.log(docs.length);
```


```text
107
```

页面粒度对于检索和下游问答来说可能太粗。进一步切分可以确保文档相关部分的语义不会被周围文本“冲淡”。我们使用 [`RecursiveCharacterTextSplitter`](/oss/javascript/integrations/splitters)，它会递归使用换行等常见分隔符切分文档，直到每个 chunk 变成合适大小。这是通用文本场景下推荐的 text splitter。


```typescript
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";

const textSplitter = new RecursiveCharacterTextSplitter({
  chunkSize: 1000,
  chunkOverlap: 200,
});

const allSplits = await textSplitter.splitDocuments(docs);

console.log(allSplits.length);
```


```text
516
```

现在我们可以把这些 chunk 索引进 vector store 了。


```typescript
await vectorStore.addDocuments(allSplits);
```


注意，大多数 vector store 实现都允许你连接到已有的 vector store，例如通过提供 client、index name 或其他信息。更多细节请看具体 [integration](/oss/javascript/integrations/vectorstores) 的文档。



一旦我们实例化了包含文档的 [`VectorStore`](https://reference.langchain.com/javascript/langchain-core/vectorstores/VectorStore)，就可以对它进行查询。[VectorStore](https://reference.langchain.com/javascript/langchain-core/vectorstores/VectorStore) 支持以下查询方式：
- 同步和异步；
- 字符串查询和向量查询；
- 返回或不返回相似度分数；
- 基于相似度，以及 [maximum marginal relevance](https://reference.langchain.com/javascript/classes/_langchain_core.vectorstores.VectorStore.html#maxMarginalRelevanceSearch)（在相似度和结果多样性之间取得平衡）。



这些方法的输出通常会包含一个 [Document](https://reference.langchain.com/javascript/langchain-core/documents/Document) 列表。

**使用方式**

embedding 通常会把文本表示成“密集”向量，使语义相近的文本在几何空间中彼此接近。这样我们只要传入问题，就能检索相关信息，而不需要知道文档里具体用了哪些关键术语。

根据字符串查询返回文档：


```typescript
const results1 = await vectorStore.similaritySearch(
  "When was Nike incorporated?"
);

console.log(results1[0]);
```
```javascript
Document {
    pageContent: 'direct to consumer operations sell products...',
    metadata: {'page': 4, 'source': '../example_data/nke-10k-2023.pdf', 'start_index': 3125}
}
```




返回分数：


```typescript
const results2 = await vectorStore.similaritySearchWithScore(
  "What was Nike's revenue in 2023?"
);

console.log(results2[0]);
```
```javascript
Score: 0.23699893057346344

Document {
    pageContent: 'Table of Contents...',
    metadata: {'page': 35, 'source': '../example_data/nke-10k-2023.pdf', 'start_index': 0}
}
```


根据嵌入后的查询返回文档：


```typescript
const embedding = await embeddings.embedQuery(
  "How were Nike's margins impacted in 2023?"
);

const results3 = await vectorStore.similaritySearchVectorWithScore(
  embedding,
  1
);

console.log(results3[0]);
```
```javascript
Document {
    pageContent: 'FISCAL 2023 COMPARED TO FISCAL 2022...',
    metadata: {
        'page': 36,
        'source': '../example_data/nke-10k-2023.pdf',
        'start_index': 0
    }
}
```

## 4. Retrievers

LangChain [`VectorStore`](https://reference.langchain.com/javascript/langchain-core/vectorstores/VectorStore) 对象并不继承 [Runnable](https://reference.langchain.com/javascript/langchain-core/runnables/Runnable)。LangChain [Retrievers](https://reference.langchain.com/javascript/interfaces/_langchain_core.retrievers.BaseRetriever.html) 则是 Runnables，因此它们实现了一套标准方法，例如同步和异步的 `invoke` 与 `batch` 操作。虽然我们可以从 vector store 构建 retriever，但 retriever 也可以连接到非 vector store 的数据源，例如外部 API。


```typescript
const retriever = vectorStore.asRetriever({
  searchType: "mmr",
  searchKwargs: {
    fetchK: 1,
  },
});

await retriever.batch([
  "When was Nike incorporated?",
  "What was Nike's revenue in 2023?",
]);
```
```javascript
[
    [Document {
        metadata: {'page': 4, 'source': '../example_data/nke-10k-2023.pdf', 'start_index': 3125},
        pageContent: 'direct to consumer operations sell products...',
    }],
    [Document {
        metadata: {'page': 3, 'source': '../example_data/nke-10k-2023.pdf', 'start_index': 0},
        pageContent: 'Table of Contents...',
    }],
]
```


retriever 也可以很容易地用于更复杂的应用，比如 [retrieval-augmented generation (RAG)](/oss/javascript/langchain/retrieval) 应用，它会把一个问题与检索到的上下文一起放进提示词里再交给 LLM。想了解如何构建这样的应用，请看 [RAG 教程](/oss/javascript/deepagents/rag)。
