解释器会在 agent 循环内部为 agent 提供一个可编程的、**内存中的**工作区。agent 会写代码来完成任务，runtime 执行这段代码，并只把相关结果返回回来。中间结果不会进入模型上下文。

如果说 [sandbox](/oss/javascript/deepagents/sandboxes) 是一种面向环境执行动作的代码优先方式，比如运行命令、安装依赖和编辑文件，那么解释器就是一种面向组合工具、保留状态，以及决定哪些信息返回给模型的代码优先方式。

<Warning>
    解释器处于 [**beta**](/oss/javascript/versioning) 阶段。API 和生命周期行为可能会在不同版本之间变化。
</Warning>



<Note>
    解释器需要 `@langchain/quickjs`。
</Note>


## 为什么要用解释器？

大多数 agent 工作都在模型推理和工具调用之间来回切换。模型一次可以发出多个工具调用，但这一批调用在发出时就固定了。若没有新的 model turn，代码就无法循环、基于结果分支、重试失败，或者把一个调用的输出喂给下一个调用；而且每个结果都会回到模型上下文。模型还要决定要发多少次调用，所以让它一次分发几百项工作并不可靠，它往往只会覆盖样本，而不是逐项覆盖。

解释器把这些编排逻辑移到代码里，这样模型只需要思考“要做什么”，而不是每一个中间步骤。

## 选择一种模式

在 agent 循环内部需要代码时，用解释器：组合工具、保留状态，以及控制哪些内容返回给模型。

在需要对环境运行代码时，用 [sandbox](/oss/javascript/deepagents/sandboxes)：shell 命令、包安装、测试、文件系统编辑，以及操作系统级执行。

| 需求 | 选择 |
| --- | --- |
| 一两个简单的外部调用 | 普通 tool calling |
| 纯内存 JavaScript：循环、分支、重试或数据转换（不需要外部工具） | 解释器 |
| 需要从代码里编排大量外部工具调用（需要 [PTC](#programmatic-tool-calling-ptc)） | 带 [程序化工具调用（PTC）](#programmatic-tool-calling-ptc) 的解释器 |
| 多个独立工作单元、多个视角，或对大输入做递归分析 | 带 [动态 subagent](/oss/javascript/deepagents/dynamic-subagents) 的解释器 |
| shell 命令、包安装、测试，或完整的操作系统文件系统访问 | [Sandbox](/oss/javascript/deepagents/sandboxes) |

## 解释器如何工作

middleware 会给 agent 添加一个 `eval` 工具。需要时，agent 会编写 JavaScript 并调用 `eval`；你不会直接调用 interpreter。这个工具会在 QuickJS context 中运行代码，变量是否能跨 `eval` 调用保留，取决于 persistence `mode`。它会捕获 `console.log`、`console.warn` 和 `console.error`，并返回最后一个表达式的结果。

代码运行在 [**QuickJS**](https://github.com/quickjs-ng/quickjs) 上，这是一个轻量级 JavaScript runtime。默认情况下，解释器代码不能访问主机文件系统、网络、shell、包管理器或时钟。它可以计算、保存状态，并写入 `console.log`、`console.warn` 或 `console.error`，除此之外什么也不能做。

有两个显式桥接会扩展它的能力：

- **工具**，通过 [程序化工具调用（PTC）](#programmatic-tool-calling-ptc)。你可以把要允许的工具作为 async 函数放到 `tools` namespace 里。这些工具可以是 agent 自己的工具，也可以是你单独定义后传入的工具。
- **Subagent**，通过 [动态 subagent](/oss/javascript/deepagents/dynamic-subagents)。当 agent 配置了 subagent 时，解释器会暴露 `task()` global，用来从代码中派发它们。

程序化工具调用默认关闭，直到你[启用它](#enable-ptc)。只要 agent 有 subagent，`task()` 的 subagent 派发默认就会开启；你也可以把它关掉。除此之外，没有任何东西会跨越 QuickJS 边界。

## 程序化工具调用（PTC）

程序化工具调用（PTC）会把选定的 agent 工具暴露到解释器的 `tools` namespace 中。与其让模型发出一次 tool call、等待结果、再决定下一次调用，不如让 agent 用代码来调用工具，实现循环、分支、重试或并行批次。

当中间结果只是下一步的输入时，这种方式尤其有用：解释器可以先过滤或聚合结果，再把任何内容返回给模型，从而让多步骤工作流更节省 token。它与 provider 无关，是通过 middleware 实现的，而不是某个 provider-specific tool-calling API。

middleware 会把每个允许调用的工具暴露成 `tools` 下的 async 函数。agent 用 `await` 调用它，在代码里处理结果，而模型只会看到最终的解释器输出，不会看到每个中间值。工具名会转换成 camelCase，但输入对象仍然遵循工具 schema，所以名为 `web_search` 的工具会变成 `tools.webSearch(...)`：

## 动态 subagent

下面这段概述说明什么时候该用动态 subagent，以及一个最小 `task()` 模式。有关配置、编排示例、工作流触发器和安全注意事项，请参见 [动态 subagent](/oss/javascript/deepagents/dynamic-subagents)。

动态 subagent 允许 interpreter 使用内置的 `task()` global，从代码中派发已配置的 [subagent](/oss/javascript/deepagents/subagents)。像检查目录中的每个文件、或者分拣一批工单这样跨越许多独立单元的任务，会变成一个 fan-out 工作并综合结果的循环。

动态 subagent 适用于：

- **Fan-out 并综合**：把同一类工作并行分发到很多条目上，再把结果合并起来。
- **验证**：把 findings 交给独立 verifier subagent，只保留经过确认的结果。
- **递归工作流**：把工作集保存在 interpreter 变量里，选择切片，调用 subagent，再逐步细化结果。

## 安全性

解释器使用 QuickJS 以严格的默认隔离来运行不受信任的 JavaScript。要把它当作一个有作用域限制的 interpreter runtime，而不是完整的生产 sandbox backend。

你通过 PTC 暴露的每个工具，都是 interpreter code 可以使用的外部能力。请把 PTC allowlist 当成权限边界：只暴露 agent 需要的工具，避免桥接那些能够访问敏感系统、花钱、修改数据或调用不受限制网络的宽泛工具，除非这是你有意为之。


| 能力 | 默认可用 | 暴露方式 |
| --- | --- | --- |
| JavaScript 执行 | 是 | 添加 interpreter middleware |
| 顶层 `await` | 是 | 在 interpreter 代码中使用 promises |
| `console.log`、`warn`、`error` 捕获 | 是 | 设为 `captureConsole: false` 关闭 |
| Agent 工具 | 否 | 添加 PTC allowlist |
| 文件系统访问 | 否 | 通过 PTC allowlist 添加 [内置文件系统工具](/oss/javascript/deepagents/overview#virtual-filesystem-access) |
| 网络访问 | 否 | 通过 PTC 暴露某个特定网络工具 |
| 实时时钟或日期时间访问 | 否 | 如果需要，暴露一个显式的时间工具 |
| shell 命令、包安装、测试、操作系统级执行 | 否 | 使用 [sandbox backend](/oss/javascript/deepagents/sandboxes) |
