围绕你的目标来构建 harness。`create_deep_agent` 给你一个生产就绪的基础：把它连接到数据，塑造它的行为，并添加你的使用场景所需的能力。



`createDeepAgent` 自带预组装的 harness：默认包含文件系统、摘要、子 agent 和 prompt caching。下面这些参数让你可以定义 agent 的 persona，把它连接到数据和工具，并用额外 middleware 扩展 [Deep Agents 栈](#deep-agents-stack)。

<CustomizationOverviewJs />

| 参数 | 作用 |
|---|---|
| `model` | 使用哪个模型 |
| `systemPrompt` | 给 agent 的自定义指令 |
| `tools` | agent 可以调用的领域工具 |
| `memory` | 启动时加载的 AGENTS.md 文件 |
| `skills` | 提供按需知识的 skills 目录 |
| `backend` | 文件系统 backend（默认是 StateBackend） |
| `permissions` | 文件系统的路径级访问控制 |
| `subagents` | 用于委派任务的自定义子 agent |
| `middleware` | 追加到 [Deep Agents 栈](#deep-agents-stack)的额外 middleware |
| `interruptOn` | 在工具调用前暂停，等待人工批准 |
| `responseFormat` | 结构化输出 schema |
| [`contextSchema`](/oss/javascript/deepagents/context-engineering#runtime-context) | 每次运行的 runtime context schema（用户 ID、API key、feature flag） |

有关完整参数列表，请参见 [`createDeepAgent`](https://reference.langchain.com/javascript/deepagents/types/CreateDeepAgentParams) API reference。若要从零开始拼装一个完全自定义的 harness，请参见 [Configure the harness](/oss/javascript/langchain/agents#configure-the-harness)。


<Tip>
随着你增加工具、子 agent 和 backend，请使用 [LangSmith](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=oss-deepagents-customization) 跟踪这些组件如何一起工作。按照 [observability quickstart](/langsmith/observability-quickstart) 完成设置，并在准备好进入生产环境时查看 [Going to production](/oss/javascript/deepagents/going-to-production) 了解 LangSmith 部署选项。

我们也建议你设置 [LangSmith Engine](/langsmith/engine)，它可以监控你的 traces、检测问题并给出修复建议。
</Tip>

<CustomizationSystemPromptJs />


当 middleware 添加特殊工具时，例如文件系统工具，它会在运行时把自己的引导追加到 system prompt 中。



<AccordionGroup>
    <Accordion title="子 agent prompts">
        声明式 [subagents](/oss/javascript/deepagents/subagents) 会针对自己的模型解析 profile 覆盖，然后把解析得到的 `base_system_prompt` / `system_prompt_suffix` 应用到子 agent 作者编写的 `system_prompt` 上。只带 `system_prompt_suffix` 的 profile（内置 Anthropic / OpenAI profile 的常见情况）只是追加到作者写的 prompt 后面。设置了 `base_system_prompt` 的 profile 会直接替换它。
    </Accordion>
    <Accordion title="通用子 agent prompt">
        自动添加的[通用子 agent](/oss/javascript/deepagents/subagents#the-general-purpose-subagent) 会把它的 base prompt 解析为 **`general_purpose_subagent.system_prompt`（如果设置了）-> `HarnessProfile.base_system_prompt`（如果设置了）-> SDK 通用默认值**，并把 profile suffix 叠加在上面。当两个覆盖字段都设置时，通用子 agent 专属的那个会获胜，这样同时调这两个字段的调用方就不会发现自己的 GP 覆盖被悄悄丢掉：

        | Stack | 最终 system prompt |
        | ----- | ------------------- |
        | Main agent | `"You are ACME's support orchestrator." + SUFFIX` |
        | GP subagent | `"You are a research subagent. Cite sources." + SUFFIX` |
    </Accordion>
</AccordionGroup>

## Middleware

Deep Agents 支持任意 [middleware](/oss/javascript/langchain/middleware/overview)，包括下方列出的内置 middleware、LangChain 的 prebuilt middleware、provider-specific middleware，以及你自己编写的自定义 middleware。



把 middleware 传给 `createDeepAgent` 的 `middleware` 参数。自定义 middleware 会追加在 [PatchToolCallsMiddleware](https://reference.langchain.com/javascript/deepagents/middleware/createPatchToolCallsMiddleware) 之后、[Deep Agents 栈](#deep-agents-stack) 中的尾部堆栈之前。


### Deep Agents 栈



`createDeepAgent` 会以固定顺序构建 middleware。[bare stack](#bare-stack) 是你只传入 model 时得到的内容。[full stack](#full-stack) 是完整的组装顺序，包括仅在你传入可选参数时才会出现的槽位，以及解析后的 [harness profile](/oss/javascript/deepagents/profiles) 贡献的槽位。


#### Bare stack



在只传入 `model`（不传其他可选参数）时，主 agent 通常包含：

1. [`FilesystemMiddleware`](https://reference.langchain.com/javascript/deepagents/middleware/createFilesystemMiddleware)
2. [`SubAgentMiddleware`](https://reference.langchain.com/javascript/deepagents/middleware/createSubAgentMiddleware)（因为[通用子 agent](/oss/javascript/deepagents/subagents#default-subagent) 默认会被自动添加，除非 harness profile 禁用了它）
3. [`SummarizationMiddleware`](https://reference.langchain.com/javascript/langchain/index/summarizationMiddleware)
4. [`PatchToolCallsMiddleware`](https://reference.langchain.com/javascript/deepagents/middleware/createPatchToolCallsMiddleware)
5. **Prompt caching** middleware（为支持的 provider 添加；其他情况 no-op）
6. **Harness profile 额外项**和**排除工具过滤**，如果解析后的模型 profile 定义了它们


#### Full stack

从前到后：



1. [TodoListMiddleware](https://reference.langchain.com/javascript/langchain/index/todoListMiddleware)：跟踪并管理 todo 列表，用于组织 agent 任务和工作。
2. [SkillsMiddleware](https://reference.langchain.com/javascript/deepagents/middleware/createSkillsMiddleware)：仅在你传入 `skills` 时启用。它会**紧跟**在 todo middleware 之后、**文件系统 middleware 之前**注入，这样在文件工具运行前就能使用 skill 元数据。
3. [FilesystemMiddleware](https://reference.langchain.com/javascript/deepagents/middleware/createFilesystemMiddleware)：处理读写和目录导航等文件系统操作。当你传入 `permissions` 时，文件系统权限 enforcement 也会包含在这里，这样它就能评估 agent 可能调用的每个工具。
4. [SubAgentMiddleware](https://reference.langchain.com/javascript/deepagents/middleware/createSubAgentMiddleware)：仅当至少存在一个同步子 agent 时启用。派生并协调子 agent，用于委派任务。它被包含在 [bare stack](#bare-stack) 中，因为通用子 agent 默认会被自动添加；要省略它，请禁用该子 agent 并且不传入同步 `subagents`。参见[在没有子 agent 的情况下运行](/oss/javascript/deepagents/subagents#running-without-subagents)。
5. [SummarizationMiddleware](https://reference.langchain.com/javascript/langchain/index/summarizationMiddleware)：当对话变长时压缩消息历史，以保持在上下文限制内（通过 [createSummarizationMiddleware](https://reference.langchain.com/javascript/deepagents/middleware/createSummarizationMiddleware)）。
6. [PatchToolCallsMiddleware](https://reference.langchain.com/javascript/deepagents/middleware/createPatchToolCallsMiddleware)：当运行在中断后恢复，或者收到格式不正确的 tool-call 参数时，修复消息历史中悬空的工具调用。它会在 Anthropic prompt caching 和下面的尾部堆栈之前运行。
7. [AsyncSubAgentMiddleware](https://reference.langchain.com/javascript/deepagents/agent/createDeepAgent)：仅在你配置 async subagent 时启用。
8. **你的 middleware 参数**：你通过 `middleware` 参数传入的可选 middleware 会追加在这里（在 Patch 之后、尾部堆栈之前）。
9. **Harness profile 额外项**：来自解析后模型 profile 的 provider-specific middleware（如果有）。
10. **排除工具过滤**：当 harness profile 列出 excluded tools 时，middleware 会把这些工具从 agent 中移除。
11. **Prompt caching**（[AnthropicPromptCachingMiddleware](https://reference.langchain.com/javascript/langchain/index/anthropicPromptCachingMiddleware) 和 [BedrockPromptCachingMiddleware](https://reference.langchain.com/javascript/langchain/index/bedrockPromptCachingMiddleware)）：会自动为 Anthropic 模型和 Amazon Bedrock Converse 模型添加。两者都在 Patch 和你的 middleware 之后运行，这样缓存前缀就与实际发送给模型的内容一致。
12. [MemoryMiddleware](https://reference.langchain.com/javascript/deepagents/middleware/createMemoryMiddleware)：仅在你传入 `memory` 时启用。

    <Note>
    `MemoryMiddleware` 被放在 profile 额外项和 prompt caching middleware 之后，这样注入的 memory 更新就更不容易让缓存前缀失效。`createDeepAgent` 的实现注释里也说明了同样的顺序考量。
    </Note>

13. `HumanInTheLoopMiddleware`：仅在你传入 `interruptOn` 时启用。在配置好的工具调用处暂停，等待人工批准或输入。



### 同步子 agent 堆栈



内置的**通用**子 agent 和每个声明式同步 `SubAgent` graph 都使用 `createDeepAgent` 在代码中构建的堆栈。它与主 agent 在大方向上保持一致（todo list、文件系统、摘要、Patch、profile 额外项、Anthropic 和 Bedrock 缓存、可选权限），但有两个不同点：

- 在这些内部 agent 上，**Skills 运行在** [PatchToolCallsMiddleware](https://reference.langchain.com/javascript/deepagents/middleware/createPatchToolCallsMiddleware) **之后**（而在主 agent 上，当设置了 `skills` 时，skills 会在文件系统 middleware 之前运行）。
- 子 agent graph 内部**没有** [SubAgentMiddleware](https://reference.langchain.com/javascript/deepagents/middleware/createSubAgentMiddleware)（只有父 agent 暴露 `task` 工具）。

当声明式子 agent 设置 `interruptOn` 时，该值会传给子 agent 的 `createAgent`，从而为配置好的工具调用接入 human-in-the-loop 处理。

## Backends

deep agent 的工具可以使用 virtual file system 来存储、访问和编辑文件。默认情况下，deep agents 使用 [StateBackend](https://reference.langchain.com/javascript/deepagents/backends/StateBackend)。

如果你使用 [skills](#skills) 或 [memory](#memory)，在创建 agent 之前必须先把预期的 skill 或 memory 文件添加到 backend。

<Tabs>
    <Tab title="StateBackend">
        一个存储在 `langgraph` state 中、线程范围的文件系统 backend。

        文件会通过你的 checkpointer 在同一 thread 的多轮之间持久化，但不会在不同 thread 之间共享。



        <BackendStateJs />

    </Tab>
    <Tab title="FilesystemBackend">
        本地机器的文件系统。

        <Warning>
            这个 backend 会让 agent 直接读写文件系统。
            请谨慎使用，只在合适的环境中使用。
            有关更多信息，请参见 [`FilesystemBackend`](/oss/javascript/deepagents/backends#filesystembackend-local-disk)。
        </Warning>



        <BackendFilesystemJs />


        <Tip>
            将 `FilesystemBackend` 包装在 `CompositeBackend` 中，可以防止内部 agent 数据（卸载的工具结果、对话历史）和项目文件一起写到磁盘。请参见[推荐模式](/oss/javascript/deepagents/backends#filesystembackend-local-disk)。
        </Tip>
    </Tab>
    <Tab title="LocalShellBackend">
        一个带有直接在主机上执行 shell 的文件系统。提供文件系统工具，以及用于运行命令的 `execute` 工具。

        <Warning>
            这个 backend 会让 agent 直接读写文件系统，**并且**在你的主机上拥有不受限制的 shell 执行能力。
            请极其谨慎地使用，只在合适的环境中使用。
            有关更多信息，请参见 [`LocalShellBackend`](/oss/javascript/deepagents/backends#localshellbackend-local-shell)。
        </Warning>



        <BackendLocalShellJs />

    </Tab>
    <Tab title="StoreBackend">
        一个提供长期存储的文件系统，会_跨 thread 持久化_。



        <BackendStoreJs />


        <Note>

        <Tip>

        </Tip>
    </Tab>
    <Tab title="ContextHubBackend">
        在 LangSmith Hub repo 中提供持久化文件系统存储。



        有关更多细节，请参见 [`ContextHubBackend`](/oss/javascript/deepagents/backends#contexthubbackend)。
    </Tab>
    <Tab title="CompositeBackend">
        一个灵活的 backend，你可以在文件系统中指定不同 route，把它们指向不同 backend。



        <BackendCompositeJs />

    </Tab>
</Tabs>

## Skills

你可以使用 [skills](/oss/javascript/deepagents/overview) 为 deep agent 提供新的能力和专长。
虽然 [tools](/oss/javascript/deepagents/customization#tools) 往往覆盖的是更底层的功能，例如原生文件系统操作或规划，但 skills 可以包含如何完成任务的详细说明、参考信息，以及模板等其他资产。
这些文件只有在 agent 判断某个 skill 对当前 prompt 有用时才会加载。
这种渐进式披露减少了 agent 启动时需要考虑的 token 和上下文量。

有关示例 skills，请参见 [Deep Agents example skills](https://github.com/langchain-ai/deepagentsjs/tree/main/examples/skills)。

## 结构化输出

Deep Agents 支持[结构化输出](/oss/javascript/langchain/structured-output)。

你可以通过在调用 `createDeepAgent()` 时传入 `responseFormat` 参数，来设置期望的结构化输出 schema。
当模型生成结构化数据时，它会被捕获、验证，并返回到 agent state 的 `structuredResponse` 键中。
