通过声明式权限规则控制 agent 可以读取或写入哪些文件和目录。把规则列表传给 `permissions=`，agent 内置的文件系统工具就会遵守这些规则。



<Note>
    权限需要 `deepagents>=1.9.1`。
</Note>




权限只适用于内置文件系统工具（`ls`、`read_file`、`glob`、`grep`、`write_file`、`edit_file`）。自定义工具和访问文件系统的 MCP 工具不受此限制。权限也不适用于 [sandbox backend](/oss/javascript/deepagents/sandboxes)，因为它们可以通过 `execute` 工具执行任意命令。


<Tip>
在你需要对内置文件系统工具做**基于路径的允许/拒绝规则**时，使用 `permissions`。在你需要自定义校验逻辑（速率限制、审计日志、内容检查）或者需要控制自定义工具时，使用 [backend policy hooks](/oss/javascript/deepagents/backends#add-policy-hooks)。
</Tip>

## 基本用法



把 `FilesystemPermission` 规则列表传给 `createDeepAgent`。规则按声明顺序求值，第一个匹配的规则生效。如果没有任何规则匹配，操作就会被允许。

## 规则结构



每个 `FilesystemPermission` 都有三个字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `operations` | `("read" \| "write")[]` | 规则适用的操作。`"read"` 覆盖 `ls`、`read_file`、`glob`、`grep`。`"write"` 覆盖 `write_file`、`edit_file`。 |
| `paths` | `string[]` | 用于匹配文件路径的 glob 模式，例如 `["/workspace/**"]`。支持 `**` 递归匹配，以及 `{a,b}` 形式的分支匹配。 |
| `mode` | `"allow" \| "deny"` | 对匹配的操作是允许还是拒绝。默认值是 `"allow"`。 |

规则使用 first-match-wins 评估：第一个 `operations` 和 `paths` 都匹配当前调用的规则会决定结果。如果没有规则匹配，该调用会被**允许**（宽松默认值）。

路径必须是绝对路径（以 `/` 开头），并且不能包含 `..` 或 `~`。无效路径会在 agent 构建时抛出错误。

## 子 agent 权限



[子 agent](/oss/javascript/deepagents/subagents) 默认继承父 agent 的权限。若要给子 agent 不同的权限，请在它的 spec 中设置 `permissions` 字段。这会**完全替换**父级规则。

<PermissionsSubagentJs />

若要显式授予子 agent 不受限制的访问权限，请设置 `permissions: []`。空数组会用无约束权限覆盖父级规则。省略 `permissions` 则表示从父级继承。



## 复合 backend



当使用带有 sandbox 默认值的 `CompositeBackend` 时，每个权限路径都必须限定在一个已知的 route 前缀下。sandbox 支持任意命令执行，所以仅靠基于路径的限制无法阻止通过 shell 命令访问文件系统。把权限限定到 route 专属的 [backend](/oss/javascript/deepagents/backends) 上，可以避免这个冲突。
