**Harness 配置档案** 允许你为特定模型或 provider 自定义 Deep Agents harness。你可以调整 system prompt 和工具描述、排除工具或 middleware、添加 middleware，以及配置通用子 agent。每当你选择匹配的模型时，Deep Agents 都会应用这些设置，无需更改你的 agent 创建代码。



<Note>
  Provider 配置档案（用于控制创建模型所用的设置）和插件注册系统都是仅限 Python 的功能。TypeScript SDK 只支持 harness 配置档案。
</Note>


## Harness 配置档案

Deep Agents 提供了 **内置 harness 配置档案**，包含针对特定 provider 和模型的默认设置。



使用 `HarnessProfileOptions` 定义 `createDeepAgent` 在构建 chat model 之后会应用的设置：

<ProfilesHarnessRegisterJs />




<ResponseField name="baseSystemPrompt" type="string">
    设置该配置档案的基础指令。对于主 agent，这些指令会跟在调用方的 system 指令之后；默认不添加基础指令。对于声明式子 agent，这会替换它们自己编写的 system prompt。
</ResponseField>

<ResponseField name="systemPromptSuffix" type="string">
    在调用方指令和配置档案的基础指令之后追加文本。该设置会同时应用于主 agent、声明式子 agent 和自动添加的通用子 agent。
</ResponseField>

<ResponseField name="toolDescriptionOverrides" type="Record<string, string>">
    按工具名覆盖单个工具描述。
</ResponseField>

<ResponseField name="excludedTools" type="string[]">
    从工具集中移除特定的 harness 级工具。按工具名匹配，作为注入后的过滤器，因此可以移除用户提供的工具，也可以移除 middleware 添加的工具。
</ResponseField>

<ResponseField name="excludedMiddleware" type="string[]">
    从组装后的堆栈中剔除特定 middleware。按每个 middleware 的 `.name` 属性匹配。不能包含必需的脚手架名称（`FilesystemMiddleware`、`SubAgentMiddleware`）。
</ResponseField>

<ResponseField name="extraMiddleware" type="AgentMiddleware[] | (() => AgentMiddleware[])">
    追加到堆栈末尾的额外 middleware。可以是静态数组，也可以是一个零参数工厂，用来在每次构建 agent 时返回新的实例。
</ResponseField>

<ResponseField name="generalPurposeSubagent" type="GeneralPurposeSubagentConfig">
    禁用、重命名，或重新提示通用子 agent（`enabled`、`description`、`systemPrompt`）。
</ResponseField>




<Note>
    调用方提供的 `systemPrompt` 永远位于组装后 prompt 的最前面，而 `systemPromptSuffix` 永远位于最后面，不受所选模型影响。同样的覆盖规则也适用于子 agent：每个子 agent 都会基于自己的模型重新执行 profile 解析。有关自定义指令和子 agent prompt 行为，请参见 [System prompt](/oss/javascript/deepagents/customization#system-prompt)。
</Note>




<Warning>
    在 `excludedMiddleware` 中列出 `FilesystemMiddleware` 或 `SubAgentMiddleware` 会在构建时抛错，因为它们是必需脚手架。若只是想让模型看不到这些工具而不是移除 middleware，请改用 `excludedTools`。
</Warning>


在创建 agent 之前注册配置档案。传入模型字符串或你自己构建的模型对象；示例参见 [配置模型参数](/oss/javascript/deepagents/models#configure-model-parameters)。harness 配置档案在两种情况下都会生效。



<Accordion
    title="预配置模型实例的查找顺序"
>
    当你传入模型对象时，harness 会使用该对象报告的 provider 和 identifier 来查找它的配置档案。



    1. 如果 identifier 不含冒号，查找 `provider:identifier`，回退到该 provider 的默认值。
    2. 如果 identifier 含冒号，直接查找，回退到其前缀的默认值。
    3. 如果两次查找都不匹配，使用所报告 provider 的默认值。

</Accordion>


## 注册键

配置档案注册使用以下键：

- **provider 级**：仅 provider 名称，例如 `"openai"`，会应用到该 provider 的所有模型。
- **model 级**：完整的 `provider:model` 键，例如 `"openai:gpt-6-astra"`，只应用到该特定模型。

当 provider 级和 model 级 profile 同时存在时，它们会在解析时合并。未设置的 model 级字段会继承 provider 级 profile；显式设置的 model 级值会覆盖 provider 级值。



TypeScript 中的 profile 注册不支持包含冒号的模型 identifier。请使用 `my_provider:my-model` 这样的键，用一个冒号分隔 provider 和模型 identifier。


例如，为某个假设 provider 的模型排除一个工具，然后为一个模型自定义 prompt 后缀：

使用 model 级注册的 agent 会排除 `execute`，并收到 100 词的后缀。`my_provider` 的其他模型会排除 `execute`，并收到 500 词的后缀。

在已有键上重新注册时，新 profile 会叠加到之前的 profile 上，而不是替换它。这也让你可以通过在内置 profile 的键下注册来自定义它。有关逐字段规则，请参见[合并语义](#merge-semantics)。

<Note>
    没有能匹配所有 provider 的通配键。若要在所有地方都应用同样的覆盖，例如无论选择哪个模型都移除 `TodoListMiddleware`，请在你使用的每个 provider 键下都注册该 profile。profile 的设计目标是对所选模型相关的调整。应在 `createDeepAgent` 调用位置完成那些与模型无关、应该无条件生效的全局调整。
</Note>


## 合并语义



| 字段 | 合并行为 |
| --- | --- |
| `baseSystemPrompt`, `systemPromptSuffix` | 若设置了新值，则新值生效；否则继承 |
| `toolDescriptionOverrides` | 映射按键合并；共享键上新值生效 |
| `excludedTools`, `excludedMiddleware` | 集合并集 |
| `extraMiddleware` | 按名称合并：新实例替换其位置上的旧实例，新的条目追加到末尾 |
| `generalPurposeSubagent` | 按字段合并（未设置字段继承） |

## 将 profile 作为插件发布



通过包 entry point 进行插件注册是 Python-only 功能。在 TypeScript 中，请在应用启动时或包初始化代码中直接调用 `registerHarnessProfile`。
