**Functional API** 用 LangGraph 的运行时能力（[持久化](/oss/javascript/langgraph/persistence)、[记忆](/oss/javascript/langgraph/add-memory)、[human-in-the-loop](/oss/javascript/langgraph/interrupts) 和 [streaming](/oss/javascript/langgraph/streaming)）封装普通函数。如果你已有现成代码，或正在使用其他框架，并希望在不把该智能体改写为图的前提下[将其部署到 LangSmith](/langsmith/deploy-other-frameworks)，请使用它。构建新智能体时优先使用 [Graph API](/oss/javascript/langgraph/graph-api)。

本页是 entrypoint、task、checkpointing 和恢复规则的概念参考。封装并部署的操作步骤请参阅[部署其他框架](/langsmith/deploy-other-frameworks)。

Functional API 使用两个构件：



* **`entrypoint`**：封装工作流逻辑，并管理执行、interrupt 和 checkpointing。
* **`task`**：标记一个离散的工作单元（例如一次 API 调用）。Task 返回一个 `Promise`，你在 entrypoint 内 await 它。


## 何时使用 Functional API

| 构建方式 | 使用 |
| --- | --- |
| 新建 LangGraph 智能体和工作流 | [Graph API](/oss/javascript/langgraph/graph-api) |
| 其他框架中已有的智能体（Claude Agent SDK、Strands、CrewAI、AutoGen 等），希望运行在 LangSmith Agent Server 上 | 通过[部署其他框架](/langsmith/deploy-other-frameworks)使用 Functional API |

与 Graph API 相比，Functional API 使用普通的语言控制流（`if` / `else`、循环和调用），把值限制在 entrypoint 和 task 的作用域内，而不是使用共享的 [state](/oss/javascript/langgraph/graph-api#state) schema；它把 task 结果保存到 entrypoint 的 checkpoint，而不是在每个 [super-step](/oss/javascript/langgraph/graph-api#super-steps) 后保存；它也不提供静态的图可视化。

## Entrypoint



`entrypoint` 函数从函数创建工作流。它负责管理长时间运行的工作和 [interrupt](/oss/javascript/langgraph/interrupts)。


### Definition

需要持久化或 human-in-the-loop 时，请传入 [checkpointer](/oss/javascript/langgraph/persistence)。在配置中用 `thread_id` 标识每次运行。thread 是一次对话或一次工作流运行的持久标识。



**entrypoint** 通过把配置和一个函数传给 `entrypoint` 来创建。

该函数**必须接受一个位置参数**，作为工作流输入。要传递多个值，请用对象作为这个参数。

结果是一个工作流对象。调用 `invoke` 来运行它。

<Warning>
**Serialization**
配置 checkpointer 时，entrypoint 的**输入**和**输出**必须是 JSON 可序列化的。请参阅 [Serialization](#serialization)。
</Warning>

### 运行与恢复



要获得最终结果，请调用 `invoke`。流式用法请参阅[流式输出](/oss/javascript/langgraph/streaming)。


在 [`interrupt`](https://reference.langchain.com/javascript/langchain-langgraph/index/interrupt) 之后，把 resume 值传入 [`Command`](https://reference.langchain.com/javascript/langchain-langgraph/index/Command) 即可恢复。具体做法请参阅 [Interrupts（中断）](/oss/javascript/langgraph/interrupts)。



出错后，用 `null` 恢复同一个 `thread_id`。


### 短期记忆

当 `entrypoint` 配置了 `checkpointer` 时，同一个 **thread id** 上的连续调用会把状态存入 [checkpoint](/oss/javascript/langgraph/checkpointers#checkpoints)。



在 entrypoint 内调用 `getPreviousState`。它返回该 thread 上最后保存的值。首次运行时它是 `undefined`。要为下一次运行保存不同的值，请使用 [`entrypoint.final`](https://reference.langchain.com/javascript/langchain-langgraph/index/entrypoint/final)。


### Injectable parameters

在添加[记忆](/oss/javascript/langgraph/add-memory)或[自定义流式输出](/oss/javascript/langgraph/streaming)之前，可以先跳过这一节。



`entrypoint` 函数可以接受第二个 `config` 参数。LangGraph 还提供了一些在函数内部调用的辅助函数：

| 辅助函数 | 说明 |
| -------- | ---- |
| **getPreviousState** | 同一 thread 上一次调用的返回值（需要配置 checkpointer）。请参阅[短期记忆](#short-term-memory)。 |
| **config** | 包含运行时配置值的 `LangGraphRunnableConfig` 对象。 |
| **config.store** | 用于[长期记忆](/oss/javascript/langgraph/add-memory)的 store 实例。 |
| **config.writer** | 用于自定义流式输出的 writer。请参阅[流式输出](/oss/javascript/langgraph/streaming)。 |

## Task

**task** 是一个离散的工作单元（例如一次 API 调用或一个数据处理步骤）。Task 有两个关键特性：

* **Concurrent execution**：调用 task 会立即启动它。只有在你等待结果时 entrypoint 才会阻塞，因此相互独立的 task 可以重叠执行。
* **Checkpointing**：task 结果会被保存，恢复时可从 checkpoint 还原。请参阅 [持久化](/oss/javascript/langgraph/persistence)。

### Definition



用 `task` 函数定义 task：

```typescript
import { task } from "@langchain/langgraph";

const slowComputation = task("slowComputation", async (inputValue: number) => {
  // Long-running or side-effecting work
  return inputValue * 2;
});
```


<Warning>
**Serialization**：task 的**输出**必须是 JSON 可序列化的，以支持 checkpointing。
</Warning>

### Execution

只能在 **entrypoint**、另一个 **task** 或 [Graph API 节点](/oss/javascript/langgraph/graph-api#nodes)中调用 **task**。不要在 workflow 之外的应用代码中调用它们。



调用 task 会返回一个 `Promise`。在 entrypoint 内 await 它：

### 何时使用 task

以下场景适合使用 **task**：

* **Checkpointing**：保存长时间运行的结果，恢复时无需重新计算。
* **Human-in-the-loop**：把暂停后不应重做的工作放进 task，例如 LLM 调用。[interrupt](/oss/javascript/langgraph/interrupts) 后恢复时会还原该结果。关于随机性，请参阅 [Determinism](#determinism)。
* **Parallel execution**：并发运行相互独立的 I/O 密集型工作。
* **Observability**：在 [LangSmith](/langsmith/observability) 中跟踪各个离散步骤。
* **Retries**：对离散工作单元应用重试策略。请参阅[容错能力](/oss/javascript/langgraph/fault-tolerance)。

## 恢复与 checkpointing

恢复时的重放依赖序列化、确定性和幂等性。

### Serialization

配置 checkpointer 时，有两条规则：

1. `entrypoint` 的输入和输出必须是 JSON 可序列化的。
2. `task` 的输出必须是 JSON 可序列化的。



请使用对象、数组、字符串、数字和布尔值等原语。


序列化让 task 结果和中间值可以在 human-in-the-loop、容错和并行执行时被还原。配置 checkpointer 时，不可序列化的值会在运行时引发错误。

### Determinism

恢复**不会**从执行停止的那一行继续。执行会回到某个 checkpoint 边界，然后**向前重放**，直到再次到达暂停点。

对 Functional API 而言，重放从 **entrypoint** 的开头开始。LangGraph 会从 checkpointer 还原已完成的 [**task**](#task) 和 [**subgraph**](/oss/javascript/langgraph/use-subgraphs) 结果，而不是重新计算。这样可以在暂停之间保持步骤顺序，包括长时间运行或非确定性的 **task** 输出。

使用 **human-in-the-loop** 时，请把非确定性工作（例如随机值）和副作用（例如文件写入或 API 调用）放进 [**task**](#task)。

不同的运行可以产生不同的结果。恢复**特定** thread 时应重放相同的已持久化 **task** 和 **subgraph** 结果。

准则：

* **Avoid repeating work**：为 entrypoint 中的每个副作用单独建一个 **task**，这样恢复时会还原输出，而不是重新执行。
* **Encapsulate non-deterministic operations**：把不同尝试之间会变化的值（随机数、系统时钟时间）放进 **task**。
* **Use idempotent operations**：关于部分失败和重试，请参阅 [Idempotency](#idempotency)。

### Idempotency

幂等性意味着同一操作执行多次与执行一次的效果相同。请把 API 调用和其他写入操作放进 **task**，并把这些 task 设计成重复运行也安全。

恢复时，LangGraph 会还原已完成的 **task** 结果。已经开始但未完成的 **task** 可能会再次运行，因此请使用幂等键，或在写入前检查已有结果。

## 常见陷阱

### 处理副作用

把副作用（写文件、发送邮件）放进 task，这样恢复时不会再次执行。

<Tabs>
    <Tab title="Incorrect">
    文件写入在 entrypoint 中执行，因此恢复时会再执行一次。



    ```typescript
    import { MemorySaver, entrypoint, interrupt } from "@langchain/langgraph";
    import fs from "fs";

    const checkpointer = new MemorySaver();

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow" },
      async (inputs: Record<string, any>) => {
        // Runs again on resume.
        fs.writeFileSync("output.txt", "Side effect executed");
        const value = interrupt("question");
        return value;
      }
    );
    ```

    </Tab>
    <Tab title="Correct">
    副作用放在 task 中，因此恢复时会还原已写入 checkpoint 的结果。



    ```typescript
    import { MemorySaver, entrypoint, task, interrupt } from "@langchain/langgraph";
    import * as fs from "fs";

    const checkpointer = new MemorySaver();

    const writeToFile = task("writeToFile", async () => {
      fs.writeFileSync("output.txt", "Side effect executed");
    });

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow" },
      async (inputs: Record<string, any>) => {
        await writeToFile();
        const value = interrupt("question");
        return value;
      }
    );
    ```

    </Tab>
</Tabs>

### 非确定性控制流

把时间和随机性封装进 task，这样恢复时会返回相同的值。

* 在 task 中：获取随机数（5）→ interrupt → 恢复 →（再次返回 5）→ ...
* 不在 task 中：获取随机数（5）→ interrupt → 恢复 → 获取新的随机数（7）→ ...

有多个 [`interrupt`](https://reference.langchain.com/javascript/langchain-langgraph/index/interrupt) 调用时，LangGraph 会**按索引**把 resume 值匹配到每个 interrupt。如果恢复时 interrupt 的顺序发生变化，一个 resume 值可能被关联到错误的 interrupt。请参阅 [Determinism](#determinism)。

<Tabs>
    <Tab title="Incorrect">
    在 entrypoint 中读取时钟可能改变恢复时执行的分支。



    ```typescript
    import { MemorySaver, entrypoint, task, interrupt } from "@langchain/langgraph";

    const checkpointer = new MemorySaver();

    const slowTask = task("slowTask", async (x: number) => x);

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow" },
      async (inputs: { t0: number }) => {
        const t1 = Date.now();

        const deltaT = t1 - inputs.t0;

        if (deltaT > 1000) {
          const result = await slowTask(1);
          const value = interrupt("question");
          return { result, value };
        } else {
          const result = await slowTask(2);
          const value = interrupt("question");
          return { result, value };
        }
      }
    );
    ```

    </Tab>
    <Tab title="Correct">


    在 task 内读取时钟，这样恢复时会还原相同的时间戳和分支。

    ```typescript
    import { MemorySaver, entrypoint, task, interrupt } from "@langchain/langgraph";

    const checkpointer = new MemorySaver();

    const slowTask = task("slowTask", async (x: number) => x);
    const getTime = task("getTime", async () => Date.now());

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow" },
      async (inputs: { t0: number }) => {
        const t1 = await getTime();

        const deltaT = t1 - inputs.t0;

        if (deltaT > 1000) {
          const result = await slowTask(1);
          const value = interrupt("question");
          return { result, value };
        } else {
          const result = await slowTask(2);
          const value = interrupt("question");
          return { result, value };
        }
      }
    );
    ```

    </Tab>
</Tabs>
