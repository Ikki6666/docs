使用 LangGraph 构建一个 [检索](/oss/javascript/deepagents/retrieval) 智能体，让它决定是搜索向量存储，还是直接回复用户。

LangChain 提供了内置的 [agent](/oss/javascript/langchain/agents) 实现，这些实现基于 [LangGraph](/oss/javascript/langgraph/overview) 原语构建。当你需要更深入的自定义时，可以直接在 LangGraph 中实现智能体。本教程将介绍一种检索智能体的实现模式。

在本教程中，你将：

1. 获取并预处理用于检索的文档。
2. 为这些文档建立语义搜索索引，并为智能体创建一个检索器工具。
3. 构建一个 agentic RAG 系统，让它能够决定何时使用检索器工具。

![Hybrid RAG](/images/langgraph-hybrid-rag-tutorial.png)

### 概念

本教程涉及以下概念：

- 使用以下组件进行[检索](/oss/javascript/deepagents/retrieval)：
  - [文档加载器](/oss/javascript/integrations/document_loaders)，
  - [文本分割器](/oss/javascript/integrations/splitters)、[嵌入](/oss/javascript/integrations/embeddings)，以及
  - [向量存储](/oss/javascript/integrations/vectorstores)
- LangGraph [Graph API](/oss/javascript/langgraph/graph-api)，包括 state、nodes、edges 和 conditional edges。

### 设置 LangSmith

RAG 应用会按顺序执行检索和生成。运行本教程中的示例时，[LangSmith](/langsmith/observability) 会为每个查询记录一条 trace，方便你检查检索、工具调用和模型响应。
[注册 LangSmith](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=oss-langgraph-agentic-rag) 后，设置环境变量即可开始记录 trace：

```shell
export LANGSMITH_TRACING="true"
export LANGSMITH_API_KEY="..."
```



<Tip>
如果你正在构建生产级智能体，我们还建议设置 [LangSmith Engine](/langsmith/engine)，它可以监控 trace、检测问题并提出修复建议。
</Tip>

## 生成查询或回复

检索器工具准备好后，就可以开始把智能体构建为 LangGraph 图。在 [Graph API](/oss/javascript/langgraph/graph-api) 中，图由以下部分组成：



- **[State](/oss/javascript/langgraph/graph-api#state)**：节点读取和更新的共享数据。本教程使用 [`MessagesAnnotation`](/oss/javascript/langgraph/graph-api#using-messages-in-your-graph)，它存储一个由 [chat messages](/oss/javascript/langchain/messages) 组成的 `messages` 列表。


- **[Nodes](/oss/javascript/langgraph/graph-api#nodes)**：接收当前状态、执行一个步骤（例如调用模型或工具）并返回状态更新的函数。
- **[Edges](/oss/javascript/langgraph/graph-api#edges)**：定义下一个运行哪个节点的连接，包括根据状态进行分支的 [conditional edges](/oss/javascript/langgraph/graph-api#conditional-edges)。

第一个节点是智能体的决策点。根据此前的对话，模型要么直接回答用户，要么在问题需要博客上下文时调用检索器工具。正是这一选择让系统具备 agentic 特性，而不是固定的“先检索再生成”流水线：只有当模型请求时才执行检索。



<Steps>
<Step title="构建节点">

构建 `generateQueryOrRespond` 节点，在当前消息上调用模型，并使用 `.bindTools` 绑定 `tools`：

<AgenticRagGenerateQueryOrRespondJs />

</Step>
<Step title="尝试简单的问候">

## 评估文档

普通边总是把图发送到同一个下一个节点。[conditional edge](/oss/javascript/langgraph/graph-api#conditional-edges) 会在运行时对当前状态执行函数，从而选择下一个节点。检索之后，可以用这种模式评估文档是否相关：如果相关，就继续生成答案；如果不相关，就重写问题并重试。



<Steps>
<Step title="添加文档评分">

添加 `gradeDocuments` 路由函数，它使用带结构化输出（Zod）的模型；如果结构化解析失败，则回退到简单的 yes/no 响应。该函数根据评分结果返回下一个节点的名称（`generate` 或 `rewrite`），因此请把它用在 conditional edge 中，而不是作为节点添加：

<AgenticRagGradeDocumentsJs />

</Step>
<Step title="使用无关文档测试">

在工具响应中使用无关文档运行：

```typescript
import { ToolMessage } from "@langchain/core/messages";

const input = {
  messages: [
    new HumanMessage("What does Lilian Weng say about types of reward hacking?"),
    new AIMessage({
      tool_calls: [
        {
          type: "tool_call",
          name: "retrieve_blog_posts",
          args: { query: "types of reward hacking" },
          id: "1",
        }
      ]
    }),
    new ToolMessage({
      content: "meow",
      tool_call_id: "1",
    })
  ]
}
const result = await gradeDocuments(input);
```

</Step>
<Step title="使用相关文档测试">

确认相关文档会被正确分类：

</Step>

## 重写问题

如果评分器把检索到的文档标记为不相关，图就不应基于该上下文回答。此时应把原始用户问题重写为更清晰的搜索查询，然后把控制权交回 generate-query-or-respond 节点，让智能体重新检索。这个重试循环能让智能体在首次检索效果不佳时恢复，而不是停止或编造答案。



<Steps>
<Step title="构建重写节点">

构建 `rewrite` 节点，在检索未命中时改进原始用户问题：

<AgenticRagRewriteQuestionJs />

</Step>
<Step title="试一试">

```typescript
import { HumanMessage, AIMessage, ToolMessage } from "@langchain/core/messages";

const input = {
  messages: [
    new HumanMessage("What does Lilian Weng say about types of reward hacking?"),
    new AIMessage({
      content: "",
      tool_calls: [
        {
          id: "1",
          name: "retrieve_blog_posts",
          args: { query: "types of reward hacking" },
          type: "tool_call"
        }
      ]
    }),
    new ToolMessage({ content: "meow", tool_call_id: "1" })
  ]
};

const response = await rewrite(input);
console.log(response.messages[0].content);
```

**输出：**

```text wrap
What are the different types of reward hacking described by Lilian Weng, and how does she explain them?
```

</Step>
</Steps>


## 生成答案

当评分器接受检索到的文档后，图会进入答案生成阶段。这个节点是经典的 RAG 步骤：把原始用户问题与包含检索上下文的 tool message 结合，然后让模型生成有依据的回复。保持提示词紧凑，让模型基于提供的上下文回答，而不是编造细节。



<Steps>
<Step title="构建答案节点">

构建 `generate` 节点，根据问题和检索到的上下文生成最终回复：

<AgenticRagGenerateAnswerJs />

</Step>
<Step title="试一试">

```typescript
import { HumanMessage, AIMessage, ToolMessage } from "@langchain/core/messages";

const input = {
  messages: [
    new HumanMessage("What does Lilian Weng say about types of reward hacking?"),
    new AIMessage({
      content: "",
      tool_calls: [
        {
          id: "1",
          name: "retrieve_blog_posts",
          args: { query: "types of reward hacking" },
          type: "tool_call"
        }
      ]
    }),
    new ToolMessage({
      content: "reward hacking can be categorized into two types: environment or goal misspecification, and reward tampering",
      tool_call_id: "1"
    })
  ]
};

const response = await generate(input);
console.log(response.messages[0].content);
```

**输出：**

```text wrap
Lilian Weng categorizes reward hacking into two types: environment or goal misspecification, and reward tampering. She considers reward hacking as a broad concept that includes both of these categories. Reward hacking occurs when an agent exploits flaws or ambiguities in the reward function to achieve high rewards without performing the intended behaviors.
```

</Step>
</Steps>


## 组装图

把节点和边组装成一个完整的图：



- 从 `generateQueryOrRespond` 开始，判断是否需要调用检索器工具。
- 使用 conditional edge 路由到下一步：
  - 如果 `generateQueryOrRespond` 返回了 `tool_calls`，就调用检索器工具检索上下文。
  - 否则，直接回复用户。
- 对检索到的文档内容进行与问题的相关性评分（`gradeDocuments`），并路由到下一步：
  - 如果不相关，就使用 `rewrite` 重写问题，然后再次调用 `generateQueryOrRespond`。
  - 如果相关，就进入 `generate`，并使用带有检索到文档上下文的 [ToolMessage](https://reference.langchain.com/javascript/langchain-core/messages/ToolMessage) 生成最终回复。
