---
title: 测试
---


在你完成 LangGraph 智能体原型后，下一步自然就是添加测试。本指南介绍了一些在编写单元测试时很有用的模式。



注意，这份指南是 LangGraph 专用的，覆盖的是带有自定义结构的图场景 - 如果你刚开始接触，可以看看使用 LangChain 内置 [`createAgent`](https://reference.langchain.com/javascript/langchain/index/createAgent) 的 [Test](/oss/javascript/langchain/test/)。



## 前提条件



首先，确保你已经安装了 [`vitest`](https://vitest.dev/)：

```bash
$ npm install -D vitest
```


## 开始使用

由于许多 LangGraph 智能体都依赖 state，一个有用的模式是在每个测试中先创建图，然后在测试里使用新的 checkpointer 实例来编译它。

下面的示例展示了它如何与一个简单的线性图一起工作，这个图会依次经过 `node1` 和 `node2`。每个节点都会更新单个 state key `my_key`：



```ts
import { test, expect } from 'vitest';
import {
  StateGraph,
  StateSchema,
  START,
  END,
  MemorySaver,
} from '@langchain/langgraph';
import * as z from "zod";

const State = new StateSchema({
  my_key: z.string(),
});

const createGraph = () => {
  return new StateGraph(State)
    .addNode('node1', (state) => ({ my_key: 'hello from node1' }))
    .addNode('node2', (state) => ({ my_key: 'hello from node2' }))
    .addEdge(START, 'node1')
    .addEdge('node1', 'node2')
    .addEdge('node2', END);
};

test('basic agent execution', async () => {
  const uncompiledGraph = createGraph();
  const checkpointer = new MemorySaver();
  const compiledGraph = uncompiledGraph.compile({ checkpointer });
  const result = await compiledGraph.invoke(
    { my_key: 'initial_value' },
    { configurable: { thread_id: '1' } }
  );
  expect(result.my_key).toBe('hello from node2');
});
```


## 测试单个节点和边

已编译的 LangGraph 智能体会把每个单独节点暴露为 `graph.nodes`。你可以利用这一点测试智能体中的单个节点。注意，这样会绕过编译图时传入的任何 checkpointer：



```ts
import { test, expect } from 'vitest';
import {
  StateGraph,
  START,
  END,
  MemorySaver,
  StateSchema,
} from '@langchain/langgraph';
import * as z from "zod";

const State = new StateSchema({
  my_key: z.string(),
});

const createGraph = () => {
  return new StateGraph(State)
    .addNode('node1', (state) => ({ my_key: 'hello from node1' }))
    .addNode('node2', (state) => ({ my_key: 'hello from node2' }))
    .addEdge(START, 'node1')
    .addEdge('node1', 'node2')
    .addEdge('node2', END);
};

test('individual node execution', async () => {
  const uncompiledGraph = createGraph();
  // 这个示例中会被忽略
  const checkpointer = new MemorySaver();
  const compiledGraph = uncompiledGraph.compile({ checkpointer });
  // 只调用 node 1
  const result = await compiledGraph.nodes['node1'].invoke(
    { my_key: 'initial_value' },
  );
  expect(result.my_key).toBe('hello from node1');
});
```


## 部分执行

对于由更大图组成的智能体，你可能希望测试智能体中某条部分执行路径，而不是端到端地测试整个流程。在某些情况下，把这些部分重构成子图可能更符合语义，这样你就可以像正常情况一样单独调用它们。

不过，如果你不想改动智能体图的整体结构，就可以使用 LangGraph 的持久化机制，模拟智能体在目标部分开始之前刚好暂停，并在目标部分结束时再次暂停。步骤如下：


1. 使用 checkpointer 编译智能体（用于测试时，内存 checkpointer [`MemorySaver`](https://reference.langchain.com/javascript/langchain-langgraph-checkpoint/MemorySaver) 就足够了）。
2. 调用智能体的 [`update_state`](/oss/javascript/langgraph/use-time-travel) 方法，并把 [`asNode`](/oss/javascript/langgraph/use-time-travel#from-a-specific-node) 参数设置为你想要测试的节点之前那个节点的名称。
3. 使用同一个 `thread_id` 调用智能体，并把 `interruptBefore` 参数设置为你想要停止的节点名称。


下面是一个只执行线性图中第二和第三个节点的示例：



```ts
import { test, expect } from 'vitest';
import {
  StateGraph,
  StateSchema,
  START,
  END,
  MemorySaver,
} from '@langchain/langgraph';
import * as z from "zod";

const State = new StateSchema({
  my_key: z.string(),
});

const createGraph = () => {
  return new StateGraph(State)
    .addNode('node1', (state) => ({ my_key: 'hello from node1' }))
    .addNode('node2', (state) => ({ my_key: 'hello from node2' }))
    .addNode('node3', (state) => ({ my_key: 'hello from node3' }))
    .addNode('node4', (state) => ({ my_key: 'hello from node4' }))
    .addEdge(START, 'node1')
    .addEdge('node1', 'node2')
    .addEdge('node2', 'node3')
    .addEdge('node3', 'node4')
    .addEdge('node4', END);
};

test('partial execution from node2 to node3', async () => {
  const uncompiledGraph = createGraph();
  const checkpointer = new MemorySaver();
  const compiledGraph = uncompiledGraph.compile({ checkpointer });
  await compiledGraph.updateState(
    { configurable: { thread_id: '1' } },
    // 传入 node 2 的 state - 模拟位于
    // node 1 结束时的状态
    { my_key: 'initial_value' },
    // 把已保存的 state 更新为仿佛它来自 node 1
    // 执行会在 node 2 恢复
    'node1',
  );
  const result = await compiledGraph.invoke(
    // 通过传入 None 继续执行
    null,
    {
      configurable: { thread_id: '1' },
      // 在 node 3 之后停止，这样 node 4 就不会运行
      interruptAfter: ['node3']
    },
  );
  expect(result.my_key).toBe('hello from node3');
});
```
