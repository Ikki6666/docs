## 概览

LangGraph 通过 [checkpoints](/oss/javascript/langgraph/checkpointers#checkpoints) 支持 time travel：

- **[Replay](#replay)**：从之前的 checkpoint 重新执行。
- **[Fork](#fork)**：从之前的 checkpoint 分叉出带有修改后 state 的替代路径。

这两种方式都是从之前的 checkpoint 恢复。checkpoint 之前的节点不会重新执行（结果已经保存好了）。checkpoint 之后的节点会重新执行，包括任何 LLM 调用、API 请求和 [interrupts](/oss/javascript/langgraph/interrupts)（这些可能会产生不同结果）。

## Replay

用之前 checkpoint 的 config 调用图，就可以从那个点回放。

<Warning>

Replay 会重新执行节点，不只是从缓存里读取。LLM 调用、API 请求和 [interrupts](/oss/javascript/langgraph/interrupts) 会再次触发，结果可能不同。从最后一个 checkpoint 回放（没有 `next` 节点）不会有任何效果。

</Warning>

![Replay](/oss/images/re_play.png)



使用 [`getStateHistory`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.pregel.Pregel.html#getStateHistory) 找到你想回放的 checkpoint，然后用该 checkpoint 的 config 调用 [`invoke`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.index.CompiledStateGraph.html#invoke)：

```typescript
import { v7 as uuid7 } from "uuid";
import { StateGraph, MemorySaver, START } from "@langchain/langgraph";

const StateAnnotation = Annotation.Root({
  topic: Annotation<string>(),
  joke: Annotation<string>(),
});

function generateTopic(state: typeof StateAnnotation.State) {
  return { topic: "socks in the dryer" };
}

function writeJoke(state: typeof StateAnnotation.State) {
  return { joke: `Why do ${state.topic} disappear? They elope!` };
}

const checkpointer = new MemorySaver();
const graph = new StateGraph(StateAnnotation)
  .addNode("generateTopic", generateTopic)
  .addNode("writeJoke", writeJoke)
  .addEdge(START, "generateTopic")
  .addEdge("generateTopic", "writeJoke")
  .compile({ checkpointer });

// Step 1: Run the graph
const config = { configurable: { thread_id: uuid7() } };
const result = await graph.invoke({}, config);

// Step 2: Find a checkpoint to replay from
const states = [];
for await (const state of graph.getStateHistory(config)) {
  states.push(state);
}

// Step 3: Replay from a specific checkpoint
const beforeJoke = states.find((s) => s.next.includes("writeJoke"));
const replayResult = await graph.invoke(null, beforeJoke.config);
// writeJoke re-executes (runs again), generateTopic does not
```


## Fork

Fork 会基于过去的 checkpoint 创建一个带有修改后 state 的新分支。调用先前 checkpoint 上的 [`update_state`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.pregel.Pregel.html#updateState) 可以创建 fork，然后用 `None` 调用 [`invoke`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.index.CompiledStateGraph.html#invoke) 继续执行。

![Fork](/oss/images/checkpoints_full_story.jpg)

<Warning>

`update_state` **不会** 回滚一个线程。它只是基于指定位置创建一个新的 checkpoint。原始执行历史会保持不变。

</Warning>



```typescript
// Find checkpoint before writeJoke
const states = [];
for await (const state of graph.getStateHistory(config)) {
  states.push(state);
}
const beforeJoke = states.find((s) => s.next.includes("writeJoke"));

// Fork: update state to change the topic
const forkConfig = await graph.updateState(
  beforeJoke.config,
  { topic: "chickens" },
);

// Resume from the fork — writeJoke re-executes with the new topic
const forkResult = await graph.invoke(null, forkConfig);
console.log(forkResult.joke); // A joke about chickens, not socks
```


### 从特定节点开始

当你调用 [`update_state`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.pregel.Pregel.html#updateState) 时，值会按照指定节点的 writers（包括 [reducers](/oss/javascript/langgraph/graph-api#reducers)）应用。checkpoint 会把那个节点记录为生成了这次更新，并从该节点的后继节点继续执行。

默认情况下，LangGraph 会根据 checkpoint 的版本历史推断 `as_node`。在从特定 checkpoint 分叉时，这个推断几乎总是正确的。

在以下情况应显式指定 `as_node`：

- **并行分支**：多个节点在同一步更新了 state，而 LangGraph 无法判断哪个是最后一个（`InvalidUpdateError`）。
- **没有执行历史**：为一个新线程设置 state（在 [testing](/oss/javascript/langgraph/test) 中很常见）。
- **跳过节点**：把 `as_node` 设置为更晚的节点，让图认为那个节点已经运行过。



```typescript
// graph: generateTopic -> writeJoke

// Treat this update as if generateTopic produced it.
// Execution resumes at writeJoke (the successor of generateTopic).
const forkConfig = await graph.updateState(
  beforeJoke.config,
  { topic: "chickens" },
  { asNode: "generateTopic" },
);
```


## Interrupts

如果你的图在 [human-in-the-loop](/oss/javascript/langgraph/interrupts) 工作流中使用 [`interrupt`](https://reference.langchain.com/javascript/langchain-langgraph/index/interrupt)，那么在 time travel 时 interrupts 总会重新触发。包含 interrupt 的节点会重新执行，而 `interrupt()` 会暂停，等待新的 `Command(resume=...)`。



```typescript
import { interrupt, Command } from "@langchain/langgraph";

function askHuman(state: { value: string[] }) {
  const answer = interrupt("What is your name?");
  return { value: [`Hello, ${answer}!`] };
}

function finalStep(state: { value: string[] }) {
  return { value: ["Done"] };
}

// ... build graph with checkpointer ...

// First run: hits interrupt
await graph.invoke({ value: [] }, config);
// Resume with answer
await graph.invoke(new Command({ resume: "Alice" }), config);

// Replay from before askHuman
const states = [];
for await (const state of graph.getStateHistory(config)) {
  states.push(state);
}
const beforeAsk = states.filter((s) => s.next.includes("askHuman")).pop();

const replayResult = await graph.invoke(null, beforeAsk.config);
// Pauses at interrupt — waiting for new Command({ resume: ... })

// Fork from before askHuman
const forkConfig = await graph.updateState(beforeAsk.config, { value: ["forked"] });
const forkResult = await graph.invoke(null, forkConfig);
// Pauses at interrupt — waiting for new Command({ resume: ... })

// Resume the forked interrupt with a different answer
await graph.invoke(new Command({ resume: "Bob" }), forkConfig);
// Result: { value: ["forked", "Hello, Bob!", "Done"] }
```


### Multiple interrupts

如果你的图在多个点收集输入（例如多步骤表单），你可以从两个 interrupt 之间 fork，这样就能在不重新询问前面问题的情况下修改后面的答案。



```typescript
// Fork from BETWEEN the two interrupts (after askName, before askAge)
const states = [];
for await (const state of graph.getStateHistory(config)) {
  states.push(state);
}
const between = states.filter((s) => s.next.includes("askAge")).pop();

const forkConfig = await graph.updateState(between.config, { value: ["modified"] });
const result = await graph.invoke(null, forkConfig);
// askName result preserved ("name:Alice")
// askAge pauses at interrupt — waiting for new answer
```


## 子图

对子图进行 time travel 时，能否从子图内部的某个点跳转，取决于子图是否有自己的 checkpointer。这决定了你可以 time travel 的 checkpoint 粒度。

<Tabs>
<Tab title="继承 checkpointer（默认）">

默认情况下，子图会继承父图的 checkpointer。父图会把整个子图当成一个 **single super-step** - 整个子图执行只会有一个父级 checkpoint。从子图之前回放时，会从头重新执行整个子图。

在默认子图里，你不能 time travel 到两个节点之间的某个点 - 你只能从父级视角进行 time travel。



```typescript
// Subgraph without its own checkpointer (default)
const subgraph = new StateGraph(StateAnnotation)
  .addNode("stepA", stepA)       // Has interrupt()
  .addNode("stepB", stepB)       // Has interrupt()
  .addEdge(START, "stepA")
  .addEdge("stepA", "stepB")
  .compile();  // No checkpointer — inherits from parent

const graph = new StateGraph(StateAnnotation)
  .addNode("subgraphNode", subgraph)
  .addEdge(START, "subgraphNode")
  .compile({ checkpointer });

// Complete both interrupts
await graph.invoke({ value: [] }, config);
await graph.invoke(new Command({ resume: "Alice" }), config);
await graph.invoke(new Command({ resume: "30" }), config);

// Time travel from before the subgraph
const states = [];
for await (const state of graph.getStateHistory(config)) {
  states.push(state);
}
const beforeSub = states.filter((s) => s.next.includes("subgraphNode")).pop();

const forkConfig = await graph.updateState(beforeSub.config, { value: ["forked"] });
const result = await graph.invoke(null, forkConfig);
// 整个子图会从头重新执行
// 你不能 time travel 到 stepA 和 stepB 之间的某个点
```


</Tab>
<Tab title="子图 checkpointer">

在子图上设置 `checkpointer=True`，就能让它拥有自己的 checkpoint 历史。这会在子图内部的每一步都创建 checkpoint，从而允许你从子图内部的某个点进行 time travel，例如两个 interrupts 之间。

使用 [`get_state`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.pregel.Pregel.html#getState) 并将 `subgraphs=True` 传入，即可访问子图自己的 checkpoint config，然后从那里 fork：



```typescript
// Subgraph with its own checkpointer
const subgraph = new StateGraph(StateAnnotation)
  .addNode("stepA", stepA)       // Has interrupt()
  .addNode("stepB", stepB)       // Has interrupt()
  .addEdge(START, "stepA")
  .addEdge("stepA", "stepB")
  .compile({ checkpointer: true });  // Own checkpoint history

const graph = new StateGraph(StateAnnotation)
  .addNode("subgraphNode", subgraph)
  .addEdge(START, "subgraphNode")
  .compile({ checkpointer });

// Run until stepA interrupt, then resume -> hits stepB interrupt
await graph.invoke({ value: [] }, config);
await graph.invoke(new Command({ resume: "Alice" }), config);

// Get the subgraph's own checkpoint (between stepA and stepB)
const parentState = await graph.getState(config, { subgraphs: true });
const subConfig = parentState.tasks[0].state.config;

// Fork from the subgraph checkpoint
const forkConfig = await graph.updateState(subConfig, { value: ["forked"] });
const result = await graph.invoke(null, forkConfig);
// stepB re-executes, stepA's result is preserved
```


</Tab>
</Tabs>

更多关于如何配置子图 checkpointer 的内容，请参阅 [subgraph persistence](/oss/javascript/langgraph/use-subgraphs#subgraph-persistence)。
