[节点](/oss/javascript/langgraph/graph-api#nodes)是 Graph API 图的步骤。本页介绍在添加节点时如何附加运行时配置、重试、超时、错误处理程序、默认值和缓存。关于把节点接入序列、分支和循环，请参阅[控制流](/oss/javascript/langgraph/graph-api-control-flow)。完整的重试、超时和错误生命周期，请参阅[容错](/oss/javascript/langgraph/fault-tolerance)。

## 添加运行时配置

把值传入运行（例如使用哪个 LLM 或系统提示），而不把这些值放入图状态。

要添加运行时配置：

1. 为配置指定 schema
2. 将配置添加到节点或条件边的函数签名
3. 将配置传入图

下面是一个简单示例：



<LanggraphGraphApiNodesRuntimeConfigJs />

```
{ myStateValue: 1 }
{ myStateValue: 2 }
```

## 添加重试策略

当节点调用可能瞬时失败的 API、数据库或 LLM 时，附加重试策略。



将 `retryPolicy` 传给 [`addNode`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.index.Graph.html#addnode)。空对象会使用内置默认值：

<LanggraphGraphApiNodesRetryDefaultJs />

重试需要显式启用：没有 `retryPolicy` 时，第一次失败就会结束尝试。如果策略省略 `retryOn`，LangGraph 会重试抛出的错误，但以下情况除外：

* 中止和取消错误（`error.name === "AbortError"`，或 `error.message` 以 `"Cancel"` 或 `"AbortError"` 开头）
* `GraphValueError`，按 `error.name` 匹配
* 中止的连接（`error.code === "ECONNABORTED"`）
* 状态码为 400、401、402、403、404、405、406、407 或 409 的 HTTP 客户端错误
* OpenAI 风格的配额错误（`error.error?.code === "insufficient_quota"`）

完整的默认列表和参数请参阅[容错](/oss/javascript/langgraph/fault-tolerance#retries)。

## 设置节点超时



<Note>
需要 `@langchain/langgraph` v1.4.0 或更高版本。
</Note>

将 `timeout` 传给 [`addNode`](https://reference.langchain.com/javascript/langchain-langgraph/index/StateGraph/addNode)，限制单次节点尝试可以运行的时间。使用数字（毫秒），或使用 [`TimeoutPolicy`](https://reference.langchain.com/javascript/langchain-langgraph/index/TimeoutPolicy) 分别设置运行和空闲限制：

<LanggraphGraphApiNodesTimeoutJs />

当节点超过超时时间时，LangGraph 抛出 [`NodeTimeoutError`](https://reference.langchain.com/javascript/langchain-langgraph/index/NodeTimeoutError)，清除失败尝试的写入，并由重试策略决定是否重试。超时独立应用于每次尝试。

完整的超时生命周期、空闲超时刷新来源和心跳，请参阅[容错](/oss/javascript/langgraph/fault-tolerance#timeouts)。

## 设置图级节点默认值



<Note>
需要 `@langchain/langgraph` v1.4.0 或更高版本。
</Note>

使用 [`setNodeDefaults`](https://reference.langchain.com/javascript/langchain-langgraph/index/StateGraph#member-setNodeDefaults) 为图中的每个节点统一设置 `retryPolicy`、`timeout`、`cachePolicy` 或 `errorHandler`，而不必在每次 `addNode` 调用中重复。每个节点的值始终优先，默认值在编译时应用：

<LanggraphGraphApiNodesNodeDefaultsJs />

`retryPolicy` 和 `timeout` 默认值适用于每个节点，包括错误处理程序节点。`cachePolicy` 和 `errorHandler` 默认值仅适用于常规节点。处理程序绝不会捕获自己，缓存处理程序结果也不安全。默认值不会被子图继承。

完整的优先级规则和适用性表格，请参阅[容错](/oss/javascript/langgraph/fault-tolerance#graph-defaults)。


## 访问节点内的执行信息



通过节点第二个参数（`LangGraphRunnableConfig`）上的 `config.executionInfo` 访问执行标识和重试信息。它会呈现线程、运行和检查点标识符以及重试状态。

| 属性 | 类型 | 描述 |
| --------- | ---- | ----------- |
| `threadId` | `string \| undefined` | 当前执行的线程 ID。 |
| `runId` | `string \| undefined` | 当前执行的运行 ID。 |
| `checkpointId` | `string` | 当前执行的检查点 ID。 |
| `checkpointNs` | `string` | 当前执行的检查点命名空间。 |
| `taskId` | `string` | 当前执行的任务 ID。 |
| `nodeAttempt` | `number` | 当前执行的尝试次数（从 1 开始）。 |
| `nodeFirstAttemptTime` | `number \| undefined` | 第一次尝试开始时的 Unix 时间戳（毫秒）。重试期间保持不变。 |

#### 访问线程和运行 ID

在节点内使用 `executionInfo` 访问线程 ID、运行 ID 和其他标识字段：

<LanggraphGraphApiNodesExecutionInfoIdsJs />

#### 根据重试状态调整行为

当节点有重试策略时，使用 `executionInfo` 检查当前尝试次数，并在第一次尝试失败后切换到回退方案：

<LanggraphGraphApiNodesExecutionInfoRetryJs />

`executionInfo` 在节点任务准备好后设置。即使没有重试策略，`nodeAttempt` 也默认为 `1`，`nodeFirstAttemptTime` 在节点开始执行时设置。

## 添加节点缓存

当某个步骤开销较大，并且希望为相同输入复用结果时，使用节点缓存。

要启用缓存：

1. 在编译图时传入缓存（例如 `InMemoryCache`）。Python 中还提供 `SqliteCache`。
2. 在节点上附加 [`CachePolicy`](https://reference.langchain.com/javascript/langchain-langgraph/index/CachePolicy)。

[`CachePolicy`](https://reference.langchain.com/javascript/langchain-langgraph/index/CachePolicy) 选项：



- **`keyFunc`**：根据节点输入构建缓存键的函数。
- **`ttl`**：生存时间（秒）。省略时，缓存条目不会过期。




<LanggraphGraphApiNodesCacheJs />

也可以使用 `setNodeDefaults` 为图统一设置 `cachePolicy`（以及其他节点选项）。请参阅[设置图级节点默认值](#set-graph-wide-node-defaults)。
