**标准测试可确保你的集成按预期工作。**

无论你是在为自己实现一个自定义类，还是准备发布成 LangChain 集成，都有必要添加测试，以确保其按预期工作。LangChain 为每种集成类型都提供了一套全面的[测试集合](https://pypi.org/project/langchain-tests/)。本指南将说明如何为每种集成类型接入 LangChain 的标准测试套件。

## 配置

首先，安装所需依赖：


<CardGroup cols={2}>
    <Card title="langchain-core" icon="cube" href="https://github.com/langchain-ai/langchainjs/tree/main/libs/langchain-core#readme" arrow>
        定义了我们在实现自定义组件时要导入的接口
    </Card>

    <Card title="langchain-tests" icon="flask" href="https://github.com/langchain-ai/langchainjs/tree/main/internal/standard-tests#readme" arrow>
        提供运行标准测试所需的测试集和插件
    </Card>
</CardGroup>






<CodeGroup>
    ```bash npm
    npm install @langchain/core
    npm install @langchain/standard-tests
    ```

    ```bash pnpm
    pnpm add @langchain/core
    pnpm add @langchain/standard-tests
    ```

    ```bash yarn
    yarn add @langchain/core
    yarn add @langchain/standard-tests
    ```

    ```bash bun
    bun add @langchain/core
    bun add @langchain/standard-tests
    ```
</CodeGroup>


`langchain-tests` 包中有 2 个命名空间：

<AccordionGroup>
    <Accordion title="单元测试" icon="settings">

        **位置**：`src.unit_tests`


        用于在不访问外部服务的情况下，对组件进行隔离测试

        [查看 API reference](https://reference.langchain.com/python/langchain-tests/unit_tests)
    </Accordion>

    <Accordion title="集成测试" icon="network">

        **位置**：`src.integration_tests`


        用于在可以访问外部服务的情况下测试组件（尤其是该组件设计要交互的外部服务）

        [查看 API reference](https://reference.langchain.com/python/langchain-tests/integration_tests)
    </Accordion>
</AccordionGroup>



## 实现标准测试

根据你的集成类型，你需要实现单元测试、集成测试，或两者都实现。

通过继承适用于你集成类型的标准测试套件，你可以获得该类型对应的整套标准测试。某个测试只有在模型支持被测试的能力时才应通过。否则，该测试应被跳过。

由于不同集成提供的能力集合各不相同，LangChain 提供的大多数标准测试默认都需要**显式启用**，以避免误报。因此，你需要通过覆写属性来说明你的集成支持哪些能力，下面的例子演示了这一点。


```javascript tests/chat_models.standard.int.test.ts
// 声明某个聊天模型支持并行工具调用

class ChatParrotLinkStandardIntegrationTests extends ChatModelIntegrationTests<
    ChatParrotLinkCallOptions,
    AIMessageChunk
> {
    constructor() {
        // ... 其他必需属性

        super({
            // ... 其他必需属性
            supportsParallelToolCalls: true,  // （默认值是 False）
            // ...
        });
    }
```


<Note>
    你应当在包根目录下使用以下子目录来组织测试：
    - `tests/unit_tests` 用于单元测试
    - `tests/integration_tests` 用于集成测试
</Note>



如需查看所有可配置能力及其默认值的完整列表，请参阅[实现标准测试](#implementing-standard-tests)。




## Sandbox 集成



Deep Agents 的 sandbox 集成使用 `@langchain/sandbox-standard-tests` 中的 `sandboxStandardTests`。
调用它时传入一个配置对象，其中包含 `createSandbox`、`resolvePath` 和 `closeSandbox`。
可以把 [Daytona integration tests](https://github.com/langchain-ai/deepagentsjs/blob/main/libs/providers/daytona/src/sandbox.int.test.ts) 作为参考实现。
发布规范请参阅[贡献 sandbox 集成](/oss/javascript/contributing/integrations-langchain)。
