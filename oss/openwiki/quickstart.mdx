OpenWiki 是一个 CLI，用于为你的代码库或个人知识编写并持续维护 Markdown wiki。Coding agent 把该 wiki 用作持久上下文，因此它们在重新探索架构、集成和其他仓库细节上花费的时间和 token 更少。人类也可以阅读相同的文档，但 agent 是主要受众。本指南涵盖安装、provider 设置和你的第一次文档运行。功能概览请参见 [OpenWiki overview](/oss/openwiki/overview)。

## 安装并生成仓库文档

<Steps>
    <Step title="安装 CLI" icon="package">
        ```bash
        npm install -g openwiki
        ```

        在 Windows 上，优先使用 `npm` 或 `pnpm`。使用 Bun 安装可能会回退到编译原生的 `better-sqlite3` 依赖，并可能需要 Visual Studio Build Tools 的 Desktop development with C++ workload。
    </Step>

    <Step title="在你的仓库中初始化" icon="player-play">
        在仓库根目录运行以下命令：

        ```bash
        openwiki --init
        ```

        在第一次交互式运行时，OpenWiki 会提示：

        - 一个 inference provider 和模型
        - provider API key（或等效凭据）
        - 可选的用于 tracing 的 LangSmith API key
        - 用于从运行时 traces 丰富 wiki 的 LangSmith 项目

        OpenWiki 将其配置和密钥保存到 `~/.openwiki/.env`。

        再次运行 `--init` 会从头重新生成仓库 wiki 和 Claims，同时保留 `openwiki/INSTRUCTIONS.md`。持久 checkout 上的中断运行会从 `openwiki/.run.json` 恢复。

        要在 Codex、Claude Code、OpenCode 或 Cursor 中运行 OpenWiki，而不是使用独立的模型会话，请参见 [Coding-agent integrations](/oss/openwiki/integrations)。
    </Step>

    <Step title="查看生成的 wiki" icon="book">
        OpenWiki 将文档写入仓库中的 `openwiki/`，包括一个 quickstart 入口和主题页面。它还会在仓库根目录维护一个 `AGENTS.md` 和 `CLAUDE.md`，添加一个指示 coding agent 查阅 wiki 获取代码库上下文的 block。事实性页面通过 `openwiki/.claims/` 下的 Claims 保持有据可依。

        仓库特定的 wiki 指令位于 `openwiki/INSTRUCTIONS.md`。OpenWiki 会读取该文件获取范围和优先级。要更改它，请编辑该文件，或在聊天中让 OpenWiki 更改 brief（例如 `openwiki "Update openwiki/INSTRUCTIONS.md to focus on the public API"`）。正常的 `--init` 和 `--update` 运行不会重写它。

        要在浏览器中浏览 wiki，请运行：

        ```bash
        openwiki visualize
        ```

        这会打开一个本地的交互式节点图，并带有一个并排的 Markdown 阅读器。请参见 [Visualize your wiki](/oss/openwiki/visualize)。
    </Step>

    <Step title="保持文档最新" icon="refresh">
        在代码更改后刷新文档：

        ```bash
        openwiki --update
        ```

        在 code 模式下，更新还会在源证据变化时调和过时的 Claims。CI 中的自动更新请参见 [Automate updates](/oss/openwiki/automate-updates)。
    </Step>
</Steps>

## 个人 wiki（可选）

要初始化一个本地个人 brain 而不是仓库文档：

```bash
openwiki personal --init
```

Personal 模式写入 `~/.openwiki/wiki`，可以摄取已配置的 connector，例如本地 git 仓库、Custom MCP、Gmail、Notion、web search、Hacker News 和 X/Twitter。请参见 [Personal mode](/oss/openwiki/personal-mode)。

## 交互式与一次性运行

裸 `openwiki` 会在 code 模式下为当前仓库打开交互式会话。传入一条消息可以带请求开始：

```bash
openwiki "Please generate documentation for this repository"
```

使用 `-p` / `--print` 进行一次性非交互式运行，打印最终的 assistant 输出并退出：

```bash
openwiki -p "Summarize what you can do"
```

在聊天中，使用 `/api-key` 更新当前 provider 的 API key，使用 `/langsmith-key` 更新或清除 LangSmith tracing 凭据，使用 `/effort` 为受支持的模型设置 reasoning effort。

## Trace with LangSmith

在 onboarding 期间，提供 LangSmith API key 可以将 OpenWiki 运行跟踪到名为 `openwiki` 的 LangSmith 项目。你也可以在 `~/.openwiki/.env` 或进程环境中设置这些值：

```bash
LANGSMITH_API_KEY=your-key
LANGCHAIN_TRACING_V2=true
LANGCHAIN_PROJECT=openwiki
```

要从 LangSmith traces 丰富仓库 wiki（与 tracing OpenWiki 本身分开），请参见 [LangSmith connector](/oss/openwiki/code-mode#langsmith-connector)。
