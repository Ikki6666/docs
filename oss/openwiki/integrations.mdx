OpenWiki 可以在已有的 coding agent 中运行，而不是启动自己的模型。Coding agent 会使用其原生的仓库工具调查仓库、规划 wiki，并编写每个被分配的页面。OpenWiki 负责持久化的页面 job 生命周期、Claims 验证与持久化、源漂移处理和确定性的最终化。

宿主驱动的运行只支持仓库 [code mode](/oss/openwiki/code-mode) wiki，不支持 [personal mode](/oss/openwiki/personal-mode)。它们使用 coding agent 已认证的模型会话，因此不需要 OpenWiki provider 凭据。来自 connector 的上下文（包括 LangSmith）在此路径上尚不支持。宿主驱动的页面编写是顺序进行的；[并行页面 worker](/oss/openwiki/code-mode#parallel-page-workers) 仅适用于原生 CLI。

## 安装集成

受支持的宿主是 **Codex**、**Claude Code**、**GitHub Copilot**、**OpenCode**、**Cursor**、**IBM Bob**（Bob Shell）、**Kiro**、**Oh My Pi**（`omp`）和 **Antigravity CLI**。安装默认为用户级，因此一次安装可以在任何 Git 仓库中使用：

```bash
openwiki integrations install codex
openwiki integrations install claude
openwiki integrations install copilot
openwiki integrations install opencode
openwiki integrations install cursor
openwiki integrations install bob
openwiki integrations install kiro
openwiki integrations install omp
openwiki integrations install antigravity
```

安装之后重启 coding agent。然后打开仓库并询问：

```txt
Initialize this repository's OpenWiki from the current source and tests.
```

对于已有 wiki，询问：

```txt
Update this repository's OpenWiki for changes since its last successful run.
```

已安装的集成还会暴露[搜索与读取工具](/oss/openwiki/search-and-link)，让宿主无需启动生成运行即可查询已有的 wiki。

### 检查或卸载

```bash
openwiki integrations list
openwiki integrations uninstall <codex|claude|copilot|opencode|cursor|bob|kiro|omp|antigravity>
```

为 `list`、`install` 或 `uninstall` 添加 `--project [path]` 可以使用仓库作用域的 state。项目路径解析为 Git 仓库根目录。

各宿主的用户级安装位置：

- **OpenCode**：`~/.config/opencode`
- **IBM Bob / Bob Shell**：`~/.agents/skills` 和 `~/.bob/settings/mcp.json`（项目作用域使用 `.agents/skills` 和 `.bob/mcp.json`）
- **Kiro**：`~/.kiro/skills` 和 `~/.kiro/settings/mcp.json`
- **Oh My Pi**：默认 profile 位于 `~/.omp/agent`。命名 profile 或已迁移的 `PI_CODING_AGENT_DIR` 请使用 `--project`
- **Antigravity CLI**：`~/.gemini/antigravity-cli/skills` 和 `~/.gemini/config/mcp_config.json`

## Pi 包

Pi 从 npm 包加载 OpenWiki 的 skill 和生命周期工具：

```bash
pi install npm:openwiki
```

使用 `pi install --local npm:openwiki` 进行项目本地安装。Pi 扩展会通过 Node 启动 OpenWiki 的 CLI，因此 `openwiki` 不需要在 `PATH` 上。Pi 不是 `openwiki integrations install` 的目标。

## 宿主驱动的运行如何工作

宿主驱动的运行遵循与原生 `openwiki --init` 和 `openwiki --update` 相同的可恢复页面 job 生命周期。Coding agent 驱动仓库研究和页面编写；OpenWiki 通过 MCP 验证每次完成、持久化 [Grounded Claims](/oss/openwiki/code-mode#grounded-claims) 并最终化元数据。

在每个页面上，宿主提交稀疏的 Claim 决策（确认、修订、新增或撤回）。OpenWiki 保留未受影响的 Claims，应用显式决策，并拒绝在最终 Claims state 持久化之前完成。当宿主需要当前页面的完整 Claims 集合时，可以调用 `openwiki_inspect_page_claims`。
