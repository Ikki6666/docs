OpenWiki 提供本地只读的检索工具，让 coding agent 无需启动生成运行，即可从已有的 wiki 中回答具体问题。使用 `openwiki link` 将相关的仓库 wiki 分组到一个命名的 workspace，然后在该 workspace 范围内进行搜索和阅读。

## 搜索与阅读

让你的 coding agent 在 wiki 中查询一个问题：

```txt
Search this repository's OpenWiki for how retry handling works, then read the
relevant sections.
```

- **`openwiki_search`**：针对具体问题返回紧凑的排序结果
- **`openwiki_read`**：获取你的 agent 从这些结果中选中的完整小节

agent 会被引导针对具体的架构或依赖问题使用检索，阅读相关小节，并在有据可依后停止。检索是可选的上下文，而不是每个任务开始时的例行步骤。这些工具不依赖模型：它们既不会启动生成运行，也不会自行发起模型调用。

当仓库被链接到 workspace 后，`openwiki_list_workspaces` 和 `openwiki_list_wikis` 提供发现功能。workspace 搜索结果会标明提供结果的 `wiki`；请把该 ID 连同结果中的页面和小节锚点一起传给 `openwiki_read`。

这些工具随 [Coding-agent 集成](/oss/openwiki/integrations)一起提供。安装集成后，重启宿主并让它搜索 wiki。

## 创建 wiki workspace

一个服务往往横跨多个仓库。使用 `openwiki link` 将这些仓库已有的 wiki 分组到一个命名的 workspace，你的 agent 便可以在整个服务范围内搜索，并阅读任意成员 wiki 的小节。

在一个包含这些仓库的目录（例如 `~/dev`）中启动 workspace 管理器：

```bash
cd ~/dev
openwiki link
```

创建一个 workspace（例如 `Payments`），然后选择要纳入的仓库。成员仓库保留自己的 wiki，可以属于多个 workspace，也不需要共享同一个父目录。查找器会从启动目录开始，沿着一条可编辑的路径向下流式列出 Git 仓库。没有 OpenWiki 文档的仓库会显示为置灰。注册表存储在 `~/.openwiki` 下（或 `OPENWIKI_CONFIG_DIR`）。

### 搜索范围

搜索按以下规则确定范围：

1. 不属于任何 workspace 的 wiki 只搜索自身。
2. 属于单个 workspace 的 wiki 会自动搜索该 workspace。
3. 属于多个 workspace 的 wiki 使用其活跃的 workspace。
4. 如果它属于多个 workspace 且没有活跃选择，搜索会返回 `workspace_required`，由 agent 询问应使用哪个 workspace。

在仓库内的任意位置设置、查看或清除该仓库的持久活跃 workspace：

```bash
openwiki workspace use payments
openwiki workspace current
openwiki workspace clear
```
