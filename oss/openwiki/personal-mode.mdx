Personal 模式从已配置的来源（例如本地仓库、Custom MCP、Gmail、Notion、web search、Hacker News、Slack 和 X/Twitter）在 `~/.openwiki/wiki` 中构建一个本地个人 brain wiki。

```bash
openwiki personal
openwiki personal --init
openwiki personal --update
openwiki personal --update "Refresh the wiki from configured connectors"
```

要将个人 wiki state 存储在 `~/.openwiki` 以外的位置，请设置 `OPENWIKI_CONFIG_DIR`。请参见 [Customize OpenWiki](/oss/openwiki/customize#override-the-state-directory)。

## 首次运行 onboarding

在首次设置时，你可以：

- 配置 inference provider、API key 和模型
- 设置 LangSmith API key
- 为受支持的来源设置 connector
- 选择 wiki 模板、自定义其范围，并保存每个来源的摄取说明和计划

**Schedule** 是针对某个 connector 来源的可选 cron，例如按周期刷新 Gmail 或 web search。OpenWiki 将这些 cron 表达式和相关设置细节与 onboarding 偏好的其余部分（所选模板、已连接来源和每个来源的摄取说明）一起存储在 `~/.openwiki/onboarding.json` 中。全局个人 wiki 指令单独保存在 `~/.openwiki/INSTRUCTIONS.md` 中。

在 macOS 上，OpenWiki 可以将受支持的 schedule 安装为 `~/Library/LaunchAgents/` 下的用户 LaunchAgents。这些 job 会运行 `openwiki --update --print`，并将日志写入 `~/.openwiki/logs/` 下。

## 连接你的来源

在 personal 模式下，OpenWiki 会从你已经在使用的工具中摄取知识，并将它们合成到你位于 `~/.openwiki/wiki/` 的本地 wiki 中。首次运行 onboarding 可以设置 Custom MCP、本地 git 仓库、Notion、Gmail、X/Twitter、web search、Hacker News 和 Slack。

在摄取运行期间，connector 工具会将原始数据和 manifest 写入 `~/.openwiki/connectors/<connector>/raw/` 下，然后针对来源的 agent 运行会从这些本地文件更新 wiki。

Connector 密钥通过环境变量名引用，并存储在 `~/.openwiki/.env` 中。

<Important>
    Connector 配置文件中永远不应包含原始密钥值。
</Important>

### 内置来源

| 来源 | 凭据 | 行为 |
| --- | --- | --- |
| `custom-mcp` | 默认无需凭据 | 连接到任意已配置的 HTTP 或 stdio MCP server，并只允许显式安全的只读工具 |
| `git-repo` | 本地路径 | 读取已配置的本地仓库路径并写入紧凑的 manifest |
| `x` | OAuth user-context 凭据 | 通过 X API 获取 Home timeline、用户帖子、提及、书签和列表帖子 |
| `notion` | Notion OAuth（hosted MCP） | 通过 Notion OAuth 进行身份验证，而不是粘贴 Notion token |
| `google` | Gmail OAuth | 在 `openwiki auth gmail` 之后通过 Gmail API 获取最近的邮件 |
| `web-search` | `TAVILY_API_KEY` | 通过 LangChain 使用 Tavily |
| `hackernews` | 无 | 公开的 Hacker News feed 和搜索 API |
| `slack` | Slack app 客户端凭据 + OAuth | 需要为 OAuth 设置 HTTPS 回调；请参见 [Slack OAuth](#slack-oauth) |

你可以多次配置同一个来源。例如，添加一个用于 AI 研究的 web search 来源，再添加一个用于 NBA 新闻的。OpenWiki 会将它们存储为独立的实例，例如 `web-search-1` 和 `web-search-2`。

### 连接一个来源

对于需要凭据的来源，请先认证，再摄取。Hacker News 和 Custom MCP 等来源默认无需认证；web search 需要在 `~/.openwiki/.env` 中设置 `TAVILY_API_KEY`。

<Steps>
    <Step title="认证 provider" icon="key">
        为需要它的 provider 运行本地浏览器 OAuth 流程。OpenWiki 会将返回的 token 保存到 `~/.openwiki/.env`，在可能的情况下创建 connector 配置，并为基于 MCP 的 provider 发现 MCP 工具：

        ```bash
        openwiki auth notion
        openwiki auth gmail
        openwiki auth x
        openwiki auth slack
        ```

        - Slack 和 Gmail 要求 app 客户端凭据已经设置在 `~/.openwiki/.env` 中
        - Notion 为 hosted MCP 使用动态客户端注册
        - X 使用带 PKCE 的 OAuth 2.0
        - 在 `openwiki auth gmail` 之后，Google connector 可以直接摄取 Gmail，无需任何 MCP transport 设置

        高级 retry 辅助命令：

        ```bash
        openwiki auth configure <provider>
        openwiki auth tools <provider>
        ```
    </Step>

    <Step title="摄取该来源" icon="download">
        将原始数据拉取到 `~/.openwiki/connectors/`，并将更新合成到个人 wiki：

        ```bash
        openwiki ingest all
        openwiki ingest web-search
        openwiki ingest web-search-2
        ```

        在来源配置好之后，你也可以从聊天或使用 `openwiki personal --update` 刷新。
    </Step>
</Steps>

### Slack OAuth

Slack OAuth 可能需要 HTTPS 重定向 URL：

```bash
openwiki ngrok start
# or with a fixed domain:
openwiki ngrok start https://your-domain.ngrok.app
```

OpenWiki 会保存 `OPENWIKI_HTTPS_OAUTH_REDIRECT_URI` 并打印需要在 Slack 中注册的回调 URL。X/Twitter 和 Gmail 认证会忽略该 HTTPS 覆盖，并默认继续使用 `http://127.0.0.1:53682/callback` 的本地回调。

### 凭据存储

OpenWiki 将密钥存储在：

- 目录：`~/.openwiki`（权限 `0o700`）
- 文件：`~/.openwiki/.env`（权限 `0o600`）

常见的与 connector 相关的 key 包括 Gmail、Notion、Slack 和 X 的 OAuth token，以及用于 web search 的 `TAVILY_API_KEY`。可选的 OAuth 回调设置：

- `OPENWIKI_OAUTH_CALLBACK_PORT`：本地回调端口
- `OPENWIKI_HTTPS_OAUTH_REDIRECT_URI`：Slack HTTPS 回调 URL

模型 provider 凭据请参见 [Model providers](/oss/openwiki/providers)。

## 管理 schedule

在 macOS 上，使用以下命令管理 connector schedule：

```bash
openwiki cron list
openwiki cron pause <source|all>
openwiki cron resume <source|all>
openwiki cron delete <source|all>
```

`cron delete` 会从 `~/.openwiki/onboarding.json` 中移除某个来源的已保存 schedule，并卸载其 LaunchAgent。它不会移除认证、connector 配置、原始数据或 wiki 内容。
