通过声明式权限规则控制 agent 可以读取或写入哪些文件和目录。把规则列表传给 `permissions=`，agent 内置的文件系统工具就会遵守这些规则。

<Note>
    权限需要 `deepagents>=0.5.2`。
</Note>




权限只适用于内置文件系统工具（`ls`、`read_file`、`glob`、`grep`、`write_file`、`edit_file`、`delete`）。自定义工具和访问文件系统的 MCP 工具不受此限制。权限也不适用于 [sandbox backends](/oss/python/deepagents/sandboxes)，因为它们可以通过 `execute` 工具执行任意命令。




<Tip>
在你需要对内置文件系统工具做**基于路径的允许/拒绝规则**时，使用 `permissions`。在你需要自定义校验逻辑（速率限制、审计日志、内容检查）或者需要控制自定义工具时，使用 [backend policy hooks](/oss/python/deepagents/backends#add-policy-hooks)。
</Tip>

## 基本用法

把 `FilesystemPermission` 规则列表传给 [create_deep_agent](https://reference.langchain.com/python/deepagents/graph/create_deep_agent)。规则按声明顺序求值，第一个匹配的规则生效。如果没有任何规则匹配，操作就会被允许。

## 规则结构

每个 `FilesystemPermission` 都有三个字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `operations` | `list["read" \| "write"]` | 规则适用的操作。`"read"` 覆盖 `ls`、`read_file`、`glob`、`grep`。`"write"` 覆盖 `write_file`、`edit_file`、`delete`。 |
| `paths` | `list[str]` | 用于匹配文件路径的 glob 模式，例如 `["/workspace/**"]`。支持 `**` 递归匹配，以及 `{a,b}` 形式的分支匹配。 |
| `mode` | `"allow" \| "deny" \| "interrupt"` | 对匹配的操作是允许、拒绝还是暂停等待人工批准。默认值是 `"allow"`。见[等待人工批准](#pause-for-human-approval)。 |

规则使用 first-match-wins 评估：第一个 `operations` 和 `paths` 都匹配当前调用的规则会决定结果。如果没有规则匹配，该调用会被**允许**（宽松默认值）。





## 等待人工批准

<Note>
`"interrupt"` 模式需要 `deepagents>=0.6.8`。
</Note>

把 `mode="interrupt"` 设为暂停并等待人工批准，而不是直接允许或拒绝匹配的操作。当 agent 在与 interrupt 模式规则匹配的路径上调用内置写入工具（`write_file`、`edit_file`、`delete`）时，`create_deep_agent` 会抛出 human-in-the-loop 中断，而不是直接运行该工具；审核者可以批准、编辑或拒绝这次调用。

<PermissionsInterruptPy />

interrupt 模式规则会自动接入 agent 的 human-in-the-loop middleware，并与任何你传入的 `interrupt_on` 规则合并，所以你可以像处理工具调用中断那样处理和恢复它们。有关恢复流程，请参见 [Human-in-the-loop](/oss/python/deepagents/human-in-the-loop)。

<Note>
删除目录是全有或全无的：`delete` 会检查目标路径及其所有后代路径上的 `write` 权限。如果其中任意一个被拒绝，整个删除操作都会失败，而不是只删除树中的一部分。`delete` 对现有的空目录也会应用这种保守检查，因为它仍然是一个目录，而不是已确认的叶子目标。

删除普通文件则属于精确匹配的情况：`delete` 解析目标的方式与 `write_file` 和 `edit_file` 相同，采用首次匹配优先的评估方式，因此更早、更窄的 `allow` 规则会胜过更靠后的全量 `deny`。这种精确匹配行为需要 `deepagents>=0.7.3`。
</Note>

<Tip>
interrupt 模式最好使用字面量的前缀段进行锚定，例如 `/secrets/**` 或 `/projects/*/secrets/**`。批量工具（`ls`、`glob`、`grep`，以及针对目录的 `delete`）会在其搜索子树可能与规则锚定前缀重叠时触发中断，因此像 `/**/secrets` 这种完全不带锚点的模式会保守地过度触发。
</Tip>

## 子 agent 权限

[子 agent](/oss/python/deepagents/subagents) 默认继承父 agent 的权限。若要给子 agent 不同的权限，请在它的 spec 中设置 `permissions` 字段。这会**完全替换**父级规则。

<PermissionsSubagentPy />





## 复合 backend

当使用带有 sandbox 默认值的 [CompositeBackend](https://reference.langchain.com/python/deepagents/backends/composite/CompositeBackend) 时，每个权限路径都必须限定在一个已知的 route 前缀下。sandbox 支持任意命令执行，所以仅靠基于路径的限制无法阻止通过 shell 命令访问文件系统。把权限限定到 route 专属的 [backend](/oss/python/deepagents/backends) 上，可以避免这个冲突。
