---
title: 容错
description: 通过 rate limiting、retry、fallback 和错误处理让你的 deep agent 更具韧性
---

容错 middleware 会在出问题时保持你的 deep agent 继续运行。并非所有错误都应该以相同的方式处理：瞬时失败（网络超时、rate limits）应该自动 retry，LLM 可以从中恢复的错误（错误的工具输出、解析失败）应该反馈给模型，而需要人工介入的错误应该暂停 agent。

## 错误处理策略

不同的错误需要不同的处理策略：

| 错误类型 | 由谁处理 | 策略 | Middleware 或功能 |
|------------|--------------|----------|----------------------|
| 瞬时错误（网络问题、rate limits） | 系统（自动） | 使用指数退避 retry | [ModelRetryMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/model_retry/ModelRetryMiddleware), [ToolRetryMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/tool_retry/ToolRetryMiddleware) |
| LLM 可恢复的错误（工具失败、解析问题） | LLM | 转换为错误 `ToolMessage` 并让模型调整 | [ToolErrorMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/tool_error/ToolErrorMiddleware) |
 | 用户可修复的错误（缺少信息、指令不清晰） | 人工 | 使用 `interrupt()` 暂停 | [Human-in-the-loop](/oss/python/deepagents/human-in-the-loop) |
| Provider 宕机 | 系统（自动） | 回退到备用模型 | [ModelFallbackMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/model_fallback/ModelFallbackMiddleware) |
| 过度调用（失控循环） | 系统（自动） | 限制每次运行的模型和工具调用次数 | [ModelCallLimitMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/model_call_limit/ModelCallLimitMiddleware), [ToolCallLimitMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/tool_call_limit/ToolCallLimitMiddleware) |
| 意外错误 | 开发者 | 让它们向上冒泡 | 无 middleware；让异常传播 |

以下章节将通过代码示例介绍每种策略。

<Tabs>
  <Tab title="瞬时错误" icon="rotate">

  添加 retry middleware 可以自动 retry 网络问题和 rate limits。模型调用和工具调用各自有带指数退避的 retry middleware：

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ModelRetryMiddleware, ToolRetryMiddleware

agent = create_agent(
    model="google_genai:gemini-3.6-flash",
    tools=[search_tool, fetch_url_tool],
    middleware=[
        ModelRetryMiddleware(max_retries=3, backoff_factor=2.0, initial_delay=1.0),
        ToolRetryMiddleware(
            max_retries=2,
            tools=["search", "fetch_url"],
            retry_on=(TimeoutError, ConnectionError),
        ),
    ],
)
```




  </Tab>

  <Tab title="LLM 可恢复" icon="brain">

  使用 [ToolErrorMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/tool_error/ToolErrorMiddleware) 捕获工具异常并将它们转换为错误 `ToolMessage`，让 LLM 可以看到出了什么问题并再次尝试：

  <Note>
  `ToolErrorMiddleware` 需要 `langchain>=1.3.14`。
  </Note>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ToolErrorMiddleware


def on_error(exc: Exception, request: ToolCallRequest) -> str | None:
    if isinstance(exc, ValueError):
        return f"Tool `{request.tool_call['name']}` failed: {type(exc).__name__}. Fix the input and retry."
    # propagate everything else


agent = create_agent(
    model="google_genai:gemini-3.6-flash",
    tools=[search_tool],
    middleware=[ToolErrorMiddleware(on_error)],
)
```

  </Tab>


  <Tab title="用户可修复" icon="user">

  在需要时暂停并从用户那里收集信息（例如账户 ID、订单号或澄清）。使用 `interrupt_on` 在特定的 tool calls 之前暂停 agent：

```python
from deepagents import create_deep_agent

agent = create_deep_agent(
    model="google_genai:gemini-3.6-flash",
    tools=[send_email_tool, delete_record_tool],
    interrupt_on={
        "send_email": True,
        "delete_record": True,
    },
)
```




  完整的 human-in-the-loop 指南请参见 [Human-in-the-loop](/oss/python/deepagents/human-in-the-loop)。

  </Tab>

  <Tab title="Provider 宕机" icon="arrows-exchange">

  如果你的主模型 provider 完全宕机，使用 [ModelFallbackMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/model_fallback/ModelFallbackMiddleware) 切换到备用模型：

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ModelFallbackMiddleware

agent = create_agent(
    model="google_genai:gemini-3.6-flash",
    tools=[search_tool],
    middleware=[
        ModelFallbackMiddleware("gpt-5.5"),
    ],
)
```




  </Tab>

  <Tab title="过度调用" icon="gauge">

  没有限制时，一个混乱的 agent 可能通过在同一个 tool call 上循环或发起数百次模型调用，在几分钟内耗尽你的 LLM API 预算。为每次运行的模型调用和工具执行都设置上限：

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ModelCallLimitMiddleware, ToolCallLimitMiddleware

agent = create_agent(
    model="google_genai:gemini-3.6-flash",
    tools=[search_tool],
    middleware=[
        ModelCallLimitMiddleware(run_limit=50),
        ToolCallLimitMiddleware(run_limit=200),
    ],
)
```




  </Tab>

  <Tab title="意外错误" icon="alert-triangle">

  让它们向上冒泡以便调试。不要捕获你无法处理的东西。[ToolErrorMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/tool_error/ToolErrorMiddleware) 只会呈现你显式为其返回内容的异常；其他一切都会原样传播：

```python
def on_error(exc: Exception, request: ToolCallRequest) -> str | None:
    if isinstance(exc, (ValueError, KeyError)):
        # Surface known, recoverable errors to the model
        return f"Tool `{request.tool_call['name']}` failed: {type(exc).__name__}."
    # Everything else (unexpected errors) propagates and halts the run
```




  </Tab>
</Tabs>

## Rate limiting

有两种互补的方式来限制资源使用：控制发往模型 provider 的请求速率，以及限制每次运行的总调用次数。

### Provider rate limiting

Chat model provider 会对给定时间段内可以发起的调用次数施加限制。要控制请求发出的速率，请在初始化模型时使用 `rate_limiter`：

```python
from langchain.rate_limiters import InMemoryRateLimiter
from langchain.chat_models import init_chat_model

rate_limiter = InMemoryRateLimiter(
    requests_per_second=0.1,  # 1 request every 10s
    check_every_n_seconds=0.1,  # Check every 100ms whether allowed to make a request
    max_bucket_size=10,  # Controls the maximum burst size
)

model = init_chat_model(
    model="google_genai:gemini-3.6-flash",
    rate_limiter=rate_limiter,  # [!code highlight]
)

agent = create_deep_agent(model=model, tools=[search_tool])
```


完整配置请参见 [Rate limiting](/oss/python/langchain/models#rate-limiting)。


### 调用限制

没有限制时，一个混乱的 agent 可能通过在同一个 tool call 上循环或发起数百次模型调用，在几分钟内耗尽你的 LLM API 预算。为每次运行的模型调用和工具执行都设置上限：

```python
from deepagents import create_deep_agent
from langchain.agents.middleware import ModelCallLimitMiddleware, ToolCallLimitMiddleware

agent = create_deep_agent(
    model="google_genai:gemini-3.6-flash",
    middleware=[
        ModelCallLimitMiddleware(run_limit=50),
        ToolCallLimitMiddleware(run_limit=200),
    ],
)
```




使用 `run_limit` 限制单次调用中的调用次数（每回合重置）。使用 `thread_limit` 限制整个对话中的调用次数（需要 checkpointer）。完整配置请参见 [ModelCallLimitMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/model_call_limit/ModelCallLimitMiddleware) 和 [ToolCallLimitMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/tool_call_limit/ToolCallLimitMiddleware)。

## Retries

瞬时失败（网络超时、rate limits）应该自动 retry。模型调用和工具调用各自有带指数退避的 retry middleware：

```python
from deepagents import create_deep_agent
from langchain.agents.middleware import ModelRetryMiddleware, ToolRetryMiddleware

agent = create_deep_agent(
    model="google_genai:gemini-3.6-flash",
    middleware=[
        # Retry model calls on rate limits, timeouts, and 5xx errors
        ModelRetryMiddleware(max_retries=3, backoff_factor=2.0, initial_delay=1.0),
        # Retry specific tools that hit external APIs (not all tools)
        ToolRetryMiddleware(
            max_retries=2,
            tools=["search", "fetch_url"],
            retry_on=(TimeoutError, ConnectionError),
        ),
    ],
)
```




将 [ToolRetryMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/tool_retry/ToolRetryMiddleware) 限定到特定工具，而不是 retry 所有内容。失败的文件系统 `read_file` 无法从 retry 中受益，但超时的 web search 很可能可以。完整配置请参见 [ModelRetryMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/model_retry/ModelRetryMiddleware)。

<Note>
主要集成包会抛出标准异常类型（[ModelAuthenticationError](https://reference.langchain.com/python/langchain-core/exceptions/ModelAuthenticationError)、[ModelRateLimitError](https://reference.langchain.com/python/langchain-core/exceptions/ModelRateLimitError)、[ModelTimeoutError](https://reference.langchain.com/python/langchain-core/exceptions/ModelTimeoutError) 等），它们带有 retry middleware 默认会遵循的 `is_retryable` 标志。完整列表请参见 [Model exceptions](/oss/python/langchain/models#model-exceptions)。
</Note>


## Fallbacks

如果你的主模型 provider 完全宕机，fallback middleware 会切换到备用模型：

```python
from deepagents import create_deep_agent
from langchain.agents.middleware import ModelFallbackMiddleware

agent = create_deep_agent(
    model="google_genai:gemini-3.6-flash",
    middleware=[
        # If the primary model is fully down, fall back to an alternative
        ModelFallbackMiddleware("gpt-5.5"),
    ],
)
```




完整配置请参见 [ModelFallbackMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/model_fallback/ModelFallbackMiddleware)。

## 错误处理

当工具在执行期间抛出异常时，agent 运行默认会停止。使用 [ToolErrorMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/tool_error/ToolErrorMiddleware) 捕获特定异常并将它们转换为模型可以看到并从中恢复的错误 ToolMessages，而不是让运行崩溃。

<Note>
`ToolErrorMiddleware` 需要 `langchain>=1.3.14`。
</Note>

```python
from deepagents import create_deep_agent
from langchain.agents.middleware import ToolErrorMiddleware


def on_error(exc: Exception, request: ToolCallRequest) -> str | None:
    if isinstance(exc, ValueError):
        return f"`{request.tool_call['name']}` failed with {type(exc).__name__}."
    # propagate everything else


agent = create_deep_agent(
    model="google_genai:gemini-3.6-flash",
    middleware=[ToolErrorMiddleware(on_error)],
)
```

完整的配置选项和使用模式（包括异步 handler 以及与 retry middleware 组合）请参见 [Prebuilt middleware](/oss/python/langchain/middleware/built-in#tool-error)。
