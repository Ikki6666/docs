<Tip>
对于新应用程序，我们推荐[事件流](/oss/python/deepagents/event-streaming)——Deep Agents v0.6 中引入的类型化投影 API。事件流为每个投影提供单独的迭代器（子代理、消息、工具调用、值），因此您可以独立使用它们，而不是在“stream_mode”块上分支。
</Tip>
Deep Agents 构建在 LangGraph 的流基础设施之上，为子代理流提供一流的支持。当深度代理将工作委托给子代理时，您可以独立地传输来自每个子代理的更新 - 实时跟踪进度、LLM 令牌和工具调用。

深度代理流可以实现什么：

* [**流子代理进度**](#subagent-progress)—跟踪每个子代理并行运行时的执行情况。
* [**流式传输 LLM 令牌**](#llm-tokens)—从主代理和每个子代理流式传输令牌。
* [**流工具调用**](#tool-calls)—查看子代理执行中的工具调用和结果。
* [**流自定义更新**](#custom-updates)—从内部子代理节点发出用户定义的信号。

## 启用子图流

深度代理使用 LangGraph 的子图流来显示子代理执行中的事件。要接收子代理事件，请在流式传输时启用“stream_subgraphs”。
<StreamingSubgraphsEnablePy />



## 命名空间

启用“子图”时，每个流事件都包含一个**命名空间**，用于标识哪个代理生成了它。命名空间是代表代理层次结构的节点名称和任务 ID 的路径。

|命名空间 |来源 |
| ---------| ------ |
| `()`（空）|主代理|
| `("工具：abc123",)` |由主代理的“任务”工具调用“abc123”生成的子代理 |
| `（“工具：abc123”，“model_request：def456”）` |子代理内的模型请求节点 |

使用命名空间将事件路由到正确的 UI 组件：
<StreamingNamespacesPy />



## 子代理进度

使用 `stream_mode="updates"` 来跟踪每个步骤完成时的子代理进度。这对于显示哪些子代理处于活动状态以及它们已完成哪些工作非常有用。
<StreamingSubagentProgressPy />

```shell title="Output"
[main agent] step: model_request
  [tools:call_abc123] step: model_request
  [tools:call_abc123] step: tools
  [tools:call_abc123] step: model_request

Subagent complete: task
  Result: ## AI Safety Report...
[main agent] step: model_request
```

### 处理 human-in-the-loop 中断

当配置了 [`interrupt_on`](/oss/python/deepagents/human-in-the-loop) 时，`updates` 流可能包含暂停执行以等待人工批准的 `__interrupt__` 条目。通过检查更新块中的 `__interrupt__` 键来检测它们。使用与 `.invoke()` 相同的扁平 `{"decisions": [...]}` 负载恢复执行：

```python
from langchain_core.utils.uuid import uuid7

config = {"configurable": {"thread_id": str(uuid7())}}

for mode, data in agent.stream(
    {"messages": [{"role": "user", "content": "Delete temp.txt"}]},
    stream_mode=["messages", "updates"],
    config=config,
):
    if mode == "updates" and isinstance(data, dict):
        if "__interrupt__" in data:  # [!code highlight]
            for interrupt_obj in data["__interrupt__"]:
                print(f"Approval needed: {interrupt_obj.value}")
```




完整的流恢复循环模式请参见 [Human-in-the-loop: Handle interrupts with streaming](/oss/python/deepagents/human-in-the-loop#handle-interrupts-with-streaming)。

## 流块形状

使用 `subgraphs=True` 时，块形状取决于传入一种还是多种流模式：

| `stream_mode` | 块形状 |
| ------------- | ----------- |
| 单一模式（例如 `"updates"`） | `(namespace, data)` |
| 多种模式（例如 `["messages", "updates"]`） | `(namespace, mode, data)` |

不使用 `subgraphs` 时，单一模式直接返回 `data`，多种模式返回 `(mode, data)`。

```python
# Single mode + subgraphs
for namespace, data in agent.stream(
    {"messages": [{"role": "user", "content": "Research quantum computing"}]},
    stream_mode="updates",
    subgraphs=True,
):
    print(namespace)  # () for main agent, ("tools:<id>",) for subagent
    print(data)

# Multiple modes + subgraphs
for namespace, mode, data in agent.stream(
    {"messages": [{"role": "user", "content": "Research quantum computing"}]},
    stream_mode=["updates", "messages", "custom"],
    subgraphs=True,
):
    print(mode)       # "updates", "messages", or "custom"
    print(namespace)  # () for main agent, ("tools:<id>",) for subagent
    print(data)
```

LangGraph 1.1 及更高版本还支持统一的 `version="v2"` `StreamPart` 字典格式。参见 [Stream output format (v2)](/oss/python/langgraph/streaming#stream-output-format-v2)。本页上的 Deep Agents 示例使用元组格式，这与 Deep Agents 当前依赖的 LangGraph 版本一致。
