## System prompt

Deep Agents 自带一个内置的 base system prompt，教会 agent 如何使用 harness 脚手架（规划、文件系统工具、子 agent）。传入 `system_prompt=` 可以把自己的 instructions 放到该 base prompt 之前：

<CustomizationSystemPromptPy />




当 middleware 添加特殊工具时，例如文件系统工具，它会在运行时把自己的引导追加到 system prompt 中。

<Note>
`SystemPromptConfig` 要求 `deepagents>=0.7.0a6`。
</Note>

若要完整控制 prompt 组装，请传入一个带 `prefix`、`base` 和 `suffix` key 的 @[SystemPromptConfig] dict：

- **`prefix`**：放在 base prompt 之前的文本（与直接传入字符串相同）。
- **`base`**：替换内置的 base prompt。省略该 key 会保留内置 base，把它设为 `None` 则完全去掉 base。
- **`suffix`**：放在 base prompt 之后的文本。

各部分按以下顺序组装：`prefix` -> `base` -> `suffix` -> 任何按模型定制的 [profile](/oss/python/deepagents/profiles) suffix。每个部分都接受 `str` 或 `SystemMessage`（为 Anthropic prompt caching 保留 `cache_control` 标记）。

```python
# 覆盖默认 base prompt：
create_deep_agent(..., system_prompt={"base": "..."})

# 除 middleware 外不设置 system prompt：
create_deep_agent(..., system_prompt={"base": None})

# 把默认 base prompt 夹在中间：
create_deep_agent(..., system_prompt={"prefix": "...", "suffix": "..."})
```

如果要做按模型定制的 system prompt 定制，例如为某个 provider 替换 base prompt 或追加 suffix，请使用 [harness profile](/oss/python/deepagents/profiles#harness-profiles)。


<AccordionGroup>
    <Accordion title="子 agent prompts">
        声明式 [subagents](/oss/python/deepagents/subagents) 会针对自己的模型解析 profile 覆盖，然后把解析得到的 `base_system_prompt` / `system_prompt_suffix` 应用到子 agent 作者编写的 `system_prompt` 上。只带 `system_prompt_suffix` 的 profile（内置 Anthropic / OpenAI profile 的常见情况）只是追加到作者写的 prompt 后面。设置了 `base_system_prompt` 的 profile 会直接替换它。
    </Accordion>
    <Accordion title="通用子 agent prompt">
        自动添加的[通用子 agent](/oss/python/deepagents/subagents#the-general-purpose-subagent) 会把它的 base prompt 解析为 **`general_purpose_subagent.system_prompt`（如果设置了）-> `HarnessProfile.base_system_prompt`（如果设置了）-> SDK 通用默认值**，并把 profile suffix 叠加在上面。当两个覆盖字段都设置时，通用子 agent 专属的那个会获胜，这样同时调这两个字段的调用方就不会发现自己的 GP 覆盖被悄悄丢掉：

        <CustomizationGpSubagentProfilePy />

        | Stack | 最终 system prompt |
        | ----- | ------------------- |
        | Main agent | `"You are ACME's support orchestrator." + SUFFIX` |
        | GP subagent | `"You are a research subagent. Cite sources." + SUFFIX` |
    </Accordion>
</AccordionGroup>

## Middleware

Deep Agents 支持任意 [middleware](/oss/python/langchain/middleware/overview)，包括下方列出的内置 middleware、LangChain 的 prebuilt middleware、provider-specific middleware，以及你自己编写的自定义 middleware。

把 middleware 传给 `create_deep_agent` 的 `middleware` 参数。每个实例都会先按 `.name` 与 [Deep Agents 栈](#deep-agents-stack)中的内置条目匹配：匹配到时会原位替换该实例，未匹配到的条目则会插入到 [`PatchToolCallsMiddleware`](https://reference.langchain.com/python/deepagents/middleware/patch_tool_calls/PatchToolCallsMiddleware) 之后。请参见[覆盖默认 middleware 实例](#override-a-default-middleware-instance)。




### Deep Agents 栈

`create_deep_agent` 会以固定顺序构建 middleware。[bare stack](#bare-stack) 是你只传入 model 时得到的内容。[full stack](#full-stack) 是完整的组装顺序，包括仅在你传入可选参数时才会出现的槽位，以及解析后的 [harness profile](/oss/python/deepagents/profiles) 贡献的槽位。




#### Bare stack

在只传入 `model`（不传其他可选参数）时，主 agent 通常包含：

1. [`FilesystemMiddleware`](https://reference.langchain.com/python/deepagents/middleware/filesystem/FilesystemMiddleware)
2. [`SubAgentMiddleware`](https://reference.langchain.com/python/deepagents/middleware/subagents/SubAgentMiddleware)（因为[通用子 agent](/oss/python/deepagents/subagents#default-subagent) 默认会被自动添加，除非 harness profile 禁用了它）
3. [`SummarizationMiddleware`](https://reference.langchain.com/python/langchain/agents/middleware/summarization/SummarizationMiddleware)
4. [`PatchToolCallsMiddleware`](https://reference.langchain.com/python/deepagents/middleware/patch_tool_calls/PatchToolCallsMiddleware)
5. **Prompt caching** middleware（始终注册；每个条目在不支持的模型上 no-op）
6. **Harness profile 额外项**和**排除工具过滤**，如果解析后的模型 profile 定义了它们




#### Full stack

从前到后：

1. [TodoListMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/todo/TodoListMiddleware)：跟踪并管理 todo 列表，用于组织 agent 任务和工作。
2. [FilesystemMiddleware](https://reference.langchain.com/python/deepagents/middleware/filesystem/FilesystemMiddleware)：处理读写和目录导航等文件系统操作。当你传入 `permissions` 时，文件系统权限 enforcement 也会包含在这里，这样它就能评估 agent 可能调用的每个工具。
3. [SubAgentMiddleware](https://reference.langchain.com/python/deepagents/middleware/subagents/SubAgentMiddleware)：仅当至少存在一个同步子 agent 时启用。派生并协调子 agent，用于委派任务。它被包含在 [bare stack](#bare-stack) 中，因为通用子 agent 默认会被自动添加；要省略它，请禁用该子 agent 并且不传入同步 `subagents`。参见[在没有子 agent 的情况下运行](/oss/python/deepagents/subagents#running-without-subagents)。
4. [SummarizationMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/summarization/SummarizationMiddleware)：当对话变长时压缩消息历史，以保持在上下文限制内（通过 [create_summarization_middleware](https://reference.langchain.com/python/deepagents/middleware/summarization/create_summarization_middleware)）。
5. [PatchToolCallsMiddleware](https://reference.langchain.com/python/deepagents/middleware/patch_tool_calls/PatchToolCallsMiddleware)：当运行在中断后恢复，或者收到格式不正确的 tool-call 参数时，修复消息历史中悬空的工具调用。它会在 Anthropic prompt caching 和下面的尾部堆栈之前运行。
6. [AsyncSubAgentMiddleware](https://reference.langchain.com/python/deepagents/middleware/async_subagents/AsyncSubAgentMiddleware)：仅在你配置 async subagent 时启用。
7. **你的 middleware 参数**：你通过 `middleware` 参数传入的可选 middleware 会在 Patch 之后、堆栈其余部分之前合并进来。如果实例的 `.name` 与上面某个内置条目匹配，就会原位替换该实例而不是重复添加；其余的则落在这里。请参见[覆盖默认 middleware 实例](#override-a-default-middleware-instance)。
8. **Harness profile 额外项**：来自解析后模型 profile 的 provider-specific middleware（如果有）。
9. [SkillsMiddleware](https://reference.langchain.com/python/deepagents/middleware/skills/SkillsMiddleware)：仅在你传入 `skills` 时启用。它在你的 middleware 之后、prompt caching 之前运行，因此能看到总结后的对话和实际调用的模型。传入名为 `SkillsMiddleware` 的 middleware 会原位替换它。
10. **Prompt caching**（[AnthropicPromptCachingMiddleware](https://reference.langchain.com/python/langchain-anthropic/middleware/prompt_caching/AnthropicPromptCachingMiddleware) 和 [BedrockPromptCachingMiddleware](https://reference.langchain.com/python/langchain-aws/middleware/prompt_caching/BedrockPromptCachingMiddleware)）：两者都会始终注册，并在 Patch 和你的 middleware 之后运行，这样缓存前缀就与实际发送给模型的内容一致。它们会在不支持的模型上 no-op（`unsupported_model_behavior="ignore"`），因此 Anthropic middleware 作用于 Anthropic 模型，Bedrock middleware 作用于支持缓存的 AWS Bedrock 模型。
11. [MemoryMiddleware](https://reference.langchain.com/python/deepagents/middleware/memory/MemoryMiddleware)：仅在你传入 `memory` 时启用。

    <Note>
    `MemoryMiddleware` 被放在 profile 额外项和 prompt caching middleware 之后，这样注入的 memory 更新就更不容易让缓存前缀失效。`create_deep_agent` 的实现注释里也说明了同样的顺序考量。
    </Note>

12. `HumanInTheLoopMiddleware`：仅在你传入 `interrupt_on` 时启用。在配置好的工具调用处暂停，等待人工批准或输入。
13. **排除工具过滤**：当 harness profile 列出 excluded tools 时，middleware 会把这些工具从 agent 中移除。





### 同步子 agent 堆栈

内置的**通用**子 agent 和每个声明式同步 `SubAgent` graph 都使用 `create_deep_agent` 在代码中构建的堆栈。它与主 agent 在大方向上保持一致（todo list、文件系统、摘要、Patch、profile 额外项、skills、Anthropic 和 Bedrock 缓存、可选权限），只是子 agent graph 内部**没有** [SubAgentMiddleware](https://reference.langchain.com/python/deepagents/middleware/subagents/SubAgentMiddleware)（只有父 agent 暴露 `task` 工具）。

当声明式子 agent 设置 `interrupt_on` 时，该值会传给子 agent 的 `create_agent`，从而为配置好的工具调用接入 human-in-the-loop 处理。

`deepagents` library 还提供 [create_summarization_tool_middleware](https://reference.langchain.com/python/deepagents/middleware/summarization/create_summarization_tool_middleware)，让 agent 能在合适的时机触发摘要，例如在任务之间，而不是按固定 token 间隔触发。更多细节请参见 [Summarization](/oss/python/deepagents/context-engineering#summarization)。

### 覆盖默认 middleware 实例

<Note>
通过匹配 `.name` 来覆盖默认 middleware 需要 `deepagents>=0.7.0a3`。
</Note>

传入一个 `.name` 与 [Deep Agents 栈](#deep-agents-stack)中的某个条目匹配的 middleware 实例，例如 [`SummarizationMiddleware`](https://reference.langchain.com/python/langchain/agents/middleware/summarization/SummarizationMiddleware)，就可以原位替换该内置实例，而不是再追加一个重复实例。任何你传入但 `.name` **不**匹配内置条目的 middleware 都不会被替换，它会落在最后一个核心 middleware 之后、profile、prompt caching 和 memory 之前。完整顺序请参见 [Full stack](#full-stack)。

```python
from deepagents import create_deep_agent
from deepagents.backends import StateBackend
from deepagents.middleware import SummarizationMiddleware

backend = StateBackend()
model = "openai:gpt-5.5"

custom_summarization = SummarizationMiddleware(
    model=model,
    backend=backend,
    summary_prompt="Your custom summary prompt here.",
)

agent = create_deep_agent(
    model=model,
    middleware=[custom_summarization],  # replaces the default SummarizationMiddleware
)
```

<Note>
覆盖会**替换**默认 middleware 实例，而不是与之合并。这意味着你的替代实例必须自行带上所需的全部配置。对 `FilesystemMiddleware` 来说这一点尤其重要：如果你覆盖它，必须把 `backend`（以及适用时的 `permissions`）直接传给你的自定义实例，因为它不会继承传给 `create_deep_agent()` 的 `backend=` 和 `permissions=`。如果你想限制可用的文件系统工具，请给自定义 [`FilesystemMiddleware`](https://reference.langchain.com/python/deepagents/middleware/filesystem/FilesystemMiddleware) 实例传入 `tools` allowlist；示例见[虚拟文件系统访问](/oss/python/deepagents/overview#virtual-filesystem-access)中的“限制文件系统工具”。

</Note>

Deep Agents 自动添加的通用子 agent 会继承主 agent 对其默认 middleware 的覆盖，但不会携带主 agent 专用的 middleware。

通过 `subagents=` 定义的声明式子 agent 不会继承主 agent 的 middleware 自定义。若要在子 agent 上应用覆盖，请直接把覆盖项传进该子 agent 自己的 [`middleware`](/oss/python/deepagents/subagents#subagent-dictionary-based) 字段；这个字段会针对[同步子 agent 堆栈](#synchronous-subagent-stack)执行匹配，就像主 agent 的 `middleware=` 针对主 agent 进行匹配一样。

#### 示例

<AccordionGroup>
    <Accordion title="调整摘要触发时机" icon="adjustments">
        用自定义的 `trigger` 和 `keep` 阈值覆盖 [`SummarizationMiddleware`](https://reference.langchain.com/python/langchain/agents/middleware/summarization/SummarizationMiddleware)，可以让对话历史比默认更早或更晚被压缩，并控制每次压缩后保留下来的最近消息数量。

        ```python
        from deepagents import create_deep_agent
        from deepagents.backends import StateBackend
        from deepagents.middleware import SummarizationMiddleware

        backend = StateBackend()
        model = "anthropic:claude-sonnet-4-6"

        agent = create_deep_agent(
            model=model,
            middleware=[
                SummarizationMiddleware(
                    model=model,
                    backend=backend,
                    trigger=("tokens", 100000),  # summarize once the conversation exceeds 100k tokens
                    keep=("messages", 20),  # keep the most recent 20 messages verbatim
                ),
            ],
        )
        ```

        `trigger` 也接受 `("fraction", ...)`，表示模型上下文窗口的某个百分比，而阈值列表会用 OR 语义组合。完整选项请参见 [`SummarizationMiddleware`](https://reference.langchain.com/python/langchain/agents/middleware/summarization/SummarizationMiddleware) reference。
    </Accordion>
    <Accordion title="更新 prompt cache TTL" icon="clock">
        覆盖 [`AnthropicPromptCachingMiddleware`](https://reference.langchain.com/python/langchain-anthropic/middleware/prompt_caching/AnthropicPromptCachingMiddleware) 以把缓存生命周期延长到默认 `5m` TTL 之外，这对轮次间隔较长的 agent 很有用。关于默认缓存应用方式，请参见 [Prompt caching](/oss/python/deepagents/overview#prompt-caching)。

        ```python
        from deepagents import create_deep_agent
        from langchain_anthropic.middleware import AnthropicPromptCachingMiddleware

        agent = create_deep_agent(
            model="anthropic:claude-sonnet-4-6",
            middleware=[
                AnthropicPromptCachingMiddleware(ttl="1h"),  # replaces the default 5m TTL
            ],
        )
        ```
    </Accordion>
    <Accordion title="自定义 system prompt 中的文件系统指令" icon="file-text">
        用 `system_prompt` 覆盖 [`FilesystemMiddleware`](https://reference.langchain.com/python/deepagents/middleware/filesystem/FilesystemMiddleware)，即可把它追加到 system prompt 中的文件系统专属指令替换为你自己的文本，而不是使用动态生成的默认内容。

        ```python
        from deepagents import create_deep_agent
        from deepagents.backends import StateBackend
        from deepagents.middleware import FilesystemMiddleware

        backend = StateBackend()

        agent = create_deep_agent(
            model="anthropic:claude-sonnet-4-6",
            backend=backend,
            middleware=[
                FilesystemMiddleware(
                    backend=backend,
                    system_prompt="Use the virtual filesystem to track long-running work. Write intermediate results to files instead of repeating them in messages.",
                ),
            ],
        )
        ```

        与任何 [`FilesystemMiddleware`](https://reference.langchain.com/python/deepagents/middleware/filesystem/FilesystemMiddleware) 覆盖一样，请传入和其他地方相同的 `backend`（以及适用时的 `permissions`），因为覆盖项不会与默认实例合并。
    </Accordion>
    <Accordion title="自定义 task 工具描述" icon="message">
        用 `task_description` 覆盖 [`SubAgentMiddleware`](https://reference.langchain.com/python/deepagents/middleware/subagents/SubAgentMiddleware)，即可替换 `task` 工具的描述，例如引导模型决定何时应该委派。这个覆盖会直接替换默认堆栈，因此你需要重新声明传给 `create_deep_agent` 的相同 `backend` 和 `subagents`。自动添加的[通用子 agent](/oss/python/deepagents/subagents#the-general-purpose-subagent) 不会自动包含在内，除非你自己补上等价条目。

        ```python
        from deepagents import create_deep_agent
        from deepagents.backends import StateBackend
        from deepagents.middleware import SubAgentMiddleware

        backend = StateBackend()
        model = "anthropic:claude-sonnet-4-6"
        researcher = {
            "name": "researcher",
            "description": "Researches a topic and returns findings.",
            "system_prompt": "You are a researcher.",
            "model": model,
            "tools": [search],
        }

        agent = create_deep_agent(
            model=model,
            subagents=[researcher],
            middleware=[
                SubAgentMiddleware(
                    backend=backend,
                    subagents=[researcher],
                    task_description="Delegate research to the `researcher` subagent only for multi-step lookups.",
                ),
            ],
        )
        ```

        `task_description` 还支持 `available_agents` 模板占位符，运行时会用子 agent 名称和描述列表填充；细节请参见 [`SubAgentMiddleware`](https://reference.langchain.com/python/deepagents/middleware/subagents/SubAgentMiddleware) reference。若你只是想更窄地改写 `task` 工具描述，而不替换整个子 agent 堆栈，也可以改用 [harness 配置档案](/oss/python/deepagents/profiles#harness-profiles) 中的 `tool_description_overrides`，参见 [Profiles](#profiles)。
    </Accordion>
    <Accordion title="自定义 skill catalog 在 system prompt 中的呈现方式" icon="template">
        用自定义的 `system_prompt=` 模板覆盖 [`SkillsMiddleware`](https://reference.langchain.com/python/deepagents/middleware/skills/SkillsMiddleware)，可以控制自动生成的 skill catalog 的呈现方式，例如添加上下文、调整段落顺序，或者把路由提示（优先级、类别偏好）放进 catalog 所在的同一个块中。模板必须包含 `{skills_locations}`、`{skills_list}` 和 `{skills_load_warnings}` 占位符，middleware 会在每一轮替换它们，因此在添加、重命名或删除 skills 时，catalog 会自动保持同步。

        下面的示例把路由提示放在 catalog 旁边：

        ```python
        from deepagents import create_deep_agent
        from deepagents.backends.filesystem import FilesystemBackend
        from deepagents.middleware.skills import SkillsMiddleware

        backend = FilesystemBackend(root_dir="/path/to/skills")

        custom_skills_prompt = """## Skills

        Routing hints:
        - For research topics → prefer arxiv-search first
        - For general questions → use web-research
        - For LangGraph documentation → langgraph-docs

        {skills_locations}

        {skills_list}

        {skills_load_warnings}
        """

        agent = create_deep_agent(
            model="anthropic:claude-sonnet-4-6",
            middleware=[
                SkillsMiddleware(
                    backend=backend,
                    sources=["/path/to/skills"],
                    system_prompt=custom_skills_prompt,
                ),
            ],
        )
        ```

        在这种情况下，不要再向 `create_deep_agent` 传入 `skills=`：覆盖实例已经拥有 `backend` 和 `sources`。缺少任何占位符（`{skills_locations}`、`{skills_list}`、`{skills_load_warnings}`）都会在构造时抛出 `ValueError`。
    </Accordion>
    <Accordion title="屏蔽自动生成的 skill catalog" icon="eye-off">
        用 `system_prompt=None` 覆盖 [`SkillsMiddleware`](https://reference.langchain.com/python/deepagents/middleware/skills/SkillsMiddleware)，可以在完全不向 system prompt 追加 skills 段落的情况下加载 skills。Skills 仍保留在 `state["skills_metadata"]` 中，skill 文件仍可通过文件系统工具访问，因此希望在 `create_deep_agent(system_prompt=...)` 中自己编写描述块（例如一段简短的手写路由摘要）的调用方，可以只添加所需的指引，而不使用内置的那一份。

        ```python
        from deepagents import create_deep_agent
        from deepagents.backends.filesystem import FilesystemBackend
        from deepagents.middleware.skills import SkillsMiddleware

        backend = FilesystemBackend(root_dir="/path/to/skills")

        agent = create_deep_agent(
            model="anthropic:claude-sonnet-4-6",
            system_prompt="""You are a research assistant.

        Skills (read the SKILL.md file when relevant):
        - /path/to/skills/arxiv-search/SKILL.md — papers
        - /path/to/skills/web-research/SKILL.md — general web lookups
        - /path/to/skills/langgraph-docs/SKILL.md — LangGraph documentation
        """,
            middleware=[
                SkillsMiddleware(
                    backend=backend,
                    sources=["/path/to/skills"],
                    system_prompt=None,
                ),
            ],
        )
        ```

        当 skills 发生变化时，`create_deep_agent` 的 `system_prompt` 中的 skill 名称、路径和任何手写提示需要由调用方自行保持同步。
    </Accordion>
</AccordionGroup>

## Backends

deep agent 的工具可以使用 virtual file system 来存储、访问和编辑文件。默认情况下，deep agents 使用 [StateBackend](https://reference.langchain.com/python/deepagents/backends/state/StateBackend)。

<Tabs>
    <Tab title="StateBackend">
        一个存储在 `langgraph` state 中、线程范围的文件系统 backend。

        文件会通过你的 checkpointer 在同一 thread 的多轮之间持久化，但不会在不同 thread 之间共享。

        <BackendStatePy />



    </Tab>
    <Tab title="FilesystemBackend">
        本地机器的文件系统。

        <Warning>
            这个 backend 会让 agent 直接读写文件系统。
            请谨慎使用，只在合适的环境中使用。
            有关更多信息，请参见 [`FilesystemBackend`](/oss/python/deepagents/backends#filesystembackend-local-disk)。

        <BackendFilesystemPy />




        <Tip>
            将 `FilesystemBackend` 包装在 `CompositeBackend` 中，可以防止内部 agent 数据（卸载的工具结果、对话历史）和项目文件一起写到磁盘。请参见[推荐模式](/oss/python/deepagents/backends#filesystembackend-local-disk)。
        </Tip>
    </Tab>
    <Tab title="LocalShellBackend">
        一个带有直接在主机上执行 shell 的文件系统。提供文件系统工具，以及用于运行命令的 `execute` 工具。

        <Warning>
            这个 backend 会让 agent 直接读写文件系统，**并且**在你的主机上拥有不受限制的 shell 执行能力。
            请极其谨慎地使用，只在合适的环境中使用。
            有关更多信息，请参见 [`LocalShellBackend`](/oss/python/deepagents/backends#localshellbackend-local-shell)。
        </Warning>

        <BackendLocalShellPy />



    </Tab>
    <Tab title="StoreBackend">
        一个提供长期存储的文件系统，会_跨 thread 持久化_。

## Skills

你可以使用 [skills](/oss/python/deepagents/overview) 为 deep agent 提供新的能力和专长。
虽然 [tools](/oss/python/deepagents/customization#tools) 往往覆盖的是更底层的功能，例如原生文件系统操作或规划，但 skills 可以包含如何完成任务的详细说明、参考信息，以及模板等其他资产。
这些文件只有在 agent 判断某个 skill 对当前 prompt 有用时才会加载。
这种渐进式披露减少了 agent 启动时需要考虑的 token 和上下文量。

有关示例 skills，请参见 [Deep Agents example skills](https://github.com/langchain-ai/deepagentsjs/tree/main/examples/skills)。

## Profiles

[harness profile](/oss/python/deepagents/profiles#harness-profiles) 是一个可复用的、按模型划分的配置包，`create_deep_agent` 会在匹配的模型被选中时自动应用它。profile 适合那些你希望跟随模型而不是跟随调用位置的行为，例如针对 Claude 指令风格调优的 system prompt suffix、为 GPT 重写的工具描述，或者只在特定 provider 上有意义的额外 middleware。

一个 profile 可以包含：自定义 base system prompt（`base_system_prompt`）、追加的 suffix（`system_prompt_suffix`）、工具描述覆盖、要排除的工具或 middleware、要注入的额外 middleware，以及对自动添加的通用子 agent 的编辑。

<CustomizationProfilesPy />

有关注册键、合并语义和插件打包，请参见 [Profiles](/oss/python/deepagents/profiles)。更窄的配套 API [provider profiles](/oss/python/deepagents/profiles#provider-profiles) 用于打包某个 provider 的模型构造参数（API key、timeout、重试设置）。
