>[CockroachDB](https://www.cockroachlabs.com/) 是一个分布式 SQL 数据库，构建在事务型且强一致的键值存储之上。它可以水平扩展，并能在磁盘、机器、机架，甚至数据中心故障时以极小的延迟波动继续运行，而无需人工干预。

**核心特性：**
- **Distributed SQL**：在保持 ACID 保证的同时实现横向扩展
- **Native vector support**：内置 `VECTOR` 类型（v24.2+）和 C-SPANN 索引（v25.2+）
- **PostgreSQL compatible**：可作为 PostgreSQL 应用的直接替代
- **Global replication**：支持低延迟的多区域部署
- **Automatic sharding**：数据会自动分布到各节点
- **SERIALIZABLE isolation**：默认提供最强隔离级别

## 安装与设置

安装 LangChain 集成：

```bash
pip install langchain-cockroachdb
```

需要 CockroachDB v25.4 或更高版本。

### 获取 CockroachDB 连接字符串

你需要一个 CockroachDB 集群。可以选择以下方式之一：

**Option 1: CockroachDB Cloud（推荐）**
1. 在 [cockroachlabs.cloud](https://cockroachlabs.cloud) 注册
2. 创建一个免费集群
3. 获取你的连接字符串：`cockroachdb://user:pass@host:26257/db?sslmode=verify-full`

**Option 2: Docker（开发环境）**

```bash
docker run -d --name cockroachdb -p 26257:26257 \
  cockroachdb/cockroach:latest start-single-node --insecure
```

连接字符串：`cockroachdb://root@localhost:26257/defaultdb?sslmode=disable`

**Option 3: 本地二进制**

从 [cockroachlabs.com/docs/releases](https://www.cockroachlabs.com/docs/releases/) 下载

## Integrations

### Vector Store

CockroachDB 可通过原生 `VECTOR` 类型和 C-SPANN 分布式索引，用作 vector store。

**核心特性：**
- 原生向量支持（v24.2+）
- 针对分布式系统优化的 C-SPANN 索引（v25.2+）
- 高级元数据过滤
- 结合全文搜索与向量相似度的混合搜索（v0.3.0+）
- 通过前缀列实现多租户
- 水平可扩展性

详细用法链接请参见 [vector stores overview 中的 CockroachDB 条目](/oss/python/integrations/vectorstores#cockroachdb)。

**快速示例：**

```python
from langchain_cockroachdb import AsyncCockroachDBVectorStore, CockroachDBEngine
from langchain_openai import OpenAIEmbeddings

# Initialize
engine = CockroachDBEngine.from_connection_string(
    "cockroachdb://user:pass@host:26257/db"
)

await engine.ainit_vectorstore_table(
    table_name="documents",
    vector_dimension=1536,
)

vectorstore = AsyncCockroachDBVectorStore(
    engine=engine,
    embeddings=OpenAIEmbeddings(),
    collection_name="documents",
)

# Use it
ids = await vectorstore.aadd_texts(["Hello world"])
results = await vectorstore.asimilarity_search("Hi", k=1)
```

**混合搜索**（v0.3.0+）并行执行全文搜索和向量搜索，并通过倒数排名融合（默认）合并排序后的结果：

```python
from langchain_cockroachdb import HybridSearchConfig

# create_tsvector=True 会添加 TSVECTOR 列和 GIN 索引
await engine.ainit_vectorstore_table(
    table_name="documents",
    vector_dimension=1536,
    create_tsvector=True,
)

vectorstore = AsyncCockroachDBVectorStore(
    engine=engine,
    embeddings=OpenAIEmbeddings(),
    collection_name="documents",
    hybrid_search_config=HybridSearchConfig(),
)

# 现在常规搜索方法会透明地执行混合搜索
results = await vectorstore.asimilarity_search("distributed database performance", k=5)
```

### Chat Message History

将对话历史存储到 CockroachDB 中，用于持久化、分布式聊天应用。

**核心特性：**
- 自动复制的分布式存储
- 强一致性（SERIALIZABLE）
- 基于 session 的组织方式
- 高可用性

详细用法参见 [CockroachDB chat history documentation](/oss/python/integrations/chat_message_histories/cockroachdb)。

**快速示例：**

```python
from langchain_cockroachdb import CockroachDBChatMessageHistory, CockroachDBEngine
import uuid

engine = CockroachDBEngine.from_connection_string(CONNECTION_STRING)

chat_history = CockroachDBChatMessageHistory(
    session_id=str(uuid.uuid4()),
    engine=engine,
    table_name="chat_history",
)

from langchain.messages import HumanMessage, AIMessage

await chat_history.aadd_message(HumanMessage(content="Hello!"))
await chat_history.aadd_message(AIMessage(content="Hi there!"))

messages = await chat_history.aget_messages()
```

共享 engine 会复用其连接池和重试策略。

### LangGraph Checkpointer

将 LangGraph workflow state 持久化到 CockroachDB 中，用于短期记忆、human-in-the-loop 交互和故障恢复。

同时提供 sync（`CockroachDBSaver`）和 async（`AsyncCockroachDBSaver`）实现。

<Tip>
首次使用 CockroachDB checkpointer 时，请调用 `checkpointer.setup()`，或 `await checkpointer.setup()`，以创建所需表。
</Tip>

<Tabs>
    <Tab title="Sync">
```python
import os
from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, MessagesState, START
from langchain_cockroachdb import CockroachDBSaver

model = init_chat_model(model="claude-haiku-4-5-20251001")

DB_URI = os.environ["COCKROACHDB_URI"]
# Example: "cockroachdb://user:password@host:26257/defaultdb?sslmode=verify-full"
with CockroachDBSaver.from_conn_string(DB_URI) as checkpointer:
    # checkpointer.setup()

    def call_model(state: MessagesState):
        response = model.invoke(state["messages"])
        return {"messages": response}

    builder = StateGraph(MessagesState)
    builder.add_node(call_model)
    builder.add_edge(START, "call_model")

    graph = builder.compile(checkpointer=checkpointer)

    config = {"configurable": {"thread_id": "1"}}

    stream = graph.stream_events(
        {"messages": [{"role": "user", "content": "hi! I'm bob"}]},
        config,
        version="v3",
    )
    for snapshot in stream.values:
        snapshot["messages"][-1].pretty_print()

    stream = graph.stream_events(
        {"messages": [{"role": "user", "content": "what's my name?"}]},
        config,
        version="v3",
    )
    for snapshot in stream.values:
        snapshot["messages"][-1].pretty_print()
```

<Note>
连接方式参见上面的 [Get your CockroachDB connection string](#get-your-cockroachdb-connection-string)，其中包括 CockroachDB Cloud、Docker 和本地二进制安装。对于本地开发，可接受 `sslmode=disable`；在生产环境中请始终使用 `sslmode=verify-full`。

</Tip>

#### Row-Level TTL（v0.2.1+）

使用 CockroachDB 的 [Row-Level TTL](https://www.cockroachlabs.com/docs/stable/row-level-ttl) 自动过期旧 checkpoint 数据：

```python
with CockroachDBSaver.from_conn_string(DB_URI) as checkpointer:
    checkpointer.setup()

    # Expire checkpoints older than 30 days, clean up daily
    checkpointer.enable_ttl(ttl_interval="30 days", cron="@daily")

    # Use the checkpointer normally -- old data is cleaned up automatically
    graph = builder.compile(checkpointer=checkpointer)

    # To disable TTL later:
    # checkpointer.disable_ttl()
```

从 v0.6.0 起，活跃的 thread 会保留它仍在使用的值，即使这些值比 interval 更旧；而 thread 一旦空闲达到该 interval，就会整体过期。当设置发生变化时，`enable_ttl()` 会暂停 TTL，等待约 15 秒，并在恢复 TTL 之前将现有 thread 更新到最新状态，因此请在升级后从单个进程运行一次。之后使用相同设置的调用会立即返回。

异步版本：`await checkpointer.aenable_ttl(ttl_interval="7 days", cron="@hourly")`

<Note>
TTL 删除是 **eventual** 的，也就是说，即使行已过期，在 CockroachDB 的后台任务按设定 cron 计划运行之前，这些行仍可能被查询到。
</Note>

#### 性能优化（v0.2.1+）

该 checkpointer 包含若干面向低延迟读取的优化：

- **Batch fetching**：`list()` 会用 2 次批量查询一次性获取所有 blobs 和 writes，而不是每个 checkpoint 执行 2 次查询
- **Raw BYTEA**：使用 psycopg3 二进制协议，而不是在 SQL 中对 blobs 做十六进制编码
- **Prepared statements**：`prepare_threshold` 默认为 5，可以在 `from_conn_string` 中修改
- **Concurrent setup**：`setup()` 可以安全地由多个进程同时运行
- **Connection pools (v0.4.1+)**：对于长期运行的服务，请传入 `psycopg_pool` 连接池，而不是单个连接。基于连接池的 saver 会并发执行操作，每个操作使用各自的池化连接，因此一个 saver 即可服务多个 agent；请将连接池的 `max_size` 设置为同时运行的 agent 数量。基于单个连接的 saver 一次只能执行一个操作，且该连接一旦断开便无法恢复，`from_conn_string(..., pipeline=True)` 也是如此
- **Atomic writes (v0.4.1+)**：包含多条语句的 checkpoint 写入会作为一个批次发送到数据库，因此中途取消的写入不会保存任何内容。它仍然只需一次往返

### LangGraph Store

将 LangGraph 长期记忆持久化到 CockroachDB：这些记忆的生命周期长于对话 thread，例如用户偏好和 agent 习得的事实。

同时提供同步（`CockroachDBStore`）和异步（`AsyncCockroachDBStore`）实现。它们要求 `langchain-cockroachdb` v0.5.0 或更高版本，并遵循 `PostgresStore` 的 API，因此可与 `create_agent(store=...)` 和 `StateGraph.compile(store=...)` 配合使用。

<Tip>
首次使用 CockroachDB store 时，请调用 `store.setup()`（或 `await store.setup()`）以创建所需的表。
</Tip>

**快速示例：**

```python
import os

from langchain_cockroachdb import CockroachDBStore

DB_URI = os.environ["COCKROACHDB_URI"]

with CockroachDBStore.from_conn_string(DB_URI, pool_config={"max_size": 10}) as store:
    store.setup()

    namespace = ("user", "alice", "memories")
    store.put(namespace, "seat", {"text": "Prefers window seats"})
    item = store.get(namespace, "seat")
    results = store.search(("user", "alice"))
```

#### 语义搜索

传入 `index`，即可在写入条目时为其生成 embedding，并按与 `query` 的相似度对搜索结果排序。沿用上面的 `DB_URI`：

```python
from langchain_openai import OpenAIEmbeddings

with CockroachDBStore.from_conn_string(
    DB_URI,
    index={
        "dims": 1536,
        "embed": OpenAIEmbeddings(model="text-embedding-3-small"),
        "fields": ["text"],
    },
) as store:
    store.setup()
    store.put(("user", "alice", "memories"), "seat", {"text": "Prefers window seats"})
    results = store.search(("user", "alice", "memories"), query="Where does Alice sit?")
```

`setup()` 会创建一个 C-SPANN 向量索引，并以 namespace 作为前缀列，因此在某个用户 namespace 下搜索时只会读取该部分索引。`distance_type` 可以是 `"cosine"`（默认值）、`"l2"` 或 `"inner_product"`。

#### 用 TTL 让记忆过期

传入 `ttl` 可为条目设置以分钟为单位的过期时间。随后 `setup()` 会开启 CockroachDB 的行级 TTL job，由服务器删除过期条目，因此不需要清理线程：

```python
with CockroachDBStore.from_conn_string(DB_URI, ttl={"default_ttl": 60 * 24 * 30}) as store:
    store.setup()
    store.put(("user", "alice", "memories"), "status", {"text": "In a meeting"}, ttl=10)
```

读取、搜索和列表操作会忽略已过期但尚未被 job 删除的条目。`get` 或 `search` 会将它返回条目的过期时间后延，除非 `refresh_on_read` 为 `False`。若要关闭该 job，请调用 `store.disable_ttl()`，在 `AsyncCockroachDBStore` 上则调用 `await store.adisable_ttl()`。

#### 删除 namespace

`delete_namespace` 会在一个事务中删除某个 namespace 及其所有后代 namespace 中的每个条目及其 vector，并返回删除的条目数：

```python
deleted = store.delete_namespace(("user", "alice"))
```

在 `AsyncCockroachDBStore` 上，请使用 `await store.adelete_namespace(...)`。

#### 让记忆保持真实（v0.6.0+）

语义搜索按与查询的相似度对记忆排序，而不是按它们是否仍然真实。`reconcile` 在一个可串行化事务中写入一条记忆，并按你选择的策略处理可能与它冲突的记忆。store 不会发起任何 LLM 调用。

<Tip>
在从 v0.5 升级而来的 store 上，使用本节中的方法前请先运行一次 `setup()`。它会应用 migration 2，添加这些方法所需的列；在它运行之前，这些方法会抛出 `ValueError`。在开启 history 之前，请等待所有写入方都运行 v0.6.0。
</Tip>

一个 slot 命名一条记忆所陈述的事实。使用 `slot="topic"` 时，候选包括同一 key 下的记忆，以及该 namespace 中 `topic` 字段具有相同值的每条存活记忆。`first_of(skip_duplicates(), supersede_same_slot())` 会跳过重复项并确认它所重复的那条记忆，否则允许同一 slot 中较新的事实取代旧事实。`reconcile` 没有默认策略。

沿用上面的 `DB_URI`，以下工具会将事实保存到由模型命名的 topic 下，并列出用户过去对该 topic 的说法：

```python
from dataclasses import dataclass

from langchain.agents import create_agent
from langchain.tools import ToolRuntime, tool
from langchain_cockroachdb import CockroachDBStore
from langchain_cockroachdb.store import first_of, skip_duplicates, supersede_same_slot

POLICY = first_of(skip_duplicates(), supersede_same_slot())


@dataclass
class Context:
    user_id: str


@tool
def remember(text: str, topic: str, runtime: ToolRuntime[Context, dict]) -> str:
    """Save a fact about the user. topic names what it is about, such as "seat"."""
    assert isinstance(runtime.store, CockroachDBStore)
    namespace = ("user", runtime.context.user_id, "memories")
    result = runtime.store.reconcile(
        namespace,
        None,  # the store generates the key
        {"topic": topic, "text": text},
        slot="topic",
        policy=POLICY,
        provenance={"source": "chat"},
    )
    if result.new != "written":
        return f"Already known: {text}"
    replaced = f", replacing {len(result.superseded)}" if result.superseded else ""
    return f"Saved: {text}{replaced}"


@tool
def past_memories(topic: str, runtime: ToolRuntime[Context, dict]) -> str:
    """List what the user used to say about a topic, newest first."""
    assert isinstance(runtime.store, CockroachDBStore)
    namespace = ("user", runtime.context.user_id, "memories")
    lines = [
        f"{version.ended_at:%Y-%m-%d}: {version.value['text']} ({version.reason})"
        for version in runtime.store.history(namespace, limit=100)
        if version.value.get("topic") == topic
    ]
    return "\n".join(lines) or f"No earlier memories about {topic}."


with CockroachDBStore.from_conn_string(DB_URI, history=True) as store:
    store.setup()
    agent = create_agent(
        "claude-sonnet-4-6",
        tools=[remember, past_memories],
        context_schema=Context,
        store=store,
    )
```

设置 `history=True` 后，每次覆盖、取代或删除记忆的写入都会保留它所终结的版本，包括它的 provenance、该事实为真的时间以及它结束的原因。普通的 `put` 和 `delete` 也会保留 history。`history(namespace, key)` 按从新到旧列出一条记忆的旧版本，而 `history(namespace)` 会列出该 namespace 中每条记忆的旧版本，因此即使记忆保存在生成的 key 下，也能给出时间线。

`confirm(namespace, key)` 会将一条记忆标记为已确认：它会记录这次确认，并续订该记忆的过期时间。当 store 的 `ttl` 中 `refresh_on_read` 设为 `False` 时，过期时间跟随确认而非读取来续订。

`record(namespace, key)` 会读取一条记忆及其版本和 provenance。`put_if(namespace, key, value, expected=record)` 和 `delete_if(namespace, key, expected=record)` 仅当该记忆仍是 `record` 返回的那一条时才会生效，因此两个写入方不会丢失更新。冲突会以结果的形式返回，而不是抛出异常：`applied` 为 `False`，`current` 保存当前存活的记忆，供你合并。

在启用了 history 的 store 上，`delete` 是软删除：它所终结的版本仍留在 history 中。`purge(namespace, key)` 会彻底遗忘一个 key：该记忆、它的 vector，以及它的 history。被 `reconcile` 取代的记忆会在 history 中保留自己的 key，因此也要 purge 那个 key，或者使用 `delete_namespace` 遗忘某个 namespace 下的所有内容，包括 history。

在 `AsyncCockroachDBStore` 上，这些方法都有一个带 `a` 前缀的异步形式，例如 `await store.areconcile(...)`。

### Multi-tenancy

通过可选的 namespace 列按租户隔离向量数据。启用后，所有 CRUD 和搜索操作都会限定在指定 namespace 范围内。

CockroachDB 的 C-SPANN 索引支持前缀列，因此 namespace 过滤可以直接使用向量索引，而无需额外扫描。

```python
from langchain_cockroachdb import AsyncCockroachDBVectorStore, CockroachDBEngine
from langchain_cockroachdb.indexes import CSPANNIndex
from langchain_openai import OpenAIEmbeddings

engine = CockroachDBEngine.from_connection_string(CONNECTION_STRING)

# Create the table with a namespace column
await engine.ainit_vectorstore_table(
    table_name="documents",
    vector_dimension=1536,
    namespace_column="namespace",
)

# Create a vectorstore scoped to a specific tenant
vectorstore = AsyncCockroachDBVectorStore(
    engine=engine,
    embeddings=OpenAIEmbeddings(),
    collection_name="documents",
    namespace="tenant_a",
)

# Index the vectors with the namespace as the prefix column, before writes start
await vectorstore.aapply_vector_index(CSPANNIndex(), prefix_columns=["namespace"])

# All operations are scoped to tenant_a
ids = await vectorstore.aadd_texts(
    ["Tenant A document"], metadatas=[{"category": "news"}]
)
results = await vectorstore.asimilarity_search("query", k=5)
results = await vectorstore.asimilarity_search(
    "query", k=5, filter={"category": "news"}
)
```

从 v0.6.0 起，带 metadata `filter` 的搜索也会使用 C-SPANN 索引：store 会对来自索引的最近行应用该 filter，只有当通过的行太少时才执行精确搜索。namespace 必须是该索引唯一的前缀列，如示例所示；来自索引的结果与任何索引搜索一样是近似结果。

Document id 必须跨 namespace 唯一。库生成的 id 始终是唯一的；如果添加的文档 id 已属于另一个 namespace，则会引发 `ValueError`，且不会写入任何内容。

### 重试与弹性（v0.4.0+）

每个操作都会重试暂时性的 CockroachDB 错误：序列化失败（`40001`）、结果不明确（`40003`）、连接错误（`08xxx`）、节点下线（`57P01`），以及 CockroachDB 的 range 和节点故障 `58C00` 和 `58C01`。所有写入都是幂等的，因此在结果不明确后重试不会重复数据。在 engine 上配置一次即可：

```python
from langchain_cockroachdb import RETRYABLE_SQLSTATES, CockroachDBEngine, RetryPolicy

engine = CockroachDBEngine.from_connection_string(
    CONNECTION_STRING,
    retry_policy=RetryPolicy(
        max_attempts=8,
        # 可选，适用于设置了 statement_timeout 的多区域应用：
        retryable_sqlstates=RETRYABLE_SQLSTATES | {"57014"},
        attempt_timeout=10,
    ),
)
```

vector store 和 chat history 会继承 engine 的策略。checkpointer 也接受 `retry_policy`；请为它们提供 `psycopg_pool` 连接池，以便在连接断开时进行替换。自 v0.4.1 起，基于连接池的 checkpointer 还会在 `psycopg` 报告连接中断时进行重试，这也覆盖了 CockroachDB Cloud 上断开的 TLS 连接。

## 为什么在 AI 应用中使用 CockroachDB？

### 天生分布式
- **Horizontal scalability**：添加节点即可处理更高负载
- **Multi-region deployments**：面向全球用户提供低延迟服务
- **Automatic rebalancing**：数据会自动在各节点间重新均衡分布

### 面向生产的可靠性
- **High availability**：能够应对节点、机架和数据中心级故障
- **Zero-downtime upgrades**：支持无停机滚动升级
- **Backups and restores**：支持时间点恢复

### 大规模向量搜索
- **C-SPANN indexes**：分布式近似最近邻搜索
- **Native vector type**：对 embeddings 提供一等支持
- **Real-time indexing**：新增向量无需重建索引
- **Multi-tenancy**：通过前缀列高效实现租户隔离

### PostgreSQL 兼容性
- **Easy migration**：可作为 PostgreSQL 的直接替代
- **Familiar SQL**：标准 PostgreSQL 语法
- **Existing tools**：可配合 PostgreSQL 驱动和工具使用
