本页介绍所有与 [Microsoft Azure](https://portal.azure.com) 以及其他 [Microsoft](https://www.microsoft.com) 产品相关的 LangChain 集成。

<Tip>
    **推荐：Microsoft Foundry**

    对于以 [Microsoft Foundry](https://learn.microsoft.com/en-us/azure/foundry/) 为中心的新 LangChain 或 LangGraph 应用，请从 [`langchain-azure-ai`](/oss/python/integrations/providers/azure_ai) 开始。它提供 Foundry 项目 endpoint、Azure 凭据集成、Agent Service、hosting、工具、Content Safety、检索和 Azure 可观测性。

    如需直接访问 [Azure OpenAI v1 API](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/api-version-lifecycle?tabs=python)、运行会在 OpenAI 与 Azure 之间切换的代码、使用传统 Azure OpenAI API 版本或 completion LLM，或者希望依赖面更小，请使用 `langchain-openai` 包。

    Foundry 资源包含 Azure OpenAI 能力，并额外提供更广泛的模型目录、agent service 和评估能力。如果你在使用 Azure OpenAI 资源，可以[将其升级为 Foundry 资源](https://learn.microsoft.com/en-us/azure/foundry/how-to/upgrade-azure-openai)，在保留现有 API endpoint、状态和安全配置的同时获得 Foundry 能力。

    **示例与教程：**
    - [Azure-Samples/langchain-azure-openai-starter](https://github.com/Azure-Samples/langchain-azure-openai-starter)：一个面向生产的 LangChain + Azure OpenAI 应用模板，可通过单个 `azd` 命令直接部署到 Azure。
    - [microsoft/langchain-for-beginners](https://github.com/microsoft/langchain-for-beginners)：一个使用 Azure OpenAI 介绍 LangChain 的实战课程。
    - [Azure-Samples/langchain-agent-python](https://github.com/Azure-Samples/langchain-agent-python)：在 Azure 上构建并部署 LangChain agents。
</Tip>

<Note>
    **Claude on Azure**

    Microsoft Foundry 也提供对全部 [Anthropic Claude models](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/how-to/use-foundry-models-claude) 的访问，包括 Opus、Sonnet 和 Haiku。Claude 模型通过 Anthropic 原生专用 endpoint 提供，而不是 Azure OpenAI v1 API。请使用指向 Foundry Anthropic endpoint 的 [`langchain-anthropic`](/oss/python/integrations/chat/anthropic)。
</Note>

## 选择包

`langchain-azure-ai` 和 [`langchain-openai`](https://reference.langchain.com/python/langchain-openai/) 是互补关系，而非二选一。`langchain-azure-ai` 依赖 `langchain-openai`，其 chat 和 embeddings 类是 [`ChatOpenAI`](https://reference.langchain.com/python/langchain-openai/chat_models/base/ChatOpenAI) 和 [`OpenAIEmbeddings`](https://reference.langchain.com/python/langchain-openai/embeddings/base/OpenAIEmbeddings) 的子类，因此安装 Azure 包并不会把 OpenAI 包从依赖链中移除。

使用下表选择起点：

| 场景 | 包 |
| --- | --- |
| 以 Foundry project 为中心的新应用 | `langchain-azure-ai` |
| Foundry Agent Service、托管 LangGraph、Toolbox、Content Safety、Azure 工具或 Application Insights | `langchain-azure-ai` |
| 从 Foundry project endpoint 配置的 embeddings | `langchain-azure-ai` |
| 直接调用 Azure OpenAI v1 chat | `langchain-openai` |
| 同一份代码需要在 OpenAI 和 Azure 之间切换 | `langchain-openai` |
| 现有的 [`AzureChatOpenAI`](https://reference.langchain.com/python/langchain-openai/chat_models/azure/AzureChatOpenAI) 应用 | `langchain-openai` |
| 传统带日期的 Azure OpenAI API 版本 | `langchain-openai` |
| completion LLM 接口 | `langchain-openai` |
| 最小依赖与运维面 | `langchain-openai` |

将现有 `langchain-openai` 应用迁移到 `langchain-azure-ai` 并不是一次简单的 import 替换：

- 配置方式不同。`azure_endpoint`、`azure_deployment`、`api_version` 和 token-provider 参数会变为 `project_endpoint` 或 `endpoint`、`model` 和 `credential`。
- 默认行为不同。当 `AzureAIOpenAIApiChatModel` 解析出 project endpoint 时，默认使用 Responses API。要保留 Chat Completions 行为，请设置 `use_responses_api=False`。
- `langchain-azure-ai` 中没有与 [`AzureOpenAI`](https://reference.langchain.com/python/langchain-openai/llms/azure/AzureOpenAI) 对应的 completion LLM。
- [`AzureChatOpenAI`](https://reference.langchain.com/python/langchain-openai/chat_models/azure/AzureChatOpenAI) 携带 Azure 特有的响应元数据和内容过滤处理，Foundry chat model 不会复现这些行为。
- 两个包都遵循 OpenAI 官方 schema，因此 DeepSeek 或 Mistral 等兼容 provider 返回的非标准字段可能不会被保留。

## Chat models

Microsoft 通过 Azure 为 chat models 提供三种主要接入方式：

1. **Microsoft Foundry**（适合以 project 为中心的应用，推荐）：使用 `langchain-azure-ai` 中的 `AzureAIOpenAIApiChatModel`，配合 Foundry project endpoint 和 Azure 凭据。该包还与 Foundry agents、hosting、工具、Content Safety、检索和可观测性集成。
2. **[Azure OpenAI](https://learn.microsoft.com/en-us/azure/ai-services/openai/)**：直接调用 v1 API 或运行在 OpenAI 与 Azure 之间切换的代码，使用 `langchain-openai` 中的 `ChatOpenAI`。传统 Azure OpenAI API 版本和现有应用，使用 `AzureChatOpenAI`。
3. **[Azure ML](https://learn.microsoft.com/en-us/azure/machine-learning/)**，支持部署和管理自定义或微调后的开源模型。

### Microsoft Foundry

Microsoft Foundry 提供 project 级别的模型和 Azure 服务访问。当你的应用使用 Foundry project、Azure 凭据或其他 Foundry 能力时，请使用 `langchain-azure-ai` 中的 `AzureAIOpenAIApiChatModel`。

<CodeGroup>
    ```bash pip
    pip install -U langchain-azure-ai
    ```

    ```bash uv
    uv add langchain-azure-ai
    ```
</CodeGroup>

设置 project endpoint：

```bash
export AZURE_AI_PROJECT_ENDPOINT="https://<resource>.services.ai.azure.com/api/projects/<project>"
```

然后创建 chat model：

```python
from azure.identity import DefaultAzureCredential
from langchain_azure_ai.chat_models import AzureAIOpenAIApiChatModel

llm = AzureAIOpenAIApiChatModel(
    model="gpt-5.2",  # your Foundry model deployment name
    credential=DefaultAzureCredential(),
)
```

完整设置指南，请参见 [Microsoft Foundry chat model 集成](/oss/python/integrations/chat/azure_ai)。

#### Responses API

Azure OpenAI 支持 [Responses API](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/how-to/responses)，可提供有状态对话、内置工具，例如 web search、file search、code interpreter，以及结构化推理摘要。设置 `reasoning` 参数时，`ChatOpenAI` 会自动路由到 Responses API，你也可以通过 `use_responses_api=True` 显式启用：

<Tabs>
    <Tab title="Entra ID (recommended)">
        ```python
        from azure.identity import DefaultAzureCredential, get_bearer_token_provider
        from langchain_openai import ChatOpenAI

        token_provider = get_bearer_token_provider(
            DefaultAzureCredential(),
            "https://cognitiveservices.azure.com/.default",
        )

        llm = ChatOpenAI(
            model="gpt-5.4-mini",
            base_url="https://YOUR-RESOURCE-NAME.openai.azure.com/openai/v1/",
            api_key=token_provider,
            use_responses_api=True,
        )

        response = llm.invoke("Summarize the bitter lesson.")
        print(response.text)
        ```
    </Tab>
    <Tab title="API key">

## Document loaders

### Azure Blob Storage

## Backends

### Azure Blob Storage Backend

>[Azure Blob Storage](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction) 是 Microsoft 面向云的对象存储解决方案。`AzureBlobBackend` 实现了 Deep Agents 的 `BackendProtocol`，因此 deep agent 可以把它的整个工作区（文件、记忆和 artifacts）持久化到 blob container 中。

<Note>
`AzureBlobBackend` 属于 `langchain-azure-storage` 包，该包目前处于 **Public Preview** 阶段。
</Note>

安装时使用 `deepagents` extra（要求 Python 3.11+）：

<CodeGroup>
    ```bash pip
    pip install -U "langchain-azure-storage[deepagents]"
    ```

    ```bash uv
    uv add "langchain-azure-storage[deepagents]"
    ```
</CodeGroup>

```python
from langchain_azure_storage.deepagents import AzureBlobBackend
```

**快速开始：**

```python
from deepagents import create_deep_agent
from langchain_azure_storage.deepagents import AzureBlobBackend

backend = AzureBlobBackend(
    account_url="https://<my-storage-account-name>.blob.core.windows.net",
    container_name="agent-workspace",
    prefix="session-001/",  # Optional: isolate each agent/session under a prefix.
)

agent = create_deep_agent(backend=backend)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "Write a hello world script to hello.py"}]}
)
```

该 backend 默认使用 [`DefaultAzureCredential`](https://learn.microsoft.com/en-us/azure/developer/python/sdk/authentication/credential-chains?tabs=dac#defaultazurecredential-overview)，并支持通过 `credential` 覆盖。

更多信息，请参见 [Backend 集成](/oss/python/integrations/backends)。完整的用法细节和安全指引，请参见[包仓库](https://github.com/langchain-ai/langchain-azure/tree/main/libs/azure-storage)。

## Memory

### Azure cosmos DB chat message history

>[Azure Cosmos DB](https://learn.microsoft.com/azure/cosmos-db/) 为会话型 AI 应用提供聊天消息历史存储能力，支持低延迟、高可用地持久化和检索对话历史。

<CodeGroup>
    ```bash pip
    pip install langchain-azure-cosmosdb
    ```

    ```bash uv
    uv add langchain-azure-cosmosdb
    ```
</CodeGroup>

配置 Azure Cosmos DB 连接，可选择同步或异步，也可使用 access key 或 Microsoft Entra ID：

```python
from langchain_azure_cosmosdb import CosmosDBChatMessageHistory

history = CosmosDBChatMessageHistory(
    cosmos_endpoint="https://<your-account>.documents.azure.com:443/",
    cosmos_database="<your-database>",
    cosmos_container="<your-container>",
    session_id="<session-id>",
    user_id="<user-id>",
    credential="<your-key-or-token-credential>",
    ttl=3600,  # optional: messages expire after 1 hour
)
history.prepare_cosmos()

history.add_user_message("Hello!")
history.add_ai_message("Hi there!")
```

若要使用异步版本，请从同一包中导入 `AsyncCosmosDBChatMessageHistory`。

### Azure cosmos DB semantic cache

>[`AzureCosmosDBNoSqlSemanticCache`](https://github.com/langchain-ai/langchain-azure/tree/main/libs/azure-cosmosdb) 使用向量相似度在 Azure Cosmos DB for NoSQL 中缓存 LLM 响应，当遇到语义相似的 prompt 时返回缓存结果。

<CodeGroup>
    ```bash pip
    pip install langchain-azure-cosmosdb
    ```

    ```bash uv
    uv add langchain-azure-cosmosdb
    ```
</CodeGroup>

```python
from azure.cosmos import CosmosClient, PartitionKey
from langchain_core.globals import set_llm_cache
from langchain_azure_cosmosdb import AzureCosmosDBNoSqlSemanticCache

cosmos_client = CosmosClient("<endpoint>", "<key>")

cache = AzureCosmosDBNoSqlSemanticCache(
    cosmos_client=cosmos_client,
    embedding=embedding,
    vector_embedding_policy=vector_embedding_policy,
    indexing_policy=indexing_policy,
    cosmos_container_properties={"partition_key": PartitionKey(path="/id")},
    cosmos_database_properties={"id": "cache-db"},
    vector_search_fields={"text_field": "text", "embedding_field": "embedding"},
    database_name="cache-db",
    container_name="cache-container",
)

set_llm_cache(cache)
```

异步版本请导入 `AsyncAzureCosmosDBNoSqlSemanticCache`。

## Vector stores

### Azure cosmos DB
AI agents 可以将 Azure Cosmos DB 作为统一的[memory system](https://learn.microsoft.com/en-us/azure/cosmos-db/ai-agents#memory-can-make-or-break-agents)方案，享受其速度、规模和简洁性。该服务曾成功[支持 OpenAI 的 ChatGPT 服务](https://www.youtube.com/watch?v=6IIUtEFKJec&t)，以高可靠和低维护成本实现动态扩展。凭借原子记录序列引擎，它是全球首个同时支持分布式 [NoSQL](https://learn.microsoft.com/en-us/azure/cosmos-db/distributed-nosql)、[关系型](https://learn.microsoft.com/en-us/azure/cosmos-db/distributed-relational) 和[向量数据库](https://learn.microsoft.com/en-us/azure/cosmos-db/vector-database)能力，并提供 serverless 模式的服务。

下面是 Azure Cosmos DB 中可提供 vector store 功能的两种 API。

#### Azure cosmos DB for MongoDB (vCore)

>[Azure Cosmos DB for MongoDB vCore](https://learn.microsoft.com/en-us/azure/documentdb/) 让你可以轻松创建一个具备原生 MongoDB 支持的数据库。
> 你可以复用已有的 MongoDB 经验，并继续使用喜爱的 MongoDB 驱动、SDK 和工具，只需将应用指向 API for MongoDB vCore 账号的连接字符串即可。
> 在 Azure Cosmos DB for MongoDB vCore 中使用向量搜索，可以将基于 AI 的应用无缝连接到存储在 Azure Cosmos DB 中的数据。

#### 安装与设置

参见[详细配置说明](/oss/python/integrations/vectorstores/azure_cosmos_db_mongo_vcore)。

#### Azure cosmos DB NoSQL

>[Azure Cosmos DB for NoSQL](https://learn.microsoft.com/en-us/azure/cosmos-db/nosql/vector-search) 现在以预览版形式提供向量索引和搜索能力。
该功能旨在处理高维向量，并在任意规模下实现高效、准确的向量搜索。现在你可以直接在文档中与常规数据一起存储向量，也就是说，数据库中的每个文档不仅可以包含传统的无 schema 数据，还可以将高维向量作为文档的其他属性。这种数据与向量的同位存储方式，使索引和搜索都更加高效，因为向量与其代表的数据存储在同一逻辑单元中。这简化了数据管理、AI 应用架构以及基于向量的操作效率。

## Runtime

### Microsoft Foundry hosted agents

[Microsoft Foundry hosted agents](https://learn.microsoft.com/en-us/azure/foundry/how-to/develop/langchain-hosted-agents) 在托管运行时中运行自定义 LangGraph 代码。使用 `langchain_azure_ai.agents.hosting` 包暴露编译好的 LangGraph graph，同时由 Foundry 管理运行时、会话、扩缩、身份和协议端点。

<Note>
    LangGraph 托管支持要求 `langchain-azure-ai[hosting]>=1.2.8`。
</Note>

开始之前，你需要一个 Azure 订阅、一个 Foundry 项目、一个已部署的聊天模型、Python 3.10 或更高版本，以及 Azure CLI 身份验证。部署 agent 还需要在项目上具有 Foundry Project Manager 角色。

根据客户端与 agent 的交互方式选择托管协议：

| 协议 | Run 参数 | SDK host 类 | 端点 | 适用场景 |
| --- | --- | --- | --- | --- |
| Responses | `--protocol responses` | `ResponsesHostServer` | `/responses` | 你需要 OpenAI 兼容的聊天、流式传输、响应历史或会话线程。大多数会话型 agent 从这里开始。 |
| Invocations | `--protocol invocations` | `InvocationsHostServer` | `/invocations` | 你需要自定义 JSON 结构、webhook 风格的端点，或非会话式处理。 |

<Note>
    对于使用基于 `BaseChatOpenAI` 的模型并接入 Responses API 的 hosted graph，请设置 `output_version="responses/v1"`。在 `langchain-openai` 1.0.0 及更高版本中可以省略该设置，除非被 `LC_OUTPUT_VERSION` 覆盖。此指南同时适用于 Responses 和 Invocations 两种托管协议。
</Note>

[Responses 协议](https://github.com/microsoft-foundry/foundry-samples/tree/main/samples/python/hosted-agents/langgraph/responses/10-run)和 [Invocations 协议](https://github.com/microsoft-foundry/foundry-samples/tree/main/samples/python/hosted-agents/langgraph/invocations/03-run)的完整运行示例见相关仓库。

#### 使用配置驱动的 runner

如果你的 agent 已经使用 LangGraph CLI 运行，可以在同一项目目录下使用 `langchain_azure_ai.agents.hosting.run` 工具。该 runner 使用现有的 `langgraph.json` 配置加载编译好的 graph，因此无需修改代码。

设置 Foundry 项目端点和模型部署名称，然后在启动 host 时选择协议：

<Tabs>
    <Tab title="Responses">
        ```bash
        export FOUNDRY_PROJECT_ENDPOINT="https://<account>.services.ai.azure.com/api/projects/<project>"
        export AZURE_AI_MODEL_DEPLOYMENT_NAME="<model-deployment-name>"
        python -m langchain_azure_ai.agents.hosting.run --protocol responses
        ```
    </Tab>
    <Tab title="Invocations">
        ```bash
        export FOUNDRY_PROJECT_ENDPOINT="https://<account>.services.ai.azure.com/api/projects/<project>"
        export AZURE_AI_MODEL_DEPLOYMENT_NAME="<model-deployment-name>"
        python -m langchain_azure_ai.agents.hosting.run --protocol invocations
        ```
    </Tab>
</Tabs>

部署时，将 `azure.yaml` 中 agent 服务上的 `codeConfiguration.entryPoint` 设置为同一个 runner 和协议。保留现有的项目路径、运行时和依赖解析设置：

<Tabs>
        <Tab title="Responses">
                ```yaml
                services:
                    my-agent:
                        codeConfiguration:
                            entryPoint: '-m langchain_azure_ai.agents.hosting.run --protocol responses'
                ```
        </Tab>
        <Tab title="Invocations">
                ```yaml
                services:
                    my-agent:
                        codeConfiguration:
                            entryPoint: '-m langchain_azure_ai.agents.hosting.run --protocol invocations'
                ...
                ```
        </Tab>
</Tabs>

#### 使用 SDK host 类

当你需要自定义服务器构建、直接控制服务器生命周期，或实现自定义路由或处理器等高级托管行为时，请使用 SDK host 类：

<Tabs>
    <Tab title="Responses">
        ```python
        from langchain_azure_ai.agents.hosting import ResponsesHostServer

        ResponsesHostServer(graph).run()
        ```
    </Tab>
    <Tab title="Invocations">
        ```python
        from langchain_azure_ai.agents.hosting import InvocationsHostServer

        InvocationsHostServer(graph).run()
        ```
    </Tab>
</Tabs>

无论采用哪种方式部署，都可以使用 `azd ai agent init` 初始化一个 hosted-agent 项目，使用 `azd ai agent run` 在本地测试，并使用 `azd deploy` 部署。只有在需要创建 Foundry 项目或其他 Azure 资源时才先运行 `azd provision`。你也可以使用 Foundry Toolkit Visual Studio Code 扩展进行部署。

Microsoft Learn 指南包含两种协议的完整示例，以及会话状态、human-in-the-loop 流程、测试、部署和故障排除。
