[LiteLLM](https://github.com/BerriAI/litellm) 是一个简化调用 Anthropic、Azure、Huggingface、Replicate 等模型的库。

本页介绍如何开始在 LangChain 中使用 LiteLLM I/O 库。

该集成提供两个聊天模型类：

- [ChatLiteLLM](https://reference.langchain.com/python/langchain-litellm/chat_models/litellm/ChatLiteLLM): LiteLLM 的主要 LangChain 聊天封装。
- [ChatLiteLLMRouter](https://reference.langchain.com/python/langchain-litellm/chat_models/litellm_router/ChatLiteLLMRouter): `ChatLiteLLM` 的一个封装，它利用 LiteLLM 的 Router 实现负载均衡和 fallback。

该包还提供 [LiteLLMEmbeddings](https://reference.langchain.com/python/langchain-litellm/embeddings/litellm/LiteLLMEmbeddings)、[LiteLLMEmbeddingsRouter](https://reference.langchain.com/python/langchain-litellm/embeddings/litellm_router/LiteLLMEmbeddingsRouter) 和 [LiteLLMOCRLoader](https://reference.langchain.com/python/langchain-litellm/document_loaders/litellm_ocr/LiteLLMOCRLoader)。详情请参见 [providers page](/oss/python/integrations/providers/litellm)。

### 设置

要访问 `ChatLiteLLM` 和 `ChatLiteLLMRouter` 模型，你需要安装 `langchain-litellm` 包，并创建 OpenAI、Anthropic、Azure、Replicate、OpenRouter、Hugging Face、Together AI 或 Cohere 账号。随后获取 API key，并将其导出为环境变量。

## 凭证

你需要选择想要使用的 LLM 提供方，并注册以获取对应的 API key。

### 示例 - Anthropic

### 示例 - OpenAI

前往 [platform.openai.com/api-keys](https://platform.openai.com/api-keys) 注册 OpenAI 并生成 API key。完成后，设置 `OPENAI_API_KEY` 环境变量。

```python
## Set ENV variables
import os

os.environ["ANTHROPIC_API_KEY"] = "your-anthropic-key"
```

```python
pip install -qU langchain-litellm
```

## 实例化

### ChatLiteLLM

你可以通过提供一个 [LiteLLM 支持的](https://docs.litellm.ai/docs/providers) `model` 名称来实例化 `ChatLiteLLM` 模型。

```python
from langchain_litellm import ChatLiteLLM

llm = ChatLiteLLM(model="gpt-5.4-nano", temperature=0.1)
```

### ChatLiteLLMRouter

你也可以像 [LiteLLM routing documentation](https://docs.litellm.ai/docs/routing) 中说明的那样，定义 model list 来利用 LiteLLM 的路由能力。

```python
from langchain_litellm import ChatLiteLLMRouter
from litellm import Router

model_list = [
    {
        "model_name": "gpt-5.5",
        "litellm_params": {
            "model": "azure/gpt-5.5",
            "api_key": "<your-api-key>",
            "api_version": "2024-10-21",
            "api_base": "https://<your-endpoint>.openai.azure.com/",
        },
    },
    {
        "model_name": "gpt-5.5",
        "litellm_params": {
            "model": "azure/gpt-5.5",
            "api_key": "<your-api-key>",
            "api_version": "2024-10-21",
            "api_base": "https://<your-endpoint>.openai.azure.com/",
        },
    },
]
litellm_router = Router(model_list=model_list)
llm = ChatLiteLLMRouter(router=litellm_router, model_name="gpt-5.5", temperature=0.1)
```

`ChatLiteLLM` 和 `ChatLiteLLMRouter` 还支持异步与流式功能：

```python
stream = await llm.astream_events("Hello, please explain how antibiotics work", version="v3")
async for token in stream.text:
    print(token, end="")
```

## 高级功能

### Gemini Enterprise Agent Platform grounding (Google Search)

对 Gemini Enterprise Agent Platform 模型（例如 `gemini-3.5-flash`）使用 Google Search grounding。grounding 元数据会出现在 `response_metadata` 中，批量与流式调用均是如此。

<Note>
从 `response_metadata` 中读取流式 grounding 元数据需要 `langchain-litellm>=0.11.0`。在此之前，`ChatLiteLLM` 会将其返回在 `additional_kwargs` 中，而 `ChatLiteLLMRouter` 在流式时不返回它。
</Note>

**Setup**

```python
import os
from langchain_litellm import ChatLiteLLM

os.environ["VERTEXAI_PROJECT"] = "your-project-id"
os.environ["VERTEXAI_LOCATION"] = "us-central1"

llm = ChatLiteLLM(model="vertex_ai/gemini-2.5-flash", temperature=0)
```

**Batch usage**

```python
# Invoke with Google Search tool enabled
response = llm.invoke(
    "What is the current stock price of Google?",
    tools=[{"googleSearch": {}}]
)

# Access citations & metadata
provider_fields = response.response_metadata.get("provider_specific_fields")
if provider_fields:
    # Vertex returns a list; the first item contains the grounding info
    print(provider_fields[0])
```

**Streaming usage**

```python
stream = llm.stream_events(
    "What is the current stock price of Google?",
    version="v3",
    tools=[{"googleSearch": {}}],
)
for token in stream.text:
    print(token, end="", flush=True)
# Metadata is available on the full output message
output = stream.output
if "provider_specific_fields" in output.response_metadata:
    print("\n[Metadata Found]:", output.response_metadata["provider_specific_fields"])
```

### Responses API

<Note>
`use_responses_api` 需要 `langchain-litellm>=0.10.0`。
</Note>

设置 `use_responses_api=True`，把 `ChatLiteLLM` 调用发送到提供方的 [Responses API](https://docs.litellm.ai/docs/response_api)，而不是 Chat Completions。LiteLLM 会对每个请求和回复进行转换，因此消息、工具、流式传输和结构化输出都照常工作。OpenAI 的内置工具（例如 web search）需要这条路由：

```python
from langchain_litellm import ChatLiteLLM

llm = ChatLiteLLM(model="openai/gpt-6-astra", use_responses_api=True)
llm_with_tools = llm.bind_tools([{"type": "web_search"}])

response = llm_with_tools.invoke("What was a positive news story from today?")
print(response.text)
```

- LiteLLM 无法发送到 Responses API 的模型会在请求发出前抛出 `ValueError`。
- 在这条路由上，LiteLLM 会丢弃仅适用于 Chat Completions 的参数，例如 `stop`、`n` 和 `seed`。
- 当 `use_responses_api` 为 `None`（默认值）或 `False` 时，LiteLLM 会自行选择 API，而且它已经会把某些模型（例如 `gpt-5-pro`）发送到 Responses API。

#### Reasoning items

<Note>
保留 reasoning items 需要 `langchain-litellm>=0.11.0`。
</Note>

Responses API 上的推理模型会以 [reasoning items](https://developers.openai.com/api/docs/guides/reasoning) 的形式返回其推理过程。在下一个请求中把当前轮次的 item 传回，可以让模型在工具循环中继续推理，而不是在每次工具调用后重新开始。item 只有连同其加密内容一起才会被传回；OpenAI 在无状态请求上默认返回该内容，并通过 `"store": False` 发送。OpenAI 也接受为该内容显式指定 `include`：

```python
from langchain.messages import HumanMessage
from langchain.tools import tool
from langchain_litellm import ChatLiteLLM


@tool
def get_weather(city: str) -> str:
    """Get the weather for a city."""
    return f"It is sunny in {city}."


llm = ChatLiteLLM(
    model="openai/gpt-6-astra",
    use_responses_api=True,
    model_kwargs={
        "extra_body": {"store": False, "include": ["reasoning.encrypted_content"]}
    },
)
llm_with_tools = llm.bind_tools([get_weather])

messages = [
    HumanMessage(
        "Get the weather for the city that hosted the Summer Olympics four years "
        "before London did."
    )
]
ai_message = llm_with_tools.invoke(messages)
reasoning_items = ai_message.additional_kwargs.get("reasoning_items", [])
print([item["id"] for item in reasoning_items])

messages.append(ai_message)
messages.extend(get_weather.invoke(call) for call in ai_message.tool_calls)
response = llm_with_tools.invoke(messages)
print(response.text)
```

回复会将其 reasoning items 保留在 `additional_kwargs["reasoning_items"]` 中，且只包含携带加密内容的 item。模型没有推理就作答的轮次则没有 item。每个被保留的 item 都带有一个 `origin` key，用于标记发出它的请求，因此在存储会话时请保留该 key。

后续请求会在以下情况把某个轮次的 item 传回：该轮次持有一个 item，且请求配置的模型、base URL 和凭证与发出它的请求相同。不匹配的请求不会传回 item，也只会丢失该轮次的推理。当请求可能到达其他 endpoint（例如通过 fallback、LiteLLM 的响应缓存或 `litellm.use_litellm_proxy`）时，它既不传回也不保留 item。

OpenAI 会用 400 `invalid_encrypted_content` 错误拒绝它无法解密的 item。匹配只覆盖 `ChatLiteLLM` 能读取的设置，因此 item 仍可能到达无法解密它的账户，例如通过路由到其他账户的网关（如 LiteLLM proxy），或通过 LiteLLM 自行找到的凭证（如 OpenAI workload identity）。

有些轮次不会传回 item：

- LiteLLM 自行发送到 Responses API 的调用（未设置 `use_responses_api`，模型名也不含 `responses/`），例如对 `gpt-5-pro` 的调用。它们的回复不保留 item。
- 持有多个 item 的流式轮次。当 LiteLLM 不以流式返回回复时，它只保留回复文本之前的最后一个 item，以及工具调用之前的最后一个 item，因此用 `invoke` 读取的同一轮次仍能传回其 item。

在 `ChatLiteLLMRouter` 上，只有未设置 fallback 且组内每个 deployment 共享相同模型、base URL、凭证以及工具与推理设置时，item 才会传回。将 deployment 的模型命名为 `<provider>/responses/<model>`，参见 [Router deployments](#router-deployments)。LiteLLM 自行发送到 Responses API 的 deployment（例如 `openai/gpt-5-pro`）不保留 item，无论是否设置 `use_responses_api`。

#### Router deployments

Router 会在每次调用时选择一个 deployment，因此没有单一模型名可供 `use_responses_api` 重新路由。将每个 deployment 的模型命名为 `<provider>/responses/<model>`，即可把它发送到 Responses API：

```python
from langchain_litellm import ChatLiteLLMRouter
from litellm import Router

model_list = [
    {
        "model_name": "gpt-6-astra",
        "litellm_params": {"model": "openai/responses/gpt-6-astra"},
    },
]
litellm_router = Router(model_list=model_list)
llm = ChatLiteLLMRouter(router=litellm_router, model_name="gpt-6-astra")
llm_with_tools = llm.bind_tools([{"type": "web_search"}])

response = llm_with_tools.invoke("What was a positive news story from today?")
print(response.text)
```

从 `langchain-litellm` 0.11.0 开始，`ChatLiteLLMRouter` 上的 `use_responses_api=True` 会检查各 deployment，而不是对它们重新路由。当 LiteLLM 会把被调用组的每个 deployment 都发送到 Responses API 时，调用会原样发出；否则会在任何请求发出之前抛出 `ValueError`，并指明每个不会走这条路由的 deployment。当调用可能到达组外的 deployment（例如通过 fallback 或 `model_group_alias`）时，它也会抛出异常。更早的版本会对 `ChatLiteLLMRouter` 上的该标志直接抛出 `ValueError`。
