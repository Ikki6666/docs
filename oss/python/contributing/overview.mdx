## Issues 和 pull request 要求

拼写错误和小修复的 pull request 可以直接提交，无需 issue、无需维护者事先批准，也无需指派。

<Warning>
    **较大的改动（例如新的教程、指南或概念页面）在打开 pull request 之前，需要链接一个 issue 并获得维护者批准。** 请等待维护者批准你的方案并把该 issue 指派给你。在批准和指派之前打开的较大 PR 可能会被自动关闭，并且在指派之前不会被审核。
</Warning>

所有 pull request 都应体现出有意义的投入和足够的上下文理解。**如果创建一个 pull request 所需的投入小于维护者审核它所需的投入，那么这份贡献就不应该被提交。** 低投入、路过式的贡献，不论是如何生成的，往往都无法满足上下文相关性、准确性和质量要求。大规模自动化贡献会构成人力审核资源上的拒绝服务攻击。

<Warning>
    **我们优先处理由实际使用场景驱动的 issue。** issue 看板是分配维护者注意力的机制，而不是所有可静态发现的缺陷的完整清单。请避免提交由（AI）代码扫描发现的 issue，除非你先亲自验证过它们，并将其建立在 LangChain 公开 API 的真实使用之上。如果维护者怀疑某个 issue 未经验证，它可能会在不被审核的情况下被关闭，并且创建该 issue 的账号可能会被封禁。
</Warning>

以下要求适用于所有外部 pull request：

* 对于较大的改动，请在打开 PR 之前链接一个 issue，且维护者已批准你的方案并把你指派到该 issue。拼写错误和小修复不受此要求约束。
* 该 pull request 必须完整填写仓库的 pull request 模板。
* 针对全新功能或改变行为的 bug 修复的 pull request，应包含 `## Release note` 一节，以面向发布说明的语言描述用户可见的变化。

如果不满足这些要求，维护者保留不作评论直接关闭 PR 的权利。**对于看起来像低投入垃圾内容的 pull request 和 issue，我们会直接关闭。**

## 语言政策

所有贡献，包括 issues、pull requests、代码审查和讨论，都必须使用英文。这可以让全球贡献者都能访问和搜索这些交流内容。

如果英文不是你的第一语言，也不用担心。我们更看重清晰表达，而不是完美语法，也欢迎使用翻译工具。

## LLM 的可接受使用方式

你可以使用 AI 助手帮助起草或修改贡献内容，但前提是你要**验证每一处改动**：运行并测试代码、对照代码库和官方 provider 文档核事实，并确保结果符合仓库风格。不要提交未经审查的大批量生成内容。无论这些内容是如何产生的，只要读起来像低投入或垃圾内容，我们都会关闭对应 pull request。
