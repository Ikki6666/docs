**标准测试可确保你的集成按预期工作。**

无论你是在为自己实现一个自定义类，还是准备发布成 LangChain 集成，都有必要添加测试，以确保其按预期工作。LangChain 为每种集成类型都提供了一套全面的[测试集合](https://pypi.org/project/langchain-tests/)。本指南将说明如何为每种集成类型接入 LangChain 的标准测试套件。

## 配置

首先，安装所需依赖：

<CardGroup cols={2}>
    <Card title="langchain-core" icon="cube" href="https://github.com/langchain-ai/langchain/tree/master/libs/core#readme" arrow>
        定义了我们在实现自定义组件时要导入的接口
    </Card>

    <Card title="langchain-tests" icon="flask" href="https://github.com/langchain-ai/langchain/tree/master/libs/standard-tests#readme" arrow>
        提供运行标准测试所需的测试集和 `pytest` 插件
    </Card>
</CardGroup>



<Warning>
    由于 `langchain-tests` 新版本中新增的测试可能会导致你的 CI/CD 流水线失败，我们建议将 [`langchain-tests`](https://pypi.org/project/langchain-tests/#history) 固定在最新版本，以避免意外变化。
</Warning>


<CodeGroup>
    ```bash pip
    pip install -U langchain-core
    pip install -U langchain-tests
    ```
    ```bash uv
    uv add langchain-core
    uv add langchain-tests
    ```
</CodeGroup>




`langchain-tests` 包中有 2 个命名空间：

<AccordionGroup>
    <Accordion title="单元测试" icon="settings">
        **位置**：`langchain_tests.unit_tests`



        用于在不访问外部服务的情况下，对组件进行隔离测试

        [查看 API reference](https://reference.langchain.com/python/langchain-tests/unit_tests)
    </Accordion>

    <Accordion title="集成测试" icon="network">
        **位置**：`langchain_tests.integration_tests`



        用于在可以访问外部服务的情况下测试组件（尤其是该组件设计要交互的外部服务）

        [查看 API reference](https://reference.langchain.com/python/langchain-tests/integration_tests)
    </Accordion>
</AccordionGroup>

这两类测试都以基于类的 [`pytest`](https://docs.pytest.org/en/stable/) 测试套件形式实现。


## 实现标准测试

根据你的集成类型，你需要实现单元测试、集成测试，或两者都实现。

通过继承适用于你集成类型的标准测试套件，你可以获得该类型对应的整套标准测试。某个测试只有在模型支持被测试的能力时才应通过。否则，该测试应被跳过。

由于不同集成提供的能力集合各不相同，LangChain 提供的大多数标准测试默认都需要**显式启用**，以避免误报。因此，你需要通过覆写属性来说明你的集成支持哪些能力，下面的例子演示了这一点。

```python tests/integration_tests/test_standard.py
# 声明某个聊天模型支持图像输入

class TestChatParrotLinkStandard(ChatModelIntegrationTests):
    # ... 其他必需属性

    @property
    def supports_image_inputs(self) -> bool:
        return True  # （默认值是 False）
```



<Note>
    你应当在包根目录下使用以下子目录来组织测试：
    - `tests/unit_tests` 用于单元测试
    - `tests/integration_tests` 用于集成测试
</Note>

如需查看所有可配置能力及其默认值的完整列表，请访问标准测试的 [API reference](https://reference.langchain.com/python/langchain-tests)。

## Sandbox 集成

Deep Agents 的 sandbox 集成使用 `langchain_tests.integration_tests` 中的 `SandboxIntegrationTests`。
请继承它，并提供一个 `sandbox` fixture，返回一个 `SandboxBackendProtocol` 实例。
可以把 [Daytona integration tests](https://github.com/langchain-ai/deepagents/blob/main/libs/partners/daytona/tests/integration_tests/test_integration.py) 作为参考实现。
发布规范请参阅[贡献 sandbox 集成](/oss/python/contributing/integrations-langchain)。

## 运行测试

如果你是从模板引导创建集成，通常会附带一个 `Makefile`，其中包含运行单元测试和集成测试的目标：

```bash
make test
make integration_test
```

否则，如果你遵循推荐的目录结构，也可以这样运行测试：

```bash
# 运行所有测试
uv run --group test pytest tests/unit_tests/
uv run --group test --group test_integration pytest -n auto tests/integration_tests/

# 对于某些单元测试，你可能需要设置特定标志和环境变量：
TIKTOKEN_CACHE_DIR=tiktoken_cache uv run --group test pytest --disable-socket --allow-unix-socket tests/unit_tests/

# 运行某个特定测试文件
uv run --group test pytest tests/integration_tests/test_chat_models.py

# 运行文件中的某个特定测试函数
uv run --group test pytest tests/integration_tests/test_chat_models.py::test_chat_completions

# 运行某个类中的特定测试函数
uv run --group test pytest tests/integration_tests/test_chat_models.py::TestChatParrotLinkIntegration::test_chat_completions
```
