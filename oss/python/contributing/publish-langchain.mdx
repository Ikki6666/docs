**让你的集成对社区可见。**

<Warning>
**不要向 LangChain 或 Deep Agents 仓库提交集成 PR。**

新的集成应当作为**独立的 PyPI 包**发布在你自己的 GitHub 组织或账号下（例如 `langchain-yourservice`），而不是向 [`langchain-ai/langchain`](https://github.com/langchain-ai/langchain) 仓库提交 PR。

主仓库只包含少量由 LangChain 团队维护的一方集成（例如 OpenAI、Anthropic 和 Ollama）。
</Warning>

现在你的包已经实现并通过测试，你可以将它发布出去并列入清单，让社区能够发现它。

## 发布你的包

<Info>
    本指南假设你已经实现了你的包，并为它编写了测试。如果还没有，请参阅[实现指南](/oss/python/contributing/implement-langchain)和[测试指南](/oss/python/contributing/standard-tests-langchain)。
</Info>

在本指南中，我们会使用 PyPI 作为包注册表。如果你更希望发布到其他注册表，也完全可以，只是具体步骤会有所不同。

### 配置凭证

首先，请确认你已经拥有一个 PyPI 账号：

<AccordionGroup>
    <Accordion title="如何创建 PyPI Token" icon="key">
        <Steps>
            <Step title="创建账号">
                前往 [PyPI 网站](https://pypi.org/) 并创建一个账号
            </Step>

            <Step title="验证邮箱">
                点击 PyPI 发送给你的邮件中的链接，完成邮箱验证
            </Step>

            <Step title="启用 2FA">
                打开你的账号设置，点击 "Generate Recovery Codes" 启用 2FA。要生成 API token，**必须**先启用 2FA
            </Step>

            <Step title="生成 token">
                打开账号设置，并[生成一个新的 API token](https://pypi.org/manage/account/token/)
            </Step>
        </Steps>
    </Accordion>
</AccordionGroup>

## 让你的集成可被发现

发布之后，请在 [LangChain 文档仓库](https://github.com/langchain-ai/docs/issues/new?template=06-integration-submission.yml)提交一个 **Integration listing** issue，这样你的包就会出现在 [integrations 标签页](/oss/python/integrations/providers/overview)下。

维护者会审核该 issue 并应用 `integration-run` 标签。这会启动自动化流程：它读取表单字段，应用下方的资格规则，并打开一个 PR，在其中 @ 一位维护者和你来审核。表单中请优先使用合作伙伴的文档 URL。

除非维护者要求，否则**不要**为新列表手动提交文档 PR。自动化流程会关闭来自外部贡献者的手动列表 PR，并引导他们使用 issue 表单。

### 托管指南的资格

只有当以下**任一**条件满足时，LangChain 才会在此文档仓库中托管完整的集成指南：

- 该包在 PyPI（TypeScript 则为 npm）上每月下载量至少达到 **50,000** 次，**或**
- 维护者将该集成标记为 **featured**

如果你不满足任一条件，自动化流程会添加一个**外部列表**（YAML + downloads 表 + provider 卡片），链接到你自己的文档。它**不会**添加托管的 MDX 页面。

### 列入 downloads 表（默认）

<Card
    title="提交 Integration listing issue"
    icon="ticket"
    href="https://github.com/langchain-ai/docs/issues/new?template=06-integration-submission.yml"
    arrow
>
    使用固定的表单字段填写显示名称、语言、组件、包名、文档 URL，以及简短的 provider 描述（最多 160 个字符）。
</Card>

自动化流程会根据你的 issue 填充 [`scripts/data/integration_external_docs.yaml`](https://github.com/langchain-ai/docs/blob/main/scripts/data/integration_external_docs.yaml) 及相关列表展示内容。

每个列表至少需要：

- **`name`**：LangChain 类名或显示名称（例如 `ChatAI21`）。
- **`pypi`** 或 **`npm`**：用于 downloads 徽章的注册表包名。
- **`docs_url`**：名称列的链接。优先使用合作伙伴文档，其次是 GitHub 仓库，最后是 PyPI 或 npm 页面。

可选地，在 issue 表单中包含组件特定的能力标志（例如 chat 的 `stream` 和 `tool_calling`），以确保表格各列的信息准确。

合并后，刷新任务会重新生成组件表格片段，使你的条目与托管集成一起显示。

<Info>
    此流程**仅用于列表元数据**。请在你自己的网站或 GitHub README 上托管使用文档。你的集成包本身应位于你自己的 GitHub 组织或账号下的独立仓库中，并作为独立包发布。
</Info>

### 托管指南（50K+ 或 featured）

如果你的包满足[资格标准](#eligibility-for-hosted-guides)，Integration listing 自动化流程可以使用以下模板之一打开一个包含文档页面的 PR。维护者也可能要求你手动编写或修订托管页面。

根据你构建的集成类型不同，你需要创建的文档页面类型也不同。LangChain 为不同类型的集成提供了模板，帮助你快速开始。

<Tip>
    如果你想参考现有文档，可以查看[集成列表](/oss/python/integrations/providers/overview)，然后找到和你类似的集成。

    如果你想查看某个文档页面的原始 markdown，可以点击页面右上角 "Copy page" 旁边的下拉按钮，然后选择 "View as Markdown"。
</Tip>

如果你被要求手动编辑托管页面，请将 [LangChain 文档仓库](https://github.com/langchain-ai/docs)（不是主 `langchain` 仓库）fork 到你的账号下，按对应的模板编写，并遵循[文档指南](/oss/python/contributing/documentation)。

如果你的包之前已列入 [`integration_external_docs.yaml`](https://github.com/langchain-ai/docs/blob/main/scripts/data/integration_external_docs.yaml)，请在同一个 PR 中移除该 YAML 条目，以免表格中出现重复行。

除非维护者要求，否则不要在 frontmatter 中设置 `featured: true`。featured 状态由维护者决定。

<Info>
    托管指南的 PR **只用于文档**。你的集成包本身应位于你自己的 GitHub 组织或账号下的独立仓库中，并作为独立包发布。
</Info>

<Warning>
    在以下情况下，我们可能会拒绝列表 issue 或 PR，或要求修改：
    - 请求托管页面时，包不符合[托管指南资格标准](#eligibility-for-hosted-guides)
    - CI 检查失败
    - 存在严重语法错误或拼写错误
    - [Mintlify components](/oss/python/contributing/documentation#mintlify-components) 使用不正确
    - 页面缺少 [frontmatter](/oss/python/contributing/documentation#page-structure)
    - 缺少[本地化](/oss/python/contributing/documentation#localization)（在适用情况下）
    - [代码示例](/oss/python/contributing/documentation#in-code-documentation) 无法运行或存在错误
    - 不符合[质量标准](/oss/python/contributing/documentation#quality-standards)
</Warning>

由于我们需要处理大量提交，请保持耐心。自动化 PR 打开后请及时查看审核。**不要反复 @ 维护者催促你的 issue 或 PR。**

<Note>
    如果 PR 包含 AI 生成内容，你必须遵循我们的[LLM 可接受使用方式](/oss/python/contributing/overview#acceptable-uses-of-llms)政策。
</Note>
