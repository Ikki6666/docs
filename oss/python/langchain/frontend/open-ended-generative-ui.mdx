## 概览

开放式 generative UI 位于 [generative UI 范围](/oss/python/langchain/frontend/generative-ui-overview) 中由智能体创建的一端。界面在你的应用程序之外编写，例如由 MCP 服务器编写，你的前端在沙盒中渲染它。你和智能体都不编写组件：第三方发布它们，你的应用托管它们。

这种方式提供了最宽的表达空间：智能体拥有画布。一项能力可以带着自己的界面一起到来，因此你可以呈现你从未实现过的交互式工具，而你这边不需要任何前端代码。它适合一次性的可视化和定制化回答，在这些场景下，一个令人惊喜且足够好的结果胜过可预测的结果。它也是最具实验性的方式：确定性最低、运行更慢、成本更高，而且不受信任的 UI 最难做到一致、无障碍和安全，因此必须将它与应用程序的其他部分隔离。

## 何时使用这种方式

当你想要呈现存在于你的应用程序之外、并独立于它演进的能力和界面时，使用开放式 generative UI，例如由 MCP 服务器生态发布的工具。当你需要保证品牌、无障碍性或布局时，沿着这个范围退回到[声明式](/oss/python/langchain/frontend/declarative-generative-ui)或[受控](/oss/python/langchain/frontend/controlled-generative-ui) generative UI，由你的应用程序掌管组件。

## MCP Apps

[Model Context Protocol](https://modelcontextprotocol.io) 让智能体可以连接到提供工具和资源的外部服务器。MCP Apps 将这个想法扩展到界面：MCP 服务器发布交互式 UI，前端渲染它，通常在 iframe 中，直接呈现在对话里。服务器掌管组件、数据和交互，而你的应用程序提供框架和与智能体的连接。

CopilotKit 将这种模式记录为 [MCP Apps](https://docs.copilotkit.ai/generative-ui/mcp-apps)。

## 沙盒与安全

由于界面来自第三方，请将其视为不受信任的内容。在隔离的 context 中渲染它，例如沙盒化的 iframe，并约束它可以访问的内容，这样行为不当或恶意应用就无法触及你页面的其他部分或用户的数据。沙盒化让这个范围的开放端可以在生产环境中使用：它约束的是表达范围，而不是限制它。
