**Functional API** 用 LangGraph 的运行时能力（[持久化](/oss/python/langgraph/persistence)、[记忆](/oss/python/langgraph/add-memory)、[human-in-the-loop](/oss/python/langgraph/interrupts) 和 [streaming](/oss/python/langgraph/streaming)）封装普通函数。如果你已有现成代码，或正在使用其他框架，并希望在不把该智能体改写为图的前提下[将其部署到 LangSmith](/langsmith/deploy-other-frameworks)，请使用它。构建新智能体时优先使用 [Graph API](/oss/python/langgraph/graph-api)。

本页是 entrypoint、task、checkpointing 和恢复规则的概念参考。封装并部署的操作步骤请参阅[部署其他框架](/langsmith/deploy-other-frameworks)。

Functional API 使用两个构件：

* **`@entrypoint`**：把一个函数标记为工作流起点。它负责管理执行、interrupt 和 checkpointing。
* **`@task`**：标记一个离散的工作单元（例如一次 API 调用）。Task 返回一个类 future 对象，你可以等待它，或用 `.result()` 解析它。




## 何时使用 Functional API

| 构建方式 | 使用 |
| --- | --- |
| 新建 LangGraph 智能体和工作流 | [Graph API](/oss/python/langgraph/graph-api) |
| 其他框架中已有的智能体（Claude Agent SDK、Strands、CrewAI、AutoGen 等），希望运行在 LangSmith Deployment 上 | 通过[部署其他框架](/langsmith/deploy-other-frameworks)使用 Functional API |

与 Graph API 相比，Functional API 使用普通的语言控制流（`if` / `else`、循环和调用），把值限制在 entrypoint 和 task 的作用域内，而不是使用共享的 [state](/oss/python/langgraph/graph-api#state) schema；它把 task 结果保存到 entrypoint 的 checkpoint，而不是在每个 [super-step](/oss/python/langgraph/graph-api#super-steps) 后保存；它也不提供静态的图可视化。

## Entrypoint

`@entrypoint` 装饰器从函数创建工作流。它负责管理长时间运行的工作和 [interrupt](/oss/python/langgraph/interrupts)。




### Definition

需要持久化或 human-in-the-loop 时，请传入 [checkpointer](/oss/python/langgraph/persistence)。在配置中用 `thread_id` 标识每次运行。thread 是一次对话或一次工作流运行的持久标识。

**entrypoint** 是用 `@entrypoint` 装饰的函数。

该函数**必须接受一个位置参数**，作为工作流输入。要传递多个值，请用字典（或类似结构）作为这个参数。

装饰该函数会生成一个工作流对象（[`Pregel`](https://reference.langchain.com/python/langgraph/pregel/#langgraph.pregel.Pregel.stream) 实例）。调用 `invoke` 或 `ainvoke` 来运行它。

### 运行与恢复

要获得最终结果，请调用 `invoke` 或 `ainvoke`。流式用法请参阅[流式输出](/oss/python/langgraph/streaming)。




在 [`interrupt`](https://reference.langchain.com/python/langgraph/types/interrupt) 之后，把 resume 值传入 [`Command`](https://reference.langchain.com/python/langgraph/types/Command) 即可恢复。具体做法请参阅 [Interrupts（中断）](/oss/python/langgraph/interrupts)。

出错后，用 `None` 恢复同一个 `thread_id`。




### 短期记忆

当 `entrypoint` 配置了 `checkpointer` 时，同一个 **thread id** 上的连续调用会把状态存入 [checkpoint](/oss/python/langgraph/checkpointers#checkpoints)。

添加一个仅限关键字的 `previous` 参数。LangGraph 会把它设为该 thread 上最后保存的值。首次运行时它是 `None`。要为下一次运行保存不同的值，请使用 [`entrypoint.final`](https://reference.langchain.com/python/langgraph/func/entrypoint/final)。




### Injectable parameters

在添加[记忆](/oss/python/langgraph/add-memory)或[自定义流式输出](/oss/python/langgraph/streaming)之前，可以先跳过这一节。

定义 `entrypoint` 时，你可以请求额外参数，LangGraph 会在运行时注入它们：

| 参数 | 说明 |
| ---- | ---- |
| **previous** | 同一 thread 上一次调用的返回值（需要配置 checkpointer）。请参阅[短期记忆](#short-term-memory)。 |
| **config** | 包含运行时配置值的 [`RunnableConfig`](https://reference.langchain.com/python/langchain-core/runnables/config/RunnableConfig) 对象。 |
| **store** | 用于[长期记忆](/oss/python/langgraph/add-memory)的 [`BaseStore`](https://reference.langchain.com/python/langchain-core/stores/BaseStore) 实例。也可以从 `runtime.store` 访问。 |
| **writer** | 用于自定义流式输出的 `StreamWriter`。也可以从 `runtime.stream_writer` 访问。请参阅[流式输出](/oss/python/langgraph/streaming)。 |
| **runtime** | 当前运行的 [`Runtime`](https://reference.langchain.com/python/langgraph/runtime/Runtime) 对象，包含 context、store 和 writer。 |

<Warning>
请用合适的名称和类型注解声明这些可注入参数。
</Warning>

## Task

**task** 是一个离散的工作单元（例如一次 API 调用或一个数据处理步骤）。Task 有两个关键特性：

* **Concurrent execution**：调用 task 会立即启动它。只有在你等待结果时 entrypoint 才会阻塞，因此相互独立的 task 可以重叠执行。
* **Checkpointing**：task 结果会被保存，恢复时可从 checkpoint 还原。请参阅 [持久化](/oss/python/langgraph/persistence)。

### 何时使用 task

以下场景适合使用 **task**：

* **Checkpointing**：保存长时间运行的结果，恢复时无需重新计算。
* **Human-in-the-loop**：把暂停后不应重做的工作放进 task，例如 LLM 调用。[interrupt](/oss/python/langgraph/interrupts) 后恢复时会还原该结果。关于随机性，请参阅 [Determinism](#determinism)。
* **Parallel execution**：并发运行相互独立的 I/O 密集型工作。
* **Observability**：在 [LangSmith](/langsmith/observability) 中跟踪各个离散步骤。
* **Retries**：对离散工作单元应用重试策略。请参阅[容错能力](/oss/python/langgraph/fault-tolerance)。

## 恢复与 checkpointing

恢复时的重放依赖序列化、确定性和幂等性。

### Serialization

配置 checkpointer 时，有两条规则：

1. `entrypoint` 的输入和输出必须是 JSON 可序列化的。
2. `task` 的输出必须是 JSON 可序列化的。

请使用字典、列表、字符串、数字和布尔值等 Python 原语。




序列化让 task 结果和中间值可以在 human-in-the-loop、容错和并行执行时被还原。配置 checkpointer 时，不可序列化的值会在运行时引发错误。

### Determinism

恢复**不会**从执行停止的那一行继续。执行会回到某个 checkpoint 边界，然后**向前重放**，直到再次到达暂停点。

对 Functional API 而言，重放从 **entrypoint** 的开头开始。LangGraph 会从 checkpointer 还原已完成的 [**task**](#task) 和 [**subgraph**](/oss/python/langgraph/use-subgraphs) 结果，而不是重新计算。这样可以在暂停之间保持步骤顺序，包括长时间运行或非确定性的 **task** 输出。

使用 **human-in-the-loop** 时，请把非确定性工作（例如随机值）和副作用（例如文件写入或 API 调用）放进 [**task**](#task)。

不同的运行可以产生不同的结果。恢复**特定** thread 时应重放相同的已持久化 **task** 和 **subgraph** 结果。

准则：

* **Avoid repeating work**：为 entrypoint 中的每个副作用单独建一个 **task**，这样恢复时会还原输出，而不是重新执行。
* **Encapsulate non-deterministic operations**：把不同尝试之间会变化的值（随机数、系统时钟时间）放进 **task**。
* **Use idempotent operations**：关于部分失败和重试，请参阅 [Idempotency](#idempotency)。

### Idempotency

幂等性意味着同一操作执行多次与执行一次的效果相同。请把 API 调用和其他写入操作放进 **task**，并把这些 task 设计成重复运行也安全。

恢复时，LangGraph 会还原已完成的 **task** 结果。已经开始但未完成的 **task** 可能会再次运行，因此请使用幂等键，或在写入前检查已有结果。

## 常见陷阱

### 处理副作用

把副作用（写文件、发送邮件）放进 task，这样恢复时不会再次执行。

<Tabs>
    <Tab title="Incorrect">
    文件写入在 entrypoint 中执行，因此恢复时会再执行一次。

    ```python
    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint
    from langgraph.types import interrupt

    checkpointer = InMemorySaver()

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        # Runs again on resume.
        with open("output.txt", "w") as f:  # [!code highlight]
            f.write("Side effect executed")  # [!code highlight]
        value = interrupt("question")
        return value
    ```



    </Tab>
    <Tab title="Correct">
    副作用放在 task 中，因此恢复时会还原已写入 checkpoint 的结果。

    ```python
    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint, task
    from langgraph.types import interrupt

    checkpointer = InMemorySaver()

    @task  # [!code highlight]
    def write_to_file() -> None:  # [!code highlight]
        with open("output.txt", "w") as f:
            f.write("Side effect executed")

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        write_to_file().result()
        value = interrupt("question")
        return value
    ```



    </Tab>
</Tabs>

### 非确定性控制流

把时间和随机性封装进 task，这样恢复时会返回相同的值。

* 在 task 中：获取随机数（5）→ interrupt → 恢复 →（再次返回 5）→ ...
* 不在 task 中：获取随机数（5）→ interrupt → 恢复 → 获取新的随机数（7）→ ...

有多个 [`interrupt`](https://reference.langchain.com/python/langgraph/types/interrupt) 调用时，LangGraph 会**按索引**把 resume 值匹配到每个 interrupt。如果恢复时 interrupt 的顺序发生变化，一个 resume 值可能被关联到错误的 interrupt。请参阅 [Determinism](#determinism)。

<Tabs>
    <Tab title="Incorrect">
    在 entrypoint 中读取时钟可能改变恢复时执行的分支。

    ```python
    import time

    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint, task
    from langgraph.types import interrupt

    checkpointer = InMemorySaver()

    @task
    def slow_task(x: int) -> int:
        return x

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> dict:
        t0 = inputs["t0"]
        t1 = time.time()  # [!code highlight]

        delta_t = t1 - t0

        if delta_t > 1:
            result = slow_task(1).result()
            value = interrupt("question")
        else:
            result = slow_task(2).result()
            value = interrupt("question")

        return {"result": result, "value": value}
    ```



    </Tab>
    <Tab title="Correct">
    在 task 内读取时钟，这样恢复时会还原相同的时间戳和分支。

    ```python
    import time

    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint, task
    from langgraph.types import interrupt

    checkpointer = InMemorySaver()

    @task
    def slow_task(x: int) -> int:
        return x

    @task  # [!code highlight]
    def get_time() -> float:  # [!code highlight]
        return time.time()

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> dict:
        t0 = inputs["t0"]
        t1 = get_time().result()  # [!code highlight]

        delta_t = t1 - t0

        if delta_t > 1:
            result = slow_task(1).result()
            value = interrupt("question")
        else:
            result = slow_task(2).result()
            value = interrupt("question")

        return {"result": result, "value": value}
    ```



    </Tab>
</Tabs>
