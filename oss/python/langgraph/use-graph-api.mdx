## 构建你的图

按顺序处理这些决策。每一步都包含一个简短示例，并链接到包含完整做法的操作指南。

<Steps>
<Step title="定义共享状态">
确定节点之间共享哪些数据，以及更新如何合并。

- 选择一种 schema（`TypedDict`、dataclass，或在 TypeScript 中使用 `StateSchema`）。
- 为多个节点写入的每个键添加 [reducer](/oss/python/langgraph/graph-api#reducers)（例如追加消息）。
- 当图需要向调用方隐藏内部通道时，使用私有 schema 或输入/输出 schema。

关于 schema、reducer、消息和私有状态，参见 [定义和更新状态](/oss/python/langgraph/graph-api-state)。
</Step>

<Step title="选择控制流">
确定工作如何在节点之间流转。

- **顺序**：按固定顺序执行的步骤。
- **分支**：条件边根据状态选择下一个节点。
- **并行**：扇出到多个节点，然后再扇入（通常配合 reducer）。
- **循环**：反复执行直到满足终止条件，或用[递归限制](/oss/python/langgraph/graph-api#recursion-limit)限制运行次数。

关于分支、并行路径和循环，参见 [构建序列、分支和循环](/oss/python/langgraph/graph-api-control-flow)。
</Step>

<Step title="判断是否需要 Send 或 Command">
大多数图只需要节点、边和条件边。除非遇到下面的情况，否则把路由逻辑放在边里。模式与示例参见 [使用 Send 和 Command](/oss/python/langgraph/graph-api-send-command)。

当默认模型不够用时，再使用这些额外机制：

- 当需要对同一节点按条目各运行一次、每个条目有各自的输入，且条目数量只有在运行时才知道时（map-reduce / orchestrator-worker），使用 [`Send`](https://reference.langchain.com/python/langgraph/types/Send)。
- 当一步操作既要更新状态又要选择下一个节点、需要在[中断](/oss/python/langgraph/interrupts)后恢复，或需要从工具中更新状态时，使用 [`Command`](https://reference.langchain.com/python/langgraph/types/Command)。

<LanggraphUseGraphApiSendCommandPy />




</Step>

<Step title="按需配置节点">
当可靠性或成本很重要时，添加运行时选项：

- 针对不稳定或缓慢步骤的重试与超时
- 错误处理程序和全图节点默认值
- 针对开销较大的重复工作的缓存
- 为不属于状态的依赖提供运行时上下文或 config

参见 [配置节点](/oss/python/langgraph/graph-api-nodes)。
</Step>

</Step>
</Steps>
