LangSmith 会根据你的[套餐](/langsmith/pricing-plans)和[部署类型](/langsmith/platform-setup)，提供多种查看[组织](/langsmith/administration-overview)使用情况的方式。本页说明可用的数据、各项指标的含义，以及 [self-hosted](/langsmith/self-hosted) 部署适用的限制。

## 使用情况视图

| View | Where to find it | Who can see it | Plan availability |
|------|-----------------|----------------|-------------------|
| [Usage graph](#usage-graph) |**Enterprise**: Settings > Usage > Usage graph<br></br>**Self-serve**: Settings > Billing > Usage graph | All org members | All plans |
| [Granular usage](#granular-usage) | **Enterprise**: Settings > Usage > Granular usage<br></br>**Self-serve**: Settings > Billing > Granular usage | All org members | All plans |
| [Contract usage](#contract-usage) | **Enterprise**: Settings > Usage > Contract usage<br></br>**Self-serve**: Settings > Billing > Contract usage | Org admins only (`organization:manage`) | Enterprise only |
| [Invoices](#invoices) | Settings > Billing > Invoices | All org members | Self-serve cloud only |

## 使用情况图表

使用情况图表会显示组织的聚合 trace 消耗，并按 workspace 拆分。它覆盖当前计费周期，但不显示花费金额，如需查看花费，请参考发票。

进入 **Settings** → **Billing and Usage** → **Usage Graph**。

### 计费指标

| Metric | What it counts |
|--------|----------------|
| **LangSmith Traces (Base Charge)** | 当前计费周期内发送到 LangSmith 的每一条 trace，无论数据保留层级如何。 |
| **LangSmith Traces (Extended Data Retention Upgrades)** | 被升级为扩展保留的 traces，默认保留 400 天，[企业客户可自定义](/langsmith/data-purging-compliance#customize-extended-retention-policy)。这部分费用是在基础费用之外单独计费的。 |
| **LangSmith Deployment Runs** | 已部署 LangGraph 智能体的端到端调用次数。定价详情请参阅 [LangSmith Deployment billing](/langsmith/billing#langsmith-deployment-billing)。 |
| **LangSmith Fleet Runs** | [Fleet](/langsmith/fleet) 智能体的端到端调用次数。cloud-hosted 和 self-hosted 部署会分别统计。 |
| **LangSmith Deployment Nodes Executed** | 已部署智能体中各个 LangGraph 节点的单次执行次数。部署图中的每一步都会计为一次节点执行。cloud-hosted 和 self-hosted 部署会分别统计。 |

有关 trace 保留层级的更多细节，请参阅[数据保留](/langsmith/usage-and-billing#data-retention)。

<Note>
在使用情况图表中，`tenant_id` 与 workspace ID 是可互换使用的术语。
</Note>

## 合同使用情况

拥有预付承诺额度的企业客户可以查看合同已消耗了多少。

进入 **Settings** → **Usage Configuration** → **Contract Usage**。

此视图会显示：

- **Usage summary**：总使用量、总 credits，以及任何超额部分。当使用量超过预付承诺总额时，就会出现超额。
- **Commitment progress bars**：每项承诺的可视化进度条，显示已消耗百分比，以及已使用和剩余的美元金额。合同中可能有多项适用于不同时间段的承诺，例如多年合同的第一年和第二年，或者不同产品。
- **Monthly usage chart**：柱状图，显示合同期内每个月的使用量。
- **Product rates**：列出你有权使用的产品及其定价的表格。

<Note>
合同使用情况要求具备 [`organization:manage` 权限](/langsmith/organization-workspace-operations)，并且仅对拥有预付承诺的 Enterprise 客户开放。
</Note>

<Note>
如果你的合同覆盖同一计费实体下的多个组织，合同使用情况视图显示的是这些组织的**合并**使用量，而不只是你当前查看的那个组织。[Granular usage](#granular-usage) 始终限定在单个组织范围内，因此如果要查看某个特定组织的 granular usage，请切换到该组织后单独查看。
</Note>

## 发票

发票仅在 **self-serve cloud plans** 中可用。Enterprise cloud 组织会使用单独的使用情况视图来跟踪花费。

进入 **Settings** → **Billing and Usage** → **Invoices**，查看你的使用情况如何转换为花费。显示的第一张发票是当月发票的草稿，反映截至目前的累计花费。

## Granular usage

Granular usage 会按照你选择的维度，例如 workspace、project、user 或 API key，在你选定的时间范围内细分 trace 数量。这适用于内部成本分摊、识别高使用量团队，或审计 trace 活动。

进入 **Settings** → **Billing and Usage** → **Granular Usage**，或使用 [granular usage API](/langsmith/granular-usage)。

### 这里的 “traces” 指什么

Granular usage 统计的是 **traces**，也就是根级 run 及其所有子 span 作为一个整体来计数。这与[billing](/langsmith/billing)所使用的计量单位相同。它不会单独统计每个 span、token 或模型调用。

### 使用量在何时记录

Granular usage 按 **insertion time** 来记录 traces，也就是 LangSmith 接收到并存储 trace 的时间，而不是它在你应用里实际运行的时间。实际场景中这个差异通常可以忽略，但如果 trace 存在明显延迟才被发送，例如 SDK 缓冲后批量上传，它可能会出现在比预期更晚的时间桶中。

有关分组选项、时间桶粒度和 API 参考，请参阅 [Granular billable usage](/langsmith/granular-usage)。

## Self-hosted 限制

由于计费基础设施不同，[self-hosted](/langsmith/self-hosted) 的 LangSmith [deployments](/langsmith/deployment) 与 [Cloud](/langsmith/cloud) 相比，可用的使用情况视图也有所不同。

| **Feature** | **Self-hosted availability** |
|---------|--------------------------|
| Granular usage (trace attribution) | 可用，但需要 feature flags，或版本 ≥ 0.13.12 |
| Usage graph (aggregate traces) | Helm chart 0.9.5 及以后版本可用 |
| Contract usage | 启用 Beacon phone-home 后可用 |
| Invoices and payment management | 不可用，计费在 LangSmith 之外处理 |

### Self-hosted 上的 granular usage

Granular usage 在 self-hosted 部署中可用，但需要显式启用：

- 在 **LangSmith 0.13.12 及以后版本**中，granular usage 采集默认启用。
- 在**更早版本**中，需要同时设置以下两个环境变量：

    ```env
    DEFAULT_ORG_FEATURE_ENABLE_GRANULAR_USAGE_REPORTING=true
    GRANULAR_USAGE_TABLE_ENABLED=true
    ```

<Warning>
数据采集会从功能启用的那一刻开始。启用之前的历史使用数据不会回填。选择启用时机时请提前规划。
</Warning>

### Self-hosted 上的聚合使用情况

使用情况图表可用于运行 Helm chart 0.9.5 或更高版本的 self-hosted 部署。LangSmith 会自动生成并同步组织使用情况图表，可在 **Settings** → **Usage and billing** → **Usage graph** 中查看：

- **Usage by Workspace**：按 workspace 统计的 trace 数量，即 root runs
- **Organization Usage**：整个组织的总 trace 数量

图表每 5 分钟刷新一次，以纳入新增 workspace，且不可编辑。

如需以编程方式访问 trace 计数，请参阅[查看整个组织的 trace 计数](/langsmith/self-host-organization-charts)。
