<Note>
本指南假定你已经阅读过[管理员指南](/langsmith/administration-overview)和[组织设置指南](/langsmith/set-up-hierarchy#set-up-an-organization)。
</Note>

LangSmith 通过 feature flags 为用户管理提供了一些额外的自定义功能。

## 功能

### 在 workspace 层级邀请用户加入组织

LangSmith 的默认行为是，只有 Organization Admin 才能邀请新用户加入组织。对于希望把这项职责下放给 workspace Admin 的 self-hosted 客户，可以设置一个 feature flag，使 workspace Admin 也能**在 workspace 层级**邀请新用户加入组织及其对应的 workspace。

通过下面的配置选项启用该功能后，workspace Admin 就可以在 `Settings` > `Workspaces` 下的 `Workspace members` 标签页中添加新用户。在 workspace 层级发起邀请时，以下两种情况都受支持，而组织层级的邀请流程与之前相同。

1. 邀请尚未在组织中激活的用户：这会把这些用户以 pending 状态加入组织和指定 workspace。
2. 邀请已经在组织中激活的用户：这会把这些用户直接作为 active member 加入指定 workspace，不会经过 pending 状态。

管理员可以在同一次操作中同时邀请上述两类用户。

#### 配置

```yaml Helm
config:
  workspaceScopeOrgInvitesEnabled: true
```

### SSO 新成员登录流程

从 helm **v0.11.10** 开始，使用 OAuth SSO 的 self-hosted 部署不再需要在 LangSmith 设置中手动添加成员，用户才能加入。部署将拥有一个<b>默认</b>组织，新用户在首次登录 LangSmith 时会自动被加入该组织。

对于你的**默认**组织，你可以设置新成员应被分配到哪些 workspace，以及对应的 workspace 角色。对于**非默认**组织，邀请流程保持不变。
用户一旦加入某个组织，之后若要变更其 workspace 或角色，除默认组织设置外，仍需通过 LangSmith 设置，和之前一样，或通过 SCIM 来管理。
<Note>
默认情况下，所有新用户都会被加入该组织初始配置的 workspace，默认是 **Workspace 1**，并赋予 **Workspace Editor** 角色。
</Note>
![Update SSO Member Settings](/langsmith/images/sso-member-settings-update.png)

<Note>
如需修改默认组织，请在组织选择器下拉菜单中使用 **Set Default Organization**。源组织和目标组织都需要 Org Admin 权限。
</Note>


### SSO Groups Sync

<Note>
self-hosted 上的 SSO Groups Sync 要求 LangSmith chart 版本为 **0.15.0-rc.3**，应用版本 **0.15.2rc1**，或更高版本。
</Note>

[SSO Groups Sync](/langsmith/user-management#sso-groups-sync-alternative) 会从 OIDC ID token 中读取 group membership，并使用 [SCIM naming convention](/langsmith/user-management#group-naming-convention) 来分配组织和 workspace 角色。对于那些 IdP 可以在 OIDC token 中包含 groups、但不方便运行 SCIM provisioning 的 self-hosted 组织来说，这是 [SCIM](/langsmith/user-management#set-up-scim-for-your-organization) 的一种更简单替代方案。

关于 IdP 侧的配置，例如 claim 和 scope，请参阅 OIDC SSO 设置指南中的 [SSO Groups Sync 部分](/langsmith/self-host-sso#sso-groups-sync)。有关设置参考和具体行为，请参阅[主 SSO Groups Sync 文档](/langsmith/user-management#sso-groups-sync-alternative)。

### 禁止创建组织

默认情况下，任何用户都可以在 LangSmith 中创建组织。对于 self-hosted 客户，管理员可能希望在初始化组织完成后限制这项能力。这个 feature flag 允许管理员禁用用户创建新组织的能力。


#### 配置

<Note>
对于使用[basic auth](/langsmith/self-host-basic-auth)或 [SSO](/langsmith/self-host-sso) 的组织，`userOrgCreationDisabled` feature flag 默认就是 `true`。
</Note>

```yaml Helm
config:
  userOrgCreationDisabled: true
```

### 禁止个人组织

默认情况下，任何登录 LangSmith 的用户都会为自己创建一个个人组织。对于 self-hosted 客户，管理员可能希望限制这项能力。这个 feature flag 允许管理员禁用用户创建个人组织的能力。

#### 配置

<Note>
对于使用[basic auth](/langsmith/self-host-basic-auth)或 [SSO](/langsmith/self-host-sso) 的组织，`personalOrgsDisabled` feature flag 默认就是 `true`。
</Note>

```yaml Helm
config:
  personalOrgsDisabled: true
```

### 禁止创建 personal access tokens

<Note>
此功能要求 Helm chart 版本为 0.13.12，对应应用版本也为 0.13.12，或更高版本。
</Note>

默认情况下，用户可以在任意组织中创建 Personal Access Tokens，PATs。对于 self-hosted 客户，管理员可能希望在整个实例范围内全局禁用 PAT 创建。这个环境变量允许管理员阻止用户在实例中的任何组织里创建新的 PAT。

如果你想只对单个组织禁用 PAT 创建，请参阅[按组织配置的 API 选项](/langsmith/manage-organization-by-api#security-settings)。

#### 配置

```yaml Helm
commonEnv:
  - name: PAT_CREATION_DISABLED
    value: "true"
```
