LLM Gateway 位于你的应用与工作区所配置的 model providers 之间。它会认证调用者、选择上游路由、应用治理策略、在 API 格式之间进行转换，并追踪结果。

## 跟随请求穿过 gateway

对于发往标准 endpoint 的每个请求，gateway 会执行以下步骤。它应用的 provider keys、权限和策略来自[设置 gateway](/langsmith/llm-gateway-admin-setup)。

1. **根据 LangSmith API key 认证并授权调用者**，包括 `gateway:invoke` 权限检查。详细信息请参见[认证 LLM Gateway](/langsmith/llm-gateway-authentication)。
2. **解析路由**，依据 endpoint 和 model ID，包括已配置的 [fallback candidates](/langsmith/llm-gateway-fallbacks)。
3. **加载上游凭证**，例如工作区 provider key 或 [Gateway Credits](/langsmith/llm-gateway-credits) 凭证。详细信息请参见 [Provider authentication](/langsmith/llm-gateway-provider-authentication)。
4. **评估请求前策略。** [Spend](/langsmith/llm-gateway-spend-policies)、[rate](/langsmith/llm-gateway-rate-limit-policies) 和 [model access](/langsmith/llm-gateway-model-access-policies) 限制可以拦截请求。[Data protection policies](/langsmith/llm-gateway-data-policy) 会针对请求体运行，并在配置后对请求体进行脱敏。
5. **转换请求**，当所选 provider 使用不同的 API 格式时。详细信息请参见[理解转换行为](/langsmith/llm-gateway-api-formats#understand-translation-behavior)。
6. **向上游发送请求**，并接收或流式接收 provider 响应。
7. **转换响应**，转换回 client 所请求的 API 格式，并在适用时恢复脱敏占位符。
8. **返回响应**给调用者，同时记录用量、成本、路由和策略 metadata，以及 LangSmith trace。详细信息请参见[查看 LLM Gateway traces](/langsmith/llm-gateway-traces)。

[Direct model access](/langsmith/llm-gateway-direct-model-access) 会跳过第 5 步和第 7 步。gateway 仍然会认证、解析凭证、评估策略并追踪调用，但会以 provider 的原生格式透传请求和响应。

## 选择凭证管理方式

gateway 会为每次调用解析一个上游凭证。一个工作区可以使用自己的 provider keys、Gateway Credits，或两者兼用。有关每种凭证来源以及由谁计费，请参见 [Provider authentication](/langsmith/llm-gateway-provider-authentication#choose-a-credential-source)。

## 理解工作区范围

请求会使用其 API key 所属工作区的设置。Gateway 设置的作用范围有所不同：

- **Provider keys**：工作区 secret。每个调用某个 provider 的工作区都需要自己的 key。
- **Fallback 链**：在一个工作区中创建，并应用于来自该工作区 API keys 的请求。请参见[模型 fallback](/langsmith/llm-gateway-fallbacks)。
- **Traces**：记录在发出请求的 API key 所属工作区中。
- **模型配置**：工作区或组织范围。组织范围的配置会读取组织 secret。请参见[自定义模型配置](/langsmith/llm-gateway-model-configurations)。
- **策略**：每条[支出限制](/langsmith/llm-gateway-spend-policies)、[速率限制](/langsmith/llm-gateway-rate-limit-policies)、[模型访问策略](/langsmith/llm-gateway-model-access-policies)和[数据策略](/langsmith/llm-gateway-data-policy)都适用于整个组织、一个工作区、一个用户或一个 API key。

## 检查可用性

gateway 运行在：

- LangSmith Cloud 的每个 LangSmith region
- [自带云（BYOC）](/langsmith/byoc)，它运行在你的 data plane 内，因此模型请求及其 traces 都留在你的 VPC 中
- [Self-hosted](/langsmith/self-hosted) LangSmith

这三种环境使用相同的 API 格式、model IDs、策略和 tracing。只有 hostname 和 path prefix 不同。在低于应用版本 0.18.9（Helm chart 版本低于 0.18.0-rc.22）的自托管 LangSmith 上，管理策略需要 `organization:manage` 而非 `organization:gateway:manage`。

### 使用区域 gateway

把 `gateway.smith.langchain.com` 替换为你所在 LangSmith region 的 hostname，并保留你所使用的 API 格式对应的 path：

| Region | Gateway hostname |
| --- | --- |
| GCP US | `gateway.smith.langchain.com` |
| GCP EU | `eu.gateway.smith.langchain.com` |
| GCP APAC | `apac.gateway.smith.langchain.com` |
| AWS US | `aws.gateway.smith.langchain.com` |

### 使用 BYOC data plane

在 BYOC 上，把 gateway hostname 替换为你的 [data plane endpoint](/langsmith/byoc-usage#find-your-data-plane-endpoint)，并在 path 前加上 `/gateway`：

| API 格式 | Base URL | Prompt endpoint |
| --- | --- | --- |
| OpenAI Chat Completions | `https://<data_plane_host>/gateway/v1` | `POST /chat/completions` |
| Anthropic Messages | `https://<data_plane_host>/gateway` | `POST /v1/messages` |
| OpenAI Responses | `https://<data_plane_host>/gateway/v1` | `POST /responses` |

使用范围限定为该 data plane 中某个 workspace 的 API key 进行认证，并按照[发送 key](/langsmith/llm-gateway-authentication#send-the-key)中列出的任意 header 传入。Provider secrets、model IDs、策略和 tracing 的行为与 Cloud 上相同。

<Warning>
Data planes 默认以 private endpoint 预配，因此你需要私有连接才能访问 base URL，例如 Tailscale、AWS PrivateLink 或 VPC peering。
</Warning>

### 使用自托管安装

在自托管 LangSmith 上，管理员需要先[在 Helm chart 中启用 gateway](/langsmith/llm-gateway-self-hosted)。然后把 gateway hostname 替换为你的 LangSmith hostname，并在 path 前加上 `/gateway`：

| API 格式 | Base URL | Prompt endpoint |
| --- | --- | --- |
| OpenAI Chat Completions | `https://<your-hostname>/gateway/v1` | `POST /chat/completions` |
| Anthropic Messages | `https://<your-hostname>/gateway` | `POST /v1/messages` |
| OpenAI Responses | `https://<your-hostname>/gateway/v1` | `POST /responses` |

使用范围限定为你安装中某个 workspace 的 API key 进行认证，并按照[发送 key](/langsmith/llm-gateway-authentication#send-the-key)中列出的任意 header 传入。
