这是一份将应用部署到 LangSmith Cloud 的完整配置与管理指南。LangSmith Cloud 运行在 AWS 和 GCP 上（具体区域请参阅 [Cloud overview page](/langsmith/cloud)）。

本指南涵盖两种部署方式：一是通过 [LangSmith UI](https://smith.langchain.com) 从关联的 GitHub 仓库部署，二是通过 [`langgraph deploy` CLI 命令](/langsmith/cli#deploy) 直接从你的本地机器构建并推送。

<Callout icon="bolt" color="#4F46E5" iconType="regular">
**如果你想快速开始**，建议先看[quickstart guide](/langsmith/deployment-quickstart)。
</Callout>

在开始之前，请先阅读 [Cloud overview page](/langsmith/cloud)，理解 Cloud 的托管模型。

## 前置条件

- 一个 [Plus plan 或更高版本](https://www.langchain.com/pricing) 的 LangSmith 账户。
- [确认 LangGraph API 能在本地成功运行](/langsmith/local-dev-testing)。如果 API 本地运行失败（即 `langgraph dev` 无法正常工作），那么部署到 LangSmith 也同样会失败。

## 创建新 deployment

请选择与你的工作流匹配的部署方式：LangSmith UI 会连接 GitHub 仓库，并支持在 push 后自动部署；而 `langgraph deploy` CLI 命令则会直接从本地项目目录构建并部署。

<Tabs>
  <Tab title="LangSmith UI">
    <Note>
    **One-Time Setup Required**：GitHub organization owner 或 admin 必须先在 LangSmith UI 中完成 OAuth 流程，以授权 `hosted-langserve` GitHub app。这个步骤在每个 workspace 中只需执行一次。完成首次 OAuth 授权后，所有拥有部署权限的开发者都可以创建和管理 deployments，而不再需要 GitHub admin 权限。
    </Note>

    从 [LangSmith UI](https://smith.langchain.com) 开始，在左侧导航中选择 **Deployments**，进入 **Deployments** 页面。在右上角点击 **+ New Deployment** 创建一个新 deployment：

    1. 在 **Create New Deployment** 面板中，填写必需字段。对于 **Deployment details**：
        1. 选择 **Import from GitHub**，并按照 GitHub OAuth 流程安装并授权 LangChain 的 `hosted-langserve` GitHub app，使其可以访问所选仓库。安装完成后，返回 **Create New Deployment** 面板，并从下拉菜单中选择要部署的 GitHub 仓库。
            <Note> 安装 LangChain `hosted-langserve` GitHub app 的 GitHub 用户必须是该 organization 或账户的[owner](https://docs.github.com/en/organizations/managing-peoples-access-to-your-organization-with-roles/roles-in-an-organization#organization-owners)。该授权在每个 LangSmith workspace 中只需要做一次，后续任意拥有 deployment 权限的用户都可以创建 deployments。</Note>
        1. 指定 deployment 名称。
        1. 指定目标 **Git Branch**。一个 deployment 会与一个 branch 绑定。创建新 revision 时，系统会部署该 branch 对应的代码。后续你也可以在[Deployment Settings](#deployment-settings)中修改 branch。
        1. 指定 [LangGraph API config file](/langsmith/cli#configuration-file) 的完整路径，包括文件名。例如，如果 `langgraph.json` 位于仓库根目录，那么填写 `langgraph.json`。
        1. 使用复选框开启 **Automatically update deployment on push to branch**。如果勾选，当变更被 push 到指定 **Git Branch** 时，deployment 会自动更新。你之后也可以在 [Deployment Settings](#deployment-settings) 的 [UI](https://smith.langchain.com) 中启用或禁用该项。
        For **Deployment Type**:
            - Development deployments 用于非生产场景，并只分配最小资源。
            - Production deployments 可支持最高 500 requests/second，并配备高可用存储和自动备份。
        1. 决定该 deployment 是否应 **Shareable through Studio**。
            1. 若不勾选，则只有持有该 [workspace](/langsmith/administration-overview#workspaces) 的有效 LangSmith API key 的用户才能访问此 deployment。
            1. 若勾选，则任何 LangSmith 用户都可以通过 [Studio](/langsmith/studio) 访问此 deployment。系统还会提供该 deployment 的 Studio 直达链接，便于分享给其他 LangSmith 用户。
        1. 指定 **Environment Variables** 和 secrets。若要为 deployment 配置更多变量，请参阅 [Environment Variables reference](/langsmith/env-var-cloud)。
            1. 像 API keys 这样的敏感值（例如 `OPENAI_API_KEY`）应作为 secrets 配置。
            1. 你也可以额外配置非 secret 的环境变量。
        1. 系统会自动创建一个与 deployment 同名的 LangSmith [tracing project](/langsmith/observability)。
    1. 在右上角点击 **Submit**。几秒后，**Deployment** 视图会出现，新的 deployment 将进入 provisioning 队列。
  </Tab>
  <Tab title="LangGraph CLI">
    <Note>
    `langgraph deploy` 命令当前处于 **[beta](/langsmith/release-stages)**。它要求本机已经安装并运行 [Docker](https://docs.docker.com/get-docker/)。如果你使用 Apple Silicon（M1/M2/M3），还需要安装 [Docker Buildx](https://docs.docker.com/build/install-buildx/) 以便交叉编译到 `linux/amd64`。
    </Note>

    1. 安装 [LangGraph CLI](/langsmith/cli)：
        ```shell
        uv tool install langgraph-cli
        ```
    1. 在项目根目录的 `.env` 文件中添加 LangSmith API key：
        ```shell
        LANGSMITH_API_KEY=lsv2_...
        ```
    1. 在你的项目目录中执行部署命令：
        ```shell
        langgraph deploy
        ```
        这会创建一个名为项目目录名的 `dev` deployment。如果想指定其他名称，可以使用 `--name`；如果想创建 production deployment，则使用 `--deployment-type prod`：
        ```shell
        langgraph deploy --name my-agent --deployment-type prod
        ```
        命令完成后，deployment 会进入 provisioning 队列。环境变量可以在 deployment 创建后通过 [LangSmith UI](https://smith.langchain.com) 管理，也可以配置在 [`langgraph.json` 的 `env` 字段中](/langsmith/cli#configuration-file)。
  </Tab>
</Tabs>

## 创建新 revision

在[创建新 deployment](#create-new-deployment)时，系统默认会创建一个新 revision。之后如果你有新的代码变更，也可以创建后续 revisions。

<Tabs>
  <Tab title="LangSmith UI">
    从 [LangSmith UI](https://smith.langchain.com) 开始，在左侧导航中选择 **Deployments**。选中某个已有 deployment，为它创建新的 revision。

    1. 在 **Deployment** 视图中，点击右上角的 **+ New Revision**。
    1. 在 **New Revision** 模态框中，填写必需字段。
        1. 指定 [API config file](/langsmith/cli#configuration-file) 的完整路径，包括文件名。例如，如果 `langgraph.json` 位于仓库根目录，则填写 `langgraph.json`。
        1. 决定 deployment 是否应 **Shareable through Studio**。
            - 若不勾选，则只有持有该 [workspace](/langsmith/administration-overview#workspaces) 有效 LangSmith API key 的用户才能访问。
            - 若勾选，则任何 LangSmith 用户都可以通过 [Studio](/langsmith/studio) 访问该 deployment。系统还会提供直达此 deployment 的 Studio 链接，便于分享。
        1. 指定 **Environment Variables** 和 secrets。现有 secrets 和环境变量会预先填充。如需为 revision 配置更多变量，请参阅 [Environment Variables reference](/langsmith/env-var-cloud)。
            1. 新增 secrets 或环境变量。
            1. 删除已有 secrets 或环境变量。
            1. 更新已有 secrets 或环境变量的值。
    1. 点击 **Submit**。几秒后，**New Revision** 模态框会关闭，新的 revision 会进入部署队列。
  </Tab>
  <Tab title="LangGraph CLI">
    在项目目录中重新执行 `langgraph deploy`。该命令会根据名称找到已有 deployment，并基于你最新的代码变更创建一个新的 revision：

    ```shell
    langgraph deploy
    ```

    如果你想通过 deployment ID 而不是名称来指定目标，请使用 `--deployment-id`：

    ```shell
    langgraph deploy --deployment-id <DEPLOYMENT_ID>
    ```

    使用 `langgraph deploy list` 可以查看所有 deployments 并查找它们的 IDs：

    ```shell
    langgraph deploy list
    ```

    <Note>
    `langgraph deploy` 只能更新最初也是通过 `langgraph deploy` 创建的 deployments。通过 LangSmith UI 或 GitHub integration 创建的 deployments，不能使用这个命令更新。
    </Note>
  </Tab>
</Tabs>

## 查看构建日志和服务端日志

每个 revision 都有对应的构建日志与服务端日志。

<Tabs>
  <Tab title="LangSmith UI">
    从 **Deployments** 视图开始：

    1. 在 **Revisions** 表格中选择目标 revision。右侧会滑出一个面板，默认选中 **Build** 标签页，用于展示该 revision 的构建日志。
    1. 在面板中切换到 **Server** 标签页，即可查看该 revision 的服务端日志。服务端日志只有在 revision 已经部署完成后才可用。
    1. 在 **Server** 标签页中，根据需要调整日期 / 时间范围选择器。默认值为 **Last 7 days**。
  </Tab>
  <Tab title="LangGraph CLI">
    使用 `langgraph deploy logs` 获取 deployment 的日志。

    若要查看服务端（运行时）日志：

    ```shell
    langgraph deploy logs
    ```

    若要查看构建日志：

    ```shell
    langgraph deploy logs --type build
    ```

    若要持续 tail 日志：

    ```shell
    langgraph deploy logs --follow
    ```

    你还可以通过时间范围、日志级别或搜索字符串来过滤日志：

    ```shell
    langgraph deploy logs --start-time 2026-03-01T00:00:00Z --level ERROR
    ```

    如果你有多个 deployments，可以通过名称或 ID 来指定目标：

    ```shell
    langgraph deploy logs --name my-agent
    langgraph deploy logs --deployment-id <DEPLOYMENT_ID>
    ```

    所有可用选项请参阅 [`deploy logs` CLI reference](/langsmith/cli#deploy-logs)。
  </Tab>
</Tabs>

## 查看 deployment metrics

一旦 deployment 上线，你就可以在 [LangSmith UI](https://smith.langchain.com) 中监控其性能。

从 LangSmith UI 开始：

1. 在左侧导航中选择 **Deployments**。
1. 选择一个已有 deployment 进行监控。
1. 切换到 **Monitoring** 标签页查看 deployment metrics。所有可用指标请参阅[完整指标列表](/langsmith/control-plane#monitoring)。
1. 在 **Monitoring** 标签页中，根据需要调整日期 / 时间范围选择器。默认值为 **Last 15 minutes**。

## 中断 revision

中断 revision 会停止该 revision 的部署。

<Warning>
**Undefined Behavior**
被中断的 revision 处于未定义行为状态。这个功能仅适用于你需要部署新的 revision，而当前已有某个 revision 卡住不动的情况。未来这个功能可能会被移除。
</Warning>

从 **Deployments** 视图开始：

1. 在 **Revisions** 表格中，点击目标 revision 所在行右侧的菜单图标（三个点）。
1. 选择 **Interrupt**。
1. 会弹出一个模态框。阅读确认信息后，点击 **Interrupt revision**。

## 删除 deployment

<Tabs>
  <Tab title="LangSmith UI">
    从 [LangSmith UI](https://smith.langchain.com) 开始：

    1. 在左侧导航中选择 **Deployments**，进入已有 deployments 列表。
    1. 点击目标 deployment 所在行右侧的菜单图标（三个点），并选择 **Delete**。
    1. 会弹出一个 **Confirmation** 模态框。点击 **Delete**。
  </Tab>
  <Tab title="LangGraph CLI">
    使用 `langgraph deploy list` 查找你想删除的 deployment ID：

    ```shell
    langgraph deploy list
    ```

    然后通过 ID 删除：

    ```shell
    langgraph deploy delete <DEPLOYMENT_ID>
    ```

    如果想跳过确认提示，可使用 `--force`：

    ```shell
    langgraph deploy delete --force <DEPLOYMENT_ID>
    ```
  </Tab>
</Tabs>

## Deployment settings

从 **Deployments** 视图开始：

1. 在右上角点击齿轮图标（**Deployment Settings**）。
1. 将 `Git Branch` 更新为目标 branch。
1. 勾选 / 取消勾选 **Automatically update deployment on push to branch**。
    1. 创建 / 删除 branch，以及创建 / 删除 tag，都不会触发更新。只有 push 到已有 branch 才会触发。
    1. 如果在很短时间内连续向同一 branch push，多次更新会排队处理。当前构建完成后，只有最新一次提交会开始构建，其余排队构建会被跳过。

## 添加或移除 GitHub repositories

安装并授权 LangChain 的 `hosted-langserve` GitHub app 后，你可以调整它的仓库访问范围，以添加新仓库或移除已有仓库。如果创建了新的仓库，可能还需要显式添加。

1. 在 GitHub 个人资料中进入 **Settings** > **Applications** > `hosted-langserve` > 点击 **Configure**。
1. 在 **Repository access** 下，选择 **All repositories** 或 **Only select repositories**。如果选择 **Only select repositories**，则后续新增仓库时需要显式添加。
1. 点击 **Save**。
1. 当你创建新 deployment 时，下拉菜单中的 GitHub 仓库列表会自动反映这些访问权限变更。
