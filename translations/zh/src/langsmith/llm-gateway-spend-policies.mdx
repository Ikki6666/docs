支出策略为某个特定范围（组织、工作区、API key 或用户）定义了一个时间窗口（按月、按周、按日或按小时）内的成本上限。[LLM Gateway](/langsmith/llm-gateway) 会实时跟踪支出，并阻止任何会让支出超过该上限的请求，返回 `402` 响应：

```
API Error: 402 request blocked by gateway policies: R&D Spend Cap
```

被阻止的请求会被追踪到 LangSmith，并把策略违规信息记录为 metadata，因此你可以准确看到什么被拦住了，以及原因是什么。

## 策略维度

支出策略会按照从最宽到最窄的顺序评估。所有匹配的策略都会被检查，只要有任意一条策略返回 block，请求就会被拒绝。你可以把策略设为 default（为所有工作区、用户或 API keys 施加统一支出上限），也可以设为 granular policy（针对单个实体或一组实体设置更细粒度的限制）。

| 范围 | 它限制什么 | 示例 |
| --- | --- | --- |
| **Organization** | 该组织内所有工作区的总支出 | “整个组织每月在 LLM 调用上的支出不能超过 10,000 美元” |
| **Workspace** | 单个工作区或一组工作区内的总支出 | “与 R&D 相关的工作区每月总支出不能超过 2,000 美元” |
| **API key** | 单个 API key 或一组 API keys 的支出（映射到某个服务或 agent） | “客服 agent 使用的这些 keys 每月累计支出不能超过 500 美元” |
| **User** | 单个用户或一组用户的支出（从 API key 的身份解析而来） | “每个开发者每天最多只能花费 50 美元” |

### 冲突解决

默认情况下，LLM Gateway 会优先评估最宽的范围。如果有更细粒度的策略适用，则以最严格的策略为准。更窄的范围只能进一步收紧限制，不能放松限制。如果组织级策略限定每月上限为 10,000 美元，而工作区级策略限定为 15,000 美元，那么仍然会应用 10,000 美元的组织级上限。

### 默认策略与细粒度策略

支出策略有两个维度：

1. **沿某个维度求和后的总上限：** 某个范围的总 cap。例如：“这个工作区的总支出每月不能超过 5,000 美元。”
2. **对该维度中每个成员设置默认上限：** 一个默认基础限制，会施加到范围内的每个 API key 或用户，除非被更具体的策略覆盖。例如：“该工作区中的每个 API key 默认每月上限为 200 美元。”单个 API key 也可以获得额外策略来提高它的专属上限，但任何策略都不能放宽更宽层级已设定的 cap。

## 时间窗口

| 窗口 | 重置时机 | 适用场景 |
| --- | --- | --- |
| **Monthly** | 每月第一天 | 与预算周期对齐，控制总体成本 |
| **Weekly** | 每周一 UTC 零点 | 周度预算控制 |
| **Daily** | 每天 UTC 零点 | 防止单日成本暴涨，例如某个 coding agent 夜间陷入重试循环 |
| **Hourly** | 每小时整点 | 快速捕获失控 agent |

你可以对同一范围应用多个时间窗口。例如，一个工作区可以同时拥有每月 5,000 美元上限和每天 500 美元上限。这些限制会独立执行。

## 创建支出策略

<Warning>
创建和管理策略需要 `organization:manage` 权限。完整权限说明请参见[Traces、Engine 与访问控制](/langsmith/llm-gateway-access)。
</Warning>

1. 前往 **Settings → Gateway → LLM Gateway**。
1. 点击 **Create policy**。
1. 选择范围（organization、workspace、API key 或 user）。
1. 设置时间窗口（monthly、weekly、daily 或 hourly）。
1. 设置 USD 计的支出上限。
1. 保存。

策略会立即生效。Gateway 会在每个入站请求上评估它们，执行延迟低于 1 秒。

## 查看支出

支出可视化仪表板会显示实时成本汇总，帮助你在触顶之前就理解 LLM 预算的去向。

在 gateway 设置页面中，你可以查看每条策略相对于其 cap 已经花费了多少。

## 与 LangSmith Engine 集成

当某条支出策略拦住请求时，违规信息会被记录为 trace 上的 metadata。这些违规随后会作为问题出现在 [LangSmith Engine](/langsmith/engine) 中，你可以从问题直接点击进入 trace，查看 agent 在触达限制时到底在做什么。

这对于判断被拦截请求究竟是一个真实的成本问题，例如某个 coding agent 陷入重试循环，还是某条策略本身需要调整，例如一个合理的工作负载已经增长超出原有 cap，都会很有帮助。
