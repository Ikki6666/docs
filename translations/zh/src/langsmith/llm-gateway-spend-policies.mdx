支出策略为某个特定范围（组织、工作区、用户或 API key）定义了一个时间窗口（按月、按周、按日或按小时）内的成本上限。当该窗口内记录的支出达到上限后，[LLM Gateway](/langsmith/llm-gateway) 会阻止后续请求，并返回一个会指明拦截策略的 `402` 响应：

```json
{"type":"error","error":{"message":"request blocked by gateway policies: <POLICY_NAME>"}}
```

gateway 会在请求完成后记录该请求的成本。跨越上限的那个请求仍会成功，只有之后的请求才会被阻止，因此一个窗口内的支出可能超过上限。如果多个请求几乎同时发出，它们可能都在第一个请求被记录之前通过，所以超出的金额可能超过一个请求的成本。

被阻止的请求会被追踪到 LangSmith，并把策略违规信息记录为 metadata，因此你可以准确看到什么被拦住了，以及原因是什么。违规还会作为问题出现在 [LangSmith Engine](/langsmith/llm-gateway-traces#langsmith-engine-integration) 中。

<Info>
支出策略不适用于计入 [Claude 订阅](/langsmith/llm-gateway-coding-agents#use-claude-subscription-oauth) 的调用，这些调用也不计入支出总额。
</Info>

## 策略维度

支出策略会按照从最宽到最窄的顺序评估。所有匹配的策略都会被检查，只要有任意一条策略返回 block，请求就会被拒绝。你可以把策略设为 default（为所有工作区、用户或 API keys 施加统一支出上限），也可以设为 granular policy（针对单个实体或一组实体设置更细粒度的限制）。

| 范围 | 它限制什么 | 示例 |
| --- | --- | --- |
| **Organization** | 该组织内所有工作区的总支出 | “整个组织每月在 LLM 调用上的支出不能超过 10,000 美元” |
| **Workspace** | 单个工作区或一组工作区内的总支出 | “与 R&D 相关的工作区每月总支出不能超过 2,000 美元” |
| **User** | 单个用户或一组用户的支出（从 API key 的身份解析而来） | “每个开发者每天最多只能花费 50 美元” |
| **API key** | 单个 API key 或一组 API keys 的支出（映射到某个服务或 agent） | “客服 agent 使用的这些 keys 每月累计支出不能超过 500 美元” |

### 冲突解决

默认情况下，gateway 会优先评估最宽的范围。更窄的范围只能进一步收紧限制，不能放松限制。例如，如果组织级策略限定每月上限为 10,000 美元，而工作区级策略限定为 15,000 美元，那么仍然会应用 10,000 美元的组织级上限。

### 默认策略与细粒度策略

支出策略有两个维度：

1. **沿某个维度求和后的总上限：** 某个范围的总 cap。例如：“这个工作区的总支出每月不能超过 5,000 美元。”
2. **对该维度中每个成员设置默认上限：** 一个默认基础限制，会施加到范围内的每个 API key 或用户，除非被更具体的策略覆盖。例如：“该工作区中的每个 API key 默认每月上限为 200 美元。”单个 API key 也可以获得额外策略来提高它的专属上限，但任何策略都不能放宽更宽层级已设定的 cap。

## 时间窗口周期

时间窗口决定支出相对于上限累计的周期。每个窗口结束时，已记录的支出会重置为零：

| 周期 | 重置时机 | 适用场景 |
| --- | --- | --- |
| **Monthly** | 每月第一天 | 与预算周期对齐，控制总体成本 |
| **Weekly** | 每周一 UTC 零点 | 周度预算控制 |
| **Daily** | 每天 UTC 零点 | 防止单日成本暴涨，例如某个 coding agent 夜间陷入重试循环 |
| **Hourly** | 每小时整点 | 快速捕获失控 agent |

<Tip>
你可以对同一范围应用多个时间窗口。例如，一个工作区可以同时拥有每月 5,000 美元上限和每天 500 美元上限。这些限制会独立执行。
</Tip>

## 创建支出策略

<Warning>
创建和管理策略需要 `organization:gateway:manage` 权限。Organization Admins 和 Organization Operators 默认拥有该权限。各组织角色的具体权限请参见[组织角色](/langsmith/rbac#organization-roles)。
</Warning>

1. 前往 **LLM Gateway** 并选择 **Cost Controls**。
1. 点击 **Create spend limit**。
1. 选择 **scope**（organization、workspace、user 或 API key）。
1. （可选）若要按 header 拆分默认限额，请选择 **Workspace**、**User** 或 **API Key**，并默认将限额应用于该类型的每个 subject。勾选 **Separate limits by custom header**，输入不带 `X-Gateway-` 前缀的 header 名称，例如 `Customer-Id`。请求中请发送完整的 `X-Gateway-Customer-Id` header。每个 subject 与 header 值的组合都会获得独立的限额。
1. 以美元设置支出上限，并设置时间窗口周期（monthly、weekly、daily 或 hourly）。
1. 点击 **Create spend limit**。

策略会立即生效。Gateway 会在每个入站请求上评估它们，执行延迟低于 1 秒。

<Tip>
支出策略也可以使用自定义请求 header，在同一个 API key 下为每个终端客户、租户或团队提供独立的限额。更多信息请参见[基于 header 的策略](/langsmith/llm-gateway-header-policies)。
</Tip>

## 查看支出

在 **LLM Gateway** > **Cost Controls** 中，**Usage** 列会显示每条策略已花费的金额（美元）及其占上限的百分比。

若要按用户、API key、模型或请求 header 分析一段时间内的支出，请使用 **Usage** 标签页。更多信息请参见[监控 LLM Gateway 支出](/langsmith/llm-gateway-monitoring)。
