<Info>
本页仅适用于未运行在离线（air-gapped）模式下的客户，并假设你使用的是版本 `0.9.0` 或更高的自托管 LangSmith 实例。
</Info>

自托管 LangSmith 会将平台数据存储在你的环境中。只要你不是在离线模式下运行，LangSmith 就需要访问 `https://beacon.langchain.com`，以发送以下遥测：

| 遥测类型 | 发送内容 | 是否必需 |
|-----------|---------------|----------|
| [Billing](#billing-telemetry) | 许可证校验，以及订阅 / 使用量上报 | 是 |
| [Operational](#operational-telemetry) | 用于支持诊断的日志、指标和 traces | 否，可禁用 |
| [Usage](#usage-telemetry) | 匿名使用指标，以及组织安全联系人电子邮件地址 | 否，可禁用 |

<Warning>
**必须允许访问 `https://beacon.langchain.com`。** 如需静态 IP 地址，请参见 [allowlisting IP section](/langsmith/cloud-ip-allowlist#allowlisting-ip-addresses)。
</Warning>

<Note>
如果你启用了 [Engine](/langsmith/engine-self-hosted)，内容会发往 LangSmith Intelligence 或你自己的 model providers。使用你自己的 providers 时，LangChain 只会通过配置的上报 endpoint 接收使用量 metadata。所需的 egress 目的地请参阅[用于 Engine 的 LangSmith Intelligence](#langsmith-intelligence-for-engine)。
</Note>

## Billing telemetry

对于未运行在离线模式下的自托管 LangSmith 实例，billing telemetry 是**必需的**。它包括许可证校验以及订阅 / 使用量上报。

<Info>
Billing telemetry **不能被禁用**。如果你需要在完全没有任何 egress 的情况下运行，请[联系销售团队](https://www.langchain.com/contact-sales)申请离线（air-gapped）许可证。
</Info>

### 它的作用

- **License verification**：在启动时以及之后的周期性时间点校验你的 LangSmith license key。
- **Subscription/usage reporting**：按照你的订单权限项，为计费目的上报平台使用指标。

### 我们收集什么

- License key 校验请求
- 聚合后的使用量统计（trace 数量、分配的 seats、正在使用的 seats）
- Organization 和 workspace 标识符

### 示例 payloads

#### License verification

**Endpoint:** `POST beacon.langchain.com/v1/beacon/verify`

**Request:**

```json
{
  "license": "<YOUR_LICENSE_KEY>"
}
```

**Response:**

```json
{
  "token": "Valid JWT" //Short-lived JWT token to avoid repeated license checks
}
```

#### Subscription/usage reporting

**Endpoint:** `POST beacon.langchain.com/v1/beacon/ingest-traces`

**Request:**

## Operational telemetry

从版本 **0.11** 开始，LangSmith 部署默认会发送 operational telemetry。这些遥测数据有助于 LangChain 团队为自托管实例提供更主动的支持和更快速的故障排查。

<Info>
Operational telemetry 与 billing telemetry **彼此独立**。你可以禁用 operational telemetry，同时仍然保留 billing telemetry。
</Info>

### 它的作用

- 支持对自托管实例进行更主动的支持与更快速的故障排查
- 帮助进行性能调优
- 基于真实使用模式，帮助确定改进优先级

### 我们收集什么

- **Request metadata**：匿名化的请求数量、大小和时长
- **Database metrics**：查询耗时、错误率和性能计数器
- **Operational traces**：高延迟或失败请求的耗时与错误信息（这些**不是**客户 traces，而是关于 LangSmith 实例本身运行状态的 traces）
- **Log messages**：仅包含 warning 和 error 级别的日志消息

<Info>
我们不会收集实际 payload 内容、数据库记录，或任何可以识别你的终端用户或客户的数据。所有 telemetry 数据都只与 organization 和 deployment 关联，不会标识到具体用户。我们**不会收集 PII**（个人可识别信息）。
</Info>

有关 LangChain 保留的每项指标及其保留的属性，请参阅 [operational telemetry 指标参考](/langsmith/self-host-telemetry-metrics)。

### 如何禁用

你可以在 `langsmith_config.yaml` 文件中设置以下值来禁用 operational telemetry：

```yaml
config:
  telemetry:
    logs: false
    metrics: false
    traces: false
```

你也可以只将其中某些值设为 `false`，从而只禁用特定类型的 telemetry。

<Warning>
禁用 operational telemetry 会停止导出本节描述的日志、指标和 traces，但**不会**禁用 billing telemetry（license verification 和 subscription/usage reporting）。
</Warning>

### 为单个数据存储禁用指标 {#disable-metrics-for-one-datastore}

`queue` 部署会收集 PostgreSQL、Redis、ClickHouse 和 SmithDB 的指标。若要在保留其余数据存储指标的同时停止发送某一个数据存储的指标，请在 `queue.deployment.extraEnv` 中将其环境变量设置为 `false`。例如，要停止发送 SmithDB 指标：

```yaml
queue:
  deployment:
    extraEnv:
      - name: ENABLE_SMITHDB_METRICS_CRON
        value: "false"
```

| 数据存储 | 环境变量 |
| --- | --- |
| PostgreSQL | `ENABLE_POSTGRES_METRICS_CRON` |
| Redis | `ENABLE_REDIS_METRICS_CRON` |
| ClickHouse | `ENABLE_CLICKHOUSE_METRICS_CRON` |
| SmithDB | `ENABLE_SMITHDB_METRICS_CRON`（LangSmith v0.18 或更高版本） |

LangSmith 服务仍会发送其自身的指标。要停止发送所有指标，请将 `config.telemetry.metrics` 设置为 `false`。

## Usage telemetry

Usage telemetry 会收集你的 LangSmith 实例匿名使用指标的快照。这些数据帮助 LangChain 了解平台采用情况，并为产品开发决策提供依据。快照还可能包含用于接收 LangChain 通知的安全联系人。

<Info>
Usage telemetry **默认启用**，也可以被禁用。与 billing telemetry 不同，你可以完全控制是否将这些快照发送给 LangChain。
</Info>

### 它的作用

- 定期采集聚合后的使用指标
- 提供关于功能采用情况和平台增长的洞察
- 基于真实使用情况，帮助 LangChain 确定改进和新功能的优先级

### 我们收集什么

- **Platform metrics**：workspaces、projects、experiments、datasets、evaluators 及其他平台资源的数量
- **Feature usage**：run rules、annotation queues、prompts 以及与 prompts 相关活动的数量
- **Users**：注册用户总数，以及过去 30 天内活跃的 PATs（Personal Access Tokens）数量
- **Timestamps**：快照的时间范围（UTC 的起止时间戳）
- **Security contacts**：为每个组织配置的电子邮件地址，以及组织和安装标识符

<Info>
所有指标都只是**聚合后的数量**。指标中不包含任何单个资源的数据或标识符。安全联系人电子邮件地址及其关联标识符不是匿名的。
</Info>

当 phone-home 和 usage reporting 启用时，联系人上报默认启用。离线实例不会发送这些快照。要更新地址，请参阅[管理安全联系人](/langsmith/set-up-hierarchy#manage-security-contacts)。

### 禁用安全联系人上报

要在保持 usage telemetry 启用的同时停止发送安全联系人，请将以下内容添加到 Helm values 的 `commonEnv` 中并重新部署：

```yaml
commonEnv:
  - name: PHONE_HOME_SECURITY_CONTACTS_REPORTING_ENABLED
    value: "false"
```

下一次包含联系人报告的使用量快照会发送空列表，以清除该安装先前上报的联系人。没有安装标识符的快照无法清除联系人。如果 phone-home 或 usage reporting 已禁用，则不会发送任何快照，此设置也不会清除先前上报的联系人。此设置不会从本地组织设置中移除联系人。

### 如何禁用

你可以在部署配置中设置以下环境变量来禁用 usage telemetry：

```yaml
PHONE_HOME_USAGE_REPORTING_ENABLED: false
```

将它加入 Helm 配置的 `commonEnv` 部分，即可永久禁用 usage telemetry 上报。

禁用 usage telemetry 会停止所有使用量快照，因此 LangChain 会保留你的安装已经上报的任何安全联系人。若要同时清除这些联系人：

1. [禁用安全联系人上报](#disable-security-contact-reporting)。
1. 等待下一次每日使用量快照（默认 02:00 UTC），该快照会发送空联系人列表。
1. 将 `PHONE_HOME_USAGE_REPORTING_ENABLED` 设置为 `false`。

<Warning>
禁用 usage telemetry **不会**影响 billing telemetry 或 operational telemetry。License verification 与 subscription/usage reporting 仍会正常工作。
</Warning>

## 用于 Engine 的 GitHub

当你[将 GitHub 连接到 Engine](/langsmith/engine-self-hosted-github) 时，需要允许 LangSmith 服务和 sandbox 主机向你的 GitHub 实例发起出站 HTTPS 连接。GitHub 也必须能访问 LangSmith 的 webhook URL，以便在合并后自动关联 PR 并完成 issue。

这些连接与 model provider 访问相互独立。所需的主机、连接方向和私有网络配置，请参阅 [Engine 的 GitHub 网络要求](/langsmith/engine-self-hosted-github#allow-network-access)。

## LangSmith Intelligence for Engine

[Engine](/langsmith/engine-self-hosted) 会向 LangSmith Intelligence（LSI）上报使用量，LSI 也可以运行其模型。如果你使用自己的 model providers，LSI 只会接收使用量 metadata。[air-gapped 安装](/langsmith/engine-self-hosted#air-gapped-installations)不会连接 LSI。

针对你的 [model provider 选择](/langsmith/engine-self-hosted#choose-how-engine-runs-its-models)，允许出站 HTTPS 访问 `engine.intelligenceBaseUrl` 中配置的 endpoint：

- **LangSmith Intelligence**：`beacon.aws.langchain.com`。若要让这部分流量走私有网络，请[通过 AWS PrivateLink 连接](/langsmith/engine-self-hosted-model-providers#connect-with-aws-privatelink)。
- **你自己的 model providers**：`beacon.langchain.com`，即本页已要求的主机，用于使用量上报。此外还需允许出站 HTTPS 访问每个 provider 的 API endpoint。

<Warning>
请将每个目的地作为特定的 allowlist 条目添加，而不是开放通用的出站访问。发往 LangSmith Intelligence 的请求使用在 LangSmith 许可证校验期间获取的短期 license JWT 进行认证。
</Warning>

### 它的作用

- **运行 Engine 的模型**（当组织选择 LangSmith Intelligence 时）。
- **记录 Engine 的使用量**用于计费，无论 Engine 以哪种方式运行其模型。

### 我们收集的内容

当 Engine 运行在 LangSmith Intelligence 上时，每个请求可能携带 Engine 完成其工作所需的 trace 内容、源代码和中间输出。LangSmith Intelligence 不会持久化 prompt 或 completion 正文。当 Engine 运行在你自己的 model providers 上时，LangSmith Intelligence 只会接收使用量 metadata。

LangSmith Intelligence 会保留以下用于用量归因和计费的元数据：

- 用于用量归因的账户、工作区和项目标识符。
- 用于计费的模型和 token 使用量元数据。

完整的数据流和模型 provider 承诺，请参阅[自托管上的 Engine](/langsmith/engine-self-hosted)。

<Info>
离线（air-gapped）的自托管环境可以在你自己的 model providers 上运行 Engine。请参阅 [Air-gapped installations](/langsmith/engine-self-hosted#air-gapped-installations)。
</Info>

## 我们的承诺

以下承诺适用于本页所述的 billing、operational 和 usage telemetry。除上文所述的安全联系人电子邮件地址外，LangChain 不会在该 telemetry 中存储敏感信息，也不会与第三方共享该 telemetry。日志消息会被过滤，只包含 error 严重级别，并且不会采集可能包含敏感应用数据的日志消息。Engine 对 LangSmith Intelligence 的使用是另一个独立的数据流，详见[自托管上的 Engine](/langsmith/engine-self-hosted)。如果你对发送的数据有任何顾虑，请禁用可选的 telemetry，或[联系销售团队](https://www.langchain.com/contact-sales)。
