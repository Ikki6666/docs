<Info>
本页仅适用于未运行在离线（air-gapped）模式下的客户，并假设你使用的是版本 `0.9.0` 或更高的自托管 LangSmith 实例。
</Info>

自托管 LangSmith 会将平台数据存储在你的环境中。只要你不是在离线模式下运行，LangSmith 就需要访问 `https://beacon.langchain.com`，原因如下：

- **Billing telemetry**：许可证校验，以及订阅 / 使用量上报（必需）
- **Operational telemetry**：用于支持诊断的日志、指标和 traces（可选，可禁用）
- **Usage telemetry**：用于产品洞察的匿名使用快照（可选，可禁用）

<Warning>
**必须允许访问 `https://beacon.langchain.com`。** 如需静态 IP 地址，请参见 [allowlisting IP section](/langsmith/cloud#allowlisting-ip-addresses)。
</Warning>

<Note>
如果你启用了 [Engine](/langsmith/deploy-self-hosted-full-platform#enable-engine)，它需要第二个 egress 目标，并且 Engine 内容会通过该目标离开你的环境。请参阅[用于 Engine 的 LangSmith Intelligence](#langsmith-intelligence-for-engine)。
</Note>

## Billing telemetry

对于未运行在离线模式下的自托管 LangSmith 实例，billing telemetry 是**必需的**。它包括许可证校验以及订阅 / 使用量上报。

<Info>
Billing telemetry **不能被禁用**。如果你需要在完全没有任何 egress 的情况下运行，请联系你的客户团队申请离线（air-gapped）许可证。
</Info>

### 它的作用

- **License verification**：在启动时以及之后的周期性时间点校验你的 LangSmith license key。
- **Subscription/usage reporting**：按照你的订单权限项，为计费目的上报平台使用指标。

### 我们收集什么

- License key 校验请求
- 聚合后的使用量统计（trace 数量、分配的 seats、正在使用的 seats）
- Organization 和 workspace 标识符

### 示例 payloads

#### License verification

**Endpoint:** `POST beacon.langchain.com/v1/beacon/verify`

**Request:**

```json
{
  "license": "<YOUR_LICENSE_KEY>"
}
```

**Response:**

```json
{
  "token": "Valid JWT" //Short-lived JWT token to avoid repeated license checks
}
```

**Request:**

## Operational telemetry

从版本 **0.11** 开始，LangSmith 部署默认会发送 operational telemetry。这些遥测数据有助于 LangChain 团队为自托管实例提供更主动的支持和更快速的故障排查。

<Info>
Operational telemetry 与 billing telemetry **彼此独立**。你可以禁用 operational telemetry，同时仍然保留 billing telemetry。
</Info>

### 它的作用

- 支持对自托管实例进行更主动的支持与更快速的故障排查
- 帮助进行性能调优
- 基于真实使用模式，帮助确定改进优先级

### 我们收集什么

- **Request metadata**：匿名化的请求数量、大小和时长
- **Database metrics**：查询耗时、错误率和性能计数器
- **Operational traces**：高延迟或失败请求的耗时与错误信息（这些**不是**客户 traces，而是关于 LangSmith 实例本身运行状态的 traces）
- **Log messages**：仅包含 warning 和 error 级别的日志消息

<Info>
我们不会收集实际 payload 内容、数据库记录，或任何可以识别你的终端用户或客户的数据。所有 telemetry 数据都只与 organization 和 deployment 关联，不会标识到具体用户。我们**不会收集 PII**（个人可识别信息）。
</Info>

### 如何禁用

你可以在 `langsmith_config.yaml` 文件中设置以下值来禁用 operational telemetry：

```yaml
config:
  telemetry:
    logs: false
    metrics: false
    traces: false
```

你也可以只将其中某些值设为 `false`，从而只禁用特定类型的 telemetry。

<Warning>
禁用 operational telemetry 会停止导出本节描述的日志、指标和 traces，但**不会**禁用 billing telemetry（license verification 和 subscription/usage reporting）。
</Warning>

## Usage telemetry

Usage telemetry 会收集你的 LangSmith 实例使用指标的匿名快照。这些数据帮助 LangChain 了解平台采用情况，并为产品开发决策提供依据。

<Info>
Usage telemetry **默认启用**，也可以被禁用。与 billing telemetry 不同，你可以完全控制是否将这些快照发送给 LangChain。
</Info>

### 它的作用

- 定期采集聚合后的使用指标
- 提供关于功能采用情况和平台增长的洞察
- 基于真实使用情况，帮助 LangChain 确定改进和新功能的优先级

### 我们收集什么

- **Platform metrics**：workspaces、projects、experiments、datasets、evaluators 及其他平台资源的数量
- **Feature usage**：run rules、annotation queues、prompts 以及与 prompts 相关活动的数量
- **Users**：注册用户总数，以及过去 30 天内活跃的 PATs（Personal Access Tokens）数量
- **Timestamps**：快照的时间范围（UTC 的起止时间戳）

<Info>
所有指标都只是**聚合后的数量**。不会收集任何单个资源的数据、标识符或使用模式。也不会收集任何能识别你的终端用户或客户的信息。
</Info>

### 示例 payloads

**Endpoint:** `POST /v1/beacon/usage-snapshot`

**Request:**

```json
{
  "license_key": "<YOUR_LICENSE_KEY>",
  "from_timestamp": "2026-03-25T02:00:00+00:00",
  "to_timestamp": "2026-03-26T02:00:00+00:00",
  "measures": {
    "workspaces": 12,
    "users": 63,
    "projects": 87,
    "experiments": 34,
    "datasets": 15,
    "evaluators": 8,
    "run_rules": 5,
    "annotation_queues": 3,
    "prompts": 22,
    "prompt_commits": 156,
    "prompt_pulls": 1043,
    "active_pats_30d": 47
  }
}
```

### 如何禁用

你可以在部署配置中设置以下环境变量来禁用 usage telemetry：

```yaml
PHONE_HOME_USAGE_REPORTING_ENABLED: false
```

将它加入 Helm 配置的 `commonEnv` 部分，即可永久禁用 usage telemetry 上报。

<Warning>
禁用 usage telemetry **不会**影响 billing telemetry 或 operational telemetry。License verification 与 subscription/usage reporting 仍会正常工作。
</Warning>

## LangSmith Intelligence for Engine

本节仅适用于你启用了 [Engine](/langsmith/deploy-self-hosted-full-platform#enable-engine) 的情况。LangSmith Intelligence 是 LangChain 托管的、为 Engine 提供支持的服务。LangSmith 的其他功能均不依赖它，也不需要本页已描述内容之外的任何 egress。

Engine 无法完全在你的集群内运行。它会向 LangSmith Intelligence 发送请求，后者是一个 LangChain 托管的零数据保留（ZDR）服务，会将请求路由到 LangChain 环境内的某个模型 provider。请为你的云允许出站 HTTPS 到对应的网关：AWS 上为 `beacon.aws.langchain.com`，GCP 上为 `beacon.langchain.com`。在 GCP 上，这与本页已要求的主机相同，因此 Engine 只是新增了一条路径，而非一个新的目的地。

<Note>
自托管 LangSmith 的 Engine 适用于 **AWS US** 和 **GCP US**。AWS EU 和 Azure 已在计划中。请参阅[按云和区域的可用性](/langsmith/engine-self-hosted#availability-by-cloud-and-region)。
</Note>

<Warning>
请将该网关作为特定的 allowlist 条目添加，而不是开放通用的出站访问。请求使用在 LangSmith 许可证校验期间获取的短期 license JWT 进行认证。无需额外的模型 provider 凭据。
</Warning>

### 它的作用

- **为 Engine 提供支持**：Engine 依赖 LangSmith Intelligence，没有它就无法运行。

### 我们收集的内容

每个请求可能携带 Engine 完成其工作所需的 trace 内容、源代码和中间输出。LangSmith Intelligence 和模型 provider 会处理这些内容以响应该请求。LangSmith Intelligence 不会持久化 prompt 或 completion 正文。

LangSmith Intelligence 会保留以下用于用量归因和计费的元数据：

- 用于用量归因的账户、工作区和项目标识符。
- 用于计费的模型和 token 使用量元数据。

完整的数据流和模型 provider 承诺，请参阅[自托管上的 Engine](/langsmith/engine-self-hosted)。

<Info>
离线（air-gapped）的自托管环境无法运行 Engine，因为它无法访问 LangSmith Intelligence。LangSmith 的其他所有功能在离线下均可正常工作。
</Info>

## 我们的承诺

以下承诺适用于本页所述的 billing、operational 和 usage telemetry。LangChain 不会在该 telemetry 中存储敏感信息，也不会与第三方共享。日志消息会被过滤，只包含 error 严重级别，并且不会采集可能包含敏感应用数据的日志消息。Engine 对 LangSmith Intelligence 的使用是另一个独立的数据流，详见[自托管上的 Engine](/langsmith/engine-self-hosted)。如果你对发送的数据有任何顾虑，请禁用可选的 telemetry，或联系你的客户团队。
