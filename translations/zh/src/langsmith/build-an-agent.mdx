**Build** 标签页在 LangSmith 内部（而不是在代码中）创建一个 agent。你填写一个配置表单，LangSmith 会在你提交时根据它创建一个 [no-code agent](/langsmith/fleet)。在你操作之前，什么都不会被创建。

当你想要一个不需要本地项目或部署、开箱即用的 agent 时，就可以使用它。它产生的一切都是一个与其他 agent 无异的 [agent](/langsmith/agents)，因此它的 traces、dashboards 和 evaluators 的行为与你自行 instrument 的 agent 完全相同。

<AgentBetaNote />

<Note>
在这里创建 agent 需要 [computer use](/langsmith/fleet/computer-use)，它属于 Plus 和 Enterprise plans。没有该功能时，表单仍然可以打开，但会显示一条 banner，说明 agent 创建不可用。
</Note>

**Build** 标签页只出现在 agent-based workspace 中。如果你想改为从自己机器上的文件构建 agent，请参阅 [Managed Deep Agents](/langsmith/managed-deep-agents-overview)。

## 创建 agent

要创建一个 agent：

1. 在左侧导航中点击 **Build**。在没有选中 agent 的情况下，Build 会要求你选择一个，并在列表下方提供 **+ New agent**。该列表只包含在这里构建的 agents，因此你从代码 trace 的 agent 不会出现在其中。
1. 填写[配置部分](#configure-the-agent)。表单标题下方的一行文字显示 **Nothing is created until you click Create Agent.**
1. 点击 **Create Agent**。

LangSmith 创建该 agent，然后完成其余的设置，例如连接账号和注册 schedules。一个对话框会报告创建结果，并提供 **Go to Studio** 以测试该 agent。

**Cancel** 在不创建任何内容的情况下退出，并返回 agent 列表。

如果设置中有部分未完成，表单会报告是哪一部分并提供 **Retry unfinished changes**，因此第二次尝试不会创建第二个 agent。

agent 列表上方的 **+ Agent** 也会进入这个表单。它会打开 **New Agent** 面板，其中的 **Builder** 选项（"Build and configure inside LangSmith"）会在空白表单上打开这个标签页。关于该面板的其他三个选项，请参阅 [Create an agent](/langsmith/create-an-agent)。

## 配置 agent

这个表单是由可折叠部分组成的一页。每个部分默认展开，浏览器会记住你折叠了哪些部分。

- **Basics**：agent 的 **Name**、描述其用途的 **Description**，以及为其响应提供动力的 **Model**。名称是必填项，它是你在 agent 切换器中看到的标签。创建 agent 时 model 也是必填的。
- **Instructions**：**Agent instructions**，涵盖 agent 的角色、职责，以及它应该如何工作。LangSmith 会按输入的原样保存这些内容。
- **Tools and accounts**：agent 的 tools 所使用的连接，通过 **Add connection** 添加。在新 agent 上，账号会在创建 agent 时被授权，添加 workspace 连接会立即启动其授权流程。关于 agent 使用谁的凭证，请参阅 [Agent identity](/langsmith/fleet/agent-identity)。
- **Skills and memory**：agent 为特定任务引入的 [skills](/langsmith/fleet/skills)，以及它在 runs 之间保留的 memory 文件。**Update memory and instructions** 允许 agent 修改自己的配置，可以选择自动应用，或保留等待你的批准。
- **Channels**：agent 是否在 Slack 中工作。在新 agent 上，你在创建 agent 之后授权 Slack。在已有 agent 上，连接或移除 Slack 会立即生效。当 workspace 中无法使用 Slack 设置时，该部分会说明这一点。
- **Schedules**：agent 自行进行的 [scheduled runs](/langsmith/fleet/schedules)。

agent 创建完成后，标题下方的状态行会显示 **Unsaved changes** 或 **All changes saved**。

## 之后更改配置

在 Build 中选中该 agent 以重新打开其配置，此时标题为 **Agent configuration**。编辑任意部分并点击 **Save changes**。

没有该 agent 的编辑权限时，表单以 **View only** 方式打开。重命名需要更新该 agent 的 tracing projects 的权限，缺少权限时 **Name** 字段会说明这一点。

## 查找 traces

在这里构建的 agent 创建时只有 **Production** 这个 [environment](/langsmith/agent-environments)，它的 runs 会落在那里。只有当有内容上报到其他 environment 时，它才会获得这些 environment。

要查看它的 environments，请选中该 agent 并打开 **Tracing**，或者阅读 [agent Overview](/langsmith/navigate-agents#read-the-agent-overview) 上的摘要。

在 UI 中构建的 agent 没有 deployment，因为它运行在 Studio runtime 上，而不是你部署的 runtime。它的 Overview 上没有 **Deployments** 部分，也无法为它创建 deployment，因此 [agent environment deploy flags](/langsmith/deploy-to-agent-environment) 对它不适用。选中该 agent 时，workspace 的其他 deployments 会被隐藏。
