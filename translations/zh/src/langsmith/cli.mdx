**LangGraph CLI** 是一个命令行工具，用于在本地构建和运行 [Agent Server](/langsmith/agent-server)。生成的 server 会暴露 runs、threads、assistants 等全部 API endpoint，并包含 checkpointing 和 storage 所需的托管数据库等配套服务。

## Installation

1. 确保已安装 Docker，例如执行 `docker --version`。
1. 安装 CLI：

    <CodeGroup>
    ```bash [Python (pip)]
    pip install langgraph-cli
    ```
    ```bash JavaScript
    # Use latest on demand
    npx @langchain/langgraph-cli

    # Or install globally (available as `langgraphjs`)
    npm install -g @langchain/langgraph-cli
    ```
    </CodeGroup>

1. 验证安装

    <CodeGroup>
    ```bash [Python (pip)]
    langgraph --help
    ```
    ```bash JavaScript
    npx @langchain/langgraph-cli --help
    ```
    </CodeGroup>

### Quick commands

| Command | What it does |
| --- | --- |
| [`langgraph dev`](#dev) | 启动一个轻量级本地开发服务器，不需要 Docker，适合快速测试。 |
| [`langgraph build`](#build) | 为你的 LangGraph API server 构建 Docker image，用于部署。 |
| [`langgraph deploy`](#deploy) | 直接构建并部署 LangGraph image 到 LangSmith Deployments，一步完成。 |
| [`langgraph dockerfile`](#dockerfile) | 根据配置导出一个 Dockerfile，便于自定义构建。 |
| [`langgraph up`](#up) | 在 Docker 中本地启动 LangGraph API server。需要正在运行的 Docker；本地开发还需要 LangSmith API key；生产环境需要 license。 |

对于 JS，请使用 `npx @langchain/langgraph-cli <command>`，如果已全局安装，则可使用 `langgraphjs`。

    #### Using Wolfi base images

        你可以使用 `image_distro` 字段指定 base image 的 Linux 发行版。有效值是 `debian`、`wolfi`、`bookworm` 或 `bullseye`。推荐使用 Wolfi，因为它提供更小且更安全的 image。该能力适用于 `langgraph-cli>=0.2.11`。

    ```json
    {
      "$schema": "https://langgra.ph/schema.json",
      "dependencies": ["."],
      "graphs": {
        "chat": "chat.graph:graph"
      },
      "image_distro": "wolfi"
    }
    ```

    #### Adding semantic search to the store

    所有 deployment 都自带一个数据库支持的 BaseStore。为 `langgraph.json` 添加 `"index"` 配置后，即可在 deployment 的 BaseStore 中启用 [semantic search](/langsmith/semantic-search)。

    `index.fields` 配置决定了文档中哪些部分会被嵌入：

    * 如果省略，或设置为 `["$"]`，整个文档都会被嵌入
    * 如需仅嵌入特定字段，请使用 JSON path 表示法，例如 `["metadata.title", "content.text"]`
    * 如果文档缺少指定字段，仍会被存储，但这些字段不会生成 embedding
    * 你仍可在 `put` 时通过 `index` 参数覆盖特定 item 使用哪些字段进行 embedding

    ```json
    {
      "dependencies": ["."],
      "graphs": {
        "memory_agent": "./agent/graph.py:graph"
      },
      "store": {
        "index": {
          "embed": "openai:text-embedding-3-small",
          "dims": 1536,
          "fields": ["$"]
        }
      }
    }
    ```

    <Note>
    **Common model dimensions**
    * `openai:text-embedding-3-large`: 3072
    * `openai:text-embedding-3-small`: 1536
    * `openai:text-embedding-ada-002`: 1536
    * `cohere:embed-english-v3.0`: 1024
    * `cohere:embed-english-light-v3.0`: 384
    * `cohere:embed-multilingual-v3.0`: 1024
    * `cohere:embed-multilingual-light-v3.0`: 384
    </Note>

    #### Semantic search with a custom embedding function

    如果你想配合自定义 embedding function 使用 semantic search，可以传入一个自定义 embedding function 的路径：

    ```json
    {
      "dependencies": ["."],
      "graphs": {
        "memory_agent": "./agent/graph.py:graph"
      },
      "store": {
        "index": {
          "embed": "./embeddings.py:embed_texts",
          "dims": 768,
          "fields": ["text", "summary"]
        }
      }
    }
    ```

    `store` 配置中的 `embed` 字段可以引用一个自定义函数，该函数接收字符串列表并返回 embedding 列表。示例实现如下：

    ```python
    # embeddings.py
    def embed_texts(texts: list[str]) -> list[list[float]]:
        """Custom embedding function for semantic search."""
        # Implementation using your preferred embedding model
        return [[0.1, 0.2, ...] for _ in texts]  # dims-dimensional vectors
    ```

        <a id="ttl"></a>
    #### Configuring store item Time-to-Live

    你可以使用 `store.ttl` 键为 BaseStore 中的 item 或 memory 配置默认数据过期时间。它决定了 item 在最后一次访问后会保留多久，读取时可能因为 `refresh_on_read` 而刷新计时器。请注意，这些默认值也可以通过修改 `get`、`search` 等调用中的相应参数，在单次调用级别覆盖。

    `ttl` 配置是一个对象，包含以下可选字段：

    * `refresh_on_read`：如果为 `true`，默认值，则通过 `get` 或 `search` 访问 item 时会重置其过期计时器。若设置为 `false`，则只会在写入时，即 `put`，刷新 TTL。
    * `default_ttl`：item 的默认生命周期，单位为 **分钟**。仅对新创建的 item 生效；已有 item 不会被修改。如果未设置，item 默认不过期。
    * `sweep_interval_minutes`：系统运行后台清理过期 item 的频率，单位为分钟。如果未设置，则不会自动进行清理。

    下例启用了 7 天的 TTL，10080 分钟，读取时刷新，并且每小时执行一次清理：

    ```json
    {
      "$schema": "https://langgra.ph/schema.json",
      "dependencies": ["."],
      "graphs": {
        "memory_agent": "./agent/graph.py:graph"
      },
      "store": {
        "ttl": {
          "refresh_on_read": true,
          "sweep_interval_minutes": 60,
          "default_ttl": 10080
        }
      }
    }
    ```

        <a id="ttl"></a>
    #### Configuring checkpoint Time-to-Live

    你可以使用 `checkpointer` 键为 checkpoint 配置 time-to-live，TTL。这决定了 checkpoint 数据在被按指定策略自动处理前，会保留多长时间，例如被删除。支持两个可选子对象：

    * `ttl`：包括 `strategy`、`sweep_interval_minutes`、`default_ttl` 和 `sweep_limit`，Agent server v0.8+，用于共同定义 checkpoint 如何过期。
    * `serde` _(Agent server v0.5+)_：用于控制 checkpoint payload 的反序列化行为。

    下面的示例将默认 TTL 设为 30 天，43200 分钟：

    ```json
    {
      "$schema": "https://langgra.ph/schema.json",
      "dependencies": ["."],
      "graphs": {
        "chat": "chat.graph:graph"
      },
      "checkpointer": {
        "ttl": {
          "strategy": "delete",
          "sweep_interval_minutes": 10,
          "default_ttl": 43200
        }
      }
    }
    ```

    在这个示例中，超过 30 天的 checkpoint 会被删除，并且每 10 分钟检查一次。

    #### Configuring checkpointer serde

    `checkpointer.serde` 对象用于控制反序列化：

    * `allowed_json_modules`：定义一个 allow list，允许 server 从以 “json” 模式保存的 payload 中反序列化你自定义的 Python 对象。它是一个由 `[path, to, module, file, symbol]` 组成的列表。如果省略，则仅允许 LangChain 安全默认值。你也可以不安全地将其设置为 `true`，允许反序列化任意 module。
    * `pickle_fallback`：当 JSON 解码失败时，是否回退到 pickle 反序列化。

    ```json
    {
      "checkpointer": {
        "serde": {
          "allowed_json_modules": [
            ["my_agent", "auth", "SessionState"]
          ]
        }
      }
    }
    ```

    #### Customizing HTTP middleware and headers

    `http` block 可用于细粒度控制 request 处理：

    * `middleware_order`：可选 `"auth_first"`，让认证先于你的 middleware 执行，或者 `"middleware_first"`，默认值，表示先执行 middleware。
    * `enable_custom_route_auth`：将认证能力扩展到通过 `http.app` 挂载的 route。
    * `configurable_headers` / `logging_headers`：都接收一个对象，其中可包含 `includes` 和 `excludes` 数组；支持通配符，并且 exclusions 会先于 inclusions 执行。
    * `cors`：自定义 server 的 CORS，Cross-Origin Resource Sharing，配置。示例 `langgraph.json` 文件如下：

        ```json
        {
          ...
          "http": {
            "cors": {
              "allow_origins": ["https://example.com", "https://app.example.com"],
              "allow_methods": ["GET", "POST"],
              "allow_headers": ["Authorization", "Content-Type"],
              "allow_credentials": true,
              "allow_origin_regex": "^https://.*\\.example\\.com$",
              "expose_headers": ["x-pagination-total", "x-pagination-next", "x-request-id"],
              "max_age": 600
            }
          },
          ...
        }
        ```

        <Note>
        自定义 server 的 CORS 配置会覆盖 [`CORS_ALLOW_ORIGINS` environment variable](/langsmith/env-var-cloud) 的行为。
        </Note>

    #### Configuring webhooks

    你可以为 outbound webhook request 配置自定义 header 和 URL 限制：

    ```json
    {
      "$schema": "https://langgra.ph/schema.json",
      "dependencies": ["."],
      "graphs": {
        "chat": "chat.graph:graph"
      },
      "webhooks": {
        "headers": {
          "Authorization": "Bearer ${{ env.LG_WEBHOOK_TOKEN }}"
        },
        "url": {
          "allowed_domains": ["*.mycompany.com"],
          "require_https": true
        }
      }
    }
    ```

    关于 header 配置、环境变量模板，以及 URL 限制，请参阅 [Use webhooks](/langsmith/use-webhooks#add-headers-to-webhook-requests)。

        <a id="api-version"></a>
    #### Pinning API version

    _(Added in v0.3.7)_

    你可以通过 `api_version` 键固定 Agent Server 的 API 版本。这在你希望 server 始终使用某个特定 API 版本时很有用。
    默认情况下，Cloud deployment 构建会使用 server 的最新稳定版本。你可以将 `api_version` 设置为某个具体版本来固定它。

    ```json
    {
      "$schema": "https://langgra.ph/schema.json",
      "dependencies": ["."],
      "graphs": {
        "chat": "chat.graph:graph"
      },
      "api_version": "0.2"
    }
    ```

    #### Disabling built-in routes

    你可以在 `http` 配置块中使用布尔开关，按组禁用内置 HTTP route。这对于生产部署很有用，特别是在你想尽量缩小 server 暴露面时。

    例如，下面的配置会禁用系统信息和文档 route：

    ```json
    {
      "$schema": "https://langgra.ph/schema.json",
      "dependencies": ["."],
      "graphs": {
        "chat": "chat.graph:graph"
      },
      "http": {
        "disable_meta": true
      }
    }
    ```

    将 `disable_meta` 设为 `true` 后，会禁用以下 route：

    - `/`，root health check
    - `/info`，server 版本和配置信息
    - `/metrics`，Prometheus 和 JSON metrics
    - `/docs`，API documentation UI
    - `/openapi.json`，OpenAPI specification

    即使设置了 `disable_meta`，`/ok` 健康检查 endpoint 仍然可用，因此 Kubernetes 等编排器仍可执行 liveness 和 readiness probe。

    其他 route 开关还包括 `disable_assistants`、`disable_runs`、`disable_threads`、`disable_store` 和 `disable_ui`。对于 MCP、A2A 和 webhooks，请参阅各自文档：[Disable MCP](/langsmith/server-mcp#disable-mcp)、[Disable A2A](/langsmith/server-a2a#disable-a2a)、[Disable webhooks](/langsmith/use-webhooks#disable-webhooks)。

### `dockerfile`

<Tabs>
    <Tab title="Python">
    生成用于构建 LangSmith API server Docker image 的 Dockerfile。

    **Usage**

    ```
    langgraph dockerfile [OPTIONS] SAVE_PATH
    ```

    **Options**

    | Option              | Default          | Description |
    | ------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------- |
    | `-c, --config FILE` | `langgraph.json` | 声明依赖、graphs 和环境变量的 [configuration file](#configuration-file) 路径。 |
    | `--help`            |                  | 显示帮助并退出。 |

    示例：

    ```bash
    langgraph dockerfile -c langgraph.json Dockerfile
    ```

    生成的 Dockerfile 大致如下：

    ```dockerfile
    FROM langchain/langgraph-api:3.11

    ADD ./pipconf.txt /pipconfig.txt

    RUN PIP_CONFIG_FILE=/pipconfig.txt PYTHONDONTWRITEBYTECODE=1 pip install --no-cache-dir -c /api/constraints.txt langchain_anthropic langchain_openai wikipedia scikit-learn

    ADD ./graphs /deps/__outer_graphs/src
    RUN set -ex && \
        for line in '[project]' \
                    'name = "graphs"' \
                    'version = "0.1"' \
                    '[tool.setuptools.package-data]' \
                    '"*" = ["**/*"]'; do \
            echo "$line" >> /deps/__outer_graphs/pyproject.toml; \
        done

    RUN PIP_CONFIG_FILE=/pipconfig.txt PYTHONDONTWRITEBYTECODE=1 pip install --no-cache-dir -c /api/constraints.txt -e /deps/*

    ENV LANGSERVE_GRAPHS='{"agent": "/deps/__outer_graphs/src/agent.py:graph", "storm": "/deps/__outer_graphs/src/storm.py:graph"}'
    ```

        <Note>`langgraph dockerfile` 命令会把 `langgraph.json` 文件中的全部配置翻译成 Dockerfile 命令。使用该命令时，只要你更新了 `langgraph.json`，就需要重新运行它，否则这些变更不会反映到构建或运行出来的 dockerfile 中。</Note>

    </Tab>
    <Tab title="JS">
    生成用于构建 LangSmith API server Docker image 的 Dockerfile。

    **Usage**

    ```
    npx @langchain/langgraph-cli dockerfile [OPTIONS] SAVE_PATH
    ```

    **Options**

    | Option              | Default          | Description |
    | ------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------- |
    | `-c, --config FILE` | `langgraph.json` | 声明依赖、graphs 和环境变量的 [configuration file](#configuration-file) 路径。 |
    | `--help`            |                  | 显示帮助并退出。 |

    示例：

    ```bash
    npx @langchain/langgraph-cli dockerfile -c langgraph.json Dockerfile
    ```

    生成的 Dockerfile 大致如下：

    ```dockerfile
    FROM langchain/langgraphjs-api:20

    ADD . /deps/agent

    RUN cd /deps/agent && yarn install

    ENV LANGSERVE_GRAPHS='{"agent":"./src/react_agent/graph.ts:graph"}'

    WORKDIR /deps/agent

    RUN (test ! -f /api/langgraph_api/js/build.mts && echo "Prebuild script not found, skipping") || tsx /api/langgraph_api/js/build.mts
    ```

        <Note>`npx @langchain/langgraph-cli dockerfile` 命令会把 `langgraph.json` 文件中的全部配置翻译成 Dockerfile 命令。使用该命令时，只要你更新了 `langgraph.json`，就需要重新运行它，否则这些变更不会反映到构建或运行出来的 dockerfile 中。</Note>
