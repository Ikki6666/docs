本文介绍在 LangGraph CLI 和 Agent Server 中，数据是如何被处理的，包括内存型服务器（`langgraph dev`）和本地 Docker 服务器（`langgraph up`）。它也说明了在与托管版 Studio 前端交互时，会跟踪哪些数据。

## CLI

LangGraph **CLI** 是用于构建和运行 LangGraph 应用的命令行界面；更多信息请参见 [CLI 指南](/langsmith/cli)。

默认情况下，大多数 CLI 命令在调用时都会记录一条 analytics event。这能帮助我们更好地决定 CLI 体验的改进优先级。每条遥测事件都包含调用进程的操作系统、操作系统版本、Python 版本、CLI 版本、命令名称（`dev`、`up`、`run` 等），以及一组表示某个 flag 是否被传入命令的布尔值。更多信息请参见[完整 analytics 逻辑](https://github.com/langchain-ai/langgraph/blob/main/libs/cli/langgraph-cli/analytics.py)。

你可以通过设置 `LANGGRAPH_CLI_NO_ANALYTICS=1` 来禁用所有 CLI telemetry。

## Agent Server

[Agent Server](/langsmith/agent-server) 提供持久化执行运行时，会把应用状态 checkpoint、长期记忆、线程元数据、assistants 以及类似资源持久化到本地文件系统或数据库中。除非你显式自定义过存储位置，否则这些信息要么写入本地磁盘（`langgraph dev`），要么写入 PostgreSQL 数据库（`langgraph up` 以及所有部署场景）。

### LangSmith tracing

运行 Agent server 时（无论是内存模式还是 Docker 模式），可以启用 LangSmith tracing，以帮助更快地调试，并在生产环境中获得 graph state 和 LLM prompts 的可观测性。你随时可以在服务运行时环境中设置 `LANGSMITH_TRACING=false` 来关闭 tracing。

<Note>
如果你需要更细粒度的控制，可以使用[条件 tracing](/langsmith/conditional-tracing)，根据运行时条件（例如客户要求或数据敏感级别）有选择地启用或关闭 tracing。
</Note>

<a id="langgraph-dev"></a>
### 内存开发服务器

`langgraph dev` 会以单个 Python 进程运行一个[内存型开发服务器](/langsmith/local-dev-testing)，适合快速开发和测试。它会把所有 checkpoint 与 memory 数据保存到当前工作目录下的 `.langgraph_api` 目录中。除 [CLI](#cli) 小节中提到的 telemetry 数据外，除非你启用了 tracing，或者你的 graph 代码主动访问外部服务，否则不会有任何数据离开本机。

<a id="langgraph-up"></a>
### 独立服务器

`langgraph up` 会把你的本地包构建成 Docker image，并把服务作为[data plane](/langsmith/self-hosted)运行，包含三个容器：API server、PostgreSQL 容器和 Redis 容器。所有持久化数据（checkpoints、assistants 等）都会存储在 PostgreSQL 数据库中。Redis 被用作实时事件流的 pubsub 连接。你可以通过设置有效的 `LANGGRAPH_AES_KEY` 环境变量，在 checkpoint 保存到数据库前先进行加密。你也可以在 `langgraph.json` 中为 checkpoints 和跨线程 memories 指定 [TTL](/langsmith/configure-ttl)，以控制数据保留时间。所有持久化线程、记忆和其他数据都可以通过相应 API 端点删除。

系统还会发起额外的 API 调用，以确认 server 拥有有效 license，并跟踪执行的 runs 和 tasks 数量。API server 还会定期校验所提供的 license key（或 API key）。

如果你已经关闭了[tracing](#langsmith-tracing)，那么除非你的 graph 代码显式访问外部服务，否则不会有用户数据被持久化到外部系统。

## Studio

[Studio](/langsmith/studio) 是一个用于与 Agent Server 交互的图形界面。它不会持久化任何私有数据（你发送给 server 的数据不会被转发给 LangSmith）。虽然 Studio 界面托管在 [smith.langchain.com](https://smith.langchain.com)，但它运行在你的浏览器里，并直接连接到本地 Agent Server，因此无需把数据发送到 LangSmith。

如果你已登录，LangSmith 会收集一些 usage analytics，以帮助改进调试体验。这包括：

* 页面访问和导航模式
* 用户操作（按钮点击）
* 浏览器类型和版本
* 屏幕分辨率和视口尺寸

重要的是，我们不会收集任何应用数据、代码或其他敏感配置细节。这些内容都存储在你的 Agent Server 的持久层中。若以匿名方式使用 Studio，则无需创建账户，也不会收集 usage analytics。

## 快速参考

总结一下，你可以通过关闭 CLI analytics 并禁用 tracing 来退出服务端 telemetry。

| 变量 | 用途 | 默认值 |
| --- | --- | --- |
| `LANGGRAPH_CLI_NO_ANALYTICS=1` | 禁用 CLI analytics | 默认启用 analytics |
| `LANGSMITH_API_KEY` | 启用 LangSmith tracing | 默认关闭 tracing |
| `LANGSMITH_TRACING=false` | 禁用 LangSmith tracing | 取决于运行环境 |
