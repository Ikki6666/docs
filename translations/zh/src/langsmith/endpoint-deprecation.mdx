LangSmith 在移除 API endpoints 和 SDK methods 之前会先弃用它们，让你有时间迁移到替代方案。本页介绍弃用如何公告，以及它们会继续被支持多久。

<Note>本政策仅适用于 [LangSmith API reference](/langsmith/smith-api-ref) 和 [Agent Server API reference](/langsmith/server-api-ref) 中记录的公共 endpoints。内部未公开的 endpoints 不在覆盖范围内，可能随时更改，包括破坏性变更。</Note>

## 弃用生命周期

每次弃用都遵循相同的阶段：

1. **Announced**：弃用在 [changelog](/langsmith/changelog) 中公布，一旦确定移除日期就会一并公布；在需要更改调用处的地方，还会发布记录替代方案的 migration guide。
2. **Marked**：被弃用的 API endpoint 会返回 `Deprecation: true` 和 `Sunset: <date>` response headers。被弃用的 SDK methods 会在文档中标记，并且在支持的地方于调用时抛出弃用警告。
3. **Supported**：被弃用的 endpoint 会在一个最小窗口期内继续工作，该窗口取决于你的 deployment。请参阅 [Deprecation window by deployment](#deprecation-window-by-deployment)。
4. **Removed**：支持窗口结束后，该 endpoint 被移除。

在 Cloud 中，如果临近移除日期仍有活跃的消费方，LangSmith 可能会对该弃用 endpoint 施加速率限制和更高延迟，并在一部分请求上返回明确的错误信息，作为在移除前引起剩余使用注意的最后手段。受影响的客户会提前得到直接通知。

## 按 deployment 划分的弃用窗口

| Deployment | 最小支持窗口 |
|---|---|
| Cloud | 从公告到移除 6 个月 |
| Self-hosted | 至少一个 major release |

Self-hosted major releases 大致按六周的节奏发布。详情请参阅 [Release policy](/langsmith/release-versions)。

## SDK method 弃用

大多数 SDK methods 是 API endpoint 的轻量封装，因此一个 method 会与它调用的 endpoint 在同一时间线上弃用，并在 endpoint 被移除时从 SDK 中移除。

不与 endpoint 一一对应、或独立于任何 endpoint 变更而弃用的 method，可以有不同的弃用时间线。它会在两处明确公告：在 SDK 中，通过文档和弃用警告；在 API 中，通过上述流程。

## 字段级弃用

被弃用的字段在版本边界移除，而不是按日期移除：

- **API 字段和参数**：被弃用的 response 字段、request body 字段或 query parameter 会在同一个 endpoint 版本内继续工作。移除是破坏性变更，因此只随下一个 endpoint 版本发布，例如 v1 到 v2。
- **SDK method 字段和参数**：在当前 major SDK 版本内继续工作。移除需要新的 major SDK 版本，独立于 API 自身的版本管理。
