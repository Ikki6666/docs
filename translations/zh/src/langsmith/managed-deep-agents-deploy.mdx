部署 Managed Deep Agent 会把代码优先项目编译成托管 LangGraph app，将 deploy 负责的 context 同步到 [Context Hub](/langsmith/use-the-context-hub)，上传编译后的源码，并触发 LangSmith hosted deployment build。

## 前置条件

在部署前，请确认你已经具备：

- 一个拥有 Managed Deep Agents [private beta 访问权限](https://www.langchain.com/langsmith-managed-deep-agents-waitlist) 的 workspace。
- 该 workspace 的 [LangSmith API key](/langsmith/create-account-api-key)，并把它放在 `.env` 或 shell 环境变量中。
- 从 `managed-deepagents` 安装好的 `mda` CLI。
- 已安装项目依赖，TypeScript 项目使用 `npm install`，生成的 Python 项目使用 `uv sync`。
- 模型 provider 凭据，例如 `OPENAI_API_KEY`，并放在 `.env`、shell 环境变量或 LangSmith workspace secrets 中。

CLI 默认面向美国区域 LangSmith Cloud。

## 项目文件

Managed Deep Agents 项目以 agent 入口文件为起点，可以按需包含若干项目目录。你可以通过 `mda init` 创建项目，也可以在现有 TypeScript 或 Python 项目根目录中加入 `agent.ts`、`agent.tsx` 或 `agent.py` 来适配现有项目。

完整文件布局与打包规则请参见 [CLI project file reference](/langsmith/managed-deep-agents-cli#project-file-reference)。如果你需要定义 agent 入口、tools、middleware 和 interrupts，请参见 [quickstart](/langsmith/managed-deep-agents-quickstart#edit-the-agent)。

## 配置 instructions、skills 和 memory

请把 system prompt 放在项目根 agent 入口旁边的 `instructions.md` 中：

```markdown instructions.md
# Assistant

You are a careful assistant. Use available tools when needed and cite sources.
```

请把 deploy 负责的 skills 放在项目根 agent 入口旁边的 `skills/` 目录下。Deploy 会把 `instructions.md` 和 `skills/**` 同步到与该 deployment 关联的 Context Hub repo。

托管 memory 存储在同一个 Context Hub repo 的 `/memories/AGENTS.md` 中。Deploy 会同步 `instructions.md` 和 `skills/**`，但会保留 memory，不会覆盖 `memories/**`。如果要关闭 MDA 托管 memory，请在 agent 定义中设置 `disableMemory: true` 或 `disable_memory=True`。

## 添加 tools、connectors 和 middleware

请直接在 agent 源码中添加自编写 tools 和 middleware。MDA 会把项目文件复制到编译后的 build 中，因此从 `tools/`、`middleware/` 或其他本地模块导入时，行为与普通 Python 或 TypeScript 项目一致。

- 对于业务逻辑、私有 API、数据库访问以及其他项目自有代码，请使用 [custom tools](/langsmith/managed-deep-agents-tools)。
- 对于围绕模型调用、工具调用、生命周期 hooks、重试、限制和数据处理的横切逻辑，请使用 [custom middleware](/langsmith/managed-deep-agents-middleware)。
- 在 `connectors/mcp.ts` 或 `connectors/mcp.py` 中声明远程 MCP servers；MDA 会在运行时加载这些 connector tools，并把它们追加到自编写 tools 之后。示例和指导请参见 [Connect MCP tools](/langsmith/managed-deep-agents-mcp)。

如果你希望在敏感 tool calls 前暂停等待人工批准，请在 agent 定义中设置 `interrupt_on`。请参见 [Human-in-the-loop](/langsmith/managed-deep-agents-middleware#human-in-the-loop)。

## 添加 schedules

如果 agent 需要按固定频率运行，请在 `schedules/` 下添加托管 cron schedules。每个 schedule 文件都要导出一个使用 `defineSchedule` 或 `define_schedule` 创建的命名 `schedule` 声明。

示例与 schedule 限制请参见 [Schedules](/langsmith/managed-deep-agents-schedules)。

## 配置 sandbox

当 agent 需要隔离的代码执行环境或文件系统操作能力时，请使用 sandbox。你可以在 `sandbox/index.ts` 或 `sandbox/__init__.py` 中导出 `sandbox`。

<CodeGroup>

```python sandbox/__init__.py
from managed_deepagents import define_sandbox
from deepagents.backends import LangSmithSandbox

sandbox = define_sandbox(
    LangSmithSandbox,
    scope="thread",
    idle_ttl_seconds=600,
    default_timeout=600,
)
```

```ts sandbox/index.ts
import { defineSandbox } from "managed-deepagents";
import { LangSmithSandbox } from "deepagents";

export const sandbox = defineSandbox(LangSmithSandbox, {
  scope: "thread",
  idleTtlSeconds: 600,
  defaultTimeout: 600,
});
```

</CodeGroup>

Sandboxes 以 thread 为作用域。每个 durable thread 或 conversation 都拥有自己的 sandbox。

如果存在 `sandbox/setup.sh`，MDA 会在新建托管 sandbox 时运行一次。你可以用它来安装包、准备文件或初始化工作区状态。

关于 sandbox 的 scope 和本地开发时的生命周期，请参见 [How Managed Deep Agents work](/langsmith/managed-deep-agents-how-it-works#sandboxes)。

## 本地运行

运行本地 LangGraph dev server：

```bash
mda dev .
```

`mda dev` 会编译到 `.mda/build`，并从该目录启动对应的 LangGraph dev server。你可以传入 `--port`、`--hostname`、`--browser` 或 `--no-reload` 来控制本地 dev server 行为。

在本地开发时，`mda dev` 会把项目 `.env` 文件暂存到 `.mda/build/.env`，以便 LangGraph 加载 model provider keys 和 connector tokens。

对于 Python 项目，`mda dev` 要求 `uv` 位于 `PATH` 中，并会自动解析本地 LangGraph dev server。

如果配置了 sandbox，`mda dev` 会优先尝试配置的 provider；当缺少 provider 凭据时，它会退回到本地临时目录 sandbox。这个本地 fallback 仅适用于开发。

全部 `mda dev` flags 请参见 [CLI reference](/langsmith/managed-deep-agents-cli#develop-locally)。

## 部署到 LangSmith

部署本地项目：

```bash
mda deploy .
```

<Tip>
`mda deploy` 会把本地项目输入路由到不同的托管目标：

```text
instructions.md + skills/**  -> Context Hub 中由 deploy 管理的 context
memories/**                  -> 忽略；保留已有 Context Hub memory
.env                         -> deploy 鉴权 + 非保留托管 secrets，不打包归档
project source files         -> .mda/build 源码归档 -> 托管 deployment
schedules/**                 -> deployment 可用后同步为 LangSmith cron jobs
```
</Tip>

如果目录名不是你希望的 deployment 名称，可以显式设置名称：

```bash
mda deploy . --name research-assistant
```

创建生产 deployment 时，请使用 `--deployment-type prod`：

```bash
mda deploy . --deployment-type prod
```

如果你只想触发 build 而不等待完成，可以使用 `--no-wait`：

```bash
mda deploy . --no-wait
```

启用 `--no-wait` 时，CLI 会在 deployment 进入 `DEPLOYED` 之前退出，因此这次调用不会对 schedules 执行 reconcile。

成功后，CLI 会打印 LangSmith deployment dashboard URL。完整 deploy 步骤请参见 [CLI reference](/langsmith/managed-deep-agents-cli#deploy-projects)。

## Secrets 与环境文件

`mda deploy` 会优先读取项目 `.env`，再读取 shell 环境变量。你可以把用于 deploy 鉴权的 LangSmith API key，以及托管 deployment 所需的运行时 secrets 放进 `.env`：

```text .env
LANGSMITH_API_KEY=<LANGSMITH_API_KEY>
OPENAI_API_KEY=<OPENAI_API_KEY>
GITHUB_MCP_TOKEN=<GITHUB_MCP_TOKEN>
DATABASE_URL=<DATABASE_URL>
```

`LANGSMITH_API_KEY`、`LANGGRAPH_HOST_API_KEY`、`LANGCHAIN_API_KEY` 以及其他平台变量属于保留变量。它们可用于 deploy 鉴权，但不会作为用户可管理的 deployment secrets 上传。

诸如模型 provider keys、MCP tokens 和自定义 tool 凭据等非保留 `.env` 项，会在 `mda deploy` 创建或更新 deployment 时转发为托管 deployment secrets。如果所配置的模型依赖某个 provider key，而该 key 在 `.env`、shell 环境变量或 LangSmith workspace secrets 中都找不到，deploy 会在上传前失败。如果 provider key 仅存在于 shell 环境变量中，`mda deploy` 也会在这次部署中将其作为 secret 转发。

保留平台变量、空值、`.env` 和 `.env.*` 文件都不会被复制到编译后的 build archive 中。

关于认证 key 的优先顺序和保留变量清单，请参见 [CLI reference](/langsmith/managed-deep-agents-cli#authentication)。

## 排查 deploy 问题

Deploy 故障排查请参见 [CLI reference](/langsmith/managed-deep-agents-cli#troubleshooting)。

如果 deployment 进入 `BUILD_FAILED` 或 `DEPLOY_FAILED`，请在 LangSmith 中打开 CLI 打印出的 deployment URL，查看 revision logs。
