部署 Managed Deep Agent 会把代码优先项目编译成托管 LangGraph app，将 deploy 负责的 context 同步到 [Context Hub](/langsmith/managed-deep-agents-context-hub)，上传编译后的源码，并触发 LangSmith hosted deployment build。最终得到的是一个 [Agent Server](/langsmith/agent-server-overview) deployment，包括 Agent Server API 和 [MCP endpoint](/langsmith/managed-deep-agents-mcp-endpoint)。

<ManagedDeepAgentsPublicBetaNote />

本页介绍 secrets 路由和 deploy 选项。要在部署前测试 agent，请参见[使用 LangSmith Studio 进行本地开发](/langsmith/managed-deep-agents-local-development)。关于命令 flags、deploy 步骤清单和故障排查，请参见 [CLI reference](/langsmith/managed-deep-agents-cli)。

## 前置条件

在部署前，请确认你已经具备：

- 一个拥有 Managed Deep Agents 公开 beta 访问权限的 workspace。
- 该 workspace 的 [LangSmith API key](/langsmith/create-account-api-key)，并把它放在 `.env` 或 shell 环境变量中。
- 从 `managed-deepagents` 安装好的 `mda` CLI。
:::python
- 已安装项目依赖，生成的 Python 项目使用 `uv sync`。
:::

:::js
- 已安装项目依赖，TypeScript 项目使用 `npm install`。
:::

- 模型 provider 凭据，例如 `OPENAI_API_KEY`，并放在 `.env`、shell 环境变量或 LangSmith workspace secrets 中。

CLI 默认面向美国区域 LangSmith Cloud。

## 部署到 LangSmith

部署本地项目：

:::python
```bash
uv run mda deploy
```
:::

:::js
<CodeGroup>
    ```bash npm
    npx mda deploy
    ```

    ```bash pnpm
    pnpm exec mda deploy
    ```

    ```bash bun
    bunx mda deploy
    ```
</CodeGroup>
:::

<Tip>
`mda deploy` 会把本地项目输入路由到不同的托管目标：

```text
instructions.md + skills/**  -> Context Hub 中由 deploy 管理的 context
.env                         -> deploy 鉴权 + 非保留托管 secrets，不打包归档
project source files         -> .mda/build 源码归档 -> 托管 deployment
schedules/**                 -> deployment 可用后同步为 LangSmith cron jobs
```
</Tip>

如果目录名不是你希望的 deployment 名称，可以显式设置名称：

:::python
```bash
uv run mda deploy --name research-assistant
```
:::

:::js

    ```

    ```
</CodeGroup>
:::

:::

如果你只想触发 build 而不等待完成，可以使用 `--no-wait`：

:::python
```bash
uv run mda deploy --no-wait
```
:::

:::js
<CodeGroup>
    ```bash npm
    npx mda deploy --no-wait
    ```

    ```bash pnpm
    pnpm exec mda deploy --no-wait
    ```

    ```bash bun
    bunx mda deploy --no-wait
    ```
</CodeGroup>
:::

启用 `--no-wait` 时，CLI 会在 deployment 进入 `DEPLOYED` 之前退出，因此这次调用不会对 schedules 执行 reconcile。

成功后，CLI 会打印 LangSmith deployment dashboard URL。完整 deploy 步骤请参见 [CLI reference](/langsmith/managed-deep-agents-cli#deploy-projects)。

## 设置 Python 版本

<Note>
配置 Python 版本需要 `managed-deepagents>=0.8.0`。
</Note>

MDA 构建 deployment 镜像时支持 Python 3.11、3.12、3.13 或 3.14，默认选择 `requires-python` 允许的最新版本。要固定版本，请将可选的 `[tool.mda]` 表加入 `pyproject.toml`：

```toml pyproject.toml
[project]
requires-python = ">=3.11"

[tool.mda]
python-version = "3.14"
```

设置后，`python-version` 接受带引号的 `major.minor` 字符串，不含 patch 版本。MDA 会把解析后的版本写入生成的 `langgraph.json` 中的 `python_version`，并选择匹配的 [Agent Server](/langsmith/agent-server-overview) 镜像。`requires-python` 仍然是项目自身的兼容性要求。

当 MDA 新增对更新 Python 的支持时，固定该版本可以让 deployment 停留在同一个 minor 版本。若只在单次 build 中覆盖，可设置 `MDA_PYTHON_VERSION`：

```bash
MDA_PYTHON_VERSION=3.12 uv run mda deploy
```

`requires-python` 排除的目标会导致 build 失败。依赖镜像确切 patch 版本的目标只会触发警告，因为镜像 tag 不会固定 patch 版本。

`python-version` 只控制 deployment 镜像。本地 build、`mda dev`、Harbor task 镜像和[执行 sandbox](/langsmith/managed-deep-agents-sandboxes) 会分别选择各自的解释器。
:::

## Secrets 与环境文件

`mda deploy` 会优先读取项目 `.env`，再读取 shell 环境变量。你可以把用于 deploy 鉴权的 LangSmith API key，以及托管 deployment 所需的运行时 secrets 放进 `.env`：

```text .env
LANGSMITH_API_KEY=<LANGSMITH_API_KEY>
OPENAI_API_KEY=<OPENAI_API_KEY>
GITHUB_MCP_TOKEN=<GITHUB_MCP_TOKEN>
DATABASE_URL=<DATABASE_URL>
MDA_INGRESS_SECRET=<MDA_INGRESS_SECRET>
```

只有当项目声明了[后端 identity](/langsmith/managed-deep-agents-identity#configure-identity-with-your-own-backend) 时，才需要 `MDA_INGRESS_SECRET`。如果存在该声明但缺少对应值，deploy 会在 preflight 阶段失败。

`LANGSMITH_API_KEY`、`LANGGRAPH_HOST_API_KEY`、`LANGCHAIN_API_KEY` 以及其他平台变量属于保留变量。它们可用于 deploy 鉴权，但不会作为用户可管理的 deployment secrets 上传。

诸如模型 provider keys、MCP tokens 和自定义 tool 凭据等非保留 `.env` 项，会在 `mda deploy` 创建或更新 deployment 时转发为托管 deployment secrets。如果所配置的模型依赖某个 provider key，而该 key 在 `.env`、shell 环境变量或 LangSmith workspace secrets 中都找不到，deploy 会在上传前失败。如果 provider key 仅存在于 shell 环境变量中，`mda deploy` 也会在这次部署中将其作为 secret 转发。

保留平台变量、空值、`.env` 和 `.env.*` 文件都不会被复制到编译后的 build archive 中。

关于认证 key 的优先顺序和保留变量清单，请参见 [CLI reference](/langsmith/managed-deep-agents-cli#authentication)。

## 排查 deploy 问题

Deploy 故障排查请参见 [CLI reference](/langsmith/managed-deep-agents-cli#troubleshooting)。

如果 deployment 进入 `BUILD_FAILED` 或 `DEPLOY_FAILED`，请在 LangSmith 中打开 CLI 打印出的 deployment URL，查看 revision logs。
