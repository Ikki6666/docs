[LangSmith data migration tool](https://github.com/langchain-ai/langsmith-data-migration-tool) 会将数据从现有的 LangSmith Cloud 组织或 [self-hosted](/langsmith/self-hosted) 实例复制到 BYOC data plane。该工具是复制数据（而不是搬移数据），因此源实例保持不变，并在迁移过程中保持可用。

在你的 data plane [处于活动状态且可访问](/langsmith/byoc-onboarding)之后再运行迁移。Trace 数据不会被迁移，因此请将[工具不迁移的手动步骤](#move-data-the-tool-does-not-migrate)与该工具一起规划。

## 受支持的资源

该工具会在源实例与目标 data plane 之间迁移以下资源：

| 资源 | 详情 |
|----------|---------|
| 用户和角色 | 自定义角色、组织成员和 workspace 成员身份。 |
| Datasets | Datasets 及其 examples 和文件附件。 |
| Experiments | Experiments、experiment runs 和 feedback，随其 datasets 一起迁移。 |
| Annotation queues | Queue 配置和设置。迁移后的 queues 初始为空。 |
| Automation rules | 项目 automation rules，映射到目标项目。 |
| Prompts | Prompts 及其完整的 commit history。 |
| 图表 | 监控图表和 dashboards。 |
| 自定义模型定价 | Workspace 级自定义模型价格条目。 |
| Fleet | Agents、共享 skills、MCP servers、integrations、auth providers、schedules、triggers、webhooks、usage limits、sandbox policies 以及 workspace secrets。 |
| Context Hub | Context Hub agents 和 skills，包括文件、仓库元数据、commit history 和 commit tags。 |

每种资源类型都有自己的命令、flags 和注意事项。命令参考请参阅[工具 README](https://github.com/langchain-ai/langsmith-data-migration-tool/blob/main/README.md)。

<Note>
属于 BYOC 尚不支持的功能的资源无法迁移，例如 [Engine](/langsmith/engine-overview)。参见 [Available features](/langsmith/byoc#available-features)。
</Note>

## 使用工具进行迁移

<Steps>

<Step title="Install the tool">
使用 `uv`、`uvx` 或 `pip` 安装最新版本。当前安装命令请参阅 [Installation](https://github.com/langchain-ai/langsmith-data-migration-tool#installation)。

验证安装：

```bash
langsmith-migrator --help
```
</Step>

<Step title="Create the destination workspaces">
Workspace ID 在不同实例之间不同，因此请先在 data plane 中创建目标 workspaces。请参阅 [BYOC 入门文档](/langsmith/byoc-onboarding)的 `Create workspaces` 部分。

迁移命令按 workspace pair 运行。对每一对重复执行。
</Step>

<Step title="Create the destination tracing projects">
该工具不会创建 tracing projects。在迁移 automation rules 或图表之前，请先在目标 workspace 中创建所需的项目，否则这些映射将没有目标。
</Step>

<Step title="Configure the connection details">
设置源和目标的凭证与 endpoint：

```bash
export LANGSMITH_OLD_API_KEY="<source_instance_key>"
export LANGSMITH_NEW_API_KEY="<data_plane_key>"
export LANGSMITH_OLD_BASE_URL="<source_instance_api_url>"
export LANGSMITH_NEW_BASE_URL="https://<data_plane_host>"
export LANGSMITH_VERIFY_SSL=true
```

<Note>
`OLD` 指你当前的 LangSmith 部署，`NEW` 指目标 BYOC data plane：

- **`LANGSMITH_OLD_API_KEY`**：来自你当前部署的 API key，具有读取你要迁移的所有资源的权限。对于位于 [smith.langchain.com](https://smith.langchain.com) 的 LangSmith Cloud，在 **Settings > API Keys** 下创建。对于其他 Cloud region 或 self-hosted 实例，使用该部署的 UI。
- **`LANGSMITH_NEW_API_KEY`**：在 [aws.smith.langchain.com](https://aws.smith.langchain.com) 的 **Settings > API Keys** 下创建的 API key。将其范围限定为你的目标 BYOC data plane 中的一个 workspace。参见 [Create an API key](/langsmith/create-account-api-key#api-keys)。
- **`LANGSMITH_OLD_BASE_URL`**：你当前部署的 API URL。对于 GCP US 的 LangSmith Cloud，使用 `https://api.smith.langchain.com`。对于其他 Cloud region，使用其[区域 API URL](/langsmith/create-account-api-key#configure-the-sdk)。对于 self-hosted LangSmith，使用你实例的 API URL。
- **`LANGSMITH_NEW_BASE_URL`**：你的目标 BYOC data plane 的 API URL，包括 `https://`。可以在 **Settings > Data Planes** 下找到。参见 [BYOC 入门](/langsmith/byoc-onboarding)。
</Note>

<Warning>
目标 key 的范围必须限定为目标 data plane 中的一个 workspace。组织级 key 无法使用。

要迁移带 owner 的 Fleet agents，请使用个人访问令牌（`lsv2_pt_*`）作为目标 key。Workspace API keys 不携带用户身份，因此用它们创建的 agents 没有 owner。
</Warning>
</Step>

<Step title="Test both connections">
```bash
langsmith-migrator test
```
</Step>

<Step title="Run the migration">
使用交互式向导遍历每种资源类型：

```bash
langsmith-migrator migrate-all
```

要一次迁移一种资源类型，请改为运行它的命令，例如 `datasets`、`prompts` 或 `fleet`。添加 `--dry-run` 可以在不写入的情况下预览某一步骤，添加 `-v` 可以获得详细输出。使用 `langsmith-migrator resume` 可以重试上一次会话中待处理或失败的项目。

各命令的 flags、workspace 映射和 project 映射请参阅[工具 README](https://github.com/langchain-ai/langsmith-data-migration-tool/blob/main/README.md)。
</Step>

</Steps>

## 完成 Fleet 手动步骤

[Fleet](/langsmith/fleet/index) 资源会通过 `fleet` 命令迁移，但某些值无法跨实例传输。迁移完成后，请在目标 workspace 中完成以下操作：

- **重新输入 secret 值**：Fleet API 不返回 secret 值。该工具会创建 workspace secrets 和 auth provider client secrets 的空占位符。
- **重新进行 OAuth 连接认证**：按用户的 agent 连接（例如 Gmail、Slack 和 GitHub）绑定到单个用户的 token。每个用户必须重新连接。
- **重新共享 agents**：按用户的访问列表只保留目标实例上存在的用户 ID。该工具会报告它移除了哪些用户。
- **检查 agent 模型**：当目标 catalog 不提供源模型时，该工具会替换为一个替代模型。它会记录每一次替换。
- **配置基础设施级设置**：OAuth providers、GitHub App 和 Slack app 可以在 `Settings > Oauth Providers` 和 `Fleet > Integrations` UI 中重新创建。

Fleet migrators 从不覆盖目标实例上已存在的资源，因此重新运行 `fleet` 是安全的。

## 迁移工具不迁移的数据

### Traces

该工具不会迁移 traces。若要在旧实例的生命周期之外保留历史 traces，请将它们[批量导出](/langsmith/data-export)到 S3 兼容的存储桶。

要迁移 tracing 应用，请创建范围限定为 data plane 中某个 workspace 的 API keys，然后重新指向该应用：

- **直接切换**：将 `LANGSMITH_ENDPOINT` 设置为 data plane endpoint，将 `LANGSMITH_API_KEY` 设置为新的 key。参见 [Trace to a data plane](/langsmith/byoc-usage#trace-to-a-data-plane)。
- **双写 traces**：在过渡期间同时写入旧实例和 data plane。参见 [Trace to multiple endpoints](/langsmith/byoc-usage#trace-to-multiple-endpoints)。

### 已部署的 agents

将运行在现有实例上的 agents 重新部署到 data plane 中的一个 workspace。使用 LangSmith UI 或 API。你可能还需要在 data plane 集群中重新创建 service accounts、image pull secrets 和其他资源。

对于 agent 数据库和缓存，请选择以下方式之一：

- 在 data plane 中创建新实例，并将重新部署的 agents 指向它们。可以以空状态开始，或从旧实例的备份恢复。
- 将重新部署的 agents 指向你现有的数据库实例，并从 data plane 集群通过 PrivateLink 或 VPC peering 访问它们。

更多信息，请参阅 [LangSmith Deployment](/langsmith/deployment)。

### Insights reports

[Insights](/langsmith/insights) reports 不会跨实例迁移。若要保留一份 report，请在 LangSmith UI 中打开其详情并选择 **Download**。
