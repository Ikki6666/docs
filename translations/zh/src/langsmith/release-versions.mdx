自托管 LangSmith 通过两个发布通道交付：一个供客户在生产环境中运行的稳定通道，以及一个跟踪下一个大版本的预览通道。

## 发布通道

### Stable

当前已正式发布的主要版本。LangSmith 建议在生产环境中使用该通道。Stable 每周接收一次补丁发布，其中仅包含关键 bug 修复和安全补丁。在各个大版本之间，不会向 stable 引入新特性、数据迁移或基础设施变更。

在本页中，`N` 指代当前的 stable 大版本。Preview 跟踪下一个大版本，即 `N+1`。

### Preview

下一个大版本的开发构建。Preview 会随着 LangSmith SaaS 的变更合入而包含新特性和修复，因此可以在其成为 stable 之前先评估下一个大版本。Preview 构建可能包含数据迁移，但不会新增或移除服务，也不会引入破坏性变更。

Preview 适合在测试和预发布环境中评估。LangSmith 不建议在生产环境中运行 preview。

## 发布节奏

| Channel | Cadence |
|---------|---------|
| Preview | 随 LangSmith SaaS 的发布节奏同步发布 |
| Stable: new major (`v0.X.0`) | 大约每 6 周一次（每季度两次） |
| Stable: patch (`v0.X.Y`) | 每周一次（通常在周五），如果没有变更则跳过。遇到关键客户问题时会发布临时版本。 |

## 每个通道包含的内容

|  | Preview | Stable patch | Next major |
|--|:-:|:-:|:-:|
| 新特性 | yes | no | yes |
| Bug 修复 | yes | critical only | yes |
| 安全补丁 | yes | yes | yes |
| 数据迁移和回填 | yes | no | yes |
| 新增或移除服务 | no | no | yes |
| 破坏性变更 | no | no | yes |

服务新增、服务移除以及破坏性变更只会出现在新的大版本中，因此在规划升级到新大版本时需要考虑这一点。

## 版本号规则

每个自托管发布都有两个版本号：

- **chart 版本**是你安装并固定的 Helm chart 版本。发布的命名以它为准，无论是在[自托管 changelog](/langsmith/self-hosted-changelog) 中，还是作为 [Helm repository](https://github.com/langchain-ai/helm/releases) 的发布标签，例如 `langsmith-0.17.2`。
- **LangSmith 版本**是该 chart 部署的应用版本，记录为 chart 中的 `appVersion`。

|  | Chart 版本 | 示例 |
|--|--|--|
| Stable | `0.17.Y` | Chart `0.17.2` 部署 LangSmith `0.17.30` |
| Preview（候选发布版） | `0.18.0-rc.N` | Chart `0.18.0-rc.12` 部署 LangSmith `0.18.4rc1` |

每行当前的补丁版本和候选发布版本，请参见[自托管 changelog](/langsmith/self-hosted-changelog) 或 Helm repository 的发布标签。

- Stable chart 版本为 `0.X.Y`，其中 `X` 是大版本，`Y` 随每次补丁发布递增。
- Preview chart 版本为 `0.X.0-rc.N`，其中 `N` 随每次候选发布递增。
- 两个版本号独立推进。chart 的补丁号和 LangSmith 的补丁号不必一致。

用于发布列车（`v16`、`v17`）的 `vX` 简写指代大版本，因此 `v17` 表示 chart 版本 `0.17.Y`。

## 配对 sandbox runtime chart

在独立集群中运行 [Sandboxes](/langsmith/self-host-sandbox-separate-cluster) 的安装会为 sandbox runtime 额外安装一个 chart，即 `langsmith-sandbox`。两个 chart 按 appVersion（即 LangSmith 版本）配对，而不是按 chart 版本配对：

- 运行 appVersion 与你的 `langsmith` chart 的 appVersion 相同的最新 `langsmith-sandbox` chart。runtime chart 与大版本保持一致，例如 `0.18`，但其补丁号和候选发布号与 `langsmith` chart 独立推进。
- 将 runtime chart 中的 `images.sandboxHostImage.tag` 留空，使 runtime 镜像跟随该 chart 的 appVersion。

要列出 runtime chart 版本及其 appVersion，请运行：

```bash
helm search repo langchain/langsmith-sandbox --versions --devel
```

[自托管 changelog](/langsmith/self-hosted-changelog) 中的每个发布也会链接其 runtime chart，适用于需要镜像 chart 或无法访问 Helm repository 的安装。

有关升级顺序，请参阅[升级独立的 sandbox 集群](/langsmith/self-host-upgrades#upgrade-separate-sandbox-clusters)。

## 版本支持

LangSmith 支持当前 stable 大版本（`N`）以及前一个 stable 大版本（`N-1`）：

- `N` 获得活跃支持：关键 bug 修复、安全补丁，以及每周的补丁发布。
- `N-1` 仅获得关键支持：关键 bug 修复和安全补丁，按需发布而非每周发布。
- 早于 `N-1` 的版本已结束生命周期，不会再收到新的补丁发布、bug 修复或安全更新。

由于大约每 6 周会发布一个新的大版本，某个版本在被取代为 stable 之后大约 6 周即到达生命周期终点。一旦版本到达生命周期终点，修复不会被回移植；请升级到受支持的大版本以获取这些修复。

除两个受支持的 stable 版本外，下一个大版本会以一系列候选发布版的形式在 preview 通道上提供，例如 `0.18.0-rc.12`。Preview 构建会持续发布，并始终携带最新的修复，但其用途是在测试和预发布环境中进行评估，而非用于生产。在非生产环境中运行 preview，是在下一个大版本成为 stable 之前对其进行验证的推荐方式。

## 建议

- **在生产环境中运行 stable。** Preview 仅用于评估，可能包含仍在验证中的未发布特性。
- **在测试或预发布环境中使用 preview。** 在非生产环境中运行 preview，是及早发现问题并为下一个大版本升级做准备的最佳方式。
- **提前规划大版本升级。** 数据迁移、服务新增或移除，以及破坏性变更只会出现在新的大版本中。升级前请查看[自托管更新日志](/langsmith/self-hosted-changelog)，并为所需的数据或基础设施变更做好规划。
- **保持在受支持版本上。** LangSmith 建议在每个新大版本发布后尽快升级，以按推荐节奏获得架构改进。
