<Warning>
这些是估算值，不是报价。AWS 会不另行通知地调整价格。你的账单取决于 region、使用量，以及你与 AWS 达成的任何折扣协议，例如 Enterprise Discount Program 或 Savings Plan。
</Warning>

这是你的 AWS 账户中一个 LangSmith data plane 的粗略月度成本。

<Note>
在部署保持在安全运行范围内的前提下，任何资源的扩容容量都可以在需要时下调。对于注重成本或预生产环境的部署，可以关闭 Multi-AZ。这会降低月度成本，但会降低容错能力。
</Note>

<Tabs>
  <Tab title="ClickHouse">
    ClickHouse 也可以作为单节点运行，而不是副本集群。这会降低月度成本，但会降低容错能力。

    | 项目 | 粗略月度估算 | 备注 |
    | --- | --- | --- |
    | RDS PostgreSQL | \$100–\$150 | `db.t4g.medium`，Multi-AZ，50 GB 初始存储。 |
    | ElastiCache Redis | \$140–\$280 | 下限为不启用 read replicas 的情况。上限为启用 read replicas 的情况。 |
    | EKS control plane | ~\$75 | 一个 EKS 集群，按标准小时费率计费。 |
    | System node group | ~\$210 | 3 个 `m6i.large` on-demand 节点。 |
    | Application、ClickHouse 和 ZooKeeper worker 节点 | \$1,000–\$1,500 | LangSmith pods 和 ClickHouse pods。 |
    | EBS 卷 | \$200–\$350 | ClickHouse、ZooKeeper、节点卷，以及 gp3 性能设置。 |
    | 网络 | \$150–\$300 | NAT gateways、load balancer、PrivateLink 或 VPC endpoints，以及低流量数据处理。 |
    | S3、Secrets Manager、CloudWatch | \$50–\$200 | 低流量基线。随 trace payload、日志和保留策略增长。 |

    预计月度总计：**\$1,925–\$3,065**
  </Tab>
  <Tab title="SmithDB">
    默认情况下，SmithDB 运行 [Configure SmithDB for scale](/langsmith/self-host-smithdb-scale) 中的 Small tier：大约每秒 10 次 run 和每秒 10 次查询。LangSmith 会根据 tracing 量按需提升该 tier。

    <Warning>
    SmithDB 迁移完成后，ClickHouse 和 ZooKeeper 会被缩容。如果成本是考虑因素，可以关闭 ClickHouse。这会降低月度成本，但会降低可靠性，因为不再有 ClickHouse fallback。
    </Warning>

    | 项目 | 粗略月度估算 | 备注 |
    | --- | --- | --- |
    | RDS PostgreSQL | \$100–\$150 | `db.t4g.medium`，Multi-AZ，50 GB 初始存储。 |
    | ElastiCache Redis | \$140–\$280 | 下限为不启用 read replicas 的情况。上限为启用 read replicas 的情况。 |
    | EKS control plane | ~\$75 | 一个 EKS 集群，按标准小时费率计费。 |
    | System node group | ~\$210 | 3 个 `m6i.large` on-demand 节点。 |
    | Application、ClickHouse 和 ZooKeeper worker 节点 | \$650 | 缩容后的 ClickHouse 成本。 |
    | EBS 卷 | \$200–\$350 | ClickHouse、ZooKeeper、节点卷，以及 gp3 性能设置。这些卷缩小后会降低。 |
    | 网络 | \$150–\$300 | NAT gateways、load balancer、PrivateLink 或 VPC endpoints，以及低流量数据处理。 |
    | S3、Secrets Manager、CloudWatch | \$50–\$200 | 低流量基线。随 trace payload、日志和保留策略增长。 |
    | SmithDB 计算 | \$1,550 | 2 x `m7gd.4xlarge`，分布在两个可用区，每个节点另有一个 100 GiB gp3 启动卷。 |
    | SmithDB metastore | \$210 | Aurora PostgreSQL 18 Serverless v2，writer 和 reader，最低 1 ACU，50 GB。 |
    | SmithDB bucket | \$5–\$120 | S3 存储成本，主要取决于 trace payload 大小和保留策略。 |

    预计月度总计：**\$3,340–\$4,095**

    ### SmithDB 对象存储定价

    | 每 trace 存储大小 | 14 天保留 | 400 天保留 |
    | --- | --- | --- |
    | 10 KB | \$2 每年 | \$74 每年 |
    | 50 KB | \$15 每年 | \$368 每年 |
    | 200 KB | \$52 每年 | \$1,472 每年 |

    一次 [ClickHouse backfill](/langsmith/self-host-smithdb-migrate) 需要为迁移任务额外使用一个 `m7gd.4xlarge`，约为每天 **\$24**。Backfill 完成后该成本即停止（任务会在几天内完成，取决于 tracing 量）。

    SmithDB 基础设施的细节请参阅 [Prepare SmithDB supporting infrastructure](/langsmith/self-host-smithdb-infrastructure)。
