自带 IAM（BYOIAM）让你可以创建和管理 LangSmith BYOC data plane 所使用的 AWS IAM 资源。在 LangChain 使用这些资源预置和运维 data plane 的同时，由你掌控角色、policies 和权限边界。

如果希望由 LangChain 管理 IAM 资源，请遵循标准的 [BYOC 入门指南](/langsmith/byoc-onboarding)。

## 开始之前

完成 [BYOC 前提条件](/langsmith/byoc#prerequisites)，准备一个启用了 BYOC 的 LangSmith 组织。

## 创建 IAM 资源

[`byoiam` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/byoiam) 会创建共享的 data plane 角色、policies 和 Karpenter instance profile。对于使用这些角色的所有 region 和 data plane，在每个 AWS 账户中应用一次即可。

创建 IAM 资源的步骤：

1. 为计划部署 data plane 的账户配置 AWS provider。
2. 将该 module 添加到你的 Terraform 配置中。将 `regions` 设置为角色需要运作的[受支持 AWS regions](/langsmith/byoc#regions-and-cloud-providers)。
3. （可选）将 `permissions_boundary_arn` 设置为你的 IAM permissions boundary policy 的 ARN。该 module 会将它应用到其创建的所有角色上，service-linked roles 除外。
4. 使用 `service_linked_roles_to_create` 创建缺失的 service-linked roles。默认不创建任何角色。省略已存在的角色，或者先将它们导入 Terraform。
5. 初始化 Terraform，检查 plan，然后应用到你的账户。

以下配置为两个 region 创建共享的 IAM 资源：

```hcl
module "byoiam" {
  source = "github.com/langchain-ai/terraform//modules/byoc/aws/byoiam?ref=main"

  regions = ["us-east-1", "us-west-1"]
}
```

### 使用自定义 IAM 名称

默认情况下，该 module 使用 `byoc-smith-` 前缀为其资源命名。如果你的组织强制实施 IAM 命名规范，例如强制前缀，请使用以下输入覆盖名称：

- **`role_names`**：自定义角色名称的 map，以角色用途为键。键与该 module 的 `role_names` 输出一致，例如 `eks-cluster-role` 或 `workload-iam-role`。省略的角色保留其默认名称。
- **`karpenter_instance_profile_name`**：Karpenter 节点 instance profile 的自定义名称。
- **`karpenter_controller_policy_name`**：Karpenter controller policy 的自定义名称。

每个角色名称必须唯一，且最多 64 个字符。

```hcl
module "byoiam" {
  source = "github.com/langchain-ai/terraform//modules/byoc/aws/byoiam?ref=main"

  regions                  = ["us-east-1"]
  permissions_boundary_arn = "arn:aws:iam::<account-id>:policy/<boundary>"
  role_names = {
    eks-cluster-role                  = "ACME-langsmith-eks-cluster"
    eks-node-role                     = "ACME-langsmith-eks-node"
    ebs-csi-role                      = "ACME-langsmith-ebs-csi"
    karpenter-node-role               = "ACME-langsmith-karpenter-node"
    karpenter-controller-role         = "ACME-langsmith-karpenter-controller"
    postgres-monitoring-role          = "ACME-langsmith-postgres-monitoring"
    smithdb-metastore-monitoring-role = "ACME-langsmith-smithdb-metastore-monitoring"
    workload-iam-role                 = "ACME-langsmith-workload"
    postgres-setup-iam-role           = "ACME-langsmith-postgres-setup"
    smithdb-iam-role                  = "ACME-langsmith-smithdb"
    smithdb-setup-iam-role            = "ACME-langsmith-smithdb-setup"
    external-secrets-iam-role         = "ACME-langsmith-external-secrets"
    lbc-role                          = "ACME-langsmith-lbc"
    clickhouse-backup-iam-role        = "ACME-langsmith-clickhouse-backup"
    privatelink-lambda-role           = "ACME-langsmith-privatelink-lambda"
    juicefs-csi-iam-role              = "ACME-langsmith-juicefs-csi"
  }
  karpenter_instance_profile_name  = "ACME-langsmith-karpenter-node"
  karpenter_controller_policy_name = "ACME-langsmith-karpenter-controller"
}
```

保留 `module.byoiam.role_names` 和 `module.byoiam.karpenter_instance_profile_name` 输出。在[创建 data plane](#deploy-the-data-plane-with-existing-roles)时，将它们粘贴到 data plane 表单中。不要将 Karpenter controller policy 名称粘贴到 LangSmith 中。

## 从预置角色中移除 IAM 管理权限

[`langsmith-byoc-role` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role) 会创建 LangChain 用于管理你的 data plane 的跨账户角色。

创建 IAM 资源后，按如下方式配置预置角色：

1. 通过 **Settings > Data Planes** 中 **Data Planes** 标题旁的按钮复制 external ID。将它作为 `external_id` 传递给该角色 module。该角色的信任策略必须在 `ExternalId` 条件中使用此值。
2. 在你的 `langsmith-byoc-role` module 配置中设置 `allow_iam_management_permissions = false`。
3. 将你在[创建 IAM 资源](#create-the-iam-resources)中应用的 `byoiam` module 的输出传递给该角色 module：

   ```hcl
   module "langsmith_byoc_role" {
     # ... other inputs ...

     # Outputs from the byoiam module
     byoiam_role_arns                       = values(module.byoiam.role_arns)
     byoiam_instance_profile_name           = module.byoiam.karpenter_instance_profile_name
     byoiam_karpenter_controller_policy_arn = module.byoiam.karpenter_controller_policy_arn
   }
   ```

4. 检查并应用 Terraform 更改。保留用于 data plane 创建的 `crossplane_role_arn` 输出。

预置角色的默认权限仅匹配默认的 `byoc-smith-` 名称。使用[自定义 IAM 名称](#use-custom-iam-names)时，这些输入是必需的。它们授予对这些确切 ARN 的读取和 `iam:PassRole` 访问权限。使用默认名称时，这些输入是冗余的，但不会造成影响。

设置 `allow_iam_management_permissions = false` 会改变该角色的权限：

- **移除**：IAM 创建、修改和删除权限，包括 service-linked role 的创建。
- **保留**：IAM 读取权限，以及限定范围的 `iam:PassRole` 和 `iam:SimulatePrincipalPolicy`，用于使用和验证你现有的资源。

启用 `allow_delete_permissions` 不会恢复 IAM 管理权限。

如果还想[自带 VPC](/langsmith/byoc-byovpc)，请设置 `allow_vpc_creation_permissions = false`，并在 `vpc_ids` 中提供 VPC ID。

## 使用现有角色部署 data plane

<Warning>
必须使用 [`byoiam` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/byoiam) 创建 LangSmith 所需的确切 IAM 角色。LangSmith 在部署 data plane 之前会对这些 IAM 资源进行大量验证。
</Warning>

**Use existing IAM roles** 复选框会将 data plane 配置为使用你创建的 IAM 资源。

部署 data plane 的步骤：

1. 前往 **Settings > Data Planes** 并创建一个 data plane。
2. 提供 [BYOC 入门](/langsmith/byoc-onboarding)中所述的名称、AWS region、网络配置和 load balancer 访问方式。选择一个包含在该 module 的 `regions` 输入中的 region。
3. 将预置角色的 `crossplane_role_arn` 输出用于 **AWS IAM role ARN**。
4. 选择 **Use existing IAM roles**。
5. 如果你设置了[自定义 IAM 名称](#use-custom-iam-names)，请将 `module.byoiam.role_names` 和 `module.byoiam.karpenter_instance_profile_name` 的值粘贴到 data plane 表单中。
6. 提交请求。
