Hybrid 是 [LangSmith Deployment](/langsmith/deployment) 的一种平台部署方式，它用于**在生产环境中部署并运行 agents**。

在 hybrid 平台部署中，你会在自己的基础设施中自托管 [Agent Servers](/langsmith/agent-server)，并将它们的 traces 发送到 LangSmith，而这个 LangSmith 可以是[self-hosted](/langsmith/self-hosted) 实例，也可以是 [LangSmith Cloud](/langsmith/cloud)。

这种方式让你能够控制 agent workloads 运行的位置，同时还能根据可观测性和合规性需求，选择最适合你的 [LangSmith platform option](/langsmith/platform-setup)。

## Components

| Component | Where it runs | Who manages it |
|-----------|---------------|----------------|
| <Tooltip tip="运行你应用的服务器。">Agent Servers</Tooltip> <br></br>for [LangSmith Deployment](/langsmith/deployment) | 你的基础设施 | 你 |
| LangSmith <br></br>（tracing、evaluation、prompts） | 你自己的基础设施中的 self-hosted 实例，或 LangSmith SaaS | 你（self-hosted）或 LangSmith（SaaS） |

<Note>
Hybrid 是 LangSmith Deployment（agent serving）的一种平台部署方式。如果你只想为 observability、evaluation 和 prompt engineering 配置 LangSmith，请参阅 [Set up LangSmith](/langsmith/platform-setup)。
</Note>

## Workflow

1. 在本地构建并测试你的 agent。
1. 将 agent 部署到[运行在你自己基础设施中的 Agent Server](#self-host-your-agent-servers)。
1. 将 agent 的 traces 发送到[LangSmith（self-hosted 或 SaaS）以进行 observability 和 evaluation](#choose-where-traces-are-sent)。

### Self-host your Agent Servers

使用 Docker、Docker Compose 或 Kubernetes 部署独立 Agent Servers。关于前置条件、环境变量以及各平台说明，请参阅 [standalone server guide](/langsmith/deploy-standalone-server)。

### Choose where traces are sent

Agent Servers 会依据 `LANGSMITH_ENDPOINT` 环境变量将 traces 发送到 LangSmith：

- **LangSmith SaaS**：省略 `LANGSMITH_ENDPOINT` 即使用默认值（GCP US），或者将其设置为你所在区域的 endpoint：

    <SaasRegionUrls />

- **Self-hosted LangSmith**：将 `LANGSMITH_ENDPOINT` 设置为你的[self-hosted LangSmith](/langsmith/self-hosted)实例的主机名。

无论哪种情况，都请使用目标 LangSmith 实例签发的 [LangSmith API key](/langsmith/create-account-api-key) 完成认证。
