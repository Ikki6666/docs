Direct model access 通过 provider 专属的 gateway path 暴露每个 provider API。gateway 仍然处理认证、provider secrets、策略和 tracing，但不会把请求和响应转换为另一个 provider 的 API 格式。

Direct model access 是 [LangChain 和 Deep Agents](#配置-langchain-和-deep-agents) 默认使用的路径。对于其他 client，当你需要 provider 原生的请求和响应行为时可以使用它。要使用一种 API 格式跨 providers 调用模型，请改用[标准 endpoint](/langsmith/llm-gateway-api-formats)。

## 选择 provider path

把 provider path 附加到你的[区域 gateway](/langsmith/llm-gateway-how-it-works#use-a-regional-gateway) base URL 上，例如在 GCP EU 中直接访问 Anthropic 使用 `https://eu.gateway.smith.langchain.com/anthropic`：

| Provider | Gateway path |
| --- | --- |
| Anthropic | `/anthropic` |
| AWS Bedrock | `/bedrock` |
| Azure Foundry | `/azure` |
| Baseten | `/baseten` |
| Fireworks | `/fireworks` |
| Google Gemini | `/gemini` |
| Gemini Enterprise Agent Platform (Vertex AI) | `/vertex` |
| OpenAI | `/openai` |
| ScaleDown | `/scaledown` |
| TypeSafe | `/typesafe` |
| xAI | `/xai` |

每个 path 都会使用调用者工作区中存储的 provider key。secret 名称请参见 [Provider authentication](/langsmith/llm-gateway-provider-authentication#add-a-provider-key)。

[Gateway Credits 模型](/langsmith/llm-gateway-credits)使用标准 endpoint 而不是 provider 专属 path。这些托管模型不需要你自己的 provider secret。

## 配置 provider SDK

把每个 provider SDK 的 base URL 设置为它对应的 direct gateway path，并使用你的 LangSmith API key 作为 provider API key：

```bash
export LANGSMITH_API_KEY="lsv2_..._....cbed3e"
export BASE_URL="https://gateway.smith.langchain.com"

export ANTHROPIC_BASE_URL="$BASE_URL/anthropic"
export OPENAI_BASE_URL="$BASE_URL/openai/v1"
export GOOGLE_GEMINI_BASE_URL="$BASE_URL/gemini"

export ANTHROPIC_API_KEY="$LANGSMITH_API_KEY"
export OPENAI_API_KEY="$LANGSMITH_API_KEY"
export GEMINI_API_KEY="$LANGSMITH_API_KEY"
export GOOGLE_API_KEY="$LANGSMITH_API_KEY"
```

gateway 会从 provider secrets 中解析出实际的 provider key，因此 provider key 不需要保存在本地。

<CodeGroup>

```python OpenAI SDK
import os

from openai import OpenAI

client = OpenAI(
    base_url=os.environ["OPENAI_BASE_URL"],
    api_key=os.environ["LANGSMITH_API_KEY"],
)
response = client.chat.completions.create(
    model="gpt-5.4-mini",
    messages=[{"role": "user", "content": "ping"}],
)
print(response.choices[0].message.content)
```

```python Anthropic SDK
import os

import anthropic

client = anthropic.Anthropic(
    base_url=os.environ["ANTHROPIC_BASE_URL"],
    api_key=os.environ["LANGSMITH_API_KEY"],
)
message = client.messages.create(
    model="claude-opus-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "ping"}],
)
print(message.content[0].text)
```

</CodeGroup>

Direct path 使用 provider 的原生模型名称，不带 provider 前缀。

## 创建 embeddings

gateway 会通过各 provider 的直接路径把 embeddings 请求路由到 OpenAI、Azure Foundry 和 Gemini Enterprise Agent Platform。使用这些路径，可以像其他 gateway 请求一样，借助相同的工作区凭证、策略和 tracing 生成向量。[标准 endpoint](/langsmith/llm-gateway-api-formats) 不接受 embeddings 请求。

在发送请求之前，先配置 provider 的[工作区凭证](/langsmith/llm-gateway-provider-authentication#add-a-provider-key)。请使用你的 LangSmith API key 向 gateway 进行认证，而不是 provider key。示例使用美国 Cloud 主机名。如需使用其他区域，请将其替换为你的[区域 gateway](/langsmith/llm-gateway-how-it-works#use-a-regional-gateway)主机名。

| Provider | Embeddings endpoint | 请求格式 |
| --- | --- | --- |
| OpenAI | `POST /openai/v1/embeddings` | `model` 和 `input`。 |
| Azure Foundry | `POST /azure/v1/embeddings` | `model`（deployment 名称）和 `input`。 |
| Gemini Enterprise Agent Platform | `POST /vertex/v1/publishers/google/models/{model}:embedContent` | `content.parts`。 |
| Gemini Enterprise Agent Platform | `POST /vertex/v1/publishers/google/models/{model}:batchEmbedContents` | `requests`，每个请求包含 `content.parts`。 |
| Gemini Enterprise Agent Platform | `POST /vertex/v1/publishers/google/models/{model}:predict` | `instances`，每个实例包含 `content`。仅支持 `gemini-embedding-*` 模型。 |

### 调用 OpenAI 或 Azure Foundry

对于 OpenAI，请把 `model` 设置为不带 `openai/` 前缀的 embedding 模型 ID。对于 Azure Foundry，请使用[已配置的 Foundry 资源](/langsmith/llm-gateway-provider-authentication#configure-azure-foundry)上的 deployment 名称，而不是底层模型 ID。

<CodeGroup>

```bash OpenAI
curl https://gateway.smith.langchain.com/openai/v1/embeddings \
  --header "Authorization: Bearer $LANGSMITH_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "text-embedding-3-small",
    "input": "The quick brown fox"
  }'
```

```bash Azure Foundry
curl https://gateway.smith.langchain.com/azure/v1/embeddings \
  --header "Authorization: Bearer $LANGSMITH_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "<deployment-name>",
    "input": "The quick brown fox"
  }'
```

</CodeGroup>

两个 endpoint 都返回 provider 的 OpenAI 格式 embeddings 响应，向量位于 `data[].embedding`。

### 调用 Gemini Enterprise Agent Platform

Gemini Enterprise Agent Platform 使用 Google 原生的请求和响应格式。

表中的短路径使用你的 [Gemini Enterprise Agent Platform 凭证和工作区 secrets](/langsmith/llm-gateway-provider-authentication#configure-gemini-enterprise-agent-platform) 中的 project 和 location。你也可以在路径中指定它们：`/vertex/v1/projects/{project}/locations/{location}/publishers/google/models/{model}:{action}`。gateway 在 `v1beta` 和 `v1beta1` 下也接受相同的路径形式。

<CodeGroup>

```bash Single embedding
curl https://gateway.smith.langchain.com/vertex/v1/publishers/google/models/gemini-embedding-2:embedContent \
  --header "Authorization: Bearer $LANGSMITH_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "content": {"parts": [{"text": "The quick brown fox"}]}
  }'
```

```bash Batch embeddings
curl https://gateway.smith.langchain.com/vertex/v1/publishers/google/models/gemini-embedding-2:batchEmbedContents \
  --header "Authorization: Bearer $LANGSMITH_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "requests": [
      {"content": {"parts": [{"text": "Name 5 colors"}]}},
      {"content": {"parts": [{"text": "Name 5 animals"}]}}
    ]
  }'
```

```bash Predict embeddings
curl "https://gateway.smith.langchain.com/vertex/v1/projects/<project-id>/locations/us-central1/publishers/google/models/gemini-embedding-001:predict" \
  --header "Authorization: Bearer $LANGSMITH_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "instances": [{"content": "The quick brown fox"}]
  }'
```

</CodeGroup>

将 `:predict` 示例中的 `<project-id>` 替换为你的 Google Cloud project ID。选择一个模型可用的 location。`:predict` 路由只接受以 `gemini-embedding-` 开头的模型 ID。其他模型（包括 `text-embedding-*`、`text-multilingual-embedding-*` 和 `multimodalembedding@001`）会返回 `501`。

从 `embedContent` 的 `embedding.values`、`batchEmbedContents` 的 `embeddings[].values`，以及 `predict` 的 `predictions[].embeddings.values` 中读取向量。

### 使用 LangChain embeddings

使用直接 gateway base URL 和你的 LangSmith API key 显式配置 [OpenAIEmbeddings](/oss/integrations/embeddings/openai)：

```python
import os

from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small",
    base_url="https://gateway.smith.langchain.com/openai/v1",
    api_key=os.environ["LANGSMITH_API_KEY"],
)
vector = embeddings.embed_query("The quick brown fox")
```

下一节中用于 chat models 的 `LANGSMITH_GATEWAY` 设置不能替代配置 embeddings client 的 base URL。

### 跟踪用量并应用策略

Embeddings 请求会经过 gateway 策略，并作为 LLM runs 出现在 [gateway traces](/langsmith/llm-gateway-traces) 中。Token 用量来自 provider 响应。Embeddings 请求不使用 [fallback 链](/langsmith/llm-gateway-fallbacks)。

如果模型没有匹配的价格条目，请[添加模型价格](/langsmith/cost-tracking#create-a-new-or-modify-an-existing-model-price-entry)以跟踪 embedding 成本。

## 配置 LangChain 和 Deep Agents

[LangChain](/oss/langchain/overview) chat models 和 [Deep Agents](/oss/deepagents/overview)（包括 [Deep Agents Code](/oss/deepagents/code/overview)）通过 `LANGSMITH_GATEWAY` 环境变量访问这些 provider paths：

```bash
export LANGSMITH_API_KEY="lsv2_..."
export LANGSMITH_GATEWAY="true"
```

Deep Agents Code 还需要 `LANGSMITH_GATEWAY_API_KEY`。请把它设置为同一个 key：

```bash
export LANGSMITH_GATEWAY_API_KEY="$LANGSMITH_API_KEY"
```

<Note>
`LANGSMITH_GATEWAY` 支持需要以下最低 Python 包版本：`langchain-anthropic>=1.5.1`、`langchain-baseten>=0.2.3`、`langchain-fireworks>=1.5.1`、`langchain-google-genai>=4.3.2` 和 `langchain-openai>=1.4.1`。
</Note>

每个受支持的集成都会附加自己的 provider path，因此 `ChatAnthropic` 调用 `https://gateway.smith.langchain.com/anthropic`，`ChatOpenAI` 调用 `https://gateway.smith.langchain.com/openai/v1`。要改为通过标准 endpoint 路由请求，请参见[发送第一个 LLM Gateway 请求](/langsmith/llm-gateway-first-request#send-a-request-from-your-code)。
