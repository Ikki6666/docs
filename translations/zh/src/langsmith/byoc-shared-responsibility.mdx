BYOC 共享责任模型定义了在 LangSmith BYOC 部署中，哪些由 LangChain 管理、哪些由你的组织管理。在该模型下，正常运行期间敏感数据不会经过 LangChain 基础设施。以下小节介绍这一责任划分如何覆盖平台与基础设施、数据与安全，以及运维与支持。

<Tip>
多租户 SaaS 的对应说明请参阅 [LangSmith 共享责任模型](/langsmith/shared-responsibility-model)。Control plane 与 data plane 的技术结构请参阅 [AWS](/langsmith/byoc-architecture-aws)、[GCP](/langsmith/byoc-architecture-gcp) 或 [Azure](/langsmith/byoc-architecture-azure) 上的 BYOC 架构。
</Tip>

## 访问模型

- **Control plane 与 data plane 分离**：LangChain 运行 control plane。你拥有包含 data plane 的云环境，LangChain 通过委托访问管理该环境内的基础设施。
- **访问遵循最小权限原则，break-glass（紧急访问）是例外**：LangChain 持有的常规访问仅限于预置和运维。正常运行不需要数据访问。事件排查可能需要经客户批准的 break-glass 访问，通过共享支持渠道授予。
- **你始终对自己的云账户负责**：你控制自己的云账户或订阅治理、网络连接和内部访问策略。

有关 LangChain 在各个云上持有的具体访问权限，请参阅 [AWS 上的跨账户 IAM 权限](/langsmith/byoc-architecture-aws#cross-account-iam-permissions)、[GCP 上的访问和权限](/langsmith/byoc-architecture-gcp#access-and-permissions)，以及 [Azure 上的访问和权限](/langsmith/byoc-architecture-azure#access-and-permissions)。

## 平台与基础设施

| 领域 | LangChain 职责 | 你的职责 |
| :---- | :---- | :---- |
| **服务范围与架构** | <ul><li>定义 BYOC 架构</li><li>运维 control plane，涵盖组织配置、身份验证、计费元数据和前端资源</li></ul> | <ul><li>获得你的安全、基础设施和应用团队的批准</li><li>确认 BYOC 架构满足你的要求</li></ul> |
| **云账户所有权** | <ul><li>仅通过客户委托的 role 和范围内的权限进行操作</li></ul> | <ul><li>拥有并管理你的云账户或订阅和预算</li><li>拥有账户护栏（例如 AWS 上的 service control policies）</li><li>拥有组织结构和账户生命周期</li></ul> |
| **预置与变更** | <ul><li>预置运行 LangSmith data plane 的 BYOC 基础设施和 Kubernetes 资源</li><li>管理由 BYOC 管理的组件的更新和发布</li><li>通过共享支持渠道确认并安排变更请求</li></ul> | <ul><li>批准入门步骤并提供所需的账户和 region 信息</li><li>避免手动编辑由 BYOC 管理的资源</li><li>通过共享支持渠道请求变更</li></ul> |
| **网络** | <ul><li>为受支持的连接模型（例如 AWS PrivateLink、GCP Private Service Connect 或 Azure Private Link）配置 LangSmith 组件</li><li>预置并运维 data plane 负载均衡器及其背后的所有组件</li><li>传达所需的 endpoint 和限制</li></ul> | <ul><li>拥有你的用户和应用访问 LangSmith BYOC data plane 所需的内部连接</li><li>对于面向互联网的负载均衡器，拥有其前方的边缘控制措施，例如 web 应用防火墙（WAF）或内容分发网络（CDN）</li></ul> |
| **负载均衡器** | <ul><li>预置你在创建 data plane 时选择的负载均衡器，可以是私有或面向互联网的。在 AWS 上，默认是 Network Load Balancer（NLB），也可以是 Application Load Balancer（ALB）。创建后无法更改类型。</li><li>运维监听器和 TLS 证书，在 AWS 上还包括[源 IP 允许列表](/langsmith/byoc-operations-aws#ingress-allowlist)</li><li>保留 ALB 上的 AWS WAF web ACL 和 AWS Shield Advanced 关联</li></ul> | <ul><li>在创建 data plane 时选择 ALB 以使用 AWS WAF，因为 WAF 无法关联到 NLB</li><li>创建 web ACL，将其关联到 ALB，并管理其规则，包括误报和请求正文检查限制</li><li>启用 AWS Shield Advanced，并拥有 ALB 前方的任何 CDN 或 Amazon CloudFront 分发</li><li>通过 [VPC peering、transit gateway 或 VPN](/langsmith/byoc-operations-aws#connect-with-vpc-peering-a-transit-gateway-or-a-vpn) 私有访问 ALB data plane，因为 ALB 不支持 [AWS PrivateLink](/langsmith/byoc-operations-aws#connect-with-aws-privatelink)</li><li>在创建时选择私有或面向互联网。对于 ALB，之后无法更改，因为更改会替换 ALB 并移除你的 web ACL 关联。</li></ul> |
| **Control plane** | <ul><li>运维身份验证、组织配置和 API key 管理</li><li>提供静态前端资源，并运维使用量与计费界面</li></ul> | <ul><li>管理组织级 admin，并治理谁可以创建和管理 data plane 与 workspace</li></ul> |
| **Data plane 服务** | <ul><li>运维摄取和查询 traces、prompts、datasets、评估、insights 和 deployments 的服务</li><li>通过监控、扩缩容和升级保持这些服务健康</li></ul> | <ul><li>不要在 BYOC 集群或私有网络中共同部署无关的工作负载</li><li>在你的环境中验证应用行为</li></ul> |
| **扩缩容与容量** | <ul><li>监控并扩缩由 BYOC 管理的服务</li><li>在可能的情况下，在重大扩缩事件之前提前通知，并说明预期的成本影响</li></ul> | <ul><li>确保云服务配额足以支撑已部署的服务，并按需申请提升</li><li>接受你云账户中的成本影响</li><li>定义内部成本护栏和告警</li></ul> |
| **升级与修补** | <ul><li>向由 BYOC 管理的组件发布升级和补丁</li><li>就重大变更和维护窗口进行协调</li></ul> | <ul><li>在内部规划变更管理，包括干系人沟通和 staging 验证</li><li>遵循你自己的变更控制流程</li></ul> |

有关升级、自动扩缩容和维护窗口如何运作的详细信息，请参阅 [AWS](/langsmith/byoc-operations-aws) 或 [Azure](/langsmith/byoc-operations-azure) 上的 BYOC 运维。在 GCP 上，请参阅 [GKE 与计算](/langsmith/byoc-architecture-gcp#gke-and-compute) 和 [更改 data plane 设置](/langsmith/byoc-onboarding-gcp#change-data-plane-settings)。

<Note>
在 AWS 上使用 [BYOVPC](/langsmith/byoc-byovpc-aws) 时，你还需要创建并维护：
- VPC
- 子网
- 路由
- 网关
- 客户侧 VPC endpoints
- flow logs
- 出站控制（egress controls）

LangChain 会在预置之前验证所提供的网络，并管理其中的工作负载基础设施。客户管理的网络资源在运行期间以及 data plane 删除之后仍由你负责。
</Note>

## 数据与安全

| 领域 | LangChain 职责 | 你的职责 |
| :---- | :---- | :---- |
| **客户数据** | <ul><li>设计系统，使正常运行期间敏感数据不会经过 LangChain 基础设施</li><li>正常运行期间避免访问客户数据</li></ul> | <ul><li>拥有 data plane 中的数据，包括分类、保留和访问控制</li><li>承担该数据的法律与合规义务</li><li>在内部批准任何数据导出或共享</li></ul> |
| **数据驻留** | <ul><li>仅在你指定的云 region 内预置所有 data plane 组件和存储</li><li>正常运行期间将客户数据保留在 LangChain 管理的基础设施之外</li></ul> | <ul><li>在入门时指定所需的云 region</li><li>提前告知数据驻留要求的任何变更</li></ul> |
| **Secrets 管理** | <ul><li>使用客户账户中的 secret store 存放运行时 secrets</li><li>引用 secrets，而不在 control plane 中持久化敏感值</li></ul> | <ul><li>应用任何组织特定的密钥管理要求</li></ul> |
| **Break-glass 访问** | <ul><li>仅在事件缓解时使用 break-glass 访问，且需客户批准并有明确的流程</li><li>尽量缩短该访问的持续时间和范围</li><li>尽可能提前通知</li><li>提供涵盖时间戳、所执行操作和所访问数据的访问后摘要</li></ul> | <ul><li>在需要时批准 break-glass 访问</li><li>定义内部审批工作流</li><li>查看事件后的访问日志和记录</li></ul> |
| **访问审计日志** | <ul><li>在 AWS 上，在你的账户中预置日志基础设施，使 LangChain 的访问被记录下来，包括 EKS 审计日志</li><li>不会代表你查看、分析这些日志或对其设置告警</li></ul> | <ul><li>保留云服务商记录的 LangChain 活动账户级日志，例如针对 LangChain 所 assume 的 role 的 AWS CloudTrail，或 Azure Activity Log</li><li>在 Azure 上，配置诊断设置和 flow logs 以收集资源和网络日志，LangSmith 不会配置这些内容</li><li>查看并分析这些日志，并对其设置自己的告警</li><li>通过共享支持渠道将异常情况上报给 LangChain</li></ul> |
| **安全事件通知** | <ul><li>在 LangChain 拥有的基础设施中发生影响你部署的已确认安全事件时通知你，涵盖 control plane、公司系统和 BYOC 构建与发布流水线</li><li>分享事件范围、影响评估和修复步骤</li><li>配合开展联合取证</li><li>不会在你的云账户内运行安全监控</li></ul> | <ul><li>在你的账户中为 BYOC 组件部署并运行安全监控，例如 EDR、IDS、容器安全、云安全态势管理和日志聚合</li><li>确保这些监控不影响由 BYOC 管理资源的运行</li><li>指定安全联系人并定义内部事件响应流程</li><li>发现客户侧凭证或访问疑似泄露时立即通知 LangChain</li></ul> |
| **合规与审计** | <ul><li>提供关于 BYOC 架构和运维模式的文档</li><li>提供由 LangChain 运维控制的审计证据，包括访问日志、变更历史、安全政策和渗透测试摘要</li><li>支持 SOC 2、ISO 27001 及等效的审计项目</li></ul> | <ul><li>对你的云环境和所有客户管理的控制的合规态势负责</li><li>为该环境运行或协调审计与证据收集</li></ul> |

有关在各云上界定 LangChain 访问范围的权限，请参阅[访问模型](#access-model)。有关 break-glass 访问在 AWS 上的运作方式，请参阅 [Break-glass 访问](/langsmith/byoc-operations-aws#break-glass-access)。有关审计日志的位置和访问方式，请参阅 [AWS](/langsmith/byoc-operations-aws#auditing) 或 [Azure](/langsmith/byoc-operations-azure#auditing) 上的审计。

## 运维与支持

| 领域 | LangChain 职责 | 你的职责 |
| :---- | :---- | :---- |
| **可观测性** | <ul><li>为 BYOC 管理的组件提供并运维服务级监控和告警</li><li>在诊断需要时请求客户提供信号</li></ul> | <ul><li>从你自己的系统提供所需的日志、指标和时间戳</li><li>在故障排查需要时，从你的网络层提供同样的信息</li></ul> |
| **事件响应与支持** | <ul><li>担任由 LangChain 管理组件的主要响应方，涵盖 control plane 和由 BYOC 管理的 data plane 服务</li><li>通过共享支持渠道协调沟通</li></ul> | <ul><li>担任客户自有层面的主要响应方，包括云政策、内部网络和访问控制</li><li>为调查及时提供访问权限和批准</li></ul> |
| **备份与灾难恢复** | <ul><li>为 LangChain 管理的 data plane 组件定义并运行备份流程</li><li>按单 region 内跨多个可用区的高可用性预置 data plane</li></ul> | <ul><li>定义你的内部恢复目标，并与 LangChain 团队一起验证</li><li>为 BYOC 范围之外的任何客户管理数据存储负责备份</li></ul> |
| **维护窗口与变更冻结** | <ul><li>在约定的维护窗口内执行基础设施维护和升级</li><li>只有在为保持 data plane 正常运行而必须进行变更时（例如负载增加）才在该窗口之外行动</li><li>在合理的提前通知下，配合敏感业务时期所请求的变更冻结</li></ul> | <ul><li>在 LangSmith UI 中设置 AWS 维护窗口，或对 GCP 和 Azure 使用 API</li><li>在合理的提前通知下，告知即将到来的变更冻结（例如财年结账或重大发布）</li></ul> |
| **退出与终止** | <ul><li>在合同终止后约定的时限内移除所有 LangChain 管理的资源、IAM role 和委托访问</li><li>提供取消预置已完成的书面确认</li></ul> | <ul><li>通过共享支持渠道启动退出流程</li><li>在确认后验证资源和访问权限的清理</li><li>撤销与 BYOC 关联的客户管理 role 和访问授权</li></ul> |
