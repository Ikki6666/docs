LangSmith 支持通过用户名/密码登录，但有以下限制：

* 不能将现有安装从 basic auth 模式切换为带 PKCE 的 OAuth，已弃用，或反过来切换。安装必须二选一。**基础身份验证安装需要一次全新的安装，包括独立的 PostgreSQL 数据库或 schema，除非你是从现有的 `None` 类型安装迁移，见下文。**
* 用户在被邀请后，必须先拿到系统自动生成的初始密码。之后，任何 Organization Admin 都可以修改该密码。
* 不能同时使用 basic auth 和带 client secret 的 OAuth。

## 要求与特性

* 初始安装时会预置一个名为 `Default` 的组织，不支持创建额外组织
* 你下面配置的初始密码长度必须至少为 12 个字符，并且至少包含一个小写字母、一个大写字母和一个符号
* 用于签发 JWT 的 secret 没有严格格式要求，但建议安全地生成一个至少 32 个字符的字符串。例如：`openssl rand -base64 32`

### 从 none auth 迁移

**仅在 0.7 及以上版本中受支持。**

将安装从 [None](/langsmith/authentication-methods#none) auth 模式迁移过来时，系统会用配置中的凭证替换原本唯一的 `"default"` 用户，同时保留所有现有资源。迁移后，唯一已存在 workspace 的 ID 仍然是 `00000000-0000-0000-0000-000000000000`，但除此之外，迁移后的安装与标准基础身份验证安装没有区别。

要迁移，只需按下方方式更新配置，然后照常运行 `helm upgrade`。

### 配置

<Note>
更改 JWT secret 会让所有用户退出登录
</Note>

```yaml Helm
config:
  authType: mixed
  basicAuth:
    enabled: true
    initialOrgAdminEmail: <YOUR EMAIL ADDRESS>
    initialOrgAdminPassword: <PASSWORD> # Must be at least 12 characters long and have at least one lowercase, uppercase, and symbol
    jwtSecret: <SECRET>
```

配置完成后，你会看到如下登录界面。此时应能使用 `initialOrgAdminEmail` 和 `initialOrgAdminPassword` 的值登录，并且该用户会被自动预置为 `Organization Admin` 角色。关于组织角色的更多细节，请参阅[管理员指南](/langsmith/administration-overview#organization-roles)。
