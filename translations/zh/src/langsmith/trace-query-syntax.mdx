[LangSmith SDK](https://reference.langchain.com/python/langsmith/) 和 [REST API](/langsmith/smith-api-ref) 允许你通过一组过滤参数和结构化过滤查询语言，以编程方式对 [runs](/langsmith/observability-concepts#runs) 进行过滤、查询和导出。本页说明这些过滤参数和查询语言，并提供常见查询示例。

如需查看将这些过滤器与 SDK 组合使用的可运行端到端示例，请参阅[使用 SDK 查询 traces](/langsmith/export-traces)。

## 过滤参数

| Keys                          | Description |
| ----------------------------- | ----------- |
| `project_id` / `project_name` | 从指定 project 获取 runs，可传单个 project 或 project 列表。 |
| `trace_id`                    | 获取属于某个特定 trace 的 runs。 |
| `run_type`                    | 获取指定[run 类型](/langsmith/run-data-format#run-types)的 runs，例如 `llm`、`chain`、`tool`、`retriever`。 |
| `dataset_name` / `dataset_id` | 获取与指定 dataset 中示例行相关联的 runs。这对于在某个 dataset 上比较 prompts 或 models 很有用。 |
| `reference_example_id`        | 获取与某个特定示例行相关联的 runs。这对于在某个给定输入上比较 prompts 或 models 很有用。 |
| `parent_run_id`               | 获取某个给定 run 的子 runs。这对于获取使用 context manager 组织在一起的 runs，或获取某个 agent 轨迹时很有用。 |
| `error`                       | 获取发生错误或未发生错误的 runs。 |
| `run_ids`                     | 获取给定 run id 列表对应的 runs。注意：**这会忽略所有其他过滤参数。** |
| `filter`                      | 获取匹配指定结构化过滤语句的 runs。更多细节请参阅下方的[过滤查询语言](#filter-query-language)部分。 |
| `trace_filter`                | 应用于 trace 根 run 的过滤器。可与 `filter` 配合使用，以根 run 的属性进一步收窄结果。 |
| `tree_filter`                 | 应用于 trace 树中任意 run，根、同级或子级，的过滤器。可与 `filter` 配合使用，以任意 run 的属性进一步收窄结果。 |
| `is_root`                     | 仅返回根 runs。 |
| `select`                      | 选择响应中返回的字段。默认会返回所有字段。可用字段请参阅 [run data format](/langsmith/run-data-format)。 |
| `query`，_experimental_       | 自然语言查询，会将你的查询翻译为一个过滤语句。 |

<Note>
**性能提示：** 传入 `select` 参数，并从返回字段中排除 `inputs` 和 `outputs`，通常可以显著提升查询性能并减少响应大小，尤其是对大型 runs 来说。
</Note>

## 过滤查询语言

LangSmith 支持一种过滤查询语言，可在获取 runs 时执行复杂过滤操作。这在你通过 SDK 或 API 以编程方式查询 traces 时尤其有用，例如在 [evaluation](/langsmith/evaluation) pipelines、监控脚本，或检查先前 [traces](/langsmith/observability-concepts#traces) 的 agentic workflows 中。

### 比较器

过滤语法基于作用于 run 对象字段的比较函数：

| Comparator | Description | Example |
| ---------- | ----------- | ------- |
| `eq`       | 等于 | `eq(run_type, "llm")` |
| `neq`      | 不等于 | `neq(status, "error")` |
| `gt`       | 大于 | `gt(latency, "5s")` |
| `gte`      | 大于等于 | `gte(latency, 1.5)` |
| `lt`       | 小于 | `lt(start_time, "2024-01-01T00:00:00Z")` |
| `lte`      | 小于等于 | `lte(feedback_score, 0.5)` |
| `like`     | 模式匹配；`%` 匹配任意字符序列 | `like(metadata_value, "%prod%")` |
| `notlike`  | `like` 的取反 | `notlike(metadata_value, "%staging%")` |
| `has`      | 检查 run 是否包含某个 tag 或 metadata 键值 | `has(tags, "production")` |
| `search`   | 在所有字符串字段中搜索某个子串 | `search("invoice")` |
| `in`       | 检查字段值是否位于一个列表中 | `in(metadata_key, ["session_id", "thread_id"])` |

### 通配符模式匹配

`like` 和 `notlike` 将字段值与一个模式进行匹配。模式如何应用取决于具体字段：

- **`name`、`metadata_key` 和 `metadata_value`**：`%` 匹配任意字符序列，包括空序列。匹配区分大小写。不带 `%` 时，`like` 只匹配完全相等的值，与 `eq` 相同。
- **`inputs`、`outputs` 和 `error`**：匹配不区分大小写，且始终按子串匹配，因此 `%` 是可选的。LangSmith 可能会将模式中的每个单词单独匹配，而不是作为一个短语整体匹配，因此不要依赖 `like` 在这些字段中匹配精确短语。

例如：

- `like(metadata_value, "%prod%")` 匹配任何包含 `prod` 的值，例如 `production` 或 `eu-prod-1`。
- `notlike(metadata_value, "%staging%")` 匹配任何不包含 `staging` 的值。

在 UI 过滤器构建器中，**contains** 和 **does not contain** 运算符会生成 `like` 和 `notlike` 过滤器。要将搜索栏查询翻译为这种语言，请参阅 [UI 到 API 运算符映射](#ui-to-api-operator-map)。

### 逻辑运算符

使用 `and` 和 `or` 来组合多个比较器：

```text
and(eq(run_type, "llm"), gt(latency, "2s"))
or(eq(status, "error"), and(eq(feedback_key, "score"), lt(feedback_score, 0.5)))
```

### 可过滤字段

| Field             | Type | Notes |
| ----------------- | ---- | ----- |
| `id`              | string，UUID | Run ID |
| `name`            | string | Run 名称 |
| `run_type`        | string | `llm`、`chain`、`tool`、`retriever`、`embedding`、`prompt`、`parser` 之一 |
| `status`          | string | `"success"`、`"error"` 或 `"pending"`。可用来过滤出错或成功的 runs。 |
| `start_time`      | ISO 8601 string | 例如 `"2024-01-15T00:00:00Z"` |
| `end_time`        | ISO 8601 string | |
| `latency`         | duration string or number | 秒，例如 `"5s"`、`"1.5s"` 或 `1.5`。只支持 `s` 后缀。 |
| `tags`            | list of strings | 使用 `has(tags, "value")` |
| `metadata_key`    | string | run 的 metadata 字典中的键 |
| `metadata_value`  | string | run 的 metadata 字典中的值 |
| `feedback_key`    | string | 某个反馈分数的名称 |
| `feedback_score`  | number | 某个反馈分数的数值 |

### 值格式

- **字符串**：使用双引号或单引号包裹，例如 `eq(name, "MyChain")` 或 `eq(name, 'MyChain')`。
- **时间戳**：ISO 8601 格式，例如 `"2024-06-01T00:00:00Z"`。
- **时长**：以秒表示，可以是数字，也可以是带 `s` 后缀的字符串，例如 `"5s"`、`"1.5s"`、`"90s"` 或 `1.5`。不支持其他单位后缀，例如 `m`、`h`。
- **列表**：使用 JSON 数组语法，例如 `["session_id", "thread_id"]`。

## UI 到 API 运算符映射

LangSmith UI 中的搜索栏使用自己的语法，相关说明见[过滤 traces](/langsmith/filter-traces#operators)。下表将每个搜索栏运算符映射到这种语言中完成同样工作的比较器：

| Search bar operator | Search bar syntax | API comparator |
| ------------------- | ----------------- | -------------- |
| is | `name:value` | `eq(name, "value")` |
| is not | `-name:value` | `neq(name, "value")` |
| wildcard | `name:*value*` | `like(name, "%value%")`。将每个 `*` 替换为 `%`。 |
| matches | `input:~value` | `like(inputs, "%value%")`。同样适用于 `outputs` 和 `error`。 |
| does not match | `-input:~value` | `notlike(inputs, "%value%")` |
| comparison | `latency:>5` | `gt(latency, 5)`。`>=`、`<` 和 `<=` 分别使用 `gte`、`lt` 和 `lte`。 |
| exists | `metadata.env:*` | `eq(metadata_key, "env")` |

## 告警过滤器

告警规则在其 `filter` 和 `denominator_filter` 字段中接受同样的过滤查询语言：

- **`filter`**：选择计入告警的 runs。
- **`denominator_filter`**：为基于百分比的告警选择基线总体。为空时，所有 runs 都计入基线。

告警过滤器只接受 `and`。不支持使用 `or` 组合条件。

以下示例告警过滤器匹配 `env` metadata 值不包含 `staging` 的 runs：

```text
and(eq(metadata_key, "env"), notlike(metadata_value, "%staging%"))
```

## 快速参考示例

以下示例仅展示过滤字符串本身。你可以将这个字符串作为 `filter`、`trace_filter` 或 `tree_filter` 参数，传给 `client.list_runs()` 或 `/runs/query` API endpoint。

<Tip>
完整的 Python、TypeScript 和 Java SDK 示例，请参阅[使用 SDK 查询 traces](/langsmith/export-traces#use-filter-query-language)。
</Tip>

### 按 run 名称过滤

```text
eq(name, "my_chain")
```

### 按错误状态过滤

```text
# Runs that errored
eq(status, "error")

# Runs that did not error
eq(status, "success")
```

### 按延迟过滤

```text
# Runs slower than 5 seconds
gt(latency, "5s")

# Runs faster than 1 second
lt(latency, "1s")
```

### 按时间范围过滤

```text
and(gt(start_time, "2024-01-01T00:00:00Z"), lt(start_time, "2024-02-01T00:00:00Z"))
```

### 按 tags 过滤

```text
has(tags, "production")

# Multiple tags (any match)
or(has(tags, "production"), has(tags, "staging"))
```

### 按 metadata key 或 value 过滤

```text
# Runs with a "user_id" metadata key
eq(metadata_key, "user_id")

# Runs with a specific user ID value
and(eq(metadata_key, "user_id"), eq(metadata_value, "usr_abc123"))

# Runs from the production environment
and(eq(metadata_key, "environment"), eq(metadata_value, "production"))

# Runs whose "env" metadata value contains "prod" (like: contains)
and(eq(metadata_key, "env"), like(metadata_value, "%prod%"))

# Runs whose "env" metadata value does not contain "staging" (notlike: does not contain)
and(eq(metadata_key, "env"), notlike(metadata_value, "%staging%"))
```

### 按 thread ID 过滤

```text
and(in(metadata_key, ["session_id", "thread_id"]), eq(metadata_value, "<your_thread_id>"))
```

### 按反馈分数过滤

```text
# Runs with a "thumbs_up" score of 1
and(eq(feedback_key, "thumbs_up"), eq(feedback_score, 1))

# Runs with a "correctness" score below 0.5
and(eq(feedback_key, "correctness"), lt(feedback_score, 0.5))
```

### 在所有字符串字段上做全文搜索

```text
search("my search term")
```

### 组合多个条件

```text
# Errors that started after a specific time
and(gt(start_time, "2024-06-01T00:00:00Z"), eq(status, "error"))

# Slow LLM runs with low correctness feedback
and(gt(latency, "10s"), eq(feedback_key, "correctness"), lt(feedback_score, 0.5))

# Complex: errors OR low score, both starting after a timestamp
and(gt(start_time, "2023-07-15T12:34:56Z"), or(eq(status, "error"), and(eq(feedback_key, "Correctness"), eq(feedback_score, 0.0))))
```

### 使用 trace_filter 和 tree_filter

`filter` 作用于返回的 run。`trace_filter` 作用于 trace 的根 run。`tree_filter` 作用于 trace 树中的任意 run。

```text
# filter: the run you want
eq(name, "RetrieveDocs")

# trace_filter: condition on the root run (e.g. human feedback on the overall trace)
and(eq(feedback_key, "user_score"), eq(feedback_score, 1))

# tree_filter: condition on any run in the trace tree
eq(name, "ExpandQuery")
```

<Note>
`tree_filter` 会把同样的查询语法应用到 trace 树中任意位置的 runs 上。对于任意嵌套子 run 字段上的谓词，例如返回的 `inputs`、`outputs` 或 `extra` payload 路径，建议先使用服务端过滤器缩小候选范围，再将根 traces 连同子 runs 一起加载回来并在本地遍历。参阅[使用子 run 谓词查询 trace 树](/langsmith/export-traces#query-trace-trees-with-child-run-predicates)。
</Note>
