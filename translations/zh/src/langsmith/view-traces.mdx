---
title: 查看 traces
description: 在 LangSmith 中使用 Messages 视图或 Details 视图检查智能体 threads。
---

在 tracing project 中，使用 **Threads**、**Traces** 或 **Runs** 标签页切换表格中显示的内容。点击任意一行即可打开侧边面板。

侧边面板围绕 [threads](/langsmith/observability-concepts#threads) 这一主要导航单位来组织。UI 不会把每个 [run](/langsmith/observability-concepts#runs) 当作彼此孤立的对象，而是保持周围对话可见，这样你就能理解某个 run 在智能体整体执行过程中的位置。

<Note>
Threads 标签页和 Turns 视图只对带有 `thread_id` metadata 字段的 runs 可用。如果没有 thread instrumentation，你看到的 traces 会是单独的 runs，也无法使用 Turns 视图。
</Note>

侧边面板顶部提供三种视图：

- [**Messages**](#messages-view)（**beta**）：对话层。以输入、输出、reasoning、工具调用和 subagent 活动的形式浏览完整 thread。用它来定位该看哪里。按 `M` 可切换到此视图。
- [**Turns**](#turns-view)：按回合汇总的层。将 thread 中的每一回合作为卡片显示其输入和输出，并支持展开和折叠。适合在不渲染完整对话的情况下先看结构概览。按 `T` 可切换到此视图。
- [**Details**](#details-view)：调试层。深入查看某个特定 run 的输入、输出、耗时、token 计数、错误和 metadata。适合理解执行中某个具体时刻发生了什么。按 `D` 可切换到此视图。

<Note>
如果 thread 中没有任何可渲染的消息，Messages 标签页会被禁用。Messages 视图目前处于 **[beta](/langsmith/release-stages)** 阶段，因此侧边面板默认打开的是 Details 视图。
</Note>

先用 Messages 视图定位对话上下文和关注点，再切换到 Details 视图检查具体 run：

<Steps>
  <Step title="从 Messages 视图开始">
    打开一个 thread，并切换到 Messages 视图查看完整 thread。
  </Step>
  <Step title="调查问题">
    浏览 thread，找出异常行为，例如错误的工具结果、意外的 subagent handoff，或者延迟峰值。
  </Step>
  <Step title="检查该 run">
    点击相关消息或工具调用，直接在产生它的那个确切 run 上打开 Details 视图。检查其输入、输出、耗时、错误和 metadata。
  </Step>
  <Step title="返回 thread">
    切回 Messages 视图，继续浏览整段对话。
  </Step>
</Steps>

## Messages 视图

<Note>The Messages view is in **[beta](/langsmith/release-stages)**. The side panel defaults to the [Details view](#details-view).</Note>

使用 Messages 视图浏览完整 thread，先识别异常行为，例如错误的工具结果、意外的 subagent handoff 或延迟峰值，然后再深入查看具体 run。

### Messages 视图会显示什么

thread 中的每一回合都会渲染为一个独立区块，其中包含模型响应、它触发的工具调用，以及这些工具返回的结果。你可以直接浏览整段 thread 并阅读智能体行为，而不需要打开子 run。

每个区块的 metadata 行会显示：

- **Token usage:** 本次调用的总 token 数
- **Cost:** 本次调用的总成本
- **Model name**
- 指向 [Details view](#details-view) 中对应 run 的 **LLM call** 链接，仅当 AI message 有可见文本时显示

当模型启用 extended thinking 时，**Thought** 区块会以内联形式出现在 assistant 消息中，默认折叠。点击即可展开该回合的思维链。

**Subagents** 会作为独立动作以内联形式出现在对话中。点击某个 subagent，可打开它自己的嵌套消息视图；点击返回即可回到父 thread。

**Tool calls** 会与触发它们的 assistant 消息一起显示。每张工具调用卡片都包含一个指向 [Details view](#details-view) 中对应 run 的链接。当智能体一次发起多个工具调用时，无论是同一个工具重复调用，还是多个不同工具并行调用，这些调用都会折叠为一行分组展示。展开该分组即可查看每一条单独调用。

在 Messages 和 Details 标签页之间切换时，LangSmith 会保留消息的折叠和展开状态。

如需将 thread 下载为 Markdown 文件，请使用 Messages 视图中的下载按钮。导出的文件会包含完整对话转录，包括 human 和 AI 回合、工具调用和工具结果，并采用适合在任意 Markdown 查看器中阅读的格式。

### 自定义 Messages 视图

你可以通过单个 run 上的 metadata key 控制其在 Messages 视图中的显示方式。

- `ls_agent_type`：控制某个类似智能体的 run 所产生的消息显示在哪里。可接受值：

  | Value | Messages view behavior |
  |---|---|
  | `"root"` | 此 run 的消息显示在主 Messages 视图中。 |
  | `"subagent"` | 此 run 的消息显示为对话 thread 中的 subagent 动作。 |

    ```python
    @traceable(metadata={"ls_agent_type": "root"})
    def my_agent():
        ...
    ```

- `ls_message_format`：覆盖自动格式检测。可接受值：
  - `"langchain"`：按 LangChain message format 解析
  - `"anthropic"`：按 Anthropic message format 解析
  - `"responses"`：按 OpenAI Responses API format 解析
- `LS_MESSAGE_VIEW_EXCLUDE`：从 Messages 视图中排除单个 run。可从 `langsmith` 导入该常量，Python 和 JS 都支持，也可以直接使用字面字符串 `"ls_message_view_exclude"`。代码示例请参阅[从 Messages 视图中排除 runs](/langsmith/messages-view-integrations#exclude-runs-from-the-messages-view)。
  - 对于 `@traceable` / `traceable()`：在被标记 run 的 tracing 上下文中执行的子 runs 会继承该排除设置。
  - 对于 `wrap_openai` / `wrapOpenAI`、`wrapAISDK`、`RunTree.createChild` 和 LangChain `RunnableConfig`：需要在每个你想隐藏的 run 上单独设置该 key。这里不保证对子 runs 的继承。

## Turns 视图

使用 Turns 视图，你可以按回合浏览 thread 的结构，而不需要 Messages 视图那样完整渲染整段对话。thread 中的每一回合都会显示为一张卡片，展示根 run 的输入和输出。点击卡片的 chevron 可展开或折叠其内容。

Turns 视图适用于以下场景：

- thread 没有可渲染的消息，例如某些 Messages 视图暂不支持的集成所生成的 trace。
- 你想先快速查看 thread 的结构，再决定要深入哪一回合。
- 你想查看每个回合的原始输入和输出，而不希望它们被规范化为聊天式对话。

点击任意一回合即可在生成该回合的 run 上打开 [Details view](#details-view)。

### 自定义 Turns 视图

默认情况下，LangSmith 会通过启发式方式选取每张 turn 卡片显示的输入和输出字段。如需覆盖显示内容，请点击 thread 顶部的 **Format** 按钮打开格式面板，选择你想显示的具体输入和输出路径后保存。你的选择会为该 project 持久保存。

## Details 视图

Details 视图是调试层。当你点击查看某个特定 run 时，周围的 thread 上下文仍然可见，因此你可以理解该 run 在整个对话中的位置。你可以在不丢失 thread 线索的前提下，检查输入、输出、metadata、耗时、错误和子 runs。

### 自定义 Details 视图

给某个 run 设置 `run_type="llm"` 后，Details 视图会为该 run 渲染 token 计数和延迟。完整的消息格式规范请参阅[记录 LLM trace](/langsmith/log-llm-trace)。

当 run 的 `run_type` 是 `tool` 时，工具消息会自动展开。

给某个 run 设置 `run_type="retriever"` 后，Details 视图会以内联方式渲染每个检索到的文档及其内容和 metadata。所需的返回格式请参阅[记录 retriever traces](/langsmith/log-retriever-trace)。

### 可执行操作

在 Details 视图中，你还可以：

- **Share a trace:** 生成该 trace 的公开链接。参阅[管理 trace](/langsmith/manage-trace#share-a-trace)。
- **View server logs:** 访问与某条由 LangSmith deployment 生成的 trace 相关联的服务器日志。参阅[管理 trace](/langsmith/manage-trace#view-server-logs)。
- **Add to a dataset:** 将该 run 保存为数据集中的一个示例，以便后续评估使用。参阅[在应用中管理数据集](/langsmith/manage-datasets-in-application#manually-from-a-tracing-project)。
- **Add to an annotation queue:** 将该 run 发送到一个队列中，供人工审核和反馈。参阅[Annotation queues](/langsmith/annotation-queues#assign-runs-to-a-single-run-queue)。
