_environment_ 记录 agent 产生某条 trace 时运行在何处。agent 记录的每一条 [trace](/langsmith/agents) 都会落在这个 agent 的某一个 environment 中，而 environment 取自一个固定的四元素集合。

由于 environment 随 trace 一起记录，agent 运行在哪里就成了 trace 本身的一个属性。

<AgentBetaNote />

## Environment 名称

这四个 environment 是固定的，不支持自定义名称。environment 切换器按最接近生产环境的顺序列出它们：

- **Production**
- **Staging**
- **Development**
- **Local**

一个 agent 拥有这四个中的几个，取决于它是[如何被创建](/langsmith/create-an-agent)的。在 UI 中通过 [Build](/langsmith/build-an-agent) 创建的 agent 最初只有 **Production**，其余的会在第一次有 trace 指向它们时出现。以其他任何方式创建的 agent 则一开始就拥有全部四个。

除了把每个 environment 的 traces 分开之外，LangSmith 不会为这个选择附加任何行为。environment 不会改变 agent 的 instrumentation 方式，同一个 build 也可以通过更改其 [agent addressing](/langsmith/log-traces-to-agent) 上报到不同的 environment。

## 选择一个 environment

凡是 LangSmith 需要单个 environment 而不是全部 environment 的地方，它都使用同一个控件：一个显示当前 environment 的按钮，点击后打开列表。列表按上述顺序列出该 agent 的 environments。

进入某个区块时默认选中的 environment 取决于该区块：

- **Studio 和 alerts**：**Production**。
- **Monitoring 和 Deployments**：你上次为该 agent 使用的 environment，如果没有则默认为 **Production**。
- **Tracing**：你上次为该 agent 使用的 environment，其次是 **Local**，再其次是该 agent 拥有的第一个 environment。

在 Deployments 中，**Local** 不会显示；当 preview builds 开启且该 agent 拥有 previews 时，列表会添加一个 **Preview** 条目。

列表只显示该 agent 实际存在的 environments。

Tracing、Monitoring、alerts、[Engine](/langsmith/engine-overview)、Studio 和 Deployments 上的 environment 选择都由这个控件驱动。[Evaluators](/langsmith/evaluators) 和 [Insights](/langsmith/insights) 也按单个 environment 划分范围，但不使用这个下拉框。
