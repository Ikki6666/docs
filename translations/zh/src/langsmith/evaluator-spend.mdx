为每个 evaluator 设置每周 LLM 花费上限，防止单个 evaluator 超出预算。LangSmith 会跟踪本周至今的 evaluator 花费，并在每周一 UTC 00:00 重置。它允许[组织管理员](/langsmith/rbac#organization-admin)为每个 evaluator 的[已附加项目和数据集](/langsmith/evaluation-concepts#attaching-an-evaluator-to-a-tracing-project-or-dataset)设置每周上限。这个上限可以是组织范围内的统一默认值，也可以是针对某个已附加项目或数据集的自定义覆盖值。

本指南展示如何查看和配置每周 evaluator 花费上限。

<Tip>
LangSmith 还提供[按 trace 和按模型的成本跟踪](/langsmith/cost-tracking)，以及用于成本控制的 [tracing 用量限制](/langsmith/administration-overview#usage-limits)。
</Tip>

<Warning>
花费限制适用于 OpenAI、Anthropic 和 Gemini 模型。花费限制只会对受支持且已在 LangSmith 中[配置价格](/langsmith/cost-tracking#create-a-new-or-modify-an-existing-model-price-entry)的模型运行生效。依赖限制前，请先验证模型价格配置。设置限制后，不支持的模型不能用于 evaluator。
</Warning>

<Note>
UI 会把本周至今的时间窗口标记为 **this week**。
</Note>

## 强制执行方式

LangSmith 会在每次 evaluator run 完成后记录花费，然后汇总从周一 UTC 00:00 到当前时刻的花费。当总额达到有效限制时，LangSmith 会暂停该 evaluator 在对应项目或数据集上的运行。正在运行的 run 可能会在完成前让总额略微超过上限，因此花费可能短暂小幅超出。

Agent 和 trace 不受影响。只有 evaluator 会停止产出分数，直到花费限制重置，或限制被[手动提高](#override-the-default-for-an-attached-project-or-dataset)。

## 查看 evaluator 花费

你可以在以下 UI 位置找到花费：

### Evaluators 页面仪表板

从左侧边栏进入 **Evaluators** 页面。页面顶部会显示 workspace 范围内的每周视图：

- **Daily evaluator spend**：按天展示花费的堆叠柱状图。可在 **Evaluator** 和 **Project / Dataset** 拆分之间切换。
- **Evaluator spend this week**：所有 evaluator 的美元总花费，并显示相对上一周的变化。
- **Evaluator traces this week**：所有 evaluator 的 trace 总数，并显示相对上一周的变化。
- **Weekly evaluator spend limit monitoring**：按花费排序的高花费项列表，以项目或数据集为粒度展示 `$ spent / $ limit` 进度条。标题会显示已达到限制（**Limit hit**）或**按当前节奏将达到限制**的项目或数据集数量。

使用页面标题中的 **Prev week** 和 **Next week** 控件切换每周视图。

Tracing project 或 dataset 视图中也有一个 **Evaluators** 标签页，会显示限定在该项目或数据集范围内的相同 widget，例如 **Daily evaluator spend on this tracing project**。

### Evaluators 表格

同一页面上的 Evaluators 表格包含：

- **Spend (this week)**：自周一 UTC 00:00 起，该 evaluator 在所有已附加项目和数据集上的 LLM 总成本。不调用 LLM 的 evaluator（例如 code evaluator）、已禁用 evaluator，以及没有附加项目或数据集的 evaluator 不显示值。
- **Spend Status**：以下状态之一：
    - **Under limits**：至少一个已附加项目或数据集设置了限制，并且没有达到上限。
    - **N limit hit**：该 evaluator 在一个或多个已附加项目或数据集中达到限制。数字表示有多少项已暂停。
    - **Unlimited**：未设置任何限制。
    - 不调用 LLM 的 evaluator（例如 code evaluator）以及没有附加项目或数据集的 evaluator 不显示值。

### Evaluator 上的 Projects & Datasets 标签页

打开 evaluator 并选择 **Projects & Datasets** 标签页，可查看按项目或数据集划分的花费和限制：

- **Spend (this week)**：自周一 UTC 00:00 起，该 evaluator 在该项目或数据集上的 LLM 总成本。
- **Percent of Spend Limit**：显示自周一 UTC 00:00 起花费相对于限制的进度条。
- **Weekly Limit**：该项目或数据集的有效每周限制，可以是组织默认值，也可以是自定义覆盖值。

有关附加关系管理，请参见[管理 evaluators](/langsmith/evaluators)。

## 设置组织默认花费限制

组织管理员可以设置一个统一的每周上限，应用到组织内每个 workspace 中所有 evaluator 的已附加项目和数据集。每个组织只有一个默认值，不是每个 workspace 一个。

<Note>设置和编辑组织默认值需要 `organization:manage` [权限](/langsmith/rbac)。</Note>

1. 打开组织 **Settings**，进入 **Usage Configuration**。
1. 在 **Evaluator spend limit** 中输入美元金额。单位是 `/ week`。留空表示不设限制。
1. 点击 **Save**。

如果未设置组织默认值，已附加项目和数据集将不受限制，除非配置了自定义覆盖值。清除默认值会从当前继承默认值的每个已附加项目或数据集中移除上限。

更改默认值只会更新继承默认值的已附加项目和数据集。自定义覆盖值会保留。

## 为已附加项目或数据集覆盖默认值

组织管理员可以为附加到 evaluator 的特定项目或数据集覆盖默认值。

1. 从左侧边栏进入 **Evaluators**，打开该 evaluator。
1. 点击右上角的 **Edit evaluator** 图标。
1. 在 **Source** 下，选择特定项目或数据集。
1. 滚动经过 **Filters** 和 **Sampling Rate**，然后展开 **Advanced**。
1. 在 **Spend limit** 字段中设置自定义美元金额。单位是 `/ week`。
1. **Save** evaluator 配置。

字段下方的提示文本会显示当前值是组织默认值还是自定义限制。要把覆盖值恢复为组织默认值，请点击 **Reset to organization default**。

没有 `organization:manage` 的成员可以看到限制，但不能修改。只读视图会显示以下之一：

- `Unlimited / week (organization default)`
- `$<amount> / week (organization default)`
- `$<amount> / week (custom limit)`

## 达到限制时

当某个已附加项目或数据集上的每周花费达到有效限制时：

- LangSmith 会停止在该项目或数据集的新 run 上运行 evaluator。
- Evaluators 表格的 **Spend Status** 列会显示 **N limit hit**，Weekly evaluator spend limit monitoring widget 会显示受影响的项目或数据集。
- 被跳过的 run 不会回填。花费限制重置后，或限制被[手动提高](#override-the-default-for-an-attached-project-or-dataset)后，evaluation 会自动在新的 run 上恢复。

## 配置模型价格

设置花费限制后，evaluator 只能在受支持的模型（OpenAI、Anthropic 和 Gemini）上运行，并且这些模型需要已配置价格。没有配置价格的模型不能用于 evaluator。

在 [Model pricing](/langsmith/cost-tracking#create-a-new-or-modify-an-existing-model-price-entry) 中为 evaluator 使用的模型配置价格。

## 故障排查

**创建 evaluator 时遇到问题**：设置限制后，evaluator 必须使用受支持的模型（OpenAI、Anthropic 或 Gemini），并且该模型需要在 [Model pricing](/langsmith/cost-tracking#create-a-new-or-modify-an-existing-model-price-entry) 中有价格条目。

**LangSmith 花费与我的 LLM provider 账单不一致**：LangSmith 根据 [Model pricing](/langsmith/cost-tracking#create-a-new-or-modify-an-existing-model-price-entry) 中配置的按模型费率计算花费，而不是根据 provider 账单计算。如果你的 provider 应用了折扣、自定义合同，或你还没有把某些模型变体添加到 LangSmith，出现差异是正常的。
