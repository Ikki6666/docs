---

LangSmith Fleet 的核心功能构成了你的 agents 的基础能力，包括 tools、channels、memory、sub-agents 和 approvals。

## Agent identity

Agent identity 决定了 agent 在与应用和服务交互时使用谁的[凭证](/langsmith/fleet/workspace-admin)。

更多信息请参阅 [Agent identity](/langsmith/fleet/agent-identity)。

## Agent sidebar

你可以通过内置于 agent 聊天页面的侧边栏来配置你的 agent。该侧边栏把 agent 配置项整理为多个抽屉：

- **Channels**：连接 agent 运行所在的位置，例如 Slack、Gmail 和 Microsoft Teams。请参阅 [Channels](/langsmith/fleet/channels)。
- **Sharing**：控制谁可以使用该 agent，可选择 private、workspace 或指定的人员。请参阅[更改 agent 的访问权限](/langsmith/fleet/manage-agent-settings#change-access-to-the-agent)。
- **Connections**：管理 agent 可用的集成和工具、设置连接格式，并将每个工具设为自动运行或需要审批。请参阅 [Tools](#tools)、[Agent identity](#agent-identity) 和 [Human-in-the-loop](#human-in-the-loop)。
- **Knowledge**：管理 agent 的 instructions、skills 和 memory。请参阅 [Instructions](#instructions)、[Skills](#skills) 和 [Memory](#memory)。
- **Schedule**：按固定周期运行你的 agent。请参阅 [Schedules](/langsmith/fleet/schedules)。
- **Advanced settings**：配置 agent 的 model、API keys、sub-agents、诊断和开发者选项。

<Tip>
你也可以通过与 agent 聊天来配置它。在 agent 聊天中，告诉 agent 如何改进自己，例如：“Add the Slack tools so you can respond to messages.”
</Tip>

## Channels

<Anchor id="triggers" />

Channels 定义了你的 agent 何时开始运行。你可以把 agent 连接到外部工具或基于时间的 schedule，让它自动响应消息、邮件或周期性事件。

关于设置步骤和支持的 channel 类型，请参阅 [Channels](/langsmith/fleet/channels)。

## Human-in-the-loop

你可以继续掌控关键决策。你可以将 agent 配置为在执行某些操作之前暂停，并请求你的批准。这样 agent 可以自动处理大部分任务，而你仍然保有监督权。

### 设置审批模式

每个工具都有一个审批模式，你可以在 [agent sidebar](#agent-sidebar) 的 **Connections** 抽屉中设置：

- **Auto**：工具自动运行，无需审批。
- **Ask**：agent 会暂停，并等待你批准后再运行该工具。

如果要求对某个工具进行审批，请将其设为 **Ask**。当 agent 执行到该工具时，它会暂停，直到你做出回应。

### 当 agent 暂停等待审批时你可以做什么

当 agent 停下来请求审批时，你有两个选项：

<CardGroup cols={2}>
  <Card title="Accept" icon="check">
    直接放行，让 agent 按计划继续执行。
  </Card>
  <Card title="Reject" icon="x">
    拒绝该操作，并告诉 agent 需要修改什么。
  </Card>
</CardGroup>

<Note>
当 agent 由 Slack 触发时，它会直接在 Slack thread 中提出审批请求，并附带 **Approve** 和 **Deny** 按钮，让你无需离开 Slack 即可做出回应。请参阅[在 Slack 中批准或拒绝操作](/langsmith/fleet/slack-app#approve-or-deny-actions-in-slack)。
</Note>

## Instructions

Instructions 就是定义 agent 行为、风格和能力的 system prompt。它们决定了 agent 如何理解请求、如何使用工具，以及如何回应用户。

编辑 instructions 的步骤如下：

1. 在 [LangSmith UI](https://smith.langchain.com) 中，打开你的 agent。
1. 在侧边栏中展开 **Knowledge** 抽屉。
1. 在 **Instructions** 区域中，编辑 agent instructions。

<Tip>
你也可以直接在聊天里提示 agent 来更新 instructions。例如：“Update your instructions to always respond in bullet points.”
</Tip>

## LangChain Compute Units (LCUs)

Fleet 的用量以 LangChain Compute Units（LCUs）来衡量。LCU 用量取决于你的 agent 所执行的 [model](#models) 工作，包括所选的等级以及它处理和生成的内容量。

<Note>
新的 [model 等级](#models)和 LCU 计价适用于自 **2026 年 7 月 15 日**起的新 Fleet 用量。在此日期之前已经在使用 Fleet 的组织将保持当前设置，并在 **2026 年 10 月 1 日**过渡到新模式。如果你使用的是 custom model，请联系你的 LangChain 客户团队了解过渡安排。
</Note>

额度在整个组织范围内共享，并按月重置：

- **Free plan**：每个组织每月 5 LCUs。额度用完后，Fleet 会暂停新的 run，直到额度重置或组织升级到 Plus。
- **Plus plan**：每个组织每月 25 LCUs。超出部分另行计费。当前费率请参阅 [LangSmith 定价页面](https://www.langchain.com/pricing)。

不同 run 的开销各不相同。一次 Fleet run 可能会发起多次 model 调用，而任务的长短和复杂程度也各不相同。更长的任务、更大的上下文量或更高的等级，相比 Fast 等级中的短任务，会消耗更多 LCUs。

如果你的组织享有旧版 Plus 席位或 trace 计费费率，当 Fleet 切换到 LCU 计价时，这些费率不会改变。请联系你的客户团队确认你所在组织的计价方式。

## Memory

Agents 会记住之前对话中的重要信息，并能通过自我更新来工作得更好。Fleet agents 使用两类 memory：

- **Thread-scoped memory**：当前对话 thread 中的上下文，包括该 thread 中的消息和 actions。
- **Long-term memory**：agent workspace 中的持久化文件，例如 `AGENTS.md`、`tools.json`（工具配置）、`subagents/*` 和 `skills/*`。这些文件会在运行时加载，并从每次 run 一开始就可用。`AGENTS.md` 会自动插入 system prompt。其他长期文件不会自动加入 prompt，agent 需要按需读取它们（例如通过 `read_file` 工具）。

Agents 会通过向 **memories folder** 写入文件（使用 `write_file` 和 `edit_file` 工具调用）来持久化过去交互中的相关细节，从而帮助它们在未来对话中做出更好的决策。

<Note>
默认情况下，agent 在保存到 memories folder 之前需要获得审批。你可以在 **Knowledge** 抽屉的 **Memory** 下修改这一要求。

对于运行在自动化 [schedules](/langsmith/fleet/schedules#add-a-schedule)上的 agents，我们建议你[关闭 memory 更新所需审批](/langsmith/fleet/manage-agent-settings#disable-required-approval-for-memory-updates)，这样 agent 就能在无需人工干预的情况下持久化信息。
</Note>

关于更多背景，请参阅 [How we built the memory system for Fleet (formerly known as Agent Builder)](https://www.langchain.com/conceptual-guides/how-we-built-agent-builders-memory)。

## Models

Fleet 会代为管理 models。它会为每个任务选择并维护一个强劲的 model，让你无需自己挑选 provider、配置 model 或提供 API key，也能获得良好的效果。用量以 [LangChain Compute Units (LCUs)](#langchain-compute-units-lcus) 计费。

<Note>
新的 model 等级和 [LCU](#langchain-compute-units-lcus) 计价适用于自 **2026 年 7 月 15 日**起的新 Fleet 用量。在此日期之前已经在使用 Fleet 的组织将保持当前设置，并在 **2026 年 10 月 1 日**过渡到新模式。如果你使用的是 custom model，请联系你的 LangChain 客户团队了解过渡安排。
</Note>

Fleet 提供三个托管等级。每个等级背后的 model 会随着新模型的推出而变化，因此你可以根据需要完成的工作来选择，而不是指定某个具体的 provider 或 model。

| Tier | 适用场景 | <Tooltip tip="Higher tiers typically cost more and take longer.">相对开销</Tooltip> |
| ---- | -------- | ------------- |
| **Fast** | 日常任务，例如调研、摘要和起草 | 低 |
| **Pro** | 更复杂的任务，能从更强推理能力中受益 | 中 |
| **Max** | 最具挑战性的任务，能力最大化最为重要 | 高 |

### Custom models

Custom models 无法与 Fast、Pro 和 Max 一起在 Fleet 托管的 model 选择器中使用。LangChain 负责托管等级的 model-provider 访问，因此你无需自己的 model-provider API key。如果企业部署必须使用 custom models，请联系你的 LangChain 客户团队或[联系销售](https://www.langchain.com/contact-sales)。

## Self-updates

Agents 可以自我更新：它们可以添加新工具、移除不再需要的工具，或调整自己的 instructions。不过，agents 不能修改自己的名称、描述，也不能修改触发它们运行的 channels。

## Skills

Skills 用于打包能力，并在某些上下文并非普遍相关时提供更具体的信息。

使用 skills 可以帮助你：

- 只在当前任务相关时提供上下文，从而节省 token 用量。
- 避免 system prompt 中塞入过多上下文，否则容易导致 hallucination 和错误响应。

要添加 skill，请在 agent sidebar 中展开 **Knowledge** 抽屉，然后点击 **+ Add skill**。

更多信息请参阅 [Skills](/langsmith/fleet/skills)。

## Sub-agents

你可以通过把大任务拆成更小、更专门的辅助单元来构建复杂 agents。可以把 sub-agents 理解为一个专家团队，每个成员处理任务中的某个特定部分，与主 agent 协同工作。

这种方式更容易构建复杂系统。与其让单个 agent 试图包办一切，不如让多个专门的辅助 agent 各自擅长自己的部分。

你可以这样使用 sub-agents：

- 拆分子任务：让一个 agent 拉取数据，另一个做总结，第三个负责整理输出格式。
- 工具专门化：根据不同任务需要，为不同 agents 分配不同工具。
- 独立工作：让 sub-agents 各自完成工作，再把结果带回主 agent。

要添加 sub-agent，请打开你的 agent，在侧边栏中展开 **Advanced settings** 抽屉，然后在 **Subagents** 下点击 **+ Add subagent**。

## Threads

Threads 是你与 agent 之间的对话。每个 thread 都包含消息、agent 响应，以及 agent 执行的任何 actions。

要查看 threads，请在 [LangSmith UI](https://smith.langchain.com) 中进入你的 agent。inbox 会展示该 agent 的所有 threads。点击任意 thread 即可查看对应对话。

### 已读与未读状态

thread 的标记方式取决于 agent 是否使用了 channels：

- **Chat agents（没有 channel）**：agent 响应后会把 thread 标记为 **unread**。查看该 thread 后会将其标记为已读。
- **基于 channel 的 agents**：agent 响应后默认仍保持 **read** 状态。

你可以随时手动将任意 thread 标记为已读或未读。

## Tools

Tools 让你的 agents 可以与应用和服务交互。你的 agents 可以发送邮件、创建日历事件、发布消息、执行网页搜索等等。你可以从 Gmail、Slack、Google Calendar、GitHub 等大量内置工具中进行选择。

无论 agent 是如何被触发的，tools 都可用。例如，你可以在 Fleet 聊天 UI 中发起一个任务，然后让 agent 在完成后给你发送一条 [Slack message](/langsmith/fleet/slack-app#add-slack-tools)。

更多信息请参阅 [Tool integrations](/langsmith/fleet/tools)。

## Traces

Traces 是你的 agent 从输入到输出所经历的一系列步骤。你可以用 [LangSmith](/langsmith/observability) 来可视化这些执行步骤。

要查看某个 agent 的所有 traces：

1. 在 [LangSmith UI](https://smith.langchain.com) 中，打开你的 agent。
1. 在侧边栏中展开 **Advanced settings** 抽屉。
1. 在 **Diagnostics** 下，点击 **View agent traces**。

要查看某个具体 thread 的 trace：

1. 在 [LangSmith UI](https://smith.langchain.com) 中，进入该 agent 的 inbox。
1. 右键点击你想跟踪的 thread，然后选择 **View trace**。

更多信息请参阅 [LangSmith Observability](/langsmith/observability)。

<Note>
Fleet 会跟踪所有 agent runs，并将其存储在 LangSmith 中。LLM 提供商不会保留你的数据。在 LangSmith Cloud 上，trace 数据默认保留 14 天。
</Note>
