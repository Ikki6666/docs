LangSmith Fleet 的核心功能构成了你的 agents 的基础能力，包括 tools、channels、memory、sub-agents 和 approvals。

## Agent identity

Agent identity 决定了 agent 在与应用和服务交互时使用谁的[凭证](/langsmith/fleet/workspace-admin)。

更多信息请参阅 [Agent identity](/langsmith/fleet/agent-identity)。

## Channels

<Anchor id="triggers" />

Channels 定义了你的 agent 何时开始运行。你可以把 agent 连接到外部工具或基于时间的 schedule，让它自动响应消息、邮件或周期性事件。

关于设置步骤和支持的 channel 类型，请参阅 [Channels](/langsmith/fleet/channels)。

## Custom models

Fleet 支持 custom models。你可以连接任何支持 **OpenAI chat completions spec** 或 **Anthropic chat spec** 的 LLM API。

常见用例包括：

- **LLM proxies**：通过 LiteLLM、Portkey 或你自己的代理服务转发请求。
- **Self-hosted models**：连接运行在你自己基础设施上的模型。
- **Alternative providers**：使用任何提供兼容 API 的供应商。

添加 custom model 的步骤如下：

1. 在 [LangSmith UI](https://smith.langchain.com) 中，进入你要编辑的 agent。
1. 点击右上角的 <Icon icon="settings" /> 设置图标。
1. 在 **Model** 区域中，选择 **+ Add custom model**。
1. 输入 model ID、display name、base URL、API key 的名称和值。
1. 点击 **Save**。

<Note>
  Custom models 必须能通过公网 API endpoint 访问。LangSmith 无法连接到位于私有网络、VPN 后面，或没有暴露到互联网的机器上的模型。
</Note>

## Human-in-the-loop

你可以继续掌控关键决策。你可以将 agent 配置为在执行某些操作之前暂停，并请求你的批准。这样 agent 可以自动处理大部分任务，而你仍然保有监督权。

### 设置审批步骤

<Steps>
  <Step title="Select a tool">
    在配置 agent 时，先选择你希望在执行前进行审查的工具或操作。
  </Step>
  <Step title="Turn on approval">
    找到该工具对应的审批选项，并将其开启。
  </Step>
  <Step title="Agent waits for you">
    当 agent 执行到该步骤时，它会暂停并等待你的批准后再继续。
  </Step>
</Steps>

### 当 agent 暂停等待审批时你可以做什么

当 agent 停下来请求审批时，你有三个选项：

<CardGroup cols={3}>
  <Card title="Accept" icon="check">
    直接放行，让 agent 按计划继续执行。
  </Card>
  <Card title="Edit" icon="edit">
    在允许继续之前，先修改 agent 的消息或参数。
  </Card>
  <Card title="Send feedback" icon="message">
    提供反馈，帮助 agent 学习和改进。
  </Card>
</CardGroup>

## Instructions

Instructions 就是定义 agent 行为、风格和能力的 system prompt。它们决定了 agent 如何理解请求、如何使用工具，以及如何回应用户。

编辑 instructions 的步骤如下：

1. 在 [LangSmith UI](https://smith.langchain.com) 中，进入你要编辑的 agent。
1. 点击右上角的 <Icon icon="pencil" /> **Edit**。
1. 在 **Instructions** 面板中，点击 <Icon icon="pencil" /> **Edit**。
1. 编辑 instructions。
1. 点击 **Done**，然后点击 **Save changes**。

<Tip>
你也可以直接在聊天里提示 agent 来更新 instructions。例如：“Update your instructions to always respond in bullet points.”
</Tip>

## Memory

Agents 会记住之前对话中的重要信息，并能通过自我更新来工作得更好。Fleet agents 使用两类 memory：

- **Thread-scoped memory**：当前对话 thread 中的上下文，包括该 thread 中的消息和 actions。
- **Long-term memory**：agent workspace 中的持久化文件，例如 `AGENTS.md`、`tools.json`（工具配置）、`subagents/*` 和 `skills/*`。这些文件会在运行时加载，并从每次 run 一开始就可用。`AGENTS.md` 会自动插入 system prompt。其他长期文件不会自动加入 prompt，agent 需要按需读取它们（例如通过 `read_file` 工具）。

Agents 会通过向 **memories folder** 写入文件（使用 `write_file` 和 `edit_file` 工具调用）来持久化过去交互中的相关细节，从而帮助它们在未来对话中做出更好的决策。

<Note>
默认情况下，agent 在保存到 memories folder 之前需要获得审批。你可以在 agent 设置中关闭这一要求。

对于运行在自动化 [schedules](/langsmith/fleet/schedules#add-a-schedule)上的 agents，我们建议你[关闭 memory 更新所需审批](/langsmith/fleet/manage-agent-settings#disable-required-approval-for-memory-updates)，这样 agent 就能在无需人工干预的情况下持久化信息。
</Note>

关于更多背景，请参阅 [How we built the memory system for Fleet (formerly known as Agent Builder)](https://www.langchain.com/conceptual-guides/how-we-built-agent-builders-memory)。

## Self-updates

Agents 可以自我更新：它们可以添加新工具、移除不再需要的工具，或调整自己的 instructions。不过，agents 不能修改自己的名称、描述，也不能修改触发它们运行的 channels。

## Skills

Skills 用于打包能力，并在某些上下文并非普遍相关时提供更具体的信息。

使用 skills 可以帮助你：

- 只在当前任务相关时提供上下文，从而节省 token 用量。
- 避免 system prompt 中塞入过多上下文，否则容易导致 hallucination 和错误响应。

更多信息请参阅 [Skills](/langsmith/fleet/skills)。

## Sub-agents

你可以通过把大任务拆成更小、更专门的辅助单元来构建复杂 agents。可以把 sub-agents 理解为一个专家团队，每个成员处理任务中的某个特定部分，并与主 agent 协同工作。

这种方式更容易构建复杂系统。与其让单个 agent 试图包办一切，不如让多个专门的辅助 agent 各自擅长自己的部分。

你可以这样使用 sub-agents：

- 拆分子任务：让一个 agent 拉取数据，另一个做总结，第三个负责整理输出格式。
- 工具专门化：根据不同任务需要，为不同 agents 分配不同工具。
- 独立工作：让 sub-agents 各自完成工作，再把结果带回主 agent。

## Threads

Threads 是你与 agent 之间的对话。每个 thread 都包含消息、agent 响应，以及 agent 执行的任何 actions。

要查看 threads，请在 [LangSmith UI](https://smith.langchain.com) 中进入你的 agent。inbox 会展示该 agent 的所有 threads。点击任意 thread 即可查看对应对话。

### 已读与未读状态

thread 的标记方式取决于 agent 是否使用了 channels：

- **Chat agents（没有 channel）**：agent 响应后会把 thread 标记为 **unread**。查看该 thread 后会将其标记为已读。
- **基于 channel 的 agents**：agent 响应后默认仍保持 **read** 状态。

你可以随时手动将任意 thread 标记为已读或未读。

## Tools

Tools 让你的 agents 可以与应用和服务交互。你的 agents 可以发送邮件、创建日历事件、发布消息、执行网页搜索等等。你可以从 Gmail、Slack、Google Calendar、GitHub 等大量内置工具中进行选择。

无论 agent 是如何被触发的，tools 都可用。例如，你可以在 Fleet 聊天 UI 中发起一个任务，然后让 agent 在完成后给你发送一条 [Slack message](/langsmith/fleet/slack-app#add-slack-tools)。

更多信息请参阅 [Tool integrations](/langsmith/fleet/tools)。

## Traces

Traces 是你的 agent 从输入到输出所经历的一系列步骤。你可以用 [LangSmith](/langsmith/observability) 来可视化这些执行步骤。

要查看某个 agent 的所有 traces：

1. 在 [LangSmith UI](https://smith.langchain.com) 中，进入该 agent 的 inbox。
1. 在 agent 名称旁边，点击 **View Agent Traces** 图标。

要查看某个具体 thread 的 trace：

1. 在 [LangSmith UI](https://smith.langchain.com) 中，进入该 agent 的 inbox。
1. 右键点击你想跟踪的 thread，然后选择 **View trace**。

更多信息请参阅 [LangSmith Observability](/langsmith/observability)。

<Note>
Fleet 会跟踪所有 agent runs，并将其存储在 LangSmith 中。LLM 提供商不会保留你的数据。在 LangSmith Cloud 上，trace 数据默认保留 14 天。
</Note>
