[**LangSmith Fleet**](/langsmith/fleet/index) 是一个企业级 agent 平台，可用于在组织内部构建、共享和治理 agents。本页将它与其他类似平台进行比较，帮助你为团队选出更合适的方案。

<div className="compact-first-col">

| **Platform** | **Choose if...** |
| ------------ | ---------------- |
| [LangSmith Fleet](/langsmith/fleet/index) | 你希望在组织内部构建并共享面向特定场景的 agents，希望保持模型无关性，并通过 LangSmith 获得完整的可观测性。**Fleet** 还是唯一一个支持自托管部署路径、并可通过 [Deep Agents](/oss/deepagents/overview) 将 agents 导出为代码的方案。 |
| Claude Cowork | 你希望在桌面端把开放式任务委派给 Claude，用于个人知识工作，并且设备本地数据存储已满足你的隐私要求。 |
| Amazon Quick | 你已经在使用 AWS，希望获得一个能够直接访问 AWS 数据源和企业集成的 AI 助手。 |
| Google Workspace Studio | 你的组织基于 Google Workspace 运作，并希望使用无需代码的 agents，在 Gmail、Drive 和 Sheets 中原生工作，而不离开 Google 生态。 |
| Microsoft Copilot | 你的组织基于 Microsoft 365 运作，并希望使用低代码 agents（通过 Copilot Studio），并原生发布到 Teams 与 Microsoft 365 Copilot，由 Power Platform 管理中心统一治理。 |

</div>

### 目标用户

**Fleet** 同时覆盖组织级和个人级使用场景。团队可以构建面向特定业务的 agents，在整个组织中共享（例如服务整个运营团队的供应商准入 agent，或者每周一帮所有客户经理节省半小时的周报 agent）；同时，任意用户也可以通过 Fleet 默认的通用聊天 agent，借助任意工具完成任意任务。其他平台通常更偏向个人效率、特定生态内自动化，或二者结合，但没有哪一个同时具备无代码 agent 构建、组织级共享和代码导出能力。

**Fleet** 还允许你设置工具级审批要求，让 agent 在执行敏感操作前先征得你的同意，并通过一个[集中式收件箱](https://smith.langchain.com/agents/inbox)来统一查看、编辑和批准操作。本页对比中的其他平台都没有提供跨所有 agents 统一的集中审批收件箱。

### 模型灵活性

**Fleet** 支持任何符合 OpenAI 或 Anthropic chat 规范的 LLM，包括自托管提供商，不依赖于某个单一生态。Microsoft Copilot 支持精选的多厂商模型，并可通过 Azure AI Foundry 自带模型，但若想获得完整灵活性，仍需要 Azure 基础设施。Google Workspace Studio 和 Amazon Quick 则更受各自厂商生态约束。

在本页比较的平台中，只有 Fleet 能够接入任意兼容 OpenAI 或 Anthropic API 的端点，而不受云厂商限制。

### 可观测性与治理

**Fleet** 最明显的优势，是它与 LangSmith 的原生连接。每一次 agent 运行都会被 trace 到 LangSmith 中，因此你可以方便地调试性能，并大规模运行评估。其他平台虽然也提供基础日志与审计能力，但没有任何一个能达到 Fleet 在 LLM 感知 tracing、评估与调试方面的深度。

### 代码导出与托管

**Fleet** 支持将你构建的任意 agent 通过 [Deep Agents](/oss/deepagents/overview) 导出为代码，而 Fleet 本身就是运行在这个开源 agent runtime 之上的。导出的 agents 使用 MIT 许可证，可以独立于 Fleet 部署、在代码中修改，或通过 [API](/langsmith/fleet/code) 直接集成到你自己的应用里。对比中的其他平台都不提供代码导出路径。

**Fleet** 还是本页比较中唯一一个支持自托管部署的平台。对于有合规要求的团队，自托管和 BYOC（bring your own cloud）配置让你可以把 Fleet 完全运行在自己的基础设施中。其余平台都只提供云端托管服务。
