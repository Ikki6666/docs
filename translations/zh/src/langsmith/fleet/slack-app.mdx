Fleet 可以把任意 agent 变成 Slack 中的队友，你的团队可以在频道中 @ 它，也可以直接私信。这个 bot 就是 agent 本身，而不是 agent 前面的中转：它使用 agent 自己的 instructions、tools 和 permissions 运行。每个 agent 都可以拥有自己的 Slack app，因此单个 Slack workspace 可以运行与你拥有的 agent 一样多的 Slack bot：一个负责分诊支持，一个监控 on-call 轮值，一个用于深入研究。

## Agent 在 Slack 中能做什么

连接后，agent 可以：

- 从频道中的 @、私信或群组私信启动一次 run。
- 在它被 @ 的 thread 中回复。
- 读取 thread 和频道历史，获取相关上下文。
- 读取收到的消息中的文件附件。
- 在敏感工具上暂停，并在 Slack 中收集你的审批。

每个 agent 恰好映射到一个 Slack app。

<Warning>
**AI 生成内容**：agent 在 Slack 中的所有响应均由 AI 生成，可能包含错误或不准确之处。对于重要信息，请始终自行核实。
</Warning>

<Info>
Fleet 的 Slack 集成本身没有单独定价。不过，agent runs 和 traces 会按照你组织的套餐，通过 [LangSmith 平台](https://smith.langchain.com)计费。

最新定价信息请参阅 [LangSmith pricing page](https://www.langchain.com/pricing)。
</Info>

## 在 LangSmith Cloud 上设置 Slack

在 LangSmith Cloud 上，Fleet 会为你创建并安装每个 agent 的 Slack app。连接一次 Slack，然后一键为任意 agent 添加 Slack app。

### 前置要求

- Fleet 中已经存在一个 agent（可参考 [Quickstart](/langsmith/fleet/quickstart) 创建）。
- 一个允许你安装应用的 Slack workspace。

### Step 1. 连接 Fleet Slack manager

Fleet Slack app 作为你 workspace 的 manager。一次连接授予两样东西：

- **Slack 工具访问**：agent 发送消息、读取频道和 thread 历史，以及发送私信所需的 bot scopes。
- **App 管理**：让 Fleet 为 agent 创建专用 Slack app 并代表你安装到 workspace 的 scopes，这是一键部署的基础。

要连接，请打开 [Fleet](https://smith.langchain.com/agents) 中的 **Integrations** 页面，搜索 **Slack**，并在 Slack 卡片上点击 **Connect**。Fleet 也会在你首次为 agent 添加 Slack app 时内联运行此连接，因此你可以直接跳到 [Step 2](#step-2-add-a-slack-app-to-an-agent)，在提示时授权即可。

<Note>
当你的 workspace 中有人首次连接时，Slack 可能会将请求路由给 Slack workspace admin。admin 审核后可以：

- **允许 Fleet 安装 apps**：之后 workspace 中的任何人都可以从 Fleet 创建 Slack agent，无需再次审批。
- **要求逐个 app 审批**：Fleet 创建的每个 Slack agent 在安装前都需要单独的 admin 审批。

如果你的 workspace 要求逐个 app 审批，请按照[添加需要 admin 审批的 app](#add-an-app-that-needs-admin-approval) 操作。
</Note>

### Step 2. 为 agent 添加 Slack app

<Steps>
  <Step title="Add Slack to the agent">
    在 [Fleet](https://smith.langchain.com/agents) 中选择你的 agent，打开其配置侧边栏。展开 **Channels** 抽屉并选择 **Slack**。点击 **Add to Slack**。如果你尚未连接 Slack，Fleet 会先运行 [manager 授权](#step-1-connect-the-fleet-slack-manager)。

    （可选）展开 **Advanced** 并启用 **Allow bot triggers**，允许来自其他 Slack bot 的消息启动一次 run。
  </Step>
  <Step title="Confirm the install">
    Fleet 会以你的 agent 命名创建一个 Slack app，使用其描述和图标，并将其安装到你的 workspace。然后 bot 会给你发一条私信，介绍如何邀请它到频道以及如何 @ 它。

    要确认 app 已连接，请在 agent 的配置侧边栏中展开 **Channels** 抽屉。一个活跃的 Slack channel 会显示 **Active** 状态。
  </Step>
</Steps>

### 添加需要 admin 审批的 app

如果你的 Slack workspace 要求 admin 审批每个 app，Fleet 会将新 app 保存为草稿而不是安装。完成设置需要两轮：

1. 在待处理的 Slack 行上点击 **Finish setup**。Slack 会打开一个窗口，你点击 **Request** 将 app 发送给 workspace admin。
1. admin 批准后，返回 Fleet 并再次点击 **Finish setup**。Fleet 会安装 app 并激活 channel。

## 在 Self-hosted 上设置 Slack

自托管部署不使用 Fleet Slack manager。相反，为实例配置一次 Slack OAuth provider，然后从 Fleet 生成的 manifest 为每个 agent 创建一个 custom Slack app。

### Step 1. 设置 Slack OAuth provider

每个自托管实例在 agent 使用 Slack 之前都需要这一一次性设置。它为你的 agent 启用 [Slack 工具](#add-slack-tools)，并开启 Slack channel，这就是让你在 Step 2 中添加 custom app 的前提。

<Steps>
  <Step title="Configure Helm">
    选择一个 provider ID，例如 `slack-oauth-provider`。将其添加到你的 [`langsmith_config.yaml`](/langsmith/kubernetes#configure-your-helm-charts) 中，连同持有 OAuth providers 的 organization，然后部署：

    ```yaml
    fleet:
      oauth:
        # Organization ID where OAuth providers are configured
        providerOrgId: "<your-org-id>"
        slackOAuthProvider: "<provider-id>"
    ```

    ```bash
    helm upgrade -i langsmith langchain/langsmith --values langsmith_config.yaml --version <version> -n <namespace> --wait --debug
    ```

    确认 Fleet pods 重启。此时 provider ID 只是一个名称。后续步骤会创建它所引用的 provider。
  </Step>

  <Step title="Create a Slack app for the provider">
    前往 [api.slack.com/apps](https://api.slack.com/apps) 并点击 **Create New App**。
  </Step>

  <Step title="Add bot scopes">
    在 **OAuth & Permissions** 中，添加以下 bot token scopes：

    - `channels:history`
    - `channels:read`
    - `chat:write`
    - `files:write`
    - `groups:history`
    - `groups:read`
    - `im:history`
    - `im:read`
    - `im:write`
    - `mpim:history`
    - `mpim:read`
    - `team:read`
    - `users:read`
    - `users:read.email`
  </Step>

  <Step title="Register the provider in LangSmith">
    从 Slack app 的 **Basic Information** 中复制 **Client ID** 和 **Client Secret**。在 LangSmith 中，进入 **Settings > OAuth Providers** 并添加一个 provider：

    - **Provider ID**：你设置为 `slackOAuthProvider` 的 ID。
    - **Client ID**：来自 Slack app。
    - **Client Secret**：来自 Slack app。
    - **Authorization URL**：`https://slack.com/oauth/v2/authorize`
    - **Token URL**：`https://slack.com/api/oauth.v2.access`

    在你设置为 `providerOrgId` 的 organization 中注册它。Fleet 从该 organization 解析 provider，因此在其他地方注册的 provider 会因未知 provider 错误而失败。
  </Step>

  <Step title="Add the redirect URI to Slack">
    在 Slack app 中，进入 **OAuth & Permissions > Redirect URLs** 并添加以下内容，将 `<hostname>` 替换为你的 LangSmith 主机名，`<provider-id>` 替换为你的 provider ID：

    ```
    https://<hostname>/host-oauth-callback/<provider-id>
    ```
  </Step>
</Steps>

在 `slackOAuthProvider` 设置之前，Fleet 不会注册 Slack trigger，**Add Slack App** 保持禁用状态，Slack channel 不会出现在 agents 上。

<Note>
[Step 2](#step-2-create-a-custom-slack-app) 中的每个 custom Slack app 都会获得自己的 OAuth provider，该 provider 由你粘贴的凭据注册。这就是 Step 2 要求单独的 client ID、client secret 和 signing secret 的原因。
</Note>

### Step 2. 创建 custom Slack app

从你希望 bot 运行的 agent 开始此流程，这样 Fleet 会在你完成时为你关联 app。

<Steps>
  <Step title="Open the Slack setup dialog">
    选择你的 agent 并打开其配置侧边栏。展开 **Channels** 抽屉并选择 **Slack**。

    你也可以从 **Integrations** 页面开始：在左侧导航中选择 **Slack & Teams**，然后在 **Slack Apps** 区域点击 **Add Slack App**。
  </Step>

  <Step title="Create the app in Slack">
    1. 输入 bot 名称。
    1. 点击 **Create Slack App**。Fleet 会打开 Slack API 网站，并带有预填的 app manifest。
    1. 选择你要安装 bot 的 workspace。

    <Warning>
    不要在此流程之外创建 Slack app。生成的 manifest 设置了 Fleet 所需的 event subscription URL、interactivity URL、OAuth redirect URL 和 scopes。手动创建的 app 不会收到事件。
    </Warning>
  </Step>

  <Step title="Enter your app credentials">
    回到 Fleet，点击 **Continue To Credentials** 并从你的新 Slack app 复制以下值：

    - **App ID**：来自 **Basic Information**。
    - **Client ID**：来自 **Basic Information > App Credentials**。
    - **Client secret**：来自 **Basic Information > App Credentials**。在 Slack 中点击 **Show** 并复制完整值。
    - **Signing secret**：来自 **Basic Information > App Credentials**。在 Slack 中点击 **Show** 并复制完整值。

    （可选）启用 **Allow bot triggers** 以允许来自其他 Slack bot 的消息启动一次 run。

    点击 **Save Credentials**。
  </Step>

  <Step title="Connect OAuth">
    1. 点击 **Connect OAuth**。Slack 会打开一个授权窗口。
    1. 点击 **Allow** 以将 app 安装到你的 workspace。

    **需要 admin 审批的 Slack apps**：如果 Slack 显示 **Request** 而不是 **Allow**，你的 workspace 要求 admin 审批：

    1. 在 Slack 窗口中，点击 **Request** 将安装请求发送给 admin。这才是实际通知 admin 的操作。
    1. 回到 Fleet，点击 **Save & Request Approval**。尽管它的名字如此，这个按钮只是将 app 保存为草稿，以便你在 admin 批准后继续。

    请参见[完成草稿 Slack app](#finish-a-draft-slack-app)。
  </Step>

  <Step title="Finish setup">
    点击 **Finish**。如果你从 agent 开始，Fleet 会将 app 关联到该 agent。如果你从 **Integrations** 页面开始，请从下拉菜单中选择一个 agent，或点击 **Finish Without Agent** 稍后关联。
  </Step>
</Steps>

### 完成草稿 Slack app

点击 **Save & Request Approval** 会将 app 保存为草稿，因此在 Slack admin 审核安装请求期间你可以保留进度。草稿会显示在 **Slack Apps** 区域的 **Pending Slack admin approval** 下。

admin 批准 app 后：

1. 在 **Integrations** 页面，选择左侧导航中的 **Slack & Teams** 打开 **Slack Apps** 区域。
1. 在草稿上点击 **Resume Setup**。
1. 重新输入 **Client secret** 和 **Signing secret**。Fleet 不会在草稿上存储 secrets，因此请再次从 Slack 复制。
1. 点击 **Save Credentials**，然后 **Connect OAuth**，再在 Slack 中点击 **Allow**。
1. 选择要关联 app 的 agent，然后点击 **Finish**。

<Note>
每个 agent 只能拥有一个 Slack app，每个 Slack app 也只能关联到一个 agent。
</Note>

## 在 Slack 中使用你的 agent

app 安装后，邀请 agent 到频道，@ 它启动一次 run，并无需离开 Slack 即可响应审批请求。

### 把 agent 邀请到频道

1. 在 Slack 中打开你想使用该 agent 的频道。
1. 输入 `/invite @YourAgentName`，将 agent 邀请进频道。
1. 用 `@YourAgentName` 提及该 agent 来启动一次 run。agent 会在一个 thread 中回复。

你也可以给 bot 发私信，或将其添加到群组私信中。

### 在 Slack 中批准或拒绝操作

当 agent 在某个需要审批的工具上暂停时，它会直接在 Slack 中提出请求。消息中会标明工具和操作名称，并附带 **Approve** 和 **Deny** 按钮，让你无需离开 Slack 即可做出回应。

更多信息请参阅 [Human-in-the-loop](/langsmith/fleet/essentials#human-in-the-loop)。

### Slack 中的错误消息

如果 agent 在某次 run 中遇到错误，它会在 Slack thread 中回复，而不是静默无响应。对于某些错误类型（例如认证错误），回复中会包含更多细节，方便你解决问题。

## 添加 Slack 工具

Slack 工具可以让 agent 发送消息、在线程中回复、读取历史，并发送私信。无论 agent 是通过 Slack、Fleet UI、schedule，还是 webhook 被触发，这些工具都能工作。

例如，你可以先在 Fleet 聊天 UI 中启动一个长期运行的研究任务，再让 agent 在完成后给你发一条 Slack 消息。

要添加 Slack 工具：

1. 打开你的 agent，然后在侧边栏中展开 **Connections** 抽屉。
1. 点击 **Add connection**，如果 Slack 尚未连接，则添加 Slack。
1. 添加你需要的 Slack 工具：
   - **Send Channel Message**：向频道发送消息。
   - **Reply to Message**：在线程中回复。
   - **Write Private Message**：发送私信。
   - **Read Channel History**：读取最近的频道消息。
   - **Read Thread Messages**：读取线程中的回复。
1. 如有提示，请授权 Slack 连接。

<Tip>
你也可以直接要求 agent 自己把这些工具加上。在 agent 聊天中可以试试："Add the Slack tools so you can respond to messages."
</Tip>

<Note>
将每个工具设为 **Auto** 可在无需审批的情况下运行，或设为 **Ask** 以在运行前要求审批。更多信息请参阅 [Human-in-the-loop](/langsmith/fleet/essentials#human-in-the-loop)。
</Note>

## 故障排查

### Agent 没有响应

如果你的 agent 没有响应，可以尝试以下检查：

- 查看 Fleet UI 中该 thread 是否有错误。
- 确认 agent 已被邀请到目标频道。
- 确认 Slack channel 没有在 **Channels** 抽屉中被暂停。
- 在 **Channels** 抽屉中删除该 Slack app，然后重新设置。

### 不允许提及 bot

如果你收到一条私信，提示你无权提及该 bot，说明你的 Slack ID 没有被授权使用这个 agent。该 agent 的所有者需要把 agent [分享](/langsmith/fleet/manage-agent-settings#change-access-to-the-agent)给你，可以是把 run 权限共享给整个 LangSmith workspace，或单独共享给你。

### Slack app 一直处于待审批状态

如果 Slack 行一直处于待处理状态，说明它在等待 Slack admin。请让 admin 在 Slack 中批准该 app，然后再次点击 **Finish setup**。请参见[添加需要 admin 审批的 app](#add-an-app-that-needs-admin-approval)。

### Add Slack App 被禁用

在 Self-hosted 上，**Slack Apps** 区域中的 **Add Slack App** 按钮在设置 `fleet.oauth.slackOAuthProvider` 之前是禁用的。请参见[设置 Slack OAuth provider](#step-1-set-up-the-slack-oauth-provider)。
