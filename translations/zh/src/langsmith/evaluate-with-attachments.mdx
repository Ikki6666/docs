LangSmith 支持你创建带文件附件的数据集示例，例如图片、音频文件或文档，并在使用多模态内容运行评估时，在 prompts 和 evaluators 中使用这些附件。

虽然你也可以通过 base64 编码把多模态数据直接放进示例中，但这种方式效率不高，因为编码后的数据会比原始二进制文件占用更多空间，从而导致与 LangSmith 之间的传输变慢。使用附件则有两个明显好处：

- 上传和下载速度更快，因为二进制文件传输更高效。
- 在 LangSmith UI 中可以更直观地预览不同类型的文件。

本指南将介绍如何创建带附件的示例、如何构建使用这些附件的多模态 prompts 和 evaluators，以及如何运行包含多模态内容的评估。请选择 [**UI**](#ui) 或 [**SDK**](#sdk) 标签页开始。

**请选择你偏好的方式：**

## 1. 创建带附件的示例

你可以通过几种不同方式，把带附件的示例添加到数据集中。

#### 从已有 runs 添加

将 runs 添加到 LangSmith 数据集时，可以选择性地把附件从源 run 传递到目标示例。更多信息请参阅[在应用中管理数据集](/langsmith/manage-datasets-in-application#manually-from-a-tracing-project)。

![Add trace with attachments to dataset](/langsmith/images/add-trace-with-attachments-to-dataset.png)

#### 从零开始创建

你也可以直接在 LangSmith UI 中创建带附件的示例。在数据集 UI 的 `Examples` 标签页中点击 `+ Example` 按钮，然后使用 “Upload Files” 按钮上传附件：

![Create example with attachments](/langsmith/images/create-example-with-attachments.png)

上传完成后，你可以在 LangSmith UI 中查看带附件的示例。每个附件都会带预览，便于快速检查。![Attachments with examples](/langsmith/images/attachments-with-examples.png)

## 2. 创建多模态 prompt

在评估多模态模型时，LangSmith UI 允许你把附件直接放进 prompt 中：

首先，在你想加入多模态内容的消息中点击文件图标。然后，为你希望在每个示例中包含的附件添加模板变量。

- 如果你想包含某个特定附件，可以使用推荐的变量名，例如 `{{attachment.file_name}}`，这样会把附件列表中名为 `file_name` 的文件映射到 evaluator 中。
- 如果你希望包含所有附件，则使用 `{{attachments}}` 变量。

![Adding multimodal variable](/langsmith/images/adding-multimodal-variable.gif)

## 3. 定义自定义 evaluators

你可以创建使用数据集示例中多模态内容的 evaluators。

<Note>
Evaluators 所使用的模型必须同时支持对应输入模态和 structured output。对于音频附件，目前只有 Gemini 支持。图片和 PDF 附件则可以使用任何支持视觉能力并能返回 structured output 的模型。
</Note>

由于你的数据集已经包含带附件的示例（在步骤 1 中添加），你可以在 evaluator 中直接引用它们。操作方式如下：

1. 在数据集页面点击 **+ Evaluator**。
1. 在 **Template variables** 编辑器中，添加你希望包含的附件变量：
   - 如果你想包含某个特定附件，可以使用推荐变量名，例如 `{{attachment.file_name}}`，这样会把附件列表中名为 `file_name` 的文件映射进 evaluator。
    - 如果你想包含所有附件，则使用 `{{attachments}}` 变量。

    <img
        className="block dark:hidden"
        src="/langsmith/images/evaluator-attach-file-light.png"
        alt="Create evaluator modal with an audio attachment selected for output variable."
    />

    <img
        className="hidden dark:block"
        src="/langsmith/images/evaluator-attach-file-dark.png"
        alt="Create evaluator modal with an audio attachment selected for output variable."
    />


随后，evaluator 就可以结合这些附件和模型输出一起判断质量。例如，你可以创建这样的 evaluator：

- 检查图片描述是否与实际图片内容一致。
- 验证转录文本是否准确反映了音频内容。
- 校验从 PDF 中抽取出的文本是否正确。

你也可以创建不使用附件、仅评估文本输出的 evaluator：

- OCR → 文本纠正：先用视觉模型从文档中提取文本，再评估提取结果是否准确。
- Speech-to-text → 转录质量：先用语音模型把音频转成文本，再将其与参考答案进行对比评估。

<Tip>
如果你的 traces 在输入或输出中已经包含 base64 编码的多模态内容（例如你遵循了[记录多模态 traces](/langsmith/log-multimodal-traces)指南），那么进行评估时不一定需要附件。你可以在 evaluator prompt 中直接使用标准变量映射，例如 `{{input}}` 或 `{{output}}`，base64 内容会被正确传递给 LLM evaluator，用于可视化和评估。
</Tip>

关于如何定义自定义 evaluators，请参阅 [LLM as Judge](/langsmith/llm-as-judge) 指南。

## 1. 创建带附件的示例

如果你想通过 SDK 上传带附件的示例，可使用 Python 中的 [create_examples](https://docs.smith.langchain.com/reference/python/client/langsmith.client.Client#langsmith.client.Client.create_examples) / [update_examples](https://docs.smith.langchain.com/reference/python/client/langsmith.client.Client#langsmith.client.Client.update_examples)，或 TypeScript 中的 [uploadExamplesMultipart](https://docs.smith.langchain.com/reference/js/classes/client.Client#uploadexamplesmultipart) / [updateExamplesMultipart](https://docs.smith.langchain.com/reference/js/classes/client.Client#updateexamplesmultipart)。

#### Python

Requires `langsmith>=0.3.13`

```python
import requests
import uuid
from pathlib import Path
from langsmith import Client

# Publicly available test files
pdf_url = "https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf"
wav_url = "https://openaiassets.blob.core.windows.net/$web/API/docs/audio/alloy.wav"
img_url = "https://www.w3.org/Graphics/PNG/nurbcup2si.png"

# Fetch the files as bytes
pdf_bytes = requests.get(pdf_url).content
wav_bytes = requests.get(wav_url).content
img_bytes = requests.get(img_url).content

# Create the dataset
ls_client = Client()
dataset_name = "attachment-test-dataset"
dataset = ls_client.create_dataset(
  dataset_name=dataset_name,
  description="Test dataset for evals with publicly available attachments",
)

inputs = {
  "audio_question": "What is in this audio clip?",
  "image_question": "What is in this image?",
}

outputs = {
  "audio_answer": "The sun rises in the east and sets in the west. This simple fact has been observed by humans for thousands of years.",
  "image_answer": "A mug with a blanket over it.",
}

# Define an example with attachments
example_id = uuid.uuid4()
example = {
  "id": example_id,
  "inputs": inputs,
  "outputs": outputs,
  "attachments": {
      "my_pdf": {"mime_type": "application/pdf", "data": pdf_bytes},
      "my_wav": {"mime_type": "audio/wav", "data": wav_bytes},
      "my_img": {"mime_type": "image/png", "data": img_bytes},
      # Example of an attachment specified via a local file path:
      # "my_local_img": {"mime_type": "image/png", "data": Path(__file__).parent / "my_local_img.png"},
  },
}

# Create the example
ls_client.create_examples(
  dataset_id=dataset.id,
  examples=[example],
  # Uncomment this flag if you'd like to upload attachments from local files:
  # dangerously_allow_filesystem=True
)
```

#### TypeScript

Requires version >= 0.2.13

你可以使用 `uploadExamplesMultipart` 方法上传带附件的示例。

请注意，这与标准的 `createExamples` 方法不同，后者当前还不支持附件。每个附件的数据类型都必须是 `Uint8Array` 或 `ArrayBuffer` 之一。

* `Uint8Array`：适合直接处理二进制数据。
* `ArrayBuffer`：表示定长二进制数据，需要时可转换为 `Uint8Array`。

还要注意，在 TypeScript SDK 中不能直接传入文件路径，因为并非所有运行时环境都支持访问本地文件。


```typescript
import { Client } from "langsmith";
import { v4 as uuid4 } from "uuid";

// Publicly available test files
const pdfUrl = "https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf";
const wavUrl = "https://openaiassets.blob.core.windows.net/$web/API/docs/audio/alloy.wav";
const pngUrl = "https://www.w3.org/Graphics/PNG/nurbcup2si.png";

// Helper function to fetch file as ArrayBuffer
async function fetchArrayBuffer(url: string): Promise<ArrayBuffer> {
  const response = await fetch(url);
  if (!response.ok) {
    throw new Error(`Failed to fetch ${url}: ${response.statusText}`);
  }
  return response.arrayBuffer();
}

// Fetch files as ArrayBuffer
const pdfArrayBuffer = await fetchArrayBuffer(pdfUrl);
const wavArrayBuffer = await fetchArrayBuffer(wavUrl);
const pngArrayBuffer = await fetchArrayBuffer(pngUrl);

// Create the LangSmith client (Ensure LANGSMITH_API_KEY is set in env)
const langsmithClient = new Client();

// Create a unique dataset name
const datasetName = "attachment-test-dataset:" + uuid4().substring(0, 8);

// Create the dataset
const dataset = await langsmithClient.createDataset(datasetName, {
  description: "Test dataset for evals with publicly available attachments",
});

// Define the example with attachments
const exampleId = uuid4();
const example = {
  id: exampleId,
  inputs: {
      audio_question: "What is in this audio clip?",
      image_question: "What is in this image?",
  },
  outputs: {
      audio_answer: "The sun rises in the east and sets in the west. This simple fact has been observed by humans for thousands of years.",
      image_answer: "A mug with a blanket over it.",
  },
  attachments: {
    my_pdf: {
      mimeType: "application/pdf",
      data: pdfArrayBuffer
    },
    my_wav: {
      mimeType: "audio/wav",
      data: wavArrayBuffer
    },
    my_img: {
      mimeType: "image/png",
      data: pngArrayBuffer
    },
  },
};

// Upload the example with attachments to the dataset
await langsmithClient.uploadExamplesMultipart(dataset.id, [example]);
```

<Info>
除了直接传入 bytes 外，也可以把附件指定为本地文件路径。做法是把文件路径传给附件的 `data` 字段，并设置参数 `dangerously_allow_filesystem=True`：

```python
client.create_examples(..., dangerously_allow_filesystem=True)
```
</Info>

## 2. 运行评估

### 定义目标函数

现在我们已经有了一个包含附件示例的数据集，就可以定义一个目标函数，在这些示例上运行评估。下面的示例只是简单地使用 OpenAI 的 GPT-4o 模型来回答关于图片和音频片段的问题。

#### Python

你要评估的目标函数必须接受两个位置参数，才能消费与该示例关联的附件：第一个参数必须叫 `inputs`，第二个参数必须叫 `attachments`。

* `inputs` 参数是一个字典，包含该示例的输入数据，但不包括附件。
* `attachments` 参数是一个字典，把附件名映射到另一个字典，该字典中包含 presigned url、mime_type，以及一个可读取文件字节内容的 reader。你可以使用 presigned url，也可以使用 reader 获取文件内容。`attachments` 字典中每个 value 的结构如下：

```python
{
    "presigned_url": str,
    "mime_type": str,
    "reader": BinaryIO
}
```

```python
from langsmith.wrappers import wrap_openai
import base64
from openai import OpenAI

client = wrap_openai(OpenAI())

# Define target function that uses attachments
def file_qa(inputs, attachments):
    # Read the audio bytes from the reader and encode them in base64
    audio_reader = attachments["my_wav"]["reader"]
    audio_b64 = base64.b64encode(audio_reader.read()).decode('utf-8')

    audio_completion = client.chat.completions.create(
        model="gpt-4o-audio-preview",
        messages=[
            {
                "role": "user",
                "content": [
                    {
                        "type": "text",
                        "text": inputs["audio_question"]
                    },
                    {
                        "type": "input_audio",
                        "input_audio": {
                            "data": audio_b64,
                            "format": "wav"
                        }
                    }
                ]
            }
        ]
    )

    # Most models support taking in an image URL directly in addition to base64 encoded images
    # You can pipe the image pre-signed URL directly to the model
    image_url = attachments["my_img"]["presigned_url"]
    image_completion = client.chat.completions.create(
        model="gpt-5.4-mini",
        messages=[
          {
            "role": "user",
            "content": [
              {"type": "text", "text": inputs["image_question"]},
              {
                "type": "image_url",
                "image_url": {
                  "url": image_url,
                },
              },
            ],
          }
        ],
    )

    return {
        "audio_answer": audio_completion.choices[0].message.content,
        "image_answer": image_completion.choices[0].message.content,
    }
```

#### TypeScript

在 TypeScript SDK 中，如果设置了 `includeAttachments=true`，就会通过 `config` 参数把附件传给目标函数。

`config` 中会包含 `attachments`，它是一个对象，把附件名映射到如下结构的对象：

```typescript
{
  presigned_url: string,
  mime_type: string,
}
```

```typescript
import OpenAI from "openai";
import { wrapOpenAI } from "langsmith/wrappers";

const client: any = wrapOpenAI(new OpenAI());

async function fileQA(inputs: Record<string, any>, config?: Record<string, any>) {
  const presignedUrl = config?.attachments?.["my_wav"]?.presigned_url;
  if (!presignedUrl) {
    throw new Error("No presigned URL provided for audio.");
  }

  const response = await fetch(presignedUrl);
  if (!response.ok) {
    throw new Error(`Failed to fetch audio: ${response.statusText}`);
  }

  const arrayBuffer = await response.arrayBuffer();
  const uint8Array = new Uint8Array(arrayBuffer);
  const audioB64 = Buffer.from(uint8Array).toString("base64");

  const audioCompletion = await client.chat.completions.create({
    model: "gpt-4o-audio-preview",
    messages: [
      {
        role: "user",
        content: [
          { type: "text", text: inputs["audio_question"] },
          {
            type: "input_audio",
            input_audio: {
              data: audioB64,
              format: "wav",
            },
          },
        ],
      },
    ],
  });

  const imageUrl = config?.attachments?.["my_img"]?.presigned_url
  const imageCompletion = await client.chat.completions.create({
    model: "gpt-5.4-mini",
    messages: [
      {
        role: "user",
        content: [
          { type: "text", text: inputs["image_question"] },
          {
            type: "image_url",
            image_url: {
              url: imageUrl,
            },
          },
        ],
      },
    ],
  });

  return {
    audio_answer: audioCompletion.choices[0].message.content,
    image_answer: imageCompletion.choices[0].message.content,
  };
}
```

### 定义自定义 evaluators

<Note>你也可以在 UI 中定义一个多模态 evaluator，引用这些附件输入和输出。基于 UI 的 evaluators 会自动运行在每一次 experiment 上，包括通过 SDK 调用的实验。具体操作请参阅 [**UI**](#ui) 标签页。</Note>

上文中关于是否应将附件传给 evaluator 的规则，在这里完全同样适用。

下面这个 evaluator 使用 LLM 来判断推理过程和答案是否一致。关于如何定义基于 LLM 的 evaluator，请参阅[如何定义 LLM-as-a-judge evaluator](/langsmith/llm-as-judge)。

<CodeGroup>

```python Python
# Assumes you've installed pydantic
from pydantic import BaseModel

def valid_image_description(outputs: dict, attachments: dict) -> bool:
  """Use an LLM to judge if the image description and images are consistent."""
  instructions = """
  Does the description of the following image make sense?
  Please carefully review the image and the description to determine if the description is valid.
  """

  class Response(BaseModel):
      description_is_valid: bool

  image_url = attachments["my_img"]["presigned_url"]
  response = client.beta.chat.completions.parse(
      model="gpt-5.5",
      messages=[
          {
              "role": "system",
              "content": instructions
          },
          {
              "role": "user",
              "content": [
                  {"type": "image_url", "image_url": {"url": image_url}},
                  {"type": "text", "text": outputs["image_answer"]}
              ]
          }
      ],
      response_format=Response
  )
  return response.choices[0].message.parsed.description_is_valid

ls_client.evaluate(
  file_qa,
  data=dataset_name,
  evaluators=[valid_image_description],
)
```

```typescript TypeScript
import { zodResponseFormat } from 'openai/helpers/zod';
import { z } from 'zod';
import { evaluate } from "langsmith/evaluation";

const DescriptionResponse = z.object({
  description_is_valid: z.boolean(),
});

async function validImageDescription({
  outputs,
  attachments,
}: {
  outputs?: any;
  attachments?: any;
}): Promise<{ key: string; score: boolean}> {
  const instructions = `Does the description of the following image make sense?
Please carefully review the image and the description to determine if the description is valid.`;

  const imageUrl = attachments?.["my_img"]?.presigned_url
  const completion = await client.beta.chat.completions.parse({
      model: "gpt-5.5",
      messages: [
          {
              role: "system",
              content: instructions,
          },
          {
              role: "user",
              content: [
                  { type: "image_url", image_url: { url: imageUrl } },
                  { type: "text", text: outputs?.image_answer },
              ],
          },
      ],
      response_format: zodResponseFormat(DescriptionResponse, 'imageResponse'),
  });

  const score: boolean = completion.choices[0]?.message?.parsed?.description_is_valid ?? false;
  return { key: "valid_image_description", score };
}

const resp = await evaluate(fileQA, {
  data: datasetName,
  // Need to pass flag to include attachments
  includeAttachments: true,
  evaluators: [validImageDescription],
  client: langsmithClient
});
```

## 3. 更新带附件的示例

上面的代码已经演示了如何向数据集添加带附件的示例。你也可以通过 SDK 更新这些已有示例。

和已有示例一样，带附件更新后的数据集也会进行版本化。因此，你可以前往数据集版本历史，查看每个示例发生了哪些变化。更多信息请参阅[在 UI 中创建和管理数据集](/langsmith/manage-datasets-in-application)。

更新带附件示例时，你可以通过几种不同方式处理附件：

* 传入新附件
* 重命名已有附件
* 删除已有附件

请注意：

* 任何现有附件，如果没有在 `rename` 或 `retain` 中显式保留，**都会被删除**。
* 如果你在 `retain` 或 `rename` 中传入了不存在的附件名，会抛出错误。
* 如果 `attachments` 和 `attachment_operations` 字段中出现同名附件，则新附件会优先于现有附件。

<CodeGroup>

```python Python
example_update = {
  "id": example_id,
  "attachments": {
      # These are net new attachments
      "my_new_file": ("text/plain", b"foo bar"),
  },
  "inputs": inputs,
  "outputs": outputs,
  # Any attachments not in rename/retain will be deleted.
  # In this case, that would be "my_img" if we uploaded it.
  "attachments_operations": {
      # Retained attachments will stay exactly the same
      "retain": ["my_pdf"],
      # Renaming attachments preserves the original data
      "rename": {
          "my_wav": "my_new_wav",
      }
  },
}

ls_client.update_examples(dataset_id=dataset.id, updates=[example_update])
```

```typescript TypeScript
import { ExampleUpdateWithAttachments } from "langsmith/schemas";

const exampleUpdate: ExampleUpdateWithAttachments = {
  id: exampleId,
  attachments: {
    // These are net new attachments
    "my_new_file": {
      mimeType: "text/plain",
      data: Buffer.from("foo bar")
    },
  },
  attachments_operations: {
    // Retained attachments will stay exactly the same
    retain: ["my_img"],
    // Renaming attachments preserves the original data
    rename: {
      "my_wav": "my_new_wav",
    },
    // Any attachments not in rename/retain will be deleted
    // In this case, that would be "my_pdf"
  },
};

await langsmithClient.updateExamplesMultipart(dataset.id, [exampleUpdate]);
```
