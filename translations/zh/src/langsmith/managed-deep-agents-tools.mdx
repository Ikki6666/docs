Managed Deep Agents 支持标准 Deep Agents 的 `tools` 配置面。

:::python
你可以在项目中定义 LangChain tools，把它们导入 `agent.py`，然后传给 `define_deep_agent`。
:::

:::js
你可以在项目中定义 LangChain tools，把它们导入 `agent.ts`，然后传给 `defineDeepAgent`。
:::

要从远程 MCP server 加载 tools，请使用 [MCP connector](/langsmith/managed-deep-agents-mcp-connectors)。

<ManagedDeepAgentsPrivateBetaNote />

## 项目结构

请将 agent 入口文件放在项目根目录，自编写 tools 放在 `tools/` 目录下：

:::python
```text
my-agent/
  agent.py
  tools/
    customer.py
```
:::

:::js
```text
my-agent/
  agent.ts
  tools/
    customer.ts
```
:::

## 添加自编写 tools

自编写 tools 适合业务逻辑、私有 API、数据库访问，以及其他属于 agent 项目的代码。Managed Deep Agents 会把源代码复制到编译后的 build，并把这些 tools 传给 Deep Agents。

关于 LangChain tool 定义的更多信息，请参见 [Tools](/oss/langchain/tools)。

## 添加 tool 模块

:::python
```python tools/customer.py
from langchain.tools import tool


@tool(parse_docstring=True)
def lookup_customer(customer_id: str) -> str:
    """Look up a customer record by ID.

    Args:
        customer_id: Customer ID from the CRM.
    """
    return f"Customer {customer_id} is on the enterprise plan."
```
:::

:::js
```ts tools/customer.ts
import { tool } from "langchain";
import { z } from "zod";

export const lookupCustomer = tool(
  async ({ customerId }) => `Customer ${customerId} is on the enterprise plan.`,
  {
    name: "lookup_customer",
    description: "Look up a customer record by ID.",
    schema: z.object({
      customerId: z.string().describe("Customer ID from the CRM."),
    }),
  },
);
```
:::

## 将 tools 挂到 agent 上

把这些 tools 导入项目根目录下的 agent 入口，并放进 `tools` 列表中。

:::python
```python agent.py
from managed_deepagents import define_deep_agent

from tools.customer import lookup_customer

agent = define_deep_agent(
    name="support-agent",
    model="openai:gpt-5.5",
    tools=[lookup_customer],
)
```
:::

:::js
```ts agent.ts
import { defineDeepAgent } from "managed-deepagents";

import { lookupCustomer } from "./tools/customer";

export const agent = defineDeepAgent({
  name: "support-agent",
  model: "openai:gpt-5.5",
  tools: [lookupCustomer],
});
```
:::

`mda dev` 和 `mda deploy` 会把项目文件复制到编译后的 build 中。

:::python
你的 imports 行为应与普通本地 Python 项目一致。
:::

:::js
你的 imports 行为应与普通本地 TypeScript 项目一致。
:::

请使用清晰且唯一的 tool 名称，以避免命名冲突。

## Human-in-the-loop

在敏感 tool calls 执行前暂停 agent，让人工可以批准、编辑或拒绝。

:::python
你可以在 agent 定义中设置 `interrupt_on`，并根据需要结合 `permissions` 限制工具和文件系统访问。
:::

:::js
你可以在 agent 定义中设置 `interruptOn`，并根据需要结合 `permissions` 限制工具和文件系统访问。
:::

:::python
```python agent.py
from managed_deepagents import define_deep_agent

from tools.customer import lookup_customer

agent = define_deep_agent(
    name="support-agent",
    model="openai:gpt-5.5",
    tools=[lookup_customer],
    interrupt_on={"lookup_customer": True},
)
```
:::

:::js
```ts agent.ts
import { defineDeepAgent } from "managed-deepagents";

import { lookupCustomer } from "./tools/customer";

export const agent = defineDeepAgent({
  name: "support-agent",
  model: "openai:gpt-5.5",
  tools: [lookupCustomer],
  interruptOn: {
    lookup_customer: true,
  },
});
```
:::

:::python
`interrupt_on` 的行为与 LangChain 的 [human-in-the-loop middleware](/oss/langchain/guardrails#human-in-the-loop) 一致。
:::

:::js
`interruptOn` 的行为与 LangChain 的 [human-in-the-loop middleware](/oss/langchain/guardrails#human-in-the-loop) 一致。
:::

关于决策类型（approve、edit、reject）、条件中断与 permission 规则，请参见 Deep Agents 的 [Human-in-the-loop](/oss/deepagents/human-in-the-loop) 和 [Permissions](/oss/deepagents/permissions) 指南。

### 响应 interrupt

当 run 命中 interrupt 时，它会暂停，并在继续之前等待人工响应。

- **本地开发时**，`mda dev` 会在 LangSmith Studio 中运行 agent，你可以在那里查看待执行的 tool call 并恢复 run。
:::python
- **部署后的 agent**，你需要通过 LangGraph server API 发送 `Command(resume=...)` payload 来恢复暂停的 run。请参见 [Human-in-the-loop using server API](/langsmith/add-human-in-the-loop)。
:::
:::js
- **部署后的 agent**，你需要通过 LangGraph server API 发送 resume payload 来恢复暂停的 run。请参见 [Human-in-the-loop using server API](/langsmith/add-human-in-the-loop)。
:::

<Note>
在公开 beta 期间，Managed Deep Agents 以 CLI 为主，当前尚未文档化编程式调用。如果你需要从自己的应用中以编程方式恢复 run，请联系 LangChain 团队。
</Note>

Human-in-the-loop 依赖持久化 thread state 才能暂停和恢复。托管运行时负责 checkpointer，因此不需要额外配置。

## 使用 secrets 和 context

Tools 可以通过环境变量读取 deployment secrets。本地开发时，把值写入 `.env`，供 `mda dev` 加载；部署时，`mda deploy` 会把非保留 `.env` 值转发为托管 deployment secrets。

对于 request metadata 或 feature flags 等按 run 变化的值，请使用标准 LangChain 工具运行时 context 模式。请参见 [how to access context from within your tools](/oss/langchain/tools#access-context)。
