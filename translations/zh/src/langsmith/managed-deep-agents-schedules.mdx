Managed Deep Agents 可以按 cron schedule 运行 agent。部署项目时，`mda deploy` 会在 deployment 可用后把每个 schedule 配置成 LangSmith cron。

<ManagedDeepAgentsPrivateBetaNote />

## 项目结构

Schedule 声明放在项目级别的 `schedules/` 目录中，每个文件一个 schedule：

:::python
```text
my-agent/
  agent.py
  schedules/
    daily_digest.py
```
:::

:::js
```text
my-agent/
  agent.ts
  schedules/
    daily-digest.ts
```
:::

## 添加 schedule

文件名会成为托管 schedule 名称。

:::python
Schedule 模块必须定义一个命名的 `schedule` 声明。
:::

:::js
Schedule 模块必须导出一个命名的 `schedule` 声明。
:::

:::python
```python schedules/daily_digest.py
from managed_deepagents import define_schedule

schedule = define_schedule(
    cron="0 8 * * 1-5",
    timezone="America/Los_Angeles",
    prompt="Write the daily digest.",
)
```
:::

:::js
```ts schedules/daily-digest.ts
import { defineSchedule } from "managed-deepagents";

export const schedule = defineSchedule({
  cron: "0 8 * * 1-5",
  timezone: "America/Los_Angeles",
  prompt: "Write the daily digest.",
});
```
:::

## 配置 schedule 输入

每个 schedule 必须且只能定义以下其中一种：

- `prompt`：自然语言 prompt。Managed Deep Agents 会在 cron 触发时把它转成一条 user message。
- `input`：结构化的 LangGraph input 对象。当你需要传递自定义 graph input，而不是单条 prompt 时使用。

:::python
```python schedules/nightly_sweep.py
from managed_deepagents import define_schedule

schedule = define_schedule(
    cron="30 2 * * *",
    input={
        "messages": [
            {"role": "user", "content": "Sweep stale tickets and summarize changes."}
        ]
    },
)
```
:::

:::js
```ts schedules/nightly-sweep.ts
import { defineSchedule } from "managed-deepagents";

export const schedule = defineSchedule({
  cron: "30 2 * * *",
  input: {
    messages: [
      { role: "user", content: "Sweep stale tickets and summarize changes." },
    ],
  },
});
```
:::

`cron` 必须是标准五段式 cron 表达式，依次为分钟、小时、每月日期、月份和星期几。如果省略 `timezone`，LangSmith crons 会使用 UTC。

## 选择 thread 行为

Schedules 默认使用 ephemeral threads。Managed Deep Agents 会为每次 run 创建一个新的 thread，并在 run 完成后要求 LangSmith 删除该临时 thread。

只有当你希望 schedule runs 在多次触发之间持续累积 thread state 时，才应使用 persistent thread。

<Note>
以下示例需要[持久 memory](/langsmith/managed-deep-agents-memory)。
</Note>

:::python
```python schedules/nightly_memory.py
from managed_deepagents import define_schedule

schedule = define_schedule(
    cron="0 3 * * *",
    prompt="Review the current project memory and list follow-up tasks.",
    thread={"mode": "persistent", "id": "nightly-memory"},
)
```
:::

:::js
```ts schedules/nightly-memory.ts
import { defineSchedule } from "managed-deepagents";

export const schedule = defineSchedule({
  cron: "0 3 * * *",
  prompt: "Review the current project memory and list follow-up tasks.",
  thread: { mode: "persistent", id: "nightly-memory" },
});
```
:::

## 将结果投递到 Slack

:::python
设置 `deliver_to`，通过已配置的 [Slack channel](/langsmith/managed-deep-agents-channels-slack) 投递最终响应。
:::

:::js
设置 `deliverTo`，通过已配置的 [Slack channel](/langsmith/managed-deep-agents-channels-slack) 投递最终响应。
:::

使用 Slack channel ID，因为 schedule runs 没有发起它的原始 thread。

<Note>
:::python
Schedule 投递需要 `managed-deepagents>=0.4.0`。
:::

:::js
Schedule 投递需要 `managed-deepagents` 0.4.0 或更高版本。
:::
</Note>

:::python
```python schedules/monday_greeting.py
from managed_deepagents import define_schedule

schedule = define_schedule(
    cron="0 9 * * 1",
    prompt="Send a Monday greeting to the team.",
    deliver_to={"slack": {"channel_id": "C1234567890"}},
)
```
:::

:::js
```ts schedules/monday-greeting.ts
import { defineSchedule } from "managed-deepagents";

export const schedule = defineSchedule({
  cron: "0 9 * * 1",
  prompt: "Send a Monday greeting to the team.",
  deliverTo: { slack: { channelId: "C1234567890" } },
});
```
:::

Slack bot 必须有权访问目标。

## 使用静态声明

Schedule 声明会在编译时提取，因此配置必须是静态可序列化的：

:::python
- 可以使用 literals、lists、dictionaries，以及对顶层 literal constants 的引用。
- 不要读取环境变量、调用函数、使用 `**kwargs`，或动态计算 schedule 值。
:::

:::js
- 可以使用 literals、arrays、objects，以及对顶层 literal constants 的引用。
- 不要读取环境变量、调用函数、spread objects，或动态计算 schedule 值。
:::

- 需要动态行为时，请把逻辑放到 agent、tools、middleware 或 runtime context 中。

## 部署 schedules

<ManagedDeepAgentsTestAndDeploy />

当 deployment 进入 `DEPLOYED` 状态后，`mda deploy` 会查找部署目标上已有的 Managed Deep Agents-owned cron jobs，删除它们，再根据当前 `schedules/` 声明创建新的 cron jobs。删除本地 schedule 文件并重新部署，就会移除对应的托管 cron。

<Warning>
如果你使用 `--no-wait` 进行部署，CLI 会在远程 build 触发后立即退出，而不会等待 deployment 进入 `DEPLOYED`，因此这次调用不会对 schedules 执行 reconcile。添加、修改或删除 schedules 时，请使用不带 `--no-wait` 的 `mda deploy .`。
</Warning>

## 排查 schedules 问题

:::python
- `must export a named schedule declaration`：请在 `schedules/` 中的每个文件里定义顶层 `schedule`。
:::

:::js
- `must export a named schedule declaration`：请在 `schedules/` 中的每个文件里导出顶层 `schedule`。
:::

- `must define exactly one of prompt or input`：请只设置 `prompt` 或 `input` 其中之一，不能同时设置。
- `cron must be a standard 5-field expression`：请使用五段式 cron，而不是带 seconds 的 cron 语法。
- `schedule is not static`：请把计算值替换为 literals 或顶层 literal constants。
- `failed to create cron for schedule`：请在 LangSmith 中打开 deployment URL，确认部署后的 Agent Server 处于健康状态。
