[模型配置](/langsmith/model-configurations)是命名的、可复用的定义，它把 provider 和 model 与凭证及设置组合在一起。把 model ID 设置为 `custom/<name>` 时，LLM Gateway 就能通过一条已保存的配置来路由请求。当需要访问带 provider 前缀的 model ID 无法寻址的 endpoint 时，可以使用配置，例如自定义的 OpenAI 兼容 endpoint。

## 了解 gateway 使用了什么

bring-your-own-key gateway 调用通常指向一个带 provider 前缀 ID 的模型，例如 `openai/gpt-5.4-mini`。当 model ID 为 `custom/<name>` 时，gateway 会改为从已保存的配置中读取以下内容：

- **Provider 和 model**：gateway 会向上游发送配置中的模型名称，替换请求体中的 `custom/<name>` 值。
- **API key secret**：gateway 使用配置中指定的 workspace secret 向 provider 进行认证。
- **连接设置**：base URL、OpenAI provider API（Chat Completions 或 Responses）、Vertex AI 的 project 和 location，以及 Amazon Bedrock 的 **Preferred Bedrock Endpoint**，provider 会按需使用这些设置。只有 gateway 会读取 Bedrock endpoint 设置。

gateway 会忽略保存在配置上的生成参数，例如 temperature、top P 和 max output tokens。请改为在每次 API 请求中传入这些参数。

工作区管理员可以在 **Settings** > **Model configurations** 下创建配置，组织管理员可以创建[组织范围的配置](/langsmith/model-configurations#organization-scoped-model-configurations)。具体步骤请参见[创建配置](/langsmith/model-configurations#create-a-configuration)。

## 选择配置类型

gateway 可以为以下 providers 调用配置：

- **自定义 endpoint**：OpenAI 兼容、Anthropic 兼容和 [TypeSafe 兼容](/langsmith/compatible-decision-model-provider) endpoint。
- **内置 provider**：Anthropic、Amazon Bedrock、Fireworks、Gemini Enterprise Agent Platform、Google Gemini、OpenAI、TypeSafe 和 xAI。

为任何其他 provider 创建的配置都会返回错误。每种自定义 endpoint 类型处理其 URL 的方式不同：

- **OpenAI 兼容**：base URL 是 API 根路径。gateway 会附加请求路径，例如 `/chat/completions`，不会额外添加 `/v1`，因此如果服务器需要 `/v1`，请在 base URL 中包含它。
- **Anthropic 兼容**：gateway 会完全按输入的 URL 发送请求，因此请输入完整的 Messages endpoint，例如 `https://example.com/v1/messages`。仅支持 Messages 请求。
- **TypeSafe 兼容**：gateway 会附加 `/v1/systemone`，除非你清除 **Append /v1/systemone**，此时它会完全按输入的 URL 使用。

## 通过 gateway 调用配置

在任意标准 gateway 请求中，把 `custom/<name>` 用作 model ID，并将 `<name>` 替换为该配置在 **Settings** > **Model configurations** 中显示的准确名称：

<CodeGroup>

```bash Cloud
curl https://gateway.smith.langchain.com/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"custom/my-openai-config","input":"Hello!"}'
```

```bash BYOC
curl https://<data_plane_host>/gateway/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"custom/my-openai-config","input":"Hello!"}'
```

</CodeGroup>

gateway 会在 API key 所属工作区中按名称查找配置，包括[组织范围的模型配置](/langsmith/model-configurations#organization-scoped-model-configurations)，将请求路由到配置的 provider 和 endpoint，并以 client 所使用的 [API 格式](/langsmith/llm-gateway-api-formats)返回响应。当工作区配置和组织范围的配置同名时，gateway 会使用工作区配置。

gateway 不会检查 [Feature Access](/langsmith/model-configurations#feature-access) 表，因此无需在工作区中启用，就可以调用组织范围的配置。它还会忽略保存在配置上的 [OAuth client credentials](/langsmith/model-configurations#oauth-client-credentials)，并使用配置的 API key secret 进行认证。

已保存的配置不会出现在 `GET /v1/models` 列表中，因此请直接与开发者共享配置名称。

如果某条[模型访问策略](/langsmith/llm-gateway-model-access-policies#allow-saved-model-configurations)适用于该请求，该策略必须允许已保存的模型配置，否则 gateway 会返回 `403` 响应。

已保存的配置也可以作为 fallback 链中的主模型或备用模型。具体步骤（包括如何让 Playground prompt 拥有自己的 fallback 行为）请参见[模型 fallback](/langsmith/llm-gateway-fallbacks)。
