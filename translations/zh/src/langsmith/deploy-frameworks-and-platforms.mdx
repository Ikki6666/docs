以下页面提供参考实现，展示如何在 JavaScript 框架和托管平台上把 LangChain agents 运行到生产环境中。[deployment cookbook repository](https://github.com/langchain-ai/deployment-cookbook) 里的每个示例，都是一个完整的全栈聊天应用，具备流式 UI、subagents 和 thread history，并通过相同的 [Agent Streaming Protocol](https://github.com/langchain-ai/agent-protocol/tree/main/streaming) 部署在不同平台上。

当你需要交付一个由 agent 驱动的产品时，可以使用这些指南：复制与你托管环境匹配的技术栈，换成你自己的 tools 和 models，并在不再满足于单实例时升级持久化能力。

## 一个 agent deployment 由哪些部分组成

每个示例都遵循相同的结构。变化的是框架和托管方式，不变的是职责分工。

### Agent runtime

Agent 本身，通常是一个 LangGraph graph 或 [`deepagents`](https://www.npmjs.com/package/deepagents) 协调器，包含 tools、可选 subagents 和 middleware。它会结合 **checkpointer** 一起编译，使会话状态能够跨轮次保留。示例中为了简洁，通常从内存版 `MemorySaver` 开始；生产部署则会切换到 Redis（[`@langchain/langgraph-checkpoint-redis`](https://www.npmjs.com/package/@langchain/langgraph-checkpoint-redis)）、Postgres（[`@langchain/langgraph-checkpoint-postgres`](https://www.npmjs.com/package/@langchain/langgraph-checkpoint-postgres)）、SQLite（[`@langchain/langgraph-checkpoint-sqlite`](https://www.npmjs.com/package/@langchain/langgraph-checkpoint-sqlite)）或平台特定存储。

### Protocol server

HTTP route handlers 会在 `/api/threads/...` 下实现 [Agent Streaming Protocol](https://github.com/langchain-ai/agent-protocol/tree/main/streaming)。

#### 最小集合（流式聊天）

对于 `HttpAgentServerAdapter` 来说，以下三个 endpoints 就足以支撑一个单 thread 的流式聊天：

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/threads/:threadId/commands` | 接收命令（`run.start` 等）并启动 runs |
| `POST` | `/api/threads/:threadId/stream` | 提供某个 run 的协议事件 SSE 流 |
| `GET` / `POST` | `/api/threads/:threadId/state` | 读取并初始化带 checkpoint 的 thread state |

#### Thread 侧边栏（所有示例）

每个示例还实现了 thread history 侧边栏所需的 endpoints：

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/threads` | 列出 checkpointer 中已知的 threads |
| `DELETE` | `/api/threads/:threadId` | 删除某个 thread 的 session 与 checkpoints |
| `POST` | `/api/threads/:threadId/history` | 分页返回 checkpoint history |

### Session 和 run 管理

服务端逻辑会跟踪活跃 runs，把命令桥接给 agent，并通过 SSE 广播实时事件。借助 registry 或 session store，客户端可以重新连接到进行中的流。在 serverless 或多实例托管平台上，这一层必须是共享的，或者与 checkpointer 共址。

### Chat frontend

浏览器 UI 通过 [`@langchain/react`](https://www.npmjs.com/package/@langchain/react)、[`@langchain/vue`](https://www.npmjs.com/package/@langchain/vue)、[`@langchain/svelte`](https://www.npmjs.com/package/@langchain/svelte) 或 [`@langchain/angular`](https://www.npmjs.com/package/@langchain/angular) 中的 `HttpAgentServerAdapter` 接入协议。客户端会初始化 thread state、提交消息、消费 SSE 流，并渲染 tokens、tool calls、reasoning 和 subagent activity。

这些绑定本身不附带任何组件。像 `useStream` 这样的 hooks 只会返回普通的响应式状态（messages、tool calls、loading flags、thread metadata），具体如何接到视觉层，由你自己决定。关于 adapter 模式及其取舍，请参阅[frontend integrations 概览](/oss/langchain/frontend/integrations/overview)。
