<Info>
自托管 LangSmith 是 Enterprise plan 的附加能力，面向 LangChain 规模最大、最重视安全性的客户。更多细节请参阅 [Pricing](https://www.langchain.com/pricing)。如果你需要 license key 以在自己的环境中试用 LangSmith，请[联系销售团队](https://www.langchain.com/contact-sales)。
</Info>

本指南介绍如何在 Kubernetes 集群中设置 LangSmith。你将使用 Helm 安装 LangSmith 及其依赖项。

完成本指南后，你将拥有：

- **LangSmith UI 和 API**：可观测性、追踪、评估、Insights 和 Chat。
- **后端服务**：queue、playground 和 ACE。
- **数据存储**：PostgreSQL、Redis、ClickHouse，以及可选的 blob 存储。

LangSmith 可以运行在任何符合规范的 Kubernetes 集群上。它已在以下发行版上完成测试：

- Google Kubernetes Engine (GKE)
- Amazon Elastic Kubernetes Service (EKS)
- Azure Kubernetes Service (AKS)
- OpenShift 4.14 或更高版本
- Minikube 和 Kind（用于开发环境）

<Tip>
**想用基础设施即代码？** [Deploy with Terraform](/langsmith/self-host-terraform) 会把 AWS、Azure 和 GCP 的集群预配、secrets 配置以及 Helm release 整合到一个流程中。本指南介绍的是仅使用 Helm 的方式，适用于你已自行管理的任意兼容集群。
</Tip>

## 前置条件

要在 Kubernetes 上自托管 LangSmith，请在安装前准备好以下内容。

### 工具

- **kubectl**：用于访问你的 Kubernetes 集群。
- **Helm**：安装 LangSmith chart 的包管理器。安装方法请参见 [Helm 文档](https://helm.sh/docs/intro/install/)。
- **OpenSSL**：用于生成 API key salt 和 JWT secret。
- **Python（需安装 `cryptography` 包）**：用于生成 Insights 和 Chat 的加密密钥。

### 密钥和 secret

- **LangSmith license key**：从你的 LangChain 对接人员处获取。[联系销售团队](https://www.langchain.com/contact-sales)可了解更多信息。
- **API key salt** 和 **JWT secret**：随机字符串。LangSmith 使用 salt 对静态存储的 API key 进行哈希，并使用 JWT secret 为 basic auth 的 token 签名。请为两者分别生成不同的值：

  ```bash
  openssl rand -base64 32
  ```

- **Insights 和 Chat 加密密钥**：Insights 和 Chat（原 Polly）在 Helm chart 0.15.1 或更高版本中默认启用。每个功能在安装时都需要一个 Fernet 加密密钥。请为每个功能分别生成一个密钥：

  ```bash
  python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
  ```

### Kubernetes 集群

你需要一个可以通过 `kubectl` 访问、可正常工作的 Kubernetes 集群。集群至少需要满足以下资源要求：

1. 建议：至少可用 16 个 vCPU、64GB 内存。

   * 你可能需要根据组织规模和使用情况，为每个服务调优资源请求与限制。建议请参见[自托管扩缩容指南](/langsmith/self-host-scale)。
   * 使用 cluster autoscaler，根据资源使用情况自动扩缩节点。
   * 设置 metrics server，以便启用自动扩缩容。
   * 如果你在集群内部运行 ClickHouse，则必须至少有一个节点具备 4 个 vCPU 和 16GB **allocatable** 内存，因为 ClickHouse 默认会请求这部分资源。

2. 集群中需要有可用的动态 PV provisioner 或 PV（仅当数据存储运行在集群内部时需要）。

   * 为了启用持久化，LangSmith 会尝试为所有在集群内运行的数据存储预配卷。
   * 如果你在集群中使用 PV，请在生产环境中配置备份。
   * **请使用 SSD 支持的 storage class 以获得更好性能。LangChain 建议 7000 IOPS 和 1000 MiB/s 吞吐量。**
   * 在 EKS 上，你可能需要安装并配置 `ebs-csi-driver` 以支持动态预配。更多信息请参见 [EBS CSI Driver 文档](https://docs.aws.amazon.com/eks/latest/userguide/ebs-csi.html)。

   请运行以下命令进行验证：

   ```bash
   kubectl get storageclass
   ```

   输出中应至少包含一个支持动态预配的 storage class。例如：

   ```txt
   NAME            PROVISIONER                 RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
   gp2 (default)   ebs.csi.eks.amazonaws.com   Delete          WaitForFirstConsumer   true                   161d
   ```

   <Note>
   请使用支持卷扩容的 storage class。trace 可能会占用大量磁盘空间，卷大小也可能需要随着时间推移进行扩展。
   </Note>

   更多信息请参见 [Kubernetes 文档](https://kubernetes.io/docs/concepts/storage/storage-classes/) 中关于 storage class 的内容。

<Note>
LangSmith 服务默认从 0.14.0 起同时监听 IPv4 和 IPv6。IPv4-only、IPv6-only 或双栈集群均无需额外配置。
</Note>

### 网络访问

- **许可证校验**：除非以离线（air-gapped）模式运行，LangSmith 需要访问 `https://beacon.langchain.com` 的出口，用于许可证校验和用量上报。详情请参见 [Egress](/langsmith/self-host-egress)。
- **模型 provider 访问**：Insights 和 Chat 需要 [provider 凭据和模型配置](/langsmith/model-configurations)。如果你的集群无法访问互联网，请在安装前确认集群可以访问哪些模型 provider endpoint。
- **容器镜像和 chart**：如果你的集群无法访问公共 registry，请[镜像同步 LangSmith 镜像](/langsmith/self-host-mirroring-images)到你自己的 registry，并从本地 chart 安装。

### 数据存储

LangSmith 使用 PostgreSQL 数据库、Redis 缓存，以及 ClickHouse 数据库来存储 trace。默认情况下，这些服务会安装在 Kubernetes 集群内部。生产环境中请改用外部数据存储。对于 PostgreSQL 和 Redis，最佳选择通常是云厂商提供的托管服务。

更多信息请参见以下外部服务配置指南：

- [PostgreSQL](/langsmith/self-host-external-postgres)
- [Redis](/langsmith/self-host-external-redis)
- [ClickHouse](/langsmith/self-host-external-clickhouse)

各数据存储支持的最低版本，请参见[自托管依赖的最低版本要求](/langsmith/self-host-dependency-versions)。[SmithDB](/langsmith/self-host-smithdb) 是一个可选的数据存储，可在基础安装完成后启用。本指南不需要它。

## 配置 Helm chart

1. 创建一个名为 `langsmith_config.yaml` 的新文件。只设置你的安装所需的配置项：

   * 如果你刚接触 Kubernetes 或 Helm，请从 [LangSmith Helm chart 示例](https://github.com/langchain-ai/helm/tree/main/charts/langsmith/examples)开始。
   * 完整配置项列表请参见 [LangSmith Helm chart `values.yaml`](https://github.com/langchain-ai/helm/tree/main/charts/langsmith/values.yaml)。

   <Warning>
   只在 `langsmith_config.yaml` 中覆盖你需要的设置。不要复制整个 `values.yaml`。让配置保持最小化，可以确保你继续继承 Helm chart 的新默认值和升级项。
   </Warning>

   <Tip>
   如果你的集群强制执行非 root 或只读容器策略，请从[只读 Helm 配置示例](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/examples/read_only_config.yaml)开始。LangSmith 容器不需要 root 权限。该示例展示了如何设置 `runAsNonRoot`、服务的 UID 和 GID、`fsGroup`、`RuntimeDefault` seccomp profile、移除 capability、禁用提权，以及为需要临时存储的服务挂载可写 `emptyDir`。
   </Tip>

2. 请设置以下最低配置项（使用 basic auth），并使用[前置条件](#keys-and-secrets)中的密钥和 secret：

   <Warning>
   `apiKeySalt` 只能设置一次，之后不要再改。该值用于对所有静态存储的 API key 进行哈希。轮换它会永久使组织中现有的所有 API key 失效，届时所有用户都必须重新生成自己的 key。
   </Warning>

   ```yaml
   config:
     langsmithLicenseKey: "<your license key>"
     apiKeySalt: "<your api key salt>"
     authType: mixed
     initialOrgAdminEmail: "admin@langchain.dev" # Change this to your admin email address
     basicAuth:
       enabled: true
       initialOrgAdminPassword: "secure-password" # Must be at least 12 characters long and have at least one lowercase, uppercase, and symbol
       jwtSecret: "<your jwt secret>" # A random string of characters used to sign JWT tokens for basic auth.

   insights:
     enabled: true # Enabled by default; key required
     encryptionKey: "<insights-encryption-key>"

   polly:
     enabled: true # Enabled by default; key required
     encryptionKey: "<chat-encryption-key>"
   ```

   如需将密钥存入已有的 Secret，或禁用 Insights 或 Chat，参见[配置 Insights 和 Chat](/langsmith/self-host-insights-chat)。

3. 如果你使用外部数据存储，请添加它们的连接信息。

## 部署到 Kubernetes

1. 确认你可以连接到 Kubernetes 集群。请安装到一个空的 namespace 中。

   1. 运行 `kubectl get pods`

      输出应类似如下：

      ```txt
        langsmith-eks-2vauP7wf 21:07:46 No resources found in default namespace.
      ```

   <Note>
   如果你使用的不是默认 namespace，请在 `helm` 和 `kubectl` 命令中通过 `-n <namespace>` 指定对应 namespace。
   </Note>

2. 确保已经添加 LangChain Helm 仓库（如果你使用的是本地 chart，可以跳过此步骤）。

   ```bash
   helm repo add langchain https://langchain-ai.github.io/helm
   ```

3. 查找 chart 的最新版本。可在 [Helm Chart 仓库](https://github.com/langchain-ai/helm/releases)中查看可用版本。

   * LangChain 建议使用最新版本。
   * 你也可以运行 `helm search repo langchain/langsmith --versions` 查看可用版本，输出类似如下：

   ```txt
    langchain/langsmith              	0.13.0      	0.13.1    	Helm chart to deploy the langsmith application ...
    langchain/langsmith              	0.12.34      	0.12.73    	Helm chart to deploy the langsmith application ...
    langchain/langsmith              	0.12.33      	0.12.72    	Helm chart to deploy the langsmith application ...
    langchain/langsmith              	0.12.32      	0.12.70    	Helm chart to deploy the langsmith application ...
    langchain/langsmith              	0.12.31      	0.12.69    	Helm chart to deploy the langsmith application ...
   ```

4. 运行 `helm upgrade -i langsmith langchain/langsmith --values langsmith_config.yaml --version <version> -n <namespace> --wait --debug`

   * 将 `<namespace>` 替换为你希望部署 LangSmith 的 namespace。
   * 将 `<version>` 替换为上一步中选择的 LangSmith 版本。大多数用户都应该安装当前可用的最新版本。

   <Note>
   使用 `-n <namespace>` 指定的 namespace 必须在运行此命令之前已存在。如果不存在，可以先使用 `kubectl create namespace <namespace>` 创建它，或者在上面的 helm 命令中添加 `--create-namespace` 标志。
   </Note>

   当 `helm install` 命令成功完成后，你应看到类似如下的输出：

   ```txt
   NAME: langsmith
   LAST DEPLOYED: Fri Sep 17 21:08:47 2021
   NAMESPACE: langsmith
   STATUS: deployed
   REVISION: 1
   TEST SUITE: None
   ```

   这个过程可能需要几分钟，因为它会创建多个 Kubernetes 资源，并运行若干作业来初始化数据库及其他服务。

5. 运行 `kubectl get pods`。此时输出应类似如下（注意：具体 Pod 名称可能因版本和配置不同而有所变化）：

   ```txt
    langsmith-ace-backend-98fbd468c-x9gjl         1/1     Running   0
    langsmith-backend-84999bbcb7-dfhml            1/1     Running   0
    langsmith-clickhouse-0                        1/1     Running   0
    langsmith-frontend-79bdcbccc6-r7pt7           1/1     Running   0
    langsmith-ingest-queue-cbb67748-8rl8x         1/1     Running   0
    langsmith-platform-backend-586bd9d97c-2g5mv   1/1     Running   0
    langsmith-playground-859d44b46c-fjqjh         1/1     Running   0
    langsmith-postgres-0                          1/1     Running   0
    langsmith-queue-7bd6cb8b9b-bmvxm              1/1     Running   0
    langsmith-redis-0                             1/1     Running   0
   ```

## 后续步骤

完成本指南后，你的 LangSmith 实例应该已经运行，但可能尚未完成全部配置。

1. 使用你在 `langsmith_config.yaml` 中设置的管理员邮箱地址和密码登录。
2. 为 Insights 和 Chat 配置模型访问。参见[配置模型访问](/langsmith/self-host-insights-chat#configure-model-access)。
3. 将你的 agent 指向该实例并开始追踪。参见[与你的自托管实例交互](/langsmith/self-host-usage)。
4. 与基础设施管理员协作完成以下事项：

   * 为 LangSmith 实例配置 DNS，以便更方便地访问。
   * 配置 SSL，确保提交到 LangSmith 的 trace 在传输过程中被加密。
   * 为 LangSmith 配置 [Single Sign-On](/langsmith/self-host-sso)，提升实例安全性。
   * 配置用于存储大文件的 [blob 存储](/langsmith/self-host-blob-storage)。

5. 可选：添加 Sandboxes、Engine、Fleet 或 LangSmith Deployment。在[配置其他自托管功能](/langsmith/self-host-additional-features)中，只需遵循你的使用场景所需的设置指南。
