LangSmith 提供了多种工具，帮助你更高效地管理 [_prompts_](/langsmith/prompt-engineering-concepts)。本页介绍以下功能：

- [Environments](#environments)，用于在 **Staging** 与 **Production** 之间提升 commit。
- [Commit tags](#commit-tags)，用于版本控制和环境管理。
- [Prompt owners](#prompt-owners)，用于控制谁可以提升 commit 以及删除 prompt。
- [Webhook triggers](#trigger-a-webhook-on-prompt-commit)，用于在 prompt 更新时自动触发工作流。
- [Public prompt hub](#public-prompt-hub)，用于发现并使用社区创建的 prompts。

## Prompt 详情页

从 [**Prompts** 表格](/langsmith/create-a-prompt#view-your-prompts) 中选择一个 prompt，可打开它的详情页。页面采用双栏布局：左侧显示 commit 历史和环境，右侧显示 commit 详情。

你可以通过切换右上角的 **Diff**，将某个 commit 与它的前一个版本进行比较。

## Environments

Environment 代表命名的部署目标，即 **Staging** 和 **Production**，你可以将它们绑定到特定 commit。它们帮助你追踪每个环境当前启用的是哪个 prompt 版本，以及在不同环境之间提升 commit。

Environment 是通过保留的 [commit tags](#commit-tags)（`staging` 和 `production`）定义的，这些标签通过提升 UI 管理，而不是在自由输入的 tag 选择器中手动设置。

### 提升一个 commit

提升一个 commit 会将它分配给某个 environment。你可以把任意 commit 提升到 Staging 或 Production。

提升步骤如下：

1. 将鼠标悬停在左侧栏中的某个 commit 上，会显示 **Promote**，或者点击页面右上角的 **Promote**。然后从下拉菜单中选择 **Staging** 或 **Production**。
2. 系统会打开一个部署模态框，显示该 environment 当前绑定的 commit 以及即将被替换的版本。
3. 确认提升后，environment 指针会立即更新。

<Note>
将某个 commit 提升到 Production 并不会把它从 Staging 中移除。如果某个 commit 已经在 Staging 中，而你又把它提升到了 Production，它依然会保留在 Staging 中。
</Note>

### 回滚一个 environment

每个 environment 都会维护一份按时间排序的历史记录，记录曾经指向过哪些 commit，以及对应时间。若要回滚到先前的 commit：

1. 在左侧栏中找到你想回滚的 environment。
2. 点击该 environment 对应的回滚图标。
3. 在出现的 **Rollback history** 中，选择你要回滚到的 commit。environment 指针会更新到该 commit。

## Commit tags

[_Commit tags_](/langsmith/prompt-engineering-concepts#tags) 是指向某个特定 [_commit_](/langsmith/prompt-engineering-concepts#commits) 的标签。它们可以帮助你标记重要版本，并控制不同环境运行哪个版本。与其在代码中直接引用 commit ID，不如引用 tag，这样你就能在不修改代码的情况下切换实际使用的版本。

每个 tag 在任意时刻只指向一个 commit，但你可以重新将它指向其他 commit。

<Note>
**保留标签：** `staging` 和 `production` 是用于 environment 管理的保留标签，不能在自由输入的 tag 选择器中设置。请通过[提升流程](#promote-a-commit)来为这些 environment 分配 commit。
</Note>

<Note>
**不要与 resource tags 混淆**：Commit tags 专用于 prompt 版本管理，指向 prompt 历史中的某个单独 commit。[Resource tags](/langsmith/set-up-resource-tags) 则是用于组织工作区资源（如项目、数据集和 prompts）的键值对。虽然两者都可能使用类似 `prod` 或 `staging` 这样的命名，但 commit tags 控制的是 prompt **运行哪个版本**，而 resource tags 用于在工作区中**组织和筛选**资源。
</Note>

### 创建 tag

要创建一个 tag，请先在 prompt 详情页左侧栏中选择你要打标的 commit。然后点击右侧栏右上角的 **Tag**。在下拉菜单中点击 **Commit Tag**，并输入名称。

### 移动 tag

如果你想把某个 tag 指向另一个 commit，请先在 prompt 详情页左侧栏中选择目标 commit。然后点击右侧栏右上角的 **Tag**，并在下拉菜单中选择要移动的 tag。系统会自动把该 tag 更新为指向新的 commit。

### 删除 tag

如果你想删除某个 tag，点击右侧栏右上角的 **Tag**。（此时选中哪个 commit 无关紧要。）在下拉菜单中点击目标 tag 旁边的删除图标。这样会彻底移除该 tag，它将不再关联到任何 commit。

### 在代码中使用 tag

Tag 为你在代码中引用 prompt 的特定版本提供了一种稳定方式。与其直接写死 commit hash，不如引用一个可更新的 tag，这样无需改动代码即可切换所使用的版本。

下面是一个在 Python 中按 tag 拉取 prompt 的示例：

```python
prompt = client.pull_prompt("joke-generator:production")
# If production tag points to commit a1b2c3d4, this is equivalent to:
prompt = client.pull_prompt("joke-generator:a1b2c3d4")
```

关于如何在代码中使用 prompts，请参见 [Managing prompts programmatically](/langsmith/manage-prompts-programmatically)。

## Prompt owners

Prompt owners 功能可以让你更细粒度地控制谁能够为特定 prompt 打 tag 和删除 prompt。这对于生产环境的提升流程很有帮助，例如你希望只允许特定成员通过分配或移动 tag 的方式，将某个 commit 提升到特定 environment。

### 访问模式

每个 prompt 都有两种访问模式，可在 [UI](https://smith.langchain.com) 的 **Access and Permissions** 中进行配置：

- **Workspace authorized users**（默认）：工作区中任何拥有 [`prompts:tag`](/langsmith/organization-workspace-operations#prompts) 权限的用户，都可以创建、更新和删除 tag，也可以删除该 prompt。
- **Owners only**：只有被添加为 prompt owner 的用户，才能创建或更新 commit tags、将 commit 提升到 environment，以及删除该 prompt。

LangSmith 会自动将 prompt 的创建者添加为 owner。

### 配置访问与权限

1. 在 LangSmith UI 中打开该 prompt。
2. 点击右上角的 <Icon icon="dots-vertical"/> **More** 图标，并选择 **Access and Permissions**。
3. 选择 **Owners only** 模式。
4. 添加或移除 owners 组中的用户。

<Warning>
如果你保存的变更把自己从 owner 中移除了，你将失去管理 owners 或将该 prompt 切回 workspace authorized users 模式的能力。只有其他 owner 才能恢复你的访问权限。
</Warning>

当 **Owners only** 模式启用后，只有 owner 可以关闭该模式，或添加、移除其他 owners。

## 在 prompt commit 时触发 webhook

你可以配置一个 webhook，在某个 prompt 有新 commit 时自动触发。

常见用途包括：

* 当 prompt 更新时触发 CI/CD pipeline。
* 将 prompts 与 GitHub 仓库同步。
* 向团队成员通知 prompt 修改。

### 配置 webhook

在左侧边栏或应用首页中进入 **Prompts**。然后点击右上角的 `+ Webhook` 按钮。

添加 webhook URL 以及所需的请求头。

<Note>
每个 workspace 目前只能配置一个 webhook。如果你希望每个 workspace 支持多个 webhook，或为不同 prompt 配置不同 webhook，欢迎在 [LangChain Forum](https://forum.langchain.com/) 中告诉我们。
</Note>

若要测试 webhook，可点击 **Send test notification** 按钮。系统会向你提供的 webhook URL 发送一条带示例 payload 的测试通知。

示例 payload 是一个 JSON 对象，包含以下字段：

- `prompt_id`: 被提交的 prompt ID。
- `prompt_name`: 被提交的 prompt 名称。
- `commit_hash`: 该 prompt 的 commit hash。
- `created_at`: 该 commit 的时间。
- `created_by`: 该 commit 的作者。
- `manifest`: prompt 的 manifest。

### 触发 webhook

只要对某个 prompt 执行 commit，就会触发你配置好的 webhook。

#### 在 Playground 中

如果你是在 Playground 中执行 commit，系统会提示你取消选择那些你不想触发的 webhooks。

![Commit Playground](/langsmith/images/commit-playground.png)

#### 使用 API

如果你通过 API 提交 commit，可以通过将 `skip_webhooks` 参数设置为 `true`，或者传入一个需要忽略的 webhook id 数组，来跳过 webhook 触发。详见 [API docs](/langsmith/smith-api/commits/create-a-commit)。

## Public prompt hub

LangSmith 的 public prompt hub 是由 LangChain 社区创建的一组 prompts 集合，你可以用它们作为参考。

<Note>
请注意，这些 prompts 由用户生成且未经验证。LangChain 不会审核或背书 public prompts，请自行评估风险。使用 Prompt Hub 时还需遵守我们的 [Terms of Service](https://www.langchain.com/terms-of-service)。
</Note>

进入左侧边栏的 **Prompts**，然后点击 **Browse all Public Prompts in the LangChain Hub**。

你将在这里看到 LangChain Hub 中所有公开列出的 prompts。你可以按名称、handle、use case、描述或模型搜索 prompts。你可以将 prompts fork 到个人组织、查看 prompt 详情，或者在 Playground 中运行它。你也可以使用 SDK [把任意 public prompt 拉到你的代码中](/langsmith/manage-prompts-programmatically)。

如果你想查看与自己工作区相关的 prompts，请直接进入侧边栏中的 **Prompts**。

![Prompts tab](/langsmith/images/prompts-tab.png)
