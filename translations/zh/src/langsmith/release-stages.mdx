LangSmith 通过三个发布阶段交付功能：alpha、beta 和 generally available（GA）。每个阶段都为功能的稳定性、运行环境和支持方式设定了一致预期，帮助你决定何时采用。

随着功能成熟，它会在这些阶段间推进，不过较小的功能也可能跳过 alpha 或 beta，直接以 GA 上线。下表总结了各阶段。

| Stage | Availability | Changes | Self-hosted / BYOC | Support |
|-------|-------------|-----------|----------------------|---------|
| [Alpha](#alpha) | 仅限 design partners | 预期会有 breaking changes；功能可能大幅变化，甚至永不发布 | 不保证提供 | 无正式 SLA |
| [Beta](#beta) | 公开或面向某个私有群体 | 接口或行为仍可能变化；预计几个月内达到 GA | 通常会在 beta 阶段加入 | 积极维护中；SLA 因功能而异 |
| [GA](#generally-available-ga) | 公开 | 稳定；breaking changes 需要经过弃用周期 | 支持 | 完整支持 |

## Alpha

Alpha 是最早的发布阶段，用于在更广泛发布之前，先与一小部分受众验证功能。

- **Availability**：仅对 design partners 开放。Alpha 功能不会公开宣布。
- **Readiness**：可能不完整或仅为部分实现，其目的是早期验证，而不是生产使用。
- **Changes**：breaking changes 是预期中的。功能可能大幅变化，甚至可能永远不会以 GA 发布。
- **Pricing**：没有定价承诺。
- **Deployments**：不一定会在 self-hosted 或 BYOC 环境中提供。
- **Support**：不适用 SLA。

Alpha 是可选阶段，某些功能可能会跳过它。

## Beta

Beta 会让某个功能可以在真实场景中使用，同时其接口和行为仍在最终定型。Beta 功能是端到端可用的，而不是不完整实现，因此你可以在生产工作流中采用它们，并在它们走向 GA 之前参与打磨。

- **Availability**：面向公众或某个私有群体开放，并在适用时于产品 UI 和文档中标记为 `Beta`。
- **Readiness**：端到端可用，适合真实工作流。
- **Changes**：在功能达到 GA 前，接口或行为仍可能变化，通常预计会在几个月内进入 GA。
- **Pricing**：可能已有定价，但尚未最终确定。
- **Deployments**：对 self-hosted 和 BYOC 环境的支持通常会在 beta 阶段加入。
- **Support**：Beta 功能会基于反馈持续维护和改进。SLA 覆盖范围因功能而异。

Beta 也是可选阶段。较小的功能可能会跳过它。

## Generally available (GA)

GA 功能稳定且得到完整支持，可用于生产环境。

- **Availability**：公开可用。
- **Readiness**：完整且可用于生产。
- **Changes**：API 行为稳定。breaking changes 需要经过弃用周期。
- **Pricing**：定价已最终确定。
- **Deployments**：在所有环境中都受支持，包括 self-hosted 和 BYOC。
- **Support**：完整支持并有充分文档。

任何未被标记为 alpha 或 beta 的功能都视为 GA，并会立即且持续受到支持。LangSmith 可能偶尔弃用某个 generally available 功能，但这并不常见。
