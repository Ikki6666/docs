基于角色的访问控制（RBAC）决定谁可以访问你的 LangSmith 组织和[工作区](/langsmith/administration-overview#workspaces)，以及他们在其中可以执行哪些操作。

每个用户都有：

- 一个在整个组织中生效的[组织角色](#organization-roles)。
- 在其所属的每个工作区中各有一个[工作区角色](#workspace-roles)。

用户还可以通过[用户组](/langsmith/user-groups)获得额外的工作区角色。此时，该用户同时拥有其已分配角色的权限，以及每个用户组在该工作区中的角色所授予的权限。

你可以分配哪些角色取决于你的[方案](https://langchain.com/pricing)：

- **Developer**：每个用户都拥有 Organization Admin 和 Workspace Admin 角色。
- **Plus**：所有组织角色均可用。每个工作区成员都拥有 Workspace Admin 角色。
- **Enterprise**：所有组织角色和工作区角色均可用，并且你可以创建[自定义角色](#custom-roles)。如需升级，请[联系销售团队](https://www.langchain.com/contact-sales)。

<Note>
要设置 RBAC 并分配角色，请参见[用户管理指南](/langsmith/user-management#set-up-access-control)。你的身份提供方还可以通过 [SCIM 组](/langsmith/user-management#set-up-scim-for-your-organization) 或 [SSO Groups Sync](/langsmith/user-management#sso-groups-sync-alternative) 自动分配角色。关于每项操作所需的权限，请参见[组织与工作区操作参考](/langsmith/organization-workspace-operations)。
</Note>

## 组织角色

组织角色控制用户在组织范围内可以执行的操作，例如管理计费、成员和工作区。它们与[工作区角色](#workspace-roles)相互独立，后者控制对工作区内资源的访问。组织角色由系统预定义，不能修改，也不能扩展。

| 角色 | 说明 | 可用性 |
| --- | --- | --- |
| [Organization Admin](#organization-admin) | 对组织配置、用户、计费和工作区拥有完整管理权限 | 所有方案 |
| [Organization Operator](#organization-operator) | 拥有面向日常运营的工作区和用户管理权限，但不包含管理员级别权限 | [Plus 和 Enterprise](https://langchain.com/pricing) |
| [Organization User](#organization-user) | 可读取组织信息，并可创建个人访问令牌 | [Plus 和 Enterprise](https://langchain.com/pricing) |
| [Organization Viewer](#organization-viewer) | 对组织信息拥有只读权限 | [Plus 和 Enterprise](https://langchain.com/pricing) |
| [Organization Restricted](#organization-restricted) | 可访问工作区，但没有组织范围的读取权限 | [Plus 和 Enterprise](https://langchain.com/pricing) |

### Organization Admin

Organization Admin 角色对所有组织配置、用户、计费和工作区拥有完整管理权限。

**关键权限**：

| 权限 | 授予内容 |
|------|--------|
| `organization:manage` | 完整控制组织设置、SSO、安全和计费 |
| `organization:read` | 读取所有组织信息 |
| `organization:pats:create` | 创建组织级[个人访问令牌](/langsmith/administration-overview#personal-access-tokens-pats) |
| `organization:pats:read` | 查看所有组织成员的个人访问令牌 |
| `organization:pats:manage` | 停用、重新启用或删除任何组织成员的个人访问令牌 |

**关键能力**：

- 管理[组织设置](/langsmith/set-up-hierarchy#set-up-an-organization)和品牌配置
- 配置 [SSO 和认证方式](/langsmith/user-management#set-up-saml-sso-for-your-organization)
- 管理[计费](/langsmith/billing)和订阅方案
- 创建和删除工作区
- 邀请和移除组织成员
- 查看、停用、重新启用和删除任何成员的个人访问令牌
- 为成员分配组织角色和工作区角色
- 创建和管理[自定义角色](#custom-roles)
- 配置 RBAC 和[基于属性的访问控制（ABAC）](/langsmith/abac)策略
- 查看组织[用量](/langsmith/usage-and-billing#usage-limits)和分析数据
- 查看[审计日志](/langsmith/audit-logs)（Enterprise）

关于如何设置和管理组织，请参见[管理概览](/langsmith/administration-overview#organizations)。

### Organization Operator

Organization Operator 角色拥有面向日常运营的管理权限，包括工作区和用户管理，但不能管理 Organization Admin，也不能创建组织范围的服务密钥。

**关键权限**：

| 权限 | 授予内容 |
|------|--------|
| `organization:manage` | 管理组织设置、工作区和非管理员用户 |
| `organization:read` | 读取所有组织信息 |
| `organization:pats:create` | 创建个人访问令牌 |
| `organization:pats:read` | 查看所有组织成员的个人访问令牌 |
| `organization:pats:manage` | 停用、重新启用或删除任何组织成员的个人访问令牌 |

**关键能力**：

- 创建和管理[工作区](/langsmith/set-up-hierarchy#set-up-a-workspace)
- 邀请组织成员，可分配除 Organization Admin 之外的任何角色
- 修改和移除 Organization User、Viewer 和 Operator
- 查看、停用、重新启用和删除任何成员的个人访问令牌
- 为成员分配工作区角色
- 创建工作区范围的服务密钥和服务账户
- 管理组织计费和订阅方案
- 创建、编辑和删除自定义角色
- 配置 SSO 和认证方式
- 查看组织用量和分析数据
- 查看审计日志（Enterprise）

**限制**：

- 不能邀请、修改或移除 Organization Admin
- 不能把用户分配为 Organization Admin
- 不能创建组织范围（非工作区特定）的服务密钥
- 不会自动加入已有工作区。Organization Operator 只会加入自己创建的工作区，或被显式邀请的工作区。

### Organization User

Organization User 角色可读取组织信息，并能够创建个人访问令牌。

**关键权限**：

| 权限 | 授予内容 |
|------|--------|
| `organization:read` | 读取组织信息 |
| `organization:pats:create` | 创建个人访问令牌 |

**关键能力**：

- 查看组织成员和工作区
- 查看组织设置
- 创建用于 API 访问的个人访问令牌
- 加入被邀请进入的工作区

**限制**：

- 不能修改组织设置
- 不能管理计费或订阅
- 不能创建或删除工作区
- 不能邀请或移除组织成员
- 不能管理角色或权限

Organization User 可以属于部分工作区，并在每个工作区中拥有一个工作区角色，用于设置其在该工作区中的权限。

### Organization Viewer

Organization Viewer 角色对组织信息拥有只读访问权限。

**关键权限**：

| 权限 | 授予内容 |
|------|--------|
| `organization:read` | 读取组织信息 |

**关键能力**：

- 查看组织成员和工作区
- 查看组织设置

**限制**：

- 不能修改任何组织级内容
- 不能创建个人访问令牌
- 不能管理计费、工作区或成员

### Organization Restricted

Organization Restricted 角色允许访问分配给自己的工作区，但没有组织范围的读取权限。请将它分配给那些只应在自己的工作区中工作、不应看到其他组织成员或组织级详细信息的用户。

**关键权限**：

| 权限 | 授予内容 |
|------|--------|
| `organization:read-metadata` | 读取组织元数据，包括组织角色 |

**关键能力**：

- 查看组织元数据和角色定义。
- 在分配的工作区中工作，权限由各工作区的工作区角色设置。

**限制**：

- 不包含 `organization:read`，因此不能列出组织成员或服务密钥。
- 不能通过[即时（JIT）预配](/langsmith/jit-invite-sso)分配。通过 JIT 创建的新用户会获得 Organization User，而 SSO 默认角色设置仅适用于工作区角色。

分配 Organization Restricted 的方式与其他组织角色相同：通过成员邀请、[SCIM 组](/langsmith/user-management#group-naming-convention)或 [SSO Groups Sync](/langsmith/user-management#sso-groups-sync-alternative) 组匹配。

作用域为工作区的[服务密钥](/langsmith/administration-overview#service-keys)也可以持有该角色。创建或编辑作用域为 **Specific Workspaces** 的服务密钥时，请选择 Organization Viewer（默认）或 Organization Restricted。此选择不会改变谁可以创建或编辑服务密钥。

## 工作区角色

工作区角色控制用户和 API key 可以在工作区内对资源执行哪些操作。

| 角色 | 说明 |
| --- | --- |
| [Workspace Admin](#workspace-admin) | 对所有资源拥有完整权限，包括工作区设置和成员管理 |
| [Workspace Editor](#workspace-editor) | 对大多数资源拥有完整权限，但不能管理工作区设置，也不能删除某些资源 |
| [Workspace Viewer](#workspace-viewer) | 对所有工作区资源拥有只读访问权限 |
| [Fleet User](#fleet-roles) | 使用并评价共享给自己的 Fleet agents，但不能访问 traces |
| [Fleet Builder](#fleet-roles) | 拥有 Fleet User 权限，并可创建、编辑和删除 Fleet agents 与 skills |
| [Fleet Admin](#fleet-roles) | 拥有 Fleet Builder 权限，并可进行 Fleet 管理、管理工作区集成和 secrets、管理 deployments、读取 traces，以及管理工作区 |
| [Workspace Member Only](#workspace-member-only) | 仅具备工作区成员身份，本身没有任何权限 |

<Note>
LangSmith 还为 [LangSmith 创建的 keys](#roles-for-keys-that-langsmith-creates)定义了工作区角色。这些角色会出现在角色列表中，例如 service key 的角色选择器，但不适用于用户。
</Note>

### Workspace Admin

Workspace Admin 角色对工作区中的所有资源拥有完整权限，并且可以管理工作区本身。

**关键权限**：

- 对所有资源类型拥有创建、读取、更新、删除和共享权限。
- 工作区管理权限，包括 `workspaces:manage` 和 `workspaces:manage-members`。

### Workspace Editor

Workspace Editor 角色对工作区中的大多数资源拥有完整权限，但不能管理工作区设置，也不能删除某些关键资源。

**限制**：

- 不能删除 [runs](/langsmith/observability-concepts#runs)。
- 不能管理工作区设置，例如工作区名称。
- 不能管理工作区成员（添加、移除或更新成员角色）。

### Workspace Viewer

Workspace Viewer 角色对工作区中的所有资源拥有只读访问权限。

**关键权限**：

- 对所有资源类型拥有只读访问权限。

### Fleet 角色

Fleet 角色授予对 [Fleet](/langsmith/fleet/index) 的访问权限，但不包含 Workspace Editor 或 Workspace Admin 角色那样广泛的访问权限。每个角色都包含表中上一角色所拥有的权限：

| 角色 | 权限 |
|------|-------------|
| Fleet User | `fleet-agents:read`、`fleet-agents:invoke`、`fleet-skills:read`、`mcp-servers:read`、`mcp-servers:invoke`、`deployments:read`、`prompts:read`、`workspaces:read`、`feedback:read`、`feedback:update` 和 `feedback:delete`。无法访问 traces。 |
| Fleet Builder | Fleet User 权限，另加 `fleet-agents:create`、`fleet-agents:update`、`fleet-agents:delete`、`fleet-skills:create`、`fleet-skills:update` 和 `fleet-skills:delete`。 |
| Fleet Admin | Fleet Builder 权限，另加：<br/>• Fleet 管理：`fleet:read-admin-config`、`fleet:write-admin-config` 和 `workspaces:fleet-feedback:read-all`<br/>• MCP servers 和集成：`mcp-servers:create`、`mcp-servers:update`、`mcp-servers:delete` 和 `workspaces:integrations:manage`<br/>• Deployments、sandboxes 和 snapshots：`deployments:create`、`deployments:update`、`deployments:delete`、`sandboxes:read`、`snapshots:create` 和 `snapshots:delete`<br/>• Traces：`projects:read` 和 `runs:read`<br/>• 工作区管理：`workspaces:manage` 和 `workspaces:manage-secrets` |

Fleet Admin 包含 `workspaces:manage`，它也涵盖 Fleet 之外的工作区设置。它不包含 `workspaces:manage-members`。关于每项 Fleet 权限允许执行的操作，请参见 [Fleet access and oversight](/langsmith/fleet/access-and-oversight#configure-a-fleet-role)。

### Workspace Member Only

Workspace Member Only 角色使用户成为工作区成员，但不授予任何权限。用户在该工作区中的访问权限来自其[用户组](/langsmith/user-groups)的角色。

### LangSmith 创建的 keys 的角色

这些工作区角色属于 LangSmith 为其自身功能创建的 API keys，例如 deployments、[Engine](/langsmith/engine) 和 taskset runs。它们在 LangSmith UI 中的描述以 `(System)` 开头。

| 角色 | 用途 | 权限 |
|------|----------|-------------|
| Deployment Runtime | LangSmith 为 deployment 运行时创建的 keys | Workspace Editor 权限，但不含 `simulations:create`、`tasksets:run` 或 `workspaces:tracing-keys:create`，另加 `gateway:invoke`、`sandboxes:exec`、`snapshots:update`、`functions:update` 和 `agent-auth-credentials:use` |
| Gateway Invoker | LangSmith 为调用 [LLM Gateway](/langsmith/llm-gateway) 而创建的 keys | `gateway:invoke` 和 `workspaces:read` |
| Taskset Agent | 为 taskset trial 的 Agent Server 写入 traces 的 keys | `projects:create`、`projects:read`、`runs:create`、`prompts:read` 和 `workspaces:read` |
| Issues Agent | Engine 为分析 traces 和记录 issues 而创建的短期 keys | 对 traces、feedback、issues、prompts、rules、charts 和 model prices 的读取权限，另加 `issues:create`、`issues:update` 和 `gateway:invoke` |
| Issues Agent (Replica) | 供 Engine 使用的短期 keys | Issues Agent 权限，但不含 `gateway:invoke` |
| Issues Agent Data Tenant Reader | 供 Engine 使用的短期 keys | 对 traces、feedback、issues、prompts、rules、charts 和 model prices 的只读权限 |
| Issues Agent Trace Writer | 写入 Engine 自身 traces 的短期 keys | `projects:read`、`workspaces:read`、`runs:create`、`feedback:create`、`feedback:update` 和 `agent-auth-connections:read` |

不要把这些角色分配给用户。你可以把 Gateway Invoker 分配给仅调用 LLM Gateway 的 service key。详情请参见[授予调用 LLM Gateway 的权限](/langsmith/llm-gateway-authentication#grant-permission-to-call-the-gateway)。

## 自定义角色

<Info>创建自定义角色仅适用于 Enterprise 方案的组织。</Info>

自定义角色是自行定义的工作区角色。[Organization Admin](#organization-admin) 和 [Organization Operator](#organization-operator) 可以创建包含特定工作区级权限组合的自定义角色，然后与内置[工作区角色](#workspace-roles)一起分配。

### 创建自定义角色

自定义角色在[组织](/langsmith/administration-overview#organizations)级别创建，并可分配给该组织内任意[工作区](/langsmith/administration-overview#workspaces)中的用户。

要创建自定义角色：

1. 前往 Organization **Settings** > **Roles**。
2. 点击 **Create Role**。
3. 输入 **Role Name**，并可选填写 **Description**。
4. 在 **Permissions** 下选择该角色应包含的权限。
5. 点击 **Create**。

创建角色后，请在特定工作区中[把它分配给用户](/langsmith/user-management#assign-a-role-to-a-user)。

关于每项操作需要哪些具体权限，请参见[组织与工作区操作参考](/langsmith/organization-workspace-operations)。

关于自定义角色，还需注意以下事项：

- 只有 Organization Admin 和 Organization Operator 才能创建和管理自定义角色。
- 自定义角色仅在所属组织内有效（不能跨组织迁移）。
- 每个自定义角色都可以包含任意工作区级权限组合。
- 自定义角色不能拥有组织级权限。
- 用户可以在不同工作区中拥有不同角色，包括自定义角色。

### 理解权限行为

当用于自定义角色时，部分权限支持更细粒度的控制：

- `workspaces:manage` **不包含**管理工作区成员的能力。若希望自定义角色可以添加、移除或更新工作区成员，必须显式授予 `workspaces:manage-members`。内置 Workspace Admin 角色会自动包含这两个权限。
- `workspaces:manage-model-configs` 控制创建、编辑或删除[模型配置](/langsmith/model-configurations)的能力，包括绑定 [OAuth client credentials](/langsmith/model-configurations#oauth-client-credentials)，以及修改各 LangSmith 功能可用的模型范围。它与 `workspaces:manage` 相互独立，因此应显式授予需要配置模型的自定义角色。内置 Workspace Admin 角色会自动包含它。
- `workspaces:manage-keys` 控制创建和删除工作区 API key（工作区范围的 service keys）的能力。它与 `workspaces:manage` 相互独立，因此应显式授予需要管理 API keys 但不希望拥有完整工作区管理权限的自定义角色。为防止权限提升，由不具备 `workspaces:manage` 权限的用户创建的 key，不能被授予超出该用户所持权限的更多权限，也不能被分配组织已标记为 restricted 的角色。内置 Workspace Admin 角色会自动包含它。
- `bulk-exports:read` 和 `bulk-exports:manage` 覆盖 bulk export 相关端点，包括列出、创建、取消导出以及管理导出目的地。你可以在自定义角色中授予它们，以在不授予 `workspaces:manage` 的前提下，实现最小权限的 bulk export 访问。内置 Workspace Admin 自动包含 `bulk-exports:manage`，所有可读角色都会自动包含 `bulk-exports:read`。
- `projects:increase-trace-tier` 和 `projects:decrease-trace-tier` 是相互独立的，可以分别授予。例如，你可以允许某个角色降低 retention，但不允许提升 retention。如果用户两项权限都没有，则 retention 设置 UI 会完全隐藏；如果只有其中之一，则 UI 会部分启用，禁止方向会显示为禁用状态。
- `runs:read-inputs` 和 `runs:read-outputs` 控制角色是否可以查看 run 的 inputs 和 outputs，它们与 `runs:read` 相互独立。拥有 `runs:read` 但缺少其中一项权限的角色，仍然可以列出和打开 runs，但响应中会省略被拒绝的字段及其预览。Message 和 trajectory 视图需要同时具备这两项权限。如果只想在特定 project 中隐藏 inputs 或 outputs，请使用[访问策略](/langsmith/abac#control-access-to-run-inputs-and-outputs)。
- `projects:update` 只覆盖元数据更新（名称、描述、标签），**不**授予修改 trace retention 的能力。若要允许自定义角色修改 trace tier，必须显式授予 `projects:increase-trace-tier`、`projects:decrease-trace-tier`，或同时授予两者。

## 限制角色

<Info>角色限制仅适用于 [Enterprise](/langsmith/pricing-plans) 方案的组织。</Info>

[Organization Admins](#organization-admin) 和 [Organization Operators](#organization-operator)（即拥有 `organization:manage` 权限的角色）可以将任意角色，无论是系统角色还是自定义角色，标记为 **restricted**。被限制的角色只能由持有内置 [Workspace Admin](#workspace-admin) 角色的用户分配给工作区成员。即使某个用户拥有 `workspaces:manage-members` 权限，只要他本身不是 Workspace Admin，也不能分配受限角色。

这可以防止权限提升。换句话说，即使某个用户被授权管理工作区成员关系，他也不能授予那些被明确划定为不允许其分配的角色。

默认情况下没有任何角色是受限的。组织必须显式限制每个角色。

如需在 [LangSmith UI](https://smith.langchain.com) 中限制某个角色：

1. 前往 Organization **Settings** > **Roles**。
1. 在 Roles 表中找到你要限制的角色。
1. 选中该角色的 **Restricted** 复选框。

一旦某个角色被限制，非 Workspace Admin 用户就无法在成员邀请、成员编辑或 API key 创建流程中看到或分配该角色。API 也会拒绝来自非 Workspace Admin 调用方的分配请求。如果某个非 Workspace Admin 用户创建了 API key，他不能把自己的受限角色用作该 key 的默认角色。

如需解除限制，重复相同步骤并清除 **Restricted** 复选框即可。

<Note>
角色限制同时适用于系统角色（例如 Workspace Admin、Workspace Editor 和 Workspace Viewer）和自定义角色。该功能在 LangSmith [Cloud](/langsmith/cloud) 和 [Self-hosted](/langsmith/self-hosted) 中都可用。
</Note>
