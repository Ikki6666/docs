本参考文档介绍 LangSmith 的基于角色的访问控制（RBAC）系统，用于管理组织级和工作区级权限。

<Note>
RBAC（Role-Based Access Control）是一个 Enterprise 功能，用于管理工作区级权限。如果你对该功能感兴趣，请[联系销售团队](https://www.langchain.com/contact-sales)。其他方案默认所有用户都使用 Admin 角色。
</Note>

LangSmith 的 RBAC 系统用于管理用户在工作区内的权限。借助 RBAC，你可以控制谁可以访问你的 LangSmith[工作区](/langsmith/administration-overview#workspaces)，以及他们在其中可以执行哪些操作。

在 LangSmith 中，每个用户都会拥有：
- 一个适用于整个组织的[**组织角色**](#organization-roles)（它独立于工作区 RBAC）。
    - <OrgWorkspaceRole/>
- 对其所属每个工作区分别拥有一个[**工作区角色**](#workspace-roles)（需要 Enterprise RBAC 功能）。

在 Enterprise 方案中，组织还可以创建[自定义工作区角色](#custom-roles)，用更细粒度的权限组合来满足需求。

要了解如何设置 RBAC 并把角色分配给用户，请参见[用户管理指南](/langsmith/user-management#set-up-access-control)。你的身份提供方也可以通过 [SCIM groups](/langsmith/user-management#set-up-scim-for-your-organization) 或 [SSO Groups Sync](/langsmith/user-management#sso-groups-sync-alternative) 自动分配角色。

## 角色类型

### 组织角色

组织角色**不同于工作区 RBAC 功能**，它们用于管理整个组织范围内的能力。这些角色由系统预定义，不能修改，也不能扩展。[Organization User](#organization-user) 和 [Organization Viewer](#organization-viewer) 角色仅适用于 [Plus 和 Enterprise 方案](https://langchain.com/pricing) 的组织。在 Developer 组织（单工作区）中，所有用户默认都被分配为 [Organization Admin](#organization-admin)。

| 角色 | 说明 |
| --- | --- |
| [Organization Admin](#organization-admin) | 对组织配置、用户、计费和工作区拥有完整管理权限 |
| [Organization Operator](#organization-operator) | 拥有面向日常运营的工作区和用户管理权限，但不包含管理员级别权限 |
| [Organization User](#organization-user) | 可读取组织信息，并可创建个人访问令牌 |
| [Organization Viewer](#organization-viewer) | 对组织信息拥有只读权限 |

#### Organization admin

**说明**：对所有组织配置、用户、计费和工作区拥有完整管理权限。

**权限**：
- `organization:manage` - 完整控制组织设置、SSO、安全和计费
- `organization:read` - 读取所有组织信息
- `organization:pats:create` - 创建组织级[个人访问令牌](/langsmith/administration-overview#personal-access-tokens-pats)

<PermissionReference/>

**关键能力**：
- 管理[组织设置](/langsmith/set-up-hierarchy#set-up-an-organization)和品牌配置
- 配置 [SSO 和认证方式](/langsmith/user-management#set-up-saml-sso-for-your-organization)
- 管理[计费](/langsmith/billing)和订阅方案
- 创建和删除[工作区](/langsmith/set-up-hierarchy)
- 邀请和移除组织成员
- 为成员分配组织角色和工作区角色
- 创建和管理[自定义角色](#custom-roles)
- 配置 RBAC 和 ABAC（基于属性的访问控制）策略
- 查看组织[用量](/langsmith/usage-and-billing#usage-limits)和分析数据
- 查看[审计日志](/langsmith/audit-logs)（Enterprise）

关于如何设置和管理组织，请参见[管理概览](/langsmith/administration-overview#organizations)。

#### Organization Operator

具备面向日常运营的管理权限，包括工作区和用户管理，但不能管理 Organization Admin，也不能创建组织范围的服务密钥。

**权限：**
- `organization:manage` - 管理组织设置、工作区和非管理员用户
- `organization:read` - 读取所有组织信息
- `organization:pats:create` - 创建个人访问令牌

<PermissionReference/>

**关键能力：**
- 创建和管理[工作区](/langsmith/set-up-hierarchy#set-up-a-workspace)
- 邀请组织成员（除 Organization Admin 之外的所有角色）
- 管理非管理员组织成员（修改和移除 Organization User、Viewer 和 Operator）
- 为成员分配工作区角色
- 创建工作区范围的服务密钥和服务账户
- 查看组织[用量](/langsmith/usage-and-billing#usage-limits)和分析数据
- 查看[审计日志](/langsmith/audit-logs)（Enterprise）

**限制：**

- 不能邀请、修改或移除 Organization Admin
- 不能把用户分配为 Organization Admin
- 不能创建组织范围的服务密钥（非工作区特定）
- 不会自动加入已有工作区（只会加入自己创建的工作区，或被显式邀请的工作区）
- 不能管理组织[计费](/langsmith/billing)或订阅方案
- 不能配置 [SSO 或认证方式](/langsmith/user-management#set-up-saml-sso-for-your-organization)
- 不能创建或管理[自定义角色](#custom-roles)

#### Organization User

**说明**：可读取组织信息，并能够创建个人访问令牌。

**权限**：
- `organization:read` - 读取组织信息
- `organization:pats:create` - 创建个人访问令牌

<PermissionReference/>

**关键能力**：
- 查看组织成员和工作区
- 查看组织设置（但不能修改）
- 创建用于 API 访问的[个人访问令牌](/langsmith/administration-overview#personal-access-tokens-pats)
- 加入被邀请进入的工作区

**限制：**
- 不能修改组织设置
- 不能管理计费或订阅
- 不能创建或删除工作区
- 不能邀请或移除组织成员
- 不能管理角色或权限

你可以把 Organization User 加入部分工作区，并为其分配工作区角色（若已启用 RBAC），这些角色将定义工作区级权限。

#### Organization viewer

**说明**：对组织信息拥有只读访问权限。

**权限**：
- `organization:read` - 读取组织信息

<PermissionReference/>

**关键能力**：
- 查看组织成员和工作区
- 查看组织设置

**限制：**
- 不能修改任何组织级内容
- 不能创建个人访问令牌
- 不能管理计费、工作区或成员

### 工作区角色

工作区角色属于 **Enterprise RBAC 功能** 的一部分，用于控制用户在工作区内可以对资源执行什么操作：

| 角色 | 说明 |
| --- | --- |
| [Workspace Admin](#workspace-admin) | 对所有资源拥有完整权限，包括工作区设置和成员管理 |
| [Workspace Editor](#workspace-editor) | 对大多数资源拥有完整权限，但不能管理工作区设置，也不能删除某些资源 |
| [Workspace Viewer](#workspace-viewer) | 对所有工作区资源拥有只读访问权限 |

<Note>
RBAC（Role-Based Access Control）仅适用于 [Enterprise](https://langchain.com/pricing) 客户。如果你对该功能感兴趣，请[联系销售团队](https://www.langchain.com/contact-sales)。其他方案默认所有用户都使用 Admin 角色。
</Note>

#### Workspace admin

**说明**：对所有资源拥有完整权限，并且可以管理工作区。

**权限**：
- 对所有资源类型都拥有创建、读取、更新、删除和共享权限
- 拥有工作区管理能力

<PermissionReference/>

#### Workspace editor

**说明**：对大多数资源拥有完整权限，但不能管理工作区设置，也不能删除某些关键资源。

**与 Admin 的主要区别：**
- 不能删除[runs](/langsmith/observability-concepts#runs)
- 不能管理工作区设置（例如修改工作区名称）
- 不能管理工作区成员（包括添加、移除或更新成员角色）

#### Workspace viewer

**说明**：对所有工作区资源拥有只读访问权限。

**权限**：对所有资源类型均为只读访问。

<PermissionReference/>

<Tip>
关于如何为用户分配工作区角色的分步说明，请参见[用户管理指南](/langsmith/user-management#assign-a-role-to-a-user)。
</Tip>

## 自定义角色

<Info>创建自定义角色仅适用于 Enterprise 方案的组织。</Info>

[Organization Admins](#organization-admin) 可以创建自定义角色，用特定权限组合来满足组织需求。

### 创建自定义角色

自定义角色在[组织](/langsmith/administration-overview#organizations)级别创建，并可分配给该组织内任意[工作区](/langsmith/administration-overview#workspaces)中的用户。

**步骤**：
1. 前往 Organization **Settings** > **Roles**。
2. 点击 **Create Custom Role**。
3. 选择该角色应包含的权限。
4. 在特定工作区中把该自定义角色分配给用户。

关于每项操作需要哪些具体权限，请参见[组织与工作区操作参考](/langsmith/organization-workspace-operations)。

关于自定义角色，还需注意以下事项：

- 只有 Organization Admin 才能创建和管理自定义角色。
- 自定义角色仅在所属组织内有效（不能跨组织迁移）。
- 每个自定义角色都可以包含任意工作区级权限组合。
- 自定义角色不能拥有组织级权限。
- 用户可以在不同工作区中拥有不同角色，包括自定义角色。

### 限制角色

<Info>角色限制仅适用于 [Enterprise](/langsmith/pricing-plans) 方案的组织。</Info>

[Organization Admins](#organization-admin) 和 [Organization Operators](#organization-operator)（即拥有 `organization:manage` 权限的角色）可以将任意角色，无论是系统角色还是自定义角色，标记为 **restricted**。被限制的角色只能由持有内置 [Workspace Admin](#workspace-admin) 角色的用户分配给工作区成员。即使某个用户拥有 `workspaces:manage-members` 权限，只要他本身不是 Workspace Admin，也不能分配受限角色。

这可以防止权限提升。换句话说，即使某个用户被授权管理工作区成员关系，他也不能授予那些被明确划定为不允许其分配的角色。

**默认行为**：默认情况下没有任何角色是受限的。组织必须针对每个角色显式开启限制。

如需在 [LangSmith UI](https://smith.langchain.com) 中限制某个角色：

1. 前往 Organization **Settings** > **Roles**。
1. 在 Roles 表中找到你要限制的角色。
1. 打开该角色的 **Restricted** 开关。

一旦某个角色被限制，成员邀请和成员编辑流程都会对非 Workspace Admin 用户隐藏该角色，API 也会拒绝来自非 Workspace Admin 调用方的分配请求。

如需解除限制，重复相同步骤并关闭 **Restricted** 开关即可。

<Note>
角色限制同时适用于系统角色（Workspace Admin、Workspace Editor、Workspace Viewer）和自定义角色。该功能在 LangSmith [Cloud](/langsmith/cloud) 和 [Self-hosted](/langsmith/self-hosted) 中都可用。
</Note>

### 理解权限行为

当用于自定义角色时，部分权限支持更细粒度的控制：

- `workspaces:manage` **不包含**管理工作区成员的能力。若希望自定义角色可以添加、移除或更新工作区成员，必须显式授予 `workspaces:manage-members`。内置 Workspace Admin 角色会自动包含这两个权限。
- `workspaces:manage-model-configs` 控制创建、编辑或删除[模型配置](/langsmith/model-configurations)的能力，包括绑定 [OAuth client credentials](/langsmith/model-configurations#oauth-client-credentials)，以及修改各 LangSmith 功能可用的模型范围。它与 `workspaces:manage` 相互独立，因此应显式授予需要配置模型的自定义角色。内置 Workspace Admin 角色会自动包含它。
- `bulk-exports:read` 和 `bulk-exports:manage` 覆盖 bulk export 相关端点，包括列出、创建、取消导出以及管理导出目的地。你可以在自定义角色中授予它们，以在不授予 `workspaces:manage` 的前提下，实现最小权限的 bulk export 访问。内置 Workspace Admin 自动包含 `bulk-exports:manage`，所有可读角色都会自动包含 `bulk-exports:read`。
- `projects:increase-trace-tier` 和 `projects:decrease-trace-tier` 是相互独立的，可以分别授予。例如，你可以允许某个角色降低 retention，但不允许提升 retention。如果用户两项权限都没有，则 retention 设置 UI 会完全隐藏；如果只有其中之一，则 UI 会部分启用，禁止方向会显示为禁用状态。
- `projects:update` 只覆盖元数据更新（名称、描述、标签），**不**授予修改 trace retention 的能力。若要允许自定义角色修改 trace tier，必须显式授予 `projects:increase-trace-tier`、`projects:decrease-trace-tier`，或同时授予两者。
