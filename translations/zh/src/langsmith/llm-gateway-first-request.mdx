[LLM Gateway](/langsmith/llm-gateway) 通过一个 endpoint 调用各 provider 的模型，并使用一个 [LangSmith API key](/langsmith/create-account-api-key) 认证。你的代码无需把每个 provider 的 key 复制到每个应用中，而是使用一个 key，并通过更改 model ID 来切换 provider，同时 LangSmith 会追踪每次调用并应用你团队的支出限制。

本页介绍如何从 LangSmith UI 的 Simulator 和你的代码中发送请求，然后在 LangSmith 中查看它的 trace。

<Tip>
本页面向通过 gateway 发送请求的开发者。如果你正在为团队设置 gateway，请先阅读[设置 LLM Gateway](/langsmith/llm-gateway-admin-setup)。
</Tip>

## 开始之前

你需要：

- **加入某个使用付费方案的 LangSmith 组织。** 在 Developer 方案中，Simulator 只提供 LangChain 托管的模型，这些模型计入 [Gateway Credits](/langsmith/llm-gateway-credits)，而不是使用 provider key。
- **model provider 的 API key**，除非你的工作区已有。Simulator 会显示哪些 provider 已经设置完成。

## 在 Simulator 中运行请求

Simulator 会从你的浏览器通过 gateway 发送一个示例请求，让你可以在更改任何代码之前确认 key 和模型工作正常。

gateway 使用两个 key：

- 你的 provider key 以[工作区 secret](/langsmith/llm-gateway-provider-authentication#add-a-provider-key)的形式保留在 LangSmith 中。gateway 使用它调用 provider。
- 你的 gateway key 是一个以 `lsv2_` 开头的 LangSmith API key，由你的代码发送给 gateway。

要运行请求：

1. 在 [LangSmith](https://smith.langchain.com) 中，前往 **LLM Gateway** 并选择 **Simulator** 标签页。
1. 在 **Model routing** 下选择一个模型。模型卡片上的 **Needs key** 表示你的工作区还没有该 provider 的 key。
1. 点击 **Run request**。如果缺少 key，Simulator 会在发送请求前提示你提供。

响应会显示在请求下方。如果请求失败，请记下错误，并参见[故障排查](#故障排查)。

## 从代码中发送请求

与直接调用 provider 相比，gateway 请求有两处不同：

- base URL 指向 gateway，而不是 provider 的 API。
- API key 使用你的 LangSmith API key，而不是 provider 的 key。

要发送请求：

1. 在环境中设置你的 LangSmith API key 和 gateway 的 base URL：

    ```bash
    export LANGSMITH_API_KEY="lsv2_..."
    export LANGSMITH_GATEWAY_BASE_URL="https://gateway.smith.langchain.com/v1"
    ```

    这是 US gateway。对于其他区域，请把主机名替换为你的[区域 gateway](/langsmith/llm-gateway-how-it-works#use-a-regional-gateway)。在 [BYOC](/langsmith/llm-gateway-how-it-works#use-a-byoc-data-plane) 上，使用你的 data plane URL 后接 `/gateway/v1`。在[自托管 LangSmith](/langsmith/llm-gateway-self-hosted#make-your-first-call) 上，使用你的 LangSmith URL 后接 `/gateway/v1`。

1. [列出你可以调用的模型](/langsmith/llm-gateway-api-formats#list-models)：

    ```bash
    curl "$LANGSMITH_GATEWAY_BASE_URL/models" \
        -H "Authorization: Bearer $LANGSMITH_API_KEY"
    ```

    响应中的每个 `id` 都是一个 model ID。该列表反映你工作区的 provider keys 和 model access policies。

1. 发送请求。把 `<MODEL_ID>` 替换为列表中的 chat model ID，例如你在 Simulator 中测试过的模型：

    ```bash
    curl "$LANGSMITH_GATEWAY_BASE_URL/chat/completions" \
        -H "Authorization: Bearer $LANGSMITH_API_KEY" \
        -H "Content-Type: application/json" \
        -d '{"model":"<MODEL_ID>","messages":[{"role":"user","content":"Explain what an LLM gateway does in one sentence."}]}'
    ```

    成功的请求会返回包含一句话答案的 JSON 响应。如果失败，请参见 [Fix authentication errors](/langsmith/llm-gateway-authentication#fix-authentication-errors)。

<Tip>
该请求使用 Chat Completions [API 格式](/langsmith/llm-gateway-api-formats)。如需同一请求的 Python 或 TypeScript 版本，或 Anthropic Messages、Responses 格式版本，请在 Simulator 中选择格式和语言，然后点击复制图标。复制出的代码已经使用你部署环境的 gateway URL。
</Tip>

[LangChain](/oss/langchain/overview) chat models 和 [Deep Agents](/oss/deepagents/overview) 无需更改代码。在设置 `LANGSMITH_API_KEY` 的同时把 `LANGSMITH_GATEWAY` 设为 `true`，进程中每个受支持的 chat model 都会以其 provider 的原生 API 格式调用 gateway。详情请参见 [Direct model access](/langsmith/llm-gateway-direct-model-access#configure-langchain-and-deep-agents)。

## 查看 trace

在 Simulator 中，点击响应旁边的 **View trace**。来自你的代码的请求会出现在 **LLM Gateway** 的同一个 **Traces** 标签页中。默认情况下，trace 会记录 token 数量和成本等 metadata。更多信息请参见[查看 LLM Gateway traces](/langsmith/llm-gateway-traces)。

## 故障排查

关于 `401` 和 `403` 错误，请参见 [Fix authentication errors](/langsmith/llm-gateway-authentication#fix-authentication-errors)。关于 `424` 错误，请参见 [Fix provider credential errors](/langsmith/llm-gateway-provider-authentication#fix-provider-credential-errors)。

Simulator 会在没有错误代码的情况下提示缺少权限：

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| 没有 **Run request** 按钮 | 你缺少 `gateway:invoke` 权限。 | 请工作区管理员授予该权限。 |
| Simulator 要求你联系管理员 | 你无权添加 provider keys。 | 请工作区管理员添加 provider key。 |

## 下一步

现在你已经可以通过 gateway 发送请求，可以继续了解它的其他能力：

- [设置支出限制](/langsmith/llm-gateway-spend-policies)：按组织、工作区、API key 或用户设置支出上限。
- [添加模型回退](/langsmith/llm-gateway-fallbacks)：在备用模型上重试失败的请求，并在 Simulator 中测试该回退链。
- [API 格式](/langsmith/llm-gateway-api-formats)：发送 Chat Completions、Messages 或 Responses 请求。
- [设置 coding agents](/langsmith/llm-gateway-coding-agents)：将 Claude Code、Codex、Gemini CLI 或 Deep Agents Code 通过 gateway 路由。
- [Gateway Credits](/langsmith/llm-gateway-credits)：无需 provider key 即可调用 LangChain 托管的模型。
