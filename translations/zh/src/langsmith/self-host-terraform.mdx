LangChain 在 [github.com/langchain-ai/terraform](https://github.com/langchain-ai/terraform) 上发布了面向 [LangSmith self-hosted](/langsmith/self-hosted) 的生产可用 Terraform modules。这些 module 会预配云基础设施（网络、集群、数据库、缓存、对象存储、机密、DNS），并按照合理的默认值安装 LangSmith Helm chart。

如果你希望从第一天起就采用基础设施即代码，请使用这条路径。如果你已经用自己的工具管理云基础设施，只需要安装应用本身，请改为遵循 [Helm installation guide](/langsmith/kubernetes)。

<Tip>
**更偏好 Helm？** [Kubernetes setup guide](/langsmith/kubernetes) 介绍了如何在任何符合规范的集群上使用 Helm 安装，无需 Terraform。Terraform 路径则把集群预配、机密接线和 Helm release 打包成同一个工作流。
</Tip>

## 前置条件

在运行这些 module 之前，先安装以下工具：

| 工具 | 版本 | 用途 |
|---|---|---|
| `terraform` | 1.5 | 运行这些 module |
| `kubectl` | 1.33 | 预配完成后检查集群 |
| `helm` | 3.12 | 管理 LangSmith chart release |
| Cloud CLI | latest | 目标 provider 对应的 `aws`、`az` 或 `gcloud` |

你还需要：

- 一个 LangSmith license key。可[联系销售团队](https://www.langchain.com/contact-sales)申请。
- 目标云账号中的权限，能够创建 VPC 或 VNet 网络、托管 Kubernetes 集群、托管数据库、对象存储、机密和 IAM 角色。
- 一个已注册的域名（或子域名），用于 LangSmith UI endpoint。

## 部署层级

只需设置一个 Terraform 变量即可选择层级。各 module 会据此调整所有依赖资源的大小。

| 层级 | PostgreSQL | Redis | ClickHouse | 使用场景 |
|---|---|---|---|---|
| `dev` | In-cluster | In-cluster | In-cluster | 演示、evaluations、短期 POC |
| `production` | Cloud-managed（RDS、Cloud SQL、Azure Database） | Cloud-managed（ElastiCache、Memorystore、Azure Cache） | [LangChain Managed ClickHouse](/langsmith/langsmith-managed-clickhouse) | 持久化、可扩展的生产环境 |
| `production-large` | Cloud-managed，更大的实例规格 | Cloud-managed，更大的实例规格 | LangChain Managed ClickHouse | 高吞吐量生产环境 |

<Warning>
In-cluster ClickHouse 仅用于开发和 POC，不要用于生产环境。生产部署必须使用 [LangChain Managed ClickHouse](/langsmith/langsmith-managed-clickhouse) 或自行管理的外部 ClickHouse 集群。无论哪种层级，blob storage 都是必需的，因为 trace payload 不能存放在 ClickHouse 中。
</Warning>

## module 预配的内容

- **网络：** 包含公网和私网子网、NAT 和安全组的 VPC 或 VNet。
- **计算：** 托管 Kubernetes（EKS、AKS 或 GKE），节点池支持自动扩缩容，并按层级调整规格。
- **Data plane：** 托管 PostgreSQL、托管 Redis 或缓存，以及用于存放 trace payload 的 blob storage bucket。
- **机密：** 云原生 secret store（AWS SSM Parameter Store、Azure Key Vault、GCP Secret Manager），由 [External Secrets Operator](https://external-secrets.io/) 同步到 Kubernetes。
- **Ingress：** 默认使用云原生负载均衡器。Envoy Gateway（Gateway API）适用于多 namespace 的 dataplane 部署。
- **可选加固（目前仅 AWS）：** 带 FQDN 出站 allowlist 的 AWS Network Firewall、WAFv2、CloudTrail，以及支持 SSM bastion 访问的私有 EKS API endpoint。

## Enterprise 功能开关

每个 module 都为可选的 LangSmith add-on 提供了开关。在运行 `make apply` 之前，先在 `tfvars` 文件中逐项设置。

- **[LangSmith Deployment](/langsmith/deploy-self-hosted-full-platform)**（`enable_deployments`）：Agent Server，以及运行和管理已部署 agent 的 host-backend、listener 和 operator。
- **[Fleet](/langsmith/fleet)**（`enable_fleet`）：agent 构建产品，原名 Agent Builder，以独立服务形式部署（chart v0.15+）。
- **Insights**（`enable_insights`）：基于 ClickHouse 的分析功能。
- **Polly**（`enable_polly`）：AI 评估与监控。
