Insights 会自动分析你的 trace，检测使用模式、常见 agent 行为和失败模式，因此你不需要手动审查成千上万条 trace。

Insights 使用分层分类，hierarchical categorization，来理解你的数据，并突出显示可执行的趋势。

<Note>
Insights 适用于 LangSmith Plus 和 Enterprise [plans](/langsmith/pricing-plans)。
</Note>

## Prerequisites

- 在 workspace 中为 Insights 配置好 [model configuration](/langsmith/model-configurations)。
- 具有在 LangSmith 中创建规则的 [Permissions](/langsmith/organization-workspace-operations#projects)，生成新的 Insights Report 需要。
- 具有查看 LangSmith tracing project 的 [Permissions](/langsmith/organization-workspace-operations#projects)，查看现有 Insights Report 需要。

## Generate your first Insights report

<Tabs>
  <Tab title="UI" icon="layout-dashboard">

1. 在左侧菜单中进入 **Tracing Projects**，并选择一个 tracing project。
1. 点击右上角的 **+New**，然后选择 **New Insights Report**，为该项目生成新的 insight。
1. 输入 job 名称。
1. 如果还没有，请先在 workspace settings 中为 Insights [configure a model](/langsmith/model-configurations)。
1. 回答引导问题，让 Insights Report 聚焦于你想了解的 agent 信息，然后点击 **Run job**。

<Tip>切换到 Manual mode，可以 [configure the job manually](#configure-a-job)。</Tip>

这会启动一个后台 Insights Report。报告最多可能需要 30 分钟完成。

  </Tab>
  <Tab title="SDK" icon="code">

你可以使用 [Python SDK](/langsmith/smith-python-sdk) 对存储在 LangSmith 之外的数据生成 Insights Report。这让你能够分析生产系统中的 chat history、日志或其他来源的数据。

当你调用 `generate_insights()` 时，SDK 会：

1. 将你的 chat history 作为 trace 上传到一个新的 LangSmith project。
1. 基于这些已上传的 trace 生成一个 Insights Report。
1. 返回一个指向 [LangSmith UI](https://smith.langchain.com) 结果页的链接。

<CodeGroup>

```python Python
import os
from langsmith import Client

client = Client()

chat_histories = [
    [
        {"role": "user", "content": "how are you"},
        {"role": "assistant", "content": "good!"},
    ],
    [
        {"role": "user", "content": "do you like art"},
        {"role": "assistant", "content": "only Tarkovsky"},
    ],
]

report = client.generate_insights(
    chat_histories=chat_histories,
    name="Customer Support Topics - March 2024",
    instructions="What are the main topics and questions users are asking about?",
    openai_api_key=os.environ["OPENAI_API_KEY"],  # optional if already set as workspace secret
)

# client.poll_insights(report=report)
```
</CodeGroup>

  </Tab>
</Tabs>

<Note>
    使用 OpenAI 模型对 1,000 个 thread 生成 insight，通常成本为 \$1.00-\$2.00；使用当前 Anthropic 模型时，通常为 \$3.00-\$4.00。成本会随采样 thread 数量和每个 thread 的大小而扩展。
</Note>

## Understand the results

当 job 完成后，你可以进入 **Insights** 标签页，在那里看到一个 Insights Report 表格。每个 Report 都包含了针对某个 tracing project 中特定 trace 样本生成的 insight。

<Frame caption="Insights Reports for a single tracing project"><img src="/langsmith/images/insights-job-results.png" /> </Frame>

点击你的 job，可以查看按自动生成类别组织起来的 trace。

你可以逐层深入查看 category 和 subcategory，以查看底层 trace、feedback 和 run 统计信息。

<Frame caption="Common topics of conversations with the https://chat.langchain.com chatbot"><img src="/langsmith/images/insights-nav.gif" /> </Frame>

### Executive summary

在每份报告顶部，你会看到一个 executive summary，它会汇总 trace 中最重要的模式，包括：

- 关键发现，以及显示每种模式出现频率的百分比。
- 可点击的引用，例如 #1、#2、#3，链接到 agent 认定与你问题高度相关的 trace。

### Top-level categories

你的 trace 会被自动归为 top-level category，这些类别代表了数据中最宏观的模式。

分布条，distribution bars，会显示每种模式出现的频率，帮助你快速发现某些行为是否比预期更常见，或更少见。

每个 category 都有简短描述，并展示其中 trace 的聚合指标，包括：

- 典型 trace 统计信息，例如 error rate、latency、cost
- 来自 evaluator 的 feedback score
- 在 job 中提取的 [Attributes](#attributes)

### Subcategories

点击任意 category，可以看到更细的 subcategory 拆分，从而更细粒度地理解该类 trace 中的交互模式。

例如在 [Chat Langchain](https://chat.langchain.com) 示例中，在 **Data & Retrieval** 下就有 **Vector Stores** 和 **Data Ingestion** 等 subcategory。

### Individual traces

你可以点击 category 或 subcategory 进入 traces table，查看被分配到该类下的 trace。然后，你可以继续点开任意 trace，查看完整对话详情。

## Configure a job

你既可以使用自动生成流程创建 Insights Report，也可以手动配置。

### Autogenerating a config

1. 打开 **New Insights**，并确保 **Auto** 开关处于启用状态。
2. 用自然语言回答关于 agent 目的、你想了解什么、以及 trace 是如何组织的这些问题。Insights 会把你的回答转换成一个 config 草稿，包括 job name、summary prompt、attributes 和 sampling 默认值。
3. 选择 provider，然后点击 **Generate config** 预览，或点击 **Run job** 直接启动。

**Providing useful context**

为了获得更好的结果，建议你为每个提示写一到两句话，给 Insights 提供所需上下文，例如你想了解什么、哪些 signal 或字段最重要、以及哪些信息你已经知道并不重要。你越清楚地说明 agent 做什么、trace 如何组织，Insights 就越能按一种更具体、可执行，并且符合你理解数据方式的方式来对 example 进行分组。

**Describing your traces**

请说明你的数据是如何组织的：它们是单次 run，还是多轮对话？哪些 input 和 output 包含关键信息？这有助于 Insights 生成更聚焦的 summary prompt 和 attributes。必要时，你也可以直接指定 [summary prompt](#summary-prompt) 部分中的变量。

### Choose models

Insights 使用两个模型：

- **Thinking model**：执行聚类步骤，能力更强，成本更高。
- **Summarization model**：生成每条 trace 的摘要，更快，成本更低。

这两个模型都从你在 workspace 中配置好的 provider 中选择。如果你在 [model configurations](/langsmith/model-configurations) 中为 Insights 启用了具体模型，你可以分别单独选择它们。如果没有配置具体模型，你只需要选择 provider，OpenAI 或 Anthropic，Insights 会使用该 provider 的默认模型。

为了获得最佳效果，建议两个角色都使用同一 provider 的模型。

### Manual configuration

手动配置会给你更多控制权，例如预先定义你希望数据被分进哪些类别，或者仅针对满足特定 feedback score 和 filter 条件的 trace。

#### Select traces

- **Sample size**：要分析的 trace 最大数量，上限 1,000。
- **Time range**：trace 会从这个时间范围内采样。
- **Filters**：额外的 trace filter。你在调整 filter 时，会看到有多少 trace 符合条件。

#### Categories

默认情况下，top-level category 会从底层 trace 自下而上自动生成。

在某些情况下，你事先就知道自己想关注哪些类别，并希望 job 将 trace 分配到这些预定义 category 中。

配置中的 **Categories** 部分支持这种做法，你可以直接列出希望使用的 top-level category 名称和描述。

Subcategory 仍然会在这些预定义 top-level category 内由算法自动生成。

当某个 job 完成时，如果该 config 原先没有定义 category，系统会自动把发现到的 top-level category 保存回 config。这意味着后续的定时运行会复用这些 category，以保持一致性。

#### Summary prompt

这个 job 的第一步，是先为每条 trace 生成一段简短 summary，然后再对这些 summary 分类。

从 summary 中提取正确的信息，是获得有用分类结果的关键。

你可以编辑生成这些 summary 所使用的 prompt。编辑时需要考虑两点：

- Summarization instructions：如果某个信息没有出现在 trace summary 中，它就不会影响最终生成的 category，因此请明确说明每条 trace 中哪些信息是重要的、需要被提取出来。
- Trace content：使用 mustache 格式来指定每条 trace 中哪些部分会传给 summarizer。包含大量 input 和 output 的大 trace 可能既昂贵又嘈杂。把 prompt 缩减到只包含最相关部分，通常能提升结果质量。

你必须使用以下至少一个模板变量，来指定每条 trace 的哪些部分要发送给 summarizer：

| Variable | Description | Example |
| --- | --- | --- |
| `run.inputs` | 最近一次 root run 的输入 | `{{run.inputs}}` |
| `run.outputs` | 最近一次 root run 的输出 | `{{run.outputs}}` |
| `run.error` | 如果 run 失败，则为错误字符串 | `{{run.error}}` |
| `run.feedback` | 所有 feedback score，作为 JSON blob | `{{run.feedback}}` |
| `run.feedback.<key>` | 某个特定 feedback key 的 score | `{{run.feedback.correctness}}` |
| `all_thread_messages` | thread 的完整消息历史，仅适用于带有 [threads](/langsmith/threads) 的项目 | `{{all_thread_messages}}` |

你可以使用点表示法访问嵌套字段。例如，`{{run.inputs.foo.bar}}` 只会包含最后一次 run 的输入中 `foo` 里的 `bar` 字段。

<Note>
对于带有 [threads](/langsmith/threads) 的项目，Insights 会分析完整对话。`run.*` 变量只会使用每个 thread 中最近一次 root run。若要访问完整对话历史，请使用 `all_thread_messages`。
</Note>

#### Attributes

除了 summary 外，你还可以定义额外的字符串、数值和布尔属性，从每条 trace 中提取。
这些属性会影响分类步骤，具有相似属性值的 trace 往往会更容易被归在一起。
你还可以按 category 查看这些属性的聚合结果。

例如，你可能希望从每条 trace 中提取 `user_satisfied: boolean` 这个属性，从而让算法更倾向于按正向和负向用户体验拆分类别，并查看每个 category 的平均用户满意度。

#### Filter attributes

你可以在布尔属性上使用 `filter_by` 参数，在生成 insight 之前预先过滤 trace。启用后，只有当该属性被评估为 `true` 的 trace 才会纳入分析。

当你想把 Insights Report 聚焦到某个特定子集的 trace 时，这会很有帮助。例如，只分析错误、只查看英语对话，或只包含符合某些质量标准的 trace。

**How it works:**
- 在为 Insights 创建 config 时，为任意布尔 attribute 添加 `"filter_by": true`。
- LLM 会在 summarization 阶段根据属性描述评估每条 trace。
- 如果某条 trace 的该属性为 `false`，或缺失，则会在生成 insight 前被排除。

## Schedule Insights Reports

你可以把 Insights report 配置为周期性自动运行。创建或编辑配置时，使用 **Schedule** 部分来选择：

- **Daily**：每天 8:00 UTC 运行。
- **Weekly on Monday**：每周一 8:00 UTC 运行。
- **Custom**：输入你自己的 cron 表达式，时区为 UTC。

每次定时运行都会使用你保存的配置生成一份新报告。时间范围是动态计算的。例如，“last 24 hours” 总是在执行时分析最近 24 小时窗口，而不是你配置该 job 时的那个时间窗口。

## Save your config

你可以选择使用 **Save as** 按钮保存配置，以便将来重复使用。
如果你想对比一段时间内的 Insights Report，从而识别用户与 agent 行为的变化，这会特别有用。

在创建新的 Insights Report 时，你可以通过面板左上角的下拉框选择之前保存过的 config。
