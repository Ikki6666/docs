Insights 会持续将智能体的 traces 归入类别和子类别，让你无需逐条审查 trace，就能了解用户提出了哪些请求、智能体表现如何，以及在哪里失败。你通过针对自己的流量提出一个问题来启动 insight。Insights 会根据近期 traces 构建类别，然后随着新对话到达将其分配给相应类别，因此图表和指标始终保持最新。

智能体的 Insights 页面会列出该智能体的所有 insight，并标注其所属的[环境](/langsmith/agent-environments)。你在 UI 中创建的 insight 会归入 **Production**。

<Note>
Insights 适用于 LangSmith Plus 和 Enterprise [套餐](/langsmith/pricing-plans)。在自托管 LangSmith 上，持续型 Insights 需要 v0.18 或更高版本，并启用 [SmithDB](/langsmith/self-host-smithdb)。其他自托管安装会改为生成[批量报告](/langsmith/insights-batch-reports)。要检查你的安装使用哪种模式，请参阅[检查 Insights 是否持续运行](/langsmith/self-host-insights-chat#check-whether-insights-runs-continuously)。
</Note>

## Insights 的工作方式

每个 insight 分两个阶段运行：

1. **Build categories**：Insights 会汇总近期 traces 的样本，默认最多 500 条来自过去 7 天的 trace，并将这些摘要归入顶级类别和子类别。首次构建会在你创建 insight 时开始，最多可能需要 30 分钟。
1. **Categorize new conversations**：Insights 会在对话到达时对其进行采样。对于每个采样到的对话，它会生成摘要、提取相应的[属性](#add-attributes)，并分配最匹配的类别和子类别。一个对话可以是一个 [thread](/langsmith/threads)，也可以是一条不属于 thread 的 trace。Insights 会在 thread 空闲达到该环境的 [thread 空闲时间](/langsmith/rules#set-the-thread-idle-time)后分析该 thread，默认是 10 分钟。

类别不会自行变化。当你[刷新类别](#refresh-categories)时，已有类别的 traces 会保留原类别，新对话则使用刷新后的类别。

每个 insight 依靠 Insights 创建并管理的三条[自动化规则](/langsmith/rules)运行。这些规则不会显示在环境的 **Online Evaluators** 标签页上。在 LangSmith Cloud 上，它们会计入工作区可开启的自动化规则数量上限；如果某个 insight 的规则超过该上限，该 insight 会[暂停](#check-the-status-of-an-insight)。

## 前提条件

- Insights 的模型访问权限：为 Insights 使用的每个模型提供方在工作区中保存 API key。要检查或添加 key，请在创建 insight 时点击 **Configure**，或在现有 insight 上点击 **Edit**，然后在[选择模型](#select-models)部分点击 **API keys**。有关工作区范围的模型设置，请参阅[模型配置](/langsmith/model-configurations)。
- 查看智能体环境的[权限](/langsmith/organization-workspace-operations#projects)。如果访问策略限制了你在某个环境中可查看的 traces，Insights 不会显示该环境的 insight。
- 创建 insight 并刷新其类别需要 `rules:create` 权限，编辑它们需要 `rules:update`，删除它们需要 `rules:delete`。

## 创建 insight {#create-an-insight}

<Tabs>
  <Tab title="UI" icon="layout-dashboard">

要创建 insight：

1. 在[智能体切换器](/langsmith/navigate-agents)中选择你的智能体，然后在左侧菜单中点击 **Insights**。
1. 如果 Insights 页面中已有 insight，请点击 **New insight**。
1. 在 **What do you want to know about your users?** 下输入一个问题，例如“用户最常提出哪些请求？”
1. （可选）点击 **Configure**，在首次构建前更改设置。请参阅[配置 insight](#configure-an-insight)。
1. 点击 **Run analysis**。

Insights 会根据你的问题为该 insight 命名，并编写其摘要指令，然后开始构建类别。构建运行期间，Insights 会显示各步骤：收集 traces、汇总 traces、将 traces 归入类别，以及保存类别。构建完成后，该 insight 会开始对新对话进行分类。

  </Tab>
  <Tab title="SDK" icon="code">

你可以使用 [Python SDK](/langsmith/smith-python-sdk)，为存储在 LangSmith 之外的聊天历史创建 insight，例如生产日志。

当你调用 `generate_insights()` 时，SDK 会：

1. 将你的聊天历史作为 traces 上传到 LangSmith。
1. 基于这些 traces 创建 insight，并开始构建其类别。
1. 返回一个对象，其 `link` 可在 [LangSmith UI](https://smith.langchain.com) 中打开该 insight。在构建完成前，该链接会显示进度。

<Note>
如果工作区没有该模型提供方的 key，`generate_insights()` 会把你传入的 key 保存为工作区密钥。每次调用时，SDK 最多上传 1,000 条聊天历史。
</Note>

<CodeGroup>

```python Python
import os
from langsmith import Client

client = Client()

chat_histories = [
    [
        {"role": "user", "content": "how are you"},
        {"role": "assistant", "content": "good!"},
    ],
    [
        {"role": "user", "content": "do you like art"},
        {"role": "assistant", "content": "only Tarkovsky"},
    ],
]

report = client.generate_insights(
    chat_histories=chat_histories,
    name="Customer Support Topics - March 2024",
    instructions="What are the main topics and questions users are asking about?",
    openai_api_key=os.environ["OPENAI_API_KEY"],  # optional if already set as workspace secret
)

# client.poll_insights(report=report)
```
</CodeGroup>

要等待构建完成，请将该报告对象传给 `poll_insights()`。

  </Tab>
  <Tab title="CLI" icon="terminal-2">

[LangSmith CLI](/langsmith/langsmith-cli) 会根据 JSON 配置文件创建 insight，并开始构建其类别：

```bash
langsmith insights create --project "<environment-tracer-session-name>" --config insights.json --wait
```

将 `<environment-tracer-session-name>` 替换为该 insight 所分析智能体环境的 [`tracer_session_name`](/langsmith/create-an-agent#use-an-environment-project)。

有关文件格式以及刷新、列出和更新 insight 的命令，请参阅[管理 insight](/langsmith/langsmith-cli#manage-insights)。

  </Tab>
</Tabs>

## 查看 insight

Insights 会为每个 insight 显示一张卡片，其中包含过去 14 天内的顶级类别。点击卡片即可打开该 insight。

打开 insight 后，页面会显示其[状态](#check-the-status-of-an-insight)、上次归类 trace 的时间，以及所选时间范围内的以下视图：

- **Top categories**：每个类别中已归类 traces 的数量。点击某个类别，可将图表和表格聚焦到该类别。
- **Categories over time**：每个类别按 UTC 计算的每日数量。**Trends** 会为每个类别绘制一条线，**Volume** 会将各类别堆叠为已归类的总量。**Categories updated** 标记会显示 insight 的类别上次发生变化的时间。
- **Breakdown table**：每个类别的描述、trace 数量、Number 和 Boolean [属性](#add-attributes)值、反馈分数、错误率、P50 和 P99 延迟、P50 token 数以及 P50 成本。Boolean 属性会显示该属性为 true 的 traces 百分比。String 属性不会出现在表格中。展开某个类别可查看其子类别。点击某个子类别，或点击没有子类别的类别，可在新标签页中打开其 traces。

要更改时间范围，请使用 **Share** 旁边的范围菜单。菜单提供过去 7、14 或 30 天，默认是 14 天。

计数只包含 Insights 已归类的 traces。例如，在 10% 的采样率下，这些计数大约覆盖你流量的十分之一。请用它们比较类别、跟踪趋势，而不是衡量总流量。

### 检查 insight 的状态 {#check-the-status-of-an-insight}

insight 名称下方的状态行会说明它是否归类新对话，以及未归类时应采取什么操作：

- **Building categories**：首次构建正在运行。状态会显示当前步骤。
- **Continuously analyzing**：该 insight 正在持续分析。状态会显示其采样率。
- **Paused**：要么[采样率](#choose-runs)为 0%，要么该 insight 的部分自动化规则缺失。如果采样率为 0%，请设置更高的采样率。如果规则缺失，说明工作区已达到规则上限：关闭或删除未使用的规则，然后点击 **Refresh categories** 重新创建这些规则。
- **Off**：该 insight 不会分析新对话，例如来自一次性批量报告的已保存配置。设置采样率即可启动。
- **Not live**：该 insight 需要先完成一次构建才能启动。点击 **Build categories** 或 **Refresh categories**。如果上次构建未找到可归类的 traces，请检查该 insight 的[过滤器](#choose-runs)。

如果首次构建失败，Insights 会在该 insight 的位置显示错误，例如缺少模型 API key 或 key 无效。点击 **Review** 修正设置，或点击 **Dismiss** 移除失败的构建。

### 来自早期批量报告的 insight

在持续分析功能推出前创建的批量报告，其保存的配置会作为 insight 显示。按计划运行的配置会归类新对话。其他配置在设置采样率前会处于 **Off** 状态。定时计划不再启动报告。

过去的报告不再以报告页面打开。每份报告归类过的对话会显示在对应 insight 的图表中，日期范围与报告覆盖的日期一致。要读取过去报告的执行摘要和类别统计信息，请使用 [`langsmith insights get`](/langsmith/langsmith-cli#manage-insights)。

## 配置 insight {#configure-an-insight}

要更改现有 insight，请打开它并点击 **Edit**。要在首次构建前设置这些选项，请在[创建 insight](#create-an-insight)时点击 **Configure**。

编辑内容会应用于保存后分析的对话，已有类别的 traces 会保留原类别。更改 insight 的类别会保存该 insight 并启动一次构建，因此按钮会显示为 **Save and run**。

### 选择 runs {#choose-runs}

- **Add filters (optional)**：选择条件，只包含特定 runs。Insights 始终分析 root runs。过滤器下方，Insights 会显示上周有多少对话匹配这些条件。
- **Choose sampling rate**：Insights 分析的传入对话百分比。采样率越高，结果越有代表性，成本也越高。0% 会暂停该 insight。

如果你未设置采样率，Insights 会根据上周匹配的对话选择一个采样率，目标是每周约 1,000 个对话。如果匹配的对话少于 1,000 个，采样率就是 100%。Insights 只设置一次该采样率，不会随流量变化调整。

### 选择模型 {#select-models}

Insights 使用两个模型：

- **Summarization model**：汇总每条 trace 并提取属性。速度快、上下文窗口大的模型效果较好。
- **Categorization model**：将 traces 归入类别，并将新 traces 分配给这些类别。推理能力强的模型效果较好。

选择 **Recommended** 以使用工作区的默认 Insights 模型，或选择 **Custom** 分别选择每个模型。

要查看默认模型，请前往 **Settings** > **Workspace** > **Models** > **Feature Access**，找到 **Insights (Summarization)** 和 **Insights (Thinking)** 两行。如果某行没有默认模型，Insights 会使用该行可用的第一个模型。如果没有可用模型，Insights 会使用 OpenAI 模型，这要求工作区中提供 OpenAI API key。有关更多信息，请参阅 [Feature Access](/langsmith/model-configurations#feature-access)。

点击 **API keys**，检查工作区中是否为每个模型提供方配置了 key。

### 创建类别

默认情况下，**AI Suggested** 会让 Insights 在首次构建时查找类别和子类别。要自行设置顶级类别，请选择 **Custom**，并最多添加 10 个类别，每个类别都有名称和描述。每次构建时，Insights 仍会在这些类别内查找子类别。

编辑 insight 时，可以添加、删除或重命名其类别。保存后会使用新类别启动一次构建。

### 添加属性 {#add-attributes}

属性用于记录每条 trace 的特征，例如情绪或用户满意度，明细表会按类别报告这些属性。要添加属性，请点击 **Add Attribute** 并设置：

- **Name**：属性的名称。对于 Number 和 Boolean 属性，该名称就是明细表中的列名。
- **Type**：**Boolean**、**Number** 或 **String**。
- **What should Insights look for?**：属性的描述，汇总模型会据此提取该属性。
- **Filter**：仅适用于 Boolean 属性。选中后，Insights 只会归类并统计该属性为 true 的 traces，例如让 insight 聚焦于智能体出错的对话。

### 删除 insight

要删除 insight，请打开它，点击 **Edit**，然后点击其设置底部的 **Delete**。删除 insight 会停止归类新 traces。它已归类的 traces 会保留其类别。

## 刷新类别 {#refresh-categories}

类别不会自动刷新。要根据近期 traces 的新样本重新构建 insight 的类别，请打开该 insight 并点击 **Refresh categories**。

在构建完成前，新对话会继续使用当前类别。构建运行期间，insight 会显示 **Refreshing categories**。如果构建失败，insight 会显示 **Refresh failed** 并保留当前类别。如果构建未找到可用类别，则显示 **Categories not updated**。

## 共享 insight

要共享 insight，请打开它并点击 **Share**：

- **Copy link**：复制指向你当前所见 insight 的链接，包括时间范围和任何已选类别。
- **Download CSV**：下载每个类别和子类别及其所有统计信息，不受表格当前显示内容限制。
- **Download PDF**：下载图表和完整明细。图表数据加载完成后，此选项才可用。

## 将更新发送到 Slack

Insights 可以将 insight 的更新发布到 Slack 频道。这需要将 Slack 工作区连接到你的 LangSmith 组织。如果尚未连接，insight 设置的 **Slack notifications** 部分会显示 **Connect Slack** 按钮。在自托管 LangSmith 上，操作员必须先[配置 Slack 应用](/langsmith/self-host-slack)。

要将更新发送到 Slack：

1. 在 insight 的设置中，前往 **Slack notifications** 并选择一个频道。
1. 开启你需要的更新：
    - **Categories ready**：在 insight 的类别首次构建完成时以及每次刷新后发布。
    - **Digest**：按计划发布顶级类别及其变化。选择 **Daily** 或 **Weekly**，然后选择日期和时间。计划使用你首次设置时所用浏览器的时区。
1. 点击 **Save**。

每条更新会显示 insight 的名称、覆盖的时间段、Insights 已归类的 trace 数量以及采样率。更新会列出前五个类别及其 trace 数量，以及最多三项关键变化：新出现的类别，或 trace 占比相比上一时间段变化达到 5 个百分点或以上的类别。**Open in LangSmith** 会打开该更新覆盖日期范围内的 insight。

要停止更新，请关闭这两个选项并保存。

## 管理成本

Insights 会针对其分析的每个对话调用你的模型，因此成本取决于：

- **Sampling rate and traffic**：每个采样对话会分别调用一次汇总模型和一次分类模型。由于采样率不会随流量调整，流量激增会增加成本。
- **Conversation size**：对话越长，发送给汇总模型的 token 越多。
- **Category builds**：每次构建最多汇总 500 条 traces，并使用分类模型对它们分组。

要降低成本，请降低[采样率](#choose-runs)、添加过滤器，或[选择](#select-models)更小的模型。

## 限制

- Insights 会为每条 trace 分配一个最匹配的类别，即使没有任何类别完全匹配。
- Insights 会读取 trace 的输入、输出、错误、反馈和 thread 消息。它不会读取 trace 元数据。
- 一个智能体环境最多可包含 100 个 insight。
- 一个工作区一次最多可为三个 insight 构建类别。
