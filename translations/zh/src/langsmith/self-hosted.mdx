<Note>
自托管 LangSmith 是 Enterprise plan 的附加能力，面向 LangChain 规模最大、最重视安全性的客户。更多细节请参阅 [Pricing](https://www.langchain.com/pricing)。如果你希望获取 license key，在自己的环境中试用 LangSmith，请[联系销售团队](https://www.langchain.com/contact-sales)。
</Note>

自托管 LangSmith 会在你自己的基础设施中运行 LangSmith 平台，使 trace 和运营数据保留在你的环境中。基础安装包含[可观测性](/langsmith/observability)、[评估](/langsmith/evaluation)、[prompt engineering](/langsmith/prompt-context-hub#prompts)、[Insights](/langsmith/insights)和 [Chat](/langsmith/chat)。当你的使用场景需要时，还可以添加 [Sandboxes](/langsmith/sandboxes)、[Engine](/langsmith/engine-overview)、[Fleet](/langsmith/fleet/index)、[LLM Gateway](/langsmith/llm-gateway)和 [LangSmith Deployment](/langsmith/deployment)。

## 功能

| 功能 | 可用性 | 安装要求 |
|---------|--------------|---------------------|
| 可观测性、评估和 prompt engineering | 包含 | [基础安装](/langsmith/kubernetes)。 |
| [Insights](/langsmith/insights)和 [Chat](/langsmith/chat)（原 Polly） | Helm chart 0.15.1 或更高版本默认启用 | 每个功能一个加密密钥以及模型访问。参见[配置 Insights 和 Chat](/langsmith/self-host-insights-chat)。 |
| [Sandboxes](/langsmith/enable-self-hosted-sandboxes) | 可选 | EKS、GKE 或 AKS 上支持 KVM 的节点和 JuiceFS 存储。 |
| [Engine](/langsmith/engine-self-hosted) | 可选 | Sandboxes、包含 Engine 授权的 license，以及 Helm chart 0.16.0 或更高版本。离线（air-gapped）安装需要 Helm chart 0.17.0 或更高版本。 |
| [Fleet](/langsmith/enable-self-hosted-fleet) | 可选 | 集群中的 Fleet 服务。不需要 LangSmith Deployment。 |
| [LLM Gateway](/langsmith/llm-gateway-self-hosted) | 可选（beta） | Helm chart 0.17.1 或更高版本。`agent-gateway` 服务需要访问 PostgreSQL、Redis 和其他 LangSmith pods。 |
| [LangSmith Deployment](/langsmith/deploy-self-hosted-full-platform) | 可选 | KEDA、一个 ingress，以及控制平面和数据平面。要在没有控制平面的情况下运行 Agent Servers，参见[独立服务器](/langsmith/deploy-standalone-server)。 |

自托管 LangSmith 实例运行一组应用服务，这些服务由多个存储服务支撑。

要访问 LangSmith UI 并发送 API 请求，请暴露 [LangSmith frontend](#services) 服务。根据安装方式不同，它可以是一个负载均衡器，也可以是主机上暴露出来的端口。

关于各云厂商的架构模式与最佳实践，请参见 [AWS](/langsmith/aws-self-hosted)、[GCP](/langsmith/gcp-self-hosted)和 [Azure](/langsmith/azure-self-hosted) 指南。

### 服务

| Service | Description |
|---------|-------------|
| <a id="langsmith-frontend"></a> **LangSmith frontend** | 前端使用 Nginx 提供 LangSmith UI，并将 API 请求路由到其他服务。它是应用的入口点，也是唯一必须向用户暴露的组件。 |
| <a id="langsmith-backend"></a> **LangSmith backend** | Backend 是 CRUD API 请求的主要入口，并承担应用的大部分业务逻辑。这包括处理来自 frontend 和 SDK 的请求、为 traces 做入库准备，以及支持 hub API。 |
| <a id="langsmith-queue"></a> **LangSmith queue** | Queue 负责处理传入的 traces 和 feedback，确保它们被异步摄取并持久化到 traces 和 feedback 数据存储中，同时进行数据完整性检查，并在数据库错误或暂时无法连接数据库等情况下处理重试。 |
| <a id="langsmith-platform-backend"></a> **LangSmith platform backend** | Platform backend 是另一个关键服务，主要处理认证、run 摄取以及其他高吞吐任务。 |
| <a id="langsmith-playground"></a> **LangSmith Playground** | Playground 是一个将请求转发到各种 LLM API 的服务，用来支持 Playground 功能。它也可用于连接你自己的自定义模型服务。 |
| <a id="langsmith-ace-arbitrary-code-execution-backend"></a> **LangSmith ACE（Arbitrary Code Execution）backend** | ACE backend 是一个在安全环境中执行任意代码的服务，用于支持在 LangSmith 中运行自定义代码。 |

### 存储服务

<Note>
LangSmith 默认内置所有存储服务。你也可以将其配置为使用所有外部存储服务。生产环境中请使用外部存储服务。
</Note>

| Service | Description |
|---------|-------------|
| <a id="clickhouse"></a> **ClickHouse** | [ClickHouse](https://clickhouse.com/docs/en/intro) 是一个高性能、面向列的 SQL 数据库管理系统（DBMS），适用于在线分析处理（OLAP）。<br/><br/>LangSmith 使用 ClickHouse 作为 traces 和 feedback（高吞吐数据）的主数据存储。<br/><br/>💡 [连接外部 ClickHouse](/langsmith/self-host-external-clickhouse) |
| <a id="smithdb"></a> **SmithDB** | SmithDB 是一个为 agent trace 数据构建的可选列式 datastore：深层嵌套的 spans、多模态内容，以及会保持打开数小时的 spans。<br/><br/>SmithDB 在 LangSmith 0.17 及更高版本上可用。<br/><br/>💡 [启用 SmithDB](/langsmith/self-host-smithdb) |
| <a id="postgresql"></a> **PostgreSQL** | [PostgreSQL](https://www.postgresql.org/about/) 是一个功能强大的开源对象关系型数据库系统，它使用并扩展 SQL 语言，结合了许多特性，可安全地存储和扩展复杂的数据工作负载。<br/><br/>LangSmith 使用 PostgreSQL 作为事务型工作负载和运行数据（几乎所有 traces 和 feedback 之外的数据）的主数据存储。<br/><br/>💡 [连接外部 PostgreSQL](/langsmith/self-host-external-postgres) - AWS RDS、GCP Cloud SQL、Azure Database |
| <a id="redis"></a> **Redis / Valkey** | [Redis](https://github.com/redis/redis) 是一个强大的内存键值数据库，同时支持持久化到磁盘。通过将数据保存在内存中，Redis 在缓存等操作中提供高性能。<br/><br/>LangSmith 使用 Redis 支撑队列和缓存操作。[Valkey](https://valkey.io/) 也被正式支持，可作为 Redis 的 drop-in replacement。<br/><br/>💡 [连接外部 Redis 或 Valkey](/langsmith/self-host-external-redis) - AWS ElastiCache、GCP Memorystore、Azure Cache |
| <a id="blob-storage"></a> **Blob storage** | LangSmith 支持多种 blob storage 提供商，包括 [AWS S3](https://aws.amazon.com/s3/)、[Azure Blob Storage](https://azure.microsoft.com/en-us/services/storage/blobs/) 和 [Google Cloud Storage](https://cloud.google.com/storage)。<br/><br/>LangSmith 使用 blob storage 存储大文件，例如 trace artifacts、feedback 附件以及其他大型数据对象。Blob storage 是可选的，但强烈建议在生产部署中启用。<br/><br/>💡 [启用 blob storage](/langsmith/self-host-blob-storage) - AWS S3、GCP GCS、Azure Blob |

## 安装流程

本页是概览。实际安装在 [Kubernetes 安装指南](/langsmith/kubernetes)中进行，可选功能则有各自的设置指南。

要从本页得到一个运行中的实例：

<Steps>
  <Step title="安装基础平台">
    从头到尾完成[在 Kubernetes 上自托管 LangSmith](/langsmith/kubernetes)。它涵盖前置条件、Helm 配置、Insights 和 Chat 加密密钥、部署以及验证。完成后，你将拥有一个运行中的 LangSmith 实例，包含可观测性、评估、prompt engineering、Insights 和 Chat。

    开始之前，请先查看[自托管依赖的最低版本要求](/langsmith/self-host-dependency-versions)。如果想一并预配集群、数据存储和 Helm release，请使用 [Deploy with Terraform](/langsmith/self-host-terraform)，而不是仅使用 Helm 的指南。
  </Step>
  <Step title="（可选）添加功能">
    基础平台运行起来之后，根据[功能](#features)表启用你的使用场景所需的可选功能。参见[配置其他自托管功能](/langsmith/self-host-additional-features)。如果基础安装已覆盖你的使用场景，可跳过这一步。
  </Step>
</Steps>
