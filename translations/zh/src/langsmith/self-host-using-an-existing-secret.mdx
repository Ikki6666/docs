默认情况下，LangSmith 会创建若干 Kubernetes secrets，用于存放 license keys、salts 以及其他配置参数等敏感信息。不过，你也可以改为使用自己已经在 Kubernetes 集群中创建好的 secret（或者通过某种 secrets operator 预先生成的 secret）。如果你希望以集中方式管理敏感信息，或者有特定安全要求，这会很有用。

默认情况下，我们会创建以下与 LangSmith 各组件对应的 secrets：

* `langsmith-secrets`：这个 secret 包含 license key 和一些其他基础配置参数。入门可参考 [secrets template](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/templates/secrets.yaml)。
* `langsmith-redis`：这个 secret 包含 Redis 连接字符串（如果使用 Redis cluster，则为 node URIs）和密码。入门可参考 [Redis secrets template](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/templates/redis/secrets.yaml)。
* `langsmith-postgres`：这个 secret 包含 Postgres 连接字符串和密码。入门可参考 [Postgres secrets template](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/templates/postgres/secrets.yaml)。
* `langsmith-clickhouse`：这个 secret 包含 ClickHouse 连接字符串和密码。入门可参考 [ClickHouse secrets template](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/templates/clickhouse/secrets.yaml)。

## 要求

* 一个现有的 Kubernetes 集群
* 一种在集群中创建 Kubernetes secrets 的方式。这可以通过 `kubectl`、Helm chart，或像 [Sealed Secrets](https://github.com/bitnami-labs/sealed-secrets) 这样的 secrets operator 来实现

## 参数

你需要创建自己的 Kubernetes secrets，并确保它们符合 LangSmith Helm Chart 所创建 secrets 的结构。

<Warning>
这些 secrets 的结构必须与 LangSmith Helm Chart 创建的 secrets 保持一致（上面的链接里可以查看具体 secret 结构）。如果缺少任何必需 key，LangSmith 实例可能无法正常工作。
</Warning>

一个示例 secret 可能如下所示：

<Warning>
`api_key_salt` 只应设置一次，之后不要再更改。这个值用于对所有静态存储的 API keys 进行哈希。轮换它会永久使组织中现有的每一个 API key 失效，要求所有用户重新生成自己的 key。
</Warning>

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: langsmith-secrets
  namespace: langsmith
stringData:
  oauth_client_id: foo
  oauth_client_secret: foo
  oauth_issuer_url: foo
  langsmith_license_key: foo
  langgraph_cloud_license_key: foo
  api_key_salt: foo
  jwt_secret: foo
  initial_org_admin_password: foo
  blob_storage_access_key: foo
  blob_storage_access_key_secret: foo
  azure_storage_account_key: foo
  azure_storage_connection_string: foo
  agent_builder_encryption_key: foo
  insights_encryption_key: foo
  # Chat (formerly Polly)
  polly_encryption_key: foo
  # Optional. Ed25519/OKP JWKS (JSON) that signs OAuth Authorization Server /
  # Remote MCP tokens. Required only to enable the LangSmith Remote MCP server
  # (see /langsmith/langsmith-remote-mcp); omit it otherwise.
  langsmith_signing_jwks: foo
```

## 配置

在这些 secrets 创建好后，你可以让 LangSmith 实例直接使用这些 secrets，以避免通过明文传递 secret 值。做法是修改 LangSmith Helm Chart 安装中使用的 `langsmith_config.yaml` 文件。

```yaml
config:
  existingSecretName: "langsmith-secrets" # The name of the secret that contains the license key and other basic configuration parameters
redis:
  external:
    enabled: true # Set to true to use an external Redis instance. This secret is only needed if you are using an external Redis instance
    existingSecretName: "langsmith-redis" # The name of the secret that contains the Redis connection string and password
postgres:
  external:
    enabled: true # Set to true to use an external Postgres instance. This secret is only needed if you are using an external Postgres instance
    existingSecretName: "langsmith-postgres" # The name of the secret that contains the Postgres connection string and password
clickhouse:
  external:
    enabled: true # Set to true to use an external ClickHouse instance. This secret is only needed if you are using an external ClickHouse instance
    existingSecretName: "langsmith-clickhouse" # The name of the secret that contains the ClickHouse connection string and password
```

配置完成后，需要更新 LangSmith 安装。可以参考[升级指南](/langsmith/self-host-upgrades)。如果一切配置正确，你的 LangSmith 实例现在应该可以通过 Ingress 正常访问。可以运行下面的命令，检查 secrets 是否被正确使用：

```bash
kubectl describe deployment langsmith-backend | grep -i <secret-name>
```

输出中应看到类似下面的内容：

```bash
POSTGRES_DATABASE_URI:                    <set to the key 'connection_url' in secret <your-secret-name>  Optional: false
CLICKHOUSE_DB:                            <set to the key 'clickhouse_db' in secret <your-secret-name>   Optional: false
```
