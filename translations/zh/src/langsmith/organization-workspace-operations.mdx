本页提供一份完整的参考表，说明 [workspace](/langsmith/administration-overview#workspaces) 和 [organization](/langsmith/administration-overview#organizations) 层面的操作，以及哪些角色可以执行这些操作。

该列表涵盖了 LangSmith 中的 API 操作，并同时说明：

- 哪些系统角色可以执行该操作。
- 所需的具体权限字符串。
- 关于部分访问或特殊情况的备注。

<Info>
如需了解 LangSmith 的 RBAC 系统、角色定义和权限概念，请参阅 [Role-based access control](/langsmith/rbac)。
</Info>

## 图例

- ✓ **Allowed**：拥有该角色的用户可以执行此操作
- ✗ **Not Allowed**：拥有该角色的用户不能执行此操作
- ⚠ **Partial**：用户只有部分权限，详见备注

<Note>
\* `projects:increase-trace-tier` 与 `projects:decrease-trace-tier` 是相互独立的权限，可以分别授予到自定义角色中。例如，你可以允许某个角色降低保留层级，但不允许其提高保留层级。如果用户两个权限都没有，retention settings UI 会被完全隐藏；如果只拥有其中一个，则 UI 只会部分可用，禁止方向会被禁用。
</Note>

## 权限继承

### 组织到工作区

- [Organization Admin](/langsmith/rbac#organization-admin) 自动拥有所有工作区的完整权限。
- [Organization Operator](/langsmith/rbac#organization-operator) 只有在被显式加入某个工作区并分配工作区角色时，才会获得对应工作区权限，或者在他们自己创建的工作区中获得权限。
- [Organization User](/langsmith/rbac#organization-user) 和 [Organization Viewer](/langsmith/rbac#organization-viewer) 也只有在被显式加入某个工作区并分配工作区角色时，才会拥有对应工作区权限。

关于更详细的角色定义，请参阅 [Organization roles](/langsmith/rbac#organization-roles) 和 [Workspace roles](/langsmith/rbac#workspace-roles)。

### 工作区角色独立性

- 用户在不同工作区中可以拥有不同的工作区角色。
- 某个用户可以在一个工作区中是 [Workspace Admin](/langsmith/rbac#workspace-admin)，而在另一个工作区中只是 [Workspace Viewer](/langsmith/rbac#workspace-viewer)。
