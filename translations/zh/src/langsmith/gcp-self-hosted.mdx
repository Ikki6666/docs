当你在 [Google Cloud Platform (GCP)](https://cloud.google.com/) 上运行 LangSmith 时，[self-hosted](/langsmith/self-hosted) 模式会部署一个具备 observability 功能的完整 LangSmith 平台。

本页提供以下内容：

- [初始设置步骤](#initial-setup)：介绍如何部署到 GKE、配置托管服务，以及设置认证。
- [GCP 专属架构模式](#reference-architecture)和参考图。
- [服务建议](#compute-options)与最佳实践。
- [Google Cloud Well-Architected 最佳实践](#google-cloud-well-architected-best-practices)，涵盖运维卓越性、安全性与可靠性。

<Note>
LangChain 提供了专门面向 GCP 的 Terraform modules，用于帮助你为 LangSmith 预置基础设施。这些 modules 可以快速建立 GKE clusters、Cloud SQL、Memorystore Redis、Cloud Storage 以及网络资源。

请查看 [GCP Terraform modules](https://github.com/langchain-ai/terraform/tree/main/modules/gcp) 获取文档和示例。
</Note>

## 初始设置

<Steps>
  <Step title="Deploy to Kubernetes">
    请按照 [Kubernetes installation guide](/langsmith/kubernetes) 进行部署。LangSmith 已在 Google Kubernetes Engine (GKE) 上完成测试。

    **GKE 专属说明：**
    - LangSmith 可运行在标准 GKE clusters 上
    - 请使用 GCE persistent disk storage class
  </Step>

  <Step title="Configure external services">
    对于生产环境部署，请连接到 GCP 托管服务：

    <CardGroup cols={2}>
      <Card title="Google Cloud Storage" icon="database" href="/langsmith/self-host-blob-storage#google-cloud-storage">
        在 GCS 中存储 trace 数据
      </Card>
      <Card title="Cloud SQL" icon="database" href="/langsmith/self-host-external-postgres#google-cloud-sql">
        PostgreSQL 数据库
      </Card>
      <Card title="Memorystore" icon="cpu" href="/langsmith/self-host-external-redis#google-cloud-memorystore">
        使用 Redis 或 Valkey 作为缓存
      </Card>
      <Card title="ClickHouse Cloud" icon="chart-line" href="/langsmith/self-host-external-clickhouse">
        分析型数据库
      </Card>
    </CardGroup>
  </Step>

  <Step title="Set up authentication">
    请使用 [Workload Identity](https://cloud.google.com/kubernetes-engine/docs/how-to/workload-identity)，让 LangSmith pods 能够认证并访问 GCP 服务。

    **关键页面：**
    - [GCS HMAC key authentication](/langsmith/self-host-blob-storage#google-cloud-storage)
    - [Cloud SQL IAM authentication](/langsmith/self-host-external-postgres#iam-authentication)
    - [Memorystore IAM authentication](/langsmith/self-host-external-redis#iam-authentication)
  </Step>
</Steps>

完成这些初始设置后，你就可以继续查看下面更完整的 GCP 架构与最佳实践内容。

## 参考架构

我们建议充分利用 GCP 的托管服务，构建一个可扩展、安全且具备弹性的服务平台。下图中的架构同时适用于 self-hosted 和 hybrid，并与 [Google Cloud Well-Architected Framework](https://docs.cloud.google.com/architecture/framework) 保持一致：

![Architecture diagram showing GCP relations to LangSmith services](/langsmith/images/gcp-architecture-self-hosted.png)

- <Icon icon="globe" /> **Ingress & networking**：请求通过你 [VPC](https://cloud.google.com/vpc) 内的 [Cloud Load Balancing](https://cloud.google.com/load-balancing) 进入系统，并使用 [Cloud Armor](https://cloud.google.com/armor) 与基于 [IAM](https://cloud.google.com/iam) 的认证机制进行保护。
- <Icon icon="cube" /> **Frontend & backend services:** 容器运行在 [Google Kubernetes Engine (GKE)](https://cloud.google.com/kubernetes-engine) 上，并位于 load balancer 后方。必要时会把请求路由到 cluster 内部的其他服务。
- <Icon icon="database" /> **Storage & databases:**
  - [Cloud SQL for PostgreSQL](https://cloud.google.com/sql/docs/postgres)：用于存储 metadata、projects、users，以及已部署 agents 的短期与长期 memory。LangSmith 支持 PostgreSQL 14 及以上版本。
  - [Memorystore](https://cloud.google.com/memorystore)（[Redis](https://cloud.google.com/memorystore/docs/redis) 或 [Valkey](https://cloud.google.com/memorystore/docs/valkey)）：用于缓存与作业队列。Memorystore 可运行在单实例或 cluster 模式。LangSmith 需要 Redis OSS 5 或更高版本，或 Valkey 8。
  - ClickHouse + [Persistent Disks](https://cloud.google.com/compute/docs/disks)：用于分析与 trace 存储。
    - 除非出于安全或合规原因无法这样做，否则我们建议使用[外部托管的 ClickHouse 方案](/langsmith/self-host-external-clickhouse)。
    - Hybrid 部署不要求必须使用 ClickHouse。
  - [Cloud Storage](https://cloud.google.com/storage)：用于存储 trace artifacts 和 telemetry。

- <Icon icon="sparkles" /> **LLM integration:** 可选地将请求代理到 [Vertex AI](https://cloud.google.com/vertex-ai) 执行 LLM 推理。
- <Icon icon="chart-line" /> **Monitoring & observability:** 可与 [Cloud Monitoring](https://cloud.google.com/monitoring) 和 [Cloud Logging](https://cloud.google.com/logging) 集成。


## 计算选项

LangSmith 支持多种计算方式，你可以根据自身需求进行选择：

| Compute option | Description | Suitable for |
|-----------------|-------------|--------------|
| **Google Kubernetes Engine（推荐）** | 支持高级扩缩容与多租户能力 | 大型企业 |
| **基于 Compute Engine** | 完整控制权，自带基础设施（BYO-infra） | 受监管或 air-gapped 环境 |

## Google Cloud Well-Architected 最佳实践

本参考设计遵循 Google Cloud Well-Architected Framework 的六大支柱：

### 运维卓越性

- 使用 IaC（[Terraform](https://www.terraform.io/) / [Deployment Manager](https://cloud.google.com/deployment-manager)）自动化部署。
- 使用 [Secret Manager](https://cloud.google.com/secret-manager) 管理配置和敏感数据。
- 配置你的 LangSmith 实例以[导出 telemetry 数据](/langsmith/export-backend)，并通过 [Cloud Logging](https://cloud.google.com/logging) 持续监控。
- 管理 [LangSmith deployments](/langsmith/deployment) 的推荐方式，是建立一套 CI 流程：构建 [Agent Server](/langsmith/agent-server) 镜像并推送到 [Artifact Registry](https://cloud.google.com/artifact-registry)。在 PR 阶段先创建测试部署，再在 PR 合并后把新 revision 部署到 staging 或 production。

### 安全

- 使用遵循最小权限原则的 [IAM](https://cloud.google.com/iam) 角色，并结合 [Workload Identity](https://cloud.google.com/kubernetes-engine/docs/how-to/workload-identity) 实现安全的 pod 到 GCP 服务认证。
- 启用静态加密（[Cloud SQL](https://docs.cloud.google.com/sql/docs/postgres/cmek)、[Cloud Storage](https://cloud.google.com/storage/docs/encryption)、Persistent Disks）和传输加密（TLS 1.2+）。
- 使用 [Secret Manager](https://cloud.google.com/secret-manager) 管理凭证。
- 将 [Identity Platform](https://cloud.google.com/identity-platform) 或 [Workload Identity Federation](https://cloud.google.com/iam/docs/workload-identity-federation) 作为 IDP，与 LangSmith 内置认证和授权能力结合，以保护 agents 及其工具的访问安全。

### 可靠性

- 跨区域复制 LangSmith [data plane](/langsmith/data-plane)：对于 LangSmith Deployment，可将相同 data planes 部署到不同区域的 Kubernetes clusters 中。同时，将 [Cloud SQL](https://cloud.google.com/sql/docs/postgres/high-availability) 与 [GKE](https://docs.cloud.google.com/kubernetes-engine/docs/concepts/configuration-overview) 服务配置为多可用区。
- 使用 [Horizontal Pod Autoscaler](https://cloud.google.com/kubernetes-engine/docs/concepts/horizontalpodautoscaler) 与 [Cluster Autoscaler](https://cloud.google.com/kubernetes-engine/docs/concepts/cluster-autoscaler)，为后端 workers 实现[自动扩缩容](https://cloud.google.com/kubernetes-engine/docs/concepts/cluster-autoscaler)。
- 使用 [Cloud DNS](https://cloud.google.com/dns) 健康检查与故障转移策略。

### 性能优化

- 使用 [Compute Engine](https://cloud.google.com/compute) 实例，并根据 [machine type selection](https://cloud.google.com/compute/docs/machine-types) 选择合适机型，以优化计算性能。
- 对访问频率较低的 trace 数据，使用 [Cloud Storage lifecycle policies](https://cloud.google.com/storage/docs/lifecycle)，将其迁移到 [Nearline](https://cloud.google.com/storage/docs/storage-classes#nearline) 或 [Coldline](https://cloud.google.com/storage/docs/storage-classes#coldline) 存储类型。

### 成本优化

- 通过 [Committed Use Discounts](https://cloud.google.com/compute/docs/instances/signing-up-committed-use-discounts) 与 [Sustained Use Discounts](https://cloud.google.com/compute/docs/sustained-use-discounts)，为 [GKE](https://cloud.google.com/kubernetes-engine) clusters 做合理规格规划。
- 使用 [Cloud Billing](https://cloud.google.com/billing/docs) dashboards 和 [Cost Management](https://cloud.google.com/cost-management) 工具来监控成本 KPI。

### 可持续性

- 使用按需计算与[自动扩缩容](https://cloud.google.com/kubernetes-engine/docs/concepts/cluster-autoscaler)，尽量减少空闲工作负载。
- 使用 [Cloud Storage lifecycle policies](https://cloud.google.com/storage/docs/lifecycle)，把 telemetry 存入低时延、低成本层级。
- 使用[计划动作](https://cloud.google.com/compute/docs/instances/schedule-instance-start-stop)，对非生产环境启用自动关停。

## 安全与合规

LangSmith 可以配置为支持：

- 仅通过 [Private Service Connect](https://cloud.google.com/vpc/docs/private-service-connect) 访问（除计费所需的必要出站流量外，不暴露到公网）。
- 通过 [Cloud KMS](https://cloud.google.com/kms) 为 Cloud Storage、Cloud SQL 和 Persistent Disks 提供加密密钥。
- 将审计日志发送到 [Cloud Logging](https://cloud.google.com/logging) 和 [Cloud Audit Logs](https://cloud.google.com/logging/docs/audit)。

客户也可以根据需要部署在 [Assured Workloads](https://cloud.google.com/assured-workloads) 区域，以满足 ISO、HIPAA 或其他监管合规要求。

## Monitoring 与 evals

你可以使用 LangSmith 来：

- 捕获运行在 [Vertex AI](https://cloud.google.com/vertex-ai) 上的 LLM 应用 traces。
- 通过 [LangSmith datasets](/langsmith/manage-datasets) 评估模型输出。
- 跟踪延迟、token 用量和成功率。

也可以与以下系统集成：

- [Cloud Monitoring](https://cloud.google.com/monitoring) dashboards。
- [OpenTelemetry](https://opentelemetry.io/) 和 [Prometheus](https://prometheus.io/) exporters。
