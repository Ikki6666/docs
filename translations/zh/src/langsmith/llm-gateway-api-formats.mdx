标准的 LLM Gateway API 支持三种请求和响应格式。选择你的应用已经在使用的格式。然后通过同一个 endpoint，使用你自己的 provider key 或 Gateway Credits 调用模型。

## 比较 API 格式

在 US 区域的 LangSmith Cloud 上，每种格式使用以下 base URL 和 endpoint。关于其他区域、BYOC data planes 和自托管安装，请参见[检查可用性](/langsmith/llm-gateway-how-it-works#check-availability)。

| API 格式 | Base URL | Prompt endpoint | 常用 client |
| --- | --- | --- | --- |
| OpenAI Chat Completions | `https://gateway.smith.langchain.com/v1` | `POST /chat/completions` | OpenAI SDK 和大多数 OpenAI 兼容工具 |
| Anthropic Messages | `https://gateway.smith.langchain.com` | `POST /v1/messages` | Anthropic SDK、[Claude Code](/langsmith/llm-gateway-coding-agents) |
| OpenAI Responses | `https://gateway.smith.langchain.com/v1` | `POST /responses` | OpenAI SDK、[Codex](/langsmith/llm-gateway-coding-agents) |

<Tip>
所有格式都使用工作区范围的 LangSmith API key 进行认证。关于 key 类型、权限以及每个 client 发送的 header，请参见 [Authenticate to the LLM Gateway](/langsmith/llm-gateway-authentication)。
</Tip>

## 理解转换行为

endpoint 决定你的应用发送和接收的格式，model ID 决定上游 provider。

- 当 provider 原生支持所选格式时，gateway 会保留该格式。
- 否则，gateway 会把请求转换为 provider 支持的格式，并把响应转换回来，包括流式响应。
- 转换可能会拒绝无法在目标 provider 格式中表达的字段。当需要 provider 原生行为时，请使用 [Direct model access](/langsmith/llm-gateway-direct-model-access)。

无论使用哪种格式，每个请求都会解析相同的 provider secrets、策略和 tracing 配置。

### 使用 prompt caching

如何请求 prompt caching 取决于你发送的格式和调用的模型：

- **OpenAI 模型**：OpenAI 会自动缓存 prompt。要控制缓存生命周期或断点，请使用 OpenAI 的缓存字段，例如 `prompt_cache_options` 或 `prompt_cache_retention`。每个模型接受哪些字段和值由 OpenAI 决定。详情请参见 [OpenAI prompt caching 指南](https://developers.openai.com/api/docs/guides/prompt-caching)。
- **Messages 格式的 Anthropic 模型**：使用 Anthropic 的 `cache_control` 字段。详情请参见 [Anthropic prompt caching 指南](https://platform.claude.com/docs/en/docs/build-with-claude/prompt-caching)。
- **Chat Completions 或 Responses 格式的 Anthropic 模型**：设置 `prompt_cache_options`、`prompt_cache_retention` 或 `prompt_cache_key` 中的任意一个。gateway 会以 Anthropic 默认的五分钟缓存生命周期开启 Anthropic prompt caching。它不会沿用请求中指定的生命周期、保留时间或断点模式。
- **Messages 格式的 OpenAI 模型**：gateway 会丢弃 `cache_control` 字段。OpenAI 的自动缓存仍然生效。

## 发送请求

每种格式都有自己的请求结构。例如，Chat Completions 使用 `messages`，Responses 使用 `input`，而 Messages 需要 `max_tokens`。把 `<MODEL_ID>` 替换为一个 [model ID](#选择-model-id)：

<CodeGroup>

```bash Chat Completions
curl https://gateway.smith.langchain.com/v1/chat/completions \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"<MODEL_ID>","messages":[{"role":"user","content":"Hello!"}]}'
```

```bash Messages
curl https://gateway.smith.langchain.com/v1/messages \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"<MODEL_ID>","max_tokens":1024,"messages":[{"role":"user","content":"Hello!"}]}'
```

```bash Responses
curl https://gateway.smith.langchain.com/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"<MODEL_ID>","input":"Hello!"}'
```

</CodeGroup>

完整的请求和响应 schema 请参见 [OpenAI Chat Completions API](https://platform.openai.com/docs/api-reference/chat)、[Anthropic Messages API](https://docs.anthropic.com/en/api/messages) 和 [OpenAI Responses API](https://platform.openai.com/docs/api-reference/responses)。

<Tip>
要获取 Python 或 TypeScript 版本的相同请求，请打开 **LLM Gateway** 中的 **Simulator** 标签页，选择格式和语言，然后点击复制图标。复制的代码已经使用你的 deployment 的 gateway URL。详情请参见 [Send your first LLM Gateway request](/langsmith/llm-gateway-first-request)。
</Tip>

## 选择 model ID

model ID 决定 provider 以及为该调用付费的凭证。model ID 在所有格式中的工作方式相同：

- **你自己的 provider key**：`<provider>/<model>`，例如 `openai/gpt-5.4-mini` 或 `azure/<deployment-name>`。gateway 会使用存储在你工作区中的 [provider key](/langsmith/llm-gateway-provider-authentication) 调用 provider。
- **Gateway Credits**：托管模型 slug，例如 `moonshotai/kimi-k3`。[Gateway Credits](/langsmith/llm-gateway-credits) 会把 LangChain 托管的模型费用计入你的 LangSmith account，无需 provider key。
- **已保存的模型配置**：`custom/<name>`。gateway 会使用已保存的[模型配置](/langsmith/llm-gateway-model-configurations)中的 provider、模型和凭证。

### 列出模型

调用 `GET /v1/models` 可以列出你的工作区可调用的 model ID。gateway 会返回一个 OpenAI 兼容的列表：

```bash
curl https://gateway.smith.langchain.com/v1/models \
    -H "Authorization: Bearer $LANGSMITH_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    {"id": "openai/gpt-5.4-mini", "object": "model"},
    {"id": "fireworks/accounts/fireworks/models/glm-5p2", "object": "model"},
    {"id": "anthropic/claude-opus-5", "object": "model"},
    {"id": "moonshotai/kimi-k3", "object": "model"}
  ]
}
```

请按原样传入 ID。该列表会省略未配置 provider key 的 provider，以及被你的 [model access policies](/langsmith/llm-gateway-model-access-policies) 阻止的模型。已保存的模型配置不会出现在列表中。

## 读取响应 metadata

gateway 会在响应中添加 `X-LangSmith-Gateway-Metadata` header。该 header 是一个 JSON 对象，描述 gateway 如何处理请求，例如它调用了哪个 provider 和模型，以及是否有策略阻止了请求。它不包含凭证，也不包含 prompt 和响应内容。

要区分 gateway 的决策和 provider 错误，请读取两个字段：`outcome` 表示请求如何结束，例如 `success`、`blocked` 或 `upstream_error`；`error_source` 表示失败来自调用方（`request`）、provider（`upstream`）还是 gateway（`internal`）。当 [fallback 链](/langsmith/llm-gateway-fallbacks#investigate-fallback-attempts)运行时，该 header 还会列出每次尝试。

Python 中的 LangChain chat models（`langchain-openai>=1.6.7` 或 `langchain-anthropic>=1.7.5`）会把该 header 附加到模型的 run 上，因此在开启 [tracing](/langsmith/observability) 时，相同的详细信息会显示在该 run 的 **Gateway** 部分。

## 修复请求错误

| 状态或现象 | 含义 |
| --- | --- |
| `400 Bad Request` | 请求格式错误、model ID 不可用或格式不正确，或请求无法被转换。 |
| `429 Too Many Requests` | 触发了 gateway [rate limit policy](/langsmith/llm-gateway-rate-limit-policies) 或达到了上游 provider 的速率限制。 |
| `GET /v1/models` 中没有出现带 provider 前缀的模型 | provider 可能未配置，或者没有返回模型目录。 |

要判断错误是由 gateway 还是 provider 返回的，请读取[响应 metadata](#读取响应-metadata)中的 `outcome` 和 `error_source` 字段。

<Tip>
关于 `401` 和 `403` 错误，请参见 [Fix authentication errors](/langsmith/llm-gateway-authentication#fix-authentication-errors)。关于 `424` 错误，请参见 [Fix provider credential errors](/langsmith/llm-gateway-provider-authentication#fix-provider-credential-errors)。
</Tip>
