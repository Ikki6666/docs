LangSmith 中的 [Evaluators](/langsmith/evaluation-concepts#evaluators) 是[工作区级别](/langsmith/administration-overview#workspaces)资源。可以将一个 evaluator 附加到多个[tracing projects](/langsmith/observability-concepts#projects)和[datasets](/langsmith/evaluation-concepts#datasets)上，因此能在整个工作中复用一致的评估逻辑，而不必每次重新创建。

<Tip>
[LangSmith Engine](/langsmith/engine) 会为检测到的问题推荐自定义 evaluators，并支持一键部署。
</Tip>

## 查看 evaluators

在 [LangSmith UI](https://smith.langchain.com) 中，点击左侧边栏的 **Evaluators**，即可查看工作区中的所有 evaluators。

Evaluators 表格包含以下列：

| Column | Description |
|--------|-------------|
| Name | evaluator 名称 |
| Type | **LLM as a judge** 或 **Code**。Composite score evaluators 仅作用于单个 tracing project 和 dataset，因此不会显示在这里。 |
| Feedback Key | evaluator 产出的 feedback key |
| Projects & Datasets | 该 evaluator 关联的 tracing projects 和 datasets |
| Evaluator Trace Count (this week) | 该 evaluator 在过去一周运行过的 traces 数量。仅在启用 spend tracking 时显示；对于 Code evaluators 或没有附加规则的 evaluators 显示为 **–**。 |
| Spend (this week) | 该 evaluator 在过去一周的预估美元花费。仅在启用 spend tracking 时显示；对于 Code evaluators 或没有附加规则的 evaluators 显示为 **–**。 |
| Spend Status | evaluator 当前是 **Under limits**、**Unlimited**，还是已触达一个或多个配置的花费限制。仅在启用 spend tracking 时显示；对于 Code evaluators 显示为 **–**。 |
| Created By | 创建该 evaluator 的工作区成员 |
| Updated At | 上次修改时间 |
| Created At | 创建时间 |

## 创建 evaluator

可以在 [LangSmith UI](https://smith.langchain.com) 中创建 evaluator，也可以通过 [SDK](#使用-sdk-创建-evaluator) 以编程方式创建。无论通过哪种方式创建，evaluator 都是工作区级资源，并会显示在 **Evaluators** 表中。

### 在 UI 中创建 evaluator

1. 在 [LangSmith UI](https://smith.langchain.com) 中，点击左侧边栏的 **Evaluators**。
1. 点击 **+ Evaluator** 打开新 evaluator 面板。
1. 该面板允许你：
   - **Create from scratch**：新建一个 [LLM-as-a-Judge](/langsmith/llm-as-judge) 或 [Code](/langsmith/online-evaluations-code) evaluator。
   - **Add a LangChain Tuned Evaluator**：为一个兼容的 tracing project 关联一个[由 LangChain 管理的专用 judge](/langsmith/tuned-evaluators)，无需配置 prompt、model 或 API key。
   - **Create from a template**：从现成 evaluator（也称 prebuilt evaluator）模板开始，适用于常见评估模式。面板中会先显示一个 **Recommended** 区域，列出热门模板，之后再按以下类别组织：

     | Category | Description |
     |----------|-------------|
     | Security | 检测泄露、注入和对抗性输入。 |
     | Safety | 评估内容安全和审核表现。 |
     | Quality | 衡量输出质量和准确性。 |
     | Conversation | 评估对话质量和用户体验。 |
     | Trajectory | 评估 agent 的工具使用和决策路径。 |
     | Image Evaluations | 评估图像内容质量与安全性。 |
     | Voice Evaluation | 评估语音和音频交互质量。 |

也可以直接在[tracing project](/langsmith/observability-concepts#projects)或[dataset](/langsmith/evaluation-concepts#datasets)中添加 evaluator。在这个流程里，还可以从工作区中**附加一个已有 evaluator**，或者创建一个 [Composite](/langsmith/composite-evaluators-ui) evaluator。可参阅[设置 LLM-as-a-judge 在线 evaluators](/langsmith/online-evaluations-llm-as-judge)和[在实验上自动运行 evaluators](/langsmith/bind-evaluator-to-dataset)。

### 使用 SDK 创建 evaluator

可以使用 LangSmith SDK 以编程方式创建 evaluator。SDK 提供 [Python](/langsmith/smith-python-sdk) 和 [TypeScript](/langsmith/smith-js-ts-sdk) 版本。通过 SDK 创建的 evaluator 也会与通过 UI 创建的 evaluator 一样，显示在 **Evaluators** 表中。

<Note>
通过 SDK 管理 evaluators 需要 `langsmith>=0.9.8`（Python，PyPI）或 `langsmith>=0.7.16`（TypeScript，npm）。
</Note>

<CodeGroup>
```python Python
import asyncio

from langsmith import Client


async def main():
    client = Client()

    created = await client.evaluators.create(
        name="Correctness evaluator",
        type="code",
        code_evaluator={
            "code": "def perform_eval(run, example):\n    return {'score': 1}",
            "language": "python",
        },
    )
    print("Created evaluator:", created.evaluator.id)


asyncio.run(main())
```
```typescript TypeScript
import { Client } from "langsmith";

const client = new Client();

const created = await client.evaluators.create({
  name: "Correctness evaluator",
  type: "code",
  code_evaluator: {
    code: "def perform_eval(run, example):\n    return {'score': 1}",
    language: "python",
  },
});
console.log("Created evaluator:", created.evaluator?.id);
```
</CodeGroup>

若要创建 LLM-as-a-judge evaluator，以及检索、更新、列出或删除 evaluator，请参阅[使用 SDK 管理 evaluators](/langsmith/manage-evaluators-sdk)。

## 查看 evaluator 详情

点击表格中的任意 evaluator，即可打开详情视图。详情视图包含四个标签页：

- **Overview**：evaluator 的反馈配置，以及 prompt 或代码定义。
- **Traces**：该 evaluator 在所有已附加资源上处理过的 traces。
- **Logs**：该 evaluator 在所有已附加资源上的执行日志。
- **Projects & Datasets**：该 evaluator 当前附加到的 tracing projects 和 datasets，以及每个附加项对应的[每周支出与限制](/langsmith/evaluator-spend)。

## 编辑 evaluator

打开某个 evaluator。在 **Overview** 标签页中，点击 **Edit evaluator** <Icon icon="pencil"/> 图标，打开 **Configure Evaluator** 面板。更新 evaluator 配置后，点击 **Save**。

由于 evaluator 是共享资源，修改会应用到它附加的所有 tracing projects 和 datasets。

## 管理 evaluator trace retention

当在线 evaluator 为某条 trace 打分时，它会将 feedback 附加到该 trace 上，这会[自动将 trace 升级为 extended retention](/langsmith/usage-and-billing#data-retention-auto-upgrades)。Extended retention 会让 trace 保留更久，但成本也更高。为[tracing project](/langsmith/observability-concepts#projects)设置在线 evaluator 时，可以选择退出这个升级，使已评分 traces 继续保持项目的基础保留策略。

只有当项目的[默认保留策略](/langsmith/billing#change-project-level-default-retention)是[base tier](/langsmith/usage-and-billing#how-it-works)时，这个控制项才可用。如果项目默认就是 extended retention（[可在项目级或工作区级设置](/langsmith/data-purging-compliance#data-retention)），那么 evaluator 打分后的 traces 会沿用该默认值，并且这个选项会被锁定。

若要关闭已评分 traces 的 retention 延长：

1. 在[创建](#create-an-evaluator)或[编辑](#edit-an-evaluator)在线 evaluator 时，将 source 设为一个[tracing project](/langsmith/observability-concepts#projects)，而不是[dataset](/langsmith/evaluation-concepts#datasets)。
1. 展开 evaluator 配置面板中的 **Advanced** 区域。
1. 取消选中 **Extend trace retention**。

这一变更只会影响保存之后被该 evaluator 打分的新 traces。已有已评分 traces 会保留当前的 retention tier。

## 纳入扩展统计信息

在 [run-level evaluator](/langsmith/online-evaluations-llm-as-judge) 中使用 **Include extended stats (feedback, costs, tokens)**，可以评估来自该 run 的 feedback 统计信息、token 用量或成本数据。`feedback_stats` 字段包含 feedback 统计信息，包括每个 feedback key 的数量和平均值。此选项不适用于[multi-turn（thread-level）evaluator](/langsmith/online-evaluations-multi-turn)。

LangSmith 会为启用了此选项的 evaluator 额外拉取数据。仅当你的评估逻辑或 prompt 需要这些字段时才启用它。

要纳入扩展统计信息：

1. 在[创建](#create-an-evaluator)或[编辑](#edit-an-evaluator) run-level evaluator 时，展开 evaluator 配置面板中的 **Advanced** 区域。
1. 选中 **Include extended stats (feedback, costs, tokens)**。

### 访问扩展统计信息

[Code evaluators](/langsmith/online-evaluations-code) 会在 `run` 对象中接收到这些字段，包括 `feedback_stats`、`total_tokens` 和 `total_cost`。无论是否启用扩展统计信息，它们都会在 `run["feedback"]` 中收到[单条 feedback 记录](/langsmith/feedback-data-format)。对于 [LLM-as-a-judge evaluator](/langsmith/online-evaluations-llm-as-judge)，请将对应的 `run.*` 字段映射到某个 prompt 变量。例如，把 `{{correctness_average}}` 映射到 `run.feedback_stats.correctness.avg`，即可在 prompt 中纳入 `correctness` feedback 的平均值。可用的 `run.*` 字段还包括 prompt 和 completion 的 token、成本以及 detail 字段。完整的 run 数据 schema 请参阅 [Run data format](/langsmith/run-data-format)。

### 链式 evaluator

扩展统计信息可用于链式 evaluator：一个 code evaluator 读取另一个 evaluator 已经产生的分数。将第二个 evaluator 按第一个 evaluator 的 feedback key 进行过滤（例如 `has(feedback_key, "answer_usefulness")`），然后启用扩展统计信息。该过滤器使 code evaluator 仅在该分数存在之后才运行，而扩展统计信息让该分数可以通过 `run["feedback_stats"]["answer_usefulness"]["avg"]` 读取。

过滤器匹配的是 feedback key，而非产生它的 evaluator，因此任何来源只要使用了该 key，其 feedback 都会触发该 code evaluator。要配置过滤器，请参阅[为触发 evaluator 的 run 应用过滤器](/langsmith/online-evaluations-code#configure-online-evaluators)。

## 删除 evaluator

当 evaluator 仍附加在某个 tracing project 或 dataset 上时，无法删除。要删除 evaluator：

1. 在 [LangSmith UI](https://smith.langchain.com) 中，点击左侧边栏的 **Evaluators**。
1. 选择你要删除的 evaluator。
1. 打开 **Projects & Datasets** 标签页。对于每个已附加的 tracing project 和 dataset，在该行右侧的 **Actions** 菜单中选择 **Detach**。
1. 返回 **Evaluators** 页面，点击页面顶部的 **Delete**。
