[`langsmith-codex-plugins`](https://github.com/langchain-ai/langsmith-codex-plugins) marketplace 提供了一个 tracing plugin，可将 [OpenAI Codex](https://developers.openai.com/codex) 会话数据发送到 LangSmith。你可以用它检查 Codex 工作流中的智能体回合、模型 metadata、token 用量、工具调用和 subagent threads。

## 前提条件

在设置 tracing 之前，确保你已具备：

- [Codex CLI](https://developers.openai.com/codex/quickstart?setup=cli) v0.128 或更高版本。
- 一个 [LangSmith API key](/langsmith/create-account-api-key)。

## 安装并启用插件

使用 Codex CLI 添加 marketplace：

```bash
codex plugin marketplace add langchain-ai/langsmith-codex-plugins
```

在全局 `~/.codex/config.toml` 中，或仅在某个项目的 `.codex/config.toml` 中，启用 plugin hooks 和 tracing plugin：

```toml
[features]
plugin_hooks = true

[plugins."tracing@langsmith-codex-plugins"]
enabled = true
```

## 配置 tracing

只有当 `TRACE_TO_LANGSMITH` 为 `"true"`，或配置文件中 `enabled` 为 `true` 时，tracing 才会启用。你可以通过环境变量、JSON 配置文件，或两者结合来配置凭证。

### 环境变量

插件会优先读取 Codex 专用变量，然后回退到通用的 LangSmith SDK 变量。

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `TRACE_TO_LANGSMITH` | Yes | - | 设置为 `"true"` 以启用 tracing。 |
| `LANGSMITH_CODEX_API_KEY` | Conditional | - | LangSmith API key。回退到 `LANGSMITH_API_KEY`。除非每个 replica 都提供自己的 API key，否则该项必填。 |
| `LANGSMITH_CODEX_ENDPOINT` | No | `https://api.smith.langchain.com` | LangSmith API URL。回退到 `LANGSMITH_ENDPOINT`。 |
| `LANGSMITH_CODEX_PROJECT` | No | `codex` | LangSmith project 名称。回退到 `LANGSMITH_PROJECT`。 |
| `LANGSMITH_CODEX_METADATA` | No | - | 合并到根 trace metadata 的 JSON 对象。回退到 `LANGSMITH_METADATA`。 |
| `LANGSMITH_CODEX_RUNS_ENDPOINTS` | No | - | replica 目标的 JSON 数组。回退到 `LANGSMITH_RUNS_ENDPOINTS`。 |

把这些变量加到你的 shell 配置文件中，例如 `~/.zshrc`、`~/.bashrc` 或 `~/.bash_profile`：

```bash
export TRACE_TO_LANGSMITH="true"
export LANGSMITH_CODEX_API_KEY="<your-langsmith-api-key>"
export LANGSMITH_CODEX_PROJECT="codex"
```

### 配置文件

使用 `<project>/.codex/langsmith.json` 作为项目级设置，或使用 `~/.codex/langsmith.json` 作为全局默认值。全局文件会先加载，项目文件会覆盖它，而匹配的环境变量又会优先于这两者。

```json
{
  "enabled": true,
  "api_key": "<your-langsmith-api-key>",
  "api_url": "https://api.smith.langchain.com",
  "project": "codex",
  "metadata": {
    "team": "agents",
    "environment": "dev"
  }
}
```

| Field | Environment variable | Default | Description |
| --- | --- | --- | --- |
| `enabled` | `TRACE_TO_LANGSMITH` | `false` | 设置为 `true` 以启用 tracing。 |
| `api_key` | `LANGSMITH_CODEX_API_KEY`, `LANGSMITH_API_KEY` | - | LangSmith API key。 |
| `api_url` | `LANGSMITH_CODEX_ENDPOINT`, `LANGSMITH_ENDPOINT` | LangSmith default | LangSmith API URL。 |
| `project` | `LANGSMITH_CODEX_PROJECT`, `LANGSMITH_PROJECT` | `codex` | LangSmith project 名称。 |
| `metadata` | `LANGSMITH_CODEX_METADATA`, `LANGSMITH_METADATA` | - | 合并到根 trace metadata 的对象。 |
| `replicas` | `LANGSMITH_CODEX_RUNS_ENDPOINTS`, `LANGSMITH_RUNS_ENDPOINTS` | - | 额外的 LangSmith 目标，用于复制 traces。 |

包含 API keys 的配置文件不要纳入版本控制。

## 跟踪到多个目标

在 `langsmith.json` 或 `LANGSMITH_CODEX_RUNS_ENDPOINTS` 中设置 `replicas`，即可将相同的 trace 数据发送到额外的 LangSmith workspaces 或 projects。设置后，replica 列表会覆盖其他 client 设置。

跟踪到多个 [replicas](/langsmith/log-traces-to-project) 的常见用途包括：

- 同时将 traces 发送到生产 project 和 staging project。
- 使用不同 API keys 将 traces 发送到多个 workspaces。
- 为特定 replica 目标附加额外 metadata。

<Tabs>

<Tab title="Config file (recommended)">

在 `<project>/.codex/langsmith.json` 或 `~/.codex/langsmith.json` 中：

```json
{
  "enabled": true,
  "replicas": [
    {
      "apiUrl": "https://api.smith.langchain.com",
      "apiKey": "lsv2_pt_workspace_a",
      "projectName": "project-prod"
    },
    {
      "apiUrl": "https://api.smith.langchain.com",
      "apiKey": "lsv2_pt_workspace_b",
      "projectName": "project-staging",
      "updates": { "metadata": { "environment": "staging" } }
    }
  ]
}
```

</Tab>

<Tab title="Shell environment variable">

```bash
export LANGSMITH_CODEX_RUNS_ENDPOINTS='[{"apiUrl":"https://api.smith.langchain.com","apiKey":"lsv2_pt_workspace_a","projectName":"project-prod"},{"apiUrl":"https://api.smith.langchain.com","apiKey":"lsv2_pt_workspace_b","projectName":"project-staging","updates":{"metadata":{"environment":"staging"}}}]'
```

如需生成转义后的 JSON 字符串，可以使用：

```bash
echo '[{"apiUrl":"...","apiKey":"...","projectName":"..."}]' | jq -c .
```

</Tab>

</Tabs>

每个 replica 对象支持以下字段：

| Field | Required | Description |
| --- | --- | --- |
| `apiUrl` | Yes | LangSmith API URL，通常为 `https://api.smith.langchain.com`。 |
| `apiKey` | Yes | 目标 workspace 的 API key。 |
| `projectName` | Yes | 目标 workspace 中的 project 名称。 |
| `updates` | No | 可选的 run 字段覆盖项，例如额外 metadata。 |

## 会跟踪哪些内容

每个 LLM run 都会包含：

- **Inputs**：累计的对话消息。
- **Outputs**：assistant 响应内容。
- **Metadata**：模型 provider、模型名称、停止原因和 token 用量。

工具调用，函数调用、shell 调用、computer 调用、文件读取、web 搜索，都会连同它们的输入和输出一起记录。Subagent threads 会被解析并作为嵌套子 runs，上传到父回合下。

如果用户在响应中途取消，导致回合被中断，该回合仍会在整个会话完成后上传。

## 在 LangSmith 中查看 traces

打开配置好的 LangSmith project，并完成一个 Codex 回合。默认情况下，traces 会出现在 `codex` project 中。该插件会上传已完成的 Codex transcript 数据，包括消息、工具调用输入与输出、模型 metadata、token 用量，以及 subagent thread 结构。

<Warning>
该插件会将完整的 Codex transcript 数据上传到 LangSmith。对于包含你不希望存储在 LangSmith 中的数据的会话，请不要启用 tracing。
</Warning>

## 故障排查

如果 traces 没有出现在 LangSmith 中：

- 确认 `plugin_hooks = true`，并且 tracing plugin 已在 `config.toml` 中启用。
- 确认 `TRACE_TO_LANGSMITH=true` 对 Codex 进程是可见的。
- 确认 `LANGSMITH_CODEX_API_KEY` 或 `LANGSMITH_API_KEY` 已设置且有效。
- 如果 runs 落到了错误的 project，请设置 `LANGSMITH_CODEX_PROJECT` 或配置中的 `project` key。
- 如果自定义 endpoint 没生效，请设置 `LANGSMITH_CODEX_ENDPOINT` 或配置中的 `api_url` key。
