LangSmith tracing 插件会把你的 [OpenAI Codex](https://developers.openai.com/codex) 会话发送到 LangSmith，让你看到 agent 做了什么。每个 turn 都会成为一条 trace，同一会话中的 turns 则归入同一个 thread。

## 前提条件

- [Codex CLI](https://developers.openai.com/codex/quickstart?setup=cli) v0.153.4 或更高版本。
- 拥有一个 LangSmith 账户。
- 在 Windows 和 Linux 上需要 [Node.js](https://nodejs.org/) 22.x 或更高版本。在 macOS 上，插件会自行构建，无需 Node.js。

## 安装插件

添加 marketplace 并安装插件：

```bash
codex plugin marketplace add langchain-ai/langsmith-codex-plugins
codex plugin add tracing@langsmith-codex-plugins
```

然后在 Codex 中用 `/hooks` 信任该插件的 hooks，因为在你信任之前不会进行任何 tracing。Codex 只会在交互式界面中询问，因此在你信任一次之前，`codex exec` 会跳过这些 hooks。信任后请重启 Codex。想为所有人安装该插件，请参阅[部署到组织](#部署到组织)。有关安装插件的更多信息，请参阅 Codex 文档中的 [Plugins](https://developers.openai.com/codex/plugins)。

## 登录

使用 LangSmith CLI 登录一次。如果还没有安装，请参阅[安装 LangSmith CLI](/langsmith/langsmith-cli#install)。

```bash
langsmith auth login
```

如果你使用 CLI 登录并且有多个 profile，请在配置文件中把 `profile` 设为插件应使用的那个。你自己的 `api_key` 会忽略此设置，但在设置了 `profile` 时，通用的 `LANGSMITH_API_KEY` 不会被用作回退。

如果想改用 API key，请把它添加到 `~/.codex/langsmith.json`：

```json
{ "enabled": true, "api_key": "lsv2_pt_...", "agent_id": "shared-codex" }
```

如果设置了多个凭据，插件会使用它找到的第一个：

1. 插件自己的 key，来自 `api_key` 或 `LANGSMITH_CODEX_API_KEY`。
2. 你的 `langsmith auth login` 登录。
3. 环境中的通用 `LANGSMITH_API_KEY`。

当登录过期或 key 被拒绝时，tracing 会停止，这段空档期内的 turn 永远不会被上传。在你修复之前，Codex 会在聊天中显示一条通知。管理员还可以为每个 prompt [要求有效的登录](#要求有效的登录)。

## 开启 tracing

除非管理员已经通过[托管文件](#锁定设置)开启了 tracing，否则在你于 `~/.codex/langsmith.json` 中开启之前，tracing 都处于关闭状态。使用 `agent_id` 把 traces 发送到某个 [agent](/langsmith/log-traces-to-agent#send-traces-to-an-agent)：

```json
{ "enabled": true, "agent_id": "shared-codex" }
```

或者使用 `project` 把它们发送到某个 project：

```json
{ "enabled": true, "project": "shared-codex" }
```

两者任选其一。如果同时设置，`agent_id` 优先。

<Warning>
项目可以用 `<project>/.codex/langsmith.json` 或 `<project>/langsmith-plugins.json` 覆盖这些设置。克隆下来的仓库可以利用它们开启 tracing，把你的对话和文件发送到别人的服务器。在你信任某个仓库之前，请连同 `.codex/config.toml` 和 `.codex/hooks.json` 一起检查它的 LangSmith 配置文件。
</Warning>

完成一个 turn，然后在 [LangSmith](https://smith.langchain.com) 中打开你的 agent 或 project。

## 隐藏对话

发送 `langsmith-tracing:mute` 作为普通消息（不要带前导斜杠），可以让 thread 内容不进入 LangSmith；发送 `langsmith-tracing:unmute` 则重新开启。确认信息会以被 hook 阻止的 prompt 形式出现，因为这就是 Codex 展示插件回复的方式。若要默认静音所有 thread，请将 `defaultMuted` 设为 `true`。

## 设置

每项设置都有一个配置文件 key 和一个环境变量。两者都设置时，环境变量优先。

| 配置 key | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enabled` | `TRACE_TO_LANGSMITH` | `false` | 开启 tracing。 |
| `api_key` | `LANGSMITH_CODEX_API_KEY` | 无 | LangSmith API key。如果使用 CLI 登录则不需要。 |
| `project` | `LANGSMITH_CODEX_PROJECT` | `codex` | traces 发送到的 project。与 `agent_id` 二选一。 |
| `agent_id` | `LANGSMITH_AGENT_ID` | 无 | traces 发送到的 agent。两者都设置时优先于 `project`。 |
| `api_url` | `LANGSMITH_CODEX_ENDPOINT` | `https://api.smith.langchain.com` | 发送到的 LangSmith 服务器。 |

有关全部设置，请参阅[插件设置](https://github.com/langchain-ai/langsmith-codex-plugins#settings)。要把 traces 发送到多个地方，请参阅[把 trace 发送到多个地方](https://github.com/langchain-ai/langsmith-codex-plugins#send-a-trace-to-more-than-one-place)。

## 故障排查

- **没有 traces**：检查插件是否已安装、其 hooks 是否已通过 `/hooks` 信任，以及 tracing 是否已开启。
- **更新后停止**：每当某个版本更改了 hook，Codex 都会要求你重新信任它。运行 `/hooks` 并批准。
- **Tracing 已暂停**：再次运行 `langsmith auth login`，或替换被拒绝的 API key。

更多修复方法，请参阅[当没有任何内容出现时](https://github.com/langchain-ai/langsmith-codex-plugins#when-nothing-shows-up)。
