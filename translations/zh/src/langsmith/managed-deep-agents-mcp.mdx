Managed Deep Agents 通过 connectors 加载远程 MCP server 暴露的 tools。你需要在 `connectors/mcp.ts` 或 `connectors/mcp.py` 中声明 MCP servers，并导出一个命名的 `mcp` 声明，MDA 会在运行时把这些 tools 加载到 agent 中。

<Note>
<ManagedDeepAgentsPrivateBetaNote />
</Note>

当前 `mda` CLI 不包含 workspace MCP server 管理命令。对于 Managed Deep Agents 项目，请不要继续使用旧的 `deepagents mcp-servers ...` 示例。需要 MCP tools 时，请使用本页介绍的 `connectors/` 项目约定。

## 添加 connector

在 agent 入口文件旁边添加 `connectors/mcp.py` 或 `connectors/mcp.ts`。完整项目布局请参见 [CLI project file reference](/langsmith/managed-deep-agents-cli#project-file-reference)。

Connector 模块必须导出一个命名的 `mcp` 声明。

<CodeGroup>

```python connectors/mcp.py
from managed_deepagents.connectors import define_mcp_servers

mcp = define_mcp_servers(
    mcp_servers={
        "langchainDocs": {
            "transport": "http",
            "url": "https://docs.langchain.com/mcp",
        },
    },
)
```

```ts connectors/mcp.ts
import { defineMcpServers } from "managed-deepagents";

export const mcp = defineMcpServers({
  mcpServers: {
    langchainDocs: {
      transport: "http",
      url: "https://docs.langchain.com/mcp",
    },
  },
});
```

</CodeGroup>

你不需要自己导入 `MultiServerMCPClient`，也不需要手动调用 `getTools()` 或 `get_tools()`。`mda` 会自动发现 connector 模块，向编译后的 build 注入 MCP adapter 依赖，在托管运行时创建 client、加载 tools，并将它们追加到 `agent.ts` 或 `agent.py` 中定义的自编写 tools 后面。

## 支持的 servers

Connectors 仅支持远程 MCP servers：

| Transport | 用途 |
| --- | --- |
| `http` | Streamable HTTP MCP servers。 |
| `sse` | 旧版 SSE MCP servers。 |

Connectors 不支持 stdio MCP servers。如果某个 server 依赖本地进程管理，请将其改为通过 HTTP/SSE 暴露，或把它封装为普通自编写 tool。

## 配置 server 选项

每个 server key 都是 MDA 在校验、tracing metadata 和 tool-name prefixing 中使用的逻辑 server 名称。Server 配置中可以包含静态 headers。

Connectors 不会执行 OAuth 授权流程。如果某个 MCP server 需要 OAuth，请通过 headers 传入预先发放的 access token，或传入其他静态凭据。请将 token 存在 `.env` 中，以便 `mda dev` 在本地加载，`mda deploy` 在部署时转发为托管 deployment secret。

Connector 模块本身就是普通项目代码，因此应在 Python 中通过 `os.environ`，在 TypeScript 中通过 `process.env` 读取 secrets。不要直接导入 `.env` 文件。

<CodeGroup>

```python connectors/mcp.py
import os

from managed_deepagents.connectors import define_mcp_servers

mcp = define_mcp_servers(
    mcp_servers={
        "github": {
            "transport": "http",
            "url": "https://example.com/mcp",
            "headers": {
                "Authorization": f"Bearer {os.environ['GITHUB_MCP_TOKEN']}",
            },
        },
    },
)
```

```ts connectors/mcp.ts
import { defineMcpServers } from "managed-deepagents";

export const mcp = defineMcpServers({
  mcpServers: {
    github: {
      transport: "http",
      url: "https://example.com/mcp",
      headers: {
        Authorization: `Bearer ${process.env.GITHUB_MCP_TOKEN}`,
      },
    },
  },
});
```

</CodeGroup>

<Warning>
不要提交 MCP tokens、API keys、OAuth access tokens 或密码。本地值请放在 `.env` 中；`mda dev` 会在本地开发时加载它们，`mda deploy` 会把非保留 `.env` 值转发为托管 deployment secrets。
</Warning>

## Connector 默认值

MDA 在加载 connector tools 时会应用一组托管默认值：

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `prefixToolNameWithServerName` / `prefix_tool_name_with_server_name` | `true` | 以 server 名称作为 MCP tool 前缀，例如 `github__search`，避免命名冲突。 |
| `throwOnLoadError` / `throw_on_load_error` | `true` | 若 tools 无法加载，则直接失败，而不是带着残缺的 tool surface 启动。 |
| `useStandardContentBlocks` / `use_standard_content_blocks` | `true` | 将 MCP tool 输出转换为标准 LangChain content blocks。Python connectors 当前必须使用默认值 `true`。 |
| `onConnectionError` / `on_connection_error` | `"throw"` | 当 server 不可达时直接失败。当前仅支持 `"throw"`。 |

只有在你明确知道 MCP tool 名称不会冲突时，才应关闭 tool-name prefixing。关闭前缀时，MDA 会校验是否存在重复的 MCP tool 名称。

## 将 connectors 与自编写 tools 结合

Connector tools 会追加到你在 agent 文件中定义的 tools 之后。对于项目自有代码，请使用 [custom tools](/langsmith/managed-deep-agents-tools)；对于围绕模型调用、工具调用、生命周期 hooks、重试、限制和数据处理的横切行为，请使用 [custom middleware](/langsmith/managed-deep-agents-middleware)。
