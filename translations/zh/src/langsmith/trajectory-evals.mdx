许多 agent 行为只有在使用真实 LLM 时才会显现出来，例如 agent 会决定调用哪个工具、它如何组织响应格式，或者 prompt 的修改是否会影响整个执行轨迹。LangChain 的 [`agentevals`](https://github.com/langchain-ai/agentevals) 包提供了一组专门用于使用在线模型测试 agent trajectories 的 evaluators。

<Note>
本指南介绍开源 [LangChain](/oss/langchain/overview) `agentevals` 包，它与 LangSmith 集成用于 trajectory evaluation。
</Note>

AgentEvals 支持通过 _trajectory match_，或者借助 _LLM judge_，来评估 agent 的 trajectory（即消息的精确序列，包括 tool calls）：

<Card title="Trajectory match" icon="equal" arrow="true" href="#trajectory-match-evaluator">
为某个给定输入硬编码一个参考 trajectory，并通过逐步比对来验证运行结果。

适用于行为预期明确的工作流测试场景。适合在你清楚知道应该调用哪些工具、以及调用顺序时使用。该方法具备确定性、速度快、成本低的优点，因为它不需要额外的 LLM 调用。
</Card>

<Card title="LLM-as-judge" icon="hammer" arrow="true" href="#llm-as-judge-evaluator">
使用 LLM 从定性角度验证 agent 的执行 trajectory。"judge" LLM 会根据 prompt rubric（其中也可以包含参考 trajectory）来审查 agent 的决策。

这种方式更加灵活，可以评估效率和适切性等细腻维度，但需要额外的 LLM 调用，且确定性更弱。适合在你想评估 trajectory 的整体质量与合理性，而不是对工具调用或顺序有严格要求时使用。
</Card>

## Trajectory match evaluator

AgentEvals 在 Python 中提供 `create_trajectory_match_evaluator` 函数，在 TypeScript 中提供 `createTrajectoryMatchEvaluator`，用于将 agent 的 trajectory 与参考 trajectory 进行匹配。

你可以使用以下模式：

| Mode | Description | Use Case |
|------|-------------|----------|
| [`strict`](#strict-match) | 消息和 tool calls 在相同顺序下完全匹配 | 测试特定顺序（例如先查询策略，再执行授权） |
| [`unordered`](#unordered-match) | 相同的 tool calls 可以按任意顺序出现 | 验证信息检索类场景，在顺序无关紧要时使用 |
| [`subset`](#subset-and-superset-match) | agent 只能调用参考中出现的工具（不能有额外工具） | 确保 agent 不会超出预期范围 |
| [`superset`](#subset-and-superset-match) | agent 至少调用参考中的工具（允许额外工具） | 验证最低限度的必要动作已经执行 |

### Strict match

`strict` 模式要求 trajectory 中的消息和 tool calls 在相同顺序下保持一致，虽然允许消息内容本身存在差异。当你需要强制某个特定操作顺序时，这种方式很有用，例如要求必须先查询策略，再授权某个动作。

<CodeGroup>

```python Python
from langchain.agents import create_agent
from langchain.tools import tool
from langchain.messages import HumanMessage, AIMessage, ToolMessage
from agentevals.trajectory.match import create_trajectory_match_evaluator


@tool
def get_weather(city: str):
    """Get weather information for a city."""
    return f"It's 75 degrees and sunny in {city}."

agent = create_agent("gpt-5.5", tools=[get_weather])

evaluator = create_trajectory_match_evaluator(  # [!code highlight]
    trajectory_match_mode="strict",  # [!code highlight]
)  # [!code highlight]

def test_weather_tool_called_strict():
    result = agent.invoke({
        "messages": [HumanMessage(content="What's the weather in San Francisco?")]
    })

    reference_trajectory = [
        HumanMessage(content="What's the weather in San Francisco?"),
        AIMessage(content="", tool_calls=[
            {"id": "call_1", "name": "get_weather", "args": {"city": "San Francisco"}}
        ]),
        ToolMessage(content="It's 75 degrees and sunny in San Francisco.", tool_call_id="call_1"),
        AIMessage(content="The weather in San Francisco is 75 degrees and sunny."),
    ]

    evaluation = evaluator(
        outputs=result["messages"],
        reference_outputs=reference_trajectory
    )
    # {
    #     'key': 'trajectory_strict_match',
    #     'score': True,
    #     'comment': None,
    # }
    assert evaluation["score"] is True
```

```ts TypeScript
import { createAgent, tool, HumanMessage, AIMessage, ToolMessage } from "langchain"
import { createTrajectoryMatchEvaluator } from "agentevals";
import * as z from "zod";

const getWeather = tool(
  async ({ city }: { city: string }) => {
    return `It's 75 degrees and sunny in ${city}.`;
  },
  {
    name: "get_weather",
    description: "Get weather information for a city.",
    schema: z.object({
      city: z.string(),
    }),
  }
);

const agent = createAgent({
  model: "gpt-5.5",
  tools: [getWeather]
});

const evaluator = createTrajectoryMatchEvaluator({  // [!code highlight]
  trajectoryMatchMode: "strict",  // [!code highlight]
});  // [!code highlight]

async function testWeatherToolCalledStrict() {
  const result = await agent.invoke({
    messages: [new HumanMessage("What's the weather in San Francisco?")]
  });

  const referenceTrajectory = [
    new HumanMessage("What's the weather in San Francisco?"),
    new AIMessage({
      content: "",
      tool_calls: [
        { id: "call_1", name: "get_weather", args: { city: "San Francisco" } }
      ]
    }),
    new ToolMessage({
      content: "It's 75 degrees and sunny in San Francisco.",
      tool_call_id: "call_1"
    }),
    new AIMessage("The weather in San Francisco is 75 degrees and sunny."),
  ];

  const evaluation = await evaluator({
    outputs: result.messages,
    referenceOutputs: referenceTrajectory
  });
  // {
  //     'key': 'trajectory_strict_match',
  //     'score': true,
  //     'comment': null,
  // }
  expect(evaluation.score).toBe(true);
}
```

</CodeGroup>

### Unordered match

`unordered` 模式允许相同的 tool calls 以任意顺序出现。这在你只关心是否调用了正确的一组工具，而不关心具体先后顺序时非常有用。例如，agent 可能既需要检查某城市的天气，又需要查询活动信息，但调用顺序并不重要。

<CodeGroup>

```python Python
from langchain.agents import create_agent
from langchain.tools import tool
from langchain.messages import HumanMessage, AIMessage, ToolMessage
from agentevals.trajectory.match import create_trajectory_match_evaluator


@tool
def get_weather(city: str):
    """Get weather information for a city."""
    return f"It's 75 degrees and sunny in {city}."

@tool
def get_events(city: str):
    """Get events happening in a city."""
    return f"Concert at the park in {city} tonight."

agent = create_agent("gpt-5.5", tools=[get_weather, get_events])

evaluator = create_trajectory_match_evaluator(  # [!code highlight]
    trajectory_match_mode="unordered",  # [!code highlight]
)  # [!code highlight]

def test_multiple_tools_any_order():
    result = agent.invoke({
        "messages": [HumanMessage(content="What's happening in SF today?")]
    })

    # Reference shows tools called in different order than actual execution
    reference_trajectory = [
        HumanMessage(content="What's happening in SF today?"),
        AIMessage(content="", tool_calls=[
            {"id": "call_1", "name": "get_events", "args": {"city": "SF"}},
            {"id": "call_2", "name": "get_weather", "args": {"city": "SF"}},
        ]),
        ToolMessage(content="Concert at the park in SF tonight.", tool_call_id="call_1"),
        ToolMessage(content="It's 75 degrees and sunny in SF.", tool_call_id="call_2"),
        AIMessage(content="Today in SF: 75 degrees and sunny with a concert at the park tonight."),
    ]

    evaluation = evaluator(
        outputs=result["messages"],
        reference_outputs=reference_trajectory,
    )
    # {
    #     'key': 'trajectory_unordered_match',
    #     'score': True,
    # }
    assert evaluation["score"] is True
```

### Subset and superset match

`superset` 和 `subset` 模式关注的是调用了哪些工具，而不是 tool calls 的顺序，因此你可以控制 agent 的工具调用必须与参考对齐到什么程度。

- 当你想验证执行过程中调用了若干关键工具，但不介意 agent 额外调用更多工具时，使用 `superset` 模式。agent 的 trajectory 必须至少包含参考 trajectory 中的所有工具调用，但也可以多出额外工具调用。
- 当你想通过验证 agent 没有调用任何与参考无关或不必要的额外工具，来确保 agent 更高效时，使用 `subset` 模式。agent 的 trajectory 只能包含参考 trajectory 中出现过的工具调用。

下面的示例演示 `superset` 模式：参考 trajectory 只要求调用 `get_weather` 工具，但 agent 可以额外调用其他工具：

<CodeGroup>

```python Python
from langchain.agents import create_agent
from langchain.tools import tool
from langchain.messages import HumanMessage, AIMessage, ToolMessage
from agentevals.trajectory.match import create_trajectory_match_evaluator


@tool
def get_weather(city: str):
    """Get weather information for a city."""
    return f"It's 75 degrees and sunny in {city}."

@tool
def get_detailed_forecast(city: str):
    """Get detailed weather forecast for a city."""
    return f"Detailed forecast for {city}: sunny all week."

agent = create_agent("gpt-5.5", tools=[get_weather, get_detailed_forecast])

evaluator = create_trajectory_match_evaluator(  # [!code highlight]
    trajectory_match_mode="superset",  # [!code highlight]
)  # [!code highlight]

def test_agent_calls_required_tools_plus_extra():
    result = agent.invoke({
        "messages": [HumanMessage(content="What's the weather in Boston?")]
    })

    # Reference only requires get_weather, but agent may call additional tools
    reference_trajectory = [
        HumanMessage(content="What's the weather in Boston?"),
        AIMessage(content="", tool_calls=[
            {"id": "call_1", "name": "get_weather", "args": {"city": "Boston"}},
        ]),
        ToolMessage(content="It's 75 degrees and sunny in Boston.", tool_call_id="call_1"),
        AIMessage(content="The weather in Boston is 75 degrees and sunny."),
    ]

    evaluation = evaluator(
        outputs=result["messages"],
        reference_outputs=reference_trajectory,
    )
    # {
    #     'key': 'trajectory_superset_match',
    #     'score': True,
    #     'comment': None,
    # }
    assert evaluation["score"] is True
```

## LLM-as-judge evaluator

<Note>
本节介绍的是 `agentevals` 包中面向 trajectory 的 LLM-as-a-judge evaluator。如果你想了解 LangSmith 中更通用的 LLM-as-a-judge evaluators，请参见 [LLM-as-a-judge evaluator](/langsmith/llm-as-judge)。
</Note>

你也可以使用 LLM 来评估 agent 的执行路径。与 trajectory match evaluators 不同，它不需要参考 trajectory，不过如果你有的话也可以提供。

### 不带参考 trajectory

<CodeGroup>

```python Python
from langchain.agents import create_agent
from langchain.tools import tool
from langchain.messages import HumanMessage, AIMessage, ToolMessage
from agentevals.trajectory.llm import create_trajectory_llm_as_judge, TRAJECTORY_ACCURACY_PROMPT


@tool
def get_weather(city: str):
    """Get weather information for a city."""
    return f"It's 75 degrees and sunny in {city}."

agent = create_agent("gpt-5.5", tools=[get_weather])

evaluator = create_trajectory_llm_as_judge(  # [!code highlight]
    model="openai:o3-mini",  # [!code highlight]
    prompt=TRAJECTORY_ACCURACY_PROMPT,  # [!code highlight]
)  # [!code highlight]

def test_trajectory_quality():
    result = agent.invoke({
        "messages": [HumanMessage(content="What's the weather in Seattle?")]
    })

    evaluation = evaluator(
        outputs=result["messages"],
    )
    # {
    #     'key': 'trajectory_accuracy',
    #     'score': True,
    #     'comment': 'The provided agent trajectory is reasonable...'
    # }
    assert evaluation["score"] is True
```

```ts TypeScript
import { createAgent } from "langchain"
import { tool } from "@langchain/core/tools";
import { HumanMessage, AIMessage, ToolMessage } from "@langchain/core/messages";
import { createTrajectoryLLMAsJudge, TRAJECTORY_ACCURACY_PROMPT } from "agentevals";
import * as z from "zod";

const getWeather = tool(
  async ({ city }: { city: string }) => {
    return `It's 75 degrees and sunny in ${city}.`;
  },
  {
    name: "get_weather",
    description: "Get weather information for a city.",
    schema: z.object({ city: z.string() }),
  }
);

const agent = createAgent({
  model: "gpt-5.5",
  tools: [getWeather]
});

const evaluator = createTrajectoryLLMAsJudge({  // [!code highlight]
  model: "openai:o3-mini",  // [!code highlight]
  prompt: TRAJECTORY_ACCURACY_PROMPT,  // [!code highlight]
});  // [!code highlight]

async function testTrajectoryQuality() {
  const result = await agent.invoke({
    messages: [new HumanMessage("What's the weather in Seattle?")]
  });

  const evaluation = await evaluator({
    outputs: result.messages,
  });
  // {
  //     'key': 'trajectory_accuracy',
  //     'score': true,
  //     'comment': 'The provided agent trajectory is reasonable...'
  // }
  expect(evaluation.score).toBe(true);
}
```

</CodeGroup>

### 带参考 trajectory

如果你有参考 trajectory，可以在 prompt 中加入一个额外变量，并把参考 trajectory 传进去。下面使用预构建的 `TRAJECTORY_ACCURACY_PROMPT_WITH_REFERENCE` prompt，并配置 `reference_outputs` 变量：

<CodeGroup>

```python Python
evaluator = create_trajectory_llm_as_judge(
    model="openai:o3-mini",
    prompt=TRAJECTORY_ACCURACY_PROMPT_WITH_REFERENCE,
)
evaluation = evaluator(
    outputs=result["messages"],
    reference_outputs=reference_trajectory,
)
```

```ts TypeScript
import { TRAJECTORY_ACCURACY_PROMPT_WITH_REFERENCE } from "agentevals";

const evaluator = createTrajectoryLLMAsJudge({
  model: "openai:o3-mini",
  prompt: TRAJECTORY_ACCURACY_PROMPT_WITH_REFERENCE,
});

const evaluation = await evaluator({
  outputs: result.messages,
  referenceOutputs: referenceTrajectory,
});
```

</CodeGroup>

## Async 支持（Python）

所有 `agentevals` evaluators 都支持 Python asyncio。对于使用工厂函数创建的 evaluators，只需要在函数名中的 `create_` 后添加 `async`，就可以使用异步版本。

下面是一个使用异步 judge 和 evaluator 的示例：

```python
from agentevals.trajectory.llm import create_async_trajectory_llm_as_judge, TRAJECTORY_ACCURACY_PROMPT
from agentevals.trajectory.match import create_async_trajectory_match_evaluator

async_judge = create_async_trajectory_llm_as_judge(
    model="openai:o3-mini",
    prompt=TRAJECTORY_ACCURACY_PROMPT,
)

async_evaluator = create_async_trajectory_match_evaluator(
    trajectory_match_mode="strict",
)

async def test_async_evaluation():
    result = await agent.ainvoke({
        "messages": [HumanMessage(content="What's the weather?")]
    })

    evaluation = await async_judge(outputs=result["messages"])
    assert evaluation["score"] is True
```
