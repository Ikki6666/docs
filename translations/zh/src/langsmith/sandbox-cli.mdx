[LangSmith CLI](/langsmith/langsmith-cli) 提供了一组 sandbox 命令，用于创建 snapshots、启动 sandboxes、运行命令、打开交互式 shell，以及把 TCP 连接隧道转发进 sandbox。

Sandbox CLI 命令要求使用 LangSmith CLI `v0.2.26` 或更高版本。

## 安装并认证

安装或升级 LangSmith CLI：

```bash
curl -fsSL https://cli.langsmith.com/install.sh | sh
langsmith self-update
```

使用你的 LangSmith API key 对 CLI 进行认证，并将其指向该 key 所属的环境：

```bash
export LANGSMITH_API_KEY="<LANGSMITH_API_KEY>"
export LANGSMITH_ENDPOINT="<LANGSMITH_ENDPOINT>"
```

<LangsmithEndpointValues />

CLI 默认输出 JSON。如果你希望 `list` 类命令以更适合人读的表格形式展示，请加上 `--format pretty`：

```bash
langsmith --format pretty sandbox list
```

## 端到端工作流

先创建一个 sandbox，然后在其中运行命令：

```bash
langsmith sandbox create my-vm --wait

langsmith sandbox exec my-vm -- python --version
```

用完 sandbox 后，把它删除：

```bash
langsmith sandbox delete my-vm
```

## 管理 snapshots

从 Docker 镜像构建 snapshots：

```bash
langsmith sandbox snapshot build my-snapshot \
  --docker-image ubuntu:24.04 \
  --capacity 8gb \
  --wait
```

对于私有镜像，请先创建一个 registry（参见 [Private registries](/langsmith/sandbox-snapshots#private-registries)），然后用 `--registry-id` 传入它的 id：

```bash
langsmith sandbox snapshot build internal-python \
  --docker-image registry.example.com/internal/python:3.12 \
  --registry-id "$REGISTRY_ID" \
  --wait
```

从正在运行的 sandbox 捕获文件系统：

```bash
langsmith sandbox snapshot capture ml-ready \
  --box my-vm \
  --wait
```

列出、检查、等待和删除 snapshots：

```bash
langsmith sandbox snapshot list
langsmith sandbox snapshot get <SNAPSHOT_ID>
langsmith sandbox snapshot wait <SNAPSHOT_ID>
langsmith sandbox snapshot delete <SNAPSHOT_ID>
```

## 管理 sandboxes

使用默认 runtime 创建 sandbox。只有当你想从可复用的自定义 snapshot 启动时，才需要加 `--snapshot-id`：

```bash
langsmith sandbox create my-vm \
  --rootfs-capacity 8gb \
  --wait
```

列出并检查 sandboxes：

```bash
langsmith sandbox list
langsmith sandbox get my-vm
langsmith sandbox wait my-vm
```

在保留文件系统的前提下停止和重新启动 sandbox：

```bash
langsmith sandbox stop my-vm
langsmith sandbox start my-vm --wait
```

更新资源或 proxy 配置：

```bash
langsmith sandbox update my-vm --rootfs-capacity 16gb
langsmith sandbox update my-vm --proxy-config @proxy.json
```

资源变更会在下次 sandbox 启动时生效。Proxy 配置变更会立即生效。

### Proxy 配置

在 `create` 或 `update` 命令里使用 `--proxy-config @proxy.json`，可以配置 sandbox auth proxy。对于凭据注入，优先使用 workspace secrets，而不要把原始 secrets 直接放在本地文件里。

```json
{
  "rules": [
    {
      "name": "openai",
      "match_hosts": ["api.openai.com"],
      "match_paths": [],
      "headers": [
        {
          "name": "Authorization",
          "type": "workspace_secret",
          "value": "Bearer {OPENAI_API_KEY}"
        }
      ],
      "enabled": true
    }
  ],
  "access_control": {
    "allow_list": ["api.openai.com"],
    "deny_list": []
  }
}
```

关于 proxy rules 的更多信息，请参见 [Sandbox auth proxy](/langsmith/sandbox-auth-proxy)。

## 运行命令

用 `sandbox exec` 执行一次性命令：

```bash
langsmith sandbox exec my-vm -- uname -a
langsmith sandbox exec my-vm -- ls -la /
langsmith sandbox exec my-vm -- cat /etc/os-release
```

`--` 之后的所有内容都会被作为命令发送到 sandbox。CLI 会把 stdout 打到 stdout、把 stderr 打到 stderr，并使用 sandbox 命令本身的退出码退出。

## 打开交互式控制台

使用 `sandbox console` 打开一个基于 PTY 的交互式 shell：

```bash
langsmith sandbox console my-vm
langsmith sandbox console my-vm --shell /bin/sh
```

你还可以把本地 SSH agent 转发进控制台会话：

```bash
langsmith sandbox console my-vm --forward-ssh-agent
```

`--forward-ssh-agent` 要求本地设置了 `SSH_AUTH_SOCK`。Windows 不支持交互式控制台会话，请改用 SSH 访问。

## 隧道转发 TCP 端口

当你需要一个本地 TCP 端口，把流量转发到 sandbox 内部正在监听的服务时，请使用 `sandbox tunnel`。这对数据库、语言服务器、自定义协议，或者依赖 `localhost` 的本地工具都很有用。

先在 sandbox 中启动一个服务，再为它建立 tunnel：

```bash
langsmith sandbox exec my-vm -- sh -c 'cd /tmp && nohup python -m http.server 8000 > /tmp/http.log 2>&1 &'
langsmith sandbox tunnel my-vm --remote-port 8000 --local-port 18000
```

然后在本地连接：

```bash
curl http://127.0.0.1:18000
```

如果省略 `--local-port`，CLI 会默认使用和 `--remote-port` 相同的值：

```bash
langsmith sandbox tunnel my-vm --remote-port 5432
```

Tunnel 进程会持续占用前台。用 `Ctrl+C` 停止它。

你也可以按 sandbox URL 而不是名字来建立 tunnel：

```bash
langsmith sandbox tunnel \
  --url <SANDBOX_URL> \
  --remote-port 5432
```

<Tip>
如果你要打开的是浏览器中的 HTTP 应用，或者要和团队成员共享，请使用 [Sandbox service URLs](/langsmith/sandbox-service-urls)。Tunnels 更适合原始 TCP 协议或本地开发工具。
</Tip>

## 配置 SSH 访问

使用 `sandbox ssh-setup` 可以为标准 SSH 工具（例如 `ssh`、`scp`、`rsync`、`sftp`）配置一条通过 sandbox tunnel 的访问路径。

```bash
langsmith sandbox ssh-setup my-vm
langsmith sandbox ssh-setup my-vm --identity ~/.ssh/id_ed25519.pub
```

该命令会把你的 SSH 公钥上传到 sandbox，在可用时抓取 sandbox 的 host key，把 `Host sandbox-<name>` 配置块写入 `~/.ssh/config`，并把 sandbox host keys 写入 `~/.ssh/known_hosts_sandboxes`。

配置完成后，可通过以下方式连接：

```bash
ssh sandbox-my-vm
```

Sandbox 镜像必须在 `22` 端口运行 `sshd`。如果 `sshd` 没有运行，`ssh-setup` 会给出警告，而 SSH 连接也要等你在 sandbox 内把它启动后才会生效。

<Warning>
`ssh-setup` 会修改本地 SSH 配置，并写入一个调用 `langsmith sandbox tunnel` 的 `ProxyCommand`。具体取决于 CLI 的认证方式，生成的配置块中可能包含凭据或对凭据的引用。请只在可信机器上运行它，不要提交或共享生成出来的 SSH config 配置块。
</Warning>

## 命令参考

| Command | Description |
| --- | --- |
| `langsmith sandbox snapshot list` | 列出 snapshots。 |
| `langsmith sandbox snapshot build <name> --docker-image <image>` | 从 Docker 镜像构建 snapshot。 |
| `langsmith sandbox snapshot capture <name> --box <sandbox>` | 从运行中的 sandbox 捕获 snapshot。 |
| `langsmith sandbox snapshot get <snapshot-id>` | 检查一个 snapshot。 |
| `langsmith sandbox snapshot wait <snapshot-id>` | 等待 snapshot 进入就绪状态。 |
| `langsmith sandbox snapshot delete <snapshot-id>` | 删除一个 snapshot。 |
| `langsmith sandbox create <name>` | 用默认 runtime 创建 sandbox。 |
| `langsmith sandbox list` | 列出 sandboxes。 |
| `langsmith sandbox get <name>` | 检查一个 sandbox。 |
| `langsmith sandbox update <name>` | 更新 sandbox 的资源或 proxy 配置。 |
| `langsmith sandbox wait <name>` | 等待 sandbox 进入就绪状态。 |
| `langsmith sandbox start <name>` | 启动一个已停止的 sandbox。 |
| `langsmith sandbox stop <name>` | 停止一个正在运行的 sandbox，同时保留其文件系统状态。 |
| `langsmith sandbox delete <name>` | 删除一个 sandbox。 |
| `langsmith sandbox exec <name> -- <command>` | 在 sandbox 内运行一次性命令。 |
| `langsmith sandbox console <name>` | 在 sandbox 内打开一个交互式 shell。 |
| `langsmith sandbox tunnel <name> --remote-port <port>` | 把本地 TCP 端口转发到 sandbox 端口。 |
| `langsmith sandbox ssh-setup <name>` | 通过 `sandbox tunnel --stdio` 配置本地 SSH 访问。 |
