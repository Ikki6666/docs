每个 sandbox 都会记录一个**创建者**，也就是使用 API key 或 session 创建它的 workspace 成员。默认情况下，只有创建者可以在该 sandbox 上运行命令、读写文件、打开 tunnels，或访问其 service URLs。其他 workspace 成员如果想与不是自己创建的 sandbox 交互，则需要 `sandboxes:exec` [permission](/langsmith/rbac)。Sandbox 永远不会被其创建所在工作区之外的 workspace 访问到。

## Who can do what

| Caller | Default | With `sandboxes:exec` |
| --- | --- | --- |
| Sandbox creator | ✅ 所有运行时操作 | ✅ 所有运行时操作 |
| Other workspace member | ❌ 拒绝 | ✅ 所有运行时操作 |
| Different workspace | ❌ 隐藏（视为 not found） | ❌ 隐藏（视为 not found） |

“运行时操作”涵盖创建完成后与正在运行的 sandbox 交互的四种方式：

- **Execute** 命令（`langsmith sandbox exec`、`SandboxClient.exec`）
- **File** 操作（读取、写入、列出 sandbox 内路径）
- **Tunnel** 将 TCP 端口回传到你的机器（`langsmith sandbox tunnel`）
- 通过 [service URL](/langsmith/sandbox-service-urls) **Proxy** 请求

生命周期操作，例如创建、列出、更新、删除 sandboxes，仍然继续使用现有的 `sandboxes:create` / `sandboxes:read` / `sandboxes:update` / `sandboxes:delete` 权限。这部分没有变化。

## Denied requests

当请求被拒绝时，sandbox 会返回 `HTTP 403`，并在响应体中标明触发的规则：

```json
{
  "detail": {
    "error": "Forbidden",
    "message": "sandbox access denied: not the creator and missing sandboxes:exec"
  }
}
```

如果某个 sandbox 存在于另一个 workspace，请求会返回 `404 Not Found`，而不是 `403`，这样响应就不会泄露该 sandbox 是否存在于其他地方。

## Sharing a sandbox

你有两种方式让团队成员使用你拥有的 sandbox：

1. **授予 `sandboxes:exec`** 给某个自定义角色，并在 workspace 中分配该角色。拥有该角色的任何人都可以与该 workspace 中的所有 sandbox 交互。
2. **使用 [service URL](/langsmith/sandbox-service-urls)** 暴露运行在 sandbox 内的 HTTP 服务。Service URLs 使用自己的 access tokens，不要求接收方一定是 workspace 成员。

对于临时协作，service URL 往往更简单；当团队成员需要广泛操作并非自己创建的 sandboxes 时，再考虑使用 `sandboxes:exec`。
