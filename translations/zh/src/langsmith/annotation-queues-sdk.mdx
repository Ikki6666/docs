使用 LangSmith SDK 以编程方式管理反馈配置和[标注队列](/langsmith/evaluation-concepts#human) rubric，并将 runs 和 threads 添加到队列以供审查。你可以在组织层定义可复用的反馈 schema，例如准确率分数或 pass/fail 判断，然后把它们配上自定义说明，分配给具体队列。这样可以实现版本控制、跨项目自动化，以及评估配置的一致性，尤其适合用于 CI/CD pipeline，或在不同环境间复制同一套评估设置。

<Callout icon="code">
本指南使用 Python 和 TypeScript SDK。安装与初始化请参阅 [Python SDK documentation](https://reference.langchain.com/python/langsmith) 和 [TypeScript SDK documentation](https://reference.langchain.com/javascript/langsmith)。
</Callout>

<Note>
如需审查 [LangSmith Engine](/langsmith/engine) 针对反复出现的问题提出的自由形式验收标准，请参阅[使用 assertions](/langsmith/assertions)。
</Note>

## 反馈层级

LangSmith 对结构化人工反馈采用三层架构：

1. **反馈配置（Feedback configs）**：组织范围内的反馈 key 定义，用来建立评估指标 schema。例如，你可以把 “accuracy” 定义成 0–1 的连续分数，或把 “correctness” 定义成 pass/fail 的分类选择。这些配置可以在组织内所有标注队列中复用。
1. **标注队列 rubric items**：队列级别的分配，用于决定标注者在审查某个队列中的[runs](/langsmith/observability-concepts#runs)时，必须填写哪些反馈项。每个 rubric item 都可以带有自定义描述、具体分值说明、该项是必填还是可选，以及根据前面的回答显示或要求该项的条件。
1. **反馈（Feedback）**：标注者针对具体[runs](/langsmith/observability-concepts#runs)提交的实际分数和数值。这些就是根据你定义好的 schema 收集到的真实评估数据。更多信息请参阅[LangSmith 中的反馈](/langsmith/observability-concepts#feedback)。

## 反馈配置

### 创建反馈配置

反馈配置定义了一个反馈 key 的 schema，例如它是连续分数、分类选项，还是自由文本。每个配置都通过一个唯一 key 在组织内标识，并规定标注者如何为这一指标提交反馈。

<Note>
如果调用 @[`create_feedback_config`] 时，传入的配置与已存在的配置完全一致，则会返回现有配置；如果同一个 key 已存在但配置不同，系统会抛出 400 错误。
</Note>

<CodeGroup>
```python Python
from langsmith import Client

client = Client()

# Continuous score
client.create_feedback_config(
    "accuracy",
    feedback_config={
        "type": "continuous",
        "min": 0,
        "max": 1,
    },
    is_lower_score_better=False,
)

# Categorical
client.create_feedback_config(
    "correctness",
    feedback_config={
        "type": "categorical",
        "categories": [
            {"value": 1, "label": "Pass"},
            {"value": 0, "label": "Fail"},
        ],
    },
)

# Freeform text
client.create_feedback_config(
    "notes",
    feedback_config={"type": "freeform"},
)
```
```typescript TypeScript
import { Client } from "langsmith";

const client = new Client();

// Continuous score
await client.createFeedbackConfig({
  feedbackKey: "accuracy",
  feedbackConfig: { type: "continuous", min: 0, max: 1 },
  isLowerScoreBetter: false,
});

// Categorical
await client.createFeedbackConfig({
  feedbackKey: "correctness",
  feedbackConfig: {
    type: "categorical",
    categories: [
      { value: 1, label: "Pass" },
      { value: 0, label: "Fail" },
    ],
  },
});

// Freeform text
await client.createFeedbackConfig({
  feedbackKey: "notes",
  feedbackConfig: { type: "freeform" },
});
```
</CodeGroup>

- **连续型**（`"accuracy"`）：定义一个从 0 到 1 的数值刻度。`is_lower_score_better` 用来表示数值越低是否代表表现越好。连续型配置适用于评分量表或百分比类指标。
- **分类型**（`"correctness"`）：提供一组预定义选项，每个选项都带有对应的值。每个 category 都需要一个 `value`（用于计分和分析）和一个 `label`（展示给标注者）。分类型配置适用于二元判断或多类别分类。
- **自由文本**（`"notes"`）：允许开放式文本输入，没有预定义结构。适用于记录定性观察或解释说明。

### 列出反馈配置

使用 @[`list_feedback_configs`] 查看组织内当前可用的评估标准。你可以列出全部配置，也可以按指定 keys 过滤。每个返回的配置对象都会包含 key、type、详细配置（例如 `min` / `max` 或 `categories`），以及 `is_lower_score_better` 之类的元数据：

<CodeGroup>
```python Python
# List all configs
for config in client.list_feedback_configs():
    print(f"{config.feedback_key}: {config.feedback_config}")

# Filter by specific keys
for config in client.list_feedback_configs(
    feedback_key=["accuracy", "correctness"]
):
    print(config.feedback_key)
```
```typescript TypeScript
// List all configs
for await (const config of client.listFeedbackConfigs()) {
  console.log(`${config.feedback_key}: ${JSON.stringify(config.feedback_config)}`);
}

// Filter by specific keys
for await (const config of client.listFeedbackConfigs({
  feedbackKeys: ["accuracy", "correctness"],
})) {
  console.log(config.feedback_key);
}
```
</CodeGroup>

### 更新反馈配置

使用 @[`update_feedback_config`] 修改现有反馈配置。这个方法只会更新你显式提供的字段，其余配置保持不变。也就是说，它是一个部分更新操作，会保留其他已有设置：

<CodeGroup>
```python Python
client.update_feedback_config(
    "accuracy",
    is_lower_score_better=True,
)
```
```typescript TypeScript
await client.updateFeedbackConfig("accuracy", {
  isLowerScoreBetter: true,
});
```
</CodeGroup>

传入 `feedback_config` 会替换整个配置，包括其 category 列表。要让多选配置保持多选，请在新配置中包含 `allows_multiple_categories`。

#### 添加或移除 categories {#add-or-remove-categories}

如果 category 列表很大，不想每次重发整份列表，可以用 `add_feedback_categories` 和 `remove_feedback_categories` 单独添加或移除 categories。这两种方法都会保留配置中的其他 categories 及其 `allows_multiple_categories` 设置：

<Note>
这些方法要求 Python 版 `langsmith>=0.15.0` 或 TypeScript 版 `langsmith>=0.12.0`。自托管 LangSmith 需要 v0.18 或更高版本。早期版本会忽略该更改，并原样返回配置。
</Note>

<CodeGroup>
```python Python
# Add categories. Values and labels must not match existing ones.
client.add_feedback_categories(
    "topics",
    [{"value": 3, "label": "warranty"}],
)

# Remove categories by value, not label.
client.remove_feedback_categories("topics", [2])
```
```typescript TypeScript
// Add categories. Values and labels must not match existing ones.
await client.addFeedbackCategories("topics", [
  { value: 3, label: "warranty" },
]);

// Remove categories by value, not label.
await client.removeFeedbackCategories("topics", [2]);
```
</CodeGroup>

移除 category 不会改变已经使用该值写入的反馈。categorical 配置必须至少保留两个 categories，因此如果移除后少于两个，就会返回 422 错误。

### 删除反馈配置

使用 @[`delete_feedback_config`] 从组织中删除某个反馈配置。这个操作是软删除，只会将该配置标记为已删除，而不会真正从系统中彻底移除。如果之后需要，你仍然可以用同一个 key 重新创建配置：

<CodeGroup>
```python Python
client.delete_feedback_config("accuracy")
```
```typescript TypeScript
await client.deleteFeedbackConfig("accuracy");
```
</CodeGroup>

## 标注队列 rubric items

Rubric items 会把反馈配置分配到某个具体标注队列上。它们决定了标注者在审查该队列中的[runs](/langsmith/observability-concepts#runs)时，会看到哪些反馈表单，以及这些表单是必填还是可选。

### 创建带 rubric items 的队列

使用 @[`create_annotation_queue`] 创建标注队列，并通过 rubric items 把反馈配置分配给它。每个 rubric item 都会通过 key 引用一个反馈配置，并定制它在这个队列里呈现给标注者的方式。

下面的示例创建了一个包含 3 个 rubric items 的队列。队列级别的 `rubric_instructions` 会作为整体说明显示在标注界面顶部：

<CodeGroup>
```python Python
queue = client.create_annotation_queue(
    name="QA Review Queue",
    description="Review LLM outputs for accuracy and correctness",
    rubric_instructions="Score each response. Add notes for anything unusual.",
    rubric_items=[
        {
            "feedback_key": "accuracy",
            "description": "How accurate is the response?",
            "score_descriptions": {
                "0": "Completely wrong",
                "1": "Perfectly accurate",
            },
            "is_required": True,
        },
        {
            "feedback_key": "correctness",
            "description": "Did the response pass or fail?",
            "value_descriptions": {
                "Pass": "Factually correct",
                "Fail": "Contains errors",
            },
            "is_required": True,
        },
        {
            "feedback_key": "notes",
            "description": "Any additional observations",
            "is_required": False,
        },
    ],
)
```
```typescript TypeScript
const queue = await client.createAnnotationQueue({
  name: "QA Review Queue",
  description: "Review LLM outputs for accuracy and correctness",
  rubricInstructions: "Score each response. Add notes for anything unusual.",
  rubricItems: [
    {
      feedback_key: "accuracy",
      description: "How accurate is the response?",
      score_descriptions: { "0": "Completely wrong", "1": "Perfectly accurate" },
      is_required: true,
    },
    {
      feedback_key: "correctness",
      description: "Did the response pass or fail?",
      value_descriptions: { Pass: "Factually correct", Fail: "Contains errors" },
      is_required: true,
    },
    {
      feedback_key: "notes",
      description: "Any additional observations",
      is_required: false,
    },
  ],
});
```
</CodeGroup>

- `feedback_key`：已有反馈配置的 key，必须先创建对应配置。
- `description`：该指标在当前队列中展示给标注者的说明。
- `score_descriptions` / `value_descriptions`：可选标签，用来解释具体数值的含义（连续型使用 `score_descriptions`，分类型使用 `value_descriptions`）。
- `is_required`：标注者提交前是否必须完成这一项。

### 更新已有队列上的 rubric items

使用 @[`update_annotation_queue`] 修改某个标注队列的 rubric items。这个操作会直接替换整份 rubric items 列表，因此你必须把所有想保留的 items 一并传回去，未包含的 items 会被移除。

你需要先拿到队列 ID，可以在创建队列时获得，也可以通过列出队列拿到：

<Note>
更新 rubric items 会替换整份列表。你想保留的所有 items 都必须一并传入。
</Note>

<CodeGroup>
```python Python
client.update_annotation_queue(
    queue.id,
    rubric_items=[
        {"feedback_key": "accuracy", "is_required": True},
        {"feedback_key": "correctness", "is_required": True},
        {
            "feedback_key": "tone",
            "description": "Is the tone appropriate?",
            "is_required": False,
        },
    ],
)
```
```typescript TypeScript
await client.updateAnnotationQueue(queue.id, {
  rubricItems: [
    { feedback_key: "accuracy", is_required: true },
    { feedback_key: "correctness", is_required: true },
    { feedback_key: "tone", description: "Is the tone appropriate?", is_required: false },
  ],
});
```
</CodeGroup>

如果更新时省略了某个 item 的 `required_if` 或 `visible_if`，该 item 会保留当前条件。要清除条件，请传入 `None`（Python）或 `null`（TypeScript）。

### 为 rubric items 添加条件 {#add-conditions-to-rubric-items}

条件可以让某个 rubric item 依赖前序 items 的回答，这样标注者只会在适用时看到后续问题。每个 rubric item 都接受两个可选的条件字段：

- **`required_if`**：始终显示该 item，并且仅在条件成立时才必填。
- **`visible_if`**：在条件成立前隐藏该 item。一旦显示，就遵循 `is_required`。

<Note>
Rubric item 条件要求 Python 版 `langsmith>=0.15.0` 或 TypeScript 版 `langsmith>=0.12.0`。
</Note>

每个条件对象都包含一个取值为 `"all"` 或 `"any"` 的 `join`，以及一组 `rules`。每条 rule 都指定同一 rubric 中前序 item 的 `key`、一个 `op`，以及要匹配的 category `values`：

- **`is`**：前序 item 的回答等于所给的那个值。
- **`is_one_of`**：前序 item 的回答是所给值中的任意一个。
- **`is_empty`**：前序 item 没有回答。不接受任何值。
- **`is_not_empty`**：前序 item 有回答。不接受任何值。

Rule 中的值指的是 category 的值，而不是 label。对于多选 item，只要任一已选 category 匹配，`is` 和 `is_one_of` 就成立。

下面的示例仅在标注者将响应标记为失败时，才要求提供失败原因：

<CodeGroup>
```python Python
client.update_annotation_queue(
    queue.id,
    rubric_items=[
        {"feedback_key": "correctness", "is_required": True},
        {
            "feedback_key": "failure_reason",
            "description": "Why did the response fail?",
            "is_required": True,
            "visible_if": {
                "join": "all",
                "rules": [{"key": "correctness", "op": "is", "values": [0]}],
            },
        },
    ],
)
```
```typescript TypeScript
await client.updateAnnotationQueue(queue.id, {
  rubricItems: [
    { feedback_key: "correctness", is_required: true },
    {
      feedback_key: "failure_reason",
      description: "Why did the response fail?",
      is_required: true,
      visible_if: {
        join: "all",
        rules: [{ key: "correctness", op: "is", values: [0] }],
      },
    },
  ],
});
```
</CodeGroup>

一条 rule 只能引用 rubric 中排在其前面的 item。引用后面的 item 或该 item 自身的 rule 会返回 422 错误。LangSmith 会存储条件，并由审核视图应用这些条件。直接写入反馈时，API 不会强制执行这些条件。

### 将 rubric 复制到另一个队列 {#copy-a-rubric-to-another-queue}

`read_annotation_queue` 会按顺序返回队列的 rubric items，每个 item 都包含其使用的反馈配置。要复制 rubric，请将这些 items 原样传给另一个队列的 `rubric_items`：

<Note>
读取带有反馈配置的 rubric items 需要 Python 版 `langsmith>=0.15.0` 或 TypeScript 版 `langsmith>=0.12.0`。
</Note>

<CodeGroup>
```python Python
source = client.read_annotation_queue(source_queue_id)

client.update_annotation_queue(
    target_queue_id,
    rubric_instructions=source.rubric_instructions,
    rubric_items=source.rubric_items,
)
```
```typescript TypeScript
const source = await client.readAnnotationQueue(sourceQueueId);

await client.updateAnnotationQueue(targetQueueId, {
  rubricInstructions: source.rubric_instructions,
  rubricItems: source.rubric_items,
});
```
</CodeGroup>

由于更新会替换完整的 rubric item 列表，因此该更新会替换目标队列的 rubric。若要保留目标队列现有的 items，请在更新前合并两个列表。

## 将 runs 和 threads 添加到队列

使用标注队列的 `items` 资源，可以将[runs](/langsmith/observability-concepts#runs)和[threads](/langsmith/observability-concepts#threads)添加到单个 run 的标注队列中。单个请求可以同时接收 run items 和 thread items 的混合批次，因此这个方法覆盖了 UI [添加流程](/langsmith/annotation-queues#assign-runs-and-threads-to-a-single-run-queue)支持的一切操作。

<Note>
`items` 资源要求 Python 版 `langsmith>=0.10.13` 或 TypeScript 版 `langsmith>=0.8.8`，并由 `0.16.14` 或更高版本的 LangSmith 后端提供支持。
</Note>

每个 item 都会将 `item_type` 设置为 `RUN` 或 `THREAD`：

- **RUN items** 需要 `run_id`。同时提供 `project_id`（project UUID）和 `start_time`，两者一起可以准确定位到具体的 run。
- **THREAD items** 需要 `thread_id` 和 `project_id`。

使用 SDK 查找这些 ID：

- **`project_id`**：用 @[`read_project`] 按名称查找 project 并读取其 `id`，例如 `client.read_project(project_name="my-project").id`。
- **`run_id`**：使用 `client.runs.query()` 查询 runs。每个 run 都会暴露 `id`、`project_id` 和 `start_time`，这正是 RUN item 需要的字段。
- **`thread_id`**：使用 `client.threads.query()` 查询 threads。每个结果都会暴露其 `thread_id`。

你也可以在 [LangSmith UI](https://smith.langchain.com) 中找到这些 ID：

- **`project_id`**：即 agent environment 的 `tracer_session_id`。选择你的 agent，前往 **Tracing**，再选择 environment。点击 environment 名称旁边的 **ID** 徽章并复制 **Tracing Project ID**。要了解这些 API 为何接收 project ID，请参阅[与旧版 API 的兼容性](/langsmith/observability-concepts#tracing-projects)。
- **`run_id`**：在 [Details view](/langsmith/view-traces#details-view) 中打开一个 run，点击 run 名称旁边的 **ID** 徽章即可复制 run ID。
- **`thread_id`**：选择你的 agent，前往 **Tracing**，选择 environment，然后打开 **Threads** 标签页。从 **Thread ID** 列复制该值。

如需延长所添加 run items 的 trace 保留时间，请传入 `extend_trace_retention=True`。响应是一个信封，其中包含一个 `items` 数组，每个已添加的 item 对应一个条目。

<Note>
在 Python 中，`annotation_queues.items.create` 是异步方法，因此需要在事件循环中 `await` 它。
</Note>

<CodeGroup>
```python Python
import asyncio

async def main():
    queue_name = "<queue_name>"
    project_id = "<project_id>"
    run_id = "<run_id>"
    thread_id = "<thread_id>"

    # Look up the annotation queue by name to get its ID.
    queue = next(client.list_annotation_queues(name=queue_name), None)
    if queue is None:
        raise SystemExit(f"No annotation queue named {queue_name!r}")

    # Fetch the run to add by id + project_id. runs.retrieve() requires
    # `selects` (uppercase RunSelectField names) to return fields like
    # start_time.
    run = await client.runs.retrieve(
        run_id=run_id,
        project_id=project_id,
        selects=["ID", "PROJECT_ID", "START_TIME"],
    )

    response = await client.annotation_queues.items.create(
        str(queue.id),
        items=[
            {
                "item_type": "RUN",
                "run_id": run_id,
                "project_id": project_id,
                "start_time": run.start_time,
            },
            {
                "item_type": "THREAD",
                "thread_id": thread_id,
                "project_id": project_id,
            },
        ],
    )

    # response.items contains one entry per added item.
    for item in response.items or []:
        print(item.id, item.item_type)

asyncio.run(main())
```
```typescript TypeScript
const queueName = "<queue_name>";
const projectId = "<project_id>";
const runId = "<run_id>";
const threadId = "<thread_id>";

// Look up the annotation queue by name to get its ID.
let queue;
for await (const q of client.listAnnotationQueues({ name: queueName })) {
  queue = q;
  break;
}
if (!queue) {
  throw new Error(`No annotation queue named ${queueName}`);
}

// Fetch the run to add by id + project_id. retrieve() requires `selects`
// (uppercase RunSelectField names) to return fields like start_time.
const run = await client.runs.retrieve(runId, {
  project_id: projectId,
  selects: ["ID", "PROJECT_ID", "START_TIME"],
});

const response = await client.annotationQueues.items.create(queue.id, {
  items: [
    {
      item_type: "RUN",
      run_id: runId,
      project_id: projectId,
      start_time: run.start_time,
    },
    {
      item_type: "THREAD",
      thread_id: threadId,
      project_id: projectId,
    },
  ],
});

// response.items contains one entry per added item.
for (const item of response.items ?? []) {
  console.log(item.id, item.item_type);
}
```
</CodeGroup>

<Note>
对于只添加 runs 的场景，@[`add_runs_to_annotation_queue`] 仍然可用，并且在你不需要添加 threads 时是最简单的选项。需要同时添加 threads 或混合 run、thread 批次的新代码，应使用 `items` 资源。
</Note>

## 反馈配置类型详解

### Continuous

Continuous 配置用于定义带最小值和最大值的数值评分刻度。标注者可以在这个范围内选择任意数值，因此它非常适合用于准确率、质量、相关性等数值型评分维度：

<CodeGroup>
```python Python
# Simple continuous score
client.create_feedback_config(
    "accuracy",
    feedback_config={
        "type": "continuous",
        "min": 0,
        "max": 1,
    },
)

# Continuous with labeled points on the scale
client.create_feedback_config(
    "quality",
    feedback_config={
        "type": "continuous",
        "min": 1,
        "max": 5,
        "categories": [
            {"value": 1, "label": "Poor"},
            {"value": 3, "label": "Average"},
            {"value": 5, "label": "Excellent"},
        ],
    },
)
```
```typescript TypeScript
await client.createFeedbackConfig({
  feedbackKey: "accuracy",
  feedbackConfig: { type: "continuous", min: 0, max: 1 },
});

await client.createFeedbackConfig({
  feedbackKey: "quality",
  feedbackConfig: {
    type: "continuous",
    min: 1,
    max: 5,
    categories: [
      { value: 1, label: "Poor" },
      { value: 3, label: "Average" },
      { value: 5, label: "Excellent" },
    ],
  },
});
```
</CodeGroup>

第一个例子展示的是一个没有标签的 0–1 分制。第二个例子则展示了如何通过 `categories` 为刻度上的锚点加上标签，例如 “Poor”“Average”“Excellent”，帮助标注者理解不同数值代表什么。这些标签是可选的，但通常有助于提升不同标注者之间的一致性。

### Categorical

Categorical 配置会提供一组离散的预定义选项供标注者选择。每个 category 都必须包含一个 `value`（用于评分和分析的数值标识）和一个 `label`（展示给标注者的文字）。你至少需要定义 2 个 categories。

Categorical 配置适合用于二元判断（pass/fail、correct/incorrect）、多类别分类（情感、主题分类），或任何固定离散选项的评估场景。对于 categorical 配置，不应设置 `min` 或 `max`：

<CodeGroup>
```python Python
# Binary pass/fail
client.create_feedback_config(
    "correctness",
    feedback_config={
        "type": "categorical",
        "categories": [
            {"value": 1, "label": "Pass"},
            {"value": 0, "label": "Fail"},
        ],
    },
)

# Multi-class
client.create_feedback_config(
    "sentiment",
    feedback_config={
        "type": "categorical",
        "categories": [
            {"value": 0, "label": "Negative"},
            {"value": 1, "label": "Neutral"},
            {"value": 2, "label": "Positive"},
        ],
    },
)
```
```typescript TypeScript
await client.createFeedbackConfig({
  feedbackKey: "correctness",
  feedbackConfig: {
    type: "categorical",
    categories: [
      { value: 1, label: "Pass" },
      { value: 0, label: "Fail" },
    ],
  },
});

await client.createFeedbackConfig({
  feedbackKey: "sentiment",
  feedbackConfig: {
    type: "categorical",
    categories: [
      { value: 0, label: "Negative" },
      { value: 1, label: "Neutral" },
      { value: 2, label: "Positive" },
    ],
  },
});
```
</CodeGroup>

第一个例子是典型的 pass/fail 二元配置。第二个例子是一个包含三种情感类别的多分类配置。即便是分类反馈，这些数值也能用于后续聚合分析。

#### 允许多选 {#allow-multiple-selections}

设置 `allows_multiple_categories` 可以让标注者为单个 item 选择多个 categories。它适用于多标签分类体系，例如为一通对话涉及的每个主题打标签。该标志默认为 `false`，且仅适用于 categorical 配置：

<Note>
`allows_multiple_categories` 要求 Python 版 `langsmith>=0.15.0` 或 TypeScript 版 `langsmith>=0.12.0`。
</Note>

<CodeGroup>
```python Python
client.create_feedback_config(
    "topics",
    feedback_config={
        "type": "categorical",
        "categories": [
            {"value": 0, "label": "billing"},
            {"value": 1, "label": "shipping"},
            {"value": 2, "label": "returns"},
        ],
        "allows_multiple_categories": True,
    },
)
```
```typescript TypeScript
await client.createFeedbackConfig({
  feedbackKey: "topics",
  feedbackConfig: {
    type: "categorical",
    categories: [
      { value: 0, label: "billing" },
      { value: 1, label: "shipping" },
      { value: 2, label: "returns" },
    ],
    allows_multiple_categories: true,
  },
});
```
</CodeGroup>

当标注者在审核窗格中选择多个 categories 时，LangSmith 会把每个选择分别保存为该配置 key 下的一条反馈记录，其中 category label 作为 `value`，category value 作为 `score`。取消选择会删除对应记录。要使用 SDK 写入多选答案，请为每个 category 创建一条反馈记录。

复合评估器不能包含多选 key，因为同一个 run 在该 key 下可能有多个分数。

### Freeform

Freeform 配置允许标注者输入开放式文本反馈，没有任何预定义结构或限制。它没有 `min`、`max` 或 `categories` 这些字段，标注者可以填写任意内容。

相比结构化反馈，自由文本反馈更适合捕捉细节和 nuanced insight，但后续聚合和分析也会更困难：

<CodeGroup>
```python Python
client.create_feedback_config(
    "notes",
    feedback_config={"type": "freeform"},
)
```
```typescript TypeScript
await client.createFeedbackConfig({
  feedbackKey: "notes",
  feedbackConfig: { type: "freeform" },
});
```
</CodeGroup>

## 校验规则

| Type | min/max | categories | Constraints |
|------|---------|-----------|-------------|
| `continuous` | Optional | Optional（带标签的刻度点） | `min < max`；category values 必须落在 [`min`, `max`] 范围内 |
| `categorical` | Must not be set | Required，最少 2 个 | values 和 labels 必须唯一 |
| `freeform` | Must not be set | Must not be set | N/A |

## 参考

### 反馈配置类型

| Type | Fields | Description |
|------|--------|-------------|
| `continuous` | `min`, `max` | 在某个范围内的数值分数 |
| `categorical` | categories（`{value, label}` 列表） | 从预定义选项中选择 |
| `freeform` | None | 自由文本输入 |

### Rubric item 字段

| Field | Type | Description |
|-------|------|-------------|
| `feedback_key` | `string` | 必填，必须匹配已有 feedback config key。 |
| `description` | `string` | 显示给标注者的该项说明。 |
| `score_descriptions` | `Record<string, string>` | 特定分值的说明标签（continuous）。 |
| `value_descriptions` | `Record<string, string>` | 特定分类值的说明标签（categorical）。 |
| `is_required` | `boolean` | 提交前是否必须完成该项，默认值为 false。 |
| `required_if` | `object` | 前序 items 上的条件。仅当条件成立时，该项才必填。请参阅[为 rubric items 添加条件](#add-conditions-to-rubric-items)。 |
| `visible_if` | `object` | 前序 items 上的条件。在条件成立前隐藏该项。请参阅[为 rubric items 添加条件](#add-conditions-to-rubric-items)。 |

| Field | Type | Description |
|-------|------|-------------|
| `allows_multiple_categories` | `boolean` | 仅适用于 categorical。标注者是否可以选择多个 categories。默认值为 false。 |
