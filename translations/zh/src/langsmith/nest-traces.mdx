当你使用 LangSmith SDK、LangGraph 和 LangChain 进行 tracing 时，系统通常会自动传播正确的上下文，因此父级 trace 内执行的代码会在 UI 中显示在预期的位置。

如果你发现某个子级 run 跑到了另一条独立 trace 中（并出现在顶层），可能是由以下一些已知“边界情况”导致的。

## Python

下面列出的是在 Python 中构建时，造成 trace “拆分”的常见原因。

### 使用 asyncio 进行上下文传播

在 Python 版本低于 3.11 时，如果你使用异步调用（尤其是流式调用），可能会遇到 trace 嵌套问题。这是因为 Python 的 `asyncio` 直到 3.11 才[完整支持传递上下文](https://docs.python.org/3/library/asyncio-task.html#asyncio.create_task)。

#### 原因

LangChain 和 LangSmith SDK 使用 [contextvars](https://docs.python.org/3/library/contextvars.html) 来隐式传播 tracing 信息。在 Python 3.11 及以上版本中，这一机制工作良好。但在更早的版本（3.8、3.9、3.10）中，`asyncio` 任务缺乏对 `contextvar` 的完善支持，因此容易导致 traces 断开。

#### 解决方式

1. **升级 Python 版本（推荐）**：如果条件允许，请升级到 Python 3.11 或更高版本，以获得自动上下文传播能力。

2. **手动传播上下文**：如果暂时无法升级，就需要手动传播 tracing 上下文。具体方法取决于你的使用方式：

   a) **使用 LangGraph 或 LangChain**：把父级 `config` 传给子调用：

   ```python
   import asyncio
   from langchain_core.runnables import RunnableConfig, RunnableLambda

   @RunnableLambda
   async def my_child_runnable(
       inputs: str,
       # The config arg (present in parent_runnable below) is optional
   ):
       yield "A"
       yield "response"

   @RunnableLambda
   async def parent_runnable(inputs: str, config: RunnableConfig):
       async for chunk in my_child_runnable.astream(inputs, config):
           yield chunk

   async def main():
       return [val async for val in parent_runnable.astream("call")]

   asyncio.run(main())
   ```

   b) **直接使用 LangSmith**：直接传递 run tree：

   ```python
   import asyncio
   import langsmith as ls

   @ls.traceable
   async def my_child_function(inputs: str):
       yield "A"
       yield "response"

   @ls.traceable
   async def parent_function(
       inputs: str,
       # The run tree can be auto-populated by the decorator
       run_tree: ls.RunTree,
   ):
       async for chunk in my_child_function(inputs, langsmith_extra={"parent": run_tree}):
           yield chunk

   async def main():
       return [val async for val in parent_function("call")]

   asyncio.run(main())
   ```

   c) **将装饰器代码与 LangGraph/LangChain 混用**：结合多种技术手动传递上下文：

   ```python
   import asyncio
   import langsmith as ls
   from langchain_core.runnables import RunnableConfig, RunnableLambda

   @RunnableLambda
   async def my_child_runnable(inputs: str):
       yield "A"
       yield "response"

   @ls.traceable
   async def my_child_function(inputs: str, run_tree: ls.RunTree):
       with ls.tracing_context(parent=run_tree):
           async for chunk in my_child_runnable.astream(inputs):
               yield chunk

   @RunnableLambda
   async def parent_runnable(inputs: str, config: RunnableConfig):
       # @traceable decorated functions can directly accept a RunnableConfig when passed in via "config"
       async for chunk in my_child_function(inputs, langsmith_extra={"config": config}):
           yield chunk

   @ls.traceable
   async def parent_function(inputs: str, run_tree: ls.RunTree):
       # You can set the tracing context manually
       with ls.tracing_context(parent=run_tree):
           async for chunk in parent_runnable.astream(inputs):
               yield chunk

   async def main():
       return [val async for val in parent_function("call")]

   asyncio.run(main())
   ```

### 使用 threading 进行上下文传播

另一种常见场景是：你在同一条 trace 内启动 tracing，然后希望子任务以并行方式运行。Python 标准库里的 `ThreadPoolExecutor` 默认会打断 tracing。

#### 原因

在新线程中，Python 的 `contextvars` 默认是空的。下面有两种方式可以保持 trace 的连续性：

#### 解决方式

1. **使用 LangSmith 的 `ContextThreadPoolExecutor`**

   LangSmith 提供了一个 `ContextThreadPoolExecutor`，会自动处理上下文传播：

   ```python
   from langsmith.utils import ContextThreadPoolExecutor
   from langsmith import traceable

   @traceable
   def outer_func():
       with ContextThreadPoolExecutor() as executor:
           inputs = [1, 2]
           r = list(executor.map(inner_func, inputs))

   @traceable
   def inner_func(x):
       print(x)

   outer_func()
   ```

2. **手动传递父级 run tree**

   或者，你也可以手动将父级 run tree 传给内部函数：

   ```python
   from langsmith import traceable, get_current_run_tree
   from concurrent.futures import ThreadPoolExecutor

   @traceable
   def outer_func():
       rt = get_current_run_tree()
       with ThreadPoolExecutor() as executor:
           r = list(
               executor.map(
                   lambda x: inner_func(x, langsmith_extra={"parent": rt}), [1, 2]
               )
           )

   @traceable
   def inner_func(x):
       print(x)

   outer_func()
   ```

在这种方式中，我们通过 `get_current_run_tree()` 获取当前 run tree，然后用 `langsmith_extra` 参数把它传给内部函数。

这两种方式都能确保：即使内部函数运行在不同线程中，它们也仍会被正确聚合到原始 trace 栈之下。
