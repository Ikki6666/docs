## Amazon Bedrock

在使用这个模型前，请确保你拥有 [AWS credentials 或 IAM role](https://docs.aws.amazon.com/bedrock/latest/userguide/security-iam.html)。

### Authentication

Amazon Bedrock 支持两种鉴权方式。**IAM trusted entity 是推荐方案**，因为它不需要把长期有效的 AWS access keys 共享给 LangSmith。

#### IAM trusted entity（推荐）

<Note>
**不适用于 [self-hosted LangSmith](/langsmith/self-hosted)。** 这类场景请改用 Access Keys（或 Bedrock API Key）。
</Note>

使用 IAM trusted entity 鉴权时，你需要在自己的 AWS 账号中创建一个 IAM role，并允许 LangSmith 去 assume 这个 role。LangSmith 不会存储任何 access keys，而是会在每次请求时通过 [AWS STS](https://docs.aws.amazon.com/STS/latest/APIReference/welcome.html) 来 assume 该 role。

配置步骤如下：

1. 在你的 AWS 账号中创建一个 IAM role，并赋予它调用 Bedrock 模型的权限，例如 `bedrock:InvokeModel`。
2. 添加一条 trust policy，允许 LangSmith 的 AWS 账号（`808407022534`）通过你的 LangSmith workspace ID 作为 external ID 来 assume 这个 role：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::808407022534:root"
      },
      "Action": "sts:AssumeRole",
      "Condition": {
        "StringEquals": {
          "sts:ExternalId": "<your-langsmith-workspace-id>"
        }
      }
    }
  ]
}
```

<Tip>
你可以在 [LangSmith workspace settings](https://smith.langchain.com/settings) 中找到自己的 workspace ID。
</Tip>

3. 在 LangSmith Playground 中，点击 **Key** 图标打开 Bedrock provider 的 secrets 配置（IAM Trusted Entity 选项不会直接出现在模型配置下拉菜单中）。然后展开 **IAM Trusted Entity** 区域，并填入你刚创建的 role ARN。

    ![Bedrock secrets and API keys configuration with the IAM Trusted Entity section](/images/langsmith/bedrock-secrets-config.png)

关于 trust policy 的更多细节，请参见 [AWS 文档](https://aws.amazon.com/blogs/security/how-to-use-trust-policies-with-iam-roles/)。

#### Access keys

另一种方式是使用 AWS access keys（`AWS_ACCESS_KEY_ID` 和 `AWS_SECRET_ACCESS_KEY`）进行鉴权。你可以在 Playground 的 Bedrock provider 配置中填入这些值。这种方式配置更简单，但安全性较低，因为它要求在 LangSmith 中存储长期有效的凭据。

### Available models

AWS Bedrock 提供了多个 provider 的 foundation models：

- **Anthropic：** Claude models
- **Amazon：** Titan models
- **Cohere：** Command models
- **Meta：** Llama models
- **Others：** 其他可用 provider，取决于所在 region

最新可用模型列表请参见 [AWS Bedrock 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)。

### Configuration parameters

参数取决于底层 model provider：

#### 对于 Anthropic models

使用 Anthropic 的配置方式（见下方 [Anthropic](#anthropic) 小节）。

#### 对于 Amazon Titan

| Parameter | Range | Description |
|-----------|-------|-------------|
| **Temperature** | 0.0 - 1.0 | 响应随机性 |
| **Max Tokens** | 1+ | 最大响应长度 |
| **Top P** | 0.0 - 1.0 | Nucleus sampling |

#### AWS-specific settings

- **Region：** 模型部署所在的 AWS region

### Tool calling

取决于底层模型：
- **Anthropic models：** `auto`、`any`
- **Cohere models：** `auto`

## Anthropic

在使用这个模型前，请确保你拥有一个 [Anthropic API key](https://console.anthropic.com/settings/keys)。

### Available models

Anthropic 的 Claude 系列模型通常分为三档：

- **Opus：** 智能水平和能力最强
- **Sonnet：** 性能与成本之间的平衡
- **Haiku：** 速度快、成本低

较新的 Claude 模型支持 extended thinking 能力，可以展示推理过程。

最新可用模型列表请参见 [Anthropic 文档](https://docs.anthropic.com/claude/docs/models-overview)。

### Configuration parameters

| Parameter | Range | Default | Description |
|-----------|-------|---------|-------------|
| **Temperature** | 0.0 - 1.0 | Optional | 随机性控制（取消勾选则使用模型默认值） |
| **Max Output Tokens** | 1+ | 1024 | 最大响应长度 |
| **Top P** | 0.0 - 1.0 | Optional | Nucleus sampling（取消勾选则使用模型默认值） |
| **Top K** | 1+ | Optional | 限制为 top K tokens（取消勾选则使用模型默认值） |

<Note>
Temperature、Top P 和 Top K 都是可选项。取消勾选后，Claude 会使用它自己的内部默认值。
</Note>

#### Extended Thinking

适用于支持该能力的 Claude 模型。开启后，模型会在正式回答前展示思考过程，类似 OpenAI 的 o-series。

| Parameter | Range | Description |
|-----------|-------|-------------|
| **Enable Extended Thinking** | Toggle | 是否展示 thinking 过程 |
| **Budget Tokens** | 1+ | 用于 thinking 的最大 token 数（默认：1024） |

开启后，响应会包含：

1. 一个展示模型推理过程的 “thinking” 区块
1. 最终正式回答

#### Advanced options

- **Base URL：** 为自定义部署覆盖默认 API endpoint

### Tool calling

- **Supported Tool Choices：** `auto`、`any`（要求至少有一个 tool）
- **Parallel Execution：** 否，仅支持串行

## Azure OpenAI

在使用这个模型前，请确保你拥有 [Azure OpenAI credentials](https://learn.microsoft.com/en-us/azure/ai-services/openai/quickstart)（endpoint + API key）。

### Available models

Azure OpenAI 提供与 OpenAI 相同系列的模型：

- **GPT series：** 通用聊天模型
- **o-series：** 偏推理任务的模型
- **Legacy models：** GPT-3.5 和 GPT-4 的旧版本

模型可用性取决于 Azure region，并且需要先部署后使用。

最新可用模型列表请参见 [Azure OpenAI 文档](https://learn.microsoft.com/en-us/azure/ai-services/openai/concepts/models)。

### Configuration parameters

Azure OpenAI 支持与 OpenAI 相同的参数：

#### Standard parameters

| Parameter | Range | Description |
|-----------|-------|-------------|
| **Temperature** | 0.0 - 2.0 | 控制随机性。越低越聚焦，越高越有创造性。 |
| **Max Output Tokens** | 1+ | 最大响应长度 |
| **Top P** | 0.0 - 1.0 | Nucleus sampling 阈值，是 Temperature 的替代方案。 |
| **Presence Penalty** | -2.0 - 2.0 | 惩罚新话题（正值）或鼓励新话题（负值） |
| **Frequency Penalty** | -2.0 - 2.0 | 惩罚重复（正值）或允许重复（负值） |
| **Seed** | Integer | 用于可复现输出 |

#### Advanced parameters

**Reasoning Effort：** 适用于偏推理的模型（o-series 和较新的 GPT 模型）。

**Service Tier：** 适用于较新的模型。

**Other parameters：**
- **JSON Mode：** 强制返回合法 JSON
- **Parallel Tool Calls：** 并行执行多个 tools

#### Azure-specific features

- **Deployment Management：** 模型必须先部署后使用
- **Regional Availability：** 可选择 Azure regions 以满足数据驻留要求
- **Content Filtering：** 内置内容审核与安全能力
- **Managed Identity：** 支持 Azure AD 鉴权
- **Private Endpoints：** 支持通过 VNet 集成实现安全访问

### Tool calling

- **Supported Tool Choices：** `auto`、`required`、`none`，或指定某个具体 tool 名称
- **Parallel Execution：** 是

## OpenAI

在使用这个模型前，请确保你拥有一个 [OpenAI API key](https://platform.openai.com/api-keys) 或 [Azure OpenAI credentials](https://learn.microsoft.com/en-us/azure/ai-services/openai/quickstart)。

### Available models

OpenAI 提供多种模型家族，能力和价格各不相同：

- **GPT series：** 通用聊天模型，按规模和能力分层
- **o-series：** 偏推理任务的模型，适合复杂问题求解
- **Legacy models：** 较旧的 GPT-3.5 和 GPT-4 变体

最新可用模型列表请参见 [OpenAI documentation](https://platform.openai.com/docs/models)。

### Configuration parameters

Standard：

| Parameter | Range | Description |
|-----------|-------|-------------|
| **Temperature** | 0.0 - 2.0 | 控制随机性。越低越聚焦，越高越有创造性。 |
| **Max Output Tokens** | 1+ | 最大响应长度 |
| **Top P** | 0.0 - 1.0 | Nucleus sampling 阈值，是 Temperature 的替代方案。 |
| **Presence Penalty** | -2.0 - 2.0 | 惩罚新话题（正值）或鼓励新话题（负值） |
| **Frequency Penalty** | -2.0 - 2.0 | 惩罚重复（正值）或允许重复（负值） |
| **Seed** | Integer | 用于可复现输出 |

Advanced：

**Reasoning Effort**：适用于偏推理模型（o-series 和较新的 GPT 模型）。

它控制模型在正式回答前的推理深度。Effort 越高，复杂任务的质量通常越好，但延迟也会更长。

| Value | Description |
|-------|-------------|
| `none` | 禁用推理，表现为标准聊天模式 |
| `minimal` | 最少推理 |
| `low` | 轻量推理 |
| `medium` | 中等推理（默认） |
| `high` | 深度推理 |
| `xhigh` | 更深层推理（如果模型支持） |

<Note>
当 `reasoning_effort` 被启用（不为 `none`）时，temperature、top_p 和 penalties 会自动失效。
</Note>

**Service Tier**：适用于较新的模型。

它用于控制请求优先级和处理资源分配。

| Value | Description |
|-------|-------------|
| `auto` | 系统根据负载自动决定（默认） |
| `default` | 标准处理队列 |
| `flex` | 成本更低，但延迟更不稳定（如果模型支持） |
| `priority` | 高优先级队列，延迟更低、成本更高 |

**Other parameters：**
- **JSON Mode：** 强制返回合法 JSON
- **Responses API：** 改善 streaming（默认开启）
- **Parallel Tool Calls：** 并行执行多个 tools

### Tool calling

- **Supported Tool Choices：** `auto`、`required`、`none`，或指定某个具体 tool 名称
- **Parallel Execution：** 是

## OpenAI Compatible Endpoint

鉴权方式会因 endpoint 而异。常见选项包括：

- **API key**：作为 [workspace secret](/langsmith/administration-overview#workspaces) 存储，并通过 `Authorization: Bearer <key>` 转发
- **None**：适用于不需要鉴权的本地 endpoints，例如运行在 `localhost` 上的 Ollama
- **OAuth2 `client_credentials`**：存储在 model configuration 中。LangSmith 会在请求时生成短期 bearer，并在过期前刷新。详见 [OAuth client credentials](/langsmith/model-configurations#oauth-client-credentials)

### Configuration

**Required：**
- **Base URL：** 你的 endpoint URL，例如 `https://your-endpoint.com/v1`
- **Model Name：** 你的模型标识符

它适用于任何实现了 OpenAI-compatible API 格式的框架或服务，包括：

- 自托管的开源推理服务
- 模型路由代理
- 自定义模型 endpoint

### Configuration parameters

支持全部 OpenAI-compatible 参数：

| Parameter | Range | Description |
|-----------|-------|-------------|
| **Temperature** | 0.0 - 2.0 | 响应随机性 |
| **Max Tokens** | 1+ | 最大响应长度 |
| **Top P** | 0.0 - 1.0 | Nucleus sampling |
| **Frequency Penalty** | -2.0 - 2.0 | 降低重复 |
| **Presence Penalty** | -2.0 - 2.0 | 鼓励新话题 |

**Advanced：**
- **JSON Mode：** 如果 endpoint 支持
- **Streaming：** 如果 endpoint 支持
- **Function Calling：** 如果 endpoint 实现了 OpenAI 格式

### Tool calling

- **Supported Tool Choices：** `auto`、`required`、`none`（如果 endpoint 支持）
- **Parallel Execution：** 是（如果 endpoint 支持）

## 所有 Providers 通用的配置

### Extra Parameters

所有 providers 都支持一个 **JSON editor**，用来传入 UI 中未显式暴露的额外参数：

```json
{
  "logprobs": true,
  "top_logprobs": 5,
  "custom_parameter": "value"
}
```

**适用场景：**
- provider 的 beta 特性
- UI 里暂未支持的高级参数
- 用于追踪的自定义 metadata

**限制：** 不能覆盖已经在 UI 中设置过的参数，例如你不能在这里再次设置上方已经填好的 temperature

### Rate Limiting

**Requests Per Second (RPS)**：适用于所有 providers，尤其是在对 dataset 运行时：

- **Range：** 0 - 500 RPS
- **Purpose：** 遵守 API 限流规则，并控制成本
- **Default：** 因 provider 不同而异

当你运行实验或评估时，可以设置这个值，以避免触发限流。
