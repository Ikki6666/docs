安装自 `deepagents-cli` 包的 `deepagents` CLI，为 [Managed Deep Agents](/langsmith/managed-deep-agents-overview) 提供部署工具。你可以用它来生成本地 agent 项目、将其部署到 LangSmith、管理 Managed Deep Agent 资源，并注册 MCP servers。

<Note>
Managed Deep Agents 当前处于 **private beta**，仅在美国区域的 [LangSmith Cloud](/langsmith/cloud) 中可用。你可以[加入候补名单](https://www.langchain.com/langsmith-managed-deep-agents-waitlist)来申请访问权限。
</Note>

若要快速走通端到端流程，请参见 [quickstart](/langsmith/managed-deep-agents-quickstart)。如需查看工作流指南，请参见 [Connect tools](/langsmith/managed-deep-agents-mcp)、[Deploy an agent](/langsmith/managed-deep-agents-deploy) 和 [Run an agent](/langsmith/managed-deep-agents-invoke)。

## 要求

<Note>
    Managed Deep Agents 要求 `deepagents-cli>=0.2.2`。
</Note>

通过 `uv`（推荐）或 `pip` 安装 `deepagents-cli`：

<CodeGroup>

```bash uv
uv tool install "deepagents-cli>=0.2.2"
```

```bash pip
pip install -U "deepagents-cli>=0.2.2"
```

</CodeGroup>

若要升级现有的 `uv` 安装，请运行 `uv tool upgrade deepagents-cli`。

CLI 会读取 `LANGSMITH_API_KEY`。创建 key 的方法请参见 [Create an API key](/langsmith/create-account-api-key)。如果你想覆盖默认 endpoint，请设置 `LANGSMITH_ENDPOINT`。

```bash
export LANGSMITH_API_KEY="<LANGSMITH_API_KEY>"
```

项目目录中的 `.env` 文件可以设置 API keys。但项目 `.env` 文件不能设置用于 managed API 请求的 endpoint、proxy 或 TLS 环境变量。若要覆盖这些配置，请在 shell 或 `~/.deepagents/.env` 中设置。

## 命令概览

| Command | Use |
| --- | --- |
| `deepagents --help` | 显示 CLI 帮助。 |
| `deepagents --version` | 显示已安装的 `deepagents-cli` 版本。 |
| `deepagents init [name]` | 生成一个新的 Managed Deep Agents 项目骨架。 |
| `deepagents deploy` | 根据本地项目文件创建或更新一个 Managed Deep Agent。 |
| `deepagents agents list` | 列出工作区中的 Managed Deep Agents。 |
| `deepagents agents get <agent_id>` | 查看单个 Managed Deep Agent。 |
| `deepagents agents delete <agent_id>` | 删除单个 Managed Deep Agent。 |
| `deepagents mcp-servers list` | 列出已注册的工作区 MCP servers。 |
| `deepagents mcp-servers add` | 注册一个工作区 MCP server。 |
| `deepagents mcp-servers get <server>` | 查看单个 MCP server，并对 header 值进行脱敏。 |
| `deepagents mcp-servers tools <server>` | 列出某个 server 的工具，并打印一个 `tools.json` 片段。 |
| `deepagents mcp-servers update <server>` | 更新 MCP server 的 URL、headers 或 auth type。 |
| `deepagents mcp-servers delete <server>` | 删除单个 MCP server。 |
| `deepagents mcp-servers connect <server>` | 为某个 OAuth MCP server 完成 OAuth 连接。 |

裸执行 `deepagents` 不会启动交互式 REPL。如需交互式编码会话，请安装并运行 [Deep Agents Code](/oss/deepagents/code/overview)。

## 初始化项目

使用 `deepagents init` 创建一个项目目录：

```bash
deepagents init my-agent
```

如果你省略项目名，CLI 会主动提示输入：

```bash
deepagents init
```

| Argument or flag | Use |
| --- | --- |
| `name` | 项目目录名称。如果省略，CLI 会提示输入。 |
| `--force` | 覆盖已存在项目目录中的文件。 |
| `-h`, `--help` | 显示命令帮助。 |

`init` 命令会在项目目录中创建以下文件：

| File or directory | Description |
| --- | --- |
| `agent.json` | Agent 元数据、模型、backend、权限，以及可选的目标 `agent_id`。详见 [agent.json](#agent-json) 部分。 |
| `AGENTS.md` | 主 agent 指令。详见 [AGENTS.md](#agents-md) 部分。 |
| `tools.json` | 空的工具配置。注册 MCP server 后，可以加入基于 MCP 的工具。详见 [tools.json](#tools-json) 部分。 |
| `skills/example-skill/` | 示例 skill 目录。你可以编辑、替换或删除它。详见 [skills](#skills) 部分。 |
| `subagents/researcher/` | 示例 subagent 目录。你可以编辑、替换或删除它。详见 [subagents](#subagents) 部分。 |
| `.gitignore` | 用于排除本地 `.env` 文件。 |

## 部署项目

在项目目录中运行 `deepagents deploy`：

```bash
deepagents deploy
```

第一次部署会创建一个 Managed Deep Agent，之后的部署则会更新同一个 agent。部署状态保存在用户本地、项目目录之外，因此提交到代码仓库中的文件不会改变你部署到哪个 agent。

默认情况下，deploy 会上传项目、轮询 agent 健康检查 endpoint，并打印 agent 名称、ID、短 revision、agent URL，以及一次部署后的 MCP 健康检查结果。若要跳过轮询并在创建或更新后立即退出，可使用 `--detach`。

| Flag | Use |
| --- | --- |
| `--dir DIR` | 项目目录。默认使用当前工作目录。 |
| `--dry-run` | 打印 agent payload 和托管文件树，但不发送请求。 |
| `--detach` | 创建或更新后立即退出，不轮询 agent 健康检查 endpoint。 |
| `--reset` | 丢弃本地部署状态并创建一个全新的 agent。当 `agent.json` 中声明了 `agent_id` 时不能使用。 |
| `--yes` | 更新目标 agent 时跳过确认提示。 |
| `-h`, `--help` | 显示命令帮助。 |

`deepagents deploy --dry-run` 会打印包含以下字段的 JSON：

| Field | Description |
| --- | --- |
| `agent_payload` | 用于创建或更新 Managed Deep Agent 资源的 payload。 |
| `directory_files` | deploy 将同步到 Context Hub 的托管文件树。 |

### 以现有 agent 作为目标

对于共享仓库或明确希望更新某个已有 Managed Deep Agent 的场景，可以在 `agent.json` 中声明目标：

```json
{
  "name": "my-agent",
  "agent_id": "agent-uuid",
  "model": "openai:gpt-5.5",
  "backend": {
    "type": "state"
  }
}
```

首次使用时，CLI 会在更新该远程 agent 前要求你确认。使用 `--yes` 可以跳过提示。

### 部署前验证项目

如果项目格式不正确，deploy 会在发送请求之前直接失败。常见校验规则包括：

- `agent.json` 和 `AGENTS.md` 是必需的。
- `agent.json` 必须包含非空的 `name`。
- `backend.sandbox_config` 只有在 `backend.type` 为 `sandbox` 时才允许出现。
- `backend.sandbox_config.scope` 必须为 `thread` 或 `agent`。
- `backend.sandbox_config.policy_ids` 必须是字符串数组。
- `backend.sandbox_config.idle_ttl_seconds` 和 `backend.sandbox_config.delete_after_stop_seconds` 必须是整数。
- deploy 项目输入中不允许出现 symlink。
- `tools.json` 必须包含 `tools` 数组。
- `tools.json` 中的每个 tool 都必须包含 `name` 和 `mcp_server_url`。
- skill 文件必须包含带 `name` 和 `description` 的 YAML frontmatter。
- subagent 目录必须包含 `agent.json` 和 `AGENTS.md`。
- 旧版 `deepagents.toml` 和 `mcp.json` 文件不会被部署，而是返回迁移提示。

在部署前，CLI 还会校验被引用的 MCP server URL。如果某个 server URL 尚未注册，deploy 会失败，并给出添加该 server 的命令提示。如果某个 OAuth server 已注册，但当前调用者尚无法调用它，deploy 也会失败，并提示你运行 `deepagents mcp-servers connect <id|name|url>`。

## 管理 agents

列出 agents：

```bash
deepagents agents list
```

该命令会打印制表符分隔的行，包含 agent ID、agent 名称和更新时间：

```text
e2de7a35-9dda-462b-b982-9e57051993bc\tmy-agent\t2026-06-01T12:00:00Z
```

查看某个 agent：

```bash
deepagents agents get <agent_id>
```

如需在响应中包含托管文件：

```bash
deepagents agents get <agent_id> --include-files
```

| Flag | Use |
| --- | --- |
| `--include-files` | 在响应中包含托管文件。 |
| `-h`, `--help` | 显示命令帮助。 |

删除某个 agent：

```bash
deepagents agents delete <agent_id>
```

删除命令默认会要求确认。你可以使用 `--yes` 跳过提示：

```bash
deepagents agents delete <agent_id> --yes
```

| Flag | Use |
| --- | --- |
| `--yes` | 跳过确认提示。 |
| `-h`, `--help` | 显示命令帮助。 |

## 管理 MCP servers

实际操作指南请参见 [Connect tools](/langsmith/managed-deep-agents-mcp)。

| Command | Use |
| --- | --- |
| `deepagents mcp-servers list` | 列出 MCP server ID、名称和 URL。 |
| `deepagents mcp-servers add --url URL` | 注册一个静态 header MCP server。 |
| `deepagents mcp-servers add --url URL --auth-type oauth` | 注册一个 OAuth MCP server。 |
| `deepagents mcp-servers get <server>` | 以 JSON 打印某个 MCP server，并对 header 值进行脱敏。 |
| `deepagents mcp-servers tools <server>` | 列出某个 server 的工具并打印一个 `tools.json` 片段。 |
| `deepagents mcp-servers update <server>` | 更新 server URL、headers 或 auth type。 |
| `deepagents mcp-servers delete <server>` | 删除单个 MCP server。 |
| `deepagents mcp-servers connect <server>` | 为某个 MCP server 发起或复用 OAuth 授权。 |

凡是接受 `<server>` 的命令，都支持传入 MCP server 的 ID、精确名称或 URL。非 ID 值会基于 `deepagents mcp-servers list` 结果进行解析；URL 匹配时会忽略大小写和尾部斜杠。如果某个名称或 URL 匹配到多个 server，请用 server ID 重新执行命令。

### 添加 MCP servers

注册一个静态 header server：

```bash
deepagents mcp-servers add \
  --url https://example.com/mcp \
  --name my-tools \
  --header Authorization="Bearer <token>"
```

| Flag | Use |
| --- | --- |
| `--url URL` | MCP server URL。必填。 |
| `--name NAME` | 显示名称。默认取 URL 的 hostname。 |
| `--header KEY=VALUE` | 静态认证 header。可重复传入多个。 |
| `--auth-type headers` | 静态 header 认证。这是默认值。 |
| `--auth-type oauth` | OAuth 认证。不能与 `--header` 同时使用。 |
| `--connect` | 为 OAuth MCP server 创建后立即发起连接。要求同时传入 `--auth-type oauth`。 |
| `--no-tools` | 注册后跳过尽力而为的工具列表查询。 |

注册一个 OAuth MCP server：

```bash
deepagents mcp-servers add \
  --url https://example.com/mcp \
  --name github-tools \
  --auth-type oauth \
  --connect
```

OAuth 的 `add` 命令还支持与 [`connect`](/langsmith/managed-deep-agents-cli#connect-oauth-mcp-servers) 相同的参数：`--scope`、`--force-new`、`--timeout` 和 `--no-browser`。

### 列出 MCP server 工具

列出某个已注册 server 的工具：

```bash
deepagents mcp-servers tools <id|name|url>
```

该命令会打印每个工具名称及其描述的第一行，然后输出一个可直接粘贴使用的 `tools.json` 片段。对于 OAuth server，请先完成连接，这样 MCP server 记录中才会包含调用方的 `oauth_provider_id`。

### 更新 MCP servers

更新 server URL 或 headers：

```bash
deepagents mcp-servers update <id|name|url> \
  --url https://new.example.com/mcp \
  --header Authorization="Bearer <token>"
```

| Flag | Use |
| --- | --- |
| `--url URL` | 替换 server URL。 |
| `--header KEY=VALUE` | 用提供的 header 集替换已存储的 headers。可重复传入多个。 |
| `--clear-headers` | 清空已存储 headers。不能与 `--header` 同时使用。 |
| `--auth-type headers` | 将认证方式设置为静态 headers。 |

该命令至少需要传入一个变更参数。

删除一个 MCP server：

```bash
deepagents mcp-servers delete <id|name|url>
```

删除命令默认会要求确认。你可以使用 `--yes` 跳过提示：

```bash
deepagents mcp-servers delete <id|name|url> --yes
```

### 连接 OAuth MCP servers

发起或复用 OAuth 授权：

```bash
deepagents mcp-servers connect <id|name|url>
```

| Flag | Use |
| --- | --- |
| `--scope SCOPE` | 请求的 OAuth scope。可重复传入多个。 |
| `--force-new` | 强制创建一个新的 OAuth 会话，而不是复用已有 token。 |
| `--timeout SECONDS` | 等待 OAuth 完成的秒数。使用 `0` 表示不轮询。默认值为 `300`。 |
| `--no-browser` | 打印验证 URL，但不自动打开浏览器。 |

如果授权仍处于等待状态，CLI 会打印验证 URL。当设置 `--timeout 0` 时，CLI 会发起授权后立即退出。你可以稍后再次运行 `deepagents mcp-servers connect <id|name|url>` 来完成或复用该连接。

## 项目文件参考

Managed Deep Agents 项目使用如下目录结构：

```text
my-agent/
  agent.json
  AGENTS.md
  tools.json
  skills/<name>/SKILL.md
  skills/<name>/<file>
  subagents/<name>/agent.json
  subagents/<name>/AGENTS.md
  subagents/<name>/tools.json
  subagents/<name>/skills/<skill-name>/SKILL.md
```

### agent.json

`agent.json` 用于配置 Managed Deep Agent 资源：

```json
{
  "name": "my-agent",
  "description": "A managed deep agent.",
  "model": "openai:gpt-5.5",
  "backend": {
    "type": "state"
  }
}
```

| Field | Description |
| --- | --- |
| `name` | 必填，非空的 agent 名称。 |
| `description` | 可选的 agent 描述。 |
| `agent_id` | 可选的现有 Managed Deep Agent ID，用于更新该 agent。 |
| `model` | 可选的简写模型标识符，格式为 `{provider}:{model_id}`。 |
| `runtime` | 可选，符合 API 结构的 runtime 对象。`model` 和 `runtime` 二者只能选其一。 |
| `backend` | 可选的 backend 配置。 |
| `permissions` | 可选的 identity、visibility 和 tenant access 设置。 |
| `extras` | 可选的额外 metadata，会原样透传给 API。 |

### 配置 backend

由 `deepagents-cli>=0.2.2` 生成的 Managed Deep Agents 项目默认使用 `state` backend。当 agent 需要用于代码执行、文件系统操作或长任务的隔离环境时，可改用 [LangSmith sandbox](/langsmith/sandboxes) backend。

| Backend type | Use for |
| --- | --- |
| `state` | 不使用任何 sandbox 特定 backend 行为。 |
| `sandbox` with `sandbox_config.scope: "thread"` | 将 LangSmith sandbox 资源按 thread 隔离。 |
| `sandbox` with `sandbox_config.scope: "agent"` | 将 LangSmith sandbox 资源按 agent 隔离。 |

Sandbox backend 可包含以下可选配置：

```json
{
  "backend": {
    "type": "sandbox",
    "sandbox_config": {
      "scope": "thread",
      "policy_ids": ["policy-id"],
      "idle_ttl_seconds": 900,
      "delete_after_stop_seconds": 300
    }
  }
}
```

`backend.sandbox_config` 仅在 `backend.type` 为 `sandbox` 时才合法。对于 snapshot、service URLs、permissions、CLI 命令和 SDK 用法等独立 sandbox 功能，请参见 [LangSmith sandboxes overview](/langsmith/sandboxes)。

| Field | Description |
| --- | --- |
| `scope` | Sandbox 作用域。`thread` 表示每个 thread 一个 sandbox，`agent` 表示整个 agent 共用一个 sandbox。 |
| `policy_ids` | Sandbox policy ID 数组。 |
| `idle_ttl_seconds` | 整数类型的空闲超时时间。 |
| `delete_after_stop_seconds` | 停止后删除前的延迟秒数，必须为整数。 |

### 配置 permissions

`agent.json` 中的可选 `permissions` 字段用于设置 identity、visibility 和 tenant access。支持的值如下：

| Field | Values |
| --- | --- |
| `identity` | `personal`, `shared` |
| `visibility` | `tenant`, `user` |
| `tenant_access_level` | `read`, `run`, `write` |

### AGENTS.md

`AGENTS.md` 保存主 agent 指令。CLI 会将其内容作为 agent system prompt 发送，并同时存储到托管文件树中。

### tools.json

`tools.json` 用于配置基于 MCP 的工具。`deepagents init` 会创建一个带空 `tools` 数组的文件。注册 MCP server 后，你可以向其中添加 tool 条目：

```json
{
  "tools": [
    {
      "name": "example_tool",
      "mcp_server_url": "https://example.com/mcp",
      "mcp_server_name": "my-tools",
      "display_name": "example_tool"
    }
  ],
  "interrupt_config": {
    "https://example.com/mcp::example_tool": true
  }
}
```

每个 tool 都必须包含 `name` 和 `mcp_server_url`。`mcp_server_name` 和 `display_name` 为可选项。`interrupt_config` 也是可选项，但如果存在则必须是对象。每个 interrupt 条目的 key 应为 `"{mcp_server_url}::{tool_name}"`。为了兼容性，也接受额外带有 `::{mcp_server_name}` 的形式。

### skills

每个 skill 存放于 `skills/<name>/SKILL.md` 下，并要求包含 YAML frontmatter：

```mdx
---
name: summarize
description: Summarize text into a one-paragraph summary.
---

# Summarize

Given a text, produce a one-paragraph summary.
```

CLI 会递归包含 skill 目录下的所有其他文件，但会排除隐藏路径。

### subagents

每个 subagent 位于 `subagents/<name>/` 下，并需要以下文件：

| File | Description |
| --- | --- |
| `agent.json` | Subagent 元数据，支持 `description` 和 `model`。 |
| `AGENTS.md` | Subagent 指令。 |
| `tools.json` | 可选的、针对 subagent 的 MCP 工具配置。 |
| `skills/` | 可选的 subagent 本地 skills。 |

示例 subagent `agent.json`：

```json
{
  "description": "Researches a topic.",
  "model": "openai:gpt-5.5"
}
```

旧版 `model_id` 键在本地 subagent 文件中仍可被接受，但新项目应使用 `model`。REST API 中的 `SubagentSpec` 使用的是 `model_id`。

Subagent 名称来自目录名，系统会以不区分大小写的方式检查重复。
