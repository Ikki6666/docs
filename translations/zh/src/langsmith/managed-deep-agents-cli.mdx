## 安装

根据你编写 agent 所使用的语言安装对应包。两个包都会暴露 `mda` 二进制。对于 npm，你可以全局安装，也可以用 `npm exec` 运行该命令。

<CodeGroup>

```bash pip
pip install --pre managed-deepagents
```

```bash npm
npm install -g managed-deepagents@dev
```

</CodeGroup>

对于 Python，`pip install --pre managed-deepagents` 会安装 `mda` CLI。由 `mda init` 生成的 Python 项目会自带 `pyproject.toml`，在本地开发或 deploy 前，请进入该项目目录并运行 `uv sync` 安装项目依赖。

TypeScript 包提供 `defineDeepAgent`、`defineIdentity`、`defineMcpServers`、`defineSchedule` 和 `defineSandbox`。Python 包提供 `define_deep_agent`、`define_identity`、`define_schedule`、`define_sandbox`、`managed_deepagents.connectors` 模块，以及 `mda` console script。

## 认证

`mda deploy` 会按以下顺序读取 API keys：

1. `LANGGRAPH_HOST_API_KEY`
2. `LANGSMITH_API_KEY`
3. `LANGCHAIN_API_KEY`

CLI 会先从项目 `.env` 文件读取这些值，再读取进程环境变量。如果在交互式终端中没有找到 key，`mda deploy` 会提示你输入 LangSmith API key，并将其保存到项目 `.env` 文件中。

```text .env
LANGSMITH_API_KEY=<LANGSMITH_API_KEY>
OPENAI_API_KEY=<OPENAI_API_KEY>
```

如果你想使用 organization-scoped key 进行部署，请设置 `LANGSMITH_TENANT_ID`，或在 `mda deploy` 时传入 `--tenant-id`。

LangSmith API key 用于 deploy 鉴权。Agent 在运行时还需要模型 provider 的凭据。你可以把 provider key 放进 `.env`、shell 环境变量，或配置为 LangSmith workspace secret。例如，`openai:gpt-5.5` 需要 `OPENAI_API_KEY`。

`mda deploy` 会把非保留的 `.env` 项，例如 `OPENAI_API_KEY`、MCP tokens 和自定义 tool 凭据，作为托管 deployment secrets 转发。包括 `LANGSMITH_API_KEY`、`LANGGRAPH_HOST_API_KEY`、`LANGCHAIN_API_KEY` 和 `LANGSMITH_TENANT_ID` 在内的保留平台变量，只用于 CLI 认证与 deploy 路由，不会作为用户可管理的 deployment secrets 上传。

## 命令概览

| 命令 | 用途 |
| --- | --- |
| `mda --help` | 显示 CLI 帮助。 |
| `mda --version` | 显示当前安装的 CLI 版本。 |
| `mda init <name>` | 创建 TypeScript 或 Python 的 Managed Deep Agents 项目脚手架。 |
| `mda dev [path]` | 编译项目，并在本地 LangGraph dev server 上运行。 |
| `mda deploy [path]` | 编译、同步 Context Hub context、上传并部署到 LangSmith。 |

## 初始化项目

使用 `mda init` 创建新项目目录：

```bash
mda init my-agent
```

| 参数 | 用途 |
| --- | --- |
| `name` | 必填，项目目录名。如果目标目录已存在，命令会失败。 |

该命令会根据当前目录自动判断语言：

| 当前目录包含 | 结果 |
| --- | --- |
| 仅有 `package.json` | TypeScript 脚手架。 |
| 仅有 `pyproject.toml` | Python 脚手架。 |
| 两者都有或都没有 | 进入交互式语言选择。 |

脚手架会创建：

| 文件 | 说明 |
| --- | --- |
| `agent.py` 或 `agent.ts` | 使用 `define_deep_agent(...)` 或 `defineDeepAgent(...)` 导出的命名 `agent`。 |
| `instructions.md` | 托管 system prompt。 |
| `pyproject.toml` 或 `package.json` | 最小语言清单文件。 |
| `README.md` | 本地项目说明。 |
| `.env` | Deploy 鉴权与运行时 secrets。不要提交真实 secrets。 |
| `.gitignore` | 忽略 `.env`、`.env.*`、`.mda/` 和依赖缓存。 |

## 本地开发

使用 `mda dev` 编译项目，并运行本地 LangGraph dev server：

```bash
mda dev .
```

| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--port PORT` | 传递端口给 LangGraph dev server。 |
| `--hostname HOSTNAME` | 传递主机名给 LangGraph dev server。 |
| `--browser` | Dev server 启动时自动打开浏览器，默认不打开。 |
| `--no-reload` | 关闭 dev server 的 hot reload。 |

`mda dev` 会先编译到 `.mda/build`，然后在该目录中启动对应语言的 LangGraph dev server：

| 项目语言 | Dev server 命令 |
| --- | --- |
| TypeScript | `npx --yes @langchain/langgraph-cli dev` |
| Python | `uv run --with langgraph-cli[inmem]>=0.4.30 langgraph dev` |

对于 Python 项目，在运行 `mda dev` 前请先安装 `uv`。CLI 会自动解析本地 LangGraph dev server，因此你不需要自行安装 `langgraph-cli[inmem]`。

如果配置了 sandbox，`mda dev` 会优先尝试配置的 provider。如果缺少 provider 凭据，或 provider 创建失败，它会退回到本地临时目录 sandbox，并打印实际使用的路径。

在本地开发时，`mda dev` 会把项目 `.env` 文件暂存到 `.mda/build/.env`，以便 LangGraph 加载 model provider keys 和 connector tokens。

## 部署项目

使用 `mda deploy` 编译并将项目部署到 LangSmith：

```bash
mda deploy .
```

| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--name NAME` | Deployment 名称。默认使用项目目录名，并规范化为小写字母、数字和连字符。 |
| `--deployment-type dev\|prod` | 创建 deployment 时使用的类型，默认为 `dev`。 |
| `--tenant-id TENANT_ID` | Workspace 或 tenant ID，会覆盖 `LANGSMITH_TENANT_ID`。 |
| `--host-url URL` | 覆盖 host backend API URL，默认指向美国区域 LangSmith Cloud。 |
| `--no-wait` | 触发远程构建后立即退出，不轮询 deployment 完成状态。 |

Deploy 会执行以下步骤：

1. 校验项目目录并加载 agent 入口文件。
2. 解析 LangSmith API key 和可选的 tenant ID。
3. 收集非保留 `.env` 值，作为托管 deployment secrets。
4. 确认模型 provider API key 可从 `.env`、shell 环境变量或 LangSmith workspace secrets 中获取。
5. 将 deploy 负责的 context 同步到 Context Hub。
6. 将项目编译到 `.mda/build`，并提取可选的 `schedules/` 声明。
7. 按名称创建或查找 LangSmith hosted deployment。
8. 打包 build、上传并触发远程构建。
9. 除非设置了 `--no-wait`，否则轮询 revision，直到状态变为 `DEPLOYED`。
10. 除非设置了 `--no-wait`，否则在 deployment 可用后对托管 LangSmith cron jobs 执行 reconcile。

成功后，CLI 会打印 LangSmith deployment dashboard URL。关于 secrets 路由和 deploy 提示，请参见 [Deploy an agent](/langsmith/managed-deep-agents-deploy)。

## 项目文件参考

Managed Deep Agents 项目采用代码优先布局：

<ManagedDeepAgentsProjectLayout />

唯一必需的是项目根目录下的 `agent.ts`、`agent.tsx` 或 `agent.py`。CLI 会按这个顺序查找第一个可用入口文件。

### Agent 入口

Agent 入口必须导出一个命名的 `agent` 定义，并且该定义由 `define_deep_agent` 或 `defineDeepAgent` 创建。最小示例请参见 [quickstart](/langsmith/managed-deep-agents-quickstart#edit-the-agent)。

这个定义支持 Deep Agents `createDeepAgent` 的全部配置面，但不允许设置托管字段。若设置了托管字段，会直接报错。

### 自编写 tools 与 middleware

把项目自有的 tools 和 middleware 放在 `tools/`、`middleware/` 等本地模块中，从 agent 入口导入，并分别通过 `tools` 和 `middleware` 字段传入。CLI 会把这些文件原样复制到编译后的 build 中，不会改写内容。

示例请参见 [Custom tools](/langsmith/managed-deep-agents-tools) 和 [Custom middleware](/langsmith/managed-deep-agents-middleware)。

### Identity

可选地在项目根目录的 `identity.ts` 或 `identity.py` 中，使用 `defineIdentity` / `define_identity`（或 `.preset(...)`）创建并导出一个命名的 `identity` 声明。

当存在该声明时，`mda` 会生成 custom auth handler，把它注入编译后的 app，并根据该声明对 threads、memory 和 store 访问做作用域隔离。未声明 identity 的项目会保持原有的编译产物。关于 presets、ingress 模式、guest tokens 和 `runtime.identity`，请参见 [Identity](/langsmith/managed-deep-agents-identity)。

### Instructions

请把 system prompt 放在项目根 agent 入口旁边的 `instructions.md` 中。

`mda dev` 会把该 prompt 嵌入生成的入口文件。`mda deploy` 会把 prompt 同步到 Context Hub，而部署后的运行时会从 Context Hub 读取它。

### Skills

请把 deploy 负责的 skills 放在项目根 agent 入口旁边的 `skills/` 目录下。部署时会把 `skills/**` 下所有 UTF-8 文件同步到 Context Hub，并删除那些线上存在但本地已删除的旧 skills。

### Memory

托管 memory 与部署后的 instructions 和 skills 存放在同一个 Context Hub repo 中，路径为 `/memories/AGENTS.md`。如果启用了 memory 且该文件不存在，deploy 会创建它。Deploy 会同步 `instructions.md` 和 `skills/**`，但不会覆盖本地或已有的 Context Hub `memories/**` 文件。

### Connectors

请把 connectors 声明为 `connectors/` 目录下直接存放的模块。发现过程与名称无关：每个文件都是一个 connector 模块（包的 `__init__.py` 文件会被忽略）。

- **MCP：**`connectors/mcp.ts` 或 `connectors/mcp.py` 必须导出一个命名的 `mcp` 声明。支持远程 `http` 和 `sse` servers，不支持 stdio。当存在该声明时，`mda` 会注入 `@langchain/mcp-adapters` 或 `langchain-mcp-adapters`，并把加载到的 MCP tools 追加到自编写 tools 后面。
- **LangSmith：**`connectors/langsmith.ts` 或 `connectors/langsmith.py` 为不受信任的调用方声明受限的 LangSmith 能力。需要声明 [identity](/langsmith/managed-deep-agents-identity)。浏览器永远不会收到 `LANGSMITH_API_KEY`。

更多示例和默认行为，请参见 [Connectors](/langsmith/managed-deep-agents-connectors)。

### Schedules

请在 `schedules/` 下声明托管 cron schedules。每个直接子 schedule 文件都必须导出一个使用 `defineSchedule(...)` 或 `define_schedule(...)` 创建的命名 `schedule` 声明。

Deploy 会从静态 literals、arrays、objects 以及顶层 literal constants 中提取 schedule 声明。在 deployment 进入 `DEPLOYED` 状态后，`mda deploy` 会用当前本地 `schedules/` 声明替换已有的托管 LangSmith cron jobs。更多示例和限制请参见 [Schedules](/langsmith/managed-deep-agents-schedules)。

### Sandbox

若要配置托管 sandbox，请在 TypeScript 项目中从 `sandbox/index.ts` 导出 `sandbox`，在 Python 项目中从 `sandbox/__init__.py` 导出 `sandbox`。Sandboxes 以 thread 为作用域。若存在 `sandbox/setup.sh`，它会在为某个 thread 首次创建托管 sandbox 时运行一次。

配置示例与生命周期行为请参见 [Configure a sandbox](/langsmith/managed-deep-agents-deploy#configure-a-sandbox)。

### 忽略路径

项目加载器会跳过以下目录：

```text
node_modules, .git, .mda, .deepagents, memories, dist, build
```

在复制文件到编译后的 build 时，它也会跳过 `.env` 和 `.env.*` 文件。`mda dev` 仅在本地开发时把根目录 `.env` 暂存到 `.mda/build/.env`；deploy 仍会把非保留 `.env` 项作为托管 secrets 转发，而不是直接打包 `.env` 文件。

## Agent 定义参考

`define_deep_agent` 和 `defineDeepAgent` 支持完整的 Deep Agents `create_deep_agent` 配置面，但托管字段除外。你应通过作者可设置字段来控制行为。

### 作者可设置字段

| 字段（Python / TypeScript） | 作用 |
| --- | --- |
| `model` | Chat model 实例，或 `{provider}:{model_id}` 标识符。 |
| `tools` | 在 agent 入口中导入的自编写 tools。 |
| `middleware` | 围绕模型与工具调用执行的有序 middleware 列表。 |
| `subagents` | Agent 可委托的 subagent 定义。 |
| `permissions` | Tool permission 规则。 |
| `interrupt_on` / `interruptOn` | 在执行前需要人工审核的 tool calls。 |
| `response_format` / `responseFormat` | Structured output 格式。 |
| `context_schema` / `contextSchema` | 每次 run 的 runtime context schema。 |
| `name` | Agent 名称。 |
| `cache` | 模型缓存配置。 |
| `debug` | 启用调试行为。 |
| `disable_memory` / `disableMemory` | 仅禁用托管 agent memory。 |

## 故障排查

| 症状 | 原因与修复 |
| --- | --- |
| `project root ... is not a directory` | 请给 `mda dev` 或 `mda deploy` 传入目录路径。 |
| `no agent entry file found` | 请在项目根目录添加 `agent.ts`、`agent.tsx` 或 `agent.py`。 |
| `mda dev` 找不到 `uv` | 对于 Python 项目，请安装 `uv`，以便 `mda dev` 解析本地 LangGraph dev server。 |
| `No LangSmith API key found` | 请设置 `LANGSMITH_API_KEY`，或把它写入项目 `.env`。 |
| Deploy 失败并返回 401 或 403 | 请确认该 API key 对应的 workspace 已获得 beta 访问权限。 |
| Deploy 报缺少模型 provider API key | 请将 `OPENAI_API_KEY` 等 provider key 加入 `.env`、导出到 shell 环境变量，或配置为 LangSmith workspace secret。 |
