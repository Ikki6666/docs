## 安装

根据你编写 agent 所使用的语言安装对应包。该包会暴露 `mda` 二进制。

:::python

```bash uv
uv tool install managed-deepagents
```

`uv tool install managed-deepagents` 会安装 `mda` CLI。由 `mda init` 生成的项目会自带 `pyproject.toml`，在本地开发或 deploy 前，请进入该项目目录并运行 `uv sync` 安装项目依赖。

该包提供 agent、identity、schedule 和 sandbox 的编写 API（snake-case 命名），以及 `mda` console script。
:::

:::js
对于 npm，你可以全局安装，也可以用 `npm exec` 运行该命令。

```bash npm
npm install managed-deepagents
```

该包提供 agent、identity、schedule 和 sandbox 的编写 API。
:::

## 认证

`mda deploy` 会按以下顺序读取 API keys：

1. `LANGGRAPH_HOST_API_KEY`
2. `LANGSMITH_API_KEY`
3. `LANGCHAIN_API_KEY`

CLI 会先从项目 `.env` 文件读取这些值，再读取进程环境变量。如果在交互式终端中没有找到 key，`mda deploy` 会提示你输入 LangSmith API key，并将其保存到项目 `.env` 文件中。

```text .env
LANGSMITH_API_KEY=<LANGSMITH_API_KEY>
OPENAI_API_KEY=<OPENAI_API_KEY>
```

如果你想使用 organization-scoped key 进行部署，请设置 `LANGSMITH_WORKSPACE_ID`，或在 `mda deploy` 时传入 `--workspace-id`。

LangSmith API key 用于 deploy 鉴权。Agent 在运行时还需要模型 provider 的凭据。你可以把 provider key 放进 `.env`、shell 环境变量，或配置为 LangSmith workspace secret。例如，`openai:gpt-5.5` 需要 `OPENAI_API_KEY`。

`mda deploy` 会把非保留的 `.env` 项，例如 `OPENAI_API_KEY`、MCP tokens 和自定义 tool 凭据，作为托管 deployment secrets 转发。包括 `LANGSMITH_API_KEY`、`LANGGRAPH_HOST_API_KEY`、`LANGCHAIN_API_KEY` 和 `LANGSMITH_WORKSPACE_ID` 在内的保留平台变量，只用于 CLI 认证与 deploy 路由，不会作为用户可管理的 deployment secrets 上传。

## 初始化项目

使用 `mda init` 创建新项目目录：

```bash
mda init my-agent
```

| 参数或 flag | 用途 |
| --- | --- |
| `name` | 必填，项目目录名。如果目标目录已存在，命令会失败。 |
| `--instructions TEXT` | 写入 `instructions.md` 的 system prompt。 |
| `--instructions-file PATH` | 从文件读取 system prompt 写入 `instructions.md`，设为 `-` 时从 stdin 读取。 |
| `--identity` | 添加带用户私有 threads 的托管认证。 |
| `--memory agent\|none` | 可选地写入一个根 memory 声明。如果省略，不会创建 memory 文件，持久 memory 处于关闭状态。 |
| `--model SPEC` | Agent 运行的 model，格式为 `provider:model`。 |
| `--no-sandbox` | 不包含托管 sandbox 声明。 |

该命令会根据当前目录自动判断语言：

:::python
| 当前目录包含 | 结果 |
| --- | --- |
| 仅有 `pyproject.toml` | Python 脚手架。 |
| 两者都有或都没有 | 进入交互式语言选择。 |
:::

:::js
| 当前目录包含 | 结果 |
| --- | --- |
| 仅有 `package.json` | TypeScript 脚手架。 |
| 两者都有或都没有 | 进入交互式语言选择。 |
:::

脚手架会创建：

:::python
| 文件 | 说明 |
| --- | --- |
| `agent.py` | 使用 `define_deep_agent(...)` 导出的命名 `agent`。 |
| `instructions.md` | 托管 system prompt。 |
| `pyproject.toml` | 最小语言清单文件。 |
| `README.md` | 本地项目说明。 |
| `.env` | Deploy 鉴权与运行时 secrets。不要提交真实 secrets。 |
| `.gitignore` | 忽略 `.env`、`.env.*`、`.mda/` 和依赖缓存。 |
:::

:::js
| 文件 | 说明 |
| --- | --- |
| `agent.ts` | 使用 `defineDeepAgent(...)` 导出的命名 `agent`。 |
| `instructions.md` | 托管 system prompt。 |
| `package.json` | 最小语言清单文件。 |
| `README.md` | 本地项目说明。 |
| `.env` | Deploy 鉴权与运行时 secrets。不要提交真实 secrets。 |
| `.gitignore` | 忽略 `.env`、`.env.*`、`.mda/` 和依赖缓存。 |
:::

Eval tasks 是可选的，`mda init` 不会创建。Managed Deep Agents evals 是 `evals/tasks/` 下的 Harbor tasks。仅在你需要可选的入门 task 时运行 `mda evals init <name>`，它会在 `evals/scaffold/` 下创建。

## 编译项目

使用 `mda build` 编译项目为托管 LangGraph app，但不部署：

```bash
mda build .
```

| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--out OUT` | 编译后 app 的输出目录，默认为 `<path>/.mda/build`。该目录在编译前会被清空，因此它必须不存在、为空，或是一个由之前编译写入的目录。 |

## 评估项目

`evals/tasks/` 是规范的 Harbor dataset。请直接在其中编写完整的 Harbor tasks。`mda eval` 命令（也可用 `mda evals`）可以创建入门 task，并为 Harbor 打包托管 agent。MDA 会打印一条 `harbor run` 命令，但不会运行 trials。

```bash
mda evals init smoke
mda evals compile .
# then run the printed `harbor run` command
```

| 子命令 | 用途 |
| --- | --- |
| `mda evals init <name>` | 在 `evals/scaffold/<name>/` 下创建一个包含 instruction 和语言原生测试的入门 task。请在项目根目录运行此命令。 |
| `mda evals compile [path]` | 编译托管 agent，将选中的 scaffold 复制到 `evals/tasks/`，并在 `evals/` 下写入 Harbor handoff。 |

传入 `mda evals init` 的 task 名称只能包含 ASCII 字母、数字、`_` 和 `-`。

`mda evals compile` flags：

| Flag | 用途 |
| --- | --- |
| `--task <name>` | 选择一个 task。可重复以选择多个 task。选中的 scaffold 会刷新 `evals/tasks/` 下匹配的 task。如果省略，则选择所有 task 并刷新每个 scaffold。已有的规范 task 会被保留，除非选中的 scaffold 同名。 |
| `--model <provider:model>` | 在 artifact manifest 中记录一个 model。可重复以记录多个 model；生成的 job config 使用第一个值。 |

关于 Harbor task 编写、可选 scaffold、凭据和运行 trials，请参见 [Evals](/langsmith/managed-deep-agents-evals)。

## 本地开发

使用 `mda dev` 编译项目，并运行本地 LangGraph dev server：

```bash
mda dev .
```

| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--port PORT` | 传递端口给 LangGraph dev server。 |
| `--hostname HOSTNAME` | 传递主机名给 LangGraph dev server。 |
| `--no-browser` | 阻止 dev server 启动时在浏览器中打开 Studio。 |
| `--no-reload` | 关闭 dev server 的 hot reload。 |

`mda dev` 会先编译到 `.mda/build`，然后在该目录中启动对应语言的 LangGraph dev server：

:::python
| 项目语言 | Dev server 命令 |
| --- | --- |
| Python | `uv run --with langgraph-cli[inmem]>=0.4.30 langgraph dev` |

在运行 `mda dev` 前请先安装 `uv`。CLI 会自动解析本地 LangGraph dev server，因此你不需要自行安装 `langgraph-cli[inmem]`。
:::

:::js
| 项目语言 | Dev server 命令 |
| --- | --- |
| TypeScript | `npx --yes @langchain/langgraph-cli dev` |
:::

如果配置了 sandbox，`mda dev` 会优先尝试配置的 provider。如果缺少 provider 凭据，或 provider 创建失败，它会退回到本地临时目录 sandbox，并打印实际使用的路径。

在本地开发时，`mda dev` 会把项目 `.env` 文件暂存到 `.mda/build/.env`，以便 LangGraph 加载 model provider keys 和 connector tokens。

## 部署项目

使用 `mda deploy` 编译并将项目部署到 LangSmith：

```bash
mda deploy .
```

| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--name NAME` | Deployment 名称。默认使用项目目录名，并规范化为小写字母、数字和连字符。 |
| `--deployment-type dev\|prod` | 创建 deployment 时使用的类型，默认为 `dev`。 |
| `--workspace-id WORKSPACE_ID` | Workspace ID，会覆盖 `LANGSMITH_WORKSPACE_ID`。 |
| `--host-url URL` | 覆盖 host backend API URL，默认指向美国区域 LangSmith Cloud。 |
| `--no-wait` | 触发远程构建后立即退出，不轮询 deployment 完成状态。 |

成功后，CLI 会打印 LangSmith deployment dashboard URL。关于 secrets 路由和 deploy 提示，请参见 [Deploy an agent](/langsmith/managed-deep-agents-deploy)。

## 查看部署日志

使用 `mda logs` 查看已部署 agent 的 Agent Server 日志：

```bash
mda logs .
```

| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--name NAME` | Deployment 名称。默认使用项目中的 agent `name`。 |
| `--lines LINES` | 获取的最近日志行数。默认为 `1000`。 |
| `--level LEVEL` | 只显示达到或超过指定严重级别的条目：`debug`、`info`、`warning`、`error` 或 `critical`。 |
| `--follow` | 持续流式输出新日志。在交互式终端中这是默认行为。 |
| `--no-follow` | 打印最近日志后退出。在输出被管道传递时这是默认行为。 |
| `--workspace-id WORKSPACE_ID` | 读取的 Workspace ID。会覆盖 `LANGSMITH_WORKSPACE_ID`。 |

## 删除 deployment

使用 `mda delete` 删除已部署的 Managed Deep Agent 及其创建的 LangSmith 资源。`mda destroy` 是其别名。

```bash
mda delete .
```

:::python
| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--name NAME` | Deployment 名称。默认使用 `define_deep_agent` 中的 agent `name`。 |
| `--workspace-id WORKSPACE_ID` | Deployment 所在的 Workspace ID。会覆盖 `LANGSMITH_WORKSPACE_ID`。 |
| `--yes` | 删除时不要求确认。 |
:::

:::js

## 故障排查

:::python
| 症状 | 原因与修复 |
| --- | --- |
| `project root ... is not a directory` | 请给 `mda dev` 或 `mda deploy` 传入目录路径。 |
| `no agent entry file found` | 请在项目根目录添加 `agent.py`。 |
| `mda dev` 找不到 `uv` | 请安装 `uv`，以便 `mda dev` 解析本地 LangGraph dev server。 |
| `No LangSmith API key found` | 请设置 `LANGSMITH_API_KEY`，或把它写入项目 `.env`。 |
| Deploy 失败并返回 401 或 403 | 请确认该 API key 对应的 workspace 已获得 beta 访问权限。 |
| Deploy 报缺少模型 provider API key | 请将 `OPENAI_API_KEY` 等 provider key 加入 `.env`、导出到 shell 环境变量，或配置为 LangSmith workspace secret。 |
| Deploy 报 Context Hub 冲突 | Context Hub repo 在 deploy 期间发生了变更。请重新运行 `mda deploy`。 |
| Build 超过 200 MB | 请在部署前从项目中移除生成的 artifacts 或大文件。 |
| Deployment 进入 `BUILD_FAILED` 或 `DEPLOY_FAILED` | 请在 LangSmith 中打开打印的 deployment URL，查看 revision logs。 |
:::

| 症状 | 原因与修复 |
