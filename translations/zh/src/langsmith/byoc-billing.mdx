## 成本模型

一个 BYOC 部署会产生两份独立的账单：

- **AWS**：Data plane 运行在你自己的 AWS 账户中，因此 AWS 会直接就其创建的基础设施向你收费。
- **LangSmith**：LangChain 根据你的合同和使用量向你开具发票。

LangSmith BYOC 可以与 AWS Marketplace 集成。

## 产生费用的 AWS 服务

以下资源会在你的账户中产生 data plane 成本。AWS 按照自己的费率对它们收费，独立于你的 LangSmith 合同。使用 [BYOVPC](/langsmith/byoc-byovpc) 时，网络成本取决于你配置和管理的网关、endpoints 和日志。

| 服务 | 覆盖内容 | 计费方式 |
|---------|----------------|---------------|
| **Amazon EKS** | Data plane 集群的 Kubernetes control plane | 按集群小时 |
| **Amazon EC2** | 在 EKS 集群中运行的节点 | 按实例小时 |
| **Amazon RDS** | 用于关系型工作负载的实例。SmithDB 使用 Aurora PostgreSQL Serverless v2 metastore。 | 按实例小时（包括 Multi-AZ），外加存储、备份和快照。Aurora 按 ACU 小时计费，外加存储和 I/O。 |
| **Amazon ElastiCache** | 用于缓存和队列工作负载的 Redis 实例 | 按节点小时 |
| **Amazon S3** | 用于 LangSmith 工作负载、ClickHouse 备份和 VPC flow logs 的存储桶 | 按存储、请求和数据传输计费 |
| **Amazon EBS** | 节点根磁盘，以及用于 ClickHouse 存储的卷 | 按 GB 月计费，外加超出 gp3 基线的预置 IOPS 和吞吐量 |
| **Regional NAT gateway** | 来自私有子网的出站流量 | 按小时计费，外加处理的数据量 |
| **Elastic Load Balancing** | 两个 network load balancer：一个位于 Istio ingress 之前，另一个用于 EKS API PrivateLink endpoint | 按 NLB 小时计费，外加 NLCUs |
| **AWS PrivateLink** | Data plane 使用的 interface VPC endpoints | 按 interface endpoint 每可用区小时计费，外加处理的数据量 |
| **AWS Lambda 和 Amazon EventBridge** | PrivateLink endpoints 的调和（reconciliation） | 按调用次数和发布的事件数计费 |
| **Amazon CloudWatch Logs** | EKS control plane 日志 | 按摄取和存储计费 |
| **VPC flow logs** | 将 flow logs 传送到 S3 | 按 GB 交付量计费 |
| **Amazon Route 53** | Private hosted zone | 按 hosted zone 月计费，外加查询 |
| **AWS Secrets Manager** | RDS 生成的 master secrets，以及 LangSmith 引用的应用 secrets | 按 secret 月计费，外加 API 调用 |

### 数据传输

BYOC 中有以下几个数据传输成本驱动因素：

- 跨可用区流量，因为 data plane 以[高可用](/langsmith/byoc-operations#high-availability)方式跨可用区运行。
- 通过 NAT gateway 的出口流量，例如调用模型提供商，或通过 webhook 调用外部 API。
- 公共 IPv4 地址，AWS 按每个地址每小时收费。Regional NAT gateway 使用一个，启用公共 ingress 时面向互联网的 load balancer 会使用另一个。

## 服务限额

AWS 按区域和账户执行默认配额。对于新建或使用较少的账户，默认值通常不足以支撑生产环境，因此请在部署之前检查以下各项，并在需要时申请提升配额：

- **EC2 vCPU 配额**：至少需要 64 vCPU 的 On-Demand 容量，用于覆盖 3 个 system nodes 和 Karpenter 工作负载。
- **子网 IP 容量**：为 pods、节点、EKS ENIs、load balancer 留出空间，并且每个 application subnet 至少要有 12 个 interface endpoints 的容量。
- **VPC endpoints**：需要 12 个 interface endpoints 和 1 个 S3 gateway endpoint 的容量。
- **Load balancer**：需要 2 个 Network Load Balancer 及其 target groups 的容量。
- **EKS**：需要 1 个 EKS 集群的容量。
- **存储**：为 ClickHouse、ZooKeeper、节点磁盘以及其他持久化工作负载准备 EBS 卷和存储容量。
- **数据库**：需要 2 个 RDS 实例、1 个用于 SmithDB metastore 的 Aurora 集群（writer 和 reader），以及 3 个 ElastiCache 副本的容量。
- **PrivateLink 和网络**：需要 1 个 endpoint service 和 1 个 regional NAT gateway 的容量。

当前默认值请参阅 [AWS service quotas](https://docs.aws.amazon.com/general/latest/gr/aws_service_limits.html)。

使用 BYOVPC 时，在检查配额时还需要考虑现有资源占用以及你选择的 endpoint 和出口配置。你提供的子网还必须满足[子网大小和可用 IP 要求](/langsmith/byoc-byovpc#configure-the-vpc-and-subnets)。

如果预置停滞或失败，配额耗尽是常见原因之一，此外还有权限缺失和 service control policies。参见 [What happens if provisioning fails?](/langsmith/byoc-faq)。
