本指南介绍如何为 LangSmith 应用添加自定义身份验证。本页中的步骤同时适用于[云端](/langsmith/cloud)和[自托管](/langsmith/self-hosted)部署，不适用于你在自定义服务器中单独使用 [LangGraph 开源库](/oss/langgraph/overview) 的场景。

## 为部署添加自定义身份验证

要在部署中利用自定义身份验证并访问用户级元数据，请设置自定义身份验证，通过自定义身份验证处理器自动填充 `config["configurable"]["langgraph_auth_user"]` 对象。随后，你可以在图中使用 `langgraph_auth_user` 键访问该对象，以[让 agent 代表用户执行需要身份验证的操作](#enable-agent-authentication)。

1. 实现身份验证：

    <Note>
    如果没有自定义 `@auth.authenticate` 处理器，LangGraph 只能看到 API 密钥的拥有者，通常是开发者，因此请求不会限定到单个终端用户。要传递自定义令牌，必须实现你自己的处理器。
    </Note>

    ```python
    from langgraph_sdk import Auth
    import requests

    auth = Auth()

    def is_valid_key(api_key: str) -> bool:
        is_valid = # your API key validation logic
        return is_valid

    @auth.authenticate # (1)!
    async def authenticate(headers: dict) -> Auth.types.MinimalUserDict:
        api_key = headers.get(b"x-api-key")
        if not api_key or not is_valid_key(api_key):
            raise Auth.exceptions.HTTPException(status_code=401, detail="Invalid API key")

        # Fetch user-specific tokens from your secret store
        user_tokens = await fetch_user_tokens(api_key)

        return { # (2)!
            "identity": api_key,  #  fetch user ID from LangSmith
            "github_token" : user_tokens.github_token
            "jira_token" : user_tokens.jira_token
            # ... custom fields/secrets here
        }
    ```
  - 该处理器接收请求信息，例如请求头，校验用户，并返回一个至少包含 `identity` 字段的字典。
  - 你可以按需添加任意自定义字段，例如 OAuth 令牌、角色、组织 ID 等。

2. 在 [`langgraph.json`](/langsmith/application-structure#configuration-file) 中添加 auth 文件路径：

    ```json highlight={7-9}
    {
        "dependencies": ["."],
        "graphs": {
        "agent": "./agent.py:graph"
        },
        "env": ".env",
        "auth": {
            "path": "./auth.py:my_auth"
        }
    }
    ```
3. 在服务器中完成身份验证设置后，请求必须根据你选择的方案附带所需的授权信息。假设你使用 JWT 令牌身份验证，可以通过以下任一方式访问部署：

      ```python
      client = get_client(
          url="http://localhost:2024",
          headers={"Authorization": f"Bearer {my_token}"}
      )
      threads = await client.threads.search()
      ```
        </Tab>

        </Tab>

## 启用 agent 身份验证

完成[身份验证](#add-custom-authentication-to-your-deployment)后，平台会创建一个特殊配置对象 `config`，并将其传递给 LangSmith 部署。这个对象包含当前用户的信息，包括你从 `@auth.authenticate` 处理器返回的任何自定义字段。

要让 agent 代表用户执行需要身份验证的操作，请在图中使用 `langgraph_auth_user` 键访问该对象：

```python
def my_node(state, config):
    user_config = config["configurable"].get("langgraph_auth_user")
    # token was resolved during the @auth.authenticate function
    token = user_config.get("github_token","")
    ...
```

<Note>
请从安全的密钥存储中获取用户凭证。不建议将密钥存储在图状态中。
</Note>

### 为 Studio 中的用户授权

默认情况下，如果你为资源添加了自定义授权规则，这些规则同样会应用到来自 [Studio](/langsmith/studio) 的交互。如果你愿意，也可以通过检查 [is_studio_user()](https://langchain-ai.github.io/langgraph/cloud/reference/sdk/python_sdk_ref/#langgraph_sdk.auth.types.StudioUser) 对登录到 Studio 的用户采用不同处理方式。

<Note>
`is_studio_user` 在 `langgraph-sdk` 0.1.73 版本中加入。如果你使用的是更早版本，仍然可以通过检查 `isinstance(ctx.user, StudioUser)` 来判断。
</Note>

```python
from langgraph_sdk.auth import is_studio_user, Auth
auth = Auth()

# ... Setup authenticate, etc.

@auth.on
async def add_owner(
    ctx: Auth.types.AuthContext,
    value: dict  # The payload being sent to this access method
) -> dict:  # Returns a filter dict that restricts access to resources
    if is_studio_user(ctx.user):
        return {}

    filters = {"owner": ctx.user.identity}
    metadata = value.setdefault("metadata", {})
    metadata.update(filters)
    return filters
```

只有当你希望允许开发者访问部署在托管 LangSmith SaaS 上的图时，才需要这样做。
