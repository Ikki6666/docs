本页指导管理员为一个团队准备好 [LLM Gateway](/langsmith/llm-gateway)：连接 providers、授予访问权限、发放 API key 并设置策略。请按顺序完成以下各节，每一节都链接到完整介绍该主题的页面。

<Tip>
部分用户无需这些设置即可开始使用。[Workspace Admin](/langsmith/rbac#workspace-admin) 已经可以调用 gateway，并且可以从 Simulator 的 **Needs key** 提示中添加 provider key。如果你是组织中唯一的用户，请直接阅读[发送第一个 LLM Gateway 请求](/langsmith/llm-gateway-first-request)。
</Tip>

## 在 self-hosted LangSmith 上启用 gateway

在 self-hosted LangSmith 上，请先在 Helm chart 中[启用 gateway](/langsmith/llm-gateway-self-hosted)，再执行其他步骤。其他部署请跳过本节。

## 添加 provider key

添加 provider key 需要在该工作区中拥有[管理 secret 的权限](/langsmith/rbac#workspace-roles)。

gateway 会使用一个 secret 调用每个 provider，该 secret 存储在调用方 API key 所属的工作区中。请在每个会调用某 provider 的工作区中，为该 provider 添加一个 key。对于这些调用，gateway 不会回退到组织级 secrets。

如果你的团队只调用 [Gateway Credits](/langsmith/llm-gateway-credits) 模型，请跳过本节，这些模型不需要 provider key。

有关操作步骤以及各 provider 使用的 secret 名称，请参见[添加 provider key](/langsmith/llm-gateway-provider-authentication#add-a-provider-key)。

## 授予调用 gateway 的权限

API key 需要 `gateway:invoke` 和 `workspaces:read` 权限才能调用 gateway。在没有工作区角色的方案中，每个用户都拥有 Workspace Admin 角色，该角色包含这两项权限，因此无需任何操作。

在 Enterprise 方案中，内置的 Workspace Editor 和 Workspace Viewer 角色都不包含这两项权限。作为 [Organization Admin](/langsmith/rbac#organization-admin)，请创建一个同时包含这两项权限的[自定义角色](/langsmith/rbac#custom-roles)，并将其分配给调用 gateway 的用户，或者直接为他们分配 Workspace Admin 角色。

更多信息请参见[授予调用 gateway 的权限](/langsmith/llm-gateway-authentication#grant-permission-to-call-the-gateway)。

## 决定开发者如何获取 API key

每个请求都使用工作区范围的 LangSmith API key 进行认证。开发者可以自行创建个人访问令牌（PAT），该令牌携带其角色；Simulator 也可以代为创建。对于共享 agents，或通过移动设备管理（MDM）面向全公司推广的场景，你也可以改为创建 service keys。

有关 key 类型和作用域，请参见[选择 key 类型](/langsmith/llm-gateway-authentication#choose-a-key-type)。coding agent 推广请参见[设置 coding agents](/langsmith/llm-gateway-coding-agents)。

## 可选：设置策略

创建策略需要 `organization:gateway:manage` 权限，Organization Admins 和 Organization Operators 默认拥有该权限。在早于应用版本 0.18.9 的 self-hosted LangSmith 上（Helm chart 版本早于 0.18.0-rc.22），则需要 `organization:manage`。

使用 **LLM Gateway** 页面上的标签页创建以下任意类型的策略：

- **[Spend limits](/langsmith/llm-gateway-spend-policies)**：在组织、工作区、API key 或用户级别设置硬性上限。你的组织可能已在 **Cost Controls** 标签页上设置了默认限额。
- **[Rate limits](/langsmith/llm-gateway-rate-limit-policies)**：在时间窗口内限制请求数或 token 数。
- **[Model access](/langsmith/llm-gateway-model-access-policies)**：限制用户可以调用哪些模型。
- **[Header-based policies](/langsmith/llm-gateway-header-policies)**：按自定义请求 header（例如客户或团队标识符）限定 spend caps、rate limits 和 model access。
- **[Data policies](/langsmith/llm-gateway-data-policy)**：在数据到达模型前检测并脱敏 PII 和 secrets，并控制是否记录请求和响应正文。

在 Enterprise 方案中，创建、更新和删除策略都会记录在[审计日志](/langsmith/audit-logs)中。

## 发送测试请求

要确认设置是否正确，请按照[发送第一个 LLM Gateway 请求](/langsmith/llm-gateway-first-request)操作。该页面会从 Simulator 和代码中分别发送一个请求，并展示对应的 trace。请把同一个页面作为开发者的入门指南分享给他们。
