<Note>
**Private beta:** LLM Gateway 当前处于私有 [beta](/langsmith/release-stages) 阶段。你可以[加入候补名单](https://www.langchain.com/langsmith-llm-gateway-waitlist)申请访问权限。
</Note>

本页介绍如何为你的 LangSmith[组织](/langsmith/administration-overview#organizations)执行一次性设置，以启用 LLM Gateway。在单个用户开始把调用路由到 gateway 之前，[组织管理员](/langsmith/rbac#organization-admin)应先完成这些步骤。

## 前置条件

你需要在 LangSmith 中拥有 [`organization:manage` 权限](/langsmith/organization-workspace-operations)。[第 3 步的选项 A](/langsmith/llm-gateway-admin-setup#option-a-create-a-custom-workspace-role-recommended) 还要求你使用包含 [RBAC](/langsmith/rbac)（自定义角色）的方案。

## 1. 启用 LLM Gateway

在 private beta 期间，gateway 需要由 LangChain 为你的组织手动开启。加入 beta 后，系统会为你的组织打开 `llm_gateway_enabled` feature flag。

到 Generally Available 阶段时，这会变成一个可自助启用的设置。

## 2. 添加 Provider Secrets

Gateway 会从你工作区的 Provider Secrets 中解析 provider API keys，这样它才能在不让单个用户持有本地 provider keys 副本的前提下，把请求代理到上游 providers。

前往 **Settings → Integrations → Provider Secrets**，并为你希望通过 gateway 代理的 providers 添加相应密钥：

| Secret name | Provider |
| --- | --- |
| `ANTHROPIC_API_KEY` | Anthropic |
| `AWS_BEARER_TOKEN_BEDROCK` | AWS Bedrock |
| `BASETEN_API_KEY` | Baseten |
| `FIREWORKS_API_KEY` | Fireworks |
| `GOOGLE_API_KEY` | Google Gemini |
| `OPENAI_API_KEY` | OpenAI |
| `VERTEX_SERVICE_ACCOUNT_JSON` | Google Vertex AI |

只添加你组织真正会使用的 providers。如果用户尝试调用某个尚未添加密钥的 provider，gateway 会返回错误。

## 3. 为用户配置 gateway 访问权限

内置角色 `WORKSPACE_USER` 和 `WORKSPACE_VIEWER` 不包含 `gateway:invoke` 权限，并且无法编辑。你有两种方式来授予 gateway 访问权限：

### 选项 A：创建自定义工作区角色（推荐）

要求方案已启用 RBAC。

1. 前往 **Settings → Members/Roles**。
1. 创建一个新的工作区角色。
1. 至少授予该角色 `gateway:invoke` 和 `workspaces:read`。
1. 把需要 gateway 访问权限的用户分配到这个角色上。

当你希望在不授予完整 workspace-admin 权限的前提下，向特定用户开放 gateway 访问时，请使用这种方式。它能让你最精确地控制谁可以使用 gateway。

### 选项 B：使用 workspace admin 角色

无方案要求。

`WORKSPACE_ADMIN` 角色默认已经包含 `gateway:invoke` 和 `workspaces:read`。把需要 gateway 访问的用户分配到这个角色即可。

如果你不需要细粒度访问控制，或者你的方案没有启用 RBAC，就可以使用这种方式。

## 4. 配置策略（可选）

管理 gateway 策略需要 `organization:manage` 权限。

前往 **Settings → Gateway → LLM Gateway** 创建治理策略。你可以配置：

- **Spend limits:** 在组织、工作区、API key 或用户级别设置硬性上限。详见[支出策略](/langsmith/llm-gateway-spend-policies)。
- **PII 和 secrets 脱敏:** 在数据到达模型前检测并脱敏敏感信息。详见[PII 和 secrets 脱敏](/langsmith/llm-gateway-redaction)。

策略在初始设置阶段不是必须的。在你配置好策略之前，gateway 会自由放行所有调用。

## 5. 向用户分发 API keys

为需要 gateway 访问的用户创建工作区范围的[服务密钥](/langsmith/administration-overview#service-keys)。每个 key 都应绑定到包含 `gateway:invoke` 和 `workspaces:read` 的角色上。

请使用工作区范围 keys，而不是组织范围 keys。详情请参见 [API key 作用域](/langsmith/llm-gateway-access#api-key-scoping)。

把 key 和 gateway endpoint 分享给每个用户，或者通过 MDM（移动设备管理）分发它们，以支持面向全公司的 coding agent rollout。若要查看按 agent 分类的配置说明，请参见 [Set up coding agents](/langsmith/llm-gateway-coding-agents)。

## 验证

请让某位用户运行 [Quickstart](/langsmith/llm-gateway-quickstart#2-make-a-call) 中的验证 curl。收到 `200` 响应，说明 gateway、API key、provider secrets 和角色权限都配置正确。该调用会作为一条 trace 出现在该工作区中的 **gateway** tracing project 下。
