工具包是一组选定的工具，由 [Tool Gateway](/langsmith/tool-gateway) 在一个 MCP URL 上提供。这些工具可以来自任意数量的 MCP 服务器和内置服务器。为每个 agent 提供一个只包含其所需工具的工具包，可以让它的工具列表保持简短，工具选择也更准确。

工具包负责筛选某个端点对外暴露哪些工具。它不控制调用方可以调用哪些工具：同一个调用方仍可通过 [me 工具包](#use-the-me-kit)访问其可用的所有工具。要限制调用方能做什么，请使用权限和[策略](/langsmith/tool-gateway-policies)。请参阅[工具包负责筛选，策略负责执行](/langsmith/tool-gateway-how-it-works#tool-kits-curate-policies-enforce)。

## 创建工具包

工具包从已[添加](/langsmith/tool-gateway-servers)的服务器中选择工具。管理工具包需要用户凭证，例如个人访问令牌。服务密钥可以调用工具包中的工具，但不能创建、更改或删除工具包。

### 选择范围

每个工具包都有一个范围。范围在创建工具包时选定，之后无法更改：

- **Workspace**：工作区中的所有人都可以查看和使用该工具包。它可以包含工作区服务器和内置服务器，但不能包含个人服务器。Workspace Admin 可以创建工作区工具包。
- **Personal**：只有你可以查看、使用、更改或删除该工具包。它还可以包含你的个人服务器。Workspace Admin 和 Workspace Editor 可以创建个人工具包。

如果工作区工具包包含个人服务器的工具，则返回 `400`。要同时使用个人工具和工作区工具，请创建个人工具包。

### 选择工具

<Tabs>
  <Tab title="UI">
    1. 进入 **Tools** > **Tool kits**，然后点击 **Create tool kit**。
    1. 输入 **Tool kit name**，并可选填描述。
    1. 选择 **Workspace** 或 **Personal**，以确定谁可以使用该工具包。
    1. 在工具选择器中，选择要包含的工具。按服务器筛选可以更快找到工具。
    1. 点击 **Review tool selection**。（可选）为任意工具输入 **Custom label**，或移除误选的工具。
    1. 点击 **Create tool kit**。

    该工具包的面板会以 agent 调用时使用的名称列出其工具，并显示该工具包的 MCP URL。
  </Tab>
  <Tab title="API">
    发送 `POST /v1/managed-tools/kits`，携带 `name` 和 `tools` 数组。每个条目指定一个服务器上的一个工具。对于你添加的服务器，设置 `server_id`；对于内置服务器，设置 `builtin_server_key`。将 `tool_name` 设为该工具在该服务器上的名称。本页的 API 示例使用[快速入门](/langsmith/tool-gateway-quickstart)中的环境变量。

    ```bash
    curl -sS -X POST "$LANGSMITH_ENDPOINT/v1/managed-tools/kits" \
      -H "X-Api-Key: $LANGSMITH_API_KEY" \
      -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "Support agent tools",
        "description": "Tools for the support agent",
        "scope": "workspace",
        "tools": [
          {"server_id": "<server-id>", "tool_name": "<tool-name>"},
          {"builtin_server_key": "<built-in-key>", "tool_name": "<tool-name>"}
        ]
      }'
    ```

    响应中包含该工具包的 `id`、其 `mcp_path`，以及每个工具的 `mcp_name`（即 agent 调用时使用的名称）。`scope` 默认为 `workspace`。要为工具设置显示标签，请在其条目中添加 `exposed_name`。

    LangSmith 会检查每个服务器是否存在，但不会检查每个工具名称是否存在于该服务器上。请完全按照服务器列出的内容复制工具名称。
  </Tab>
</Tabs>

工具包名称必须在工作区中唯一。创建工具包时需包含 1 到 10,000 个工具。更新时可以将其留空。

要将 agent 或 MCP 客户端连接到工具包的 URL，请参阅[连接 MCP 客户端](/langsmith/tool-gateway-clients)。

## 工具包中工具的命名方式

Tool Gateway 会为工具包中的每个工具加上前缀命名，这样来自不同服务器的工具就不会冲突：

- **你添加的服务器**：`<server>_<tool>`，其中 `<server>` 是服务器名称的小写形式，每一段非字母和数字的连续字符都替换为一个下划线。例如，名为 `Linear` 的服务器上的 `list_issues` 会变成 `linear_list_issues`。
- **内置服务器**：`langsmith_<key>_<tool>`，其中 `<key>` 是内置服务器的 key。

Tool Gateway 会在你首次将工具添加到工具包时设置其名称。之后重命名服务器不会改变该名称，因此已在调用该工具的 agent 可以继续正常工作。

工具包中的两个工具最终可能同名，例如两个服务器的名称仅在标点上不同。创建或保存这样的工具包会返回 `400`。请重命名其中一个服务器，然后重试。

自定义标签（API 中的 `exposed_name`）会更改客户端为该工具显示的标题，但不会更改 agent 调用时使用的名称。

## 调用方在连接前会看到什么

工具包会向每个调用方列出其所有工具，包括调用方尚未连接的服务器上的工具。调用其中某个工具时，会要求调用方连接该服务器，然后由调用方重试调用。使用 agent 身份或 profile 的调用方无法连接，因此在管理员连接凭证之前，其调用会失败。请参阅[调用工具](/langsmith/tool-gateway-call-tools)。

Tool Gateway 可以向尚未连接某个服务器的调用方列出该服务器的工具。当有人保存或刷新工具包时，Tool Gateway 会存储通过该人的连接获取到的工具列表。如果保存或刷新该工具包的人都没有连接某个服务器，工具包就会改为为该服务器列出一个名为 `connect_<server>` 的占位工具。调用该占位工具会要求调用方进行连接。

## 刷新工具包中的工具

Tool Gateway 会将每个服务器的工具列表缓存两小时。当服务器添加、移除或更改工具时，刷新工具包可以更快地获取这些变更。刷新还会更新未连接调用方所看到的已存储工具列表。

刷新需要更新该工具包的权限。

- **UI**：在 **Tools** > **Tool kits** 上，打开该工具包，然后点击 **Refresh tools**。
- **API**：

    ```bash
    curl -sS -X POST "$LANGSMITH_ENDPOINT/v1/managed-tools/kits/<kit-id>/tool-refresh" \
      -H "X-Api-Key: $LANGSMITH_API_KEY" \
      -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID"
    ```

    响应中的 `missing_credentials` 会列出你尚未连接的服务器。它们的工具列表不会被刷新。请连接这些服务器，然后再次刷新。

服务器不再列出的工具会保留在工具包的选择中，但不再向调用方列出。要移除它，请[更新工具包](#update-a-tool-kit)。

## 使用 me 工具包

me 工具包位于 `/v1/managed-tools/kits/me/mcp`，提供调用方可使用的所有工具。这包括调用方可以调用的工作区服务器、调用方自己的个人服务器，以及所有已启用的内置服务器。你无需创建它。Tool Gateway 在每次请求时构建它，从不保存。

如果你想为自己的 MCP 客户端提供你可用的所有工具，又不想精心筛选工具包，可以使用 me 工具包。对于 agent，建议使用只包含该 agent 所需工具的已保存工具包。

me 工具包与已保存工具包的区别如下：

- 调用方尚未连接的服务器始终会列为一个 `connect_<server>` 工具，而不是列出其各个工具。
- 当调用方的两个服务器同名时，它们的工具会命名为 `<server>_<id>_<tool>`，其中 `<id>` 是服务器 ID 的末尾部分。
- 由于它可能提供大量工具，可以考虑使用搜索模式，该模式会列出三个工具，用于搜索并调用其余工具。请参阅[连接 MCP 客户端](/langsmith/tool-gateway-clients)。

## 更新工具包

你可以更改工具包的名称、描述和工具，但无法更改其范围。

- **UI**：在 **Tools** > **Tool kits** 上，打开该工具包，然后点击 **Edit**。更改详细信息或工具选择，然后点击 **Save changes**。
- **API**：发送 `PATCH /v1/managed-tools/kits/<kit-id>`，仅携带要更改的字段：

    ```bash
    curl -sS -X PATCH "$LANGSMITH_ENDPOINT/v1/managed-tools/kits/<kit-id>" \
      -H "X-Api-Key: $LANGSMITH_API_KEY" \
      -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID" \
      -H "Content-Type: application/json" \
      -d '{
        "tools": [
          {"server_id": "<server-id>", "tool_name": "<tool-name>"}
        ]
      }'
    ```

    `tools` 会替换工具包的整个选择。请包含工具包应保留的每个工具。空数组会移除所有工具。

要查找工具包的 ID，可以在 UI 中从工具包的 MCP URL 中复制，或使用 `GET /v1/managed-tools/kits` 列出工具包。添加 `?scope=workspace` 或 `?scope=personal` 可以只列出某一个范围。

## 删除工具包

删除工具包会移除其 MCP URL。它使用的服务器和所有已连接的账户都保持不变。使用该工具包 URL 的 agent 和客户端将停止工作。

- **UI**：在 **Tools** > **Tool kits** 上，打开该工具包，点击 **Delete**，然后确认。
- **API**：

    ```bash
    curl -sS -X DELETE "$LANGSMITH_ENDPOINT/v1/managed-tools/kits/<kit-id>" \
      -H "X-Api-Key: $LANGSMITH_API_KEY" \
      -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID"
    ```

    该请求返回 `204`，即使工具包已被删除也是如此。

删除工作区工具包需要删除 MCP 服务器的权限。只有所有者可以删除个人工具包。
