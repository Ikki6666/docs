## Observability

### *我无法在 UI 中创建 API 密钥或管理用户，这是为什么？*

* 你很可能是在没有配置 SSO 的情况下部署了 LangSmith。LangSmith 需要配置 SSO 才能管理用户和 API 密钥。关于如何设置 SSO，请参见[配置部分](/langsmith/self-host-sso)。

### *负载均衡或 ingress 是怎么工作的？*

* 你需要把 frontend 容器或服务暴露给你的应用或用户。它会负责把请求路由到下游各个服务。
* 你需要在 ingress 层终止 SSL。建议使用 AWS ALB、GCP Load Balancer 或 Nginx 之类的托管服务。

### *如何对应用做认证？*

* 当前，自托管方案支持使用 OAuth2.0 和 OIDC 的 SSO 作为认证方案。注意，我们也提供无认证方案，但强烈建议在进入生产环境前先配置 OAuth。

关于如何设置 SSO，请参见[配置部分](/langsmith/self-host-sso)。

### *可以使用外部存储服务吗？*

* 你可以把 LangSmith 配置为使用所有存储服务的外部版本。在生产环境中，强烈建议使用外部存储服务。更多信息请参见[配置部分](/langsmith/self-hosted)。

### *应用要正常工作，是否需要出站网络（egress）？*

我们的部署只需要为少数场景提供 egress，其中大多数都可以放在你的 VPC 内部：

* 拉取镜像（如果你已经镜像同步，这项可能不需要）

* 访问任意 LLM endpoint

* 访问你配置的外部存储服务

* 拉取 OAuth 信息

* 订阅指标和运维元数据（如果不是 offline mode）

  * 需要放行到 `https://beacon.langchain.com` 的 egress
  * 更多信息请参见 [Egress](/langsmith/self-host-egress)

你的 VPC 可以通过规则限制其他访问。另请注意，后端服务必须允许透传 `X-Organization-Id` 和 `X-Tenant-Id` 请求头。它们用于判断请求对应哪个组织和工作区（旧称 tenant）。

### *应用的资源要求是什么？*

* 在 kubernetes 中，建议至少采用 [medium size 示例](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/examples/medium_size.yaml) 中的 Helm 配置。对于 Docker，建议最低配为 16GB 内存和 4 个 CPU。
* 对于 Postgres，建议至少 8GB 内存和 2 个 CPU。
* 对于 Redis，建议 4GB 内存和 2 个 CPU。
* 对于 Clickhouse，建议 32GB 内存和 8 个 CPU。

### SAML SSO FAQ

#### *如何修改 SAML SSO 用户的邮箱地址？*

有些身份提供方在邮箱变更后仍会保留原始 `User ID`，有些则不会。为避免在 LangSmith 中产生重复用户，建议按以下步骤操作：

1. 将该用户从组织中移除（参见[管理用户](/langsmith/set-up-hierarchy#manage-users)）
2. 在 IdP 中修改其邮箱地址
3. 让用户再次通过 SAML SSO 登录 LangSmith，这会触发常规的 [JIT provisioning](/langsmith/user-management#just-in-time-jit-provisioning) 流程，并使用新邮箱地址

对于具有多个已关联登录方式的用户，目前不支持通过 SCIM 或其他方式修改邮箱地址。此时会显示错误信息：`email update not supported with linked login methods`。例如，用户此前已经通过邮箱/密码或 Google 社交登录登录过，之后又用同一邮箱通过 SSO 加入，那么该用户将不支持修改邮箱地址。这个限制同时适用于自托管和云端。

#### *可以切换身份提供方吗？*

请通过 [https://support.langchain.com](https://support.langchain.com) 联系 LangChain 支持团队，获取迁移支持。

#### *如何解决 “405 method not allowed”？*

请确认你使用的是正确的 ACS URL：[https://auth.langchain.com/auth/v1/sso/saml/acs](https://auth.langchain.com/auth/v1/sso/saml/acs)

### SCIM FAQ

#### *没有 SAML SSO 也能使用 SCIM 吗？*

* **Cloud**：不能，云端部署中的 SCIM 依赖 SAML SSO
* **Self-hosted**：可以，SCIM 可与使用 Client Secret 认证模式的 OAuth 一起使用

#### *如果同时启用了 JIT provisioning 和 SCIM，会发生什么？*

JIT provisioning 和 SCIM 可能会彼此冲突。建议在启用 SCIM 前先关闭 JIT provisioning，以保证用户开通行为一致。

#### *如何修改用户的角色或工作区访问权限？*

请在你的 IdP 中更新用户所属的组。变更会按照[角色优先级规则](/langsmith/user-management#role-precedence)同步到 LangSmith。

#### *当用户被移出所有组时会怎样？*

该用户会按照 IdP 的去配置规则，从你的 LangSmith 组织中被去开通（deprovision）。

#### *可以使用自定义组名吗？*

可以。如果你的身份提供方支持把备用字段同步到 `displayName` 组属性，你可以在 LangSmith 中把备用属性（例如 `description`）用作 `displayName`，从而保留对 IdP 组名的完全自定义能力。否则，组名必须遵循[组命名约定](/langsmith/user-management#group-naming-convention)中的命名规则，才能正确映射到 LangSmith 角色和工作区。

你也可以[配置自定义分隔符](/langsmith/user-management#configure-custom-separator)，例如 `-`、`_` 或 `&`，以替代默认的冒号（`:`），从而适配对组名字符有限制的身份提供方。

#### _为什么我的 Okta 集成无法正常工作？_

请参见 Okta 的故障排查指南：https://help.okta.com/en-us/content/topics/users-groups-profiles/usgp-group-push-troubleshoot.htm。

### *支持降级吗？*

官方不支持降级。LangSmith 升级可能包含数据库迁移以及其他不向后兼容的改动。如果你需要回滚到旧版本，请通过[支持门户](https://support.langchain.com)联系技术支持，以获取指导。

## Deployment

### 使用 LangGraph 一定要用 LangChain 吗？两者有什么区别？

不需要。LangGraph 是一个面向复杂 agent 系统的编排框架，粒度更低、可控性更强；LangChain 提供与模型和其他组件交互的标准接口，更适合相对直接的 chain 和检索流程。

### LangGraph 和其他 agent 框架有什么不同？

其他 agent 框架在简单、通用的任务上可能足够，但在适配公司独特需求的复杂任务上往往不够。LangGraph 提供了更有表达力的框架，可以处理企业特有任务，而不会把用户限制在某一种黑盒式认知架构中。

### LangGraph 会影响我的应用性能吗？

LangGraph 不会给你的代码引入额外开销，并且它在设计上就特别适合流式工作流。

### LangGraph 是开源的吗？免费吗？

是。LangGraph 是采用 MIT 许可证的开源库，可以免费使用。

### LangGraph 和 LangSmith 有什么不同？

LangGraph 是一个有状态的编排框架，为 agent 工作流带来更强控制力。LangSmith 则是一个用于部署和扩展 agent 应用的服务，提供了一套有观点的 API 来构建 agent UX，并内置开发者 UI。

| Features | LangGraph (open source) | LangSmith |
| --- | --- | --- |
| Description | 用于 agent 应用的有状态编排框架 | 用于部署 LangGraph 应用的可扩展基础设施 |
| SDKs | Python 和 JavaScript | Python 和 JavaScript |
| HTTP APIs | 无 | 有，可用于获取和更新状态或长期记忆，也可用于创建可配置 assistant |
| Streaming | 基础支持 | 提供逐 token 消息流的专用模式 |
| Checkpointer | 社区贡献 | 开箱即用 |
| Persistence Layer | 自行管理 | 托管 Postgres，具备高效存储 |
| Deployment | 自行管理 | • Cloud <br /> • 免费自托管 <br /> • Enterprise（付费自托管） |
| Scalability | 自行管理 | 任务队列和服务自动扩缩容 |
| Fault-tolerance | 自行管理 | 自动重试 |
| Concurrency Control | 简单线程化 | 支持 double-texting |
| Scheduling | 无 | Cron 调度 |
| Monitoring | 无 | 与 LangSmith 集成，提供 observability |
| IDE integration | Studio | Studio |

### LangSmith 是开源的吗？

不是。LangSmith 是专有软件。

更多信息请参见 [LangSmith 定价页](https://www.langchain.com/pricing)。

### 对于不支持 tool calling 的 LLM，LangGraph 也能工作吗？

可以。你可以把 LangGraph 与任何 LLM 一起使用。我们常用支持 tool calling 的 LLM，主要是因为它们更方便让模型自行决定下一步做什么。如果你的 LLM 不支持 tool calling，依然可以使用，只是你需要补一些逻辑，把原始字符串响应转换成下一步动作的决策。

### LangGraph 支持 OSS LLM 吗？

支持。LangGraph 对底层使用什么 LLM 完全没有偏向。我们在大多数教程中使用闭源 LLM，主要是因为它们对 tool calling 的支持更顺滑，而 OSS LLM 通常没有。但 tool calling 并不是必须的，参见[对于不支持 tool calling 的 LLM，LangGraph 也能工作吗？](#对于不支持-tool-calling-的-llmlanggraph-也能工作吗)，因此你完全可以把 LangGraph 与 OSS LLM 一起使用。

### 不登录 LangSmith 也能使用 Studio 吗？

可以。你可以使用 [Agent Server 的开发版](/langsmith/local-dev-testing)在本地运行后端。
这样会连接到作为 LangSmith 一部分托管的 Studio 前端。
如果你设置环境变量 `LANGSMITH_TRACING=false`，则不会向 LangSmith 发送 trace。

### 什么是 Deployment Run？

Deployment Run 是指一次通过 LangSmith Deployment 部署的 LangGraph agent 的端到端调用。节点和子图不会被单独计费。对其他 LangGraph agent 的调用（无论是通过 RemoteGraph、LangGraph SDK，还是直接通过 API）会单独计费到被调用 agent 所在的部署。对于 human-in-the-loop 中断，恢复执行时会创建一个新的 Deployment Run。
