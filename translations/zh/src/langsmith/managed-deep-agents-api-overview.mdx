Managed Deep Agents API 用于创建、更新、连接和调用 [Managed Deep Agents](/langsmith/managed-deep-agents-overview)。对于 Python、TypeScript 和 React 应用，请优先使用 [Managed Deep Agents SDKs](/langsmith/managed-deep-agents-sdk)。当你需要直接控制请求 payload 时，再使用 REST API。推荐的端到端工作流请参见 [quickstart](/langsmith/managed-deep-agents-quickstart)。

<Note>
Managed Deep Agents 目前处于 **private beta**，仅在美国区域的 [LangSmith Cloud](/langsmith/cloud) 提供。[加入候补名单](https://www.langchain.com/langsmith-managed-deep-agents-waitlist)以申请访问权限。
</Note>

## 设置请求默认值

API 使用 `/v1/deepagents`：

```bash
export LANGSMITH_API_KEY="<LANGSMITH_API_KEY>"
export LANGSMITH_API_URL="https://api.smith.langchain.com"
export DEEPAGENTS_BASE_URL="$LANGSMITH_API_URL/v1/deepagents"
```

请求需要携带 `X-Api-Key` header：

```txt
X-Api-Key: <LANGSMITH_API_KEY>
```

例如，在上面这些基础 URL 和 header 设置好后，可以这样列出 agents：

```bash
curl "$DEEPAGENTS_BASE_URL/agents" \
  -H "X-Api-Key: $LANGSMITH_API_KEY"
```

缺少 `X-Api-Key` header 时会返回 `401` 和 `{"error": "Unauthorized"}`。如果 key 无效，或没有对应 workspace 的访问权限，则会返回 `403` 和 `{"error": "Forbidden"}`。这类鉴权响应使用扁平的 `{"error": "..."}` body，不同于其他 `4xx` 响应返回的结构化错误体。如果 key 本身有效，但其角色缺少所需权限，也会返回 `403`，不过 body 会是纯文本并指出缺失的权限名，例如 `missing permission mcp-servers:create`，SDK 会把它暴露在 `error.body` 中。

## 了解资源分组

| Resource group | Purpose |
| --- | --- |
| Agents | 创建和管理 Managed Deep Agent 资源，包括 runtime 和 backend 配置。 |
| Threads | 创建和管理 Managed Deep Agents 的持久线程状态。 |
| Runs | 在 threads 上启动和流式传输 Managed Deep Agent runs。 |
| MCP servers | 注册 MCP servers，并保存 agent tools 引用的凭据。 |
| MCP tools | 列出某个已注册 MCP server 暴露的 tools，供客户端构建 `tools.json` 条目。 |
| Auth sessions | 为 OAuth 类型的 MCP servers 启动并轮询用户 OAuth 会话。 |

Managed Deep Agents 不是 LangSmith Deployments。创建一个 Managed Deep Agent 时，会同时创建一个 Managed Deep Agent 资源、一个独立的 LangSmith tracing project，以及一个用于托管文件树的 Context Hub agent repo。

## 配置 sandboxes

创建 agent 和更新 agent 的 payload 都可以包含 `backend` 对象。当 agent 不需要与 sandbox 相关的 backend 行为时，使用 `state`：

```json
{
  "backend": {
    "type": "state"
  }
}
```

当 agent 需要使用 [LangSmith sandbox](/langsmith/sandboxes) 来执行代码、处理文件系统操作，或运行长时间任务时，使用 `sandbox`。Sandbox backend 的配置放在 `backend.sandbox_config` 下，并且只有在 `backend.type` 为 `sandbox` 时才有效：

```json
{
  "backend": {
    "type": "sandbox",
    "sandbox_config": {
      "scope": "thread",
      "policy_ids": ["policy-id"],
      "idle_ttl_seconds": 900,
      "delete_after_stop_seconds": 300
    }
  }
}
```

`sandbox` 对象支持以下字段：

| Field | Description |
| --- | --- |
| `scope` | Sandbox 作用域。`thread` 表示每个 thread 一个 sandbox，`agent` 表示整个 agent 共享一个 sandbox。 |
| `policy_ids` | 要应用的 sandbox policy IDs。 |
| `idle_ttl_seconds` | sandbox 空闲多久后停止，单位为秒。 |
| `delete_after_stop_seconds` | sandbox 停止后，延迟多久删除，单位为秒。 |

关于 backend 的选择建议，请参见 [Deploy an agent](/langsmith/managed-deep-agents-deploy#choose-a-backend)。关于独立的 sandbox 概念，请参见 [LangSmith sandboxes overview](/langsmith/sandboxes)。

## 为 agents 列表分页

[`GET /v1/deepagents/agents`](/langsmith/managed-deep-agents-api/agents/list-agents) 使用 cursor 分页。你可以传入 `page_size`（默认 `20`，最大 `100`）以及前一页响应返回的 opaque `cursor`。响应会把结果放在 `items` 数组中，并通过 `next_cursor` 字段指向下一页；最后一页时该字段为 `null`：

```json
{
  "items": [],
  "next_cursor": null
}
```

这个 endpoint 还支持 `name`（按名称子串过滤）、`sort_by`（`created_at`、`updated_at` 或 `name`，默认 `updated_at`）以及 `sort_order`（`asc` 或 `desc`，默认 `desc`）。

## 理解 API 稳定性

路由按 `/v1/` 进行版本管理，但整个接口面目前仍处于 private beta，在正式 GA 前，可能会发生不向后兼容的变更。关于 breaking change 的沟通方式，请参见 [API stability](/langsmith/managed-deep-agents-overview#api-stability)。

这个 API 并不会镜像 LangSmith Deployment 的所有 endpoint。像 integrations、triggers、skills、sandboxes、auth providers 和 auth tokens 这些 endpoint groups 都不会被镜像。
