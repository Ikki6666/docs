`@langchain/langsmith-opencode` 插件会把 [OpenCode](https://opencode.ai/) 会话 traces 发送到 LangSmith。你可以用它来检查 OpenCode 工作流中的智能体回合、模型 metadata、token 用量、工具调用、工具错误、附件和 subagent 活动。

## 前提条件

在设置 tracing 之前，确保你已具备：

- 已安装并配置 [OpenCode](https://opencode.ai/)。
- 一个 [LangSmith API key](/langsmith/create-account-api-key)。
- 可配置 `opencode.json` 或 `~/.config/opencode/opencode.json` 中 `plugin` key 的权限。

## 安装并启用插件

将插件添加到你的 OpenCode 配置文件中。你可以在 `opencode.json` 中进行本地配置，或在 `~/.config/opencode/opencode.json` 中进行全局配置：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@langchain/langsmith-opencode"]
}
```

在启动 OpenCode 之前启用 tracing，并提供你的 LangSmith API key：

```bash
export TRACE_TO_LANGSMITH="true"
export LANGSMITH_API_KEY="<your-langsmith-api-key>"
export LANGSMITH_PROJECT="opencode"
```

像平常一样运行 OpenCode。该插件会把已完成的用户回合发送到配置好的 LangSmith project。

## 配置 tracing

Tracing 默认是关闭的。设置 `TRACE_TO_LANGSMITH=true` 后，插件会将 traces 发送到 LangSmith。你也可以通过 LangSmith 配置文件启用 tracing。

### 环境变量

插件会优先读取 OpenCode 专用变量，然后在可用时回退到通用的 LangSmith SDK 变量。

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `TRACE_TO_LANGSMITH` | Yes | `false` | 设置为 `"true"` 以启用 tracing。 |
| `LANGSMITH_OPENCODE_API_KEY` | Conditional | - | LangSmith API key。回退到 `LANGSMITH_API_KEY`。除非每个 replica 都提供自己的 API key，否则该项必填。 |
| `LANGSMITH_OPENCODE_ENDPOINT` | No | LangSmith SDK default | LangSmith API URL。回退到 `LANGSMITH_ENDPOINT`。 |
| `LANGSMITH_OPENCODE_PROJECT` | No | `opencode` | LangSmith project 名称。回退到 `LANGSMITH_PROJECT`。 |
| `LANGSMITH_OPENCODE_METADATA` | No | - | 合并到根 trace metadata 的 JSON 对象。 |
| `LANGSMITH_OPENCODE_RUNS_ENDPOINTS` | No | - | replica 目标的 JSON 数组。 |

例如：

```bash
export TRACE_TO_LANGSMITH="true"
export LANGSMITH_API_KEY="<your-langsmith-api-key>"
export LANGSMITH_PROJECT="opencode"
export LANGSMITH_OPENCODE_METADATA='{"team":"agents","environment":"dev"}'
```

### 配置文件

使用 `.opencode/langsmith.json` 作为项目级设置，或使用 `~/.config/opencode/langsmith.json` 作为全局默认值。

```json
{
  "enabled": true,
  "api_key": "<your-langsmith-api-key>",
  "api_url": "https://api.smith.langchain.com",
  "project": "opencode",
  "metadata": {
    "team": "agents",
    "environment": "dev"
  }
}
```

| Field | Required | Default | Description |
| --- | --- | --- | --- |
| `enabled` | Yes | `false` | 设置为 `true` 后，可从配置文件启用 tracing。 |
| `api_key` | Conditional | - | LangSmith API key。除非通过环境变量或 replicas 提供，否则该项必填。 |
| `api_url` | No | LangSmith SDK default | LangSmith API URL，通常为 `https://api.smith.langchain.com`。 |
| `project` | No | `opencode` | LangSmith project 名称。 |
| `metadata` | No | - | 合并到根 trace metadata 的对象。 |
| `replicas` | No | - | 额外的 LangSmith 目标，用于复制 traces。 |

包含 API keys 的配置文件不要纳入版本控制。

## 跟踪到多个目标

在 `langsmith.json` 或 `LANGSMITH_OPENCODE_RUNS_ENDPOINTS` 中设置 `replicas`，即可将同一份 trace 数据发送到额外的 LangSmith workspace 或 project。

```json
{
  "enabled": true,
  "api_key": "<your-langsmith-api-key>",
  "project": "opencode",
  "replicas": [
    {
      "api_url": "https://api.smith.langchain.com",
      "api_key": "<your-replica-langsmith-api-key>",
      "project": "opencode-replica",
      "updates": {
        "metadata": {
          "replica": true
        }
      }
    }
  ]
}
```

Replica 对象同时支持 snake_case 和 LangSmith SDK 风格的 camelCase 字段名。在配置文件中建议使用 snake_case。

| Field | Description |
| --- | --- |
| `api_url` / `apiUrl` | replica 目标的 LangSmith API URL。 |
| `api_key` / `apiKey` | 目标 workspace 的 API key。 |
| `project` / `projectName` | 目标 workspace 中的 project 名称。 |
| `updates` | 可选的 run 字段覆盖项，例如附加 metadata。 |

## 会跟踪哪些内容

插件会监听 OpenCode 的 chat 和 event hooks，将每个已完成的用户回合聚合后，以 run tree 的形式提交到 LangSmith。

- 已完成用户回合的 `opencode.session` root runs。
- 用于 assistant 和模型响应的 `opencode.assistant.turn` 子 runs。
- 工具调用对应的嵌套工具 runs，包括输入、输出、错误、耗时，以及在可用时的附件。
- 嵌套在父工具调用下的 subagent sessions。
- 模型名称、provider、调用参数、token 用量，以及 thread 或 session ID metadata。
- 与 assistant 回合相关联的用户消息、assistant 消息、reasoning blocks、file parts 和 system prompts。

Trace 的完成判定基于 OpenCode 的 `step-finish` 事件。插件也会在 OpenCode server 关闭时刷新仍处于待发送状态的 trace 批次。

## 在 LangSmith 中查看 traces

打开配置好的 LangSmith project，并查找名为 `opencode.session` 的 root runs。每条 trace 都以用户回合作为根输入，其下包含 assistant 响应、工具调用和 subagent traces 作为子 runs。插件会把 OpenCode session ID 存成 `thread_id` metadata，因此你可以在 LangSmith 中基于它对相关 OpenCode 回合进行筛选或分组。

## 故障排查

如果 traces 没有出现在 LangSmith 中：

- 确认已通过 `TRACE_TO_LANGSMITH=true` 或配置中的 `"enabled": true` 启用 tracing。
- 确认 LangSmith API key 已在 OpenCode 实际使用的同一个 shell、项目配置或全局配置中设置。
- 确认插件包安装在 OpenCode 可以解析到的位置。
- 检查当前选择的 LangSmith project。如果没有配置 project，traces 会发送到 `opencode`。
- 修改 `opencode.json`、`langsmith.json` 或环境变量后，重启 OpenCode。
- 确保至少有一个用户回合已完成。插件不会发送未完成的回合。
