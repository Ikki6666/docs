本指南介绍当数据到达 LangSmith Cloud 服务器之后，你可以使用的各种能力，以帮助你满足自己的隐私目标。

## 数据保留

LangSmith 提供自动化的数据保留能力，以帮助你满足合规要求并管理存储。数据保留策略可以在两个层级配置：

- **工作区级别：** 拥有相应权限的 Enterprise 客户可以把 extended retention 设为工作区默认值，并自定义保留时长（最长 400 天）。详见[自定义 extended retention 策略](#customize-extended-retention-policy)。
- **项目级别：** 拥有相应权限的客户可以为每个 tracing project 设置默认保留层级，可在 base（14 天）和 extended retention（400 天）之间选择。详见[修改项目级默认保留策略](/langsmith/billing#change-project-level-default-retention)。

关于数据保留配置与管理的详细信息，请参见[数据保留概念](/langsmith/usage-and-billing#data-retention)文档。

## 自定义 extended retention 策略

<Note>
此功能适用于 [Enterprise](/langsmith/pricing-plans) 方案客户。对于[self-hosted](/langsmith/self-hosted) Enterprise 客户，请参见[自托管工作区级配置](#workspace-level-extended-retention-for-self-hosted)部分。
</Note>

[Enterprise](/langsmith/pricing-plans) 客户可以在[工作区](/langsmith/administration-overview#workspaces)级别自定义 traces 的 extended data retention 周期，以满足特定合规要求。默认 extended retention 为 400 天，但你可以根据组织需要进行调整。保留期的更改仅适用于新的 traces。

<Note>
保留期的变更只作用于新的 traces。已有 traces 不受影响。
</Note>

### 配置 extended retention

Organization Admin 和 Operator（`organization:manage`）可以为任意工作区配置 retention。Workspace Admin（`workspaces:manage`）则可以配置自己的工作区。完整权限参考请参见[组织与工作区操作](/langsmith/organization-workspace-operations)。

<Tabs>
  <Tab title="UI">
    在 [LangSmith UI](https://smith.langchain.com) 中：

    1. 前往页面底部的 **Settings**。
    1. 从左侧菜单中选择 **Usage configuration**。
    1. 在列表中找到你想配置的工作区。
    1. 点击该工作区 **Data retention policy** 列下的值。
    1. 在 **workspace usage configurations** 弹窗中，使用 **Extended - All traces are retained for** 下拉框自定义 extended policy。可选时长包括：30d、60d、90d、120d、150d、180d、240d、300d、365d 和 400d。
    1. 选择 **Save**。
  </Tab>
  <Tab title="API">
    读取当前设置：

    **组织级**（`organization:manage`）

    ```bash
    curl -X GET "https://api.smith.langchain.com/api/v1/orgs/ttl-settings" \
      -H "x-api-key: YOUR_API_KEY"
    ```

    **工作区级**（`workspaces:manage`）

    ```bash
    curl -X GET "https://api.smith.langchain.com/api/v1/ttl-settings" \
      -H "x-api-key: YOUR_API_KEY"
    ```

    更新保留期时，请把 `resource_type` 设为 `"run"`，并把 `ttl_days` 设为期望时长。可选值包括：30、60、90、120、150、180、240、300、365 和 400 天。

    **组织级**（`organization:manage`）

    ```bash
    curl -X PUT "https://api.smith.langchain.com/api/v1/orgs/ttl-settings" \
      -H "x-api-key: YOUR_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"resource_type": "run", "ttl_days": 90}'
    ```

    **工作区级**（`workspaces:manage`）

    ```bash
    curl -X PUT "https://api.smith.langchain.com/api/v1/ttl-settings" \
      -H "x-api-key: YOUR_API_KEY" \

      -d '{"resource_type": "run", "ttl_days": 90}'
    ```

### 自托管下的工作区级 extended retention

self-hosted [Enterprise](/langsmith/pricing-plans) 客户也可以使用工作区级 extended retention 配置，而不是系统级 TTL 设置。这样你就可以在不同工作区之间实现更细粒度的数据保留控制，而不必依赖环境变量变更。

<Warning>
如果你使用 blob storage，那么**必须**为每个自定义保留周期添加一条 lifecycle rule。例如，把某个工作区设置为 90 天保留，意味着 blob 数据会写入 `ttl_90d/` 前缀，而要想自动清理，就必须为这个前缀配置匹配的 lifecycle rule。详情和示例请参见 [blob storage TTL 配置](/langsmith/self-host-blob-storage#custom-workspace-level-retention-prefixes)。
</Warning>

若要在自托管部署中配置此能力，请参见 [self-hosted TTL 文档](/langsmith/self-host-ttl) 了解旧版系统级方案，或联系 [support](https://support.langchain.com)。

## Trace 删除

你可以使用 API 来执行 trace 删除。该 API 支持两种删除 trace 的方式：

1. **按 trace IDs 和 session ID 删除：** 传入一组 trace IDs 及其对应的 session ID，删除特定 traces（每次请求最多 1000 条）
2. **按 metadata 删除：** 删除工作区中匹配指定 metadata key-value 对的 traces

更多细节请参见 [API spec](/langsmith/smith-api/run/delete-runs)。

<Warning>
所有 trace 删除操作都会删除相关实体，例如 feedbacks、aggregations 和各数据存储中的 stats。
</Warning>

### 删除时间线

Trace 删除会在非高峰时段处理，并不是即时完成。LangChain 会在周末运行删除任务。系统不会给出删除确认，你需要重新查询数据，以验证其是否已经被移除。

### 删除特定 traces

若要通过 trace IDs 删除同一 session 中的特定 traces：

<Note>
这里的 `session_id` 指的就是该 trace 所属项目的项目 ID。你可以在 LangSmith UI 的 tracing project 页面中找到它。
</Note>

```bash
curl -X POST "https://api.smith.langchain.com/api/v1/runs/delete" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "trace_ids": ["trace-id-1", "trace-id-2", "trace-id-3"],
    "session_id": "session-id-1"
  }'
```

## Example 删除

你可以通过 API 自助删除 dataset examples。该接口同时支持 soft delete 和 hard delete，两者适用于不同的数据保留需求。

<Warning>
Hard delete 会把指定 examples 在整个 dataset 历史中、所有版本里的 inputs、outputs 和 metadata 永久移除。
</Warning>

### 删除 examples 是一个两步过程

对于批量操作，example 删除采用两步流程：

#### 1. 通过 metadata 搜索 examples

在工作区的所有 datasets 中，查找 metadata 匹配的 examples。

[GET /examples](/langsmith/smith-api/examples/read-examples)

- `as_of` 必须显式指定为一个时间戳。只有在该 `as_of` 时间点之前创建的 examples 才会被返回

```bash
curl -X GET "https://api.smith.langchain.com/api/v1/examples?as_of=2024-01-01T00:00:00Z" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "metadata": {
      "user_id": "user123",
      "environment": "staging"
    }
  }'
```

这个请求会返回你工作区中所有 datasets 里，metadata 中带有 `user_id: "user123"` **或** `environment: "staging"` 的 examples。

#### 2. Hard delete examples

拿到 example IDs 后，再发送删除请求。这会把这些 examples 在所有 dataset 版本中的 inputs、outputs 和 metadata 清空。

[POST /v1/platform/datasets/examples/delete/](/langsmith/smith-api/examples/hard-delete-examples)

- 在请求体中指定 `example_ids`（example ID 列表）和 `hard_delete`（布尔值）

```bash
curl -X POST "https://api.smith.langchain.com/v1/platform/datasets/examples/delete/" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "example_ids": ["example-id-1", "example-id-2", "example-id-3"],
    "hard_delete": true
  }'
```

### 删除类型

#### Soft delete（默认）

- 会在 dataset 中创建已 tombstone 化的记录，并把 inputs/outputs 设为 NULL
- 保留历史数据，并维持 dataset versioning
- 只影响 dataset 的当前版本

#### Hard delete

- 会从**所有** dataset 版本中永久移除 inputs、outputs 和 metadata
- 当合规要求对所有版本都执行彻底清零时，应使用它
- 在请求体中设置 `"hard_delete": true`
