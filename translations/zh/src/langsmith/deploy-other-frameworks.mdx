LangSmith Deployment 支持运行任意框架。对于不是基于 Deep Agents、LangChain 或 LangGraph 构建的 agents，可以使用 [`deployments-wrap-sdk`](https://pypi.org/project/deployments-wrap-sdk/) 包（Google ADK），或使用 [LangGraph Functional API](/oss/langgraph/functional-api)（适用于 Claude Agent SDK、Strands、CrewAI、AutoGen 及其他库）进行部署。

<Tip>
如果你是在新建项目，可以考虑使用 [Deep Agents](/oss/deepagents/overview)。它是一个开源 agent harness，支持规划、调用工具、委派给子代理，并处理长时程任务。Deep Agents 可以直接部署到 LangSmith Deployment；如果你希望获得完全托管的运行时，也可以使用 [Managed Deep Agents](/langsmith/deploy-managed-deep-agent)。
</Tip>

## Functional API 的工作方式

当一个 run 到达 Agent Server 上由 Functional API 包裹的 agent 时：

1. 平台会调用你用 `@entrypoint` 装饰的 `agent` 函数，并将 run 输入以及同一 thread 上先前 turn 保存的状态一并传入（通过 `previous` 参数）。
2. entrypoint 会调用用 `@task` 装饰的函数，该函数再委派给底层框架 agent（Claude Agent SDK、Strands、CrewAI、AutoGen 或其他库）。
3. entrypoint 返回 `entrypoint.final(value=..., save=...)`。其中 `value` 是本轮的响应，`save` 是会在下一轮作为 `previous` 传回来的 checkpoint 状态。
4. Agent Server 会持久化 checkpoint，在支持的情况下流式输出部分结果，并在开启 tracing 时记录 traces。

这种模式保留了你所用框架本身的执行语义，同时为你提供标准的 Agent Server 能力：持久化运行、多线程状态保存、流式端点，以及 LangSmith 可观测性。

## 前置要求

无论使用哪种框架，你都需要：

* Python 3.10+（如果是 Strands Agents，则支持 Python 3.9+）
* 一个 [LangSmith API key](/langsmith/create-account-api-key)

<Step title="用 Functional API 包裹">

通过一个名为 `agent` 的、由 `@entrypoint` 装饰的函数暴露你的 agent。在其中，使用 `@task` 包裹调用底层框架的工作单元。使用 `entrypoint.final()` 返回响应，并在同一 thread 的多轮之间持久化对话历史。

<Tabs>
<Tab title="Claude Agent SDK">

```python
import operator

from claude_agent_sdk import ClaudeSDKClient
from langgraph.func import entrypoint, task

@task
async def invoke_claude(prompt: str) -> str:
    async with ClaudeSDKClient(options=options) as client:
        await client.query(prompt)
        chunks: list[str] = []
        async for message in client.receive_response():
            chunks.append(str(message))
        return "\n".join(chunks)

@entrypoint()
async def agent(messages: list[dict], previous: list[dict] | None = None):
    history = operator.add(previous or [], messages)
    prompt = history[-1]["content"]
    response = await invoke_claude(prompt)
    new_message = {"role": "assistant", "content": response}
    return entrypoint.final(
        value=[new_message],
        save=operator.add(history, [new_message]),
    )
```

</Tab>
<Tab title="Strands Agents">

```python
import operator

from langgraph.func import entrypoint, task

```

每个示例里有两点是必须的：

1. **把由 `@entrypoint` 装饰的函数以 `agent` 名称导出到模块作用域**。Agent Server 在提供 graph 服务时会导入这个符号。
2. **返回带有 `save` 参数的 `entrypoint.final()`**，这样同一 thread 中的对话状态才能在多轮之间保留下来。

## 启用 tracing

请使用 [Project layout](#project-layout) 中对应框架的 `.env` 模板。当 `langgraph.json` 中设置了 `"env": ".env"` 时，Agent Server 会加载这个文件。

请在该文件中设置 `LANGSMITH_PROJECT` 以及框架对应的提供商凭证。对于 Claude Agent SDK 和 Strands Agents，还需要设置 `LANGSMITH_TRACING=true`。而对 CrewAI 和 AutoGen，tracing 是在 `agent.py` 中通过 `OtelSpanProcessor()` 以及框架 instrumentors 启用的，因此只需要设置 `LANGSMITH_API_KEY` 和 `LANGSMITH_PROJECT`。

[Traces](/langsmith/observability) 会在 [LangSmith UI](https://smith.langchain.com) 中展示 agent 调用、工具调用和 LLM 交互。关于各框架的 tracing 选项，请参阅[配置 tracing](#configure-tracing)中的链接。

## 本地运行

使用 [LangGraph CLI](/langsmith/cli) 启动本地 Agent Server：

```bash
langgraph dev
```

<Note>
如果 `langgraph dev` 提示缺少 `langgraph-api`，请在同一个环境中安装 `langgraph-cli[inmem]`。
</Note>

这会在 `http://127.0.0.1:2024` 提供 agent 服务，并打开 [LangSmith Studio](/langsmith/studio)。你也可以使用 `curl` 发送请求：

<Note>
`langgraph dev` 可能会使用不同端口。请查看终端输出中的 URL，并按需更新下面的 `curl` 命令。
</Note>

<Tabs>
<Tab title="Claude Agent SDK, CrewAI, AutoGen">

```bash
# Create a thread
THREAD=$(curl -s -X POST http://127.0.0.1:2024/threads \
  -H "Content-Type: application/json" -d '{}' | python -c "import sys, json; print(json.load(sys.stdin)['thread_id'])")

# Run the agent and wait for the final response
curl -s -X POST "http://127.0.0.1:2024/threads/$THREAD/runs/wait" \
  -H "Content-Type: application/json" \
  -d '{
    "assistant_id": "ASSISTANT_ID",
    "input": [{"role": "user", "content": "Hello"}]
  }'
```

</Tab>
<Tab title="Strands Agents">

```bash
# Create a thread
THREAD=$(curl -s -X POST http://127.0.0.1:2024/threads \
  -H "Content-Type: application/json" -d '{}' | python -c "import sys, json; print(json.load(sys.stdin)['thread_id'])")

# Run the agent and wait for the final response
curl -s -X POST "http://127.0.0.1:2024/threads/$THREAD/runs/wait" \
  -H "Content-Type: application/json" \
  -d '{
    "assistant_id": "ASSISTANT_ID",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "text", "text": "Hello"}
        ]
      }
    ]
  }'
```

<Note>
如果这个请求报出 `NoCredentialsError`，请为你的模型提供商配置 AWS 凭证（例如 `AWS_PROFILE`，或 `AWS_ACCESS_KEY_ID` 与 `AWS_SECRET_ACCESS_KEY`），然后重启 `langgraph dev`。
</Note>

</Tab>
</Tabs>

把 `ASSISTANT_ID` 替换成你在 `langgraph.json` 的 `graphs` 对象中配置的 graph key。例如，如果你的配置是 `"graphs": {"claude_agent": "./agent.py:agent"}`，那就用 `claude_agent`；如果配置是 `"graphs": {"strands_agent": "./agent.py:agent"}`，那就用 `strands_agent`。

<Note>
在部署前，请先[验证 LangGraph API 能否在本地运行](/langsmith/local-dev-testing)。如果 `langgraph dev` 本地就无法启动，那么部署到 LangSmith 也会失败。
</Note>

## 部署到 LangSmith

当 agent 已经能在本地运行后，就可以使用 `langgraph deploy` 进行部署：

```bash
langgraph deploy --name my-agent
```

关于环境配置、部署类型和 revision 管理，请参阅[部署到云端](/langsmith/deploy-to-cloud)。关于自托管方案，请参阅[自托管部署](/langsmith/self-hosted)。如果你只需要 Docker 方式托管，而不想要 control plane，请参阅[独立部署](/langsmith/deploy-standalone-server)。
