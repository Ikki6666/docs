LangSmith tracing 插件会把你的 [Claude Code](https://code.claude.com/docs/en/overview) 对话发送到 LangSmith，让你看到 agent 做了什么。每条消息都会成为一条 trace，同一会话中的消息则归入同一个 thread。

## 前置条件

- 已安装 [Claude Code](https://code.claude.com/docs/en/overview)。
- 拥有一个 LangSmith 账户。
- 在 Windows 和 Linux 上需要 [Node.js](https://nodejs.org/) 20 或更高版本。在 macOS 上，插件会自行构建，无需 Node.js。

## 安装插件

在 Claude Code 中运行以下命令：

```bash
/plugin marketplace add langchain-ai/langsmith-claude-code-plugins
/plugin install langsmith-tracing@langsmith-claude-code-plugins
/reload-plugins
```

该 marketplace 默认关闭自动更新。要开启自动更新，请运行 `/plugin` 并打开 **Marketplaces**。想为所有人安装该插件，请参阅[部署到组织](#部署到组织)。有关安装插件的更多信息，请参阅 Claude Code 文档中的[安装插件](https://code.claude.com/docs/en/plugins/install)。

## 登录

使用 LangSmith CLI 登录一次。如果还没有安装，请参阅[安装 LangSmith CLI](/langsmith/langsmith-cli#install)。

```bash
langsmith auth login
```

如果你使用 CLI 登录并且有多个 profile，请在配置文件中把 `profile` 设为插件应使用的那个。你自己的 `api_key` 会忽略此设置，但在设置了 `profile` 时，通用的 `LANGSMITH_API_KEY` 不会被用作回退。

如果想改用 API key，请把它添加到 `~/.claude/langsmith.json`：

```json
{ "enabled": true, "api_key": "lsv2_pt_...", "agent_id": "shared-claude" }
```

如果设置了多个凭据，插件会使用它找到的第一个：

1. 插件自己的 key，来自 `api_key` 或 `CC_LANGSMITH_API_KEY`。
2. 你的 `langsmith auth login` 登录。
3. 环境中的通用 `LANGSMITH_API_KEY`。

当登录过期或 key 被拒绝时，tracing 会停止，这段空档期内的 turn 永远不会被上传。在你修复之前，Claude Code 会在聊天中提醒你。管理员还可以为每个 prompt [要求有效的登录](#要求有效的登录)。

## 开启 tracing

除非管理员已经通过[托管文件](#锁定设置)开启了 tracing，否则在你于 `~/.claude/langsmith.json` 中开启之前，tracing 都处于关闭状态。使用 `agent_id` 把 traces 发送到某个 [agent](/langsmith/log-traces-to-agent#send-traces-to-an-agent)：

```json
{ "enabled": true, "agent_id": "shared-claude" }
```

或者使用 `project` 把它们发送到某个 project：

```json
{ "enabled": true, "project": "shared-claude" }
```

两者任选其一。如果同时设置，`agent_id` 优先。

<Warning>
项目可以用 `<project>/.claude/langsmith.json` 或 `<project>/langsmith-plugins.json` 覆盖这些设置。克隆下来的仓库可以利用它们开启 tracing，把你的对话发送到别人的服务器。在你信任某个仓库之前，请连同 `.claude/settings.json` 和 `.claude/settings.local.json` 一起检查这些文件。
</Warning>

发送一条消息，然后在 [LangSmith](https://smith.langchain.com) 中打开你的 agent 或 project。运行 `/langsmith-tracing:trace` 可获取当前对话 trace 的链接。

## 隐藏对话

在 Claude Code 中运行 `/langsmith-tracing:mute` 可以让对话内容不进入 LangSmith，运行 `/langsmith-tracing:unmute` 则重新开启。确认信息会以被 hook 阻止的 prompt 形式出现，因为这就是 Claude Code 展示插件回复的方式。若要默认静音所有对话，请将 `defaultMuted` 设为 `true`。

## 设置

每项设置都有一个配置文件 key 和一个环境变量。两者都设置时，环境变量优先。

| 配置 key | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enabled` | `TRACE_TO_LANGSMITH` | `false` | 开启 tracing。 |
| `api_key` | `CC_LANGSMITH_API_KEY` | 无 | LangSmith API key。如果使用 CLI 登录则不需要。 |
| `project` | `CC_LANGSMITH_PROJECT` | `claude-code` | traces 发送到的 project。与 `agent_id` 二选一。 |
| `agent_id` | `LANGSMITH_AGENT_ID` | 无 | traces 发送到的 agent。两者都设置时优先于 `project`。 |
| `api_url` | `LANGSMITH_ENDPOINT` | `https://api.smith.langchain.com` | 发送到的 LangSmith 服务器。 |

有关全部设置，请参阅[插件设置](https://github.com/langchain-ai/langsmith-claude-code-plugins#settings)。

## 故障排查

- **没有 traces**：检查插件是否已在 `/plugin` 中启用，以及 tracing 是否已开启。
- **Tracing 已暂停**：再次运行 `langsmith auth login`，或替换被拒绝的 API key。
- **仍然无法解决**：设置 `CC_LANGSMITH_DEBUG=true` 并检查 `~/.claude/state/hook.log`。

更多修复方法，请参阅[当没有任何内容出现时](https://github.com/langchain-ai/langsmith-claude-code-plugins#when-nothing-shows-up)。
