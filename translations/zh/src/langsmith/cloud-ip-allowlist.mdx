#### 允许 Vertex AI 访问

对于从 GCP 上的 LangSmith SaaS 发起的 Vertex AI 连接，仅将公网出站 IP 加入允许列表可能无法满足 VPC Service Controls 的要求。Private Google Access 会让 Google API 流量保留在 Google 网络内，而不是使用 NAT gateway 的公网 IP 地址。参见 Google 的[源 IP 访问指南](https://docs.cloud.google.com/vpc-service-controls/docs/access-level-design#granting_access_based_on_source_ip)。

为与你的 LangSmith SaaS 区域对应的源项目配置 VPC Service Controls 入站规则：

| LangSmith SaaS 区域 | 源 GCP 项目 ID | 用于入站规则的源项目编号 |
| -------------------- | --------------------- | -------------------------------------- |
| US (`smith.langchain.com`) | `langchain-prod` | `projects/83409505503` |
| EU (`eu.smith.langchain.com`) | `langchain-prod` | `projects/83409505503` |
| APAC (`apac.smith.langchain.com`) | `langchain-apac-prod` | `projects/774533884377` |

这些源项目专门用于从 US、EU 和 APAC GCP SaaS 区域发起的 Vertex AI 连接。在入站规则中请使用数字形式的 `projects/PROJECT_NUMBER` 值，而不是项目 ID。请将该规则限制为仅允许调用方身份、你的目标项目以及所需的 Vertex AI 操作。该连接仍然需要相应的 IAM 权限。参见 Google 的[入站规则配置](https://docs.cloud.google.com/vpc-service-controls/docs/ingress-egress-rules)。

请根据你的 LangSmith SaaS 区域（而不是 Vertex AI 模型所在的区域）来选择源项目。Pod 或节点扩缩容不会改变源项目编号。将源工作负载或 VPC 网络迁移到另一个项目，可能会改变所需的允许列表。

### 出站 IP 清单

获取<a href="/langsmith/egress-ip-addresses.json" target="_blank" rel="noopener noreferrer">出站 IP 清单（JSON）</a>，即可自动更新允许列表。

按以下条件筛选 `addresses`：

- `service`：`langsmith` 或 `langsmith-deployment`（已部署的 agents）。
- `cloud`：`gcp`、`aws` 或 `azure`。
- `region`：`us`、`eu` 或 `apac`。

将每个匹配的 `cidr` 加入允许列表。清单中的地址可能现在使用，也可能将来使用。请定期轮询并比较 `version` 以发现变更。更新防火墙规则前，先审查新增和移除的条目。
