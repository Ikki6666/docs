title: Custom Apps

---

<Note>
Custom apps 在 [**Plus** 和 **Enterprise** plans](https://www.langchain.com/pricing) 上可用。
</Note>

Custom app 是你构建的一个 UI，它在 LangSmith 内部运行并调用 [LangSmith API](/langsmith/smith-api-ref)。当内置 UI 未覆盖某个工作流时可以使用它，例如一个专用的标注界面、一个 experiment 比较视图，或一个仅针对你自己的 traces 的 dashboard。

已部署的 app 会显示在侧边栏的 **Custom Apps** 下，对 workspace 中所有拥有 `custom-apps:read` 权限的人可见。你不需要托管一个单独的服务，也不需要管理一个单独的登录。

App 在一个没有自身网络访问权限的 sandbox 中运行。host 会以查看者的凭证转发其 LangSmith API 请求，因此每个人只能看到其[权限](/langsmith/organization-workspace-operations)允许的数据。host 不转发其他任何内容，并且会封锁 API keys、members、users、identities、roles、permissions、SCIM 和 service accounts 的 endpoints。

## 配置 self-hosted chat

<Warning>
在 self-hosted deployments 上，使用 chat 构建和编辑 app 需要 [sandbox service URLs](/langsmith/deploy-self-hosted-full-platform#optional-enable-service-urls)。仅启用 Sandboxes 是不够的。
</Warning>

<Note>
使用 chat 构建和编辑 app 的功能从 Helm chart 版本 0.17.3（v0.17）和 0.18.0-rc.13（v0.18 preview）开始启用。
</Note>

## 构建 app

通过[在浏览器中与 LangSmith Chat 对话](#build-with-chat)构建 app，或者[在本地使用 CLI](#build-locally-with-the-cli) 和你自己的 coding agent 构建。两种路径产生相同的 app 并存储相同的源码，因此任何一方都可以[编辑](#edit-an-app)另一方构建的内容。

### 使用 chat 构建

在浏览器中构建有两个要求：

- **Sandboxes**：每个会话都在一个 [sandbox](/langsmith/sandboxes) 中运行。在 self-hosted deployments 上，请先完成 [self-hosted chat setup](#configure-self-hosted-chat)。
- **Permissions**：`custom-apps:create`、`custom-apps:update`、`custom-apps:delete` 和 `custom-apps:download` 权限，以及 [sandbox permissions](#permissions)。

两者都缺少时，**App** 操作会打开 CLI 说明。Chat 还需要先为 [workspace 设置好 model API key](/langsmith/chat#get-started)，才能发送消息。

要使用 chat 构建一个 app：

<Steps>
<Step title="Start a new app">
前往 **Custom Apps** 并选择 **App** 打开 chat。在还没有任何 app 的 workspace 中，页面会直接打开 chat。
</Step>
<Step title="Describe what you want to build">
在 composer 中输入 app 应该做什么，并从 composer 中的 model 菜单选择用于构建的 model。在它背后的 sandbox 还在启动时，composer 就可以接受 prompt。当 Chat 开始写入文件时，LangSmith 会保存一个草稿，并在 chat 旁边打开 **Preview** 和 **Code** 标签页。
</Step>
<Step title="Review what Chat built">
**Preview** 标签页实时渲染你的更改的构建结果。**Code** 标签页包含文件树、源码，以及本次会话的更改。header 中的一个 badge 会统计被更改的文件数。
</Step>
<Step title="Deploy the app">
选择 **Deploy**。第一次部署会要求一个名称，构建 app 并将其发布到 workspace。

如果你在第一次部署完成前离开页面，LangSmith 会丢弃该 app。一旦 Chat 开始编辑，LangSmith 会在丢弃之前询问你。
</Step>
</Steps>

### 在本地使用 CLI 构建

本地构建使用 [LangSmith CLI](/langsmith/langsmith-cli)，它会生成一个 starter、在你机器上的真实 sandbox 中运行它，并在你准备好时上传它。要在本地构建一个 app：

<Steps>
<Step title="Install the CLI">
```bash
curl -fsSL https://cli.langsmith.com/install.sh | sh
```

Windows、Homebrew 和其他选项，请参阅 [Install](/langsmith/langsmith-cli#install)。
</Step>
<Step title="Authenticate">
```bash
langsmith auth login
```

要改用 API key，请设置 `LANGSMITH_API_KEY`，self-hosted 实例还需要设置 `LANGSMITH_ENDPOINT`。关于 profiles 和其他选项，请参阅 [Authenticate](/langsmith/langsmith-cli#authenticate)。
</Step>
<Step title="Scaffold an app">
```bash
langsmith apps init --name my-annotation-view --template annotation-queue
```

`init` 会创建一个以 app 命名的目录，并且如果 `npm` 在你的 `PATH` 上，还会安装其 dependencies。它还会写入一个 `AGENTS.md`，向 coding agent 提供它在第一次就能产出一个可用 app 所需的约定和 API surface。省略 `--template` 可以得到一个空白的单文件 starter。
</Step>
<Step title="Iterate locally">
```bash
cd my-annotation-view
langsmith apps dev
```

App 运行在与它在 LangSmith 内部获得的同一种 sandbox 中，API 调用通过你自己的凭证代理。失败的调用和未捕获的错误会流式输出到终端，因此大多数调试无需浏览器 devtools。添加 `--verbose` 可以看到每个成功的调用和所有 console 输出，或用 `--quiet` 让 app 静音。
</Step>
<Step title="Push it live">
```bash
langsmith apps push
```

第一次 push 会创建该 app 并将其 ID 记录在 `.langsmith/app.json` 中，该文件将目录与 app 关联起来。之后的 push 更新同一个 app。请提交这个文件，让团队成员 push 到同一个 app。
</Step>
</Steps>

#### Starter templates

将下面之一传给 `langsmith apps init --template`：

| Template | 它生成的内容 |
|----------|-------------------|
| `annotation-queue` | 一个 queue 评审 UI：run 和 thread 条目、一个按类型定制的 viewer，以及一个 feedback rubric。 |
| `annotation-queue-grid` | 以可编辑表格形式呈现的同一评审工作流。 |
| `experiment-comparison` | 将 evaluation experiments 与 baseline 并排比较的视图。 |
| `coding-agent-dashboard` | coding-agent runs 的图表：随时间变化的 usage、cost、errors 和 activity。 |

## 编辑 app

在浏览器中使用 chat 编辑 app，或拉取其源码在本地编辑。

### 使用 chat 编辑

从 **Custom Apps** 打开一个 app 并选择 **Edit**。已发布的 app 会被编辑工作区替换：左侧是 chat，右侧是相同的 **Preview** 和 **Code** 标签页。

在 chat 中提出更改要求，或直接在 **Code** 中编辑文件并用 `Cmd+S`（Windows 和 Linux 上为 `Ctrl+S`）保存。无论哪种方式，preview 都会重新构建，header 中的 badge 会更新其已更改文件的计数。

两个操作会结束会话：

- **Deploy**：构建 app 并将其作为新版本发布给 workspace。
- **Cancel**：不部署而退出。未部署的更改会保留在编辑 sandbox 中。

编辑在一个会在一段时间不活动后停止的 sandbox 中运行。重新打开该 app 会唤醒 sandbox，未部署的更改完好无损。如果 sandbox 已被删除，选择 **Recreate from saved source** 可以从最后一次部署的源码重建会话。未部署的更改会丢失。

要重命名一个 app、复制其 ID 或更改共享对象，请在 app 列表的 row 菜单中选择 **Edit**。

### 在本地使用 CLI 编辑

从浏览器部署会存储 app 的源码，`langsmith apps push` 也是如此。要在本地编辑一个 app，先把它拉下来：

```bash
langsmith apps pull my-app
npm install --prefix my-app
```

用你自己的 coding agent 编辑源码，然后运行 `langsmith apps push` 发布它。

生成的 `AGENTS.md` 要求 agent 在 app 根目录维护一个 `context.md` 作为 app 的记忆：app 做什么、哪些文件重要，以及背后的决策。任何根文件都会随源码一起传输，因此拉取该 app 的团队成员可以从你积累的经验出发，而不是从零开始。

## 与你的组织共享 app

Custom app 属于创建它的 workspace。要与组织共享一个 app，打开 app 列表中的 row 菜单，选择 **Edit**，然后选择 **Share with organization**。组织中的每个 workspace 之后都可以查看、更新和删除它。

要将共享的 app 移回单个 workspace，从该 workspace 选择 **Pull into this workspace**。如果该 workspace 已有一个同名 app，LangSmith 会要求你重命名。

当 CLI 按名称解析 app 时，workspace app 优先于同名的 organization app。

## CLI reference

| Command | 它做什么 |
|---------|-------------|
| `langsmith apps init --name NAME [--template TEMPLATE]` | 在一个以 app 命名的新目录中生成 starter app，并安装其 dependencies。 |
| `langsmith apps dev` | 在真实 sandbox 中本地运行当前目录的 app。 |
| `langsmith apps push` | 将当前目录上传为 custom app，第一次 push 时创建它。传入 `--no-build` 可按原样上传当前文件。 |
| `langsmith apps pull APP_ID_OR_NAME` | 将一个 app 的源码下载到新目录。 |
| `langsmith apps list` | 列出 custom apps。 |
| `langsmith apps delete APP_ID_OR_NAME` | 按 ID 或名称删除一个 app。传入 `--yes` 可跳过确认。 |

`dev` 和 `push` 作用于当前目录，因此请先进入该 app 的目录。

## Permissions

`custom-apps:*` 权限控制对 custom apps 的访问。完整表格请参阅 [Custom apps](/langsmith/organization-workspace-operations#custom-apps)。

在浏览器中编辑还需要 `sandboxes:create`、`sandboxes:read`、`sandboxes:update`、`sandboxes:delete` 和 `sandboxes:exec` 权限，因为每个会话都在一个 sandbox 中运行。**Edit** 操作只对拥有 `custom-apps:update`、`custom-apps:download` 和 sandbox permissions 的用户显示。
