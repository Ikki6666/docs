部署到 agent environment 会将一个 [deployment](/langsmith/deployment) 绑定到一个 [agent](/langsmith/agents) 以及该 agent 的某个 [environment](/langsmith/agent-environments)。两个 flags 承载这一绑定，LangGraph CLI 和 `mda` CLI 都接受它们。

使用它可以将同一个 agent 的 staging build 和 production build 分开，使各自的报告进入自己的 environment。

<AgentBetaNote />

## 前置条件

两个 CLI 都需要以下内容：

- 位于 `.env` 或 shell 环境中的 [LangSmith API key](/langsmith/create-account-api-key)。
- 一个包含 `langgraph.json` 的项目文件夹。请从该文件夹运行 CLI。
- 一个 agent-based workspace，因为这些 flags 要求 workspace 开启 agent mode。

Org-scoped API key 还需要指定 workspace，并且每个 CLI 从不同的变量读取它：LangGraph CLI 读取 `LANGSMITH_TENANT_ID`，`mda` CLI 读取 `LANGSMITH_WORKSPACE_ID`。Workspace-scoped key 则两者都不需要。当 key 是 org-scoped 时，LangGraph CLI 会提示输入该值。在脚本或 CI job 中，请提前设置 `LANGSMITH_TENANT_ID`，并传入 `--no-input`，这样 LangGraph CLI 会直接失败而不是等待输入。Python 和 TypeScript LangGraph CLI 都接受 `--no-input`。

## Addressing flags

两个 CLI 都接受相同的两个 flags：

- **`--agent-id`**：要部署到的 agent。值是 agent 的 identifier，而不是其 display name。关于哪个值是哪个，请参阅 [Identifiers and display names](/langsmith/agents#identifiers-and-display-names)。
- **`--agent-environment`**：deployment 上报到的 environment，取 `development`、`staging` 或 `production` 之一。deployment 不能使用 `local`。该 environment [在 deployments 上完全不显示](/langsmith/agent-environments#select-an-environment)，这是这个集合与 [agent addressing](/langsmith/log-traces-to-agent#addressing-variables) 接受的四个值之间唯一的区别。

这些 flags 指定与 tracing 一侧 agent addressing 所指定的同一对值。LangGraph CLI 还会从相同的两个变量 `LANGSMITH_AGENT_ID` 和 `LANGSMITH_AGENT_ENVIRONMENT` 读取这些 flags。`mda` CLI 不读取这些变量，因此请将 flags 直接传给它。

## 使用 LangGraph CLI 部署

这些 flags 要求 Python 中 `langgraph-cli` v0.4.32 或更高版本，TypeScript 中 `@langchain/langgraph-cli` 1.5.2-dev.0。TypeScript 版本是一个 prerelease build。请精确安装，因为当前的稳定版本 1.5.1 不接受这些 flags。要部署：

1. 安装 CLI：

   <CodeGroup>
   ```bash Python
   uv tool install --force "langgraph-cli>=0.4.32"
   ```

   ```bash TypeScript
   npm install -g "@langchain/langgraph-cli@1.5.2-dev.0"
   ```
   </CodeGroup>

1. 部署，并指定 agent 和 environment：

   <CodeGroup>
   ```bash Python
   langgraph deploy --agent-id my-agent --agent-environment staging --remote
   ```

   ```bash TypeScript
   langgraphjs deploy --agent-id my-agent --agent-environment staging --remote
   ```
   </CodeGroup>

两个 flags 要么都传，要么都不传，因为 CLI 会拒绝单独出现的任何一个。不要将它们与 `--name` 或 `--deployment-id` 组合，这两者直接命名一个 deployment，CLI 会拒绝它们与 agent 并用。

`--remote` 强制进行 remote build。不传时，只要 Docker 可用，CLI 就会进行本地构建。其余 flags 请参阅 [`langgraph deploy`](/langsmith/cli#deploy)。

## 使用 mda CLI 部署

这些 flags 要求 Python 中 `managed-deepagents` 0.7.5.dev4，或 TypeScript 中 0.7.5-dev.4。两者都是 prerelease builds。请精确安装该版本，因为 0.8.0 及更高版本不接受这些 flags，而版本范围会解析到一个拒绝它们的 build。要部署：

1. 安装 CLI：

   <CodeGroup>
   ```bash Python
   uv tool install --force --prerelease allow "managed-deepagents==0.7.5.dev4"
   uv add --prerelease allow "managed-deepagents==0.7.5.dev4"
   ```

   ```bash TypeScript
   npm install "managed-deepagents@0.7.5-dev.4"
   ```
   </CodeGroup>

1. 部署当前文件夹中的项目：

   <CodeGroup>
   ```bash Python
   mda deploy . --agent-id my-agent --agent-environment staging
   ```

   ```bash TypeScript
   npx mda deploy . --agent-id my-agent --agent-environment staging
   ```
   </CodeGroup>

在 Python 中，将 CLI 安装为 tool 并在项目依赖中固定相同版本，可以让全局 `mda` 二进制文件与项目自身的依赖保持同一版本。其余 flags 请参阅 [Deploy projects](/langsmith/managed-deep-agents-cli#deploy-projects)；不使用 agent flags 的部署请参阅 [Deploy a Managed Deep Agent](/langsmith/managed-deep-agents-deploy)。

## 确认绑定

打开该 agent，阅读其 [Overview](/langsmith/navigate-agents#read-the-agent-overview) 的 **Deployments** 部分。部署成功后，新的 deployment 会立即作为一行出现在那里，并且该行链接到 deployment。

如果新的 deployment 没有对应行，或者 Overview 没有 **Deployments** 部分，说明 deployment 未绑定到该 agent。这通常发生在你设置了 `LANGSMITH_AGENT_ID` 和 `LANGSMITH_AGENT_ENVIRONMENT` 变量并使用 `mda` CLI 部署时，因为 `mda` CLI 会忽略这些变量。请改为在 deploy 命令中添加 `--agent-id` 和 `--agent-environment`。
