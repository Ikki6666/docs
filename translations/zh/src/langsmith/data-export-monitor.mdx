当你已经[创建好一个 export job](/langsmith/data-export#2-create-an-export-job)后，可以使用本页介绍的 APIs 跟踪其进度、检查单个 runs，并在需要时停止它。本页也会介绍 LangSmith 如何自动处理失败，以及当导出在重试耗尽后仍然失败时该怎么做。

本页包含：

- 针对特定 export 的[导出状态监控](#monitor-export-status)和[run 列表查询](#list-runs-for-an-export)。
- 查询工作区中[所有 exports](#list-all-exports)。
- [停止一个 export](#stop-an-export)。

- [排查失败的 exports](#troubleshooting-failed-exports)。

<Note>
**适用于 self-hosted、GCP EU、GCP APAC 和 AWS US SaaS**

如果你使用的是 self-hosted、GCP EU（`eu.api.smith.langchain.com`）、GCP APAC（`apac.api.smith.langchain.com`）或 AWS US（`aws.api.smith.langchain.com`），请将下面请求中的 LangSmith URL 替换为对应地址。

## 监控导出状态

如果要监控某个 export job 的状态，请使用以下 cURL 命令：

```bash
curl --request GET \
  --url 'https://api.smith.langchain.com/api/v1/bulk-exports/{export_id}' \
  --header 'Content-Type: application/json' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'X-Tenant-Id: YOUR_WORKSPACE_ID'
```

将 `{export_id}` 替换为你想监控的 export ID。该命令会返回指定 export job 的当前状态。

## 列出某个 export 的 runs

一个 export 通常会被拆分成多个 runs，每个 run 对应一个特定的日期分区。
如果要列出某个 export 关联的所有 runs，请使用以下 cURL 命令：

```bash
curl --request GET \
  --url 'https://api.smith.langchain.com/api/v1/bulk-exports/{export_id}/runs' \
  --header 'Content-Type: application/json' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'X-Tenant-Id: YOUR_WORKSPACE_ID'
```

该命令会返回指定 export 关联的所有 runs，以及它们的 run ID、状态、创建时间、已导出行数等信息。

## 列出所有 exports

如果要获取全部 export jobs 的列表，请使用以下 cURL 命令：

```bash
curl --request GET \
  --url 'https://api.smith.langchain.com/api/v1/bulk-exports' \
  --header 'Content-Type: application/json' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'X-Tenant-Id: YOUR_WORKSPACE_ID'
```

该命令会返回所有 export jobs，以及它们当前状态和创建时间戳。

## 停止一个 export

如果要停止一个已有 export，请使用以下 cURL 命令：

```bash
curl --request PATCH \
  --url 'https://api.smith.langchain.com/api/v1/bulk-exports/{export_id}' \
  --header 'Content-Type: application/json' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'X-Tenant-Id: YOUR_WORKSPACE_ID' \
  --data '{
    "status": "Cancelled"
}'
```

将 `{export_id}` 替换为你想取消的 export ID。请注意，任务一旦被取消，就不能再次启动；你需要重新创建一个新的 export job。

## 失败模式与重试策略

LangSmith bulk exports 会自动处理瞬时失败和基础设施问题，以保证弹性。

每个 bulk export 都会被拆分为多个 _runs_，每个 run 负责处理某个[特定日期分区](/langsmith/data-export#partitioning-scheme)的数据（通常按天组织）。这些 runs 会独立处理，这样可以带来：

- 针对不同时间段的并行处理。
- 每个 run 独立的重试逻辑。
- 在被中断时，可从特定 checkpoint 恢复。

你 export 中的每个 run（日期范围）都有自己独立的[失败处理](#failure-scenarios)和[重试预算](#automatic-retry-behavior)。如果某个 run 在耗尽所有重试后仍然失败，则整个 export 会被标记为 `FAILED`。

### 自动重试行为

导出任务会自动重试瞬时失败，行为如下：

- **Maximum retry attempts**：每个 run 最多重试 20 次（后续可能调整）。
- **Retry delay**：每次重试之间固定间隔 30 秒（无指数退避）。
- **Run timeout**：单个 run 最长可运行 4 小时。
- **Overall workflow timeout**：整个 export 工作流最长可运行 72 小时。

### 失败场景

| Failure type | Cause | Automatic retry? | Action required |
|--------------|-------|------------------|-----------------|
| **Infrastructure interruption** | [Deployments](/langsmith/deployment)、服务端重启、worker 崩溃 | Yes，会自动使用剩余重试次数重新入队。 | 无，任务会自动恢复。 |
| **Run timeout** | 单个 run 超过 4 小时限制 | Yes，最多重试 20 次（后续可能调整）。 | 如果持续发生，请缩小日期范围、增加 filters，或[限制导出字段](/langsmith/data-export#limit-exported-fields)。 |
| **Workflow timeout** | 整个 export 超过 72 小时 | No | 缩小导出范围（日期范围、filters），或拆成多个更小的 exports。 |
| **Storage/destination errors** | [凭证无效](/langsmith/data-export-destinations#credentials-configuration)、[bucket 缺失](/langsmith/data-export-destinations#configuration-fields)、[权限问题](/langsmith/data-export-destinations#permissions-required) | No | 修复 destination 配置，然后重新创建 export。 |
| **Destination deleted** | 导出过程中 bucket 被删除 | No | 重建 destination 并重新启动 export。 |
| **Terminal processing errors** | 数据序列化问题、资源耗尽 | Yes，最多重试 20 次（后续可能调整）。 | 检查 run 错误详情，可能需要进一步调查。 |

<Note>
任意一个单独 run 的失败（在所有重试都耗尽后）都会导致整个 export 失败。
</Note>

### Export 状态生命周期

Exports 可能具有以下状态：

| Status | Description |
|--------|-------------|
| `CREATED` | Export 已创建，但尚未开始处理。 |
| `RUNNING` | Export 正在处理 runs。 |
| `COMPLETED` | 所有 runs 都已成功导出。 |
| `FAILED` | 一个或多个 runs 在重试耗尽后失败。 |
| `CANCELLED` | Export 被用户手动取消。 |
| `TIMEDOUT` | Export 超过了 48 小时工作流超时限制。 |

单个 runs 也会有同样的状态集合：`CREATED`、`RUNNING`、`COMPLETED`、`FAILED`、`CANCELLED` 或 `TIMEDOUT`。

### 并发与速率限制

为了保证系统稳定性，exports 会受到以下限制：

- **Maximum concurrent runs per export**：45
- **Maximum concurrent exports per workspace**：15

如果你同时运行多个 exports，新的 run jobs 会排队等待，直到系统有可用容量。

### 进度跟踪与可恢复性

导出系统会为每个 run 维护详细的进度元数据：
- 数据流中的最新 cursor 位置。
- 已导出的行数。
- 已写出的 Parquet 文件列表。

这些进度跟踪能力可以实现：
- **Graceful resumption**：如果某个 run 被中断（例如因 deployment 触发），它会从最近一个 checkpoint 恢复，而不是从头开始。
- **Progress monitoring**：通过 API 跟踪已经导出了多少数据。
- **Efficient retries**：失败的 runs 不会重复导出已经成功写出的数据。

### 排查失败的 exports

如果你的 export 失败了，请按以下步骤处理：

1. **检查 export 状态**：使用 [`GET /api/v1/bulk-exports/{export_id}` endpoint](/langsmith/smith-api/bulk-exports/get-bulk-export) 获取 export 详情与状态。
2. **查看 run 错误**：你可以使用[列出 runs 的 API](#list-runs-for-an-export)来监控 runs。每个 run 都包含 `errors` 字段，其中按重试轮次记录了详细错误信息（例如 `retry_0`、`retry_1`）。
3. **验证 destination 访问**：确保你的[destination bucket](/langsmith/data-export-destinations#configuration-fields)仍然存在，且[凭证](/langsmith/data-export-destinations#credentials-configuration)仍然有效。
4. **检查 run 大小**：如果你看到超时错误，可能是某些日期分区包含的数据太多。此时可以考虑[限制导出字段](/langsmith/data-export#limit-exported-fields)。
5. **检查系统限制**：确认你没有触碰到[并发限制](#concurrency-and-rate-limits)（每个 export 5 个 runs、每个 workspace 3 个 exports）。

对于存储相关错误，在重试 export 之前，你可以先使用 AWS CLI 或 gsutil 测试 destination 配置。
