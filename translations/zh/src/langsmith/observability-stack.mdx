LangSmith 应用会暴露 telemetry 数据，你可以将其发送到自己选择的后端。如果你尚未搭建 observability stack，或者希望将 LangSmith telemetry 与主应用分离，可以使用 LangSmith Observability Helm chart 来部署一套基础 observability stack。

# 第 1 部分：Prometheus exporters

如果你只想为自托管部署中的组件部署 metrics exporters，然后再由自己的 telemetry 系统抓取这些指标，请使用本节。如果你希望为你直接部署一整套完整 observability stack，请跳到 [End-to-End Deployment Section](/langsmith/observability-stack#prerequisites)。

该 helm chart 提供了一组 Prometheus exporters，用于暴露 [Redis](https://github.com/prometheus-community/helm-charts/tree/main/charts/prometheus-redis-exporter)、[Postgres](https://github.com/prometheus-community/helm-charts/tree/main/charts/prometheus-postgres-exporter)、[Nginx](https://github.com/prometheus-community/helm-charts/tree/main/charts/prometheus-nginx-exporter) 和 [Kube state metrics](https://github.com/prometheus-community/helm-charts/tree/main/charts/kube-state-metrics) 的指标。

1. 创建一个本地文件 `langsmith_obs_config.yaml`
2. 将这个[文件](https://github.com/langchain-ai/helm/blob/main/charts/langsmith-observability/examples/metric-exporters-only.yaml)中的值复制到 `langsmith_obs_config.yaml` 中，并根据你的 LangSmith 部署修改相应配置。
3. 运行 `helm search repo langchain/langsmith-observability --versions` 查找 chart 的最新版本。
4. 取最新版本号，并运行 `helm install langsmith-observability langchain/langsmith-observability --values langsmith_obs_config.yaml --version <version> -n <namespace> --wait --debug`

安装完成后，你可以从以下 service endpoint 抓取指标：

* Postgres: `langsmith-observability-postgres-exporter:9187/metrics`
* Redis: `langsmith-observability-redis-exporter:9121/metrics`
* Nginx: `langsmith-observability-nginx-exporter:9113/metrics`
* KubeStateMetrics: `langsmith-observability-kube-state-metrics:8080/metrics`

# 第 2 部分：完整 observability stack

<Warning>
**这不是一套生产级 observability stack。它适合用于快速查看部署中的 logs、metrics 和 traces。其设计目标仅是每天处理几十 GB 的数据量。**
</Warning>

本节将演示如何使用 [Helm Chart](https://github.com/langchain-ai/helm/tree/main/charts/langsmith-observability) 为 LangSmith 部署一整套端到端 observability stack。

该 chart 基于 Grafana 的开源 LGTM Stack，包含：

* [Loki](https://grafana.com/docs/loki/latest/)：用于日志。
* [Mimir](https://grafana.com/docs/mimir/latest/)：用于指标和告警。
* [Tempo](https://grafana.com/docs/tempo/latest/)：用于 traces。
* [Grafana](https://grafana.com/docs/grafana/latest/)：用于监控 UI。

同时还包括用于采集 telemetry 数据的 [OpenTelemetry Collectors](https://opentelemetry.io/docs/collector/)。

## 前置条件

### 1. 计算资源

该 stack 各组件的资源 request 和 limit 都可以在 helm chart 中修改。当前分配如下（request/limit）：

* Loki: `2vCPU/3vCPU + 2Gi/4Gi`
* Mimir: `1vCPU/2vCPU + 2Gi/4Gi`
* Tempo: `1vCPU/2vCPU + 4Gi/6Gi`

请在拉起 helm chart 前确保这些资源已就绪，或者在你的 helm 配置文件中调整对应资源值。

### 2. Cert-Manager

该 helm chart 使用 OpenTelemetry Operator 来 provision collectors。而该 operator 要求你的 Kubernetes 集群中已安装 [cert-manager](https://cert-manager.io/docs/installation/)。

如果尚未安装，可运行以下命令：

```bash
helm repo add jetstack https://charts.jetstack.iohelm repo updatehelm install cert-manager jetstack/cert-manager -n cert-manager --create-namespace
```

### 3. OpenTelemetry operator

使用以下命令安装 OpenTelemetry Operator：

```bash
helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-chartshelm repo updatehelm install opentelemetry-operator open-telemetry/opentelemetry-operator -n <namespace>
```

## 安装

以下步骤会启动 OTel collectors、LGTM stack、Grafana 以及 Prometheus exporters。

1. 创建一个本地文件 `langsmith_obs_config.yaml`
2. 将这个[文件](https://github.com/langchain-ai/helm/blob/main/charts/langsmith-observability/examples/e2e-stack.yaml)中的值复制到 `langsmith_obs_config.yaml` 中，并按你的 LangSmith 部署进行修改。
3. 运行 `helm search repo langchain/langsmith-observability --versions` 查找 chart 的最新版本。
4. 取最新版本号，并运行 `helm install langsmith-observability langchain/langsmith-observability --values langsmith_obs_config.yaml --version <version> -n <namespace> --wait --debug`

<Note>
**你可以通过修改配置文件中 `otelCollector` 下的布尔值，有选择地采集 logs、metrics 或 traces。你也可以单独启用后端的某些部分（Loki、Mimir、Tempo）。**

## 安装后步骤

### 在 LangSmith 中启用 logs 与 traces

安装 observability helm chart 后，你还需要在 *LangSmith* 的 helm 配置文件中设置以下值，才能启用 logs 与 traces 的采集。

```yaml
commonPodAnnotations:
  # E.g.: "langsmith-observability/langsmith-observability-collector-sidecar"
  sidecar.opentelemetry.io/inject: "${LANGSMITH_OBS_NAMESPACE}/${LANGSMITH_OTEL_CRD_NAME}"
observability:
  tracing:
    enabled: true
    # Replace this with the endpoint of your trace collector.
    # E.g.: "http://langsmith-observability-collector-gateway-collector.langsmith-observability.svc.cluster.local:4318/v1/traces"
    endpoint: "http://${GATEWAY_COLLECTOR_SERVICE_NAME}.${LANGSMITH_OBS_NAMESPACE}.svc.cluster.local:4318/v1/traces"
```

<Info>
1. 要获取 `${LANGSMITH_OTEL_CRD_NAME}`，可运行 `kubectl get opentelemetrycollectors -n ${LANGSMITH_OBS_NAMESPACE}`，选择其中 `MODE = sidecar` 的那个名称。
2. 要获取 `${GATEWAY_COLLECTOR_SERVICE_NAME}`，运行 `kubectl get services -n ${LANGSMITH_OBS_NAMESPACE}`，选择那个同时暴露 4317/4318 端口、并且拥有 ClusterIP 的 service。它通常类似 `langsmith-observability-collector-gateway-collector`。
</Info>

然后运行 `helm upgrade langsmith langchain/langsmith --values langsmith_config.yaml -n <langsmith-namespace> --wait --debug`

## 使用 Grafana

全部安装完成后，先通过以下命令获取 Grafana 密码：

```bash
kubectl get secret langsmith-observability-grafana -n <langsmith_observability_namespace> -o jsonpath="{.data.admin-password}" | base64 --decode
```

然后将 `langsmith-observability-grafana` 容器的 3000 端口做端口转发，并在浏览器中打开 `localhost:3000`。用户名使用 `admin`，密码则使用上面命令拿到的 secret。

登录 Grafana 后，你就可以通过 UI 查看 logs、metrics 和 traces。Grafana 还预打包了多套 dashboard，可用于监控部署中的主要组件。
