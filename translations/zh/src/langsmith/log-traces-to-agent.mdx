每条 trace 都属于 workspace 中的某个 [agent](/langsmith/agents) 及其某个 [environment](/langsmith/agent-environments)。在代码或环境变量中配置 agent 标识符和环境，LangSmith 会用它们把每条 trace 路由到所选环境。

<Note>
将 traces 发送到 agent 仅适用于 agent-based workspaces。它支持于：

- Python SDK，从 `langsmith>=0.14.9` 起
- TypeScript SDK，从 `langsmith>=0.10.9` 起
- Go SDK，从 `github.com/langchain-ai/langsmith-go@v0.28.0` 起
- Java SDK，从 `com.langchain.smith:langsmith-java:0.1.0-beta.26` 起

对于需要 `project_name` 的集成，请把该环境的 [`tracer_session_name`](/langsmith/create-an-agent#use-an-environment-project) 用作兼容值。对于基于项目的工作区（包括自托管 LangSmith），请按照 [tracing 快速开始](/langsmith/observability-quickstart)操作。
</Note>

## 前置条件

- **一个 agent-based workspace。** [Agent-based workspaces](/langsmith/migrate-to-agent-based-workspaces) 在 [LangSmith Cloud](/langsmith/cloud) 上可用，在[自托管](/langsmith/self-hosted)的 LangSmith 上不可用。在 agent-based workspace 中，将 traces 发送到 agent 已经开启，你无需更改任何设置。要判断你拥有哪种 workspace，请看左上角的控件。在 agent-based workspace 中，它显示你的 workspace 名称。在 project-based workspace 中，它显示 LangSmith logo，并且将 traces 发送到 agent 是关闭的。
- **一个已存在的 agent。** 在运行 tracing 示例之前，先在目标 workspace 中[创建该 agent](/langsmith/create-an-agent)。这些示例使用标识符 `checkout`。请替换为你自己的标识符。
- **来自该 workspace 的一个 API key。** 请参阅[创建 API key](/langsmith/create-account-api-key)。
- **SDK。** 将 traces 发送到 agent 在 Python 中需要 `langsmith>=0.14.9`，在 TypeScript 中需要 `langsmith@>=0.10.9`，在 Go 中需要 `github.com/langchain-ai/langsmith-go` v0.28.0 或更高版本，在 Java 中需要 `com.langchain.smith:langsmith-java` 0.1.0-beta.26 或更高版本：

  <CodeGroup>

  ```bash uv
  uv add "langsmith>=0.14.9"
  ```

  ```bash pip
  pip install -U "langsmith>=0.14.9"
  ```

  ```bash npm
  npm install "langsmith@>=0.10.9"
  ```

  ```bash go
  go get github.com/langchain-ai/langsmith-go@v0.28.0
  ```

  ```kotlin Java/Kotlin (Gradle)
  implementation("com.langchain.smith:langsmith-java:0.1.0-beta.26")
  ```

  </CodeGroup>

## 将 traces 发送到 agent

将 agent 和 environment 一起指定，在代码中或通过环境变量。代码中的 agent 优先于变量。只有当代码中没有指定目的地时，SDK 才读取变量，而且此时两者都需要。

- **Agent ID**：agent 的 identifier，浏览器地址栏会携带它，agent 的 Overview 上的 **ID** 字段可以复制它。它不是 display name。[Display name 是一个单独的、可编辑的值](/langsmith/agents#identifiers-and-display-names)，不必与 identifier 一致，因此请从 agent 本身读取 identifier，而不是从 agent 的名称推导它。identifier 必须遵循的规则请参阅 [Identifier rules](/langsmith/create-an-agent#identifier-rules)。请先创建 agent，再使用其 identifier。已归档的 agent 仍持有其 identifier，LangSmith 会以 `409` 拒绝发送到它的 run。
- **Environment**：该 run 所属的 environment，取 `local`、`development`、`staging` 或 `production` 之一。Environment 名称不区分大小写，它们映射到 UI 中的 Local、Development、Staging 和 Production 标签。没有默认值，因为单独的 agent 或 environment 都无法确定一个目的地。

### 使用环境变量

设置这两个变量：

```bash
export LANGSMITH_TRACING=true
export LANGSMITH_API_KEY=<your-api-key>
export LANGSMITH_AGENT_ID=checkout
export LANGSMITH_AGENT_ENVIRONMENT=production
```

前两个是通常的 tracing 前置条件，而不是指定 agent 的一部分。如果只设置了两个 agent 变量之一，SDK 会记录一条警告。它不会替你挑选一个 environment，而是让代码中未指定目的地的每个调用都不被 trace，因此这些调用不会有任何内容到达 LangSmith。

### 使用 OpenTelemetry

要将 OTLP traces 发送到 agent，请设置 `Langsmith-Agent-Id` 和 `Langsmith-Agent-Environment` headers，而不是 `Langsmith-Project`。在 `langsmith>=0.14.9` 下，当 `OTEL_EXPORTER_OTLP_HEADERS` 未设置时，Python SDK 的 OpenTelemetry exporter 会根据 agent 变量设置这两个 headers。关于 header 规则以及 LangSmith 返回的错误，请参阅 [Trace with OpenTelemetry](/langsmith/trace-with-opentelemetry#trace-a-non-langchain-application)。

## 发送你的第一条 trace

运行你的 agent，让它至少发送一条 trace。在 LangSmith 中，在顶栏选择该 agent，前往 **Tracing**，并将 environment 控件设置为你发送 trace 所到的那个。trace 会出现在那里。

## 查询 agent 环境

要查询 traces，请先把 [agent 标识符和环境解析](/langsmith/resolve-an-agent)为 `session_id`。将该值传给需要 `project_id` 或 `project_ids` 的查询 API。

## 移除冲突的目的地设置

不要将 agent addressing 与遗留的目的地设置组合使用。对于冲突的设置，SDK 的处理方式如下：

- **同时设置 agent 变量和遗留变量**：不允许。如果你设置了 agent 变量，还设置了 `LANGSMITH_PROJECT`、`LANGCHAIN_PROJECT` 或 `LANGCHAIN_SESSION`，这条 trace 就有两个目的地，SDK 不会替你选择。它会在客户端启动时记录一条警告，并且除非代码指定了目的地，否则不会 trace 该调用。如果你在同一次调用中同时传入 `address` 和 `project_name`，SDK 会抛出错误并且不发送任何内容：Python 中 `@traceable` 或 `tracing_context()` 抛出 `LangSmithUserError`，TypeScript 中 `traceable` 抛出 `Error`。对于同时提供两种地址类型的摄取请求，LangSmith 也会拒绝。
- **在代码中覆盖 `project_name`**：覆盖 agent 变量。在 Python 中将 `project_name` 传给 `@traceable` 或 `tracing_context()`，或在 TypeScript 中传入 `traceable` 的 config，会把该 run trace 到覆盖后的目的地并忽略 agent 变量，不会报错。这就是让一个 [evaluation](/langsmith/evaluation) 使用自己的实验目的地，而 agent 变量在进程的其余部分保持设置的原因。

## 故障排查

如果 tracing 报告 agent 不存在，请检查 workspace 和标识符。使用 UI 或设置凭据[注册该 agent](/langsmith/create-an-agent)，然后重试。

在自托管的 LangSmith 上，agent-based workspaces 不可用，LangSmith 会以 `403` 拒绝发送到 agent 的 runs，并附带消息 `agent addressing is not enabled for this workspace`。它会拒绝携带这些 runs 的整个请求，因此该请求中的 runs 都不会被记录。请参阅[前置条件](#prerequisites)。
