<Note>
  FIPS 和 airgapped LangSmith 部署都要求你在上线前先与 LangChain 客户经理沟通。请在修改安装之前，先确认 licensing、受支持配置以及 upgrade path。
</Note>

从 v15 开始，每一个由 LangChain 编写的 LangSmith 镜像都提供对应的 `-fips` 版本，并以 FIPS 140 模式运行。从 v18（LangSmith `appVersion` 0.18.0）开始，SmithDB 镜像也提供对应的 `-fips` 版本。如果你的自托管部署需要满足 FIPS 合规要求，例如联邦机构、国防承包商或受监管行业，就应该使用这些镜像。

## 这些镜像是如何构建的

`-fips` 变体基于 [Chainguard FIPS container images](https://edu.chainguard.dev/chainguard/fips/fips-images/) 构建。它们内置了经过 NIST 验证的加密模块（具体可能是 OpenSSL FIPS provider、Bouncy Castle FIPS 或 BoringCrypto，取决于底层镜像）。如需查看模块清单及其 CMVP 证书，请参见 [Chainguard's FIPS commitment](https://edu.chainguard.dev/chainguard/fips/fips-images/)。

每个由 LangChain 编写的镜像，在与非 FIPS 版本相同的 tag 下，都有一个对应的 `-fips` 版本：

| Non-FIPS image | FIPS image |
| --- | --- |
| `langchain/langsmith-ace-backend` | `langchain/langsmith-ace-backend-fips` |
| `langchain/langsmith-backend` | `langchain/langsmith-backend-fips` |
| `langchain/langsmith-frontend` | `langchain/langsmith-frontend-fips` |
| `langchain/langgraph-operator` | `langchain/langgraph-operator-fips` |
| `langchain/smithdb` | `langchain/smithdb-fips` |

<Note>
  **从 LangSmith 0.16.21（chart `0.16.0-rc.17`）开始，镜像数量减少。** platform backend、playground、host backend 以及 Fleet 工具服务器和触发器服务器现在都从单一的 `langsmith-backend` 镜像运行，因此不再需要 `langsmith-go-backend-fips`、`langsmith-playground-fips`、`hosted-langserve-backend-fips`、`agent-builder-tool-server-fips` 和 `agent-builder-trigger-server-fips`。对应的 `values.yaml` 键 `platformBackendImage`、`playgroundImage`、`hostBackendImage`、`fleetToolServerImage` 和 `fleetTriggerServerImage` 已从 chart 中移除；如果你仍为这些键设置值，这些值会被忽略。

  在**更早**的版本中，这五个镜像也会以相同的 tag 发布对应的 `-fips` 版本；同样要把每个键指向其 `-fips` repository。
</Note>

PostgreSQL、Redis 和 ClickHouse 的 FIPS 变体并不是由 LangChain 发布的。如果你的部署也要求这些组件满足 FIPS，请自行接入 FIPS 模式的服务，并通过 [external Postgres](/langsmith/self-host-external-postgres)、[external Redis](/langsmith/self-host-external-redis) 或 [external ClickHouse](/langsmith/self-host-external-clickhouse) 完成配置。

### ACE backend 的 FIPS 边界说明

`langsmith-ace-backend-fips` 与其他所有 `-fips` 镜像一样，构建于同一个 Chainguard FIPS 基础镜像之上，但它的代码执行运行时（Deno 和 Pyodide/WebAssembly）会打包自己的加密库，而不会动态链接系统中经过 FIPS 验证的 OpenSSL，因此执行运行时本身在技术上并不位于 FIPS 140 模块边界之内。

我们认为这在受监管环境中是可接受的。FIPS 规范约束的是平台对敏感数据执行的加密操作，而 ACE 不执行这类操作。它不会把 secrets 注入用户代码，不会持久化任何数据，也不执行任何静态数据加密，并且其执行子进程没有网络访问能力。ACE 是一个集群内 HTTP 服务，由 LangSmith backend 调用；当 TLS 在上游由经过 FIPS 验证的 service mesh 或 ingress 终止时，ACE 本身不会执行任何处于 FIPS 范围内的加密操作。

### SmithDB 的 FIPS 边界说明

`langchain/smithdb-fips` 中的 SmithDB 服务通过 `aws-lc-fips-sys` 加密模块执行安全关键型加密和哈希操作，并使用 `rustls` 的 `aws-lc-rs` crypto provider，而不是系统的 OpenSSL FIPS provider。`smithdb` 二进制文件包含一个 `check-fips` 子命令，除标准的 `openssl-fips-test` 检查之外，该子命令还会确认此 provider 已启用，并且 AWS-LC 正在 FIPS 模式下运行。参见[验证 SmithDB 镜像](#verify-the-smithdb-image)。

## 使用 FIPS 镜像

在 LangSmith Helm 安装的 `values.yaml` 中，把各个 LangChain 镜像仓库切换为对应的 `-fips` 版本，同时保留原有 tag。把下面的 `0.18.2026112100` 替换成你想部署的 [LangSmith version](/langsmith/self-hosted-changelog)：

```yaml
images:
  aceBackendImage:
    repository: "langchain/langsmith-ace-backend-fips"
    pullPolicy: IfNotPresent
    tag: "0.18.2026112100"
  backendImage:
    repository: "langchain/langsmith-backend-fips"
    pullPolicy: IfNotPresent
    tag: "0.18.2026112100"
  frontendImage:
    repository: "langchain/langsmith-frontend-fips"
    pullPolicy: IfNotPresent
    tag: "0.18.2026112100"
  operatorImage: # The operator is versioned separately from LangSmith
    repository: "langchain/langgraph-operator-fips"
    pullPolicy: IfNotPresent
    tag: "0.1.66"
  smithdbImage: # Only when SmithDB is enabled
    repository: "langchain/smithdb-fips"
    pullPolicy: IfNotPresent
    tag: "0.18.2026112100"
```

修改完成后，请按 [Upgrading LangSmith](/langsmith/self-host-upgrades) 指南执行升级。

## 验证 FIPS 模式

Chainguard 在每个 FIPS 镜像中都内置了 `openssl-fips-test` 工具。你可以在 pod 中运行它，它会打印 FIPS 自检结果、当前激活的 FIPS provider 版本，以及对应 CMVP 证书链接。

检查一个正在运行的 pod：

```bash
kubectl exec <pod-name> -- openssl-fips-test
```

预期输出（节选）：

```text
Checking OpenSSL lifecycle assurance.
	✓ Self-test KAT_Integrity HMAC ... passed.
	✓ Self-test Module_Integrity HMAC ... passed.
	...
	✓ 29 out of 29 self-tests passed.
	✓ Check FIPS cryptographic module is available... passed.
	✓ Check FIPS approved only mode (EVP_default_properties_is_fips_enabled)... passed.
Public OpenSSL API (libssl.so & libcrypto.so):
	name:      OpenSSL 3.6.0 1 Oct 2025
	version:   3.6.0
FIPS cryptographic module provider details (fips.so):
	name:      OpenSSL FIPS Provider
	version:   3.1.2
Locate applicable CMVP certificate(s) at: CMVP #4985
```

你也可以在 Kubernetes 之外验证镜像：

```bash
docker run --rm --entrypoint openssl-fips-test langchain/langsmith-backend-fips:0.18.2026112100
```

如果需要更详细地理解输出内容，请参见 [Chainguard's FIPS verification guide](https://edu.chainguard.dev/chainguard/fips/verify-fips/)。

### 验证 SmithDB 镜像 {#verify-the-smithdb-image}

每个 SmithDB FIPS 镜像都附带一份采用 CycloneDX 格式的已签名 SBOM（software bill of materials，软件物料清单）。该 SBOM 会列出依赖树，其中包括执行加密的 crate，因此你可以确认 FIPS 验证过的 crate 已经构建。

安装 [`cosign`](https://docs.sigstore.dev/cosign/system_config/installation/)，然后验证 tag。SBOM attestation 会附加到多平台索引和每个平台的 manifest 上，因此验证 tag 会检查每个平台，并为每个平台返回一条 attestation：

```bash
cosign verify-attestation --type cyclonedx \
    --certificate-identity-regexp '^https://github\.com/langchain-ai/smithdb/\.github/workflows/promote-self-hosted-release\.yml@refs/heads/main$' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com \
    docker.io/langchain/smithdb-fips:0.18.2026112100
```

该命令会打印每条 attestation 的验证结果，随后以 JSON 形式打印 attestation 本身：

```text
Verification for docker.io/langchain/smithdb-fips:0.18.2026112100 --
The following checks were performed on each of these signatures:
  - The cosign claims were validated
  - Existence of the claims in the transparency log was verified offline
  - The code-signing certificate was verified using trusted certificate authority certificates
Certificate subject: https://github.com/langchain-ai/smithdb/.github/workflows/promote-self-hosted-release.yml@refs/heads/main
Certificate issuer URL: https://token.actions.githubusercontent.com
GitHub Workflow Trigger: repository_dispatch
GitHub Workflow SHA: ...
GitHub Workflow Name: Promote Self-Hosted Release
GitHub Workflow Repository: langchain-ai/smithdb
GitHub Workflow Ref: refs/heads/main
```

每条 attestation 都是一个 in-toto statement，其 `predicate` 包含 CycloneDX 文档。要把单个平台的 SBOM 保存为独立的 CycloneDX 文件，请解析该平台的 digest，并改为验证该 digest，而不是验证 tag：

```bash
# List the digest of each platform-specific image
docker manifest inspect docker.io/langchain/smithdb-fips:0.18.2026112100 \
  | jq -r '.manifests[] | select(.platform.os != "unknown") | "\(.platform.os)/\(.platform.architecture) \(.digest)"'

# Verify one platform's attestation and extract its SBOM
cosign verify-attestation --type cyclonedx \
    --certificate-identity-regexp '^https://github\.com/langchain-ai/smithdb/\.github/workflows/promote-self-hosted-release\.yml@refs/heads/main$' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com \
    docker.io/langchain/smithdb-fips@<platform-digest> \
  | jq '.payload | @base64d | fromjson | .predicate' > sbom.json
```

将 `<platform-digest>` 替换为第一条命令中的 `sha256:...` digest。然后，`sbom.json` 会包含该平台的 CycloneDX SBOM。

除了 `openssl-fips-test` 之外，SmithDB FIPS 镜像还包含 `smithdb check-fips` 命令。它会打印当前启用的 crypto provider，并且除非 rustls provider 已获得 FIPS 批准且 AWS-LC 在已认证的模块版本上以 FIPS 模式运行，否则会以非零状态退出。

```bash
docker run --rm langchain/smithdb-fips:0.18.2026112100 check-fips
```

预期输出：

```text
FIPS mode: rustls crypto provider aws-lc-rs on AWS-LC FIPS 3.1.0
```

## 为 airgapped 部署做镜像镜像同步

当你把镜像同步到私有仓库时，`-fips` 命名规则完全一致。请按 [image mirroring guide](/langsmith/self-host-mirroring-images) 操作，只是把每个 repository 替换成对应的 `-fips` 版本即可。无论是否启用 FIPS，airgapped rollout 都要求你在开始前先与 LangChain 客户经理完成范围确认。
