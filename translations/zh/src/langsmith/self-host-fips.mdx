从 v15 开始，每一个由 LangChain 编写的 LangSmith 镜像都提供对应的 `-fips` 版本，并以 FIPS 140 模式运行。如果你的自托管部署需要满足 FIPS 合规要求，例如联邦机构、国防承包商或受监管行业，就应该使用这些镜像。

## 这些镜像是如何构建的

`-fips` 变体基于 [Chainguard FIPS container images](https://edu.chainguard.dev/chainguard/fips/fips-images/) 构建。它们内置了经过 NIST 验证的加密模块（具体可能是 OpenSSL FIPS provider、Bouncy Castle FIPS 或 BoringCrypto，取决于底层镜像）。如需查看模块清单及其 CMVP 证书，请参见 [Chainguard's FIPS commitment](https://edu.chainguard.dev/chainguard/fips/fips-images/)。

每个由 LangChain 编写的镜像，在与非 FIPS 版本相同的 tag 下，都有一个对应的 `-fips` 版本：

| Non-FIPS image | FIPS image |
| --- | --- |
| `langchain/langsmith-ace-backend` | `langchain/langsmith-ace-backend-fips` |
| `langchain/langsmith-backend` | `langchain/langsmith-backend-fips` |
| `langchain/langsmith-frontend` | `langchain/langsmith-frontend-fips` |
| `langchain/langsmith-go-backend` | `langchain/langsmith-go-backend-fips` |
| `langchain/langsmith-playground` | `langchain/langsmith-playground-fips` |
| `langchain/hosted-langserve-backend` | `langchain/hosted-langserve-backend-fips` |
| `langchain/langgraph-operator` | `langchain/langgraph-operator-fips` |
| `langchain/agent-builder-tool-server` | `langchain/agent-builder-tool-server-fips` |
| `langchain/agent-builder-trigger-server` | `langchain/agent-builder-trigger-server-fips` |

PostgreSQL、Redis 和 ClickHouse 的 FIPS 变体并不是由 LangChain 发布的。如果你的部署也要求这些组件满足 FIPS，请自行接入 FIPS 模式的服务，并通过 [external Postgres](/langsmith/self-host-external-postgres)、[external Redis](/langsmith/self-host-external-redis) 或 [external ClickHouse](/langsmith/self-host-external-clickhouse) 完成配置。

### ACE backend 的 FIPS 边界说明

`langsmith-ace-backend-fips` 与其他所有 `-fips` 镜像一样，构建于同一个 Chainguard FIPS 基础镜像之上，但它的代码执行运行时（Deno 和 Pyodide/WebAssembly）会打包自己的加密库，而不会动态链接系统中经过 FIPS 验证的 OpenSSL，因此执行运行时本身在技术上并不位于 FIPS 140 模块边界之内。

我们认为这在受监管环境中是可接受的。FIPS 规范约束的是平台对敏感数据执行的加密操作，而 ACE 不执行这类操作。它不会把 secrets 注入用户代码，不会持久化任何数据，也不执行任何静态数据加密，并且其执行子进程没有网络访问能力。ACE 是一个集群内 HTTP 服务，由 LangSmith backend 调用；当 TLS 在上游由经过 FIPS 验证的 service mesh 或 ingress 终止时，ACE 本身不会执行任何处于 FIPS 范围内的加密操作。

## 使用 FIPS 镜像

在 LangSmith Helm 安装的 `values.yaml` 中，把各个 LangChain 镜像仓库切换为对应的 `-fips` 版本，同时保留原有 tag。把下面的 `0.15.0` 替换成你想部署的 [LangSmith version](/langsmith/self-hosted-changelog)：

```yaml
images:
  aceBackendImage:
    repository: "langchain/langsmith-ace-backend-fips"
    pullPolicy: IfNotPresent
    tag: "0.15.0"
  backendImage:
    repository: "langchain/langsmith-backend-fips"
    pullPolicy: IfNotPresent
    tag: "0.15.0"
  frontendImage:
    repository: "langchain/langsmith-frontend-fips"
    pullPolicy: IfNotPresent
    tag: "0.15.0"
  hostBackendImage:
    repository: "langchain/hosted-langserve-backend-fips"
    pullPolicy: IfNotPresent
    tag: "0.15.0"
  operatorImage:
    repository: "langchain/langgraph-operator-fips"
    pullPolicy: IfNotPresent
    tag: "0.15.0"
  platformBackendImage:
    repository: "langchain/langsmith-go-backend-fips"
    pullPolicy: IfNotPresent
    tag: "0.15.0"
  playgroundImage:
    repository: "langchain/langsmith-playground-fips"
    pullPolicy: IfNotPresent
    tag: "0.15.0"
```

修改完成后，请按 [Upgrading LangSmith](/langsmith/self-host-upgrades) 指南执行升级。

## 验证 FIPS 模式

Chainguard 在每个 FIPS 镜像中都内置了 `openssl-fips-test` 工具。你可以在 pod 中运行它，它会打印 FIPS 自检结果、当前激活的 FIPS provider 版本，以及对应 CMVP 证书链接。

检查一个正在运行的 pod：

```bash
kubectl exec <pod-name> -- openssl-fips-test
```

预期输出（节选）：

```text
Checking OpenSSL lifecycle assurance.
	✓ Self-test KAT_Integrity HMAC ... passed.
	✓ Self-test Module_Integrity HMAC ... passed.
	...
	✓ 29 out of 29 self-tests passed.
	✓ Check FIPS cryptographic module is available... passed.
	✓ Check FIPS approved only mode (EVP_default_properties_is_fips_enabled)... passed.
Public OpenSSL API (libssl.so & libcrypto.so):
	name:      OpenSSL 3.6.0 1 Oct 2025
	version:   3.6.0
FIPS cryptographic module provider details (fips.so):
	name:      OpenSSL FIPS Provider
	version:   3.1.2
Locate applicable CMVP certificate(s) at: CMVP #4985
```

你也可以在 Kubernetes 之外验证镜像：

```bash
docker run --rm --entrypoint openssl-fips-test langchain/langsmith-go-backend-fips:0.15.0
```

如果需要更详细地理解输出内容，请参见 [Chainguard's FIPS verification guide](https://edu.chainguard.dev/chainguard/fips/verify-fips/)。

## 为 airgapped 部署做镜像镜像同步

当你把镜像同步到私有仓库时，`-fips` 命名规则完全一致。请按 [image mirroring guide](/langsmith/self-host-mirroring-images) 操作，只是把每个 repository 替换成对应的 `-fips` 版本即可。无论是否启用 FIPS，airgapped rollout 都要求你在开始前先与 LangChain 客户经理完成范围确认。
