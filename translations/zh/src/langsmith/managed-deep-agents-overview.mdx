Managed Deep Agents 是一个托管运行时，用于在 LangSmith 中创建、运行和运维 deep agents。你可以用它来运行持久化、长时间执行的 agent，而无需自行搭建 agent server。

它将 [Deep Agents](/oss/deepagents/overview) harness 与托管基础设施组合在一起，包括持久化 runs、[LangSmith sandboxes](/langsmith/sandboxes)、thread state、MCP tools、文件树、traces 和 agent revisions。

<Note>
Managed Deep Agents 当前处于 **private beta**，仅在美国区域的 [LangSmith Cloud](/langsmith/cloud) 中可用。你可以[加入候补名单](https://www.langchain.com/langsmith-managed-deep-agents-waitlist)来申请访问权限。
</Note>

推荐工作流如下：

1. 创建或编辑本地的 Managed Deep Agents 项目。
2. 使用默认 backend，或切换到 LangSmith sandbox backend。
3. 当 agent 需要外部能力时，连接 MCP tools。
4. 将项目部署到 Managed Deep Agents。
5. 使用 Python 或 TypeScript SDK 运行 agent。
6. 在 LangSmith 中查看 traces、文件、tool calls、运行时状态和 revisions。

## 使用 Managed Deep Agents

你可以用 Managed Deep Agents 来：

- 从本地项目文件创建和管理 deep agents。
- 在不搭建自定义 agent server 的情况下运行长时间执行的 agent。
- 为每个 thread 或 agent 提供隔离的 LangSmith sandbox 资源，用于代码执行、文件系统操作和长任务。
- 流式运行 agent 并持久化 thread state。
- 使用托管文件树来保存 instructions、skills、subagents、tools 和运行时文件。
- 注册工作区级 MCP servers，包括 OAuth MCP servers，并列出其可用工具。
- 在 LangSmith 中检查 traces 和 agent 行为。

<Tip>
    你也可以使用标准的 [LangSmith Deployment](/langsmith/deployment-quickstart) 来部署 Deep Agents。如果你需要自定义应用代码、自定义路由、更高级的认证、完整的 Agent Server API、更强的隔离控制或更高的可扩展性，请选择那条路径。
</Tip>

## 会创建的资源

当你创建一个 Managed Deep Agent 时，LangSmith 会为你配置：

- 一个 Managed Deep Agent 资源。
- 一个独立的 [LangSmith tracing project](/langsmith/observability-concepts#projects)，用于该 agent。
- 一个 [Context Hub](/langsmith/use-the-context-hub) agent repo，用于存储托管文件树。

它不会创建 LangSmith Deployment。

Managed Deep Agent 的运行会记录到为该 agent 单独创建的 tracing project 中。你可以在 LangSmith 中打开 traces，查看运行期间产生的用户输入、最终回复、模型调用、工具调用、subagent 活动、文件和运行时状态。

Context Hub agent repo 会保存该 agent 的托管文件树，包括 instructions、skills、subagents 和 tool 配置。

## LangSmith sandbox backend

由 `deepagents-cli>=0.2.2` 生成的 Managed Deep Agents 项目默认使用 `state` backend：

```json
{
  "backend": {
    "type": "state"
  }
}
```

LangSmith sandboxes 是隔离环境，用于执行代码、访问文件系统等操作，而不会影响你的主基础设施。在 Managed Deep Agents 中，它们为 agent 提供一个适合长任务运行的托管运行时，而底层 sandbox 生命周期由 LangSmith 负责管理。

请选择适合你使用范围的 backend：

- `state`：不启用任何 sandbox 特有 backend 行为。
- `sandbox` 且 `sandbox_config.scope: "thread"`：sandbox 资源按 thread 隔离。
- `sandbox` 且 `sandbox_config.scope: "agent"`：sandbox 资源按 agent 隔离，而不是按单个 thread。

关于独立 sandbox 概念，请参见 [LangSmith sandboxes overview](/langsmith/sandboxes)。关于 Managed Deep Agents 的配置字段与校验规则，请参见 [Deploy an agent](/langsmith/managed-deep-agents-deploy#choose-a-backend) 和 [CLI reference](/langsmith/managed-deep-agents-cli#project-file-reference)。

## 限制与说明

以下是 private beta 期间适用的运行说明。在正式 GA 前，这些行为仍可能调整。

### 稳定的部署体验

在 private beta 期间，Managed Deep Agents deploy 通过 beta 版 CLI 提供。稳定版 Deep Agents deploy 体验仍将继续有效，直到 Managed Deep Agents 进入 public beta，并且 deploy 命令切换到新行为。

### 支持的模型

模型标识符应使用 `{provider}:{model_id}` 形式，例如 `openai:gpt-5.5`。运行时会通过 `init_chat_model` 解析模型，因此凡是 `init_chat_model` 支持的 provider，都可以在 Managed Deep Agents 中使用。当前可用列表请参见 [Supported providers and models](/oss/langchain/models#supported-providers-and-models)。

如果值中不包含冒号，系统会将其解释为某个已保存 Playground 配置的引用，而不是模型标识符。因此在直接配置模型时，请始终提供完整的 `{provider}:{model_id}` 形式。

### Thread 保留策略

在 private beta 期间，threads 没有保留时间窗口，也没有按工作区限制数量。你可以按需创建任意数量的 threads。已有 threads 在整个 beta 期间都可访问。

### 速率限制与配额

在 private beta 期间，Managed Deep Agents endpoint 不会对每个 key、每个工作区或每个 agent 施加请求速率限制。

### Agent 限制

免费的 LangSmith 工作区最多只能创建一个 Managed Deep Agent。付费方案则可以创建无限数量的 agent。如果免费工作区已达到上限，则 `deepagents deploy` 和 `POST /v1/deepagents/agents` 会返回 `HTTP 409`，并提示你删除已有 agent 或升级套餐。

### 删除 agents

`DELETE /v1/deepagents/agents/{agent_id}` 不会级联删除 threads。针对已删除 agent 创建的 threads 仍可查询，但不能再发起新的 runs。如果你想彻底清理，需要显式跟踪并删除这些 threads。

### API 稳定性

当前路由位于 `/v1/deepagents` 下，但整个接口在 private beta 阶段仍可能发生变化。若有破坏性变更，会通过你获得访问权限时提供的联系方式直接通知 beta 用户。

### 支持与反馈

Beta 访问包含直接支持。Bug 报告和功能请求的联系渠道，会包含在你获得访问权限时收到的邮件中。

## Private beta 范围

Managed Deep Agents 在 private beta 期间仅面向美国区域的 LangSmith Cloud 提供。暂不支持 Self-hosted 与 Hybrid 部署，EU 及其他区域预计会在 GA 之后支持。

同时，在 private beta 期间，其 API 也不会完整镜像 LangSmith Deployment 的所有 endpoint。Managed Deep Agent 不是 LangSmith Deployment。
