Managed Deep Agents 是 LangSmith 中用于部署和运行代码优先 Deep Agents 的托管运行时，它将 [Deep Agents](/oss/deepagents/overview) harness 与托管基础设施结合起来。你无需自行搭建 agent server 或底层基础设施，就可以运行生产级 agent。你可以用 Python 或 TypeScript 编写 agent，然后使用 `mda` CLI 进行本地测试并部署到托管运行时。

托管运行时提供：

- Durable runs
- [LangSmith sandboxes](/langsmith/sandboxes)
- 基于 [Context Hub](/langsmith/use-the-context-hub) 的 instructions、skills 和 memory
- Traces
- 托管的 LangGraph deployment

要部署第一个 agent，请参见 [quickstart](/langsmith/managed-deep-agents-quickstart)。

## 何时使用 Managed Deep Agents

根据你对控制权和基础设施的需求选择合适的路径：

| 路径 | 适用场景 | 你负责 | LangSmith 负责 |
|------|----------|--------|----------------|
| **Managed Deep Agents** | 你想把代码优先 Deep Agent 快速部署到托管基础设施。 | Agent 代码、tools、middleware、instructions、schedules。 | Backend、store、checkpointer、memory、skills、sandbox、托管 deployment。 |
| **[LangSmith Deployment](/langsmith/deployment-quickstart)** | 你需要自定义应用代码、自定义路由、更高级认证、更强隔离能力或更高扩展性。 | 应用代码、server、deployment 配置。 | 托管基础设施与伸缩能力。 |
| **[OSS Deep Agents](/oss/deepagents/overview)** | 你想在自己的环境中运行 Deep Agents harness。 | 包括托管与持久化在内的一切。 | 无，自行管理。 |

## 组织你的 agent 项目

Managed Deep Agent 是一个本地项目目录。文件所在的位置决定了它的角色：CLI 会读取目录结构，识别 agent 入口、托管 instructions、skills、connectors、schedules 和 sandbox 配置，然后把这些内容打包为一个托管 deployment。

完整目录结构与打包规则请参见 [CLI project file reference](/langsmith/managed-deep-agents-cli#project-file-reference)。如果想了解 CLI 如何编译该目录，以及一次 deploy 会创建什么，请参见 [How Managed Deep Agents work](/langsmith/managed-deep-agents-how-it-works)。

## 推荐工作流

1. 为 Python 或 TypeScript 安装 `managed-deepagents`。
2. 使用 `mda init` 创建本地代码优先 agent 项目。
3. 把 agent 的 system prompt 放进 `instructions.md`。
4. 添加自定义 tools、middleware、schedules、skills、MCP connectors，以及可选的 sandbox。
5. 使用 `mda dev` 在本地 LangSmith Studio 中测试 agent，然后使用 `mda deploy` 部署到 LangSmith。
6. 在 LangSmith 中检查 deployment、traces 和运行时状态。

如果你刚接触 Managed Deep Agents，先从 [quickstart](/langsmith/managed-deep-agents-quickstart) 开始，再通过 [tutorial](/langsmith/managed-deep-agents-tutorial) 逐步构建一个完整 agent。

## Beta 说明与限制

以下运行说明适用于 private beta 期间，行为可能在正式 GA 前发生变化。

### 支持的模型

模型标识符应使用 `{provider}:{model_id}` 格式，例如 `openai:gpt-5.5`。运行时通过 `init_chat_model` 解析模型，因此只要运行时拥有对应 provider 的凭据，任何 `init_chat_model` 支持的 provider 都可以在 Managed Deep Agents 中使用。当前列表请参见 [Supported providers and models](/oss/langchain/models#supported-providers-and-models)。

你可以把本地密钥放在 `.env` 中，在 shell 中导出，或配置为 LangSmith workspace secrets 后再部署。

### Context Hub memory

托管 memory 存储在与部署 instructions 和 skills 相同的 Context Hub repo 中，路径为 `/memories/AGENTS.md`。部署时会同步 `instructions.md` 和 `skills/**`，但会保留已有的 `memories/**` 文件，不会覆盖运行时创建的 memory。将 `disableMemory: true` 或 `disable_memory=True` 设为真，只会禁用内置的 agent 级 memory。关于 memory 的持久化方式，请参见 [How Managed Deep Agents work](/langsmith/managed-deep-agents-how-it-works#threads-and-memory)。

### 速率限制与配额

在 private beta 期间，Managed Deep Agents 不公开按 key、workspace 或 agent 维度的请求速率限制。工作区级限制请联系 beta 访问邮件中的 LangChain 团队联系人。

### 支持与反馈

Beta 访问包含直接支持。Bug 报告和功能请求的联系渠道，会包含在你获得访问权限时收到的邮件中。

### Private beta 范围

Managed Deep Agents 在 private beta 期间仅支持美国区域的 LangSmith Cloud。当前不支持 Self-hosted 或 Hybrid 部署。
