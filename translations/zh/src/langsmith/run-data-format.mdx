LangSmith 会将每个 [run](/langsmith/observability-concepts) 存储为结构化记录。理解这种格式，对于导出 traces、查询 API 或构建集成都很有帮助。

| Field Name                    | Type             | Description                                                                                                                   |
| ----------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **`id`**                        | UUID             | span 的唯一标识符。                                                                                               |
| **`name`**                      | string           | 与该 run 关联的名称。                                                                                             |
| **`inputs`**                    | object           | 传给该 run 的输入映射。对于 `run_type='llm'` 的 runs，这里通常包含一个 `messages` 数组，里面是发送给模型的消息对象。                                                                                   |
| **`run_type`**                 | string           | [run 的类型](#run-types)，例如 `'llm'`、`'chain'`、`'tool'`。                                                            |
| **`start_time`**               | datetime         | run 的开始时间。                                                                                                        |
| **`end_time`**                 | datetime         | run 的结束时间。                                                                                                          |
| **`extra`**                     | object           | run 的额外信息。                                                                                                    |
| **`error`**                     | string           | 如果 run 执行时遇到错误，这里会记录错误消息。                                                                                |
| **`outputs`**                   | object           | run 生成的输出映射。对于 `run_type='llm'` 的 runs，这里通常包含一个 `messages` 数组，里面是模型返回的消息对象。                                                                                 |
| **`events`**                    | array of objects | 与 run 关联的事件对象列表。对于以流式方式执行的 runs，这个字段尤为相关。                           |
| **`tags`**                      | array of strings | 与该 run 关联的 tags 或 labels。                                                                                       |
| **`trace_id`**                 | UUID             | 该 run 所属 trace 的唯一标识符，同时也是该 trace 根 run 的 `id` 字段。                |
| **`dotted_order`**             | string           | [排序字符串](#what-is-dotted_order)，具有层级结构。格式为：`<run_start_time>Z<run_uuid>`.`<child_run_start_time>Z<child_run_uuid>`...                 |
| **`status`**                    | string           | run 执行的当前状态，例如 `'error'`、`'pending'`、`'success'`。                                                      |
| **`child_run_ids`**           | array of UUIDs   | 所有子 runs 的 ID 列表。                                                                                               |
| **`direct_child_run_ids`**   | array of UUIDs   | 该 run 的直接子节点 ID 列表。                                                                                  |
| **`parent_run_ids`**          | array of UUIDs   | 所有父级 runs 的 ID 列表。                                                                                              |
| **`feedback_stats`**           | object           | 该 run 的反馈统计聚合结果。                                                                              |
| **`reference_example_id`**    | UUID             | 与该 run 关联的参考 example 的 ID。这个字段通常只会出现在 evaluation runs 中。                          |
| **`total_tokens`**             | integer          | run 处理的 token 总数。                                                                                  |
| **`prompt_tokens`**            | integer          | run 的 prompt 部分所使用的 token 数。                                                                                    |
| **`completion_tokens`**        | integer          | run 的 completion 部分所使用的 token 数。                                                                                |
| **`total_cost`**               | decimal          | 处理该 run 的总成本。                                                                                |
| **`prompt_cost`**              | decimal          | prompt 部分对应的成本。                                                                              |
| **`completion_cost`**          | decimal          | completion 部分对应的成本。                                                                               |
| **`first_token_time`**        | datetime         | 模型输出第一个 token 生成的时间。仅适用于 `run_type="llm"` 且启用了流式输出的 runs。 |
| **`session_id`**               | string           | 该 run 的 session 标识符，也可理解为 tracing project ID。                                                         |
| **`in_dataset`**               | boolean          | 表示该 run 是否被纳入某个 dataset。                                                                           |
| **`parent_run_id`**           | UUID             | 父级 run 的唯一标识符。                                                                                          |
| `execution_order` (deprecated) | integer          | 该 run 在 trace 中的执行顺序。                                                                    |
| `serialized`                    | object           | 如果适用，执行该 run 的对象的序列化状态。                                                               |
| `manifest_id` (deprecated)     | UUID             | 与该 span 关联的 manifest 标识符。                                                                           |
| `manifest_s3_id`              | UUID             | manifest 的 S3 标识符。                                                                                               |
| `inputs_s3_urls`              | object           | inputs 对应的 S3 URLs。                                                                                                       |
| `outputs_s3_urls`             | object           | outputs 对应的 S3 URLs。                                                                                                      |
| `price_model_id`              | UUID             | 应用于该 run 的定价模型标识符。                                                                          |
| `app_path`                     | string           | 该 run 对应的应用（UI）路径。                                                                                           |
| `last_queued_at`              | datetime         | 该 span 最近一次进入队列的时间。                                                                                                |
| `share_token`                  | string           | 用于共享访问该 run 数据的 token。                                                                                   |

## Run types

`run_type` 字段用于标识一个 span 代表哪类操作。LangSmith 会用它在 trace UI 中应用合适的渲染方式，并启用对应类型的专属能力。

| Run type | Description |
|----------|-------------|
| `chain` | 一系列步骤，或多个步骤的组合。 |
| `llm` | 一次语言模型调用。 |
| `embedding` | Embedding API 调用。（在 UI 中显示为 `chain` 图标。） |
| `prompt` | 一个 [prompt template](/langsmith/prompt-template-format)，它会在把输入传给模型前先进行格式化。 |
| `tool` | 由模型触发的函数或外部操作。 |
| `retriever` | 用于获取相关文档或上下文的检索操作。 |
| `parser` | 一个输出解析器，用来把原始模型输出转换成结构化格式。 |

在通过 [`@traceable`](/langsmith/annotate-code#use-%40traceable-%2F-traceable) 或 [`RunTree`](/langsmith/annotate-code#use-the-runtree-api) 打点时，请设置 @[`run_type`][run_type]：

<CodeGroup>
```python Python
from langsmith import traceable

@traceable(run_type="tool")
def my_tool(query: str) -> str:
    ...
```
```typescript TypeScript
import { traceable } from "langsmith/traceable";

const myTool = traceable(
  async (query: string): Promise<string> => {
    // ...
  },
  { run_type: "tool" }
);
```
</CodeGroup>

某些 run types 在 LangSmith UI 中还有专门的 trace 视图：

- [Log LLM calls](/langsmith/log-llm-trace)
- [Log retriever traces](/langsmith/log-retriever-trace)

## What is `dotted_order`?

一个 run 的 `dotted_order` 是一个可排序的 key，它完整描述了该 run 在 tracing 层级结构中的位置。

看下面这个例子：

```python
import langsmith as ls

@ls.traceable
def grandchild():
    p("grandchild")

@ls.traceable
def child():
    grandchild()

@ls.traceable
def parent():
    child()
```

如果你在每个阶段打印出 ID，可能会得到如下结果：

```python
parent	run_id=0e01bf50-474d-4536-810f-67d3ee7ea3e7	trace_id=0e01bf50-474d-4536-810f-67d3ee7ea3e7  parent_run_id=null	dotted_order=20240919T171648521691Z0e01bf50-474d-4536-810f-67d3ee7ea3e7
child	run_id=a8024e23-5b82-47fd-970e-f6a5ba3f5097	trace_id=0e01bf50-474d-4536-810f-67d3ee7ea3e7  parent_run_id=0e01bf50-474d-4536-810f-67d3ee7ea3e7	dotted_order=20240919T171648521691Z0e01bf50-474d-4536-810f-67d3ee7ea3e7.20240919T171648523407Za8024e23-5b82-47fd-970e-f6a5ba3f5097
grandchild	run_id=0ec6b845-18b9-4aa1-8f1b-6ba3f9fdefd6	trace_id=0e01bf50-474d-4536-810f-67d3ee7ea3e7  parent_run_id=a8024e23-5b82-47fd-970e-f6a5ba3f5097	dotted_order=20240919T171648521691Z0e01bf50-474d-4536-810f-67d3ee7ea3e7.20240919T171648523407Za8024e23-5b82-47fd-970e-f6a5ba3f5097.20240919T171648523563Z0ec6b845-18b9-4aa1-8f1b-6ba3f9fdefd6
```

请注意几个不变条件：

* `id` 等于 `dotted_order` 最后 36 个字符，也就是最后一个 `'Z'` 之后的后缀。以 grandchild 为例，就是 `0ec6b845-18b9-4aa1-8f1b-6ba3f9fdefd6`。
* `trace_id` 等于 `dotted_order` 中的第一个 UUID，也就是 `dotted_order.split('.')[0].split('Z')[1]`
* 如果存在 `parent_run_id`，它就等于 `dotted_order` 中倒数第二个 UUID。以 grandchild 为例，就是 `a8024e23-5b82-47fd-970e-f6a5ba3f5097`。
* 如果你按点号拆分 `dotted_order`，每一段都遵循 `(<run_start_time>Z<run_id>)` 这种格式。
