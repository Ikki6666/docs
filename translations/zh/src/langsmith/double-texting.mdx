---
title: Double texting
sidebarTitle: 概览
---

<Info>
**前置条件**
* [Agent Server](/langsmith/agent-server)
</Info>

很多时候，用户会以非预期方式与你的 graph 交互。
例如，用户可能发送一条消息后，在 graph 还没运行完成前又发送了第二条消息。
更一般地说，用户可能会在第一次 run 结束之前，第二次调用 graph。
我们把这种情况称为 “double texting”。

[Enqueue](#enqueue-default) 是在 [Agent Server](/langsmith/agent-server) 中创建 runs 时默认的 double texting（multi-tasking）策略。

<Note>
Double texting 是 LangSmith Deployment 的一个特性，不适用于 [LangGraph 开源框架](/oss/langgraph/overview)。
</Note>

![Double-text strategies across first vs. second run: Reject keeps only the first; Enqueue runs the second afterward; Interrupt halts the first to run the second; Rollback reverts the first and reruns with the second.](/langsmith/images/double-texting.png)

## Enqueue (default)

该选项允许当前 run 完成之后，再处理任何新输入。传入请求会进入队列，并在先前 runs 完成后按顺序执行。

关于如何配置 enqueue 这种 double text 选项，请参阅对应的 [how-to guide](/langsmith/enqueue-concurrent)。

## Reject

该选项会在当前 run 进行中时拒绝任何额外传入的 runs，从而避免并发执行或 double texting。

关于如何配置 reject 这种 double text 选项，请参阅对应的 [how-to guide](/langsmith/reject-concurrent)。

## Interrupt

该选项会中止当前执行，并保留截至中断点之前已经取得的进度。新的用户输入随后会被插入，执行会从该状态继续。

使用此选项时，你的 graph 必须能够处理潜在边界情况。例如，某个工具调用可能已经发起，但在中断发生时尚未完成。在这类情况下，可能需要处理或移除这些部分完成的工具调用，以避免遗留未解决的操作。

关于如何配置 interrupt 这种 double text 选项，请参阅对应的 [how-to guide](/langsmith/interrupt-concurrent)。

## Rollback

该选项会中止当前执行，并回滚所有进度，包括最初的 run 输入，然后再处理新的用户输入。新的输入会被视为一次全新的 run，从初始状态开始执行。

关于如何配置 rollback 这种 double text 选项，请参阅对应的 [how-to guide](/langsmith/rollback-concurrent)。
