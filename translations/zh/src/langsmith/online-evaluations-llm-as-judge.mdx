[在线评估](/langsmith/evaluation-concepts#online-evaluations)会对生产 traces 提供实时反馈。这对于持续监控应用表现很有用，可以帮助你识别问题、衡量改进效果，并随着时间推移确保质量稳定。

**[LLM-as-a-judge](/langsmith/evaluation-concepts#llm-as-judge)** evaluators 使用 LLM 来评估 traces，作为类人判断的一种可扩展替代方案。本指南覆盖的是评估单个 run 的 **run-level** evaluators。如果你要评估整段会话 thread，请参阅[多轮在线 evaluators](/langsmith/online-evaluations-multi-turn)。

<Note>当在线 evaluator 作用于 trace 中的任意 run 时，该 trace 会自动升级为[extended data retention](/langsmith/usage-and-billing#data-retention-auto-upgrades)。这会影响 trace 计费，但能确保符合评估条件的 traces（通常也是最值得分析的那些）被保留下来以供调查。 </Note>

## 查看在线 evaluators

在 [LangSmith UI](https://smith.langchain.com) 中，进入 **Tracing Projects** 标签页并选择一个 tracing project。要查看该项目中已有的在线 evaluators，请点击 **Evaluators** 标签页。

## 添加在线 evaluator

1. 在 [LangSmith UI](https://smith.langchain.com) 中，进入 **Tracing** 页面并选择一个 tracing project。
1. 点击 **Evaluators** 标签页。
1. 点击 **+ Evaluator** 打开 **Add Evaluator** 面板。
1. 选择以下方式之一：
   - **Create from scratch**：选择 **LLM-as-a-Judge Evaluator**。
   - **Attach an existing evaluator**：选择工作区中已有 evaluator 进行复用。
   - **Create from a template**：从现成 evaluator 模板开始。
1. 为 evaluator 命名。

## 为触发 evaluator 的 runs 应用过滤器

你可以为会触发 evaluator 的 runs 设置过滤器。常见场景包括：

- 用户留下了[反馈](/langsmith/attach-user-feedback)，表明回答不令人满意的 runs。
- 调用了特定工具的 runs。更多信息请参阅[按 tool calls 过滤](/langsmith/filter-traces-in-application#example-filtering-for-tool-calls)。
- 匹配特定 metadata 的 runs（例如你在 trace 中记录了 `plan_type`，并且只想对企业客户的 traces 运行评估）。更多信息请参阅[给 traces 添加 metadata](/langsmith/add-metadata-tags)。

[Evaluator 上的 filters](/langsmith/filter-traces-in-application) 与你在项目中筛选 traces 的方式完全相同。

<Tip>
在为 evaluator 创建过滤器时，边看 runs 边调过滤条件通常很有帮助。保持 evaluator 配置面板打开时，你可以同时查看 runs 并对它们应用过滤器。你在 runs 表格中应用的任何过滤器，都会自动同步到 evaluator 的过滤器上。
</Tip>

<Tip>
如果你在这个项目上也配置了 webhook automation rule，并且希望 webhook payload 包含该 evaluator 的分数，请在 webhook rule 上添加 feedback filter，而不要依赖规则执行顺序。例如，可以使用 `has(feedback_key, "answer_usefulness")` 这样的过滤条件，让 webhook 只在分数已经存在后触发。详情请参阅[确保评估在 webhook 触发前完成](/langsmith/webhooks#ensuring-evaluations-complete-before-the-webhook-fires)。
</Tip>

## 配置采样率

配置采样率可以控制已过滤 runs 中有多少百分比会触发自动化动作。例如，为了控制成本，可能只想把 evaluator 应用到 10% 的 traces。在这种情况下，就应将采样率设置为 0.1。

## 将规则应用到历史 runs

可以通过打开 **Apply to past runs** 并填写 “Backfill from” 日期，将规则应用到历史 runs。该操作只在创建规则时可用。

<Note>
回填会作为后台作业处理，因此你不会立即看到结果。
</Note>

若要跟踪回填进度，可以进入 tracing project 内的 **Evaluators** 标签页，并点击所创建 evaluator 的 Logs 按钮查看日志。在线 evaluator 日志与[自动化规则日志](/langsmith/rules#view-logs-for-your-automations)类似。

1. 添加 evaluator 名称。
1. 可选地为想应用 evaluator 的 runs 设置过滤器，或者配置采样率。
1. 选择 **Apply Evaluator**。

## 将多模态内容映射到 evaluator

如果 traces 中包含图像、音频或文档等多模态内容，你也可以在 evaluator prompt 中使用这些内容。主要有两种方式：

- **使用 traces 中的 base64 编码内容**：如果你的应用把多模态内容以 base64 编码形式记录在 trace 中（例如保存在 run 的输入或输出中），你可以在 evaluator prompt 中使用模板变量直接引用这些内容。Evaluator 会从 trace 中提取 base64 数据并传给 LLM。
- **使用 traces 中的 attachments**：类似于[带附件的离线评估](/langsmith/evaluate-with-attachments)，你也可以在在线评估中使用 traces 自带的 attachments。由于这些 traces 已通过 SDK 记录了 attachments，你可以直接引用它们。
    1. 从 dataset 页面选择 **+ Evaluator**。
    1. 在 **Template variables** 编辑器中，为要包含的 attachment(s) 添加变量：
        - 如果只想包含某个特定 attachment，可以使用建议的变量名，例如 `{{attachment.file_name}}`，这会把 attachment 列表中名为 `file_name` 的文件映射给 evaluator。
        - 如果想包含所有 attachments，则使用 `{{attachments}`}` 变量。

Evaluator 随后就可以在评估 trace 时访问这些 attachments。这对以下类型的 evaluators 特别有用：

- 验证图像描述是否与 trace 中的实际图像一致。
- 检查转录内容是否准确反映了音频输入。
- 验证从文档中提取的文本是否正确。
