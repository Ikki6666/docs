本页介绍仅适用于 [Cloud](/langsmith/cloud) 部署的平台特性。对应的自托管能力请参阅[部署到自托管环境](/langsmith/deploy-to-self-hosted-overview)。

## 数据区域

Deployments 可以创建在两个数据区域中：US 和 EU。

某个 deployment 的数据区域由其创建所在 LangSmith organization 的数据区域决定。Deployments 及其底层数据库都不能在不同数据区域之间迁移。

## 静态 IP 地址

所有在 2025 年 1 月 6 日之后创建的 deployments，其流量都会经过 NAT gateway。该 NAT gateway 会根据数据区域拥有若干静态 IP 地址。静态 IP 地址列表请参阅[Allowlist IP addresses table](/langsmith/deploy-to-cloud#allowlist-ip-addresses)。

## Payload 大小

发送到 Cloud deployments 的所有请求，其最大 payload 大小为 25MB。超过 25MB 的请求会返回 `413 Payload Too Large` 错误。

## Deployment 类型

Control plane 提供两种 deployment 类型：Serverless 和 Dedicated。每种类型都提供三种规格：Small、Medium 和 Large。

仍在使用旧定价的组织，在 2026 年 10 月 1 日之前仍可继续创建 Development 和 Production deployments。这些类型不支持缩容到零。如需通过 CLI 选择它们，请传入 `--deployment-type dev` 或 `--deployment-type prod`。关于定价和过渡时间表，请参阅[计费管理](/langsmith/billing#langsmith-deployment-billing)。关于 `--deployment-type` 取值的完整列表，请参阅 [`langgraph deploy`](/langsmith/cli#deploy)。

| **Deployment type** | **Scaling** | **Database** | **Best for** |
|---|---|---|---|
| Serverless | 不活跃后缩容到零，下一个请求时唤醒 | 共享、多租户 | 后台或对延迟容忍的 agent，以及开发/测试 deployment |
| Dedicated | 始终在线，跨 replicas 自动扩缩容 | 独享，带自动备份和高可用 | 处于关键路径上的生产工作负载 |

<Warning>
**不可变 deployment 类型**
一旦 deployment 创建完成，就无法更改 deployment 类型。但你仍可以更改它的[规格](#sizes)。
</Warning>

### Serverless

Serverless deployments 针对后台和对延迟容忍的 agent，以及开发、测试和预发布分支进行了成本优化。Serverless deployment 在一段时间不活跃后会缩容到零，并在下一个请求时唤醒。在资源 provision 期间都会计收计算费用，包括缩容前的空闲时间。这使其非常适合间歇性运行、或能够容忍短暂启动延迟的 agent，因为缩容后的第一个请求在 deployment 启动期间需要更长时间才能响应。

对于需要持续低延迟或保证正常运行时间的工作负载，请改用 Dedicated。Serverless deployments 运行在共享的多租户基础设施上。

<Note>
缩容到零目前处于 [beta](/langsmith/release-stages) 阶段，初期仅适用于采用新的基于用量计费的 deployments。在功能逐步推出期间，缩容前的不活跃时间窗口可能会有变化。关于定价和过渡时间表，请参阅[计费管理](/langsmith/billing#langsmith-deployment-billing)。
</Note>

Agent Server 具备容错能力：它会自动从临时的 Redis 或 Postgres 中断中恢复，并重试失败的后台 runs。

### Dedicated

Dedicated deployments 始终在线，专为处于关键路径上的生产工作负载（例如面向客户的应用）而设计。每个 Dedicated deployment 都拥有自己的数据库，带有自动备份和高可用，并会随着负载增加跨 replicas 自动扩缩容。详情请参阅[扩缩容](#scaling)。

对于 Dedicated deployments，可以根据具体用例和容量约束按个案增加资源。如需申请增加资源，请通过 [support.langchain.com](https://support.langchain.com) 联系支持团队。

### Sizes

Serverless 和 Dedicated 都提供三种规格：Small、Medium 和 Large。每种规格设定了 deployment 所 provision 的计算和内存，规格越大，自动扩缩容的 replicas 数量也越多。下表列出了每种规格包含的资源：

| Resource | Serverless S | Serverless M | Serverless L | Dedicated S | Dedicated M | Dedicated L |
|---|---|---|---|---|---|---|
| Runtime compute (vCPU) | 1 | 5 | 9 | 3 | 5 | 10 |
| Runtime memory (GiB) | 3 | 6 | 11 | 6 | 12 | 24 |
| Database compute (vCPU) | — | — | — | 1 | 2 | 4 |
| Database memory (GiB) | — | — | — | 4 | 8 | 16 |
| Storage | Shared | Shared | Shared | Auto-scaling | Auto-scaling | Auto-scaling |

<Note>
Runtime compute 和 memory 是 deployment 各容器所 provision 的 vCPU 和内存总和，按最接近的整数取整。Serverless deployments 使用共享的多租户数据库，因此没有专属的数据库资源。Dedicated 的存储是一块随用量自动扩容的磁盘。
</Note>

关于每种规格的价格，请参阅[定价页面](https://www.langchain.com/pricing)，其中包含 deployment 成本计算器。关于 Serverless 和 Dedicated deployments 的计费方式，请参阅[计费管理](/langsmith/billing#langsmith-deployment-billing)。

## 数据库配置

Control plane 与 [data plane](/langsmith/data-plane) listener application 会协同工作，为每个 Cloud deployment 自动创建一个 Postgres 数据库。该数据库充当 deployment 的[持久化层](/oss/langgraph/persistence#memory-store)。

在实现 LangGraph 应用时，无需手动配置 [checkpointer](/oss/langgraph/persistence#checkpointer-libraries)。系统会自动为 graph 配置一个 checkpointer。任何为 graph 显式配置的 checkpointer，都会被自动配置的那个替换。

无法直接访问数据库。所有数据库访问都必须通过 [Agent Server](/langsmith/agent-server)。

只有当 deployment 自身被删除时，数据库才会被删除。

关于自托管部署，请参阅[自定义 PostgreSQL 配置](/langsmith/self-hosted-platform-features#custom-postgresql)。

## 扩缩容

Cloud deployments 会自动扩缩容；你不需要直接配置 queue workers、replicas 或 pool sizes。Dedicated deployment 会基于 CPU 利用率、内存利用率和 pending run 数量来增减 replicas，上限为该规格所允许的最大值。每个指标都会独立评估，并按照需要最多 replicas 的那个指标来扩容。[Queue workers](/langsmith/agent-server#runtime-architecture) 按 pending run 数量扩缩容，而 [API servers](/langsmith/agent-server#runtime-architecture) 按 CPU 和内存扩缩容，因此读取流量不会拖慢 run 提交，反之亦然。为避免在突发负载下频繁抖动，缩容动作会延迟执行。

自动扩缩容只改变 replicas 的数量，每个 replica 可用的 CPU 和内存由 deployment 的[规格](#sizes)固定。如果某个 deployment 持续承受 CPU 或内存压力，请将其升级到更大的规格。规格变更会以无停机的新 revision 方式推出；但 deployment 类型无法更改。

应用层的扩缩容手段（durability modes、异步模式、避免同步阻塞、使用 `/join` 而非轮询）对 Cloud 和自托管同样适用。底层概念请参阅[自托管环境下的扩缩容](/langsmith/agent-server-scale)；但其中涉及的 Helm 和资源配置不适用于 Cloud。
