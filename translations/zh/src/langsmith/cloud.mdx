**Cloud** 托管选项是一种完全托管模式，由 LangChain 托管并运维全部 LangSmith 基础设施和服务：

- **Fully managed infrastructure**：LangChain 负责所有基础设施、更新、扩缩容和维护。
- [**LangSmith UI**](https://smith.langchain.com)：完整访问 [observability](/langsmith/observability)、[evaluation](/langsmith/evaluation)、[agent deployment management](/langsmith/deployment) 和 [Studio](/langsmith/studio)。
- **Deploy Agent Servers from GitHub**：连接你的仓库，只需几次点击即可将 [Agent Servers](/langsmith/deployment) 部署到 Cloud。
- **Automated CI/CD for Agent Servers**：你的 [Agent Servers](/langsmith/deployment) 的构建和部署流程由平台自动处理。

|                   | **由谁管理** | **运行位置** |
|-------------------|-------------------|-------------------|
| **LangSmith platform (UI, APIs, datastores)** | LangChain | LangChain 的云环境（AWS 和 GCP） |
| **Your Agent Servers** | LangChain | LangChain 的云环境（AWS 和 GCP） |
| **CI/CD for your apps** | LangChain | LangChain 的云环境（AWS 和 GCP） |

<Callout icon="rocket" color="#4F46E5" iconType="regular">
如果你已经准备好将应用部署到 LangSmith Cloud（AWS 或 GCP），请参阅 [Cloud deployment quickstart](/langsmith/deployment-quickstart) 或 [full setup guide](/langsmith/deploy-to-cloud)。本页面用于说明 Cloud 托管架构，供参考使用。
</Callout>

## Cloud 架构与可扩展性

<Note>
本节仅适用于托管在 [https://smith.langchain.com](https://smith.langchain.com)、[https://eu.smith.langchain.com](https://eu.smith.langchain.com)、[https://apac.smith.langchain.com](https://apac.smith.langchain.com) 和 [https://aws.smith.langchain.com](https://aws.smith.langchain.com) 上的云托管 LangSmith。

如需了解自托管版本，请参阅 [Self-hosted documentation](/langsmith/self-hosted)。

LangSmith 在美国、欧盟和 APAC 的 SaaS 区域托管在 Google Cloud Platform (GCP) 上，在 AWS 托管的美国 SaaS 区域托管在 Amazon Web Services (AWS) 上。该平台具备高可扩展性，许多客户都在 LangSmith 上运行生产级 LLM 应用 observability、evaluation 和 agent deployment 工作负载。

位于美国的 LangSmith 服务，默认 GCP 区域，托管在 GCP 的 `us-central1`（Iowa）。

<Note>
[EU-based LangSmith service](https://eu.smith.langchain.com) 已可用，托管在 GCP 的 `europe-west4`（Netherlands）。如果你希望在该区域使用 Enterprise 计划，请 [contact our sales team](https://www.langchain.com/contact-sales)。
</Note>

<Note>
截至 2026 年 4 月，LangSmith SaaS 已在 AWS 的 `us-east-2`（Ohio）提供服务。
</Note>

<Note>
截至 2026 年 5 月，LangSmith SaaS 已在 APAC 的 GCP `australia-southeast1`（Sydney）提供服务。
</Note>

### GCP 服务

以下内容适用于 **US、EU 和 APAC** 三个部署在 GCP 上的 SaaS 区域。

LangSmith 由以下服务构成，全部托管在 Google Kubernetes Engine (GKE) 上：

- LangSmith Frontend：提供 LangSmith UI。
- LangSmith Backend：提供 LangSmith API。
- LangSmith Platform Backend：处理认证和其他高吞吐内部任务。（内部服务）
- LangSmith Playground：负责将 Playground 功能中的请求转发给各类 LLM 提供商。
- LangSmith Queue：负责处理异步任务。（内部服务）

LangSmith 使用以下 GCP 存储服务：

- Google Cloud Storage (GCS) 用于存储 run 的输入和输出。
- Google Cloud SQL PostgreSQL 用于事务型工作负载。
- Google Cloud Memorystore for Redis 用于队列和缓存。
- 部署在 GCP 上的 Clickhouse Cloud 用于 trace ingest 和分析。我们的服务通过私有 endpoint 连接到同一区域的 Clickhouse Cloud。

我们还使用了一些额外的 GCP 服务：

- Google Cloud Load Balancer 用于将流量路由到 LangSmith 服务。
- Google Cloud CDN 用于缓存静态资源。
- Google Cloud Armor 用于安全防护和速率限制。关于我们施加的速率限制，请参阅 [Rate limits](/langsmith/usage-and-billing#rate-limits)。

### AWS 服务

以下内容适用于部署在 `us-east-2`（Ohio）的 **AWS US** SaaS 区域。相同的 LangSmith 逻辑组件运行在 **Amazon EKS** 上，而不是 GKE。

LangSmith 由以下服务构成，全部托管在 Amazon EKS 上：

- LangSmith Frontend：提供 LangSmith UI。
- LangSmith Backend：提供 LangSmith API。
- LangSmith Platform Backend：处理认证和其他高吞吐内部任务。（内部服务）
- LangSmith Playground：负责将 Playground 功能中的请求转发给各类 LLM 提供商。
- LangSmith Queue：负责处理异步任务。（内部服务）

LangSmith 使用以下 AWS 存储和数据服务：

- Amazon S3 用于存储 run 的输入和输出。
- Amazon RDS for PostgreSQL 用于事务型工作负载。
- Amazon ElastiCache for Redis 用于队列和缓存。
- 通过 AWS PrivateLink 连接的 ClickHouse Cloud，位于 `us-east-2`，用于 trace ingest 和分析，并与上文 [regional storage](#regional-storage) 表格保持一致。

我们还使用了一些额外的 AWS 服务：

- Elastic Load Balancing（Network Load Balancers）和 Istio ingress，用于将流量路由到 LangSmith 服务。文档中定义的 API rate limit 在 Istio ingress gateway 上执行。详情请参阅 [Rate limits](/langsmith/usage-and-billing#rate-limits)。
- Amazon CloudFront 用于缓存静态资源，包括 web UI 主机名 `aws.smith.langchain.com`。
- 部署在 CloudFront 上的 AWS WAF，用于边缘层的托管规则组，例如 AWS Managed Rules common protections 和 Bot Control。

## Private connectivity (Enterprise)

<Callout icon="lock" color="#4F46E5" iconType="regular">
[**仅限 Enterprise。**](/langsmith/pricing-plans) Private connectivity 仅对 Enterprise 客户提供。请联系你的客户代表或发邮件至 [sales@langchain.dev](mailto:sales@langchain.dev) 以启用该功能。
</Callout>

Enterprise 客户可以通过 **AWS PrivateLink** 或 **GCP Private Service Connect (PSC)** 连接到 LangSmith，而无需将流量暴露到公共互联网。

### AWS PrivateLink

在 **AWS** 上的客户可以通过 [AWS PrivateLink](https://docs.aws.amazon.com/vpc/latest/privatelink/) 连接到 LangSmith，从任意 VPC 提供私有连接，并且原生支持跨区域连接。

#### Endpoint service name

| Region | Service Name |
|--------|-------------|
| US (`us-east-2`) | `com.amazonaws.vpce.us-east-2.vpce-svc-054f37092752bff6b` |

#### Setup

**1. Request access：** 向你的客户代表或 [sales@langchain.dev](mailto:sales@langchain.dev) 提供 AWS account ID，LangChain 会将你的账号加入 endpoint service 的 allowed principals 列表。

**2. Create an Interface VPC Endpoint**：在你的 AWS account 中创建 Interface VPC Endpoint。为它附加一个 security group，允许来自 VPC CIDR，或需要访问 LangSmith 的实例，访问 **TCP 443 inbound**：

<CodeGroup>
```bash AWS CLI
aws ec2 create-vpc-endpoint \
  --vpc-id <YOUR_VPC_ID> \
  --service-name <SERVICE_NAME_FROM_TABLE_ABOVE> \
  --vpc-endpoint-type Interface \
  --subnet-ids <YOUR_SUBNET_IDS> \
  --security-group-ids <YOUR_SECURITY_GROUP_ID> \
  --region <YOUR_REGION>
```

```hcl Terraform
resource "aws_vpc_endpoint" "langsmith" {
  vpc_id              = "<YOUR_VPC_ID>"
  service_name        = "<SERVICE_NAME_FROM_TABLE_ABOVE>"
  vpc_endpoint_type   = "Interface"
  subnet_ids          = ["<YOUR_SUBNET_IDS>"]
  security_group_ids  = ["<YOUR_SECURITY_GROUP_ID>"]
}
```
</CodeGroup>

**3. Wait for acceptance.** LangChain 会接受该连接。Endpoint 状态会从 `pendingAcceptance` 变为 `available`。在开始连通性测试之前，请再等待几分钟，让变更完全生效。

#### 配置 DNS

配置 DNS，使得在你的 VPC 内，`aws.api.smith.langchain.com` 解析到 VPC endpoint 的私有 DNS 名称。你可以使用任意私有 DNS 方案：Route 53 Private Hosted Zones、企业 DNS resolver，或 VPC 内可访问的任意 DNS 服务器。

首先，获取 endpoint 的 DNS 名称：

```bash
aws ec2 describe-vpc-endpoints \
  --vpc-endpoint-ids <YOUR_ENDPOINT_ID> \
  --query 'VpcEndpoints[0].DnsEntries[0].DnsName' \
  --output text --region <YOUR_REGION>
```

然后，创建一个 CNAME 记录，将 `aws.api.smith.langchain.com` 指向该 DNS 名称。下面是使用 Route 53 的示例：

<CodeGroup>
```bash AWS CLI
aws route53 create-hosted-zone \
  --name aws.api.smith.langchain.com \
  --vpc VPCRegion=<YOUR_REGION>,VPCId=<YOUR_VPC_ID> \
  --caller-reference langsmith-privatelink-$(date +%s) \
  --hosted-zone-config PrivateZone=true

aws route53 change-resource-record-sets \
  --hosted-zone-id <HOSTED_ZONE_ID> \
  --change-batch '{
    "Changes": [{
      "Action": "CREATE",
      "ResourceRecordSet": {
        "Name": "aws.api.smith.langchain.com",
        "Type": "CNAME",
        "TTL": 300,
        "ResourceRecords": [{"Value": "<ENDPOINT_DNS_NAME>"}]
      }
    }]
  }'
```

```hcl Terraform
resource "aws_route53_zone" "langsmith_privatelink" {
  name = "aws.api.smith.langchain.com"

  vpc {
    vpc_id = "<YOUR_VPC_ID>"
  }
}

resource "aws_route53_record" "langsmith_privatelink" {
  zone_id = aws_route53_zone.langsmith_privatelink.zone_id
  name    = "aws.api.smith.langchain.com"
  type    = "CNAME"
  ttl     = 300
  records = [aws_vpc_endpoint.langsmith.dns_entry[0]["dns_name"]]
}
```
</CodeGroup>

#### 验证连通性

从 VPC 中的 EC2 实例或容器执行：

```bash
curl https://aws.api.smith.langchain.com/ok
```

### GCP Private Service Connect

使用 **GCP** 的 Enterprise 客户可以通过 [Private Service Connect (PSC)](https://cloud.google.com/vpc/docs/private-service-connect) 连接到 LangSmith，无需将流量暴露到公共互联网。

#### Service attachment URIs

使用以下 service attachment URI 在你的 VPC 中创建 PSC endpoint：

| Region | Service Attachment URI |
|--------|----------------------|
| US (`us-central1`) | `projects/langchain-prod/regions/us-central1/serviceAttachments/gateway-psc-publish` |
| EU (`europe-west4`) | `projects/langchain-prod/regions/europe-west4/serviceAttachments/gateway-psc-publish` |
| APAC (`australia-southeast1`) | `projects/langchain-apac-prod/regions/australia-southeast1/serviceAttachments/gateway-psc-publish` |

#### PSC 域名

设置完成后，可使用以下域名通过 PSC 连接访问 LangSmith：

| Region | Domain |
|--------|--------|
| US | `us-central1.p.api.smith.langchain.com` |
| EU | `europe-west4.p.api.smith.langchain.com` |
| APAC | `australia-southeast1.p.api.smith.langchain.com` |

#### Setup

**Request access：** 向你的客户代表或 [sales@langchain.dev](mailto:sales@langchain.dev) 提供 GCP project ID。LangChain 会将你的项目加入 service attachment 的 allowed consumer 列表。

在授权完成后，可使用 gcloud CLI 或 Terraform 创建 PSC endpoint 并配置 DNS。

#### 创建 PSC endpoint

在你的 VPC 中创建一个 forwarding rule，目标指向该 service attachment：

<CodeGroup>
```bash gcloud CLI
# Create the PSC endpoint
gcloud compute forwarding-rules create langsmith-psc-endpoint \
  --region=<REGION> \
  --network=<YOUR_VPC_NETWORK> \
  --subnet=<YOUR_SUBNET> \
  --target-service-attachment=projects/langchain-prod/regions/<REGION>/serviceAttachments/gateway-psc-publish \
  --load-balancing-scheme=""

# Get the assigned IP address
gcloud compute forwarding-rules describe langsmith-psc-endpoint \
  --region=<REGION> \
  --format="value(IPAddress)"
```

```hcl Terraform
resource "google_compute_forwarding_rule" "langsmith_psc" {
  name                  = "langsmith-psc-endpoint"
  project               = "<YOUR_PROJECT_ID>"
  region                = "<REGION>"
  network               = "<YOUR_VPC_NETWORK>"
  subnetwork            = "<YOUR_SUBNET>"
  target                = "projects/langchain-prod/regions/<REGION>/serviceAttachments/gateway-psc-publish"
  load_balancing_scheme = ""
}
```
</CodeGroup>

#### 配置 DNS

在你的 VPC 中创建私有 DNS zone，并添加一条 A 记录指向 PSC endpoint IP：

<CodeGroup>
```bash gcloud CLI
# Create a private DNS zone
gcloud dns managed-zones create langsmith-psc \
  --dns-name="<REGION>.p.api.smith.langchain.com." \
  --visibility=private \
  --networks=<YOUR_VPC_NETWORK>

# Add an A record pointing to the PSC endpoint IP
gcloud dns record-sets create "<REGION>.p.api.smith.langchain.com." \
  --zone=langsmith-psc \
  --type=A \
  --rrdatas=<PSC_ENDPOINT_IP>
```

```hcl Terraform
resource "google_dns_managed_zone" "langsmith_psc" {
  name        = "langsmith-psc"
  project     = "<YOUR_PROJECT_ID>"
  dns_name    = "<REGION>.p.api.smith.langchain.com."
  visibility  = "private"

  private_visibility_config {
    networks {
      network_url = "<YOUR_VPC_NETWORK_SELF_LINK>"
    }
  }
}

resource "google_dns_record_set" "langsmith_psc" {
  name         = "<REGION>.p.api.smith.langchain.com."
  project      = "<YOUR_PROJECT_ID>"
  managed_zone = google_dns_managed_zone.langsmith_psc.name
  type         = "A"
  ttl          = 300
  rrdatas      = [google_compute_forwarding_rule.langsmith_psc.ip_address]
}
```
</CodeGroup>

#### 验证连通性

从 VPC 中的 VM 执行：

```bash
curl https://<REGION>.p.api.smith.langchain.com/ok
```

## API rate limits

LangSmith 会对 API endpoint 实施速率限制，以确保服务稳定性和公平使用。下表展示了 GCP US 和 GCP EU 区域中不同 endpoint 的速率限制。GCP APAC 和 AWS US 也会实施相近的服务级限制；如果你需要精确的组织级限制，请联系支持团队。请注意：

- Rate limit 以 `count / interval` 表示，其中 count 是在 interval，单位秒，内允许的请求数。例如，`2000 / 10` 表示每 10 秒允许 2000 个请求。
- 如果 endpoint 列中未指定 HTTP method，则该速率限制适用于该 endpoint 的所有 HTTP method。
- 如果列出了特定 method，例如 `POST`、`GET`，则该速率限制只适用于该 method。

| `/auth` | `x-api-key` | 2000 / 10 | 2000 / 10 | [High throughput](#rate-limit-categories) |
| `/auth` | `x-user-id` + IP | 2000 / 10 | 2000 / 10 | [High throughput](#rate-limit-categories) |

### Rate limit categories

- **High throughput**：用于认证、metadata 和 feedback 等核心操作的高吞吐 endpoint。
- **Repository**：仓库和 prompt 管理操作。
- **Run ingest**：用于 observability 的单条 trace/run 写入 endpoint。
- **Charts**：图表生成和可视化 endpoint。
- **Multipart ingest**：通过 multipart upload 进行的大规模 run ingest。
- **Run query (API)**：使用 API key 的 run 查询操作，对复杂查询施加更严格限制。
- **Run query (User)**：基于用户身份的 run 查询操作，适用于交互式使用，限制更高。
- **Generation**：AI 驱动的代码和内容生成 endpoint，用于防止滥用。
- **Commits**：Prompt 版本管理和 commit 操作。
- **Deletion**：Session 删除和 workflow trigger 操作。
- **Run lookup**：按 UUID 获取特定 run。
- **Examples**：获取用于 few-shot prompting 的 dataset example。
- **Default (API key)**：未命中特定规则时，对已认证 API 请求生效的默认速率限制。
- **Default (User)**：未命中特定规则时，对已认证用户请求生效的默认速率限制。
- **Public download**：面向共享资源的高吞吐公开下载 endpoint。
- **Stats**：Run 统计和分析 endpoint，可能存在区域差异。
- **Public (catch-all)**：未认证公开访问的默认速率限制。

如需了解更多 rate limit 和其他服务限制，请参阅 [Administration overview](/langsmith/usage-and-billing#rate-limits)。
