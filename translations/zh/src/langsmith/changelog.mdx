## Access control

- 访问策略 endpoints 现在以 RFC 7807 problem details 的形式报告错误。错误消息从 `error` 字段移至 `detail`，语义上无效的请求 body 会返回 HTTP 422。
- 将资源标签键或值的描述设置为 `null`，可通过 PATCH API 清除该描述。
- 当客户端请求 confidential 认证方式时，到托管 LangSmith MCP server 的新连接此前无法注册。动态客户端注册现在会在这种情况下签发一个 public client，而不是返回错误，因此从 Claude 和其他 MCP 客户端连接的功能已恢复。
- 角色权限和访问策略变更现在能可靠地使缓存的授权结果失效，包括当较旧的事务在较新的更新之后提交时。
- LangSmith 现在会在角色访问策略的权限发生变化时立即刷新缓存的策略，防止 split-plane 部署中出现陈旧的授权决策。
- Members 设置页面上的 Active、Pending 和 Deactivated 标签页现在可以在第一次点击时切换，同时保持分页和排序同步。

## Datasets and experiments

- Attachment 和 object 下载现在总是会声明浏览器应如何处理响应。类型无法识别或存储时未带类型的文件会以下载方式交付，而不是在页面中渲染。
- 从 Datasets 或 Home 空状态创建 dataset 时，现在会打开新的 dataset，而不是短暂显示 Page not found 页面。
- Dataset JSON schema 描述现在会在编辑器提示框中安全渲染。
- 使用格式不正确的 UUID 作为 `dataset_id` 创建或验证 example 时，现在会返回一个 422 并指出该字段，而不是 500。
- 使用不支持的 `filter` 表达式、不可过滤的属性，或值不是有效 JSON 的 `has(...)` 比较来列出或计数 examples 时，现在会返回一个 422 并指出 `filter` 参数，而不是 500。
- 创建 experiment 时不再转换同名的现有 tracing project。当存在冲突时，请重命名该 experiment 或选择一个新的 project 名称。
- 在大型 experiment comparison 结果中滚动时，不再在每次 lazy-load 时重新获取第一页 examples，从而减少冗余网络流量并缩短加载时间。

## Monitoring and alerting

- 仪表板上的图表标题在标题或描述较长时不再溢出或换行，描述现在会截断并显示一个悬停提示框以展示完整文本。展开图表操作也采用了标准的图标按钮悬停效果。
- 告警预览现在会以与告警评估一致的方式处理整数元数据及其字符串表示。

## Engine

- 为 organization 禁用 Engine 或为 project 暂停 Engine 时，现在会提供一个简短的提示询问原因，并支持可选评论。只需一次点击即可直接前往构建 Engine 的团队。
- Engine 支出控制现在会说明，达到月度上限时新的 runs 会暂停，而正在进行中的 runs 可能会完成并使计费支出超出上限。
- Engine 标签页在 Engine 开启之前再次对 tracing projects 可见，因此管理员可以启用它、成员可以申请访问、个人 organization 可以升级，所有操作都可以直接在该标签页中完成。
- Engine GitHub 设置现在会链接到 LangSmith Cloud 和自托管部署的设置说明，并在连接失败时提供更清晰的指引。
- Engine 对非 coding-agent board 的扫描现在会应用已配置的 priority chips、用户指令和 trace-scope 过滤器，而不是审查整个 project。
- Engine issue 描述现在会保留 Markdown 段落边界，因此更新、附加症状和修正内容仍然易于浏览。

## Feedback and evaluation

- Feedback 修正现在可以将分数重置为其原始值，包括零。
- 在 experiment comparison 视图中，按元数据分组和元数据列再次可选。
- Feedback card 的 Source 行中过长的 evaluator 名称现在会截断，而不是延伸到 card 之外；当某个 key 有多个条目时，已修正分数的编辑控件会避开分页箭头。
- 将 feedback 值切换到不同类别时，即使两个类别映射到相同的数值分数，现在也会保存。此前在 run 详情和 annotation queue rubrics 中该更改会被静默丢弃。
- 用于修正 evaluator 分数的铅笔图标现在仅在你有更新 feedback 权限时才会显示。此前任何能看到该分数的人都会看到它，而保存修正时会失败。
- LangSmith 现在在渲染评估 commit 链接时会拒绝带有凭据和非 GitHub 的远程 URL。
- 存储在 run 上的 attachments 现在会在 annotation queue 中审核时显示，包括 pairwise queue。此前仅显示内嵌在 run 输入或输出中的媒体。
- Evaluator 支出表格在 evaluator 没有过滤器时，会让 All runs 过滤器徽标保持非活动状态。
- Evaluators 页面上的每日 evaluator 支出、每周总计和支出上限监控现在会遵循当前选中的应用，而不是显示跨所有应用的数据。
- Evaluator 支出图表再次将其 evaluator 和 project/dataset 分组控件保留在图表标题中，便于访问。

## Tracing and observability

- 通过 gateway 统一 endpoint 发送的、带有 provider/model slug 的 chat model runs 现在会匹配模型定价规则，从而生成准确的 trace 成本。
- Insights 报告仅分析 traces，因此报告中过滤器的 "Is Trace" 条件现在已修复。此前将其设为 false 会生成一个成功运行但从未找到任何 insights 的报告。
- LangSmith Chat 现在会遵循 workspace OpenAI model 配置上的 Provider API 设置。配置为 Responses API 的模型不再回退到 Chat Completions，此前这会导致设置了 reasoning effort 的较新推理模型失败。
- 消息上的大型 PDF、JSON 和 CSV 预览现在会渲染，而不是显示空框，PDF 和 JSON 预览还在展开控件旁新增了在新标签页打开的控件。
- Trace 视图现在会从 SmithDB 获取 token 和 feedback 统计信息，而不再尝试不可用的 ClickHouse 查询。
- Thread 详情中的 waterfall 过滤器现在会保持深度嵌套匹配项可见，并在新摄取的 traces 仍在出现时保留过滤控件。
- LangSmith MCP 的 `fetch_runs` 工具现在可以包含调用参数，包括发送给 LLM 的工具和函数 schema，以便更轻松地诊断 tool-calling 问题。
- PDF attachment 图标现在在 attachment 列表中与其他文件类型保持一致对齐。
- Thread 查询 API 现在通过 `trace_filter`、`tree_filter` 和 `thread_filter` 支持 trace、run-tree 和 thread 级别的过滤表达式。
- 公共共享 trace 链接现在会在 trace 查询超时时显示 "temporarily unavailable, try again" 消息，而不是误导性的 "trace not found, ask the owner to re-share" 消息。
- 在未配置所选模型 API key 的情况下点击 starter prompt，现在会显示 add-a-key 表单，与输入消息时相同，而不是使请求失败。

## Prompts and playground

- 未配置凭据 secret 时，Vertex AI 上的 Claude 模型现在可以在 Playground 中成功加载，与 GCP Workload Identity 或 AWS IRSA 下现有 Gemini 行为一致。
- Prompts 页面现在支持按 prompt 类型、prompt 标签和 commit 标签过滤，因此你可以快速缩小列表范围，找到所需的 prompts。
- 当 Bedrock、Azure OpenAI 或 Vertex AI provider 必填字段留空时，model 配置现在会显示内联错误，而不是静默保存。
- Studio 的 chat 面板在发送消息和第一个流式 token 之间不再显示 "No data" 占位符。assistant 消息现在一旦有内容可显示就会出现。
- Playground 现在会将缺失的 AWS 凭据和其他 Bedrock 拒绝报告为请求错误，并附带 provider 自己的消息，而不是通用的服务器错误。
- Studio chat 现在会显示已耗时的响应状态、保留完整的流式响应，并跟随新输出，同时不会打断向上滚动的读者。

## Automations

- 通过 API 手动触发 automation rule 现在可以正常工作。`POST /runs/rules/{rule_id}/trigger` 以及 `POST /runs/rules/trigger` 的 `rule_ids` 形式此前会对每个请求返回 500。
- 你现在可以手动触发 workspace 中的任何 automation，包括仅 webhook、仅告警和延长保留期的 rules。此前触发 endpoint 仅识别一部分操作，对其余操作返回 not found。
- 配置了 OpenAI 兼容或 Anthropic 兼容自定义 endpoint 的在线 evaluators，现在会在实时 traces 上使用该 endpoint 自己的 URL 和 API key，而不是因认证错误而失败。自定义 endpoint 上的 evaluators 不计入 evaluator 支出限制。

## Deployment

- 自托管部署表单现在支持 Redis 的 CPU 和内存 requests 及 limits。配置的值会应用到由 Kubernetes operator 管理的 Redis workload。
- 使用平台默认 LangGraph API 版本的部署现在会正确复用匹配的镜像，而不是启动不必要的重新构建。
- 进入 public preview 的 Managed Deep Agent 部署现在会报告其正常的部署使用量。
- 回滚从上传的源归档创建的部署时，现在会重新部署该 revision 的归档，而不是最新的那个。
- Managed Deep Agent 部署的 Details 侧边栏现在会链接到持有其已部署指令、技能和记忆的 Context Hub 仓库。已归档的仓库会被标注，以便清楚了解上下文何时不再有效。

## Sandboxes

- 恢复暂停的 sandbox 时，现在会检查你 organization 的真实 sandbox 配额，包括方案特定的限制，而不是默认上限。确实超出配额的请求会返回 429 并附带配额消息，而不是 502 Bad Gateway。
- 自托管 LangSmith 现在仅当部署 license 包含 sandbox 访问权限时才启用 sandbox API 和 UI 访问。
- 在线自托管 LangSmith 安装现在会在启用 phone-home 使用量报告时，为计费报告已最终确定的 sandbox 运行时间和资源使用量。离线和已选择退出的安装不会发送 sandbox 使用量。

## Administration

- 将鼠标悬停在页脚菜单中的 organization 行上时，organization 子菜单现在会打开。
- 自托管部署现在每 5 分钟刷新一次 license，而不是每 24 小时，因此授权变更会在做出后不久生效。刷新失败不再重启服务，它会继续使用上次验证的 license，直到该 license 自身到期。调整参数现在为 LICENSE_REFRESH_INTERVAL_SECONDS（默认 300），替代了 LICENSE_REFRESH_INTERVAL_HOURS。
- 使用 Cmd+K 搜索 workspaces 时，现在会在 organization 标题中高亮查询词，从而清楚说明为何匹配 organization 名称的词会返回该 organization 的所有 workspaces。
- 账户菜单现在提供 Get help。Enterprise 用户可以在 LangSmith 中提交支持请求，而其他 cloud 用户会被引导至 Support Portal。
- Plans and pricing 页面现在会保留浏览器的后退和前进触控板手势，并使方案卡片居中。

## LLM Gateway

- 通过 gateway credit 模型发送到 moonshotai/kimi-k3 和 moonshotai/kimi-k2.6 的请求，现在在用户追踪的代码中发送时会与价格映射进行匹配。
- LLM Gateway Usage 现在提供交互式支出图例、一致的图表布局和保持可见的提示框。单系列视图会清楚说明未关联到用户的支出，而不是显示空图表。
- 你现在可以购买低至 $4.50 的 Gateway Credits，相当于 3 个 LCU。
- 通过 LLM gateway 的 Bedrock 请求现在会使用 Amazon Bedrock 价格映射，因此其成本会被正确计算。
- 余额现在显示在连接卡片上方，用于成本控制、model fallbacks 和支出监控的快捷卡片对 Developer 方案的 organization 保持可见（锁定，并带有 "Upgrade plan" 提示），而不是消失。
- Cost Controls、Rate Limiting 和 Model Fallbacks 标签页现在会说明尚未生效的内容，并在策略表上方提供创建按钮和文档链接。每个标签页的创建按钮、对话框标题和提交按钮也共享同一个标签，例如 "Create spend limit"，而不是通用的 "Create policy"。

## Observability and evaluations

### Datasets and experiments

- LangSmith 通过公共 API 和 SDK 生成流程暴露了 annotation queue item endpoints，用于添加、列出、更新、删除、计数、定位和审核 run 或 thread queue items。
- 上传 .csv 或 .jsonl dataset 现在不再受浏览器报告的 Content-Type 影响。Windows 浏览器会将 .csv 文件标记为 Excel 类型，此前会导致合法上传失败。大写文件名（如 DATASET.CSV）现在也被接受。
- dataset 或 tracing project 上的 evaluator 列表现在显示 evaluator 的当前名称，而不是其被附加时的名称。重命名不会改变 feedback keys。
- experiment comparison 网格中的 metadata 列，包括 `example.metadata.<key>`，现在会渲染其值，而不是保持为空。
- LangSmith 将所有被 SmithDB SDK 迁移指南取代的旧版 endpoint 标记为已弃用：v1 runs query 和 retrieve endpoints、v1 run sharing 和 public-run read endpoints、`POST /api/v1/datasets/{dataset_id}/runs`，以及 annotation queue run endpoints。所有这些 endpoint 现在都会响应 `Deprecation: true`、`Sunset` 日期 2027 年 1 月 31 日，以及指向迁移指南的 `Link` header，在存在单一替代 endpoint 的情况下也会指向后续 endpoint。[了解更多](/langsmith/smithdb-sdk-migration)。
- 当启用 SmithDB 查询且禁用 ClickHouse 查询时，dataset experiment 表格可以按 feedback score 排序。
- Annotation queue item API 使用 project_id 来标识 tracing project。请求 body 也接受 session_id 作为别名。
- Dataset example 视图恢复了 example 详情和标签页导航之间的清晰间距。
- Pairwise annotation queue runs 再次包含在禁用 ClickHouse 查询支持时创建 feedback 所需的 tracing project id。
- 从 experiment results grid 修正 evaluator score 现在会立即更新单元格及其弹出框，而无需刷新页面。
- Configure Evaluator 面板的 header 和 templates 导航在暗色模式下再次与面板本身渲染相同的背景色。
- Dataset 和 run attachments 现在会在自托管部署中预览、打开或下载之前解析相对签名下载 URL。

### Monitoring and alerting

- 为 LangSmith 设计系统添加了可复用的 ChartCard 组件，标准化了图表标题、移动、展开和溢出操作、响应式全宽布局，以及图表和图例间距。

### Engine

- 当 Engine 将一条新的匹配 trace 链接到某个已解决的 issue 时，该 issue 现在会立即返回到 Open 状态。此前该 trace 会被归档为证据，但 issue 保持关闭状态，因此再次出现的问题不会在 board 上重新浮现。已 dismiss 的 issue 保持 dismissed。
- Issue 详情 header 现在将 category 和 tag 徽标与标题渲染在同一行，而不是堆叠在下方，使 header 更紧凑，减少垂直空间浪费。
- 在 issue board 上配置 Slack channel 或 webhook 目标时，不再提供 "Engine failed to complete a run" 触发器。已订阅该触发器的目标仍会继续接收这些通知。
- Engine run webhooks 和 sandbox 链接现在会从 LANGSMITH_PUBLIC_API_ENDPOINT 解析外部可达的 API base，并回退到 LANGCHAIN_PLATFORM_ENDPOINT，然后是 LANGCHAIN_ENDPOINT。仅在 chart 中设置了 LANGSMITH_PUBLIC_API_ENDPOINT 的安装此前会构建相对 URL，导致每个非 shadow Engine run 都失败，因为 run webhook 被拒绝为 loopback 地址。

### Tracing

- Trace 详情面板再次使用与其 section headers 匹配的 elevated 背景。
- Bulk exports 接受一个新的 opt-in `feedbacks` 列，以 JSON 数组形式携带每个 run 的各个 feedback 条目，包括其 key 和 comment。创建 export 时将 `feedbacks` 添加到 `export_fields`；省略 `export_fields` 的 export 保持现有列。
- 在确认破坏性操作后，可以从 run details 操作菜单删除整条 trace。
- 当 ClickHouse 使用优化后的 runs 表时，negative feedback-key 过滤器现在能正确返回匹配的 traces。
- 当 project 配置了自定义 output renderer 时，trace Output 部分现在会将其作为 Custom 选项与 Markdown、Plain、JSON 和 YAML 并列提供，而不是替换它们。Custom 保持为默认值，你的选择会被记住。
- 使用 6.2 之前版本 Redis 的自托管部署中，tracing project 活动和排序现在保持最新。
- `POST /api/v1/runs/stats` 现在在请求的 tracing project 不存在于你的 workspace 中时返回 404，并以真实状态和消息报告其他客户端错误（例如 `start_time` 早于支持的回溯窗口），而不是通用的 500 内部服务器错误。
- 自托管部署现在会补全缺失的 tracing project 最后运行时间戳，使 project 排序反映最近的历史活动。
- Run 过滤器现在在路由的查询后端之间一致地支持 total、prompt 和 completion token 计数和成本。
- Token Count / Cost 过滤器现在默认为 total tokens / cost，而不是 input tokens。Input 和 output token / cost 分解仍可在选择器中使用。
- 在 tracing project 上重置视图现在会将 Threads/Traces/Runs 切换器与显示的行同步移回。此前切换器可能停留在 Runs 上，而表格已经返回到 traces。

### Feedback

- Annotation queue item endpoints 现在已在 /api/v1/platform 下的服务路径中文档化，因此用于列出、添加、更新、计数、删除和放置 queue items 的生成 SDK 方法可以到达 API，而不是返回 404。
- 附加到消息的 PDF 和其他文档现在渲染在全宽预览框中，带有可几乎全屏打开的 header 控件，而不是折叠为缩略图大小的框。

### Prompts and playground

- 当 model provider 拒绝 playground run（例如 API key 错误或配额用尽）时，playground 现在会显示 provider 自己的错误消息，而不是通用的服务器错误，因此可以从错误本身看清原因。
- Playground batch 和 invoke endpoints 现在会在响应之前将缓冲的 run trees 净化为 JSON 安全的 payload，因此当 run graph 无法序列化时，online evaluations 不再因不透明的 500 错误而失败。

### Automations

- Fork 一个 evaluator 时，副本会附加到 fork 对话框中指定的 project 或 dataset。此前副本可能被创建为未附加到任何内容，导致原始 evaluator 仍在运行你刚刚编辑过的版本。

## Deployment

- Create New Deployment 表单现在在提交值未通过验证（例如无效的 image 路径）时显示清晰的逐字段消息，而不是原始的后端错误 payload。
- 删除一个 LangGraph deployment 仍在删除后保留期内的 tracing project 时，现在会调度该 project 与 deployment 一起删除，并在错误消息中说明这一点，而不是要求你删除一个已经删除的 deployment。
- LangGraph deployment 的删除确认现在会说明底层数据库的清理在你确认之后运行，并且已删除 deployment 的名称在清理完成之前保持保留。

## Sandboxes

- Sandboxes 接受新的流式执行请求，以 Server-Sent Events 形式返回 stdout 和 stderr，适用于无法保持 WebSocket 的客户端。传入 command ID 可重用正在运行的 command，单独的 resume 请求可继续中断的流，而不是重新运行 command。
- Sandboxes 现在在 PATH 上附带 `langsmith` CLI，因此 agents 无需先安装即可查询 traces、runs 和 datasets。
- Sandbox 和 snapshot 行现在使用带上下文菜单的单列布局，snapshot 源仍可在其菜单中使用，换行的名称保持左对齐。
- 自托管部署中的 Engine sandbox 命令现在通过 WebSocket 使用 deployment service key 进行认证，防止成功创建 sandbox 后出现 401 失败。
- Sandboxes 中的 `langsmith` CLI 已更新到 v0.2.44。其请求现在可在将 API 服务于 `/api` 下的自托管部署上解析，此前 `trace messages` 和 project issues 命令等会失败。

- LangSmith 现在为每个工作区可复用的 [evaluators](/langsmith/evaluators) 设置了上限，以防止资源无限增长。如果你的工作区需要更高限制，请联系支持团队。
- 通过[source runs](/langsmith/manage-datasets) 创建 [dataset examples](/langsmith/manage-datasets) 时，现在可以正确获取由 SmithDB 支持的 run inputs 和 outputs，并且当多个 source runs 中某一个找不到时，也不再导致整个请求失败。
- 你现在可以在 experiment 中选中多行（或选中当前过滤条件匹配的所有行），一次性添加、替换或移除它们的 dataset splits，也可以把选中的 examples 复制到另一个 dataset，而不必逐行编辑。
- `/runs/rules/validate` endpoint 现在支持 [thread evaluators](/langsmith/online-evaluations-multi-turn)。传入 `test_thread_id` 和 `session_id`，即可在保存前针对真实对话测试多轮 evaluator。
- 当自定义 code evaluator 在某个 run 上超时或失败时，现在会在该 run 上记录一个 error，而不是静默地留下没有 feedback 的状态，因此 experiment 中的部分评估失败现在可见。
- Example 页面上的 Open source run 操作，现在会从创建时填充的专用 example 字段中读取 session 和 start time，从而能够可靠地导航到 SmithDB 中的源 trace。
- Thread evaluator config 预览现在会显示该 evaluator 实际映射的 thread message 格式，而不是列出所有可用格式。
- Evaluator config 现在会为托管的 thread evaluators 显示一个锁定的 “Trace count ≥ 2” filter，明确表示它们只会在多轮 thread 上运行。
- Experiment comparison 和单个 experiment 视图现在可以在通过 SSO/OAuth session cookie 鉴权 UI 的自托管部署上加载 run rows。此前即使 metrics 和 feedback 已加载，这些视图也可能显示 “No results found”。
- Experiment 统计信息现在会对最近运行的 experiments 及时刷新，同时保持对历史 experiment 扫描的范围限制。
- 通过 “Add evaluator” 添加的 Assertions evaluator 现在会像自动挂载版本一样从 reference output 读取 assertions，因此它会针对真实 assertions 进行评分，而不是始终失败。
- Evaluator spend chart 的 y 轴现在会对 $1,000 及以上的金额进行缩写，让高支出数值更易于浏览。
- 当某个 run rule 的采样率为 0（或未设置）时，此前会向 SmithDB 查询服务发送超出范围的 sample_rate（并被拒绝），还会把 ClickHouse thread grouping 置零。现在 flat 和 grouped 两种 fetch 路径都会回退到 1.0（不采样），因此这些 rule 可以正常查询。
- 当 dataset comparison 视图的 CSV 导出超过内部大小限制时，现在会返回清晰的 “file is too large to export” 错误，而不是通用的服务器错误。
- 某一行 Splits 单元格中的每个 split chip 现在在 experiment results 和 comparison 视图中都是可交互的，其中的 Edit splits 操作会打开单个 example 的 split picker，让你无需离开表格即可重新分配 splits。

### Tracing

- 批量 run ingestion 日志现在会把 run_verbs 作为 run_id 和 verbs 对象的列表输出，而不是以 run UUID 为键的 map，从而避免结构化日志聚合器耗尽动态字段上限。
- LangSmith 现在会对单个项目和用户执行用户自定义的每月 trace 上限。超过配置上限的新 traces 会被拒绝，而对已接受 traces 的 patch 和 feedback 仍然可以继续流转。
- Tracing 和 evaluation onboarding quickstarts 现在会为自带云数据平面的工作区显示正确的 `LANGSMITH_ENDPOINT`，而不是共享的多租户 endpoint。
- 对 trace 中任意 run 执行分享、查看分享或取消分享，现在都会作用于 trace root，因此共享 trace 中的每个 run 都可被公开查看，而公共 run 链接会在共享 trace 中打开所选 run。
- 当项目已有 traces，但当前过滤条件或时间窗口中没有近期 runs 时，项目不再错误显示 onboarding 页面。项目 run-count 检查现在会回看 30 天，而不是之前的 1 小时时间窗。
- Bulk export compression 现在默认使用 zstandard（zstd）以提升性能。自托管环境仍可通过 `FF_BULK_EXPORT_DEFAULT_COMPRESSION` 环境变量保留 gzip 默认值。
- 已登录用户查看公共 runs 时，现在会在侧边栏看到其上次所选工作区的导航。未登录的查看者仍可看到公共 run，但没有已登录工作区的导航。
- 当提交重复的 run create 或 update payload 时，LangSmith 现在会返回更清晰的 409 Conflict 消息。消息会在可能时指出这是重复的 run create 还是 run update 请求。
- 获取 runs 或 thread history 的 LangSmith [MCP tools](/langsmith/langsmith-mcp-server) 现在除了项目名外，也接受 `project UUIDs`，让基于 trace URL 的排查更快、更不容易出错。
- OpenTelemetry resource attributes（通过 `OTEL_RESOURCE_ATTRIBUTES` 设置）现在会以 `otel.resource.*` 命名空间显示在 traces 元数据中，因此你可以附加诸如用户 ID 之类的信息，而不必修改 tracer 发出的 spans。
- 通过原始 OpenTelemetry 发送的 Vercel AI SDK traces，现在会在 Messages 视图中正确渲染。此前这些 traces 会显示一个空的 Messages 标签页，因为没有格式适配器接管它们。
- 选择流式返回的 thread stats 请求，现在会先返回主统计信息，并在 feedback stats 准备好后再补充返回。
- 原生 OpenTelemetry child spans 在早于 SDK 归属的 parent span 到达时不再被丢弃；它们会被缓冲，并无论到达顺序如何都能正确嵌套。
- 当 runs 查询超时时，runs table 现在会显示 timeout banner，以提升响应体验。
- 当 multipart ingestion 批次里某个 run 的 inputs 或 outputs 过大时，LangSmith 现在会保留整个 trace。超大的 input 和 output 字段会被占位内容替换，而不是让整个批次都被拒绝。
- 当 ABAC 拒绝 trace 加载时，Thread 页面现在会显示明确的访问控制消息，而不是通用的检索错误。
- Tracing 视图中的所有时间过滤器现在会查询完整的保留期窗口，而不再回退到较短的后端默认值。这样在扩展时间范围时，trace、thread 和 run 的结果保持一致。
- 来自 VS Code Copilot Chat 的 OpenTelemetry traces 现在会按每个用户回合渲染为一条干净的嵌套 trace。辅助的 title/summary 调用和孤立的 tool spans 会被抑制，message 角色会被修正，token 计数会去重，并自动附加标准化的元数据（integration、agent runtime、thread ID、repo/git 信息）。
- Insights 的 cluster run 统计信息（run 数量、延迟、tokens 和 feedback）现在只反映每个 cluster 内的 runs，而不再为每个 cluster 都显示相同的项目级总计。
- LangSmith Chat 现在在搜索文档时会使用 guest token 向 Chat LangChain 进行身份验证，因此在 Chat LangChain 收紧身份验证后，文档问答仍能继续工作。
- 对于包含 middleware guardrails 或 subagent 侧边对话的 traces，Trace Messages 查看器现在会识别出 “主” 对话，因此消息列表只显示主要交互，而不会把 middleware/subagent 分区交错在一起。其正确性已由覆盖 11 个集成（横跨 LangChain、OpenAI Agents SDK、Vercel AI SDK、Claude Agent SDK、deepagents 和原始 provider 封装）的扩展快照测试套件验证。
- 自定义 dashboard 图表现在可以查询 input 和 output cost 的 P50 和 P99，而不会导致 runs analytics 请求失败。
- Thread stats API 现在接受 `filter` 查询参数，让你可以把聚合统计范围限定在匹配某个 LangSmith filter 表达式（例如 start time 或 trace ID）的 traces。
- LangSmith Chat 现在会从 Chat LangChain LangGraph host（`POST /identity/guest`）签发 Managed Deep Agent guest token 用于文档搜索，而不是使用旧版 Chat LangChain 前端的 guest 路由。

### Engine

- 当 Engine 项目达到其每月支出上限时，Next Run 状态 chip 和项目支出卡片现在会明确显示 “Monthly spend limit reached” 状态，并附带一个可直接跳转去提高上限的按钮。
- 升级了 Redis client 以改善从 Redis 集群拓扑变更中的恢复，修复了集群重连可能卡住的情况。
- Engine 现在允许父 agent 从模型可操作的子任务失败中恢复，并在使 run 失败之前重试临时的 provider 或网络错误。这有助于 issue 扫描在可恢复的模型错误下继续进行，同时仍保留对 auth、配置和代码异常这类硬失败的处理。
- LangSmith 现在通过托管的 [MCP tools](/langsmith/langsmith-mcp-server) 和生成的 SDK 方法暴露 Engine issue 的列表与获取能力。Agents 和 API 客户端现在可以直接通过 `issue ID` 获取 issue 详情，或按项目、状态、严重级别、标签和更新时间过滤 issues。
- 新的 Engine board callout 会引导你前往 trace-scope 设置页面，在那里你可以把 Engine 的 review 限制在匹配特定 run name 或 metadata 值的 runs 上。
- 自托管 Engine 部署现在可以通过设置 `ENGINE_ANTHROPIC_BASE_URL`，把兼容 Anthropic 的模型调用路由到 Gateway 或兼容 LSI 的 endpoint。
- 带有 assertions 的 Engine 生成 examples，现在在从 annotation queue 保存到 dataset 时会添加 Assertions evaluator，与直接使用 Add offline examples 流程保持一致。
- Engine issue 列表现在使用单一的 filter 和 sort 菜单，为 Priority、Status、Tags 和 Sort by 提供紧凑、可折叠的布局，取代了此前两个独立的 popover。
- 当 Engine issue 列表的排序与默认值不同时，现在会在 filter chips 旁边显示当前排序方式作为一个可移除的 chip。
- Engine issue 列表不再显示扫描时序信息（下一次扫描倒计时、上次运行时间或 Run now 操作）；board 设置中单独的区块里仍保留 Pause/Resume 控制。

### Prompts and playground

- 自托管 [Playground](/langsmith/playground-model-providers) 与 evaluator 的出站模型调用现在会遵循 proxy 环境变量，同时保留对每个请求的 SSRF 校验。
- 当你从 playground 将 prompt 保存到某个 application 时，LangSmith 现在会保持工作区 application filter 仍处于 All Applications，而不是把 UI 的其他部分切换到该 application。
- 在 Context Hub 搜索框中输入工作区成员的姓名或邮箱时，现在也会返回他们创建的 prompts 和资源。
- Playground 现在已在 Anthropic、Bedrock 和 Vertex AI 的模型选择器中加入 Claude Sonnet 5、Claude Fable 5 和 Claude Opus 4.8。新的 Anthropic playground 会话默认使用 Claude Sonnet 5。
- Playground 和 evaluator 在通过 IAM Trusted Entity 调用 Amazon Bedrock 时，现在会在 AWS 托管的 LangSmith 中扮演客户角色之前先解析出正确的 LangSmith AWS 凭证。这修复了此前在客户角色被扮演之前报 “Failed to assume role” 的失败。
- 通过 forward proxy 路由的出站模型调用，现在会在 proxy CONNECT 隧道中发送原始 hostname，而不是已解析的 IP，因此按域名对隧道目标做白名单的 proxy 不再会拒绝它们。这修复了自托管 Playground 和 evaluator 调用仅能通过此类 proxy 才能访问的内部 OpenAI 兼容 endpoint 的问题。
- Review 一个 prompt commit 时，现在会显示设置在模型上的所有额外参数（例如 verbosity），而不仅是固定的某个子集。

### Feedback

- 编辑 evaluator 生成 feedback 的分数时（例如在 experiment comparison 视图中），现在可以正确保存，而不会再报 “Failed to add feedback correction”。
- 向 annotation queue 添加 runs 的 POST 请求现在接受可选的 `extend_trace_retention` 查询参数。当设置为 false 时，短保留期 traces 不会被升级到 extended retention。默认值仍为 true，以保持向后兼容。
- 从 LangSmith UI 添加 feedback 或 reviewer notes 时，现在不会再把短保留期 traces 升级到 extended retention。长保留期 traces 不受影响。
- Feedback statistics queries 现在通过官方 ClickHouse client 路由，解决了查询失败问题，并提升了与 ClickHouse 25.x 的兼容性。
- 当客户端提供 session 和 start time 时，feedback 创建现在会从 SmithDB 解析 run metadata，因此仅使用 SmithDB 的部署不再依赖 ClickHouse 来执行 eager feedback 写入。
- `POST /feedback/eager` endpoint 已被弃用，取而代之的是 `POST /feedback`，并计划于 2026-08-10 移除。请将任何直接调用 `/feedback/eager` 的集成更新为使用 `POST /feedback`。

### Monitoring and alerting

- Alert chart previews 现在可以一致地处理相对日期范围，避免加载 14 天或 30 天预览时失败。
- [Dashboards](/langsmith/dashboards) 图表的 tooltip 和坐标轴现在最多显示 8 位小数（此前为 2 位），因此极小的成本和比率不再被四舍五入为 0。
- 自定义 dashboard 上的时间序列图表，现在会为缺失数据点保留空隙，而不是把它们画成 0；折线也会跨过这些空隙连接起来，因此趋势仍然清晰可读。

### Automations

- 在没有 filter 的情况下应用预构建 evaluator 时，现在默认只在 root runs 上运行，与手动创建的 evaluators 保持一致。此前它会在 trace 中的每个嵌套 run 上都运行。
- 打开或关闭在线 evaluator 或 automation 时，现在任何有权编辑 rules 的角色都可以成功保存，而不会再对没有 retention-configuration 权限的成员静默回滚。

## Deployment

- 自托管部署现在可以申请超过此前 Cloud 限制的 CPU 和内存配置，即超过 8/16 核和 32/16 GB，只受你的集群容量约束。下限、128 的倍数粒度，以及 Redis 内存顺序规则仍然适用。
- 自定义 Slack app triggers 现在可以选择允许第三方 bots 触发 agent。你可以在某个 registration 上启用 allow bot triggers 开关，以接收外部 bots 的事件；来自你自己的 bot 和其他 LangSmith 注册 bots 的回显仍会被丢弃，以避免循环。
- Agents 现在会立即跳过不可达或配置错误的非默认 MCP servers，而不是反复重试，从而减少 tool-loading 步骤中的慢往返，并缩短首个 token 的时间。
- 对于 LangGraph Platform deployments，standby（uptime）分钟数此前在不同 usage-reporting 运行中，如果副本上报了重叠区间，可能会被重复计费。现在报表会对每一分钟在不同运行间去重，因此每分钟最多只计费一次。
- Studio assistants 页面上的多选下拉菜单（例如 Selected Tools）现在会渲染在配置对话框上方，而不是被它遮挡，因此其选项可见且可选。
- 使用 Microsoft Entra ID（Azure IAM）身份验证的 Redis 连接，现在会在 access token 过期之前自动重新进行身份验证，因此长连接不再会断开。集群版 Azure Redis 现在也支持 IAM 身份验证。
- Deployment 的 Crons 标签页现在会以你的本地时区显示每个调度，而不再是原始 UTC，与 Next Run Date 列保持一致。
- LangSmith Deployment 现在支持通过 control plane API 把 deployment 更新到固定的资源层级。更新会应用所选层级的资源配置，调整 Cloud SQL 或 RDS 的规格，并滚动出一个新 revision。
- 你现在可以从某个 deployment 的 Settings 中对其进行重命名，为其设置一个友好的显示名，而无需重新创建。该 deployment 的 URL 和基础设施保持不变。

## Sandboxes

- Sandbox 命令输出现在会重新切分为有边界的单个 WebSocket frame，因此不会重组 continuation frames 的客户端（包括 Go SDK）现在也可以读取大型流式或回放输出，而不会出现 JSON 被截断的情况。
- S3 sandbox mounts 现在在未提供 `endpoint_url` 时，会默认使用 `https://s3.amazonaws.com`，因此挂载标准 AWS S3 bucket 时不再必须填写该字段。
- [Sandboxes](/langsmith/sandboxes) 现在可在宿主机有空闲容量时，将 CPU 突发提升到所请求配额的 2 倍，并支持最低 0.05 的分数（子核）vCPU 请求。
- 创建 sandbox 时，你现在可以配置 Git、S3 和 GCS 文件系统挂载，包括挂载路径、Git remotes、bucket 设置和缓存选项。配置好的 mounts 会显示在 sandbox 表格和详情页中。
- LangSmith SDK 现在支持为拉取私有容器镜像创建、列出、更新和删除 sandbox registries，与现有的 sandbox 和 snapshot 操作并存。
- 当底层宿主机受到扰动时，sandbox 创建不再会间歇性报 “sandbox not ready” 错误。受影响的容量现在会重试争用的资源锁并自动恢复，而不会让池处于降级状态。
- Sandbox 宿主机启动现在在复用前会校验完整的版本目录，因此在部分或陈旧的安装之后，缺失 initrd 不再会导致创建时失败。
- 从 Docker 镜像创建 sandbox snapshot 时，现在会记录该镜像的 tag（例如 ubuntu:24.04 会变成 24.04 tag）；在未带 tag 的情况下用 snapshot 名创建 sandbox 时，会解析为 latest tag，与 Docker 行为一致。
- 自托管 LangSmith 安装现在会显示 Sandboxes 导航项，并使用实例级 sandbox 标志来打开 Sandboxes 页面。
- Sandbox 内的 shells 和工具现在会把 sandbox 的名称作为 hostname 上报，而不再是通用的默认值，并且该名称可以从 sandbox 内部解析。
- 自托管 LangSmith 安装现在无需启用 Deployments 前端即可打开 Sandboxes 页面。
- Sandbox 现在会默认设置通用的 CA-bundle 环境变量，因此 Python、Node、Deno、curl 和 git 工具会自动信任 sandbox 的 egress proxy 证书，当其流量被代理时不再会因 TLS 证书校验错误而失败。

## Administration

- 组织 Roles 设置页面上的 roles 表格，现在在 roles 数量超过屏幕可容纳时可以正确滚动。
- 企业版 Usage 配置页面上新增了 Project and user limits 标签页，让你可以针对特定项目或用户设置每月 trace 数量上限。可以在页面上添加、编辑和删除这些上限。
- 匿名组织现在会在成员页面上显示 “Anonymity mode is on” 横幅，并且用量明细会对非内部查看者隐藏 group-by-user 选项。
- 新建 API keys 现在默认使用有限的有效期，而不再要求自定义值。当组织强制使用更短的最大有效期时，表单会默认采用该最大值。
- 你现在可以直接通过 `GET /api/v1/workspaces/{workspace_id}` 获取单个工作区，而不必列出所有工作区并在客户端过滤。
- 组织和工作区管理员现在可以直接在 Members 设置页面上编辑待处理成员邀请的角色，而无需取消并重新发送邀请。
- Usage limits 页面现在会显示每个工作区配置的总 trace 上限和 extended（长保留期）trace 上限，包括此前在支出上限显示为 “Unlimited” 时被隐藏的那些上限。
- 批量工作区邀请 endpoint 在邀请已经是待处理组织受邀请者或活跃组织成员的用户时，不再会返回 409 错误。这些用户会被直接添加到工作区，而无需发起新的组织邀请。
- 编辑待处理成员邀请对话框中的角色选择器现在使用可滚动的 select，与邀请流程保持一致。这确保在定义了大量工作区角色时，所有自定义角色都可访问。
- 自托管部署现在可以把 OIDC authorization request 中的空格编码为 %20 而不是 +，从而在身份提供者拒绝 scope 列表默认的 + 编码时也能正常进行单点登录。可通过设置 OAUTH_URL_ENCODE_SCOPE_SPACES=true 来启用。
- Billing 升级对话框现在会保持在视口内，并在支付或业务信息使表单高出屏幕时滚动。
- 拥有 manage-members 权限的非管理员调用者，不能再向工作区成员分配受限角色，也不能用受限角色邀请用户加入工作区。
- 在 API keys 设置页面上，现在可以按工作区过滤组织级 service keys 和 personal access tokens。
- 没有 workspaces:manage 权限的用户，不能在 UI 中对邀请、角色变更或用户删除使用受限角色。
- 组织管理员可以从组织设置中跨所有工作区禁用 model providers。被禁用的 providers 会出现在 playground、evaluators、Fleet 和其他模型选择器中并隐藏起来，工作区管理员也无法重新启用。

### Tracing

- LangSmith 现在会对单个项目和用户执行用户自定义的每月 trace 上限。超过配置上限的新 traces 会被拒绝，而对已接受 traces 的 patch 和 feedback 仍然可以继续流转。
- Tracing 和 evaluation onboarding quickstarts 现在会为自带云数据平面的工作区显示正确的 `LANGSMITH_ENDPOINT`，而不是共享的多租户 endpoint。
- 对 trace 中任意 run 执行分享、查看分享或取消分享，现在都会作用于 trace root，因此共享 trace 中的每个 run 都可被公开查看，而公共 run 链接会在共享 trace 中打开所选 run。
- 当项目已有 traces，但当前过滤条件或时间窗口中没有近期 runs 时，项目不再错误显示 onboarding 页面。项目 run-count 检查现在会回看 30 天，而不是之前的 1 小时时间窗。

- 当提交重复的 run create 或 update payload 时，LangSmith 现在会返回更清晰的 409 Conflict 消息。消息会在可能时指出这是重复的 run create 还是 run update 请求。
- 获取 runs 或 thread history 的 LangSmith [MCP tools](/langsmith/langsmith-mcp-server) 现在除了项目名外，也接受 `project UUIDs`，让基于 trace URL 的排查更快、更不容易出错。
