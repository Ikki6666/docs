## Observability and evaluations

### Tracing

- ABAC 策略现在可以授予访问匹配 project traces 的权限。
- 现在可以在 tracing 中直接打开 deployment threads。
- traces 上现在会出现更清晰的 Engine issue 操作。
- 现在可以通过公开 API 读取 shared threads。
- Trace 和树状过滤器现在也适用于 thread evaluations。
- 不受支持的 run 过滤器现在会返回更清晰的错误。
- Studio Trace 的嵌套 run 选择现在可以正常工作。
- Gateway usage 视图现在可以打开过滤后的 traces。

### Datasets and experiments

- experiment evaluator 列名现在会使用完整的列宽。
- 现在可以克隆 model configurations。
- Tuned Evaluators 在 tracing project 中更容易找到。
- 数据网格现在可以适应放大的浏览器字体。
- 表单错误现在会以一致的方式播报。
- 仪表盘十字准线现在在各个图表之间保持同步。
- Engine chat 启动器现在会建议问题。

### Engine

- Engine 现在使用按 application 范围统计的 project 计数。
- 可以在 Linear 中创建已存在的 Engine issue。
- 现在可以直接从工具栏为 Engine issue 打开 pull request。
- Engine issue 现在会与 Linear 保持同步。
- Engine 现在会在侧边栏显示发布公告。
- Engine 现在可以区分缺失的能力与出错或部分接入的 tool，从而减少误报的 Feature Gap issues。
- Engine 修复的 pull request 现在会自动打开。
- 从 Engine issue 打开第二个关联 trace 现在可以可靠工作。
- 对于落后于 base branch 的修复，Open PR 也可以正常使用。
- Engine 用量现在消耗的 Usage Credits 减少 40%。

### Gateway

- 较新的 OpenAI 模型现在会通过 Amazon Bedrock 路由。
- LLM Gateway 路由现在支持末尾斜杠。
- 现在会阻止递归的 LLM Gateway 配置。
- PII redaction 现在是 LLM Gateway 的一项独立授权。
- Claude Max OAuth 流量现在不计入 Gateway 支出。
- 保存的 model configurations 现在可以在统一的 LLM Gateway endpoint 上使用。
- 自定义 provider 现在可以在统一的 LLM Gateway endpoint 上使用。
- Gateway 数据策略现在默认可用。
- 你可以在 LLM Gateway 路由中使用保存的 model configurations。
- Gemini Enterprise Agent Platform gateway 现在支持现有的 web credentials。
- 现在会遵循 OpenAI 兼容的 API base paths。
- 自定义 provider 配置的生效速度更快。
- LLM gateway traces 默认不再捕获请求和响应内容。
- Gateway quickstart 现在提供长期有效的 API keys。

### Platform and deployment

- Dedicated deployment 现在至少运行两个副本。
- Run rules 现在支持 Redis cluster-safe 模式。
- Thread annotation queues 现在在 self-hosted 部署中可用。
- 在 self-hosted 部署中，thread 自动化可以添加到 annotation queues。
- Sandbox 执行超时错误信息更清晰。
- 更新 sandbox 的 proxy 配置不再与启动操作冲突。

### Fleet

- Fleet sandbox API 现在支持外部 OIDC 认证。
- Fleet computers 会在本地保留上传的 Excel 工作簿。
- 可以查看 Outlook 日历的忙闲状态。

</Update>

## Observability and evaluations

### Datasets and experiments

- Experiments 表格 config 单元格中的 model、prompt 和 tool chips 现在基于实际测量进行布局以实现准确截断，+N 溢出徽标是一个可点击的下拉菜单，其条目提供与 chip 自身菜单相同的操作（filter、group by、在 playground 中打开以及 details）。
- 当 repetition root 只有 project ID 而没有 session ID 时，在 experiment comparison 视图中展开 repetition runs 的 run tree 现在可以可靠工作。
- 关联到 Hub prompts 的 evaluators 现在可以正确加载 flat 和 playground 形状的 prompt commits，修复了编辑现有 evaluators 时的崩溃。
- Code evaluator 上传现在接受带有 PEP 604 联合返回类型注解（例如 `-> dict | None`）的 Python 入口点。
- POST /v2/datasets/{dataset_id}/experiment-runs 是受支持的公开 API，用于分页的 experiment comparison。旧版 dataset comparison 辅助接口已从公开 OpenAPI spec 和生成的 SDK 中移除；现有 HTTP 路由仍可继续为 LangSmith UI 客户端工作。
- 每个 example 的 dataset splits 现在在 dataset Examples 表格中渲染为 chips，基于实际测量布局，当某个 example 所属的 splits 超出列宽时显示可点击的 +N 溢出菜单。
- 作为持续进行的 ClickHouse 弃用工作的一部分，当启用 SmithDB experiments 标志时，对现有 experiments 应用 Apply Evaluator 现在从 SmithDB 而不是 ClickHouse 读取 runs。
- 新增 `langsmith evaluator create-llm`，可基于 prompt、schema 和模型配置文件定义结构化的 LLM-as-judge evaluator 规则，作用于 project 或 dataset。
- experiment comparison 视图现在提供一个可选、可重新排序的 "Splits (latest)" 列，以 chips 形式显示每个 example 当前的 dataset split 分配情况，反映实时成员关系而非 run 时的快照。
- project 和 dataset evaluator 标签页上的 evaluator 支出图表在窄屏上保持桌面布局并水平滚动，而不是压缩图表和统计卡片。
- experiment comparison 和 group-by 视图现在显示每个 example 当前的 dataset split，而不是 experiment 运行时的 split，因此无需重新运行 experiment 即可判断失败是否已属于某个 split。
- comparison 视图现在从 SmithDB 为 root runs 加载 token 和成本统计数据，因此统计列会再次填充数据，而不再保持空白
- LangSmith 现在为每个 workspace 的可重用 evaluators 设置上限，以防止资源无限制增长。如果你的 workspace 需要更高的上限，请联系支持团队。
- 从 source runs 创建 dataset examples 时，现在可以正确获取由 SmithDB 支持的 run 输入和输出，并且在多个 source runs 中有一个找不到时不再导致整个请求失败。
- 在 experiment 中选择多行（或选择所有匹配当前过滤器的行），即可通过一次操作添加、替换或删除它们的 dataset splits，或将所选 examples 复制到另一个 dataset，而不再需要逐行编辑。
- /runs/rules/validate endpoint 现在支持 thread evaluators。传入 test_thread_id 和 session_id，即可在保存前针对真实对话测试 multi-turn evaluator。
- 在某个 run 上超时或失败的自定义 code evaluators 现在会在该 run 上记录错误，而不是静默地不留下任何 feedback，因此部分评估失败会在 experiment 上可见。
- example 页面上的 Open source run 操作现在从创建时填充的专用 example 字段读取 session 和 start time，从而可靠地导航到 SmithDB 上的源 trace。
- Adhoc experiment evaluation 现在通过 v2 runs query API 获取 runs，从而正确处理宽列存储并完成排队的 evaluators。
- thread evaluator 配置预览现在显示 evaluator 实际映射的 thread 消息格式，而不是列出所有可用格式。
- Multi-turn evaluators 现在包含一个 Test 操作，可在保存规则前针对示例 thread 运行该 evaluator。
- experiments 页面上的聚合 feedback 统计现在会针对仅数值分数的 evaluators 省略内部的 {} 占位符，因此值细分只列出真实的类别标签。
- evaluator 配置现在为托管 thread evaluators 显示一个锁定的 "Trace count ≥ 2" 过滤器，明确它们只在具有多轮对话的 threads 上运行。
- experiment comparison 和单个 experiment 视图现在可以通过 SSO/OAuth session cookies 认证 UI 的自托管部署上加载 run 行。此前即使 metrics 和 feedback 已加载，这些视图也可能显示 'No results found'。
- experiment 统计信息现在会为最近运行的 experiments 及时刷新，同时保持对历史 experiments 的扫描有界。
- 通过 "Add evaluator" 添加的 Assertions evaluator 现在会像自动附加版本一样从 reference output 读取断言，因此会针对真实的断言进行评分，而不是总是失败。
- evaluator 支出图表的 y 轴现在会对 $1,000 及以上的金额进行缩写，使高支出值更易于浏览。
- 当导出超过内部大小限制时，将 dataset comparison 视图导出为 CSV 现在会返回清晰的 "file is too large to export" 错误，而不是通用的服务器错误。
- 打开 chip 的下拉菜单（例如在 experiments 和 evaluators 表格中）不再阻止滚动下方的表格或页面；菜单后面的内容可以按预期滚动。
- 在 experiment 结果和 comparison 视图中，某行 Splits 单元格中的每个 split chip 现在都是可交互的，其 Edit splits 操作会打开单 example 的 split 选择器，因此无需离开表格即可重新分配 splits。
- 通过 POST /annotation-queues/{queue_id}/items 将 RUN items 添加到单个 annotation queue。服务器通过 ClickHouse 或 SmithDB 解析 runs 并返回标准形状的 items envelope；THREAD 支持将在后续版本中提供。
- LangSmith CLI 现在在使用 `evaluator upload --replace` 时会就地更新现有的 code evaluator 规则，避免在替换上传失败时出现先删除后创建的窗口期。
- 将读取 datasets 的权限拆分为一个新的下载 datasets 权限，并在应用和 API 中都强制执行该新权限。没有下载权限的用户会看到下载按钮被禁用。[了解更多](/langsmith/organization-workspace-operations#datasets)。
- 当 experiment runs 通过 v2 响应形状提供其 project 标识符时，公开 dataset 的 experiment traces 可以正确打开。
- 采样率为 0 的 run 规则不会处理任何 runs，但调度器此前仍会在每个 tick 枚举它。调度器查询现在会跳过 sampling_rate 为 0 的规则（与 is_enabled 检查保持一致），因此它们永远不会被分发。
- dataset 和 experiment 表格现在会截断过长的输入和 reference-output 文本，并将检测到的 base64 图像显示为小缩略图（延迟加载更大的预览），从而避免过大的隐藏 DOM 内容。
- experiment 表格现在会将完整 payload 渲染和输出 diff 准备工作推迟到请求这些视图时进行，提高了包含大型 agent 轨迹的 runs 的响应速度。
- 当 ClickHouse 查询被禁用时，公开 dataset 分享链接现在会从 SmithDB 解析 sessions 列表（含统计信息），因此共享的 dataset 页面不再在仅 SmithDB 的部署上加载失败。
- 通过 POST /annotation-queues/{queue_id}/items 使用 item_type THREAD（thread_id + session_id）将对话 threads 添加到单个 annotation queue。支持混合 RUN 和 THREAD 批次；服务器通过 ClickHouse 或 SmithDB 解析 threads。
- code evaluators 现在有更多时间运行每个批次，因此导入 scikit-learn 等重型库的 evaluators 不太容易超时。
- POST /annotation-queues/{queue_id}/items 现在每个请求最多接受 100 个 items，超过限制时会返回清晰的验证错误。处于限制内的请求仍会成功。
- 在线 evaluator 定义现在包含一个高级设置，用于开启或关闭 evaluator 执行 tracing。禁用 tracing 时 feedback 生成仍会继续运行。
- 在大型 experiments 上向现有 experiment 应用 evaluator 时可能因 "Failed to start evaluation" 而失败。现在即使 run 计数暂时不可用，它也能可靠启动。
- 当 LangSmith 使用 ClickHouse 兼容路径时，链接的 runs 可以从公开 dataset 分享中正确加载。
- GET /annotation-queues/{id}/items 现在会与 RUN items 一起返回 THREAD queue items，并支持可选的 item_type 过滤器。THREAD 列表行在 item 上公开标识信息（thread_id/session_id/start_time）并省略嵌套 thread；RUN 列表目前仍会填充嵌套 run（计划同样在仅元数据列表中省略）。审核时，traces 和消息通过 v2 threads APIs 加载。
- GET /annotation-queues/{id}/runs 及相关 size endpoints 会排除 THREAD queue 行（run_id 为 null），因此混合队列不再返回 500。请使用 GET /items 列出 threads。
- project 设置现在要求 thread 空闲时间至少为两分钟，以确保 thread evaluations 包含所有已摄取的 runs。
- annotation queue item 添加请求现在对 runs 和 threads 一致地强制执行 100 个 items 的限制。超限错误会清楚显示配置的限制。
- annotation queue 审核 UI 现在根据 GET /items 的成员元数据构建左侧导航列表，并通过 GET /v2/runs/{id} 加载所选 run 的 annotate 字段。列表响应不再需要嵌套的 run payloads。
- GET /annotation-queues/{id}/items 返回 RUN 和 THREAD items 的 Postgres 成员元数据，而不会从 ClickHouse 或 SmithDB 填充嵌套的 run 或 thread payloads。孤立的 queue 行仍会列出。include_stats 查询参数已被移除。Annotate payloads 通过 get-one / review APIs 加载。
- 从 tracing project 批量添加 runs 时，其默认 dataset 现在会显示在 dataset 选择器的首位。
- 在 thread annotation queue item 上提供 feedback 时，现在会使用 queue membership id 正确记录最后审核时间，因此 runs 和 threads 的审核进度都会被保存。
- annotation queue 审核列表现在将未命名的 run 行标注为 `Run <ID>`，与 thread 行保持一致，使混合队列更易于浏览。
- 从 pairwise annotation queue 打开 pairwise experiment comparison 时，当两个被比较的 runs 来自同一个 experiment 时不再导致页面崩溃。
- LangSmith 通过公开 API 和 SDK 生成流程公开了用于添加、列出、更新、删除、计数、定位和审核 run 或 thread queue items 的 annotation queue item endpoints。
- 上传 .csv 或 .jsonl dataset 现在无论浏览器报告的 Content-Type 是什么都可正常工作。Windows 浏览器会将 .csv 文件标记为 Excel 类型，此前这会导致有效上传失败。现在也接受诸如 DATASET.CSV 之类的大写文件名。
- dataset 或 tracing project 上的 evaluator 列表现在显示 evaluator 的当前名称，而不是附加时的名称。重命名不会更改 feedback keys。
- experiment comparison 网格中的元数据列（包括 `example.metadata.<key>`）现在会渲染其值，而不再保持为空。
- LangSmith 将所有被 SmithDB SDK 迁移指南取代的旧版 endpoint 标记为已弃用：v1 runs query 和 retrieve endpoints、v1 run sharing 和 public-run read endpoints、`POST /api/v1/datasets/{dataset_id}/runs`，以及 annotation queue run endpoints。所有这些 endpoint 现在都会响应 `Deprecation: true`、`Sunset` 日期 2027 年 1 月 31 日，以及指向迁移指南的 `Link` header，在存在单一替代 endpoint 的情况下也会指向后续 endpoint。[了解更多](/langsmith/smithdb-sdk-migration)。
- 当启用 SmithDB 查询并禁用 ClickHouse 查询时，dataset experiment 表格可以按 feedback 分数排序。
- annotation queue item APIs 使用 project_id 表示 tracing project。请求 body 还接受 session_id 作为别名。
- dataset example 视图恢复了 example 详情与标签页导航之间的清晰间距。
- 当禁用 ClickHouse 查询支持时，pairwise annotation queue runs 再次包含创建 feedback 所需的 tracing project id。
- 从 experiment 结果网格中修正 evaluator 分数现在会立即更新单元格及其弹出框，而不再需要刷新页面。
- Configure Evaluator 窗格的 header 和 templates 导航在深色模式下再次绘制与窗格本身相同的背景。
- 在自托管部署中，dataset 和 run attachments 现在会在预览、打开或下载之前解析相对的签名下载 URL。
- Attachment 和 object 下载现在总是会声明浏览器应如何处理响应。类型无法识别或存储时未带类型的文件会以下载方式交付，而不是在页面中渲染。
- 从 Datasets 或 Home 空状态创建 dataset 时，现在会打开新的 dataset，而不是短暂显示 Page not found 页面。
- dataset JSON schema 描述现在会在编辑器提示框中安全渲染。
- 使用格式不正确的 UUID 作为 `dataset_id` 创建或验证 example 时，现在会返回一个 422 并指出该字段，而不是 500。
- 使用不支持的 `filter` 表达式、不可过滤的属性，或值不是有效 JSON 的 `has(...)` 比较来列出或计数 examples 时，现在会返回一个 422 并指出 `filter` 参数，而不是 500。
- experiment comparison 视图中，按元数据分组和元数据列再次可选。[了解更多](/langsmith/analyze-an-experiment#group-results-by-metadata)。
- LangSmith 现在在渲染评估 commit 链接时会拒绝带有凭据和非 GitHub 的远程 URL。
- 在大型 experiment comparison 结果中滚动时，不再在每次 lazy-load 时重新获取第一页 examples，从而减少冗余网络流量并缩短加载时间。
- 从 experiment 创建 annotation queue（或将 experiment 添加到现有队列）现在会包含所有匹配的 runs，而不会在大型 experiments 上失败。
- evaluator 支出表格在 evaluator 没有过滤器时，会让 All runs 过滤器徽标保持非活动状态。
- Evaluators 页面上的每日 evaluator 支出、每周总计和支出上限监控现在会遵循当前选中的应用，而不是显示跨所有应用的数据。
- 将已跟踪的 run 添加到 dataset 时，现在会将该 run 的 attachments 复制到新的 example 上。在新 runs 存储后端所服务的工作区中，attachments 此前会被静默丢弃；example 创建时没有它们，也没有报告任何错误。从这些工作区传递给在线 evaluators 的 attachments 也以相同方式修复。
- evaluator 支出图表再次将其 evaluator 和 project/dataset 分组控件保留在图表标题中，便于访问。
- 当 example 与某个 thread 关联时，dataset example 读取 API 现在会包含 `source_thread_id`，使从 threads 创建的 examples 更容易追溯到其来源。
- dataset example 创建 API 现在接受并保留 `source_thread_id`，使从 threads 创建的 examples 与其源 thread 保持持久链接。
- annotation queue 表格现在将队列内容标注为 items，而不再是 runs，同时涵盖单 run 和 pairwise 队列。
- input、output 或 metadata keys 中包含冒号的 datasets 现在可以导出为 CSV。这解除了从带有 feedback 的 runs 构建 datasets 的阻碍，feedback 此前存储在 `source_run_feedback:<key>` metadata key 下。
- 托管 evaluator 配置不再显示 evaluator tracing 控件。
- Datasets & Experiments 表格现在使用 Dataset 列标题标注 dataset 名称，使 datasets 与 experiments 之间的关系更清晰。
- annotation queue 中的自由格式 rubric items 现在支持可选的正则表达式验证器。审核者的评论与配置的模式不匹配时会被阻止保存，并显示内联错误，而不是静默保存。
- 组织管理员现在可以直接从暂停的 evaluator 警告和已禁用切换按钮的提示框中打开 Tuned Evaluator 设置。其他用户会看到联系组织管理员的指引。
- annotation queues 现在支持 Data Formatting 设置，可在审核时隐藏 run 的 Inputs 和 Outputs 中选定的 JSON 路径；可通过基于示例 run 生成的复选框选择字段，或手动输入路径。仅适用于 run items，不适用于 threads。
- Tuned Evaluators 现在在 BYOC 工作区和自托管部署中隐藏，因为在这些环境中无法使用 LangChain 管理的推理。

### Tracing

- 批量 run 摄取日志现在将 run_verbs 作为 run_id 和 verbs 对象的列表输出，而不是以 run UUID 为键的 map，防止结构化日志聚合器耗尽动态字段限制。
- LangSmith 现在强制执行作用于单个 project 和用户的用户自定义月度 trace 限制。超过配置限制的新 traces 会被拒绝，而针对已接受 traces 的 patches 和 feedback 仍会继续处理。
- tracing 和评估 onboarding quickstarts 现在会为 bring-your-own-cloud 数据平面工作区显示正确的 LANGSMITH_ENDPOINT，而不是共享的多租户 endpoint。
- 共享、查看或取消共享 trace 中的任何 run 现在都会作用于 trace root，因此共享 trace 中的每个 run 都是公开可见的，并且公开的 run 链接会在共享 trace 中打开所选的 run。
- 已有 traces 的 projects 在过滤或限定到没有近期 runs 的时间窗口时，不再错误地显示 onboarding 界面。project run 计数检查现在回溯 30 天，而不是之前的一小时窗口。
- 批量导出压缩现在默认使用 zstandard (zstd)，以提升性能。

### Feedback

- 编辑 evaluator 生成的 feedback（例如来自 experiment comparison 视图）上的分数时，现在可以正确保存，而不再因 "Failed to add feedback correction" 而失败。
- 将 runs 添加到 annotation queue 的 POST 请求现在接受可选的 `extend_trace_retention` 查询参数。设置为 false 时，短期 traces 不会升级为扩展保留。默认值仍为 true，以保持向后兼容。
- 从 LangSmith UI 添加 feedback 或审核者备注不再将短期 traces 升级为扩展保留。长期 traces 不受影响。
- feedback 统计查询现在通过官方 ClickHouse 客户端路由，解决了查询失败问题并提高了与 ClickHouse 25.x 的兼容性。
- 当客户端提供 session 和 start time 时，feedback 创建现在会从 SmithDB 解析 run 元数据，因此仅 SmithDB 的部署不再依赖 ClickHouse 进行 eager feedback 写入。
- 当禁用 SmithDB 查询时，通过 by-key endpoint 将 runs 添加到 annotation queue 现在会回退到 ClickHouse run 查找，因此 SDK 的 annotation-queue 添加操作无论是否启用 SmithDB 都能工作。
- POST /feedback/eager endpoint 已弃用，由 POST /feedback 取代，计划于 2026-08-10 移除。请更新任何调用 /feedback/eager 的直接集成，改用 POST /feedback。
- feedback 创建现在接受 thread 标识符，使 feedback 可以与对话 thread 关联，而不仅仅是单个 run 或 session。
- GET feedback 请求现在可以在 project 内按 thread ID 过滤，使 thread 级别的 feedback 无需先解析 run 即可检索。
- 从 thread 或 traces 表格添加到 annotation queue 时，你现在可以选择将整个 thread 入队，而不是单个 run。
- annotation queue rubric feedback 现在会为 thread queue items 加载 thread 范围的 feedback。
- annotation queue rubric feedback 现在会针对 thread queue items 保存到所选的 thread。
- 直接从 tracing project 的 threads 视图中选择 threads，并将其批量添加到 annotation queue。
- annotation queue 审核页面上的 Delete 现在会通过 items delete API 移除 RUN 和 THREAD 成员资格。
- 在 View all items 上，可以批量删除所选的 run 和 thread 成员资格、将已完成的 runs 导出到 CSV，以及将已完成的 runs 添加到 dataset。
- View all items 现在会列出带有输入/输出预览的 run 和 thread 成员资格，因此你可以打开任何 item 进行审核。
- 审核页面上的 View item 操作会为 RUN 成员资格打开页面内的 run peek，为 THREAD 成员资格打开页面内的 thread peek。
- 在 annotation queue 中审核 thread 时，Add to Dataset 会被禁用，并带有解释尚不支持将 threads 添加到 datasets 的提示框。
- annotation queue item endpoints 现在记录在 /api/v1/platform 下的实际服务路径中，因此用于列出、添加、更新、计数、删除和定位 queue items 的生成的 SDK 方法可以访问 API，而不是返回 404。
- 打开或刷新指向特定 annotation queue item 的链接现在会加载队列，而不是停留在加载状态。
- 附加到消息的 PDF 和其他文档现在会在全宽预览框架中渲染，并带有一个可将它们几乎全屏打开的 header 控件，而不是折叠成缩略图大小的框。
- feedback 修正现在可以将分数重置为其原始值，包括零。
- feedback card 的 Source 行中过长的 evaluator 名称现在会截断，而不是延伸到 card 之外；当某个 key 有多个条目时，已修正分数的编辑控件会避开分页箭头。
- 将 feedback 值切换到不同类别时，即使两个类别映射到相同的数值分数，现在也会保存。此前在 run 详情和 annotation queue rubrics 中该更改会被静默丢弃。
- 用于修正 evaluator 分数的铅笔图标现在仅在你有更新 feedback 权限时才会显示。此前任何能看到该分数的人都会看到它，而保存修正时会失败。
- 存储在 run 上的 attachments 现在会在 annotation queue 中审核时显示，包括 pairwise queue。此前仅显示内嵌在 run 输入或输出中的媒体。
- 已弃用的 POST /feedback/eager endpoint 已被移除。请改用 POST /feedback。

### Automations

- 应用不带过滤器的预构建 evaluator 时，现在默认仅在 root runs 上运行，与手动创建的 evaluators 保持一致。此前它会在 trace 中的每个嵌套 run 上运行。
- 开启或关闭在线 evaluator 或 automation 时，现在任何可以编辑规则的角色都可以保存，而不再对没有 retention-configuration 权限的成员静默回退。
- 解决了 SAQ 队列 worker 中无限制的内存泄漏，此前 croniter 对象每秒都会重建，累积从未释放的缓存条目。croniter 依赖已升级到 6.2.2+，并且 croniter 对象现在会在调度 tick 之间重用。
- 当 sandbox 验证缓慢时，创建在线 evaluator（LLM-as-judge 或自定义代码）不再间歇性失败。
- Thread（分组）evaluators 现在要求最小空闲时间为 120 秒。将 project 的 thread 空闲时间设置为低于 120 秒会被拒绝。
- 在 thread 中的某个 run 上留下 feedback 现在会使该 thread 有资格重新评估，因此 thread 级别的 evaluators 会在新 feedback 到达时重新运行。
- 当 sandbox 验证缓慢时，编辑在线 evaluator（LLM-as-judge 或自定义代码）不再间歇性失败。
- 在 tracing project 上，LangSmith Chat 现在可以为你填写 New Evaluator 面板：一个基于它在你的 runs 中发现的失败构建的 LLM-as-judge，其中 prompt、feedback keys、模型、采样和过滤器均已设置好。你可以让它修改任何内容，然后自行审查并按 Create。
- 分叉 evaluator 时，现在会将副本附加到 fork 对话框中指定的 project 或 dataset。此前副本可能在创建时未附加到任何对象，导致原始 evaluator 继续运行你刚刚编辑掉的版本。
- 为 LLM-as-judge evaluator 关闭 few-shot 修正时，现在会在保存时移除 few-shot prompt 分节，并持久化已禁用的设置。
- 当 prompt 不使用 few-shot 示例时，LLM-as-judge 评估不再添加 examples_few_shot 输入，因此缺失输入的错误仅显示相关字段。
- 非管理员用户现在可以使用 "Annotate for alignment" 首次创建 evaluator 的对齐 annotation queue，而不会遇到 retention 权限错误。
- 通过 API 手动触发 automation 规则现在可以正常工作。`POST /runs/rules/{rule_id}/trigger` 和 `POST /runs/rules/trigger` 的 `rule_ids` 形式此前对每个请求都返回 500。
- 你可以手动触发 workspace 中的任何 automation，包括仅 webhook、仅告警和 extend-retention 规则。此前触发 endpoint 仅识别一部分操作，对其余操作返回 not found。
- 配置了 OpenAI 兼容或 Anthropic 兼容自定义 endpoint 的在线 evaluators，现在会在实时 traces 上使用该 endpoint 自己的 URL 和 API key，而不再因认证错误而失败。自定义 endpoint 上的 evaluators 不计入 evaluator 支出限制。
- 配置了已保存的自定义 provider 模型配置（OpenAI 兼容或 Anthropic 兼容）的在线 evaluators，现在会在实时 traces 上使用该配置的 endpoint 和凭据，而不再因权限错误而失败。
- 非管理员用户现在可以在 dataset、tracing project 和 thread 窗格中保存 evaluator 编辑，而不会再遇到 retention 权限错误。
- 按 thread 分组的 automations 现在可以为每个匹配的对话添加一个 annotation queue item，因此审核者可以查看整条 thread，而不仅仅是单个 run。
- Thread webhook 和 annotation-queue automations 现在会显示 thread 过滤器而不是 run 过滤器，并且不再默认为 `Is Trace = true`。
- 作用于 threads 的 automation 规则现在会显示 project 的 thread 空闲时间，并带有在 project 设置中更改它的链接。

- 自定义 Slack 应用触发器现在可以选择允许第三方 bots 触发 agent。在注册上启用 allow bot triggers 切换按钮即可接受来自外部 bots 的事件；来自你自己的和其他 LangSmith 注册 bots 的回显仍会被丢弃以防止循环。
- Agents 现在会立即跳过无法访问或配置错误的非默认 MCP 服务器，而不是重试它们，从而从工具加载步骤中移除缓慢的往返并缩短首 token 时间。

## Sandboxes

- sandbox 命令输出现在会被重新分块为有界的单个 WebSocket 帧，因此不会重组 continuation 帧的客户端（包括 Go SDK）可以读取大型流式或重放的输出，而不会出现截断的 JSON。
- 当未提供 endpoint_url 时，S3 sandbox 挂载现在默认将其设置为 https://s3.amazonaws.com，因此在挂载标准 AWS S3 存储桶时该字段不再是必需的。
- 当主机有备用容量时，sandboxes 现在可以将 CPU 突发到其请求分配量的 2 倍，并且你可以请求低至 0.05 的小数（子核）vCPU。
- 创建 sandbox 时，你现在可以配置 Git、S3 和 GCS 文件系统挂载，包括挂载路径、Git remotes、存储桶设置和缓存选项。配置的挂载会显示在 sandbox 表格和详情视图中。
- LangSmith SDKs 现在支持创建、列出、更新和删除用于拉取私有容器镜像的 sandbox registries，以及现有的 sandbox 和 snapshot 操作。
- Sandbox snapshots 现在的工作方式类似于 Docker 镜像。创建 snapshot 时为其指定名称和 tag；从 Docker 镜像构建时默认沿用该镜像的 tag，对运行中的 sandbox 做 snapshot 默认使用 latest；然后从 name:tag 启动，其中裸名称表示 name:latest。在现有 name:tag 上发布新 snapshot 会将 tag 移动到它，并保留之前的 snapshot，仍然可以通过 id 启动，因此提升构建和回滚是同一操作；没有单独的 retag 步骤。API 接受 snapshot id 的任何地方现在也接受引用：sandbox create 接受单个 snapshot 字段，可包含 id、name:tag 或裸名称，获取裸名称会列出其下的每个 tag 及各自解析到的 snapshot。Snapshots 还有自己的权限：snapshots:create、snapshots:delete 和 snapshots:update，在编辑角色时显示为 Snapshots 分节，现有角色保留其已有的访问权限。snapshot 名称属于最先在其下发布的人，该人可以继续自由发布；其他任何人都需要 snapshots:update，因为移动共享 tag 会改变所有者 sandboxes 启动的内容。snapshot 名称可以打标签，因此访问策略可以在带有特定标签的名称上授予或拒绝该权限，让团队共享一个名称而不是由一个人拥有。
- 当底层主机受到干扰时，sandbox 创建不再间歇性地因 "sandbox not ready" 错误而失败。受影响的容量现在会重试争用的资源锁并自动恢复，而不是让池保持降级状态。
- sandbox 主机启动现在会在重用之前验证完整的版本目录，因此在部分安装或安装过期后，缺失的 initrd 不再导致创建时失败。
- 从 Docker 镜像创建 sandbox snapshot 时现在会记录镜像的 tag（例如 ubuntu:24.04 会成为 24.04 tag），并且从不带 tag 的 snapshot 名称创建 sandbox 时会解析最新的 tag，与 Docker 保持一致。
- 自托管 LangSmith 安装现在会显示 Sandboxes 导航项，并使用实例级 sandbox 标志打开 Sandboxes 页面。
- sandbox 内的 shell 和工具现在会将 sandbox 的名称报告为主机名，而不是通用的默认值，并且该名称可以在 sandbox 内解析。
- 自托管 LangSmith 安装可以在不启用 Deployments 前端的情况下打开 Sandboxes 页面。
- sandboxes 现在默认设置常见的 CA-bundle 环境变量，因此 Python、Node、Deno、curl 和 git 工具会自动信任 sandbox 的 egress 代理证书，并且在流量被代理时不再因 TLS 证书验证错误而失败。
- sandboxes 现在可以选择在停止时保留其内存，因此下一次启动会从上次中断的地方继续，而不是冷启动。创建 sandbox 时设置 preserve_memory_on_stop；默认为关闭。
- sandbox 代理配置现在可以定义应用于 sandbox 中每个命令的环境变量。当某个工具拒绝运行（除非存在凭据环境变量，例如 gh 需要 GH_TOKEN），即使 egress 代理会在网络层注入真实凭据时，这非常方便；设置一个占位值即可使命令启动。
- 创建 sandbox 或 snapshot 时可以附加自由格式的键/值标签。标签会被存储并在读取时返回；sandboxes 继承其 snapshot 的标签，从 Docker 镜像构建的 snapshots 继承镜像的标签。
- sandbox 网络 egress 现在会尝试目的地的每个已解析 IP，而不仅仅是第一个，因此对多宿主主机（例如 apt 软件包镜像）的请求不再在第一个地址在请求端口上不可达时失败。
- 仅设置 mem_bytes 创建 sandbox 时，现在会自动推导出匹配的 CPU 分配，因此较大内存 sandboxes 的请求不再需要显式的 vcpus 值来满足 CPU 与内存的比率。
- sandboxes 接受新的流式执行请求，以 Server-Sent Events 的形式返回 stdout 和 stderr，适用于无法保持 WebSocket 的客户端。传递命令 ID 会重用正在运行的命令，单独的恢复请求会继续被中断的流，而不是再次运行该命令。
- sandboxes 现在自带 PATH 上的 `langsmith` CLI，因此 agents 无需先安装即可查询 traces、runs 和 datasets。
- sandbox 和 snapshot 行现在使用单列布局并将操作放入上下文菜单，snapshot sources 仍可在其菜单中使用，换行的名称保持左对齐。
- 自托管部署中的 Engine sandbox 命令现在会使用 deployment service key 通过 WebSocket 进行认证，防止 sandbox 创建成功后出现 401 失败。
- sandboxes 中的 `langsmith` CLI 已更新到 v0.2.44。其请求现在可以在 `/api` 下提供 API 的自托管部署上解析，此前 `trace messages` 和 project issues 命令在此类部署上会失败。
- 恢复挂起的 sandbox 现在会检查你组织的真实 sandbox 配额（包括特定方案的限制），而不是默认上限。真正超出配额的请求会返回 429 并附带配额消息，而不是 502 Bad Gateway。
- 自托管 LangSmith 现在仅在 deployment 许可证包含 sandbox 访问权限时才启用 sandbox API 和 UI 访问。
- 当启用 phone-home 使用量报告时，在线的自托管 LangSmith 安装现在会报告最终确定的 sandbox 正常运行时间和资源使用情况以进行计费。离线和选择退出的安装不会发送 sandbox 使用量。
- 将 git 仓库挂载到 sandbox 不再会静默失败。克隆现在会信任 sandbox 的证书 bundle，因此仓库会出现在其挂载路径下，而不再以空目录启动。
- Sandboxes 现在会保留近期的 CPU、内存和网络使用量历史，便于了解资源消耗并诊断性能瓶颈。
- 通过 sandbox service URL 的 WebSocket 连接现在会带着完整的 query string 到达你的服务。使用 query 参数（例如 Vite 的 HMR token）自行认证 WebSocket 的开发服务器现在可以连接成功，而不再失败。
- sandboxes 现在通过只读的、由主机服务的文件系统挂载 Context Hub 仓库，因此文件可以直接访问，而无需轮询异步的客户机物化。仓库更新会原子地出现，并且挂载可以在基于内存的停止和启动之间恢复。
- 创建或捕获 snapshot 时，以及为代理规则和代理配置附加自由格式的描述。描述会被存储并在读取时返回，因此你可以向 agent 提供一份关于其 sandbox 镜像和网络访问能力的简明摘要。
- sandbox 文件下载现在接受 Range header，因此你可以获取大文件的一部分或恢复中断的传输，而不是重新开始。响应带有用于安全恢复的 ETag，同一路径支持 HEAD，可在不传输文件的情况下报告文件大小。
- 你现在可以生成一个无需 LangSmith 凭据即可下载单个 sandbox 文件的签名链接，因此文件可以交给浏览器或任何无法携带 API key 的客户端。链接由 sandbox 服务域提供，除非你设置 expires_in_seconds 否则永不过期，并且可以固定响应的内容类型和处置方式。链接的内容会被无限期缓存，因此在文件更改时请生成新链接。
- sandbox 代理规则和回调不再接受诸如 `*.com` 或 `*.co.uk` 之类的 match_hosts 模式，这些模式会将注入的凭据发送到顶级域下的每个主机。通配符现在必须指明可注册的域，例如 `*.example.com`。
- GET /v2/sandboxes/boxes 现在使用 page_size 和不透明游标分页，返回 items 和 next_cursor。limit 和 offset 参数以及 sandboxes 和 offset 响应字段仍然有效，但已弃用。
- 更新 sandbox 的代理配置不再要求 sandbox 正在运行。停止的 sandbox 会存储新配置，并在下次启动时应用它，而不是拒绝该请求。
- GET /v2/sandboxes/snapshots 现在使用 page_size 和不透明游标分页，返回 items 和 next_cursor。limit 和 offset 参数以及 snapshots 和 offset 响应字段仍然有效，但已弃用。

### LLM Gateway

- LLM gateway 数据保护策略现在可以配置 guard pipeline 超时时是放行请求还是阻止请求。现有策略默认在超时时放行请求。
- LLM gateway 现在支持 POST /openai/v1/responses/compact（以及旧版 /responses/compact），并通过 chat 形状的 responses 处理器路由它。
- guard 策略现在允许你选择要检测哪些 PII 规则类别，并分别提供更快的基于规则和较慢的基于模型的检测选项，而不是单一的开/关 PII 切换。
- gateway guard 密钥脱敏现在可以检测更多令牌格式，包括 SendGrid API 令牌、Google OAuth 访问令牌、JWT、Slack webhook URL 和旧版 LangSmith keys。
- LLM gateway 现在接受最大 60 MiB 的请求 body（此前为 10 MiB），因此携带大型图像或文件输入的请求不再被 413 拒绝。
- 当 gateway 支出上限策略针对多个用户、workspaces 或 API keys 时，创建/编辑策略表单现在会说明该限制适用于所选实体的合并支出，而不是每个实体单独计算。

- 某一行 Splits 单元格中的每个 split chip 现在在 experiment results 和 comparison 视图中都是可交互的，其中的 Edit splits 操作会打开单个 example 的 split picker，让你无需离开表格即可重新分配 splits。

### Tracing

- 批量 run ingestion 日志现在会把 run_verbs 作为 run_id 和 verbs 对象的列表输出，而不是以 run UUID 为键的 map，从而避免结构化日志聚合器耗尽动态字段上限。
- LangSmith 现在会对单个项目和用户执行用户自定义的每月 trace 上限。超过配置上限的新 traces 会被拒绝，而对已接受 traces 的 patch 和 feedback 仍然可以继续流转。
- Tracing 和 evaluation onboarding quickstarts 现在会为自带云数据平面的工作区显示正确的 `LANGSMITH_ENDPOINT`，而不是共享的多租户 endpoint。
- 对 trace 中任意 run 执行分享、查看分享或取消分享，现在都会作用于 trace root，因此共享 trace 中的每个 run 都可被公开查看，而公共 run 链接会在共享 trace 中打开所选 run。
- 当项目已有 traces，但当前过滤条件或时间窗口中没有近期 runs 时，项目不再错误显示 onboarding 页面。项目 run-count 检查现在会回看 30 天，而不是之前的 1 小时时间窗。
- Bulk export compression 现在默认使用 zstandard（zstd）以提升性能。自托管环境仍可通过 `FF_BULK_EXPORT_DEFAULT_COMPRESSION` 环境变量保留 gzip 默认值。
- 已登录用户查看公共 runs 时，现在会在侧边栏看到其上次所选工作区的导航。未登录的查看者仍可看到公共 run，但没有已登录工作区的导航。
- 当提交重复的 run create 或 update payload 时，LangSmith 现在会返回更清晰的 409 Conflict 消息。消息会在可能时指出这是重复的 run create 还是 run update 请求。
- 获取 runs 或 thread history 的 LangSmith [MCP tools](/langsmith/langsmith-mcp-server) 现在除了项目名外，也接受 `project UUIDs`，让基于 trace URL 的排查更快、更不容易出错。
- OpenTelemetry resource attributes（通过 `OTEL_RESOURCE_ATTRIBUTES` 设置）现在会以 `otel.resource.*` 命名空间显示在 traces 元数据中，因此你可以附加诸如用户 ID 之类的信息，而不必修改 tracer 发出的 spans。
- 通过原始 OpenTelemetry 发送的 Vercel AI SDK traces，现在会在 Messages 视图中正确渲染。此前这些 traces 会显示一个空的 Messages 标签页，因为没有格式适配器接管它们。
- 选择流式返回的 thread stats 请求，现在会先返回主统计信息，并在 feedback stats 准备好后再补充返回。
- 原生 OpenTelemetry child spans 在早于 SDK 归属的 parent span 到达时不再被丢弃；它们会被缓冲，并无论到达顺序如何都能正确嵌套。
- 当 runs 查询超时时，runs table 现在会显示 timeout banner，以提升响应体验。
- 当 multipart ingestion 批次里某个 run 的 inputs 或 outputs 过大时，LangSmith 现在会保留整个 trace。超大的 input 和 output 字段会被占位内容替换，而不是让整个批次都被拒绝。
- 当 ABAC 拒绝 trace 加载时，Thread 页面现在会显示明确的访问控制消息，而不是通用的检索错误。
- Tracing 视图中的所有时间过滤器现在会查询完整的保留期窗口，而不再回退到较短的后端默认值。这样在扩展时间范围时，trace、thread 和 run 的结果保持一致。
- 来自 VS Code Copilot Chat 的 OpenTelemetry traces 现在会按每个用户回合渲染为一条干净的嵌套 trace。辅助的 title/summary 调用和孤立的 tool spans 会被抑制，message 角色会被修正，token 计数会去重，并自动附加标准化的元数据（integration、agent runtime、thread ID、repo/git 信息）。
- Insights 的 cluster run 统计信息（run 数量、延迟、tokens 和 feedback）现在只反映每个 cluster 内的 runs，而不再为每个 cluster 都显示相同的项目级总计。
- LangSmith Chat 现在在搜索文档时会使用 guest token 向 Chat LangChain 进行身份验证，因此在 Chat LangChain 收紧身份验证后，文档问答仍能继续工作。
- 对于包含 middleware guardrails 或 subagent 侧边对话的 traces，Trace Messages 查看器现在会识别出 “主” 对话，因此消息列表只显示主要交互，而不会把 middleware/subagent 分区交错在一起。其正确性已由覆盖 11 个集成（横跨 LangChain、OpenAI Agents SDK、Vercel AI SDK、Claude Agent SDK、deepagents 和原始 provider 封装）的扩展快照测试套件验证。
- 自定义 dashboard 图表现在可以查询 input 和 output cost 的 P50 和 P99，而不会导致 runs analytics 请求失败。
- Thread stats API 现在接受 `filter` 查询参数，让你可以把聚合统计范围限定在匹配某个 LangSmith filter 表达式（例如 start time 或 trace ID）的 traces。
- LangSmith Chat 现在会从 Chat LangChain LangGraph host（`POST /identity/guest`）签发 Managed Deep Agent guest token 用于文档搜索，而不是使用旧版 Chat LangChain 前端的 guest 路由。

### Engine

- 当 Engine 项目达到其每月支出上限时，Next Run 状态 chip 和项目支出卡片现在会明确显示 “Monthly spend limit reached” 状态，并附带一个可直接跳转去提高上限的按钮。
- 升级了 Redis client 以改善从 Redis 集群拓扑变更中的恢复，修复了集群重连可能卡住的情况。
- Engine 现在允许父 agent 从模型可操作的子任务失败中恢复，并在使 run 失败之前重试临时的 provider 或网络错误。这有助于 issue 扫描在可恢复的模型错误下继续进行，同时仍保留对 auth、配置和代码异常这类硬失败的处理。
- LangSmith 现在通过托管的 [MCP tools](/langsmith/langsmith-mcp-server) 和生成的 SDK 方法暴露 Engine issue 的列表与获取能力。Agents 和 API 客户端现在可以直接通过 `issue ID` 获取 issue 详情，或按项目、状态、严重级别、标签和更新时间过滤 issues。
- 新的 Engine board callout 会引导你前往 trace-scope 设置页面，在那里你可以把 Engine 的 review 限制在匹配特定 run name 或 metadata 值的 runs 上。
- 自托管 Engine 部署现在可以通过设置 `ENGINE_ANTHROPIC_BASE_URL`，把兼容 Anthropic 的模型调用路由到 Gateway 或兼容 LSI 的 endpoint。
- 带有 assertions 的 Engine 生成 examples，现在在从 annotation queue 保存到 dataset 时会添加 Assertions evaluator，与直接使用 Add offline examples 流程保持一致。
- Engine issue 列表现在使用单一的 filter 和 sort 菜单，为 Priority、Status、Tags 和 Sort by 提供紧凑、可折叠的布局，取代了此前两个独立的 popover。
- 当 Engine issue 列表的排序与默认值不同时，现在会在 filter chips 旁边显示当前排序方式作为一个可移除的 chip。
- Engine issue 列表不再显示扫描时序信息（下一次扫描倒计时、上次运行时间或 Run now 操作）；board 设置中单独的区块里仍保留 Pause/Resume 控制。

### Prompts and playground

- 自托管 [Playground](/langsmith/playground-model-providers) 与 evaluator 的出站模型调用现在会遵循 proxy 环境变量，同时保留对每个请求的 SSRF 校验。
- 当你从 playground 将 prompt 保存到某个 application 时，LangSmith 现在会保持工作区 application filter 仍处于 All Applications，而不是把 UI 的其他部分切换到该 application。
- 在 Context Hub 搜索框中输入工作区成员的姓名或邮箱时，现在也会返回他们创建的 prompts 和资源。
- Playground 现在已在 Anthropic、Bedrock 和 Gemini Enterprise Agent Platform 的模型选择器中加入 Claude Sonnet 5、Claude Fable 5 和 Claude Opus 4.8。新的 Anthropic playground 会话默认使用 Claude Sonnet 5。
- Playground 和 evaluator 在通过 IAM Trusted Entity 调用 Amazon Bedrock 时，现在会在 AWS 托管的 LangSmith 中扮演客户角色之前先解析出正确的 LangSmith AWS 凭证。这修复了此前在客户角色被扮演之前报 “Failed to assume role” 的失败。
- 通过 forward proxy 路由的出站模型调用，现在会在 proxy CONNECT 隧道中发送原始 hostname，而不是已解析的 IP，因此按域名对隧道目标做白名单的 proxy 不再会拒绝它们。这修复了自托管 Playground 和 evaluator 调用仅能通过此类 proxy 才能访问的内部 OpenAI 兼容 endpoint 的问题。
- Review 一个 prompt commit 时，现在会显示设置在模型上的所有额外参数（例如 verbosity），而不仅是固定的某个子集。

### Feedback

- 编辑 evaluator 生成 feedback 的分数时（例如在 experiment comparison 视图中），现在可以正确保存，而不会再报 “Failed to add feedback correction”。
- 向 annotation queue 添加 runs 的 POST 请求现在接受可选的 `extend_trace_retention` 查询参数。当设置为 false 时，短保留期 traces 不会被升级到 extended retention。默认值仍为 true，以保持向后兼容。
- 从 LangSmith UI 添加 feedback 或 reviewer notes 时，现在不会再把短保留期 traces 升级到 extended retention。长保留期 traces 不受影响。
- Feedback statistics queries 现在通过官方 ClickHouse client 路由，解决了查询失败问题，并提升了与 ClickHouse 25.x 的兼容性。
- 当客户端提供 session 和 start time 时，feedback 创建现在会从 SmithDB 解析 run metadata，因此仅使用 SmithDB 的部署不再依赖 ClickHouse 来执行 eager feedback 写入。
- `POST /feedback/eager` endpoint 已被弃用，取而代之的是 `POST /feedback`，并计划于 2026-08-10 移除。请将任何直接调用 `/feedback/eager` 的集成更新为使用 `POST /feedback`。

### Monitoring and alerting

- Alert chart previews 现在可以一致地处理相对日期范围，避免加载 14 天或 30 天预览时失败。
- [Dashboards](/langsmith/dashboards) 图表的 tooltip 和坐标轴现在最多显示 8 位小数（此前为 2 位），因此极小的成本和比率不再被四舍五入为 0。
- 自定义 dashboard 上的时间序列图表，现在会为缺失数据点保留空隙，而不是把它们画成 0；折线也会跨过这些空隙连接起来，因此趋势仍然清晰可读。

### Automations

- 在没有 filter 的情况下应用预构建 evaluator 时，现在默认只在 root runs 上运行，与手动创建的 evaluators 保持一致。此前它会在 trace 中的每个嵌套 run 上都运行。
- 打开或关闭在线 evaluator 或 automation 时，现在任何有权编辑 rules 的角色都可以成功保存，而不会再对没有 retention-configuration 权限的成员静默回滚。

## Deployment

- 自托管部署现在可以申请超过此前 Cloud 限制的 CPU 和内存配置，即超过 8/16 核和 32/16 GB，只受你的集群容量约束。下限、128 的倍数粒度，以及 Redis 内存顺序规则仍然适用。
- 自定义 Slack app triggers 现在可以选择允许第三方 bots 触发 agent。你可以在某个 registration 上启用 allow bot triggers 开关，以接收外部 bots 的事件；来自你自己的 bot 和其他 LangSmith 注册 bots 的回显仍会被丢弃，以避免循环。
- Agents 现在会立即跳过不可达或配置错误的非默认 MCP servers，而不是反复重试，从而减少 tool-loading 步骤中的慢往返，并缩短首个 token 的时间。
- 对于 LangGraph Platform deployments，standby（uptime）分钟数此前在不同 usage-reporting 运行中，如果副本上报了重叠区间，可能会被重复计费。现在报表会对每一分钟在不同运行间去重，因此每分钟最多只计费一次。
- Studio assistants 页面上的多选下拉菜单（例如 Selected Tools）现在会渲染在配置对话框上方，而不是被它遮挡，因此其选项可见且可选。
- 使用 Microsoft Entra ID（Azure IAM）身份验证的 Redis 连接，现在会在 access token 过期之前自动重新进行身份验证，因此长连接不再会断开。集群版 Azure Redis 现在也支持 IAM 身份验证。
- Deployment 的 Crons 标签页现在会以你的本地时区显示每个调度，而不再是原始 UTC，与 Next Run Date 列保持一致。
- LangSmith Deployment 现在支持通过 control plane API 把 deployment 更新到固定的资源层级。更新会应用所选层级的资源配置，调整 Cloud SQL 或 RDS 的规格，并滚动出一个新 revision。
- 你现在可以从某个 deployment 的 Settings 中对其进行重命名，为其设置一个友好的显示名，而无需重新创建。该 deployment 的 URL 和基础设施保持不变。

## Sandboxes

- Sandbox 命令输出现在会重新切分为有边界的单个 WebSocket frame，因此不会重组 continuation frames 的客户端（包括 Go SDK）现在也可以读取大型流式或回放输出，而不会出现 JSON 被截断的情况。
- S3 sandbox mounts 现在在未提供 `endpoint_url` 时，会默认使用 `https://s3.amazonaws.com`，因此挂载标准 AWS S3 bucket 时不再必须填写该字段。
- [Sandboxes](/langsmith/sandboxes) 现在可在宿主机有空闲容量时，将 CPU 突发提升到所请求配额的 2 倍，并支持最低 0.05 的分数（子核）vCPU 请求。
- 创建 sandbox 时，你现在可以配置 Git、S3 和 GCS 文件系统挂载，包括挂载路径、Git remotes、bucket 设置和缓存选项。配置好的 mounts 会显示在 sandbox 表格和详情页中。
- LangSmith SDK 现在支持为拉取私有容器镜像创建、列出、更新和删除 sandbox registries，与现有的 sandbox 和 snapshot 操作并存。
- 当底层宿主机受到扰动时，sandbox 创建不再会间歇性报 “sandbox not ready” 错误。受影响的容量现在会重试争用的资源锁并自动恢复，而不会让池处于降级状态。
- Sandbox 宿主机启动现在在复用前会校验完整的版本目录，因此在部分或陈旧的安装之后，缺失 initrd 不再会导致创建时失败。
- 从 Docker 镜像创建 sandbox snapshot 时，现在会记录该镜像的 tag（例如 ubuntu:24.04 会变成 24.04 tag）；在未带 tag 的情况下用 snapshot 名创建 sandbox 时，会解析为 latest tag，与 Docker 行为一致。
- 自托管 LangSmith 安装现在会显示 Sandboxes 导航项，并使用实例级 sandbox 标志来打开 Sandboxes 页面。
- Sandbox 内的 shells 和工具现在会把 sandbox 的名称作为 hostname 上报，而不再是通用的默认值，并且该名称可以从 sandbox 内部解析。
- 自托管 LangSmith 安装现在无需启用 Deployments 前端即可打开 Sandboxes 页面。
- Sandbox 现在会默认设置通用的 CA-bundle 环境变量，因此 Python、Node、Deno、curl 和 git 工具会自动信任 sandbox 的 egress proxy 证书，当其流量被代理时不再会因 TLS 证书校验错误而失败。

### LLM Gateway

- LLM gateway 数据保护策略现在可以配置当 guard pipeline 超时时代是放行请求还是阻止请求。现有策略默认在超时时放行请求。
- LLM gateway 现在支持 `POST /openai/v1/responses/compact`（以及旧版的 `/responses/compact`），并通过 chat 形态的 responses handler 路由。
- Guard policies 现在让你可以选择要检测哪些 PII rule 类别，分别提供更快的基于规则的检测和较慢的基于模型的检测选项，而不再是单一的 PII 开关。
- Gateway guard 的 secret redaction 现在会检测更多 token 格式，包括 SendGrid API tokens、Google OAuth access tokens、JWTs、Slack webhook URLs 和旧版 LangSmith keys。
- 当 gateway spend-cap 策略针对不止一个用户、工作区或 API key 时，创建/编辑策略表单现在会说明该上限适用于所选实体的合计支出，而不是按单个实体计算。
- LLM gateway 现在会把它不直接处理的每一个已记录的 OpenAI API 路由（models、files、batches、images 等）转发到上游 provider，因此客户端可以通过 gateway 访问完整的 OpenAI 接口面。自定义的 OpenAI 兼容 providers 会继承相同的 passthrough 路由。
- LLM Gateway 策略页面现在允许你按支出上限或使用率百分比排序每个分区，并过滤到特定的工作区、用户或 API key。
- LLM gateway 数据保护的 redaction 现在会在被屏蔽的消息文本前加一段简短声明，让模型知道 SAFE_TO_USE 占位符可以原样复用。
- LLM Gateway 现在会代理 Anthropic 的 Files 和 Managed Agents endpoint，因此你可以在使用 gateway 管理的工作区 key 的同时，将它们与 Messages 和 Models 一起使用。
- 创建 LLM Gateway 支出或数据保护策略时，现在会应用于你当前登录的组织，组织下拉框被替换为当前组织的只读显示。
- 较长的所选值（例如 Gateway Policies filter 中的用户邮箱），现在会以省略号截断，而不再与下拉箭头重叠。
- LLM Gateway 现在在其 provider 路由上接受工作区范围的 LangSmith OAuth bearer token，因此 OAuth 客户端无需 LangSmith API key 即可调用已配置的模型。
