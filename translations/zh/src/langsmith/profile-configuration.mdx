LangSmith SDK 的 profile 让你可以把 [API 密钥](/langsmith/create-account-api-key)、端点和工作区 ID 保存在可复用的 JSON 文件中，而不是在每个 shell 会话里反复设置同样的环境变量。

如果你经常在不同的 [LangSmith Cloud 区域](/langsmith/cloud#regional-storage)、自托管实例或 [工作区](/langsmith/administration-overview#workspaces) 之间切换，或者希望远程运行时从挂载文件中加载同一套 SDK 配置，就适合使用 profile。

<Warning>
Profile 文件可能包含 API 密钥和 OAuth 刷新令牌。不要把它们提交到源码控制，不要打包进容器镜像，也不要输出到日志中。请像保护其他凭证一样存储和挂载这些文件。
</Warning>

## 最低版本

以下版本开始支持 profile：

| 工具或 SDK | 最低版本 |
| --- | --- |
| LangSmith CLI profile commands | `v0.2.26` |
| `langsmith auth login` | `v0.2.30` |
| Go SDK | `v0.7.0` |
| Python SDK | `v0.8.1` |
| TypeScript SDK | `v0.6.1` |
| Java SDK | `v0.1.0-beta.3` |

## Profile 文件位置

默认情况下，[SDK](/langsmith/reference) 会在以下位置查找 profile 文件：

```text
~/.langsmith/config.json
```

如果你想使用其他路径，请设置 `LANGSMITH_CONFIG_FILE`：

```shell
export LANGSMITH_CONFIG_FILE=/path/to/langsmith-config.json
```

TypeScript SDK 只会在类似 Node.js 的运行时中加载 profile。浏览器和 Web Worker 运行时没有文件系统访问能力，因此在这些环境中请显式传入配置。

## 创建 profile 文件

创建 `~/.langsmith/config.json`，并在其中定义 `profiles` 对象。每个 profile 可以包含：

| 字段 | 说明 |
| --- | --- |
| `api_url` | LangSmith API 端点。使用方式与 `LANGSMITH_ENDPOINT` 相同。 |
| `api_key` | LangSmith API 密钥。参见[创建账户和 API 密钥](/langsmith/create-account-api-key)。 |
| `workspace_id` | 工作区 ID。当 API 密钥可以访问多个工作区时必填。 |
| `oauth` | 由 LangSmith 工具创建的 OAuth 令牌元数据。 |

```json
{
  "current_profile": "dev",
  "profiles": {
    "dev": {
      "api_url": "https://api.smith.langchain.com",
      "api_key": "<LANGSMITH_API_KEY>",
      "workspace_id": "<WORKSPACE_ID>"
    },
    "eu": {
      "api_url": "https://eu.api.smith.langchain.com",
      "api_key": "<EU_LANGSMITH_API_KEY>",
      "workspace_id": "<EU_WORKSPACE_ID>"
    },
    "apac": {
      "api_url": "https://apac.api.smith.langchain.com",
      "api_key": "<APAC_LANGSMITH_API_KEY>",
      "workspace_id": "<APAC_WORKSPACE_ID>"
    }
  }
}
```

请限制文件权限，只允许当前用户读取：

```shell
chmod 600 ~/.langsmith/config.json
```

## 选择 profile

SDK 会按以下顺序选择 profile：

1. 如果设置了 `LANGSMITH_PROFILE`，优先使用它。
1. 如果 profile 文件中设置了 `current_profile`，使用它。
1. 如果存在名为 `default` 的 profile，使用它。

例如：

```shell
export LANGSMITH_PROFILE=eu
```

[LangSmith CLI](/langsmith/langsmith-cli) 也支持全局 `--profile` 参数。对于该命令，它的优先级高于 `LANGSMITH_PROFILE`：

```shell
langsmith --profile eu project list
```

## 使用 CLI 管理 profile

使用 [LangSmith CLI](/langsmith/langsmith-cli) 可以创建、查看、切换和删除 profile，而不必手动编辑 JSON 文件。

如果要基于现有 API 密钥创建一个 profile：

```shell
export LANGSMITH_API_KEY=<LANGSMITH_API_KEY>
langsmith profile create dev \
  --workspace-id <WORKSPACE_ID> \
  --set-current
```

你也可以通过命令参数传入密钥和端点。共享机器上更推荐使用环境变量，因为 shell 历史记录可能会保留命令参数。

```shell
langsmith profile create eu \
  --api-key <EU_LANGSMITH_API_KEY> \
  --api-url https://eu.api.smith.langchain.com \
  --workspace-id <EU_WORKSPACE_ID>
```

常用 profile 命令如下：

| 命令 | 说明 |
| --- | --- |
| `langsmith profile list` | 列出已保存的 profile。别名：`langsmith profile ls`。 |
| `langsmith profile show <name>` | 显示指定 profile。输出中的敏感值会被打码。 |
| `langsmith profile use <name>` | 在 profile 文件中设置 `current_profile`。 |
| `langsmith profile set-workspace <workspace-id>` | 为当前选中的 profile 设置默认工作区。 |
| `langsmith profile delete <name>` | 删除指定 profile。 |

如果想要更适合人工阅读的表格输出，请使用 `--format pretty`：

```shell
langsmith --format pretty profile list
```

## 使用 `langsmith auth login` 进行认证

运行 `langsmith auth login` 可以通过 OAuth 完成认证，而不是手动创建基于 API 密钥的 profile。该命令会启动基于浏览器的设备授权流程，把 OAuth 令牌保存到所选 profile 中，并将其设为当前 profile。

<Note>
`langsmith auth login` 在 LangSmith CLI `v0.2.46` 及以上版本中也可以用于自托管实例，前提是该部署为 LangSmith `0.16` 或以上版本，并且启用了 OAuth 授权服务器。当你的 Helm chart 中设置了 `config.hostname` **并且**配置了签名 JWKS（`config.signingJwks` 或 `config.existingSecretName` 中的 `langsmith_signing_jwks` 键）时，OAuth 授权服务器会自动启用。在更早的部署上，或未配置签名 JWKS 的情况下，请改用基于 API 密钥的 profile。
</Note>

```shell
langsmith auth login
```

可以使用 `--profile` 或 `LANGSMITH_PROFILE` 选择 profile：

```shell
langsmith auth login --profile dev
```

对于自托管实例，请传入其 base URL。CLI 会读取部署的授权服务器元数据来查找 OAuth 端点：

```shell
langsmith auth login --api-url https://langsmith.example.com --profile self-hosted
```
自托管的 OAuth 登录要求 Helm chart 为 `0.16.0` 或以上版本，并配置了签名 JWKS。有关配置方式，请参阅[启用 Remote MCP](/langsmith/langsmith-remote-mcp#enabling-remote-mcp)。否则请改用基于 API 密钥的 profile。

对于无图形界面的环境，可以禁止自动打开浏览器，并传入工作区 ID：

```shell
langsmith auth login \
  --profile prod \
  --no-browser \
  --workspace-id <WORKSPACE_ID>
```

`langsmith auth login` 会按以下顺序选择 profile 名称：

1. 如果传入了 `--profile`，优先使用它。
1. 如果设置了 `LANGSMITH_PROFILE`，使用它。
1. 如果 profile 文件中设置了 `current_profile`，使用它。
1. `default`。

它会按以下顺序选择 API URL：

1. 如果传入了 `--api-url`，优先使用它。
1. 如果设置了 `LANGSMITH_ENDPOINT`，使用它。
1. 如果所选 profile 中存在 `api_url`，使用它。
1. 使用默认的 LangSmith Cloud 端点。

登录后，CLI 和 SDK 都可以使用保存下来的 profile。CLI 会在需要时刷新 OAuth 令牌，并把更新后的令牌字段写回 profile 文件。SDK 也会在未设置环境变量或构造函数 API 密钥认证时，使用 profile 中的 OAuth 访问令牌。

## 覆盖 profile 值

显式传入的客户端构造参数和环境变量优先级高于 profile 中的值。

| 配置项 | 优先级 |
| --- | --- |
| Endpoint | 构造函数 `api_url` 或 `apiUrl`，然后 `LANGSMITH_ENDPOINT`，然后 profile 中的 `api_url`，最后是默认的 LangSmith Cloud 端点。 |
| Authentication | 构造函数 API key，然后 `LANGSMITH_API_KEY`，然后 profile 中的 OAuth access token，最后是 profile 中的 `api_key`。 |
| Workspace | 构造函数 `workspace_id` 或 `workspaceId`，然后 `LANGSMITH_WORKSPACE_ID`，然后 profile 中的 `workspace_id`。 |

旧的 `LANGCHAIN_API_KEY`、`LANGCHAIN_ENDPOINT` 和 `LANGCHAIN_WORKSPACE_ID` 别名仍然可用，但新的配置请优先使用 `LANGSMITH_*` 名称。

如果某个 profile 同时包含 `oauth.access_token` 和 `api_key`，SDK 会优先使用 OAuth access token。如果存在 OAuth refresh token，并且 access token 已过期或接近过期，SDK 可以刷新令牌，并把更新后的令牌字段写回 profile 文件。

<Note>
如果你把 profile 文件以只读方式挂载，就无法持久化 OAuth 刷新后的新令牌。只读挂载适合基于 API 密钥的 profile。只有在你明确依赖 OAuth 令牌刷新时，才应使用可写挂载。
</Note>

## 在代码中使用 profile

当 profile 文件存在时，像平常一样创建客户端即可：

<CodeGroup>

```python Python
from langsmith import Client

client = Client()
```

```typescript TypeScript
import { Client } from "langsmith";

const client = new Client();
```

</CodeGroup>

如果你想在代码中覆盖 profile，请显式传入对应的值：

<CodeGroup>

```python Python
from langsmith import Client

client = Client(api_key="<LANGSMITH_API_KEY>")
```

```typescript TypeScript
import { Client } from "langsmith";

const client = new Client({ apiKey: "<LANGSMITH_API_KEY>" });
```

</CodeGroup>

## 在远程运行时挂载 profile

对于远程运行时，请把 profile 文件作为 secret 文件挂载，并将 `LANGSMITH_CONFIG_FILE` 设置为挂载路径。不要把该文件复制进镜像或仓库中。

### Docker

把本地 profile 目录挂载到容器中：

```shell
docker run --rm \
  -e LANGSMITH_CONFIG_FILE=/home/app/.langsmith/config.json \
  -e LANGSMITH_PROFILE=prod \
  -v "$HOME/.langsmith:/home/app/.langsmith:ro" \
  my-image
```

只有当 profile 使用 OAuth 刷新令牌时，才应使用读写挂载：

```shell
docker run --rm \
  -e LANGSMITH_CONFIG_FILE=/home/app/.langsmith/config.json \
  -e LANGSMITH_PROFILE=prod \
  -v "$HOME/.langsmith:/home/app/.langsmith" \
  my-image
```

### Kubernetes

基于 profile 文件创建 Kubernetes secret：

```shell
kubectl create secret generic langsmith-profile \
  --from-file=config.json="$HOME/.langsmith/config.json"
```

挂载该 secret，并让 SDK 指向它：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app
spec:
  template:
    spec:
      containers:
        - name: app
          image: my-image
          env:
            - name: LANGSMITH_CONFIG_FILE
              value: /var/run/langsmith/config.json
            - name: LANGSMITH_PROFILE
              value: prod
          volumeMounts:
            - name: langsmith-profile
              mountPath: /var/run/langsmith
              readOnly: true
      volumes:
        - name: langsmith-profile
          secret:
            secretName: langsmith-profile
```

Kubernetes secret volume 是只读的。这个模式更适合基于 API 密钥的 profile；如果你的 OAuth profile 需要刷新并持久化令牌，请改用可写的 secret 同步机制。

### 远程开发和 CI

在远程开发环境或 CI 作业中，把 profile JSON 存到平台的 secret 存储里，在运行时写入临时文件，并把 `LANGSMITH_CONFIG_FILE` 指向该文件路径。

```shell
mkdir -p "$RUNNER_TEMP/langsmith"
printf '%s' "$LANGSMITH_PROFILE_JSON" > "$RUNNER_TEMP/langsmith/config.json"
chmod 600 "$RUNNER_TEMP/langsmith/config.json"
export LANGSMITH_CONFIG_FILE="$RUNNER_TEMP/langsmith/config.json"
export LANGSMITH_PROFILE=prod
```

对于托管的 [LangSmith Cloud](/langsmith/cloud)，除非平台明确支持挂载 secret 文件，否则请把这些值配置为环境变量或[工作区 secret](/langsmith/set-up-hierarchy#configure-workspace-settings)。
