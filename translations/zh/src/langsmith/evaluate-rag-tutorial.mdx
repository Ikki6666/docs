Retrieval Augmented Generation（RAG）是一种通过为 Large Language Models（LLMs）提供相关外部知识来增强其能力的技术。它已经成为构建 LLM 应用最常见的方法之一。

本教程会向你展示如何使用 LangSmith 评估 RAG 应用。你将学到：

1. 如何创建测试数据集
2. 如何在这些数据集上运行 RAG 应用
3. 如何用不同评估指标衡量应用表现

## 概览

一个典型的 RAG 评估工作流包含 3 个主要步骤：

1. 创建一个包含问题及其期望答案的数据集

2. 在这些问题上运行你的 RAG 应用

3. 使用 evaluators 衡量应用表现，重点观察以下因素：

   * 答案相关性
   * 答案准确性
   * 检索质量

在本教程中，我们会创建并评估一个 bot，它回答关于 [Lilian Weng](https://lilianweng.github.io/) 几篇高质量博客文章的问题。

## Evaluators

理解不同类型的 RAG evaluators 的一个常见方式，是把它们看作“评估对象 X 比较基准”的组合：

1. **Correctness**：Response vs reference answer

   * `Goal`：衡量“*RAG chain 的答案，相对于 ground-truth answer 来说，有多相似 / 多正确*”
   * `Mode`：需要通过 dataset 提供 ground truth（reference）answer
   * `Evaluator`：使用 LLM-as-judge 评估答案正确性

2. **Relevance**：Response vs input

   * `Goal`：衡量“*生成的回答对最初用户输入的回应程度如何*”
   * `Mode`：不需要 reference answer，因为它只比较回答与输入问题
   * `Evaluator`：使用 LLM-as-judge 评估答案相关性、帮助性等

3. **Groundedness**：Response vs retrieved docs

   * `Goal`：衡量“*生成的回答在多大程度上与检索到的上下文一致*”
   * `Mode`：不需要 reference answer，因为它会把回答和检索上下文相比较
   * `Evaluator`：使用 LLM-as-judge 评估 faithful 程度、是否 hallucination 等

4. **Retrieval relevance**：Retrieved docs vs input

   * `Goal`：衡量“*对于这个 query，我检索出的结果是否相关*”
   * `Mode`：不需要 reference answer，因为它会把问题与检索上下文相比较
   * `Evaluator`：使用 LLM-as-judge 评估相关性
