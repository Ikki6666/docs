速率限制策略限制 subject 在一个较短的滚动时间窗口内通过 [LLM Gateway](/langsmith/llm-gateway) 消耗的**请求数**或**token 数**。gateway 会实时强制执行该限制，并阻止任何会把 subject 推过上限的请求，返回带有 `Retry-After` header 的 `429` 响应，且响应体会指明拦截策略：

```json
{"type":"error","error":{"message":"request blocked by gateway policies: <POLICY_NAME>"}}
```

`Retry-After` 的值是距当前窗口重置的秒数。client 应该遵守这个 header，在重试之前先退避。

被阻止的请求永远不会到达 provider，因此不会触发 [fallback 链](/langsmith/llm-gateway-fallbacks)，即使 `429` 是默认的 fallback 触发条件。

<Tip>
速率限制策略和 [spend cap policies](/langsmith/llm-gateway-spend-policies) 互补，可以同时启用：spend caps 用于成本控制，rate limits 用于吞吐量和流量控制。
</Tip>

## 策略维度

速率限制策略会在每个入站请求上评估。

| Subject | 限制什么 | 示例 |
| --- | --- | --- |
| **Organization** | 该组织内所有工作区的请求数或 token 数 | "整个组织每分钟最多发送 5,000 个请求" |
| **Workspace** | 单个[工作区](/langsmith/administration-overview#workspaces)或一组工作区内的请求数或 token 数 | "R&D 工作区每小时不能超过 1,000,000 tokens" |
| **User** | 来自单个用户或一组用户的请求或 token（从 API key 的身份解析而来） | "任何单个开发者每分钟最多发送 100 个请求" |
| **API key** | 来自单个 [API key](/langsmith/create-account-api-key) 或一组 API keys 的请求或 token | "客服 agent keys 共享每分钟 200 个请求的限制" |

### 默认策略与细粒度策略

速率限制策略有两种模式：

1. **默认策略**自动应用于某个 subject 维度的每个成员。例如："这个工作区中的每个用户都获得每分钟 100 个请求的默认上限。"无需为每个人创建策略。
2. **细粒度策略**针对一个命名的 subject，并仅为该 subject 覆盖默认值。例如："值班工程师获得每分钟 500 个请求。"编辑默认策略会更新仍然应用它的所有人。

### 独立执行

每个 subject 都被单独跟踪和限制。一个用户达到自己的限额不会影响其他用户。

## 限制

一条速率限制策略可以同时强制执行**多个限制**。例如，一条策略可以同时执行每分钟 100 个请求和每小时 1,000,000 tokens。

每个限制有三个字段：

| 字段 | 允许的值 |
| --- | --- |
| **Value** | 正整数（上限） |
| **Metric** | `requests` 或 `tokens`（provider 报告的总 tokens） |
| **Window** | `minute` 或 `hour` |

规则：

- 每条策略至少需要一个限制。
- 一条策略中不能有两个 metric 和 window 组合相同的限制。

## 创建速率限制策略

<Warning>
创建和管理策略需要 `organization:gateway:manage` 权限。Organization Admins 和 Organization Operators 默认拥有该权限。各组织角色的具体权限请参见[组织角色](/langsmith/rbac#organization-roles)。
</Warning>

1. 前往 **LLM Gateway** 并选择 **Rate limiting**。
1. 点击 **Create rate limit**。
1. 选择范围（organization、workspace、user 或 API key）。
1. 添加一个或多个限制，每个限制包含 value、metric 和 window。
1. 点击 **Create rate limit**。

策略会立即生效。

速率限制策略还可以携带一个针对自定义请求 header 的条件，使来自单个 subject 的流量按 header 值拆分为独立的限额。用它在一个 API key 下为每个终端客户、租户或团队提供自己的吞吐量配额。更多信息请参见[基于 header 的策略](/langsmith/llm-gateway-header-policies)。
