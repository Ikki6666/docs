LangSmith 以多租户 SaaS 方案运行。我们的安全模型力求清晰简单：LangChain 负责保护平台基础设施与应用本身，你则负责保护自己的具体使用方式、数据输入，以及你构建的 AI agents。

## 责任矩阵

| 领域 | LangChain 责任（provider） | 客户责任（user） |
| :---- | :---- | :---- |
| **Infrastructure** | 我们管理底层云基础设施（通过 GCP），包括服务器、网络、操作系统补丁和容量规划。GCP 负责物理数据中心。 | 不适用。你无需在 SaaS 环境中配置或维护计算资源。 |
| **Application** | 我们负责 LangSmith 应用代码、API endpoints 和数据库集群的安全，包括代码扫描和渗透测试。 | 你需要对使用我们 SDK 构建的 AI chains 与 agents 的安全性负责。 |
| **Data** | 我们执行租户隔离，并对静态数据采用 AES-256 加密，对传输中数据采用 TLS 1.2 及以上版本加密。 | 你控制发送给我们的数据内容，并且必须在数据离开你的环境前，通过 SDK 过滤敏感 PII。 |
| **Identity** | 我们提供包括 SSO/SCIM、MFA enforcement 选项和 RBAC 框架在内的控制护栏。 | 你负责管理用户名册、分配角色（例如 Admin 与 Viewer），以及撤销离职员工的访问权限。 |
| **Secrets** | 我们会安全地存储你托付给平台的 secrets。 | 你负责轮换自己的 API keys，并确保它们不会被硬编码进应用。 |

## LangChain 的职责（平台侧）

- 我们维持 SOC 2 Type II、GDPR 和 HIPAA 合规性，并每年接受第三方审计和渗透测试。
- 我们管理 Google Cloud Platform（GCP）上的所有底层基础设施，包括网络防火墙、通过 Cloud Armor 提供的 DDoS 防护，以及容器安全。
- 我们按照 SLA 维护高可用性，执行每日备份，并为 LangSmith 服务处理灾难恢复。
- 我们会在严格的服务级别协议内修复已确认的平台漏洞，其中严重等级问题会在 2 周内修复，高等级问题会在 30 天内修复。
- 我们对所有客户数据在静态时使用 AES-256 加密，在传输中使用 TLS 1.2 及以上版本加密。

## 客户的职责（使用侧）

- 你必须执行最小权限原则，并在员工离开组织时立即撤销其访问权限。
- 你必须确保不会向平台发送被禁止的数据，例如 PCI DSS 持卡人数据，并在源头使用 SDK 的 masking 功能脱敏 PII。
- 你需要对运行 LangChain SDK 的环境安全负责，包括你的笔记本电脑和服务器。
- 你必须定期轮换 API keys，并确保它们存放在环境变量中，而不是硬编码在源代码里。

## 面向客户的安全最佳实践

为了与你在我们 SOC 2 Type II 框架下的安全假设保持一致，我们建议客户维持以下内部规范：

- 在租户设置中维护最新的技术联系人和安全联系人信息，以便在发生事件时我们的团队能联系到你。
- 如果怀疑凭证泄露，请立即通过自助门户轮换密钥。如有问题或需要在泄露处理中获得协助，也可以随时联系 LangChain 安全团队。
- 为你的具体应用制定灾难恢复计划，以应对 LangSmith 服务不可用的场景。
- 确保访问 LangSmith UI 的工作站和终端设备被定期打补丁并保持安全。
