传统软件应用的逻辑主要通过编写代码来实现，而 AI 应用的逻辑往往更多地来自 prompts。

本指南将介绍 LangSmith 中 prompt engineering 的核心概念。

## 为什么需要 prompt engineering？

Prompt 可以在不改变模型底层能力的前提下，引导模型的行为。通过提供指令、示例和上下文，prompt 会塑造模型如何响应输入。

Prompt engineering 之所以重要，是因为它能帮助你修改模型行为。虽然也存在其他方法，比如 fine-tuning，但 prompt engineering 通常具有最低的使用门槛，而且往往能带来最高的投入回报比。

Prompt engineering 往往是一个跨学科协作的过程。最有效的 prompt engineer，未必是构建应用的软件工程师，也可能是产品经理、领域专家或其他非技术团队成员。要支撑这种跨职能协作，合适的工具和基础设施至关重要。

## Prompt 类型

Prompt 格式主要有两类：`chat` 风格 prompts 和 `completion` 风格 prompts。

**Chat prompts** 是一组消息列表，每条消息都带有一个角色，例如 `system`、`user` 或 `assistant`。这是当前大多数模型 API 支持的 prompting 方式，也是推荐格式。

**Completion prompts** 是单个字符串。这是一种较老的 prompting 风格，现在主要是为了向后兼容而保留。

<Note>
除非你有明确理由必须使用 completion prompts，否则新项目请优先使用 chat prompts。对于多轮对话，chat prompts 的结构更清晰，也更受现代 LLM 支持。
</Note>

## Prompts 与 prompt templates

虽然 *prompt* 和 *prompt template* 常常被混用，但理解两者的区别，有助于更清楚地理解 LangSmith 如何管理和评估你的 AI 应用。

- **Prompts** 指的是实际传给语言模型的消息内容。
- **Prompt templates** 则允许你创建可复用的 prompt，其中包含会在运行时填充的动态占位符。你不必把值硬编码到 prompt 里，而是定义变量，由 LangSmith 在每次运行 prompt 时用不同输入替换它们。这会让 prompts 更灵活、更容易测试，也更便于迭代。

下面是模板在实际中的工作方式：

1. **定义模板**：创建一个带变量（花括号标记）的 prompt，这些变量会在运行时被替换：

    ```
    You are a customer support agent. This is the refund policy:

    {refund_policy}

    Please respond to the user's question:

    {question}
    ```

1. **提供输入值**：为每个变量传入实际值：

    ```json
    {
    "refund_policy": "no refunds under any circumstances",
    "question": "can I get a refund for this hat?"
    }
    ```

1. **得到最终 prompt**：LangSmith 会用这些输入替换变量，生成最终发给模型的 prompt：

    ```
    You are a customer support agent. This is the refund policy:

    no refunds under any circumstances

    Please respond to the user's question:

    Can I get a refund for this hat?
    ```

<Tip>
关于模板变量语法和格式选项的更多说明，请参见 [Prompt template format](/langsmith/create-a-prompt#template-format)。
</Tip>

## LangSmith 中的 prompts

你可以在 LangSmith 中存储并版本化 prompt templates。这些模板可以在 Playground 中测试，通过 commits 和 tags 进行版本管理，并被拉取到你的应用代码中。

<Callout type="info" color="#4F46E5" icon="player-play" iconType="regular">
打开 [Playground](https://smith.langchain.com/playground) 创建并测试你的第一个 prompt template。分步说明请参见 [Create a prompt](/langsmith/create-a-prompt)。
</Callout>

下面几节将介绍 prompt templates 的关键方面。

### F-string 与 mustache

你可以使用 [f-string](https://realpython.com/python-f-strings/) 或 [mustache](https://mustache.github.io/mustache.5.html) 格式，将输入变量填充到 prompt template 中。

关于如何在 Playground 中使用这些格式，请参见 [Template format](/langsmith/create-a-prompt#template-format)。

<Check>
[Playground](https://smith.langchain.com/playground) 默认使用 `f-string` 作为模板格式，但你也可以在 prompt settings/template format 部分切换到 `mustache`。`mustache` 在条件变量、循环和嵌套 keys 方面更灵活。对于条件变量，你需要在 `inputs` 区域手动添加 JSON 变量。详情请阅读[官方文档](https://mustache.github.io/mustache.5.html)。
</Check>

### Tools

[Tools](/langsmith/use-tools) 是 LLM 用来与外部世界交互的接口。一个 tool 由名称、描述，以及用于调用该 tool 的参数 JSON schema 组成。

### Structured output

Structured output 是大多数先进 LLM 都支持的一项能力。模型输出的不是原始文本，而是遵循指定 schema 的结构化结果。它在底层可能会使用 [Tools](#tools)，也可能不会。

<Check>
Structured output 和 tools 类似，但有几个关键区别。使用 tools 时，LLM 会自己决定调用哪个 tool，或者选择不调用任何 tool；而使用 structured output 时，LLM **总是** 会按该格式响应。使用 tools 时，LLM 可能会选择 **多个** tools；而 structured output 只会生成一个响应。
</Check>

### Model

你也可以选择把模型配置和 prompt template 一起存储下来。这包括模型名称和其他参数，例如 temperature 等。

## Prompt 版本管理

版本管理是 prompt 迭代和协作中的关键能力。

### Commits

每次保存 prompt 更新时，都会生成一个带唯一 commit hash 的新 commit。这让你可以：

- 查看 prompt 的完整变更历史。
- 审查更早版本。
- 在需要时回退到之前的状态。
- 在代码中通过 commit hash 引用特定版本，例如 `client.pull_prompt("prompt_name:commit_hash")`。

在 UI 中，你可以在 [Prompt detail page](/langsmith/manage-prompts#prompt-detail-page) 右上角切换 **Diff**，把某个 commit 与它的前一个版本进行比较。

### Tags

Commit tags 是可读性更好的标签，它们指向 prompt 历史中的特定 commits。与 commit hash 不同，tag 可以移动到其他 commits 上，因此你可以在不改代码的情况下，更新代码实际引用的 prompt 版本。

Commit tags 的常见用途包括：

- **Environments**：`staging` 和 `production` 标签是 [Environments](/langsmith/manage-prompts#environments) 功能保留的，用于在命名部署目标之间推广 commits，并在不改代码的情况下切换版本。
- **Version control**：为稳定版本打标，例如 `v1`、`v2`，从而在代码中引用特定版本，并长期跟踪其变化。
- **Collaboration**：标记可供审核的版本，便于与你的协作者共享具体版本并获取反馈。

<Note>
**不要与 resource tags 混淆**：Commit tags 用于引用 prompt 的特定版本；[Resource tags](/langsmith/set-up-resource-tags) 则是用于组织 workspace 资源的键值对。
</Note>

关于如何创建和管理 commit tags，请参见 [Manage prompts](/langsmith/manage-prompts#commit-tags)。

## Playground

Playground 提供了一个用于迭代和测试 prompts 的界面。你可以从侧边栏进入 Playground，也可以直接从某个已保存 prompt 打开。

在 Playground 中，你可以：

* 更换使用的模型
* 更换使用的 prompt template
* 更换输出 schema
* 更换可用 tools
* 输入要传入 prompt template 的变量
* 让 prompt 经过模型运行
* 观察输出结果

<Callout type="info" icon="feather">
你可以在 Playground 的 **[Chat](/langsmith/chat)** 中借助 AI 辅助来优化 prompts、生成 tools，以及创建输出 schema。
</Callout>
