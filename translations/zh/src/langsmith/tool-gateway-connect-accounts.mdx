连接账号会存储 [Tool Gateway](/langsmith/tool-gateway) 在调用 MCP server 时附加的凭据。该凭据是 OAuth token；对于期望在请求头中提供 API key 的 server，则是 API key。

每个凭据只属于一个 owner。因此，同一个 server 可以为调用它的每个用户、agent 或 profile 以不同账号运行。关于 Tool Gateway 在每次调用时如何选择 owner，请参见[凭据 owner](/langsmith/tool-gateway-how-it-works#credential-owners)。

添加 server 之后再连接账号。public server 不需要凭据，因此没有可连接的内容。要添加 server，请参见[添加 MCP server](/langsmith/tool-gateway-servers)。

| Owner | 由谁连接 | 位置 |
|-------|-----------------|-------|
| [你](#connect-your-own-account) | 任何可以调用该 server 的用户 | **Connected as** > **You** |
| [agent](#connect-an-account-for-an-agent) | workspace 管理员 | **Connected as** > **Agent** |
| [profile](#connect-an-account-for-a-profile) | workspace 管理员 | **Connected as** > **Profile** |
| [workspace](#connect-one-api-key-for-the-workspace) | workspace 管理员 | 添加 server 时，或通过 API |

**Connected as** 选择器位于 **Tools** > **MCP servers** 的 **Workspace** 视图中。

本页的 API 示例使用 [quickstart](/langsmith/tool-gateway-quickstart#before-you-begin) 中的环境变量。管理其他 owner 的凭据需要使用用户凭据（例如 personal access token），而不是 service key。

## 连接你自己的账号

连接你自己的账号，以便以你本人身份调用 server，例如从使用你的 API key 的 MCP client 发起调用。每个用户分别连接，其他任何人都不能使用你的凭据。

<Tabs>
  <Tab title="UI">
    1. 转到 **Tools** > **MCP servers**。
    1. 在该 server 所在行，点击 **Connect**。
    1. 完成与该 server 凭据类型对应的步骤：
        - **OAuth**：在打开的标签页中，向该服务批准访问。LangSmith 页面会确认身份验证成功。
        - **API key**：输入你的 key，然后点击 **Save and connect**。

    该 server 的状态会变为 **Connected**。
  </Tab>
  <Tab title="API">
    对于 OAuth server，启动连接并打印登录链接：

    ```bash
    curl -sS -X POST "$LANGSMITH_ENDPOINT/v1/managed-tools/kits/me/connections/<server-id>" \
      -H "X-Api-Key: $LANGSMITH_API_KEY" \
      -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID" \
      | jq -r '.verification_url'
    ```

    打开链接并批准访问。如果你已连接，或该 server 不需要凭据，请求会返回 `204`，不含链接。

    对于期望 API key 的 server，可直接存储你的 key。`fields` 的键是 server 声明的请求头名称，每个值都是完整的请求头值，包括 `Bearer ` 之类的前缀：

    ```bash
    curl -sS -X PUT "$LANGSMITH_ENDPOINT/v1/managed-tools/servers/<server-id>/credential" \
      -H "X-Api-Key: $LANGSMITH_API_KEY" \
      -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID" \
      -H "Content-Type: application/json" \
      -d '{"fields": {"X-Api-Key": "<your-service-api-key>"}}'
    ```

    再次发送该请求会替换已存储的 key。Tool Gateway 从不返回已存储的值。
  </Tab>
</Tabs>

你也可以在首次需要时再连接。对尚未连接的 server 发起 tool 调用会返回登录链接。请参见[调用工具](/langsmith/tool-gateway-call-tools)。

## 为 agent 连接账号

agent 的凭据让 agent 以自身身份调用 server，适用于使用绑定到该 agent 环境的 API key 发起的调用。每个 [agent 环境](/langsmith/agent-environments)持有自己的凭据，因此 agent 的开发和生成环境可以使用不同的账号。

为 agent 连接账号需要 `workspaces:credentials:manage` 权限，以及 agent 环境对应 tracing project 上的 `projects:update` 权限。

<Tabs>
  <Tab title="UI">
    1. 转到 **Tools** > **MCP servers**，并将 **Connected as** 设为 **Agent**。
    1. 选择 agent，然后选择 environment。
    1. 在该 server 所在行，点击 **Connect**，完成登录或输入该 agent 的 API key。
  </Tab>
  <Tab title="API">
    使用 `GET /api/v1/agents/<agent-id>` 查找 agent 环境 ID，或在 UI 中通过 **Copy agent environment ID** 复制。然后为该 agent 启动凭据会话：

    ```bash
    curl -sS -X POST "$LANGSMITH_ENDPOINT/v1/managed-tools/servers/<server-id>/credential-sessions?credential_owner_type=agent_identity&credential_owner_id=<agent-environment-id>" \
      -H "X-Api-Key: $LANGSMITH_API_KEY" \
      -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID"
    ```

    打开响应中的 `verification_url`，使用该 agent 应使用的账号登录，或输入其 API key。该链接只能使用一次，10 分钟后过期。对于使用 client credentials 的 OAuth server，响应中 `"status": "completed"` 且不含链接，因为 Tool Gateway 会在请求过程中完成连接。

    对于期望 API key 的 server，也可以改用 `PUT /v1/managed-tools/servers/<server-id>/credential` 并带上相同的查询参数，直接存储该 agent 的 key。
  </Tab>
</Tabs>

agent 无法连接自己的凭据。如果缺少凭据，agent 的 tool 调用会返回 `409`，直到管理员为其连接。

要绑定 agent 调用时使用的 API key，请参见[以 agent 身份调用](/langsmith/tool-gateway-identity#call-as-an-agent)。

## 为 profile 连接账号

profile 是一组具名凭据，由管理员一次性连接，供在无人登录状态下运行的 agent 或其他调用方使用。调用方通过在 `X-LangSmith-Profile` 请求头中发送其 ID 来选择 profile。请参见[以用户和 agent 身份调用](/langsmith/tool-gateway-identity)。

创建 profile 并连接其凭据需要 `workspaces:credentials:manage` 权限。连接某个 server 还需要调用该 server 的权限。

<Tabs>
  <Tab title="UI">
    1. 转到 **Tools** > **MCP servers**，并将 **Connected as** 设为 **Profile**。
    1. 点击 **Add profile**，输入名称（例如 `Support agent`），然后点击 **Create profile**。
    1. 在每个 server 所在行，点击 **Connect**，完成登录或输入该 profile 的 API key。

    要复制用于选择该 profile 的请求头，请点击 **Copy profile header**。
  </Tab>
  <Tab title="API">
    创建 profile 并保存其 ID：

    ```bash
    export PROFILE_ID=$(curl -sS -X POST "$LANGSMITH_ENDPOINT/v1/managed-tools/profiles" \
      -H "X-Api-Key: $LANGSMITH_API_KEY" \
      -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID" \
      -H "Content-Type: application/json" \
      -d '{"name": "Support agent"}' \
      | jq -r '.id')
    ```

    为该 profile 需要的每个 server 启动凭据会话：

    ```bash
    curl -sS -X POST "$LANGSMITH_ENDPOINT/v1/managed-tools/profiles/$PROFILE_ID/servers/<server-id>/credential-sessions" \
      -H "X-Api-Key: $LANGSMITH_API_KEY" \
      -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID"
    ```

    打开响应中的 `verification_url`，代该 profile 登录或输入 API key。与 agent 相同，该链接只能使用一次，10 分钟后过期；使用 client credentials 的 OAuth server 连接时不含链接。

    对于期望 API key 的 server，也可以使用 `PUT /v1/managed-tools/profiles/$PROFILE_ID/servers/<server-id>/credential` 和 `fields` 请求体直接存储该 key。
  </Tab>
</Tabs>

使用 profile 的调用方无法连接缺失的凭据。在管理员连接之前，其 tool 调用会返回 `409`。

要重命名或删除 profile，请使用 UI 中该 profile 的操作菜单，或 `PATCH` / `DELETE /v1/managed-tools/profiles/<profile-id>`。删除 profile 会删除连接到它的每个凭据，并向 provider 撤销其 OAuth token。使用该 profile 的 agent 将停止工作。

## 为 workspace 连接一个 API key

workspace 凭据是一个 API key，server 的每个调用方都使用它，包括 workspace 中的 agent。它适用于所有人共用一个账号的服务，这样任何用户都无需连接自己的 key。

只有期望 API key 的 workspace server 才接受 workspace 凭据。设置该凭据需要 `workspaces:credentials:manage` 权限。

<Warning>
存储 workspace 凭据会永久删除该 server 上所有其他凭据，涉及每个用户、agent 和 profile。在 workspace 凭据已存储期间，其他任何 owner 都无法连接凭据。
</Warning>

在添加 server 时设置该 key：选择 **API key**，将 **Credentials** 设为 **Workspace**，然后输入 key。在 API 中，请在 `POST /v1/managed-tools/servers` 请求中包含 `"credential": {"owner_type": "workspace", "fields": {...}}`。请参见[添加 MCP server](/langsmith/tool-gateway-servers)。

要在已存在的 server 上设置或替换该 key，请使用 API：

```bash
curl -sS -X PUT "$LANGSMITH_ENDPOINT/v1/managed-tools/servers/<server-id>/credential?credential_owner_type=workspace&credential_owner_id=$LANGSMITH_WORKSPACE_ID" \
  -H "X-Api-Key: $LANGSMITH_API_KEY" \
  -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID" \
  -H "Content-Type: application/json" \
  -d '{"fields": {"X-Api-Key": "<shared-service-api-key>"}}'
```

不期望 API key 的 server，或不是 workspace server 的 server，会返回 `409`。

## 断开账号连接

断开连接会删除某个 owner 的凭据，并保留该 server 以及其他所有 owner 的凭据。依赖该凭据的调用会失败，直到该 owner 重新连接。断开连接会向 provider 撤销 OAuth token。

要断开你自己的账号：

- **UI**：在 **Tools** > **MCP servers** 中打开该 server，然后点击 **Disconnect**。不要使用该行的删除操作，它会为所有人删除该 server。
- **API**：

    ```bash
    curl -sS -X DELETE "$LANGSMITH_ENDPOINT/v1/managed-tools/servers/<server-id>/credential" \
      -H "X-Api-Key: $LANGSMITH_API_KEY" \
      -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID"
    ```

要断开另一个 owner 的连接，请在 UI 中将 **Connected as** 设为该 owner，并在该 server 所在行点击 **Disconnect**。在 API 中，发送相同的请求并指明 owner：

- **agent**：添加 `?credential_owner_type=agent_identity&credential_owner_id=<agent-environment-id>`。
- **profile**：发送 `DELETE /v1/managed-tools/profiles/<profile-id>/servers/<server-id>/credential`。
- **workspace**：添加 `?credential_owner_type=workspace&credential_owner_id=$LANGSMITH_WORKSPACE_ID`。此后调用方在该 server 上没有凭据，直到它们连接自己的凭据。

如果该 owner 已断开连接，请求会返回 `204`。

如果该 server 使用 [Manual OAuth](/langsmith/tool-gateway-servers#choose-what-credentials-the-server-needs)，你的凭据存放在共享的 [Agent Auth](/langsmith/agent-auth) connection 中。断开连接会将其从使用该 connection 的每个 server 和集成中移除。
