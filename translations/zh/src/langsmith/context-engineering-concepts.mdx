当 context 管理不善时，agents 在生产环境中的行为就会不稳定。_Context_ 指的是 agent 赖以行动的信息，例如 system instructions、tool definitions 和参考资料。_Context engineering_ 则是构建并优化这些 context，以提升 agent 性能和能力的实践。

本页介绍 LangSmith 中 context engineering 的核心概念：[skills](#skills)、[agents](#agents)、[Context Hub](#context-hub-vs-store-backend)、[版本控制](#versioning)以及[共享](#sharing-and-permissions)。

## Skills

_Skill_ 是 Context Hub 中的一个带版本 repo，用于封装 agent 可调用的可复用能力。

Skill repo 通常包含：

**常见文件：**
- 根目录中的 `SKILL.md`，用于提供说明和使用指导。
- 可选的辅助文件，例如 references、templates 和 schemas。

常见示例包括邮件格式化、代码审查和网页研究。

## Agents

_Agent_ 是一个可以借助 tools、skills 和 subagents 端到端完成任务的 AI 系统。_Agent repo_ 用于打包它的配置，包括高层指令、关联的 skills 和 subagents，以及工具配置。

Agent repo 通常包含：

**常见文件：**
- `AGENTS.md`，用于 system prompt 和运行指令。
- 可选文件，例如 `tools.json`，以及关联的 `agents/*` 或 `skills/*` 条目。

示例包括邮件助理、coding copilot 或客服 agent。

## 如何在 skills 和 agents 之间选择

Skills 是可复用的 context 模块。Agent repos 则是定义一个 agent 如何运行的顶层打包形式。

- 当你需要在多个 agents 之间共享可复用说明、策略或示例时，使用 skills。
- 当你要定义某一个 agent 的运行指令、tools 及其关联依赖时，使用 agent repos。

## Linked repos

Context Hub commits 在 `files` 中支持三种条目类型：

- `file`：内联文件内容。
- `agent`：链接到另一个 agent repo。
- `skill`：链接到另一个 skill repo。

当某个被链接的 agent 或 skill repo 有了新 commit 时，LangSmith 会把更新传播到引用它的父 repos。

<Tip>
如果你发现自己在多个 agents 中反复复制同一段 context，就把它抽出来做成一个 skill repo，再让各个 agent 去引用它。
</Tip>

## Context Hub 与 store backend

LangSmith 中的 context 可以通过两种不同后端来管理：**Context Hub** 和 **store backend**。它们的用途不同，而且大多数 agents 通常会同时使用两者。

[Context Hub](/langsmith/use-the-context-hub) 是 agent 的长期 context 存储。它会把每次变更都记录为 commit，并支持版本控制、共享和持续改进。

_Store backend_ 则用于运行时状态。它保存 agent 在运行过程中逐步积累的信息，例如 memories、conversation history、user preferences、learned facts，以及其他按会话或按用户变化的数据。

## 版本控制

在 **Context Hub** 中，对 repo 的每一次修改都会生成一个新的 commit。Commits 是不可变、可浏览、可比较的，因此你可以：

- 精确查看某个 agent 的两个版本之间到底改了什么。
- 如果某次修改导致行为退化，可以回退到任意历史 commit。
- 为重要 commit 打 tag（例如某天实际发布的那个 commit），方便后续引用。
- 将某个 commit 发布到 `Staging` 或 `Production` 这类**环境**中，使下游 agents 拉取的是一个稳定版本，而不是最新编辑中的内容。

如果这套工作流让你联想到 Git，那是有意为之：Context Hub 把 Git 在代码管理中的纪律，带到了 agent 指令管理里。

## 共享与权限

**Context Hub** 是为团队协作设计的。每个 repo 都存在于某个[工作区](/langsmith/administration-overview#workspaces)中，而访问权限由工作区权限和 repo 可见性共同决定：

- **Private** repos 只在工作区内部可见。
- **Public** repos 可被任何人发现并拉取。
- 创建 commits、添加 tags、发布 environments 需要拥有工作区的更新权限。

工作区级别的共享和可见性控制，使得 Hub 成为团队协作维护 agents 和 skills，并随着时间不断改进它们的天然场所。
