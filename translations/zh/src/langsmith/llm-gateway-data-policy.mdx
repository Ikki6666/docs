data policy 控制经过 [LLM Gateway](/langsmith/llm-gateway) 的请求内容会如何处理：

- gateway 在请求到达 LLM provider 之前会脱敏哪些敏感数据，例如个人信息或 API keys。
- LangSmith 是否在 traces 中存储请求和响应体。

管理员可以使用 data policies 在不更改应用代码的情况下完成以下操作：

- 让开发者或 agents 写入 prompt 的客户数据和凭证不流向第三方 providers。
- 限制 LangSmith 存储的内容。

与其他 gateway policies 一样，data policy 可以应用于组织、用户组、工作区、用户或 API key。在 LLM Gateway 的 **Policies** 标签页中，data policies 的策略类型为 **Data protection**。每条策略结合三个选项和一个超时设置：

- **Redact personal information (PII)** 和 **Redact secrets**：在请求到达 LLM provider 之前，gateway 会扫描并脱敏哪些敏感数据。请参阅[脱敏如何运作](#how-redaction-works)。
- **Store trace content**：gateway 是否把请求和响应体写入 LangSmith trace。请参阅[存储 trace 内容](#store-trace-content)。
- **If redaction takes too long**：这次扫描最长可以运行多久，以及超出限制时请求是否继续。请参阅[扫描时间与超时行为](#scan-time-and-timeout-behavior)。

## 可用性

拥有 LLM Gateway 访问权限的每个组织都可以使用 data policies。每个此类组织都可以创建用于脱敏 secrets 和存储 trace content 的 policies。

PII redaction 需要单独的 entitlement，默认关闭，仅对选定的组织启用。没有该 entitlement 时：

- 创建和编辑表单中的 **Redact personal information (PII)** 选项会显示为锁定状态，并带有 **Request access** 链接。
- **If redaction takes too long** 设置会被隐藏，策略使用默认超时行为。
- API 会拒绝任何配置为检测 PII 的策略。

要启用 PII redaction，请点击 **Request access** 或联系你的 account team。

## 脱敏如何运作 {#how-redaction-works}

当 data policy 启用检测时，gateway 会在出站请求到达 LLM provider 之前对它们进行扫描。检测到的值会在请求被转发上游之前替换为占位符，因此 provider 只会看到脱敏后的 payload。对于成功的响应，gateway 会在把响应返回给调用者之前，把占位符恢复为原始值。

**Redact personal information (PII)** 和 **Redact secrets** 选项相互独立。在新策略上，PII redaction 默认开启并选中所有类型（对拥有该 entitlement 的组织），secrets redaction 和 trace content 默认关闭。

### 脱敏个人信息 {#redact-personal-information}

**Redact personal information (PII)** 选项覆盖姓名、电子邮件、美国电话号码、地址和美国 SSN。选择该选项后，其下方会出现六种类型，每种都可以单独选择，并按 gateway 的检测方式分为两组。

**Pattern match (instant)** 下的类型使用正则表达式匹配：

| 类别 | 检测到的模式 |
| --- | --- |
| **Emails** | 电子邮件地址模式 |
| **US phone numbers** | 常见美国格式，例如 `415-555-1234` 和 `+1 (415) 555-1234`。不带格式的 10 位数字不会被匹配 |
| **US Social Security numbers** | 美国 SSN 模式，例如 `123-45-6789` |

**Model detection (slower)** 下的类型由 Presidio 匹配：

| 类别 | 示例 |
| --- | --- |
| **Names** | 自然语言中的人名 |
| **Locations** | 地址、城市、国家 |
| **Nationality, religious, and political groups** | 国籍、宗教信仰、政治立场 |

### 脱敏 secrets {#redact-secrets}

**Redact secrets** 选项检测常见的 API keys、tokens 和凭证，并把它们从请求中脱敏：

| 类别 | 检测到的模式 |
| --- | --- |
| **LangSmith** | Personal access tokens、service keys、旧版 API keys |
| **AWS** | Access tokens |
| **GitHub** | Personal access tokens、fine-grained PATs、OAuth tokens、app tokens |
| **GitLab** | Personal access tokens |
| **AI providers** | OpenAI API keys、Anthropic API keys |
| **Cloud platforms** | GCP API keys、Azure AD client secrets、Google OAuth access tokens |
| **Collaboration tools** | Slack bot、user 和 app tokens，Slack webhook URLs，Datadog access tokens |
| **Package registries** | PyPI upload tokens、npm access tokens |
| **Cryptographic** | 私钥、JWTs |
| **Other** | Stripe access tokens、SendGrid API tokens |

检测刻意保持狭窄。只应用锚定到可识别 token 形状的规则，因此 prompt 中的高熵文本不会触发脱敏。

### 扫描时间与超时行为 {#scan-time-and-timeout-behavior}

每条 data policy 都会限制扫描管道可以运行的最长时间，并决定达到该上限时会发生什么。在 **If redaction takes too long** 下，设置等待的秒数，默认 2，可配置范围为 0.1 到 30。然后选择扫描未及时完成时的行为：**Allow request unredacted**（默认）或 **Block request**。

此设置仅对拥有 PII redaction entitlement 的组织显示。其他组织使用默认值。

## 存储 trace 内容 {#store-trace-content}

**Store trace content** 选项控制请求和响应体是否存储在 gateway traces 中。它对所有组织默认关闭，由 data policy 针对该策略匹配的请求开启。若要在不脱敏任何内容的情况下存储内容，请创建只选择 **Store trace content** 的 data policy。当多条 data policies 匹配同一请求时，由最具体的范围决定。如果同一范围内的策略意见不一致，内容不会被存储。内容关闭时，traces 仍会记录 token 用量、延迟、状态、模型信息和策略评估结果等 metadata。

关于 gateway traces 会出现在哪里、携带哪些 metadata，以及 trace content 如何影响计费，请参见 [View LLM Gateway traces](/langsmith/llm-gateway-traces)。

## 创建 data policy

<Warning>
创建和管理策略需要 `organization:gateway:manage` 权限。选择用户组还需要 `organization:user-groups:read`；关于可用性和设置，请参见[用户组](/langsmith/user-groups)。
</Warning>

1. 前往 **LLM Gateway** 并选择 **Policies** 标签页。
1. 点击 **+ Policy**。
1. 在 **Policy type** 下，选择 **Data protection**。
1. 输入 **Name**，或保留自动生成的名称。
1. 定义 **Scope** 以及该策略适用的对象。
1. 在 **What should this policy do** 下，选择 **Redact personal information (PII)**、**Redact secrets** 和 **Store trace content** 的任意组合。对于 PII，选择要脱敏的类型。
1. （可选）在 **If redaction takes too long** 下，设置秒数以及扫描未及时完成时的行为。
1. 点击 **Create policy**。

Data policies 应用于在其配置范围内穿过 gateway 的所有请求。它们会立即生效。

## 脱敏后的内容如何呈现

当检测到 PII 或 secret 时，内容会在发送给 provider 的请求和 LangSmith trace 中都被替换为占位符。例如：

**原始请求：**

```text
Please process the refund for John Smith, SSN 123-45-6789.
```

**上游脱敏结果：**

```text
## disclaimer: Some values have been redacted by a reverse proxy and replaced with placeholders containing unique identifiers.

Please process the refund for [SAFE_TO_USE:PERSON_kbqdjxyz], SSN [SAFE_TO_USE:US_SSN_abqxlmwp].
```

gateway 会前置这条 disclaimer，让模型把这些占位符当作可以原样复用的值。

占位符遵循格式 `[SAFE_TO_USE:<CATEGORY>_<suffix>]`：

- **SAFE_TO_USE：** 固定前缀，标记该值是一个脱敏占位符。
- **\<CATEGORY\>：** 检测到的类型。示例：`PERSON`、`LOCATION`、`US_SSN`、`US_PHONE_NUMBER`、`OPENAI_API_KEY`、`GITHUB_PAT`、`LANGSMITH_PERSONAL_TOKEN`。
- **\<suffix\>：** 一个 8 字符的标记。同一请求中出现两次的值两次都会得到相同的占位符，并且这些标记无法跨请求关联。

LangSmith 中的 trace 会显示脱敏后的版本，并附带表明发生了脱敏以及检测到哪些类别的 metadata。

**下游还原后的响应：**

当上游 provider 返回成功响应时，gateway 会把占位符替换为调用者的原始值。流式响应会逐事件重写，因此还原不会延迟流。例如，你的 agent 可能会看到这样的响应：

```text
Confirming John Smith's SSN as 123-45-6789. I will process the full refund.
```

## 脱敏覆盖范围

**覆盖的内容：**

- 出站请求内容（发送给 LLM provider 的消息）会在离开 gateway 之前被扫描和脱敏。
- 脱敏后的版本就是出现在 LangSmith traces 中的版本。
- 成功 provider 响应（无论是否流式）中的占位符，会在响应到达调用者之前恢复为原始值。

**不覆盖的内容：**

- **来自 LLM provider 的响应：** 如果模型在其响应中生成了敏感数据，这些内容不会被扫描或脱敏。只有请求会被扫描。
- **Provider 错误：** 当 provider 返回 400 或更高的状态码时，gateway 会原样透传响应体，因此调用者看到的是占位符而不是原始值。
- **gateway 之外的应用 traces：** 你的应用收到的是还原后的值，因此它自己的 traces 可以捕获这些值。
- **你 traces 中已有的数据：** 脱敏只适用于穿过 gateway 的请求。直接写入 LangSmith API（绕过 gateway）的 traces 不会被扫描。
- **Platform 级别的摄取：** 如果你的要求是不管数据以何种方式进入都阻止 PII 进入 LangSmith（例如数据驻留合规），仅靠 gateway 脱敏是不够的。这需要摄取级别的脱敏，那是一项独立的能力。
- **System 和 developer prompts：** 这些会被跳过，同时跳过的还有 assistant tool-call metadata 以及以单个 JSON 字符串形式到达的 tool-call arguments。User messages、tool results 和结构化 tool-call arguments 会被扫描。

**扫描器失败时 fail open：** 如果某个扫描器不可达或出错，请求会带着该阶段产出的内容继续发往 provider。只有扫描超时才能拦截请求，且仅当策略的 timeout action 设置为 **Block request** 时。

覆盖边界很重要。如果你的安全模型要求敏感数据永远不进入任何系统（不只是 LLM provider），请确保你理解 gateway 覆盖哪些层面，哪些层面需要额外的控制。
