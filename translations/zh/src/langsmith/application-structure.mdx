若要部署到 LangSmith，一个 application 必须由一个或多个 graphs、一个配置文件（`langgraph.json`）、一个用于声明依赖的文件，以及一个可选的、用于声明环境变量的 `.env` 文件组成。

本页说明 LangSmith application 的组织方式，以及部署所需配置细节应如何提供。

## 关键概念

若要使用 LangSmith 部署，请提供以下信息：

1. 一个[配置文件](#configuration-file-concepts)（`langgraph.json`），用于指定该 application 所使用的 dependencies、graphs 和 environment variables。
1. 实现 application 逻辑的[graphs](#graphs)。
1. 一个用于声明运行 application 所需[依赖](#dependencies)的文件。
1. 应用运行所需的[环境变量](#environment-variables)。

## 文件结构

以下是 Python 和 JavaScript applications 的目录结构示例：

<Tabs>
    <Tab title="Python (requirements.txt)">
    ```plaintext
    my-app/
    ├── my_agent # all project code lies within here
    │   ├── utils # utilities for your graph
    │   │   ├── __init__.py
    │   │   ├── tools.py # tools for your graph
    │   │   ├── nodes.py # node functions for your graph
    │   │   └── state.py # state definition of your graph
    │   ├── __init__.py
    │   └── agent.py # code for constructing your graph
    ├── .env # environment variables
    ├── requirements.txt # package dependencies
    └── langgraph.json # configuration file for LangGraph
    ```
    </Tab>
    <Tab title="Python (pyproject.toml)">
    ```plaintext
    my-app/
    ├── my_agent # all project code lies within here
    │   ├── utils # utilities for your graph
    │   │   ├── __init__.py
    │   │   ├── tools.py # tools for your graph
    │   │   ├── nodes.py # node functions for your graph
    │   │   └── state.py # state definition of your graph
    │   ├── __init__.py
    │   └── agent.py # code for constructing your graph
    ├── .env # environment variables
    ├── langgraph.json  # configuration file for LangGraph
    └── pyproject.toml # dependencies for your project
    ```
    </Tab>
    <Tab title="JS (package.json)">
    ```plaintext
    my-app/
    ├── src # all project code lies within here
    │   ├── utils # optional utilities for your graph
    │   │   ├── tools.ts # tools for your graph
    │   │   ├── nodes.ts # node functions for your graph
    │   │   └── state.ts # state definition of your graph
    │   └── agent.ts # code for constructing your graph
    ├── package.json # package dependencies
    ├── .env # environment variables
    └── langgraph.json # configuration file for LangGraph
    ```

</Tabs>

## 配置文件

`langgraph.json` 文件是一个 JSON 文件，用于指定部署 application 所需的 dependencies、graphs、environment variables 和其他设置。

如需了解该 JSON 文件支持的全部 keys，请参阅 [LangGraph configuration file reference](/langsmith/cli#configuration-file)。

<Tip>
[LangGraph CLI](/langsmith/cli) 默认会使用当前目录中的 `langgraph.json` 作为配置文件。
</Tip>

### 示例

<Tabs>
    <Tab title="Python">
    * 依赖包括一个自定义本地 package 和 `langchain_openai` package。
    * 会从 `./your_package/your_file.py` 文件中加载一个 graph，并使用其中的 `agent` 变量。
    * 环境变量会从 `.env` 文件中加载。

    ```json
    {
        "dependencies": [
            "langchain_openai",
            "./your_package"
        ],
        "graphs": {
            "my_agent": "./your_package/your_file.py:agent"
        },
        "env": "./.env"
    }
    ```
    </Tab>
    <Tab title="JavaScript">
    * 依赖会从本地目录中的依赖文件加载（例如 `package.json`）。
    * 会从 `./your_package/your_file.js` 文件中加载一个 graph，并使用其中的 `agent` function。
    * 环境变量 `OPENAI_API_KEY` 以内联方式设置。

    ```json
    {
        "dependencies": [
            "."
        ],
        "graphs": {
            "my_agent": "./your_package/your_file.js:agent"
        },
        "env": {
            "OPENAI_API_KEY": "secret-key"
        }
    }
    ```
    </Tab>
</Tabs>

## 依赖

一个 application 可能依赖其他 Python packages 或 JavaScript libraries，具体取决于应用所使用的编程语言。

通常你需要提供以下信息，才能正确设置 dependencies：

1. 目录中一个用于声明依赖的文件（例如 `requirements.txt`、`pyproject.toml` 或 `package.json`）。
2. [配置文件](#configuration-file-concepts)中的 `dependencies` key，用于声明运行 application 所需的依赖。
3. 任何额外的二进制文件或系统库，可以通过 [LangGraph 配置文件](#configuration-file-concepts)中的 `dockerfile_lines` key 指定。

## Graphs

使用[配置文件](#configuration-file-concepts)中的 `graphs` key，指定哪些 graphs 会在部署后的 application 中可用。

你可以在配置文件中指定一个或多个 graphs。每个 graph 都通过唯一名称以及一个路径来标识，该路径指向以下两者之一：(1) 编译后的 graph，或 (2) 定义 graph 的 function。

### 在 LangSmith Deployment 中使用任意 framework

虽然 LangSmith Deployment 要求应用以 LangGraph graph 的形式组织，但 graph 中的各个节点内部可以包含任意代码。这意味着你仍然可以在节点里使用任何 framework 或 library，同时继续享受 LangSmith 的部署基础设施能力。

Graph 结构充当的是部署接口，而你的核心应用逻辑可以使用最适合自己需求的工具和 frameworks。

若要部署到 LangSmith，你需要：

<Tabs>
  <Tab title="Python">

    1. **A LangGraph graph structure**：使用 @[`StateGraph`]、@[`add_node`] 和 @[`add_edge`] 定义一个 graph。
    1. **Node functions with arbitrary logic**：你的 node functions 内部可以调用任意 framework 或 library。
    1. **A compiled graph**：对 graph 执行 @[Compile][StateGraph.compile]，创建可部署的 application。

    下例演示如何把你已有的 application 逻辑包装进一个最小的 LangGraph 结构中：

  ```python
  from langgraph.graph import StateGraph, START, END
  from typing import TypedDict

  # Your existing application logic using any framework
  from app_logic import process_data
  from app_logic import fetch_data

  class State(TypedDict):
      input: str
      result: str

  def my_app_node(state: State) -> State:
      """Node containing arbitrary framework code."""
      # Use any framework or library here
      raw_data = fetch_data(state["input"])
      processed = process_data(raw_data)
      return {"result": processed}

  # Define the graph structure
  graph = StateGraph(State)
  graph.add_node("process", my_app_node)  # Add node with your logic
  graph.add_edge(START, "process")  # Connect start to your node
  graph.add_edge("process", END)  # Connect your node to end

  # Compile for deployment
  app = graph.compile()
  ```
  </Tab>
  <Tab title="JavaScript">

    1. **A LangGraph graph structure**：使用 [`StateGraph`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.index.StateGraph.html)、[`addNode`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.index.StateGraph.html#addnode) 和 [`addEdge`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.index.StateGraph.html#addedge) 定义一个 graph。
    1. **Node functions with arbitrary logic**：你的 node functions 内部可以调用任意 framework 或 library。
    1. **A compiled graph**：[Compile](https://reference.langchain.com/javascript/classes/_langchain_langgraph.index.StateGraph.html#compile) 该 graph，创建可部署的 application。

    下例演示如何把你已有的 application 逻辑包装进一个最小的 LangGraph 结构中：

  ```typescript
  import { StateGraph, START, END } from "@langchain/langgraph";
  import { Annotation } from "@langchain/langgraph";

  // Your existing application logic using any framework
  import { processData } from "./app-logic";
  import { fetchData } from "./app-logic";

  const State = Annotation.Root({
    input: Annotation<string>,
    result: Annotation<string>
  });

  async function myAppNode(state: typeof State.State) {
    // Use any framework or library here
    const rawData = await fetchData(state.input);
    const processed = await processData(rawData);
    return { result: processed };
  }

  // Define the graph structure
  const graph = new StateGraph(State)
    .addNode("process", myAppNode)  // Add node with your logic
    .addEdge(START, "process")  // Connect start to your node
    .addEdge("process", END);  // Connect your node to end

  // Compile for deployment
  export const app = graph.compile();
  ```
  </Tab>
</Tabs>

在这个示例中，node functions（Python 中的 `my_app_node`，以及 JavaScript 中的 `myAppNode`）内部都可以调用任意 framework 或 library。LangGraph 结构只是提供部署接口和编排层。

关于端到端示例，请参阅 [Google ADK](/langsmith/deploy-google-adk) 以及 [Claude Agent SDK、Strands、CrewAI 和 AutoGen](/langsmith/deploy-other-frameworks) 的部署指南。LangSmith 通过 [`deployments-wrap-sdk`](https://pypi.org/project/deployments-wrap-sdk/) 添加了对 Google ADK 的支持，这是一个可扩展的 package，用于包装 agent SDK，使其能够运行在 LangSmith Deployment 上。

## 环境变量

如果你在[本地](/langsmith/local-dev-testing)使用已部署的 LangGraph application，可以在[配置文件](#configuration-file-concepts)的 `env` key 中配置 environment variables。

对于生产部署，你通常会希望直接在 deployment environment 中配置这些 environment variables。
