配置 coding agents 使用标准 LLM Gateway endpoint，以实现集中化的成本控制、可观测性和审计轨迹。gateway 会对每个调用方进行身份验证，按 model ID 路由，执行策略，并记录 trace。

## 前置条件

- 管理员已完成所有必需的 [gateway 设置](/langsmith/llm-gateway-admin-setup)。
- 你拥有一个工作区范围的 LangSmith API key。关于 key 类型、权限以及各客户端发送的 header，请参见 [Authenticate to the LLM Gateway](/langsmith/llm-gateway-authentication)。
- 对于 bring-your-own-key 模型，你的工作区需要具备对应的 provider secret。[Gateway Credits 模型](/langsmith/llm-gateway-credits)不需要 provider secret。

在配置客户端之前，请设置你的 LangSmith API key：

```bash
export LANGSMITH_API_KEY="lsv2_..._....cbed3e"
```

然后配置你的 agent：

- [Claude Code](#claude-code-cli) 使用标准 Anthropic Messages 格式。
- [Codex](#codex-cli) 和 [Deep Agents Code](#deep-agents-code) 使用标准 OpenAI 兼容格式。
- [Gemini CLI](#gemini-cli) 使用 Google 原生 API，需要[直接模型访问](/langsmith/llm-gateway-direct-model-access)。

## Claude Code CLI

Claude Code 始终使用你的 LangSmith API key 向 gateway 进行认证。gateway 对 Anthropic 的认证支持两种方式，每种方式的计费对象不同。配置前请先选择其中一种：

- **工作区 provider secret**：组织通过保存在工作区密钥中的 provider key 管理计费和策略。组织统一管理用量时使用此方式。
- **Claude 订阅 OAuth**：Anthropic 会把 LLM 调用计入用户个人的 Claude Plus 或 Max 订阅，而不是工作区 provider secret。LangSmith 仍会执行 gateway 权限、速率限制、模型访问和 data policies，并记录每次调用的 trace。支出限制不适用。开发者拥有自己的订阅时使用此方式。

### 使用工作区 provider secret

将 `ANTHROPIC_API_KEY` 设置为你的 LangSmith API key。Claude Code 会从你的 shell 环境或通过 `--settings` 传入的配置文件中的 `env` 块读取这些变量。

如果你的 LangSmith 部署位于区域实例上，请把下文示例中的 gateway 主机名替换为你的[区域 gateway](/langsmith/llm-gateway-how-it-works#use-a-regional-gateway) 主机名。在[自托管安装](/langsmith/llm-gateway-how-it-works#use-a-self-hosted-installation)上，请把 `https://gateway.smith.langchain.com` 替换为 `https://<your-hostname>/gateway`。

#### 仅使用 Anthropic 模型

将 `ANTHROPIC_BASE_URL` 设置为 Anthropic 格式的 gateway endpoint。gateway 会从该 endpoint 推断出 `anthropic/` provider 前缀。

<Tabs>
  <Tab title="配置文件（推荐）">
    通过 `--settings` 文件声明的变量优先于 shell 中已导出的任何内容，因此 gateway URL 和 API key 必定会覆盖环境中可能已存在的任何 `ANTHROPIC_*` 值（例如来自全局 shell profile 或其他工具）。

    ```bash
    touch ~/.claude/langsmith_gateway.settings.json
    echo '{"env": {"ANTHROPIC_BASE_URL": "https://gateway.smith.langchain.com/anthropic/","ANTHROPIC_API_KEY": "YOUR_LANGSMITH_KEY_HERE"}}' > ~/.claude/langsmith_gateway.settings.json
    claude --settings ~/.claude/langsmith_gateway.settings.json
    ```

    将 `YOUR_LANGSMITH_KEY_HERE` 替换为你的 LangSmith API key。
  </Tab>
  <Tab title="环境变量">
    ```bash
    export ANTHROPIC_BASE_URL="https://gateway.smith.langchain.com/anthropic/"
    export ANTHROPIC_API_KEY="$LANGSMITH_API_KEY"

    claude
    ```
  </Tab>
</Tabs>

#### 跨 provider 路由模型分层

将 `ANTHROPIC_BASE_URL` 设置为 gateway 根地址，然后把每个 Claude 模型层级映射到一个带 provider 前缀的 gateway model ID。

<Tabs>
  <Tab title="配置文件（推荐）">
    通过 `--settings` 文件声明的变量优先于 shell 中已导出的任何内容，因此 gateway URL、API key 和模型映射必定会覆盖环境中可能已存在的任何 `ANTHROPIC_*` 值。

    ```bash
    touch ~/.claude/langsmith_gateway.settings.json
    echo '{"env": {"ANTHROPIC_BASE_URL": "https://gateway.smith.langchain.com","ANTHROPIC_API_KEY": "YOUR_LANGSMITH_KEY_HERE","ANTHROPIC_DEFAULT_OPUS_MODEL": "anthropic/claude-opus-5","ANTHROPIC_DEFAULT_SONNET_MODEL": "openai/gpt-5.6-terra","ANTHROPIC_DEFAULT_HAIKU_MODEL": "fireworks/accounts/fireworks/models/glm-5p2"}}' > ~/.claude/langsmith_gateway.settings.json
    claude --settings ~/.claude/langsmith_gateway.settings.json
    ```

    将 `YOUR_LANGSMITH_KEY_HERE` 替换为你的 LangSmith API key。
  </Tab>
  <Tab title="环境变量">
    ```bash
    export ANTHROPIC_BASE_URL="https://gateway.smith.langchain.com"
    export ANTHROPIC_API_KEY="$LANGSMITH_API_KEY"
    export ANTHROPIC_DEFAULT_OPUS_MODEL="anthropic/claude-opus-5"
    export ANTHROPIC_DEFAULT_SONNET_MODEL="openai/gpt-5.6-terra"
    export ANTHROPIC_DEFAULT_HAIKU_MODEL="fireworks/accounts/fireworks/models/glm-5p2"

    claude
    ```
  </Tab>
</Tabs>

这些 model ID 仅为示例。请把每个层级映射到任何在你的工作区密钥中配置的模型，或任何可通过 [Gateway Credits](/langsmith/llm-gateway-credits) 使用的模型；gateway 会负责跨 provider 的请求转换。详细信息参见 [API 格式](/langsmith/llm-gateway-api-formats#understand-translation-behavior)。

<a id="use-claude-subscription-oauth"></a>
### 使用 Claude 订阅 OAuth

<Note>
Claude 订阅 OAuth 需要有效的 Claude Code Plus 或 Max 订阅。如果你使用的是工作区 Anthropic API key，请改用[工作区 provider secret](#使用工作区-provider-secret) 方式。
</Note>

Claude Code Plus 和 Max 用户可以将其保存的 Anthropic OAuth 凭证通过 gateway 发送。此模式不需要在工作区 provider secrets 中设置 `ANTHROPIC_API_KEY`。

使用你的订阅登录 Claude Code，然后配置 gateway。

<Tabs>
  <Tab title="配置文件（推荐）">
    通过 `--settings` 文件声明的变量优先于 shell 中已导出的任何内容，因此 gateway URL 和自定义 header 必定会覆盖环境中可能已存在的任何 `ANTHROPIC_*` 值。配置文件还能让你的 LangSmith API key 不出现在 shell 历史和 dotfiles 中。

    ```bash
    touch ~/.claude/langsmith_gateway.settings.json
    echo '{"env": {"ANTHROPIC_BASE_URL": "https://gateway.smith.langchain.com/anthropic","ANTHROPIC_CUSTOM_HEADERS": "X-Api-Key: YOUR_LANGSMITH_KEY_HERE"}}' > ~/.claude/langsmith_gateway.settings.json
    claude --settings ~/.claude/langsmith_gateway.settings.json
    ```

    将 `YOUR_LANGSMITH_KEY_HERE` 替换为你的 LangSmith API key。
  </Tab>
  <Tab title="环境变量">
    ```bash
    export ANTHROPIC_BASE_URL="https://gateway.smith.langchain.com/anthropic"
    export ANTHROPIC_CUSTOM_HEADERS="X-Api-Key: $LANGSMITH_API_KEY"

    claude
    ```

    请把 `ANTHROPIC_CUSTOM_HEADERS` 的值当作 secret 对待：其中嵌入了你的 LangSmith API key，因此不要让它进入 shell 历史、dotfiles 和共享配置。
  </Tab>
</Tabs>

Claude Code 会使用并刷新其保存登录中的 OAuth 凭证，并在 `anthropic-beta` header 中包含所需的 OAuth capability。

LangSmith API key 负责对 gateway 请求进行身份验证，并仍然受 gateway 权限以及速率限制、模型访问和 data policies 的约束。gateway 会将 OAuth bearer 转发给 Anthropic，因此 Anthropic 会把这些调用计入用户的 Claude 订阅，而不是工作区 provider secret。[支出限制](/langsmith/llm-gateway-spend-policies)不适用于这些调用，这些调用也不会计入支出总额。要确认调用经过 gateway 路由，请按[验证设置](#验证设置)中的说明检查 `gateway` tracing project 中是否出现了 trace。

<Warning>
对于此模式，请保持 `ANTHROPIC_AUTH_TOKEN` 和 `ANTHROPIC_API_KEY` 未设置。这两个变量中的任何一个都会优先于保存的订阅登录。
</Warning>

<Warning>
一旦配置了 gateway，Claude Desktop plugins 会失效。
</Warning>

## Codex CLI

Codex 使用 Responses API。将以下内容添加到 `~/.codex/config.toml`，通过标准 endpoint 以 Gateway Credits 调用托管的 Kimi K3 模型：

```toml
model = "moonshotai/kimi-k3"
model_provider = "langsmith-gateway"

[model_providers.langsmith-gateway]
name = "LangSmith Gateway"
base_url = "https://gateway.smith.langchain.com/v1"
env_key = "LANGSMITH_API_KEY"
wire_api = "responses"
supports_websockets = false
```

然后运行：

```bash
codex
```

要改用 bring-your-own-key 模型，请将 `model` 替换为其带 provider 前缀的 ID，例如 `openai/gpt-5.4-mini`。

<Warning>
一旦配置了 gateway，Codex Desktop plugins 会失效。由于 TOML 配置强制通过 gateway 完成身份验证，OpenAI 将不再直接处理 plugin 的认证。
</Warning>

## Gemini CLI

Gemini CLI 发送 Google 原生的 Generate Content 请求，标准 endpoint 不暴露该请求。请按[直接模型访问](/langsmith/llm-gateway-direct-model-access#configure-provider-sdks)中的说明配置 `/gemini` 路由，然后运行：

```bash
gemini
```

## Deep Agents Code

使用 OpenAI 兼容客户端配合标准 endpoint，然后通过 `openai` integration 传入托管 model slug：

```bash
export OPENAI_BASE_URL="https://gateway.smith.langchain.com/v1"
export OPENAI_API_KEY="$LANGSMITH_API_KEY"

dcode --model openai:moonshotai/kimi-k3
```

要改用 bring-your-own-key 模型，请保持标准 base URL 不变，并在 `openai:` 之后传入带 provider 前缀的 model，例如 `openai:anthropic/claude-opus-5`。关于 provider 原生 integrations 和 model ID，请参见[直接模型访问](/langsmith/llm-gateway-direct-model-access#configure-langchain-and-deep-agents)。

## 全公司范围部署

如果你的组织希望把 gateway 推给所有开发者使用，可以通过移动设备管理或共享 shell profile 来分发配置。需要分发的内容有：

1. 每个客户端的标准 gateway base URL。
1. 每位用户或团队一个工作区范围的 [LangSmith API key](/langsmith/llm-gateway-authentication#choose-a-key-type)，具体取决于你的策略粒度。
1. 为每个 coding agent 批准的 model ID。
1. 如果你的组织使用 Codex，还需要分发 Codex 的 `config.toml`。

provider API keys 仍然会集中保存在 LangSmith 工作区密钥中。

## 将调用归入会话线程

gateway 会将识别到的 coding-agent 会话头部映射为 LangSmith 的 `thread_id` 元数据。使用同一个 ID 的调用属于同一个 tracing project 中的同一条会话线程。

头部检测适用于所有 providers、请求路径和 API 格式。gateway 会按以下顺序检查这些头部：

1. `X-Claude-Code-Session-Id`
1. `X-Deepseek-Harness-Session-Id`
1. `thread-id`
1. `thread_id`
1. `session-id`
1. `session_id`

gateway 会去除首尾空白、跳过空值，并使用第一个非空白的头部值。

如果没有头部提供 ID，gateway 可以从 Chat Completions 或 Responses 请求的请求体中读取 ID。它会使用 `conversation` 字段（可以是字符串，也可以是对象的 `id`），并回退到 `prompt_cache_key`。只有当 gateway 已经因为其他原因（例如防护策略）加载了请求体时，才会读取这些字段。要获得一致的线程归属，请发送头部。

要显式设置 thread ID，请发送 `X-Gateway-Thread-Id`，或在 `X-Gateway-Metadata` 的 JSON 对象中设置 `thread_id`。非空的显式值会覆盖自动检测。如果两个元数据头部都指定了 thread ID，则以 `X-Gateway-Metadata` 为准。

如果 gateway 未找到显式 ID、可识别的会话头部或请求体字段，则不会添加 `thread_id` 元数据。

## 验证设置

配置好 coding agent 后，执行一次测试调用，并确认：

1. 调用成功，也就是 agent 收到了响应
1. 你的 LangSmith 工作区中的 `gateway` tracing project 里出现了新的 trace

如果调用因 `401` 或 `403` 失败，请参见 [Fix authentication errors](/langsmith/llm-gateway-authentication#fix-authentication-errors)。如果 bring-your-own-key 调用返回 `424` 并提示缺失 provider key，请让工作区管理员把对应 provider 的 key 添加到工作区密钥中。详情请参见 [Fix provider credential errors](/langsmith/llm-gateway-provider-authentication#fix-provider-credential-errors)。
