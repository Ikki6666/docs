<Note>
**Private beta:** LLM Gateway 当前处于私有 [beta](/langsmith/release-stages) 阶段。请[加入等待名单](https://www.langchain.com/langsmith-llm-gateway-waitlist)获取访问权限。
</Note>

配置 coding agents 通过 LLM Gateway 路由 LLM 调用，这样你的组织就能在不修改 agent 代码的前提下，对开发者使用 LLM 的行为施加成本控制、可观测性和审计轨迹。

大多数 coding agents 都允许你通过环境变量或配置文件覆盖 LLM provider endpoint。把它们指向 LLM Gateway，而不是直接指向 provider 后，所有 LLM 调用都会流经 gateway。gateway 会对调用方进行身份验证，从工作区密钥中解析出真实 provider key，执行策略，并记录 trace。无需修改 agent 代码。

gateway 支持 Anthropic、AWS Bedrock、Baseten、Fireworks、Google Gemini、Google Vertex AI 和 OpenAI。完整列表及所需密钥请参阅[支持的 providers](/langsmith/llm-gateway#supported-providers)。

## 前置条件

- 你的 [Organization admin](/langsmith/rbac#organization-admin) 已完成[管理员设置](/langsmith/llm-gateway-admin-setup)
- 你拥有一个工作区级别的 [LangSmith API key](/langsmith/create-account-api-key)，并具备 `gateway:invoke` 和 `workspaces:read` [permissions](/langsmith/organization-workspace-operations)
- 你已经在终端中设置好[gateway 环境变量](/langsmith/llm-gateway-quickstart#1-set-environment-variables)

## 支持的客户端

- Claude Code CLI
- Codex CLI
- Gemini CLI
- Deep Agents

## Claude Code CLI

除了[gateway 环境变量](/langsmith/llm-gateway-quickstart#1-set-environment-variables)之外，不需要额外配置。直接运行：

```bash
claude
```

Claude Code 会自动使用你环境中的 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_API_KEY`。

<Warning>
一旦配置了 gateway，Claude Desktop desktop plugins 会失效。当前也还不支持已付费套餐，Plus、Max，的 Claude 用户。
</Warning>

## Codex CLI

Codex 除了环境变量外，还需要一个 TOML 配置文件。

把下面内容加入 `~/.codex/config.toml`：

```toml
model_provider = "langsmith-gateway"

[model_providers.langsmith-gateway]
name = "LangSmith Gateway"
base_url = "https://gateway.smith.langchain.com/openai/v1"
env_key = "LANGSMITH_API_KEY"
supports_websockets = false
```

确认 `LANGSMITH_API_KEY` 环境变量已经[设置好](/langsmith/llm-gateway-quickstart#1-set-environment-variables)，然后运行：

```bash
codex
```

<Warning>
一旦配置了 gateway，Codex Desktop plugins 会失效。由于 TOML 配置强制通过 gateway 完成身份验证，OpenAI 将不再直接处理 plugin 的认证。
</Warning>

## Gemini CLI

除了[gateway 环境变量](/langsmith/llm-gateway-quickstart#1-set-environment-variables)之外，不需要额外配置。运行：

```bash
gemini
```

Gemini CLI 会自动使用你环境中的 `GOOGLE_GEMINI_BASE_URL` 和 `GEMINI_API_KEY`。

## Deep Agents

除了[gateway 环境变量](/langsmith/llm-gateway-quickstart#1-set-environment-variables)之外，不需要额外配置。更多细节请参阅[provider selection docs](/oss/deepagents/code/providers#provider-reference)。运行：

```bash
deepagents
```

## Python SDK 用法

如果你不是通过 coding agent，而是通过 Python 脚本直接调用 LLM providers，那么只需要替换 `base_url`：

<Tabs>
  <Tab title="OpenAI SDK">
    ```python
    import os

    from openai import OpenAI

    client = OpenAI(
        base_url="https://gateway.smith.langchain.com/openai/v1",
        api_key=os.environ["LANGSMITH_API_KEY"],
    )
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "Say hello!"}],
    )
    print(response.choices[0].message.content)
    ```
  </Tab>
  <Tab title="Anthropic SDK">
    ```python
    import os

    import anthropic

    client = anthropic.Anthropic(
        base_url="https://gateway.smith.langchain.com/anthropic",
        api_key=os.environ["LANGSMITH_API_KEY"],
    )
    message = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=1024,
        messages=[{"role": "user", "content": "Say hello!"}],
    )
    print(message.content[0].text)
    ```
  </Tab>
</Tabs>

## 全公司范围部署

如果你的组织希望把 gateway 推给所有开发者使用，可以通过 MDM，也就是 mobile device management，或者共享 shell profile 来分发配置。需要统一分发的关键内容有：

1. gateway base URL，也就是 `https://gateway.smith.langchain.com`
1. 每位用户一个工作区级别的 [LangSmith API key](/langsmith/create-account-api-key)，或者按团队分发，具体取决于你的策略粒度
1. 如果你的组织使用 Codex，还需要分发 Codex 的 `config.toml`

provider API keys 仍然会集中保存在 LangSmith 工作区密钥中。

## 验证设置

配置好 coding agent 后，执行一次测试调用，并确认：

1. 调用成功，也就是 agent 收到了响应
1. 你的 LangSmith 工作区中的 `gateway` 和 `gateway-<short_api_key>-<api_key_id>` tracing projects 里出现了新的 trace

如果调用因 `403` 失败，请检查你的 API key 所属角色是否包含 `gateway:invoke` 和 `workspaces:read`。如果因为缺失 provider key 而返回 `400`，请让 org admin 把对应 provider 的 key 添加到工作区密钥中。
