<Note>
**Self-hosted version requirement**：访问 alerts 需要 Helm chart 版本 **0.10.3** 或更高版本。
</Note>

对 LLM 应用实现有效 observability，需要主动检测失败、性能退化和回归。LangSmith 的 alerts 功能可以帮助你识别以下关键问题：

- 模型提供商返回的 API rate limit 违规。
- 应用延迟上升。
- 影响终端用户体验反馈分数的应用变更。
- LLM 使用带来的异常成本飙升。

LangSmith 中的 alerts 按项目作用域划分，因此每个受监控项目都需要单独配置。

<Tip>
Alerts 可以通过 [route](#step-4-configure-notification-channel) 发送到 Slack、PagerDuty、Dynatrace，或任意 HTTP endpoint 的 webhook。**Webhook** 标签页中还提供了面向 Microsoft Teams、email，以及 self-hosted 部署上的 Slack 的 [example recipes](#example-recipes)。
</Tip>

按照以下步骤配置 alert。

## Step 1: Navigate to create alert

在 [UI](https://smith.langchain.com) 中，进入你想配置 alerts 的 Tracing 项目。点击页面右上角的 **Alerts** 图标，查看该项目已有的 alerts，并创建新的 alert。

## Step 2: Select metric type

LangSmith 对以下指标提供基于阈值的 alerting：

| Metric Type        | Description                         | Use Case                                                                                                                                                                                 |
| ------------------ | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Run Count**      | 跟踪某个时间窗口内 [runs](/langsmith/observability-concepts#runs) 的总数。 | 监控 pipeline 是否按预期产出 run，并在数量意外下降时告警。 |
| **Cost**           | 跟踪某个时间窗口内 runs 的总成本。 | 监控 LLM 支出，并在成本超过预期阈值时告警。要求先配置 [cost tracking](/langsmith/cost-tracking)。 |
| **Errors**   | 跟踪错误状态的 runs。可按错误总数，或错误率，errored runs 占所有 runs 的比例，进行告警。 | 监控应用中的故障，或在错误率超过可接受阈值时告警。 |
| **Feedback Score** | 衡量平均反馈分数。 | 跟踪 [feedback from end users](/langsmith/attach-user-feedback) 或 [online evaluation results](/langsmith/online-evaluations-llm-as-judge)，并对回归进行告警。 |
| **Latency**        | 衡量平均 run 执行时间。 | 跟踪应用延迟，并对延迟峰值和性能瓶颈进行告警。 |

此外，对于 **Errors** 和 **Latency**，你可以使用 filter builder 在 **Status**、**Run Type**、**Tag** 和 **Error** 等字段上叠加条件。例如，你可以将某个错误 alert 限定为仅匹配 **Status** 为 `error`、**Run Type** 为 `llm`、**Tag** 为 `support_agent`，并且 **Error** 匹配 `RateLimitExceeded` 的 run。

## Step 3: Define alert conditions

Alert 条件由以下几个部分组成：

- **Aggregation Method**：Average、Percentage 或 Count。
- **Comparison Operator**：`>=`、`<=`，或 exceeds threshold。
- **Threshold Value**：触发告警的数值阈值。
- **Aggregation Window**：用于计算指标的时间窗口，可选择 5 或 15 分钟。
- **Feedback Key**：仅适用于 Feedback Score alert，用于指定要监控的反馈指标。

## Step 4: Configure notification channel

<Tabs>
  <Tab title="Slack">
    使用 LangSmith 原生 Slack 集成功能，将告警通知直接发送到 Slack channel。无需自定义 webhook 或 Slack app 配置。

    <Note>
    原生 Slack 通知类型仅在 LangSmith Cloud 中可用。对于 self-hosted 部署，请改用 **Webhook** 标签页中的 [webhook Slack recipe](#example-recipes)。
    </Note>

    **Prerequisites**

    - 一个已连接到 LangSmith organization 的 Slack workspace。如果尚未连接，LangSmith 会在你配置该通知类型时内联提示你进行连接。

    ### 1. Configure the Slack notification

    1. 在 alert 配置的 **Notification Settings** 区域中，选择 **Slack**。
    2. 点击 channel 选择器。如果还没有关联 Slack workspace，请点击 **Connect Slack** 并完成 OAuth 流程以授权 LangSmith。
    3. 将 `@LangSmith` app 添加到你希望接收通知的 channel 中。该 app 必须是该 channel 的成员，你可以在 channel 中输入 `/invite @LangSmith` 完成添加。
    4. 从下拉菜单中选择 workspace 和 channel。如果 channel 没有立即出现，请点击刷新图标。
    5. 点击 **Save** 保存通知配置。

    ### 2. Test the integration

    点击 **Send Test Notification**，验证 LangSmith 是否可以向该 channel 发送消息。然后在对应 channel 中查看测试消息。

    ### Notification format

    当 alert 触发时，LangSmith 会发送一条结构化 Slack 消息，其中包括：

    - **Headline**：alert 名称和你的 LangSmith workspace 名称。
    - **Detail line**：指标属性、触发值、比较运算符、配置的阈值、聚合方式和时间窗口，例如：`Total Cost: $12.50 ≥ $5.00 · avg · 30 min`。
    - **Action buttons**：**View Alert**，跳转到 LangSmith 中的 alert preview；以及 **View Runs**，跳转到触发该 alert 的筛选 run 列表。
  </Tab>
  <Tab title="PagerDuty">
    通过 PagerDuty 的 [Events API v2](https://developer.pagerduty.com/docs/events-api-v2-overview) 将 PagerDuty 配置为通知通道。该集成可在关键 LLM 应用问题出现时触发 PagerDuty incident，从而接入你现有的事故响应流程。

    **Prerequisites**

    - 一个具有管理员权限的有效 PagerDuty account
    - PagerDuty 中相应 service 级别的权限

    如果你使用的是 LangSmith 的自定义部署，请确保没有 firewall 阻止 LangSmith 服务的出口流量。

    ### 1. Create a Service in PagerDuty

    1. 登录 PagerDuty account
    2. 进入 **Services → Service Directory**
    3. 点击 **+ New Service**
    4. 完成以下字段：
       - **Name**：填写描述性名称，例如 “LangSmith Monitoring”
       - **Description**：填写受监控应用的说明
       - **Escalation Policy**：选择合适的团队升级策略
       - **Integration Type**：选择 “Events API V2”
    5. 点击 **Add Service** 创建该 service

    ### 2. Obtain integration key

    创建 service 后，获取 Integration Key：

    1. 在 **Service Directory** 中找到并点击刚创建的 service
    2. 选择 **Integrations** 标签页
    3. 找到 “Events API V2” integration
    4. 复制 **Integration Key**，它是一个 32 位的字母数字字符串

    ![PagerDuty Integration Key Location](/langsmith/images/pager-duty.png)

    ### 3. Configure LangSmith alert with PagerDuty

    <Info>
    如果你希望在 alert 被触发后 1 小时内再次收到同一个 alert，需要先在 PagerDuty 中解决该 alert 创建的 active incident。
    </Info>

    ![PagerDuty Setup](/langsmith/images/pagerduty-setup.png)

    1. 在 LangSmith 的 alert 配置通知区域中，选择 **PagerDuty**
    2. 点击钥匙图标，将 Integration Key 保存为 Workspace secret，或选择已有的 Workspace secret。最佳实践是将 Integration Key 保存为 Workspace Secret，而不是直接写入，这样可以在同一 workspace 的多个 alert 中复用。
    3. 配置额外通知选项：
       - **Severity**：映射到 PagerDuty incident priority
    4. 点击 **Send Test Alert** 发送测试告警
    5. 验证 PagerDuty 是否成功触发 incident，并确认其中包含相关的 LangSmith alert 信息

    ### Troubleshooting

    如果 PagerDuty 中没有创建 incident：

    - 确认在 LangSmith 中输入的 Integration Key 正确无误
    - 确认 PagerDuty service 处于活动状态，且未处于维护模式
    - 确认你的 PagerDuty account 已启用 Events API v2
    - 如果某个预期的 alert trigger 没有出现在 PagerDuty 中，请检查它是否发生在同一条 alert rule 上一次触发后的 1 小时内，并确认上一次创建的 incident 是否仍然处于 open 状态
    - 如果你的 LangSmith 实例位于防火墙后方，请检查网络连通性

    ### Additional resources

    - [PagerDuty Events API v2 Documentation](https://developer.pagerduty.com/docs/events-api-v2/overview/)
    - [PagerDuty Integration Guide](https://support.pagerduty.com/docs/services-and-integrations)
  </Tab>
  <Tab title="Dynatrace">
    通过 Dynatrace 的 [Events API v2](https://docs.dynatrace.com/docs/dynatrace-api/environment-api/events-v2/post-event) 将 Dynatrace 配置为通知通道。该集成会把 LangSmith alert event 发送到你的 Dynatrace 环境中，以便与更广泛的基础设施监控数据进行关联。

    **Prerequisites**

    - 一个有效的 Dynatrace 环境，SaaS 或 Managed 均可。
    - 一个包含 `events.ingest` scope 的 Dynatrace API access token。

    如果你是在自定义 [deployment](/langsmith/self-hosted) 的 LangSmith 上工作，请确保没有 firewall 阻止 LangSmith 服务的出口流量。

    ### 1. Create an API token in Dynatrace

    1. 登录你的 Dynatrace 环境。
    1. 进入 **Access Tokens**。
    1. 点击 **Generate new token**。
    1. 提供一个描述性名称，例如 “LangSmith Alerts”。
    1. 在 **Scopes** 中搜索并启用 `events.ingest`，Ingest events。
    1. 点击 **Generate token**。
    1. 复制生成的 token 并妥善保存，该 token 只会显示一次。

    ### 2. Obtain your Dynatrace environment URL

    你的 Dynatrace 环境 URL 格式如下：

    ```
    https://{your-environment-id}.live.dynatrace.com
    ```

    登录 Dynatrace 后，可以从浏览器地址栏中找到 environment ID。

    ### 3. Configure LangSmith alert with Dynatrace

    1. 在 LangSmith 中 alert 设置的 **Notifications Settings** 区域，选择 **Dynatrace**。
    1. 输入你的 Dynatrace environment URL。
    1. 点击钥匙图标，将 API token 保存为 workspace secret，或选择已有的 workspace secret。最佳实践是将 API token 保存为 workspace secret，而不是直接写入，这样可以在同一 workspace 的多个 alert 中复用。
    1. 配置额外通知选项：
       - **Event Type**：选择 Dynatrace event type，例如 `CUSTOM_ALERT`、`ERROR_EVENT`
    1. 点击 **Send Test Notification** 发送测试通知。
    1. 验证 event 是否出现在你的 Dynatrace 环境中。

    ### Troubleshooting

    如果 event 没有出现在 Dynatrace 中：

    - 确认 API token 具有 `events.ingest` scope，且未过期。
    - 确认 environment URL 正确，并且包含正确的 environment ID。
    - 确认 `Authorization` header 使用的是 `Api-Token` 格式，而不是 `Bearer`。
    - 确认你的 Dynatrace 环境处于活动状态且可访问。
    - 如果你的 LangSmith 实例位于防火墙后方，请检查网络连通性。

    ### Additional resources

    - [Dynatrace Events API v2 Documentation](https://docs.dynatrace.com/docs/dynatrace-api/environment-api/events-v2/post-event)
    - [Dynatrace Access Tokens](https://docs.dynatrace.com/docs/manage/access-control/access-tokens)
  </Tab>
  <Tab title="Webhook">
    Webhook 通过在 alert 条件触发时发送 HTTP POST 请求，支持与你的自定义服务或第三方平台集成。你可以使用 webhook 将 alert 数据转发到工单系统、聊天应用或自定义监控方案。

    **Prerequisites**

    - 一个能够接收 HTTP POST 请求的 endpoint
    - 如果接收服务需要认证，还需要对应的认证凭据

    ### 1. Prepare your receiving endpoint

    在 LangSmith 中配置 webhook 之前，请确保接收 endpoint：

    - 接受 HTTP POST 请求
    - 能处理 JSON payload
    - 能从外部服务访问
    - 已具备合适的认证机制，如果需要

    如果你使用的是 LangSmith 的自定义部署，请确保没有 firewall 阻止 LangSmith 服务的出口流量。

    ### 2. Configure webhook parameters

    在 [LangSmith UI](https://smith.langchain.com) 的 **Monitoring** 区域下，进入 **Alerts** 标签页，点击 **+ Alert** 创建一个新的 alert。

    在 **Notification Settings** 区域中，填写以下 webhook 配置参数：

    **Required fields**

    - **URL**：接收 endpoint 的完整 URL
      - 示例：`https://api.example.com/incident-webhook`

    **Optional fields**

    - **Headers**：随 webhook 请求一同发送的 JSON key-value 对
      - 常见 headers 包括：
        - `Authorization`：用于认证 token
        - `Content-Type`：通常设置为 `application/json`，默认即如此
        - `X-Source`：用于标识来源是 LangSmith
      - 如果没有 headers，请使用 `{}`

    - **Request Body Template**：自定义发送到 endpoint 的 JSON payload
      - 默认情况下，LangSmith 会发送其定义的 payload，并附加以下顶层 key-value：
        - `project_name`：触发 alert 的项目名称
        - `alert_rule_id`：用于标识 LangSmith alert 的 UUID，可在 webhook 服务中用作去重 key
        - `alert_rule_name`：alert rule 的名称
        - `alert_rule_type`：alert 类型，截至 2025-04-01，所有 alert 均为 `threshold`
        - `alert_rule_attribute`：与 alert rule 关联的属性，例如 `error_count`、`feedback_score`、`latency` 或 `cost`
        - `triggered_metric_value`：阈值被触发时的指标值
        - `triggered_threshold`：触发 alert 的阈值
        - `timestamp`：触发 alert 的时间戳

    <Info>
    LangSmith 不会对 request body 做模板变量替换。上面这些自动填充字段会作为顶层 key 合并到最终发出的 JSON 中，与你手动配置的 body 一起发送。像 `{alert_rule_name}` 这样的占位符会原样发给接收方。只有当接收方本身能够从传入 JSON 中提取这些字段时，它们才会解析成真实值，例如 Power Automate Workflow、AWS Lambda 或自定义 HTTP handler。
    </Info>

    ### 3. Test the webhook

    点击 **Send Test Alert** 发送测试 webhook 通知，确认通知按预期工作。

    ### Troubleshooting

    如果 webhook 通知没有成功送达：

    - 确认 webhook URL 正确且可访问
    - 确认所有认证 header 格式正确
    - 确认接收 endpoint 接受 POST 请求
    - 检查接收 endpoint 的日志，看是否有收到但被拒绝的请求
    - 确认自定义 payload template 是合法 JSON

    ### Security considerations

    - 对 webhook endpoint 使用 HTTPS
    - 为 webhook endpoint 实施认证
    - 可以在 header 中加入共享密钥以验证 webhook 来源
    - 在处理前校验传入的 webhook 请求

    ### Example recipes

    <Accordion title="Configure Slack notifications via webhook">
      以下示例展示了如何通过 Slack 的 [`chat.postMessage`](https://api.slack.com/methods/chat.postMessage) API，将 LangSmith alerts 发送到 Slack channel。

      **Prerequisites**

      - 可访问的 Slack workspace
      - 已可用于配置 alert 的 LangSmith 项目
      - 创建 Slack application 的权限

      **Step 1: Create a Slack app**

      1. 访问 [Slack API Applications page](https://api.slack.com/apps)。
      2. 点击 **Create New App**。
      3. 选择 **From scratch**。
      4. 提供 **App Name**，例如 “LangSmith Alerts”。
      5. 选择要安装应用的 workspace。
      6. 点击 **Create App**。

      **Step 2: Configure bot permissions**

      1. 在 Slack app 配置页左侧边栏中，点击 **OAuth & Permissions**。
      2. 在 **Scopes** 下方滚动到 **Bot Token Scopes**，然后点击 **Add an OAuth Scope**。
      3. 添加以下 scope：
         - `chat:write`，允许 app 发送消息。
         - `chat:write.public`，允许 app 向尚未加入的 channel 发送消息。
         - `channels:read`，查看 channel 基本信息。

      **Step 3: Install the app to your workspace**

      1. 滚动回 **OAuth & Permissions** 页面的顶部。
      2. 点击 **Install to Workspace**。
      3. 查看权限并点击 **Allow**。
      4. 复制显示出来的 **Bot User OAuth Token**，格式以 `xoxb-` 开头。

      **Step 4: Add the bot to a Slack channel**

      将 bot 添加到你希望接收 alert 的特定 channel 中。可以在消息输入框里提及它，例如 `@botname`，将 bot 加入该 channel。

      你还需要 channel ID 才能在 LangSmith 中配置 webhook alert。可以通过打开 channel details > About 获取 channel ID。

      **Step 5: Configure the webhook alert in LangSmith**

      1. 在 LangSmith 中进入你的项目。
      2. 选择 **Alerts → Create Alert**。
      3. 定义 alert 的指标和条件。
      4. 在通知区域选择 **Webhook**。
      5. 使用以下设置配置 webhook：

      **Webhook URL**

      ```json
      https://slack.com/api/chat.postMessage
      ```

      **Headers**
      <Note>请将 `xoxb-your-token-here` 替换为你的 Bot User OAuth Token</Note>

      ```json
      {
        "Content-Type": "application/json",
        "Authorization": "Bearer xoxb-your-token-here"
      }
      ```

      **Request Body Template**
      <Note>这里必须填写 Step 4 中获得的 `{channel_id}`。<br /><br />其余字段 `alert_name`、`project_name` 和 `project_url` 用于为 alert 消息补充额外上下文。你可以在浏览器地址栏中找到 `project_url`，复制到不含 query 参数的部分即可。</Note>

      ```json
      {
        "channel": "{channel_id}",
        "text": "{alert_name} triggered for {project_name}",
        "blocks": [
          {
            "type": "section",
            "text": {
              "type": "mrkdwn",
              "text": "🚨{alert_name} has been triggered"
            }
          },
          {
            "type": "section",
            "text": {
              "type": "mrkdwn",
              "text": "Please check the following link for more information:"
            }
          },
          {
            "type": "section",
            "text": {
              "type": "mrkdwn",
              "text": "<{project-url}|View in LangSmith>"
            }
          }
        ]
      }
      ```

      6. 点击 **Save** 激活 webhook 配置。

      **Step 6: Test the integration**

      1. 在 LangSmith 的 alert 配置中点击 **Test Alert**。
      2. 检查指定 Slack channel 中是否收到了测试通知。
      3. 确认消息中包含预期的 alert 信息。

      **(Optional) Step 7: Link to the alert preview in the request body**

      在创建 alert 后，你还可以选择在 webhook 的 request body 中加入 alert preview 链接。

      ![Alert Preview Pane](/langsmith/images/alert-preview-pane.png)

      配置步骤如下：

      1. 保存 alert。
      2. 在 alerts table 中找到已保存的 alert 并点击它。
      3. 复制显示出的 URL。
      4. 点击 “Edit Alert”。
      5. 用刚复制的 alert preview URL 替换原来的 project URL。
    </Accordion>

    <Accordion title="Configure Microsoft Teams notifications via webhook">
      以下示例展示了如何通过 [Workflows app](https://support.microsoft.com/en-us/office/create-incoming-webhooks-with-workflows-for-microsoft-teams-8ae491c7-0394-4861-ba59-055e33f75498)，即 Power Automate，将 LangSmith alerts 发送到 Microsoft Teams channel。推荐这种方式，因为它会在 flow 内从传入 JSON 中提取字段，因此 LangSmith 自动填充的 alert 字段能够在 Teams 消息中正确渲染。

      <Note>
      Microsoft 的旧版 Office 365 Incoming Webhook connector 正在退役。新的集成请使用 Workflows app。
      </Note>

      **Prerequisites**

      - 可访问的 Microsoft Teams workspace，并且具有添加 Workflows 的权限
      - 已可用于配置 alert 的 LangSmith 项目

      **Step 1: Create a Workflow in Teams**

      1. 在 Microsoft Teams 中，进入希望接收 alert 的 channel。
      2. 点击 channel 名称旁边的 **...**，More options 菜单。
      3. 选择 **Workflows**。
      4. 搜索并选择 **Post to a channel when a webhook request is received** 模板。
      5. 登录并确认连接，然后点击 **Next**。
      6. 确认团队和用于接收 alert 的 channel，然后点击 **Add workflow**。
      7. 复制生成的 **HTTP POST URL**，后续要在 LangSmith 中使用。

      **Step 2: Customize the message in Power Automate (optional)**

      默认 workflow 会把原始 JSON body 作为卡片发出。如需格式化 alert 细节，请在 Power Automate 中编辑该 flow：

      1. 打开 [Power Automate portal](https://make.powerautomate.com)，编辑你创建的 workflow。
      2. 点击 **Post card in a chat or channel** action。
      3. 在 **Adaptive Card** 字段中，使用 `triggerOutputs()?['body/alert_rule_name']`、`triggerOutputs()?['body/project_name']`、`triggerOutputs()?['body/triggered_metric_value']`、`triggerOutputs()?['body/triggered_threshold']`、`triggerOutputs()?['body/timestamp']` 和 `triggerOutputs()?['body/alert_rule_url']` 引用传入字段。
      4. 保存该 flow。

      **Step 3: Configure the webhook alert in LangSmith**

      1. 在 LangSmith 中进入你的项目。
      2. 选择 **Alerts → Create Alert**。
      3. 定义 alert 的指标和条件。
      4. 在通知区域选择 **Webhook**。
      5. 使用以下设置配置 webhook：

      **Webhook URL**

      将 Teams Workflow 提供的 HTTP POST URL 粘贴到这里：

      ```
      https://prod-XX.westus.logic.azure.com:443/workflows/.../triggers/manual/paths/invoke?...
      ```

      **Headers**

      ```json
      {
        "Content-Type": "application/json"
      }
      ```

      **Request Body Template**

      LangSmith 会自动把 `alert_rule_name`、`project_name`、`triggered_metric_value`、`triggered_threshold`、`timestamp`、`alert_rule_url` 等字段合并到 request body 作为顶层 JSON key。Power Automate 会直接从传入 payload 中读取这些字段，因此空 body 即可：

      ```json
      {}
      ```

      6. 点击 **Save** 激活 webhook 配置。

      **Step 4: Test the integration**

      1. 在 LangSmith 的 alert 配置中点击 **Send Test Alert**。
      2. 检查指定 Teams channel 中是否收到了测试通知。
      3. 确认卡片中包含预期的 alert 信息。

      **Reference implementation**

      如需参考一个可工作的实现，它可以把 LangSmith webhook payload，包括 threshold alerts、run rules 和 generic events，转换为格式化的 Teams Adaptive Cards，请查看 [langsmith-teams-webhook](https://github.com/langchain-samples/langsmith-teams-webhook) 示例仓库。该示例以前置的小型 Python 服务形式运行在 Teams Workflow URL 前面，因此无需直接定制 Power Automate flow。
    </Accordion>

    <Accordion title="Configure email notifications via webhook">
      以下示例展示了如何使用 [SendGrid's Mail Send API](https://docs.sendgrid.com/api-reference/mail-send/mail-send) 通过 webhook 发送邮件通知。你也可以使用任何支持 HTTP API 的事务型邮件服务商，例如 Mailgun、Amazon SES 或 Postmark。

      **Prerequisites**

      - 一个 SendGrid account，并且已验证 sender identity
      - 一个具有 **Mail Send** 权限的 SendGrid API key
      - 已可用于配置 alert 的 LangSmith 项目

      **Step 1: Create a SendGrid API key**

      1. 登录 [SendGrid dashboard](https://app.sendgrid.com)。
      2. 进入 **Settings → API Keys**。
      3. 点击 **Create API Key**。
      4. 选择 **Restricted Access**，并启用 **Mail Send → Full Access**。
      5. 点击 **Create & View**，复制该 key 并妥善保存。

      **Step 2: Verify your sender email**

      1. 在 SendGrid 中进入 **Settings → Sender Authentication**。
      2. 完成 **Domain Authentication**，推荐，或 **Single Sender Verification**，用于你希望发件的邮箱地址。

      **Step 3: Configure the webhook alert in LangSmith**

      1. 在 LangSmith 中进入你的项目。
      2. 选择 **Alerts → Create Alert**。
      3. 定义 alert 的指标和条件。
      4. 在通知区域选择 **Webhook**。
      5. 使用以下设置配置 webhook：

      **Webhook URL**

      ```
      https://api.sendgrid.com/v3/mail/send
      ```

      **Headers**

      <Note>请将 `SG.your-api-key-here` 替换为你的 SendGrid API key。</Note>

      ```json
      {
        "Content-Type": "application/json",
        "Authorization": "Bearer SG.your-api-key-here"
      }
      ```

      **Request Body Template**

      <Note>
      请将 `alerts@your-company.com` 替换为已验证的发件地址，将 `oncall@your-company.com` 替换为收件地址。SendGrid 不会从任意顶层 JSON key 中提取字段，因此该示例使用固定的邮件主题和正文。如果你希望在邮件中包含具体 alert 值，请先将 LangSmith webhook 发送到一个中间层，例如 Power Automate flow、AWS Lambda 或 Zapier webhook，再由它读取传入 payload 并渲染 SendGrid 请求。
      </Note>

      ```json
      {
        "personalizations": [
          {
            "to": [
              {
                "email": "oncall@your-company.com"
              }
            ],
            "subject": "LangSmith alert triggered"
          }
        ],
        "from": {
          "email": "alerts@your-company.com",
          "name": "LangSmith Alerts"
        },
        "content": [
          {
            "type": "text/plain",
            "value": "A LangSmith alert was triggered. Open your LangSmith workspace to view the alert details, including the project, metric value, threshold, and timestamp."
          }
        ]
      }
      ```

      6. 点击 **Save** 激活 webhook 配置。

      **Step 4: Test the integration**

      1. 在 LangSmith 的 alert 配置中点击 **Send Test Alert**。
      2. 检查收件邮箱中是否收到了测试邮件。
      3. 确认邮件中包含预期的 alert 信息。

      **Using other email providers**

      其他支持静态认证 header 的事务型邮件 API 也可以采用同样的模式。只需将 **Webhook URL** 和 **Headers** 替换成对应服务商的要求：

      | Provider | Webhook URL | Auth header format |
      |----------|-------------|--------------------|
      | Mailgun | `https://api.mailgun.net/v3/{your-domain}/messages` | `Authorization: Basic <base64(api:<key>)>` |
      | Postmark | `https://api.postmarkapp.com/email` | `X-Postmark-Server-Token: <token>` |

      然后根据各自服务商的 payload 结构调整 **Request Body Template**。Amazon SES 不能直接兼容这种方式，因为 SES API 需要对每个请求执行 AWS SigV4 签名，这无法通过静态 header 表达。如果要使用 SES，请通过中间层处理，例如带 HTTP 触发器的 Lambda 函数。
    </Accordion>

- 确保 alert 路由能够送达合适的 on-call 人员
