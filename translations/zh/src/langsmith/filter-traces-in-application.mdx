Tracing 项目会在[threads](/langsmith/observability-concepts#threads)、[traces](/langsmith/observability-concepts#traces) 和 [runs](/langsmith/observability-concepts#runs) 这几个层面累积大量数据。LangSmith 的筛选工具可以帮助你更精确地浏览和分析这些数据。

如果你希望通过 [API](/langsmith/smith-api/run/query-runs) 或 [SDK](https://docs.smith.langchain.com/reference/python/client/langsmith.client.Client#langsmith.client.Client.list_runs) 以编程方式导出数据进行分析，请改看[导出 traces 指南](/langsmith/export-traces)。

## 创建并应用筛选条件

### 按 run 属性筛选

在 tracing 项目中有两种方式可以筛选数据：

1. **Filters**：位于 **Tracing** 项目页面左上角，用于构建和管理筛选条件。
    - 第一个下拉框用于在默认视图和[已保存视图](#save-a-filter)之间切换。
    - 可快速按 **Threads**、**Traces** 或 **Runs** 筛选。
    - 使用 **Add filter** 可根据属性或全文搜索来[配置筛选条件](#specific-filtering-techniques)。

1. **Filter Shortcuts**：位于 **Tracing** 项目页面右侧边栏。该面板会基于项目中 runs 最常出现的属性，提供常用筛选条件的快捷入口。

### 筛选运算符

可用的筛选运算符取决于你所筛选属性的数据类型。常见运算符如下：

- **is**：与筛选值精确匹配
- **is not**：与筛选值不匹配
- **contains**：与筛选值部分匹配
- **does not contain**：不包含筛选值中的内容
- **is one of**：匹配列表中的任意值
- `>` / `<`：适用于数值字段

## 具体筛选技巧

### 筛选 runs（spans）

如果要筛选 runs（spans），请将默认视图从 **Traces** 改为 **Runs**。例如，当你想按照 **run name** 或 **run type** 筛选时，就需要这样做。

run metadata 和 tags 也很适合拿来筛选，不过这依赖于你在整个 pipeline 中保持良好的打标习惯。更多信息请参阅[向 traces 添加 metadata 和 tags](/langsmith/add-metadata-tags)。

随着你添加更多筛选条件，还可以逐个点击每个筛选项，更新所搜索的属性。

### 按 inputs 和 outputs 筛选

你可以根据 thread、trace 或 run 的 inputs 和 outputs 中的内容来筛选 tracing 数据。

如果要按 inputs 或 outputs 筛选，可以使用 **<Icon icon="zoom"/> Full-Text Search** 过滤器，它会匹配任一字段中的关键词。若要做更有针对性的搜索，可以使用 **{<Icon icon="arrow-down-right"/>} Input** 或 **<Icon icon="arrow-up-left"/> Output** 过滤器，它们只会分别匹配对应字段中的内容。

<Note>
出于性能考虑，LangSmith 只会为最多 250 个字符建立全文检索索引。如果你的搜索查询超过这个限制，建议改用 [Input/Output 键值搜索](/langsmith/filter-traces-in-application#filter-based-on-input-%2F-output-key-value-pairs)。
</Note>

如果你想让多个条件同时匹配，可以采用以下任一方式：

- 在 **Full-Text Search** 中输入多个以空白字符分隔的词。
- 添加第一个筛选条件后，使用 <Icon icon="plus"/> 按钮继续添加多个过滤器。

LangSmith 会拆分文本，并以任意顺序匹配任意部分关键词。系统还会排除常见停用词，包括 nltk 停用词列表以及一些常见 JSON 关键词。

<Note>
被索引的 token 至少要有 2 个字符。单字符 token（例如 `a`、`x`）不会参与搜索。
</Note>

### 按 input / output 键值对筛选

除了全文搜索外，你还可以根据 inputs 和 outputs 中的特定键值对进行筛选。这在处理结构化数据时能提供更精确的筛选效果。

<Note>
为了保持数据有序且可检索，LangSmith 每个 run 最多索引 100 个唯一 key。每个 key 的 value 也有 250 个字符的上限。如果你的数据超出任一限制，这部分文本将不会被索引。这有助于保证快速且稳定的性能。
</Note>

例如，如果你想按照下面这段 input 进行筛选：

```json
{
  "input": "What is the capital of France?"
}
```

1. 选择 **Add filter**。
1. 在第一个下拉框中选择 **Input**，第二个下拉框保持 **Key**，然后选择 `input` 作为 key。
1. 点击 **+ Value**，并填入值：`What is the capital of France?`。

你也可以使用点号表示法匹配嵌套 key。例如，如果要匹配 output 中的嵌套 key：

```json
{
  "documents": [
    {
      "page_content": "The capital of France is Paris",
      "metadata": {},
      "type": "Document"
    }
  ]
}
```

选择 **Output Key**，输入 `documents.page_content` 作为 key，再输入 `The capital of France is Paris` 作为值。这样就会匹配嵌套 key `documents.page_content` 及其对应值。

你可以添加多个键值筛选条件来构造更复杂的查询。你也可以使用右侧的 **Filter Shortcuts**，快速按常见键值对进行筛选：

### 示例：筛选包含工具调用的 traces

很多场景下，你会希望搜索包含特定工具调用的 traces。工具调用通常会体现在某个 LLM run 的 output 中。要筛选这类工具调用，应使用 **Output Key** 过滤器。

虽然这个示例演示的是如何筛选工具调用，但同样的思路也适用于 output 中任意键值对的筛选。

假设你要筛选的 output 如下：

```json
{
  "generations": [
    [
      {
        "text": "",
        "type": "ChatGeneration",
        "message": {
          "lc": 1,
          "type": "constructor",
          "id": [],
          "kwargs": {
            "type": "ai",
            "id": "run-ca7f7531-f4de-4790-9c3e-960be7f8b109",
            "tool_calls": [
              {
                "name": "Plan",
                "args": {
                  "steps": [
                    "Research LangGraph's node configuration capabilities",
                    "Investigate how to add a Python code execution node",
                    "Find an example or create a sample implementation of a code execution node"
                  ]
                },
                "id": "toolu_01XexPzAVknT3gRmUB5PK5BP",
                "type": "tool_call"
              }
            ]
          }
        }
      }
    ]
  ],
  "llm_output": null,
  "run": null,
  "type": "LLMResult"
}
```

在这个例子中，KV 搜索会把每条嵌套 JSON 路径映射成可用于搜索和筛选的键值对。

LangSmith 会将它拆解成如下可搜索的键值对集合：

| Key                                                | Value                                                                        |
| -------------------------------------------------- | ---------------------------------------------------------------------------- |
| `generations.type`                                 | `ChatGeneration`                                                             |
| `generations.message.type`                         | `constructor`                                                                |
| `generations.message.kwargs.type`                  | `ai`                                                                         |
| `generations.message.kwargs.id`                    | `run-ca7f7531-f4de-4790-9c3e-960be7f8b109`                                   |
| `generations.message.kwargs.tool_calls.name`       | `Plan`                                                                       |
| `generations.message.kwargs.tool_calls.args.steps` | `Research LangGraph's node configuration capabilities`                       |
| `generations.message.kwargs.tool_calls.args.steps` | `Investigate how to add a Python code execution node`                        |
| `generations.message.kwargs.tool_calls.args.steps` | `Find an example or create a sample implementation of a code execution node` |
| `generations.message.kwargs.tool_calls.id`         | `toolu_01XexPzAVknT3gRmUB5PK5BP`                                             |
| `generations.message.kwargs.tool_calls.type`       | `tool_call`                                                                  |
| `type`                                             | `LLMResult`                                                                  |

如果你要搜索某个具体工具调用，可以去掉 root runs 过滤条件，并使用下面的 **Output Key** 查询：

`generations.message.kwargs.tool_calls.name` = `Plan`

这样就能匹配到 root runs 和非 root runs 中，`tool_calls` 名称为 `Plan` 的记录。

### 对键值对做负向筛选

你可以对 **\{x} Metadata**、**<Icon icon="arrow-down-right"/> Input** 和 **<Icon icon="arrow-up-left"/> Output** 字段使用不同类型的负向筛选，以排除特定 runs。

例如，如果要查找 metadata 中 key 为 `phone` 但值不等于 `1234567890` 的所有 runs：

1. 将 **Metadata Key** 的运算符设为 `is`，并把 **Key** 字段设为 `phone`。
1. 将 **Value** 的运算符设为 `is not`，并把 **Value** 字段设为 `1234567890`。

这样会匹配所有 metadata 中包含 `phone` 键、且其值不是 `1234567890` 的 runs。

如果想找出不包含特定 metadata key 的 runs，请将 **Key** 运算符设为 `is not`。例如，把 **Key** 运算符设为 `is not`，key 填 `phone`，就会匹配所有 metadata 中没有 `phone` 字段的 runs。

你也可以筛选既不包含某个 key，也不包含某个值的 runs。比如，要查找 metadata 中既没有 `phone` 这个 key，也没有任何字段值为 `1234567890` 的 runs，可以将 **Key** 运算符设为 `is not` 并填入 `phone`，同时将 **Value** 运算符设为 `is not` 并填入 `1234567890`。

最后，你也可以筛选没有某个 key、但存在某个值的 runs。比如，要查找没有 `phone` key，但其他某个 key 的值为 `1234567890` 的 runs，可以把 **Key** 运算符设为 `is not` 并填 `phone`，同时把 **Value** 运算符设为 `is` 并填 `1234567890`。

<Tip>
如果你需要做子串匹配，可以使用 `does not contain` 运算符替代 `is not`。
</Tip>

## 保存筛选条件

保存筛选条件后，你可以存储并重复使用常用的筛选配置。已保存的筛选条件仅适用于当前 tracing 项目。

构建好筛选条件后，点击 **Save as** 按钮即可保存。随后会弹出一个对话框，让你填写该筛选条件的名称和描述。

保存后，它会出现在视图下拉框中，供你作为快速筛选使用。

### 更新已保存的筛选条件

在下拉框中选中该筛选条件后，你可以修改任意筛选参数，然后点击 **Save** 进行更新。

### 删除已保存的筛选条件

点击下拉框中已保存筛选条件旁边的 <Icon icon="dots-vertical"/> 图标，然后使用垃圾桶 <Icon icon="trash"/> 图标删除该筛选条件。

## 复制筛选条件

你可以复制已构建好的筛选条件，用于与同事共享、后续复用，或在 [API](/langsmith/smith-api/run/query-runs) 或 [SDK](https://docs.smith.langchain.com/reference/python/client/langsmith.client.Client#langsmith.client.Client.list_runs) 中以编程方式查询 runs。

复制方法如下：

1. 先在 UI 中创建好筛选条件。
1. 点击筛选栏中的 <Icon icon="copy"/> 图标。如果你已经构建了 tree 或 trace 过滤器，也可以一并复制。
1. 系统会返回一个使用 LangSmith 查询语言表示的字符串。例如：`and(eq(is_root, true), and(eq(feedback_key, "user_score"), eq(feedback_score, 1)))`。

如需了解更多查询语言语法，请参阅 [Trace query syntax](/langsmith/trace-query-syntax#filter-query-language)。

## 在 Details 视图中筛选 runs

你也可以直接在 [Details 视图](/langsmith/view-traces#details-view)中应用筛选条件，这对于从包含大量 runs 的 trace 中快速缩小范围非常有用。这里可用的筛选条件与主 runs 表格视图中的一致。

默认情况下，只会显示匹配筛选条件的 runs。如果你希望在整个 trace tree 的上下文中查看这些命中项，可以将视图选项从 “Filtered Only” 切换为 “Show All” 或 “Most relevant”。

## 手动编写原始 LangSmith 查询语句

如果你已经[复制了之前构建好的筛选条件](#copy-a-filter)，可能希望在后续会话中手动再次应用这条原始查询语句。

要这样做，可以在 Details 视图的筛选弹窗底部点击 **Switch to raw query**。然后把原始查询粘贴到文本框中即可。

<Note>
这会把该查询添加到现有查询中，而不是覆盖原有查询。
</Note>

## 高级筛选

### 按 root 的属性筛选 runs（spans）

一种常见需求是：筛选那些所属 trace 的 root run 满足某些属性条件的 runs。比如，只看某类 runs，并且它们所在 trace 的 root run 带有正向或负向反馈。操作方式如下：

1. 在 Threads/Traces/Runs 切换器中点击 **Runs**。
1. 再添加一条筛选规则，然后点击筛选下拉框底部的 **Advanced** 链接。
1. 弹出的模态框中可以添加 **Trace** 过滤器。这些过滤器会应用到你已经筛出的各个 run 的所有父级 trace 上。

### 按子 runs 的属性筛选 runs（spans）

你可能还希望查找那些拥有特定子 runs 类型的 runs。例如，搜索所有包含名为 `Foo` 的子 run 的 traces。当 `Foo` 并非总会被调用，但你只想分析调用过它的情况时，这就非常有用。

1. 在 Threads/Traces/Runs 切换器中点击 **Runs**。
1. 再添加一条筛选规则，然后点击筛选下拉框底部的 **Advanced** 链接。
1. 弹出的模态框中可以添加 **Tree** 过滤器。你指定的规则会应用到已经筛出的各个 run 的所有子 runs 上。

### 示例：筛选 tree 中包含工具调用过滤条件的所有 runs

延续[工具调用筛选示例](#example-filtering-for-tool-calls)，如果你想筛选所有 _其 tree 中包含_ 某个工具调用过滤条件的 runs，可以在 **Advanced** 筛选设置中使用 tree filter。
