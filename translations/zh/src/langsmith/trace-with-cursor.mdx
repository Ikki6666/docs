LangSmith tracing 插件会把你的 [Cursor](https://cursor.com/) 智能体对话发送到 LangSmith，让你看到 agent 做了什么。每个 prompt 都会成为一条 trace，同一对话中的 prompts 则归入同一个 thread。

## 前提条件

- 已安装 [Cursor](https://cursor.com/)。
- 拥有一个 LangSmith 账户。
- 在 Windows 和 Linux 上需要 [Node.js](https://nodejs.org/) 22.13 或更高版本。在 macOS 上，插件会自行构建，无需 Node.js。

## 安装插件

要为自己安装该插件：

1. 在 Cursor 中打开 **Customize**，然后选择 **Add Marketplace**。
2. 输入 `https://github.com/langchain-ai/langsmith-cursor-plugins`。
3. 在 agent 聊天中运行 `/add-plugin langsmith-tracing`，或从 **Customize** 中新增的 **LangChain** 标签页安装。
4. 彻底重启 Cursor，以加载插件的 hooks。

想为所有人安装该插件，请参阅[部署到组织](#部署到组织)。有关安装插件的更多信息，请参阅 Cursor 文档中的 [Plugins](https://cursor.com/docs/plugins)。

## 登录

使用 LangSmith CLI 登录一次。如果还没有安装，请参阅[安装 LangSmith CLI](/langsmith/langsmith-cli#install)。

```bash
langsmith auth login
```

如果你使用 CLI 登录并且有多个 profile，请在配置文件中把 `profile` 设为插件应使用的那个。你自己的 `api_key` 会忽略此设置，但在设置了 `profile` 时，通用的 `LANGSMITH_API_KEY` 不会被用作回退。

如果想改用 API key，请把它添加到 `~/.cursor/langsmith.json`：

```json
{ "enabled": true, "api_key": "lsv2_pt_...", "agent_id": "shared-cursor" }
```

如果设置了多个凭据，插件会使用它找到的第一个：

1. 插件自己的 key，来自 `api_key` 或 `LANGSMITH_CURSOR_API_KEY`。
2. 你的 `langsmith auth login` 登录。
3. 环境中的通用 `LANGSMITH_API_KEY`。

当登录过期或 key 被拒绝时，tracing 会停止，这段空档期内的 turn 永远不会被上传。Cursor 在不中止 prompt 的情况下无法显示消息，因此插件会把原因写入 `~/.cursor/langsmith_hook.log`。管理员还可以为每个 prompt [要求有效的登录](#要求有效的登录)。

## 开启 tracing

除非管理员已经通过[托管文件](#锁定设置)开启了 tracing，否则在你于 `~/.cursor/langsmith.json` 中开启之前，tracing 都处于关闭状态。使用 `agent_id` 把 traces 发送到某个 [agent](/langsmith/log-traces-to-agent#send-traces-to-an-agent)：

```json
{ "enabled": true, "agent_id": "shared-cursor" }
```

或者使用 `project` 把它们发送到某个 project：

```json
{ "enabled": true, "project": "shared-cursor" }
```

两者任选其一。如果同时设置，`agent_id` 优先。

<Warning>
项目可以用 `<project>/.cursor/langsmith.json` 或 `<project>/langsmith-plugins.json` 覆盖这些设置。克隆下来的仓库可以利用它们开启 tracing，把你的 prompts 和文件发送到别人的服务器。在你信任某个仓库之前，请检查这些文件。Cursor 自己的 `.cursor/hooks.json` 可以运行命令，因此也要检查它。
</Warning>

发送一个 prompt，然后在 [LangSmith](https://smith.langchain.com) 中打开你的 agent 或 project。在 Auto 模式下，模型会显示为 `default`，subagents 不会显示 token 计数，因为 Cursor 不会报告其中任何一项。

## 隐藏对话

在 Cursor 的 agent 聊天中发送 `langsmith-tracing:mute` 作为消息，可以让对话内容不进入 LangSmith；发送 `langsmith-tracing:unmute` 则重新开启。请准确发送该文本，不要带斜杠，否则它会被当作普通 prompt 进行 tracing。确认信息会以被拦截的 prompt 形式出现，因为这就是 Cursor 展示插件回复的方式。

若要默认静音所有新对话，请将 `defaultMuted` 设为 `true`。

## Secret 脱敏

你在 prompt 中附加的图片会跳过脱敏。将 `attachments` 设为 `false` 可停止发送它们。要关闭脱敏或添加自己的 pattern，请参阅[插件设置](https://github.com/langchain-ai/langsmith-cursor-plugins#settings)。

## 设置

每项设置都有一个配置文件 key 和一个环境变量。两者都设置时，环境变量优先。

| 配置 key | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enabled` | `TRACE_TO_LANGSMITH` | `false` | 开启 tracing。 |
| `api_key` | `LANGSMITH_CURSOR_API_KEY` | 无 | LangSmith API key。如果使用 CLI 登录则不需要。 |
| `project` | `LANGSMITH_CURSOR_PROJECT` | `cursor` | traces 发送到的 project。与 `agent_id` 二选一。 |
| `agent_id` | `LANGSMITH_AGENT_ID` | 无 | traces 发送到的 agent。两者都设置时优先于 `project`。 |
| `api_url` | `LANGSMITH_CURSOR_ENDPOINT` | `https://api.smith.langchain.com` | 发送到的 LangSmith 服务器。 |

有关全部设置，请参阅[插件设置](https://github.com/langchain-ai/langsmith-cursor-plugins#settings)。

## 故障排查

- **没有 traces**：检查插件是否在 Cursor 的插件列表中，以及安装后是否彻底重启了 Cursor。然后检查 tracing 是否已开启。
- **Tracing 已暂停**：再次运行 `langsmith auth login`，或替换被拒绝的 API key。
- **仍然无法解决**：在发送 prompt 时运行 `tail -f ~/.cursor/langsmith_hook.log`。设置 `LANGSMITH_CURSOR_DEBUG=1` 可获取更多详细信息。

更多修复方法，请参阅[当没有任何内容出现时](https://github.com/langchain-ai/langsmith-cursor-plugins#when-nothing-shows-up)。
