使用 [Cursor hooks](https://cursor.com/docs/agent/hooks)，在 LangSmith 中跟踪 [Cursor](https://cursor.com/) 智能体会话。每个回合都会成为一条 trace，并按每个 Cursor 对话归入同一个 thread，从而捕获 prompts、模型响应、工具调用、token 用量和 subagent 活动。你可以利用这些 traces 调试智能体行为、审计工具调用、跟踪每回合 token 花费，以及比较 Cursor 的运行结果。

插件源码位于 [`langchain-ai/langsmith-cursor-plugins`](https://github.com/langchain-ai/langsmith-cursor-plugins)。

## 前提条件

在设置 tracing 之前，确保你已具备：

- 已安装 [Cursor](https://cursor.com/)。
- [Node.js](https://nodejs.org/) 22.13 或更高版本。该 hooks 使用内置 `node:sqlite` 模块，从 Cursor 的本地数据库中恢复附件。
- 一个 [LangSmith API key](/langsmith/create-account-api-key)。

## 安装并启用插件

在 Cursor 的设置中，直接从 GitHub 仓库安装插件：

1. 打开 **Cursor → Settings → Plugins**。
2. 将 `https://github.com/langchain-ai/langsmith-cursor-plugins` 粘贴到插件链接输入框中。
3. 确认添加 **LangSmith Tracing for Cursor**。

这是推荐方式，因为仓库已自带预编译 bundle，因此安装 hooks 时不需要 clone 或 build。

<Warning>
安装完成后请彻底重启 Cursor，以便重新加载 `hooks.json`。
</Warning>

### 备选方案：从本地 clone 安装

从本地 clone 的 [`langsmith-cursor-plugins`](https://github.com/langchain-ai/langsmith-cursor-plugins) 安装 hooks。这样会为所有 Cursor 项目写入 `~/.cursor/hooks.json`：

```bash
node scripts/install.mjs
```

如果你只想把 hooks 限定到某个项目，请在项目目录中运行安装器：

```bash
node scripts/install.mjs --project
```

如果你只想预览 hook 配置而不实际写入，请运行：

```bash
node scripts/install.mjs --print
```

安装器会把它自己的条目与现有 `hooks.json` 合并。由于仓库中已提交 `bundle/`，因此这些命令无需先执行 `pnpm install` 或 `pnpm build`，只有在你要为 TypeScript 源码贡献修改时才需要。

安装完成后请重启 Cursor，以便重新加载 `hooks.json`。

## 配置 tracing

只有当 `enabled` 为真，或 `TRACE_TO_LANGSMITH=true`，并且已设置 API key 时，tracing 才会启用。你可以通过[环境变量](#environment-variables)、[JSON 配置文件](#config-file)，或两者结合进行配置。

### 环境变量

每个 `LANGSMITH_CURSOR_*` 变量都同时接受更短的 `LANGSMITH_*` 形式。如果两者都设置了，`LANGSMITH_CURSOR_*` 优先。

| Variable | Default | Description |
| --- | --- | --- |
| `TRACE_TO_LANGSMITH` | `false` | 设置为 `"true"` 以启用 tracing。 |
| `LANGSMITH_CURSOR_API_KEY` | - | LangSmith API key。回退到 `LANGSMITH_API_KEY`。 |
| `LANGSMITH_CURSOR_ENDPOINT` | `https://api.smith.langchain.com` | LangSmith API URL。回退到 `LANGSMITH_ENDPOINT`。 |
| `LANGSMITH_CURSOR_PROJECT` | `cursor` | LangSmith project 名称。回退到 `LANGSMITH_PROJECT`。 |
| `LANGSMITH_CURSOR_METADATA` | - | 合并到根 trace metadata 的 JSON 对象。 |
| `LANGSMITH_CURSOR_RUNS_ENDPOINTS` | - | replica 目标的 JSON 数组。 |
| `LANGSMITH_CURSOR_ATTACHMENTS` | `true` | 设置为 `"false"` 以禁用附件增强。 |
| `LANGSMITH_CURSOR_DB_PATH` | platform default | 覆盖用于附件恢复的 Cursor `state.vscdb` 路径。 |
| `LANGSMITH_CURSOR_STATE_FILE` | `~/.cursor/langsmith-state.json` | 覆盖磁盘上的 event-buffer 状态文件。 |
| `LANGSMITH_CURSOR_LOG_FILE` | `~/.cursor/langsmith-hook.log` | 覆盖 hook 日志文件。 |
| `LANGSMITH_CURSOR_DEBUG` | `false` | 设置为 `"true"` 以启用详细 hook 日志。 |

把这些变量加到你的 shell 配置文件中，例如 `~/.zshrc`、`~/.bashrc` 或 `~/.bash_profile`：

```bash
export TRACE_TO_LANGSMITH="true"
export LANGSMITH_CURSOR_API_KEY="<your-langsmith-api-key>"
export LANGSMITH_CURSOR_PROJECT="cursor"
```

如需验证 hook 活动，可持续查看日志文件：

```bash
tail -f ~/.cursor/langsmith-hook.log
```

### 配置文件

使用 `~/.cursor/langsmith.json` 作为全局默认设置，或使用 `./.cursor/langsmith.json` 作为项目级设置。设置按以下顺序解析，后者覆盖前者：默认值、全局配置、项目配置、环境变量。

```json
{
  "enabled": true,
  "api_key": "<your-langsmith-api-key>",
  "api_url": "https://api.smith.langchain.com",
  "project": "cursor"
}
```

| Field | Environment variable | Default | Description |
| --- | --- | --- | --- |
| `enabled` | `TRACE_TO_LANGSMITH` | `false` | 设置为 `true` 以启用 tracing。 |
| `api_key` | `LANGSMITH_CURSOR_API_KEY`, `LANGSMITH_API_KEY` | - | LangSmith API key。 |
| `api_url` | `LANGSMITH_CURSOR_ENDPOINT`, `LANGSMITH_ENDPOINT` | `https://api.smith.langchain.com` | LangSmith API URL。 |
| `project` | `LANGSMITH_CURSOR_PROJECT`, `LANGSMITH_PROJECT` | `cursor` | LangSmith project 名称。 |
| `metadata` | `LANGSMITH_CURSOR_METADATA`, `LANGSMITH_METADATA` | - | 合并到根 trace metadata 的对象。 |
| `replicas` | `LANGSMITH_CURSOR_RUNS_ENDPOINTS`, `LANGSMITH_RUNS_ENDPOINTS` | - | 额外的 LangSmith 目标，用于复制 traces。 |
| `attachments` | `LANGSMITH_CURSOR_ATTACHMENTS` | `true` | 设置为 `false` 可跳过从 Cursor 本地数据库中提取图片和文件附件字节并补充到回合中的过程。 |
| `cursor_db_path` | `LANGSMITH_CURSOR_DB_PATH` | platform default | 覆盖用于附件恢复的 Cursor `state.vscdb` 路径。 |

包含 API keys 的配置文件不要纳入版本控制。

## 会跟踪哪些内容

插件会监听 Cursor hooks，并为每个智能体回合组装出一条 trace：

- **Turns**：每个回合都会成为一条独立 trace，并通过 `thread_id`，也就是 Cursor 的 `conversation_id`，归入同一个 thread。该 trace 会在回合之下嵌套模型 run，以及任何工具或 subagent runs。
- **Token usage**：记录在模型 run 上的每回合 `usage_metadata`。
- **Model and provider**：`ls_model_name` 和 `ls_provider`，会从 Cursor 的模型标签规范化为标准 provider id，例如 `claude-4.6-sonnet` 会变成 `claude-sonnet-4-6`。Auto 模式会记录为 provider `cursor`、模型 `default`。
- **Tool calls**：无论成功还是失败，都会为工具调用生成 tool runs，并记录输入与输出。
- **Attachments**：从 Cursor 的本地数据库中恢复图片和文件附件，并以内联形式渲染在用户消息上。将 `attachments` 设为 `false` 可跳过这一步。
- **Subagents**：每个 subagent 都会作为一个嵌套 chain run 出现，其下方再嵌套自己的工具调用。

<Note>
插件不会在本地计算成本。因为 `ls_model_name` 已规范化为标准 id，且 `usage_metadata` 携带了 token 细分信息，因此 LangSmith 服务器端的模型价格表可以在 UI 中渲染出成本。Auto 模式会记录为 `default`，LangSmith 无法为其计算价格。
</Note>

<Warning>
该插件会上传 Cursor 对话数据，包括 prompts、模型响应、工具输入与输出，以及恢复出的附件。对于包含你不希望存储在 LangSmith 中的数据的会话，请不要启用 tracing。
</Warning>

### Trace metadata

每个 run 都会在 `run.extra.metadata` 上携带统一的 `coding-agent-v1` metadata contract，这使得来自任意 coding agent，Claude Code、Codex、Cursor，的 traces 都能通过同一套稳定 keys 被识别和分组。

| Scope | Keys |
| --- | --- |
| Always present | `ls_agent_type`（`"root"`、`"subagent"`、`"middleware"` 或 `"compaction"`），`ls_agent_purpose`（`"coding"`），`ls_integration`（`"cursor"`），`ls_agent_runtime`（`"Cursor"`），`ls_trace_schema_version`（`"coding-agent-v1"`），`thread_id`（即 Cursor 的 `conversation_id`）。 |
| Present where known | `ls_integration_version`、`ls_agent_runtime_version`，即 Cursor 的 `cursor_version`、`turn_id`，即 Cursor 的 `generation_id`、`turn_number`、`repository_url`、`repository_provider`、`repository_name`、`git_branch`、`git_commit_sha`、`cwd`。 |
| Contextual | `local_username`、`user_email`，临时字段。 |
| Subagent runs only | `ls_subagent_id`、`ls_subagent_type`。 |
| Tool runs only | `ls_tool_name`，仅当 run name 与原生工具名不同才会发出。 |
| Model and tool runs only | `ls_provider`、`ls_model_name`、`ls_invocation_params`、`usage_metadata`。 |

Cursor 的 hooks 不会暴露 `user_id`、`sandbox_type` 或 `approval_policy` 的稳定来源，因此这些 keys 会被省略。

## 在 LangSmith 中查看 traces

打开配置好的 LangSmith project，默认为 `cursor`，并完成一个 Cursor 回合。插件会按以下结构上传每个回合的一条 trace：

```
Cursor Turn N (chain)
├── <provider> (llm)   model and provider, token usage, assistant text
├── Read / Shell / ... (tool)
└── Task (tool)        subagent (type and task)
```

如需将相关回合分组，请在项目的 **Threads** 标签页中按 `thread_id` 进行过滤。

## 已知限制

- **Subagent token usage**：Cursor 不会通过 hooks 或其本地数据库暴露每个 subagent 的 token 用量明细，因此 subagent 的 `Task` run 会带有其工具调用，但没有 token 计数。

## 故障排查

如果 traces 没有出现在 LangSmith 中：

- 确认已通过 `TRACE_TO_LANGSMITH=true` 或某个配置文件中的 `"enabled": true` 启用 tracing，并且 Cursor 进程能看到这些设置。
- 确认 `LANGSMITH_CURSOR_API_KEY` 或 `LANGSMITH_API_KEY` 已设置且有效。
- 确认安装 hooks 后已彻底重启 Cursor。
- 持续查看 hook 日志，检查是否有错误：`tail -f ~/.cursor/langsmith-hook.log`。
- 将 `LANGSMITH_CURSOR_DEBUG=true` 打开详细日志后，再次检查日志。
- 如果 runs 落到了错误的 project，请设置 `LANGSMITH_CURSOR_PROJECT` 或配置中的 `project` key。
