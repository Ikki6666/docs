## Durable execution

从本质上说，LangSmith Deployment 是一个 durable execution engine。你的 agents 运行在托管任务队列上，并带有自动 checkpointing，因此任何 run 都可以从精确的中断点进行重试、重放或恢复，而不是从头开始。

由于执行具有持久性，agents 可以完成一些在无状态运行时中脆弱甚至不可能完成的事情：

- **等待外部输入。** agent 调用 [`interrupt()`](/langsmith/add-human-in-the-loop) 后，运行时会将其状态 checkpoint，释放资源，并等待人工批准一笔交易、审稿人修改草稿，或另一个系统返回结果。当数小时或数天后 [`Command(resume=...)`](/langsmith/add-human-in-the-loop) 到达时，执行会精确地从中断点继续。这是 [human-in-the-loop](/langsmith/add-human-in-the-loop) 工作流和 [time-travel debugging](/langsmith/human-in-the-loop-time-travel) 的底层原语。
- **后台运行。** [Background runs](/langsmith/background-run) 会在不阻塞调用方的情况下执行。运行时负责完整生命周期（排队、执行、checkpoint、完成），而 client 可以继续做别的事情。
- **按计划运行。** [Cron jobs](/langsmith/cron-jobs) 会以周期性节奏触发 agent 执行。无论是每日摘要 agent、每周报告还是周期性数据同步，运行时都会按计划启动新的执行，并提供同样的持久性保障。
- **处理并发输入。** 当用户在 agent 运行过程中又发送新输入（[double-texting](/langsmith/double-texting)）时，运行时可以将其排队、取消正在进行的 run，或并行处理两者，而不会出现数据竞争或状态损坏。
- **失败后重试。** 可配置的 [retry policies](/oss/langgraph/use-graph-api#add-retry-policies) 可按节点控制退避、最大重试次数，以及哪些异常会触发重试。即使进程重启、基础设施故障，或代码在执行中途发布了新版本，runs 也能继续存活。

如需了解容器、进程和任务队列如何协同工作，请参阅 [Agent Server: Runtime architecture](/langsmith/agent-server#runtime-architecture)。如需了解扩缩容和吞吐调优，请参阅 [Configure Agent Server for scale](/langsmith/agent-server-scale)。
