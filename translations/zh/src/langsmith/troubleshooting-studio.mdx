## Safari 连接问题

Safari 会阻止 localhost 上的明文 HTTP 流量。使用 `langgraph dev` 运行 Studio 时，你可能会看到 “Failed to load assistants” 错误。

### 解决方案 1：使用 Cloudflare Tunnel

<Tabs>
    <Tab title="Python">
    ```shell
    pip install -U langgraph-cli>=0.2.6
    langgraph dev --tunnel
    ```
    </Tab>
    <Tab title="JS">
    ```shell
    # Requires @langchain/langgraph-cli>=0.0.26
    npx @langchain/langgraph-cli dev --tunnel
    ```
    </Tab>
</Tabs>

该命令会输出一个 tunnel URL。要连接 Studio：

1. 复制 tunnel URL，例如 `https://hamilton-praise-heart-costumes.trycloudflare.com`
2. 打开位于 `https://smith.langchain.com/studio/` 的 Studio
3. 点击 **Connect to a local server**
4. 粘贴 tunnel URL，并将其添加到 **Allowed Origins**
5. 点击 **Connect**

这一步需要手动完成，出于安全原因，Studio 在连接外部 URL 之前需要用户显式确认。

<Note>
Cloudflare tunnels 可能不太稳定，并且偶尔会中断连接。
</Note>

### 解决方案 2：使用 Chromium 浏览器

Chrome 及其他 Chromium 浏览器允许在 localhost 上使用 HTTP。你可以直接使用 `langgraph dev`，无需额外配置。

## Chrome 连接问题

从 Chrome 142 开始，当你尝试通过 [`langgraph dev`](/langsmith/cli) 将 [LangSmith Studio](/langsmith/studio) 连接到本地开发服务器时，可能会看到 “Failed to initialize Studio” 和 “TypeError: Failed to fetch” 错误。即使 `http://127.0.0.1:2024/docs` 上的 API server 能正常打开，这个问题也依然可能发生。

**根因：** Chrome 142 已完整强制执行 Private Network Access, PNA, 规范，且不再保留回退机制。这会默认阻止 HTTPS 站点，例如 `https://smith.langchain.com`，访问本地的 HTTP localhost servers。

### 症状

- 运行 `langgraph dev` 后，server 可以成功启动。
- 打开 `http://127.0.0.1:2024/docs` 时，API 文档显示正常。
- 位于 `https://smith.langchain.com` 的 LangSmith Studio 会显示：“Failed to initialize Studio - Please verify if the API server is running or accessible from the browser. TypeError: Failed to fetch”。
- 浏览器控制台会显示类似这样的错误：`Permission was denied for this request to access the 'unknown' address space`。

### 解决方案：在 Chrome 中允许本地网络访问

1. 在 Chrome 中打开位于 `https://smith.langchain.com` 的 LangSmith Studio。
2. 点击地址栏左侧的**锁图标**，或站点信息图标。
3. 在下拉菜单中找到 **"Local network access"** 选项。
4. 将设置从 **"Ask (default)"** 或 **"Block"** 改为 **"Allow"**。
5. 重新加载页面。

此后，Studio 应能成功连接到你的本地开发服务器。

### 额外故障排查

**检查是否有浏览器扩展冲突**

浏览器扩展，尤其是 Ollama Chrome 扩展或其他 AI 模型相关扩展，可能会干扰 localhost 连接：

1. 暂时禁用所有浏览器扩展。
2. 重启 Chrome。
3. 再次尝试连接 Studio。
4. 如果问题消失，则逐个重新启用扩展，以定位问题来源。

**确认依赖已更新到最新版本**

```shell
pip install -U "langgraph-cli[inmem]"
```

**清理浏览器缓存与站点数据**

1. 在 Chrome 中进入 **Settings** > **Privacy and Security** > **Site Settings**。
2. 在列表中找到 `https://smith.langchain.com`。
3. 点击 **Clear data**。
4. 重启 Chrome 后再次尝试。

## Graph edge 问题

未定义的 conditional edges 可能会在图中显示出意料之外的连接。这是因为如果没有正确定义，Studio 会假定该 conditional edge 可以访问所有其他节点。要解决这个问题，请用以下任一方式显式定义路由路径：

### 解决方案 1：Path map

定义 router 输出与目标节点之间的映射关系：

<Tabs>
    <Tab title="Python">
    ```python
    graph.add_conditional_edges("node_a", routing_function, {True: "node_b", False: "node_c"})
    ```
    </Tab>
    <Tab title="Javascript">
    ```ts
    graph.addConditionalEdges("node_a", routingFunction, { true: "node_b", false: "node_c" });
    ```
    </Tab>
</Tabs>

<a id="python"></a>
### 解决方案 2：Router 类型定义

使用 Python 的 `Literal` 类型，指定可能的路由目标：

```python
def routing_function(state: GraphState) -> Literal["node_b","node_c"]:
    if state['some_condition'] == True:
        return "node_b"
    else:
        return "node_c"
```

## Studio 中的实验故障排查

### **Run experiment** 按钮不可用

请检查以下内容：

- **Deployed application**：如果你的应用已经部署在 LangSmith 上，你可能需要创建一个新的 revision 才能启用此功能。
- **Local development server**：如果你是在本地运行应用，请确保已升级到最新版 `langgraph-cli`，例如 `pip install -U langgraph-cli`。此外，还要确保通过在项目的 `.env` 文件中设置 `LANGSMITH_API_KEY`，启用了 tracing。

### Evaluator 结果缺失

当你运行实验时，所有附带的 evaluators 都会被排入队列等待执行。如果结果没有立刻出现，通常意味着它们仍在排队处理中。
