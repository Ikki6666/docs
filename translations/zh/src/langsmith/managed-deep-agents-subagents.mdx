为 managed deep agent 配置 subagents，用于委派专业化或上下文繁重的工作，例如调研某个主题、审查一项变更，或使用 async subagent 在后台运行长时间任务，同时 agent 继续与用户对话。每个 subagent 都有自己的 prompt 和上下文窗口，也可以使用自己的 model 和 tools。

<ManagedDeepAgentsPublicBetaNote />

Subagent 分为两种类型：

| 类型 | Agent 如何使用 | 适用场景 |
| --- | --- | --- |
| Subagent | 使用 `task` 调用并等待其回答 | Agent 需要先取得结果才能继续的专注型工作 |
| Async subagent | 使用 `start_async_task` 启动后继续工作；subagent 完成时会回报结果 | Agent 无需等待的长时间运行或并行工作 |

Subagent 运行在 agent 的 graph 内。Managed Deep Agents 会在同一 deployment 中将每个 async subagent 构建为独立的 graph。两种 subagent 都在 agent 的 [sandbox](/langsmith/managed-deep-agents-sandboxes) 中工作。关于 subagents 在开源 Deep Agents SDK 中的工作方式，请参见 [Subagents](/oss/deepagents/subagents) 和 [Async subagents](/oss/deepagents/async-subagents)。

<Note>
Async subagents 需要 `managed-deepagents>=0.10.0`。
</Note>

## 声明 subagent

在 [agent definition](/langsmith/managed-deep-agents-agent-definition) 的 `subagents` 中添加 subagent 定义。每个 subagent 都需要 `name` 和 `description`；agent 使用 description 决定何时委派。要让 subagent 变为异步，请在其定义中添加 `async`：

:::python
<Tabs>
  <Tab title="Subagent">
```python agent.py
from managed_deepagents import define_deep_agent

agent = define_deep_agent(
    name="research-assistant",
    model="openai:gpt-5.5",
    subagents=[
        {
            "name": "reviewer",
            "description": "Reviews a draft for accuracy and clarity.",
            "system_prompt": "Review the draft and list concrete fixes.",
        },
    ],
)
```
  </Tab>
  <Tab title="Async subagent">
```python agent.py
from managed_deepagents import define_deep_agent

agent = define_deep_agent(

        {
            "name": "researcher",
            "description": "Researches a topic in the background.",
            "system_prompt": "Research the topic and report your findings.",
            "async": True,
        },
    ],
)
```
  </Tab>
</Tabs>

## 同步 subagents

Agent 使用 `task` tool 运行 subagent，并等待其回答。Subagent 运行在 agent 的 graph 内，并在 agent 的 [sandbox](/langsmith/managed-deep-agents-sandboxes) 中工作。

每个 agent 还会获得一个 `general-purpose` subagent，用于处理与任何已声明 subagent 都不匹配的委派工作。请参见 [The general-purpose subagent](/oss/deepagents/subagents#the-general-purpose-subagent)。

### Subagent 继承的内容

Subagent 以 agent 的配置为起点，并替换其定义所设置的内容：

:::python
| 设置 | 行为 |
| --- | --- |
| `model`, `tools`, `permissions`, `interrupt_on` | 使用 agent 的设置，除非 subagent 设置了自己的值 |
| `system_prompt` | 仅使用 subagent 自己的 prompt，不使用 agent 的 [instructions](/langsmith/managed-deep-agents-instructions) |
| `skills` | 仅加载 subagent 列出的 skills；列出 `"/skills/"` 可加载 agent 的 skills |
| `middleware`, `response_format` | 仅使用 subagent 自己的设置 |
| Memory | 不加载 |
:::

:::js
| 设置 | 行为 |
| --- | --- |
| `model`, `tools`, `permissions`, `interruptOn` | 使用 agent 的设置，除非 subagent 设置了自己的值 |
| `systemPrompt` | 仅使用 subagent 自己的 prompt，不使用 agent 的 [instructions](/langsmith/managed-deep-agents-instructions) |
| `skills` | 仅加载 subagent 列出的 skills；列出 `"/skills/"` 可加载 agent 的 skills |
| `middleware`, `responseFormat` | 仅使用 subagent 自己的设置 |
| Memory | 不加载 |
:::

处于 fork 模式的 subagent 会以 agent 对话的副本开始，并且还会使用 agent 的 instructions、middleware、skills 和 memory。请参见 [Choose a launch mode](/oss/deepagents/async-subagents#choose-a-launch-mode)。

## 异步 subagents

Agent 使用 `start_async_task` 启动 async subagent，并在 subagent 于自己的 thread 上运行时继续工作。Subagent 完成时会回报结果。

### Async subagent 的运行方式

每个 async subagent 在 deployment 中都表现为独立的 graph，名称由 agent 和 subagent 组成，例如 `research-assistant--researcher`。Managed Deep Agents 在构建时通过读取 agent 文件来发现 async subagents，而不是通过运行 agent 文件。请直接在 `subagents` 中或在变量中编写每个 async subagent，并为 `name` 和 `async` 提供固定值。由函数或循环构建的 async subagent 不会获得 graph，agent 也会启动失败。[Graph factory](/langsmith/managed-deep-agents-agent-definition#select-configuration-per-run) 也可以声明 async subagents，前提是它直接返回 agent 定义。

由 `mda dev` 或 deployment 提供服务的 agent 还会获得 `general-purpose` subagent 的异步版本，因此 agent 可以在前台或后台运行委派工作。

Agent 使用以下 tools 管理 async subagents：

| Tool | 作用 |
| --- | --- |
| `start_async_task` | 在独立 thread 上启动 async subagent，并立即返回 task ID |
| `check_async_task` | 获取 task 的状态，并在其完成后获取结果 |
| `update_async_task` | 向 task 发送新指令 |
| `cancel_async_task` | 停止正在运行的 task |
| `list_async_tasks` | 列出 agent 的 tasks 及其状态 |

这些 tools 随异步 `general-purpose` subagent 一起提供，因此由 `mda dev` 或 deployment 提供服务的每个 agent 都拥有它们。使用 `mda eval` 运行的 agent 没有这些 tools。

### 在 subagent 完成时获取通知

无论 agent 正在忙碌、空闲还是等待审批，async subagents 都会自行回报结果。Agent 无需使用 `check_async_task` 轮询：

| Subagent 完成时，agent 处于 | 会发生什么 |
| --- | --- |
| 忙碌 | Agent 会在每次 model 调用前检查尚未完成的 tasks，因此能在 run 进行中获取结果 |
| 空闲 | Subagent 会通过一次新的 run 唤醒 agent |
| 因审批而暂停 | 审批保持原样；用户回答后，agent 会收到结果 |

每个结果只回报一次。在每次 model 调用前，agent 会对每个未完成的 task 执行一次状态检查，最多等待 5 秒。

如果 subagent 因审批而暂停，agent 会将其 task 视为 `waiting`，直到有人在 subagent 的 thread 上回答。请参见 [Answer approvals in channels](#answer-approvals-in-channels)。

### 配置 async subagent

:::python
不要设置 async subagent 的 `graph_id`、`url`、`headers` 或 `runnable`：Managed Deep Agents 会自行构建并启动其 graph。以下选项会透传给 Deep Agents：

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `update_strategy` | `"interrupt"` | `"enqueue"` 会将后续消息排入当前 run 之后，而不是中断它 |
| `notify_parent` | `True` | 当 agent 空闲而 subagent 完成时唤醒 agent。设为 `False` 可自行处理结果，例如通过 `webhook` |
| `webhook` | 未设置 | 每当 subagent 的某次 run 完成时，Agent Server 会调用的 URL，同时附带该 run 的 thread ID、run ID 和状态。请参见 [Deliver results through your app](/oss/deepagents/async-subagents#deliver-results-through-your-app) |
| `mode` | `"isolated"` | `"fork"` 会以 agent 对话的副本启动 subagent |
:::

:::js
不要设置 async subagent 的 `graphId`、`url`、`headers` 或 `runnable`：Managed Deep Agents 会自行构建并启动其 graph。以下选项会透传给 Deep Agents：

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `updateStrategy` | `"interrupt"` | `"enqueue"` 会将后续消息排入当前 run 之后，而不是中断它 |
| `notifyParent` | `true` | 当 agent 空闲而 subagent 完成时唤醒 agent。设为 `false` 可自行处理结果，例如通过 `webhook` |
| `webhook` | 未设置 | 每当 subagent 的某次 run 完成时，Agent Server 会调用的 URL，同时附带该 run 的 thread ID、run ID 和状态。请参见 [Deliver results through your app](/oss/deepagents/async-subagents#deliver-results-through-your-app) |
| `mode` | `"isolated"` | `"fork"` 会以 agent 对话的副本启动 subagent |
:::

关于每个选项的行为，请参见 [Async subagents](/oss/deepagents/async-subagents)。

要将另一个 deployment 上的 agent 用作 async subagent，请用它的 graph ID 和 `url` 声明它，并且不要设置 `async`，Managed Deep Agents 会将它原样透传给 Deep Agents。对于 Managed Deep Agent，其 graph ID 就是它的 `name`。请参见 [remote subagents](/oss/deepagents/async-subagents#http-transport-remote)。

### Async subagent 继承的内容

Async subagent 继承 agent 的方式与 [subagent](#what-a-subagent-inherits) 相同。在 fork 模式下，它以 agent 对话的副本开始，但保留自己的 prompt、tools 和 middleware，因此通常不会复用 agent 的 [prompt cache](/oss/deepagents/async-subagents#fork-mode)。

### 共享 sandbox 和 trace

Async subagent 会在新的 thread 上启动，该 thread 与 agent 的 thread 相互独立。由于 agent 以同一用户身份启动它，它会共享 agent 的 sandbox。启用 [private threads](/langsmith/managed-deep-agents-identity) 时，来自其他用户的 subagent run 会获得自己的 sandbox。共享 sandbox 时，它按原样使用 agent 的文件，仅刷新 connector 凭据。如果 agent 尚未使用其 sandbox，subagent 会创建 sandbox，之后 agent 使用同一个 sandbox。

启用 tracing 后，async subagent 的 run 会在 LangSmith 中显示在 agent 的 run 之下。

### 在 channels 中回答审批

当 agent 在 [channel](/langsmith/managed-deep-agents-channels) 中运行时，其 async subagents 会向同一个 channel thread 回报：

1. 用户在 channel thread 中请求 agent 执行工作，agent 启动 async subagent。
2. 如果 subagent 因[审批](/langsmith/managed-deep-agents-tools#human-in-the-loop)而暂停，Slack 会在该 thread 中显示请求，在那里回答即可恢复 subagent。其他 channels 不会发布该请求；请像处理任何 [interrupt](/langsmith/managed-deep-agents-tools#respond-to-an-interrupt) 一样，在 Studio 中或通过 API 恢复 subagent 的 thread。
3. Subagent 完成后，agent 会获取其结果并在该 thread 中回复：如果它仍在工作，则在当前 run 中回复；如果它处于空闲状态，则在新的 run 中回复。关闭父级通知会阻止启动新的 run。

Managed Deep Agents 不会将 subagent 的回答发布到 channel；由 agent 决定告诉用户什么。

### 评估 agent

`mda eval` 在没有 Agent Server 的情况下运行，因此无法评估声明了 async subagents 的 agent。被评估的 agent 也不会获得异步 `general-purpose` subagent 或异步 task tools。
