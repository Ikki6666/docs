本指南介绍如何使用 `@langchain/langsmith-pi-extension` 扩展，将 [Pi coding agent](https://pi.dev) 会话跟踪到 LangSmith。

完成配置后，每个 Pi 会话都会把 traces 发送到 LangSmith。每条 trace 都包含用户消息、助手响应、工具调用和单个 LLM 调用，因此你可以完整观察 Pi 编码智能体的运行情况。

## 前提条件

在设置跟踪之前，确保你已具备以下条件：

- 安装 [**Pi**](https://pi.dev)。
- 准备一个 [**LangSmith API key**](/langsmith/create-account-api-key)。

## 安装

通过 Pi 安装扩展：

```sh
pi install npm:@langchain/langsmith-pi-extension
```

## 快速开始

默认情况下，跟踪是禁用的。设置以下环境变量以启用跟踪，并连接到你的 LangSmith 账户：

```sh
export TRACE_TO_LANGSMITH=true
export LANGSMITH_PI_API_KEY="<your-langsmith-api-key>"
```

像平常一样 [运行 Pi](https://pi.dev/docs/latest/quickstart)。当会话启动时，扩展会报告 LangSmith tracing 是否已启用。你也可以随时在 Pi 内检查当前的 tracing 状态：

```text
/langsmith-tracing
```

默认情况下，traces 会写入 `pi-coding-agent` LangSmith 项目。

## 配置

配置可以来自环境变量或 JSON 配置文件。值会按以下顺序合并，后面的来源优先级更高：

1. 默认值
1. `~/.pi/langsmith.json`（全局配置）
1. `<current-working-directory>/.pi/langsmith.json`（项目配置）
1. 环境变量

### 环境变量

| Variable | Description |
|---|---|
| `TRACE_TO_LANGSMITH` | 设置为 `true`、`1`、`yes` 或 `on` 时启用 tracing。设置为 `false`、`0`、`no` 或 `off` 时禁用 tracing。 |
| `LANGSMITH_PI_API_KEY` | LangSmith API key。会回退到 `LANGSMITH_API_KEY`。 |
| `LANGSMITH_PI_ENDPOINT` | 用于 self-hosted 或自定义部署的 LangSmith API URL。会回退到 `LANGSMITH_ENDPOINT`。 |
| `LANGSMITH_PI_PROJECT` | LangSmith 项目名称。会回退到 `LANGSMITH_PROJECT`。默认值为 `pi-coding-agent`。 |
| `LANGSMITH_PI_METADATA` | 添加到根 run metadata 的 JSON 对象。会回退到 `LANGSMITH_METADATA`。 |
| `LANGSMITH_PI_RUNS_ENDPOINTS` | 复制 run 目标的 JSON 数组。会回退到 `LANGSMITH_RUNS_ENDPOINTS`。 |

示例：

```sh
export TRACE_TO_LANGSMITH=true
export LANGSMITH_PI_API_KEY="<your-langsmith-api-key>"
export LANGSMITH_PI_PROJECT="pi-coding-agent-dev"
export LANGSMITH_PI_METADATA='{"team":"infra","environment":"local"}'
```

### 配置文件

创建 `~/.pi/langsmith.json` 用于全局设置，或在项目目录中创建 `.pi/langsmith.json` 用于本地覆盖：

```json
{
  "enabled": true,
  "api_key": "<your-langsmith-api-key>",
  "api_url": "https://api.smith.langchain.com",
  "project": "pi-coding-agent",
  "metadata": { "environment": "local" }
}
```

配置文件字段：

| Field | Required | Default | Description |
|---|---|---|---|
| `enabled` | Yes | `false` | 设置为 `true` 可通过配置文件启用 tracing。 |
| `api_key` | No* | — | LangSmith API key。除非通过环境变量或 replicas 提供，否则这是必填项。 |
| `api_url` | No | LangSmith SDK default | LangSmith API URL，通常为 `https://api.smith.langchain.com`。 |
| `project` | No | `pi-coding-agent` | LangSmith 项目名称。 |
| `metadata` | No | — | 合并到根 trace metadata 的对象。 |
| `replicas` | No | — | 额外 LangSmith 目标的数组，用于复制 traces。 |

## Replicas

使用 `replicas` 可将 traces 同时发送到多个 LangSmith 目标。这适合把 traces 同时转发到个人 workspace 和共享团队项目，或者同时转发到 [self-hosted LangSmith](/langsmith/self-hosted) 实例与 [cloud](/langsmith/cloud)。

```json
{
  "enabled": true,
  "api_key": "<primary-api-key>",
  "project": "pi-coding-agent",
  "replicas": [
    {
      "api_key": "<replica-api-key>",
      "api_url": "https://replica-langsmith.example.com",
      "project": "pi-coding-agent-replica",
      "updates": {
        "tags": ["replica"]
      }
    }
  ]
}
```

每个 replica 条目都可以包含一个 `updates` 对象，用于覆盖复制后 runs 的 metadata 或 tags。
