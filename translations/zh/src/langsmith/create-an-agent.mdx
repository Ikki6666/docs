在 LangSmith 中创建 [agent](/langsmith/agents) 会为它分配一个 identifier 以及用于其 traces 的 [environments](/langsmith/agent-environments)。只需创建一次，随后在代码中使用该 identifier 和某个 environment 发送 traces。

如果你的 agent 运行在 LangSmith 之外，请先通过 UI、SDK 或 API 在 LangSmith 中创建它的记录。该记录用于组织它的 traces。你的代码仍然运行在你托管它的地方。诸如 LangChain `create_agent` 之类的框架函数构建的是运行在你代码中的 agent，它们不会创建它在 LangSmith 中的记录。

## 比较四种方式

agent 可以通过四种方式创建，它们在 identifier 的设置方式和 agent 初始拥有的 environments 上有所不同：

| 方式 | 做什么 | Identifier | 创建时的 environments |
| --- | --- | --- | --- |
| [Build 标签页](/langsmith/build-an-agent) | 在 LangSmith 内构建并运行 agent | 为你生成 | 仅 Production |
| [UI](#name-an-agent-traced-from-outside-langsmith) | 在 LangSmith 中输入名称和 ID 创建 agent 记录 | 由你设置 | 全部四个 |
| [SDK 或 API](#create-an-agent-programmatically) | 通过 SDK 调用或 API 请求创建 agent 记录 | 由你设置 | 全部四个 |
| [Deployment](/langsmith/deploy-to-agent-environment) | 将你的 agent 代码部署到 LangSmith | 你传入的 agent ID，或由 deployment 名称推导 | 全部四个 |

并非每个 agent 都能拥有 [deployment](/langsmith/deployment)。部署 agent 代码会在一开始就创建带 deployment 的 agent。通过 SDK 或 API、通过 [**New Agent** 面板](#start-from-the-new-agent-panel)中的 Observability 选项，或通过 **Create a new agent** 对话框创建的 agent 最初没有 deployment，但你之后可以[部署到它](/langsmith/deploy-to-agent-environment)。在 Build 标签页中构建的 agent 不能拥有 deployment，因为它运行在 Studio runtime 上。部署之后，agent 的 Overview 会显示一个 **Deployments** 部分。

通过 Build 标签页创建的 agent 会在第一次有 trace 指向某个 environment 时获得其余的 environments。关于这四个 environment 是什么，请参阅 [Agent environments](/langsmith/agent-environments#environment-names)。

当 LangSmith 通过这些流程构建或部署 agent 时，它会处理注册。请复用该 agent 进行追踪。不要为同一个 deployment 创建单独的外部 agent。

## Identifier 规则

identifier 为 1 到 63 个字符，使用小写字母、数字和连字符。它必须以字母开头、以字母或数字结尾，因此 `support-agent` 和 `billing-v2` 是有效的。其他任何形式都会被拒绝。

这些规则适用于你提供该值的所有地方：**Agent ID** 字段中、SDK 和 API 创建请求中，以及你部署到的 agent ID 中。Build 标签页会代为生成 identifier。没有 agent ID 的 deployment 会从 deployment 名称推导一个，并在该值已被占用时追加后缀，因此部署的 agent 最终的 identifier 可能接近但不等于 deployment 名称。

identifier 在 agent 创建后不能更改。display name 可以。关于哪个值是哪个，请参阅 [Identifiers and display names](/langsmith/agents#identifiers-and-display-names)。

## 从 New Agent 面板开始

四个控件可以打开 **New Agent** 面板：agent 列表上方的 **+ Agent**、列表末尾一张同样标题为 **New Agent** 的创建卡片上的 **+ Create new agent** 和 **Trace existing agent**，以及 agent 切换器中搜索框旁的 **+** 按钮（悬停时显示 **New agent** 提示）。**Trace existing agent** 会在 Observability 选项上打开该面板，另外三个会在其选项网格上打开它。一个 **All options** 按钮可以返回选项网格。

该面板承接四种流程。只有 Observability 会在面板内创建 agent：

- **Builder**（"Build and configure inside LangSmith"）：离开面板进入 **Build** 标签页，在那里提交表单即创建 agent。请参阅 [Build an agent in the UI](/langsmith/build-an-agent)。
- **Managed Deep Agent**（"Build locally and deploy"）：agent 在你部署时创建。请参阅 [Managed Deep Agents](/langsmith/managed-deep-agents-overview)。此方式需要付费 plan。
- **Open Source**（"Build an agent with our open source frameworks"）：使用 [LangChain](/oss/langchain/overview) 构建你的 agent，然后使用下方的 UI 或 API 创建它在 LangSmith 中的记录。
- **Observability**（"Trace an existing agent"）：在面板中为 agent 命名，LangSmith 会创建它并打开其 tracing 页面，该页面包含设置步骤。请参阅 [tracing quickstart](/langsmith/observability-quickstart)。

## 为从 LangSmith 外部 trace 的 agent 命名

在 UI 中创建外部 agent 需要 `projects:create` 权限。要注册它，请在以下两处之一为其命名：

- **New Agent** 面板中的 Observability 选项。
- **Create a new agent** 对话框，在没有选中任何 agent 时，从 Tracing 页面 agent 列表下方的 **+ New agent** 打开。

两者都接受一个 **Agent name**，并在单独的字段中接受一个 **Agent ID**，同时提示该 ID 用于 URLs 和 API 调用，之后不能更改。agent 切换器在搜索框旁也有同样的 **+** 按钮，面向拥有 `projects:create` 权限的用户，无论切换器出现在哪里，它打开的是 **New Agent** 面板而不是对话框。

创建后，配置你的代码[将 traces 发送到该 agent 和 environment](/langsmith/log-traces-to-agent)。对于需要 `project_name` 的集成，请使用[兼容性配置](#use-an-environment-project)。

## 以编程方式创建 agent

agent 创建 API 会在 LangSmith 中创建一个包含全部四个 environments 的 agent 记录。在发送 traces 之前调用一次，而不是每次 agent 运行时都调用。

使用具有 [`projects:create` 权限](/langsmith/organization-workspace-operations#projects)的[个人访问令牌或 service key](/langsmith/create-account-api-key)。tracing key 不能调用 agent 创建 API。创建 agent 后，你的代码可以使用 tracing key 提交 traces。

将 `LANGSMITH_API_KEY` 设置为用于设置的凭据。将 `LANGSMITH_WORKSPACE_ID` 设置为目标 workspace ID，将 `LANGSMITH_ENDPOINT` 设置为你的[区域的 API URL](/langsmith/create-account-api-key#configure-the-sdk)。

<Tabs>
  <Tab title="Python">
    安装 LangSmith v0.14.12 或更高版本：

    ```bash
    pip install -U "langsmith>=0.14.12"
    ```

    创建 agent 并打印其 identifier：

    <CreateAgentPy />
  </Tab>
  <Tab title="REST">
    使用任意语言的 REST API 注册该 agent。包含 `source_type: "EXTERNAL"`：

    ```bash
    curl --fail-with-body --request POST "$LANGSMITH_ENDPOINT/api/v1/agents" \
      --header "x-api-key: $LANGSMITH_API_KEY" \
      --header "x-tenant-id: $LANGSMITH_WORKSPACE_ID" \
      --header "Content-Type: application/json" \
      --data '{"id":"support-agent","name":"Support agent","source_type":"EXTERNAL"}'
    ```
  </Tab>
</Tabs>

`id` 是不可变的 agent identifier。`name` 是它可编辑的 display name。创建响应包含 `environments`，其中每个 environment 都有 `tracer_session_name` 和 `tracer_session_id`。

如果 identifier 已存在，创建操作会返回 `409`。在检查其身份后复用现有 agent，或选择另一个 identifier。将创建操作放在你的设置步骤中。当你的代码需要其配置时，检索现有 agent。

## 为 agent 配置追踪

使用 agent identifier 和 environment 作为追踪目的地：

```bash
export LANGSMITH_TRACING=true
export LANGSMITH_API_KEY="<your-tracing-api-key>"
export LANGSMITH_AGENT_ID="support-agent"
export LANGSMITH_AGENT_ENVIRONMENT="production"
```

使用创建操作返回的 identifier，而不是 display name。从你的代码运行的环境中移除旧版目的地变量（`LANGSMITH_PROJECT`、`LANGCHAIN_PROJECT` 和 `LANGCHAIN_SESSION`）。关于 SDK 版本和基于代码的配置，请参阅[将 traces 记录到 agent](/langsmith/log-traces-to-agent)。

## 配置需要 project name 的集成

一些集成仍然需要 `project_name` 或 `LANGSMITH_PROJECT` 设置。对于这些集成，请使用所选 agent environment 的 `tracer_session_name`。这是 LangSmith 返回的兼容性值，而不是需要另外创建的资源。

使用能够读取其 environments 的凭据检索该 agent。使用 Python SDK：

<AgentEnvironmentProjectPy />

使用 REST 时，使用与创建请求相同的认证头调用 `GET /api/v1/agents/support-agent`。在 `environments` 中选择 `PRODUCTION`、`STAGING`、`DEVELOPMENT` 或 `LOCAL`，并读取其 `tracer_session_name` 或 `tracer_session_id`。

将所选 environment 的 `tracer_session_name` 复制到你的集成的目的地设置中：

```bash
export LANGSMITH_PROJECT="<environment-tracer-session-name>"
```

使用返回的值，而不是从 agent ID 或 display name 推导。例如，某个集成可能将此设置称为 `project_name`、`projectName`、`LANGCHAIN_PROJECT` 或 `Langsmith-Project`。将示例中的每个目的地，包括代码中的覆盖值和 replica 目的地，都替换为目标 workspace 中所选 environment 的 `tracer_session_name`。

如果集成支持 [agent addressing](/langsmith/log-traces-to-agent)，请改为设置 agent ID 和 environment，例如 `LANGSMITH_AGENT_ID` 和 `LANGSMITH_AGENT_ENVIRONMENT`。不要将这些变量与旧版目的地变量混用。

## 排查设置问题

- **创建返回 `403`**：使用在目标 workspace 中具有 `projects:create` 权限的 PAT 或 service key。tracing key 不能调用 agent 创建 API。
- **追踪时报告 agent 缺失**：先创建 agent，然后使用其确切的 identifier 和 environment 重试追踪。
- **创建返回 `409`**：该 identifier 已被占用。已归档的 agent 也会保留其 identifier。
- **traces 出现在错误的位置**：检查 workspace、区域、environment 以及代码中的任何目的地覆盖值。使用 agent identifier，而不是其 display name。
