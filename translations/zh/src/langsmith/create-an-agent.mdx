你可以通过四种方式创建 [agent](/langsmith/agents)。你选择的方式决定了该 agent 如何获得 identifier，以及它最初拥有多少个 [environments](/langsmith/agent-environments)。

请根据 agent 运行的位置选择方式。如果你在 LangSmith 中构建 agent，LangSmith 会在你构建的同时创建该 agent。如果 agent 运行在你自己的机器上，LangSmith 可以在 agent 发送第一条 trace 时创建它。

<AgentBetaNote />

## 比较四种方式

agent 可以通过四种方式创建，它们在 identifier 的设置方式和 agent 初始拥有的 environments 上有所不同：

| 方式 | 适用场景 | Identifier | 创建时的 environments |
| --- | --- | --- | --- |
| [Build 标签页](/langsmith/build-an-agent) | LangSmith 替你运行 agent | 为你生成 | 仅 Production |
| **Create a new agent** 对话框 | 你希望在第一次 run 之前为 agent 命名 | 由你设置 | 全部四个 |
| 向一个不存在的 identifier 发送 [Tracing](/langsmith/log-traces-to-agent) | agent 已经在别处运行 | 你发送的值 | 全部四个 |
| [部署一个项目](/langsmith/deploy-to-agent-environment) | 你从一个项目部署 agent | 你传入的 agent ID，或由 deployment 名称推导 | 全部四个 |

并非每个 agent 都能拥有 [deployment](/langsmith/deployment)。通过部署项目创建的 agent 从一开始就有 deployment。通过 trace、通过 [**New Agent** 面板](#start-from-the-new-agent-panel)中的 Observability 选项，或通过 **Create a new agent** 对话框创建的 agent 最初没有 deployment，但你之后可以[部署到它](/langsmith/deploy-to-agent-environment)。在 UI 中构建的 agent 不能拥有 deployment，因为它运行在 Studio runtime 上。部署之后，agent 的 Overview 会显示一个 **Deployments** 部分。

在 UI 中创建的 agent 会在第一次有 trace 指向某个 environment 时获得其余的 environments。关于这四个 environment 是什么，请参阅 [Agent environments](/langsmith/agent-environments#environment-names)。

## Identifier 规则

identifier 为 1 到 63 个字符，使用小写字母、数字和连字符。它必须以字母开头、以字母或数字结尾，因此 `support-agent` 和 `billing-v2` 是有效的。其他任何形式都会被拒绝。

这些规则适用于你提供该值的所有地方：**Agent ID** 字段中、你 trace 到的 identifier 中，以及你部署到的 agent ID 中。Build 标签页会代为生成 identifier。没有 agent ID 的 deployment 会从 deployment 名称推导一个，并在该值已被占用时追加后缀，因此部署的 agent 最终的 identifier 可能接近但不等于 deployment 名称。

identifier 在 agent 创建后不能更改。display name 可以。关于哪个值是哪个，请参阅 [Identifiers and display names](/langsmith/agents#identifiers-and-display-names)。

## 从 New Agent 面板开始

四个控件可以打开 **New Agent** 面板：agent 列表上方的 **+ Agent**、列表末尾一张同样标题为 **New Agent** 的创建卡片上的 **+ Create new agent** 和 **Trace existing agent**，以及 agent 切换器中搜索框旁的 **+** 按钮（悬停时显示 **New agent** 提示）。**Trace existing agent** 会在 Observability 选项上打开该面板，另外三个会在其选项网格上打开它。一个 **All options** 按钮可以返回选项网格。

该面板承接四种流程。只有 Observability 会在面板内创建 agent：

- **Builder**（"Build and configure inside LangSmith"）：离开面板进入 **Build** 标签页，在那里提交表单即创建 agent。请参阅 [Build an agent in the UI](/langsmith/build-an-agent)。
- **Managed Deep Agent**（"Build locally and deploy"）：agent 在你部署时创建。请参阅 [Managed Deep Agents](/langsmith/managed-deep-agents-overview)。此方式需要付费 plan。
- **Open Source**（"Build an agent with our open source frameworks"）：agent 由第一条 trace 创建。请参阅 [LangChain](/oss/langchain/overview)。
- **Observability**（"Trace an existing agent"）：在面板中为 agent 命名，LangSmith 会创建它并打开其 tracing 页面，该页面包含设置步骤。请参阅 [tracing quickstart](/langsmith/observability-quickstart)。

## 为从 LangSmith 外部 trace 的 agent 命名

要在任何 trace 到达之前创建 agent，可以在以下两处之一为其命名：

- **New Agent** 面板中的 Observability 选项。
- **Create a new agent** 对话框，在没有选中任何 agent 时，从 Tracing 页面 agent 列表下方的 **+ New agent** 打开。

两者都接受一个 **Agent name**，并在单独的字段中接受一个 **Agent ID**，同时提示该 ID 用于 URLs 和 API 调用，之后不能更改。两者都需要创建项目的权限。agent 切换器在搜索框旁也有同样的 **+** 按钮，面向拥有相同权限的用户，无论切换器出现在哪里，它打开的是 **New Agent** 面板而不是对话框。

先创建 agent 是可选的。[向一个不存在的 identifier 发送 trace](/langsmith/log-traces-to-agent#addressing-an-agent-that-does-not-exist) 会按你发送的值创建该 agent，因此对话框用于在第一次 run 之前为 agent 命名。
