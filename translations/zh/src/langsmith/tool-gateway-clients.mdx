每个 [tool kit](/langsmith/tool-gateway-tool-kits) 都是标准的 MCP endpoint。因此，任何 MCP client 都可以调用其工具。client 发送一个 LangSmith API key，[Tool Gateway](/langsmith/tool-gateway) 则为每个 server 附加已存储的凭据。这样一来，client 自身无需持有任何服务 token 或 API key。

## 对 client 的要求

client 必须支持 Streamable HTTP，并允许你设置自定义请求头。该请求头携带 LangSmith API key，它决定每次调用使用谁的凭据：

- **Personal access token**：调用以你的身份运行，使用你[连接](/langsmith/tool-gateway-connect-accounts)的账号。用于你自己的编码助手。
- **Service key 或 agent key**：调用以某个用户、agent 或 profile 的身份运行，具体由额外请求头或 key 本身决定。请参见[以用户和 agent 身份调用](/langsmith/tool-gateway-identity)。

如果使用组织范围的 API key，还需在 `X-Tenant-Id` 请求头中发送你的 workspace ID。

## 查找 kit 的 MCP URL

kit 的 MCP URL 形式为 `<langsmith-api-url>/v1/managed-tools/kits/<kit-id>/mcp`。例如，在 US LangSmith Cloud 上：`https://api.smith.langchain.com/v1/managed-tools/kits/<kit-id>/mcp`。

要复制该 URL，请转到 **Tools** > **Tool kits** 并打开该 kit。kit 面板会显示：

- **MCP URL**，已填入你所在区域的 API URL。
- **Claude Code**、**Managed Deep Agents** 和 **Cursor** 的设置说明，每个片段中已包含该 kit 的 URL。
- **Search mode** 开关，可将 URL 和每个片段切换为 [search 模式](#use-search-mode-for-large-kits)。

若要让 client 获得你能使用的全部工具，请使用 [me kit](/langsmith/tool-gateway-tool-kits#use-the-me-kit)，而不是精选的 kit。其路径为 `/v1/managed-tools/kits/me/mcp`，在以下任何步骤中都可以用它替换 kit URL。

## 将 kit 添加到 client

每个 client 都需要相同的两个值：kit 的 MCP URL 和 LangSmith API key。区别只在于输入位置。请在下方选择你的 client，或参照[其他 MCP client](#other-mcp-clients) 中的模式。

### Claude Code

在项目中运行 `claude mcp add`，并传入 kit 的 URL 以及放在 `X-Api-Key` 请求头中的 API key。本页的命令使用 [quickstart](/langsmith/tool-gateway-quickstart#before-you-begin) 中的环境变量：

```bash
claude mcp add --transport http support-agent \
  "$LANGSMITH_ENDPOINT/v1/managed-tools/kits/<kit-id>/mcp" \
  --header "X-Api-Key: $LANGSMITH_API_KEY"
```

运行 `claude mcp list`，确认该 server 显示为已连接。有关向 Claude Code 添加 MCP server 的更多信息，请参见 [Claude Code MCP 文档](https://code.claude.com/docs/en/mcp)。

Claude Code 会列出 kit 中的每个 tool，包括你尚未连接的 server 上的工具。首次调用这些工具之一时，Claude Code 会显示一个用于连接该 server 的链接。

### Cursor

将该 kit 添加到你的 `mcp.json` 文件，并将 `<langsmith-api-key>` 替换为你的 API key：

```json
{
  "mcpServers": {
    "support-agent": {
      "url": "https://api.smith.langchain.com/v1/managed-tools/kits/<kit-id>/mcp",
      "headers": {
        "X-Api-Key": "<langsmith-api-key>"
      }
    }
  }
}
```

保存 `mcp.json` 后，在 Cursor 中打开 **Settings** > **MCPs** 并点击 **Reload**，以便 Cursor 加载该 kit。

### Managed Deep Agents

[Managed Deep Agents](/langsmith/managed-deep-agents) 项目通过 `"auth": "langsmith"` 将该 kit 声明为一个 MCP server。随后 agent 在每次调用时发送 deployment 的 LangSmith API key 和 workspace。Tool Gateway 使用运行该 agent 的人的凭据；在 agent 拥有的 schedule 中，则使用该 agent 的凭据。

<Note>
将 Tool Gateway 与 Managed Deep Agents 配合使用，要求 Python 和 TypeScript 两个包中的 `managed-deepagents` 版本均为 0.10.5 或更高。
</Note>

在 `tools/mcp.py` 或 `tools/mcp.ts` 中，将该 kit 添加到 `servers` 映射：

<CodeGroup>
```python Python
from managed_deepagents import define_mcp

mcp = define_mcp(
    servers={
        "support-agent": {
            "transport": "http",
            "url": "https://api.smith.langchain.com/v1/managed-tools/kits/<kit-id>/mcp",
            "auth": "langsmith",
        },
    },
)
```

```typescript TypeScript
import { defineMcp } from "managed-deepagents";

export const mcp = defineMcp({
  servers: {
    "support-agent": {
      transport: "http",
      url: "https://api.smith.langchain.com/v1/managed-tools/kits/<kit-id>/mcp",
      auth: "langsmith",
    },
  },
});
```
</CodeGroup>

每个项目只定义一次 `mcp`，并将每个 kit 或 server 作为条目添加到其 `servers` 映射中。要在 Studio 中本地运行 agent，请在环境中将 `LANGSMITH_WORKSPACE_ID` 设为你的 workspace ID，并将 `LANGSMITH_API_KEY` 设为 personal access token。

`"auth": "langsmith"` 不能与 `connection` 组合，也不能与用于选择使用谁的凭据的请求头组合。若要在每次 run 中都使用某个 [profile](/langsmith/tool-gateway-connect-accounts#connect-an-account-for-a-profile)，请改为设置 `"auth": {"type": "langsmith", "profile": "<profile-id>"}`。有关其他 MCP server 选项，请参见 [MCP connectors](/langsmith/managed-deep-agents-mcp-connectors)。

### 其他 MCP client

任何满足[要求](#client-requirements)的 client 都以相同方式工作：向它提供 kit 的 URL 和一个 `X-Api-Key` 请求头。例如，使用 LangChain agent 和 `langchain-mcp-adapters`：

<CodeGroup>
```python Python
import asyncio

from langchain.agents import create_agent
from langchain_mcp_adapters.client import MultiServerMCPClient

client = MultiServerMCPClient(
    {
        "support-agent": {
            "transport": "streamable_http",
            "url": "https://api.smith.langchain.com/v1/managed-tools/kits/<kit-id>/mcp",
            "headers": {
                "X-Api-Key": "<langsmith-api-key>",
                "X-Tenant-Id": "<workspace-id>",
            },
        }
    }
)


async def main():
    tools = await client.get_tools()
    agent = create_agent("anthropic:claude-sonnet-5-5", tools=tools)
    result = await agent.ainvoke({"messages": [{"role": "user", "content": "List my open issues."}]})
    print(result["messages"][-1].content)


asyncio.run(main())
```

```typescript TypeScript
import { MultiServerMCPClient } from "@langchain/mcp-adapters";
import { createAgent } from "langchain";

const client = new MultiServerMCPClient({
  mcpServers: {
    "support-agent": {
      transport: "http",
      url: "https://api.smith.langchain.com/v1/managed-tools/kits/<kit-id>/mcp",
      headers: {
        "X-Api-Key": "<langsmith-api-key>",
        "X-Tenant-Id": "<workspace-id>",
      },
    },
  },
});

const agent = createAgent({
  model: "anthropic:claude-sonnet-5-5",
  tools: await client.getTools(),
});
```
</CodeGroup>

若要将每个 tool 调用嵌套在 agent 的 trace 下，请参见[将 tool 调用嵌套在 agent run 下](/langsmith/tool-gateway-traces#nest-tool-calls-under-your-agent-run)。若要在不使用 client 的情况下发送 MCP 请求，请参见[调用工具](/langsmith/tool-gateway-call-tools)。

## 为大型 kit 使用 search 模式

许多 client 会将 server 列出的每个 tool 都放入模型提示中。包含大量工具的 kit 会用 tool 定义填满提示，从而降低工具选择的准确性。在 search 模式下，kit 改为只列出三个工具，由模型用它们查找并调用所需的工具。

要开启 search 模式，请在 kit 的 URL 后添加 `?mode=search`，或在 kit 面板中开启 **Search mode**：

```txt
https://api.smith.langchain.com/v1/managed-tools/kits/<kit-id>/mcp?mode=search
```

在 shell 命令中，请为 URL 加引号，因为 shell 会将 `?` 视为通配符：

```bash
claude mcp add --transport http support-agent \
  "$LANGSMITH_ENDPOINT/v1/managed-tools/kits/<kit-id>/mcp?mode=search" \
  --header "X-Api-Key: $LANGSMITH_API_KEY"
```

search 模式适用于已保存的 kit 和 me kit，不适用于单个 server 的 endpoint。

该 kit 会列出以下工具：

| Tool | 参数 | 返回 |
|------|-----------|---------|
| `search_tools` | `query`（必填）、`limit`（默认 10，最大 50）、`full_results`（默认 `false`） | 最佳匹配项，每个包含其名称、server、描述，以及调用方是否已连接其 server。当 `full_results` 设为 `true` 时，每个匹配项还会包含其 input schema。 |
| `get_tool` | `name`，来自 `search_tools` | 单个 tool 的完整定义，包括其 input schema。 |
| `call_tool` | `name`，以及与 tool 的 input schema 匹配的 `arguments` | 该 tool 的结果，与直接调用返回的一致。 |

模型通常先调用 `search_tools`，再调用 `get_tool`，然后调用 `call_tool`。要跳过 `get_tool`，模型可以在调用 `search_tools` 时将 `full_results` 设为 `true`。像 Claude Code 这样的 client 无需额外设置即可使用这三个工具。

search 模式只改变 kit 列出的内容：

- **你尚未连接的 server**：其工具仍会出现在搜索结果中，`connected` 设为 `false`，并且仅按名称匹配。调用其中之一会要求你连接，与直接调用相同。
- **直接调用**：按 kit 名称（例如 `linear_list_issues`）调用 tool，在 search 模式下仍然有效。
- **策略**：[策略](/langsmith/tool-gateway-policies)适用于 `call_tool` 所运行的 tool，与直接调用相同。
