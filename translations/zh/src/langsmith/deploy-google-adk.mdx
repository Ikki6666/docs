本指南会介绍如何借助 [`deployments-wrap-sdk`](https://pypi.org/project/deployments-wrap-sdk/) package，将 [Google Agent Development Kit (ADK)](https://github.com/google/adk-python) agent 部署到 [LangSmith Agent Server](/langsmith/agent-server) 上。

`deployments-wrap-sdk` 提供了一个轻量封装，可以把已配置好的 ADK `Runner` 转成兼容 LangGraph 的 graph，因此你无需手写[Functional API](/oss/langgraph/functional-api) glue，就能部署 ADK agents。这个 wrapper 会：

- 将 ADK sessions 对接到 Agent Server 的[checkpoint 持久化](/langsmith/agent-server#persistence)中，因此 session state 能跨重启和跨 runs 恢复。
- 通过 LangGraph 的流式管线转发 ADK token events，因此部分 tokens 会出现在 [`stream_mode="messages"`](/langsmith/streaming) 和 [LangSmith Studio](/langsmith/studio) 中。
- 当设置了 `LANGSMITH_TRACING` 时，自动为 ADK 启用[LangSmith tracing](/langsmith/trace-with-google-adk)。

## 前置条件

- Python 3.11+
- 用于本地开发和部署的 [LangGraph CLI](/langsmith/cli)
- LangSmith API key，参见[创建账户和 API key](https://docs.langchain.com/langsmith/create-account-api-key)
- 如果你使用 Gemini models，还需要 Google AI API key，参见 [Google AI Studio](https://aistudio.google.com/api-keys)

## 安装

安装带 `google-adk` extra 的 package。这个 extra 会拉取 `google-adk` 及 wrapper 所需的其他依赖：

```bash
pip install "deployments-wrap-sdk[google-adk]"
```

<Note>
PyPI 发行包名称是 `deployments-wrap-sdk`，但 Python import 路径是 `saf_sdk`。它们指向同一个 package。
</Note>

## Quickstart

下面这个最小示例会构建一个 agent，它直接返回输入内容，而不需要真实的模型 API key。该 agent 会绕过 LLM 调用，这样你可以先验证 deployment 是否工作正常，再接入真实模型。

创建 `agent.py`：

```python agent.py
from google.adk.agents import Agent
from google.adk.models.llm_response import LlmResponse
from google.adk.runners import Runner
from google.genai.types import Content, Part
from saf_sdk.adk import LangsmithSessionService, wrap


def echo_callback(callback_context, llm_request):
    """Return the user's message instead of calling a real model."""
    user_text = ""
    if callback_context.user_content and callback_context.user_content.parts:
        for part in callback_context.user_content.parts:
            if part.text:
                user_text += part.text
    return LlmResponse(
        content=Content(role="model", parts=[Part(text=f"echo: {user_text}")])
    )


agent = wrap(
    Runner(
        agent=Agent(
            name="echo_agent",
            model="gemini-2.5-flash",
            instruction="Echo the user message.",
            before_model_callback=echo_callback,
        ),
        app_name="adk_echo",
        session_service=LangsmithSessionService(),
    )
)
```

这里有两点是必须的：

1. **将 `LangsmithSessionService()` 作为 runner 的 `session_service` 传入。** 如果你忘了这一步，`wrap()` 会抛出 `TypeError`。Agent Server 需要这个 hook，才能通过自己的 checkpointer 加载和保存 ADK session state。
2. **把封装后的 `agent` 导出为模块级变量。** Agent Server 在提供 graph 服务时会导入这个 symbol。

如果你要部署真实 agent，只需去掉 `before_model_callback`，然后直接配置真实模型。例如，可以设置 `model="gemini-2.5-flash"` 并配置 `GOOGLE_API_KEY` 来使用 Gemini，或通过 ADK 的 LiteLLM adapter（`google.adk.models.lite_llm.LiteLlm`，可通过 `google-adk[extensions]` 获取）来使用 Claude / OpenAI。

## 能力与限制

`wrap()` 将 ADK 运行时的一个已定义子集桥接到 Agent Server。在迁移已有 ADK agent 之前，请先看清这些边界，因为有些 ADK 功能会原样透传，有些则被明确标记为不支持。

### Supported

- **Agent primitives**：`Agent`、`SequentialAgent` 和 `ParallelAgent`，包括通过 `sub_agents` 参数进行的嵌套 sub-agent delegation。
- **Tools**：Python function tools 和 `LongRunningFunctionTool`。
- **Models**：原生 Gemini models，以及 ADK LiteLLM adapter（`google.adk.models.lite_llm.LiteLlm`，可通过 `google-adk[extensions]` 获取）支持的任意模型。只需在 deployment 中配置对应 provider 的 API key。
- **Token streaming**：ADK partial events 会通过 LangGraph 的 async callback manager 转发，因此 token chunks 能到达消费 `stream_mode="messages"` 的客户端以及 Studio 聊天视图。
- **Structured output**：如果 agent 配置了 `output_schema` 和 `output_key`，除了 `messages` 外，它的 typed value 也会暴露在 graph response 中。
- **Session persistence**：`LangsmithSessionService` 会把 ADK session state 保存进 deployment 的 checkpoint store 中。状态能跨重启持久化，并在同一 thread 的下一次 turn 中重新加载。
- **Tracing**：当 `LANGSMITH_TRACING=true` 时，wrapper 会自动调用 `configure_google_adk()`（见[启用 tracing](#enable-tracing)）。
- **Authentication**：如果 Agent Server 启用了[authentication](/langsmith/auth)，则认证用户的 user id 会成为 ADK 的 `user_id`。否则，user id 会被设为 `"anonymous"`。

### Not supported

- **Multimodal input**：wrapper 只会把 `messages[-1].content` 作为单个文本 part 转发。输入中的图片、文件、音频或内联二进制内容不会传给 ADK runner。
- **每轮多个新消息**：只有 `messages` 列表中的最后一项会被视为本轮新用户消息。对话历史是从 ADK session state 中重建，而不是直接从 LangGraph message 列表重建。
- **Bidirectional / live streaming**：wrapper 写死使用 `RunConfig(streaming_mode=StreamingMode.SSE)`。ADK 的 `Runner.run_live()` 和用于音频 / 语音 agents 的双向流式模式不会被调用，因此 live audio 和 voice agents 无法通过 `wrap()` 部署。
- **非文本输出 parts**：只会收集 ADK events 中的 `part.text` 值。agent 产生的图片、音频或文件不会出现在 graph 的 `messages` 输出中。
- **把中间事件作为 messages 暴露**：响应会作为一条聚合后的 `AIMessage` 输出，其中包含拼接后的完整文本。Tool calls、tool results 和中间 sub-agent turns 不会在 graph 的 `messages` 字段中拆分展示。请改为在 [LangSmith traces](/langsmith/observability) 中查看它们。
- **替代 ADK session services**：`runner.session_service` 必须是 `LangsmithSessionService`。ADK 的 `InMemorySessionService`、`DatabaseSessionService` 和 `VertexAiSessionService` 会被拒绝，并抛出 `TypeError`，因为 session state 必须由 LangGraph checkpoint 承载。
- **原生 LangGraph interrupts**：wrapper 不暴露 LangGraph 的 `interrupt` 或 `Command(resume=...)` 机制。基于 `LongRunningFunctionTool` 构建的人类介入流程，会遵循 ADK 自己的模式：tool 返回诸如 `pending_approval` 之类的状态，agent 做出响应，然后在后续 turn 中继续完成 pending call。

## 项目结构

一个可部署的项目需要三个文件：

```
my-adk-agent/
├── agent.py              # exports the wrapped agent
├── langgraph.json        # Agent Server config
└── pyproject.toml        # Python dependencies
```

[`langgraph.json`](/langsmith/application-structure#configuration-file-concepts) 用来指向 Agent Server 要导入的 symbol：

```json langgraph.json
{
  "$schema": "https://langgra.ph/schema.json",
  "dependencies": ["."],
  "graphs": {
    "adk_echo": "./agent.py:agent"
  },
  "env": ".env"
}
```

`pyproject.toml` 中声明依赖：

```toml pyproject.toml
[project]
name = "my-adk-agent"
version = "0.0.1"
requires-python = ">=3.11"
dependencies = [
    "deployments-wrap-sdk[google-adk]>=0.0.1",
]
```

## 安装依赖

```bash
pip install -e .
```

## 本地运行

使用 [LangGraph CLI](/langsmith/cli) 启动本地 Agent Server：

```bash
langgraph dev
```

它会把 agent 服务启动在 `http://127.0.0.1:2024`，并打开 [LangSmith Studio](/langsmith/studio)，你可以直接在里面与 agent 对话。你也可以通过 `curl` 直接发请求：

```bash
# Create a thread
THREAD=$(curl -s -X POST http://127.0.0.1:2024/threads \
  -H "Content-Type: application/json" -d '{}' | python -c "import sys, json; print(json.load(sys.stdin)['thread_id'])")

# Run the agent and wait for the final response
curl -s -X POST "http://127.0.0.1:2024/threads/$THREAD/runs/wait" \
  -H "Content-Type: application/json" \
  -d '{
    "assistant_id": "adk_echo",
    "input": {"messages": [{"type": "human", "content": "Hello"}]}
  }'
```

## 部署到 LangSmith

当 agent 能在本地正常运行后，就可以通过 `langgraph deploy` 把它部署到 LangSmith：

```bash
langgraph deploy --name my-adk-agent
```

有关环境配置、deployment 类型和 revision 管理，请参阅[部署到 cloud](/langsmith/deploy-to-cloud)。对于 self-hosted 场景，请参阅[self-hosted deployments](/langsmith/self-hosted)。

## 启用 tracing

当 LangSmith tracing 启用时，`wrap()` 会自动调用 `langsmith.integrations.google_adk.configure_google_adk()`，因此你只需要在 deployment 中设置以下环境变量：

```bash .env
LANGSMITH_API_KEY=your-langsmith-api-key
LANGSMITH_TRACING=true
LANGSMITH_PROJECT=my-adk-agent     # optional
GOOGLE_API_KEY=your-google-api-key
```

[Traces](/langsmith/observability) 会在 [LangSmith UI](https://smith.langchain.com) 中展示 agent invocations、tool calls 和 LLM interactions。关于 tracing 集成本身的更多内容，请参阅[追踪 Google ADK applications](/langsmith/trace-with-google-adk)。

## API reference

### `wrap(runner)`

对已配置好的 `google.adk.runners.Runner` 进行包装，并返回一个 LangGraph `Pregel` graph。这个 graph 可以从你的模块中导出，并由 Agent Server 提供服务。

| Argument | Type | Description |
|---|---|---|
| `runner` | `google.adk.runners.Runner` | 一个已配置好的 ADK Runner。其中的 `session_service` **必须**是 `LangsmithSessionService`。 |

**Returns:** 返回一个 `Pregel` graph，其名称为 `runner.app_name`。

**Raises:** 如果 `runner.session_service` 不是 `LangsmithSessionService`，则抛出 `TypeError`。

如果 `runner.agent` 定义了 `output_key`，那么该 key 对应的值也会暴露在 graph output 中，除了 `messages` 之外一并返回。这正是 ADK 结构化输出 agent（`output_schema=...`、`output_key=...`）能在 Studio 和 `/runs/wait` 响应中正常工作的原因。

### `LangsmithSessionService`

这是一个基于 Agent Server checkpoint store 实现的 `google.adk.sessions.BaseSessionService`。wrapper 会自动管理 session 生命周期：它会在 thread 的第一轮创建 session，在后续 turns 中从 checkpoint 加载 session，并在 run 完成后把更新后的 session 再次写回。

请为每个 `Runner` 使用一个新的实例：

```python
session_service = LangsmithSessionService()
```

通常你不需要直接调用它的方法，`wrap()` 会通过 ADK 的正常 session lifecycle 自动驱动它。

### `ADKInput`

wrapped agent 默认使用的输入 schema。

| Field | Type | Description |
|---|---|---|
| `messages` | `list[AnyMessage]` | （必填）对话消息；wrapper 会把 `messages[-1].content` 作为本轮新的用户消息发给 ADK runner。 |
| `state_delta` | `dict[str, Any] \| None` | （可选）会透传给 `runner.run_async(state_delta=...)`，用于在本轮运行中修改 ADK session state。 |

### `ADKOutput`

wrapped agent 默认使用的输出 schema。

| Field | Type | Description |
|---|---|---|
| `messages` | `list[AnyMessage]` | agent 的响应消息，会通过 LangGraph 的 `add_messages` reducer 追加到 thread 中。 |

把 `messages` 作为 typed field 暴露（而不是普通 `dict`）正是 Studio 能识别该 graph 为 chat-compatible，并启用 chat mode toggle 的原因。

## 工作原理

当一次 run 到来时：

1. wrapped graph 会从 run config 中读取 `thread_id`，并把它作为 ADK 的 `session_id`。如果启用了[authentication](/langsmith/auth)，认证用户的 id 会被用作 ADK 的 `user_id`；否则 user id 为 `"anonymous"`。
2. wrapper 会先从 LangGraph checkpoint 中把前一次 session（如果存在）加载进 `LangsmithSessionService`，然后让 runner 处理最新消息。
3. runner 发出 ADK events。wrapper 会将部分 token events 通过 LangGraph 的 async callback manager 转发出去，使其能够通过 `stream_mode="messages"` 流式返回，并同时收集最终文本，组成响应消息。
4. 当 run 完成时，wrapper 会通过 `entrypoint.final(save=...)` 序列化 ADK session，并把它保存回 checkpoint。这样，同一个 thread 的下一次 run 就能从该状态继续。

这意味着 ADK 自身的 session / state 语义能够端到端保留，同时 deployment 也能获得标准的 Agent Server 特性：持久化 runs、流式输出、多 thread 持久化，以及 tracing。
