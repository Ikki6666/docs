模型访问策略定义哪些 providers 和模型被允许通过 [LLM Gateway](/langsmith/llm-gateway)。gateway 会阻止策略未包含的 providers 或模型的请求，返回 `403` 响应，并在响应正文中指明拦截该请求的策略：

```json
{"error":{"code":null,"message":"request blocked by gateway policies: <POLICY_NAME>","param":null,"type":"permission_error"}}
```

如果没有适用的策略，所有 providers 和模型都可用。

## 策略维度

模型访问策略被限定在一个 subject 层级：

| 范围 | 适用于 |
| --- | --- |
| **Organization** | 组织中的所有用户和工作区 |
| **Workspace** | 一个工作区中的所有用户 |
| **User** | 单个用户 |
| **API key** | 单个 API key |

### 策略覆盖

策略覆盖（policy overrides）让你可以给更具体的 subject 授予与更宽泛默认不同的访问权限。一个常见场景是：让某个 API key 访问组织中其他成员不可用的某个高级模型。

当请求在多个层级匹配到策略时，只有最具体的层级适用，顺序为 API key、user、workspace、organization。更具体的策略会完全替换更宽泛的策略。例如，如果组织策略允许 OpenAI 和 Anthropic，而某个 API key 策略只允许 OpenAI 和 Gemini，那么使用该 key 的请求只能访问 OpenAI 和 Gemini。

如果同一层级有多条策略匹配，模型必须被所有策略允许才可以访问。错误信息只会指明拒绝该模型的那条策略。

## 允许的 providers 和模型

模型访问策略列出一个或多个 providers，每个 provider 带有一种访问模式：

- **All models**：该 provider 提供的每个模型都被允许。
- **Selected models**：只允许你指定的模型。至少需要一个模型。

在 **Selected models** 下，gateway 还会阻止其 model 无法读取的请求，例如没有 `model` 字段、`model` 不是字符串，或 `model` 字段出现两次的请求。
### 允许已保存的模型配置

通过 `custom/<name>` 模型 ID 或 fallback 链调用已保存的[模型配置](/langsmith/llm-gateway-model-configurations)的请求会被拦截，除非策略中列出了 **Model configurations** provider。该 provider 使用同样的两种访问模式，但 **Selected** 接受的是配置名称（精确匹配），而不是模型 ID。名称会在调用 API key 的工作区中解析，因此组织级策略上的一条条目适用于每个工作区自己的配置。

## 创建模型访问策略

<Warning>
创建和管理策略需要 `organization:gateway:manage` 权限。Organization Admins 和 Organization Operators 默认拥有该权限。关于每个组织角色可以执行的操作，请参见[组织角色](/langsmith/rbac#organization-roles)。
</Warning>

1. 前往 **LLM Gateway** 并选择 **Model Access** 标签页。
1. 点击 **Create model access**。
1. 在 **Applies to** 下选择范围（organization、workspace、user 或 API key）。
1. 在 **Allowed providers and models** 下，开启每个要允许的 provider 并选择其访问模式。providers 默认处于关闭状态，因此任何未开启的 provider 都会被阻止。
1. 点击 **Create model access**。

策略会立即生效。
