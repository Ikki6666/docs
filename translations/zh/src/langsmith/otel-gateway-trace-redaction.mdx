使用 [LangChain](/langsmith/trace-with-langchain)、[LangGraph](/langsmith/trace-with-langgraph) 或 [Deep Agents](/langsmith/trace-deep-agents) 构建的 agent 支持基于 [OpenTelemetry 的 tracing](/langsmith/trace-with-opentelemetry)。你可以不把 traces 直接发往 LangSmith，而是先把它们路由到你自己控制的 OpenTelemetry collector，在那里应用脱敏规则，移除敏感字段，然后再把清洗后的 traces 转发到 LangSmith。

Traces 会通过 OTLP/HTTP 从 agent 流向 collector。collector 上会运行一个 transform processor，在把清洗后的 spans 转发到 LangSmith API 之前，对敏感的 span attributes，例如 prompt 输入和模型 completion，执行脱敏。

你可以通过两种方式把 traces 发送到 collector：[通过 LangChain、LangGraph 或 Deep Agents 集成](#使用-langchain-或-langgraph-tracing)，或[直接配置 OpenTelemetry SDK](#直接使用-opentelemetry-sdk-tracing)。

## 前置条件

两种方式都需要以下环境变量。把 `OTEL_EXPORTER_OTLP_ENDPOINT` 设置为你的 collector 地址：

```bash
LANGSMITH_OTEL_ENABLED="true"
LANGSMITH_TRACING="true"
LANGSMITH_OTEL_ONLY="true"
LANGSMITH_AGENT_ID="<your-agent-id>"
LANGSMITH_AGENT_ENVIRONMENT="production"
OTEL_EXPORTER_OTLP_ENDPOINT="http://<my-otel-collector-endpoint>:4318"
```

`LANGSMITH_AGENT_ID` 和 `LANGSMITH_AGENT_ENVIRONMENT` 用于指定这些 traces 所属的 agent 和环境。更多信息，请参阅[将 traces 记录到 agent](/langsmith/log-traces-to-agent)。

## 配置 collector

这两种方式都要求你在 agent 与 LangSmith 之间运行一个 OpenTelemetry collector，作为中间层。下面这份配置会在 `4318` 端口上启用一个 OTLP receiver，配置一个 transform processor，用来对 `gen_ai.prompt` 和 `gen_ai.completion` 这两个 span attributes 做脱敏，并用 exporter 把清洗后的 traces 转发给 LangSmith API：

```yaml
receivers:
  otlp:
    protocols:
      http:
        endpoint: 0.0.0.0:4318


processors:
  transform/redact:
    error_mode: ignore
    trace_statements:
      - context: span
        statements:
          - replace_pattern(attributes["gen_ai.completion"], "[\\s\\S]*", "[REDACTED]")
          - replace_pattern(attributes["gen_ai.prompt"], "[\\s\\S]*", "[REDACTED]")

exporters:
  otlphttp/langsmith:
    traces_endpoint: "https://api.smith.langchain.com/otel/v1/traces"
    headers:
      x-api-key: "${env:LANGSMITH_API_KEY}"
      Langsmith-Agent-Id: "${env:LANGSMITH_AGENT_ID}"
      Langsmith-Agent-Environment: "${env:LANGSMITH_AGENT_ENVIRONMENT}"
      x-Tenant-Id: "${env:LANGSMITH_TENANT_ID}" # Required if API key is not scoped to a specific workspace


service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [transform/redact]
      exporters: [otlphttp/langsmith]
```

collector 会从自身所在的环境读取 `LANGSMITH_API_KEY`、`LANGSMITH_AGENT_ID` 和 `LANGSMITH_AGENT_ENVIRONMENT`，而不是从你的应用环境读取。请在运行 collector 的环境中设置这些变量；如果你的 API key 未限定到特定 workspace，还需要设置 `LANGSMITH_TENANT_ID`。

### 将 traces 发送到 agent

决定哪些 agent 和环境接收 traces 的是 collector，而不是你的应用。collector 会向 LangSmith 发送自己的请求头，默认不会转发你的应用发送的请求头。前面配置中的 `otlphttp/langsmith` exporter 会同时设置两个 agent 请求头：

- **`Langsmith-Agent-Id`**：agent 的标识符。必须由 1 到 63 个小写字母、数字或连字符组成，以字母开头，并以字母或数字结尾。
- **`Langsmith-Agent-Environment`**：traces 所属的环境。取值为 `local`、`development`、`staging` 或 `production`。

两个 agent 请求头必须同时发送，或都不发送。如果只设置其中一个，或将其中任意一个与 `Langsmith-Project` 一起设置，LangSmith 会返回 `400` 错误拒绝请求。

这些请求头会应用于该 exporter 发送的每个 span。若要将 traces 发送到多个 agent 或环境，请为每个 agent 或环境定义一个 exporter，并将每个 agent 的 spans 路由到对应的 exporter。span attributes（包括 `gen_ai.agent.name`）不会把 traces 发送到某个 agent。要详细了解如何将 traces 发送到 agent，请参阅[将 traces 记录到 agent](/langsmith/log-traces-to-agent)。

## 使用 LangChain 或 LangGraph tracing

如果你的 agent 已经在使用 [LangChain](/langsmith/trace-with-langchain)、[LangGraph](/langsmith/trace-with-langgraph) 或 [Deep Agents](/langsmith/trace-deep-agents)，请使用这种方式。tracing 集成会基于环境变量自动处理 span 创建，因此不需要额外编写 instrumentation 代码：

```python
from langchain.agents import create_agent
from langchain.tools import tool
from langchain_openai import ChatOpenAI


@tool
def tell_joke(topic: str) -> str:
   llm = ChatOpenAI()
   response = llm.invoke(f"Tell me a short, funny joke about {topic}.")
   return response.content


agent = create_agent(
   model=ChatOpenAI(),
   tools=[tell_joke],
   system_prompt="When the user asks for jokes, use the tell_joke tool for each topic.",
)


topics = ["programming", "python", "kubernetes", "machine learning"]


result = agent.invoke(
   {"messages": [{"role": "user", "content": f"Tell me jokes about these topics: {', '.join(topics)}"}]}
)


print(result["messages"][-1].content)
```

## 直接使用 OpenTelemetry SDK tracing

如果你需要对 tracer provider 和 exporter 做编程式控制，例如指定运行哪些 span processor，或指定 exporter 把 spans 发送到哪里，请使用这种方式。你需要在代码中显式配置 provider，而不是只依赖环境变量。决定由哪个 agent 接收 traces 的是 collector 的 exporter，而不是你的代码：

```python
import os

from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from opentelemetry import trace
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor


otlp_endpoint = os.environ["OTEL_EXPORTER_OTLP_ENDPOINT"]


provider = TracerProvider()
provider.add_span_processor(
   BatchSpanProcessor(
       OTLPSpanExporter(
           endpoint=otlp_endpoint+"/v1/traces",
       )
   )
)
trace.set_tracer_provider(provider)


chain = ChatPromptTemplate.from_template("Tell me a joke about {topic}") | ChatOpenAI()


for topic in ["programming", "python", "databases", "kubernetes", "machine learning"]:
   print(f"Asking about {topic}...")
   result = chain.invoke({"topic": topic})
   print(f"  {result.content[:100]}\n")


provider.force_flush()
provider.shutdown()
```

<Note>
如果你更希望在不经过 collector 的前提下对敏感数据脱敏，请参阅[阻止在 traces 中记录敏感数据](/langsmith/mask-inputs-outputs)。
</Note>
