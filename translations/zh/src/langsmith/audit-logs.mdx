<Note>
审计日志适用于 [**Enterprise** 方案](/langsmith/pricing-plans)。如果你有升级到 Enterprise 的需求，请[联系销售团队](https://www.langchain.com/contact-sales)。
</Note>

LangSmith 审计日志为组织内发生的管理和配置操作提供了一份防篡改记录。它可以帮助你回答如下问题：

- **谁**删除了某个 API key、dataset 或 deployment？
- **何时**邀请了新成员、修改了角色，或更新了 examples？
- **什么**计费、SSO 或数据保留配置被修改了？
- **哪些** datasets、tracing projects 或 prompt webhooks 被变更了？

审计日志适用于安全审查、合规要求，以及一般性的运维可见性场景。

## 前置条件

- 你的组织必须处于 [**Enterprise** 方案](/langsmith/pricing-plans)。
- 你必须拥有 **Organization Admin** 或 **Organization Operator** 角色（即拥有 [`organization:manage` 权限](/langsmith/rbac#organization-admin)），才能查看审计日志。

## 记录内容

审计日志会记录组织设置、成员关系、凭证、工作区和其他资源的变更。每条事件都包含时间戳、操作人、操作名称、受影响资源，以及操作是否成功。完整的操作名称列表请参见[跟踪操作参考](#tracked-operations-reference)。

## 保留期

审计日志最多保留 **400 天**。超过 400 天的事件可能会被自动移除。

## 为自托管部署启用审计日志

运行 Helm chart **0.12.33** 或更高版本的 [self-hosted](/langsmith/self-hosted) LangSmith 实例支持审计日志。各个操作的覆盖范围是逐步扩展的，关于每个操作最早在哪个 chart 版本可用，请参见[自托管版本可用性](#self-hosted-version-availability)。

升级后，可通过以下任一方式启用审计日志：

- **为单个组织启用：** 对你的 LangSmith PostgreSQL 数据库执行如下语句，并把 `<organization_id>` 替换成从 UI 组织设置页复制出来的 ID：

    ```sql
    UPDATE organizations SET config = config || '{"can_use_audit_logs": true}' WHERE id = '<organization_id>' AND NOT is_personal;
    ```

- **为所有组织启用：** 在 `values.yaml` 的 `commonEnv` 中加入如下环境变量：

    ```yaml
    DEFAULT_ORG_FEATURE_CAN_USE_AUDIT_LOGS: "true"
    ```

    <Note>
    该环境变量对 personal organizations 不生效。
    </Note>

关于自托管版本发布的更多信息，请参见[自托管更新日志](/langsmith/self-hosted-changelog)。

## 通过 API 查询审计日志

使用 `GET /api/v1/audit-logs` 端点（[API reference](/langsmith/smith-api/audit-logs/get-audit-logs)）获取审计日志事件。返回结果遵循 [OCSF API Activity](https://schema.ocsf.io/1.7.0/classes/api_activity) schema。

### 请求示例

```bash
curl -G \
  'https://api.smith.langchain.com/api/v1/audit-logs' \
  -H 'accept: application/json' \
  -H 'X-API-Key: lsv2_sk_...' \
  -H 'X-Organization-Id: abc123...' \
  -d 'limit=2' \
  --data-urlencode 'start_time=2026-01-01T18:35:16.232Z' \
  --data-urlencode 'end_time=2026-01-13T18:35:16.232Z' \
  --data-urlencode 'operations=create_api_key' \
  --data-urlencode 'operations=delete_api_key'
```

## 响应格式

审计日志事件以 [OCSF v1.7.0 API Activity（Class UID 6003）](https://schema.ocsf.io/1.7.0/classes/api_activity) 格式返回。关键字段包括：

| 字段 | 说明 |
| --- | --- |
| `actor.user.uid` | 执行该操作的用户 UUID。 |
| `actor.user.credential_uid` | 用于认证该请求的 API key、PAT 或 service key 的 UUID。如果用户是通过 session（例如 UI）认证，则为 `null`。 |
| `api.operation` | LangSmith 操作名称，例如 `create_api_key`、`delete_workspace`。完整值请参见[跟踪操作参考](#tracked-operations-reference)。 |
| `status` | `Success`、`Failure` 或 `Unknown`。 |
| `resources` | 本次操作影响到的资源 UUID 列表，例如被更新的角色或被创建的工作区。 |
| `metadata.uid` | 该审计日志事件的唯一标识。 |
| `unmapped.original_audit_log` | LangSmith 原生日志记录的完整内容，包括 `organization_id` 和 `workspace_id`。 |

## 转发到外部系统

如果你想把审计日志事件转发到外部 SIEM 或日志平台，可以实现一个定时函数，每小时拉取前一个小时的事件。例如，配合 [AWS Lambda + EventBridge Scheduler](https://docs.aws.amazon.com/lambda/latest/dg/with-eventbridge-scheduler.html) 使用时，失败任务会落入 dead-letter queue，以便你知道哪些时间窗需要重试。

## FAQ

<AccordionGroup>
<Accordion title="谁可以查看审计日志？">
拥有 [**Organization Admin**](/langsmith/rbac#organization-admin) 或 [**Organization Operator**](/langsmith/rbac#organization-operator) 角色的用户可以访问审计日志，这两个角色都授予 `organization:manage` 权限。工作区级角色不提供审计日志访问权限。
</Accordion>

<Accordion title="Plus 或 Developer 方案可以使用审计日志吗？">
不可以。审计日志是 Enterprise 功能。方案细节请参见[定价](https://www.langchain.com/pricing-langsmith)。
</Accordion>

<Accordion title="有用于查看审计日志的 UI 吗？">
目前还没有。审计日志当前通过[API](#query-audit-logs-via-api)提供。
</Accordion>

<Accordion title="读取类操作会被记录吗？">
当前审计日志主要聚焦写操作。未来可能会增加对更多读取操作的支持。
</Accordion>

<Accordion title="未来会跟踪更多操作吗？">

<Accordion title="可以用 OCSF 之外的格式获取审计日志吗？">
API 仅以 OCSF 格式返回事件。如果你需要不同的数据形状，可使用每条事件中的 `unmapped.original_audit_log` 字段，其中包含原始 LangSmith 审计日志记录。
</Accordion>

<Accordion title="什么是 OCSF？">
[Open Cybersecurity Schema Framework (OCSF)](https://schema.ocsf.io/) 是一个面向安全事件数据的开放标准。LangSmith 返回的审计日志事件遵循 OCSF v1.7.0 API Activity（Class 6003）对象格式。
</Accordion>
