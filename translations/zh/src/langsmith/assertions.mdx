Assertions 可以把用自然语言表达的标准转化为自动化检查。它们是简短、自由形式的断言，用来描述一个正确答案应该包含什么或不应该包含什么。[LangSmith Engine](/langsmith/engine-issues) 会针对反复出现的生产问题背后的 traces 提出 assertions。你在[单 run annotation queue](/langsmith/annotation-queues#single-run-annotation-queues)中审核并编辑这些断言，LangSmith 会把它们保存在一个[dataset example](/langsmith/example-data-format)上。之后，任何[离线 evaluator](/langsmith/evaluation-concepts#offline-evaluations)都可以检查应用的新输出是否满足每条断言。

当某次 run 的输出有误时，你可以用 assertions 描述一个正确答案，而不必手动编写一个。

<Note>
**Assertions** 部分只会出现在 LangSmith Engine 提议作为离线 examples 的 run 项上。它不会出现在其他 runs、[thread](/langsmith/observability-concepts#threads) 项或 [pairwise queues](/langsmith/annotation-queues#pairwise-annotation-queues) 中。Assertions 仅在 LangSmith UI 中可用。
</Note>

## 审核提出的 assertions

要审核并保存 Engine 提出的 assertions：

1. 在某个 Engine issue 上，点击 **Engine proposed N examples**，然后点击 **Edit in annotation queue**。详情请参阅[添加离线 examples](/langsmith/engine-issues#add-offline-examples)。
1. 在 annotation queue 中，找到侧边面板中的 **Assertions** 部分。Engine 会在其中填入它提出的 assertions，并且该 run 会显示 **Proposed by Engine** 横幅。
1. 编辑每条 assertion 的 **key**（对该断言的简短概括，例如 `must_cite_source` 或 `must_not_invent_url`）及其用于描述该断言的一句话 **comment**。

    key 是自由格式的。`must_` 和 `must_not_` 前缀只是一种命名约定。LangSmith 不会对它们做特殊处理。

1. （可选）点击 **+ Add** 添加一条 assertion，或点击某一行上的删除图标将其移除。

    当该 run 有 assertions 时，LangSmith 会用 assertions 的只读预览替换该 run 的 outputs，并将其标注为 reference outputs。这个预览内容会被保存到 dataset 中。该 run 的实际输出不会被保存，因为 assertions 描述的是一个正确答案应该包含什么，而不是这次 run 实际产生了什么。

    要在保存 example 之前编辑该 run 的 **Inputs**（例如优化 prompt），请为该 queue 启用 [**Classic Trace View**](/langsmith/annotation-queues#data-formatting)。只要还有 assertions 存在，outputs 就会一直锁定在 assertion 预览上。

1. 点击侧边面板底部的 **Add to Dataset & Next**（快捷键：macOS 上为 <kbd>⌘ Enter</kbd>，其他系统为 <kbd>Ctrl Enter</kbd>）。LangSmith 会将当前 run 添加到该 queue 的[默认 dataset](/langsmith/annotation-queues#basic-details)中；如果没有配置默认 dataset，则会提示你先选一个。随后队列会自动切换到下一个 run。

保存后的 example 的 `outputs` 字段会以 JSON 形式存储。例如：

```json
{
  "assertions": [
    {
      "key": "must_cite_source",
      "comment": "The response cites the source URL it is drawing from."
    },
    {
      "key": "must_not_invent_url",
      "comment": "The response does not include URLs that do not appear in the inputs."
    }
  ]
}
```

Example 的 `inputs` 字段会保存该 run 的 inputs，或者在你做过修改时保存修改后的版本。完整结构请参阅[Example data format](/langsmith/example-data-format)。

## 基于 assertions 做评估

编写一个[离线 evaluator](/langsmith/evaluation-concepts#offline-evaluations)，从 `reference_outputs["assertions"]` 读取保存好的 assertions，并为每条 assertion 返回一条 feedback 分数。最小形态如下：

```python
def grade_against_assertions(outputs: dict, reference_outputs: dict) -> list[dict]:
    """Return one feedback score per assertion."""
    feedback = []
    for assertion in reference_outputs["assertions"]:
        # Replace with your scoring logic: LLM judge, regex, schema check, and so on.
        score = ...
        feedback.append({"key": assertion["key"], "score": score})
    return feedback
```

如何为每条断言打分完全由你决定。常见的有三种模式，而且可以在同一个 evaluator 中组合使用：

- **[LLM-as-a-judge](/langsmith/llm-as-judge)**：针对每条 assertion，把应用输出和 assertion 的 `comment` 一起喂给模型，并让它返回一个分数。适用于主观性较强、难以通过机械方式验证的断言。
- **[基于代码的检查](/langsmith/code-evaluator-ui)**：针对每条 assertion，依据其 `key` 执行确定性的检查，例如正则匹配、schema 校验或子串存在性判断。适用于具有明确、机械化答案的断言。
- **[部分得分](/langsmith/multiple-scores)**：返回数值分数（例如 0.0 到 1.0 之间），而不是布尔值，从而按尺度打分，并对满足部分条件但未满足全部条件的输出给予“部分得分”。
