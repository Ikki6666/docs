`mda dev` 会编译 Managed Deep Agents 项目，并在本地 Agent Server 上运行它。它会打开 [LangSmith Studio](/langsmith/studio)，让你在部署之前与 agent 交互并观察其行为。

<ManagedDeepAgentsPublicBetaNote />

## 启动本地 Studio

安装项目依赖，并将模型 provider 的凭据添加到 `.env`。

:::python
Python 项目还需要 [`uv`](https://docs.astral.sh/uv/)。
:::

在项目根目录下运行：

:::python
```bash
uv run mda dev
```
:::

:::js
<CodeGroup>
    ```bash npm
    npx mda dev
    ```

    ```bash pnpm
    pnpm exec mda dev
    ```

    ```bash bun
    bunx mda dev
    ```
</CodeGroup>
:::

CLI 会打印本地服务器和 Studio 的 URL，并在你的浏览器中打开 Studio。在 Studio 中发送消息，以检查模型响应、tool 调用、state 和 interrupts。

修改项目文件后，请停止并重新运行 `mda dev`，以重新编译项目。

## `mda dev` 做了什么

`mda dev` 会：

1. 校验项目并将其编译到 `.mda/build`。
2. 将项目的 `.env` 复制到本地 build 中，并在需要时添加仅限本地使用的 identity 配置。
3. 为 instructions、skills 和 memory 创建本地 [Context Hub](/langsmith/managed-deep-agents-context-hub) mock。
4. 启动对应语言的 LangGraph development server。
5. 在 Studio 中打开该 agent。

本地开发不会创建或更新任何托管的 deployment。

## 配置本地服务器

| Flag | 用途 |
| --- | --- |
| `--port PORT` | 设置本地服务器端口。 |
| `--hostname HOSTNAME` | 设置服务器监听的 hostname。 |
| `--no-browser` | 启动服务器时不自动打开 Studio。 |
| `--no-reload` | 禁用 LangGraph development server 的热重载。 |

完整的命令细节请参阅 [`mda dev` CLI reference](/langsmith/managed-deep-agents-cli#develop-locally)。

## 理解本地行为

`mda dev` 使用以下本地默认值来简化测试：

- 如果 agent 使用 identity，Studio 会自动提供一个本地测试用户。
- 如果配置的 sandbox 不可用，agent 会改用一个临时本地文件夹。CLI 会打印该文件夹的路径。
- [Schedules](/langsmith/managed-deep-agents-schedules) 不会运行。`mda dev` 会在启动时列出每个 schedule，但不会预置它，因此本地不会有任何调度 run 触发。

这些默认值与已部署的 agent 不同。在生产环境使用 agent 之前，请先在 development deployment 中测试 identity 和 sandbox 行为。
