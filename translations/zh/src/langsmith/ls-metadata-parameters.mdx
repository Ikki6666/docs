当你使用 LangSmith 为 LLM 调用做 tracing 时，通常会希望[追踪成本](/langsmith/cost-tracking)、比较模型配置，以及分析不同提供商之间的性能表现。LangSmith 的原生集成，比如 [LangChain](/langsmith/trace-with-langchain) 或 [OpenAI](/langsmith/trace-openai) / [Anthropic](/langsmith/trace-anthropic) 包装器，会自动处理这些信息；但对于自定义模型包装器和自托管模型，则需要一种标准化方式来提供这些信息。LangSmith 为此使用 `ls_` metadata 参数。

这些 metadata 参数都带有 `ls_` 前缀，你可以通过标准的 `metadata` 字段传递模型配置和标识信息。设置后，LangSmith 就能自动计算成本、在 UI 中展示模型信息，并支持对 traces 进行[过滤](/langsmith/filter-traces-in-application)和分析。

你可以使用 `ls_` metadata 参数来：

- **为自定义或自托管模型启用自动成本追踪**，通过标明 provider 和 model name。
- **记录模型配置**，例如 temperature、max tokens 等，用于实验对比。
- **按 provider 或配置项过滤和分析 traces**。
- **为自定义 agent instrumentation 定制 Messages 视图的渲染效果**。
- **标记中断错误**，让 LangSmith 将 interrupted runs 与其他错误区分开来。
- **提升调试能力**，准确记录每次 run 使用的模型设置。

## 基本用法示例

最常见的用法是为自定义模型包装器启用成本追踪。为此，你需要提供两项关键信息：provider 名称（`ls_provider`）和模型名称（`ls_model_name`）。LangSmith 会将两者组合起来，与自己的定价数据库进行匹配。

<CodeGroup>

```python Python
from langsmith import traceable

@traceable(
    run_type="llm",
    metadata={
        "ls_provider": "my_provider",
        "ls_model_name": "my_custom_model"
    }
)
def my_custom_llm(prompt: str):
    return call_custom_api(prompt)
```

```typescript TypeScript
import { traceable } from "langsmith/traceable";

const myCustomLlm = traceable(
  async (prompt: string) => {
    return callCustomApi(prompt);
  },
  {
    run_type: "llm",
    metadata: {
      ls_provider: "my_provider",
      ls_model_name: "my_custom_model"
    }
  }
);
```

这套最小配置会告诉 LangSmith 你在使用哪个模型。如果该模型已存在于定价数据库中，或者你已经[配置了自定义定价](/langsmith/cost-tracking#llm-calls-automatically-track-costs-based-on-token-counts)，LangSmith 就能自动计算成本。

如果你希望进行更完整的追踪，还可以添加更多配置参数。这在[运行实验](/langsmith/evaluation-quickstart)或比较不同模型设置时尤其有用：

<CodeGroup>

```python Python
@traceable(
    run_type="llm",
    metadata={
        "ls_provider": "openai",
        "ls_model_name": "gpt-5.5",
        "ls_temperature": 0.7,
        "ls_max_tokens": 4096,
        "ls_stop": ["END"],
        "ls_invocation_params": {
            "top_p": 0.9,
            "frequency_penalty": 0.5
        }
    }
)
def my_configured_llm(messages: list):
    return call_llm(messages)
```

```typescript TypeScript
const myConfiguredLlm = traceable(
  async (messages: Array<any>) => {
    return callLlm(messages);

      ls_max_tokens: 4096,
      ls_stop: ["END"],
      ls_invocation_params: {
        top_p: 0.9,
        frequency_penalty: 0.5
      }
    }
  }
);
```

## 全部参数

### 用户可配置参数

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| [`ls_provider`](#ls_provider) | `string` | Yes* | 用于成本追踪的 LLM provider 名称 |
| [`ls_model_name`](#ls_model_name) | `string` | Yes* | 用于成本追踪的模型标识符 |
| [`ls_temperature`](#ls_temperature) | `number` | No | 使用的 temperature 参数 |
| [`ls_max_tokens`](#ls_max_tokens) | `number` | No | 使用的最大 token 数参数 |
| [`ls_stop`](#ls_stop) | `string[]` | No | 使用的 stop sequences |
| [`ls_invocation_params`](#ls_invocation_params) | `object` | No | 附加调用参数 |
| [`ls_agent_type`](#ls_agent_type) | `string` | No | 控制 agent runs 在 Messages 视图中的展示方式：`"root"`、`"subagent"` 或 `"middleware"` |
| [`ls_message_view_exclude`](#ls_message_view_exclude) | `boolean` | No | 在 Messages 视图中隐藏该 run |
| [`ls_is_error_interrupt`](#ls_is_error_interrupt) | `boolean` | No | 当设为 `true` 时，将 errored run 标记为 interrupted |

\* `ls_provider` 和 `ls_model_name` 必须一起提供，才能启用成本追踪

### 系统生成参数

| Parameter | Type | Description |
|-----------|------|-------------|
| [`ls_run_depth`](#ls_run_depth) | `integer` | trace 树中的深度（0=root、1=child 等），自动计算 |
| [`ls_method`](#ls_method) | `string` | 使用的 tracing 方法（例如 `"traceable"`），由 SDK 设置 |

### 实验参数

| Parameter | Type | Description |
|-----------|------|-------------|
| [`ls_example_*`](#ls_example_) | `any` | 实验期间添加的、带 `ls_example_` 前缀的 example metadata |
| [`ls_experiment_id`](#ls_experiment_id) | `string` (UUID) | 实验的唯一标识符，实验期间自动添加 |

## 参数详情

### `ls_provider`

- **Type:** `string`
- **Required:** Yes（需与 [`ls_model_name`](#ls_model_name) 一起提供）

**作用：**
标识 LLM provider。与 `ls_model_name` 配合使用后，LangSmith 会通过匹配 [LangSmith 的模型定价数据库](https://smith.langchain.com/settings/workspaces/models) 来自动计算成本。

**常见取值：**
- `"openai"`
- `"anthropic"`
- `"azure"`
- `"bedrock"`
- `"google_vertexai"`
- `"google_genai"`
- `"fireworks"`
- `"mistral"`
- `"groq"`
- 或任意自定义字符串

**适用场景：**
当你想为自定义模型包装器或自托管模型启用[自动成本追踪](/langsmith/cost-tracking)时。

**示例：**
```python
@traceable(
    run_type="llm",
    metadata={
        "ls_provider": "openai",
        "ls_model_name": "gpt-5.5"
    }
)
def my_llm_call(prompt: str):
    return call_api(prompt)
```

**关系：**
- **需要** [`ls_model_name`](#ls_model_name) 才能完成成本追踪。
- 会结合 token usage 数据一起计算成本。

### `ls_model_name`

- **Type:** `string`
- **Required:** Yes（需与 `ls_provider` 一起提供）

**作用：**
标识具体模型。与 `ls_provider` 一起使用时，可匹配定价数据库并自动计算成本。

**常见取值：**
- OpenAI: `"gpt-5.5"`、`"gpt-5.4-mini"`、`"gpt-3.5-turbo"`
- Anthropic: `"claude-3-5-sonnet-20241022"`、`"claude-3-opus-20240229"`
- Custom: 任意模型标识符

**适用场景：**
当你希望在 [UI](https://smith.langchain.com) 中识别模型，并启用自动[成本追踪](/langsmith/cost-tracking)时。

**示例：**
```python
@traceable(
    run_type="llm",
    metadata={
        "ls_provider": "anthropic",
        "ls_model_name": "claude-3-5-sonnet-20241022"
    }
)
def my_claude_call(messages: list):
    return call_claude(messages)
```

**关系：**
- **需要** [`ls_provider`](#ls_provider) 才能完成成本追踪。
- 会结合 token usage 数据一起计算成本。

### `ls_temperature`

- **Type:** `number`（nullable）
- **Required:** No

**作用：**
记录所使用的 temperature 设置。它只用于记录，不会影响 LangSmith 的行为。

**适用场景：**
当你希望为实验或调试记录模型配置时。

**示例：**
```python
metadata={
    "ls_provider": "openai",
    "ls_model_name": "gpt-5.5",
    "ls_temperature": 0.7
}
```

**关系：**
- 独立存在，仅用于追踪。
- 可与其他配置参数配合，用于实验对比。

### `ls_max_tokens`

- **Type:** `number`（nullable）
- **Required:** No

**作用：**
记录所使用的最大 token 数设置。它只用于记录，不会影响 LangSmith 的行为。

**适用场景：**
当你希望为实验或调试记录模型配置时。

**示例：**
```python
metadata={
    "ls_provider": "openai",
    "ls_model_name": "gpt-5.5",
    "ls_max_tokens": 4096
}
```

**关系：**
- 独立存在，仅用于追踪。
- 与实际 token usage 配合时，可用于成本分析。

### `ls_stop`

- **Type:** `string[]`（nullable）
- **Required:** No

**作用：**
记录所使用的 stop sequences。它只用于记录，不会影响 LangSmith 的行为。

**适用场景：**
当你希望为实验或调试记录模型配置时。

**示例：**
```python
metadata={
    "ls_provider": "openai",
    "ls_model_name": "gpt-5.5",
    "ls_stop": ["END", "STOP", "\n\n"]
}
```

**关系：**
- 独立存在，仅用于追踪。

### `ls_invocation_params`

- **Type:** `object`（任意键值对）
- **Required:** No

**作用：**
存储无法放进特定 `ls_` 参数中的其他模型参数，也可以包含 provider 特有的配置。

**常见参数：**
`top_p`、`frequency_penalty`、`presence_penalty`、`top_k`、`seed`，或任意自定义参数

**适用场景：**
当你需要记录标准参数之外的额外配置时。

**示例：**
```python
metadata={
    "ls_provider": "openai",
    "ls_model_name": "gpt-5.5",
    "ls_invocation_params": {
        "top_p": 0.9,
        "frequency_penalty": 0.5,
        "presence_penalty": 0.3,
        "seed": 12345
    }
}
```

**关系：**
- 独立存在，用于保存任意配置。

### `ls_agent_type`

- **Type:** `"root" | "subagent" | "middleware"`
- **Required:** No

**作用：**
控制自定义 agent 风格 runs 中的消息如何显示在 [Messages 视图](/langsmith/view-traces#messages-view) 中。

新版 LangSmith SDK 的 tracing 包装器集成在需要时会自动设置这个 metadata。对于自定义 instrumentation，你需要在代表 agent 或 middleware 步骤的 run 上设置这个 key。

**可选值：**
- `"root"`：该 run 的消息会显示在主 Messages 视图中。
- `"subagent"`：该 run 的消息会显示在侧边线程中，与主对话分离。
- `"middleware"`：该 run 的消息会在 Messages 视图中隐藏。

**适用场景：**
当你在构建自定义 agent instrumentation，并希望 Messages 视图区分 root agent、subagent 和 middleware 时。

更多信息请参见 [Customize the Messages view](/langsmith/view-traces#customize-the-messages-view)。

**关系：**
- 与模型标识和成本追踪 metadata 独立。
- 它补充了 trace 的父子结构，用于标识某个 run 在 agent trace 中承担的角色。

### `ls_message_view_exclude`

- **Type:** `boolean`（presence-based）
- **Required:** No

**作用：**
在 [Messages 视图](/langsmith/view-traces#messages-view) 中隐藏该 run。被排除的 run 仍会出现在常规 trace 视图、runs explorer 和 metrics 中。

过滤逻辑检查的是 **key 是否存在**，而不是真值。即使 `{LS_MESSAGE_VIEW_EXCLUDE: False}` 也仍然会隐藏该 run。若要包含该 run，请完全省略这个 key。

**导入常量：**
这个 key 以 `LS_MESSAGE_VIEW_EXCLUDE` 常量的形式从 `langsmith`（Python 和 JS）导出，其值为字符串 `"ls_message_view_exclude"`。推荐使用该常量以避免拼写错误，不过直接写字符串也可以。

**适用场景：**
当某些 LLM 子 span 并不属于对话轮次，比如分类调用、embedding 查询、安全过滤或路由/guardrail 决策，而你仍希望它们在 LangSmith 的其他位置可见，但不想让它们干扰对话转录时。

**示例：**
```python
from langsmith import LS_MESSAGE_VIEW_EXCLUDE, traceable

@traceable(run_type="llm", metadata={LS_MESSAGE_VIEW_EXCLUDE: True})
def classify_intent(query: str) -> str:
    return llm.predict(f"Classify: {query}")
```

如需查看更多 Python 和 JS 场景下的代码示例（`@traceable`、`trace`、`wrap_openai`、`RunnableConfig`、`wrapAISDK`、`RunTree.createChild`），请参见 [Exclude runs from the Messages view](/langsmith/messages-view-integrations#exclude-runs-from-the-messages-view)。

**关系：**
- 与模型标识和成本追踪 metadata 独立。
- 它补充了 [`ls_agent_type`](#ls_agent_type)；后者是按角色路由消息，而不是彻底隐藏 run。

### `ls_is_error_interrupt`

- **Type:** `boolean`
- **Required:** No

**作用：**
当某个带错误的 run 设置为 `true` 时，会将其状态标记为 interrupted，而不是 error。

**适用场景：**
当你的 instrumentation 能识别某个错误实际上代表了中断，例如用户中断或 human-in-the-loop 中断，并且你希望 LangSmith 将其与其他错误区分展示时。

**示例：**
```python
metadata={
    "ls_is_error_interrupt": True
}
```

**关系：**
- 只会影响带有 error 的 runs。
- 与模型标识和成本追踪 metadata 独立。

### `ls_run_depth`

- **Type:** `integer`
- **Set by:** LangSmith backend（自动）
- **Cannot be overridden**

**作用：**
表示 trace 树中的深度：
- `0` = Root run（顶层）
- `1` = 直接子级
- `2` = 孙级
- 依此类推

**使用时机：**
在 trace 写入时自动计算。常用于过滤（例如“只看 root runs”）和 UI 展示。

**示例查询：**
```
metadata_key = 'ls_run_depth' AND metadata_value = 0
```

**关系：**
- 由 trace 的父子结构决定。
- 不能手动设置。

### `ls_method`

- **Type:** `string`
- **Set by:** SDK（自动）

**作用：**
标识是由哪个 SDK 方法创建了该 trace（常见值为 `@traceable` 装饰器对应的 `"traceable"`）。

**使用时机：**
由 tracing SDK 自动设置，通常用于调试和分析。

**关系：**
- 由 SDK 根据 trace 的创建方式设置。
- 不能手动设置。

### `ls_example_*`

- **Type:** 任意（取决于 example metadata）
- **Pattern:** `ls_example_{original_key}`
- **Set by:** LangSmith experiments system（自动）

**作用：**
在[基于数据集运行实验](/langsmith/evaluation-quickstart)时，example 上的 metadata 会自动加上 `ls_example_` 前缀并写入 trace。

**特殊参数：**
- `ls_example_dataset_split`：数据集 split，例如 `"train"`、`"test"`、`"validation"`

**使用时机：**
用于数据集实验期间，方便按样本特征进行过滤和分组。

**示例：**
如果某个 example 的 metadata 是 `{"category": "technical", "difficulty": "hard"}`，那么 trace 会得到：
```json
{
  "metadata": {
    "ls_example_category": "technical",
    "ls_example_difficulty": "hard",
    "ls_example_dataset_split": "test"
  }
}
```

**关系：**
- 自动从 example metadata 派生。
- 不能在 trace 上手动设置。

### `ls_experiment_id`

- **Type:** `string`（UUID）
- **Set by:** LangSmith experiments system（自动）

**作用：**
表示一次实验运行的唯一标识符。

**使用时机：**
在[对数据集运行实验/评估](/langsmith/evaluation-quickstart)时自动添加，用于将同一次实验的所有 runs 归组。

**关系：**
- 用于将 runs 关联到特定实验。
- 不能手动设置。

## 参数之间的关系

### 成本追踪依赖项

要让 LangSmith 自动计算成本，需要多个参数协同工作，要求如下：

**核心要求：** [`ls_provider`](#ls_provider) + [`ls_model_name`](#ls_model_name)
- 两者都应存在，才能自动计算成本。
- 如果缺少 [`ls_model_name`](#ls_model_name)，系统会回退到 [`ls_invocation_params`](#ls_invocation_params) 中查找模型名。
- [`ls_provider`](#ls_provider) 必须能匹配[定价数据库](https://smith.langchain.com/settings/workspaces/models)中的 provider，或者你已经配置了自定义定价。

**附加要求：**
- run 必须带有 `run_type="llm"`，或者启用了[任意 run 的成本追踪](/langsmith/cost-tracking#other-runs-send-costs)。
- trace 中必须包含[token usage 数据](/langsmith/log-llm-trace#provide-token-and-cost-information)（`prompt_tokens`、`completion_tokens`）。
- 模型必须存在于定价数据库中，或已[配置自定义定价](/langsmith/cost-tracking#llm-calls-automatically-track-costs-based-on-token-counts)。

**回退行为：**
如果 metadata 中没有 [`ls_model_name`](#ls_model_name)，系统会在 [`ls_invocation_params`](#ls_invocation_params) 中查找类似 `"model"` 的模型标识，再决定是否放弃成本追踪。

### 配置追踪参数组

这些参数用于记录模型设置，但不会影响 LangSmith 的核心功能：

**可选，且彼此独立：** [`ls_temperature`](#ls_temperature)、[`ls_max_tokens`](#ls_max_tokens)、[`ls_stop`](#ls_stop)
- 它们仅用于记录和展示。
- 不会影响 LangSmith 的行为，也不会直接影响成本计算。
- 适合用于实验对比和调试。

### 中断渲染

当某个 run 的错误应被展示为 interrupted 而非 error 时，请将 [`ls_is_error_interrupt`](#ls_is_error_interrupt) 设为 `true`。这个参数只会影响带有 error 的 runs。

### Invocation params 的特殊情况

`ls_invocation_params` 既是一个记录字段，也承担回退机制的作用：

**[`ls_invocation_params`](#ls_invocation_params)**：部分独立，同时承担回退角色
- 主要用于记录任意配置参数。
- 当缺少 [`ls_model_name`](#ls_model_name) 时，**可以作为成本追踪的回退来源**。
- 当 [`ls_model_name`](#ls_model_name) 已存在时，它本身不会直接影响成本计算。

### 系统参数

这些参数由 LangSmith 自动生成，不能手动设置：

**用户不可设置：** [`ls_run_depth`](#ls_run_depth)、[`ls_method`](#ls_method)、[`ls_example_*`](#ls_example_)、[`ls_experiment_id`](#ls_experiment_id)
- 由系统自动设置。
- 用于过滤、分析和系统级追踪。

## 按 metadata 参数过滤 traces

一旦你在 traces 中加入了 `ls_` metadata 参数，就可以通过 [API](/langsmith/smith-api/run/query-runs) 以编程方式过滤和搜索，也可以在 [LangSmith UI](https://smith.langchain.com) 中交互式使用这些参数。这样可以按模型、provider、配置项或 trace 深度缩小范围。

### 使用 API

在 Python 中使用 [`Client`](https://docs.smith.langchain.com/reference/python/client/langsmith.client.Client) 类及其 [`list_runs()`](https://docs.smith.langchain.com/reference/python/client/langsmith.client.Client#langsmith.client.Client.list_runs) 方法，在 TypeScript 中使用 [`listRuns()`](https://docs.smith.langchain.com/reference/js/classes/client.Client#listruns) 方法，根据 metadata 值查询 traces。[过滤语法](/langsmith/trace-query-syntax)支持等值判断、比较运算和逻辑运算。

<CodeGroup>

```python Python
from langsmith import Client

client = Client()

# Filter runs by provider
runs = client.list_runs(
    project_name="my-app",
    filter='metadata_key = "ls_provider" AND metadata_value = "openai"'
)

# Filter by specific model
runs = client.list_runs(
    project_name="my-app",
    filter='metadata_key = "ls_model_name" AND metadata_value = "gpt-5.5"'
)

# Filter root runs only (top-level traces)
runs = client.list_runs(
    project_name="my-app",
    filter='metadata_key = "ls_run_depth" AND metadata_value = 0'
)

# Filter by temperature threshold
runs = client.list_runs(
```

```typescript TypeScript
import { Client } from "langsmith";

const client = new Client();

// Filter runs by provider
const runsByProvider: any[] = [];
for await (const run of client.listRuns({
  projectName: "my-app",
  filter: 'metadata_key = "ls_provider" AND metadata_value = "openai"'
})) {
  runsByProvider.push(run);
}

// Filter by specific model
const runsByModel: any[] = [];
for await (const run of client.listRuns({
  projectName: "my-app",
  filter: 'metadata_key = "ls_model_name" AND metadata_value = "gpt-5.5"'
})) {
  runsByModel.push(run);
}

// Filter root runs only (top-level traces)
const rootRuns: any[] = [];
for await (const run of client.listRuns({
  projectName: "my-app",
  filter: 'metadata_key = "ls_run_depth" AND metadata_value = 0'
})) {
  rootRuns.push(run);
}

// Filter by temperature threshold
const highTempRuns: any[] = [];
for await (const run of client.listRuns({
  projectName: "my-app",
  filter: 'metadata_key = "ls_temperature" AND metadata_value > 0.5'
})) {
  highTempRuns.push(run);
}
```

这些示例展示了几种常见过滤模式：
- **按 provider 或 model 过滤**，分析特定模型的使用模式或成本。
- **按 run depth 过滤**，只获取 root traces（depth 0）或特定层级的子 runs。
- **按配置项过滤**，比较不同 temperature、max tokens 或其他设置下的实验结果。
