TypeSafe-compatible endpoint 是一个保存下来的 [model configuration](/langsmith/model-configurations)。它将 decision model evaluator 的请求发送到任何实现 [TypeSafe System One API](https://docs.typesafe.ai) 的服务器。使用 TypeSafe-compatible endpoint，你可以通过其他提供商（例如 OpenRouter）调用 TypeSafe 模型，或调用你自己托管的 decision model。对于实现 OpenAI API 的模型，请参阅[连接 OpenAI 兼容的 model provider/proxy](/langsmith/custom-openai-compliant-model)。

TypeSafe-compatible endpoints 可用于 [decision model evaluators](/langsmith/decision-model-evaluator)。要直接从 TypeSafe 使用 Jev，你不需要兼容的 endpoint。

## 配置

TypeSafe-compatible endpoint 有三个设置：

- **Model**：服务器期望的模型 ID。默认为 `jev-latest`。
- **API Key Name**：存储服务器 API key 的 workspace secret 的名称。默认为 `TYPESAFE_API_KEY`。
- **Base URL**：服务器 System One API 的根路径。请参阅 [Base URL 格式](#base-url-格式)。

## 在 evaluator 中使用该 endpoint

只有在将该 endpoint 保存为 model configuration 之后，evaluator 才能使用 TypeSafe-compatible endpoint。

在 evaluator 中使用 TypeSafe-compatible endpoint：

1. 将服务器的 API key 添加为 workspace secret。进入 **Settings > Integrations > Provider secrets**，点击 **+ Secret**，然后选择 **Custom** 以输入你自己的 secret 名称。要使用默认名称，请改为选择 **TypeSafe**。
1. 在 evaluator 中，在 **Prompt & Model** 下，打开 **Model Configuration**。
1. 对于 **Provider**，选择 **TypeSafe Compatible Endpoint**。它会显示在 **Other** 下。
1. 输入 **Model**、**API Key Name** 和 **Base URL**。
1. 点击 **Save as preset** 并为该配置命名。
1. 选择已保存的配置作为 evaluator 的模型。

当 evaluator 运行时，它会使用你输入在 **API Key Name** 中的 secret 所存储的 API key 调用该 endpoint。接下来，按照[如何定义 decision model evaluator](/langsmith/decision-model-evaluator) 中所述，添加问题并保存 evaluator。

## Base URL 格式

**Base URL** 应指向服务器 System One API 的根路径。LangSmith 会自动追加 `/v1/systemone`。不要在 Base URL 中包含它。

### 示例 base URLs

| Provider | Model | Example Base URL |
|----------|-------|------------------|
| [TypeSafe](https://docs.typesafe.ai) | `jev-latest` | `https://api.typesafe.ai` |
| [OpenRouter](https://openrouter.ai) | `~typesafe/jev-latest` | `https://openrouter.ai/api` |
| Self-hosted（远程） | 你的模型 ID | `https://my-model-server.example.com` |
