Goals 和 rubrics 可以帮助 Deep Agents Code 检查自己的工作是否满足你关心的标准。目标适合需要 agent 先帮助定义验收标准的任务；rubric 则适合你已经知道要按哪些标准来评审的场景。

## 选择 goal 还是 rubric

当你只有一个可衡量的目标，并希望 Deep Agents Code 在开始前先起草验收标准时，请使用 **goal**。goal 有一个生命周期：一旦你接受，它就会跨轮次保持激活，直到你暂停它、agent 将其标记为 completed 或 blocked，或者你清除它。你也可以在不重启工作的情况下修改一个激活的 goal。

当你已经知道想让 agent 按哪些标准打分时，请使用 **rubric**。rubric 可以只作用于下一轮，也可以持续应用到未来的所有轮次。

常见模式：

- **一个目标，由 agent 起草标准**：使用 `/goal <objective>`。
- **对每一轮都生效的持久标准**：使用 `/rubric set <criteria>`。
- **存储在文件中的标准**：使用 `/rubric file <path>`。
- **单轮质量门禁**：使用 `/rubric next <criteria>`。

## 使用 goal

当你知道自己想要什么结果，但希望 Deep Agents Code 在开始前先提出验收标准时，请使用 `/goal`。Goals 适合开放式工作：agent 会把目标转化为清晰的完成定义，然后反复迭代，直到满足这些标准。

```text
/goal add OAuth refresh handling
```

Deep Agents Code 会在开始任务前先起草验收标准供你审阅。

在内联审阅中，你可以接受该提案、编辑标准、要求再次修订，或者取消它。你接受这些标准后，goal 会在多个回合中保持激活，直到它被暂停、完成、标记为 blocked，或者被清除。

这种方式让你可以在多个回合中推进一个更大的目标：

```text
/goal migrate auth callbacks to the new API
start with the OAuth callback
now update the tests
check the docs too
```

输入框上方的 goal 面板会显示当前目标及其是否处于 active、paused、blocked 或 completed 状态。使用 `/goal show` 查看当前 goal，使用 `/goal clear` 删除它。

### 修改、暂停和恢复 goal

在不取消当前任务、不重放工作的情况下，对一个进行中的 goal 进行引导：

- `/goal amend <feedback>` 会提出对目标和标准的协调更新。修改会经过同样的内联审阅（接受、编辑、修订或取消）后才最终确认。
- `/goal pause` 会保存 goal，但不让它驱动工作或评分，因此中间穿插的 prompt 可以在没有它的情况下运行。`/goal resume` 会重新激活已保存的 goal，并从现有对话继续。

```text
/goal amend remove JSON export, add streaming CSV support, keep the CSV tests
/goal pause
/goal resume
```

### 完成和评分

每一轮后续对话都会按 goal 的验收标准进行评分，直到工作完成。

- 当一个 goal 的完成被批准时，Deep Agents Code 会清除该 goal

<AccordionGroup>
    <Accordion title="Goal 命令参考">
        - `/goal <objective>`：从一个自然语言目标起草验收标准，并在工作开始前审阅它们。
        - `/goal amend <feedback>`：提出对目标和标准的协调更新，供审阅。
        - `/goal pause`：保存 goal，但不让它驱动工作或评分。
        - `/goal resume`：重新激活一个已暂停的 goal，并从现有对话继续。
        - `/goal show`：查看当前 goal、它的状态和标准。
        - `/goal clear`：移除激活的 goal。
        - `/goal model [provider:model|clear]`：设置或清除为该 goal 评分的模型。
        - `/goal max-iterations <N|clear>`：设置或清除该 goal 的最大评分迭代次数。
    </Accordion>
</AccordionGroup>

## 使用 rubric

当你已经知道验收标准，并希望它们成为 agent 工作质量门禁时，请使用 `/rubric`。

```text
/rubric set tests pass; no unrelated files changed; help text is updated
/rubric next only change the auth callback; do not refactor unrelated code
/rubric file acceptance.md
```

sticky rubric 会应用到后续轮次，直到被清除。next-turn rubric 只会作用于下一次提交的任务。

<AccordionGroup>
    <Accordion title="Rubric 命令参考">
        - `/rubric show`：查看当前 rubric。
        - `/rubric clear`：移除当前 rubric。
        - `/rubric model <provider:model>`：设置用于评审 rubric 结果的模型。
    </Accordion>

    <Accordion title="在非交互模式下使用 rubrics">
        非交互式运行无法暂停进行 goal 审阅。对于已经知道标准的任务，请使用 `--rubric`：

        ```bash
        dcode -n "implement OAuth refresh handling" --rubric "tests pass; no unrelated files changed"
        dcode -n "implement OAuth refresh handling" --rubric @acceptance.md
        ```

        你也可以设置 grader model 和最大评审迭代次数：

        ```bash
        dcode -n "implement OAuth refresh handling" \
          --rubric "tests pass; no unrelated files changed" \
          --rubric-model openai:gpt-5.5 \
          --rubric-max-iterations 3
        ```
    </Accordion>
</AccordionGroup>
