Deep Agents Code (`dcode`) 是一个基于 [Deep Agents SDK](/oss/deepagents/quickstart) 构建的开源编码 agent。
它可以与任何大型语言模型协作，并支持在会话中途切换 provider 或 model。
持久化 memory 会把上下文带到不同对话中，可自定义的 skills 会塑造它的行为，而审批控制会在代码执行前做把关。

## 快速开始

<Steps>

    <Step title="安装并启动" icon="terminal">
        ```bash
        curl -LsSf https://langch.in/dcode | bash
        ```
        {/* ![Deep Agents Code](/oss/images/deepagents/deepagents-cli.png) */}
        {/* TODO: maybe add back when updating to current */}

    </Step>

    <Step title="添加 provider 凭据" icon="key">
        Deep Agents Code 可以与任何支持 tool calling 的 LLM 配合使用。OpenAI、Anthropic 和 Google 都开箱可用。

        使用 `/auth` 命令连接某个 provider。完整列表和凭据详情见 [Providers](/oss/deepagents/code/providers)。

        <Note>
            Web search 使用 [Tavily](https://tavily.com)。可以通过 `/auth` 添加 key，或者设置 `TAVILY_API_KEY`。详见 [启用 web search](/oss/deepagents/code/configuration#enable-web-search-with-tavily)。
        </Note>
    </Step>

    <Step title="选择模型（可选）" icon="cpu">
        在会话中运行 `/model` 打开交互式切换器，或者启动时带上 `--model`：

        ```bash
        dcode --model anthropic:claude-opus-4-8
        dcode --model openai:gpt-5.5
        dcode --model fireworks:accounts/fireworks/models/deepseek-v4-pro
        dcode --model baseten:moonshotai/Kimi-K2.7-Code
        ```

        完整 provider 列表、open weights 选项和凭据详情见 [Model providers](/oss/deepagents/code/providers)。
    </Step>

    <Step title="给 agent 一个任务" icon="message">
        ```txt
        Create a Python script that prints "Hello, World!"
        ```

        agent 会解释你的请求，并在修改文件前先提出带 diffs 的变更供你批准。必要时，它可以运行 shell commands 来测试代码、检查文档，或搜索最新信息。
    </Step>

    <Step title="启用 tracing（可选）" icon="chart-dots">
        要把 agent 操作、tool call 和决策记录到 LangSmith，请把以下内容添加到 `~/.deepagents/.env`，或者把变量导出到 shell 中：

        ```bash title="~/.deepagents/.env"
        LANGSMITH_TRACING=true
        LANGSMITH_API_KEY=lsv2_...
        LANGSMITH_PROJECT=optional-project-name  # 指定项目名，或默认使用 "deepagents-code"
        ```

        更多细节和用法见 [Trace with LangSmith](#trace-with-langsmith)。
    </Step>
</Steps>

<Note>
    Deep Agents Code 在 Windows 上没有官方支持。Windows 用户可以尝试在 [Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/en-us/windows/wsl/install) 中运行它。
</Note>

## 能力

Deep Agents Code 具有以下内置能力：

* <Icon icon="file" size={16} /> **文件操作** - 读、写、编辑和删除磁盘上的文件。
* <Icon icon="terminal" size={16} /> **Shell 执行** - 执行命令来运行测试、构建项目、管理依赖，以及与版本控制交互。
* <Icon icon="cloud" size={16} /> **[Remote sandboxes](/oss/deepagents/code/remote-sandboxes)** - 在远程运行 agent tools，而不是在本机上运行。
* <Icon icon="search" size={16} /> **Web search** - 搜索最新信息和文档。需要 [Tavily API key](/oss/deepagents/code/configuration#enable-web-search-with-tavily)。
* <Icon icon="list-check" size={16} /> **任务规划和跟踪** - 把复杂任务拆成离散步骤并跟踪进度。
* <Icon icon="target-arrow" size={16} /> **[Goals and rubrics](/oss/deepagents/code/goals-and-rubrics)** - 定义可衡量的目标或评分标准，让 agent 检查工作是否完成。
* <Icon icon="users" size={16} /> **[Subagents](/oss/deepagents/code/subagents)** - 把工作委派给任务专用 subagents。
* <Icon icon="brain" size={16} /> **[Memory storage and retrieval](/oss/deepagents/code/memory-and-skills#memory)** - 跨 session 存储和检索信息，让 agent 记住项目约定和学到的模式。
* <Icon icon="arrows-minimize" size={16} /> **Context compaction & offloading** - 总结较旧的对话消息，并把原始内容卸载到存储中。
* <Icon icon="user" size={16} /> **Human-in-the-loop** - 对敏感工具操作要求人工批准。
* <Icon icon="puzzle" size={16} /> **[Skills](/oss/deepagents/code/memory-and-skills#skills)** - 用自定义专长和指令扩展 agent 能力。
* <Icon icon="plug" size={16} /> **[MCP tools](/oss/deepagents/code/mcp-tools)** - 从 [Model Context Protocol](https://modelcontextprotocol.io/) servers 加载外部工具。
* <Icon icon="chart-dots" size={16} /> **[Tracing](/oss/deepagents/code/overview#trace-with-langsmith)** - 在 LangSmith 中对 agent 操作进行 tracing，便于可观测性和调试。

<Accordion title="内置工具完整列表">
    ## 内置工具

    agent 自带以下默认可用的内置工具，无需额外配置：

    | Tool | Description | Human-in-the-Loop |
    |------|-------------|-------------------|
    | `ls` | 列出文件和目录 | - |
    | `read_file` | 读取文件内容；对于图片、音频、视频和 PDF 会返回多模态 block | - |
    | `write_file` | 创建或覆盖文件 | Required<sup>1</sup> |
    | `edit_file` | 对已有文件进行定点编辑 | Required<sup>1</sup> |
    | `delete` | 删除文件，或递归删除目录及其内容 | Required<sup>1</sup> |
    | `glob` | 查找匹配 pattern 的文件 | - |
    | `grep` | 在文件中搜索文本 pattern | - |
    | `execute` | 在本地或 [remote sandbox](/oss/deepagents/code/remote-sandboxes) 中执行 shell commands | Required<sup>1</sup> |
    | `web_search` | 使用 Tavily 搜索网页（见 [启用 web search](/oss/deepagents/code/configuration#enable-web-search-with-tavily)） | Required<sup>1</sup> |
    | `fetch_url` | 抓取网页并转换为 markdown | Required<sup>1</sup> |
    | `task` | 把工作委派给 [subagents](/oss/deepagents/code/subagents) 进行并行执行<sup>3</sup> | Required<sup>1</sup> |
    | `ask_user` | 向用户提出自由格式或多选问题 | - |
    | `compact_conversation` | 总结旧消息，把原始消息卸载到 backend storage，并在上下文中用摘要替换它们 | Mixed<sup>2</sup> |
    | `write_todos` | 为复杂工作创建和管理任务列表 | - |
    | `get_current_thread_id` | 返回当前 thread ID，供 LangSmith 或 MCP tooling 使用 | - |
    | `get_rubric` | 查看当前验收标准和最新评分状态 | - |
    | `get_goal` | 查看当前 goal、状态、标准和之前的 note | - |
    | `update_goal` | 用证据把当前 goal 标记为 completed 或 blocked | - |

    <sup>1</sup>：潜在破坏性操作在执行前需要用户批准。若要绕过人工批准，你可以切换 auto-approve（`shift+tab`），或者以以下选项启动：

    ```bash
    dcode --auto-approve
    # 简短别名：
    dcode -y
    ```

    <Note>
        非交互模式默认禁用 shell。可以使用 `-S`/`--shell-allow-list`（或 `DEEPAGENTS_CODE_SHELL_ALLOW_LIST`）允许指定命令。`recommended` 表示只读安全默认值，`all` 表示允许任何命令。参见 [Non-interactive mode and piping](#non-interactive-mode-and-piping)。
    </Note>

    <sup>2</sup>：当 token 使用量超过 model-aware 阈值时，Deep Agents Code 会在后台自动卸载对话。卸载会通过 LLM 总结较旧消息，并把原始消息弹出到存储（`/conversation_history/{thread_id}.md`），在上下文中用摘要替换它们。agent 之后仍然可以在需要时从卸载文件中取回完整历史。`compact_conversation` 工具允许 agent（或你）按需触发卸载。作为 tool 调用时，默认需要用户批准。

    <sup>3</sup>：当通过 `config.toml` 中的 `[async_subagents]` section 配置 async subagents 时（见 [Async subagents](/oss/deepagents/async-subagents)），还会出现额外工具：`start_async_task`、`update_async_task` 和 `cancel_async_task`（都需要批准），以及 `check_async_task` 和 `list_async_tasks`。
</Accordion>

## Command reference

```bash
# 使用特定 agent 配置
dcode --agent mybot

# 使用特定 model（provider:model 格式，或者自动检测）
dcode --model anthropic:claude-opus-4-8
dcode --model gpt-5.5

# 自动批准工具使用（跳过 human-in-the-loop 提示）
dcode -y

# 先列出目录内容，再把它作为第一条 prompt 进行总结——命令先运行，再提交 prompt
# prompt 看不到命令输出
dcode --startup-cmd "ls -la" -m "Summarize what's in this directory"

# 带 startup command 的非交互模式：在任务运行前先显示 git status
# 任务看不到命令输出
dcode --startup-cmd "git diff --stat" -n "Review these changes"
```

## 配置

关于完整参考 - 包括 `config.toml` schema、provider 参数、profile overrides 和 hook 配置 - 请参见 [Configuration](/oss/deepagents/code/configuration)。

Deep Agents Code 把所有配置都存放在 `~/.deepagents/` 下。在这个目录里，每个 agent 都有自己的子目录（默认：`agent`）：

| Path | 用途 |
|------|---------|
| `~/.deepagents/config.toml` | 模型和 agent 默认值、provider 设置、构造参数、profile overrides、主题、更新设置 |
| `~/.deepagents/.env` | 全局 API keys 和 secret。见 [configuration](/oss/deepagents/code/configuration#environment-variables) |
| `~/.deepagents/hooks.json` | [生命周期事件 hooks](/oss/deepagents/code/configuration#hooks)（session start/end、task complete 等） |
| `~/.deepagents/<agent_name>/` | 每个 agent 的 memory、skills 和 conversation threads |
| `.deepagents/`（项目根目录） | 项目专属 memory 和 skills，在 git repo 内运行时加载 |

## 交互模式

像在聊天界面里一样自然输入即可。
agent 会使用内置工具、skills 和 memory 帮你完成任务。

<AccordionGroup>
    <Accordion title="Slash commands" icon="slash">
        在 Deep Agents Code session 中可以使用这些命令：

        - `/model`: 切换模型或打开交互式 model selector。
        - `/effort`: 设置当前模型的 reasoning effort。
        - `/agents`: 在预配置的 agents 之间热切换，而无需重新启动。详情见 [Command reference](/oss/deepagents/code/overview#command-reference)。
        - `/auth`: 管理模型 provider 和服务（例如 Tavily web search）的已存储 API keys。详情见 [Provider credentials](/oss/deepagents/code/configuration#provider-credentials)。
        - `/goal <objective>`: 通过一个可衡量的目标起草验收标准。见 [Goals and rubrics](/oss/deepagents/code/goals-and-rubrics)。
        - `/rubric`: 设置明确的评审验收标准。见 [Goals and rubrics](/oss/deepagents/code/goals-and-rubrics)。
        - `/remember [context]`: 查看对话并更新 memory 和 skills。可选地传入额外上下文。
        - `/skill:<name> [args]`: 直接按名称调用某个 skill。该 skill 的 `SKILL.md` 指令会和你提供的参数一起注入 prompt。
        - `/skill-creator [task]`: 编写高质量 agent skills 的指南。
        - `/offload`（别名 `/compact`）- 通过把消息卸载到存储并保留摘要占位符来释放上下文窗口空间。agent 需要时仍能从卸载文件中取回完整历史
        - `/tokens`: 显示当前上下文窗口 token 使用分布。
        - `/clear`: 清空对话历史并开始新的 thread。
        - `/force-clear`: 停止正在进行的工作，清空聊天，并开始新的 thread。
        - `/copy`: 把最新的 assistant message 复制到剪贴板。
        - `/threads`: 浏览并恢复之前的 conversation threads。

## Non-interactive mode and piping

使用 `-n` 可以不启动交互式 UI，直接运行单个任务：

```bash
dcode -n "Write a Python script that prints hello world"
```

每次非交互式运行都会创建一个新的 thread - 对话历史不会在不同 invocation 之间传递。基于文件的 state（memory、skills、configuration）仍然会保留。

你也可以通过 stdin pipe 输入。当输入被 pipe 时，Deep Agents Code 会自动以非交互模式运行：

```bash
echo "Explain this code" | dcode
cat error.log | dcode -n "What's causing this error?"
git diff | dcode -n "Review these changes"
git diff | dcode --skill code-review -n 'summarize changes'
```

当你把 pipe 输入和 `-n` 或 `-m` 组合使用时，pipe 的内容会排在前面，然后才是你通过 flag 传入的文本。

<Note>
    pipe 输入的最大大小是 10 MiB。
</Note>

在非交互模式下，shell execution 默认关闭。你可以使用 `-S`/`--shell-allow-list` 来启用特定命令（例如 `-S "pytest,git,make"`）、使用 `recommended` 作为安全默认值，或者用 `all` 允许任何命令。

<AccordionGroup>
    <Accordion title="限制 turn 数量" icon="gauge">
        在 CI/CD 流水线中，长时间运行或行为异常的 agents 可能会无限循环。`--max-turns N` 为运维人员提供了一个硬性上限，而无需接触 SDK internals：

        ```bash
        dcode -n "fix the failing tests" --max-turns 10
        ```

        `N` 必须是正整数，并会覆盖内部安全默认值（该默认值用于限制 runaway loops）。超出预算时会以代码 124 退出（与 GNU `timeout` 一致），这样 CI 就能把预算用尽和普通失败区分开。需要 `-n` 或 piped stdin；否则以代码 2 退出。

        如果你想用基于时间的限制，而不是（或除了）turn-count 限制，请参见 [Cap wall-clock time with `--timeout`](#non-interactive-mode-and-piping)。
    </Accordion>

    <Accordion title="限制墙钟时间" icon="clock">
        `--timeout SECONDS` 会在非交互式运行中强制执行硬性的墙钟时间上限。它与 `--max-turns`（turn 数）互补 - 先达到哪一个上限，就取消 agent。

        ```bash
        # 如果任务超过 2 分钟就在 CI 中快速失败
        dcode -n "run the test suite and summarise failures" --timeout 120

        # 与 --max-turns 组合使用 - 先达到任一上限就停止 agent
        dcode -n "refactor auth module" --timeout 300 --max-turns 20
        ```

        到期后，agent 会被取消，进程以代码 124 退出，与 `--max-turns` 使用相同的代码，因此 CI 可以统一处理这两种预算用尽情况。需要 `-n` 或 piped stdin；否则以代码 2 退出。
    </Accordion>

    <Accordion title="干净输出和缓冲" icon="buffer">
        使用 `-q` 获取适合 pipe 到其他命令的干净输出，使用 `--no-stream` 先缓冲完整 response（而不是流式输出），然后再写入 stdout：

        ```bash
        dcode -n "Generate a .gitignore for Python" -q > .gitignore
        dcode -n "List dependencies" -q --no-stream | sort
        ```

        在非交互模式下，agent 会被指示合理假设并自主推进，而不是提出澄清问题。它也会优先使用非交互式命令变体（例如 `npm init -y`、`apt-get install -y`）。
    </Accordion>

    <Accordion title="Shell execution 示例" icon="shield-check">
        ```bash
        # 允许特定命令（会根据列表验证）
        dcode -n "Run the tests and fix failures" -S "pytest,git,make"

        # 使用 curated 安全命令列表
        dcode -n "Build the project" -S recommended

        # 允许任何 shell command
        dcode -n "Fix the build" -S all
        ```
    </Accordion>
</AccordionGroup>

<Warning>
    **Use with caution.**

    `-S all`（或 `--shell-allow-list all`）会让 agent 在没有人工确认的情况下执行任意 shell commands。
</Warning>

## Trace with LangSmith

启用 [LangSmith](https://smith.langchain.com) tracing，可以在 LangSmith project 中看到 agent 操作、tool call 和决策。

把 tracing keys 添加到 `~/.deepagents/.env`，这样每个 session 都会启用 tracing，而无需逐个 shell export：

```bash title="~/.deepagents/.env"
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=lsv2_...
LANGSMITH_PROJECT=optional-project-name  # 指定项目名，或默认使用 "deepagents-code"
```

如果你想为某个特定 project 覆盖，可以把相同的 keys 添加到项目目录里的 `.env`。更多加载顺序请参见 [environment variables](/oss/deepagents/code/configuration#environment-variables)。

如果你更喜欢 shell 环境变量，也可以这样设置。Shell exports 总是优先于 `.env` 值，因此这很适合临时覆盖或测试：

```bash
export LANGSMITH_TRACING=false
```

<Accordion title="把 agent traces 和 app traces 分开">
    Deep Agents Code 可以产出两类 LangSmith traces：

    - `Agent traces` 是 Deep Agents Code 自己的 model call、tool call、编排和 middleware。
    - `Shell-command traces` 是 Deep Agents Code 为你在 shell 中运行的代码产生的 traces，例如测试、脚本或本地 LangGraph app。

    如果你想把 Deep Agents Code 自己的 traces 发送到单独的 project，请设置 `DEEPAGENTS_CODE_LANGSMITH_PROJECT`：

    ```bash title="~/.deepagents/.env"
    # 示例值；请使用你想要的任意 LangSmith project 名称。
    DEEPAGENTS_CODE_LANGSMITH_PROJECT=deepagents-code
    ```

    然后为你的应用 traces 配置 `LANGSMITH_PROJECT`：

    ```bash title=".env"
    LANGSMITH_PROJECT=customer-support-agent
    ```

    例如，假设你让 Deep Agents Code 调试一个失败的 LangGraph 测试：

    ```bash
    uv run pytest tests/test_escalation_flow.py
    ```

    如果那个测试在运行你的 app 时启用了 LangSmith tracing，那么这些 app traces 会由 shell process 产生，并进入 `customer-support-agent`。Deep Agents Code 自己的推理和 tool-use traces 则会进入 `deepagents-code`。

    你也可以使用 [`DEEPAGENTS_CODE_` 前缀](/oss/deepagents/code/configuration#deepagents_code_-prefix) 把 LangSmith 凭据限定给 Deep Agents Code（例如 `DEEPAGENTS_CODE_LANGSMITH_API_KEY`）。
</Accordion>

<Accordion title="双写 traces 到第二个 project">
    要把 agent traces 镜像到第二个 LangSmith project，请设置 `DEEPAGENTS_CODE_LANGSMITH_REPLICA_PROJECTS`。这适合把同一份 traces 同时发送到个人 project 和共享团队 project。

    ```bash title="~/.deepagents/.env"
    DEEPAGENTS_CODE_LANGSMITH_REPLICA_PROJECTS=team-shared
    ```

    当该变量被设置且 tracing 激活时，每次 agent run 都会同时写入主 project（来自 `DEEPAGENTS_CODE_LANGSMITH_PROJECT`，或者默认的 `deepagents-code`）以及你指定的 project。保持未设置则像往常一样只写入单个 project。
</Accordion>

当配置完成后，Deep Agents Code 会显示一条状态行并附上 LangSmith project 的链接。在受支持的终端里，你可以点击链接直接打开。你也可以使用 `/trace` 打印 URL，并在浏览器中打开它。

```sh
✓ LangSmith tracing: 'my-project'
```

<Tip>
我们也建议你配置 [LangSmith Engine](/oss/langsmith/engine)，它可以监控你的 traces、发现问题并提出修复建议。
</Tip>
