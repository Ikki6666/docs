Plugins 使用可复用的 [skills](/oss/deepagents/code/memory-and-skills)、[MCP server](/oss/deepagents/code/mcp-tools)、[hooks](/oss/deepagents/code/hooks) 和 [Python extensions](/oss/deepagents/code/extensions) 扩展 dcode。Marketplaces 提供目录，用于跨项目或团队发现和安装 plugins。dcode 支持 Claude 和 Codex 风格的 plugin manifest 与 marketplace 目录，如 [Create a plugin](#create-a-plugin) 和 [Create a marketplace](#create-a-marketplace) 中所述。

<Warning>
    只从你信任的来源安装 plugins 和 marketplaces。已启用的 plugin 可以以你的用户权限添加指令并运行 MCP server、hook 命令或 Python extensions。
</Warning>

## 交互式管理 plugins

要在 `dcode` 会话中浏览 marketplaces 并管理 plugins：

1. 运行 `/plugins` 打开 plugin 管理器。
2. 在 **Marketplaces** tab 中添加 marketplace。支持的来源包括：
    - `owner/repo` 格式的 GitHub 仓库，可选后跟 `@branch-or-tag`。
    - HTTPS Git 仓库 URL，可选后跟 `#branch-or-tag`。
    - 提供 marketplace JSON 文件的 HTTPS URL。
    - 本地 marketplace 目录或 JSON 文件。
3. 从 marketplace 安装 plugin。
4. 运行 `/reload` 以在不重启会话的情况下激活新安装的 plugin skills、MCP server 和 hooks。带 [Python extensions](/oss/deepagents/code/extensions) 的 plugin 需要 `/restart` 来重建 agent 图。

Plugin 管理器还允许你启用、禁用和卸载已安装的 plugins。禁用 plugin 会保持其已安装状态，但在你运行 `/reload` 或启动新会话之后排除其 skills、MCP server 和 hooks。Python extensions 在你运行 `/restart` 或启动新会话之前会一直加载在当前图中。

移除 marketplace 会卸载其 plugins 并移除受管的缓存数据。当 marketplace 来自本地目录或文件时，Deep Agents Code 会保留原始来源。运行 `/reload` 或启动新会话可以将移除应用到活动会话。

## 通过 agent 发现 plugins

agent 可以在已配置的 marketplace 目录中搜索缺失的能力并报告可用的 plugins。

询问 agent 可用的、已禁用的或尚未安装的 plugins。它会使用当前 profile 通过 `dcode plugin list --json` 和 `dcode plugin marketplace list --json` 读取本地目录。它不会搜索互联网上未连接的 marketplaces。

## 自动更新 plugins

Deep Agents Code 可以在第一个 prompt 之后在后台更新已安装的 plugins。更新只适用于通过自身 manifest 选择加入的已启用 plugins。Plugin 作者通过向该 plugin 的 `plugin.json` 添加以下代码块来按 plugin 选择加入：

```json
{
  "extensions": {
    "com.langchain.deepagents.code": {
      "autoUpdate": true
    }
  }
}
```

在你运行 `/reload` 之前，正在运行的会话会继续使用其当前的 plugin 版本。要在全局禁用自动 plugin 更新，请在 `config.toml` 中设置 `[plugins].auto_update = false`，或在环境中设置 `DEEPAGENTS_CODE_PLUGIN_AUTO_UPDATE=false`。

## 从命令行管理 plugins

使用 `dcode plugin` 进行脚本和基于终端的管理。Plugin ID 使用 `plugin-name@marketplace-name` 格式。

```bash
# Add and inspect a marketplace
dcode plugin marketplace add acme/plugins
dcode plugin marketplace list

# Browse and install plugins
dcode plugin list
dcode plugin install code-review@acme-tools

# Change plugin state
dcode plugin disable code-review@acme-tools
dcode plugin enable code-review@acme-tools

# Remove a plugin or marketplace
dcode plugin uninstall code-review@acme-tools
dcode plugin marketplace remove acme-tools
```

`plugin list` 和 `plugin marketplace list` 接受 `--json`。安装 plugin 后，在活动的交互式会话中运行 `/reload` 或启动新会话。

## 使用 plugin skills、MCP server 和 hooks

Plugin skills 使用命名空间以避免与项目、用户和其他 plugin 的 skills 冲突。使用 plugin ID 和 skill 路径调用 skill：

```text
/skill:plugin-name@marketplace-name:skill-name optional arguments
```

在交互式模式下，自动补全也会匹配较短的 `/plugin-name:skill-name` 形式，并将其展开为规范的 `/skill:` 命令。嵌套的 skill 目录会将每个目录加入命名空间。例如，`quality@acme-tools` 中的 `skills/review/security/SKILL.md` 会变为 `/skill:quality@acme-tools:review:security`。

已启用的 plugin 还可以贡献 MCP server。当 plugins 加载时，Deep Agents Code 会将这些 server 与你的常规 MCP 配置合并。使用 `/mcp` 检查可用的 server 和工具。

Plugin hooks 使用与用户和项目 hooks 相同的生命周期事件和 handler 格式。Plugin 管理器会列出每个 plugin 声明的事件。启用 plugin 是其 hooks 的唯一同意开关：workspace 信任适用于项目 hooks，不适用于 plugin hooks。

## 创建 plugin

Deep Agents Code plugin 是一个包含任意受支持组件的目录：

```text
my-plugin/
├── .claude-plugin/
│   └── plugin.json
├── skills/
│   └── review/
│       └── SKILL.md
├── hooks/
│   └── hooks.json
└── .mcp.json
```

Deep Agents Code 也识别 `.codex-plugin/plugin.json`。当组件使用其默认位置时，manifest 是可选的。如果 plugin 只包含一个 skill，你可以把 `SKILL.md` 放在 plugin 根目录，而不是创建 `skills/`。

### 定义 plugin manifest

存在时，`.claude-plugin/plugin.json` 或 `.codex-plugin/plugin.json` 必须包含 `name`。你还可以声明版本和自定义组件路径：

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "skills": "./skills",
  "mcpServers": "./.mcp.json",
  "hooks": "./hooks/hooks.json"
}
```

`skills`、`mcpServers` 和 `hooks` 字段接受路径字符串或路径数组。`mcpServers` 和 `hooks` 还可以包含内联配置对象。每个组件路径必须以 `./` 开头，保持在 plugin 根目录内，并且不包含 `..`。

当没有声明自定义路径时，Deep Agents Code 会发现：

- `skills/` 下的 skills，或在不存在 `skills/` 目录时的根 `SKILL.md`。
- 根 `.mcp.json` 文件中的 MCP server。
- `hooks/hooks.json` 中的 hooks。

### 添加 skills

将每个 skill 组织为包含 `SKILL.md` 的目录：

```text
skills/
└── review/
    ├── SKILL.md
    └── checklist.md
```

使用与独立 Deep Agents Code skills 相同的 skill 格式。已安装的 plugin 名称会成为 skill 命名空间。更多信息请参见 [Memory and skills](/oss/deepagents/code/memory-and-skills#skills)。

### 添加 MCP server

将标准 MCP server 定义放在 `.mcp.json` 中，或在 plugin manifest 中使用 `mcpServers` 内联声明。MCP server 和 hook 命令支持这些路径变量：

- `${CLAUDE_PLUGIN_ROOT}` 或 `${PLUGIN_ROOT}`：已安装的 plugin 目录。
- `${CLAUDE_PLUGIN_DATA}` 或 `${PLUGIN_DATA}`：plugin 的可写数据目录。
- `${CLAUDE_PROJECT_DIR}`：活动项目目录。

例如：

```json
{
  "mcpServers": {
    "review-tools": {
      "command": "python",
      "args": ["${CLAUDE_PLUGIN_ROOT}/server.py"],
      "env": {
        "CACHE_DIR": "${CLAUDE_PLUGIN_DATA}"
      }
    }
  }
}
```

支持的 MCP 传输和字段请参见 [MCP tools](/oss/deepagents/code/mcp-tools)。

### 添加 hooks

将 hook 文档放在 `hooks/hooks.json`，声明相对的 `hooks` 路径，或在 plugin manifest 中内联定义 hooks。Hook 命令会接收上述路径变量。配置和事件参考请参见 [Hooks](/oss/deepagents/code/hooks)。

### 添加 Python extensions

<Note>
    Python extensions 需要 `DEEPAGENTS_CODE_EXPERIMENTAL=1`。
</Note>

在 plugin manifest 中的 Deep Agents Code 命名空间下声明一个 Python 入口文件或一个列表：

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "extensions": {
    "com.langchain.deepagents.code": {
      "pythonExtensions": "./extension.py"
    }
  }
}
```

Plugin 必须声明非空的 `version`。每个入口必须以 `./` 开头并位于 plugin 根目录内。更改已安装的 plugin extension 之后，重启 dcode。设置函数、支持的注册、信任模型和安全行为请参见 [Python extensions](/oss/deepagents/code/extensions)。

## 创建 marketplace

Marketplace 是一个带有名称和 `plugins` 数组的 JSON 目录。将它存储在 marketplace 根目录的以下路径之一：

- `.claude-plugin/marketplace.json`
- `.agents/plugins/marketplace.json`
- `.agents/plugins/api_marketplace.json`

以下 marketplace 包含一个存储在同一仓库中的 plugin：

```json
{
  "name": "acme-tools",
  "plugins": [
    {
      "name": "code-review",
      "source": "./plugins/code-review",
      "description": "Review code for correctness and maintainability"
    }
  ]
}
```

每个 plugin 条目需要 `name` 和 `source`。它还可以包含 `description` 和 `author`。本地 source 路径必须以 `./` 开头并位于 marketplace 根目录内。当所有本地 plugin 共享不同的基础目录时，设置 `metadata.pluginRoot`。

Marketplace 条目还可以使用外部 Git 来源：

```json
{
  "name": "acme-tools",
  "plugins": [
    {
      "name": "code-review",
      "source": {
        "source": "github",
        "repo": "acme/code-review-plugin",
        "ref": "v1.0.0"
      }
    },
    {
      "name": "release-tools",
      "source": {
        "source": "git-subdir",
        "url": "https://github.com/acme/developer-tools.git",
        "path": "./plugins/release-tools",
        "ref": "main"
      }
    }
  ]
}
```

支持的 plugin 来源类型有 `github`、`url` 和 `git-subdir`。Remote URL 必须使用 HTTPS。以直接 JSON URL 添加的 marketplace 不能包含本地的相对 plugin 来源，因为只下载目录文件本身。当目录引用同一源码树中的 plugin 目录时，请使用 Git 仓库或本地目录。

通过添加其目录、安装一个 plugin 并启动新会话或运行 `/reload` 来测试本地 marketplace：

```bash
dcode plugin marketplace add ./my-marketplace
dcode plugin install code-review@acme-tools
```
