## 设置如何解析

Deep Agents Code 使用分层配置。优先级顺序取决于设置类型。

**通用选项**（interpreter 限制、更新设置、主题以及其他 `config.toml` key）按以下顺序使用第一个可用值：

1. 管理员拥有的 `managed_config.toml`
2. 带 `DEEPAGENTS_CODE_` 前缀的环境变量
3. 标准 env var（适用时）
4. `~/.deepagents/config.toml`
5. 内置默认值

使用 `dcode config` 或 `dcode config get <key>` 可查看当前值及其来源。参见 [查看配置](#inspect-configuration)。

**Provider API keys** 使用单独的顺序。参见 [Key resolution order](/oss/deepagents/code/credentials#key-resolution-order)。

**Dotenv 文件** 会在启动时加载：最近的 project `.env`（从启动目录向上查找），然后是 `~/.deepagents/.env`。Shell exports 始终优先于 `.env` 值。参见 [加载顺序和优先级](#loading-order-and-precedence)。

**Provider endpoints**（`base_url`）会与匹配的 API key 一起解析。参见 [Endpoints, keys, and gateways](/oss/deepagents/code/config-file#endpoints-keys-and-gateways)。

## 查看配置

`dcode config` 命令会在不启动会话的情况下，显示 Deep Agents Code 使用的设置以及每个值来自哪里。可以用它们确认管理员设置、环境变量或 `config.toml` 设置是否生效。

| 命令 | 说明 |
|---------|-------------|
| `dcode config` | 显示每个设置、其当前值以及该值的来源 |
| `dcode config get <key>` | 显示单个设置的当前值和来源，例如 `dcode config get interpreter.memory_limit_mb` |
| `dcode config path` | 显示 `managed_config.toml`、`config.toml`、project 和全局 `.env` 文件、`hooks.json` 以及 managed state 的文件位置，并标明每个文件是否存在 |

为 `dcode config` 或 `dcode config get` 加上 `--verbose` 可以显示描述、默认值以及每个设置可以在哪里定义。将 `--verbose` 与 `--json` 组合使用还可包含接受的类型和其他参考细节。这三个命令都支持 `--json`，便于机器读取输出。完整命令列表请参见 [CLI reference](/oss/deepagents/code/cli-reference)。

<Warning>
    Provider 凭据和其他 secret 只会以“已配置 / 未配置”的方式报告。`config` 和 `config get` 永远不会打印它们的值。
</Warning>

## 环境变量

除了 shell exports 之外，Deep Agents Code 还会从 dotenv 文件中读取环境变量，因此你可以把 API keys 从 shell profile 里移走，也无需在项目之间复制 `.env` 文件。

```bash title="~/.deepagents/.env"
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
```

关于 provider key 的具体情况，请参见 [Provider 凭据](/oss/deepagents/code/credentials)。

### 加载顺序和优先级

启动时，Deep Agents Code 会先读取离你启动目录最近的项目 `.env`（从当前目录向上查找，找到的第一个 `.env` 生效），然后再读取 `~/.deepagents/.env` 作为所有项目的全局回退。项目 `.env` 的优先级高于全局 `.env`，但两者都不会覆盖你 shell 中已设置的值。

要完全跳过 project `.env`（全局 `~/.deepagents/.env` 仍会加载），请设置 `startup.read_project_dotenv`。

<Tabs>
    <Tab title="Config file">
        ```toml title="~/.deepagents/config.toml"
        [startup]
        read_project_dotenv = false
        ```
    </Tab>
    <Tab title="Environment variable">
        ```bash
        export DEEPAGENTS_CODE_READ_PROJECT_DOTENV=0
        ```
    </Tab>
</Tabs>

该设置会从 managed config、环境变量和用户 `config.toml` 解析。所有这些都会在任何 project `.env` 应用之前读取，因此 project `.env` 无法为自己关闭（或重新打开）这个开关。

当环境变量来自 dotenv 文件时，Deep Agents Code 会忽略那些可能改变可执行文件查找、interpreter 或 shell 启动、Git 行为或信任设置的环境变量。

<Accordion title="查看 dotenv 文件中被阻止的环境变量">
    以下 key 不能在 project 或全局 dotenv 文件中设置：

    - Profile 和信任根：`DEEPAGENTS_HOME`、`DEEPAGENTS_HOME_IS_DEFAULT`、`DEEPAGENTS_CODE_READ_PROJECT_DOTENV`、`DEEPAGENTS_INHERITED_PYTHONPATH`
    - 动态链接器 preload/audit：`DYLD_INSERT_LIBRARIES`、`DYLD_LIBRARY_PATH`、`LD_AUDIT`、`LD_LIBRARY_PATH`、`LD_PRELOAD`
    - Interpreter 启动/路径：`NODE_OPTIONS`、`PATH`、`PYTHONEXECUTABLE`、`PYTHONHOME`、`PYTHONPATH`、`PYTHONSTARTUP`
    - Shell 启动 hooks：`BASH_ENV`、`ENV`、`BASHOPTS`、`SHELLOPTS`、`CDPATH`、`GLOBIGNORE`
    - 凭据提示劫持：`GIT_ASKPASS`、`SSH_ASKPASS`
    - Git config/exec 注入：`GIT_DIR`、`GIT_WORK_TREE`、`GIT_OBJECT_DIRECTORY`、`GIT_EXEC_PATH`、`GIT_EDITOR`、`GIT_PAGER`、`GIT_SSH`、`GIT_SSH_COMMAND`，以及前缀系列 `GIT_CONFIG_COUNT`、`GIT_CONFIG_KEY_*`、`GIT_CONFIG_VALUE_*`、`GIT_CONFIG_PARAMETERS`、`GIT_CONFIG_SYSTEM` 和 `GIT_CONFIG_GLOBAL`
    - Windows 进程变量：`COMSPEC`、`SYSTEMROOT`、`WINDIR`

    project `.env` 还不能设置 `DEEPAGENTS_CODE_DANGEROUSLY_ENABLE_PROJECT_MCP_SERVERS`、`DEEPAGENTS_CODE_DISABLED_PROJECT_MCP_SERVERS`、`DEEPAGENTS_CODE_AUTO_CLASSIFIER_MODEL`、`DEEPAGENTS_CODE_AUTO_CLASSIFIER_TIMEOUT`、`DEEPAGENTS_CODE_FORKED_SUBAGENTS` 或 `TERM_PROGRAM`。请改在 shell 或全局 `~/.deepagents/.env` 中设置它们。
</Accordion>

<Warning>
    在不受信任的项目目录中运行 `dcode` 会让你暴露在项目控制的文件之下。该目录中的恶意 `.env`、`Makefile` 或构建脚本可能会影响 agent 的进程环境和它运行的内容。把任何你不会在其中运行任意脚本的目录都视为不受信任，并在 [remote sandbox](/oss/deepagents/code/remote-sandboxes) 中处理不受信任的仓库。
</Warning>

### `DEEPAGENTS_CODE_` 前缀

所有 Deep Agents Code 专用环境变量都使用 `DEEPAGENTS_CODE_` 前缀（例如 `DEEPAGENTS_CODE_AUTO_UPDATE`、`DEEPAGENTS_CODE_DEBUG`）。完整列表请参见 [environment variable reference](#environment-variable-reference)。

这个前缀也可以作为 Deep Agents Code 读取的任意环境变量的覆盖机制，包括第三方凭据。Deep Agents Code 会先检查 `DEEPAGENTS_CODE_{NAME}`，然后回退到 `{NAME}`：

```bash title="~/.deepagents/.env"
# 给 Deep Agents Code 单独一份值，而不影响其他工具
DEEPAGENTS_CODE_OPENAI_API_KEY=sk-cli-only

# 或者把它设为空，这样 Deep Agents Code 就会忽略你 shell 里导出的 key
DEEPAGENTS_CODE_ANTHROPIC_API_KEY=
```

## Skills 目录 allowlist

默认情况下，Deep Agents Code 加载 skills 时会校验解析后的 skill 文件路径是否仍在标准 [skill directories](/oss/deepagents/code/configuration#skills) 之一中。这可以防止 skill 目录里的符号链接读取这些根目录之外的任意文件。

如果你把共享 skill 资源存放在非标准位置，并通过标准 skill 目录中的符号链接引用它们，就可以把那个位置加入 containment allowlist。这 **不会** 增加新的 skill discovery location：skills 仍然只会从标准目录中发现。

<ResponseField name="extra_allowed_dirs" type="string[]" post={["optional"]}>
    加入 skill containment allowlist 的路径。支持 `~` 展开。

    ```toml
    [skills]
    extra_allowed_dirs = [
        "~/shared-skills",
        "/opt/team-skills",
    ]
    ```
</ResponseField>

或者把 `DEEPAGENTS_CODE_EXTRA_SKILLS_DIRS` 环境变量设置为以冒号分隔的列表：

```bash
export DEEPAGENTS_CODE_EXTRA_SKILLS_DIRS="~/shared-skills:/opt/team-skills"
```

当环境变量被设置时，它的优先级高于配置文件值。修改会在 `/reload` 后生效。

## Profile 位置（`DEEPAGENTS_HOME`）

`DEEPAGENTS_HOME` 选择 Deep Agents Code 用作用户 profile 的目录——通常存放在 `~/.deepagents/` 下的所有内容都会移动到配置的路径下。这包括 `config.toml`、全局 `.env`、`~/.deepagents/.mcp.json` 和 `hooks.json`、`extensions/`、按 agent 划分的目录（`AGENTS.md`、`skills/`、`memories/`、`agents/`）、plugins，以及 `.state/`（sessions、输入历史、凭据和锁）。未设置时，profile 默认为 `~/.deepagents`。

有效形式是绝对路径，或以 `~/` 开头的路径：

```bash
export DEEPAGENTS_HOME="~/profiles/work"        # 相对于你的 home 目录解析
export DEEPAGENTS_HOME="/opt/dcode-profiles/work"  # 绝对路径；即使无法解析 home 目录也能工作
```

相对路径和 `~user` 形式会被拒绝。解析后的路径还不得是文件系统根目录、home 目录本身、已存在的非目录、不可读或不可搜索的目录，或目标缺失的符号链接——这些情况都会在启动时报错。

<Warning>
    `DEEPAGENTS_HOME` 是一个信任边界：它决定了 Deep Agents Code 把哪些 `config.toml`、`.env` 和 `.mcp.json` 视为用户信任的文件。它必须在继承的 shell 环境中设置（例如在启动前 `export DEEPAGENTS_HOME=...`）。它会在启动时、dotenv 加载之前被捕获，任何 `.env` 文件都不能设置或更改它——否则受项目控制的 `.env` 就能把信任根迁移到它控制的文件上。子进程会继承解析后的路径。
</Warning>

别名 `~/.agents/skills/`（跨 AI CLI 工具共享）会从启动时的 home 目录解析，而不是从 `DEEPAGENTS_HOME`。完整的目录树请参见 [数据位置](#data-locations)。

## 主题

使用 `/theme` 打开交互式主题选择器。你可以在列表中实时预览主题，按 `Enter` 把选择保存到 `config.toml`。

Deep Agents Code 自带许多内置主题。默认主题是 `langchain`，一种带有 LangChain 品牌配色的深色主题。选中的主题会保存在 `[ui]` 下：

```toml
[ui]
theme = "langchain-dark"
```

关于用户自定义主题、内置覆盖以及终端专属映射，请参见 [Config file](/oss/deepagents/code/config-file) 中的 `[themes.*]` 和 `[ui.terminal_themes]` sections，或者直接在 `config.toml` 中配置：

<Accordion title="用户自定义主题、覆盖和终端映射" icon="palette">
    ### 用户自定义主题

    在 `config.toml` 的 `[themes.<name>]` sections 中定义自定义主题。每个 section 都需要 `label`（str）。`dark`（bool）如果省略，默认为 `false` - 对于深色主题请设为 `true`。所有颜色字段都是可选的 - 省略的字段会根据 `dark` flag 回退到内置的深色或浅色调色板。

    ```toml
    [themes.my-solarized]
    label = "My Solarized"
    dark = true
    primary = "#268BD2"
    warning = "#B58900"

    # 带空格的主题名需要 TOML 引号
    [themes."ocean breeze"]
    label = "Ocean Breeze"
    primary = "#0077B6"
    background = "#CAF0F8"
    ```

    用户自定义主题会与内置主题一起显示在 `/theme` 选择器里。

    ### 覆盖内置主题颜色

    如果你只想微调某个内置主题的颜色，而不想新建主题，可以使用 `[themes.<builtin-name>]` section。这里只会读取颜色字段 - `label` 和 `dark` 会继承自内置主题：

    ```toml
    [themes.langchain]
    primary = "#FF5500"
    ```

    省略的颜色字段会保留现有的内置值。对 `[themes.*]` sections 的修改会在 `/reload` 后生效。

    ### 将主题映射到终端

    如果你会在不同配色方案的终端之间切换（例如一个深色的 iTerm 和一个浅色的 Apple Terminal），可以在 `[ui.terminal_themes]` 下为每个终端映射一个主题。Deep Agents Code 会匹配 shell 的 `TERM_PROGRAM`，并自动应用映射的主题：

    ```toml
    [ui.terminal_themes]
    "Apple_Terminal" = "langchain-light"
    "iTerm.app" = "langchain"
    ```

    在 `/theme` 选择器里按 `T` 可以把当前高亮主题保存给当前终端；或者运行 `echo $TERM_PROGRAM` 找到你终端的标识符，再手动添加。

    #### 常见 `TERM_PROGRAM` 值

    | Terminal | `TERM_PROGRAM` |
    | --- | --- |
    | Apple Terminal | `Apple_Terminal` |
    | iTerm2 | `iTerm.app` |
    | WezTerm | `WezTerm` |
    | VS Code integrated terminal | `vscode` |
    | Ghostty | `ghostty` |

    #### 主题解析顺序

    1. `DEEPAGENTS_CODE_THEME` 环境变量（显式覆盖）。
    2. 当前 `TERM_PROGRAM` 的 `[ui.terminal_themes]` 映射。
    3. 通过 `/theme` 保存的 `[ui] theme` 偏好。
    4. 内置默认值（`langchain`）。
</Accordion>

## 自动更新

Deep Agents Code 默认会自动检查并安装更新。

要关闭自动更新：

<Tabs>
    <Tab title="Config file">
        ```toml
        [update]
        auto_update = false
        ```
    </Tab>
    <Tab title="Environment variable">
        ```bash
        export DEEPAGENTS_CODE_AUTO_UPDATE=0
        ```
    </Tab>
</Tabs>

环境变量优先于配置文件。将环境变量设为空值会禁用该功能。

启用时（默认），Deep Agents Code 会在会话开始时检查 PyPI 是否有新版本，并自动升级。禁用后，Deep Agents Code 会改为显示一条更新提示，并给出相应的安装命令。

### 定价目录自动更新

Deep Agents Code 会在后台每小时从上游刷新其模型定价目录，使成本估算保持最新。要退出：

<Tabs>
    <Tab title="Config file">
        ```toml
        [update]
        prices_auto_update = false
        ```
    </Tab>
    <Tab title="Environment variable">
        ```bash
        export DEEPAGENTS_CODE_PRICES_AUTO_UPDATE=0
        ```
    </Tab>
</Tabs>

### 自定义定价覆盖

对于目录未覆盖的模型，可在 `~/.deepagents/prices.json` 中添加费率。该文件使用 [genai-prices](https://github.com/pydantic/genai-prices) 的 provider-array schema。例如：

```json
[
  {
    "id": "my-provider",
    "name": "My provider",
    "api_pattern": "gateway\\.example\\.com",
    "models": [
      {
        "id": "my-model",
        "match": { "equals": "my-model" },
        "prices": { "input_mtok": 2.5, "output_mtok": 10.0 }
      }
    ]
  }
]
```

费率单位为每百万 token 的美元金额。编辑文件后请重启 Deep Agents Code。自定义费率仅在 genai-prices 目录不包含该模型时适用。

要完全关闭自动更新检查：

<Tabs>
    <Tab title="Config file">
        ```toml
        [update]
        check = false
        ```
    </Tab>
    <Tab title="Environment variable">
        ```bash
        export DEEPAGENTS_CODE_NO_UPDATE_CHECK=1
        ```
    </Tab>
</Tabs>

关闭更新检查也会阻止启动时自动安装更新。

你仍然可以随时通过 `/update` slash command 手动检查并安装更新，它会按需检查并在界面中直接报告成功或失败。

升级后，Deep Agents Code 会在下次启动时显示一个 “what is new” 横幅，并链接到 changelog。

在会话结束时，如果本次会话中检测到了更高版本，也会显示一个更新横幅作为提醒。

## 自动记忆

Deep Agents Code 会自动把学到的东西保存到 memory。要在停止自动保存的同时继续加载 memory，请更改 [自动记忆设置](/oss/deepagents/code/memory-and-skills#automatic-memory)：

<Tabs>
    <Tab title="Config file">
        ```toml title="~/.deepagents/config.toml"
        [memory]
        auto_save = false
        ```
    </Tab>
    <Tab title="Environment variable">
        ```bash
        export DEEPAGENTS_CODE_MEMORY_AUTO_SAVE=0
        ```
    </Tab>
</Tabs>

你仍然可以用 `/remember` 显式保存记忆。环境变量优先于配置文件。

## 对话历史保留

使用 `/offload` 卸载 thread 时，会在 `~/.deepagents/conversation_history/` 下写入一个 markdown 归档。启动时的清理扫描会删除超过 30 天的归档。该扫描只处理归档目录内直接的普通 `.md` 文件，绝不阻塞启动，并会记录和吞掉文件系统错误。

更改保留窗口，或用 `0` 禁用清理：

<Tabs>
    <Tab title="Config file">
        ```toml title="~/.deepagents/config.toml"
        [history]
        retention_days = 90   # 0 禁用清理扫描
        ```
    </Tab>
    <Tab title="Environment variable">
        ```bash
        export DEEPAGENTS_CODE_HISTORY_RETENTION_DAYS=90
        ```
    </Tab>
</Tabs>

环境变量优先于配置文件。使用 `DEEPAGENTS_HOME` profile 时，归档位于 `$DEEPAGENTS_HOME/conversation_history/` 下。

## 恢复时压缩

恢复 thread 会还原其完整上下文，因此下一轮需要为此付费。当恢复的 thread 上下文超过阈值时，Deep Agents Code 会在你发送下一条消息之前提议压缩它；拒绝是免费的，`/compact`（或 `/offload`）仍然可用。默认阈值为 400,000 token；设为 `0` 可禁用该提议：

```toml title="~/.deepagents/config.toml"
[threads]
compact_on_resume_threshold = 200000
```

## 卸载

要移除 `dcode` 和 `deepagents-code` binaries 以及隔离的工具环境，请运行：

```bash
uv tool uninstall deepagents-code
```

卸载命令不会删除用户配置或会话数据。Deep Agents Code 会把这些文件存放在 `~/.deepagents/` 下，包括 `config.toml`、`hooks.json`、全局 `.env`，以及 `.state/` 内容，例如已保存的 sessions 和凭据。若要连这些数据一起删除，请运行：

```bash
rm -rf ~/.deepagents
```

## 托管配置

托管配置让管理员可以在整个 fleet 上控制 Deep Agents Code 设置。Deep Agents Code 会在用户环境变量和配置之前检查管理员拥有的 `managed_config.toml`，因此用户无法覆盖其中定义的设置。

### 定位托管配置文件

Deep Agents Code 会在每个操作系统上的固定位置查找 `managed_config.toml`：

| 操作系统 | 路径 |
|------------------|------|
| macOS | `/Library/Application Support/dcode/managed_config.toml` |
| Linux | `/etc/dcode/managed_config.toml` |
| Windows | `<ProgramData>\dcode\managed_config.toml` |

在 Windows 上，Deep Agents Code 通过系统注册表（而不是 `%ProgramData%` 环境变量）查找 ProgramData。环境变量无法更改托管配置的位置。如果注册表不可用，Deep Agents Code 会检查 `C:\ProgramData\dcode\managed_config.toml`。如果该文件也缺失，Deep Agents Code 就无法确定管理员是否配置了策略，因此使用配置的命令会停止，而不是在没有策略的情况下运行。

### 创建托管策略

使用与 `~/.deepagents/config.toml` 相同的 TOML sections 和 key。运行 `dcode config --verbose --json` 可查看可用设置、它们接受的类型，以及是否可以在配置文件中设置。

例如，以下策略固定 Manual 审批模式、从 `Shift+Tab` 模式循环中移除 YOLO、限制 shell 自动审批、限制模型使用、禁用 JavaScript interpreter，并启用客户端 LangSmith secret 脱敏：

```toml title="managed_config.toml"
[startup]
mode = "manual"
yolo_switcher = false

[shell]
allow_list = ["git", "make"]

[models]
allowed = ["acme:production", "openai:*"]

[interpreter]
enable_interpreter = false

[tracing]
langsmith_redact = true
```

只有管理员才应拥有该文件的编辑权限。Deep Agents Code 将其视为只读。用户仍然可以把偏好保存到 `config.toml`，但管理员设置会一直生效，直到它们从 `managed_config.toml` 中移除。

### 限制模型使用

将 `[models].allowed` 设置为精确的、区分大小写的 `provider:model` 规范，或使用 `provider:*` 允许来自某个 provider 的所有可发现模型。该 allowlist 适用于启动默认值、`--model`、`/model`、已保存的默认值、Auto classifiers、rubric graders，以及显式的本地 subagent 模型。

```toml title="managed_config.toml"
[models]
allowed = [
    "acme:production",
    "openai:*",
]
default = "acme:production"
auto_classifier = "openai:gpt-5.5"
```

如果省略 `allowed`，用户可以选择任何模型。空列表会阻止所有模型。如果用户的列表无效，Deep Agents Code 会阻止所有模型。如果管理员的列表无效，Deep Agents Code 会阻止启动、reload 和其他使用配置的命令。管理员的列表会替换用户的列表，而不是与其合并。托管的 `default`、`recent` 和 `auto_classifier` 值也必须出现在管理员的 allowlist 中。

在 `[models.providers.<name>].models` 下添加模型会使其可供选择，但不会自动允许它。请将确切的模型或 provider 通配符加入 allowlist。通配符仅覆盖该 provider 可用的模型。如果没有可用模型，Deep Agents Code 无法选择默认值。当 Deep Agents Code 能识别界面中输入的裸模型名称的 provider 时，它会在检查 allowlist 之前将名称转换为 `provider:model`。

<Warning>
    `[sandboxes].default` 只决定用户以 `--sandbox` 启动时使用哪个后端。它不会强制沙箱化。不带 `--sandbox` 的启动会在主机上运行，并报告未使用托管后端。
</Warning>

### 远程加载策略

你可以把策略存放在中央服务器上，同时在本地 `managed_config.toml` 中保留其位置：

```toml title="managed_config.toml"
[managed_config]
source = "https://config.example.com/dcode-policy.toml"
```

配置远程策略后，本地文件只能包含 `[managed_config].source` 设置。请把完整策略放在远程 TOML 文件中。Deep Agents Code 不会合并远程和本地策略设置，远程文件也不能指向另一个 source。

<Accordion title="查看远程策略要求">
    URL 必须使用 HTTPS、不包含凭据或查询参数，并且不超过 2,048 个 ASCII 字符。Deep Agents Code 不会跟随重定向、使用代理环境变量，也不会把远程策略保存到磁盘。

    服务器必须返回非空的 UTF-8 TOML 文件，HTTP 状态为 `200`、无压缩、最大 1 MiB。请求在五秒后超时。

    <Warning>
        `SSL_CERT_FILE` 和 `SSL_CERT_DIR` 可以更改 Python 信任的证书颁发机构。请确保用户无法为 Deep Agents Code 进程更改这些变量。
    </Warning>
</Accordion>

### 验证托管策略

在部署或更改策略后，使用配置和诊断命令：

```bash
dcode config path
dcode config
dcode config get startup.mode
dcode doctor
```

`dcode config path` 显示托管文件的位置以及 Deep Agents Code 能否读取它。`dcode config` 和 `dcode config get` 会将来自该文件的设置标注为 `managed config`。`dcode doctor` 列出解析错误、无效值以及需要修正的设置。对于远程策略，它还会显示本地文件和远程 URL。如果更新失败，它会确认会话是否继续使用之前的有效策略。

### 修复无效策略

当 Deep Agents Code 无法读取或解析托管文件、无法下载完整的远程策略，或无法安全地应用策略时，它会停止，而不是在没有必需的管理员设置的情况下运行。使用配置的命令会以退出码 `78` 退出。你仍然可以运行 `dcode config`、`dcode doctor`、`dcode auth path` 以及帮助命令来排查问题。

如果更新在会话运行期间失败，Deep Agents Code 会继续使用之前的有效策略并报告失败。新进程在能够加载有效策略之前无法启动。

<Accordion title="查看会 fail closed 的设置">
    以下任何设置的值无效都会停止启动，因为回退到用户值可能会移除必需的限制：

    - `interpreter.enable_interpreter`
    - `interpreter.ptc`
    - `interpreter.ptc_acknowledge_unsafe`
    - `models.allowed`
    - `models.auto_classifier`
    - `runtime.recursion_limit`
    - `sandboxes.default`
    - `shell.allow_list`
    - `skills.extra_allowed_dirs`
    - `startup.mode`
    - `startup.yolo_switcher`
    - `tracing.langsmith_redact`

    已知的配置 section 如果 TOML 结构错误，也会停止启动。对于其他设置，Deep Agents Code 会忽略无效的管理员值，使用下一个有效来源，并在 `dcode config` 和 `dcode doctor` 中列出被忽略的设置。
</Accordion>

## Managed deployments

[install script](https://github.com/langchain-ai/deepagents/blob/main/libs/code/scripts/install.sh) 支持以 root 身份运行，适用于 macOS MDM 工具（Kandji、Jamf 等）执行的、处于最小 root 环境中的脚本。

当 `id -u` 为 `0` 时，脚本会：

1. 通过 `/dev/console` 或扫描 `/Users` 目录来解析真实 console user 的 `HOME`
2. 在每个安装步骤之后把创建的文件 `chown` 回目标用户

非 root 安装不受影响：当不是 root 运行时，所有 root 专用代码路径都会直接短路。

### 使用环境变量固定安装版本

install script 会读取一些环境变量，让你可以在整台 fleet 上固定版本、选择 extras，并指定 Python 版本。把它们和 piped install 写在同一行：

```bash
# 固定一个确切版本，便于整个 fleet 进行可复现安装
curl -LsSf https://langch.in/dcode | DEEPAGENTS_CODE_VERSION="0.1.16" bash
```

## 数据位置

Deep Agents Code 把数据存储在两个目录层级中：

- **`~/.deepagents/`** — Deep Agents 专用数据（agent memory、skills、sessions）。可通过 [`DEEPAGENTS_HOME`](#profile-location-deepagents_home) 重新定位；此时下方这些路径将以该目录为根。
- **`~/.agents/`** — 工具无关数据（跨 AI CLI 工具共享的 skills）

### 目录结构

```text
~/.deepagents/
├── .state/                  # 每台机器的 Deep Agents Code 状态（自动管理）
│   ├── sessions.db          #   用于对话 checkpoints 的 SQLite 数据库
│   ├── history.jsonl        #   命令输入历史
│   ├── chatgpt-auth.json    #   openai_codex provider 的 ChatGPT OAuth token
│   ├── ...                  #   其他标记和凭据
├── extensions/              # 用户全局 Python 扩展（实验性）
└── {agent}/                 # 按 agent 划分的目录（默认："agent"）
    ├── AGENTS.md            # 对 agent instructions 的用户自定义
    ├── skills/              # 用户级 skills
    │   └── {skill-name}/
    │       └── SKILL.md
    └── agents/              # 自定义 subagent 定义
        └── {subagent-name}/
            └── AGENTS.md

~/.agents/                   # 工具无关别名（跨 AI CLI 共享）
└── skills/                  # 可供任何兼容工具使用的 skills
    └── {skill-name}/
        └── SKILL.md

{project}/                   # 项目级（在 git repo 根目录）
├── AGENTS.md                # 项目 instructions（根目录级）
└── .deepagents/
│   ├── AGENTS.md            # 项目 instructions（首选位置）
│   ├── extensions/          # 项目 Python 扩展（需要信任；实验性）
│   ├── skills/              # 项目专用 skills
│   │   └── {skill-name}/
│   │       └── SKILL.md
│   └── agents/              # 项目专用 subagents
│       └── {subagent-name}/
│           └── AGENTS.md
└── .agents/                 # 工具无关的项目 skills
    └── skills/
        └── {skill-name}/
            └── SKILL.md
```

#### 什么放在哪里

| 数据 | 位置 | 读/写 | 说明 |
|------|----------|------------|-------|
| **Sessions** | `~/.deepagents/.state/sessions.db` | R/W | SQLite checkpoint 数据库 |
| **输入历史** | `~/.deepagents/.state/history.jsonl` | R/W | JSON-lines，上/下箭头回溯 |
| **ChatGPT OAuth token** | `~/.deepagents/.state/chatgpt-auth.json` | R/W | 支撑 [`openai_codex`](/oss/deepagents/code/providers) provider；在你用 ChatGPT 登录时创建，并自动刷新。仅你的用户账户可读。 |
| **基础 instructions** | Package `default_agent_prompt.md` | R | 不可变，随 Deep Agents Code 升级更新 |
| **用户自定义** | `~/.deepagents/{agent}/AGENTS.md` | R/W | 追加到基础 instructions 之后 |
| **项目 instructions** | `.deepagents/AGENTS.md` 或 `AGENTS.md` | R | 两者都存在时都会加载 |
| **用户 skills** | `~/.deepagents/{agent}/skills/` | R/W | Agent 专属 skills |
| **共享 skills** | `~/.agents/skills/` | R | 工具无关，跨 CLI |
| **项目 skills** | `.deepagents/skills/` 或 `.agents/skills/` | R | 项目级作用域 |
| **用户 Python 扩展** | `~/.deepagents/extensions/` | R/W | 实验性；参见 [Python extensions](/oss/deepagents/code/extensions) |
| **项目 Python 扩展** | `.deepagents/extensions/` | R | 实验性；需要项目信任 |
| **自定义 subagents** | `~/.deepagents/{agent}/agents/` | R/W | 用户定义的 subagents |
| **项目 subagents** | `.deepagents/agents/` | R | 项目定义的 subagents |

### 优先级规则

当同一个 item 在多个位置都存在时，**更高优先级者完全获胜**（不合并）。

#### Skills

优先级顺序（从低到高）：

1. `~/.deepagents/{agent}/skills/` — 用户 Deep Agents Code
2. `~/.agents/skills/` — 用户工具无关
3. `.deepagents/skills/` — 项目 Deep Agents Code
4. `.agents/skills/` — 项目工具无关 *(最高)*

加载 skill 时，Deep Agents Code 会校验解析后的文件路径是否仍在这些目录之一中。解析后落在所有 skill 根目录之外的符号链接会被拒绝。要允许指向额外目录的符号链接目标，请参见 [`[skills].extra_allowed_dirs`](/oss/deepagents/code/configuration#skill-directory-allowlist)。

#### Subagents

优先级顺序（从低到高）：

1. `~/.deepagents/{agent}/agents/` — 用户级
2. `.deepagents/agents/` — 项目级 *(最高)*

每个 subagent 都是一个 `AGENTS.md` 文件，带有 YAML frontmatter（`name`、`description`、可选的 `model`）以及作为 system prompt 的 markdown 正文。完整格式参考请参见 [在 Deep Agents Code 中使用 subagents](/oss/deepagents/code/subagents)。

#### Instructions

所有 instruction 来源都会被 **组合**（而不是覆盖）：

1. Package 基础 prompt *(总是加载)*
2. `~/.deepagents/{agent}/AGENTS.md` *(追加)*
3. `.deepagents/AGENTS.md` *(追加)*
4. 项目根目录的 `AGENTS.md` *(追加)*

### `.deepagents` 与 `.agents`

| 目录 | 用途 | 何时使用 |
|-----------|---------|-------------|
| `.deepagents/` | Deep Agents Code 专用 | 使用 Deep Agents Code 专属功能的 skills 和配置 |
| `.agents/` | 工具无关 | 想跨不同 AI CLI 工具共享的 skills |

<Tip>
使用 `.agents/skills/` 存放能配合任意 AI 编码助手的 skills。
使用 `.deepagents/skills/` 存放依赖 Deep Agents 专属工具或约定的 skills。
</Tip>

### 清理

| 需求 | 操作 |
|------|--------|
| 重置所有数据 | `rm -rf ~/.deepagents` |
| 仅清除 sessions | `rm ~/.deepagents/.state/sessions.db*` |
| 清除输入历史 | `rm ~/.deepagents/.state/history.jsonl` |
| 清除已存储的 API keys | `rm ~/.deepagents/.state/auth.json` |
| 清除 MCP OAuth tokens | `rm -rf ~/.deepagents/.state/mcp-tokens` |
| 清除 MCP project 信任 | `rm ~/.deepagents/.state/mcp_trust.json` |
| 重新运行首次运行引导 | `rm ~/.deepagents/.state/onboarding_complete` |
| 重置 agent instructions | `dcode agents reset --agent {name}` |
| 移除某个 skill | `rm -rf ~/.deepagents/{agent}/skills/{skill-name}` |

<Warning>
    删除 `~/.deepagents/.state/sessions.db` 会移除所有对话历史和 checkpoints。

    除非你有 `sessions.db` 文件的备份，否则无法撤销。
</Warning>
