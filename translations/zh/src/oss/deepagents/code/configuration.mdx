## 设置如何解析

Deep Agents Code 会从多个来源合并设置。哪个来源获胜取决于设置类型。

**通用选项**（interpreter 限制、更新设置、主题以及其他 `config.toml` key）按以下顺序解析：

1. 带 `DEEPAGENTS_CODE_` 前缀的环境变量
2. 标准 env var（适用时）
3. `~/.deepagents/config.toml`
4. 内置默认值

使用 `dcode config show` 或 `dcode config get <key>` 可查看最终生效的值和来源。参见 [查看配置](#inspect-configuration)。

**Provider API keys** 使用单独的顺序。参见 [Key resolution order](/oss/deepagents/code/credentials#key-resolution-order)。

**Dotenv 文件** 会在启动时加载：最近的 project `.env`（从启动目录向上查找），然后是 `~/.deepagents/.env`。Shell exports 始终优先于 `.env` 值。参见 [加载顺序和优先级](#loading-order-and-precedence)。

**Provider endpoints**（`base_url`）会与匹配的 API key 一起解析。参见 [Endpoints, keys, and gateways](/oss/deepagents/code/config-file#endpoints-keys-and-gateways)。

## 查看配置

`dcode config` 命令组会在不启动会话的情况下，报告当前生效的配置，以及每个值来自哪里。它适合确认某个环境变量或 `config.toml` 设置是否被读取，也适合在 bug 报告中共享一份已脱敏的快照。

| 命令 | 说明 |
|---------|-------------|
| `dcode config show` | 根据当前环境和 `config.toml` 解析每个选项，打印最终生效的值以及来源 |
| `dcode config list`（别名 `ls`） | 列出所有可用选项及其类型、默认值和可设置位置，但不解析具体值 |
| `dcode config get <key>` | 显示单个选项的最终值和来源，例如 `dcode config get interpreter.memory_limit_mb` |
| `dcode config path` | 显示磁盘上的配置文件位置（`config.toml`、project/global `.env`、`hooks.json` 和 managed state 文件）以及它们是否存在 |

这四个命令都支持 `--json`，便于机器读取输出。完整的管理子命令列表请参见 [CLI reference](/oss/deepagents/code/cli-reference)。

<Warning>
    Provider 凭据和其他 secret 只会以“已配置 / 未配置”的方式报告，不会显示实际值，因此 `config show` 和 `config get` 的输出可以安全地粘贴到 bug 报告中。
</Warning>

## 环境变量

除了 shell exports 之外，Deep Agents Code 还会从 dotenv 文件中读取环境变量，因此你可以把 API keys 从 shell profile 里移走，也无需在项目之间复制 `.env` 文件。

```bash title="~/.deepagents/.env"
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
```

关于 provider key 的具体情况，请参见 [Provider 凭据](/oss/deepagents/code/credentials)。

### 加载顺序和优先级

启动时，Deep Agents Code 会先读取离你启动目录最近的项目 `.env`（从当前目录向上查找，找到的第一个 `.env` 生效），然后再读取 `~/.deepagents/.env` 作为所有项目的全局回退。项目 `.env` 的优先级高于全局 `.env`，但两者都不会覆盖你 shell 中已设置的值。运行 `/reload` 会重新读取这两个 `.env` 文件，因此你无需重启就能修改 key，不过 shell 值仍然优先。这适用于 Deep Agents Code 读取的所有变量（例如 `TAVILY_API_KEY` 或 `DEEPAGENTS_CODE_*` 设置）。

<Warning>
    在不受信任的项目目录中运行 `dcode` 会让你暴露在项目控制的文件之下。该目录中的恶意 `.env`、`Makefile` 或构建脚本可能会影响 agent 的进程环境和它运行的内容。把任何你不会在其中运行任意脚本的目录都视为不受信任，并在 [remote sandbox](/oss/deepagents/code/remote-sandboxes) 中处理不受信任的仓库。
</Warning>

### `DEEPAGENTS_CODE_` 前缀

所有 Deep Agents Code 专用环境变量都使用 `DEEPAGENTS_CODE_` 前缀（例如 `DEEPAGENTS_CODE_AUTO_UPDATE`、`DEEPAGENTS_CODE_DEBUG`）。完整列表请参见 [environment variable reference](#environment-variable-reference)。

这个前缀也可以作为 Deep Agents Code 读取的任意环境变量的覆盖机制，包括第三方凭据。Deep Agents Code 会先检查 `DEEPAGENTS_CODE_{NAME}`，然后回退到 `{NAME}`：

```bash title="~/.deepagents/.env"
# 给 Deep Agents Code 单独一份值，而不影响其他工具
DEEPAGENTS_CODE_OPENAI_API_KEY=sk-cli-only

# 或者把它设为空，这样 Deep Agents Code 就会忽略你 shell 里导出的 key
DEEPAGENTS_CODE_ANTHROPIC_API_KEY=
```

## Skills 目录 allowlist

默认情况下，Deep Agents Code 加载 skills 时会校验解析后的 skill 文件路径是否仍在标准 [skill directories](/oss/deepagents/code/configuration#skills) 之一中。这可以防止 skill 目录里的符号链接读取这些根目录之外的任意文件。

如果你把共享 skill 资源存放在非标准位置，并通过标准 skill 目录中的符号链接引用它们，就可以把那个位置加入 containment allowlist。这 **不会** 增加新的 skill discovery location：skills 仍然只会从标准目录中发现。

<ResponseField name="extra_allowed_dirs" type="string[]" post={["optional"]}>
    加入 skill containment allowlist 的路径。支持 `~` 展开。

    ```toml
    [skills]
    extra_allowed_dirs = [
        "~/shared-skills",
        "/opt/team-skills",
    ]
    ```
</ResponseField>

或者把 `DEEPAGENTS_CODE_EXTRA_SKILLS_DIRS` 环境变量设置为以冒号分隔的列表：

```bash
export DEEPAGENTS_CODE_EXTRA_SKILLS_DIRS="~/shared-skills:/opt/team-skills"
```

当环境变量被设置时，它的优先级高于配置文件值。修改会在 `/reload` 后生效。

## 主题

使用 `/theme` 打开交互式主题选择器。你可以在列表中实时预览主题，按 `Enter` 把选择保存到 `config.toml`。

Deep Agents Code 自带许多内置主题。默认主题是 `langchain`，一种带有 LangChain 品牌配色的深色主题。选中的主题会保存在 `[ui]` 下：

```toml
[ui]
theme = "langchain-dark"
```

关于用户自定义主题、内置覆盖以及终端专属映射，请参见 [Config file](/oss/deepagents/code/config-file) 中的 `[themes.*]` 和 `[ui.terminal_themes]` sections，或者直接在 `config.toml` 中配置：

<Accordion title="用户自定义主题、覆盖和终端映射" icon="palette">
    ### 用户自定义主题

    在 `config.toml` 的 `[themes.<name>]` sections 中定义自定义主题。每个 section 都需要 `label`（str）。`dark`（bool）如果省略，默认为 `false` - 对于深色主题请设为 `true`。所有颜色字段都是可选的 - 省略的字段会根据 `dark` flag 回退到内置的深色或浅色调色板。

    ```toml
    [themes.my-solarized]
    label = "My Solarized"
    dark = true
    primary = "#268BD2"
    warning = "#B58900"

    # 带空格的主题名需要 TOML 引号
    [themes."ocean breeze"]
    label = "Ocean Breeze"
    primary = "#0077B6"
    background = "#CAF0F8"
    ```

    用户自定义主题会与内置主题一起显示在 `/theme` 选择器里。

    ### 覆盖内置主题颜色

    如果你只想微调某个内置主题的颜色，而不想新建主题，可以使用 `[themes.<builtin-name>]` section。这里只会读取颜色字段 - `label` 和 `dark` 会继承自内置主题：

    ```toml
    [themes.langchain]
    primary = "#FF5500"
    ```

    省略的颜色字段会保留现有的内置值。对 `[themes.*]` sections 的修改会在 `/reload` 后生效。

    ### 将主题映射到终端

    如果你会在不同配色方案的终端之间切换（例如一个深色的 iTerm 和一个浅色的 Apple Terminal），可以在 `[ui.terminal_themes]` 下为每个终端映射一个主题。Deep Agents Code 会匹配 shell 的 `TERM_PROGRAM`，并自动应用映射的主题：

    ```toml
    [ui.terminal_themes]
    "Apple_Terminal" = "langchain-light"
    "iTerm.app" = "langchain"
    ```

    在 `/theme` 选择器里按 `T` 可以把当前高亮主题保存给当前终端；或者运行 `echo $TERM_PROGRAM` 找到你终端的标识符，再手动添加。

    #### 常见 `TERM_PROGRAM` 值

    | Terminal | `TERM_PROGRAM` |
    | --- | --- |
    | Apple Terminal | `Apple_Terminal` |
    | iTerm2 | `iTerm.app` |
    | WezTerm | `WezTerm` |
    | VS Code integrated terminal | `vscode` |
    | Ghostty | `ghostty` |

    #### 主题解析顺序

    1. `DEEPAGENTS_CODE_THEME` 环境变量（显式覆盖）。
    2. 当前 `TERM_PROGRAM` 的 `[ui.terminal_themes]` 映射。
    3. 通过 `/theme` 保存的 `[ui] theme` 偏好。
    4. 内置默认值（`langchain`）。
</Accordion>

## 自动更新

Deep Agents Code 默认会自动检查并安装更新。

要关闭自动更新：

<Tabs>
    <Tab title="Config file">
        ```toml
        [update]
        auto_update = false
        ```
    </Tab>
    <Tab title="Environment variable">
        ```bash
        export DEEPAGENTS_CODE_AUTO_UPDATE=0
        ```
    </Tab>
</Tabs>

环境变量优先于配置文件。

启用时（默认），Deep Agents Code 会在会话开始时检查 PyPI 是否有新版本，并自动升级。禁用后，Deep Agents Code 会改为显示一条更新提示，并给出相应的安装命令。

要完全关闭自动更新检查：

<Tabs>
    <Tab title="Config file">
        ```toml
        [update]
        check = false
        ```
    </Tab>
    <Tab title="Environment variable">
        ```bash
        export DEEPAGENTS_CODE_NO_UPDATE_CHECK=1
        ```
    </Tab>
</Tabs>

关闭更新检查也会阻止启动时自动安装更新。

你仍然可以随时通过 `/update` slash command 手动检查并安装更新，它会按需检查并在界面中直接报告成功或失败。

升级后，Deep Agents Code 会在下次启动时显示一个 “what's new” 横幅，并链接到 changelog。

在会话结束时，如果本次会话中检测到了更高版本，也会显示一个更新横幅作为提醒。

## 卸载

要移除 `dcode` 和 `deepagents-code` binaries 以及隔离的工具环境，请运行：

```bash
uv tool uninstall deepagents-code
```

卸载命令不会删除用户配置或会话数据。Deep Agents Code 会把这些文件存放在 `~/.deepagents/` 下，包括 `config.toml`、`hooks.json`、全局 `.env`，以及 `.state/` 内容，例如已保存的 sessions 和凭据。若要连这些数据一起删除，请运行：

```bash
rm -rf ~/.deepagents
```

## Managed deployments

[install script](https://github.com/langchain-ai/deepagents/blob/main/libs/code/scripts/install.sh) 支持以 root 身份运行，适用于 macOS MDM 工具（Kandji、Jamf 等）执行的、处于最小 root 环境中的脚本。

当 `id -u` 为 `0` 时，脚本会：

1. 通过 `/dev/console` 或扫描 `/Users` 目录来解析真实 console user 的 `HOME`
2. 在每个安装步骤之后把创建的文件 `chown` 回目标用户

非 root 安装不受影响：当不是 root 运行时，所有 root 专用代码路径都会直接短路。

### 使用环境变量固定安装版本

install script 会读取一些环境变量，让你可以在整台 fleet 上固定版本、选择 extras，并指定 Python 版本。把它们和 piped install 写在同一行：

```bash
# 固定一个确切版本，便于整个 fleet 进行可复现安装
curl -LsSf https://langch.in/dcode | DEEPAGENTS_CODE_VERSION="0.1.16" bash
```

<ResponseField name="DEEPAGENTS_CODE_VERSION" type="string" post={["optional"]}>
    要安装的精确 package 版本，例如 `0.1.0`（或者像 `0.1.0rc1` 这样的 pre-release）。与 `DEEPAGENTS_CODE_PRERELEASE` 互斥 - 同时设置两者会报错，因为精确 pin 已经选定了唯一版本。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_PRERELEASE" type="string" post={["optional"]}>
    在解析最新版本时应用的 uv pre-release 策略：`disallow`、`allow`、`if-necessary`、`explicit` 或 `if-necessary-or-explicit`。与 `DEEPAGENTS_CODE_VERSION` 互斥。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_EXTRAS" type="string" post={["optional"]}>
    以逗号分隔的 pip extras，例如 `ollama`、`ollama,groq` 或 `daytona`。可用 extras 见 [`pyproject.toml`](https://github.com/langchain-ai/deepagents/blob/main/libs/code/pyproject.toml)。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_PYTHON" type="string" default="3.13" post={["optional"]}>
    安装时使用的 Python 版本。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_SKIP_OPTIONAL" type="string" post={["optional"]}>
    设为 `1` 可跳过可选工具检查。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_VERBOSE" type="string" post={["optional"]}>
    设为 `1` 可显示 uv 原始 stderr（timing lines、未过滤的 package diff）以及默认静默的状态行（可选工具检查、安装完成页脚）。在排查安装问题时很有用。
</ResponseField>

<ResponseField name="UV_BIN" type="string" post={["optional"]}>
    uv binary 的路径。如果未设置，会自动检测。
</ResponseField>

Managed installs 默认启用 auto-update。要关闭它，可以在用户 shell profile 中设置 `DEEPAGENTS_CODE_AUTO_UPDATE=0`，或者把带 `[update] auto_update = false` 的 `config.toml` 部署到 `~/.deepagents/config.toml`。要完全关闭自动更新和更新检查，请设置 `DEEPAGENTS_CODE_NO_UPDATE_CHECK=1`，或者部署 `[update] check = false`。

要把每个用户的 model traffic 都路由通过 managed gateway（并在整个 fleet 上预置 gateway key 和 base URL），请参见 [Managed gateways](/oss/deepagents/code/config-file#managed-gateways)。

## 环境变量参考

所有 Deep Agents Code 专用环境变量都使用 `DEEPAGENTS_CODE_` 前缀。关于这个前缀如何同时作为第三方凭据的覆盖开关，请参见 [`DEEPAGENTS_CODE_` 前缀](#deepagents_code_-prefix)。

<ResponseField name="DEEPAGENTS_CODE_AUTO_UPDATE" type="string" post={["optional"]}>
    切换 Deep Agents Code 自动更新。默认启用；设为 `0`、`false`、`no` 或 `off` 可关闭。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_AUTO_CLASSIFIER_TIMEOUT" type="integer" post={["optional"]}>
    [Auto 模式](/oss/deepagents/code/approval-modes) 分类器审查每批受门控操作的时间预算（秒）。有效范围：`1`–`300`。超出范围或非整数的值会回退到默认值（`20`）。在调高该值之前，建议先考虑[选择更快的分类器模型](/oss/deepagents/code/config-file#default-and-recent-model)。会覆盖 `config.toml` 中的 `[models].auto_classifier_timeout`。参见 [Auto 分类器超时](/oss/deepagents/code/config-file#auto-classifier-timeout)。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_DEBUG" type="string" post={["optional"]}>
    启用写入文件的详细 debug logging。`1`、`true`、`yes`、`on`（不区分大小写）表示启用；`0`、`false`、`no`、`off`、空字符串或未设置表示禁用。启用后，每会话的 server 日志文件会在关闭时保留，并且其路径会打印到 stderr 供排查。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_DEBUG_FILE" type="string" default="/tmp/deepagents_debug.log" post={["optional"]}>
    debug 日志文件路径。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_EXTRA_SKILLS_DIRS" type="string" post={["optional"]}>
    添加到 [skill containment allowlist](#skill-directory-allowlist) 的以冒号分隔的路径。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_LANGSMITH_PROJECT" type="string" post={["optional"]}>
    为 Deep Agents Code 自己的 agent traces 覆盖 LangSmith project 名称。Shell commands 仍然使用用户原始的 `LANGSMITH_PROJECT`，因此 app、test 或 script traces 可以出现在不同 project 中。参见 [Trace with LangSmith](/oss/deepagents/code/quickstart#trace-with-langsmith)。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_LANGSMITH_REPLICA_PROJECTS" type="string" post={["optional"]}>
    另一个也要写入 agent traces 的 LangSmith project。设置后且 tracing 处于激活状态时，每次 agent run 都会同时写入主 project（来自 `DEEPAGENTS_CODE_LANGSMITH_PROJECT`，或默认的 `deepagents-code`）和这个 project。默认关闭。参见 [Trace with LangSmith](/oss/deepagents/code/quickstart#trace-with-langsmith)。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_NO_UPDATE_CHECK" type="string" post={["optional"]}>
    设置后禁用自动更新检查。这也会阻止启动时自动安装更新。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_ONBOARDING" type="string" post={["optional"]}>
    覆盖首次运行的 onboarding 流程。设为 truthy 值可强制每次启动都打开它；设为 falsy 值可完全跳过（适用于 CI 和预配机器）。不设置则采用默认的首次运行行为。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_SHELL_ALLOW_LIST" type="string" post={["optional"]}>
    允许的 shell commands，以逗号分隔（或者 `recommended` / `all`）。
</ResponseField>

<ResponseField name="DEEPAGENTS_CODE_USER_ID" type="string" post={["optional"]}>
    给 LangSmith trace metadata 附加一个 user identifier。
</ResponseField>

```bash
# 在终端中显示 diagnostics
dcode doctor
```

## 数据位置

Deep Agents Code 把数据存储在两个目录层级中：

- **`~/.deepagents/`** — Deep Agents 专用数据（agent memory、skills、sessions）
- **`~/.agents/`** — 工具无关数据（跨 AI CLI 工具共享的 skills）

### 目录结构

```text
~/.deepagents/
├── .state/                  # 每台机器的 Deep Agents Code 状态（自动管理）
│   ├── sessions.db          #   用于对话 checkpoints 的 SQLite 数据库
│   ├── history.jsonl        #   命令输入历史
│   ├── chatgpt-auth.json    #   openai_codex provider 的 ChatGPT OAuth token
│   ├── ...                  #   其他标记和凭据
└── {agent}/                 # 按 agent 划分的目录（默认："agent"）
    ├── AGENTS.md            # 对 agent instructions 的用户自定义
    ├── skills/              # 用户级 skills
    │   └── {skill-name}/
    │       └── SKILL.md
    └── agents/              # 自定义 subagent 定义
        └── {subagent-name}/
            └── AGENTS.md

~/.agents/                   # 工具无关别名（跨 AI CLI 共享）
└── skills/                  # 可供任何兼容工具使用的 skills
    └── {skill-name}/
        └── SKILL.md

{project}/                   # 项目级（在 git repo 根目录）
├── AGENTS.md                # 项目 instructions（根目录级）
└── .deepagents/
│   ├── AGENTS.md            # 项目 instructions（首选位置）
│   ├── skills/              # 项目专用 skills
│   │   └── {skill-name}/
│   │       └── SKILL.md
│   └── agents/              # 项目专用 subagents
│       └── {subagent-name}/
│           └── AGENTS.md
└── .agents/                 # 工具无关的项目 skills
    └── skills/
        └── {skill-name}/
            └── SKILL.md
```

#### 什么放在哪里

| 数据 | 位置 | 读/写 | 说明 |
|------|----------|------------|-------|
| **Sessions** | `~/.deepagents/.state/sessions.db` | R/W | SQLite checkpoint 数据库 |
| **输入历史** | `~/.deepagents/.state/history.jsonl` | R/W | JSON-lines，上/下箭头回溯 |
| **ChatGPT OAuth token** | `~/.deepagents/.state/chatgpt-auth.json` | R/W | 支撑 [`openai_codex`](/oss/deepagents/code/providers) provider；在你用 ChatGPT 登录时创建，并自动刷新。仅你的用户账户可读。 |
| **基础 instructions** | Package `default_agent_prompt.md` | R | 不可变，随 Deep Agents Code 升级更新 |
| **用户自定义** | `~/.deepagents/{agent}/AGENTS.md` | R/W | 追加到基础 instructions 之后 |
| **项目 instructions** | `.deepagents/AGENTS.md` 或 `AGENTS.md` | R | 两者都存在时都会加载 |
| **用户 skills** | `~/.deepagents/{agent}/skills/` | R/W | Agent 专属 skills |
| **共享 skills** | `~/.agents/skills/` | R | 工具无关，跨 CLI |
| **项目 skills** | `.deepagents/skills/` 或 `.agents/skills/` | R | 项目级作用域 |
| **自定义 subagents** | `~/.deepagents/{agent}/agents/` | R/W | 用户定义的 subagents |
| **项目 subagents** | `.deepagents/agents/` | R | 项目定义的 subagents |

### 优先级规则

当同一个 item 在多个位置都存在时，**更高优先级者完全获胜**（不合并）。

#### Skills

优先级顺序（从低到高）：

1. `~/.deepagents/{agent}/skills/` — 用户 Deep Agents Code
2. `~/.agents/skills/` — 用户工具无关
3. `.deepagents/skills/` — 项目 Deep Agents Code
4. `.agents/skills/` — 项目工具无关 *(最高)*

加载 skill 时，Deep Agents Code 会校验解析后的文件路径是否仍在这些目录之一中。解析后落在所有 skill 根目录之外的符号链接会被拒绝。要允许指向额外目录的符号链接目标，请参见 [`[skills].extra_allowed_dirs`](/oss/deepagents/code/configuration#skill-directory-allowlist)。

#### Subagents

优先级顺序（从低到高）：

1. `~/.deepagents/{agent}/agents/` — 用户级
2. `.deepagents/agents/` — 项目级 *(最高)*

每个 subagent 都是一个 `AGENTS.md` 文件，带有 YAML frontmatter（`name`、`description`、可选的 `model`）以及作为 system prompt 的 markdown 正文。完整格式参考请参见 [在 Deep Agents Code 中使用 subagents](/oss/deepagents/code/subagents)。

#### Instructions

所有 instruction 来源都会被 **组合**（而不是覆盖）：

1. Package 基础 prompt *(总是加载)*
2. `~/.deepagents/{agent}/AGENTS.md` *(追加)*
3. `.deepagents/AGENTS.md` *(追加)*
4. 项目根目录的 `AGENTS.md` *(追加)*

### `.deepagents` 与 `.agents`

| 目录 | 用途 | 何时使用 |
|-----------|---------|-------------|
| `.deepagents/` | Deep Agents Code 专用 | 使用 Deep Agents Code 专属功能的 skills 和配置 |
| `.agents/` | 工具无关 | 想跨不同 AI CLI 工具共享的 skills |

<Tip>
使用 `.agents/skills/` 存放能配合任意 AI 编码助手的 skills。
使用 `.deepagents/skills/` 存放依赖 Deep Agents 专属工具或约定的 skills。
</Tip>

### 清理

| 需求 | 操作 |
|------|--------|
| 重置所有数据 | `rm -rf ~/.deepagents` |
| 仅清除 sessions | `rm ~/.deepagents/.state/sessions.db*` |
| 清除输入历史 | `rm ~/.deepagents/.state/history.jsonl` |
| 清除已存储的 API keys | `rm ~/.deepagents/.state/auth.json` |
| 清除 MCP OAuth tokens | `rm -rf ~/.deepagents/.state/mcp-tokens` |
| 清除 MCP project 信任 | `rm ~/.deepagents/.state/mcp_trust.json` |
| 重新运行首次运行引导 | `rm ~/.deepagents/.state/onboarding_complete` |
| 重置 agent instructions | `dcode agents reset --agent {name}` |
| 移除某个 skill | `rm -rf ~/.deepagents/{agent}/skills/{skill-name}` |

<Warning>
    删除 `~/.deepagents/.state/sessions.db` 会移除所有对话历史和 checkpoints。

    除非你有 `sessions.db` 文件的备份，否则无法撤销。
</Warning>
