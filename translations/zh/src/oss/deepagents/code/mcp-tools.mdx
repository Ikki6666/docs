[MCP (Model Context Protocol)](https://modelcontextprotocol.io/) 让你可以通过外部 servers 提供的工具来扩展 Deep Agents Code - 文件系统、API、数据库等等 - 而无需修改 agent 本身。Deep Agents Code 会在启动时连接 MCP servers，发现它们的工具，并让这些工具和内置工具一起提供给 agent。

通过在项目里添加一个 `.mcp.json` 配置文件来添加 project-level scope 的 MCP servers，或者在 user-level 添加，让它对所有项目都生效。

## 快速开始

这个快速开始会把 [LangChain 文档 MCP server](https://docs.langchain.com/mcp) 添加到你机器上的每个 Deep Agents Code 会话中。你也可以用同样的结构替换成任何其他 MCP server 的 URL 或 stdio 命令。

<Steps>
    <Step title="创建配置文件" icon="file">

        如果还不存在，请创建 `.mcp.json` 文件。你可以把它放在 user-level，让这台机器上的每个项目都能使用，也可以放在 project-level。

        <Tabs>
            <Tab title="User">

                ```bash
                mkdir -p ~/.deepagents
                touch ~/.deepagents/.mcp.json
                ```

                这个文件（`~/.deepagents/.mcp.json`）中的 servers 对这台机器上的所有项目都可用。
            </Tab>
            <Tab title="Project">

                ```bash
                touch .mcp.json
                ```

                这个文件（`<project>/.mcp.json`）中的 servers 仅对当前项目可用。
            </Tab>
            <Tab title="Project (hidden)">

                ```bash
                mkdir -p .deepagents
                touch .deepagents/.mcp.json
                ```

                这个文件（`<project>/.deepagents/.mcp.json`）中的 servers 仅对当前项目可用，但不会出现在 repo root 中。
            </Tab>
        </Tabs>

        完整的优先级规则请参见 [Discovery locations](#discovery-locations)。


    </Step>

    <Step title="添加 MCP server" icon="plug">

        ```json title="~/.deepagents/.mcp.json"
        {
            "mcpServers": {
                "docs-langchain": {
                    "type": "http",
                    "url": "https://docs.langchain.com/mcp"
                }
            }
        }
        ```

        要添加更多 server，只需在 `mcpServers` 中加入更多条目。关于 OAuth、stdio、SSE 和 HTTP server 字段、环境变量和 headers，请参见 [Configuration format](#configuration-format)。
    </Step>

    <Step title="启动 Deep Agents Code" icon="terminal">
        ```bash
        dcode
        ```

        启动时，Deep Agents Code 会自动发现配置，连接到每个 server，发现其工具，并打印一条确认信息：

        ```
        ✓ Loaded 3 MCP tools
        ```

        在交互式会话中运行 `/mcp`，可以查看每个 server 的状态、transport 和已加载工具列表。agent 现在可以在整个会话期间使用这些工具 - stdio servers 会在 tool call 之间保持存活。
    </Step>
</Steps>

## 自动发现

Deep Agents Code 会自动在标准位置搜索 `.mcp.json` 文件。不需要任何 flags - 只要放置好配置文件，它就会被读取。

### 发现位置

配置文件按以下顺序检查（从低到高优先级）：

| 优先级 | 位置 | 作用域 |
|----------|----------|-------|
| 1（最低） | `~/.deepagents/.mcp.json` | User-level - 适用于所有项目 |
| 2 | `<project>/.deepagents/.mcp.json` | Project-level - `.deepagents` 子目录 |
| 3（最高） | `<project>/.mcp.json` | Project-level - root（兼容 Claude Code） |

项目 root 是包含 `.git` 文件夹的最近父目录；如果找不到，则回退到当前工作目录。

当存在多个配置文件时，它们的 `mcpServers` 条目会被合并。如果同一个 server 名称出现在多个文件中，优先级更高的配置会生效。这让 project-level 配置可以覆盖 user-level 条目（例如固定同一个 server 的不同版本），而不会影响其他项目。

### Flags

| Flag | 行为 |
|------|----------|
| `--mcp-config PATH` | 添加一个显式配置，作为最高优先级来源（会叠加在自动发现的配置之上） |
| `--no-mcp` | 完全禁用 MCP - 不加载任何 servers |

<Note>
    `--mcp-config` 和 `--no-mcp` 互斥。
</Note>

### Claude Code 兼容性

如果你的项目根目录已经有一个供 Claude Code 使用的 `.mcp.json`，Deep Agents Code 会自动读取它 - 无需额外设置。

## 配置格式

`mcpServers` 下的每个 key 都是一个 server 名称。该 server 的字段决定 Deep Agents Code 如何连接它。

### stdio servers（默认）

stdio servers 会作为子进程启动。Deep Agents Code 通过 stdin/stdout 与它们通信。

```json title="mcp-config.json"
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"],
      "env": {}
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "your-token" }
    }
  }
}
```

### SSE 和 HTTP servers

对于远程 MCP servers，把 `type` 设置为 `"sse"` 或 `"http"`，并提供 `url`：

```json title="mcp-config.json"
{
  "mcpServers": {
    "remote-api": {
      "type": "sse",
      "url": "https://api.example.com/mcp",
      "headers": { "Authorization": "Bearer your-token" }
    }
  }
}
```

### 字段参考

<AccordionGroup>
    <Accordion title="stdio（默认）">
        **必需：** `command`。**可选：** `args`、`env`，以及共享的 [tool-filter fields](#tool-filtering)。

        <ResponseField name="command" type="string" required>
            要运行的可执行文件。
        </ResponseField>

        <ResponseField name="args" type="string[]">
            传给命令的参数。
        </ResponseField>

        <ResponseField name="env" type="object">
            为子进程设置的环境变量。可用它传递 API keys 和其他凭据，而不把它们暴露在 shell history 中。
        </ResponseField>
    </Accordion>

    <Accordion title="sse">
        **必需：** `type: "sse"`、`url`。**可选：** `headers`、`auth`，以及共享的 [tool-filter fields](#tool-filtering)。

        <ResponseField name="type" type='"sse"' required>
            Transport 类型。用于 Server-Sent Events 的场景请使用 `"sse"`。
        </ResponseField>

        <ResponseField name="url" type="string" required>
            server endpoint URL。
        </ResponseField>

        <ResponseField name="headers" type="object">
            每次请求都会发送的 HTTP headers。通常用于认证。值支持 `${VAR}` 引用父 shell 环境变量（在 server 激活时解析）。
        </ResponseField>

        <ResponseField name="auth" type='"oauth"'>
            设置为 `"oauth"` 后，会通过 `dcode mcp login` 走 OAuth 登录流程，而不是提供 `Authorization` header。不能和 `Authorization` header 同时使用。参见 [OAuth login](#oauth-login)。
        </ResponseField>
    </Accordion>

    <Accordion title="http">

        <ResponseField name="type" type='"http"' required>
            Transport 类型。用于 streamable HTTP 的场景请使用 `"http"`。`streamable_http` 和 `streamable-http` 也被接受为别名。
        </ResponseField>

        <ResponseField name="url" type="string" required>
            server endpoint URL。
        </ResponseField>

        <ResponseField name="headers" type="object">
            每次请求都会发送的 HTTP headers。通常用于认证。值支持 `${VAR}` 引用父 shell 环境变量（在 server 激活时解析）。
        </ResponseField>

        <ResponseField name="auth" type='"oauth"'>
            设置为 `"oauth"` 后，会通过 `dcode mcp login` 走 OAuth 登录流程，而不是提供 `Authorization` header。不能和 `Authorization` header 同时使用。参见 [OAuth login](#oauth-login)。
        </ResponseField>
    </Accordion>
</AccordionGroup>

<Note>
    `type` 字段也可以写成 `transport`，以兼容其他 MCP clients。
</Note>

<Note>
    server 名称必须匹配 `[A-Za-z0-9_-]+`。名称会用作 OAuth token 文件的磁盘 basename，因此配置加载时会拒绝路径分隔符和其他 shell metacharacters。
</Note>

### Header 环境变量

Header values 支持从父 shell 进行 `${VAR}` 替换，并在 server 激活时解析，而不是在配置加载时解析。只有某个变量未设置时，只会让需要它的那个 server 失败，其他 server 仍会启动。

```json title=".mcp.json"
{
    "mcpServers": {
        "internal-api": {
            "type": "http",
            "url": "https://api.example.com/mcp",
            "headers": { "Authorization": "Bearer ${INTERNAL_API_TOKEN}" }
        }
    }
}
```

## 多个 servers

你可以按需配置任意多个 servers。所有 server 的工具会被合并，并提供给 agent：

```json title="mcp-config.json"
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/projects"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "ghp_..." }
    },
    "database": {
      "type": "sse",
      "url": "https://db-mcp.internal:8080/mcp",
      "headers": { "Authorization": "Bearer ..." }
    }
  }
}
```

## Tool filtering

每个 server 都可以通过两个可选字段之一来缩小它暴露给 agent 的工具范围：

- `allowedTools`：只保留列出的工具，其他全部丢弃。
- `disabledTools`：丢弃列出的工具，其他全部保留。

这些过滤规则对 stdio、HTTP 和 SSE servers 都一样有效。以下两种情况在配置加载时都会被拒绝：

- 在同一个 server 上同时设置 `allowedTools` 和 `disabledTools`。
- 把任一字段设置成空列表（这会悄悄地把所有工具都删掉，或者什么也不做）。请直接省略该字段。

```json title=".mcp.json"
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"],
      "allowedTools": ["read_file", "list_directory"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "disabledTools": ["delete_repository", "delete_*_branch"]
    }
  }
}
```

### 匹配规则

每个条目可以是字面量工具名，也可以是 [`fnmatch`](https://docs.python.org/3/library/fnmatch.html) 风格的 glob（包含 `*`、`?` 或 `[` 的条目会被视为 pattern）。条目会同时匹配裸 MCP tool 名和 server 前缀形式（`{server}_{tool}`），所以任意一种写法都可以：

```json
{
  "allowedTools": ["read_file", "fs_list_*"]
}
```

<Note>
    匹配不到任何已加载工具的条目会被记录为 warning，而不是 error - 这样底层 MCP server 的工具列表即使跨版本变化，也不会破坏你的配置。
</Note>

<ResponseField name="allowedTools" type="string[]">
    要保留的工具名或 `fnmatch` glob pattern。该 server 的其他工具都会被丢弃。与 `disabledTools` 互斥。
</ResponseField>

<ResponseField name="disabledTools" type="string[]">
    要丢弃的工具名或 `fnmatch` glob pattern。该 server 的其他工具都会被保留。与 `allowedTools` 互斥。
</ResponseField>

## OAuth 登录

对于需要 OAuth 的远程 MCP servers（Slack、GitHub、Notion、Linear，以及其他托管的 MCP endpoints），请在 server 条目上设置 `"auth": "oauth"`，并运行一次登录子命令。token 会被持久化到磁盘，并自动刷新。

### 配置 server

```json title=".mcp.json"
{
    "mcpServers": {
        "linear": {
            "type": "http",
            "url": "https://mcp.linear.app/mcp",
            "auth": "oauth"
        }
    }
}
```

`auth: "oauth"` 与同一条目上的 `Authorization` header 互斥，并且不能用于 stdio server。

要把 Deep Agents Code 连接到 LangSmith，请使用 [LangSmith Remote MCP](/langsmith/langsmith-remote-mcp)：

```json title=".mcp.json"
{
    "mcpServers": {
        "langsmith": {
            "url": "https://api.smith.langchain.com/mcp",
            "transport": "http",
            "auth": "oauth"
        }
    }
}
```

### 运行登录流程

```bash
dcode mcp login linear
```

具体流程取决于 server 的 host：

- **符合规范的 servers**（默认）：Deep Agents Code 会执行 Dynamic Client Registration，在浏览器中打开 Authorization Code + PKCE 流程，并要求你把重定向后的 URL 粘贴回终端。
- **Slack**（`slack.com`、`*.slack.com`）：同样是粘贴回传流程，但预置了 Slack 的 public client。系统会提示你输入一个可选的 team ID（例如 `T01234567`），以便把 app 安装到正确的 workspace。
- **GitHub**（`api.githubcopilot.com`）：RFC 8628 Device Authorization Grant。Deep Agents Code 会打印 verification URL 和 user code；你在浏览器中输入 code，Deep Agents Code 会轮询完成情况。

默认情况下，`dcode mcp login` 会读取 Deep Agents Code 运行时使用的同一套自动发现配置（受 project-level trust gating 影响）。传入 `--config <path>` 可以指定某个文件：

```bash
dcode mcp login linear --config ./mcp-config.json
```

<Warning>
    未被信任的 project-level configs 会在 `mcp login` 中被跳过（见 [Project-level trust](#project-level-trust)），以防攻击者控制的 `headers` 条目通过 `${VAR}` 替换外泄本地 secret。可以先在这个项目里运行一次 `dcode` 来批准配置，或者显式传入 `--config <path>`。
</Warning>

### Token 存储

token 会写入：

```text
~/.deepagents/.state/mcp-tokens/<server>-<sha256-16(url)>.json
```

`<sha256-16(url)>` 段是 server URL 的 SHA-256 前 16 个十六进制字符。这个目录的模式会锁定为 `0700`，每个 token 文件的模式为 `0600`。文件包含 OAuth access token、refresh token 和动态注册的 client 信息，全部放在一个带 schema version 的 payload 里，并以原子方式写入（先写临时文件，再 `rename`）。

<Note>
    把 URL 哈希到文件名里，意味着同一个 server 名称如果指向不同 URL（例如 dev 和 prod），会拥有独立的 token 文件，不会互相覆盖。
</Note>

### 重新认证

当运行时 refresh 失败（refresh token 过期或被撤销）时，Deep Agents Code 会把 server 标记为 `unauthenticated`，而不是让 agent 崩溃。欢迎横幅会显示未认证 server 的数量，`/mcp` 也会报告每个 server 的原因。重新运行 `dcode mcp login <server>` 即可刷新凭据 - 你的对话会继续，不需要重启。

## Server 状态

每个配置好的 server 在启动后都会进入以下三种状态之一：

| 状态 | 含义 |
|--------|---------|
| `ok` | 已连接；工具已加载并可供 agent 使用 |
| `unauthenticated` | 需要 OAuth 登录，或者 refresh 失败 - 运行 `dcode mcp login <server>` |
| `error` | 预检查、发现或 transport 设置失败；会附带错误信息 |

单个 server 失败不再会中止启动。agent 会用成功启动的 server 继续运行，欢迎横幅会在工具数量旁显示未认证和出错 server 的计数。打开交互式会话中的 `/mcp`，可以查看每个 server 的状态、transport、工具列表以及非 `ok` 条目的失败原因。这个查看器会在 server 连接时实时更新，并支持 `tab` / `shift+tab` 导航。

## Project-level trust

Project-level configs 可能包含会执行本地命令的 stdio servers，也可能包含其 `headers` 会从环境中插入 `${VAR}` 的远程 servers。为了防止不受信任的仓库在 CLI 启动时运行任意代码或外泄本地 secret，Deep Agents Code 对 project-level 条目采用 **默认拒绝** 策略。

### 工作方式

- **交互模式：** Deep Agents Code 会在激活 project servers 之前请求批准，并显示每个 stdio command 和 remote URL。批准结果会通过 SHA-256 内容指纹持久化 - 如果配置发生变化，就会再次询问。
- **非交互模式（`-n`）：** 除非传入 `--trust-project-mcp`，否则 project servers 会被静默跳过。
- **对 stdio 和 remote 条目同样适用信任控制** - 在预检查探测期间，remote servers 可以 SSRF 到 localhost 或云元数据 endpoint，并通过 headers 外泄 `${VAR}` 值，所以它们也按同样方式受限。
- **用户级配置**（`~/.deepagents/.mcp.json`）始终被信任 - 与 `config.toml` 和 `hooks.json` 相同的信任模型。
- **`dcode mcp login`** 也会遵循 project trust：未被信任的 project-level config 会在登录发现阶段被跳过，这样攻击者控制的远程条目就无法在 OAuth 握手中拉取 secret。

### Flags

| Flag | 行为 |
|------|----------|
| `--trust-project-mcp` | 无需提示即可信任所有 project-level stdio servers（用于 CI 和自动化） |

```bash
# 跳过批准提示
dcode --trust-project-mcp

# 非交互式：显式信任 project servers
dcode -n "run tests" --trust-project-mcp
```

### 信任存储

信任决策存放在 `~/.deepagents/.state/mcp_trust.json`：

```json
{
  "version": 1,
  "projects": {
    "/Users/you/myproject": "sha256:abc123..."
  }
}
```

`projects` 下的每个 key 都是一个绝对项目根路径。value 是项目级配置内容拼接后的 SHA-256 digest。要撤销信任，可以删除对应条目，或者修改项目的 `.mcp.json`（这会自动使指纹失效）。

<Warning>
    一个被信任的 stdio MCP server 拥有与你的用户账户相同的权限。只应批准你信任的仓库中的 servers。接受之前，请先检查批准提示里显示的命令。
</Warning>

## System prompt 感知

连接的 MCP servers 及其工具会自动列入 agent 的 system prompt，并按 server 名称和 transport type 分组。这能帮助模型推理工具来源和故障域，而无需手动塞入上下文。

## 故障排查

<AccordionGroup>
    <Accordion title="Server 启动失败（stdio）">
        在 Deep Agents Code 外部验证命令是否可运行：

        ```bash
        npx -y @modelcontextprotocol/server-filesystem /tmp
        ```

        常见原因：package 没安装、`npx` 不在 `PATH` 中，或者需要的环境变量缺失。
    </Accordion>

    <Accordion title="Connection refused（SSE/HTTP）">
        检查远程 server 是否正在运行，以及 URL 是否正确。如果 server 需要认证，请确保 `headers` 中包含正确凭据。
    </Accordion>

    <Accordion title="Tools 不出现">
        Deep Agents Code 会在启动时打印已加载工具数量（例如 `✓ Loaded 3 MCP tools`）。如果你看到 `0`，说明 server 启动成功，但没有声明任何工具 - 请检查 server 自己的日志或文档。
    </Accordion>

    <Accordion title="`/mcp` 中显示 `unauthenticated`">
        要么你还没有运行 `dcode mcp login <server>`，要么已持久化的 refresh token 在 server 端过期或被撤销。重新运行登录命令即可 - 你的会话会继续，等 token 刷新后 server 会重新接上。
    </Accordion>

    <Accordion title="`Invalid MCP config at ...`">
        预检查验证拒绝了 `--mcp-config`（或自动发现的 `.mcp.json`）。常见原因：不受支持的 server 名称（必须匹配 `[A-Za-z0-9_-]+`）、stdio server 上设置了 `auth: oauth`、同一个条目同时设置了 `command` 和 `url`，或者某个 header 值不是字符串。修正高亮原因后重新启动 - Deep Agents Code 不再在配置错误时打印多页子进程 trace。
    </Accordion>

    <Accordion title="`${VAR}` header 引用失败">
        header interpolation 会在激活时运行，因此某个变量未设置时，只会让需要它的 server 失败。请在父 shell 中导出该变量，或者把它加到 `~/.deepagents/.env`。要排查问题，可以设置 `DEEPAGENTS_CODE_DEBUG=1`，然后查看关闭时 stderr 打印的每会话日志路径。
    </Accordion>
</AccordionGroup>
