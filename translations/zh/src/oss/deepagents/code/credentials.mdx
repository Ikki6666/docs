Deep Agents Code 需要你使用的每个模型 provider 的 API key。推荐的添加方式是 [`/auth`](#use-%2Fauth-recommended) 凭据管理器。对于非交互式运行，可以使用 [`dcode auth`](#manage-credentials-from-the-shell-dcode-auth) 从 shell 管理相同的已存储 key，或改为设置[环境变量](#environment-variables-ci-and-headless)。

如果同一个 key 在多个地方被设置，哪个优先请参见 [Key resolution order](#key-resolution-order)。

`.env` 加载顺序和 `DEEPAGENTS_CODE_` prefix 请参见 [Configuration](/oss/deepagents/code/configuration#environment-variables)。

## 使用 `/auth`（推荐）

从任意会话打开凭据管理器：

```txt
/auth
```

管理器会列出已安装的 LLM provider 以及它们是否设置了环境 key，呈现你可以从应用内添加的已知 provider，并包含 Tavily web search 等非模型服务。选择一个 provider 可以添加或替换它的 key，为未安装的 provider 安装支持，或移除你已经存储的某个。你添加的 key 会跨会话保持。

<Accordion title="Provider 行标签" icon="list-check">
    每一行显示 provider 名称，后跟它的 key 的来源：

    | 标签 | 含义 |
    |-------|---------|
    | `[stored]` | 通过 `/auth` 保存在此管理器中的 key |
    | `[env: VARNAME]` | key 来自环境变量 `VARNAME`（解析后的名称，例如 `DEEPAGENTS_CODE_OPENAI_API_KEY` 或 `OPENAI_API_KEY`） |
    | `[missing]` | 没有 key 被存储且环境变量未设置；选择该行以粘贴一个 |
</Accordion>

`/auth` 提示中还有一个可选的 **base URL** 字段。留空以使用 provider 的默认端点，或设置一个自定义端点与此 key 一起使用。base URL 会与 key 一起保存。端点如何解析（包括通过 gateway）请参见 [Endpoints, keys, and gateways](/oss/deepagents/code/config-file#endpoints-keys-and-gateways)。

<Warning>
    存储的 base URL 不是密钥，可能会被记录；与它配对的 key 永远不会被记录。
</Warning>

<Note>
    key 的作用域是你在这台机器上的用户账户—Deep Agents Code 除了将它们发送到已配置 provider 的 API 之外，不会传输到任何地方。
</Note>

### 使用 ChatGPT 登录

在 `/auth` 中选择 `openai_codex` provider 会启动浏览器登录，而不是提示输入 API key，让你可以使用 ChatGPT 订阅来使用 OpenAI 模型。要重新认证或退出登录，请再次选择 `openai_codex`。完整流程请参见 [Sign in with ChatGPT (Codex models)](/oss/deepagents/code/providers)。

`/auth` 管理 LLM provider 凭据、Tavily web-search key 和 LangSmith tracing。输入 Tavily key 可以在下次启动时[激活 web search](#enable-web-search-with-tavily)。输入 LangSmith key 可以启用 tracing。key 也会从环境中读取。你可以[在 `~/.deepagents/.env` 或你的 shell 中设置它们](/oss/deepagents/code/configuration#environment-variables)。

## 从 shell 管理凭据（`dcode auth`）

`dcode auth` 命令组是 `/auth` 管理器的可脚本化等价物：它无需启动 TUI 即可管理相同的已存储凭据，这使它适用于 dotfile 引导、CI/CD，以及通过 SSH 在远程机器上设置 key。子命令与模态框的动作一一对应：

| 命令 | 说明 |
|---------|-------------|
| `dcode auth list`（别名 `ls`） | 列出每个已知 provider 及其 key 的解析来源 |
| `dcode auth status <provider>` | 打印某个 provider 的解析来源 |
| `dcode auth set <provider>` | 存储 API key，默认从 stdin 读取 |
| `dcode auth remove <provider>`（别名 `rm`、`delete`） | 删除已存储的凭据 |
| `dcode auth path` | 打印凭据存储（`auth.json`）的解析路径 |

`set` 默认从 **stdin** 读取 key，因此它永远不会进入 shell 历史或 `argv`。通过管道传入 key，或使用 `--from-env VAR` 从进程环境变量复制：

```bash
# Pipe the key in (stdin)
echo "$ANTHROPIC_API_KEY" | dcode auth set anthropic

# Copy it from an existing environment variable
dcode auth set openai --from-env OPENAI_API_KEY
```

<Note>
    `set` 会拒绝在交互式终端中运行，以避免意外调用因等待输入而挂起—请通过 stdin 管道传入 key 或使用 `--from-env VAR`。存储的 key 走与 `/auth` 相同的存储，因此警告（例如关于 `auth.json` 的文件权限）会输出到 stderr。
</Note>

移除已存储的 key 或打印存储位置：

```bash
dcode auth remove anthropic
dcode auth path
```

<Note>
    `dcode auth set` 只管理 API key。`openai_codex` provider 使用 ChatGPT 浏览器登录而不是 API key，因此请运行 [`/auth` 并选择 `openai_codex`](#sign-in-with-chatgpt) 来登录。`dcode auth remove openai_codex` 确实会让你退出登录。
</Note>

## 环境变量（CI 与 headless）

对于非交互式运行、CI/CD 流水线，或任何没有 TUI 的场景，在你的 shell 中导出 provider 的环境变量：

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
export OPENAI_API_KEY="sk-..."

# Prefix with DEEPAGENTS_CODE_ to scope a key to Deep Agents Code only,
# leaving a shared key used by other CI steps untouched
export DEEPAGENTS_CODE_OPENAI_API_KEY="sk-..."
```

要把 key 保存在文件中，请在[`.env` 文件](/oss/deepagents/code/configuration#environment-variables)中定义它们。

## Key 解析顺序

当某个 provider 的 key 在多个地方被设置时，Deep Agents Code 使用以下第一个已设置的：

1. **带 `DEEPAGENTS_CODE_` 前缀的环境变量**—例如作为内联 shell 导出的 `DEEPAGENTS_CODE_OPENAI_API_KEY`。[`DEEPAGENTS_CODE_` prefix](/oss/deepagents/code/configuration#deepagents_code_-prefix) 是显式的“在 Deep Agents Code 中使用此 key”的覆盖。
2. **应用存储的 key**—在 `/auth` 凭据管理器中输入的。
3. **普通 provider 环境变量**—例如来自你的 shell 或 `.env` 文件的 `OPENAI_API_KEY`。

应用存储的 key 会优先于同一个 provider 的普通环境变量 key，但带 `DEEPAGENTS_CODE_` 前缀的 key 会优先于应用存储的 key。该前缀是为单次运行覆盖已存储 key 的方式，且无需清除它：

```bash
# With a key already stored via /auth, a plain env var does not override it.
# dcode still uses the app-stored key for this run:
OPENAI_API_KEY=sk-xxxx dcode -n "..."

# The DEEPAGENTS_CODE_ prefix does override it, for this run only:
DEEPAGENTS_CODE_OPENAI_API_KEY=sk-xxxx dcode -n "..."
```

这种分层设计服务于常见场景：你的机器已经为其他目的导出了一个普通 provider 变量—被其他工具、脚本或 CI 使用的共享 `OPENAI_API_KEY`—而你不希望 Deep Agents Code 复用它。应用存储的 key 或带 `DEEPAGENTS_CODE_` 前缀的变量为 Deep Agents Code 提供自己的值，同时让不带前缀的那个保持原样供其他用途使用，两者永远不会混用。

每个 provider 的 API key 与其端点（`base_url`）作为一个配对从同一来源解析。请参见 [Endpoints, keys, and gateways](/oss/deepagents/code/config-file#endpoints-keys-and-gateways)。

## 使用 Tavily 启用 web search

内置的 `web_search` 工具使用 [Tavily](https://tavily.com)。在你提供 key 之前，Deep Agents Code 会在启动时显示“Web search disabled”通知。你可以把 key 存储在 [`/auth`](#use-%2Fauth-recommended) 凭据管理器中（Tavily 在那里显示为非模型服务），或设置 `TAVILY_API_KEY` 环境变量。

<Tabs>
    <Tab title="使用 /auth（推荐）">
        从 [tavily.com](https://tavily.com) 获取 key（以 `tvly-` 开头；免费额度足以满足大多数 Deep Agents Code 用法），然后将其存储在凭据管理器中：

        ```txt
        /auth
        ```

        从列表中选择 **Tavily** 并粘贴 key。你也可以从“Web search disabled”通知中直接进入该提示，方法是选择 **Enter API key**。
    </Tab>

    <Tab title="设置环境变量">
        <Steps>
            <Step title="获取 key">
                在 [tavily.com](https://tavily.com) 注册并复制 key（以 `tvly-` 开头）。免费额度足以满足大多数 Deep Agents Code 用法。
            </Step>

            <Step title="添加到你的环境">
                将 key 添加到 `~/.deepagents/.env`，这样每个会话都会读取它：

                ```bash title="~/.deepagents/.env"
                TAVILY_API_KEY=tvly-...
                ```

                shell 导出优先于 `.env` 值（参见 [Loading order and precedence](/oss/deepagents/code/configuration#loading-order-and-precedence)）。要把 key 限定到 Deep Agents Code 而不影响读取 `TAVILY_API_KEY` 的其他工具，请使用 [`DEEPAGENTS_CODE_` prefix](/oss/deepagents/code/configuration#deepagents_code_-prefix)：`DEEPAGENTS_CODE_TAVILY_API_KEY=tvly-...`。
            </Step>

            <Step title="重载或重启">
                在已有会话中，运行 `/reload` 重新读取 `.env` 文件。在下次启动时，“Web search disabled”通知会消失，agent 可以调用 `web_search`。
            </Step>
        </Steps>
    </Tab>
</Tabs>
