Deep Agents Code 使用 [sandbox as tool](/oss/deepagents/sandboxes#sandbox-as-tool-pattern) 模式：`dcode` 进程（LLM loop、memory、tool dispatch）运行在你的机器上，但 agent tool calls（`read_file`、`write_file`、`execute` 等）目标是远程 sandbox，而不是你的本地文件系统。要把文件放进 sandbox，可以使用 [setup script](#setup-scripts) 或 provider 的文件传输 API（见 [Working with files](/oss/deepagents/sandboxes#working-with-files)）。

如果想更深入了解 sandbox 架构、集成模式和安全最佳实践，请参见 [Sandboxes](/oss/deepagents/sandboxes)。

## Sandbox flags 和示例

| Flag | Description |
|------|-------------|
| `--sandbox TYPE` | 要使用的 sandbox provider。内置值：`langsmith`、`agentcore`、`daytona`、`modal`、`runloop`、`vercel`（默认：`none`）。[Third-party](#third-party-providers) 和 [config-declared](#config-declared-providers) providers 也可以接受。若要使用 `[sandboxes].default`，可以传入不带值的 `--sandbox` |
| `--sandbox-id ID` | 复用一个已有 sandbox 的 ID，而不是创建新的。会跳过创建和清理。仅适用于支持按 ID reattach 的 provider。更多信息请参考你的 sandbox 文档 |
| `--sandbox-snapshot-name NAME` | 使用或创建一个 sandbox snapshot。`langsmith` 和 `runloop` 支持（以及任何声明了 snapshot support 的第三方 provider）。不能和 `--sandbox-id` 一起使用 |
| `--sandbox-setup PATH` | 创建 sandbox 后要在其中运行的 setup script 路径 |

每个 provider 都会在 sandbox 内暴露一个默认工作目录。setup scripts 和 `execute` commands 会从这个目录运行，除非被覆盖：

| Provider | Working directory |
|----------|-------------------|
| LangSmith | `/root` |
| AgentCore | `/tmp` |
| Daytona | `/home/daytona` |
| Modal | `/workspace` |
| Runloop | `/home/user` |
| Vercel | `/vercel/sandbox` |
| E2B | `/home/user` |

示例：

```bash
# 创建一个新的 LangSmith sandbox
dcode --sandbox langsmith

# 复用一个已有 sandbox（跳过创建和清理）
dcode --sandbox runloop --sandbox-id dbx_abc123

# 在 sandbox 创建后运行 setup script
dcode --sandbox modal --sandbox-setup ./setup.sh

# 使用 config 中 [sandboxes].default 指定的 provider
dcode --sandbox
```

<Note>
    由于 `--sandbox` 接受一个可选值，请把不带值的 bare form 放在命令行最后。否则后面的参数（例如 `dcode --sandbox agents`）会被当作该 flag 的值。为了避免歧义，建议直接传入显式 provider 名称。
</Note>

## 可插拔 providers

上面的 built-in providers 并不是唯一选项。Deep Agents Code 会从三个来源发现 sandbox providers，因此你可以使用其他 package 提供的 provider，或者自己声明一个，而无需修改 Deep Agents Code：

1. **Built-in providers** - LangSmith、AgentCore、Daytona、Modal、Runloop 和 Vercel，随 `deepagents-code` 一起发布（LangSmith 默认包含，其余作为 extras）。
2. **[Third-party providers](#third-party-providers)** - 其他已安装 package 通过 Python entry point 发布的 provider。
3. **[Config-declared providers](#config-declared-providers)** - 在 `~/.deepagents/config.toml` 中定义的 provider。

当两个来源定义了同名 provider 时，**config 的优先级高于 third-party entry points，而 third-party entry points 的优先级又高于 built-ins**，因此你的配置文件始终可以覆盖自动发现结果。

### Third-party providers

某个 package 可以通过 `deepagents_code.sandbox_providers` [entry-point group](https://packaging.python.org/en/latest/specifications/entry-points/) 发布 sandbox provider。一旦安装该 package，它的 provider 就会自动出现在 `--sandbox` 中 - 无需配置：

```bash
# 安装发布该 provider 的 package，然后直接使用它
dcode --sandbox acme
```

例如，`langchain-e2b` package 会发布一个 `e2b` provider（见 [sandbox integrations](/oss/integrations/sandboxes)）。把它作为 package 安装，设置凭据，然后选中它：

```bash
dcode --install langchain-e2b --package
export E2B_API_KEY="..."
dcode --sandbox e2b
```

如果你传入一个尚未安装或尚未声明的 `--sandbox` 名称，Deep Agents Code 会列出可用 provider，并解释如何安装或配置缺失的那个。

<Accordion title="发布一个 sandbox provider" icon="package">
    如果你想把 provider 发布出去，让用户安装你的 package 后即可运行 `dcode --sandbox <name>`，请实现一个 `SandboxProvider` 子类，并把它注册到 `deepagents_code.sandbox_providers` entry-point group。

    覆盖 `metadata` 属性，这样 Deep Agents Code 就能在不实例化 provider 的情况下暴露它的工作目录和能力标志：

    ```python
    from deepagents_code.integrations.sandbox_provider import (
        SandboxInstallHint,
        SandboxProvider,
        SandboxProviderMetadata,
    )


    class AcmeProvider(SandboxProvider):
        @property
        def metadata(self) -> SandboxProviderMetadata:
            return SandboxProviderMetadata(
                name="acme",
                working_dir="/workspace",
                install=SandboxInstallHint(kind="package", name="acme-dcode-sandbox"),
                supports_sandbox_id=True,
                supports_snapshot_name=False,
            )

        def get_or_create(self, *, sandbox_id=None, **kwargs):
            ...  # return a SandboxBackendProtocol

        def delete(self, *, sandbox_id, **kwargs):
            ...
    ```

    实现 `get_or_create` 和 `delete`；异步调用者会由 base class 处理。然后在 package 的 `pyproject.toml` 中注册 entry point：

    ```toml
    [project.entry-points."deepagents_code.sandbox_providers"]
    acme = "acme_sandbox.provider:AcmeProvider"
    ```

    如果省略 `metadata` 属性，则会使用通用默认值（`/workspace`，不支持快照）。
</Accordion>

### 配置声明的 providers

对于不想打包的内部或本地 provider，可以在 `~/.deepagents/config.toml` 的 `[sandboxes.providers]` 下声明它。这与[任意模型 provider](/oss/deepagents/code/config-file#arbitrary-providers) 类似，并使用相同的 `class_path` 信任模型。

```toml
[sandboxes]
# 未给 `dcode --sandbox` 传值时使用。
default = "acme"

[sandboxes.providers.acme]
# 必填：要导入的 provider class，格式为 module.path:ClassName。
class_path = "acme_sandbox.provider:AcmeProvider"
# 沙箱内的默认工作目录。
working_dir = "/workspace"
# provider 依赖缺失时建议安装的 package。
package = "acme-dcode-sandbox"
# 能力标志（默认值：supports_sandbox_id = true，supports_snapshot_name = false）。
supports_sandbox_id = true
supports_snapshot_name = false

# 转发给 provider get_or_create() 的额外关键字参数。
[sandboxes.providers.acme.params]
region = "us-east-1"
```

<ResponseField name="class_path" type="string" post={["required"]}>
    `module.path:ClassName` 格式的完整 provider class。Deep Agents Code 会导入并实例化这个 class 来作为 provider。
</ResponseField>

<ResponseField name="working_dir" type="string" post={["optional"]}>
    沙箱内的默认工作目录。默认值为 `/workspace`。
</ResponseField>

<ResponseField name="package" type="string" post={["optional"]}>
    provider 依赖缺失时在错误消息中建议安装的 package 名称。
</ResponseField>

<ResponseField name="supports_sandbox_id" type="boolean" post={["optional"]}>
    是否允许此 provider 使用 `--sandbox-id` 重新连接。默认值为 `true`。
</ResponseField>

<ResponseField name="supports_snapshot_name" type="boolean" post={["optional"]}>
    是否允许此 provider 使用 `--sandbox-snapshot-name`。默认值为 `false`。
</ResponseField>

<ResponseField name="params" type="object" post={["optional"]}>
    转发给 provider 的 `get_or_create()` 的额外关键字参数。
</ResponseField>

复用内置 provider 名称的配置项会**覆盖**该内置 provider，同时保留它的依赖预检。格式错误的配置项会被跳过并给出 warning，而不是让启动崩溃。

<Warning>
    设置 `class_path` 会让 Deep Agents Code 从指定模块导入并运行任意 Python，模块级代码会在导入时执行。这与模型 [`class_path`](/oss/deepagents/code/config-file#arbitrary-providers) 使用相同的信任模型：你控制自己的机器和自己的配置文件。
</Warning>

## 设置脚本

使用 `--sandbox-setup` 可以在沙箱创建后，在沙箱内运行 shell 脚本。这适合用于克隆仓库、安装依赖和配置环境变量。

```bash title="setup.sh"
#!/bin/bash
set -e

# Clone repository using GitHub token
git clone https://x-access-token:${GITHUB_TOKEN}@github.com/username/repo.git $HOME/workspace
cd $HOME/workspace

# Make environment variables persistent
cat >> ~/.bashrc <<'EOF'
export GITHUB_TOKEN="${GITHUB_TOKEN}"
export OPENAI_API_KEY="${OPENAI_API_KEY}"
cd $HOME/workspace
EOF
source ~/.bashrc
```

Deep Agents Code 会使用你的本地环境变量展开设置脚本中的 `${VAR}` 引用。把 secrets 存在本地 `.env` 文件中，供设置脚本访问。

<Warning>
    沙箱会隔离代码执行，但代理仍然容易受到不可信输入中的 prompt injection 影响。请只使用 human-in-the-loop approval、短期 secrets 和可信的设置脚本。更多详情请参见[安全注意事项](/oss/deepagents/sandboxes#security-considerations)。
</Warning>
