Deep Agents Code（`dcode`）在启动时接受命令行 flag，并提供了用于 tools、agents、会话、skills、凭据和配置的管理子命令。当你需要从 shell 覆盖默认值、在脚本中运行非交互式任务，或在不打开会话的情况下自动执行管理操作时，可将本页面作为参考。安装和日常交互式使用请参见 [Quickstart](/oss/deepagents/code/quickstart)。CLI flag 如何融入更广泛的配置模型，请参见 [Configuration](/oss/deepagents/code/configuration)。

## 示例用法

```bash
# Use a specific agent configuration
dcode --agent mybot

# Use a specific model (provider:model format or auto-detect)
dcode --model anthropic:claude-opus-4-8
dcode --model gpt-5.5

# Auto-approve tool usage (skip human-in-the-loop prompts)
dcode -y

# List directory contents, then summarize directory as first prompt—the command runs first, then the prompt is submitted
# The prompt does NOT have access to the command output
dcode --startup-cmd "ls -la" -m "Summarize what's in this directory"

# Non-interactive with startup command: show git status before the task runs
# The task does NOT have access to the command output
dcode --startup-cmd "git diff --stat" -n "Review these changes"
```

## 选择模型

启动时使用 `--model`（`-M`）可以为单个会话固定模型。使用 `provider:model` 格式（例如 `openai:gpt-5.5`），或在 provider 无歧义时传入裸模型名称：

```bash
dcode --model anthropic:claude-opus-4-8
dcode --model openai:gpt-5.5
dcode --model fireworks:accounts/fireworks/models/deepseek-v4-pro
```

当 Deep Agents Code 在没有 `--model` 的情况下启动时，会按以下顺序解析模型：

1. **`--model` flag**（如果提供）。
2. `~/.deepagents/config.toml` 中的 **`[models].default`**。
3. `~/.deepagents/config.toml` 中的 **`[models].recent`**（在会话中切换模型时自动写入）。
4. **环境自动检测**：`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`GOOGLE_API_KEY` 和 `GOOGLE_CLOUD_PROJECT`（Gemini Enterprise Agent Platform）中第一个可用的凭据。

其他 provider（例如 Groq 或 Fireworks）仍然可以通过 `--model` 或保存的默认值使用，即使它们不在启动自动检测列表中。完整的 provider 列表和凭据设置请参见 [Model providers](/oss/deepagents/code/providers)。

### 设置或清除默认模型

为之后的所有启动持久化一个默认模型：

```bash
# Set the default
dcode --default-model anthropic:claude-opus-4-8

# View the current default
dcode --default-model

# Clear the default
dcode --clear-default-model
```

你也可以在交互式 `/model` 切换器（`Ctrl+S`）中固定默认值，或在 `config.toml` 中设置 `[models].default`。请参见 [Set a default model](/oss/deepagents/code/providers#set-a-default-model)。

### 设置 reasoning effort

`/effort` 控制当前模型的 reasoning effort。打开选择器可以看到该模型支持的级别，或使用 `/effort <level>` 直接传入级别。

Deep Agents Code 会按 `provider:model` 把选择保存在 `~/.deepagents/config.toml` 中，供以后的会话使用。运行 `/effort clear` 可以移除当前模型保存的偏好和会话覆盖。已配置的模型参数仍然可以提供 effort 值。

你可以在 agent 工作时打开 `/effort` 或点击页脚的 effort 标签。选择会等待当前任务完成；它不会改变已经在进行中的模型请求。如果模型在选择应用之前发生了变化，请为新的模型重新打开选择器。

对于 `thinking.type` 设置为 `between_tools` 的 Anthropic 模型，可用级别是 `low`、`medium` 和 `high` 中模型支持的子集。

### 选择摘要模型

为自动上下文压缩、`/offload` 和 `/compact` 使用单独的模型，而无需更改主 agent 模型：

```bash
# Set the summarization model for this launch
dcode --summarization-model openai:gpt-5.6-sol
```

在交互式会话中，运行 `/offload model` 打开模型选择器，传入模型 spec 直接切换，或传入 `clear` 以复用主 agent 模型：

```text
/offload model
/offload model openai:gpt-5.6-sol
/offload model clear
```

摘要模型按以下顺序解析：`--summarization-model`，然后是 `config.toml` 中的 `[models].summarization_default`，最后是主 agent 模型。请参见 [Set a summarization model](/oss/deepagents/code/config-file#set-a-summarization-model)。

### 模型参数与 profile 覆盖

使用 `--model-params` 以 JSON 字符串形式向模型传入额外的构造函数 kwargs。这些参数仅对当前会话生效，并覆盖 `config.toml` 的 provider 参数：

```bash
dcode --model openai:gpt-5.5 --model-params '{"reasoning": {"effort": "high"}}'
dcode --model anthropic:claude-opus-4-8 --model-params '{"thinking": {"type": "enabled", "budget_tokens": 10000}, "max_tokens": 16000}'
```

使用 `--profile-override` 覆盖 [model profile](/oss/langchain/models#model-profiles) 字段（例如 `max_input_tokens`）。值会合并到配置文件覆盖之上，并在会话中途的 `/model` 热切换之间持久保持：

```bash
dcode --profile-override '{"max_input_tokens": 4096}'
dcode --model google_genai:gemini-3.6-flash --profile-override '{"max_input_tokens": 4096}'
```

对于瞬时错误的 retry 次数，请使用 `--max-retries` 或 `config.toml` 中的 `[retries]` 部分。请参见 [Model parameters](/oss/deepagents/code/providers#model-parameters) 和 [Profile overrides](/oss/deepagents/code/config-file#profile-overrides-advanced)。

### 安装 provider extras

可选的 provider 和 sandbox 包以 extras 形式提供。无需启动会话即可从 shell 安装：

```bash
dcode --install groq
dcode --install fireworks
dcode --install ollama
```

添加 `--package` 可以通过 `uv --with` 安装任意 provider 包（参见 [Arbitrary providers](/oss/deepagents/code/config-file#arbitrary-providers)），添加 `--yes` 可以跳过确认提示。要在初始 CLI 安装期间预装 extras，请设置 `DEEPAGENTS_CODE_EXTRAS`（例如 `DEEPAGENTS_CODE_EXTRAS="groq,fireworks"`）。

### 移除可选 extra

在保留 Deep Agents Code 其余安装的前提下移除一个已安装的 extra：

<CodeGroup>
    ```bash Shell
    dcode uninstall groq
    dcode --uninstall groq
    ```

    ```text In session
    /uninstall groq
    ```
</CodeGroup>

移除操作会重建一个不含所选 extra 的 uv tool 安装，同时保留 interpreter、release channel、其他 extras，以及通过 `--package` 安装的包。

## Agents 与会话

使用 `-a`/`--agent` 可以以命名 agent 启动，该 agent 在 `~/.deepagents/<agent_name>/` 下拥有自己的 memory、skills 和 `AGENTS.md`。该 flag 会覆盖 `config.toml` 中的 `[agents].default` 和 `[agents].recent`：

```bash
dcode --agent backend-dev
```

使用 `-r`/`--resume` 恢复之前的对话。不传 ID 会打开最近的 thread，传入 thread ID 则会恢复特定会话。恢复会绕过 agent 选择 flag，并恢复该 thread 原来的 agent：

```bash
dcode -r
dcode -r abc123-thread-id
```

使用 `dcode threads list` 和 `dcode threads delete` 列出和删除会话。每个 agent 的 memory 如何工作请参见 [Memory and skills](/oss/deepagents/code/memory-and-skills)。

## 非交互式模式与管道

使用 `-n`/`--non-interactive` 可以在没有交互式 UI 的情况下运行单个任务。每次非交互式运行都会开始一个全新的 thread；基于文件的状态（memory、skills、配置）会在多次调用之间保持：

```bash
dcode -n "Write a Python script that prints hello world"
```

当 stdin 通过管道传入时，Deep Agents Code 会自动以非交互方式运行：

```bash
echo "Explain this code" | dcode
cat error.log | dcode -n "What's causing this error?"
git diff | dcode -n "Review these changes"
```

当你把管道输入与 `-n` 或 `-m` 结合使用时，管道内容会排在最前面，之后是 flag 文本。管道输入的最大大小为 10 MiB。使用 `--stdin` 可以显式从 stdin 读取，而不是自动检测。

### 输出、限制与 shell 访问

使用 `-q`/`--quiet` 可以只在 stdout 上输出 agent 的响应（适合管道传输给其他命令）。添加 `--no-stream` 可以在写入之前缓冲完整响应：

```bash
dcode -n "Generate a .gitignore for Python" -q > .gitignore
dcode -n "List dependencies" -q --no-stream | sort
```

添加 `--show-reasoning` 可以显示 provider 可见的 reasoning。在交互式会话中，reasoning 会流式输出到一个单独的行中，该行在阶段结束时折叠；按 `Ctrl+O` 可以重新打开它。在非交互式模式下，reasoning 会输出到 stderr，因此 stdout 上的最终答案仍可通过管道传输。该设置默认关闭，并对整个会话生效。持久配置请参见 [Show provider-visible reasoning](/oss/deepagents/code/config-file#show-provider-visible-reasoning)。

在 CI 中使用 `--max-turns` 或 `--timeout` 限制 agent 运行。两者在超出预算时都以退出码 124 退出。需要 `-n` 或管道 stdin：

```bash
dcode -n "fix the failing tests" --max-turns 10
dcode -n "run the test suite and summarise failures" --timeout 120
```

在非交互式模式下，shell 执行默认是禁用的。使用 `-S`/`--shell-allow-list` 启用它：

```bash
dcode -n "Run the tests and fix failures" -S "pytest,git,make"
dcode -n "Build the project" -S recommended
dcode -n "Fix the build" -S all
```

<Warning>
    `-S all` 允许 agent 在没有人工确认的情况下执行任意 shell 命令。
</Warning>

更多示例和 tracing 设置请参见 [Non-interactive mode and piping](/oss/deepagents/code/quickstart#non-interactive-mode-and-piping)。

## 启动时的 Skills

`--skill` flag 会在启动时立即调用一个 skill，交互式或非交互式模式均可：

```bash
dcode --skill code-review
dcode --skill code-review -m 'review the auth module'
cat diff.txt | dcode --skill code-review -n 'review this patch'
dcode --skill code-review -n 'review this patch' -q
```

`--skill` 与 `--quiet` 或 `--no-stream` 组合时需要 `-n`。使用 `dcode skills list`、`create`、`info` 和 `delete` 管理 skills。请参见 [Memory and skills](/oss/deepagents/code/memory-and-skills)。

## 脚本中的 Rubrics

非交互式运行无法暂停以进行交互式目标审查。当验收标准已知时，使用 `--rubric` 传入：

```bash
dcode -n "implement OAuth refresh handling" --rubric "tests pass; no unrelated files changed"
dcode -n "implement OAuth refresh handling" --rubric @acceptance.md
```

单独设置评分模型和迭代上限：

```bash
dcode -n "implement OAuth refresh handling" \
  --rubric "tests pass; no unrelated files changed" \
  --rubric-model openai:gpt-5.5 \
  --rubric-max-iterations 3
```

所有 rubric flag 都需要 `-n` 或管道 stdin。请参见 [Goals and rubrics](/oss/deepagents/code/goals-and-rubrics)。

## Human-in-the-loop 与 shell 访问

可能具有破坏性的 tool calls 默认需要批准。有三种 [approval modes](/oss/deepagents/code/approval-modes) 可供选择：默认的 Manual 模式要求在所有检查点进行确认；Auto 模式（`-y`/`--auto-approve`）使用 LLM 分类器；YOLO（`--yolo`）在没有任何审查的情况下运行受控操作。在交互式会话中用 `Shift+Tab` 在 Manual 和 Auto 之间切换：

```bash
dcode -y
dcode --yolo
```

`-S`/`--shell-allow-list` flag 在交互式和非交互式模式下都适用。传入以逗号分隔的命令名称列表，`recommended` 表示安全的只读默认值，`all` 表示允许任何命令。你也可以在环境中设置 `DEEPAGENTS_CODE_SHELL_ALLOW_LIST`。

## 限制文件系统工具

默认情况下，Deep Agents Code 会暴露所有文件系统工具。要只暴露其中一个子集，请传入以逗号分隔的列表：

```bash
dcode -n "Audit this repository" --allow-fs-tools ls,read_file,glob,grep
```

有效名称为 `ls`、`read_file`、`write_file`、`edit_file`、`delete`、`glob`、`grep` 和 `execute`。显式列表必须包含 `read_file`。该 allowlist 适用于主 agent 和同步 subagent，适用于所有会话模式，但不适用于异步 subagent 或非文件系统工具。

<Note>
    `--allow-fs-tools` 与 `-S`/`--shell-allow-list` 控制的是 shell 访问的不同层面：

    - **`--allow-fs-tools`** 控制哪些文件系统工具可用。shell 访问需要 `execute`。
    - **`-S`/`--shell-allow-list`** 控制哪些 shell 命令可以通过 `execute` 执行。它不影响其他文件系统工具。

    | `--allow-fs-tools` 包含 `execute`？ | `-S` 已设置？ | Shell 访问 |
    |---|---|---|
    | 是 | 是 | 允许的命令会运行（交互式模式会确认；非交互式模式自动批准） |
    | 是 | 否 | 工具存在，但没有任何命令被预先批准 |
    | 否 | 是 | 没有 shell 访问—`execute` 不存在，因此 `-S` 没有可控制的对象 |
    | 否 | 否 | 没有 shell 访问 |

    在非交互式模式下，同时传入两者可以在没有人工批准的情况下启用命令：

    ```bash
    dcode -n "Fix the failing tests" --allow-fs-tools execute -S "pytest,git,make"
    ```
</Note>

在会话中运行 [`/tools`](#diagnose-and-audit-a-session) 以检查当前的工具集。从 shell 调用时，把工具调整 flag 放在子命令之前：

```bash
dcode tools list
dcode --allow-fs-tools ls,read_file tools list
dcode --allow-fs-tools ls,read_file tools list --json
```

## 诊断与审计会话

dcode 提供只读斜杠命令，用于检查会话加载和消耗的内容：`/tools` 列出当前工具集，`/extensions` 列出已加载的 Python extension 注册项，`/context-doctor` 审计对话开始之前注入的上下文，`/cost` 报告该 thread 的估算消耗。可以用它们确认某个工具调整 flag 是否生效，或找出上下文意外增长的来源。

### 列出已加载的 Python extensions

在会话中运行 `/extensions` 可以列出每个 extension 注册项及其类型、名称、作用域和源路径。报告还会显示加载失败情况，以及图绑定更改是否需要 `/restart`。该命令和 Python extension 加载需要 `DEEPAGENTS_CODE_EXPERIMENTAL=1`。请参见 [Python extensions](/oss/deepagents/code/extensions)。

### 列出可用工具

在会话中运行 `/tools` 可以列出当前 agent 可以调用的工具，按内置工具和来自每个 MCP server 的工具分组：

```text
/tools
```

```text
**7 tools available**

### Built-in

| Tool | Description |
|---|---|
| read_file | Read a file from the filesystem |
| write_file | Write content to a file |
| execute | Run a shell command |
| web_search | Search the web |
| task | Launch a subagent |

### github

- create_issue
- search_repositories

MCP tool descriptions are available in /mcp.

### Unavailable MCP servers

| Server | Status |
|---|---|
| slack | needs login |
```

不可用的 MCP server 会显示在单独的表格中。更改 MCP 配置后运行 `/reload`，然后使用 `/tools` 验证当前工具集。非交互式等价方式请参见 [`dcode tools list`](#cli-commands)。

### 审计注入的上下文

在会话中运行 `/context-doctor` 可以审计会话注入到每次模型请求中的内容及其估算 token 成本。报告会将注入的上下文拆分为基础 system prompt、`AGENTS.md` memory 文件、skills 索引、内置工具 schema 和每个 MCP server 的工具 schema，然后统计 agent 在对话开始之前携带的总量：

```text
/context-doctor
```

```text
Fresh-session context audit (estimated tokens)

System prompt (base)                      ~6
AGENTS.md memory (1 files)            ~1,286
Skills index (1 loaded)                 ~477  largest: code-review ~15
Built-in tool schemas (1 tools)          ~13  sent with every request
MCP: docs (1 tool)                       ~31
MCP: broken                               ~0  connection failed
TOTAL injected before conversation  ~     1,813
Conversation history             ~     4,200
Provider-reported context              9,000
Unattributed / estimation delta       +2,987

Approximate: section counts use about four characters per token.
Trim skills or disable an MCP server, then run /context-doctor again.
```

较大的未归因增量或注入总量表明可能存在你想裁剪的上下文。更改 skills 或 MCP 配置后，再次运行 `/context-doctor` 以确认。

`/context-doctor` 与两个相关命令互补：

- [`/context`](/oss/deepagents/code/quickstart#inspect-context-window-usage) 显示上下文窗口当前有多满；`/context-doctor` 通过将 token 归因到每个注入的组件来解释原因。
- [`dcode doctor`](#run-diagnostics-dcode-doctor) 无需启动会话即可检查安装和配置的健康状况；`/context-doctor` 则从会话内部审计活动会话的上下文。

### 跟踪 thread 成本

在会话中运行 `/cost` 可以显示该 thread 以美元计的估算成本：

```text
/cost
```

```text
Estimated thread cost: $1.03

By type since this thread was loaded:
- Assistant: $0.87
- Subagents: $0.16

By model since this thread was loaded:
- anthropic:claude-sonnet-4-5: $1.03
```

总量包括来自 assistant、subagents、offloading、Auto 分类和 rubric 评分的模型调用。恢复或切换 thread 时该值会保持。估算使用 [genai-prices](https://github.com/pydantic/genai-prices) 目录；没有定价的请求会被排除。

使用 `/tokens` 查看估算背后的 token 计数。对于未覆盖的模型，请[添加自定义定价覆盖](/oss/deepagents/code/configuration#custom-pricing-overrides)。

### 提出附带问题

`/btw` 允许你在 agent 继续工作的同时就对话提出问题。输入 `/btw <question>`，或输入 `/btw` 打开问题输入框。答案会显示在一个临时对话框中，而不是主对话里。按 `Esc` 关闭它。

## 启动命令与初始 prompt

使用 `-m`/`--message` 可以在交互式会话启动时自动提交初始 prompt。与 `--startup-cmd` 组合可以先运行一个 shell 命令：

```bash
dcode --startup-cmd "git diff --stat" -m "Summarize these changes"
```

`--startup-cmd` 的输出会在记录中呈现供你参考，但**不会**加入 agent 的消息历史。要把命令输出交给 agent，请改为通过 stdin 管道传入：

```bash
git diff | dcode -n "Review these changes"
```

`--startup-cmd` 的非零退出和超时会发出警告，但不会中止会话。非交互式模式会对启动命令施加 60 秒超时。

## 远程 sandbox

使用 `--sandbox` 将代码执行路由到远程 sandbox。内置 provider 包括 `langsmith`、`agentcore`、`daytona`、`modal`、`runloop` 和 `vercel`。第三方和配置声明的 provider 也被接受。不传值直接使用 `--sandbox` 可以采用 `config.toml` 中的 `[sandboxes].default`：

```bash
dcode --sandbox langsmith
dcode --sandbox runloop --sandbox-id dbx_abc123
dcode --sandbox modal --sandbox-setup ./setup.sh
dcode --sandbox
```

<Note>
    由于 `--sandbox` 接受可选值，请将裸形式放在命令行**最后**。否则后面的参数（例如 `dcode --sandbox agents`）会被当作该 flag 的值。
</Note>

使用 `dcode --install` 安装 sandbox extras（例如 `dcode --install daytona` 或 `dcode --install all-sandboxes`）。provider 设置、工作目录和第三方 provider 请参见 [Remote sandboxes](/oss/deepagents/code/remote-sandboxes)。

## MCP flag

控制启动时 MCP server 的加载：

| Flag | 行为 |
|------|----------|
| `--mcp-config PATH` | 添加一个显式配置作为最高优先级来源（合并到自动发现的配置之上） |
| `--no-mcp` | 完全禁用 MCP |
| `--trust-project-mcp` | 对当前运行信任项目级 server 而不提示。被用户策略拒绝的 server 保持禁用。 |

`--mcp-config` 和 `--no-mcp` 互斥。在非交互式模式下，没有匹配的已保存或环境批准的项目 server 会被静默跳过，除非传入 `--trust-project-mcp`：

```bash
dcode --trust-project-mcp
dcode -n "run tests" --trust-project-mcp
```

使用 `dcode mcp login <server>` 为标记为 `auth: "oauth"` 的 MCP server 运行 OAuth 登录。不带 server 名称运行 `dcode mcp login` 可以列出需要登录的已配置 OAuth server。请参见 [MCP tools](/oss/deepagents/code/mcp-tools)。

## 命令行选项

| 选项                 | 说明                                                 |
|------------------------|-------------------------------------------------------------|
| `-a`, `--agent NAME`   | 使用具有独立 memory 的命名 agent。覆盖 `config.toml` 中的 `[agents].recent` 和 `[agents].default`。默认：`agent`（或设置 `[agents].recent` 时最近使用的 agent） |
| `-M`, `--model MODEL`  | 使用特定模型（`provider:model`）                    |

## 管理凭据（`dcode auth`）

`dcode auth` 命令组是 `/auth` 凭据管理器的可脚本化等价物。它读取和写入同一个 `auth.json` 存储，无需启动 TUI：

```bash
# Pipe the key in (stdin)—never lands in shell history
echo "$ANTHROPIC_API_KEY" | dcode auth set anthropic

# Copy from an existing environment variable
dcode auth set openai --from-env OPENAI_API_KEY

# Inspect and remove
dcode auth list
dcode auth status openai
dcode auth remove anthropic
dcode auth path
```

除非通过 stdin 管道传入 key 或使用 `--from-env`，否则 `set` 会拒绝在交互式终端中运行。`dcode auth set` 只管理 API key；`openai_codex` provider 使用通过 `/auth` 进行的 ChatGPT 浏览器登录。请参见 [Provider credentials](/oss/deepagents/code/credentials#manage-credentials-from-the-shell-dcode-auth)。

## 检查配置（`dcode config`）

`dcode config` 命令组在不启动会话的情况下报告生效的配置。可以用它确认某个环境变量或 `config.toml` 设置是否被读取，或在 bug 报告中分享脱敏后的快照：

```bash
dcode config show
dcode config get interpreter.memory_limit_mb
dcode config list
dcode config path
```

provider 凭据只报告已配置或未配置；不会打印值。所有四个命令都接受 `--json`。请参见 [Inspect configuration](/oss/deepagents/code/configuration#inspect-configuration)。

## 运行诊断（`dcode doctor`）

当 Deep Agents Code 无法正常启动、provider 或 MCP server 无法连接、tracing 配置错误，或安装或更新看起来有问题时，使用 `dcode doctor`。它无需启动会话即可汇总安装方式、依赖版本、更新状态、tracing 配置和数据目录健康状况。

当既需要高层健康检查又需要某个具体设置的确切来源时，将 `dcode doctor` 与 `dcode config show` 搭配使用。请参见 [Run diagnostics with `dcode doctor`](/oss/deepagents/code/configuration#run-diagnostics-with-dcode-doctor)。

| `dcode uninstall NAME`         | 在保留工具环境其余部分的前提下移除一个已安装的可选 extra |
| `dcode update`                  | 检查并安装 Deep Agents Code 更新 |
| `dcode doctor`                  | 无需启动会话即可运行诊断。请参见 [Run diagnostics](#run-diagnostics-dcode-doctor) |
| `dcode skills list [--project]`           | 列出所有 skills（别名：`ls`） |

| `dcode mcp login [NAME] [--mcp-config PATH]` | 带 `NAME` 时，为标记为 `auth: "oauth"` 的 server 运行 OAuth 登录流程。省略 `NAME` 可以列出需要登录的已配置 OAuth server。请参见 [MCP tools](/oss/deepagents/code/mcp-tools#oauth-login) |
| `dcode mcp config`              | 显示 MCP 配置发现路径        |

| `dcode config get KEY`          | 显示某个选项的生效值和来源（例如 `interpreter.memory_limit_mb`） |
| `dcode config path`             | 显示配置文件位置以及各自是否存在 |
| `dcode auth list`               | 列出已知 provider 及各自凭据的解析来源 |
| `dcode auth status <provider>`  | 显示某个 provider 的凭据来源 |
| `dcode auth set <provider>`     | 从 stdin 或 `--from-env` 存储 provider 凭据 |
| `dcode auth remove <provider>`  | 移除已存储的 provider 凭据 |
| `dcode auth path`               | 显示凭据存储路径 |

所有管理子命令都支持 `--json` 以获得机器可读的输出。更多信息请参见[命令行选项](#command-line-options)。

破坏性命令（`agents reset`、`skills delete`、`threads delete`）支持 `--dry-run`，可以在不进行更改的情况下预览会发生什么。在 JSON 模式下，`--dry-run` 返回带有 `dry_run: true` 字段的相同信封。
