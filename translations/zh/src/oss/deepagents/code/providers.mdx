Deep Agents Code 支持任何 [与 LangChain 兼容的 chat model provider](/oss/integrations/chat)，因此几乎任何支持 tool calling 的 LLM 都能使用。任何暴露 OpenAI-compatible 或 Anthropic-compatible API 的服务也可以开箱即用 - 见 [Compatible APIs](/oss/deepagents/code/configuration#compatible-apis)。

## 快速开始

Deep Agents Code 会自动集成 [以下 model providers](#provider-reference)；除了安装对应 provider package 之外，不需要额外配置。

1. **安装 provider packages**

    每个 model provider 都需要对应的 LangChain integration package。为了保持应用轻量，这些 package 都以 optional extras 的形式提供。OpenAI、Anthropic 和 Gemini 默认已包含。你可以在会话中通过 `/install`，或者在 shell 中通过 `dcode --install` 安装其他 extras：

    <CodeGroup>
        ```txt In session
        /install groq
        ```

        ```bash Shell
        dcode --install groq
        ```
    </CodeGroup>

    在 `/install` 后不带参数运行，可以列出所有有效 extras。若想在初次 CLI 安装时预装 extras，可以设置 `DEEPAGENTS_CODE_EXTRAS`：

    ```bash
    DEEPAGENTS_CODE_EXTRAS="baseten,groq" curl -LsSf https://langch.in/dcode | bash
    ```

2. **设置凭据**

    使用 [`/auth`](/oss/deepagents/code/configuration#use-%2Fauth-recommended) 凭据管理器为你的 provider 添加 API key：

    ```txt
    /auth
    ```

    对于非交互式运行、CI/CD 或任何无法使用 TUI 的场景，可以通过 shell 使用 [`dcode auth set`](/oss/deepagents/code/configuration#manage-credentials-from-the-shell-dcode-auth) 存储同一个 key，或者直接设置 provider 的环境变量。完整 key 解析顺序见 [Provider credentials](/oss/deepagents/code/configuration#provider-credentials)；[`DEEPAGENTS_CODE_` 前缀](/oss/deepagents/code/configuration#deepagents_code_-prefix) 用于把 key 限定给 Deep Agents Code；各 provider 对应的环境变量见 [Provider reference](#provider-reference)。

    要配置 model parameters，请参见 [Model parameters](#model-parameters)。

### 使用 ChatGPT 登录

`openai_codex` provider 让你可以用付费 **ChatGPT** 订阅来使用 OpenAI 的 Codex models，而不必使用 `OPENAI_API_KEY`。你会用 ChatGPT 账号登录，它会在 `/auth` 和 `/model` switcher 中作为独立 provider 出现，与基于 API key 的 `openai` provider 分开。

<Steps>
    <Step title="开始登录">
        在任意 session 中运行 `/auth`，然后选择 **`openai_codex`**。由于 ChatGPT 需要通过浏览器登录，这会启动浏览器登录流程，而不是要求你输入 API key。
    </Step>

    <Step title="在浏览器中授权">
        Deep Agents Code 会打开浏览器进入 ChatGPT 登录页。如果它无法打开浏览器（例如通过 SSH），它也会把登录 URL 显示在屏幕上，这样你可以复制到另一台设备的浏览器中。
    </Step>

    <Step title="选择 Codex model">
        登录完成后，Codex models 会在 `/model` switcher 中以 `openai_codex` provider 的形式出现。你可以直接用它的 spec 切换：

        ```txt
        /model openai_codex:gpt-5.5
        ```
    </Step>
</Steps>

你的登录会跨 session 保留。若要查看状态或退出登录，运行 `/auth`，选择 `openai_codex`，然后选择重新认证或登出。

<Note>
    `openai_codex` 与 `openai` 是分开的。若想使用标准 API key 来使用 OpenAI models，请改用常规 `openai` provider（例如 `/model openai:gpt-5.5`）。
</Note>

:::

## 切换模型

在 Deep Agents Code 中切换模型有三种方式：

1. **使用交互式 model switcher**，通过 `/model` 命令。

    <Note>
        不是所有模型都会出现在这里。如果你的模型缺失了，可以直接传入模型名（例如 `/model gpt-5.5`），或者把它添加到 `config.toml`。
    </Note>
2. **直接把 model 名称作为参数传入**，例如 `/model gpt-5.5`。你可以使用所选 provider 支持的任何模型，不管它是否出现在 option 1 的列表里。模型名称会传给 API request。
3. **启动时指定 model**，例如：

    ```txt
    dcode --model openai:gpt-5.5
    ```

<Accordion title="Model 解析顺序" icon="list-numbers">
    Deep Agents Code 启动时，会按以下顺序解析应该使用哪个 model：

    1. 传入时的 **`--model` flag** 永远优先。
    2. `~/.deepagents/config.toml` 中的 **`[models].default`** - 用户有意设定的长期偏好。
    3. `~/.deepagents/config.toml` 中的 **`[models].recent`** - 上一次通过 `/model` 切换的 model。自动写入；不会覆盖 `[models].default`。
    4. **环境自动检测**：回退到第一个可用的启动凭据，按以下顺序检查：`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`GOOGLE_API_KEY`、`GOOGLE_CLOUD_PROJECT`（Vertex AI）。

    这个启动回退有意只检查这四个凭据。其他受支持的 providers（例如 Groq）仍然可以通过 `--model`、`/model` 和已保存的默认值（`[models].default` / `[models].recent`）来使用。
</Accordion>

### 哪些模型会出现在切换器里

`/model` selector 会根据已安装的 provider packages 动态构建列表。展开下面可查看完整规则和故障排查。

<Accordion title="切换器如何构建模型列表" icon="list-search">
    交互式 `/model` selector 会根据已安装的 provider packages 以及 `config.toml` 中配置的模型来构建列表。

    当以下条件满足时，模型会出现：

    1. provider package 已安装。
    2. 模型可从 provider package、本地 provider 或你的 `config.toml` 获取。
    3. 模型 profile 没有把 text input 或 output 标记为不支持。

    如果某个模型缺失，可以直接使用 `/model <provider>:<model>`，或者把它添加到 [`[models.providers.<name>].models`](/oss/deepagents/code/configuration#adding-models-to-the-interactive-switcher)。

    <Tip>
        凭据状态 **不会** 影响模型是否显示。即使凭据缺失，你仍然可以选中某个模型。provider 会在请求时返回 authentication error。
    </Tip>
</Accordion>

### 开源权重模型

如果你想使用 open weights model，有两条常见路径，取决于你更喜欢本地推理还是云端托管推理。

**用 Ollama 做本地推理** 是最简单的免费上手方式，不需要 API key：

1. [安装 Ollama](https://ollama.com/) 并拉取一个模型，例如：

    ```bash
    ollama pull qwen3:4b
    ```

2. 安装 Ollama extra：

    <CodeGroup>
        ```txt In session
        /install ollama
        ```

        ```bash Shell
        dcode --install ollama
        ```
    </CodeGroup>

3. 选择模型：

    <CodeGroup>
        ```txt In session
        /model
        ```

        ```bash Shell
        dcode --model ollama:qwen3:4b
        ```
    </CodeGroup>

    可以使用交互式切换器，或者直接通过 `/model ollama:qwen3:4b` 传入模型。

**通过 Groq 使用云端托管的 open weights** 可以获得快速推理，而无需在本地运行任何东西：

1. 在 [console.groq.com](https://console.groq.com/) 获取一个免费 API key。

2. 安装 Groq extra：

    <CodeGroup>
        ```txt In session
        /install groq
        ```

        ```bash Shell
        dcode --install groq
        ```
    </CodeGroup>

3. 选择模型：

    <CodeGroup>
        ```txt In session
        /model
        ```

        ```bash Shell
        GROQ_API_KEY="your-api-key" dcode --model groq:openai/gpt-oss-120b
        ```
    </CodeGroup>

    可以使用交互式切换器，或者直接通过 `/model groq:openai/gpt-oss-120b` 传入模型。

**Fireworks** 也是一个常用的云端 open weights provider：

<CodeGroup>
    ```txt In session
    /install fireworks
    /model
    ```

    ```bash Shell
    dcode --install fireworks
    FIREWORKS_API_KEY="your-api-key" dcode --model fireworks:accounts/fireworks/models/deepseek-v4-pro
    ```
</CodeGroup>

可以使用交互式切换器，或者直接通过 `/model fireworks:accounts/fireworks/models/deepseek-v4-pro` 传入模型。

**Baseten** 也是另一个云端 open weights provider：

<CodeGroup>
    ```txt In session
    /install baseten
    /model
    ```

    ```bash Shell
    dcode --install baseten
    BASETEN_API_KEY="your-api-key" dcode --model baseten:moonshotai/Kimi-K2.7-Code
    ```
</CodeGroup>

可以使用交互式切换器，或者直接通过 `/model baseten:moonshotai/Kimi-K2.7-Code` 传入模型。

<Tip>
    如果你想在安装 CLI 的同时预装某个 provider，可以在初次安装时使用 `DEEPAGENTS_CODE_EXTRAS`：

    ```bash
    DEEPAGENTS_CODE_EXTRAS="fireworks" curl -LsSf https://langch.in/dcode | bash
    ```

    你可以组合多个 provider：`DEEPAGENTS_CODE_EXTRAS="groq,fireworks,ollama"`。如果 Deep Agents Code 已经安装，可以在 session 中使用 `/install <extra>`，或者从 shell 中使用 `dcode --install <extra>`。
</Tip>

**Together**、**OpenRouter** 和 **Hugging Face**（`langchain-huggingface`）也是其他云端 open weights 选项。凭据和 package 名称见 [Provider reference](#provider-reference)。

### 设置默认模型

你可以设置一个持久化的默认模型，让它应用于今后所有 CLI 启动：

* **通过 model selector：** 打开 `/model`，导航到目标模型，然后按 `Ctrl+S` 把它固定为默认值。再次在当前默认模型上按 `Ctrl+S` 会清除它。
* **通过命令：** `/model --default provider:model`（例如 `/model --default anthropic:claude-opus-4-8`）
* **通过配置文件：** 在 `~/.deepagents/config.toml` 中设置 `[models].default`（见 [Configuration](/oss/deepagents/code/configuration)）。
* **通过 shell：**

    ```bash
    dcode --default-model anthropic:claude-opus-4-8
    ```

要查看当前默认值：

```bash
dcode --default-model
```

要清除默认值：

* **通过 shell：**

    ```bash
    dcode --clear-default-model
    ```

* **通过命令：** `/model --default --clear`
* **通过 model selector：** 在当前已固定为默认值的模型上按 `Ctrl+S`。

如果没有默认值，Deep Agents Code 会使用最近一次使用的模型。

### Model parameters

把额外的 constructor kwargs 传给 model - 采样控制、reasoning/thinking budgets、context window 大小、请求超时，以及底层 chat-model class 接受的其他参数。设置它们有三种方式，按优先级排序（高到低）：

1. **启动时用 `--model-params` 一次性设置。** JSON string，仅当前 session 生效：

    ```bash
    # OpenAI reasoning effort
    dcode --model openai:gpt-5.5 --model-params '{"reasoning": {"effort": "high"}}'

    # Anthropic extended thinking
    dcode --model anthropic:claude-opus-4-8 --model-params '{"thinking": {"type": "enabled", "budget_tokens": 10000}, "max_tokens": 16000}'
    ```

2. **会话中通过 `/model --model-params` 设置。** 同样的 JSON syntax - 在不重启的情况下切换 params（并可选切换 model）：

    ```txt
    /model --model-params '{"temperature": 0.7}' anthropic:claude-opus-4-8
    /model --model-params '{"num_ctx": 16384}'           # 打开 selector，并把 params 应用于所选模型
    ```

3. **在 `config.toml` 中持久化。** Provider-level defaults（可选按 model 分表），每次启动都会应用：

    ```toml
    [models.providers.anthropic.params]
    thinking = { type = "enabled", budget_tokens = 10000 }
    max_tokens = 16000

    [models.providers.openai.params]
    reasoning = { effort = "high", summary = "auto" }
    output_version = "responses/v1"

    [models.providers.ollama.params]
    num_ctx = 16384
    temperature = 0

    # 按 model 覆盖 - 优先级高于 provider-level keys
    [models.providers.ollama.params."qwen3:4b"]
    temperature = 0.5
    ```

CLI flags 会覆盖 config file 的 `params`，并且只在当前 session 生效（会话中途的更改不会持久化）。`config.toml` 中按 model 分表的优先级高于 provider-level keys（浅层合并 - 语义详见 [Model constructor params](/oss/deepagents/code/configuration#model-constructor-params)）。`--model-params` 不能和 `--default` 一起使用。

对于重试次数，优先使用 `--max-retries` 或顶层的 [`[retries]` config](/oss/deepagents/code/configuration#retries)。

<Tip>
    底层 chat-model constructor 接受的任何 kwarg 都有效。完整列表请参考 provider 的 reference docs - 例如 [`ChatAnthropic`](https://reference.langchain.com/python/langchain-anthropic/langchain_anthropic/chat_models/ChatAnthropic)、[`ChatOpenAI`](https://reference.langchain.com/python/langchain-openai/langchain_openai/chat_models/base/ChatOpenAI)、[`ChatOllama`](https://reference.langchain.com/python/langchain-ollama/langchain_ollama/chat_models/ChatOllama)。未知 kwargs 会透传到上游 API request，因此新发布的参数无需等待 CLI 更新就能使用。
</Tip>

<Note>
    不要把凭据（`api_key`）放进 `params` - 应该使用 [`api_key_env`](/oss/deepagents/code/configuration#provider-configuration) 指向环境变量。
</Note>

如果你想覆盖 model 的运行时 *profile*（`max_input_tokens`、`tool_calling`、能力标志）中的字段 - 这与 constructor params 不同 - 请参见 [Profile overrides](/oss/deepagents/code/configuration#profile-overrides-advanced)。
