:::

当 middleware 添加特殊工具时，例如文件系统工具，它会在运行时把自己的引导追加到 system prompt 中。

:::python
<Note>
`SystemPromptConfig` 要求 `deepagents>=0.7.0a6`。
</Note>

若要完整控制 prompt 组装，请传入一个带 `prefix`、`base` 和 `suffix` key 的 @[SystemPromptConfig] dict：

- **`prefix`**：放在 base prompt 之前的文本（与直接传入字符串相同）。
- **`base`**：替换内置的 base prompt。省略该 key 会保留内置 base，把它设为 `None` 则完全去掉 base。
- **`suffix`**：放在 base prompt 之后的文本。

各部分按以下顺序组装：`prefix` -> `base` -> `suffix` -> 任何按模型定制的 [profile](/oss/deepagents/profiles) suffix。每个部分都接受 `str` 或 `SystemMessage`（为 Anthropic prompt caching 保留 `cache_control` 标记）。

```python
# 覆盖默认 base prompt：
create_deep_agent(..., system_prompt={"base": "..."})

# 除 middleware 外不设置 system prompt：
create_deep_agent(..., system_prompt={"base": None})

# 把默认 base prompt 夹在中间：
create_deep_agent(..., system_prompt={"prefix": "...", "suffix": "..."})
```

如果要做按模型定制的 system prompt 定制，例如为某个 provider 替换 base prompt 或追加 suffix，请使用 [harness profile](/oss/deepagents/profiles#harness-profiles)。
:::

<AccordionGroup>
    <Accordion title="子 agent prompts">
        声明式 [subagents](/oss/deepagents/subagents) 会针对自己的模型解析 profile 覆盖，然后把解析得到的 `base_system_prompt` / `system_prompt_suffix` 应用到子 agent 作者编写的 `system_prompt` 上。只带 `system_prompt_suffix` 的 profile（内置 Anthropic / OpenAI profile 的常见情况）只是追加到作者写的 prompt 后面。设置了 `base_system_prompt` 的 profile 会直接替换它。
    </Accordion>
    <Accordion title="通用子 agent prompt">
        自动添加的[通用子 agent](/oss/deepagents/subagents#the-general-purpose-subagent) 会把它的 base prompt 解析为 **`general_purpose_subagent.system_prompt`（如果设置了）-> `HarnessProfile.base_system_prompt`（如果设置了）-> SDK 通用默认值**，并把 profile suffix 叠加在上面。当两个覆盖字段都设置时，通用子 agent 专属的那个会获胜，这样同时调这两个字段的调用方就不会发现自己的 GP 覆盖被悄悄丢掉：

        <CustomizationGpSubagentProfilePy />

        | Stack | 最终 system prompt |
        | ----- | ------------------- |
        | Main agent | `"You are ACME's support orchestrator." + SUFFIX` |
        | GP subagent | `"You are a research subagent. Cite sources." + SUFFIX` |
    </Accordion>
</AccordionGroup>

## Middleware

Deep Agents 支持任意 [middleware](/oss/langchain/middleware/overview)，包括下方列出的内置 middleware、LangChain 的 prebuilt middleware、provider-specific middleware，以及你自己编写的自定义 middleware。

:::python
把 middleware 传给 `create_deep_agent` 的 `middleware` 参数。每个实例都会先按 `.name` 与[默认堆栈](#default-stack-main-agent)中的默认项匹配：匹配到时会原位替换默认实例，未匹配到的条目则会插入到 @[`PatchToolCallsMiddleware`] 之后。请参见[覆盖默认 middleware 实例](#override-a-default-middleware-instance)。
:::

:::js
把 middleware 传给 `createDeepAgent` 的 `middleware` 参数。自定义 middleware 会追加在 @[PatchToolCallsMiddleware] 之后、[默认堆栈](#default-stack-main-agent) 中的尾部堆栈之前。
:::

默认情况下，Deep Agents 可以使用以下 middleware：

### 默认堆栈（主 agent）

从前到后：

:::python

1. @[TodoListMiddleware]：跟踪并管理 todo 列表，用于组织 agent 任务和工作。
2. @[SkillsMiddleware]：仅在你传入 `skills` 时启用。它会**紧跟**在 todo middleware 之后、**文件系统 middleware 之前**注入，这样在文件工具运行前就能使用 skill 元数据。
3. @[FilesystemMiddleware]：处理读写和目录导航等文件系统操作。当你传入 `permissions` 时，文件系统权限 enforcement 也会包含在这里，这样它就能评估 agent 可能调用的每个工具。
4. @[SubAgentMiddleware]：派生并协调子 agent，用于把任务委派给专门 agent。
5. @[SummarizationMiddleware]：当对话变长时压缩消息历史，以保持在上下文限制内（通过 @[create_summarization_middleware]）。
6. @[PatchToolCallsMiddleware]：当运行在中断后恢复，或者收到格式不正确的 tool-call 参数时，修复消息历史中悬空的工具调用。它会在 Anthropic prompt caching 和下面的尾部堆栈之前运行。
7. @[AsyncSubAgentMiddleware]：仅在你配置 async subagent 时启用。
8. **你的 middleware 参数**：你通过 `middleware` 参数传入的可选 middleware 会追加在这里（在 Patch 之后、尾部堆栈之前）。
9. **Harness profile 额外项**：来自解析后模型 profile 的 provider-specific middleware（如果有）。
10. **排除工具过滤**：当 harness profile 列出 excluded tools 时，middleware 会把这些工具从 agent 中移除。
11. **Prompt caching**（@[AnthropicPromptCachingMiddleware] 和 @[BedrockPromptCachingMiddleware]）：两者都会始终注册，并在 Patch 和你的 middleware 之后运行，这样缓存前缀就与实际发送给模型的内容一致。它们会在不支持的模型上 no-op（`unsupported_model_behavior="ignore"`），因此 Anthropic middleware 作用于 Anthropic 模型，Bedrock middleware 作用于支持缓存的 AWS Bedrock 模型。
12. @[MemoryMiddleware]：仅在你传入 `memory` 时启用。

    <Note>
    `MemoryMiddleware` 被放在 profile 额外项和 prompt caching middleware 之后，这样注入的 memory 更新就更不容易让缓存前缀失效。`create_deep_agent` 的实现注释里也说明了同样的顺序考量。
    </Note>

13. `HumanInTheLoopMiddleware`：仅在你传入 `interrupt_on` 时启用。在配置好的工具调用处暂停，等待人工批准或输入。

:::

### 默认堆栈（同步 subagent）

:::python

内置的**通用**子 agent 和每个声明式同步 `SubAgent` graph 都使用 `create_deep_agent` 在代码中构建的堆栈。它与主 agent 在大方向上保持一致（todo list、文件系统、摘要、Patch、profile 额外项、Anthropic 和 Bedrock 缓存、可选权限），但有两个不同点：

- 在这些内部 agent 上，**Skills 运行在** @[PatchToolCallsMiddleware] **之后**（而在主 agent 上，当设置了 `skills` 时，skills 会在文件系统 middleware 之前运行）。
- 子 agent graph 内部**没有** @[SubAgentMiddleware]（只有父 agent 暴露 `task` 工具）。

当声明式子 agent 设置 `interrupt_on` 时，该值会传给子 agent 的 `create_agent`，从而为配置好的工具调用接入 human-in-the-loop 处理。

:::

### 覆盖默认 middleware 实例

:::python
<Note>
通过匹配 `.name` 来覆盖默认 middleware 需要 `deepagents>=0.7.0a3`。
</Note>

传入一个 `.name` 与[默认堆栈](#default-stack-main-agent)中的某个条目匹配的 middleware 实例，例如 @[`SummarizationMiddleware`]，就可以原位替换该默认实例，而不是再追加一个重复实例。任何你传入但 `.name` **不**匹配默认项的 middleware 都不会被替换，它会落在最后一个核心 middleware 之后、profile、prompt caching 和 memory 之前。完整顺序请参见[默认堆栈（主 agent）](#default-stack-main-agent)。

```python
from deepagents import create_deep_agent
from deepagents.backends import StateBackend
from deepagents.middleware import SummarizationMiddleware

backend = StateBackend()
model = "openai:gpt-5.5"

custom_summarization = SummarizationMiddleware(
    model=model,
    backend=backend,
    summary_prompt="Your custom summary prompt here.",
)

agent = create_deep_agent(
    model=model,
    middleware=[custom_summarization],  # replaces the default SummarizationMiddleware
)
```

<Note>
覆盖会**替换**默认 middleware 实例，而不是与之合并。这意味着你的替代实例必须自行带上所需的全部配置。对 `FilesystemMiddleware` 来说这一点尤其重要：如果你覆盖它，必须把 `backend`（以及适用时的 `permissions`）直接传给你的自定义实例，因为它不会继承传给 `create_deep_agent()` 的 `backend=` 和 `permissions=`。如果你想限制可用的文件系统工具，请给自定义 @[`FilesystemMiddleware`] 实例传入 `tools` allowlist；示例见[虚拟文件系统访问](/oss/deepagents/overview#virtual-filesystem-access)中的“限制文件系统工具”。

</Note>

Deep Agents 自动添加的通用子 agent 会继承主 agent 对其默认 middleware 的覆盖，但不会携带主 agent 专用的 middleware。

通过 `subagents=` 定义的声明式子 agent 不会继承主 agent 的 middleware 自定义。若要在子 agent 上应用覆盖，请直接把覆盖项传进该子 agent 自己的 [`middleware`](/oss/deepagents/subagents#subagent-dictionary-based) 字段；这个字段会像主 agent 的 `middleware=` 一样，针对子 agent 自己的默认堆栈执行匹配。

#### 示例

<AccordionGroup>
    <Accordion title="调整摘要触发时机" icon="adjustments">
        用自定义的 `trigger` 和 `keep` 阈值覆盖 @[`SummarizationMiddleware`]，可以让对话历史比默认更早或更晚被压缩，并控制每次压缩后保留下来的最近消息数量。

        ```python
        from deepagents import create_deep_agent
        from deepagents.backends import StateBackend
        from deepagents.middleware import SummarizationMiddleware

        backend = StateBackend()
        model = "anthropic:claude-sonnet-4-6"

        agent = create_deep_agent(
            model=model,
            middleware=[
                SummarizationMiddleware(
                    model=model,
                    backend=backend,
                    trigger=("tokens", 100000),  # summarize once the conversation exceeds 100k tokens
                    keep=("messages", 20),  # keep the most recent 20 messages verbatim
                ),
            ],
        )
        ```

        `trigger` 也接受 `("fraction", ...)`，表示模型上下文窗口的某个百分比，而阈值列表会用 OR 语义组合。完整选项请参见 @[`SummarizationMiddleware`] reference。
    </Accordion>
    <Accordion title="更新 prompt cache TTL" icon="clock">
        覆盖 @[`AnthropicPromptCachingMiddleware`] 以把缓存生命周期延长到默认 `5m` TTL 之外，这对轮次间隔较长的 agent 很有用。关于默认缓存应用方式，请参见 [Prompt caching](/oss/deepagents/overview#prompt-caching)。

        ```python
        from deepagents import create_deep_agent
        from langchain_anthropic.middleware import AnthropicPromptCachingMiddleware

        agent = create_deep_agent(
            model="anthropic:claude-sonnet-4-6",
            middleware=[
                AnthropicPromptCachingMiddleware(ttl="1h"),  # replaces the default 5m TTL
            ],
        )
        ```
    </Accordion>
    <Accordion title="自定义 system prompt 中的文件系统指令" icon="file-text">
        用 `system_prompt` 覆盖 @[`FilesystemMiddleware`]，即可把它追加到 system prompt 中的文件系统专属指令替换为你自己的文本，而不是使用动态生成的默认内容。

        ```python
        from deepagents import create_deep_agent
        from deepagents.backends import StateBackend
        from deepagents.middleware import FilesystemMiddleware

        backend = StateBackend()

        agent = create_deep_agent(
            model="anthropic:claude-sonnet-4-6",
            backend=backend,
            middleware=[
                FilesystemMiddleware(
                    backend=backend,
                    system_prompt="Use the virtual filesystem to track long-running work. Write intermediate results to files instead of repeating them in messages.",
                ),
            ],
        )
        ```

        与任何 @[`FilesystemMiddleware`] 覆盖一样，请传入和其他地方相同的 `backend`（以及适用时的 `permissions`），因为覆盖项不会与默认实例合并。
    </Accordion>
    <Accordion title="自定义 task 工具描述" icon="message">
        用 `task_description` 覆盖 @[`SubAgentMiddleware`]，即可替换 `task` 工具的描述，例如引导模型决定何时应该委派。这个覆盖会直接替换默认堆栈，因此你需要重新声明传给 `create_deep_agent` 的相同 `backend` 和 `subagents`。自动添加的[通用子 agent](/oss/deepagents/subagents#the-general-purpose-subagent) 不会自动包含在内，除非你自己补上等价条目。

        ```python
        from deepagents import create_deep_agent
        from deepagents.backends import StateBackend
        from deepagents.middleware import SubAgentMiddleware

        backend = StateBackend()
        model = "anthropic:claude-sonnet-4-6"
        researcher = {
            "name": "researcher",
            "description": "Researches a topic and returns findings.",
            "system_prompt": "You are a researcher.",
            "model": model,
            "tools": [search],
        }

        agent = create_deep_agent(
            model=model,
            subagents=[researcher],
            middleware=[
                SubAgentMiddleware(
                    backend=backend,
                    subagents=[researcher],
                    task_description="Delegate research to the `researcher` subagent only for multi-step lookups.",
                ),
            ],
        )
        ```

        `task_description` 还支持 `available_agents` 模板占位符，运行时会用子 agent 名称和描述列表填充；细节请参见 @[`SubAgentMiddleware`] reference。若你只是想更窄地改写 `task` 工具描述，而不替换整个子 agent 堆栈，也可以改用 [harness 配置档案](/oss/deepagents/profiles#harness-profiles) 中的 `tool_description_overrides`，参见 [Profiles](#profiles)。
    </Accordion>
</AccordionGroup>
:::

## Profiles

[harness profile](/oss/deepagents/profiles#harness-profiles) 是一个可复用的、按模型划分的配置包，`create_deep_agent` 会在匹配的模型被选中时自动应用它。profile 适合那些你希望跟随模型而不是跟随调用位置的行为，例如针对 Claude 指令风格调优的 system prompt suffix、为 GPT 重写的工具描述，或者只在特定 provider 上有意义的额外 middleware。

一个 profile 可以包含：自定义 base system prompt（`base_system_prompt`）、追加的 suffix（`system_prompt_suffix`）、工具描述覆盖、要排除的工具或 middleware、要注入的额外 middleware，以及对自动添加的通用子 agent 的编辑。
