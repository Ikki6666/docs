上下文工程是把正确的信息和工具以正确的形式提供给 deep agent，让它更可靠地完成任务。

deep agent 可以访问多种上下文。
有些上下文来源会在启动时提供给 agent；另一些则会在运行时出现，例如用户输入。
deep agents 还内置了用于在长会话中管理上下文的机制。

本页概述了 deep agent 可以访问和管理的不同类型上下文。

<Tip>
如果你刚接触上下文工程，可以先看 [概念概览](/oss/concepts/context)，了解不同类型的上下文以及适用场景。
</Tip>

## 上下文类型

| 上下文类型 | 你能控制什么 | 作用域 |
|--------------|------------------|-------|
| **[输入上下文](#input-context)** | 启动时进入 agent prompt 的内容（system prompt、memory、skills） | 静态，每次运行都应用 |
| **[运行时上下文](#runtime-context)** | 在 invoke 时传入的静态配置（用户元数据、API key、连接） | 每次运行，向 subagent 传播 |
| **[上下文压缩](#context-compression)** | 内置的卸载和总结机制，用于让上下文保持在窗口限制内 | 当接近限制时自动执行 |
| **[上下文隔离](#context-isolation-with-subagents)** | 使用 subagent 隔离重活，只把结果返回给主 agent | 每个 subagent，委派时 |
| **[长期记忆](#long-term-memory)** | 通过虚拟文件系统实现跨 thread 的持久存储 | 跨会话持久化 |

1. 用户提供的 middleware prompts（如果提供了 custom middleware）

## 上下文压缩

每次 `create_deep_agent` 调用都会包含内置的上下文压缩。你不需要额外添加 middleware 来实现卸载或总结。

长时间运行的任务会产生大量工具输出和较长的对话历史。
上下文压缩会在保留与任务相关的细节的同时，减少 agent 工作记忆中的信息量。
下面这些技术是内置机制，用来确保传给 LLM 的上下文保持在其窗口限制内：

### Offloading

Deep Agents 会使用 [内置文件系统工具](/oss/deepagents/overview#virtual-filesystem-access) 自动卸载内容，并在需要时搜索和取回这些已卸载内容。
当工具调用输入或结果超过 token 阈值（默认 20,000）时，会触发内容卸载：

1. **工具调用输入超过 20,000 tokens**：文件写入和编辑操作会在 agent 的对话历史里留下包含完整文件内容的 tool call。
    由于这些内容已经持久化到了文件系统，通常是冗余的。
    当会话上下文超过模型可用窗口的 85% 时，deep agents 会截断较旧的 tool call，把它们替换成指向磁盘文件的引用，并减少活动上下文的大小。

    ![一个展示卸载输入的示例：大输入被保存到磁盘，tool call 变成了截断版本](/oss/images/deepagents/offloading-inputs.png)

2. **工具调用结果超过 20,000 tokens**：发生这种情况时，deep agent 会把响应卸载到配置的 backend，并用文件路径引用加前 10 行预览来替代它。之后 agent 可以按需重新读取或搜索这些内容。

    ![一个展示卸载结果的示例：较大的工具响应被替换为结果位置说明和前 10 行预览](/oss/images/deepagents/offloading-results.png)

<Note>
内置上下文压缩不会缩放图片、降低图像分辨率或生成视觉 embedding。关于多模态输入、工具输出，以及压缩如何与媒体交互，请参见 [Multimodal](/oss/deepagents/multimodal)。
</Note>

### Summarization

:::js
<Note>
当前的总结行为（通过 `wrapModelCall` 在模型内进行总结、准确的 token 计数，以及自动 `ContextOverflowError` 兜底）需要 `deepagents>=1.6.0`。
</Note>
:::

每次 `create_deep_agent` 调用都会在 [bare stack](/oss/deepagents/customization#bare-stack) 中包含 @[SummarizationMiddleware]。当上下文大小接近模型的上下文窗口限制（例如 `max_input_tokens` 的 85%）时，并且没有更多可供卸载的上下文时，deep agent 会自动总结消息历史。

这个过程有两个部分：

- **上下文内摘要**：LLM 会生成一份结构化的会话摘要，包含会话意图、已创建的产物和下一步，这份摘要会替换 agent 工作记忆中的完整对话历史。
- **文件系统保留**：原始对话消息的文本表示会被写入文件系统，作为规范记录。

这种双重方式可以确保 agent 既能通过摘要保持对目标和进展的感知，又能在需要时通过文件系统搜索恢复文本细节。

![一个展示总结过程的示例：agent 的对话历史中，多步内容被压缩](/oss/images/deepagents/summarization.png)

**配置：**
- 当达到模型 [model profile](/oss/langchain/models#model-profiles) 中 `max_input_tokens` 的 85% 时触发
- 保留 10% 的 token 作为最近上下文
- 如果 model profile 不可用，则退回到 170,000 token 触发阈值 / 保留 6 条消息
- 如果任何模型调用抛出标准 @[ContextOverflowError]，deep agent 会立即回退到总结，并使用摘要 + 最近保留消息重试
- 更旧的消息由模型总结

## 使用 subagent 进行上下文隔离

Subagent 解决的是 **上下文膨胀问题**。当主 agent 使用大量输出的工具（web search、文件读取、数据库查询）时，上下文窗口会很快被填满。Subagent 会把这些工作隔离出去 - 主 agent 只会收到最终结果，而不会收到产生这些结果的几十次 tool call。你还可以把每个 subagent 单独配置成和主 agent 不同的设置（例如 model、tools、system prompt 和 skills）。

**工作方式：**

- 主 agent 拥有一个 `task` tool 来委派工作
- Subagent 使用自己全新的上下文运行
- Subagent 会自主执行直到完成
- Subagent 会向主 agent 返回单个最终报告
- 主 agent 的上下文保持干净

**最佳实践：**

1. **委派复杂任务**：把会弄乱主 agent 上下文的多步骤工作交给 subagent。
2. **让 subagent 的输出保持简洁**：让 subagent 返回摘要，而不是原始数据：

    :::

    :::js

3. **对大数据使用文件系统**：Subagent 可以把结果写到文件里；主 agent 只读取它需要的部分。

## 长期记忆

在使用默认文件系统时，deep agent 会把工作记忆文件存储在 agent state 中，而这些 state 只会在单个 thread 内持久化。
长期记忆让 deep agent 可以跨不同 thread 和会话持久保存信息。
Deep agents 可把长期记忆用于保存用户偏好、累积知识、研究进展，或任何应该跨 session 保留的信息。

要使用长期记忆，你必须使用一个 `CompositeBackend`，把特定路径（通常是 `/memories/`）路由到 LangGraph Store，从而提供跨 thread 的持久化。
`CompositeBackend` 是一种混合存储系统，其中有些文件会永久保留，而另一些文件仍然只属于单个 thread。

## 最佳实践

1. **从正确的输入上下文开始**：对于始终相关的约定，把 memory 保持得尽量精简；对任务专用能力则使用聚焦的 skills。
2. **把重活交给 subagent**：委派多步骤、输出量大的任务，以保持主 agent 上下文整洁。
3. **在配置中调整 subagent 输出**：如果你在调试时发现 subagent 输出很长，可以在 subagent 的 `system_prompt` 中加入指引，让它生成摘要和综合结论。
4. **使用文件系统**：把大输出持久化到文件中（例如 subagent 的写入或 [automatic offloading](#offloading)），这样活动上下文就能保持较小；模型需要细节时，可以用 `read_file` 和 `grep` 按片段取回。
5. **记录长期记忆结构**：告诉 agent `/memories/` 里存放什么，以及应该如何使用它。
6. **为工具传入运行时上下文**：使用 `context` 传递用户元数据、API key 和工具需要的其他静态配置。
