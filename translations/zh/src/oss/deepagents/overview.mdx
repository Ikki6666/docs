Deep Agents 是开始构建由 LLM 驱动的 agent 和应用程序的最简单方式之一。它内置了任务规划、用于上下文管理的文件系统、子 agent 派生，以及长期 memory 等能力。
你可以把 deep agents 用在任何任务上，包括复杂的多步骤任务。

Deep Agents 内置了以下能力：

- **在环境中执行动作**：通过工具执行动作，读写文件，运行代码
- **连接到你的数据**：在合适的时机加载 memory、skills 和领域知识
- **管理增长中的上下文**：在长时间运行中总结历史并卸载大型结果
- **并行化任务**：把工作委派给在隔离上下文窗口中运行的通用或专用子 agent
- **保持人在回路中**：在关键决策点暂停，等待人工批准
- **持续改进**：根据真实使用情况更新 memory、skills 和 prompts

有关每个组件的完整拆解，请参见[核心能力](#core-capabilities)。

## 执行环境

执行环境是 agent 执行动作的地方。它有四层：

- **[工具](#tools-and-mcp)**：agent 可以调用的自定义函数、API 和数据库
- **[虚拟文件系统](#virtual-filesystem-access)**：由可插拔 backend 提供支持的文件工具
- **[文件系统权限](#filesystem-permissions)**：对 agent 可以读写哪些路径的声明式访问控制
- **[代码执行](#code-execution)**：受 sandbox 保护的 shell 执行和进程内 JavaScript interpreter

**[流式输出](#streaming)** 让你可以通过类型化事件流跟进正在发生的一切，包括消息、工具、值和已委派任务。

### 工具和 MCP

通过 `tools=` 参数传入自定义函数、LangChain 工具，或任意 [MCP server](/oss/deepagents/tools#mcp-tools) 中的工具。Deep Agents 完全支持 [Model Context Protocol (MCP)](/oss/langchain/mcp)，你可以通过标准接口连接数据库、API、文件系统等。

### 虚拟文件系统访问

harness 提供可配置的虚拟文件系统，可以由不同的[可插拔 backend](/oss/deepagents/backends) 支持：内存 state、本地磁盘、LangGraph store、复合路由，或者带有[权限规则](/oss/deepagents/permissions)的自定义 backend，用于读写访问。

这些 backend 支持以下文件系统操作：

:::python

| 工具 | 说明 |
| ---- | ---- |
| `ls` | 列出目录中的文件并附带元数据（大小、修改时间） |
| `read_file` | 读取文件内容并附带行号，支持大文件的 offset/limit。也支持为非文本文件（图像、视频、音频和文档）返回多模态 content block。见下方受支持的扩展名。 |
| `write_file` | 创建新文件，或覆盖已有文件 |
| `edit_file` | 在文件中执行精确字符串替换（支持全局替换模式） |
| `delete` | 删除文件，或递归删除目录及其内容 |
| `glob` | 查找匹配模式的文件（例如 `**/*.py`） |
| `grep` | 以多种输出模式搜索文件内容（仅文件、带上下文的内容或计数） |
| `execute` | 在环境中运行 shell 命令（仅在[sandbox backend](/oss/deepagents/sandboxes) 可用） |

<Note>`delete` 工具要求 `deepagents` 0.7.a1 或更新版本。递归删除目录要求 0.7.a2 或更新版本。不支持删除的 backend 会自动向模型隐藏该工具。</Note>

:::

    # 只读 agent：绝不会显示 write_file、edit_file、delete 和 execute
    agent = create_deep_agent(

        middleware=[
            FilesystemMiddleware(backend=backend, tools=["read_file", "ls", "glob", "grep"]),
        ],
    )

</Accordion>

### 文件系统权限

harness 支持声明式权限规则，用来控制 agent 可以读写哪些文件和目录。权限适用于上面列出的内置文件系统工具，并按声明顺序用 first-match-wins 语义求值。

在创建 agent 时，通过向 `permissions=` 传入规则列表来定义权限。每条规则包含：
- `operations`：`"read"` 和/或 `"write"`
- `paths`：文件或目录的 glob 模式
- `mode`：`"allow"` 或 `"deny"`

规则从上到下求值，第一个匹配的规则生效。如果没有规则匹配，就允许该操作。

这种模型可以让你把 agent 限制在特定目录中（例如 `/workspace/`）、保护敏感文件（例如 `.env` 或凭据），并让子 agent 获得比父 agent 更窄的访问权限。

权限不适用于 [sandbox backend](/oss/deepagents/sandboxes)，因为它们可以通过 `execute` 工具执行任意命令。若需要自定义校验逻辑，请使用 [backend policy hooks](/oss/deepagents/backends#add-policy-hooks)。

有关完整规则结构、示例和子 agent 继承，请参见 [Permissions](/oss/deepagents/permissions)。

### 代码执行

Deep Agents 通过两种方式支持代码执行：

- [sandbox backend](/oss/deepagents/sandboxes) 提供 `execute` 工具，可在隔离环境中执行 shell 命令。
- [interpreter](/oss/deepagents/interpreters) 添加 `eval` 工具，可在受作用域限制的 QuickJS runtime 中运行 JavaScript。

当 agent 需要安装依赖、运行测试、调用 CLI，或与操作系统文件系统协作时，请使用 sandbox backend。sandbox backend 实现了 `SandboxBackendProtocolV2`；在检测到它时，harness 会把 `execute` 工具添加到 agent 可用工具中。

当 agent 需要一个轻量级可编程层来做循环、批处理、确定性数据转换，或程序化工具调用时，请使用 interpreter。interpreter 不提供 shell 访问、包安装，或文件系统和网络访问。

有关 sandbox 设置、provider 和文件传输 API，请参见 [Sandboxes](/oss/deepagents/sandboxes)。有关 QuickJS runtime 和程序化工具调用，请参见 [Interpreters](/oss/deepagents/interpreters)。

### 流式输出

[事件流式输出](/oss/deepagents/event-streaming) 会把 agent 运行暴露为带类型的投影，覆盖消息、工具调用、值和输出。Deep Agents 还增加了 `stream.subagents`，让每个已委派任务都拥有自己的句柄，并具备独立的消息流、工具调用流和嵌套子 agent 流。

## 上下文管理

上下文管理组件控制 agent 知道什么、在 token 限制内能运行多久，以及它在会话之间保留什么。它有四层：

- **[Skills](#skills)**：按需加载的领域知识，从 skill 文件中逐步读取
- **[Memory](#memory)**：在启动时从 `AGENTS.md` 文件加载的持久指令和偏好
- **[摘要与上下文卸载](#summarization-and-context-offloading)**：对对话历史和大型工具结果进行自动压缩
- **[Prompt 缓存](#prompt-caching)**：静态 prompt 部分可进入缓存，以加速推理并降低支持模型上的成本

### Skills

skills 会为你的 deep agent 打包专门工作流、领域知识和自定义指令。

每个 skill 都遵循 [Agent Skills standard](https://agentskills.io/)，并位于包含 `SKILL.md` 文件的目录中。skills 还可以包含脚本、模板、参考文档和其他辅助资源。

Deep Agents 通过渐进式披露加载 skills：agent 在启动时先读取 `SKILL.md` 的 frontmatter，只有在任务需要时才会读取完整 skill 内容。这样既保持了启动上下文紧凑，又能按需提供丰富能力。

有关更多信息，请参见 [Skills](/oss/deepagents/skills)。

### Memory

memory 会给你的 deep agent 提供跨会话的持久上下文，例如编码风格、偏好、约定和项目准则。

memory 使用你在创建 agent 时通过 `memory` 参数传入的 [`AGENTS.md` 文件](https://agents.md/)。与 skills 不同，memory 文件总是会被加载，且内容会存储在配置的 backend（`StateBackend`、`StoreBackend` 或 `FilesystemBackend`）中。

agent 也可以根据交互和反馈更新 memory，这样偏好和模式就能持续保留，而不用在每个线程里重复说明。

有关配置细节和示例，请参见 [Memory](/oss/deepagents/customization#memory)。

### 摘要与上下文卸载

harness 会管理上下文，使 deep agent 在 token 限制内处理长时间运行的工作，同时保留最相关的信息。

这个上下文流有四个部分：
- **输入上下文**：system prompt、memory、skills 和工具 prompt 定义了 agent 的起点。
- **压缩**：内置卸载和摘要会压缩对话历史和大型中间结果。
- **隔离**：子 agent 将重型子任务隔离开来，只返回最终结果（见[委派](#delegation)）。
- **长期 memory**：虚拟文件系统中的持久存储跨线程保存信息。

这些机制一起支持超出单个上下文窗口的多步骤任务，同时减少手动裁剪上下文和 token 使用。

有关配置细节，请参见 [Context engineering](/oss/deepagents/context-engineering)。有关多模态输入和工具输出，请参见 [Multimodal](/oss/deepagents/multimodal)。

### Prompt 缓存

对于 Anthropic 和 Amazon Bedrock 模型，`create_deep_agent` 会自动把 prompt 缓存应用到 system prompt 的静态部分，即基础 agent 指令、memory 和每一轮都会重复的 skill 内容。这可以避免跨调用重复处理相同 token，从而降低长时间运行 agent 的延迟和成本。

在使用 Anthropic 模型，或使用 Bedrock 模型（Claude 或 Nova）时，prompt 缓存默认启用。无需额外配置。

对于其他 provider，请参见 [Middleware integrations](/oss/integrations/middleware#official-integrations) 了解可用的 provider-specific 缓存 middleware。

## 委派

委派组件让 agent 能把大问题拆成更小、可并行的工作单元。它有两层：

- **[任务规划](#task-planning)**：内置的 `write_todos` 工具，用于结构化任务跟踪
- **[子 agent](#subagents)**：处理隔离子任务的短生命周期子 agent

### 任务规划

harness 提供 `write_todos` 工具，让 agent 在执行期间维护结构化任务列表。

任务支持状态跟踪（`'pending'`、`'in_progress'`、`'completed'`），并持久化在 agent state 中。这为 agent 提供了一个轻量级规划层，用于组织长时间运行和多步骤工作。

### 子 agent

harness 包含内置 `task` 工具，允许主 agent 为隔离、长时间运行、多步骤或并行任务创建短生命周期的子 agent。

子 agent 执行提供：
- **新鲜上下文**：每次调用都会创建一个带有自己上下文的新 agent 实例。
- **自主执行**：子 agent 独立运行直到完成。
- **单次交接**：它只向主 agent 返回一份最终报告。
- **可配置策略**：可以使用[默认的 `general-purpose` 子 agent](/oss/deepagents/subagents#default-subagent)（默认启用），或者定义[自定义子 agent](/oss/deepagents/subagents#custom-subagents)。
- **无状态消息**：子 agent 是无状态的，不能发回多条消息。
- **上下文和 token 效率**：重型子任务工作保持隔离，并被压缩成紧凑结果。

<Accordion title="在不使用 subagent 的情况下运行（没有 `task` 工具）" icon="ban">
    若要在没有 `task` 工具的情况下运行 agent，请参见[不使用 subagent 运行](/oss/deepagents/subagents#running-without-subagents)。不要尝试通过 `excluded_middleware` 移除 @[SubAgentMiddleware]——这会被故意拒绝。相反，请通过 [harness profile](/oss/deepagents/profiles#harness-profiles) 禁用自动添加的 subagent，并且不要通过 `subagents=` 传入同步 subagent。异步 subagent 不受影响。完整顺序请参见 [默认 middleware 堆栈](/oss/deepagents/customization#default-stack-main-agent)。
</Accordion>

有关更多信息，请参见 [Subagents](/oss/deepagents/subagents)。

## 引导

引导组件让人在运行时控制 agent 行为，并为 agent 工作设置文件系统权限。

### Human-in-the-loop

Deep Agents 与 LangGraph interrupts 集成，因此你可以在敏感工具调用前暂停并等待批准。通过 `create_deep_agent` 中的 `interrupt_on` 参数启用这一行为。

`interrupt_on` 接受一个从工具名到 interrupt 配置的映射。例如，`interrupt_on={"edit_file": True}` 会在每次编辑前暂停，让你在执行前批准调用、添加指导，或修改工具输入。

这为破坏性操作、昂贵的 API 调用和交互式调试提供了运行时安全和控制层。

有关更多信息，请参见 [Human-in-the-loop](/oss/deepagents/human-in-the-loop)。
