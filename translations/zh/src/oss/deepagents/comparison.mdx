本页解释 [LangChain Deep Agents](/oss/deepagents/overview) 与 [Claude Agent SDK](https://platform.anthropic.com/docs/en/agent-sdk/overview) 的区别。两者都是用于构建自定义 agent 的 harness，但它们在执行环境、部署和厂商耦合方面做出了不同取舍。

<Info>
    Deep Agents 已在 [OpenSWE](https://github.com/langchain-ai/open-swe) 和 [LangSmith Fleet](/langsmith/fleet/index) 中用于生产环境。
</Info>

## 一览

| | **Deep Agents** | **Claude Agent SDK** |
| --- | --- | --- |
| **agent 运行位置** | 在 sandbox 内，或在 sandbox 外通过远程命令执行 | 在 sandbox 内 |
| **执行 backend** | 可插拔：[本地、虚拟文件系统、远程 sandbox 或自定义](/oss/deepagents/backends) | 运行所在 sandbox 的本地文件系统 |
| **模型 provider** | 任意（Anthropic、OpenAI、Google、100 多个其他 provider） | Claude（Anthropic、Bedrock、Vertex、Azure） |
| **按 provider/model 调优** | [Harness profiles](/oss/deepagents/profiles)（beta）：按 provider 或特定模型注册的声明式打包，包含 system prompt、工具、middleware 和 subagent 调整 | 在每个模型调用点用代码配置 |
| **部署** | 在 LangSmith 中使用 [Managed Deep Agents](/langsmith/managed-deep-agents-overview)，或通过 [`langgraph build`](/langsmith/cli#build) 自托管 [standalone image](/langsmith/deploy-standalone-server) | [Self-host](https://code.claude.com/docs/en/agent-sdk/hosting)。你需要自己构建 server、auth 和 streaming 层。[Claude managed agents](https://platform.claude.com/docs/en/managed-agents/overview) 是另一个独立产品 |
| **多租户** | [内置](/oss/deepagents/going-to-production#multi-tenancy)：范围化线程、按用户 sandbox、RBAC | 自己实现 |
| **许可证** | MIT | MIT（Claude Code 本身是专有软件） |

## 主要差异

### Agent 和执行环境

有[两种把 agent 连接到 sandbox 的模式](https://www.langchain.com/blog/the-two-patterns-by-which-agents-connect-sandboxes)：把 agent 运行在 sandbox *内部*，或者把 agent 运行在外部，并**把 sandbox 当作工具使用**。

Claude Agent SDK 只支持第一种。你的 agent 运行在 sandbox 内，并针对 sandbox 的本地文件系统执行工具。Anthropic 托管的模型 [Claude managed agents](https://platform.claude.com/docs/en/managed-agents/overview) 使用的是解耦模型，这也反映了生产级 agent 架构的发展方向。

Deep Agents 两种都支持，并允许你选择一个 [backend](/oss/deepagents/backends#quickstart) 把它们连接起来。实际使用中，这意味着你可以：

- 在 sandbox 内运行 agent（与 Claude Agent SDK 相同的模型）。
- 在长生命周期容器中运行 agent，并[把远程 sandbox 当作工具使用](https://www.langchain.com/blog/the-two-patterns-by-which-agents-connect-sandboxes)，通过网络执行命令。
- 在测试中替换成虚拟文件系统，或在自己的基础设施上使用自定义 backend。

### 多租户

当你把应用投入生产时，通常会面向许多终端用户，并且必须隔离每个用户的环境。

在 Claude Agent SDK 中，SDK 会把 agent 绑定到它的 sandbox。若要给每个用户提供隔离的执行环境，你必须自己写一个 API wrapper，为每个用户启动一个 sandbox，跟踪哪个 sandbox 属于谁，并在之后销毁它。

Deep Agents 直接处理这一点：在 harness 中为[每个用户或每个 assistant](/oss/deepagents/going-to-production#lifecycle) 配置 sandbox，线程范围、运行历史和 [RBAC](/oss/deepagents/going-to-production#team-access-control-rbac) 都已内置。如果你使用 [LangSmith Sandbox](/langsmith/sandbox-auth-proxy)，还会自带 auth proxy，让终端用户可以从 sandbox 访问第三方 API，而无需你为每个用户单独预配凭据。

### 生产级 agent server

要把一个[自托管的 Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/hosting) 应用暴露给终端用户，你需要自己编写 HTTP/WebSocket 或 SSE server，调用 agent，把 token 流式返回，并管理对话线程。这个 server 需要你自己构建、运维和保护。

Deep Agents 部署自带一个 [agent server](/langsmith/agent-server)：流式端点、线程管理、运行历史、webhook 和 [authentication](/langsmith/auth) 都是开箱即用。

### 托管云端或自托管

Claude Agent SDK 部署是 [self-hosted](https://code.claude.com/docs/en/agent-sdk/hosting) 的。SDK 和 [Claude managed agents](https://platform.claude.com/docs/en/managed-agents/overview) 是两个独立产品。针对 SDK 编写的代码不会直接部署到托管产品中。

Deep Agents 可以在两种模式下运行，而且无需改代码：

- **托管**：在 LangSmith 中使用 [Managed Deep Agents](/langsmith/managed-deep-agents-overview) 创建、运行和运维 deep agent。
- **自托管**：运行 [`langgraph build`](/langsmith/cli#build) 生成一个可以部署到任意位置的 [standalone Docker image](/langsmith/deploy-standalone-server)。

<Tip>
    如果你想要一个适用于任意模型 provider 的托管 agent 平台，请使用 [LangSmith Fleet](/langsmith/fleet/index)。[Claude managed agents](https://platform.claude.com/docs/en/managed-agents/overview) 只适用于 Anthropic 生态。
</Tip>

### LLM

Claude Agent SDK 的执行把模型、backend 和部署捆绑在一起，并优化三者之间的配合。

使用 Deep Agents 时，你可以分别选择模型 provider、执行 backend 和部署目标。选择这个 harness 就意味着你在模型和基础设施的选择上保留了最大的灵活性。

### 生态系统

Claude Agent SDK 是为 Claude 和 Anthropic 产品面专门设计的。Deep Agents 则集成了更广泛的 LangChain 生态，包括用于可观测性、评估和部署的 LangSmith，并且可以跨任意模型 provider 使用。

## 总结

- **选择 Deep Agents**，如果你想要模型和基础设施灵活性、内置的多租户部署，以及无需改代码就能切换托管或自托管。
- **选择 Claude Agent SDK**，如果你已经深度使用 Anthropic 生态，并且愿意自己自托管并构建 API、auth 和多租户层。
