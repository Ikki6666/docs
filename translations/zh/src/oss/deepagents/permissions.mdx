通过声明式权限规则控制 agent 可以读取或写入哪些文件和目录。把规则列表传给 `permissions=`，agent 内置的文件系统工具就会遵守这些规则。

:::python
<Note>
    权限需要 `deepagents>=0.5.2`。
</Note>
:::

:::js
<Note>
    权限需要 `deepagents>=1.9.1`。
</Note>
:::

权限只适用于内置文件系统工具（`ls`、`read_file`、`glob`、`grep`、`write_file`、`edit_file`）。自定义工具和访问文件系统的 MCP 工具不受此限制。权限也不适用于 [sandbox backend](/oss/deepagents/sandboxes)，因为它们可以通过 `execute` 工具执行任意命令。

<Tip>
在你需要对内置文件系统工具做**基于路径的允许/拒绝规则**时，使用 `permissions`。在你需要自定义校验逻辑（速率限制、审计日志、内容检查）或者需要控制自定义工具时，使用 [backend policy hooks](/oss/deepagents/backends#add-policy-hooks)。
</Tip>

## 规则结构

:::python

每个 `FilesystemPermission` 都有三个字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `operations` | `list["read" \| "write"]` | 规则适用的操作。`"read"` 覆盖 `ls`、`read_file`、`glob`、`grep`。`"write"` 覆盖 `write_file`、`edit_file`。 |
| `paths` | `list[str]` | 用于匹配文件路径的 glob 模式，例如 `["/workspace/**"]`。支持 `**` 递归匹配，以及 `{a,b}` 形式的分支匹配。 |
| `mode` | `"allow" \| "deny" \| "interrupt"` | 对匹配的操作是允许、拒绝还是暂停等待人工批准。默认值是 `"allow"`。见[等待人工批准](#pause-for-human-approval)。 |

规则使用 first-match-wins 评估：第一个 `operations` 和 `paths` 都匹配当前调用的规则会决定结果。如果没有规则匹配，该调用会被**允许**（宽松默认值）。

:::

:::js

每个 `FilesystemPermission` 都有三个字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `operations` | `("read" \| "write")[]` | 规则适用的操作。`"read"` 覆盖 `ls`、`read_file`、`glob`、`grep`。`"write"` 覆盖 `write_file`、`edit_file`。 |
| `paths` | `string[]` | 用于匹配文件路径的 glob 模式，例如 `["/workspace/**"]`。支持 `**` 递归匹配，以及 `{a,b}` 形式的分支匹配。 |
| `mode` | `"allow" \| "deny"` | 对匹配的操作是允许还是拒绝。默认值是 `"allow"`。 |

规则使用 first-match-wins 评估：第一个 `operations` 和 `paths` 都匹配当前调用的规则会决定结果。如果没有规则匹配，该调用会被**允许**（宽松默认值）。

路径必须是绝对路径（以 `/` 开头），并且不能包含 `..` 或 `~`。无效路径会在 agent 构建时抛出错误。

:::

## 等待人工批准

<Note>
`"interrupt"` 模式需要 `deepagents>=0.6.8`。
</Note>

把 `mode="interrupt"` 设为暂停并等待人工批准，而不是直接允许或拒绝匹配的操作。当 agent 在与 interrupt 模式规则匹配的路径上调用内置写入工具（`write_file`、`edit_file`）时，`create_deep_agent` 会抛出 human-in-the-loop 中断，而不是直接运行该工具；审核者可以批准、编辑或拒绝这次调用。

```python
from deepagents import FilesystemPermission, create_deep_agent
from langgraph.checkpoint.memory import InMemorySaver


agent = create_deep_agent(
    model=model,
    permissions=[
        # 在写入 /secrets 下的任何内容前先暂停等待批准。
        FilesystemPermission(
            operations=["write"],
            paths=["/secrets/**"],
            mode="interrupt",
        ),
    ],
    # interrupt 模式需要 checkpointer 才能暂停和恢复。
    checkpointer=InMemorySaver(),
)
```

interrupt 模式规则会自动接入 agent 的 human-in-the-loop middleware，并与任何你传入的 `interrupt_on` 规则合并，所以你可以像处理工具调用中断那样处理和恢复它们。有关恢复流程，请参见 [Human-in-the-loop](/oss/deepagents/human-in-the-loop)。

<Tip>
interrupt 模式最好使用字面量的前缀段进行锚定，例如 `/secrets/**` 或 `/projects/*/secrets/**`。批量工具（`ls`、`glob`、`grep`）会在其搜索子树可能与规则锚定前缀重叠时触发中断，因此像 `/**/secrets` 这种完全不带锚点的模式会保守地过度触发。
</Tip>

:::

## 子 agent 权限

:::python

[子 agent](/oss/deepagents/subagents) 默认继承父 agent 的权限。若要给子 agent 不同的权限，请在它的 spec 中设置 `permissions` 字段。这会**完全替换**父级规则。

<PermissionsSubagentPy />

:::

:::js

[子 agent](/oss/deepagents/subagents) 默认继承父 agent 的权限。若要给子 agent 不同的权限，请在它的 spec 中设置 `permissions` 字段。这会**完全替换**父级规则。

<PermissionsSubagentJs />

若要显式授予子 agent 不受限制的访问权限，请设置 `permissions: []`。空数组会用无约束权限覆盖父级规则。省略 `permissions` 则表示从父级继承。

:::
