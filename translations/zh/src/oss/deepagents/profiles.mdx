:::python
**Harness 配置档案** 允许你把 Deep Agents 在选择某个 provider 或特定模型时应用的配置打包起来：system prompt 调整、工具描述覆盖、排除工具或 middleware、额外 middleware，以及通用子 agent 调整。它们是为特定模型调优 harness 行为的主要方式，而且不用改 `create_deep_agent` 的调用位置。Python 中使用 `HarnessProfile` 构建配置档案；在[从 YAML/JSON 文件加载或保存](#load-profiles-from-config-files)时，使用 `HarnessProfileConfig`。Deep Agents 为 OpenAI 和 Anthropic（Claude）模型提供了内置的 harness 配置档案。

**Provider 配置档案** 是一个更窄的配套 API，只用于 *模型构造* kwargs，不影响 harness。本页大多数读者都不需要它；当你希望把 `init_chat_model` 默认值、凭据检查，或运行时派生的 kwargs 随 provider 选择一起默认应用时，可以使用它（例如在封装 provider 集成时）。
:::

<ResponseField name="excludedMiddleware" type="string[]">
    从组装后的堆栈中剔除特定 middleware。按每个 middleware 的 `.name` 属性匹配。不能包含必需的脚手架名称（`FilesystemMiddleware`、`SubAgentMiddleware`）。

<ResponseField name="extraMiddleware" type="AgentMiddleware[] | (() => AgentMiddleware[])">

</ResponseField>

<ResponseField name="generalPurposeSubagent" type="GeneralPurposeSubagentConfig">
    禁用、重命名，或重新提示通用子 agent（`enabled`、`description`、`systemPrompt`）。
</ResponseField>

</Note>

:::python
<Warning>
    若要在没有 `task` 工具的情况下运行 agent，请参见[不使用 subagent 运行](/oss/deepagents/subagents#running-without-subagents)：把 `general_purpose_subagent=GeneralPurposeSubagentProfile(enabled=False)`，并且不要通过 `subagents=` 传入同步 subagent。只有当至少存在一个同步 subagent 时，`SubAgentMiddleware`（以及 `task` 工具）才会被挂载，因此这种配置会干净地将它移除。异步 subagent 不受影响。

    如果在 `excluded_middleware` 中列出 `FilesystemMiddleware`、`SubAgentMiddleware`，或内部权限 middleware，会抛出 `ValueError`，因为它们是 [默认 middleware 堆栈](/oss/deepagents/customization#default-stack-main-agent) 中必需的脚手架。若只是想让模型看不到这些工具而不是移除 middleware，请改用 `excluded_tools`，见[不使用默认文件系统工具运行](/oss/deepagents/overview#virtual-filesystem-access)。
</Warning>

`excluded_middleware` 中的条目支持两种形式：

- middleware *class*（按精确类型匹配），或匹配 `AgentMiddleware.name` 的纯字符串。内置项和诸如 `"SummarizationMiddleware"` 的公开别名都可以使用字符串。
- `module:Class` 导入引用（例如 `"my_pkg.middleware:TelemetryMiddleware"`），用于在配置文件中精确定位某个 middleware 类。导入引用会延迟解析，所以只应在可信的本地配置中使用，因为加载时会导入 Python 代码。
:::

:::js
<Warning>
    在 `excludedMiddleware` 中列出 `FilesystemMiddleware` 或 `SubAgentMiddleware` 会在构建时抛错，因为它们是必需脚手架。若只是想让模型看不到这些工具而不是移除 middleware，请改用 `excludedTools`。
</Warning>
:::

>
    当你传入的是已预配置的 chat model 实例，而不是 `provider:model` 字符串时，harness 会从实例中合成规范化的 `provider:identifier` 键，并按以下顺序查找：

    1. 精确匹配 `provider:identifier`
    2. 仅匹配 identifier（仅在 identifier 本身已经包含 `:` 时）
    3. provider 级回退
</Accordion>


## 注册键

两种 profile 类型使用相同的键格式：

- **provider 级**：仅 provider 名称，例如 `"openai"`，会应用到该 provider 的所有模型。
- **model 级**：完整的 `provider:model` 键，例如 `"openai:gpt-5.5"`，只应用到该特定模型。

当 provider 级和 model 级 profile 同时存在时，它们会在解析时合并。未设置的 model 级字段会继承 provider 级 profile；显式设置的 model 级值会覆盖 provider 级值。

在已有键上重新注册时，新 profile 会叠加到之前的 profile 上，而不是替换它。有关逐字段规则，请参见[合并语义](#merge-semantics)。

:::python
<Note>
    没有能匹配所有 provider 的通配键。若要在所有地方都应用同样的覆盖，例如无论选择哪个模型都移除 `TodoListMiddleware`，请在你使用的每个 provider 键下都注册该 profile。profile 的设计目标是对所选模型相关的调整。应在 `create_deep_agent` 调用位置完成那些与模型无关、应该无条件生效的全局调整。
</Note>
:::

<Note>

## 合并语义

:::python
| 字段 | 合并行为 |
| --- | --- |
| `base_system_prompt`, `system_prompt_suffix` | 若设置了新值，则新值生效；否则继承 |
| `tool_description_overrides` | 映射按键合并；共享键上新值生效 |
| `excluded_tools`, `excluded_middleware` | 集合并集 |
| `extra_middleware` | 按名称合并：新实例替换其位置上的旧实例，新的条目追加到末尾 |
| `general_purpose_subagent` | 按字段合并（未设置字段继承） |
:::

:::js
| 字段 | 合并行为 |
| --- | --- |
| `baseSystemPrompt`, `systemPromptSuffix` | 若设置了新值，则新值生效；否则继承 |
| `toolDescriptionOverrides` | 映射按键合并；共享键上新值生效 |
| `excludedTools`, `excludedMiddleware` | 集合并集 |
| `extraMiddleware` | 按名称合并：新实例替换其位置上的旧实例，新的条目追加到末尾 |
| `generalPurposeSubagent` | 按字段合并（未设置字段继承） |
:::

:::python
| `init_kwargs`（provider） | 按键合并字典；共享键上新值生效 |
| `pre_init`（provider） | 可调用对象串联：先运行已有的，再运行新的 |
| `init_kwargs_factory`（provider） | 工厂函数串联，其输出会在每次 `resolve_model` 调用时合并 |
:::
