欢迎为 LangChain 文档做贡献，包括新功能、[集成](/oss/contributing/publish-langchain)以及对现有文档的改进。

## 快速开始 - 本地开发

要在本地预览文档，请运行：

```bash
git clone https://github.com/langchain-ai/docs.git
```

```bash
cd docs
```

```bash
make install
```

```bash
make dev
```

这会在 `http://localhost:3000` 启动一个支持热重载的开发服务器。编辑 `src/` 中的文件后，你可以立即看到改动。

<Tip>
    **在使用 AI 编码代理？** 安装 [LangChain Skills](https://github.com/langchain-ai/langchain-skills) 可以提升代理在 LangChain 生态任务上的表现，然后点击本页右上角的 "Copy page" 按钮，把原始内容粘贴给代理，让它自动帮你完成环境设置。
</Tip>

<Tip>
如果你的本地预览有问题，请尝试运行 `mint update`，确保你使用的是最新版本的 Mintlify。
</Tip>

<Accordion title="前置要求">
    **必需：**
    - Python 3.13+
    - [uv](https://docs.astral.sh/uv/) - Python 包管理器
    - [Node.js](https://nodejs.org/en) 和 npm
    - [Make](https://www.gnu.org/software/make/)
    - [Git](https://git-scm.com/)

    **可选：**
    - [markdownlint-cli](https://github.com/igorshubovych/markdownlint-cli) - `npm install -g markdownlint-cli`
    - [Mintlify MDX VSCode extension](https://www.mintlify.com/blog/mdx-vscode-extension)
</Accordion>

## 编辑文档

<Accordion title="在 GitHub 上快速编辑">
    对于拼写错误或小改动，无需本地环境，直接在 GitHub 上编辑即可：

    1. 点击任意页面底部的 **Edit this page on GitHub**
    1. Fork 到你的个人账号
    1. 在 GitHub 的网页编辑器中修改
    1. 创建 pull request
</Accordion>

<Note>
    **只编辑 `src/` 中的文件**-- `build/` 目录是自动生成的。
</Note>

1. 按照我们的[写作标准](#writing-standards)编辑 `src/` 中的文件。
1. 提交前运行[质量检查](#run-quality-checks)。
1. 创建一个 pull request 供审核。

<Note>
    所有 pull request 都必须关联一个 issue 或 discussion，并且该问题的解决方案需要先得到维护者批准。请参阅我们的[pull request 要求](/oss/contributing/overview#pull-request-requirements)。
</Note>

<Accordion title="创建可分享的预览构建（仅限 LangChain 团队）">
    当你创建或更新 PR 时，会自动生成一个[预览分支/ID](https://github.com/langchain-ai/docs/actions/workflows/create-preview-branch.yml)。机器人会在 PR 中留下包含该 ID 的评论。

    1. 从评论中复制预览分支的 ID
    2. 在 [Mintlify dashboard](https://dashboard.mintlify.com/langchain-5e9cc07a/langchain-5e9cc07a?section=previews) 中点击 **Create preview deployment**
    3. 输入预览分支的 ID，然后点击 **Create deployment**
    4. 选择该预览并点击 **Visit** 查看效果

    如果要用最新改动重新部署，请在 dashboard 中点击 **Redeploy**。
</Accordion>

### 运行质量检查

在提交改动之前，请确认你的代码能通过格式化和 lint 检查：

```bash
# 检查失效链接
make broken-links

# 自动格式化代码
make format

# 检查 lint 问题
make lint

# 修复 markdown 问题
make lint_md_fix

# 运行测试，确保你的改动不会破坏现有功能
make test
```

更多细节请参阅 `README` 中的 [available commands](https://github.com/langchain-ai/docs?tab=readme-ov-file#available-commands) 一节。

<Important>
    所有 pull request 都会由 CI/CD 自动检查。相同的 lint 和格式标准会被强制执行，如果这些检查失败，PR 将无法合并。
</Important>

## 文档类型

所有文档都属于以下四类之一：

<CardGroup cols={2}>

    <Card title="How-to guides" icon="tool" href="#how-to-guides">
        面向任务的说明，适合已经明确知道自己想完成什么的用户。
    </Card>

    <Card title="Conceptual guides" icon="bulb" href="#conceptual-guides">
        提供更深层理解和洞察的解释性内容。
    </Card>

    <Card title="Reference" icon="book" href="#reference">
        对 API 和实现细节的技术性说明。
    </Card>

    <Card title="Tutorials" icon="school" href="#tutorials">
        通过实践活动逐步引导用户建立理解的课程式内容。
    </Card>

</CardGroup>

<Note>
    在适用的情况下，所有文档都必须同时包含 Python 和 JavaScript/TypeScript 内容。详情请参阅[将 Python 和 JavaScript/TypeScript 内容放在一起](#co-locate-python-and-javascript%2Ftypescript-content)一节。
</Note>

### How-to guides

How-to guides 是面向任务的说明，适合已经明确知道自己想完成什么的用户。相关示例可见 [LangChain](/oss/langchain/overview) 和 [LangGraph](/oss/langgraph/overview) 标签页。

<AccordionGroup>
    <Accordion title="特征">
        - **聚焦任务**：聚焦某个具体任务或问题
        - **分步骤**：将任务拆分为更小的步骤
        - **强调动手**：提供具体示例和代码片段
    </Accordion>

    <Accordion title="建议">
        - 关注 **how**，而不是 **why**
        - 使用具体示例和代码片段
        - 将任务拆分为更小的步骤
        - 链接到相关的概念指南和参考文档
    </Accordion>

    <Accordion title="示例">
        - [Messages](/oss/langchain/messages)
        - [Tools](/oss/langchain/tools)
        - [Streaming](/oss/langgraph/streaming)
    </Accordion>
</AccordionGroup>

### Conceptual guides

Conceptual guides 以更抽象的方式介绍核心概念，帮助用户建立更深层的理解。

<AccordionGroup>
    <Accordion title="特征">
        - **聚焦理解**：解释事物为何如此运作
        - **视角更广**：比其他类型拥有更高层、更宽泛的视角
        - **偏向设计**：解释决策与权衡
        - **上下文丰富**：使用类比和对比
    </Accordion>

    <Accordion title="建议">
        - 关注 **"why"**，而不是 "how"
        - 提供功能使用未必必需、但有帮助的补充信息
        - 可以使用类比并引用替代方案
        - 避免混入过多参考文档式内容
        - 链接到相关教程和 how-to guides
    </Accordion>

    <Accordion title="示例">
        - [Memory](/oss/concepts/memory)
        - [Context](/oss/concepts/context)
        - [Graph API](/oss/langgraph/graph-api)
        - [Functional API](/oss/langgraph/functional-api)
    </Accordion>
</AccordionGroup>

### Reference

Reference 文档包含详细的低层级信息，精确说明存在哪些功能以及如何使用它们。

<CardGroup cols={2}>
    <Card title="Python reference" href="https://reference.langchain.com/python/" icon="brand-python" arrow />
    <Card title="JavaScript/TypeScript reference" href="https://reference.langchain.com/javascript/" icon="brand-javascript" arrow />
</CardGroup>

好的 reference 应当：
- 描述现有内容（所有参数、选项、返回值）
- 全面且结构清晰，便于查阅
- 作为技术细节的权威来源

<AccordionGroup>
    <Accordion title="贡献 reference 文档">
        位于 [reference.langchain.com](https://reference.langchain.com/python/) 的生成式 API reference 在本仓库之外构建和部署。如果那里有 bug、缺失包或页面损坏，请[创建一个 reference 文档 issue](https://github.com/langchain-ai/docs/issues/new?template=04-reference-docs.yml)。
    </Accordion>

    <Accordion title="LangChain reference 最佳实践">
        - **保持一致**；遵循现有的 provider 特定文档模式
        - 同时包含基础用法（代码片段）和常见边界情况/失败模式
        - 说明某些功能何时需要特定版本
    </Accordion>

    <Accordion title="何时创建新的 reference 文档">
        - 新的集成或 provider 需要单独的 reference 页面
        - 复杂的配置选项需要详细说明
        - API 变更引入了新参数或新行为
        - 社区经常就某个特定功能提问
    </Accordion>
</AccordionGroup>

### Tutorials

Tutorials 是更长篇幅、循序渐进的指南，会层层推进，带用户完成某个具体的实践活动，以建立理解。教程通常位于 [Learn](/oss/learn) 标签页。

<Note>
    一般情况下，如果没有非常明确的需求，我们不会合并外部贡献者提交的新教程。如果你认为文档缺少某个主题，或当前覆盖不足，请[创建一个新 issue](https://github.com/langchain-ai/docs/issues)。
</Note>

<AccordionGroup>
    <Accordion title="特征">
        - **强调实践**：聚焦能帮助建立理解的实际活动。
        - **分步骤**：将活动拆分为更小的步骤。
        - **强调动手**：提供按顺序衔接、可以运行的代码片段。
        - **补充性**：提供功能使用未必必需的额外上下文和信息。
    </Accordion>

    <Accordion title="建议">
        - 如果用户按步骤顺序执行，代码片段应当是连续且可运行的。
        - 可以为活动提供一些上下文，但更详细的信息请链接到相关概念指南和参考文档。
    </Accordion>

    <Accordion title="示例">
        - [Semantic search](/oss/langchain/knowledge-base)
        - [RAG agent](/oss/langchain/rag)
    </Accordion>
</AccordionGroup>

### Mintlify 组件

使用 [Mintlify components](https://mintlify.com/docs/text) 提高可读性：

<Tabs>

### 将 Python 和 JavaScript/TypeScript 内容放在一起

在可能的情况下，所有文档都必须同时为 Python 和 JavaScript/TypeScript 编写。为此，我们使用一种自定义的内联语法，区分只应出现在单一语言版本或同时出现在两个语言版本中的内容：

```mdx
\:::python
Python 专属内容。在真实文档中，`python` 前面的反斜杠会被省略。
\:::

\:::js
JavaScript/TypeScript 专属内容。在真实文档中，`js` 前面的反斜杠会被省略。
\:::

两个语言版本都显示的内容（不包裹）
```

这会生成两个输出文件，分别位于 `/oss/python/concepts/foo.mdx` 和 `/oss/javascript/concepts/foo.mdx`。每个输出页面都需要被添加到 `/src/docs.json` 中，才会出现在导航中。

<Note>
    我们不希望因为缺少语言对齐而阻碍贡献。如果某个功能只在一种语言中可用，那么在另一种语言跟上之前，只为该语言提供文档也是可以的。在这种情况下，请附带说明该功能在另一种语言中尚不可用。

    如果你需要帮助在 Python 和 JavaScript/TypeScript 之间翻译内容，请到[社区 Slack](https://www.langchain.com/join-community)提问，或在你的 PR 中 @ 一位维护者。
</Note>

## 质量标准

### 通用指南

<AccordionGroup>
    <Accordion title="避免重复">
        多个页面覆盖同一份材料会难以维护，也会造成困惑。每个概念或功能都应只有一个规范页面。请链接到其他指南，而不是重复解释。
    </Accordion>

    <Accordion title="频繁链接">
        文档章节不是孤立存在的。请频繁链接到其他章节，帮助用户继续了解不熟悉的主题。这也包括链接到 API reference 和概念章节。
    </Accordion>

    <Accordion title="保持简洁">
        采取少即是多的方式。如果其他章节已经有很好的解释，请链接过去，而不是重新解释，除非你的内容提供了新的视角。
    </Accordion>
</AccordionGroup>

### 无障碍要求

确保文档对所有用户都可访问：

- 使用标题和列表组织内容，便于快速浏览
- 使用具体、可操作的链接文字，而不是 "click here"
- 为所有图片和图表提供描述性的 alt 文本

### 交叉引用

使用一致的交叉引用，将文档与 API reference 文档连接起来。

**从文档链接到 API reference：**

使用 `@[]` 语法链接到 API reference 页面：

```mdx
See \@[`ChatAnthropic`] for all configuration options.

The \@[`bind_tools`][ChatAnthropic.bind_tools] method accepts...
```

构建流水线会根据当前语言范围（Python 或 JavaScript），将这些内容转换为正确的 markdown 链接。例如，`\@[ChatAnthropic]` 会变成指向 Python 或 JS API reference 页面的链接，具体取决于当前构建的是哪一种文档，**但前提是 `link_map.py` 文件中存在对应条目！** 详情见下文。

<Accordion title="自动链接如何工作">

`@[]` 语法由 [`handle_auto_links.py`](https://github.com/langchain-ai/docs/blob/main/pipeline/preprocessors/handle_auto_links.py) 处理。它会在 [`link_map.py`](https://github.com/langchain-ai/docs/blob/main/pipeline/preprocessors/link_map.py) 中查找链接键，该文件为 Python 和 JavaScript 两种范围分别维护了映射字典。

**支持的格式：**

| Syntax | Result |
|--------|--------|
| `\@[ChatAnthropic]` | 以 "ChatAnthropic" 作为显示文本的链接 |
| `` \@[`ChatAnthropic`] `` | 以 `` `ChatAnthropic` ``（代码格式）作为显示文本的链接 |
| `\@[text][ChatAnthropic]` | 以 "text" 作为显示文本，并使用 `ChatAnthropic` 作为 link map 中的键 |
| `\\@[ChatAnthropic]` | 转义：渲染为字面量 `\@[ChatAnthropic]`（不会生成链接，这正是本页的用法！） |

**添加新链接：**

如果某个链接未在映射中找到，它会在输出中保持不变。要添加新的自动链接：

1. 打开 `pipeline/preprocessors/link_map.py`
2. 在 `LINK_MAPS` 中对应的范围（`python` 或 `js`）添加一个条目
3. 键是 `\@[key]` 或 `\@[text][key]` 中使用的链接名，值是相对于 reference host 的路径

</Accordion>

:::python
**从 API reference stub 链接回 OSS 文档：**

已发布的 Python API reference 中的交叉链接和深层锚点是在本仓库之外生成的。如果从 reference.langchain.com 指向 docs.langchain.com 的链接有误或已过期，请附带源 URL 和目标 URL [创建 issue](https://github.com/langchain-ai/docs/issues/new?template=04-reference-docs.yml)。
:::

### 本地化

如果某个功能在两个 SDK 中都存在，请[同时为 Python 和 JavaScript/TypeScript 编写文档](#co-locate-python-and-javascript%2Ftypescript-content)。如果目前只支持一种语言，请确保该功能及其相关引用只在该语言中可见。

### 代码内文档

示例必须正确、尽可能可以直接复制粘贴使用，并且在你打开 pull request 前要**经过测试**。对于不可直接运行的片段（例如伪代码或仅作说明的片段），请明确标注。
