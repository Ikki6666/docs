title: 版本控制
---

我们的 OSS 版本号遵循 `MAJOR.MINOR.PATCH` 格式，与 [Semantic Versioning](https://semver.org/) 的定义一致。

- **Major**：需要修改代码的 breaking API 更新。
- **Minor**：保持向后兼容的新特性和改进。
- **Patch**：bug 修复和小幅改进。

例如：

- `1.0.0`：第一个适合生产环境、API 稳定的版本
- `1.1.0`：以向后兼容的方式加入新特性
- `1.0.1`：向后兼容的 bug 修复

## API 稳定性

我们通过以下方式传达 API 的稳定性：

### 稳定 API

所有不带特殊前缀的 API 都被视为稳定，可直接用于生产环境。我们会为稳定功能保持向后兼容，并且只会在 major 版本中引入 breaking changes。

### beta API

标记为 `beta` 的 API 功能已经完整，但可能会根据用户反馈进行小幅调整。它们可以安全用于生产环境，但未来版本可能需要少量改动。

### alpha API

标记为 `alpha` 的 API 属于实验性功能，可能会发生显著变化。在生产环境中使用时请保持谨慎。

### 已弃用 API

标记为 `deprecated` 的 API 会在未来的 major 版本中移除。如果可能，我们会说明计划移除的版本。处理弃用时，请：

1. 切换到推荐的替代 API
2. 按照迁移指南操作（通常会与 major 版本一起发布）
3. 在可用时使用自动化迁移工具

### 内部 API

某些 API 会通过以下几种方式被明确标记为 "internal"：

- 有些文档会直接提到某个内容属于 internal。如果文档这样写，就意味着它可能会变化。
- 以单个前导下划线（**`_`**）为前缀的函数、方法和其他对象。这是 Python 中表示私有内容的标准约定。如果某个方法以单个 **`_`** 开头，它就是 internal API。
    - **Exception:** 某些方法虽然带有 `_` 前缀，但本身并不包含实现。这类方法是为了让提供实现的子类进行覆写。这样的方式通常属于 LangChain 的 **Public API**。

## 发布周期

<AccordionGroup>
    <Accordion title="Major releases">
        major 版本发布（例如 `1.0.0` → `2.0.0`）可能包含：

        - Breaking API changes
        - 移除已弃用功能
        - 显著的架构改进

        我们会提供：

        - 详细的迁移指南
        - 在可行时提供自动化迁移工具
        - 为上一 major 版本提供延长支持期
    </Accordion>

    <Accordion title="Minor releases">
        minor 版本发布（例如 `1.0.0` → `1.1.0`）包含：

        - 新特性和新能力
        - 性能改进
        - 新的可选参数
        - 向后兼容的增强
    </Accordion>

    <Accordion title="Patch releases">
        patch 版本发布（例如 `1.0.0` → `1.0.1`）包含：

        - Bug 修复
        - 安全更新
        - 文档改进
        - 不涉及 API 变化的性能优化
    </Accordion>
</AccordionGroup>

## 版本支持策略

- **最新 major 版本**：完整支持，并处于活跃开发中（ACTIVE 状态）
- **上一个 major 版本**：在下一个 major 版本发布后的 12 个月内，接收安全更新和关键 bug 修复（MAINTENANCE 状态）
- **更旧的版本**：仅提供社区支持

### 长期支持（LTS）版本

LangChain 1.0 和 LangGraph 1.0 都被指定为 LTS 版本：

- 1.0 会一直保持 ACTIVE 状态，直到 2.0 发布
- 2.0 发布后，1.0 会进入 MAINTENANCE 模式，至少持续 1 年
- LTS 版本遵循语义化版本控制（semver），因此可以安全地在 minor 版本之间升级
- 旧版本（LangChain 0.3 和 LangGraph 0.4）会一直处于 MAINTENANCE 模式直到 2026 年 12 月

### 1.0 之前的包

:::python
**Deep Agents**（`deepagents`）是一个仍在积极开发中的 pre-1.0 包。由于它仍在快速演进，因此 API 可能会在 minor 版本之间变化，不过我们会尽量减少 breaking changes。Deep Agents 在达到 1.0 之后，会采用与 LangChain 和 LangGraph 相同的 LTS 策略。
:::

关于发布状态和支持时间线的详细信息，请参阅[发布策略](/oss/release-policy)。

## 升级

:::python
<CodeGroup>

```bash LangChain
# 升级到最新版本
pip install -U langchain-core langchain

# 升级到指定版本
pip install langchain-core==1.0.0
```

```bash LangGraph
# 升级到最新版本
pip install -U langgraph

# 升级到指定版本
pip install langgraph==1.0.0
```

```bash Deep Agents
# 升级到最新版本
pip install -U deepagents

# 升级到指定版本
pip install deepagents==0.1.0
```
</CodeGroup>
:::

:::js
<CodeGroup>

```bash LangChain
# 升级到最新版本
npm update langchain @langchain/core

# 安装指定版本
npm install langchain@1.0.0 @langchain/core@1.0.0
```

```bash LangGraph
# 升级到最新版本
npm update @langchain/langgraph

# 安装指定版本
npm install @langchain/langgraph@1.0.0
```
</CodeGroup>
:::

## 预发布版本

我们偶尔会发布 alpha 和 beta 版本，供用户提前测试：

- **Alpha**（例如 `1.0.0a1`）：早期预览版本，预计还会有较大变化
- **Beta**（例如 `1.0.0b1`）：功能基本完整，但仍可能有小幅变化
- **Release Candidate**（例如 `1.0.0rc1`）：稳定发布前的最终测试版本
