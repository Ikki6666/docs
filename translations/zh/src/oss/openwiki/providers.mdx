OpenWiki 支持以下 provider：

| Provider | 凭据 | 说明 |
| --- | --- | --- |
| `openai` | `OPENAI_API_KEY` | 对于暴露 Responses API 的 OpenAI 兼容 gateway，可选 `OPENAI_BASE_URL` |
| `openai-chatgpt` | ChatGPT OAuth token | 使用 ChatGPT 登录；用量计入 Plus/Pro/Team Codex 额度 |
| `copilot` | GitHub CLI 会话或 `COPILOT_API_KEY` | 可选 `COPILOT_BASE_URL`。CI 需要 OAuth token，而不是经典 PAT |
| `openrouter` | `OPENROUTER_API_KEY` | 可选 `OPENWIKI_OPENROUTER_PROVIDER_ONLY` allowlist |
| `anthropic` | `ANTHROPIC_API_KEY` | 可选 `ANTHROPIC_BASE_URL` |
| `gemini` | `GEMINI_API_KEY` | Google AI Studio |
| `gemini-enterprise` | Google ADC + `GOOGLE_CLOUD_PROJECT` | 可选 `GOOGLE_CLOUD_LOCATION`（默认为 `global`） |
| `bedrock` | AWS 凭据 + 区域 | 显式的 Bedrock key 或 AWS SDK 默认链 |
| `baseten` | `BASETEN_API_KEY` | 可选 `BASETEN_BASE_URL` |
| `fireworks` | `FIREWORKS_API_KEY` | 可选 `FIREWORKS_BASE_URL` |
| `nebius` | `NEBIUS_API_KEY` | Nebius Token Factory |
| `nvidia` | `NVIDIA_API_KEY` | 可选 `NVIDIA_BASE_URL` |
| `openai-compatible` | `OPENAI_COMPATIBLE_API_KEY` | 需要 `OPENAI_COMPATIBLE_BASE_URL` 和自定义模型 ID |

凭据和默认值存储在 `~/.openwiki/.env` 中。进程环境值优先于文件值。

你可以使用以下命令设置活跃的 provider 和模型：

```bash
OPENWIKI_PROVIDER=openai
OPENWIKI_MODEL_ID=gpt-5.6-terra
```

### Provider retries

覆盖首次 provider 请求之后的 retry：

```bash
OPENWIKI_PROVIDER_RETRY_ATTEMPTS=3
```

该值必须是正整数。未设置时，OpenWiki 默认为 3 次 retry。

### 输出 token 限制

`OPENWIKI_MAX_OUTPUT_TOKENS` 是每次请求输出预算的可选覆盖。设置时，它必须是正整数。OpenWiki 会将它映射到活跃 provider 的请求形态：

- **`maxOutputTokens`**：`gemini`
- **`maxTokens`**：`anthropic`、`openai`、`openai-compatible`、`openrouter`、`bedrock`、Gemini Enterprise 非 Google 界面、`openai-chatgpt` 和 `copilot`

未设置时，OpenWiki 保留每个 provider 的 SDK 默认值，但以下内置上限除外：

- **Anthropic**：现代 Claude 4 和 5 模型默认为 `16384` token，因为较旧的 LangChain 元数据否则会将较新的 Claude alias 上限设为 `4096`
- **Bedrock**：默认为 `16000` token。当模型支持更低的上限时，使用 `OPENWIKI_BEDROCK_MAX_TOKENS` 覆盖

要在这其中的活跃 provider 上设置统一的限制，请设置：

```bash
OPENWIKI_MAX_OUTPUT_TOKENS=16384
```

默认情况下 OpenRouter 不发送 `max_tokens`，因此信用预检查会按模型完整公布的输出上限做预算，低余额可能以 402 错误失败。在 OpenRouter 运行上，`OPENWIKI_OPENROUTER_MAX_TOKENS` 优先于 `OPENWIKI_MAX_OUTPUT_TOKENS`，你可以设置 token 限制：

```bash
OPENWIKI_OPENROUTER_MAX_TOKENS=8192
```

使用限制意味着你得到的不是 402 失败，而是长生成可能被截断，因此请优先选择你的余额允许的最大值。

### Reasoning effort

`OPENWIKI_REASONING_EFFORT` 是针对声明支持 reasoning 的模型的可选全局设置。

```bash
OPENWIKI_REASONING_EFFORT=high
```

保持未设置以保留 provider 默认值。无效的 provider、模型或 effort 组合会在发送请求之前失败。当活跃的 provider 和模型不支持时，继承的值也会失败。

| Provider | 模型 | 支持的值 | 请求映射 |
| --- | --- | --- | --- |
| `openai` | `gpt-5.6-terra`、`gpt-5.6-luna`、`gpt-5.6-sol` | `none`、`low`、`medium`、`high`、`xhigh`、`max` | Responses API `reasoning.effort` |
| `openai-chatgpt` | `gpt-5.6-terra`、`gpt-5.6-luna`、`gpt-5.6-sol` | `none`、`low`、`medium`、`high`、`xhigh`、`max` | Responses API `reasoning.effort` |
| `nvidia` | `nvidia/nemotron-3-super-120b-a12b` | `none`、`low`、`high` | Chat Completions `reasoning_effort` |

所有其他 provider 和模型组合（包括 OpenRouter）不提供 reasoning effort 选择。

在交互式聊天中，使用 `/effort` 选择一个可用值，或使用 `/effort default` 恢复 provider 默认值。

## GitHub Copilot

要使用 GitHub Copilot：

1. 在 `openwiki --init` 期间选择 GitHub Copilot。如果你有活跃的 GitHub CLI 会话，OpenWiki 可以复用它。否则，从凭据提示运行 `gh auth login`。
2. 选择一个模型（例如 `gpt-5.5`）。

OpenWiki 会把 GitHub CLI token 留在 GitHub CLI 凭据存储中。它不会将该 token 复制到 `~/.openwiki/.env`。对于没有 GitHub CLI 会话的 CI 或 headless 环境，将 `COPILOT_API_KEY` 设置为 GitHub **OAuth token**。Personal Access Token（经典或 fine-grained）会被 Copilot API 以第三方集成身份拒绝。

```bash
OPENWIKI_PROVIDER=copilot
OPENWIKI_MODEL_ID=gpt-5.5
```

## OpenAI（ChatGPT 登录）

`openai-chatgpt` provider 使用你的 ChatGPT 订阅调用 OpenAI 的 Codex backend，而不是按量计费的 API key：

```bash
OPENWIKI_PROVIDER=openai-chatgpt openwiki code --init
```

向导会在浏览器中打开 OpenAI auth 页面（并为 headless 使用打印 URL）。登录之后，OpenWiki 会将受管的 OAuth token 存储在 `~/.openwiki/.env` 中，并自动刷新 access token。请将 refresh token 视为密码。

## Gemini Enterprise Agent Platform

`gemini-enterprise` provider 使用 Google Application Default Credentials。不需要 API key：

```bash
OPENWIKI_PROVIDER=gemini-enterprise
GOOGLE_CLOUD_PROJECT=your-gcp-project
GOOGLE_CLOUD_LOCATION=global
```

凭据需要 Gemini Enterprise Agent Platform 访问权限（`roles/aiplatform.user`），并且你使用的模型必须在 Model Garden 中启用。Partner/open-weight（MaaS）模型是区域特定的，因此使用它们时请显式设置 `GOOGLE_CLOUD_LOCATION`。

## AWS Bedrock

```bash
OPENWIKI_PROVIDER=bedrock
BEDROCK_AWS_ACCESS_KEY_ID=your-access-key-id
BEDROCK_AWS_SECRET_ACCESS_KEY=your-secret-access-key
BEDROCK_AWS_REGION=us-east-1
OPENWIKI_MODEL_ID=anthropic.claude-sonnet-5
```

当显式的 Bedrock 凭据未设置时，OpenWiki 会使用 AWS SDK 默认凭据 provider 链。直接粘贴 Bedrock model ID。一些较新的模型需要跨区域 inference profile ID（例如 `us.anthropic.claude-sonnet-5`）而不是裸模型 ID。

当 `OPENWIKI_MAX_OUTPUT_TOKENS` 和 `OPENWIKI_BEDROCK_MAX_TOKENS` 都未设置时，Bedrock 默认为 `16000` token 的输出上限。没有显式限制时，Converse API 会将输出上限设为 `4096` token，并可能截断较长的 wiki 页面。

对于 Bedrock stream 空闲超时，请以毫秒设置 `OPENWIKI_STREAM_IDLE_TIMEOUT`（`0` 到 `2147483647` 之间的整数）。设为 `0` 禁用 watchdog。未设置时，OpenWiki 保留 `@langchain/aws` provider 的默认值。

## OpenAI 兼容端点

对于暴露 OpenAI 兼容 chat completions 的 gateway 或本地 server，使用 `openai-compatible` provider：

```bash
OPENWIKI_PROVIDER=openai-compatible
OPENAI_COMPATIBLE_API_KEY=your-gateway-key
OPENAI_COMPATIBLE_BASE_URL=https://your-gateway.example.com/v1
OPENWIKI_MODEL_ID=your-gateway-model-name
```

Ollama（`http://localhost:11434/v1`）和 LM Studio（`http://localhost:1234/v1`）等本地示例使用相同的模式。即使本地 server 忽略 key 值，OpenWiki 仍然要求 `OPENAI_COMPATIBLE_API_KEY`。

OpenWiki 内部发送非流式请求，即使你没有在终端中观看实时输出。一些 gateway 只接受流式请求，即模型在打开的连接上分块返回输出。当 OpenWiki 以非流式请求命中这类 gateway 时，gateway 可能拒绝调用或返回内容为空的 HTTP 200。没有报错的空白 wiki 通常意味着你需要启用流式传输。

当你的 gateway 需要时，为 `openai-compatible` provider 启用流式传输：

```bash
OPENWIKI_OPENAI_COMPATIBLE_STREAMING=true
```

流式传输默认关闭，因为该 provider 可以指向任意第三方端点，而流式传输通过代理和负载均衡器不一定能工作。启用它还会让客户端报告估算的 token 计数而不是 server 上报的计数。

要让 openai-compatible provider 改用 Responses API 而不是 chat completions：

```bash
OPENWIKI_OPENAI_COMPATIBLE_USE_RESPONSES_API=true
```

## OpenRouter provider 固定

当 OpenRouter 通过多个上游 provider 提供一个模型时，限制路由：

```bash
OPENWIKI_PROVIDER=openrouter
OPENROUTER_API_KEY=your-key
OPENWIKI_OPENROUTER_PROVIDER_ONLY=Novita
```
