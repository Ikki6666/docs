OpenWiki 可以按计划刷新仓库文档，并在 wiki 变化时打开 pull request 或 merge request。示例工作流在 [OpenWiki 仓库](https://github.com/langchain-ai/openwiki/tree/main/examples)中提供。

## 添加工作流

复制适用于你的 Git provider 的示例：

| Provider | 示例 | 目标位置 |
| --- | --- | --- |
| GitHub Actions | [`openwiki-update.yml`](https://github.com/langchain-ai/openwiki/blob/main/examples/openwiki-update.yml) | `.github/workflows/openwiki-update.yml` |
| GitLab CI | [`openwiki-update.gitlab-ci.yml`](https://github.com/langchain-ai/openwiki/blob/main/examples/openwiki-update.gitlab-ci.yml) | `.gitlab-ci.yml`，或从已有的 pipeline include 它 |
| Bitbucket Pipelines | [`openwiki-update.bitbucket-pipelines.yml`](https://github.com/langchain-ai/openwiki/blob/main/examples/openwiki-update.bitbucket-pipelines.yml) | `bitbucket-pipelines.yml`，然后计划 `openwiki-update` 自定义 pipeline |

## 在 CI 中运行 update

对于 CI 中的仓库文档，使用：

```bash
openwiki code --update --print
```

你不需要在 CI 中运行 `--init`。只要工作流提供所需的 provider 和模型环境变量，`--update` 会在 `openwiki/` 文档不存在时创建初始文档。

将凭据作为仓库 secret 或 CI 变量提供。典型值包括：

- Provider API key（或无 key provider 的 Copilot OAuth token / 云凭据）
- `OPENWIKI_PROVIDER`
- `OPENWIKI_MODEL_ID`
- 可选的用于 tracing 的 `LANGSMITH_API_KEY`
- 仓库使用 [LangSmith connector](/oss/openwiki/code-mode#langsmith-connector) 时可选的 `OPENWIKI_LANGSMITH_API_KEY`

计划的工作流会在这些文件变化时，将生成的 wiki 文件、`openwiki/.claims/` 下的 Claims、`AGENTS.md`、`CLAUDE.md` 和工作流本身包含在文档 pull request 中。

在持久 workspace 上，仓库生成可以通过 `openwiki/.run.json` 和 `openwiki/.page-manifest.json` 恢复。临时 CI runner 在失败后会重新开始，除非它们的 workspace 被保留，而当运行在部分页面完成之后失败时，OpenWiki 仍可以发布部分进度。

## 空更新

干净的 `--update` 运行会跳过模型工作，并保持 wiki 内容不变，同时刷新 `openwiki/.last-update.json`，让新鲜度检查反映这次检查运行过。如果 wiki Markdown 和 Claims 没有变化，CI 不会打开 pull request。

## CI 中的遥测

计划和 CI 运行会在共享的 CI 标识符下发送匿名可靠性遥测。要在 CI 中禁用遥测，请设置：

```bash
OPENWIKI_TELEMETRY_DISABLED=1
```

你可以取消注释示例工作流中对应的行。了解收集了什么以及如何在本地退出遥测，请参见 [Customize OpenWiki](/oss/openwiki/customize#telemetry)。
