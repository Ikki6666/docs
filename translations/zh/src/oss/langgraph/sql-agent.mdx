本教程将构建一个自定义智能体，它可以使用 LangGraph 回答有关 SQL 数据库的问题。

LangChain 提供了内置的 [agent](/oss/langchain/agents) 实现，这些实现是用 [LangGraph](/oss/langgraph/overview) 原语构建的。如果需要更深度的自定义，也可以直接在 LangGraph 中实现智能体。本指南演示了一个 SQL 智能体的示例实现。若想先快速上手，可参考 [使用更高层级的 LangChain 抽象构建 SQL 智能体](/oss/langchain/sql-agent)。

<Warning>
构建 SQL 数据库问答系统需要执行模型生成的 SQL 查询。这么做有固有风险。请确保数据库连接权限始终尽可能收紧，以适配智能体的需要。这样可以缓解，但不能完全消除构建模型驱动系统的风险。
</Warning>

[prebuilt agent](/oss/langchain/sql-agent) 可以帮助我们快速起步，但它依赖 system prompt 来约束行为，例如要求智能体始终先使用“list tables”工具，并且在执行查询前始终运行 query-checker 工具。

在 LangGraph 中，我们可以通过自定义智能体获得更高程度的控制。在这里，我们实现一个简单的 ReAct 智能体方案，为特定工具调用设置专门节点。我们将使用与 prebuilt agent 相同的 [state]。

### 概念

我们会覆盖以下概念：

- 用于读取 SQL 数据库的 [Tools](/oss/langchain/tools)
- LangGraph [Graph API](/oss/langgraph/graph-api)，包括 state、nodes、edges 和 conditional edges。
- [Human-in-the-loop](/oss/langgraph/interrupts) 流程

## 6. 实现人机交互审查

在执行任何 SQL 查询之前，检查智能体生成的 SQL 查询通常是明智的，这样可以避免意外操作或低效查询。

这里我们借助 LangGraph 的 [human-in-the-loop](/oss/langgraph/interrupts) 能力，在执行 SQL 查询之前暂停运行并等待人工审查。借助 LangGraph 的 [persistence layer](/oss/langgraph/persistence)，我们可以让运行无限期暂停（或者至少在 persistence layer 存活期间暂停）。
