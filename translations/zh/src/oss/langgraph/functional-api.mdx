**Functional API** 为普通函数加入 LangGraph 的能力（[持久化](/oss/langgraph/persistence)、[记忆](/oss/langgraph/add-memory)、[human-in-the-loop](/oss/langgraph/interrupts) 和 [streaming](/oss/langgraph/streaming)）。你可以使用标准的语言控制流（`if` / `else`、循环和函数调用），而不必声明由节点和边构成的图。

本页是 entrypoint、task、checkpointing 和恢复规则的概念参考。设计思路的逐步讲解请参阅 [Functional API 的设计思路](/oss/langgraph/thinking-in-functional-api)。按顺序构建的方法请参阅 [Functional API 构建清单](/oss/langgraph/use-functional-api)。

Functional API 使用两个构件：

:::python
* **`@entrypoint`**：把一个函数标记为工作流起点。它负责管理执行、interrupt 和 checkpointing。
* **`@task`**：标记一个离散的工作单元（例如一次 API 调用）。Task 返回一个类 future 对象，你可以等待它，或用 `.result()` 解析它。
:::

:::js
* **`entrypoint`**：封装工作流逻辑，并管理执行、interrupt 和 checkpointing。
* **`task`**：标记一个离散的工作单元（例如一次 API 调用）。Task 返回一个 `Promise`，你在 entrypoint 内 await 它。
:::

## Functional API vs. Graph API

如果已经选定 Functional API，这一节可以跳过。要查看两者的对比决策指南，请参阅 [在 Graph API 和 Functional API 之间选择](/oss/langgraph/choosing-apis)。两种 API 共用同一个底层运行时，因此你可以在同一个应用里一起使用它们。

主要差异：

* **Control flow**：Functional API 使用标准的语言构造。[Graph API](/oss/langgraph/graph-api) 使用节点和边。
* **State**：Graph API 需要声明 [state](/oss/langgraph/graph-api#state)，通常还需要定义 [reducers](/oss/langgraph/graph-api#reducers)。Functional API 把状态限制在函数作用域内：task 通过返回值传递数据，没有共享的 state schema。
* **Checkpointing**：Graph API 在每个 [super-step](/oss/langgraph/graph-api#super-steps) 后生成 checkpoint。Functional API 把 task 结果保存到 entrypoint 的 checkpoint。
* **Visualization**：Graph API 支持生成图。Functional API 不支持，因为图是在运行时构建的。

## Task

**task** 是一个离散的工作单元（例如一次 API 调用或一个数据处理步骤）。Task 有两个关键特性：

* **Concurrent execution**：调用 task 会立即启动它。只有在你等待结果时 entrypoint 才会阻塞，因此相互独立的 task 可以重叠执行。
* **Checkpointing**：task 结果会被保存，恢复时可从 checkpoint 还原。请参阅 [持久化](/oss/langgraph/persistence)。

### 何时使用 task

以下场景适合使用 **task**：

* **Checkpointing**：保存长时间运行的结果，恢复时无需重新计算。
* **Human-in-the-loop**：把暂停后不应重做的工作放进 task，例如 LLM 调用。[interrupt](/oss/langgraph/interrupts) 后恢复时会还原该结果。关于随机性，请参阅 [Determinism](#determinism)。
* **Parallel execution**：并发运行相互独立的 I/O 密集型工作。
* **Observability**：在 [LangSmith](/langsmith/observability) 中跟踪各个离散步骤。
* **Retries**：对离散工作单元应用重试策略。请参阅 [配置 Functional API task](/oss/langgraph/functional-api-tasks)。

## 恢复与 checkpointing

恢复时的重放依赖序列化、确定性和幂等性。

### Serialization

配置 checkpointer 时，有两条规则：

1. `entrypoint` 的输入和输出必须是 JSON 可序列化的。
2. `task` 的输出必须是 JSON 可序列化的。

:::python
请使用字典、列表、字符串、数字和布尔值等 Python 原语。
:::

:::js
请使用对象、数组、字符串、数字和布尔值等原语。
:::

序列化让 task 结果和中间值可以在 human-in-the-loop、容错和并行执行时被还原。配置 checkpointer 时，不可序列化的值会在运行时引发错误。

### Determinism

恢复**不会**从执行停止的那一行继续。执行会回到某个 checkpoint 边界，然后**向前重放**，直到再次到达暂停点。

对 Functional API 而言，重放从 **entrypoint** 的开头开始。LangGraph 会从 checkpointer 还原已完成的 [**task**](#task) 和 [**subgraph**](/oss/langgraph/use-subgraphs) 结果，而不是重新计算。这样可以在暂停之间保持步骤顺序，包括长时间运行或非确定性的 **task** 输出。

使用 **human-in-the-loop** 时，请把非确定性工作（例如随机值）和副作用（例如文件写入或 API 调用）放进 [**task**](#task)。

不同的运行可以产生不同的结果。恢复**特定** thread 时应重放相同的已持久化 **task** 和 **subgraph** 结果。

准则：

* **Avoid repeating work**：为 entrypoint 中的每个副作用单独建一个 **task**，这样恢复时会还原输出，而不是重新执行。
* **Encapsulate non-deterministic operations**：把不同尝试之间会变化的值（随机数、系统时钟时间）放进 **task**。
* **Use idempotent operations**：关于部分失败和重试，请参阅 [Idempotency](#idempotency)。

### Idempotency

幂等性意味着同一操作执行多次与执行一次的效果相同。请把 API 调用和其他写入操作放进 **task**，并把这些 task 设计成重复运行也安全。

恢复时，LangGraph 会还原已完成的 **task** 结果。已经开始但未完成的 **task** 可能会再次运行，因此请使用幂等键，或在写入前检查已有结果。

## 常见陷阱

### 处理副作用

把副作用（写文件、发送邮件）放进 task，这样恢复时不会再次执行。

### 非确定性控制流

把时间和随机性封装进 task，这样恢复时会返回相同的值。

* 在 task 中：获取随机数（5）→ interrupt → 恢复 →（再次返回 5）→ ...
* 不在 task 中：获取随机数（5）→ interrupt → 恢复 → 获取新的随机数（7）→ ...

有多个 @[`interrupt`] 调用时，LangGraph 会**按索引**把 resume 值匹配到每个 interrupt。如果恢复时 interrupt 的顺序发生变化，一个 resume 值可能被关联到错误的 interrupt。请参阅 [Determinism](#determinism)。

<Tabs>
    <Tab title="Incorrect">
    在 entrypoint 中读取时钟可能改变恢复时执行的分支。

    ```python
    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint, task
    from langgraph.types import interrupt

    checkpointer = InMemorySaver()

    @task
    def slow_task(x: int) -> int:
        return x

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> dict:
        t0 = inputs["t0"]
        t1 = time.time()  # [!code highlight]

        delta_t = t1 - t0

        if delta_t > 1:
            result = slow_task(1).result()
            value = interrupt("question")
        else:
            result = slow_task(2).result()
            value = interrupt("question")

        return {"result": result, "value": value}
    ```
    :::

    :::js

    ```typescript
      { checkpointer, name: "workflow" },

          return { result, value };
    ```
