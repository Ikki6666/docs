**Functional API** 允许你以尽量少的现有代码改动，把 LangGraph 的关键能力([持久化](/oss/langgraph/persistence)、[记忆](/oss/langgraph/add-memory)、[human-in-the-loop](/oss/langgraph/interrupts) 和 [streaming](/oss/langgraph/streaming))加入到应用中。

它的设计目标，是把这些能力集成到已经在使用标准语言原语进行分支和控制流的现有代码里，比如 `if` 语句、`for` 循环和函数调用。与许多要求把代码重构成显式 pipeline 或 DAG 的数据编排框架不同，Functional API 允许你在不强制固定执行模型的情况下引入这些能力。

Functional API 使用两个关键构件：

:::python
* **`@entrypoint`**：把一个函数标记为工作流起点，封装工作流逻辑并管理执行流程，包括处理长时间运行任务和 interrupt。
* **@[`@task`]**：表示一个离散的工作单元，比如 API 调用或数据处理步骤，可以在 entrypoint 内异步执行。Task 会返回一个类 future 对象，可以等待或同步解析。
:::

:::js
* **`entrypoint`**：entrypoint 会封装工作流逻辑并管理执行流程，包括处理长时间运行任务和 interrupt。
* **`task`**：表示一个离散的工作单元，比如 API 调用或数据处理步骤，可以在 entrypoint 内异步执行。Task 会返回一个类 future 对象，可以等待或同步解析。
:::

这为构建带状态管理和流式传输的工作流提供了最小抽象。

<Tip>
关于如何使用 Functional API，请参阅 [Use Functional API](/oss/langgraph/use-functional-api)。
</Tip>

## Functional API vs. Graph API

对于更偏好声明式方法的用户，LangGraph 的 [Graph API](/oss/langgraph/graph-api) 允许你使用图范式定义工作流。两种 API 共用同一个底层运行时，因此你可以在同一个应用里一起使用它们。

下面是一些关键差异：

* **Control flow**：Functional API 不要求你去思考图结构。你可以使用标准 Python 构造来定义工作流，这通常会减少你需要编写的代码量。
* **Short-term memory**：**Graph API** 需要声明一个 [**State**](/oss/langgraph/graph-api#state)，并且可能需要定义 [**reducers**](/oss/langgraph/graph-api#reducers) 来管理图状态的更新。`@entrypoint` 和 `@tasks` 不需要显式状态管理，因为它们的状态只在函数作用域内，且不会在函数间共享。
* **Checkpointing**：两种 API 都会生成并使用 checkpoint。在 **Graph API** 中，每个 [superstep](/oss/langgraph/graph-api) 后都会生成新的 checkpoint。在 **Functional API** 中，当 task 执行时，它们的结果会保存到与该 entrypoint 关联的已有 checkpoint，而不是创建新的 checkpoint。
* **Visualization**：Graph API 很容易把工作流可视化为图，这对调试、理解工作流以及与他人共享都很有帮助。Functional API 不支持可视化，因为图是在运行时动态生成的。

## 示例

下面我们演示一个简单的应用：它写一篇 essay，并在中途 [interrupt](/oss/langgraph/interrupts) 请求人工审核。

:::python
```python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint, task
from langgraph.types import interrupt

@task
def write_essay(topic: str) -> str:
    """Write an essay about the given topic."""
    time.sleep(1) # A placeholder for a long-running task.
    return f"An essay about topic: {topic}"

@entrypoint(checkpointer=InMemorySaver())
def workflow(topic: str) -> dict:
    """A simple workflow that writes an essay and asks for a review."""
    essay = write_essay("cat").result()
    is_approved = interrupt({
        # Any json-serializable payload provided to interrupt as argument.
        # It will be surfaced on the client side as an Interrupt when streaming data
        # from the workflow.
        "essay": essay, # The essay we want reviewed.
        # We can add any additional information that we need.
        # For example, introduce a key called "action" with some instructions.
        "action": "Please approve/reject the essay",
    })

    return {
        "essay": essay, # The essay that was generated
        "is_approved": is_approved, # Response from HIL
    }
```
:::

:::js
```typescript
import { MemorySaver, entrypoint, task, interrupt } from "@langchain/langgraph";

const writeEssay = task("writeEssay", async (topic: string) => {
  // A placeholder for a long-running task.
  await new Promise((resolve) => setTimeout(resolve, 1000));
  return `An essay about topic: ${topic}`;
});

const workflow = entrypoint(
  { checkpointer: new MemorySaver(), name: "workflow" },
  async (topic: string) => {
    const essay = await writeEssay(topic);
    const isApproved = interrupt({
      // Any json-serializable payload provided to interrupt as argument.
      // It will be surfaced on the client side as an Interrupt when streaming data
      // from the workflow.
      essay, // The essay we want reviewed.
      // We can add any additional information that we need.
      // For example, introduce a key called "action" with some instructions.
      action: "Please approve/reject the essay",
    });

    return {
      essay, // The essay that was generated
      isApproved, // Response from HIL
    };
  }
);
```
:::

<Accordion title="Detailed Explanation">
  这个工作流会先写一篇关于 “cat” 的 essay，然后暂停，等待人工审核。只要还没有审核结果，工作流就可以无限期暂停。

  当工作流恢复时，它会从头开始重新执行；但因为 `writeEssay` task 的结果已经保存，所以会从 checkpoint 中加载该结果，而不是重新计算。

## Entrypoint

:::python
@[`@entrypoint`] 装饰器可以用来从一个函数创建工作流。它会封装工作流逻辑并管理执行流程，包括处理 _长时间运行的任务_ 和 [interrupts](/oss/langgraph/interrupts)。
:::

:::js
@[`entrypoint`][entrypoint] 函数可以用来从一个函数创建工作流。它会封装工作流逻辑并管理执行流程，包括处理 _长时间运行的任务_ 和 [interrupts](/oss/langgraph/interrupts)。
:::

### Definition

:::python
**entrypoint** 是通过给函数加上 `@entrypoint` 装饰器来定义的。

这个函数**必须接受一个位置参数**，它作为工作流输入。如果你需要传递多份数据，请把输入类型定义为字典。

用 `entrypoint` 装饰函数会生成一个 @[`Pregel`][Pregel.stream] 实例，它有助于管理工作流执行（例如处理流式传输、恢复和 checkpointing）。

你通常会想把一个 **checkpointer** 传给 `@entrypoint` 装饰器，以启用持久化并使用 **human-in-the-loop** 这类功能。

<Tabs>
    <Tab title="Sync">
    ```python
    from langgraph.func import entrypoint

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(some_input: dict) -> int:
        # 某些逻辑，可能包含 API 调用等长时间运行任务，
        # 并且可能会因 human-in-the-loop 而被 interrupt。
        ...
        return result
    ```
    </Tab>
    <Tab title="Async">
    ```python
    from langgraph.func import entrypoint

    @entrypoint(checkpointer=checkpointer)
    async def my_workflow(some_input: dict) -> int:
        # 某些逻辑，可能包含 API 调用等长时间运行任务，
        # 并且可能会因 human-in-the-loop 而被 interrupt
        ...
        return result
    ```
    </Tab>
</Tabs>
:::

:::js
entrypoint 是通过把配置和一个函数传给 `entrypoint` 函数来定义的。

这个函数**必须接受一个位置参数**，它作为工作流输入。如果你需要传递多份数据，请把输入类型定义为对象。

用一个函数创建 entrypoint 会生成一个工作流实例，它有助于管理工作流执行（例如处理流式传输、恢复和 checkpointing）。

你通常会想把一个 **checkpointer** 传给 `entrypoint` 函数，以启用持久化并使用 **human-in-the-loop** 这类功能。

```typescript
import { entrypoint } from "@langchain/langgraph";

const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (someInput: Record<string, any>): Promise<number> => {
    // 某些逻辑，可能包含 API 调用等长时间运行任务，
    // 并且可能会因 human-in-the-loop 而被 interrupt
    return result;
  }
);
```
:::

<Warning>
**Serialization**
entrypoint 的**输入**和**输出**必须是 JSON 可序列化的，以支持 checkpointing。更多细节请参阅 [serialization](#serialization) 部分。
</Warning>

:::python
### Injectable parameters

在定义 `entrypoint` 时，你可以请求额外参数，这些参数会在运行时自动注入。这些参数包括：

| Parameter    | Description                                                                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **previous** | 访问给定 thread 的上一个 `checkpoint` 关联的状态。参见 [short-term-memory](#short-term-memory)。                                      |
| **store**    | [BaseStore][langgraph.store.base.BaseStore] 的实例。适用于[长期记忆](/oss/langgraph/use-functional-api#long-term-memory)。                      |
| **writer**   | 在 Async Python 3.11 以下版本中访问 StreamWriter。详情参见 [使用 Functional API 进行流式传输](/oss/langgraph/use-functional-api#streaming)。 |
| **config**   | 用于访问运行时配置。更多信息请参阅 [RunnableConfig](https://python.langchain.com/docs/concepts/runnables/#runnableconfig)。                  |

<Warning>
请用合适的名称和类型注解声明这些参数。
</Warning>

<Accordion title="Requesting Injectable Parameters">
  ```python
  from langchain_core.runnables import RunnableConfig
  from langgraph.func import entrypoint
  from langgraph.store.base import BaseStore
  from langgraph.store.memory import InMemoryStore
  from langgraph.checkpoint.memory import InMemorySaver
  from langgraph.types import StreamWriter

  in_memory_checkpointer = InMemorySaver(...)
  in_memory_store = InMemoryStore(...)  # 用于长期记忆的 InMemoryStore 实例

  @entrypoint(
      checkpointer=in_memory_checkpointer,  # 指定 checkpointer
      store=in_memory_store  # 指定 store
  )
  def my_workflow(
      some_input: dict,  # 输入（例如通过 `invoke` 传入）
      *,
      previous: Any = None, # 用于短期记忆
      store: BaseStore,  # 用于长期记忆
      writer: StreamWriter,  # 用于流式输出自定义数据
      config: RunnableConfig  # 用于访问传给 entrypoint 的配置
  ) -> ...:
  ```
</Accordion>
:::

:::python

    <Tab title="Async Stream">

### 短期记忆

当 `entrypoint` 使用 `checkpointer` 定义时，它会把同一个 **thread id** 上的连续调用之间的信息存到 [checkpoints](/oss/langgraph/checkpointers#checkpoints) 里。

:::python
这使得你可以通过 `previous` 参数访问上一次调用中的状态。

默认情况下，`previous` 参数就是上一次调用的返回值。

```python
@entrypoint(checkpointer=checkpointer)
def my_workflow(number: int, *, previous: Any = None) -> int:
    previous = previous or 0
    return number + previous

config = {
    "configurable": {
        "thread_id": "some_thread_id"
    }
}

my_workflow.invoke(1, config)  # 1（previous 为 None）
my_workflow.invoke(2, config)  # 3（previous 来自上一次调用，值为 1）
```
:::

:::js
这使得你可以通过 `getPreviousState` 函数访问上一次调用中的状态。

默认情况下，`getPreviousState` 函数返回上一次调用的返回值。

```typescript
import { entrypoint, getPreviousState } from "@langchain/langgraph";

const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (number: number) => {
    const previous = getPreviousState<number>() ?? 0;
    return number + previous;
  }
);

const config = {
  configurable: {
    thread_id: "some_thread_id",
  },
};

await myWorkflow.invoke(1, config); // 1（previous 为 undefined）
await myWorkflow.invoke(2, config); // 3（previous 来自上一次调用，值为 1）
```
:::

#### `entrypoint.final`

:::python
@[`entrypoint.final`][entrypoint.final] 是一个特殊原语，可以从 entrypoint 返回，并允许把**保存在 checkpoint 中的值**和 **entrypoint 的返回值**解耦。

第一个值是 entrypoint 的返回值，第二个值是会被保存到 checkpoint 的值。类型注解是 `entrypoint.final[return_type, save_type]`。

```python
@entrypoint(checkpointer=checkpointer)
def my_workflow(number: int, *, previous: Any = None) -> entrypoint.final[int, int]:
    previous = previous or 0
    # 这会把 previous 值返回给调用方，同时把
    # 2 * number 保存到 checkpoint 中，供下一次调用时的
    # `previous` 参数使用。
    return entrypoint.final(value=previous, save=2 * number)

config = {
    "configurable": {
        "thread_id": "1"
    }
}

my_workflow.invoke(3, config)  # 0（previous 为 None）
my_workflow.invoke(1, config)  # 6（previous 为上一次调用中 3 * 2）
```
:::

:::js
@[`entrypoint.final`][entrypoint.final] 是一个特殊原语，可以从 entrypoint 返回，并允许把**保存在 checkpoint 中的值**和 **entrypoint 的返回值**解耦。

第一个值是 entrypoint 的返回值，第二个值是会被保存到 checkpoint 的值。

```typescript
import { entrypoint, getPreviousState } from "@langchain/langgraph";

const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (number: number) => {
    const previous = getPreviousState<number>() ?? 0;
    // 这会把 previous 值返回给调用方，同时把
    // 2 * number 保存到 checkpoint 中，供下一次调用时的
    // `previous` 参数使用。
    return entrypoint.final({
      value: previous,
      save: 2 * number,
    });
  }
);

const config = {
  configurable: {
    thread_id: "1",
  },
};

await myWorkflow.invoke(3, config); // 0（previous 为 undefined）
await myWorkflow.invoke(1, config); // 6（previous 来自上一次调用中 3 * 2）
```
:::

## Task

**task** 表示一个离散的工作单元，比如 API 调用或数据处理步骤。它有两个关键特征：

* **异步执行**：task 设计为异步执行，允许多个操作并发运行而不阻塞。
* **Checkpointing**：task 结果会保存到 checkpoint 中，从而能够从上次保存的状态继续恢复工作流。（更多细节请参阅 [persistence](/oss/langgraph/persistence)。）

### Definition

:::python
Task 通过 `@task` 装饰器定义，它会包装一个普通 Python 函数。

```python
from langgraph.func import task

@task()
def slow_computation(input_value):
    # 模拟一个长时间运行的操作
    ...
    return result
```
:::

:::js
Task 通过 `task` 函数定义，它会包装一个普通函数。

```typescript
import { task } from "@langchain/langgraph";

const slowComputation = task("slowComputation", async (inputValue: any) => {
  // 模拟一个长时间运行的操作
  return result;
});
```
:::

<Warning>
**Serialization**
task 的**输出**必须是 JSON 可序列化的，以支持 checkpointing。
</Warning>

### Execution

**task** 只能从 **entrypoint**、另一个 **task** 或 [state graph node](/oss/langgraph/graph-api#nodes) 中调用。

task **不能**直接从主应用代码调用。

:::python
当你调用一个 **task** 时，它会立即返回一个 future 对象。future 是一个占位符，表示稍后可用的结果。

要获取 **task** 的结果，你可以同步等待（用 `result()`），也可以异步等待（用 `await`）。

<Tabs>
    <Tab title="Synchronous Invocation">
    ```python
    @entrypoint(checkpointer=checkpointer)
    def my_workflow(some_input: int) -> int:
        future = slow_computation(some_input)
        return future.result()  # 同步等待结果
    ```
    </Tab>
    <Tab title="Asynchronous Invocation">
    ```python
    @entrypoint(checkpointer=checkpointer)
    async def my_workflow(some_input: int) -> int:
        return await slow_computation(some_input)  # 异步等待结果
    ```
    </Tab>
</Tabs>
:::

:::js
当你调用一个 **task** 时，它会返回一个可以被 await 的 Promise。

```typescript
const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (someInput: number): Promise<number> => {
    return await slowComputation(someInput);
  }
);
```
:::

## 何时使用 task

**task** 适合以下场景：

* **Checkpointing**：当你需要把长时间运行操作的结果保存到 checkpoint 中，这样在恢复工作流时就不必重新计算。
* **Human-in-the-loop**：如果你的工作流需要人工介入，你**必须**用 **task** 把随机性（例如 API 调用）封装起来，以确保工作流能够正确恢复。更多细节请参阅 [determinism](#determinism) 部分。
* **Parallel Execution**：对于 I/O 密集型任务，**task** 能启用并行执行，让多个操作并发运行而不阻塞（例如调用多个 API）。
* **Observability**：把操作包装进 **task**，可以通过 [LangSmith](/langsmith/observability) 跟踪工作流进度，并监控单个操作的执行。
* **Retryable Work**：当工作需要重试以处理失败或不一致时，**task** 提供了一种封装和管理重试逻辑的方法。

## Serialization

LangGraph 中的序列化有两个关键要求：

1. `entrypoint` 的输入和输出必须是 JSON 可序列化的。
2. `task` 的输出必须是 JSON 可序列化的。

:::python
这些要求是为了启用 checkpointing 和工作流恢复。请使用字典、列表、字符串、数字和布尔值等 Python 原语，确保输入和输出可序列化。
:::

:::js
这些要求是为了启用 checkpointing 和工作流恢复。请使用对象、数组、字符串、数字和布尔值等原语，确保输入和输出可序列化。
:::

序列化可以确保工作流状态（例如 task 结果和中间值）能够被可靠地保存和恢复。这对于启用 human-in-the-loop 交互、容错和并行执行至关重要。

如果工作流配置了 checkpointer，传入不可序列化的输入或输出就会在运行时触发错误。

## Determinism

当你恢复一个工作流运行时，代码**不会**从执行停止的**同一行**继续。执行会回到一个 checkpoint 边界，然后工作流会**重新播放**往前执行，直到再次到达暂停点。

对于 Functional API，回放会从 **entrypoint** 的开头开始，而 LangGraph 会从 checkpointer 中恢复已完成的 [**task**](/oss/langgraph/functional-api#task) 和 [**subgraph**](/oss/langgraph/use-subgraphs) 结果，而不是重新计算它们。这保证了跨暂停时步骤顺序被保留下来，包括长时间运行或非确定性的 **task** 输出。

要使用 **human-in-the-loop** 这类功能，你必须把非确定性工作（例如随机值）和副作用（例如文件写入或 API 调用）放进 [**tasks**](/oss/langgraph/functional-api#task)。

一个工作流的不同运行可以产生不同结果，但恢复**特定** thread 时，应该回放相同的已持久化 **task** 和 **subgraph** 结果。

为了确保工作流可确定地回放，请遵循以下准则：

* **避免重复工作**：在 **entrypoint** 中，如果你串联了多个副作用（例如日志、文件写入或网络调用），请给每一个都单独建一个 **task**，这样恢复时可以从 checkpointer 里恢复输出，而不是再次执行。
* **封装非确定性操作**：把可能在不同尝试间变化的值（例如随机数或当前时间）放进 **task**，这样回放时结果就与 checkpoint 保持一致。
* **使用幂等操作**：关于部分 task 失败和重试，请参阅 [Idempotency](#idempotency)。

## Idempotency

幂等性确保同一操作被多次执行时会产生相同结果。这样可以防止在因为失败而重跑某一步时出现重复 API 调用和重复处理。为了 checkpointing，请始终把 API 调用放进 **task** 函数里，并把它们设计成在重执行时仍然幂等。
这一点对于会产生数据写入的操作尤其重要。
当工作流恢复时，LangGraph 会从 checkpoint 中回放已完成的 **task** 结果。某个已经开始但未完成的 **task** 在恢复时可能会再次运行，因此应该把副作用设计成幂等的。可以使用幂等键，或者检查已有结果，避免非预期重复。

## 常见陷阱

### 处理副作用

把副作用（例如写文件、发送邮件）封装进 task，确保在恢复工作流时不会重复执行。

<Tabs>
    <Tab title="Incorrect">
    在这个例子里，副作用（写文件）直接写在工作流里，因此在恢复工作流时会再次执行。

    :::python
    ```python
    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        # 恢复工作流时，这段代码会再次执行。
        # 这很可能不是你想要的。
        with open("output.txt", "w") as f:  # [!code highlight]
            f.write("Side effect executed")  # [!code highlight]
        value = interrupt("question")
        return value
```
    :::

    :::js
    ```typescript
    import { entrypoint, interrupt } from "@langchain/langgraph";
    import fs from "fs";

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow },
      async (inputs: Record<string, any>) => {
        // 恢复工作流时，这段代码会再次执行。
        // 这很可能不是你想要的。
        fs.writeFileSync("output.txt", "Side effect executed");
        const value = interrupt("question");
        return value;
      }
    );
    ```
    :::
    </Tab>
    <Tab title="Correct">
    在这个例子里，副作用被封装进 task，因此在恢复时可以保持一致执行。

    :::python
    ```python
    from langgraph.func import task

    @task  # [!code highlight]
    def write_to_file():  # [!code highlight]
        with open("output.txt", "w") as f:
            f.write("Side effect executed")

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        # 现在副作用被封装进 task 了。
        write_to_file().result()
        value = interrupt("question")
        return value
```
    :::

    :::js
    ```typescript
    import { entrypoint, task, interrupt } from "@langchain/langgraph";
    import * as fs from "fs";

    const writeToFile = task("writeToFile", async () => {
      fs.writeFileSync("output.txt", "Side effect executed");
    });

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow" },
      async (inputs: Record<string, any>) => {
        // 现在副作用被封装进 task 了。
        await writeToFile();
        const value = interrupt("question");
        return value;
      }
    );
    ```

### 非确定性控制流

那些每次可能返回不同结果的操作（例如获取当前时间或随机数）应该封装进 task，以确保恢复时返回相同结果。

* 在 task 中：获取随机数（5）→ interrupt → 恢复 → （再次返回 5）→ ...
* 不在 task 中：获取随机数（5）→ interrupt → 恢复 → 获取新的随机数（7）→ ...

这在使用包含多个 interrupt 调用的 **human-in-the-loop** 工作流时尤其重要。LangGraph 会为每个 task/entrypoint 保存一组 resume 值。当遇到 interrupt 时，它会与对应的 resume 值进行匹配。这个匹配严格基于**索引**，因此 resume 值的顺序必须和 interrupt 的顺序一致。

如果恢复时没有保持执行顺序，一个 @[`interrupt`] 调用可能会匹配到错误的 `resume` 值，从而导致结果不正确。

更多细节请阅读 [determinism](#determinism) 部分。

<Tabs>
    <Tab title="Incorrect">
    在这个例子里，工作流使用当前时间来决定执行哪个 task。这是非确定性的，因为工作流结果依赖于它执行的时间点。

    :::python
    ```python
    from langgraph.func import entrypoint

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        t0 = inputs["t0"]
        t1 = time.time()  # [!code highlight]

        delta_t = t1 - t0

        if delta_t > 1:
            result = slow_task(1).result()
            value = interrupt("question")
        else:
            result = slow_task(2).result()
            value = interrupt("question")

        return {
            "result": result,
            "value": value
        }
```
    :::

    :::js
    ```typescript
    import { entrypoint, interrupt } from "@langchain/langgraph";

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow" },
      async (inputs: { t0: number }) => {
        const t1 = Date.now();

        const deltaT = t1 - inputs.t0;

        if (deltaT > 1000) {
          const result = await slowTask(1);
          const value = interrupt("question");
          return { result, value };
        } else {
          const result = await slowTask(2);
          const value = interrupt("question");
          return { result, value };
        }
      }
    );
    ```

    <Tab title="Correct">

    ```python
    from langgraph.func import task

    @task  # [!code highlight]
    def get_time() -> float:  # [!code highlight]
        return time.time()

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        t0 = inputs["t0"]
        t1 = get_time().result()  # [!code highlight]

        delta_t = t1 - t0

        if delta_t > 1:
            result = slow_task(1).result()
            value = interrupt("question")
        else:
            result = slow_task(2).result()
            value = interrupt("question")

        return {
            "result": result,
            "value": value
        }
```
