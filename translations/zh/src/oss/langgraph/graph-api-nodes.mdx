## 添加重试策略

当节点调用可能瞬时失败的 API、数据库或 LLM 时，附加重试策略。

:::python
将 `retry_policy` 传给 @[`add_node`]。该值是 `RetryPolicy` 命名元组。此示例使用默认值：

<LanggraphGraphApiNodesRetryDefaultPy />

默认情况下，`retry_on` 使用 `default_retry_on`，它会重试任何异常，但以下异常除外：

* `ValueError`
* `TypeError`
* `ArithmeticError`
* `ImportError`
* `LookupError`
* `NameError`
* `SyntaxError`
* `RuntimeError`
* `ReferenceError`
* `StopIteration`
* `StopAsyncIteration`
* `OSError`

对于 `requests` 和 `httpx` 等常用 HTTP 库的异常，它只重试 5xx 状态码。完整的默认列表和参数请参阅[容错](/oss/langgraph/fault-tolerance#retries)。
:::

:::js
将 `retryPolicy` 传给 [`addNode`](https://reference.langchain.com/javascript/classes/_langchain_langgraph.index.Graph.html#addnode)。空对象会使用内置默认值：

<LanggraphGraphApiNodesRetryDefaultJs />

重试需要显式启用：没有 `retryPolicy` 时，第一次失败就会结束尝试。如果策略省略 `retryOn`，LangGraph 会重试抛出的错误，但以下情况除外：

* 中止和取消错误（`error.name === "AbortError"`，或 `error.message` 以 `"Cancel"` 或 `"AbortError"` 开头）
* `GraphValueError`，按 `error.name` 匹配
* 中止的连接（`error.code === "ECONNABORTED"`）
* 状态码为 400、401、402、403、404、405、406、407 或 409 的 HTTP 客户端错误
* OpenAI 风格的配额错误（`error.error?.code === "insufficient_quota"`）

完整的默认列表和参数请参阅[容错](/oss/langgraph/fault-tolerance#retries)。
:::

## 设置节点超时

:::python
<Note>
需要 `langgraph>=1.2`。
</Note>

将 `timeout` 传给 @[`add_node`]，限制单次异步节点尝试可以运行的时间。使用数字（秒）、`datetime.timedelta`，或使用 @[`TimeoutPolicy`] 分别设置运行和空闲限制：

<LanggraphGraphApiNodesTimeoutPy />

节点超时仅适用于**异步**节点。在同步节点上设置 `timeout` 会在编译时失败，因为同步 Python 执行无法在进程内安全取消。要分别设置运行和空闲限制，请传入 @[`TimeoutPolicy`]。

当节点超过超时时间时，LangGraph 抛出 @[`NodeTimeoutError`]。它**不**继承内置 `TimeoutError`（`OSError` 的子类），因此设置 `retry_policy` 后，默认重试策略会将其视为可重试。超时独立应用于每次尝试，因此每次重试都会重置计时器。超时的尝试不会提交缓冲的写入。

完整的超时生命周期、空闲超时刷新来源以及 `runtime.heartbeat()`，请参阅[容错](/oss/langgraph/fault-tolerance#timeouts)。
:::

:::js
<Note>
需要 `@langchain/langgraph` v1.4.0 或更高版本。
</Note>

将 `timeout` 传给 @[`addNode`]，限制单次节点尝试可以运行的时间。使用数字（毫秒），或使用 @[`TimeoutPolicy`] 分别设置运行和空闲限制：

<LanggraphGraphApiNodesTimeoutJs />

当节点超过超时时间时，LangGraph 抛出 @[`NodeTimeoutError`]，清除失败尝试的写入，并由重试策略决定是否重试。超时独立应用于每次尝试。

完整的超时生命周期、空闲超时刷新来源和心跳，请参阅[容错](/oss/langgraph/fault-tolerance#timeouts)。
:::

## 访问节点内的执行信息

:::python
通过 `runtime.execution_info` 访问执行标识和重试信息。它会呈现线程、运行和检查点标识符以及重试状态，而无需直接读取 `config`。

| 属性 | 类型 | 描述 |
| --------- | ---- | ----------- |
| `thread_id` | `str \| None` | 当前执行的线程 ID。没有 checkpointer 时为 `None`。 |
| `run_id` | `str \| None` | 当前执行的运行 ID。配置中未提供时为 `None`。 |
| `checkpoint_id` | `str` | 当前执行的检查点 ID。 |
| `checkpoint_ns` | `str` | 当前执行的检查点命名空间。 |
| `task_id` | `str` | 当前执行的任务 ID。 |
| `node_attempt` | `int` | 当前执行的尝试次数（从 1 开始）。第一次尝试为 `1`，第一次重试为 `2`，依此类推。 |
| `node_first_attempt_time` | `float \| None` | 第一次尝试开始时的 Unix 时间戳（秒）。重试期间保持不变。 |

#### 访问线程和运行 ID

#### 根据重试状态调整行为

<LanggraphGraphApiNodesExecutionInfoRetryPy />

`execution_info` 在节点任务准备好后设置。即使没有重试策略，`node_attempt` 也默认为 `1`，`node_first_attempt_time` 在节点开始执行时设置。

## 添加节点缓存

当某个步骤开销较大，并且希望为相同输入复用结果时，使用节点缓存。

要启用缓存：

1. 在编译图时传入缓存（例如 `InMemoryCache`）。Python 中还提供 `SqliteCache`。
2. 在节点上附加 @[`CachePolicy`]。

@[`CachePolicy`] 选项：

:::python
- **`key_func`**：根据节点输入构建缓存键的函数。默认是对输入做哈希（通过 pickle）。
- **`ttl`**：生存时间（秒）。省略时，缓存条目不会过期。
:::

:::js
- **`keyFunc`**：根据节点输入构建缓存键的函数。
- **`ttl`**：生存时间（秒）。省略时，缓存条目不会过期。
:::

<LanggraphGraphApiNodesCachePy />

由于模拟的工作，第一次运行大约需要两秒。第二次运行从缓存返回。
