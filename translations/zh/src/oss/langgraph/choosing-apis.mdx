LangGraph 为智能体工作流提供两种 API：[Graph API](/oss/langgraph/graph-api) 和 [Functional API](/oss/langgraph/functional-api)。两者共用同一个运行时（持久化、流式传输、人机交互和记忆）。

Graph API 是默认选择。新建 LangGraph 智能体时，以及任何能受益于显式状态、分支或图可视化的工作流，都应优先使用它。

当你需要在 LangSmith Deployment 上[部署其他框架](/langsmith/deploy-other-frameworks)时，使用 Functional API。用 `@entrypoint` 和 `@task` 包装现有的 Claude Agent SDK、Strands、CrewAI、AutoGen 或类似智能体，让 Agent Server 能以持久化、流式传输和追踪的方式运行它。

## Graph API（默认）

直接使用 LangGraph 构建时，选择 Graph API：

- 跨节点的显式共享[状态](/oss/langgraph/graph-api#state)
- 条件分支，以及稍后合并的并行路径
- 用于调试和文档编写的图示意图
- 团队评审工作流结构

请从 [Graph API 构建清单](/oss/langgraph/use-graph-api)或 [Graph API 设计思路](/oss/langgraph/thinking-in-graph-api)开始。

## Functional API（其他框架）

当你已经在其他框架中有一个智能体，并且想获得 LangSmith Deployment 的能力而不必把它改写成图时，选择 Functional API：

- 对现有过程式代码或框架代码做最小改动
- 标准控制流（`if`/`else`、循环、函数调用）
- 函数作用域的值，而不是共享状态模式

关于包装并部署的模式，请参阅[部署其他框架](/langsmith/deploy-other-frameworks)。关于 Functional API 的概念和做法，请参阅 [Functional API 概览](/oss/langgraph/functional-api)。

Graph API 让状态和转换变得显式。Functional API 保留普通控制流，并在 task 之间传递值。

| 关注点 | Graph API | Functional API |
| --- | --- | --- |
| 风格 | 声明式节点、边和共享状态 | 命令式函数，使用 `@entrypoint` / `@task`（Python）或 `entrypoint` / `task`（TypeScript） |
| 控制流 | 边和条件边 | 语言本身的 `if`/`else`、循环和调用 |
| 状态 | 显式的[状态](/oss/langgraph/graph-api#state)和 [reducer](/oss/langgraph/graph-api#reducers) | 作用域限于 entrypoint 和 task |
| 检查点 | 每个 [super-step](/oss/langgraph/graph-api) 后生成新检查点 | task 结果保存到 entrypoint 检查点 |
| 可视化 | 原生的图示意图 | 没有静态图可视化（图在运行时构建） |
| 最佳用途 | LangGraph 工作流的默认选择 | 为部署而包装其他框架 |

当线性的 Functional API 子工作流位于 Graph API 协调器内部，或反过来时，你仍可以在同一个应用中组合两种 API。
