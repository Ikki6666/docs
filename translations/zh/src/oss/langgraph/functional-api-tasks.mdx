一个 [task](/oss/langgraph/functional-api#task) 是一个离散的工作单元，其结果可以单独生成 [checkpoint](/oss/langgraph/persistence)。当 [entrypoint](/oss/langgraph/functional-api#entrypoint) 或 [Graph API node](/oss/langgraph/graph-api#using-tasks-in-nodes) 运行多个操作时，把每个操作包在一个 task 中，而不是把所有工作都放进一个函数体。配合 checkpointer 使用时，已完成的 task 结果会被保存，因此恢复的线程可以跳过已完成的工作，从下一个 task 继续。

本页介绍 task 的重试、超时、缓存和错误恢复。概念说明请参阅 [Functional API 概览](/oss/langgraph/functional-api)。按顺序构建的路径请参阅 [Functional API 构建清单](/oss/langgraph/use-functional-api)。共享的重试和超时生命周期请参阅 [容错](/oss/langgraph/fault-tolerance)。

## 设置超时

限制单次 async 尝试可以运行多久。如果重试策略会重试超时错误，计时器会在下一次尝试时重置。

:::python
在 `@task` 或 `@entrypoint` 上以秒或 `datetime.timedelta` 传入 `timeout`。超时仅适用于 async task 和 entrypoint。在同步函数上设置 `timeout` 会在声明时抛出错误。

第一次尝试会休眠超过超时时间，并抛出 @[`NodeTimeoutError`]，它是 `TimeoutError` 的子类。重试策略会重试该错误。第二次尝试立即返回。

<LanggraphFunctionalApiTasksTimeoutPy />
:::

:::js
在 `task` 或 `entrypoint` 上以毫秒传入 `timeout`，或使用 `{ idleTimeout: 30_000 }`。用 `isNodeTimeoutError` 来收窄超时错误。设置重试策略后，`NodeTimeoutError` 可重试。

第一次尝试会休眠超过超时时间。重试策略会重试。第二次尝试立即返回。

<LanggraphFunctionalApiTasksTimeoutJs />
:::

## 错误后恢复

再次传入原始输入会开始一次新的调用，而不是恢复失败的那次调用。请参阅[选择如何继续线程](/oss/langgraph/checkpointers#choose-how-to-continue-a-thread)。
