## 构建工作流

按顺序处理以下决策。每一步都链接到完整的做法说明。

<Steps>
<Step title="组合工作流">
定义一个 entrypoint，把工作单元包装成 task，并选择各步骤之间的连接方式。

- 从单个 entrypoint 开始，把所有输入作为同一个参数传入（通常是字典）。
- 对应当独立建立检查点并重试的离散工作使用 task。
- 各步骤相互独立时，用并行 task 展开执行。
- 需要组合时，调用已编译的 [Graph API](/oss/langgraph/graph-api) 图或另一个 entrypoint。

请参阅[组合 Functional API 工作流](/oss/langgraph/functional-api-workflows)。
</Step>

<Step title="配置 task">
当步骤可能失败、挂起或重复执行时，添加可靠性控制。

- 针对暂时性失败的重试
- 针对运行缓慢的 task 或 entrypoint 的超时
- 针对代价高昂的重复工作的缓存
- 出错后恢复执行，而不重做已完成的 task

请参阅[配置 Functional API task](/oss/langgraph/functional-api-tasks)。
</Step>

<Step title="流式传输进度">
在工作流运行期间流式传输更新、模型 token 或自定义数据。

请参阅[使用 Functional API 进行流式传输](/oss/langgraph/functional-api-streaming)。
</Step>

<Step title="添加人机交互">
使用 interrupt 暂停，等待批准或工具调用审查，然后用 `Command` 恢复执行。

请参阅[为 Functional API 添加人机交互](/oss/langgraph/functional-api-human-in-the-loop)。
</Step>

<Step title="添加记忆">
使用 checkpointer 保存短期线程状态，使用 store 保存长期数据。

请参阅[为 Functional API 添加记忆](/oss/langgraph/functional-api-memory)。
</Step>
</Steps>
