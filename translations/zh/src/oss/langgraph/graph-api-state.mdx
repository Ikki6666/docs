## Define state

:::python
LangGraph 中的 [State](/oss/langgraph/graph-api#state) 可以是 `TypedDict`、`Pydantic` 模型或 dataclass。下面的示例使用 `TypedDict`。大多数图都推荐这种形式；需要对输入做运行时校验时，请参阅 [Use Pydantic models for graph state](#use-pydantic-models-for-graph-state)。
:::

:::js
LangGraph 中的 [State](/oss/langgraph/graph-api#state) 使用 `StateSchema` 类定义。它接受各个字段的 [standard schemas](https://standardschema.dev/)（如 [Zod](https://zod.dev/)），以及 `ReducedValue`、`MessagesValue` 和 `UntrackedValue` 这类值类型。请优先使用 `StateSchema`，而不是[旧版替代方案](#alternative-state-definitions)。
:::

默认情况下，图的输入和输出使用同一个 schema，并由 state 决定该 schema。需要不同的输入和输出 schema 时，请参阅 [Define input and output schemas](#define-input-and-output-schemas)。

先从 [messages](/oss/langgraph/graph-api#working-with-messages-in-graph-state) 字段开始。这种结构适合许多 LLM 应用。更多细节请参阅 [Working with messages in graph state](/oss/langgraph/graph-api#working-with-messages-in-graph-state)。

## Resetting a reducer field

使用合并型 reducer 时有一个常见困惑点：返回空值并**不会**清空该字段。因为 reducer 会把右参数合并进左参数，一个空更新会被合并进去，之前累积的值依然保留。

## Bypass reducers with `Overwrite`

## Define input and output schemas

默认情况下，`StateGraph` 使用单个 schema 运行，所有节点都通过该 schema 通信。也可以定义不同的输入和输出 schema。

指定不同的 schema 时，节点之间仍然使用内部 schema 通信。输入 schema 校验传入的输入。输出 schema 过滤内部数据，使 `invoke` 只返回输出 schema 中的字段。

定义不同的输入和输出 schema：

:::python
<LanggraphGraphApiStateInputOutputPy />

```
{'answer': 'bye'}
```
:::

:::js
<LanggraphGraphApiStateInputOutputJs />

```
{ answer: 'bye' }
```
:::

注意，invoke 的输出只包含输出 schema。

## Private channels and streaming

输入、输出和私有 schema 约束每个节点读取的内容，以及 `invoke` 返回的内容。它们**不会**对[流式传输](/oss/langgraph/streaming)隐藏 channel。

values streaming 默认会发出**所有** state channel，包括私有 channel。这适用于 [event streaming](/oss/langgraph/event-streaming) 的 values 投影（在 `stream_events` / `streamEvents` 上使用 `version="v3"` 时的 `stream.values`），也适用于 `stream_mode="values"` / `streamMode: "values"` 的 `graph.stream`。values streaming 使用的是完整 state，而不是输出 schema。私有 channel 可能不出现在 `invoke` 的输出中，但在流里可见。

## Use pydantic models for graph state

@[StateGraph] 接受 @[`state_schema`] 参数，用于指定节点可以访问和更新的状态结构。

本页大多数示例使用 Python 原生的 `TypedDict` 或 [`dataclass`](https://docs.python.org/3/library/dataclasses.html) 作为 `state_schema`。@[`state_schema`] 可以是任何 [type](https://docs.python.org/3/library/stdtypes.html#type-objects)。

当需要对**输入**做运行时校验时，使用 [Pydantic BaseModel](https://docs.pydantic.dev/latest/api/base_model/) 作为 @[`state_schema`]。

<Note>
**已知限制**
* 图的输出**不是** Pydantic 模型的实例。
* 运行时校验只发生在图中第一个节点的输入上，不会发生在后续节点或输出上。
* Pydantic 的校验错误信息不会显示错误来自哪个节点。
* Pydantic 的递归校验可能很慢。对性能敏感的应用，推荐使用 `dataclass`。
</Note>

## Alternative state definitions

新图推荐使用 `StateSchema`。LangGraph 也支持下面的方式，用于旧代码和高级 channel 控制。

### Channels API

Channels API 提供对状态管理的低级控制。LangGraph 提供几种内置的 channel 类型：

| Channel 类型 | 行为 | 使用场景 |
|--------------|----------|----------|
| `LastValue` | 存储最新值 | 会被覆盖的简单字段 |
| `BinaryOperatorAggregate` | 使用 reducer 函数组合值 | 累积值（计数器、列表） |
| `Topic` | 把所有值收集到一个序列 | 事件流、审计日志 |
| `EphemeralValue` | 在 super-step 之间重置的值 | 临时计算状态 |

### Comparison table

| 方法 | Reducer | 类型安全 | Zod 版本 | 推荐 |
|----------|----------|-------------|-------------|-------------|
| `StateSchema` | ✅ 内置 | ✅ 完整 | v3 或 v4 | ✅ 是 |
| Channels API | ✅ 手动 | ⚠️ 部分 | 不适用 | 用于高级场景 |
| `Annotation.Root` | ✅ 内置 | ✅ 完整 | 不适用 | 旧版 |
| Zod v3 + `.langgraph` | ✅ 通过插件 | ✅ 完整 | 仅 v3 | 旧版 |
