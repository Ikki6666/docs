---
title: MULTIPLE_SUBGRAPHS
---

当你在一个节点里 [调用子图](/oss/langgraph/use-subgraphs#call-a-subgraph-inside-a-node) 多次，并且这个子图使用 `checkpointer=True`（continuations 模式）编译时，就会出现这个错误。

## 排查

请根据你的需求，在下面选一个方案：

:::python
1. **不需要 interrupts？** 使用 `checkpointer=False` 彻底关闭 checkpointing：
   ```python
   subgraph = subgraph_builder.compile(checkpointer=False)
   ```

2. **需要 interrupts，但不需要跨调用持久化？** 省略 `checkpointer`，使用默认的继承模式：
   ```python
   subgraph = subgraph_builder.compile()
   ```
   每次调用都会获得一个唯一命名空间，因此并行执行可以正常工作。子图每次都会从头开始，但仍然可以使用 `interrupt()`。

3. **需要跨调用持久化？** 使用 `checkpointer=True`。LangGraph 会为每次调用分配一个基于位置的命名空间后缀（`calling_node`、`calling_node|1` 等），以避免冲突。若想使用稳定的、基于名称的命名空间，可以给每个子图包一层唯一的节点名，参见 [并行子图](/oss/langgraph/use-subgraphs#subgraph-persistence)。
:::

:::js
1. **不需要 interrupts？** 使用 `checkpointer: false` 彻底关闭 checkpointing：
   ```typescript
   const subgraph = subgraphBuilder.compile({ checkpointer: false });
   ```

2. **需要 interrupts，但不需要跨调用持久化？** 省略 `checkpointer`，使用默认的继承模式：
   ```typescript

   ```
   每次调用都会获得一个唯一命名空间，因此并行执行可以正常工作。子图每次都会从头开始，但仍然可以使用 `interrupt()`。

3. **需要跨调用持久化？** 使用 `checkpointer: true`。LangGraph 会为每次调用分配一个基于位置的命名空间后缀（`calling_node`、`calling_node|1` 等），以避免冲突。若想使用稳定的、基于名称的命名空间，可以给每个子图包一层唯一的节点名，参见 [并行子图](/oss/langgraph/use-subgraphs#subgraph-persistence)。
:::
