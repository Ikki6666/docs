Stores 让智能体可以跨线程保存信息，包括用户偏好、累积知识，以及应该在单次对话之外继续保留的事实。和 [checkpointers](/oss/langgraph/checkpointers) 不同，checkpointer 会把完整的图状态保存在单个线程范围内，而 store 则保存任何线程都能访问的任意键值数据。

![共享状态模型](/oss/images/shared_state.png)

<Info>
**Agent Server 会自动处理 store**
使用 [Agent Server](/langsmith/agent-server) 时，你不需要手动实现或配置 store。API 会在后台为你处理所有存储基础设施。
</Info>

<Note>
@[InMemoryStore] 适合开发和测试。生产环境请使用持久化 store，例如 `PostgresStore`、`MongoDBStore`、`RedisStore` 或 `UpstashStore`。所有实现都继承自 @[BaseStore]，这是你在节点函数签名中应使用的类型注解。
</Note>

可用 provider 的完整列表请参见 [store 集成](/oss/integrations/long-term-memory/index)。
</Note>

## 基本用法

下面的代码片段独立展示了 @[InMemoryStore]，没有使用 LangGraph：

:::python
```python
from langgraph.store.memory import InMemoryStore
store = InMemoryStore()
```
:::

:::js
```typescript
import { MemoryStore } from "@langchain/langgraph";

const memoryStore = new MemoryStore();
```
:::

记忆会用 `tuple` 命名空间来区分，在下面这个示例里，它是 `(<user_id>, "memories")`。命名空间长度可以是任意的，也可以代表任意含义，不必一定和用户相关。

:::python
```python
user_id = "1"
namespace_for_memory = (user_id, "memories")
```
:::

:::js
```typescript
const userId = "1";
const namespaceForMemory = [userId, "memories"];
```
:::

使用 `store.put` 方法把记忆保存到 store 中的某个命名空间。你需要指定上面定义的命名空间，以及这条记忆对应的键值对：key 只是这条记忆的唯一标识符（`memory_id`），value（一个字典）则是记忆本身。

:::python
```python
memory_id = str(uuid.uuid4())
memory = {"food_preference" : "I like pizza"}
store.put(namespace_for_memory, memory_id, memory)
```
:::

:::js
```typescript
const memoryId = crypto.randomUUID();
const memory = { food_preference: "I like pizza" };
await memoryStore.put(namespaceForMemory, memoryId, memory);
```
:::

使用 `store.search` 方法可以从命名空间中读出记忆，它会针对给定用户返回一个列表，最多返回 `limit` 个结果（默认是 `10`）。对于 `InMemoryStore`，条目按插入顺序返回，所以列表里最后一条就是最新的记忆；其他后端的排序方式可能不同（参见 [在命名空间中列出条目](#listing-items-in-a-namespace)）。

:::python
```python
memories = store.search(namespace_for_memory)
memories[-1].dict()
{'value': {'food_preference': 'I like pizza'},
 'key': '07e0caf4-1631-47b7-b15f-65515d4c1843',
 'namespace': ['1', 'memories'],
 'created_at': '2024-10-02T17:22:31.590602+00:00',
 'updated_at': '2024-10-02T17:22:31.590605+00:00'}
```

每种记忆条目都是一个 Python 类（[`Item`](https://langchain-ai.github.io/langgraph/reference/store/#langgraph.store.base.Item)），带有若干属性。我们可以通过 `.dict` 把它转换为字典来访问。

它包含这些属性：

* `value`：这条记忆的值，本身是一个字典。
* `key`：这条记忆在该命名空间中的唯一 key。
* `namespace`：一个字符串元组，表示这条记忆所属的命名空间。

    <Note>
    虽然它的类型是 `tuple[str, ...]`，但序列化为 JSON 时可能会变成列表（例如 `['1', 'memories']`）。
    </Note>

* `created_at`：这条记忆创建的时间戳。
* `updated_at`：这条记忆更新的时间戳。

:::

:::js
```typescript
const memories = await memoryStore.search(namespaceForMemory);
memories[memories.length - 1];

// {
//   value: { food_preference: 'I like pizza' },
//   key: '07e0caf4-1631-47b7-b15f-65515d4c1843',
//   namespace: ['1', 'memories'],
//   createdAt: '2024-10-02T17:22:31.590602+00:00',
//   updatedAt: '2024-10-02T17:22:31.590605+00:00'
// }
```

它包含这些属性：

* `value`：这条记忆的值。
* `key`：这条记忆在该命名空间中的唯一 key。
* `namespace`：一个字符串元组，表示这条记忆所属的命名空间。

    <Note>
    虽然它的类型是 `tuple`，但序列化为 JSON 时可能会变成列表（例如 `['1', 'memories']`）。
    </Note>

* `createdAt`：这条记忆创建的时间戳。
* `updatedAt`：这条记忆更新的时间戳。

需要记住三点行为：

- **`namespace_prefix` 是按前缀匹配，不是精确匹配。** `("alice",)` 也会返回 `("alice", "memories")`、`("alice", "preferences")` 等子命名空间下的条目。若要限制在单层，请传入完整命名空间，或者在客户端根据 `item.namespace` 过滤返回项。
- **超过 `limit` 的结果会被静默截断。** 不会有溢出信号，因此请把 `limit` 设得高于预期最大值，或者用 `offset` 分页。
- **默认排序取决于 store 后端。** `PostgresStore` 和 `AsyncPostgresStore` 会按 `updated_at` 降序返回结果（最近更新的排在前面）。`InMemoryStore` 则按插入顺序返回（最近插入的排在最后）。不要在不同实现之间依赖固定顺序；如果顺序重要，请在客户端按 `item.updated_at` 排序。

## 语义搜索

除了简单检索之外，store 还支持语义搜索，让你可以基于含义而不是精确匹配来查找记忆。要启用这一点，请用 embedding 模型配置 store：

:::python
```python
from langchain.embeddings import init_embeddings

store = InMemoryStore(
    index={
        "embed": init_embeddings("openai:text-embedding-3-small"),  # embedding 提供方
        "dims": 1536,                              # embedding 维度
        "fields": ["food_preference", "$"]              # 要嵌入的字段
    }
)
```
:::

:::js
```typescript
import { OpenAIEmbeddings } from "@langchain/openai";

const store = new InMemoryStore({
  index: {
    embeddings: new OpenAIEmbeddings({ model: "text-embedding-3-small" }),
    dims: 1536,
    fields: ["food_preference", "$"], // 要嵌入的字段
  },
});
```
:::

现在在搜索时，你可以用自然语言查询找到相关记忆：

:::python
```python
# 查找关于饮食偏好的记忆
# （这可以在把记忆写入 store 之后进行）
memories = store.search(
    namespace_for_memory,
    query="用户喜欢吃什么？",
    limit=3  # 返回前三个匹配
)
```
:::

:::js
```typescript
// 查找关于饮食偏好的记忆
// （这可以在把记忆写入 store 之后进行）
const memories = await store.search(namespaceForMemory, {
  query: "用户喜欢吃什么？",
  limit: 3, // 返回前三个匹配
});
```
:::

你可以通过配置 `fields` 参数，或者在存储记忆时指定 `index` 参数，来控制哪些内容会被嵌入：

:::python
```python
# 使用特定字段进行嵌入
store.put(
    namespace_for_memory,
    str(uuid.uuid4()),
    {
        "food_preference": "I love Italian cuisine",
        "context": "Discussing dinner plans"
    },
    index=["food_preference"]  # 只嵌入 "food_preferences" 字段
)

# 不进行嵌入的存储（仍可检索，但不可用于语义搜索）
store.put(
    namespace_for_memory,
    str(uuid.uuid4()),
    {"system_info": "Last updated: 2024-01-01"},
    index=False
)
```
:::

:::js
```typescript
// 使用特定字段进行嵌入
await store.put(
  namespaceForMemory,
  crypto.randomUUID(),
  {
    food_preference: "I love Italian cuisine",
    context: "Discussing dinner plans",
  },
  { index: ["food_preference"] } // 只嵌入 "food_preferences" 字段
);

// 不进行嵌入的存储（仍可检索，但不可用于语义搜索）
await store.put(
  namespaceForMemory,
  crypto.randomUUID(),
  { system_info: "Last updated: 2024-01-01" },
  { index: false }
);
```
:::

## 在 LangGraph 中使用

:::python
store 和 checkpointer 是配合使用的：checkpointer 会把状态保存到线程中，如上所述；store 则允许你保存任意信息，以便在 _跨线程_ 访问。像下面这样同时带上 checkpointer 和 store 来编译图。

```python
from dataclasses import dataclass
from langgraph.checkpoint.memory import InMemorySaver

@dataclass
class Context:
    user_id: str

# 我们需要这个，是因为我们想启用线程（对话）
checkpointer = InMemorySaver()

# ... 定义图 ...

# 用 checkpointer 和 store 编译图
builder = StateGraph(MessagesState, context_schema=Context)
# ... 添加节点和边 ...
graph = builder.compile(checkpointer=checkpointer, store=store)
```
:::

:::js
`memoryStore` 和 checkpointer 是配合使用的：checkpointer 会把状态保存到线程中，如上所述；`memoryStore` 则允许你保存任意信息，以便在 _跨线程_ 访问。像下面这样同时带上 checkpointer 和 `memoryStore` 来编译图。

```typescript
import { MemorySaver } from "@langchain/langgraph";

// 我们需要这个，是因为我们想启用线程（对话）
const checkpointer = new MemorySaver();

// ... 定义图 ...

// 用 checkpointer 和 store 编译图
const graph = workflow.compile({ checkpointer, store: memoryStore });
```
:::

然后像之前一样，用 `thread_id` 调用图，同时再传入 `user_id`。`user_id` 会作为这个特定用户记忆的命名空间。

:::python
```python
# 调用图
config = {"configurable": {"thread_id": "1"}}

# 先和 AI 打个招呼
for update in graph.stream(
    {"messages": [{"role": "user", "content": "hi"}]},
    config,
    stream_mode="updates",
    context=Context(user_id="1"),
):
    print(update)
```
:::

:::js
```typescript
// 调用图
const userId = "1";
const config = { configurable: { thread_id: "1" }, context: { userId } };

// 先和 AI 打个招呼
for await (const update of await graph.stream(
  { messages: [{ role: "user", content: "hi" }] },
  { ...config, streamMode: "updates" }
)) {
  console.log(update);
}
```
:::

:::python
你可以通过把 `Runtime` 对象作为节点函数参数，在 _任何节点_ 中访问 store 和 `user_id`。当你把它作为节点函数参数时，LangGraph 会自动注入 `Runtime`。你可以用它来保存记忆：

```python
from langgraph.runtime import Runtime
from dataclasses import dataclass

@dataclass
class Context:
    user_id: str

async def update_memory(state: MessagesState, runtime: Runtime[Context]):

    # 从 runtime context 里获取 user id
    user_id = runtime.context.user_id

    # 为记忆设置命名空间
    namespace = (user_id, "memories")

    # ... 分析对话并创建新记忆

    # 创建新的 memory ID
    memory_id = str(uuid.uuid4())

    # 我们创建一条新记忆
    await runtime.store.aput(namespace, memory_id, {"memory": memory})

```


:::

:::js
你可以通过 `runtime` 参数在 _任何节点_ 中访问 store 和 `userId`。你可以用它来保存记忆：

```typescript
import { StateSchema, MessagesValue, Runtime } from "@langchain/langgraph";

const MessagesState = new StateSchema({
  messages: MessagesValue,
});

const updateMemory: GraphNode<typeof MessagesState> = async (state, runtime) => {
  // 从 config 里获取 user id
  const userId = runtime.context?.user_id;
  if (!userId) throw new Error("User ID is required");

  // 为记忆设置命名空间
  const namespace = [userId, "memories"];

  // ... 分析对话并创建新记忆
  const memory = "Some memory content";

  // 创建新的 memory ID
  const memoryId = crypto.randomUUID();

  // 我们创建一条新记忆
  await runtime.store?.put(namespace, memoryId, { memory });
};
```

## 构建自定义 store


如果你想使用内置实现以外的存储后端，可以继承 @[BaseStore] 并实现它要求的方法。内置的 @[InMemoryStore] 是最简单的参考实现。

### 基础契约

全部五个 async 方法都是必需的。同步版本（`put`、`get`、`delete`、`search`、`list_namespaces`）虽然不是强制要求，但为了兼容同步图执行，仍然建议实现。

| 方法 | 说明 |
|--------|-------------|
| `aput(namespace, key, value, index=None)` | 存储或覆盖单个条目 |
| `aget(namespace, key)` | 按 key 获取单个条目；缺失时返回 `None` |
| `adelete(namespace, key)` | 删除单个条目 |
| `asearch(namespace_prefix, *, query=None, filter=None, limit=10, offset=0)` | 在命名空间前缀下搜索条目；也可按语义查询搜索 |
| `alist_namespaces(*, prefix=None, suffix=None, max_depth=None, limit=100, offset=0)` | 列出匹配某种前缀/后缀模式的命名空间 |

在实现之前，先查看精确签名：

```python
import inspect
from langgraph.store.base import BaseStore
print(inspect.getsource(BaseStore))
```

### 命名空间设计

命名空间是字符串元组，例如 `("user_id", "memories")`。store 实现必须支持：

- **前缀匹配**：`asearch(("alice",))` 会返回 `("alice",)`、`("alice", "memories")` 以及其他子命名空间下的条目。
- **精确 key 查询**：`aget(("alice", "memories"), "some-key")` 的复杂度必须是 O(1) 或接近 O(1)。

对于 SQL 后端，常见 schema 如下：

```sql
CREATE TABLE store_items (
    namespace   TEXT[] NOT NULL,
    key         TEXT NOT NULL,
    value       JSONB NOT NULL,
    created_at  TIMESTAMPTZ DEFAULT now(),
    updated_at  TIMESTAMPTZ DEFAULT now(),
    PRIMARY KEY (namespace, key)
);

CREATE INDEX ON store_items USING gin(namespace);
```

### 序列化

store 的值是普通的 Python dict，不需要特殊序列化器。你可以用 `json.dumps` / `json.loads`，或者直接使用 JSONB 列。不要存储无法 JSON 序列化的原生 Python 对象。

### 语义搜索支持

如果你的后端支持向量搜索，请在 `asearch` 中实现 `query` 参数：

- 接受 `query: str | None` 参数。
- 当 `query` 不为 `None` 时，对它做 embedding，并按余弦相似度对结果排序。
- 当传入 `query` 时，结果中的每个 `Item` 都应包含 `score` 字段。

如果你的后端不支持向量搜索，当传入 `query` 时就抛出 `NotImplementedError`。

### 测试

目前还没有自定义 store 的一致性测试套件。请以 @[InMemoryStore] 作为参考来测试：

```python
import pytest
from langgraph.store.memory import InMemoryStore
from your_module import YourStore

@pytest.fixture
async def store():
    async with YourStore.create() as s:
        yield s

@pytest.fixture
def reference():
    return InMemoryStore()

async def test_put_and_get(store, reference):
    ns = ("test", "ns")
    for s in [store, reference]:
        await s.aput(ns, "k1", {"val": 1})
        item = await s.aget(ns, "k1")
        assert item is not None
        assert item.value == {"val": 1}

    for s in [store, reference]:
        await s.aput(ns, "k1", {"val": 1})
        await s.adelete(ns, "k1")
        assert await s.aget(ns, "k1") is None
```
