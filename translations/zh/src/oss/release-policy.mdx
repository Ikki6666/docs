    :::python
    随着 LangChain 1.0 发布，`langchain` 和 `langchain-core` 的 **minor** 版本发布（例如从 `1.0.x` 到 `1.1.0`）遵循语义化版本控制，并且可能会较频繁地发布。minor 版本包含新特性和改进，但不包含 breaking changes。

    ## API 稳定性

    :::python
    LLM 应用开发是一个快速演进的领域，我们会持续从用户和社区中学习。因此，我们预计 `langchain` 和 `langchain-core` 中的 API 会继续演化，以更好地满足用户需求。
    :::
    :::js
    LLM 应用开发是一个快速演进的领域，我们会持续从用户和社区中学习。因此，我们预计 `langchain` 和 `@langchain/core` 中的 API 会继续演化，以更好地满足用户需求。
    :::

    自从 LangChain 1.0 采用语义化版本控制后：

    - 对公共 API 的 breaking changes 只会出现在 major 版本发布中（例如 `2.0.0`）
    - minor 版本升级（例如 `1.0.0` 到 `1.1.0`）只增加新特性，不包含 breaking changes
    - patch 版本升级（例如 `1.0.0` 到 `1.0.1`）包含 bug 修复和小幅改进

    我们通常会尽量避免做没有必要的改动，并会为被移除的功能提供弃用策略。

    ### 其他包的稳定性

    LangChain 生态中其他包的稳定性可能有所不同：

    - **由 LangChain 维护的 partner packages**（例如 `langchain-openai` 和 `langchain-anthropic`）遵循语义化版本控制，并且在 1.0 之后预计会保持稳定。其他 partner packages 可能采用不同的稳定性和版本策略，更多信息请参阅这些包各自的文档。

    ## 弃用策略

    在有更好的替代方案之前，我们通常会避免弃用功能。

    :::python
    在 LangChain 1.0 的语义化版本控制策略下，被弃用的功能会在整个 1.x 发布序列中继续可用。包括移除被弃用功能在内的 breaking changes，只会出现在 major 版本发布中（例如 2.0）。

    当 `langchain` 或 `langchain-core` 中的某个功能被弃用时，我们会：
    - 在代码和文档中清楚标记其已弃用
    - 提供迁移到推荐替代方案的指导
    - 在整个 1.x minor 发布周期内为该弃用功能提供安全更新
    :::

    ## 长期支持（LTS）

    LangChain 采用长期支持（LTS）策略，为生产应用提供稳定性：

    ### 发布状态定义

    包会被标记为以下状态之一：
    - **ACTIVE**：当前处于活跃开发阶段，包含 bug 修复、安全补丁和新特性
    - **MAINTENANCE**：接收所有安全补丁和关键 bug 修复，但不再添加新特性

    ### 当前 LTS 版本

    **LangChain 1.0** 被指定为 LTS 版本：
    - **Status**：在 2.0 发布之前为 ACTIVE
    - **Support period**：2.0 发布后，1.0 将进入 MAINTENANCE 模式，至少持续 1 年
    - **Semver compliance**：用户可以在 minor 版本之间升级（例如从 1.0 到 1.1），且不会遇到 breaking changes

    ### 旧版本支持

    **LangChain 0.3**：

    - **Status**：MAINTENANCE 模式
    - **Support period**：截至 2026 年 12 月
    - **Support includes**：安全补丁和关键 bug 修复

    <Tab title="LangGraph">
    LangGraph 采用结构化的发布策略，以确保面向生产应用的稳定性和可预测性。

    ## 发布节奏

    我们预计 **major** 版本之间至少间隔 6 到 12 个月，以为生产应用提供稳定性。

    **Minor** 版本通常每 1 到 2 个月发布一次，包含新特性和改进。

    **Patch** 版本会按需发布，通常为每周一次，用来处理 bug 和安全问题。

    ## API 稳定性

    ### 稳定 API

    所有不带特殊前缀的 API 都被视为稳定，可直接用于生产环境。我们会在同一 major 版本内保持对稳定功能的向后兼容性。

    ### beta 功能

    文档中标记为 `beta` 的功能：

    - 功能完整并经过测试
    - 可以用于生产环境，但你需要理解它们后续仍可能变化
    - 可能会根据用户反馈进行小幅 API 调整

    ### 实验性功能

    标记为 `experimental` 或 `alpha` 的功能：

    - 仍在积极开发中
    - 可能发生较大变化或被移除
    - 在生产环境中应谨慎使用

    ### 内部 API

    以 `_` 为前缀或被明确标记为 internal 的 API：

    - 不属于公共 API 的一部分
    - 可能在没有通知的情况下发生变化
    - 不应直接使用

    ## 弃用策略

    在弃用功能时：

    1. **Deprecation Notice**：会明确标记该功能已弃用，并提供清晰的迁移指导
    2. **Grace Period**：被弃用的功能至少会在一个 minor 版本内保持可用
    3. **Removal**：功能只会在 major 版本发布时移除
    4. **Migration Support**：我们会提供迁移指南，并在可行时提供自动化工具

    ## 平台兼容性

    :::python
    ### Python 支持

    - 我们支持仍由 Python Software Foundation 主动维护的 Python 版本
    - Python 版本要求只会在 major 版本中变更
    - 当前要求 Python 3.10 或更高版本
    :::

    :::js
    ### JavaScript/TypeScript 支持

    - 我们支持 Node.js LTS 版本
    - 所有公共 API 都提供 TypeScript 类型定义
    - 浏览器兼容性会为客户端组件单独记录
    :::

    ## Breaking changes

    breaking changes 只会在 major 版本中引入，包括：

    - 移除已弃用的 API
    - 修改必需参数
    - 修改会影响现有应用的默认行为
    - 更新最低 Python/Node.js 版本要求

    ## 迁移支持

    对于 major 版本升级，我们会提供：

    - 完整的迁移指南
    - 在可行时提供自动化迁移脚本
    - 为上一个 major 版本提供延长支持期
    - 清晰记录所有 breaking changes

    ## 长期支持（LTS）

    LangGraph 采用长期支持（LTS）策略，为生产应用提供稳定性：

    ### 发布状态定义

    包会被标记为以下状态之一：

    - **ACTIVE**：当前处于活跃开发阶段，包含 bug 修复、安全补丁和新特性
    - **MAINTENANCE**：接收所有安全补丁和关键 bug 修复，但不再添加新特性

    ### 当前 LTS 版本

    - **Status**：在 2.0 发布之前为 ACTIVE
    - **Support period**：2.0 发布后，1.0 将进入 MAINTENANCE 模式，至少持续 1 年
    - **Semver compliance**：用户可以在 minor 版本之间升级（例如从 1.0 到 1.1），且不会遇到 breaking changes

    ### 旧版本支持

    **LangGraph 0.4**：

    :::python
    Deep Agents（`deepagents`）是一个快速演进的包，用于构建高级智能体架构。

    ## 1.0 之前的状态

    Deep Agents 当前仍处于 1.0 之前的开发阶段。尽管我们会尽量减少 breaking changes，但随着我们吸收社区经验，并适应 agentic applications 快速变化的环境，API 仍可能继续演进。

    ## 发布节奏

    **Minor** 版本（例如 `0.1.0` 到 `0.2.0`）可能包含新特性，也可能包含 breaking changes，因为这个包仍在成熟过程中。

    **Patch** 版本（例如 `0.1.0` 到 `0.1.1`）包含 bug 修复和小幅改进，不会引入 breaking changes。

    ## API 稳定性

    作为一个 1.0 之前的包：

    - API 可能会在 minor 版本之间变化
    - 我们会尽力通过清晰的迁移指导来减少干扰
    - 标记为 `experimental` 或 `alpha` 的功能可能会发生更明显的变化

    ## 弃用策略

    当 Deep Agents 中的功能被弃用时：

    - 我们会尽可能提前给出弃用警告
    - 迁移指导会包含在发布说明中
    - 被弃用的功能会在后续 minor 版本中移除

    ## 通往 1.0 的路径

    Deep Agents 会在以下条件满足时达到 1.0：

    - 核心 API 基于社区反馈趋于稳定
    - 该包已经在生产环境中经过充分验证
    - 核心功能不再预期会出现 breaking changes

    在 1.0 之后，Deep Agents 将遵循与 LangChain 和 LangGraph 相同的语义化版本控制和 LTS 策略。
