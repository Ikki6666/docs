LangChain 拥有庞大的集成生态，能够接入本地或远程文件系统、API、数据库等多种外部资源。这些集成让开发者可以构建灵活的应用，把 LLM 的能力与访问、交互和操作外部资源的能力结合起来。

## 最佳实践

在构建这类应用时，开发者应当牢记以下良好安全实践：

* [**限制权限**](https://en.wikipedia.org/wiki/Principle_of_least_privilege)：将权限范围精确限制在应用所需的程度。授予宽泛或过度的权限可能引入严重的安全漏洞。为避免这类问题，请根据应用场景考虑使用只读凭证、禁止访问敏感资源、采用沙箱技术（例如在容器中运行）、指定代理配置以控制外部请求等措施。
* **预判潜在误用**：人会犯错，大语言模型（LLM）也一样。请始终假设，任何系统访问能力或凭证都可能以其权限所允许的任意方式被使用。举例来说，如果一组数据库凭证允许删除数据，那么最安全的假设就是，任何能使用这些凭证的 LLM 都确实可能删除数据。
* [**纵深防御**](https://en.wikipedia.org/wiki/Defense_in_depth_(computing))：没有任何单一安全技术是完美的。微调和良好的 chain 设计可以降低大语言模型（LLM）出错的概率，但无法彻底消除。最佳做法是组合多层安全策略，而不是依赖单层防护来保障安全。比如，同时使用只读权限和沙箱，以确保 LLM 只能访问明确授权给它使用的数据。

如果不这样做，可能带来的风险包括但不限于：

* 数据损坏或丢失。
* 未经授权访问机密信息。
* 关键资源的性能或可用性受损。

下面是一些典型场景及其缓解策略：

* 用户可能会要求一个具有文件系统访问权限的智能体删除不应删除的文件，或读取包含敏感信息的文件内容。为降低风险，请把智能体限制在特定目录中，并且只允许它读取或写入那些可以安全读写的文件。还可以进一步把智能体放进容器中运行，以增强沙箱隔离。
* 用户可能会要求一个具有外部 API 写权限的智能体向 API 写入恶意数据，或删除该 API 中的数据。为降低风险，请为智能体提供只读 API key，或将其限制为只使用那些本身就具备抗误用能力的端点。
* 用户可能会要求一个具有数据库访问权限的智能体删除表或修改 schema。为降低风险，请将凭证范围限制到智能体真正需要访问的表，并考虑发放只读凭证。

如果你正在构建会访问文件系统、API 或数据库等外部资源的应用，请考虑与公司安全团队沟通，以确定最适合的应用设计与安全方案。

## 报告 OSS 漏洞

如果发现与 LangChain 开源项目相关的安全漏洞，请使用以下流程进行报告：

1. 在漏洞所在 GitHub 仓库的 Security 标签页中**提交安全通告**。
2. 向 `security@langchain.dev` **发送邮件**，告知你已经提交了安全问题，以及提交到了哪个仓库。

在报告漏洞之前，请先阅读上面的[最佳实践](#best-practices)，以了解哪些问题被视为安全漏洞，哪些属于开发者责任范围。

### Bug bounty 资格

欢迎提交针对所有 LangChain 库的安全漏洞报告。不过，我们可能只会针对以下包中的漏洞，酌情提供临时 bug bounty：

* 由 LangChain 团队拥有并维护的核心库：`langchain-core`、`langchain`（v1）、`langgraph` 及相关 checkpointer 包（或其 JavaScript 对应版本）
* 由 LangChain 团队维护的热门集成（例如 `langchain-openai`、`langchain-anthropic` 等，或其 JavaScript 对应版本）

漏洞必须存在于库本身的代码中，而不是示例代码或示例应用中。

对于其他 LangChain 包，我们同样欢迎安全报告，并会处理有效的安全问题，但不会为超出上述范围的包发放 bug bounty。这也包括已归档的 `langchain-community`，由于其社区驱动的性质，它不在 bug bounty 范围内，但相关报告依然会被接受和处理。

### 不在范围内的目标

以下目标不在安全漏洞报告的范围内：

* **langchain-experimental**：这个已归档仓库用于实验性代码，不在安全报告范围内（参见 [package warning](https://pypi.org/project/langchain-experimental/)）。
* **示例和示例应用**：示例代码和演示应用不在安全报告范围内。
* **已附带安全提示的代码**：这类情况会逐案判断，但通常不在范围内，因为代码已经提供了开发者应遵循的安全指引。
* **与 LangSmith 相关的仓库或 API**：请参阅下文的[报告 LangSmith 漏洞](#reporting-langsmith-vulnerabilities)。

## 报告 LangSmith 漏洞

如果发现与 LangSmith 相关的安全漏洞，请发送邮件到 `security@langchain.dev`。

* LangSmith 站点：[https://smith.langchain.com](https://smith.langchain.com)
* SDK client：[https://github.com/langchain-ai/langsmith-sdk](https://github.com/langchain-ai/langsmith-sdk)

### 其他安全问题

如有其他任何安全相关问题，请通过 `security@langchain.dev` 与我们联系。
