通过实现会在 agent 执行流程特定位置运行的 hooks，来构建自定义 middleware。

## Hooks

Middleware 提供两种 hook 风格，用来拦截 agent 执行：

<CardGroup cols={2}>
    <Card title="Node-style hooks" icon="share" href="#node-style-hooks">
        在特定执行点顺序运行。
    </Card>
    <Card title="Wrap-style hooks" icon="container" href="#wrap-style-hooks">
        围绕每次 model 或 tool 调用运行。
    </Card>
</CardGroup>

### Node-style hooks

在特定执行点顺序运行。适合日志、校验和状态更新。

选择你的 middleware 需要的 hooks。你可以在 node-style hooks 和 wrap-style hooks 之间选择。

**Node-style hooks** 会在固定的执行点运行：

:::python

| Hook | 何时运行 |
|------|---------|
| `before_agent` | agent 开始之前（每次调用一次） |
| `before_model` | 每次 model 调用之前 |
| `after_model` | 每次 model 响应之后 |
| `after_agent` | agent 完成之后（每次调用一次） |
:::

:::js
| Hook | 何时运行 |
|------|---------|
| `beforeAgent` | agent 开始之前（每次调用一次） |
| `beforeModel` | 每次 model 调用之前 |
| `afterModel` | 每次 model 响应之后 |
| `afterAgent` | agent 完成之后（每次调用一次） |
:::

**Wrap-style hooks** 会包裹每次调用，让你控制执行过程：

:::python
| Hook | 何时运行 |
|------|---------|
| `wrap_model_call` | 包裹每次 model 调用 |
| `wrap_tool_call` | 包裹每次 tool 调用 |
:::

:::js
| Hook | 何时运行 |
|------|---------|
| `wrapModelCall` | 包裹每次 model 调用 |
| `wrapToolCall` | 包裹每次 tool 调用 |
:::

**示例：**

:::python

```python
from langchain.agents.middleware import before_model, after_model, AgentState
from langchain.messages import AIMessage
from langgraph.runtime import Runtime
from typing import Any


@before_model(can_jump_to=["end"])
def check_message_limit(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    if len(state["messages"]) >= 50:
        return {
            "messages": [AIMessage("Conversation limit reached.")],
            "jump_to": "end"
        }
    return None

@after_model
def log_response(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    print(f"Model returned: {state['messages'][-1].content}")
    return None
```

```python
from langchain.agents.middleware import AgentMiddleware, AgentState, hook_config
from langchain.messages import AIMessage
from langgraph.runtime import Runtime
from typing import Any

class MessageLimitMiddleware(AgentMiddleware):
    def __init__(self, max_messages: int = 50):
        super().__init__()
        self.max_messages = max_messages

    @hook_config(can_jump_to=["end"])
    def before_model(self, state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        if len(state["messages"]) >= self.max_messages:
            return {
                "messages": [AIMessage("Conversation limit reached.")],
                "jump_to": "end"
            }
        return None

    def after_model(self, state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        print(f"Model returned: {state['messages'][-1].content}")
        return None
```

:::js

```typescript
import { createMiddleware, AIMessage } from "langchain";

const createMessageLimitMiddleware = (maxMessages: number = 50) => {
  return createMiddleware({
    name: "MessageLimitMiddleware",
    beforeModel: {
      canJumpTo: ["end"],
      hook: (state) => {
        if (state.messages.length === maxMessages) {
          return {
            messages: [new AIMessage("Conversation limit reached.")],
            jumpTo: "end",
          };
        }
        return;
      }
    },
    afterModel: (state) => {
      const lastMessage = state.messages[state.messages.length - 1];
      console.log(`Model returned: ${lastMessage.content}`);
      return;
    },
  });
};
```

### Wrap-style hooks

拦截执行，并控制 handler 何时被调用。适合重试、缓存和转换。

你可以决定 handler 被调用零次（短路）、一次（正常流程），还是多次（重试逻辑）。

**可用 hooks：**

:::python
- `wrap_model_call` - 包裹每次 model 调用
- `wrap_tool_call` - 包裹每次 tool 调用
:::

:::js
- `wrapModelCall` - 包裹每次 model 调用
- `wrapToolCall` - 包裹每次 tool 调用
:::

**示例：**

:::python

<Tabs>
<Tab title="Decorator">

```python
from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse
from typing import Callable


@wrap_model_call
def retry_model(
    request: ModelRequest,
    handler: Callable[[ModelRequest], ModelResponse],
) -> ModelResponse:
    for attempt in range(3):
        try:
            return handler(request)
        except Exception as e:
            if attempt == 2:
                raise
            print(f"Retry {attempt + 1}/3 after error: {e}")
```

</Tab>

<Tab title="Class">

```python
from langchain.agents.middleware import AgentMiddleware, ModelRequest, ModelResponse
from typing import Callable

class RetryMiddleware(AgentMiddleware):
    def __init__(self, max_retries: int = 3):
        super().__init__()
        self.max_retries = max_retries

    def wrap_model_call(
        self,
        request: ModelRequest,
        handler: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        for attempt in range(self.max_retries):
            try:
                return handler(request)
            except Exception as e:
                if attempt == self.max_retries - 1:
                    raise
                print(f"Retry {attempt + 1}/{self.max_retries} after error: {e}")
```

</Tab>
</Tabs>

:::

:::js

```typescript
import { createMiddleware } from "langchain";

const createRetryMiddleware = (maxRetries: number = 3) => {
  return createMiddleware({
    name: "RetryMiddleware",
    wrapModelCall: (request, handler) => {
      for (let attempt = 0; attempt < maxRetries; attempt++) {
        try {
          return handler(request);
        } catch (e) {
          if (attempt === maxRetries - 1) {
            throw e;
          }
          console.log(`Retry ${attempt + 1}/${maxRetries} after error: ${e}`);
        }

      }
      throw new Error("Unreachable");
    },
  });
};
```

## 状态更新

node-style 和 wrap-style hooks 都可以更新 agent state。它们的机制不同：

:::python
- **Node-style hooks** (`before_agent`, `before_model`, `after_model`, `after_agent`): 直接返回一个 dict。这个 dict 会通过 graph 的 reducer 合并到 agent state。
- **Wrap-style hooks** (`wrap_model_call`, `wrap_tool_call`): 对 model 调用来说，返回一个带 @[`Command`] 的 @[`ExtendedModelResponse`]，把状态更新和 model 响应一起注入；对 tool 调用来说，直接返回一个 @[`Command`]。当你需要根据 model 或 tool 调用期间运行的逻辑来跟踪或更新 state 时就用它们，比如 summarization 触发点、usage metadata，或者从 request/response 计算出的自定义字段。
:::

:::js
- **Node-style hooks** (`beforeAgent`, `beforeModel`, `afterModel`, `afterAgent`): 直接返回一个 dict。这个 dict 会通过 graph 的 reducer 合并到 agent state。
- **Wrap-style hooks** (`wrapModelCall`, `wrapToolCall`): 对 model 调用来说，直接返回一个 @[`Command`]，把状态更新和 model 响应一起注入；对 tool 调用来说，直接返回一个 @[`Command`]。当你需要根据 model 或 tool 调用期间运行的逻辑来跟踪或更新 state 时就用它们，比如 summarization 触发点、usage metadata，或者从 request/response 计算出的自定义字段。
:::

## 自定义 state schema

如果你的 middleware 需要在多个 hook 之间跟踪 state，就可以让 middleware 通过自定义属性扩展 agent 的 state。这样 middleware 就可以：

- **跨执行跟踪 state**：维护在 agent 执行生命周期中持续存在的计数器、标记或其他值
- **在 hooks 之间共享数据**：把信息从 `before_model` 传给 `after_model`，或者在不同 middleware 实例之间传递
- **实现横切关注点**：在不修改核心 agent 逻辑的前提下，加上限流、usage 跟踪、用户上下文或审计日志等功能
- **做条件决策**：使用累积状态决定是否继续执行、跳转到不同节点，或者动态修改行为

:::python

<Tabs>
<Tab title="Decorator">

```python
from langchain.agents import create_agent
from langchain.messages import HumanMessage
from langchain.agents.middleware import AgentState, before_model, after_model
from typing_extensions import NotRequired
from typing import Any
from langgraph.runtime import Runtime


class CustomState(AgentState):
    model_call_count: NotRequired[int]
    user_id: NotRequired[str]


@before_model(state_schema=CustomState, can_jump_to=["end"])
def check_call_limit(state: CustomState, runtime: Runtime) -> dict[str, Any] | None:
    count = state.get("model_call_count", 0)
    if count > 10:
        return {"jump_to": "end"}
    return None


@after_model(state_schema=CustomState)
def increment_counter(state: CustomState, runtime: Runtime) -> dict[str, Any] | None:
    return {"model_call_count": state.get("model_call_count", 0) + 1}


agent = create_agent(
    model="gpt-5.5",
    middleware=[check_call_limit, increment_counter],
    tools=[],
)

# 带着自定义 state 调用
result = agent.invoke({
    "messages": [HumanMessage("Hello")],
    "model_call_count": 0,
    "user_id": "user-123",
})
```

```python
    tools=[],

    "model_call_count": 0,
    "user_id": "user-123",
```

:::js

```typescript
import { createMiddleware, createAgent, HumanMessage } from "langchain";
import { StateSchema } from "@langchain/langgraph";
import * as z from "zod";

const CustomState = new StateSchema({
  modelCallCount: z.number().default(0),
  userId: z.string().optional(),
});

const callCounterMiddleware = createMiddleware({
  name: "CallCounterMiddleware",
  stateSchema: CustomState,
  beforeModel: {
    canJumpTo: ["end"],
    hook: (state) => {
      if (state.modelCallCount > 10) {
        return { jumpTo: "end" };
      }

      return;
    },
  },
  afterModel: (state) => {
    return { modelCallCount: state.modelCallCount + 1 };
  },
});

const agent = createAgent({
  model: "gpt-5.5",
  tools: [...],
  middleware: [callCounterMiddleware],
});

const result = await agent.invoke({
  messages: [new HumanMessage("Hello")],
  modelCallCount: 0,
  userId: "user-123",
});
```

state 字段可以是 public 或 private。以 underscore (`_`) 开头的字段会被视为 private，不会包含在 agent 的结果里。只有 public 字段（即没有前导 underscore 的字段）才会返回。

这对于保存不应该暴露给调用方的内部 middleware state 很有用，比如临时跟踪变量或内部标记：

```typescript
import { StateSchema } from "@langchain/langgraph";
import * as z from "zod";

const PrivateState = new StateSchema({
  // 公共字段 - 会包含在 invoke 结果里
  publicCounter: z.number().default(0),
  // 私有字段 - 不会包含在 invoke 结果里
  _internalFlag: z.boolean().default(false),
});

const middleware = createMiddleware({
  name: "ExampleMiddleware",
  stateSchema: PrivateState,
  afterModel: (state) => {
    // 执行期间两个字段都可以访问
    if (state._internalFlag) {
      return { publicCounter: state.publicCounter + 1 };
    }
    return { _internalFlag: true };
  },
});

const result = await agent.invoke({
  messages: [new HumanMessage("Hello")],
  publicCounter: 0
});

// result 只包含 publicCounter，不包含 _internalFlag
console.log(result.publicCounter); // 1
console.log(result._internalFlag); // undefined
```

## 自定义流 transformer

:::python
<Note>通过 middleware 注册的 transformer 需要 `langchain>=1.3.2`。</Note>
:::

:::js
<Note>通过 middleware 注册的 transformer 需要 `langchain@1.4.3` 或更高版本。</Note>
:::

Middleware 可以注册流 transformer factory，把 live agent stream 中的事件投影到类型化的扩展 channel 上。这对于暴露计数器、side-channel artifact、部分输出，或者做 wire-level 脱敏都很有用，而且不会和框架内建的投影耦合。

在编译时，middleware 注册的 factory 会和调用方直接传给 agent factory 的配置合并。 [最终排序规则](/oss/langchain/event-streaming#register-transformers-on-middleware) 会保持内建的 `ToolCallTransformer` 在最前面，并让调用方提供的条目排在最后。

:::python
把 `transformers` 类属性设置为一个 factory callable 的元组。每个 factory 的形状是 `Callable[[tuple[str, ...]], StreamTransformer]`，并以 `factory(scope)` 的方式调用，其中 `scope` 是 mini-mux 的 scope tuple（root 是 `()`，子图则非空）；每次调用都返回一个新的 transformer，可以保证每个子图互相隔离。

```python
from langchain.agents import create_agent
from langchain.agents.middleware import AgentMiddleware


class ToolActivityMiddleware(AgentMiddleware):
    transformers = (ToolActivityTransformer,)


agent = create_agent(
    model="gpt-5-nano",
    tools=[...],
    middleware=[ToolActivityMiddleware()],
)
```
:::

:::js
把 `streamTransformers` 传给 `createMiddleware`，类型是 factory 元组。每个 factory 的形状是 `() => StreamTransformer<any>`（零参数），并且会按 scope 调用一次；每次调用都返回一个新的 transformer，可以保证每个子图互相隔离。

```typescript
import { createAgent, createMiddleware } from "langchain";

const toolActivityMiddleware = createMiddleware({
  name: "ToolActivityMiddleware",
  streamTransformers: [toolActivityTransformer],
});

const agent = createAgent({
  model: "gpt-5-nano",
  tools: [...],
  middleware: [toolActivityMiddleware],
});
```
:::

更多排序规则和 PII 脱敏示例，请看 [Register transformers on middleware](/oss/langchain/event-streaming#register-transformers-on-middleware)。

:::js
## 自定义 context

Middleware 可以定义自定义 context schema，用来访问每次调用的元数据。与 state 不同，context 是只读的，而且不会在多次调用之间持久化。这使它非常适合：

- **用户信息**：传入在执行期间不会变化的 user ID、角色或偏好
- **配置覆盖**：提供每次调用不同的设置，比如限流或 feature flag
- **租户/工作区上下文**：在多租户应用里加入组织级数据
- **请求元数据**：传入 middleware 需要的 request ID、API key 或其他元数据

用 Zod 定义 context schema，并在 middleware hook 里通过 `runtime.context` 访问它。context schema 里必填的字段会在 TypeScript 层面强制检查，这样你在调用 `agent.invoke()` 时必须提供它们。

```typescript
import { createAgent, createMiddleware, HumanMessage } from "langchain";
import * as z from "zod";

const contextSchema = z.object({
  userId: z.string(),
  tenantId: z.string(),
  apiKey: z.string().optional(),
});

const userContextMiddleware = createMiddleware({
  name: "UserContextMiddleware",
  contextSchema,
  wrapModelCall: (request, handler) => {
    // 从 runtime 访问 context
    const { userId, tenantId } = request.runtime.context;

    // 把用户上下文加到 system message
    const contextText = `User ID: ${userId}, Tenant: ${tenantId}`;
    const newSystemMessage = request.systemMessage.concat(contextText);

    return handler({
      ...request,
      systemMessage: newSystemMessage,
    });
  },
});

const agent = createAgent({
  model: "gpt-5.5",
  middleware: [userContextMiddleware],
  tools: [],
  contextSchema,
});

const result = await agent.invoke(
  { messages: [new HumanMessage("Hello")] },
  // 必填字段（userId, tenantId）必须提供
  {
    context: {
      userId: "user-123",
      tenantId: "acme-corp",
    },
  }
);
```

**必填 context 字段**：当你在 `contextSchema` 中定义了必填字段（没有 `.optional()` 或 `.default()` 的字段）时，TypeScript 会强制要求这些字段必须在 `agent.invoke()` 调用里提供。这可以保证类型安全，并防止因为缺少必填 context 而产生 runtime 错误。

```typescript
// 如果缺少 userId 或 tenantId，这里会产生 TypeScript 错误
const result = await agent.invoke(
  { messages: [new HumanMessage("Hello")] },
  { context: { userId: "user-123" } } // Error: tenantId is required
);
```

## 执行顺序

当使用多个 middleware 时，要理解它们的执行方式：

:::python
```python
agent = create_agent(
    model="gpt-5.5",
    middleware=[middleware1, middleware2, middleware3],
    tools=[...],
)
```
:::

:::js
```typescript
const agent = createAgent({
  model: "gpt-5.5",
  middleware: [middleware1, middleware2, middleware3],
  tools: [...],
});
```
:::

<Accordion title="执行流程">

**Before hooks 按顺序运行：**
1. `middleware1.before_agent()`
2. `middleware2.before_agent()`
3. `middleware3.before_agent()`

__Agent loop starts__

4. `middleware1.before_model()`
5. `middleware2.before_model()`
6. `middleware3.before_model()`

**Wrap hooks 像函数调用一样嵌套：**

7. `middleware1.wrap_model_call()` → `middleware2.wrap_model_call()` → `middleware3.wrap_model_call()` → model

**After hooks 按逆序运行：**

8. `middleware3.after_model()`
9. `middleware2.after_model()`
10. `middleware1.after_model()`

__Agent loop ends__

11. `middleware3.after_agent()`
12. `middleware2.after_agent()`
13. `middleware1.after_agent()`

</Accordion>

**关键规则：**
- `before_*` hooks：从前到后
- `after_*` hooks：从后到前（逆序）
- `wrap_*` hooks：嵌套（第一个 middleware 包裹所有其他 middleware）

## Agent jumps

如果你想从 middleware 里提前退出，就返回一个带 `jump_to` 的字典：

**可用的跳转目标：**
- `'end'`：跳到 agent 执行结束（或第一个 `after_agent` hook）
- `'tools'`：跳到 tools 节点
- `'model'`：跳到 model 节点（或第一个 `before_model` hook）

:::python

```python
from langchain.agents.middleware import after_model, hook_config, AgentState

@hook_config(can_jump_to=["end"])
def check_for_blocked(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:

    if "BLOCKED" in last_message.content:
        return {
            "messages": [AIMessage("I cannot respond to that request.")],
            "jump_to": "end"
```

## 最佳实践

1. 保持 middleware 聚焦，每个只做好一件事
2. 优雅处理错误，不要让 middleware 错误把 agent 搞崩
3. **使用合适的 hook 类型**：
    - Node-style 适合顺序逻辑（日志、校验）
    - Wrap-style 适合控制流（重试、fallback、缓存）
4. 清晰记录任何自定义 state 属性
5. 在集成前先单独给 middleware 做单元测试
6. 考虑执行顺序，把关键 middleware 放在列表前面
7. 能用内建 middleware 时尽量使用内建的

### Wrap-style hooks

:::python

从 `wrap_model_call` 返回一个带 @[`Command`] 的 @[`ExtendedModelResponse`]，就可以在 model 调用层注入状态更新：

```python
from typing import Callable
from langchain.agents.middleware import (
    wrap_model_call,
    ModelRequest,
    ModelResponse,
    AgentState,
    ExtendedModelResponse
)
from langgraph.types import Command
from typing_extensions import NotRequired

class UsageTrackingState(AgentState):
    """带 token usage 追踪的 agent state。"""

    last_model_call_tokens: NotRequired[int]


@wrap_model_call(state_schema=UsageTrackingState)
def track_usage(
    request: ModelRequest,
    handler: Callable[[ModelRequest], ModelResponse],
) -> ExtendedModelResponse:
    response = handler(request)
    return ExtendedModelResponse(
        model_response=response,
        command=Command(update={"last_model_call_tokens": 150}),
    )
```

:::

:::js

从 `wrapModelCall` 直接返回一个 @[`Command`]，就可以在 model 调用层注入状态更新：

```typescript
import * as z from "zod";
import { createMiddleware } from "langchain";
import { Command } from "@langchain/langgraph";

const usageTrackingStateSchema = z.object({
  lastModelCallTokens: z.number().optional(),
});

const trackUsage = createMiddleware({
  name: "trackUsage",
  stateSchema: usageTrackingStateSchema,
  wrapModelCall: async (request, handler) => {
    const response = await handler(request);
    return new Command({ update: { lastModelCallTokens: 150 } });
  },
});
```

:::

@[`Command`] 会沿着 graph 的 reducer 传递，所以更新会正确应用，messages 是追加式的，而不是覆盖已有 state。

#### 组合多个 middleware

:::python

当多个 middleware 层都返回 `ExtendedModelResponse` 时，它们的 command 会组合起来：

- **Command 通过 reducer 应用**：每个 `Command` 都会成为一条独立的 state 更新。对于 messages 来说，这意味着它们是追加式的。
- **冲突时外层优先**：对于没有 reducer 的 state 字段，command 会按 inner-first、outer-last 的顺序应用。最外层 middleware 的值会覆盖冲突键。
- **重试安全**：如果外层 middleware 实现了可能多次调用 `handler()` 的逻辑（比如重试），那么更早那次调用生成的 command 会被丢弃。

:::

:::js

当多个 middleware 层都返回响应时，框架会传递最后生成的 `AIMessage`：

- **AIMessage 会继续往外传**：每个 middleware 的 `handler()` 接收到的都是上一层 middleware 产生的 `AIMessage`。当某个 middleware 返回 `AIMessage` 时，它会成为下一层 handler 的输入。
- **没有 message 更新的 Command 会透传**：如果 middleware 返回的 `Command` 没有更新 `messages`，框架会把它当成 message 流里的 no-op。下一层 handler 接收到的仍是返回该 `Command` 之前的 middleware 的 `AIMessage`。
- **reducer 行为和重试安全**：Command 仍然会通过 reducer 应用（messages 追加，冲突时 outer wins）。重试逻辑会丢弃更早调用产生的 command。

:::

:::python

```python
from typing import Annotated, Callable

from langchain.agents.middleware import (
    AgentMiddleware,
    AgentState,
    ExtendedModelResponse,
    ModelRequest,
    ModelResponse,
)
from langchain.messages import SystemMessage
from langgraph.types import Command
from typing_extensions import NotRequired


def _last_wins(_a: str, b: str) -> str:
    """Reducer：最后写入者获胜（外层覆盖内层）。"""
    return b


class CustomMiddlewareState(AgentState):
    """Agent state：trace_layer 使用 last-wins（外层赢），messages 使用追加式 reducer。"""

    # 非 reducer 字段，采用 last-wins：两个 middleware 都写时，最外层值获胜
    trace_layer: NotRequired[Annotated[str, _last_wins]]


class OuterMiddleware(AgentMiddleware):
    def wrap_model_call(
        self,
        request: ModelRequest,
        handler: Callable[[ModelRequest], ModelResponse],
    ) -> ExtendedModelResponse:
        response = handler(request)
        return ExtendedModelResponse(
            model_response=response,
            command=Command(update={
                "trace_layer": "outer",
                "messages": [SystemMessage(content="[Outer ran]")],
            }),
        )


class InnerMiddleware(AgentMiddleware):
    """添加 trace_layer 和 message。外层也会写同样的键；trace_layer 外层赢，messages 采用追加式。"""

    def wrap_model_call(
        self,
        request: ModelRequest,
        handler: Callable[[ModelRequest], ModelResponse],
    ):
        response = handler(request)
        return ExtendedModelResponse(
            model_response=response,
            command=Command(update={
                "trace_layer": "inner",
                "messages": [SystemMessage(content="[Inner ran]")],
            }),
        )
```

:::

:::js

```typescript
import * as z from "zod";
import { createMiddleware } from "langchain";
import { Command, StateSchema, ReducedValue } from "@langchain/langgraph";

/** last-wins reducer：两个 middleware 都写时，外层覆盖内层。 */

        messages: [new SystemMessage({ content: "[Outer ran]" })],

    });
  },
});

const innerMiddleware = createMiddleware({
  name: "InnerMiddleware",
  stateSchema: customMiddlewareStateSchema,

    await handler(_request);
    return new Command({
      update: {
        traceLayer: "inner",
        messages: [new SystemMessage({ content: "[Inner ran]" })],
```

## 创建 middleware

:::python

你可以通过两种方式创建 middleware：

<CardGroup cols={2}>
  <Card title="基于装饰器的 middleware" icon="at" href="#decorator-based-middleware">
    适合单个 hook，简单直接。用装饰器包装单独函数。
  </Card>
  <Card title="基于类的 middleware" icon="braces" href="#class-based-middleware">
    适合更复杂的 middleware，可以包含多个 hook 或配置。

### 基于装饰器的 middleware

适合单个 hook，简单直接。用装饰器包装单独函数。

**可用装饰器：**

**Node-style:**
- @[`@before_agent`] - 在 agent 开始前运行（每次调用一次）
- @[`@before_model`] - 在每次 model 调用前运行
- @[`@after_model`] - 在每次 model 响应后运行
- @[`@after_agent`] - 在 agent 完成后运行（每次调用一次）

**Wrap-style:**
- @[`@wrap_model_call`] - 用自定义逻辑包裹每次 model 调用
- @[`@wrap_tool_call`] - 用自定义逻辑包裹每次 tool 调用

**便捷装饰器：**
- @[`@dynamic_prompt`] - 生成动态 system prompt

**示例：**

```python
from langchain.agents.middleware import (
    before_model,
    wrap_model_call,
    AgentState,
    ModelRequest,
    ModelResponse,
)
from langchain.agents import create_agent
from langgraph.runtime import Runtime
from typing import Any, Callable


@before_model
def log_before_model(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    print(f"About to call model with {len(state['messages'])} messages")
    return None

@wrap_model_call
def retry_model(
    request: ModelRequest,
    handler: Callable[[ModelRequest], ModelResponse],
) -> ModelResponse:
    for attempt in range(3):
        try:
            return handler(request)
        except Exception as e:
            if attempt == 2:
                raise
            print(f"Retry {attempt + 1}/3 after error: {e}")

agent = create_agent(
    model="gpt-5.5",
    middleware=[log_before_model, retry_model],
    tools=[...],
)
```

**何时使用装饰器：**
- 只需要一个 hook
- 没有复杂配置
- 快速原型开发

### 基于类的 middleware

如果 middleware 需要多个 hook 或配置，类方式会更强大。当你需要为同一个 hook 定义同步和异步实现，或者想把多个 hook 组合进一个 middleware 时，使用类。

:::python
`AgentMiddleware` 子类可以声明三个类属性，agent factory 会在编译时读取它们：

- `state_schema` - 用自定义字段扩展 agent state。见 [Custom state schema](#custom-state-schema)。
- `tools` - 注册 middleware 自带的额外 tools（例如待办列表 middleware 里的 `write_todos`）。
- `transformers` - 注册 scope-aware 的 stream transformer factory。见 [Custom stream transformers](#custom-stream-transformers)。
:::

:::js
`createMiddleware` 接受三个配置字段，agent factory 会在编译时读取它们：

- `stateSchema` - 用自定义字段扩展 agent state。见 [Custom state schema](#custom-state-schema)。
- `tools` - 注册 middleware 自带的额外 tools。
- `streamTransformers` - 注册 scope-aware 的 stream transformer factory。见 [Custom stream transformers](#custom-stream-transformers)。
:::

**示例：**
