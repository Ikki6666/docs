LangChain 和 [Deep Agents](/oss/deepagents/overview) 提供了一组适用于常见场景的预构建 middleware。每个 middleware 都可以直接用于生产，并且可按你的具体需求进行配置。

## 与模型无关的 middleware

下面这些 middleware 适用于任何 LLM 提供商：

### Summarization

在接近 token 上限时自动总结对话历史，保留最近消息，同时压缩更早的上下文。Summarization 适用于以下场景：
- 长时间运行、历史很长的对话。
- 具有大量历史记录的多轮对话。
- 需要保留完整对话脉络的应用。

<Note>
Summarization 是面向文本的上下文压缩。它不会对图像、音频或视频 payload 进行缩放、降采样或其他压缩。`keep` 保留的最近消息仍然保留原始多模态 blocks，而被总结掉的旧多模态消息只会以生成的文本摘要形式存在。对于图片很多的应用，请把媒体存到文件系统或对象存储中，并通过 URL 或文件引用放进消息历史。
</Note>

:::python
**API reference:** @[`SummarizationMiddleware`]

```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware

agent = create_agent(
    model="gpt-5.5",
    tools=[your_weather_tool, your_calculator_tool],
    middleware=[
        SummarizationMiddleware(
            model="gpt-5.4-mini",
            trigger=("tokens", 4000),
            keep=("messages", 20),
        ),
    ],
)
```
:::

:::js
```typescript
import { createAgent, summarizationMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [weatherTool, calculatorTool],
  middleware: [
    summarizationMiddleware({
      model: "gpt-5.4-mini",
      trigger: { tokens: 4000 },
      keep: { messages: 20 },
    }),
  ],
});
```
:::

:::python

<Tip>
    `trigger` 和 `keep` 里的 `fraction` 条件（如下所示）依赖 chat model 的 [profile data](/oss/langchain/models#model-profiles)，前提是使用 `langchain>=1.1`。如果没有这些数据，请使用其他条件或手动指定：

    ```python
    from langchain.chat_models import init_chat_model

    custom_profile = {
        "max_input_tokens": 100_000,
        # ...
    }
    model = init_chat_model("gpt-5.5", profile=custom_profile)
    ```
</Tip>

<ParamField body="model" type="string | BaseChatModel" required>
    用于生成摘要的模型。可以是模型标识字符串（例如 `'openai:gpt-5.4-mini'`），也可以是 `BaseChatModel` 实例。更多信息请参见 @[`init_chat_model`][init_chat_model(model)]。
</ParamField>

<ParamField body="trigger" type="ContextSize | TriggerClause | list[ContextSize | TriggerClause] | None">
    触发摘要的条件。可以是：

    - 单个 @[`ContextSize`] tuple（达到该阈值即触发）
    - 单个 @[`TriggerClause`] dict（其中指定的所有阈值都必须满足，AND 逻辑）
    - 混合两种形式的列表（任意一项满足即可，OR 逻辑）

    支持的阈值有：

    - `fraction`（float）：模型上下文大小的比例（0-1）
    - `tokens`（int）：绝对 token 数
    - `messages`（int）：消息数量

    @[`ContextSize`] tuple 只表达一个阈值。@[`TriggerClause`] dict 可以包含一个或多个阈值，例如 `{"tokens": 4000, "messages": 10}`，并且 dict 中所有阈值都必须满足（AND）。

    每个 @[`TriggerClause`] dict 至少要指定一个阈值。如果不提供 `trigger`，则不会自动触发摘要。

    关于 @[`ContextSize`] 和 @[`TriggerClause`] 的更多信息，请参见 API reference。
</ParamField>

<ParamField body="keep" type="ContextSize" default="('messages', 20)">
    摘要后要保留多少上下文。只需指定以下之一：

    - `fraction`（float）：保留的模型上下文比例（0-1）
    - `tokens`（int）：保留的绝对 token 数
    - `messages`（int）：保留的最近消息数量

    关于 @[`ContextSize`] 的更多信息，请参见 API reference。
</ParamField>

<ParamField body="token_counter" type="function">
    自定义 token 计数函数。默认使用基于字符的计数。
</ParamField>

<ParamField body="summary_prompt" type="string">
    用于摘要的自定义 prompt 模板。如果未指定，则使用内置模板。模板应包含 `{messages}` 占位符，供插入对话历史。
</ParamField>

<ParamField body="trim_tokens_to_summarize" type="number" default="4000">
    生成摘要时可包含的最大 token 数。会先裁剪消息，使其符合该限制。
</ParamField>

<ParamField body="summary_prefix" type="string" deprecated>
    **已弃用：** 请改用 `summary_prompt` 提供完整 prompt。
</ParamField>

<ParamField body="max_tokens_before_summary" type="number" deprecated>
    **已弃用：** 请改用 `trigger: ("tokens", value)`。
</ParamField>

<ParamField body="messages_to_keep" type="number" deprecated>
    **已弃用：** 请改用 `keep: ("messages", value)`。
</ParamField>
:::

</ParamField>

</ParamField>

    - `tokens`（number）：保留的绝对 token 数
    - `messages`（number）：保留的最近消息数量
</ParamField>

<Accordion title="Full example">

summarization middleware 会监控消息 token 数量，并在达到阈值时自动总结较早的消息。

**Trigger conditions** 控制何时运行摘要：
- 单个阈值会在满足该阈值时触发
- 包含多个阈值的 trigger clause 只有在所有阈值都满足时才会触发（AND 逻辑）
- trigger 条件列表只要命中其中一项就会触发（OR 逻辑）
- 每个阈值可以使用 `fraction`（模型上下文大小的比例）、`tokens`（绝对数）或 `messages`（消息数量）

**Keep condition** 控制要保留多少上下文（只需指定一个）：
- `fraction` - 保留的模型上下文比例
- `tokens` - 保留的绝对 token 数
- `messages` - 保留的最近消息数量

:::python
```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware


# Single condition: trigger if tokens >= 4000
agent = create_agent(
    model="gpt-5.5",
    tools=[your_weather_tool, your_calculator_tool],
    middleware=[
        SummarizationMiddleware(
            model="gpt-5.4-mini",
            trigger=("tokens", 4000),
            keep=("messages", 20),
        ),
    ],
)

# Multiple conditions: trigger if number of tokens >= 3000 OR messages >= 6
agent2 = create_agent(
    model="gpt-5.5",
    tools=[your_weather_tool, your_calculator_tool],
    middleware=[
        SummarizationMiddleware(
            model="gpt-5.4-mini",
            trigger=[
                ("tokens", 3000),
                ("messages", 6),
            ],
            keep=("messages", 20),
        ),
    ],
)

# AND logic: trigger only when tokens >= 4000 AND messages >= 10
agent3 = create_agent(
    model="gpt-5.5",
    tools=[your_weather_tool, your_calculator_tool],
    middleware=[
        SummarizationMiddleware(
            model="gpt-5.4-mini",
            trigger={"tokens": 4000, "messages": 10},
            keep=("messages", 20),
        ),
    ],
)

# Combine AND and OR: trigger if (tokens >= 5000 AND messages >= 3)
# OR (tokens >= 3000 AND messages >= 6)
agent4 = create_agent(
    model="gpt-5.5",
    tools=[your_weather_tool, your_calculator_tool],
    middleware=[
        SummarizationMiddleware(
            model="gpt-5.4-mini",
            trigger=[
                {"tokens": 5000, "messages": 3},
                {"tokens": 3000, "messages": 6},
            ],
            keep=("messages", 20),
        ),
    ],
)

# Using fractional limits
agent5 = create_agent(
    model="gpt-5.5",
    tools=[your_weather_tool, your_calculator_tool],
    middleware=[
        SummarizationMiddleware(
            model="gpt-5.4-mini",
            trigger=("fraction", 0.8),
            keep=("fraction", 0.3),
        ),
    ],
)
```
:::

:::js
```typescript

    }),
  ],
});
```

### Human-in-the-loop

在工具执行前暂停 agent，让人工审批、编辑或拒绝 tool call。[Human-in-the-loop](/oss/langchain/human-in-the-loop) 适用于以下情况：

- 需要人工批准的高风险操作，例如数据库写入或金融交易。
- 需要人工监督的合规工作流。
- 人工反馈会指导 agent 的长对话场景。

:::python
**API reference:** @[`HumanInTheLoopMiddleware`]
:::

<Warning>
    Human-in-the-loop middleware 需要一个 [checkpointer](/oss/langgraph/checkpointers#checkpoints)，以便在中断之间保留 state。
</Warning>

:::python
```python
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver


def your_read_email_tool(email_id: str) -> str:
    """Mock function to read an email by its ID."""
    return f"Email content for ID: {email_id}"

def your_send_email_tool(recipient: str, subject: str, body: str) -> str:
    """Mock function to send an email."""
    return f"Email sent to {recipient} with subject '{subject}'"

agent = create_agent(
    model="gpt-5.5",
    tools=[your_read_email_tool, your_send_email_tool],
    checkpointer=InMemorySaver(),
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "your_send_email_tool": {
                    "allowed_decisions": ["approve", "edit", "reject"],
                },
                "your_read_email_tool": False,
            }
        ),
    ],
)
```
:::

:::js
```typescript
import { createAgent, humanInTheLoopMiddleware } from "langchain";

function readEmailTool(emailId: string): string {
  /** Mock function to read an email by its ID. */

}

function sendEmailTool(recipient: string, subject: string, body: string): string {
  /** Mock function to send an email. */
  return `Email sent to ${recipient} with subject '${subject}'`;
}

const agent = createAgent({
  model: "gpt-5.5",
  tools: [readEmailTool, sendEmailTool],
  middleware: [
    humanInTheLoopMiddleware({
      interruptOn: {
        sendEmailTool: {
          allowedDecisions: ["approve", "edit", "reject"],
        },
        readEmailTool: false,
      }
    })
  ]
});
```

### Model call limit

限制模型调用次数，防止无限循环或成本过高。Model call limit 适用于以下情况：

- 防止 runaway agent 进行过多 API 调用。
- 在生产环境中控制成本。
- 在特定调用预算内测试 agent 行为。

:::python
**API reference:** @[`ModelCallLimitMiddleware`]

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ModelCallLimitMiddleware
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(
    model="gpt-5.5",
    checkpointer=InMemorySaver(),  # Required for thread limiting
    tools=[],
    middleware=[
        ModelCallLimitMiddleware(
            thread_limit=10,
            run_limit=5,
            exit_behavior="end",
        ),
    ],
)
```
:::

:::js
```typescript
import { createAgent, modelCallLimitMiddleware } from "langchain";
import { MemorySaver } from "@langchain/langgraph";

const agent = createAgent({
  model: "gpt-5.5",
  checkpointer: new MemorySaver(), // Required for thread limiting
  tools: [],
  middleware: [
    modelCallLimitMiddleware({
      threadLimit: 10,
      runLimit: 5,
      exitBehavior: "end",
    }),
  ],
});
```

### Tool call limit

通过限制 tool call 的数量来控制 agent 执行，可以是全局限制，也可以是针对特定工具的限制。Tool call limits 适用于以下情况：

- 防止对昂贵的外部 API 进行过多调用。
- 限制 web search 或数据库查询。
- 对特定 tool 的使用施加速率限制。
- 防止 agent runaway loop。

:::python
**API reference:** @[`ToolCallLimitMiddleware`]

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ToolCallLimitMiddleware

agent = create_agent(
    model="gpt-5.5",
    tools=[search_tool, database_tool],
    middleware=[
        # Global limit
        ToolCallLimitMiddleware(thread_limit=20, run_limit=10),
        # Tool-specific limit
        ToolCallLimitMiddleware(
            tool_name="search",
            thread_limit=5,
            run_limit=3,
        ),
    ],
)
```
:::

:::js
```typescript
import { createAgent, toolCallLimitMiddleware } from "langchain";

const agent = createAgent({
  model: "gpt-5.5",
  tools: [searchTool, databaseTool],
  middleware: [
    toolCallLimitMiddleware({ threadLimit: 20, runLimit: 10 }),
    toolCallLimitMiddleware({
      toolName: "search",
      threadLimit: 5,
```

#### Custom PII types

你可以通过 `detector` 参数创建自定义 PII 类型，这样就能检测超出内置类型范围的模式。

**创建自定义 detector 的三种方式：**

1. **Regex pattern string** - 简单的模式匹配
2. **RegExp object** - 需要 regex flags 时更灵活
3. **Custom function** - 带验证逻辑的复杂检测

:::python
```python
from langchain.agents import create_agent
from langchain.agents.middleware import PIIMiddleware
import re


# Method 1: Regex pattern string
agent1 = create_agent(
    model="gpt-5.5",
    tools=[],
    middleware=[
        PIIMiddleware(
            "api_key",
            detector=r"sk-[a-zA-Z0-9]{32}",
            strategy="block",
        ),
    ],
)

# Method 2: Compiled regex pattern
agent2 = create_agent(
    model="gpt-5.5",
    tools=[],
    middleware=[
        PIIMiddleware(
            "phone_number",
            detector=re.compile(r"\+?\d{1,3}[\s.-]?\d{3,4}[\s.-]?\d{4}"),
            strategy="mask",
        ),
    ],
)

# Method 3: Custom detector function
def detect_ssn(content: str) -> list[dict[str, str | int]]:
    """Detect SSN with validation.

    Returns a list of dictionaries with 'text', 'start', and 'end' keys.
    """
    import re
    matches = []
    pattern = r"\d{3}-\d{2}-\d{4}"
    for match in re.finditer(pattern, content):
        ssn = match.group(0)
        # Validate: first 3 digits shouldn't be 000, 666, or 900-999
        first_three = int(ssn[:3])
        if first_three not in [0, 666] and not (900 <= first_three <= 999):
            matches.append({
                "text": ssn,
                "start": match.start(),
                "end": match.end(),
            })
    return matches

agent3 = create_agent(
    model="gpt-5.5",
    tools=[],
    middleware=[
        PIIMiddleware(
            "ssn",
            detector=detect_ssn,
            strategy="hash",
        ),
    ],
)
```
:::

```typescript
// Method 3: Custom detector function
function detectSSN(content: string): PIIMatch[] {
  const matches: PIIMatch[] = [];
  const pattern = /\d{3}-\d{2}-\d{4}/g;
  let match: RegExpExecArray | null;

  while ((match = pattern.exec(content)) !== null) {
    const ssn = match[0];
    // Validate: first 3 digits shouldn't be 000, 666, or 900-999
    const firstThree = parseInt(ssn.substring(0, 3), 10);
    if (firstThree !== 0 && firstThree !== 666 && !(firstThree >= 900 && firstThree <= 999)) {
      matches.push({
        text: ssn,
        start: match.index ?? 0,
        end: (match.index ?? 0) + ssn.length,
      });
    }
  }
  return matches;
}

const agent3 = createAgent({
  model: "gpt-5.5",
  tools: [],
  middleware: [

      detector: detectSSN,
      strategy: "hash",
    }),
  ],
});
```

### Tool error

:::python

捕获工具执行期间抛出的异常，并将其转换为模型能看到并从中恢复的错误 `ToolMessage`，而不是让 agent 运行中止。Tool error 适用于以下情况：

- 让模型用修正后的参数重试失败的 tool call。
- 输出受控、已净化的错误消息，而不是原始的异常详情。
- 防止意外的工具异常导致 agent 崩溃。

<Note>
Tool error middleware 不会自动重试失败的调用。如需重试，请与 [Tool retry](#tool-retry) middleware 组合使用，将后者放在*更内层*（在 `middleware` 列表中更靠前），并配置 `on_failure="error"`，以便异常能到达 tool error middleware。参见下方的[完整示例](#tool-error-full-example)。
</Note>

**API reference:** @[`ToolErrorMiddleware`]

<Note>
`ToolErrorMiddleware` 需要 `langchain>=1.3.14`。
</Note>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ToolErrorMiddleware


def on_error(exc: Exception, request: ToolCallRequest) -> str | None:
    if isinstance(exc, ValueError):
        return f"`{request.tool_call['name']}` failed with {type(exc).__name__}."
    # propagate everything else


agent = create_agent(
    model="gpt-5.5",
    tools=[your_tools],
    middleware=[ToolErrorMiddleware(on_error)],
)
```

<Accordion title="Configuration options">

<ParamField body="on_error" type="Callable[[Exception, ToolCallRequest], str | list[ContentBlock] | None]">
    同步处理函数，针对工具执行期间抛出的每个异常调用。返回内容（一个 `str` 或内容块列表）可将该异常转换为 `ToolMessage(status="error")`。返回 `None` 或省略 return 语句则让异常继续传播。用于同步路径，并且除非给出了 `aon_error`，也用于异步路径。
</ParamField>

<ParamField body="aon_error" type="Callable[[Exception, ToolCallRequest], Awaitable[str | list[ContentBlock] | None]]">
    可选的异步处理函数，用于异步执行路径。未提供时回退到 `on_error`。
</ParamField>

<ParamField body="tools" type="list[BaseTool | str]">
    可选：要应用错误处理的工具或工具名列表。如果为 `None`，则应用于所有工具。
</ParamField>

<Accordion title="Tool error full example">

`on_error` 处理函数接收异常和 `ToolCallRequest`（其中包含带 name、args 和 call ID 的 tool call 字典）。对于不想处理的异常，返回 `None`，它们会正常传播。

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ToolErrorMiddleware, ToolRetryMiddleware


def on_error(exc: Exception, request: ToolCallRequest) -> str | None:
    # Surface ValueError to the model so it can correct the input
    if isinstance(exc, ValueError):
        return f"`{request.tool_call['name']}` failed: {type(exc).__name__}. Fix the input and retry."
    # Let all other exceptions propagate (halts the run)
    return None


# Async-only usage
async def aon_error(exc: Exception, request: ToolCallRequest) -> str | None:
    if isinstance(exc, ConnectionError):
        return f"Tool `{request.tool_call['name']}` encountered a connection error."
    return None


agent = create_agent(
    model="gpt-5.5",
    tools=[search_tool, database_tool],
    middleware=[
        # Place retry inner so exceptions reach ToolErrorMiddleware after retries are exhausted
        ToolRetryMiddleware(max_retries=3, on_failure="error"),
        ToolErrorMiddleware(on_error=on_error, tools=["search_tool"]),
    ],
)

# Async-only: pass aon_error alone (do not pass on_error)
async_agent = create_agent(
    model="gpt-5.5",
    tools=[api_tool],
    middleware=[ToolErrorMiddleware(aon_error=aon_error)],
)
```

<Note>
优先返回指明异常类型的内容，而不是原始的异常消息，后者可能携带敏感或内部细节。`on_error` 处理函数控制对外披露：除非你主动包含，否则原始异常消息永远不会被发送给模型。
</Note>

### Context editing

管理 conversation context，在达到 token 上限时清理较早的 tool call 输出，同时保留最近的结果。这有助于在包含大量 tool call 的长对话中维持可控的上下文窗口。Context editing 适用于以下情况：

- tool call 很多、容易超过 token 上限的长对话。
- 通过移除不再相关的旧 tool output 来降低 token 成本。
- 只保留最近 N 个 tool result 在上下文中。

:::python
**API reference:** @[`ContextEditingMiddleware`], @[`ClearToolUsesEdit`]

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ContextEditingMiddleware, ClearToolUsesEdit

agent = create_agent(
    model="gpt-5.5",
    tools=[],
    middleware=[
        ContextEditingMiddleware(
            edits=[
                ClearToolUsesEdit(
                    trigger=100000,
                    keep=3,
                ),
            ],
        ),
    ],
)
```
:::

### Provider tool search

把选定工具延后到模型 provider 的 server-side tool search，让模型按需发现这些工具，而不是一开始就收到所有 tool schema。Provider tool search 适用于以下情况：

- 在使用很多工具时减少 context 膨胀。
- 通过只展示相关工具来提高工具选择准确性。

<Note>
    需要支持 server-side tool search 的模型：Anthropic（Claude Sonnet 4+/Opus 4+/Haiku 4.5+）或 OpenAI（gpt-5.5+）。其他 provider 会抛出 `ValueError`。
</Note>

**API reference:** @[`ProviderToolSearchMiddleware`]

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ProviderToolSearchMiddleware

agent = create_agent(
    model="anthropic:claude-opus-4-8",
    tools=[get_weather, lookup_order],
    middleware=[
        ProviderToolSearchMiddleware(searchable_tools=["lookup_order"]),
    ],
)
```

<Accordion title="Configuration options">

<ParamField body="searchable_tools" type="list[str | BaseTool]">
    要通过 provider tool search 延后的工具，可以按名称或实例指定。被延后的工具会在搜索结果显现前对模型隐藏。构造时设置 `extras={"defer_loading": True}` 的工具无论如何都会被延后；如果省略 `searchable_tools`，则只延后这些预标记工具。
</ParamField>

</Accordion>

<Accordion title="Full example">

这个 middleware 会把 `searchable_tools` 中的工具都加入延后与搜索流程。工具也可以在构造时通过 `extras={"defer_loading": True}` 自己进入延后模式。

```python
    tools=[send_email],
```

### Shell tool

为 agent 暴露一个持久 shell session，用于执行命令。Shell tool middleware 适用于以下情况：

- 需要执行系统命令的 agent。
- 开发和部署自动化任务。
- 测试和验证工作流。
- 文件系统操作和脚本执行。

<Warning>
    **Security consideration**: 使用合适的 execution policy（`HostExecutionPolicy`、`DockerExecutionPolicy` 或 `CodexSandboxExecutionPolicy`），以符合你的部署安全要求。
</Warning>

<Note>
    **Limitation**: 持久 shell session 目前不支持 interrupts（human-in-the-loop）。未来预计会支持。
</Note>

**API reference:** @[`ShellToolMiddleware`]

```python
from langchain.agents import create_agent
from langchain.agents.middleware import (
    ShellToolMiddleware,
    HostExecutionPolicy,
)

agent = create_agent(
    model="gpt-5.5",
    tools=[search_tool],
    middleware=[
        ShellToolMiddleware(
            workspace_root="/workspace",
            execution_policy=HostExecutionPolicy(),
        ),
    ],
)
```

<Accordion title="Configuration options">

<ParamField body="workspace_root" type="str | Path | None">
    shell session 的基础目录。如果省略，agent 启动时会创建一个临时目录，并在结束时删除。
</ParamField>

<ParamField body="startup_commands" type="tuple[str, ...] | list[str] | str | None">
    session 启动后按顺序执行的可选命令
</ParamField>

<ParamField body="shutdown_commands" type="tuple[str, ...] | list[str] | str | None">
    session 关闭前执行的可选命令
</ParamField>

<ParamField body="execution_policy" type="BaseExecutionPolicy | None">
    控制超时、输出限制和资源配置的执行策略。可选：

    - `HostExecutionPolicy` - 完整主机访问（默认）
    - `DockerExecutionPolicy` - 为每次 agent 运行启动独立 Docker 容器
    - `CodexSandboxExecutionPolicy` - 复用 Codex CLI sandbox 进行额外的 syscall/filesystem 限制
</ParamField>

<ParamField body="redaction_rules" type="tuple[RedactionRule, ...] | list[RedactionRule] | None">
    用于在返回给模型前清理 command output 的可选规则。
    <Warning>
    Redaction rules 在执行后应用，使用 `HostExecutionPolicy` 时并不能阻止 secrets 或敏感数据泄漏。
    </Warning>
</ParamField>

<ParamField body="tool_description" type="str | None">
    注册的 shell tool description 的可选覆盖
</ParamField>

<ParamField body="shell_command" type="Sequence[str] | str | None">
    用于启动持久 session 的 shell 可执行文件（字符串）或参数序列。默认是 `/bin/bash`。
</ParamField>

<ParamField body="env" type="Mapping[str, Any] | None">
    要提供给 shell session 的可选环境变量。值在执行前会被强制转换成字符串。
</ParamField>

</Accordion>

<Accordion title="Full example">

这个 middleware 提供一个持久 shell session，agent 可以顺序执行命令。

**Execution policies:**
- `HostExecutionPolicy`（默认）- 原生执行，完全访问主机
- `DockerExecutionPolicy` - 隔离的 Docker 容器执行
- `CodexSandboxExecutionPolicy` - 通过 Codex CLI 进行 sandbox 执行

```python

)

# Docker isolation with startup commands
agent_docker = create_agent(
    model="gpt-5.5",
    tools=[],
    middleware=[
        ShellToolMiddleware(
            workspace_root="/workspace",

# With output redaction (applied post execution)
agent_redacted = create_agent(
```

### Filesystem middleware

Context engineering 是构建有效 agent 的核心挑战之一。使用返回可变长度结果的工具时尤其困难，例如 `web_search` 和 RAG，因为过长的 tool result 很快就会填满 context window。

来自 [Deep Agents](/oss/deepagents/overview) 的 `FilesystemMiddleware` 为 interacting with short-term and long-term memory 提供四个工具：

- `ls`：列出 filesystem 中的文件
- `read_file`：读取整个文件或文件的若干行
- `write_file`：向 filesystem 写入新文件
- `edit_file`：编辑 filesystem 中的已有文件

:::python
```python
from langchain.agents import create_agent
from deepagents.middleware.filesystem import FilesystemMiddleware

# FilesystemMiddleware is included by default in create_deep_agent
# You can customize it if building a custom agent
agent = create_agent(
    model="claude-sonnet-4-6",
    middleware=[
        FilesystemMiddleware(
            backend=None,  # Optional: custom backend (defaults to StateBackend)
            system_prompt="Write to the filesystem when...",  # Optional custom addition to the system prompt
            custom_tool_descriptions={
                "ls": "Use the ls tool when...",
                "read_file": "Use the read_file tool to..."
            }  # Optional: Custom descriptions for filesystem tools
        ),
    ],
)
```
:::

:::js

#### Short-term vs. long-term filesystem

默认情况下，这些工具会写入 graph state 里的本地“filesystem”。如果要在 thread 之间持久化存储，可以配置一个 `CompositeBackend`，把特定路径（如 `/memories/`）路由到 `StoreBackend`。

:::python
```python
from langchain.agents import create_agent
from deepagents.middleware import FilesystemMiddleware
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()

agent = create_agent(
    model="claude-sonnet-4-6",
    store=store,
    middleware=[
        FilesystemMiddleware(
            backend=CompositeBackend(
                default=StateBackend(),
                routes={"/memories/": StoreBackend()}
            ),
            custom_tool_descriptions={
                "ls": "Use the ls tool when...",
                "read_file": "Use the read_file tool to..."
            }  # Optional: Custom descriptions for filesystem tools
        ),
    ],
)
```
:::

:::js
```typescript
import { createAgent } from "langchain";
import { createFilesystemMiddleware, CompositeBackend, StateBackend, StoreBackend } from "deepagents";
import { InMemoryStore } from "@langchain/langgraph-checkpoint";

const store = new InMemoryStore();

const agent = createAgent({
  model: "claude-sonnet-4-6",
  store,
  middleware: [
    createFilesystemMiddleware({
      backend: new CompositeBackend(
        new StateBackend(),
        { "/memories/": new StoreBackend() }
      ),
      systemPrompt: "Write to the filesystem when...", // Optional custom system prompt override
      customToolDescriptions: {
        ls: "Use the ls tool when...",
        read_file: "Use the read_file tool to...",
      }, // Optional: Custom descriptions for filesystem tools
    }),
  ],
});
```

当你为 `/memories/` 配置了 `StoreBackend` 的 `CompositeBackend` 时，任何以 **/memories/** 为前缀的文件都会保存到持久化存储中，并跨不同 thread 保留。没有这个前缀的文件仍然保存在 ephemeral state storage 中。

### Subagent

把任务交给 subagent 可以隔离 context，让主（supervisor）agent 的 context window 保持干净，同时仍能深入处理任务。

```python
from langchain.tools import tool
from langchain.agents import create_agent
from deepagents.middleware.subagents import SubAgentMiddleware


@tool

    """Get the weather in a city."""
    return f"The weather in {city} is sunny."

agent = create_agent(
    model="claude-sonnet-4-6",
    middleware=[
        SubAgentMiddleware(
            default_model="claude-sonnet-4-6",
            default_tools=[],
            subagents=[
                {
                    "name": "weather",
                    "description": "This subagent can get weather in cities.",
                    "system_prompt": "Use the get_weather tool to get the weather in a city.",
                    "tools": [get_weather],
                    "model": "gpt-5.5",
                    "middleware": [],
                }
            ],
        )
    ],
)
```
:::

```typescript
  model: "claude-sonnet-4-6",
  middleware: [
    createSubAgentMiddleware({
      defaultModel: "claude-sonnet-4-6",
      defaultTools: [],
      subagents: [
        {
          name: "weather",
          description: "This subagent can get weather in cities.",
          systemPrompt: "Use the get_weather tool to get the weather in a city.",
          tools: [getWeather],
          model: "gpt-5.5",
          middleware: [],
        },
      ],
    }),
  ],
});
```
:::

一个 subagent 由 **name**、**description**、**system prompt** 和 **tools** 定义。你也可以为 subagent 提供自定义 **model**，或者提供额外的 **middleware**。当你想让 subagent 额外共享一个 state key 时，这会特别有用。

对于更复杂的场景，你还可以把自己预构建的 LangGraph graph 作为 subagent。

:::python
```python
from langchain.agents import create_agent
from deepagents.middleware.subagents import SubAgentMiddleware
from deepagents import CompiledSubAgent
from langgraph.graph import StateGraph

# Create a custom LangGraph graph
def create_weather_graph():
    workflow = StateGraph(...)
    # Build your custom graph
    return workflow.compile()

weather_graph = create_weather_graph()

# Wrap it in a CompiledSubAgent
weather_subagent = CompiledSubAgent(
    name="weather",
    description="This subagent can get weather in cities.",
    runnable=weather_graph
)

agent = create_agent(
    model="claude-sonnet-4-6",
    middleware=[
        SubAgentMiddleware(
            default_model="claude-sonnet-4-6",
            default_tools=[],
            subagents=[weather_subagent],
        )
    ],
)
```
:::

:::js
```typescript
import { tool, createAgent } from "langchain";
import { createSubAgentMiddleware, type SubAgent } from "deepagents";
import { z } from "zod";

const getWeather = tool(
  async ({ city }: { city: string }) => {
    return `The weather in ${city} is sunny.`;
  },
  {
    name: "get_weather",
    description: "Get the weather in a city.",
    schema: z.object({
      city: z.string(),
    }),
  },
);

const weatherSubagent: SubAgent = {
  name: "weather",
  description: "This subagent can get weather in cities.",
  systemPrompt: "Use the get_weather tool to get the weather in a city.",
  tools: [getWeather],
  model: "gpt-5.5",
  middleware: [],
};

const agent = createAgent({
  model: "claude-sonnet-4-6",
  middleware: [
    createSubAgentMiddleware({
      defaultModel: "claude-sonnet-4-6",
      defaultTools: [],
      subagents: [weatherSubagent],
    }),
  ],
});
```
:::

除了用户定义的 subagent 之外，主 agent 会一直拥有一个 `general-purpose` subagent。这个 subagent 使用和主 agent 相同的指令，以及它可以访问的所有工具。`general-purpose` subagent 的主要作用是 context isolation：主 agent 可以把复杂任务交给它，从而在不被中间 tool call 细节膨胀的情况下获得一个简洁答案。
