---
title: 概览
description: 将 useStream 连接到任意 React UI 组件库或生成式 UI 框架
---

@[`useStream`] 是 UI 无关的。它返回普通的响应式状态，包括消息、工具调用、加载标志、值和线程元数据，你可以把这些状态接到任何你选择的视觉层上。这些页面展示了不同库如何与 LangChain 前端集成，以及它们在构建 AI 聊天和生成式 UI 时各自的理念差异。

## 集成

<CardGroup cols={2}>
  <Card title="CopilotKit" icon="package" href="/oss/langchain/frontend/integrations/copilotkit">
    完整的 AI 聊天运行时，支持结构化生成式 UI。为你的 LangGraph 部署添加自定义 CopilotKit endpoint，然后在 React 中渲染动态组件树。
  </Card>
  <Card title="AI Elements" icon="package" href="/oss/langchain/frontend/integrations/ai-elements">
    基于 shadcn/ui 的可组合 AI 聊天组件。直接放入 `Conversation`、`Message`、`Tool` 和 `Reasoning`，并把它们连接到 `stream.messages`。
  </Card>
  <Card title="assistant-ui" icon="package" href="/oss/langchain/frontend/integrations/assistant-ui">
    具有完整运行时层的 headless React 框架。通过 `useExternalStoreRuntime` 适配器，把 `useStream` 桥接到 `AssistantRuntimeProvider`。
  </Card>
  <Card title="OpenUI" icon="package" href="/oss/langchain/frontend/integrations/openui">
    生成式 UI 库，允许智能体通过声明式组件 DSL 产出完整、交互式仪表盘。特别适合数据密集、报表风格的 UI。
  </Card>
</CardGroup>

## 如何选择库

每个库都适合略有不同的集成方式。选择取决于你正在构建的 UI 类型：

| | CopilotKit | AI Elements | assistant-ui | OpenUI |
| --- | --- | --- | --- | --- |
| **最适合** | 完整聊天运行时 + 结构化生成式 UI | 带丰富消息类型的聊天 | 功能完整且接入成本低的聊天 | 生成式仪表盘和报表 |
| **UI 风格** | CopilotKit 聊天壳 + 自定义消息渲染器 | 可组合的 shadcn/ui 组件 | 无头插槽 + 默认主题 | 预构建组件库 + 声明式 DSL |
| **可定制性** | 自定义后端 endpoint、智能体上下文和渲染器 | 直接编辑源文件 | 覆盖组件插槽 | 通过 CSS custom properties 调整主题 |
| **流式体验** | 运行时管理的聊天流 + 结构化 assistant payload | 组件级渐进式渲染 | 内置线程管理 | Hoisting - 壳先出现，数据随后填充 |
| **工具调用** | 通过 CopilotKit runtime 和自定义渲染器 | `Tool` / `ToolHeader` / `ToolOutput` | 通过消息插槽自定义 | 直接内嵌在生成的 UI 中 |
| **智能体格式** | 结构化 assistant 响应 + 可选 Markdown | 任意 `stream.messages` | 任意 `stream.messages` | agent outputs openui-lang text |

这四种方案都能很好地与 LangChain 智能体协作，后面三种还能直接连接到 @[`useStream`]。当你想要更丰富的运行时层，以及一个可与 [LangGraph](/oss/langgraph/overview) 部署并行存在的专用 endpoint 时，CopilotKit 尤其有用。
