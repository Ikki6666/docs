本指南会使用 `create_agent` 和 Deep Agents middleware，从最基础的组件开始搭建一个数据分析智能体。

`create_agent` 和 `create_deep_agent` 都能让你精细控制工具、记忆等能力。两者最大的区别在于，Deep Agents 自带一组常用能力，比如规划、文件系统工具和子智能体。如果 Deep Agents 的默认 harness 不符合你的需求，本指南会展示如何从 `create_agent` 出发，一块一块搭起完整 harness，这样你就能清楚看见每个组件加了什么，也能只保留你需要的部分。

按照本指南，你会构建一个能够：

1. 接收 CSV 文件进行分析
2. 在隔离沙箱中编写并执行 Python 代码
3. 把可视化工作委派给专门的子智能体
4. 从技能文件中加载数据分析模式

最终得到的技术栈与 `create_deep_agent` 默认组装的内容一致。

## 你将学到什么

每一步都会给同一个数据分析智能体增加一种能力：

| 步骤 | 没有它会有什么问题 | 你新增什么 |
|------|-------------------|-----------|
| 最小智能体 | 无 | 基线循环：模型 + 工具，没有 harness |
| 沙箱 + 文件系统 | 智能体无法读取 CSV 或运行 Python | 隔离 [后端](/oss/deepagents/backends) + 文件与执行工具 |
| 摘要 | 长会话会碰到上下文限制 | 自动压缩历史 |
| 技能 | 领域规则会把系统提示词撑大 | 通过 [渐进式披露](/oss/langchain/multi-agent/skills-sql-assistant) 按需加载专业知识 |
| 子智能体 | 图表迭代会挤占主线程上下文 | 隔离工作器 + 并行委派 |

## 添加沙箱后端

要高效分析数据，智能体需要在文件上运行代码。这需要两样东西：

- 一个隔离的 [沙箱](/oss/deepagents/sandboxes)，让智能体可以放入文件并在这些文件上运行代码，而不会接触宿主机。
- 一个 [后端](/oss/deepagents/backends)，通过 @[`FilesystemMiddleware`] 提供文件系统工具，用于处理沙箱中的 `read_file`、`write_file`、`edit_file`、`glob` 和 `grep`。因为 `LangSmithSandbox` 后端实现了沙箱协议，所以 @[`FilesystemMiddleware`] 还会额外提供 `execute` 工具，允许智能体运行 shell 命令。

@[`LangSmithSandbox`] 是文件存放和命令运行的位置。@[`FilesystemMiddleware`] 则负责把这个环境作为工具暴露给模型。同一个 middleware 也能和其他后端一起工作，只要你之后切换后端即可。

## 添加上下文管理

## 添加技能

[技能](/oss/langchain/multi-agent/skills-sql-assistant) 提供了一种按需传递领域知识的方法，使用的是渐进式披露。技能可以包含多步工作流、规则和约定。把这些信息放进技能后，它们默认不会进入系统提示词，因此只有在任务真的需要时才会消耗这些 token。

智能体启动时，只会看到每个技能的轻量元数据。等任务需要某个技能时，智能体才会按需加载完整技能文件。

在 skills 目录中创建一个技能文件：

```
skills/
  pandas-patterns/
    SKILL.md
```

```markdown
---
name: pandas-patterns
description: Common pandas and matplotlib patterns for data analysis and visualization
---

## Data loading
Use `pd.read_csv()` for CSV files. Always check `df.info()` and `df.describe()` first.

## Visualization
Use `matplotlib` for bar charts, `seaborn` for statistical plots.
Save figures with `plt.savefig("output.png", dpi=150, bbox_inches="tight")`.

## Reporting
Write a markdown summary to `report.md` alongside any generated charts.
```

这个技能里包含了可视化应该如何完成的信息。

## 添加可视化子智能体

有些任务会产生大量中间输出，比如脚本草稿、失败运行结果和文件读取内容。如果都留在同一个线程里，会挤占主智能体的上下文。子智能体会在自己的上下文窗口中运行，因此主管智能体只会看到最终结果，而不会看到沿途每一步工具调用。这能让主分析更聚焦，也给后续追问留出空间。

一个适合使用子智能体的场景是图表生成。绘图通常意味着迭代 Python 脚本、安装包、阅读错误输出，直到图表准备好。下面这个 `visualizer` 子智能体可以在隔离环境里处理这些工作，而主智能体可以继续规划和分析。借助 @[`TodoListMiddleware`]，主智能体还可以并行委派图表工作，而不用在每张图上都阻塞等待。
