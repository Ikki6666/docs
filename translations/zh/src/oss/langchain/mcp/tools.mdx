## 工具元数据

:::python
每个适配后的工具都可以在 LangChain 工具的 metadata 上的 `mcp` 命名空间中携带其 MCP 来源信息：

```python
tool.metadata
# {
#     "mcp": {
#         "tool": {
#             "annotations": {
#                 "destructive_hint": True,
#                 "read_only_hint": False,
#             },
#             "_meta": {"origin": "crm"},
#         },
#         "server": {
#             "name": "crm",
#             "version": "2.1.0",
#         },
#     },
# }
```
:::

:::js
adapter 将 MCP 工具注解存储在 `tool.metadata.annotations` 中：

```typescript
tool.metadata;
// {
//   annotations: {
//     destructiveHint: true,
//     readOnlyHint: false,
//   },
// }
```
:::

:::python
每个嵌套字段都是可选的：服务器可能提供工具注解、`_meta`、服务器身份，或它们的任意组合，也可能都不提供。`annotations` 包含诸如 `read_only_hint` 和 `destructive_hint` 之类的 MCP 提示；`_meta` 是服务器提供的不透明元数据；`server` 标识宣告该工具的 MCP 实现。

:::js
`annotations` 保存服务器的 MCP 工具注解，例如 `readOnlyHint` 和 `destructiveHint`。服务器可能省略它们，因此该字段可能是 `undefined`。

)

## 工具执行期间的服务器请求

大多数工具在调用中途不需要向客户端请求任何东西就能完成。当服务器需要输入时，@[`MCPAdapter`] 将 [elicitation](https://modelcontextprotocol.io/specification/draft/client/elicitation) 呈现为 LangGraph @[`interrupt`]。

### Elicitation

[Elicitation](https://modelcontextprotocol.io/specification/draft/client/elicitation) 让 MCP 服务器在工具调用期间请求输入。adapter 使用 LangGraph interrupt 暂停运行。你的应用程序将请求呈现给用户，并用用户的答案恢复运行。

为智能体附加一个 [checkpointer](/oss/langchain/short-term-memory)，并在调用和恢复时使用相同的 `thread_id`。

此示例假设预订工具请求一个日期并暂停一次。将示例日期替换为用户的答案。

:::python
<McpElicitationPy />

Elicitation 默认开启。adapter 宣告该能力并驱动 interrupt 循环。已经带有自己的 elicitation 处理器的预构建客户端会被优先使用，而不是被覆盖。

用 `Command(resume={"responses": {key: answer}})` 恢复。interrupt payload 和答案类型位于 `langchain.mcp.elicitation`。
:::

:::js
基于 interrupt 的 elicitation 需要现代 MCP 服务器，并且默认开启。在服务器上设置 `elicitation: false` 以选择退出。对于旧式服务器，改为在 `mode: "legacy"` 下配置 `onElicitation` 处理器。没有 checkpointer 时，请求输入的工具会以错误 `ToolMessage` 失败，而不是暂停。

<McpElicitationJs />

`createMCPElicitationResume` 将答案寻址到请求它的 interrupt。响应使用服务器的请求键。请始终用 `createMCPElicitationResume` 构建每个 resume 值，而不要使用不带服务器信息的 `{ responses }` 对象，后者没有说明它回答的是哪个 interrupt。

每个 interrupt 的 `value` 是一个 `MCPElicitationInterrupt`：`type: "mcp_elicitation"`、`server`、`tool`（服务器自己的工具名称，不带前缀）、`arguments`（生效的工具参数）和 `requests`。当同一个智能体还可能引发 human-in-the-loop interrupt 时，请检查 `type`。

当多个调用同时暂停时，要回答每个 interrupt。将 `createMCPElicitationResume` 返回的对象合并为一个 `Command({ resume })`，例如 `Object.assign({}, ...paused.__interrupt__!.map((q) => createMCPElicitationResume(q, answers)))`，或者持续恢复直到 `__interrupt__` 为空。只回答第一个 interrupt 的 resume 会让其余的保持暂停。
:::

<Note>
恢复会从头重新运行工具。在服务器请求输入之前执行的任何工作都可能重复。请确保这些工作可以安全地重复，而不会产生重复的副作用。
</Note>

每个答案使用以下操作之一：

- **`accept`**：提供与请求 schema 匹配的表单 `content`，或者在不带 `content` 的情况下确认 URL 交互已完成。
- **`decline`**：拒绝提供所请求的信息。
- **`cancel`**：表示用户取消了该交互。

adapter 将答案转发给服务器，由服务器决定工具调用如何结束。

:::python
只有 elicitation 是通过这种方式回答的。如果服务器改为请求 [sampling](https://modelcontextprotocol.io/specification/2025-06-18/client/sampling) 或 [roots](https://modelcontextprotocol.io/specification/2025-06-18/client/roots)，则会引发错误，因为现代的无会话协议没有用于这些请求的实时回传通道。参见 [Sampling and roots](/oss/migrate/langchain-mcp-adapters#sampling-and-roots)。
:::

:::js
只有 elicitation 是通过这种方式回答的。adapter 在每次调用中只宣告 elicitation 能力，因此需要 [sampling](https://modelcontextprotocol.io/specification/2025-06-18/client/sampling) 或 [roots](https://modelcontextprotocol.io/specification/2025-06-18/client/roots) 的工具会以 `ToolException` 失败，`createAgent` 会将其作为错误 `ToolMessage` 返回给模型。参见 [Sampling and roots](/oss/migrate/langchain-mcp-adapters#sampling-and-roots)。
:::

<Note>
基于 interrupt 的 elicitation 回答的是将其请求作为 `InputRequiredResult` 返回的服务器。只在旧式握手会话上推送 elicitation 的服务器无法通过这种方式回答。
</Note>
