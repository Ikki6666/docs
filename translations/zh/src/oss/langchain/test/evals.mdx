评估（"evals"）通过检查智能体的执行轨迹来衡量它表现得有多好，也就是它产生的消息序列和工具调用序列。与验证基本正确性的 [integration tests](/oss/langchain/test/integration-testing) 不同，evals 会根据参考答案或评分标准给智能体行为打分，因此在你修改提示词、工具或模型时，它们很适合用来捕捉回归。

evaluator 是一个函数，接收智能体输出（以及可选的参考输出），然后返回一个分数：

:::python
```python
def evaluator(*, outputs: dict, reference_outputs: dict):
    output_messages = outputs["messages"]
    reference_messages = reference_outputs["messages"]
    score = compare_messages(output_messages, reference_messages)
    return {"key": "evaluator_score", "score": score}
```
:::

:::js
```typescript
function evaluator({ outputs, referenceOutputs }: {
  outputs: Record<string, any>;
  referenceOutputs: Record<string, any>;
}) {
  const outputMessages = outputs.messages;
  const referenceMessages = referenceOutputs.messages;
  const score = compareMessages(outputMessages, referenceMessages);
  return { key: "evaluator_score", score: score };
}
```
:::

[`agentevals`](https://github.com/langchain-ai/agentevals) 包提供了针对智能体轨迹的预构建 evaluator。你可以通过 **trajectory match**（确定性比较）或 **LLM judge**（定性评估）来做评估：

| 方法 | 适用场景 |
|----------|-------------|
| [Trajectory match](#trajectory-match-evaluator) | 你知道期望的工具调用，并且想要快速、确定性、零成本的检查 |
| [LLM-as-judge](#llm-as-judge-evaluator) | 你想在没有严格期望的情况下评估整体质量和推理过程 |

## Trajectory match evaluator

:::python
AgentEvals 提供了 `create_trajectory_match_evaluator` 函数，用来把智能体轨迹和参考轨迹进行匹配。有四种模式：
:::
:::js
AgentEvals 提供了 `createTrajectoryMatchEvaluator` 函数，用来把智能体轨迹和参考轨迹进行匹配。有四种模式：
:::

| 模式 | 说明 | 适用场景 |
|------|-------------|----------|
| `strict` | 消息结构和工具调用必须完全一致且顺序相同（消息内容可以不同） | 测试特定执行序列，例如先做策略查询再授权 |
| `unordered` | 消息结构和工具调用与参考一致，但工具调用顺序可以不同 | 验证检索信息时不关心顺序的情况 |
| `subset` | 智能体只能调用参考中的工具，不能有额外工具 | 确保智能体没有超出预期范围 |
| `superset` | 智能体至少调用了参考中的工具，可以有额外工具 | 验证是否完成了最低限度的必要动作 |

下面的示例共用一套基础设置，一个带 `get_weather` 工具的智能体：

:::python
```python
from langchain.agents import create_agent
from langchain.tools import tool
from langchain.messages import HumanMessage, AIMessage, ToolMessage
from agentevals.trajectory.match import create_trajectory_match_evaluator


@tool
def get_weather(city: str):
    """获取某个城市的天气信息。"""
    return f"It's 75 degrees and sunny in {city}."

agent = create_agent("claude-sonnet-4-6", tools=[get_weather])
```
:::

:::js
```ts
import { createAgent } from "langchain";
import { tool } from "@langchain/core/tools";
import { HumanMessage, AIMessage, ToolMessage } from "@langchain/core/messages";
import { createTrajectoryMatchEvaluator } from "agentevals";
import * as z from "zod";

const getWeather = tool(
  async ({ city }) => {
    return `It's 75 degrees and sunny in ${city}.`;
  },
  {
    name: "get_weather",
    description: "获取某个城市的天气信息。",
    schema: z.object({ city: z.string() }),
  }
);

const agent = createAgent({
  model: "claude-sonnet-4-6",
  tools: [getWeather],
});
```
:::

<Accordion title="严格匹配">

`strict` 模式会确保轨迹包含完全相同的消息，顺序相同，工具调用也相同，不过消息内容可以不同。当你需要强制某个固定操作顺序时，这很有用，比如要求在授权动作前先查策略。

:::python
```python
evaluator = create_trajectory_match_evaluator(  # [!code highlight]
    trajectory_match_mode="strict",  # [!code highlight]
)  # [!code highlight]

def test_weather_tool_called_strict():
    result = agent.invoke({
        "messages": [HumanMessage(content="What's the weather in San Francisco?")]
    })

    reference_trajectory = [
        HumanMessage(content="What's the weather in San Francisco?"),
        AIMessage(content="", tool_calls=[
            {"id": "call_1", "name": "get_weather", "args": {"city": "San Francisco"}}
        ]),
        ToolMessage(content="It's 75 degrees and sunny in San Francisco.", tool_call_id="call_1"),
        AIMessage(content="The weather in San Francisco is 75 degrees and sunny."),
    ]

    evaluation = evaluator(
        outputs=result["messages"],
        reference_outputs=reference_trajectory
    )
    # {
    #     'key': 'trajectory_strict_match',
    #     'score': True,
    #     'comment': None,
    # }
    assert evaluation["score"] is True
```
:::

:::js
```ts
const evaluator = createTrajectoryMatchEvaluator({  // [!code highlight]
  trajectoryMatchMode: "strict",  // [!code highlight]
});  // [!code highlight]

async function testWeatherToolCalledStrict() {
  const result = await agent.invoke({
    messages: [new HumanMessage("What's the weather in San Francisco?")]
  });

  const referenceTrajectory = [
    new HumanMessage("What's the weather in San Francisco?"),
    new AIMessage({
      content: "",
      tool_calls: [
        { id: "call_1", name: "get_weather", args: { city: "San Francisco" } }
      ]
    }),
    new ToolMessage({
      content: "It's 75 degrees and sunny in San Francisco.",
      tool_call_id: "call_1"
    }),
    new AIMessage("The weather in San Francisco is 75 degrees and sunny."),
  ];

  const evaluation = await evaluator({
    outputs: result.messages,
    referenceOutputs: referenceTrajectory
  });
  expect(evaluation.score).toBe(true);
}
```
:::

</Accordion>

<Accordion title="无序匹配">

`unordered` 模式允许相同的工具调用以任意顺序出现。当你只关心是否检索到了特定信息、但不关心顺序时，这很有用。例如，一个会通过不同工具调用同时检查某个城市天气和活动的智能体。

:::python
```python
@tool
def get_events(city: str):
    """获取某个城市正在发生的活动。"""
    return f"Concert at the park in {city} tonight."

agent = create_agent("claude-sonnet-4-6", tools=[get_weather, get_events])

evaluator = create_trajectory_match_evaluator(  # [!code highlight]
    trajectory_match_mode="unordered",  # [!code highlight]
)  # [!code highlight]

def test_multiple_tools_any_order():
    result = agent.invoke({
        "messages": [HumanMessage(content="What's happening in SF today?")]
    })

    reference_trajectory = [
        HumanMessage(content="What's happening in SF today?"),
        AIMessage(content="", tool_calls=[
            {"id": "call_1", "name": "get_events", "args": {"city": "SF"}},
            {"id": "call_2", "name": "get_weather", "args": {"city": "SF"}},
        ]),
        ToolMessage(content="Concert at the park in SF tonight.", tool_call_id="call_1"),
        ToolMessage(content="It's 75 degrees and sunny in SF.", tool_call_id="call_2"),
        AIMessage(content="Today in SF: 75 degrees and sunny with a concert at the park tonight."),
    ]

    evaluation = evaluator(
        outputs=result["messages"],
        reference_outputs=reference_trajectory,
    )
    assert evaluation["score"] is True
}
```
:::

:::js

<Accordion title="Subset 和 superset 匹配">

`superset` 和 `subset` 模式会匹配部分轨迹。`superset` 模式会验证智能体至少调用了参考轨迹中的工具，允许额外工具调用。`subset` 模式会确保智能体没有调用参考之外的任何工具。

:::python
```python
@tool
def get_detailed_forecast(city: str):
    """获取某个城市的详细天气预报。"""
    return f"Detailed forecast for {city}: sunny all week."

agent = create_agent("claude-sonnet-4-6", tools=[get_weather, get_detailed_forecast])

evaluator = create_trajectory_match_evaluator(  # [!code highlight]
    trajectory_match_mode="superset",  # [!code highlight]
)  # [!code highlight]

def test_agent_calls_required_tools_plus_extra():
    result = agent.invoke({
        "messages": [HumanMessage(content="What's the weather in Boston?")]
    })

    # 参考轨迹只要求 get_weather，但智能体可以调用额外工具
    reference_trajectory = [
        HumanMessage(content="What's the weather in Boston?"),
        AIMessage(content="", tool_calls=[
            {"id": "call_1", "name": "get_weather", "args": {"city": "Boston"}},
        ]),
        ToolMessage(content="It's 75 degrees and sunny in Boston.", tool_call_id="call_1"),
        AIMessage(content="The weather in Boston is 75 degrees and sunny."),
    ]

    evaluation = evaluator(
        outputs=result["messages"],
        reference_outputs=reference_trajectory,
    )
    assert evaluation["score"] is True
```
:::

## LLM-as-judge evaluator

:::python
你可以使用 LLM 通过 `create_trajectory_llm_as_judge` 函数来评估智能体的执行路径。与 trajectory match evaluator 不同，它不需要参考轨迹，但如果有的话也可以提供。
:::
:::js
你可以使用 LLM 通过 `createTrajectoryLLMAsJudge` 函数来评估智能体的执行路径。与 trajectory match evaluator 不同，它不需要参考轨迹，但如果有的话也可以提供。
:::

<Accordion title="没有参考轨迹">
:::python
```python
from agentevals.trajectory.llm import create_trajectory_llm_as_judge, TRAJECTORY_ACCURACY_PROMPT

evaluator = create_trajectory_llm_as_judge(  # [!code highlight]
    model="openai:o3-mini",  # [!code highlight]
    prompt=TRAJECTORY_ACCURACY_PROMPT,  # [!code highlight]
)  # [!code highlight]

def test_trajectory_quality():
    result = agent.invoke({
        "messages": [HumanMessage(content="What's the weather in Seattle?")]
    })

    evaluation = evaluator(
        outputs=result["messages"],
    )
    assert evaluation["score"] is True
```
:::
:::js
```ts
import { createTrajectoryLLMAsJudge, TRAJECTORY_ACCURACY_PROMPT } from "agentevals";

const evaluator = createTrajectoryLLMAsJudge({  // [!code highlight]
  model: "openai:o3-mini",  // [!code highlight]
```

### 异步支持

所有 `agentevals` evaluator 都支持 Python asyncio。只要在函数名里把 `create_` 后面加上 `async` 就能得到异步版本。

<Accordion title="异步 judge 和 evaluator 示例">

```python
from agentevals.trajectory.llm import create_async_trajectory_llm_as_judge, TRAJECTORY_ACCURACY_PROMPT
from agentevals.trajectory.match import create_async_trajectory_match_evaluator

async_judge = create_async_trajectory_llm_as_judge(
    model="openai:o3-mini",
    prompt=TRAJECTORY_ACCURACY_PROMPT,
)

async_evaluator = create_async_trajectory_match_evaluator(
    trajectory_match_mode="strict",
)

async def test_async_evaluation():
    result = await agent.ainvoke({
        "messages": [HumanMessage(content="What's the weather?")]
    })

    evaluation = await async_judge(outputs=result["messages"])
    assert evaluation["score"] is True
```

## 在 LangSmith 中运行 evals

### Use custom test matchers

`langchain` 提供了 [custom vitest matchers](https://vitest.dev/guide/extending-matchers.html)，让结构化断言更易读，并在失败时给出清晰的错误信息。只需要在一个 setup 文件里注册一次，它们就会在每次 `expect()` 调用中可用。

### 设置

添加一个 vitest setup 文件，用 LangChain matchers 扩展 `expect`：

```ts vitest.setup.ts
import { langchainMatchers } from "@langchain/core/testing";

expect.extend(langchainMatchers);
```

在 vitest 配置里引用它：

```ts vitest.config.ts
export default defineConfig({
  test: {
    setupFiles: ["vitest.setup.ts"],
  },
});
```

TypeScript 类型会自动包含，因此不需要额外配置自动补全。

### 检查消息类型

每个消息类都有对应的 matcher：`toBeHumanMessage()`、`toBeAIMessage()`、`toBeSystemMessage()` 和 `toBeToolMessage()`。不传参数时只检查类型；传入字符串时也可以匹配内容：

```ts
const response = await agent.invoke({
  messages: [new HumanMessage("What's the weather?")]
});
const lastMessage = response.messages.at(-1);

expect(lastMessage).toBeAIMessage();
expect(lastMessage).toBeAIMessage("It's 72°F and sunny.");
```

传入对象可以匹配特定字段：

```ts
expect(lastMessage).toBeAIMessage({ name: "weather-bot" });
expect(toolMsg).toBeToolMessage({ tool_call_id: "call_1" });
```

### 断言工具调用

三个 matcher 用于对 @[`AIMessage`] 的工具调用做断言：

```ts
const response = await agent.invoke({
  messages: [new HumanMessage("Weather in SF and NYC?")]
});
const aiMsg = response.messages.find(
  (m) => AIMessage.isInstance(m) && m.tool_calls?.length
);

// 检查是否包含特定工具调用（不考虑顺序）
expect(aiMsg).toHaveToolCalls([
  { name: "get_weather", args: { city: "San Francisco" } },
  { name: "get_weather", args: { city: "New York" } },
]);

// 只检查数量
expect(aiMsg).toHaveToolCallCount(2);

// 检查是否至少有一个工具调用匹配（支持 .not）
expect(aiMsg).toContainToolCall({ name: "get_weather" });
expect(aiMsg).not.toContainToolCall({ name: "send_email" });
```

### 断言工具消息

`toHaveToolMessages()` 接收完整的消息数组，并按顺序检查其中的 @[`ToolMessage`] 实例：

```ts
expect(response.messages).toHaveToolMessages([
  { content: "72°F and sunny in San Francisco" },
  { content: "68°F and cloudy in New York" },
]);
```

### 断言中断和结构化输出

`toHaveBeenInterrupted()` 会检查 [LangGraph interrupt](/oss/langchain/human-in-the-loop) 结果里是否存在 `__interrupt__` 字段。你可以传入一个值来匹配中断 payload：

```ts
const result = await graph.invoke(input);

expect(result).toHaveBeenInterrupted();
expect(result).toHaveBeenInterrupted("confirm_action");
```

`toHaveStructuredResponse()` 会检查结果里是否有 `structuredResponse` 字段。你可以传入一个对象来匹配特定字段：

```ts
expect(result).toHaveStructuredResponse();
expect(result).toHaveStructuredResponse({ name: "Alice", age: 30 });
```

### Matcher 参考

| Matcher | 说明 |
| --- | --- |
| `toBeHumanMessage(expected?)` | 检查值是否是 `HumanMessage`。可选地匹配内容（字符串）或字段（对象）。 |
| `toBeAIMessage(expected?)` | 检查值是否是 `AIMessage`。可选地匹配内容或字段。 |
| `toBeSystemMessage(expected?)` | 检查值是否是 `SystemMessage`。可选地匹配内容或字段。 |
| `toBeToolMessage(expected?)` | 检查值是否是 `ToolMessage`。可选地匹配内容或字段，例如 `tool_call_id`。 |
| `toHaveToolCalls(expected)` | 检查 `AIMessage` 是否恰好包含给定的工具调用（不考虑顺序）。 |
| `toHaveToolCallCount(n)` | 检查 `AIMessage` 是否恰好有 `n` 个工具调用。 |
| `toContainToolCall(expected)` | 检查 `AIMessage` 是否至少包含一个匹配的工具调用。支持 `.not`。 |
| `toHaveToolMessages(expected)` | 检查消息数组是否按顺序包含给定的 `ToolMessage` 实例。 |
| `toHaveBeenInterrupted(value?)` | 检查结果是否有 `__interrupt__`。可选地匹配中断值。 |
| `toHaveStructuredResponse(expected?)` | 检查结果是否有 `structuredResponse`。可选地匹配特定字段。 |

:::

## 降低成本和延迟

调用 LLM API 的集成测试会产生真实成本。下面这些做法可以帮助你把测试套件保持得更快、更省钱：

- **使用更小的模型**：例如 `gemini-3.1-flash-lite` 或类似模型，适用于只需验证工具调用和响应结构的测试。
- **设置 `maxTokens`**：限制响应长度，避免生成过长、成本高的 completions。
- **限制测试范围**：每个测试只验证一个行为。若单轮测试就够了，就不要写会串联很多 LLM 调用的端到端场景。
- **选择性运行**：使用上面的 [测试拆分](#separate-unit-and-integration-tests) 方法，只在 CI 或上线前运行集成测试，而不是每次保存文件都跑。

:::python
```python
agent = create_agent(
    "gemini-3.1-flash-lite",
    tools=[get_weather],
    model_kwargs={"max_tokens": 256},
)
```

## 记录和回放 HTTP 调用

对于在 CI 中频繁运行的测试，你可以在第一次运行时记录 HTTP 交互，之后的运行则回放这些交互，而无需真正发起 API 调用。这样在首次记录之后就能消除成本和延迟。

[`vcrpy`](https://pypi.org/project/vcrpy/1.5.2/) 会把 HTTP 请求/响应对记录到 YAML "cassette" 文件中。[`pytest-recording`](https://pypi.org/project/pytest-recording/) 插件可以把它和 pytest 集成起来。

在 `conftest.py` 里过滤 cassette 中的敏感信息：

```py conftest.py
import pytest

@pytest.fixture(scope="session")
def vcr_config():
    return {
        "filter_headers": [
            ("authorization", "XXXX"),
            ("x-api-key", "XXXX"),
        ],
        "filter_query_parameters": [
            ("api_key", "XXXX"),
            ("key", "XXXX"),
        ],
    }
```

在项目里配置一个 `vcr` marker：

<CodeGroup>
```ini pytest.ini
[pytest]
markers =
    vcr: record/replay HTTP via VCR
addopts = --record-mode=once
```
```toml pyproject.toml
[tool.pytest.ini_options]
markers = [
  "vcr: record/replay HTTP via VCR"
]
addopts = "--record-mode=once"
```
</CodeGroup>

<Info>
    `--record-mode=once` 选项会在首次运行时记录 HTTP 交互，之后的运行则回放这些交互。
</Info>

给测试加上 `vcr` marker：

```python
@pytest.mark.vcr()
def test_agent_trajectory():
    agent = create_agent("claude-sonnet-4-6", tools=[get_weather])
    result = agent.invoke({
        "messages": [HumanMessage(content="What's the weather in SF?")]
    })
    assert any(
        tc["name"] == "get_weather"
        for msg in result["messages"]
        if hasattr(msg, "tool_calls")
        for tc in (msg.tool_calls or [])
    )
```

第一次运行会发起真实网络调用，并在 `tests/cassettes/` 中生成 cassette 文件。后续运行会回放记录好的响应。

<Warning>
    当你修改提示词、添加新工具或改变预期轨迹时，已保存的 cassette 会过期，你现有的测试 **会失败**。请删除对应的 cassette 文件，然后重新运行测试来记录新的交互。
</Warning>
:::
