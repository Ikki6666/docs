## 概览

**supervisor pattern** 是一种 [multi-agent](/oss/langchain/multi-agent) 架构：由一个中心 supervisor agent 协调多个专门的 worker agent。它特别适合需要不同专业能力的任务。与其构建一个跨多个领域统一管理工具选择的 agent，不如把工作拆成聚焦的 specialist，再由理解整体流程的 supervisor 统一编排。

在本教程里，你会构建一个个人助理系统，用一个现实工作流来展示这种模式的优势。这个系统会协调两个职责截然不同的 specialist：

- 一个 **calendar agent**，负责排期、检查可用时间，以及管理事件。
- 一个 **email agent**，负责沟通、起草消息，以及发送通知。

我们还会加入 [human-in-the-loop review](/oss/langchain/human-in-the-loop)，让用户按需批准、编辑或拒绝操作，例如外发邮件。

### 为什么使用 supervisor？

Multi-agent 架构让你可以把 [tools](/oss/langchain/tools) 按 worker 划分，每个 worker 都有自己独立的 prompt 或指令。设想一个可以直接访问所有日历和邮件 API 的 agent：它必须从许多相似工具中做选择，理解每个 API 的精确格式，并同时处理多个领域。如果性能开始下降，把相关工具和相关 prompt 拆成逻辑分组，往往会更有帮助，尤其适合迭代优化。

## 1. 定义工具

先定义需要结构化输入的工具。在真实应用里，这些工具会调用实际 API，比如 Google Calendar、SendGrid 等。这个教程里我们使用 stub 来演示模式。

:::python
```python
from langchain.tools import tool

@tool
def create_calendar_event(
    title: str,
    start_time: str,       # ISO format: "2024-01-15T14:00:00"
    end_time: str,         # ISO format: "2024-01-15T15:00:00"
    attendees: list[str],  # email addresses
    location: str = ""
) -> str:
    """Create a calendar event. Requires exact ISO datetime format."""
    # Stub: In practice, this would call Google Calendar API, Outlook API, etc.
    return f"Event created: {title} from {start_time} to {end_time} with {len(attendees)} attendees"


@tool
def send_email(
    to: list[str],  # email addresses
    subject: str,
    body: str,
    cc: list[str] = []
) -> str:
    """Send an email via email API. Requires properly formatted addresses."""
    # Stub: In practice, this would call SendGrid, Gmail API, etc.
    return f"Email sent to {', '.join(to)} - Subject: {subject}"


@tool
def get_available_time_slots(
    attendees: list[str],
    date: str,  # ISO format: "2024-01-15"
    duration_minutes: int
) -> list[str]:
    """Check calendar availability for given attendees on a specific date."""
    # Stub: In practice, this would query calendar APIs
    return ["09:00", "14:00", "16:00"]
```
:::

:::js
```typescript
import { tool } from "langchain";
import { z } from "zod";

const createCalendarEvent = tool(
  async ({ title, startTime, endTime, attendees, location }) => {
    // Stub: In practice, this would call Google Calendar API, Outlook API, etc.
    return `Event created: ${title} from ${startTime} to ${endTime} with ${attendees.length} attendees`;
  },
  {
    name: "create_calendar_event",
    description: "Create a calendar event. Requires exact ISO datetime format.",
    schema: z.object({
      title: z.string(),
      startTime: z.string().describe("ISO format: '2024-01-15T14:00:00'"),
      endTime: z.string().describe("ISO format: '2024-01-15T15:00:00'"),
      attendees: z.array(z.string()).describe("email addresses"),
      location: z.string().optional(),
    }),
  }
);

const sendEmail = tool(
  async ({ to, subject, body, cc }) => {
    // Stub: In practice, this would call SendGrid, Gmail API, etc.
    return `Email sent to ${to.join(', ')} - Subject: ${subject}`;
  },
  {
    name: "send_email",
    description: "Send an email via email API. Requires properly formatted addresses.",
    schema: z.object({
      to: z.array(z.string()).describe("email addresses"),
      subject: z.string(),
      body: z.string(),
      cc: z.array(z.string()).optional(),
    }),
  }
);

const getAvailableTimeSlots = tool(
  async ({ attendees, date, durationMinutes }) => {
    // Stub: In practice, this would query calendar APIs
    return ["09:00", "14:00", "16:00"];
  },
  {
    name: "get_available_time_slots",
    description: "Check calendar availability for given attendees on a specific date.",
    schema: z.object({
      attendees: z.array(z.string()),
      date: z.string().describe("ISO format: '2024-01-15'"),
      durationMinutes: z.number(),
    }),
  }
);
```

## 2. 创建专门化 sub-agents

接下来，我们会创建负责各自领域的专门化 sub-agent。

### 创建 calendar agent

calendar agent 理解自然语言的排期请求，并把它们转换成精确的 API 调用。它负责日期解析、可用性检查，以及事件创建。

:::python
```python
from langchain.agents import create_agent


CALENDAR_AGENT_PROMPT = (
    "You are a calendar scheduling assistant. "
    "Parse natural language scheduling requests (e.g., 'next Tuesday at 2pm') "
    "into proper ISO datetime formats. "
    "Use get_available_time_slots to check availability when needed. "
    "If there is no suitable time slot, stop and confirm unavailability in your response. "
    "Use create_calendar_event to schedule events. "
    "Always confirm what was scheduled in your final response."
)

calendar_agent = create_agent(
    model,
    tools=[create_calendar_event, get_available_time_slots],
    system_prompt=CALENDAR_AGENT_PROMPT,
)
```
:::

:::js
```typescript
import { createAgent } from "langchain";

const CALENDAR_AGENT_PROMPT = `
You are a calendar scheduling assistant.
Parse natural language scheduling requests (e.g., 'next Tuesday at 2pm')
```

## 3. 将 sub-agents 包装成工具

现在把每个 sub-agent 包装成 supervisor 可以调用的工具。这是形成分层系统的关键架构步骤。supervisor 看到的是像 “schedule_event” 这样的高层工具，而不是像 “create_calendar_event” 这样的底层工具。

:::python
```python
@tool
def schedule_event(request: str) -> str:
    """Schedule calendar events using natural language.

    Use this when the user wants to create, modify, or check calendar appointments.
    Handles date/time parsing, availability checking, and event creation.

    Input: Natural language scheduling request (e.g., 'meeting with design team
    next Tuesday at 2pm')
    """
    result = calendar_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })
    return result["messages"][-1].text


@tool
def manage_email(request: str) -> str:
    """Send emails using natural language.

    Use this when the user wants to send notifications, reminders, or any email
    communication. Handles recipient extraction, subject generation, and email
    composition.

    Input: Natural language email request (e.g., 'send them a reminder about
    the meeting')
    """
    result = email_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })
    return result["messages"][-1].text
```
:::

:::js
```typescript
const scheduleEvent = tool(
  async ({ request }) => {
    const result = await calendarAgent.invoke({
      messages: [{ role: "user", content: request }]
    });
    const lastMessage = result.messages[result.messages.length - 1];
    return lastMessage.text;
  },
  {
    name: "schedule_event",
    description: `
Schedule calendar events using natural language.

Use this when the user wants to create, modify, or check calendar appointments.
Handles date/time parsing, availability checking, and event creation.

Input: Natural language scheduling request (e.g., 'meeting with design team next Tuesday at 2pm')
    `.trim(),
    schema: z.object({
      request: z.string().describe("Natural language scheduling request"),
    }),
  }
);

const manageEmail = tool(
  async ({ request }) => {
    const result = await emailAgent.invoke({
      messages: [{ role: "user", content: request }]
    });
    const lastMessage = result.messages[result.messages.length - 1];
    return lastMessage.text;
  },
  {
    name: "manage_email",
    description: `
Send emails using natural language.

Use this when the user wants to send notifications, reminders, or any email communication.
Handles recipient extraction, subject generation, and email composition.

Input: Natural language email request (e.g., 'send them a reminder about the meeting')
    `.trim(),
    schema: z.object({
      request: z.string().describe("Natural language email request"),
    }),
  }
);
```
:::

工具描述会帮助 supervisor 决定何时使用各个工具，所以要写得清晰且具体。这里我们只返回 sub-agent 的最终回复，因为 supervisor 不需要看到中间推理或工具调用。

## 4. 创建 supervisor agent

现在创建负责编排 sub-agent 的 supervisor。supervisor 只看到高层工具，并在领域层面做路由决策，而不是在单个 API 层面做决定。

:::python
```python
SUPERVISOR_PROMPT = (
    "You are a helpful personal assistant. "
    "You can schedule calendar events and send emails. "
    "Break down user requests into appropriate tool calls and coordinate the results. "
    "When a request involves multiple actions, use multiple tools in sequence or in parallel as appropriate."
)

supervisor_agent = create_agent(
    model,
    tools=[schedule_event, manage_email],
    system_prompt=SUPERVISOR_PROMPT,
)
```
:::

:::js
```typescript
const SUPERVISOR_PROMPT = `
You are a helpful personal assistant.
You can schedule calendar events and send emails.
Break down user requests into appropriate tool calls and coordinate the results.
When a request involves multiple actions, use multiple tools in sequence or in parallel as appropriate.
`.trim();

const supervisorAgent = createAgent({
  model: llm,
  tools: [scheduleEvent, manageEmail],
  systemPrompt: SUPERVISOR_PROMPT,

```

supervisor 默认是顺序分发任务的。每个 tool call 会先完成，之后才会开始下一个。不过很多 LLM 会在一次响应里发出多个 tool call（就像上面的 trace 一样，同时调用了 `schedule_event` 和 `manage_email`），运行时会并行执行这些调用。你也可以配置显式并行分发。详情请参见 [`create_supervisor` reference docs](https://reference.langchain.com/python/langgraph-supervisor/supervisor/create_supervisor)。
</Note>

```python
    body: str,
```

### 理解架构

你的系统分为三层。最底层是要求精确格式的刚性 API 工具。中间层是接受自然语言、把它翻译成结构化 API 调用并返回自然语言确认的 sub-agent。最上层是 supervisor，它只在领域层面路由高层能力并综合结果。

这种职责分离带来几个好处：每一层都有明确职责，你可以在不影响已有内容的情况下增加新领域，而且可以独立测试和迭代每一层。

## 6. 添加 human-in-the-loop review

把 [human-in-the-loop review](/oss/langchain/human-in-the-loop) 用在敏感操作上通常更稳妥。LangChain 提供了 [built-in middleware](/oss/langchain/human-in-the-loop#configuring-interrupts)，可以 review 工具调用，这里就是 review sub-agent 调用的工具。

```python
def schedule_event(
    request: str,
    runtime: ToolRuntime

    """Schedule calendar events using natural language."""

```

这样 sub-agent 就能看到完整对话上下文，这对解决“把它安排到明天同一时间”这类含糊指代很有用。

</Tip>

### 控制 supervisor 接收到什么

你也可以自定义哪些信息会回传给 supervisor：

:::python
```python
import json

@tool
def schedule_event(request: str) -> str:
    """Schedule calendar events using natural language."""
    result = calendar_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })

    # Option 1: Return just the confirmation message
    return result["messages"][-1].text

    # Option 2: Return structured data
    # return json.dumps({
    #     "status": "success",
    #     "event_id": "evt_123",
    #     "summary": result["messages"][-1].text
    # })
```
:::

:::js
```typescript
const scheduleEvent = tool(
  async ({ request }) => {
    const result = await calendarAgent.invoke({
      messages: [{ role: "user", content: request }]
    });

    const lastMessage = result.messages[result.messages.length - 1];

    // Option 1: Return just the confirmation message
    return lastMessage.text;

    // Option 2: Return structured data
    // return JSON.stringify({
    //   status: "success",
    //   event_id: "evt_123",
    //   summary: lastMessage.text
    // });
  },
  {
    name: "schedule_event",
    description: "Schedule calendar events using natural language.",
    schema: z.object({
      request: z.string().describe("Natural language scheduling request"),
    }),
  }
);
```
:::

**重要：** 确保 sub-agent 的最终消息包含所有相关信息。一个常见失败模式是 sub-agent 已经调用了工具，但最终回复里没有带上结果。

:::js

## 8. 关键要点

supervisor pattern 会创建多层抽象，每一层都有明确职责。在设计 supervisor 系统时，先划清领域边界，给每个 sub-agent 配置聚焦的工具和 prompt，给 supervisor 写清晰的工具描述，先独立测试每一层，再把它们集成起来，并根据自己的需求控制信息流。

<Tip>
**什么时候使用 supervisor pattern**

当你有多个明确不同的领域（calendar、email、CRM、database），每个领域都有多个工具或复杂逻辑，你希望集中控制工作流，而且 sub-agent 不需要直接和用户对话时，就使用 supervisor pattern。

如果只有少量工具，直接用单一 agent 就够了。若 agent 需要和用户进行对话，请改用 [handoffs](/oss/langchain/multi-agent/handoffs)。如果你需要的是 agent 之间的点对点协作，可以考虑其他 multi-agent 模式。
</Tip>
