    ## `@langchain/core` v1.3.0

    在[事件流](/oss/langchain/event-streaming)中，tool-call 参数现在以 `tool-call-delta` 事件的形式流式传输。每个事件只携带参数中新增的部分，与 `text-delta` 对文本的处理方式相同。更早的版本发送的是 `block-delta` 事件，会重复到目前为止的全部参数。

    ### 先升级客户端，再升级服务器

    低于下列版本的客户端无法处理 `tool-call-delta`。例如，较早版本的 `@langchain/react` 可能导致 `useMessages` 视图停止更新。[Agent Server](/langsmith/agent-server) 会原样透传事件，因此服务器上的包版本决定了客户端会收到哪些事件。

    1. 在每个读取该流的客户端中，把 `@langchain/react`、`@langchain/vue`、`@langchain/svelte` 或 `@langchain/angular` 升级到 1.2.6 或更高版本。
    2. 把服务器上的 `@langchain/core` 升级到 1.3.0 或更高版本。同时升级服务器使用的下列每个 provider 包，因为较早版本仍会发送 `block-delta`：
        - `@langchain/openai` 升级到 1.7.0 或更高版本
        - `@langchain/anthropic` 升级到 1.6.0 或更高版本
        - `@langchain/aws` 升级到 1.5.0 或更高版本
        - `@langchain/xai` 升级到 1.5.0 或更高版本

    升级 `langchain`、`deepagents` 或某个 provider 包可能会带入 `@langchain/core` 1.3.0。要在升级完所有客户端之前保持服务器不变，请在 `package.json` 中把 `@langchain/core` 固定为 `<1.3.0`。第 2 步中的 provider 版本要求 `@langchain/core` 1.3.0，因此在固定生效期间无法安装它们。
</Update>

    ## `langchain` v1.5.18

    `humanInTheLoopMiddleware` 现在可以对每次 tool call 暂停一次。设置 `interruptMode: "per_call"` 后，每个受控调用都会引发自己的 interrupt，你可以通过 interrupt ID 来应答。批量模式仍然是默认值。

    ```typescript
    humanInTheLoopMiddleware({ interruptOn: {...}, interruptMode: "per_call" });
    ```

    ### 新功能

    - **类型化应答**：每个 interrupt 都携带一个 `response_schema`，列出该调用允许的决策，客户端可以根据 schema 构建表单。参见[读取 response schema](/oss/langchain/human-in-the-loop#read-the-response-schema)。
    - **保存前校验**：LangGraph 会在保存之前拒绝无效的应答，因此你可以修正后再次应答同一个 interrupt。参见[修正无效的应答](/oss/langchain/human-in-the-loop#correct-an-invalid-answer)。
    - **编辑保持在被调用的工具上**：`edit` 不能切换工具，其参数会根据该工具自身的 schema 进行校验。
    - **`respond` 全面可用**：`interruptOn: { tool: true }` 现在允许所有决策（包括 `respond`），在两种模式下均如此，与 Python 一致。

    新 agent 请使用 per-call 模式。LangChain 计划在下一个主要版本中将其设为默认值。参见[每次 tool call 暂停一次](/oss/langchain/human-in-the-loop#pause-once-per-tool-call)和 [human-in-the-loop 概述](/oss/concepts/human-in-the-loop)。
</Update>
<Update label="Mar 24, 2026" tags={["deepagents"]} rss={{ title: "Mar 24, 2026 - deepagents" }}>
    ## `deepagents` v1.9.0-alpha.0

    `deepagents` v1.9.0 的 alpha 版本。

    - **[异步子代理](/oss/deepagents/async-subagents)**：Deep Agents 可以启动非阻塞后台任务，让用户在 subagents 并发工作时继续与 agent 交互。Sub-agents 需要 [LangSmith Deployment](/langsmith/deployment)。

    - **[Backend](/oss/deepagents/backends) protocol v2**：我们引入了新的 v2 backend protocol（`BackendProtocolV2`），它以向后兼容方式更新了 Deep Agents backend 接口。主要变化：
      - **结构化结果类型**：所有方法现在返回结构化 `Result` 对象（例如 `ReadResult`、`LsResult`、`GrepResult`、`GlobResult`），并通过 `error` 字段提供一致的错误处理，而不是返回原始值或抛出异常。
      - **多模态文件支持**：`read()` 返回带 `.content` 字段的 `ReadResult`，不再返回普通字符串。对于二进制文件（图片、PDF、音频、视频），完整原始 `Uint8Array` 内容会通过 `readRaw()` 返回，让 agents 可以原生处理多模态文件。
      - **方法名简化**：`lsInfo` -> `ls`，`grepRaw` -> `grep`，`globInfo` -> `glob`。
      - **向后兼容**：现有 v1 backends 可以使用 `adaptBackendProtocol` 适配到 v2 接口。v1 接口（`BackendProtocolV1`、`SandboxBackendProtocolV1`）已弃用，但会保留以兼容旧代码。
</Update>
<Update label="Jan 14, 2026" tags={["langgraph"]} rss={{ title: "Jan 14, 2026 - langgraph" }}>
    ## v1.1.0

    ### `@langchain/langgraph`

    引入 **StateSchema**：一种更简洁、与库无关的 graph state 定义方式，可与任何符合 [Standard Schema](https://github.com/standard-schema/standard-schema) 的验证库配合使用。

    ### Standard JSON Schema 支持

    LangGraph 现在支持 [Standard JSON Schema](https://standardschema.dev/json-schema)，这是一个由 Zod 4、Valibot、ArkType 和其他 schema 库实现的开放规范。这意味着你可以使用偏好的验证库，而不会被锁定：

    ```typescript
    import { z } from "zod"; // or valibot, arktype, etc.
    import { StateSchema, ReducedValue, MessagesValue } from "@langchain/langgraph";

    const AgentState = new StateSchema({
      messages: MessagesValue,
      currentStep: z.string(),
      count: z.number().default(0),
      history: new ReducedValue(
        z.array(z.string()).default(() => []),
        {
          inputSchema: z.string(),
          reducer: (current, next) => [...current, next],
        }
      ),
    });

    // Type-safe state and update types
    type State = typeof AgentState.State;
    type Update = typeof AgentState.Update;

    const graph = new StateGraph(AgentState)
      .addNode("agent", (state) => ({ count: state.count + 1 }))
      .addEdge(START, "agent")
      .addEdge("agent", END)
      .compile();
    ```

    ### 新的 state value primitives

    * **ReducedValue**：使用自定义 reducers 定义会累积值的字段。支持为 reducer inputs 分别设置 input 和 output schemas，以获得类型安全。
    * **UntrackedValue**：定义执行期间存在但永不 checkpoint 的临时 state，适用于数据库连接、缓存或仅运行时配置。
    * **MessagesValue**：用于 chat messages 的预构建 `ReducedValue`，带标准 messages reducer。

    ### 类型 helper 导出

    新增导出的类型工具，可用于为 graph builder 之外的函数标注类型：

    * `GraphNode<Schema, Nodes?, Config?>`：用完整推断为 node 函数标注类型
    * `ConditionalEdgeRouter<Schema, Nodes?>`：为 conditional edge routers 标注类型

    ```typescript
    // Type standalone node functions
    const myNode: GraphNode<typeof AgentState> = (state, config) => {
      return { count: state.count + 1 };
    };

    // Use schema type helpers directly
    const processState = (state: typeof AgentState.State) => {
      console.log(state.count);
    };
    ```

    现有 `Annotation` 和基于 zod 的 API 会继续照常工作；`StateSchema` 是为偏好 schema-first 定义方式的用户提供的额外选项。

<Update label="Nov 25, 2025" tags={["langchain"]} rss={{ title: "Nov 25, 2025 - langchain" }}>
    ## v1.1.0

    * [Model profiles](/oss/langchain/models#model-profiles)：Chat models 现在通过 `.profile` getter 暴露支持的功能和能力。这些数据来自 [models.dev](https://models.dev)，这是一个提供模型能力数据的开源项目。
    * [Model retry middleware](/oss/langchain/middleware/built-in#model-retry)：新增 middleware，可用可配置的指数退避自动重试失败的 model calls，提高 agent 可靠性。
    * [Content moderation middleware](/oss/langchain/middleware/built-in#provider-specific-middleware)：OpenAI 内容审核 middleware，用于在 agent 交互中检测和处理不安全内容。支持检查用户输入、模型输出和工具结果。
    * [Summarization middleware](/oss/langchain/middleware/built-in#summarization)：更新为支持使用 model profiles 的灵活触发点，以实现上下文感知总结。
    * [Structured output](/oss/langchain/structured-output)：现在可以从 model profiles 推断 `ProviderStrategy` 支持（原生 structured output）。
    * [`SystemMessage` for `createAgent`](/oss/langchain/middleware/custom#dynamic-prompt)：支持将 `SystemMessage` 实例直接传给 `createAgent` 的 `systemPrompt` 参数，并新增用于扩展 system messages 的 `concat` 方法。支持 cache control 和 structured content blocks 等高级功能。
    * [Dynamic system prompt middleware](/oss/langchain/short-term-memory)：`dynamicSystemPromptMiddleware` 的返回值现在是纯追加式的。返回 @[`SystemMessage`] 或 `string` 时，它们会与现有 system messages 合并，而不是替换它们，让多个修改 prompt 的 middleware 更容易组合。
    * **兼容性改进**：修复 structured output 和 tool schemas 中 Zod v4 validation errors 的错误处理，确保详细错误消息可以正确显示。
</Update>
