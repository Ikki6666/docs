## `createAgent`

`createAgent` 是 LangChain 1.0 中构建 agents 的标准方式。相比 LangGraph 导出的 prebuilt `createReactAgent`，它提供更简单的接口，并通过 middleware 提供更大的自定义潜力。

```ts
import { createAgent } from "langchain";

const agent = createAgent({
  model: "claude-sonnet-4-6",
  tools: [getWeather],
  systemPrompt: "You are a helpful assistant.",
});

const result = await agent.invoke({
  messages: [
    { role: "user", content: "What is the weather in Tokyo?" },
  ],
});

console.log(result.content);
```

在底层，`createAgent` 构建在基础 agent loop 之上：调用模型，让模型选择要执行的工具，并在模型不再调用工具时结束：

### Middleware

Middleware 是 `createAgent` 的定义性特性。它让 `createAgent` 高度可自定义，提升了可构建内容的上限。

优秀的 agents 需要[上下文工程](/oss/langchain/context-engineering)：在正确时间把正确信息提供给模型。Middleware 通过可组合抽象，帮助你控制动态 prompts、对话总结、选择性工具访问、state 管理和 guardrails。

#### 预构建 middleware

LangChain 为常见模式提供了一些[预构建 middlewares](/oss/langchain/middleware#built-in-middleware)，包括：

- `summarizationMiddleware`：在对话历史过长时压缩它
- `humanInTheLoopMiddleware`：要求对敏感 tool calls 进行审批
- `piiRedactionMiddleware`：在发送给模型前遮蔽敏感信息

```ts
import {
  createAgent,
  summarizationMiddleware,
  humanInTheLoopMiddleware,
  piiRedactionMiddleware,
} from "langchain";

const agent = createAgent({
  model: "claude-sonnet-4-6",
  tools: [readEmail, sendEmail],
  middleware: [
    piiRedactionMiddleware({ patterns: ["email", "phone", "ssn"] }),
    summarizationMiddleware({
      model: "claude-sonnet-4-6",
      trigger: { tokens: 500 },
    }),
    humanInTheLoopMiddleware({
      interruptOn: {
        sendEmail: {
          allowedDecisions: ["approve", "edit", "reject"],
        },
      },
    }),
  ],
});
```

#### 自定义 middleware

你也可以构建自定义 middleware 来满足特定需求。

使用 `createMiddleware` 函数实现以下任一 hook，即可构建自定义 middleware：

| Hook              | 运行时机             | 用例                               |
|-------------------|----------------------|------------------------------------|
| `beforeAgent`     | 调用 agent 之前      | 加载 memory、校验输入              |
| `beforeModel`     | 每次 LLM 调用之前    | 更新 prompts、裁剪 messages        |
| `wrapModelCall`   | 包裹每次 LLM 调用    | 拦截并修改 requests/responses      |
| `wrapToolCall`    | 包裹每次 tool call   | 拦截并修改工具执行                 |
| `afterModel`      | 每次 LLM 响应之后    | 校验输出、应用 guardrails          |
| `afterAgent`      | Agent 完成之后       | 保存结果、清理                     |

  <img
    src="/oss/images/middleware_final.png"
    alt="Middleware flow diagram"
    className="rounded-lg"

自定义 middleware 示例：

```ts
import { createMiddleware } from "langchain";

const contextSchema = z.object({
  userExpertise: z.enum(["beginner", "expert"]).default("beginner"),
})

const expertiseBasedToolMiddleware = createMiddleware({
  wrapModelCall: async (request, handler) => {
    const userLevel = request.runtime.context.userExpertise;
    if (userLevel === "expert") {
      const tools = [advancedSearch, dataAnalysis];
      return handler(
        request.replace("openai:gpt-5.5", tools)
      );
    }
    const tools = [simpleSearch, basicCalculator];
    return handler(
      request.replace("openai:gpt-5-nano", tools)
    );
  },
});

const agent = createAgent({
  model: "claude-sonnet-4-6",
  tools: [simpleSearch, advancedSearch, basicCalculator, dataAnalysis],
  middleware: [expertiseBasedToolMiddleware],
  contextSchema,
});
```

更多信息请参见[完整 middleware 指南](/oss/langchain/middleware)。

### Structured output

`createAgent` 改进了 structured output 生成：

- **主循环集成**：Structured output 现在在主循环中生成，不再需要额外的 LLM 调用
- **Structured output strategy**：模型可以在调用工具和使用 provider-side structured output generation 之间选择
- **降低成本**：消除额外 LLM 调用带来的额外费用

```ts
import { createAgent } from "langchain";
import * as z from "zod";

const weatherSchema = z.object({
  temperature: z.number(),
  condition: z.string(),
});

const agent = createAgent({
  model: "gpt-5.4-mini",
  tools: [getWeather],
  responseFormat: weatherSchema,
});

const result = await agent.invoke({
  messages: [
    { role: "user", content: "What is the weather in Tokyo?" },
  ],
});

console.log(result.structuredResponse);
```

**错误处理**：通过 `ToolStrategy` 的 `handleErrors` 参数控制错误处理：
- **解析错误**：模型生成的数据不符合目标结构
- **多个 tool calls**：模型为 structured output schemas 生成 2 个或更多 tool calls

## 标准 content blocks

<Note>
    大多数包已有 1.0 版本。目前只有以下包支持新的 content blocks：

    - `langchain`
    - `@langchain/core`
    - `@langchain/anthropic`
    - `@langchain/openai`

    更广泛的 content blocks 支持正在规划中。
</Note>

### 优势

- **Provider 无关**：无论 provider 是什么，都可用同一个 API 访问 reasoning traces、citations、内置工具（web search、code interpreters 等）和其他功能
- **类型安全**：所有 content block 类型都有完整类型提示
- **向后兼容**：标准 content 可以[懒加载](/oss/langchain/messages#standard-content-blocks)，因此没有相关破坏性变更

更多信息请参见 [content blocks](/oss/langchain/messages#message-content) 指南。

## 简化后的包

LangChain v1 简化了 `langchain` 包命名空间，使其聚焦 agents 的关键构建块。该包只暴露最有用、最相关的功能：

其中大多数会为了方便从 `@langchain/core` 重新导出，让你获得专注于构建 agents 的 API surface。


### `@langchain/classic`

旧功能已移至 [`@langchain/classic`](https://www.npmjs.com/package/@langchain/classic)，以保持核心包精简、聚焦。

#### `@langchain/classic` 包含什么

- 旧 chains 和 chain implementations
- Retrievers
- Indexing API
- [`@langchain/community`](https://www.npmjs.com/package/@langchain/community) 导出
- 其他已弃用功能

如果你使用这些功能，请安装 [`@langchain/classic`](https://www.npmjs.com/package/@langchain/classic)：

<CodeGroup>
```bash npm
npm install @langchain/classic
```
```bash pnpm
pnpm install @langchain/classic
```
```bash yarn
yarn add @langchain/classic
```
```bash bun
bun add @langchain/classic
```
</CodeGroup>

然后更新 imports：

```typescript
import { ... } from "langchain"; // [!code --]
```
