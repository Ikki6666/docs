## 设置与安装

要使用这一功能，请安装 `@sap/hana-langchain` 包及其 peer dependencies：

```bash
npm install @sap/hana-langchain @langchain/core@latest @langchain/classic@latest langchain@latest
```

创建到你的 SAP HANA Cloud 实例的连接。

```typescript
import * as dotenv from 'dotenv';
// Load environment variables if needed
dotenv.config();

import hanaClient from "@sap/hana-client";

const connectionParams = {
  host: process.env.HANA_DB_ADDRESS,
  port: process.env.HANA_DB_PORT,
  user: process.env.HANA_DB_USER,
  password: process.env.HANA_DB_PASSWORD,
};
const client = hanaClient.createConnection(connectionParams);

// connect to hanaDB
await new Promise<void>((resolve, reject) => {
  client.connect((err: Error) => {
    // Use arrow function here
    if (err) {
      reject(err);
    } else {
      console.log("Connected to SAP HANA successfully.");
      resolve();
    }
  });
});
```

`HanaSparqlQAChain` 将以下部分串联起来：

1. **感知 schema 的 SPARQL 生成**
2. 针对 SAP HANA 的**查询执行**
3. **自然语言答案格式化**

## 初始化

你需要：

* 一个用于生成和解释查询的 **LLM**
* 一个包含连接、`graph_uri` 和 ontology 的 **`HanaRdfGraph`**

如需了解如何创建 `HanaRdfGraph` 实例，请参见 [HanaRdfGraph](/oss/integrations/graphs/sap_hana_rdf_graph)。

导入 `HanaSparqlQAChain`

```typescript
import { HanaSparqlQAChain } from "@sap/hana-langchain";
const qaChain = HanaSparqlQAChain.fromLLM({ llm, graph, allowDangerousRequests: true, verbose: true });
```

## Pipeline 概览

1. SPARQL 生成
   - 使用 SPARQL 生成提示词
   - 输入：`schema`（来自 `graph.getSchema()` 的 Turtle）、`prompt`（用户问题）
2. 查询后处理
   - 从模型输出中提取 SPARQL
   - 如果缺失，则注入 `FROM <graph_uri>`
   - 确保存在常见前缀（`rdf:`、`rdfs:`、`owl:`、`xsd:`）
3. 执行
   - `graph.query(generatedSparql)`
4. 答案生成
   - 使用 QA 提示词，并传入：`context`（结果）、`prompt`（原始问题）

## Prompt 模板

### “SPARQL 生成”提示词

`sparqlGenerationPrompt` 用于指导 LLM 根据用户问题和给定 schema 生成 SPARQL 查询。

### 回答提示词

`qaPrompt` 会指示 LLM 仅基于数据库结果生成自然语言答案。
默认提示词可在此查看：[`prompts.ts`](https://github.com/SAP/langchainjs-integration-for-sap-hana-cloud/blob/main/src/chains/graph_qa/prompts.ts)

## 自定义提示词

你可以在初始化时覆盖默认值：

```typescript
const qaChain = HanaSparqlQAChain.fromLLM({
  llm,
  graph,
  allowDangerousRequests: true,
  verbose: true,
  sparqlGenerationPrompt: YOUR_SPARQL_PROMPT,
  qaPrompt: YOUR_QA_PROMPT,
});
```

> - `sparql_generation_prompt` 必须包含输入变量：`["schema", "prompt"]`
> - `qa_prompt` 必须包含输入变量：`["context", "prompt"]`

## 示例：基于 “Movies” 知识图谱进行问答

**前提条件**：
你必须拥有一个已启用 **triple store** 功能的 SAP HANA Cloud 实例。
详细说明请参见：[Enable Triple Store](https://help.sap.com/docs/hana-cloud-database/sap-hana-cloud-sap-hana-database-knowledge-graph-guide/enable-triple-store/)<br />
加载 `kgdocu_movies` 示例数据。参见 [Knowledge Graph Example](https://help.sap.com/docs/hana-cloud-database/sap-hana-cloud-sap-hana-database-knowledge-graph-guide/knowledge-graph-example)。

下面我们将：

1. 实例化一个指向 “movies” 数据图谱的 `HanaRdfGraph`
2. 把它包装进一个由 LLM 驱动的 `HanaSparqlQAChain`
3. 提出自然语言问题，并打印 chain 的响应

这演示了 LLM 如何在底层生成 SPARQL、在 SAP HANA 上执行查询，并返回人类可读的答案。

## 底层发生了什么？

1. **SPARQL 生成**
   chain 会用你的 Turtle 格式 ontology（`graph.getSchema()`）和用户问题，结合 `SPARQL_GENERATION_SELECT_PROMPT` 调用 LLM。随后，LLM 会输出一个与你的 schema 匹配的合法 `SELECT` 查询。
2. **预处理与执行**
   * **提取并清理**：从 LLM 响应中提取原始 SPARQL 文本。
   * **注入图谱上下文**：如果缺失，则添加 `FROM <graph_uri>`，并确保声明了常见前缀（`rdf:`、`rdfs:`、`owl:`、`xsd:`）。
   * **在 HANA 上运行**：通过 `HanaRdfGraph.query()` 在你的命名图上执行最终查询。
3. **答案生成**
   返回的 CSV（或 Turtle）结果会再次送入 LLM，这次使用 `SPARQL_QA_PROMPT`。LLM 会严格基于检索到的数据生成简洁、可读的人类答案，而不会产生幻觉。
