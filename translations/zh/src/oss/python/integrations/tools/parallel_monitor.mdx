>[Parallel](https://platform.parallel.ai/) 是一个面向 LLM 和 AI 应用构建的实时 Web 搜索与内容提取平台。

`ParallelMonitor` 会调用 Parallel 的 [Monitor API](https://docs.parallel.ai/monitor-api/monitor-quickstart)，按周期性频率（1 小时到 30 天）调度查询，并在相关新内容出现时通过 webhook 或轮询通知你。它适用于持续性的竞品情报、监管追踪或主题监控。

### 凭证

前往 [Parallel](https://platform.parallel.ai) 注册并生成 API key。然后在环境变量中设置 `PARALLEL_API_KEY`：

```python
import getpass
import os

if not os.environ.get("PARALLEL_API_KEY"):
    os.environ["PARALLEL_API_KEY"] = getpass.getpass("Parallel API key:\n")
```

## 实例化

```python
from langchain_parallel import ParallelMonitor

client = ParallelMonitor()
```

## 创建监控器

`frequency` 的格式是 `<n><unit>`，其中 unit 为 `h`、`d` 或 `w`，最终时长必须落在 `[1h, 30d]` 范围内，例如 `"1h"`、`"6h"`、`"3d"`、`"1w"`、`"2w"`。

```python
from langchain_parallel import MonitorWebhook

monitor = client.create(
    query="Latest peer-reviewed papers on net-energy-gain fusion",
    frequency="1d",
    metadata={"label": "fusion-watch"},
    # Optional: receive new events on a webhook endpoint.
    # webhook=MonitorWebhook(
    #     url="https://example.com/parallel/webhook",
    #     event_types=["monitor.event.detected"],
    # ),
)

print(monitor["monitor_id"], "—", monitor["status"])
```

有效的 `event_types` 包括 `monitor.event.detected`、`monitor.execution.completed` 和 `monitor.execution.failed`。如果省略该字段，则会接收这三种事件。

## 获取、列出、删除

```python
got = client.retrieve(monitor["monitor_id"])

monitors = client.list(limit=20)

deleted = client.delete(monitor["monitor_id"])
```

## 列出事件

`list_events()` 会返回一个扁平的 `{"events": [...]}` 列表。新创建的监控器通常在第一次计划执行前不会有事件，但无论有没有事件，调用返回结构都一样。

```python
events = client.list_events(monitor["monitor_id"], lookback_period="7d")
for ev in events.get("events", []):
    print(ev["type"], ev.get("event_date"))
```

要检查单个事件组：

```python
group = client.get_event_group(monitor["monitor_id"], event_group_id="...")
```

## 模拟事件

在接 webhook handler 时，这个功能很有用。`simulate_event()` 会向监控器的 webhook 发送指定类型的合成事件，默认类型为 `monitor.event.detected`。

<Note>
    `simulate_event()` 要求监控器上已经配置 webhook。调用 `create()` 时先传入 `webhook=MonitorWebhook(...)`，否则 API 会返回 `400 — Webhook not configured for this monitor`。
</Note>

```python
client.simulate_event(monitor["monitor_id"], event_type="monitor.event.detected")
```

## Async

每个 CRUD 和事件方法都有一个以 `a` 为前缀的异步版本：

```python
monitor = await client.acreate(query="...", frequency="6h")
events = await client.alist_events(monitor["monitor_id"], lookback_period="7d")
await client.adelete(monitor["monitor_id"])
```

## Webhook 签名校验

Webhook 投递使用 Standard Webhooks 方案进行签名，具体为对 `<webhook-id>.<webhook-timestamp>.<body>` 做 HMAC-SHA256、base64 编码，并使用 `v1,<sig>` 格式且带有重放保护。你可以使用 `verify_webhook` 进行校验：

```python
from langchain_parallel import verify_webhook

ok = verify_webhook(
    body,
    webhook_id=request.headers["webhook-id"],
    webhook_timestamp=request.headers["webhook-timestamp"],
    webhook_signature=request.headers["webhook-signature"],
    secret=os.environ["PARALLEL_WEBHOOK_SECRET"],
)
```

签名密钥是在 Parallel 控制台的组织级 webhook endpoint 上配置的，而不是每个 monitor 单独配置。完整的投递契约请参阅 [webhook setup](https://docs.parallel.ai/resources/webhook-setup)。

## 返回格式

`create()` 和 `retrieve()` 会返回 monitor 字典。`list_events()` 会返回扁平事件 envelope。

```python
# create() / retrieve()
{
    "monitor_id": "mon_abc",
    "status": "active",
    "query": "...",
    "frequency": "1d",
    "metadata": {...},
    "webhook": {"url": "...", "event_types": [...]},
    "created_at": "2026-04-15T10:30:00Z",
    # ... additional API-side fields
}

# list_events()
{
    "events": [
        {
            "type": "event",            # or "completion" / "error"
            "event_date": "2026-04-15T10:30:00Z",
            "event_group_id": "...",
            # ... event-type-specific fields
        },
    ],
}
```
