本页介绍用于 [Microsoft Azure](https://azure.microsoft.com/) 的 Azure AI 包选择、Foundry 设置、记忆、向量存储、backends、托管 agents 与持久执行。Microsoft 集成的卡片式索引请参阅 [Microsoft 集成](/oss/integrations/providers/microsoft)。

Azure AI、Dynamic Sessions、SQL Server 的集成包维护在 [langchain-azure](https://github.com/langchain-ai/langchain-azure) 仓库中。
同一仓库还维护 Azure Durable Task Scheduler 扩展。

Foundry 资源包含 Azure OpenAI 能力，并额外提供更广泛的模型目录、agent service 和评估能力。如果你在使用 Azure OpenAI 资源，可以[将其升级为 Foundry 资源](https://learn.microsoft.com/en-us/azure/foundry/how-to/upgrade-azure-openai)，在保留现有 API endpoint、状态和安全配置的同时获得 Foundry 能力。

对于 agent 托管，请使用 [Microsoft Foundry hosted agents](#microsoft-foundry-hosted-agents)，在具有内置运行时、会话、扩缩、身份和协议端点的托管 agent 平台上部署自定义 LangGraph 代码。

## 选择包

`langchain-azure-ai` 和 @[`langchain-openai`] 是互补关系，而非二选一。`langchain-azure-ai` 依赖 `langchain-openai`，其 chat 和 embeddings 类是 @[`ChatOpenAI`] 和 @[`OpenAIEmbeddings`] 的子类，因此安装 Azure 包并不会把 OpenAI 包从依赖链中移除。

使用下表选择起点：

| 场景 | 包 |
| --- | --- |
| 以 Foundry project 为中心的新应用 | `langchain-azure-ai` |
| Foundry Agent Service、托管 LangGraph、Toolbox、Content Safety、Azure 工具或 Application Insights | `langchain-azure-ai` |
| 从 Foundry project endpoint 配置的 embeddings | `langchain-azure-ai` |
| 在 Azure Durable Task Scheduler (DTS) 上持久执行 LangGraph 和 LangChain agent | `langchain-azure-compute[durabletask]` |
| 直接调用 Azure OpenAI v1 chat | `langchain-openai` |
| 同一份代码需要在 OpenAI 和 Azure 之间切换 | `langchain-openai` |
| 现有的 @[`AzureChatOpenAI`] 应用 | `langchain-openai` |
| 传统带日期的 Azure OpenAI API 版本 | `langchain-openai` |
| completion LLM 接口 | `langchain-openai` |
| 最小依赖与运维面 | `langchain-openai` |

将现有 `langchain-openai` 应用迁移到 `langchain-azure-ai` 并不是一次简单的 import 替换：

- 配置方式不同。`azure_endpoint`、`azure_deployment`、`api_version` 和 token-provider 参数会变为 `project_endpoint` 或 `endpoint`、`model` 和 `credential`。
- 默认行为不同。当 `AzureAIOpenAIApiChatModel` 解析出 project endpoint 时，默认使用 Responses API。要保留 Chat Completions 行为，请设置 `use_responses_api=False`。
- `langchain-azure-ai` 中没有与 @[`AzureOpenAI`] 对应的 completion LLM。
- @[`AzureChatOpenAI`] 携带 Azure 特有的响应元数据和内容过滤处理，Foundry chat model 不会复现这些行为。
- 两个包都遵循 OpenAI 官方 schema，因此 DeepSeek 或 Mistral 等兼容 provider 返回的非标准字段可能不会被保留。

## 聊天模型

Microsoft 通过 Azure 为 chat models 提供三种主要接入方式：

1. **Microsoft Foundry**（适合以 project 为中心的应用，推荐）：使用 `langchain-azure-ai` 中的 `AzureAIOpenAIApiChatModel`，配合 Foundry project endpoint 和 Azure 凭据。该包还与 Foundry agents、hosting、工具、Content Safety、检索和可观测性集成。
2. **[Azure OpenAI](https://learn.microsoft.com/en-us/azure/ai-services/openai/)**：直接调用 v1 API 或运行在 OpenAI 与 Azure 之间切换的代码，使用 `langchain-openai` 中的 `ChatOpenAI`。传统 Azure OpenAI API 版本和现有应用，使用 `AzureChatOpenAI`。
3. **[Azure ML](https://learn.microsoft.com/en-us/azure/machine-learning/)**：支持使用 Azure Machine Learning 部署和管理自定义或微调后的开源模型。

请从 `langchain-azure-ai` 开始，以访问 [Azure AI Foundry](https://learn.microsoft.com/en-us/azure/ai-studio/how-to/model-catalog-overview) 中可用的模型。

### Azure AI chat completions

使用 `AzureAIOpenAIApiChatModel` 类可访问 Azure OpenAI、DeepSeek R1、Cohere、Phi 和 Mistral 等模型。

<CodeGroup>
```bash pip
pip install -U langchain-azure-ai
```

```bash uv
uv add langchain-azure-ai
```
</CodeGroup>

配置您的 endpoint。您可以结合 `DefaultAzureCredential` 使用 project endpoint，也可以直接设置 API key。

```bash
export AZURE_AI_PROJECT_ENDPOINT=your-project-endpoint
```

```python
from langchain_azure_ai.chat_models import AzureAIOpenAIApiChatModel
from azure.identity import DefaultAzureCredential

llm = AzureAIOpenAIApiChatModel(
    model="gpt-6.1-sol",
    credential=DefaultAzureCredential(),
)

llm.invoke('Tell me a joke and include some emojis')
```

## Backends

### Azure Blob Storage Backend

> [Azure Blob Storage](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction) 是 Microsoft 面向云的对象存储解决方案。`AzureBlobBackend` 实现了 Deep Agents 的 `BackendProtocol`，因此 deep agent 可以把它的整个工作区（文件、记忆和 artifacts）持久化到 blob container 中。

<Note>`AzureBlobBackend` 属于 `langchain-azure-storage` 包，该包目前处于 **Public Preview** 阶段。</Note>

安装时使用 `deepagents` extra（要求 Python 3.11+）：

<CodeGroup>
    ```bash pip
    pip install -U "langchain-azure-storage[deepagents]"
    ```

    ```bash uv
    uv add "langchain-azure-storage[deepagents]"
    ```

</CodeGroup>

```python
from langchain_azure_storage.deepagents import AzureBlobBackend
```

**快速开始：**

```python
from deepagents import create_deep_agent
from langchain_azure_storage.deepagents import AzureBlobBackend

backend = AzureBlobBackend(
    account_url="https://<my-storage-account-name>.blob.core.windows.net",
    container_name="agent-workspace",
    prefix="session-001/",  # Optional: isolate each agent/session under a prefix.
)

agent = create_deep_agent(backend=backend)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "Write a hello world script to hello.py"}]}
)
```

该 backend 默认使用 [`DefaultAzureCredential`](https://learn.microsoft.com/en-us/azure/developer/python/sdk/authentication/credential-chains?tabs=dac#defaultazurecredential-overview)，并支持通过 `credential` 覆盖。

更多信息，请参见 [Backend 集成](/oss/integrations/backends)。完整的用法细节和安全指引，请参见[包仓库](https://github.com/langchain-ai/langchain-azure/tree/main/libs/azure-storage)。

## 向量存储

### Azure CosmosDB NoSQL vector search

> [Azure CosmosDB NoSQL](https://azure.microsoft.com/en-us/products/cosmos-db/) 是一个全托管、
> 全球分布式、无服务器文档数据库，面向现代应用。它以灵活的
> JSON 文档形式存储数据，并使用类 SQL 查询语言。由此带来高性能、低延迟和自动、
> 弹性扩展能力。它还为生成式 AI 和 RAG 等 AI 工作负载提供集成式向量搜索能力。
> 这使您可以在同一个数据库中，将向量嵌入与业务数据一起存储、索引和查询。
> 您可以将向量相似度搜索与传统基于关键词的搜索相结合，以获得相关结果，并从多种索引方法中选择最佳性能方案。
> 这种统一方式可简化应用架构并确保数据一致性。

## Runtime

### Microsoft Foundry hosted agents

[Microsoft Foundry hosted agents](https://learn.microsoft.com/en-us/azure/foundry/how-to/develop/langchain-hosted-agents) 在托管运行时中运行自定义 LangGraph 代码。使用 `langchain_azure_ai.agents.hosting` 包暴露编译好的 LangGraph graph，同时由 Foundry 管理运行时、会话、扩缩、身份和协议端点。

<Note>
    LangGraph 托管支持要求 `langchain-azure-ai[hosting]>=1.2.8`。
</Note>

开始之前，你需要一个 Azure 订阅、一个 Foundry 项目、一个已部署的聊天模型、Python 3.10 或更高版本，以及 Azure CLI 身份验证。部署 agent 还需要在项目上具有 Foundry Project Manager 角色。

根据客户端与 agent 的交互方式选择托管协议：

| 协议 | Run 参数 | SDK host 类 | 端点 | 适用场景 |
| --- | --- | --- | --- | --- |
| Responses | `--protocol responses` | `ResponsesHostServer` | `/responses` | 你需要 OpenAI 兼容的聊天、流式传输、响应历史或会话线程。大多数会话型 agent 从这里开始。 |
| Invocations | `--protocol invocations` | `InvocationsHostServer` | `/invocations` | 你需要自定义 JSON 结构、webhook 风格的端点，或非会话式处理。 |

<Note>对于使用基于 `BaseChatOpenAI` 的模型并接入 Responses API 的 hosted graph，请设置 `output_version="responses/v1"`。在 `langchain-openai` 1.0.0 及更高版本中可以省略该设置，除非被 `LC_OUTPUT_VERSION` 覆盖。此指南同时适用于 Responses 和 Invocations 两种托管协议。</Note>

[Responses 协议](https://github.com/microsoft-foundry/foundry-samples/tree/main/samples/python/hosted-agents/langgraph/responses/10-run)和 [Invocations 协议](https://github.com/microsoft-foundry/foundry-samples/tree/main/samples/python/hosted-agents/langgraph/invocations/03-run)的完整运行示例见相关仓库。

### 使用 Azure Durable Task Scheduler 持久执行 LangGraph

`langchain_azure_compute.graph` 使用 `attach_durability(graph, name="...")` 将编译好的 LangGraph `StateGraph`、LangChain `create_agent` workflow 或 Deep Agents `create_deep_agent` graph 包装进确定性的 [Azure Durable Task Scheduler (DTS)](https://learn.microsoft.com/azure/durable-task/scheduler/durable-task-scheduler) 编排。模型调用、工具和 graph 步骤在 activity 中运行，而不是在会重放的 orchestrator 中运行。`create_deep_agent` 还需要 `deepagents` 包。

<Note>
持久执行集成处于公开预览阶段。其 API 可能变化。需要 `langchain-azure-compute` 0.2.0 或更高版本。
</Note>

该适配器将执行控制面与 graph 状态面分离。请将 checkpoint 保存在 LangGraph saver 中，例如 `SqliteSaver`、`PostgresSaver` 或 `CosmosDBSaver`，并让每个 worker 都能访问持久化 checkpoint 存储。使用持久化 saver 时，步骤转换会传递 checkpoint 引用，而持久化工具/节点输入输出及最终结果仍通过 DTS 传递。未配置 checkpointer 时，适配器会附加一个 `InMemorySaver`，并在 DTS payload 中携带 checkpoint bundle。

- **Activity 隔离**：使用 `@durable_tool(retries=3)` 配置工具独立的 retry 策略，使用 `@durable_node` 将 graph 节点隔离为 activity。
- **Worker 崩溃故障转移**：向同一 graph 和 task hub 注册的另一个 worker 可以从已持久化的进度恢复执行。
- **Human-in-the-loop 等待**：LangGraph `interrupt()` 使用 DTS 外部事件暂停执行，无需占用 worker 线程或在等待期间消耗计算资源。使用 `run.wait_pending()` 读取 interrupt，并使用 `run.resume(pending, value)` 继续执行。
- **Azure Functions HTTP 路由**：`LangGraphFunctionApp` 在 Azure Functions Python v2 上暴露 start、status 和 respond 路由。HTTP 控制路由不能替代 graph worker。请针对同一 scheduler 和 hub 运行专用的 `DurableTaskSchedulerWorker` 副本；Consumption 或 Flex 计划不支持嵌入式 worker。Function app 还要求验证调用方身份并进行每实例所有权检查。参见 [Azure Functions human-in-the-loop 示例](https://github.com/langchain-ai/langchain-azure/tree/main/samples/langgraph-durabletask/10_azure_functions_hitl)。

以下示例将只读工具作为隔离 activity 运行，最多尝试三次：

```python
import os

from azure.identity import DefaultAzureCredential
from durabletask.azuremanaged.client import DurableTaskSchedulerClient
from durabletask.azuremanaged.worker import DurableTaskSchedulerWorker
from langchain.agents import create_agent
from langchain.messages import HumanMessage
from langchain.tools import tool
from langchain_azure_ai.chat_models import AzureAIOpenAIApiChatModel
from langchain_azure_compute.graph import attach_durability, durable_tool, sdk_options


@durable_tool(retries=3)
@tool
def get_order_status(order_id: str) -> str:
    """Look up an order's status (replace with your order service)."""
    return f"Order {order_id} has shipped."


model = AzureAIOpenAIApiChatModel(
    project_endpoint=os.environ["AZURE_AI_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),
    model=os.environ["AZURE_AI_MODEL_DEPLOYMENT_NAME"],
    use_responses_api=True,
)
agent = create_agent(model=model, tools=[get_order_status])
reg = attach_durability(agent, name="support_agent")

opts = sdk_options()
worker = DurableTaskSchedulerWorker(**opts)
sdk = DurableTaskSchedulerClient(**opts)
try:
    reg.register(worker)
    worker.start()
    run = reg.client(sdk).start(
        {"messages": [HumanMessage(content="What is the status of order 42?")]}
    )
    result = run.wait_result(timeout=60)
    print(result["messages"][-1].content_blocks)
finally:
    worker.stop()
    sdk.close()
```

<Warning>
Activity 至少执行一次，而非恰好一次。如果外部副作用发生后、在其完成确认前发生崩溃，该副作用可能会重复。请在外部变更边界使用持久化幂等键，例如 `runtime.config["metadata"]["durable_call_id"]`。DTS 历史包含 activity 输入和输出，还可能包含 checkpoint 和最终 graph 状态；请独立于 checkpoint 存储审查其保留与清除设置。
</Warning>

有关 checkpoint 配置、payload 限制、人工审批和生产托管，请参见[持久执行包指南](https://github.com/langchain-ai/langchain-azure/tree/main/libs/azure-compute#durable-langgraph-execution-durable-task-scheduler)。
