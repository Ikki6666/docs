## Chat models

### Bedrock Mantle

[AWS Bedrock Mantle API](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html#bedrock-mantle-responses) 通过 OpenAI 和 Anthropic Messages 协议对外提供模型。`ChatOpenAIMantle` 和 `ChatAnthropicMantle` 是访问这些模型的推荐接口。

这两个类都接受通过 `bedrock_api_key` 参数或 `AWS_BEARER_TOKEN_BEDROCK` 环境变量传入的 Bedrock API key。当两者都不可用时，它们会基于标准 AWS 凭证派生短时效的 API key，并透明地自动刷新。

`ChatOpenAIMantle` 继承自 `BaseChatOpenAI`。使用示例和能力说明参见对应的 [Responses API 文档](/oss/python/integrations/chat/openai#responses-api)。支持的模型请参阅 [AWS Mantle OpenAI 兼容 API 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html#bedrock-mantle-responses)。

`ChatAnthropicMantle` 继承自 `ChatAnthropic`，面向 Mantle 上的 Anthropic Messages endpoint。使用示例和能力说明参见 [`ChatAnthropic`](/oss/python/integrations/chat/anthropic) 文档。支持的模型请参阅 [AWS Mantle Anthropic API 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-anthropic-claude-messages.html)。

```python
from langchain_aws import ChatOpenAIMantle, ChatAnthropicMantle

openai_model = ChatOpenAIMantle(
    model="openai.gpt-5.6-luna",
    region_name="us-east-1",
)

anthropic_model = ChatAnthropicMantle(
    model="anthropic.claude-opus-5-5",
    region_name="us-east-1",
)
```

### Bedrock Converse

>[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项全托管服务，通过单一 API 提供来自 `AI21 Labs`、`Anthropic`、`Cohere`、`Meta`、`OpenAI`、`Stability AI` 和 `Amazon` 等领先 AI 公司的高性能 foundation models (`FMs`) 选择。由于 `Amazon Bedrock` 是无服务器服务，你无需管理任何基础设施，并且可以使用你已经熟悉的 AWS 服务，将生成式 AI 能力安全地集成并部署到应用中。

AWS Bedrock 维护了一个 [Converse API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html)，为 Bedrock 模型提供统一的对话接口。支持的所有模型可见[这里](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html)。

参见[使用示例](/oss/integrations/chat/bedrock)。

```python
from langchain_aws import ChatBedrockConverse
```

## Vector stores

### Amazon DynamoDB

[Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 是一项全托管的 NoSQL 数据库。使用 `DynamoDBVectorStore` 可以将文档存储为 DynamoDB 条目，并通过 DynamoDB 向量索引查询，从而让业务数据和检索共用同一张表。

```python
from langchain_aws.vectorstores import DynamoDBVectorStore
```

### Amazon MemoryDB

[Amazon MemoryDB](https://aws.amazon.com/memorydb/) 是一个具备持久性的内存数据库服务，可提供极快性能。MemoryDB 兼容 Redis OSS，这是一种流行的开源数据存储，因此你可以快速使用相同的 Redis OSS API 和命令来构建应用。

`InMemoryVectorStore` 类提供了一个可连接 Amazon MemoryDB 的 vectorstore。

```python
from langchain_aws.vectorstores.inmemorydb import InMemoryVectorStore

vds = InMemoryVectorStore.from_documents(
            chunks,
            embeddings,
            redis_url="rediss://cluster_endpoint:6379/ssl=True ssl_cert_reqs=none",
            vector_schema=vector_schema,
            index_name=INDEX_NAME,
        )
```
参见[使用示例](/oss/integrations/vectorstores/memorydb)。

### Amazon S3 Vectors

[Amazon S3 Vectors](https://aws.amazon.com/s3/features/vectors/) 是原生支持存储和查询向量的云对象存储。使用 `AmazonS3Vectors` 可以将嵌入存储到 S3 向量桶中并查询，无需预置基础设施。

```python
from langchain_aws.vectorstores import AmazonS3Vectors
```

参见[使用示例](/oss/integrations/vectorstores/s3_vectors)。

### Valkey

[Valkey](https://valkey.io/) 是一个开源高性能键值数据存储，支持缓存、消息队列等工作负载，也可充当主数据库。使用 `ValkeyVectorStore` 可以连接 [Amazon ElastiCache for Valkey](https://aws.amazon.com/elasticache/) 或 [Amazon MemoryDB for Valkey](https://aws.amazon.com/memorydb/)。

```python
from langchain_aws.vectorstores import ValkeyVectorStore
```

参见[使用示例](/oss/integrations/vectorstores/valkey)。


### Amazon Bedrock AgentCore Web Search

[Amazon Bedrock AgentCore Web Search](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/web-search-api.html) 让 agents 获取网络上的最新信息，且每条结果都带有来源 URL，并使用你的 AWS 凭证（而非搜索 API key）进行认证。默认情况下，toolkit 会直接调用 Web Search API。

<CodeGroup>
    ```bash pip
    pip install langchain-aws bedrock-agentcore
    ```

    ```bash uv
    uv add langchain-aws bedrock-agentcore
    ```
</CodeGroup>

参见[使用示例](/oss/integrations/tools/bedrock_agentcore_web_search)。

```python
from langchain.agents import create_agent
from langchain_aws.tools import create_web_search_toolkit

# The factory is synchronous. With no gateway argument, it calls the Web Search API.
toolkit, tools = create_web_search_toolkit(region="us-east-1")

try:
    agent = create_agent(model=llm, tools=tools)
    result = agent.invoke(
        {"messages": [{"role": "user", "content": "What changed in the most recent boto3 release?"}]}
    )
finally:
    toolkit.close()
```

## Memory

### Amazon Bedrock AgentCore Memory

>[Amazon Bedrock AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html) 为 LangGraph agents 提供托管式持久化，使对话历史和状态可在多次会话之间保存，并具备自动扩展与高可用能力。

<CodeGroup>
    ```bash pip
    pip install langgraph-checkpoint-aws
    ```

    ```bash uv
    uv add langgraph-checkpoint-aws
    ```
</CodeGroup>

```python
from langgraph_checkpoint_aws import AgentCoreMemorySaver

# Create checkpointer
checkpointer = AgentCoreMemorySaver(
    memory_id="your-memory-id",
    region_name="us-west-2"
)

# Use with LangGraph
graph = workflow.compile(checkpointer=checkpointer)

# Invoke with thread_id and actor_id for conversation persistence
config = {
    "configurable": {
        "thread_id": "user-123",
        "actor_id": "my-agent"  # Required for AgentCore
    }
}
result = graph.invoke({"messages": []}, config)
```

核心特性：
- 托管式基础设施，无需自行搭建数据库
- 自动扩展与高可用性
- 通过 `actor_id` 隔离实现多 agent 支持
- 静态与传输中的数据加密

### Amazon Bedrock AgentCore Memory Store

>[Amazon Bedrock AgentCore Memory Store](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html) 为 LangGraph agents 提供具备语义搜索能力的长期记忆，用于跨会话存储和检索用户偏好、事实和提取出的记忆。

```python
from langgraph_checkpoint_aws import AgentCoreMemoryStore

# Initialize store for long-term memories
store = AgentCoreMemoryStore(memory_id="your-memory-id", region_name="us-west-2")

# Use in a pre-model hook to save and retrieve memories
def pre_model_hook(state, config, *, store):
    actor_id = config["configurable"]["actor_id"]
    thread_id = config["configurable"]["thread_id"]
    namespace = (actor_id, thread_id)

    # Save a message
    store.put(namespace, str(uuid.uuid4()), {"message": msg})

    # Search for relevant memories
    results = store.search(("preferences", actor_id), query="user preferences", limit=5)
    return {"model_input_messages": state["messages"]}
```

## Runtime

### Amazon Bedrock AgentCore Runtime

>[Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 为 LangGraph agents 提供托管式无服务器执行环境，内置可观测性、自动扩展能力，并可无缝集成其他 AgentCore 服务。

部署会用到两个需要分别安装的包：`bedrock-agentcore` Python SDK，它将编译后的图包装到 runtime entrypoint 中；以及 AgentCore CLI，它打包项目并将其部署。

安装 SDK：

<CodeGroup>
    ```bash pip
    pip install bedrock-agentcore
    ```

    ```bash uv
    uv add bedrock-agentcore
    ```
</CodeGroup>

将编译后的图包装到 entrypoint 中：

```python
from bedrock_agentcore.runtime import BedrockAgentCoreApp

app = BedrockAgentCoreApp()


@app.entrypoint
def agent_invocation(payload, context):
    prompt = payload["prompt"]
    if not isinstance(prompt, str):
        raise ValueError("prompt must be a string")

    # graph is your compiled LangGraph application
    result = graph.invoke({"messages": [{"role": "user", "content": prompt}]})
    return {"result": result["messages"][-1].content}


if __name__ == "__main__":
    app.run()
```

安装 AgentCore CLI，它以 npm 包的形式发布：

```bash
npm install -g @aws/agentcore
```

<Note>
    AgentCore CLI 要求 Node.js 20.12 或更高版本，其 Python 项目还需要 [uv](https://docs.astral.sh/uv/)。如果你的 `PATH` 上已经存在 Python 版的 `agentcore` 命令，它会遮蔽 npm 版本，因为两者使用相同的命令名。请卸载该 Python 命令，然后打开一个新的终端。
</Note>

基于 LangChain 模板创建项目，然后部署并 invoke agent：

```bash
# Create a project
agentcore create --name MyAgent --template agent-python-langchain
cd MyAgent

# Run the agent locally
agentcore dev

# Deploy to AgentCore Runtime
agentcore deploy

# Invoke the deployed agent
agentcore invoke --runtime agent --payload '{"prompt": "Hello"}'
```

`agent-python-langchain` 模板会在 `app/agent/` 中搭建一个使用 @[create_agent] 构建的图，同时提供一个 `pyproject.toml` 以及 `agentcore/` 下的 CDK 项目。

如需部署自己编写的 entrypoint，请向项目中添加一个空的 Python runtime：

```bash
agentcore add runtime --name MyAgent --language python
```

将 entrypoint 放到 `app/MyAgent/main.py`，并在其旁边放置一个 `pyproject.toml`，然后运行 `agentcore deploy`。CLI 会读取你的代码，并在每次 `dev`、`build` 和 `deploy` 时更新 `agentcore/agentcore.json`。

更多信息请参见 [AgentCore CLI 入门](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli.html)。

`agent-python-langchain` 模板已经声明了 traces 所需的依赖。对于你自己的 entrypoint，`pyproject.toml` 必须声明 AWS Distro for OpenTelemetry（ADOT），因为 AgentCore Runtime 会在 `opentelemetry-instrument` 下启动 entrypoint。同时还要添加 LangChain instrumentor，以便在 [CloudWatch 生成式 AI 可观测性](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-configure.html)中呈现 traces：

```toml
[project]
dependencies = [
    "aws-opentelemetry-distro>=0.18.0",
    "opentelemetry-instrumentation-langchain>=0.55.0",
]
```

ADOT 会在启动时发现 instrumentor，因此 agent 无需编写任何 instrumentation 代码。由 CLI 管理的部署已经会在 `opentelemetry-instrument` 下运行 entrypoint。若要在本地复现这一点，请运行：

```bash
opentelemetry-instrument python main.py
```

更多信息请参见 [为 AgentCore 设置 LangGraph 遥测](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/supported-frameworks-langgraph.html)。
