将 HTML 文档拆分为易于处理的块，是自然语言处理、搜索索引等多种文本处理任务中的关键步骤。本指南将介绍 LangChain 提供的 3 种不同 HTML 文本切分器，你可以用它们高效地拆分 HTML 内容：

- [**HTMLHeaderTextSplitter**](#using-htmlheadertextsplitter)
- [**HTMLSectionSplitter**](#using-htmlsectionsplitter)
- [**HTMLSemanticPreservingSplitter**](#using-htmlsemanticpreservingsplitter)

每种切分器都有不同的特性和适用场景。本指南将帮助你理解它们之间的差异、适合的使用场景，以及如何正确使用它们。

```python
pip install -qU langchain-text-splitters
```

## 切分器概览

### [HTMLHeaderTextSplitter](#using-htmlheadertextsplitter)

<Info>
**适用于你希望根据标题层级保留文档的层次结构时。**
</Info>

**Description**：根据标题标签，例如 `<h1>`、`<h2>`、`<h3>` 等拆分 HTML 文本，并为每个 chunk 添加对应标题元数据。

**Capabilities**：
- 按 HTML 元素级别拆分文本。
- 保留编码在文档结构中的上下文丰富信息。
- 可以逐元素返回 chunk，也可以将具有相同元数据的元素合并。

___

### [HTMLSectionSplitter](#using-htmlsectionsplitter)

<Info>
适用于你希望把 HTML 文档拆成更大的 section，例如 `<section>`、`<div>` 或自定义 section 时。
</Info>

**Description**：和 HTMLHeaderTextSplitter 类似，但重点是基于指定标签把 HTML 拆成 section。

**Capabilities**：
- 使用 XSLT 转换来检测并拆分 section。
- 对较大的 section 内部会使用 `RecursiveCharacterTextSplitter`。
- 会考虑字体大小来判断 section。
___

### [HTMLSemanticPreservingSplitter](#using-htmlsemanticpreservingsplitter)

<Info>
**适用于你需要确保结构化元素不会跨 chunk 被拆开，从而保留上下文相关性时。**
</Info>

**Description**：把 HTML 内容拆成可处理的块，同时保留表格、列表和其他重要 HTML 元素的语义结构。

**Capabilities**：
- 保留表格、列表和其他指定 HTML 元素。
- 允许为特定 HTML 标签自定义 handler。
- 确保文档的语义含义被保留。
- 内置标准化和停用词移除

___

### 如何选择合适的切分器

- **在以下场景使用 `HTMLHeaderTextSplitter`**：你需要按照 HTML 标题层级切分文档，并保留标题相关元数据。
- **在以下场景使用 `HTMLSectionSplitter`**：你需要把文档拆成更大、更通用的 section，可能基于自定义标签或字体大小。
- **在以下场景使用 `HTMLSemanticPreservingSplitter`**：你需要在拆分文档时保留表格、列表等语义元素，确保它们不会被拆散，并保持上下文。

| Feature | `HTMLHeaderTextSplitter` | `HTMLSectionSplitter` | `HTMLSemanticPreservingSplitter` |
|--------------------------------------------|------------------------|---------------------|-------------------------------|
| 按标题拆分 | Yes | Yes | Yes |
| 保留语义元素（表格、列表） | No | No | Yes |
| 为标题添加元数据 | Yes | Yes | Yes |
| 支持 HTML 标签自定义 handlers | No | No | Yes |
| 保留媒体（图片、视频） | No | No | Yes |
| 考虑字体大小 | No | Yes | No |
| 使用 XSLT 转换 | No | Yes | No |

## Using HTMLHeaderTextSplitter

[HTMLHeaderTextSplitter](https://reference.langchain.com/python/langchain-text-splitters/html/HTMLHeaderTextSplitter) 是一种“结构感知型” [text splitter](/oss/integrations/splitters)，它会在 HTML 元素级别拆分文本，并为每个 chunk 添加与之“相关”的标题元数据。它可以逐元素返回 chunk，也可以把具有相同元数据的元素合并，这样做的目标是：

1. 尽可能让相关文本在语义上保持聚合
2. 保留文档结构中编码的上下文信息

它可以作为 chunking pipeline 的一部分，与其他 text splitter 组合使用。

它和面向 markdown 文件的 [MarkdownHeaderTextSplitter](/oss/integrations/splitters/markdown_header_metadata_splitter) 类似。

要指定按哪些标题拆分，请在实例化 `HTMLHeaderTextSplitter` 时传入 `headers_to_split_on`：

```python
from langchain_text_splitters import HTMLHeaderTextSplitter
...
```

```text
[Document(metadata={'Header 1': 'Main Title'}, ...)]
```

如果你希望逐个元素返回，并带上它们各自关联的标题，请在实例化时指定 `return_each_element=True`：

```python
html_splitter = HTMLHeaderTextSplitter(
    headers_to_split_on,
    return_each_element=True,
)
html_header_splits_elements = html_splitter.split_text(html_string)
```

和前面按标题聚合元素的结果相比：

```python
for element in html_header_splits[:2]:
    print(element)
```

```python
page_content='This is an introductory paragraph with some basic content.' metadata={'Header 1': 'Main Title'}
...
```

现在，每个元素都会作为独立的 `Document` 返回：

```python
for element in html_header_splits_elements[:3]:
    print(element)
```

```python
page_content='This is an introductory paragraph with some basic content.' metadata={'Header 1': 'Main Title'}
...
```

### 如何从 URL 或 HTML 文件拆分

如果要直接读取 URL，请把 URL 字符串传给 `split_text_from_url` 方法。

类似地，本地 HTML 文件可以传给 `split_text_from_file` 方法。

```python
url = "https://plato.stanford.edu/entries/goedel/"
...
```

### 如何约束 chunk 大小

`HTMLHeaderTextSplitter` 按 HTML 标题拆分后，还可以与另一种基于字符长度约束切分的 splitter 组合使用，例如 `RecursiveCharacterTextSplitter`。

可以通过第二个 splitter 的 `.split_documents` 方法来实现：

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter
...
```

```text
[Document(metadata={'Header 1': 'Kurt Gödel', ...})]
```

### 限制

不同 HTML 文档之间的结构差异可能很大。虽然 `HTMLHeaderTextSplitter` 会尝试为每个 chunk 附加所有“相关”的标题，但它有时可能漏掉某些标题。例如，这个算法默认存在一种信息层级关系，即标题总是在关联文本的“上方”，也就是作为前置兄弟节点、祖先节点，或它们的组合存在。

在下面这篇新闻文章中，在本文档写作时，其文档结构是这样的：顶层 headline 虽然被标记为 `h1`，但它和正文元素处于不同的子树中。因此我们可以观察到，`h1` 元素及其对应文本没有出现在 chunk metadata 中，但在适用的地方，`h2` 和其对应文本仍然会显示出来：

```python
url = "https://www.cnn.com/2023/09/25/weather/el-nino-winter-us-climate/index.html"
...
```

## Using HTMLSectionSplitter

从概念上说，`HTMLSectionSplitter` 和 [HTMLHeaderTextSplitter](#using-htmlheadertextsplitter) 相似，同样是一种“结构感知型” [text splitter](/oss/integrations/splitters)。它在元素级别拆分文本，并为每个 chunk 添加与其“相关”的标题元数据。它允许你按 section 拆分 HTML。

它可以逐元素返回 chunk，也可以把相同元数据的元素合并，其目标仍然是：

1. 尽可能在语义上保持相关文本聚合
2. 保留文档结构中的上下文信息

使用 `xslt_path` 可以提供一个绝对路径，对 HTML 做转换，使其能根据所提供的标签检测 section。默认会使用 `data_connection/document_transformers` 目录中的 `converting_to_header.xslt`。这样做是为了把 HTML 转换为更容易识别 section 的格式，例如将基于字体大小的 `span` 转为标题标签，从而能够被识别为 section。

### 如何拆分 HTML 字符串

```python
from langchain_text_splitters import HTMLSectionSplitter
...
```

```text
[Document(metadata={'Header 1': 'Main Title'}, ...)]
```

### 如何约束 chunk 大小

`HTMLSectionSplitter` 可以和其他 text splitter 一起使用，作为 chunking pipeline 的一部分。它内部会在 section 大于 chunk size 时使用 `RecursiveCharacterTextSplitter`。同时它也会结合文本字体大小判断某段内容是否应视为一个 section。

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter
...
```

```text
[Document(metadata={'Header 1': 'Main Title'}, page_content='Main Title'), ...]
```

## Using HTMLSemanticPreservingSplitter

`HTMLSemanticPreservingSplitter` 旨在将 HTML 内容拆分为易于处理的块，同时保留表格、列表和其他 HTML 元素的重要语义结构。这能确保这些元素不会跨 chunk 被拆开，否则会丢失关键上下文，例如表头、列表头等。

这个 splitter 的核心目标，是生成上下文相关性更好的 chunk。普通的 `HTMLHeaderTextSplitter` 加通用递归拆分，可能会把表格、列表和其他结构化元素从中间截断，导致上下文丢失，生成质量不佳的 chunk。

当 HTML 内容中包含表格和列表等结构化元素，并且保持这些元素完整非常关键时，`HTMLSemanticPreservingSplitter` 非常有用。此外，它还支持为特定 HTML 标签定义自定义 handler，因此在处理复杂 HTML 文档时很灵活。

**IMPORTANT**：`max_chunk_size` 不是一个绝对的 chunk 最大值。这个大小的计算是在“被保留内容尚未并入 chunk”时进行的，为的是确保这些内容不会被拆开。当保留的数据重新加入 chunk 后，chunk 大小有可能超过 `max_chunk_size`。这对于保持原始文档结构是必要的。

<Info>

Notes:

1. 我们定义了一个自定义 handler，用于重新格式化代码块内容
2. 我们为某些 HTML 元素定义了 deny list，在预处理阶段会分解这些标签及其内容
3. 我们故意设置了一个较小的 chunk size，以演示元素不会被拆开

</Info>

```python
# BeautifulSoup is required to use the custom handlers
from bs4 import Tag
from langchain_text_splitters import HTMLSemanticPreservingSplitter
...
```

```text
[Document(metadata={'Header 1': 'Main Title'}, ...)]
```

### 保留表格和列表

在这个示例中，我们将展示 `HTMLSemanticPreservingSplitter` 如何在 HTML 文档中保留表格和一个较长列表。chunk size 会设置为 50 个字符，以说明即使这些元素超过设定的最大大小，splitter 依然会保证它们不会被拆开。

```python
from langchain_text_splitters import HTMLSemanticPreservingSplitter
...
```

```text
[Document(metadata={'Header 1': 'Section 1'}, ...)]
```
