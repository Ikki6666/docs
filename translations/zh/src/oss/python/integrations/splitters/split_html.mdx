将 HTML 文档拆分为易于处理的块，是自然语言处理、搜索索引等多种文本处理任务中的关键步骤。本指南将介绍 LangChain 提供的 3 种不同 HTML 文本切分器，你可以用它们高效地拆分 HTML 内容：

- [**HTMLHeaderTextSplitter**](#using-htmlheadertextsplitter)
- [**HTMLSectionSplitter**](#using-htmlsectionsplitter)
- [**HTMLSemanticPreservingSplitter**](#using-htmlsemanticpreservingsplitter)

每种切分器都有独特的功能和适用场景。本指南将帮助你理解它们之间的差异、为什么选择其中某一种，以及如何高效地使用它们。

```
pip install -qU langchain-text-splitters
```

## 切分器概览

### [HTMLHeaderTextSplitter](#using-htmlheadertextsplitter)

<Info>
**适用于你希望根据标题保留文档的层次结构时。**
</Info>

**Description**：根据标题标签（例如 `<h1>`、`<h2>`、`<h3>` 等）拆分 HTML 文本，并为任意给定 chunk 添加每个相关标题的元数据。

**Capabilities**：
- 在 HTML 元素级别拆分文本。
- 保留编码在文档结构中的上下文丰富信息。
- 可以逐元素返回 chunk，也可以合并具有相同元数据的元素。

___


### [HTMLSectionSplitter](#using-htmlsectionsplitter)

<Info>
适用于你希望将 HTML 文档拆分为更大的 section，例如 `<section>`、`<div>` 或自定义 section 时。
</Info>

**Description**：与 HTMLHeaderTextSplitter 类似，但侧重于根据指定标签将 HTML 拆分为 section。

**Capabilities**：
- 使用 XSLT 转换来检测并拆分 section。
- 对较大的 section 内部使用 `RecursiveCharacterTextSplitter`。
- 会考虑字体大小来确定 section。
___

### [HTMLSemanticPreservingSplitter](#using-htmlsemanticpreservingsplitter)

<Info>
**适用于你需要确保结构化元素不会跨 chunk 被拆分，从而保留上下文相关性时。**
</Info>

**Description**：将 HTML 内容拆分为易于处理的块，同时保留表格、列表和其他重要 HTML 元素的语义结构。

**Capabilities**：
- 保留表格、列表和其他指定的 HTML 元素。
- 允许为特定 HTML 标签提供自定义 handler。
- 确保文档的语义含义得以保留。
- 内置标准化和停用词移除。

___

### 如何选择合适的切分器

- **在以下场景使用 `HTMLHeaderTextSplitter`**：你需要按照 HTML 标题层级拆分文档，并保留标题相关元数据。
- **在以下场景使用 `HTMLSectionSplitter`**：你需要将文档拆分为更大、更通用的 section，可能基于自定义标签或字体大小。
- **在以下场景使用 `HTMLSemanticPreservingSplitter`**：你需要在拆分文档时保留表格、列表等语义元素，确保它们不会被拆分，并保持其上下文。

| Feature | `HTMLHeaderTextSplitter` | `HTMLSectionSplitter` | `HTMLSemanticPreservingSplitter` |
|--------------------------------------------|------------------------|---------------------|-------------------------------|
| 按标题拆分 | Yes | Yes | Yes |
| 保留语义元素（表格、列表） | No | No | Yes |
| 为标题添加元数据 | Yes | Yes | Yes |
| 支持 HTML 标签自定义 handlers | No | No | Yes |
| 保留媒体（图片、视频） | No | No | Yes |
| 考虑字体大小 | No | Yes | No |
| 使用 XSLT 转换 | No | Yes | No |

## Using HTMLHeaderTextSplitter

[HTMLHeaderTextSplitter](https://reference.langchain.com/python/langchain-text-splitters/html/HTMLHeaderTextSplitter) 是一种“结构感知型” [text splitter](/oss/integrations/splitters)，它会在 HTML 元素级别拆分文本，并为任意给定 chunk 添加每个“相关”标题的元数据。它可以逐元素返回 chunk，也可以合并具有相同元数据的元素，目标是：(a) 尽可能在语义上让相关文本保持聚合；(b) 保留文档结构中编码的上下文丰富信息。它可以作为 chunking pipeline 的一部分，与其他 text splitter 一起使用。

它类似于面向 markdown 文件的 [MarkdownHeaderTextSplitter](/oss/integrations/splitters/markdown_header_metadata_splitter)。

要指定按哪些标题拆分，请在实例化 `HTMLHeaderTextSplitter` 时传入 `headers_to_split_on`，如下所示：


```python
from langchain_text_splitters import HTMLHeaderTextSplitter

headers_to_split_on = [
    ("h1", "Header 1"),
    ("h2", "Header 2"),
    ("h3", "Header 3"),
]

html_splitter = HTMLHeaderTextSplitter(headers_to_split_on)
html_header_splits = html_splitter.split_text(html_string)
html_header_splits
```

如果希望逐个元素返回，并带上各自关联的标题，请在实例化 `HTMLHeaderTextSplitter` 时指定 `return_each_element=True`：


```python

    headers_to_split_on,
```

### 如何从 URL 或 HTML 文件拆分

要直接从 URL 读取，请把 URL 字符串传给 `split_text_from_url` 方法。

类似地，本地 HTML 文件可以传给 `split_text_from_file` 方法。


```python
url = "https://plato.stanford.edu/entries/goedel/"

headers_to_split_on = [
    ("h1", "Header 1"),
    ("h2", "Header 2"),
    ("h3", "Header 3"),
    ("h4", "Header 4"),
]

html_splitter = HTMLHeaderTextSplitter(headers_to_split_on)

# for local file use html_splitter.split_text_from_file(<path_to_file>)
html_header_splits = html_splitter.split_text_from_url(url)
```

### 如何约束 chunk 大小

`HTMLHeaderTextSplitter` 按 HTML 标题拆分后，还可以与另一种基于字符长度约束切分的 splitter 组合使用，例如 `RecursiveCharacterTextSplitter`。

可以通过第二个 splitter 的 `.split_documents` 方法来实现：


```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

chunk_size = 500
chunk_overlap = 30
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=chunk_size, chunk_overlap=chunk_overlap
)

# Split
splits = text_splitter.split_documents(html_header_splits)
splits[80:85]
```

## Using HTMLSectionSplitter

从概念上说，`HTMLSectionSplitter` 与 [HTMLHeaderTextSplitter](#using-htmlheadertextsplitter) 相似，同样是一种“结构感知型” [text splitter](/oss/integrations/splitters)。它在元素级别拆分文本，并为任意给定 chunk 添加每个“相关”标题的元数据。它允许你按 section 拆分 HTML。

它可以逐元素返回 chunk，也可以合并具有相同元数据的元素，目标是：(a) 尽可能在语义上让相关文本保持聚合；(b) 保留文档结构中编码的上下文丰富信息。

使用 `xslt_path` 可以提供一个绝对路径，对 HTML 做转换，使其能根据所提供的标签检测 section。默认会使用 `data_connection/document_transformers` 目录中的 `converting_to_header.xslt`。这样做是为了把 HTML 转换为更容易识别 section 的格式或布局。例如，将基于字体大小的 `span` 转为标题标签，从而能够被识别为 section。

### 如何拆分 HTML 字符串：

## Using HTMLSemanticPreservingSplitter

`HTMLSemanticPreservingSplitter` 旨在将 HTML 内容拆分为易于处理的块，同时保留表格、列表和其他 HTML 元素的重要语义结构。这能确保这些元素不会跨 chunk 被拆分，否则会丢失上下文相关性，例如表头、列表头等。

这个 splitter 的核心目标，是生成上下文相关性更好的 chunk。普通的 `HTMLHeaderTextSplitter` 加通用递归拆分，可能会把表格、列表和其他结构化元素从中间截断，导致上下文丢失，生成质量不佳的 chunk。

当 HTML 内容中包含表格和列表等结构化元素，并且保持这些元素完整非常关键时，`HTMLSemanticPreservingSplitter` 非常有用。此外，它还支持为特定 HTML 标签定义自定义 handler，因此在处理复杂 HTML 文档时是一款通用的工具。

**IMPORTANT**：`max_chunk_size` 不是一个绝对的 chunk 最大值。这个大小的计算是在“被保留内容尚未并入 chunk”时进行的，为的是确保这些内容不会被拆分。当保留的数据重新加入 chunk 后，chunk 大小有可能超过 `max_chunk_size`。这对于保持原始文档结构是必要的。

<Info>

说明：

1. 我们定义了一个自定义 handler，用于重新格式化代码块内容
2. 我们为某些 HTML 元素定义了 deny list，在预处理阶段会分解这些标签及其内容
3. 我们故意设置了一个较小的 chunk size，以演示元素不会被拆分

</Info>


```python
# BeautifulSoup is required to use the custom handlers
from bs4 import Tag
from langchain_text_splitters import HTMLSemanticPreservingSplitter

headers_to_split_on = [
    ("h1", "Header 1"),
    ("h2", "Header 2"),
]


def code_handler(element: Tag) -> str:
    data_lang = element.get("data-lang")
    code_format = f"<code:{data_lang}>{element.get_text()}</code>"

    return code_format


splitter = HTMLSemanticPreservingSplitter(
    headers_to_split_on=headers_to_split_on,
    separators=["\n\n", "\n", ". ", "! ", "? "],
    max_chunk_size=50,
    preserve_images=True,
    preserve_videos=True,
    elements_to_preserve=["table", "ul", "ol", "code"],
    denylist_tags=["script", "style", "head"],
    custom_handlers={"code": code_handler},
)

documents = splitter.split_text(html_string)
documents
```

### 保留表格和列表

在这个示例中，我们将展示 `HTMLSemanticPreservingSplitter` 如何在 HTML 文档中保留表格和一个较长列表。chunk size 会设置为 50 个字符，以说明即使这些元素超过设定的最大大小，splitter 依然会保证它们不会被拆分。

```python
from langchain_text_splitters import HTMLSemanticPreservingSplitter
```

### 使用自定义 handler
`HTMLSemanticPreservingSplitter` 允许你为特定 HTML 元素定义自定义 handler。某些平台具有 `BeautifulSoup` 无法原生解析的自定义 HTML 标签；遇到这种情况时，你可以利用自定义 handler 轻松添加格式化逻辑。

这对于需要特殊处理的元素（例如 `<iframe>` 标签或特定的“data-”元素）尤其有用。在这个示例中，我们将为 `iframe` 标签创建一个自定义 handler，将它们转换为类似 Markdown 的链接。


```python
def custom_iframe_extractor(iframe_tag):
    iframe_src = iframe_tag.get("src", "")
    return f"[iframe:{iframe_src}]({iframe_src})"


splitter = HTMLSemanticPreservingSplitter(
    headers_to_split_on=headers_to_split_on,
    max_chunk_size=50,
    separators=["\n\n", "\n", ". "],
    elements_to_preserve=["table", "ul", "ol"],
    custom_handlers={"iframe": custom_iframe_extractor},
)

html_string = """
<!DOCTYPE html>
<html>
    <body>
        <div>
            <h1>Section with Iframe</h1>
            <iframe src="https://example.com/embed"></iframe>
            <p>Some text after the iframe.</p>
            <ul>
                <li>Item 1: Description of item 1, which is quite detailed and important.</li>
                <li>Item 2: Description of item 2, which also contains significant information.</li>
                <li>Item 3: Description of item 3, another item that we don't want to split across chunks.</li>
            </ul>
        </div>
    </body>
</html>
"""

documents = splitter.split_text(html_string)
print(documents)
```
```text
[Document(metadata={'Header 1': 'Section with Iframe'}, page_content='[iframe:https://example.com/embed](https://example.com/embed) Some text after the iframe'), Document(metadata={'Header 1': 'Section with Iframe'}, page_content=". Item 1: Description of item 1, which is quite detailed and important. Item 2: Description of item 2, which also contains significant information. Item 3: Description of item 3, another item that we don't want to split across chunks.")]
```
#### 说明
在这个示例中，我们为 `iframe` 标签定义了一个自定义 handler，将它们转换为类似 Markdown 的链接。当 splitter 处理 HTML 内容时，会使用该自定义 handler 转换 `iframe` 标签，同时保留表格和列表等其他元素。生成的 @[`Document`] 对象展示了 iframe 如何按照你提供的自定义逻辑进行处理。

**重要**：在保留链接等条目时，注意不要在分隔符中包含 `.`，也不要让分隔符为空。`RecursiveCharacterTextSplitter` 会按句号拆分，这会把链接截成两半。请确保提供的分隔符列表中改用 `. `。

### 使用自定义 handler 通过 LLM 分析图像

借助自定义 handler，我们还可以覆盖任何元素的默认处理方式。一个很好的例子是，在 chunking 流程中直接插入对文档中图像的语义分析。

由于我们的函数会在发现标签时被调用，因此可以覆盖 `<img>` 标签并关闭 `preserve_images`，从而插入任何我们希望嵌入 chunk 的内容。

```python
"""This example assumes you have helper methods `load_image_from_url` and an LLM agent `llm` that can process image data."""

from langchain_classic.agents import AgentExecutor

# This example needs to be replaced with your own agent
llm = AgentExecutor(...)


# This method is a placeholder for loading image data from a URL and is not implemented here
def load_image_from_url(image_url: str) -> bytes:
    # Assuming this method fetches the image data from the URL
    return b"image_data"


html_string = """
<!DOCTYPE html>
<html>
    <body>
        <div>
            <h1>Section with Image and Link</h1>
            <p>
                <img src="https://example.com/image.jpg" alt="An example image" />
                Some text after the image.
            </p>
            <ul>
                <li>Item 1: Description of item 1, which is quite detailed and important.</li>
                <li>Item 2: Description of item 2, which also contains significant information.</li>
                <li>Item 3: Description of item 3, another item that we don't want to split across chunks.</li>
            </ul>
        </div>
    </body>
</html>
"""


def custom_image_handler(img_tag) -> str:
    img_src = img_tag.get("src", "")
    img_alt = img_tag.get("alt", "No alt text provided")

    image_data = load_image_from_url(img_src)
    semantic_meaning = llm.invoke(image_data)

    markdown_text = f"[Image Alt Text: {img_alt} | Image Source: {img_src} | Image Semantic Meaning: {semantic_meaning}]"

    return markdown_text


splitter = HTMLSemanticPreservingSplitter(
    headers_to_split_on=headers_to_split_on,
    max_chunk_size=50,
    separators=["\n\n", "\n", ". "],
    elements_to_preserve=["ul"],
    preserve_images=False,
    custom_handlers={"img": custom_image_handler},
)

documents = splitter.split_text(html_string)

print(documents)
```

Item 2: Description of item 2, which also contains significant information. Item 3: Description of item 3, another item that we don't want to split across chunks.")]

#### 说明：

我们编写的自定义 handler 可以从 HTML 的 `<img>` 元素中提取特定字段，随后用 agent 进一步处理这些数据，并把结果直接插入 chunk。请务必确保 `preserve_images` 设置为 `False`，否则会执行 `<img>` 字段的默认处理。
