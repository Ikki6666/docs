Memgraph 是一个开源图数据库，面向动态分析环境进行了优化，并且与 Neo4j 兼容。Memgraph 使用 Cypher 来查询数据库，Cypher 是属性图数据库中应用最广、规范完整的开源查询语言。

本示例将展示如何[使用自然语言查询 Memgraph](#natural-language-querying)，以及如何从非结构化数据中[构建知识图谱](#constructing-knowledge-graph)。

先确保你已经[完成环境设置](#setting-up)。

## 设置

运行本指南需要先安装 [Docker](https://www.docker.com/get-started/) 和 [Python 3.x](https://www.python.org/)。

如果想第一次快速启动 **Memgraph Platform**，也就是 Memgraph 数据库、MAGE 库和 Memgraph Lab，可以执行下面的命令：

在 Linux/MacOS 上：

```
curl https://install.memgraph.com | sh
```

在 Windows 上：

```
iwr https://windows.memgraph.com | iex
```

这两个命令都会运行一个脚本，把 Docker Compose 文件下载到本地，然后在两个独立容器中构建并启动 `memgraph-mage` 和 `memgraph-lab` Docker 服务。这样你就可以开始使用 Memgraph 了。有关安装流程的更多信息，请参阅 [Memgraph 文档](https://memgraph.com/docs/getting-started/install-memgraph)。

要使用 LangChain，请安装并导入所有必要的包。这里我们会使用包管理器 [pip](https://pip.pypa.io/en/stable/installation/) 和 `--user` 标志，以确保权限正确。如果你已经安装了 Python 3.4 或更高版本，`pip` 会默认附带。你可以使用下面的命令安装所需的全部包：

```
pip install langchain langchain-openai langchain-memgraph --user
```

你可以直接在这个 notebook 中运行下面的代码块，也可以用单独的 Python 文件来试验 Memgraph 和 LangChain。

## 自然语言查询

Memgraph 与 LangChain 的集成包含自然语言查询功能。要使用它，先导入所需内容。我们会在代码出现时再解释这些导入项。

首先实例化 `MemgraphGraph`。这个对象保存了到运行中 Memgraph 实例的连接。请确保把所有环境变量都设置正确。

```python
import os

from langchain_core.prompts import PromptTemplate
from langchain_memgraph.chains.graph_qa import MemgraphQAChain
from langchain_memgraph.graphs.memgraph import MemgraphLangChain
from langchain_openai import ChatOpenAI

url = os.environ.get("MEMGRAPH_URI", "bolt://localhost:7687")
username = os.environ.get("MEMGRAPH_USERNAME", "")
password = os.environ.get("MEMGRAPH_PASSWORD", "")

graph = MemgraphLangChain(
    url=url, username=username, password=password, refresh_schema=False
)
```

`refresh_schema` 初始值设为 `False`，因为数据库里此时还没有数据，我们希望避免不必要的数据库调用。

### 填充数据库

在填充数据库之前，先确保它是空的。最有效的方法是切换到内存分析存储模式，删除图，然后切回内存事务存储模式。更多信息请参阅 Memgraph 的[存储模式](https://memgraph.com/docs/fundamentals/storage-memory-usage#storage-modes)。

接下来要写入数据库的数据是一组视频游戏，涵盖不同类型、不同平台，以及它们对应的发行商。

```python
# 删除图
graph.query("STORAGE MODE IN_MEMORY_ANALYTICAL")
graph.query("DROP GRAPH")
graph.query("STORAGE MODE IN_MEMORY_TRANSACTIONAL")

# 创建并执行种子查询
query = """
    MERGE (g:Game {name: "Baldur's Gate 3"})
    WITH g, ["PlayStation 5", "Mac OS", "Windows", "Xbox Series X/S"] AS platforms,
            ["Adventure", "Role-Playing Game", "Strategy"] AS genres
    FOREACH (platform IN platforms |
        MERGE (p:Platform {name: platform})
        MERGE (g)-[:AVAILABLE_ON]->(p)
    )
    FOREACH (genre IN genres |
        MERGE (gn:Genre {name: genre})
        MERGE (g)-[:HAS_GENRE]->(gn)
    )
    MERGE (p:Publisher {name: "Larian Studios"})
    MERGE (g)-[:PUBLISHED_BY]->(p);
"""

graph.query(query)
```

```text
[]
```

注意 `graph` 对象提供了 `query` 方法。这个方法会在 Memgraph 中执行查询，而 `MemgraphQAChain` 也会用它来查询数据库。

既然新数据已经写入 Memgraph，就需要刷新模式。生成出来的 schema 会被 `MemgraphQAChain` 用来指导 LLM 生成更好的 Cypher 查询。

```python
graph.refresh_schema()
```

为了熟悉数据并验证更新后的图模式，你可以用下面的语句把它打印出来：

```python
print(graph.get_schema)
```

### 查询数据库

要与 OpenAI API 交互，你必须把 API key 配置为环境变量。这样可以确保请求的授权正确。关于如何获取 API key 的更多信息，可以查看 [OpenAI 帮助中心](https://help.openai.com/en/articles/4936850-where-do-i-find-my-secret-api-key)。配置 API key 时，可以使用 Python 的 [os](https://docs.python.org/3/library/os.html) 包：

```
os.environ["OPENAI_API_KEY"] = "your-key-here"
```

如果你是在 Jupyter notebook 中运行代码，请执行上面的代码片段。

接下来创建 `MemgraphQAChain`，它会在基于图数据的问答流程中使用。`temperature` 参数设为 0，是为了确保回答可预测且稳定一致。你也可以把 `verbose` 参数设为 `True`，这样能看到更详细的查询生成信息。

```python
chain = MemgraphQAChain.from_llm(
    ChatOpenAI(temperature=0),
    graph=graph,
    model_name="gpt-4-turbo",
    allow_dangerous_requests=True,
)
```

现在就可以开始提问了！

```python
response = chain.invoke("Which platforms is Baldur's Gate 3 available on?")
print(response["result"])
```

```text
MATCH (:Game{name: "Baldur's Gate 3"})-[:AVAILABLE_ON]->(platform:Platform)
RETURN platform.name
Baldur's Gate 3 is available on PlayStation 5, Mac OS, Windows, and Xbox Series X/S.
```

```python
response = chain.invoke("Is Baldur's Gate 3 available on Windows?")
print(response["result"])
```

```text
MATCH (:Game{name: "Baldur's Gate 3"})-[:AVAILABLE_ON]->(:Platform{name: "Windows"})
RETURN "Yes"
Yes, Baldur's Gate 3 is available on Windows.
```

### 链修饰器

如果想调整链的行为，并获取更多上下文或附加信息，可以修改链的参数。

#### 直接返回查询结果

`return_direct` 修饰器决定是直接返回已执行 Cypher 查询的结果，还是返回处理后的自然语言响应。

```python
# 直接返回图查询结果
chain = MemgraphQAChain.from_llm(
    ChatOpenAI(temperature=0),
    graph=graph,
    return_direct=True,
    allow_dangerous_requests=True,
    model_name="gpt-4-turbo",
)

response = chain.invoke("Which studio published Baldur's Gate 3?")
print(response["result"])
```

```text
MATCH (g:Game {name: "Baldur's Gate 3"})-[:PUBLISHED_BY]->(p:Publisher)
RETURN p.name
[{'p.name': 'Larian Studios'}]
```

#### 返回查询中间步骤

`return_intermediate_steps` 链修饰器会在返回结果中包含查询的中间步骤，而不仅仅是初始结果。

```python
# 返回查询执行过程中的所有中间步骤
chain = MemgraphQAChain.from_llm(
    ChatOpenAI(temperature=0),
    graph=graph,
    allow_dangerous_requests=True,
    return_intermediate_steps=True,
    model_name="gpt-4-turbo",
)

response = chain.invoke("Is Baldur's Gate 3 an Adventure game?")
print(f"Intermediate steps: {response['intermediate_steps']}")
print(f"Final response: {response['result']}")
```

```text
MATCH (:Game {name: "Baldur's Gate 3"})-[:HAS_GENRE]->(:Genre {name: "Adventure"})
RETURN "Yes"
Intermediate steps: [{'query': 'MATCH (:Game {name: "Baldur\'s Gate 3"})-[:HAS_GENRE]->(:Genre {name: "Adventure"})\nRETURN "Yes"'}, {'context': [{'"Yes"': 'Yes'}]}]
Final response: Yes.
```

#### 限制查询结果数量

`top_k` 修饰器可用于限制查询返回结果的最大数量。

```python
# 限制查询返回的最大结果数
chain = MemgraphQAChain.from_llm(
    ChatOpenAI(temperature=0),
    graph=graph,
    top_k=2,
    allow_dangerous_requests=True,
    model_name="gpt-4-turbo",
)

response = chain.invoke("What genres are associated with Baldur's Gate 3?")
print(response["result"])
```

```text
MATCH (:Game {name: "Baldur's Gate 3"})-[:HAS_GENRE]->(g:Genre)
RETURN g.name;
Adventure, Role-Playing Game
```

### 进阶查询

随着方案复杂度提升，你可能会遇到需要更细致处理的不同场景。确保应用具备良好的可扩展性非常重要，这样用户流程才不会卡顿。

我们再实例化一次链，尝试回答一些用户可能会问的问题。

```python
chain = MemgraphQAChain.from_llm(
    ChatOpenAI(temperature=0),
    graph=graph,
    model_name="gpt-4-turbo",
    allow_dangerous_requests=True,
)

response = chain.invoke("Is Baldur's Gate 3 available on PS5?")
print(response["result"])
```

```text
MATCH (:Game{name: "Baldur's Gate 3"})-[:AVAILABLE_ON]->(:Platform{name: "PS5"})
RETURN "Yes"
I don't know the answer.
```

生成出来的 Cypher 查询看起来没问题，但响应里没有获得任何信息。这说明了使用 LLM 时一个常见的挑战，也就是用户的表达方式与数据实际存储方式之间的不一致。在这个例子里，用户认知与真实数据存储之间的差异会导致不匹配。提示词优化，也就是打磨模型提示词、让它更好理解这些差异，是一种能有效解决这个问题的方法。通过提示词优化，模型能够更准确地生成查询，从而成功检索到所需数据。

#### 提示词优化

为了解决这个问题，我们可以调整 QA 链的初始 Cypher 提示词。做法是给 LLM 增加指导，告诉它用户可能会如何称呼某些平台，比如这里的 PS5。我们通过 LangChain 的 `PromptTemplate` 来创建一个修改后的初始提示词，然后把它作为参数传给优化后的 `MemgraphQAChain` 实例。

```python
MEMGRAPH_GENERATION_TEMPLATE = """Your task is to directly translate natural language inquiry into precise and executable Cypher query for Memgraph database.
You will utilize a provided database schema to understand the structure, nodes and relationships within the Memgraph database.
Instructions:
- Use provided node and relationship labels and property names from the
schema which describes the database's structure. Upon receiving a user
question, synthesize the schema to craft a precise Cypher query that
directly corresponds to the user's intent.
- Generate valid executable Cypher queries on top of Memgraph database.
Any explanation, context, or additional information that is not a part
of the Cypher query syntax should be omitted entirely.
- Use Memgraph MAGE procedures instead of Neo4j APOC procedures.
- Do not include any explanations or apologies in your responses.
- Do not include any text except the generated Cypher statement.
- For queries that ask for information or functionalities outside the direct
generation of Cypher queries, use the Cypher query format to communicate
limitations or capabilities. For example: RETURN "I am designed to generate
Cypher queries based on the provided schema only."
Schema:
{schema}

With all the above information and instructions, generate Cypher query for the
user question.
If the user asks about PS5, Play Station 5 or PS 5, that is the platform called PlayStation 5.

The question is:
{question}"""

MEMGRAPH_GENERATION_PROMPT = PromptTemplate(
    input_variables=["schema", "question"], template=MEMGRAPH_GENERATION_TEMPLATE
)

chain = MemgraphQAChain.from_llm(
    ChatOpenAI(temperature=0),
    cypher_prompt=MEMGRAPH_GENERATION_PROMPT,
    graph=graph,
    model_name="gpt-4-turbo",
    allow_dangerous_requests=True,
)

response = chain.invoke("Is Baldur's Gate 3 available on PS5?")
print(response["result"])
```

```text
MATCH (:Game{name: "Baldur's Gate 3"})-[:AVAILABLE_ON]->(:Platform{name: "PlayStation 5"})
RETURN "Yes"
Yes, Baldur's Gate 3 is available on PS5.
```

现在，随着新的 Cypher 提示词加入了平台命名指导，得到的结果更准确，也更贴近用户的提问。

这样做还允许你进一步改进 QA 链。你可以很轻松地往链里加入更多提示词优化数据，从而提升应用的整体体验。

## 构建知识图谱

把非结构化数据转换为结构化数据并不容易，也不简单。本指南会展示如何借助 LLM 来完成这件事，以及如何在 Memgraph 中构建知识图谱。知识图谱创建完成后，你就可以把它用于 GraphRAG 应用。

从文本中构建知识图谱的步骤如下：

- [从文本中提取结构化信息](#extracting-structured-information-from-text)：使用 LLM 从文本中提取结构化图信息，形式为节点和关系。
- [存储到 Memgraph](#storing-into-memgraph)：将提取出的结构化图信息存入 Memgraph。

### 存储到 Memgraph

一旦你准备好 `GraphDocument` 这种格式的数据，也就是节点和关系，就可以使用 `add_graph_documents` 方法把它导入 Memgraph。这个方法会把 `graph_documents` 列表转换成适合在 Memgraph 中执行的 Cypher 查询。执行完成后，知识图谱就会存入 Memgraph。

```python
# 清空数据库
graph.query("STORAGE MODE IN_MEMORY_ANALYTICAL")
graph.query("DROP GRAPH")
graph.query("STORAGE MODE IN_MEMORY_TRANSACTIONAL")

# 创建知识图谱
graph.add_graph_documents(graph_documents)
```

<Note>
图谱构建过程不是确定性的，因为这里用于从非结构化数据生成节点和关系的 LLM 本身就是非确定性的。
</Note>

```python
# 清空数据库
graph.query("STORAGE MODE IN_MEMORY_ANALYTICAL")
graph.query("DROP GRAPH")
graph.query("STORAGE MODE IN_MEMORY_TRANSACTIONAL")

# 使用 Entity 标签存储到 Memgraph
graph.add_graph_documents(graph_documents, baseEntityLabel=True)
```

另外，还可以把图中获取到的信息来源一并记录下来。为此，把 `include_source` 设为 `True`，然后源文档就会被存储，并通过 `MENTIONS` 关系与图中的节点关联起来。

```python
# 清空数据库
graph.query("STORAGE MODE IN_MEMORY_ANALYTICAL")
graph.query("DROP GRAPH")
graph.query("STORAGE MODE IN_MEMORY_TRANSACTIONAL")

# 存储到 Memgraph，并包含 source
graph.add_graph_documents(graph_documents, include_source=True)
```

注意，源内容会被存储，同时还会生成 `id` 属性，因为文档本身没有 `id`。
你可以把 `__Entity__` 标签和文档 source 同时使用。不过要注意，这两者都会占用内存，尤其是包含长字符串内容的 source，更要留意。

最后，你可以像前面部分所解释的那样查询知识图谱：

```python
chain = MemgraphQAChain.from_llm(
    ChatOpenAI(temperature=0),
    graph=graph,
    model_name="gpt-4-turbo",
    allow_dangerous_requests=True,
)
print(chain.invoke("Who Charles Robert Darwin collaborated with?")["result"])
```

```text
MATCH (:Person {id: "Charles Robert Darwin"})-[:COLLABORATION]->(collaborator)
RETURN collaborator;
Alfred Russel Wallace
```
