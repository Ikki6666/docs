>[Timbr](https://docs.timbr.ai/doc/docs/integration/langchain-sdk/) 将自然语言输入与 Timbr 的 ontology 驱动语义层结合起来。借助 Timbr 强大的 ontology 能力，这个 SDK 能与 Timbr 数据模型和语义关系、注释集成，让用户可以用更贴近业务的语言来查询数据。

>Timbr 提供了一个预构建的 SQL agent，`TimbrSqlAgent`，可用于从用户提示词出发，经过语义 SQL 生成与校验，再到查询执行和结果分析的端到端流程。

>如果你只需要部分能力，或者想做自定义，可以使用 LangChain chain 和 LangGraph node，以及下面这 5 个主要工具：

>- `IdentifyTimbrConceptChain` 和 `IdentifyConceptNode` - 从用户提示中识别相关概念
>- `GenerateTimbrSqlChain` 和 `GenerateTimbrSqlNode` - 从自然语言提示生成 SQL 查询
>- `ValidateTimbrSqlChain` 和 `ValidateSemanticSqlNode` - 基于 Timbr knowledge graph schema 校验 SQL 查询
>- `ExecuteTimbrQueryChain` 和 `ExecuteSemanticQueryNode` - 在 Timbr knowledge graph 数据库上执行（语义和普通）SQL 查询
>- `GenerateAnswerChain` 和 `GenerateResponseNode` - 基于给定提示和数据行生成可读的人类答案

>此外，`langchain-timbr` 还提供 `TimbrLlmConnector`，方便通过 LLM provider 手动集成 Timbr 的语义层。

有关 `langchain-timbr` 集成的完整示例，请参见 [demo notebook](https://github.com/WPSemantix/Timbr-GenAI/tree/main/LangChain/LangChain_Timbr_Demo.ipynb)。

```bash
pip install langchain-timbr
```

## 配置项

从 `langchain-timbr` v2.0.0 开始，所有 chain、agent 和 node 都支持可选的基于环境变量的配置。你可以设置下面这些环境变量，为内置工具提供默认值并简化配置：

### Timbr 连接参数

- `TIMBR_URL`：默认的 Timbr 服务器 URL
- `TIMBR_TOKEN`：默认的 Timbr 认证 token
- `TIMBR_ONTOLOGY`：默认的 ontology/knowledge graph 名称

设置这些环境变量后，对应参数（`url`、`token`、`ontology`）在所有 chain 和 agent 构造函数中都变为可选，并会默认使用环境变量值。

### LLM 配置参数

- **LLM_TYPE**：LLM provider 类型（`langchain_timbr` 的 `LlmTypes` 枚举之一：`'openai-chat'`、`'anthropic-chat'`、`'chat-google-generative-ai'`、`'azure-openai-chat'`、`'snowflake-cortex'`、`'chat-databricks'`）
- **LLM_API_KEY**：用于认证 LLM provider 的 API key
- **LLM_MODEL**：要使用的模型名或 deployment
- **LLM_TEMPERATURE**：LLM 的温度设置
- **LLM_ADDITIONAL_PARAMS**：额外参数，格式可以是 dict 或 JSON 字符串

当设置了 LLM 环境变量后，`llm` 参数也会变成可选，并会使用带环境配置的 `LlmWrapper`。

环境变量示例：

```bash
# Timbr 连接
export TIMBR_URL="https://your-timbr-app.com/"
export TIMBR_TOKEN="tk_XXXXXXXXXXXXXXXXXXXXXXXX"
export TIMBR_ONTOLOGY="timbr_knowledge_graph"

# LLM 配置
export LLM_TYPE="openai-chat"
export LLM_API_KEY="your-openai-api-key"
export LLM_MODEL="gpt-5.5"
export LLM_TEMPERATURE="0.1"
export LLM_ADDITIONAL_PARAMS='{"max_tokens": 1000}'
```

## 查询语义层

现在我们可以使用 Timbr 的 chain 来查询语义层。导入并使用你想要的 chain/node，或者使用 `TimbrLlmConnector` 手动集成 Timbr 的语义层。

```python
from langchain_timbr import ExecuteTimbrQueryChain
from langchain_openai import ChatOpenAI
```

```python
# 你可以使用标准的 LangChain ChatOpenAI/ChatAnthropic 模型
# 或任何基于 langchain_core.language_models.chat.BaseChatModel 的其他 LLM 模型
llm = ChatOpenAI(model="gpt-5.5", temperature=0, openai_api_key="open-ai-api-key")

# 可选替代方案：使用 Timbr 的 LlmWrapper，它为不同的 LLM provider 提供通用连接
from langchain_timbr import LlmWrapper, LlmTypes
llm = LlmWrapper(llm_type=LlmTypes.OpenAI, api_key="open-ai-api-key", model="gpt-5.5")
```

### ExecuteTimbrQueryChain 示例

```python
execute_timbr_query_chain = ExecuteTimbrQueryChain(
    llm=llm,
    url="https://your-timbr-app.com/",
    token="tk_XXXXXXXXXXXXXXXXXXXXXXXX",
    ontology="timbr_knowledge_graph",
    schema="dtimbr",              # 可选
    concept="Sales",              # 可选
    concepts_list=["Sales","Orders"],  # 可选
    views_list=["sales_view"],         # 可选
    note="We only need sums",     # 可选
    retries=3,                    # 可选
    should_validate_sql=True      # 可选
)

result = execute_timbr_query_chain.invoke({"prompt": "What are the total sales for last month?"})
rows = result["rows"]
sql = result["sql"]
concept = result["concept"]
schema = result["schema"]
error = result.get("error", None)

usage_metadata = result.get("execute_timbr_usage_metadata", {})
determine_concept_usage = usage_metadata.get('determine_concept', {})
generate_sql_usage = usage_metadata.get('generate_sql', {})
# 每个 usage_metadata 项都包含：
# * 'approximate'：在调用 LLM 之前估算的 token 数
# * 'input_tokens'/'output_tokens'/'total_tokens'/等：LLM 返回的实际 token 使用量
```

```python
{'rows': [{'total_sales': 150000}], 'sql': 'SELECT SUM(amount) as total_sales FROM sales WHERE date >= DATEADD(month, -1, GETDATE())', 'concept': 'Sales', 'schema': 'dtimbr'}
```

### 使用 SequentialChain 组合多个 chain

你可以把多个 Timbr chain 组合起来，构建更复杂的工作流。

```python
from langchain_classic.chains import SequentialChain
from langchain_timbr import ExecuteTimbrQueryChain, GenerateAnswerChain

execute_timbr_query_chain = ExecuteTimbrQueryChain(
    llm=llm,
    url='https://your-timbr-app.com/',
    token='tk_XXXXXXXXXXXXXXXXXXXXXXXX',
    ontology='timbr_knowledge_graph',
)

generate_answer_chain = GenerateAnswerChain(
    llm=llm,
    url='https://your-timbr-app.com/',
    token='tk_XXXXXXXXXXXXXXXXXXXXXXXX',
)

pipeline = SequentialChain(
    chains=[execute_timbr_query_chain, generate_answer_chain],
    input_variables=["prompt"],
    output_variables=["answer", "sql"]
)

result = pipeline.invoke({"prompt": "What are the total sales for last month?"})
```

```python
{'prompt': 'What are the total sales for last month?', 'answer': 'Based on the query results, the total sales for last month amount to $150,000.', 'sql': 'SELECT SUM(amount) as total_sales FROM sales WHERE date >= DATEADD(month, -1, GETDATE())'}
```

## 使用 TimbrLlmConnector

如果你想手动集成 Timbr 的语义层，可以使用 `TimbrLlmConnector`，它包含以下方法：

- `get_ontologies` - 列出 Timbr 的语义知识图谱
- `get_concepts` - 列出所选 knowledge graph ontology representation 的概念
- `get_views` - 列出所选 knowledge graph ontology representation 的视图
- `determine_concept` - 从用户提示中识别相关概念
- `generate_sql` - 从自然语言提示生成 SQL 查询
- `validate_sql` - 基于 Timbr knowledge graph schema 校验 SQL 查询
- `run_timbr_query` - 在 Timbr knowledge graph 数据库上执行（语义和普通）SQL 查询
- `run_llm_query` - 执行 agent pipeline，从自然语言提示中依次确定概念、生成 SQL 并运行查询

```python
from langchain_timbr import TimbrLlmConnector

connector = TimbrLlmConnector(
    llm=llm,
    url="https://your-timbr-app.com/",
    token="tk_XXXXXXXXXXXXXXXXXXXXXXXX",
    ontology="timbr_knowledge_graph"
)

# 获取可用概念
concepts = connector.get_concepts()
print("Available concepts:", concepts)

# 运行完整查询流水线
result = connector.run_llm_query("What are the top 5 customers by revenue?")
print("Query result:", result)
```
