## 设置

要访问 Anthropic（Claude）模型，需要安装 `langchain-anthropic` 集成包并获取一个 [Claude](https://platform.claude.com/docs/en/get-started#prerequisites) API key。

### 安装

<CodeGroup>
    ```bash pip
    pip install -U langchain-anthropic
    ```
    ```bash uv
    uv add langchain-anthropic
    ```
</CodeGroup>

### 凭证

前往 [Claude console](https://console.anthropic.com) 注册并生成 Claude API key。完成后，设置 `ANTHROPIC_API_KEY` 环境变量：

```python
import getpass
import os

if "ANTHROPIC_API_KEY" not in os.environ:
    os.environ["ANTHROPIC_API_KEY"] = getpass.getpass("Enter your Anthropic API key: ")
```

要启用模型调用的自动 tracing，请设置 [LangSmith](/langsmith/observability) API key：

```python
os.environ["LANGSMITH_API_KEY"] = getpass.getpass("Enter your LangSmith API key: ")
os.environ["LANGSMITH_TRACING"] = "true"
```

## 内容块

在使用工具、[extended thinking](#extended-thinking) 等功能时，单个 Anthropic @[`AIMessage`] 中的内容既可能是单个字符串，也可能是 Anthropic content block 列表。

例如，当 Anthropic 模型调用工具时，工具调用会成为消息内容的一部分，同时也会暴露在标准化的 @[`AIMessage.tool_calls`] 中：

```python
from langchain_anthropic import ChatAnthropic
from typing_extensions import Annotated

model = ChatAnthropic(model="claude-haiku-4-5-20251001")


def get_weather(
    location: Annotated[str, ..., "Location as city and state."]
) -> str:
    """Get the weather at a location."""
    return "It's sunny."


model_with_tools = model.bind_tools([get_weather])
response = model_with_tools.invoke("Which city is hotter today: LA or NY?")
response.content
```


## 工具

Anthropic 的工具使用功能允许你定义 Claude 在对话中可以调用的外部函数。这可以支持动态信息检索、计算以及与外部系统交互。

关于如何将工具绑定到模型实例，请参见 @[`ChatAnthropic.bind_tools`]。

<Note>
    关于 Claude 的内置工具，例如代码执行、网页浏览、Files API 等，请参见 [Built-in tools](#built-in-tools)。
</Note>

```python
from pydantic import BaseModel, Field


class GetWeather(BaseModel):
    '''Get the current weather in a given location'''

    location: str = Field(description="The city and state, e.g. San Francisco, CA")


class GetPopulation(BaseModel):
    '''Get the current population in a given location'''

    location: str = Field(description="The city and state, e.g. San Francisco, CA")


model_with_tools = model.bind_tools([GetWeather, GetPopulation]) # [!code highlight]
ai_msg = model_with_tools.invoke("Which city is hotter today and which is bigger: LA or NY?")
ai_msg.tool_calls
```

### 严格工具使用

<Info>
    Strict tool use 需要 `langchain-anthropic>=1.1.0`。支持的模型请参见 [Claude docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/strict-tool-use)。
</Info>

Anthropic 支持选择性启用 [strict schema adherence to tool calls](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)。这可以通过 constrained decoding 保证工具名称和参数会被校验，并且类型正确。

在非 strict 模式下，Claude 偶尔会生成无效的工具输入，从而导致应用出错：

- **类型不匹配**：例如 `passengers: "2"` 而不是 `passengers: 2`
- **缺少必填字段**：遗漏函数所需字段
- **无效枚举值**：取值超出允许集合
- **Schema 违规**：嵌套对象与预期结构不匹配

Strict tool use 会保证工具调用符合 schema：

- 工具输入严格遵循 `input_schema`
- 字段类型和必填字段有保证
- 可以免去畸形输入的错误处理
- 使用的工具 `name` 一定来自你提供的工具列表

| Use strict tool use | Use standard tool calling |
|---------------------|---------------------------|
| Building agentic workflows where reliability is critical | Simple, single-turn tool calls |
| Tools with many parameters or nested objects | Prototyping and experimentation |
| Functions that require specific types (e.g., `int` vs `str`) |  |

要启用 strict tool use，在调用 @[`bind_tools`][ChatAnthropic.bind_tools] 时指定 `strict=True`。

```python
from langchain_anthropic import ChatAnthropic

model = ChatAnthropic(model="claude-sonnet-4-6")

def get_weather(location: str) -> str:
    """Get the weather at a location."""
    return "It's sunny."

model_with_tools = model.bind_tools([get_weather], strict=True)  # [!code highlight]
```

<Accordion
    title="Example: Type-safe booking system"
>
    设想一个预订系统，其中 `passengers` 必须是整数：

    ```python
    from langchain_anthropic import ChatAnthropic
    from typing import Literal

    model = ChatAnthropic(model="claude-sonnet-4-6")

    def book_flight(
        destination: str,
        departure_date: str,
        passengers: int, # [!code highlight]
        cabin_class: Literal["economy", "business", "first"]
    ) -> str:
        """Book a flight to a destination.

        Args:
            destination: The destination city
            departure_date: Date in YYYY-MM-DD format
            passengers: Number of passengers (must be an integer)
            cabin_class: The cabin class for the flight
        """
        return f"Booked {passengers} passengers to {destination}"

    model_with_tools = model.bind_tools(
        [book_flight],
        strict=True, # [!code highlight]
        tool_choice="any",
    )
    response = model_with_tools.invoke("Book 2 passengers to Tokyo, business class, 2025-01-15")

    # With strict=True, passengers is guaranteed to be int, not "2" or "two"
    print(response.tool_calls[0]["args"]["passengers"])
    ```

    ```text
    2
    ```
</Accordion>

Strict tool use 在 JSON schema 上有一些限制。详情请参见 [Claude docs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs#json-schema-limitations)。

如果工具 schema 使用了不受支持的特性，你会收到 400 错误。这种情况下，请简化 schema，或改用标准的非 strict 工具调用。

### 输入示例

对于复杂工具，可以提供使用示例，帮助 Claude 更准确地理解如何使用该工具。实现方式是在工具的 `extras` 参数中设置 `input_examples`。

```python
from langchain_anthropic import ChatAnthropic
from langchain.tools import tool

@tool(
    extras={ # [!code highlight]
        "input_examples": [ # [!code highlight]
            { # [!code highlight]
                "query": "weather report", # [!code highlight]
                "location": "San Francisco", # [!code highlight]
                "format": "detailed" # [!code highlight]
            }, # [!code highlight]
            { # [!code highlight]
                "query": "temperature", # [!code highlight]
                "location": "New York", # [!code highlight]
                "format": "brief" # [!code highlight]
            } # [!code highlight]
        ] # [!code highlight]
    } # [!code highlight]
)
def search_weather_data(query: str, location: str, format: str = "brief") -> str:
    """Search weather database with specific query and format preferences.

    Args:
        query: The type of weather information to retrieve
        location: City or region to search
        format: Output format, either 'brief' or 'detailed'
    """
    return f"{format.title()} {query} for {location}: Data found"

model = ChatAnthropic(model="claude-sonnet-4-6")
model_with_tools = model.bind_tools([search_weather_data])

response = model_with_tools.invoke(
    "Get me a detailed weather report for Seattle"
)
```

`extras` 参数还支持：
- `defer_loading`（bool）：为 [tool search](#tool-search) 按需加载工具
- `cache_control`（dict）：为工具启用 [prompt caching](#caching-tools)
- `eager_input_streaming`（bool）：为该工具启用 [fine-grained tool streaming](#fine-grained-tool-streaming)

### 细粒度工具流式输出

Anthropic 支持 [fine-grained tool streaming](https://platform.claude.com/docs/en/agents-and-tools/tool-use/fine-grained-tool-streaming)，在流式传输带有大参数的工具调用时可以降低延迟。

与其先缓存整个参数值再传输，细粒度流式输出会在参数数据可用时立即发送。这可以将大参数场景下的初始延迟从 15 秒降到约 3 秒。

<Warning>
    细粒度流式输出可能会返回无效或不完整的 JSON 输入，尤其是在响应达到 `max_tokens` 之前尚未输出完成时。请为不完整 JSON 数据做好合适的错误处理。
</Warning>

要为某个工具启用细粒度工具流式输出，请在该工具上设置 `extras={"eager_input_streaming": True}`。这个值会透传到 Anthropic API 的工具定义中。

```python
from langchain_anthropic import ChatAnthropic
from langchain.tools import tool

model = ChatAnthropic(model="claude-sonnet-4-6")

@tool(extras={"eager_input_streaming": True})
def write_document(title: str, content: str) -> str:
    """Write a document with the given title and content."""
    return f"Document '{title}' written successfully"

model_with_tools = model.bind_tools([write_document])

# Stream tool calls with reduced latency
for chunk in model_with_tools.stream(
    "Write a detailed technical document about the benefits of streaming APIs"
):
    print(chunk.content)
```

流式数据会以 `input_json_delta` block 的形式出现在 `chunk.content` 中。你可以累积这些 block 来构造完整的工具参数：

```python
import json

from langchain_anthropic import ChatAnthropic
from langchain.tools import tool

model = ChatAnthropic(model="claude-sonnet-4-6")

@tool(extras={"eager_input_streaming": True})
def write_document(title: str, content: str) -> str:
    """Write a document with the given title and content."""
    return f"Document '{title}' written successfully"

model_with_tools = model.bind_tools([write_document])

accumulated_json = ""

for chunk in model_with_tools.stream("Write a document about AI"):
    for block in chunk.content:
        if isinstance(block, dict) and block.get("type") == "input_json_delta":
            accumulated_json += block.get("partial_json", "")
            try:
                # Try to parse accumulated JSON
                parsed = json.loads(accumulated_json)
                print(f"Complete args: {parsed}")
            except json.JSONDecodeError:
                # JSON is still incomplete, continue accumulating
                pass
```

```text
Complete args: {'title': 'Artificial Intelligence: An Overview', 'content': '# Artificial Intelligence: An Overview...
```

### 程序化工具调用

<Info>
    Programmatic tool calling 需要 `langchain-anthropic>=1.3.0`。支持模型请参见 [Claude docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling)。
</Info>

可以将工具配置为可从 Claude 的 [code execution](#code-execution) 环境中被调用，这样在涉及大规模数据处理或多工具工作流的场景下，可以降低延迟和 token 消耗。

详情请参见 Claude 的 [programmatic tool calling guide](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling)。使用该特性时：

- 在工具列表中包含 [code execution](#code-execution) 内置工具
- 对希望被程序化调用的工具指定 `extras={"allowed_callers": ["code_execution_20250825"]}`

下面给出了一个结合 [`create_agent`](/oss/langchain/agents) 的完整示例。

<Tip>
    你可以在初始化时指定 `reuse_last_container`，以自动复用前一次模型响应中的代码执行容器。
</Tip>

```python
from langchain.agents import create_agent
from langchain.tools import tool
from langchain_anthropic import ChatAnthropic


@tool(extras={"allowed_callers": ["code_execution_20250825"]}) # [!code highlight]
def get_weather(location: str) -> str:
    """Get the weather at a location."""
    return "It's sunny."

tools = [
    {"type": "code_execution_20250825", "name": "code_execution"}, # [!code highlight]
    get_weather,
]

model = ChatAnthropic(
    model="claude-sonnet-4-6",
    reuse_last_container=True,  # [!code highlight]
)

agent = create_agent(model, tools=tools)

input_query = {
    "role": "user",
    "content": "What's the weather in Boston?",
}

result = agent.invoke({"messages": [input_query]})
```

## Effort

某些 Claude 模型支持 [effort](https://platform.claude.com/docs/en/build-with-claude/effort) 功能，用来控制 Claude 在生成响应时使用多少 token。这有助于在响应质量、延迟和成本之间进行平衡。

## 任务预算

### 在工具结果中使用（agentic RAG）

Claude 支持 [search_result](https://platform.claude.com/docs/en/build-with-claude/search-results) 内容块，用于表示来自知识库或其他自定义来源查询得到的、可被引用的结果。这些内容块既可以像上面的示例一样直接放在顶层，也可以放在工具结果中。这样 Claude 就能在回答中引用工具调用返回的结果。

如果你想在工具调用结果中传入 search result，需要定义一个工具，使其以 Anthropic 原生格式返回 `search_result` 内容块列表。例如：

```python
def retrieval_tool(query: str) -> list[dict]:
    """Access my knowledge base."""

    # Run a search (e.g., with a LangChain vector store)
    results = vector_store.similarity_search(query=query, k=2)

    # Package results into search_result blocks
    return [
        {
            "type": "search_result",
            # Customize fields as desired, using document metadata or otherwise
            "title": "My Document Title",
            "source": "Source description or provenance",
            "citations": {"enabled": True},
            "content": [{"type": "text", "text": doc.page_content}],
        }
        for doc in results
    ]
```

<Accordion title="End to end example with LangGraph">
    这里展示一个端到端示例，我们先用示例文档填充 LangChain [vector store](/oss/integrations/vectorstores/)，再给 Claude 配一个可以查询这些文档的工具。

    该工具接收一个搜索查询和一个 `category` 字面量字符串，不过你也可以使用任何合法的工具签名。

    本示例需要安装 `langchain-openai` 和 `numpy`：

    ```python
    from langchain.chat_models import init_chat_model
    from langchain.embeddings import init_embeddings
    from langchain_core.documents import Document
    from langchain_core.vectorstores import InMemoryVectorStore
    from langgraph.checkpoint.memory import InMemorySaver
    from langchain.agents import create_agent


    # Set up vector store
    # Ensure you set your OPENAI_API_KEY environment variable
    embeddings = init_embeddings("openai:text-embedding-3-small")
    vector_store = InMemoryVectorStore(embeddings)

    document_1 = Document(
        id="1",
        page_content=(
            "To request vacation days, submit a leave request form through the "
            "HR portal. Approval will be sent by email."
        ),
        metadata={
            "category": "HR Policy",
            "doc_title": "Leave Policy",
            "provenance": "Leave Policy - page 1",
        },
    )
    document_2 = Document(
        id="2",
        page_content="Managers will review vacation requests within 3 business days.",
        metadata={
            "category": "HR Policy",
            "doc_title": "Leave Policy",
            "provenance": "Leave Policy - page 2",
        },
    )
    document_3 = Document(
        id="3",
        page_content=(
            "Employees with over 6 months tenure are eligible for 20 paid vacation days "
            "per year."
        ),
        metadata={
            "category": "Benefits Policy",
            "doc_title": "Benefits Guide 2025",
            "provenance": "Benefits Policy - page 1",
        },
    )

    documents = [document_1, document_2, document_3]
    vector_store.add_documents(documents=documents)


    # Define tool
    async def retrieval_tool(
        query: str, category: Literal["HR Policy", "Benefits Policy"]
    ) -> list[dict]:
        """Access my knowledge base."""

        def _filter_function(doc: Document) -> bool:
            return doc.metadata.get("category") == category

        results = vector_store.similarity_search(
            query=query, k=2, filter=_filter_function
        )

        return [
            {
                "type": "search_result",
                "title": doc.metadata["doc_title"],
                "source": doc.metadata["provenance"],
                "citations": {"enabled": True},
                "content": [{"type": "text", "text": doc.page_content}],
            }
            for doc in results
        ]



    # Create agent
    model = init_chat_model("claude-haiku-4-5-20251001")

    checkpointer = InMemorySaver()
    agent = create_agent(model, [retrieval_tool], checkpointer=checkpointer)


    # Invoke on a query
    config = {"configurable": {"thread_id": "session_1"}}

    input_message = {
        "role": "user",
        "content": "How do I request vacation days?",
    }
    stream = await agent.astream_events(
        {"messages": [input_message]},
        config,
        version="v3",
    )
    async for snapshot in stream.values:
        snapshot["messages"][-1].pretty_print()
    ```

## Prompt 缓存

Anthropic 支持对提示中的元素进行 [caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)，包括消息、工具定义、工具结果、图片和文档。这样你可以复用大文档、说明、[few-shot documents](/langsmith/create-few-shot-evaluators) 以及其他数据，从而降低延迟和成本。

在直接模型调用中，有两种启用 prompt caching 的方式：

- **[Automatic caching](#automatic-caching)**：在调用时传入 `cache_control`（`model.invoke(..., cache_control=...)`）。这是 provider/API 级缓存，Anthropic API 会自动把缓存断点应用到最后一个可缓存的 block，并随着对话增长向前推进。
- **[Explicit cache breakpoints](#explicit-cache-breakpoints)**：直接在单独的内容块上放置 `cache_control`，从而精细控制具体缓存哪些部分。

<Warning>
    只有部分 Claude 模型支持 prompt caching。详情请参见 [Claude documentation](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#supported-models)。
</Warning>

<Note>
    对于 LangChain agent，如果你希望 LangChain 自动优化稳定的 system prompt 和 tool 内容，优先使用 [`AnthropicPromptCachingMiddleware`](/oss/integrations/middleware/anthropic#prompt-caching)。该 middleware 是 LangChain agent/harness 级优化，并不等同于下面展示的调用级 `cache_control`，后者是对 Anthropic API 行为的直接映射。
</Note>

### 自动缓存

<Info>
    Automatic caching 需要 `langchain-anthropic>=1.4.0`。
</Info>

通过调用参数传入 `cache_control`，即可自动缓存直到最后一个可缓存 block 为止的全部内容。之后如果再次请求相同前缀，就会自动复用缓存内容。随着对话增长，缓存断点会自动向前推进，因此你不需要手动管理单独的 `cache_control` 标记。

```python
from langchain_anthropic import ChatAnthropic
import requests

model = ChatAnthropic(model="claude-sonnet-4-5")

# Pull LangChain readme
get_response = requests.get(
    "https://raw.githubusercontent.com/langchain-ai/langchain/b476fdb54aa6e6f5f0b24a68c2f4a94e43b369f9/README.md"
)
readme = get_response.text

messages = [
    {
        "role": "system",
        "content": [
            {
                "type": "text",
                "text": "You are a technology expert.",
            },
            {
                "type": "text",
                "text": f"{readme}"
            },
        ],
    },
    {
        "role": "user",
        "content": "What's LangChain, according to its README?",
    },
]

response = model.invoke(
    messages,
    cache_control={"type": "ephemeral"},  # [!code highlight]
)

usage = response.usage_metadata["input_token_details"]
print(f"Usage:\n{usage}")

```

如果需要 1 小时缓存，可以指定 `ttl` 字段：

```python
response = model.invoke(
    messages,
    cache_control={"type": "ephemeral", "ttl": "1h"},  # [!code highlight]
)
```

#### 对话式应用中的增量缓存

Prompt caching 可以用于[多轮对话](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#continuing-a-multi-turn-conversation)，在保留先前消息上下文的同时避免重复处理。

我们可以通过给最后一条消息打上 `cache_control` 来启用增量缓存。Claude 会自动为后续消息使用之前最长的已缓存前缀。

下面实现了一个简单 chatbot，它基于 LangChain [chatbot tutorial](/oss/langchain/quickstart)，但额外加了一个自定义 [reducer](/oss/langgraph/graph-api#reducers)，会自动给每条用户消息中的最后一个内容块加上 `cache_control`：

<Accordion title="Chatbot with incremental prompt caching">
    ```python expandable
    import requests
    from langchain_anthropic import ChatAnthropic
    from langgraph.checkpoint.memory import MemorySaver
    from langgraph.graph import START, StateGraph, add_messages
    from typing_extensions import Annotated, TypedDict


    model = ChatAnthropic(model="claude-sonnet-4-6")

    # Pull LangChain readme
    get_response = requests.get(
        "https://raw.githubusercontent.com/langchain-ai/langchain/master/README.md"
    )
    readme = get_response.text


    def messages_reducer(left: list, right: list) -> list:
        # Update last user message
        for i in range(len(right) - 1, -1, -1):
            if right[i].type == "human":
                right[i].content[-1]["cache_control"] = {"type": "ephemeral"}
                break

        return add_messages(left, right)


    class State(TypedDict):
        messages: Annotated[list, messages_reducer]


    workflow = StateGraph(state_schema=State)


    # Define the function that calls the model
    def call_model(state: State):
        response = model.invoke(state["messages"])
        return {"messages": [response]}


    # Define the (single) node in the graph
    workflow.add_edge(START, "model")
    workflow.add_node("model", call_model)

    # Add memory
    memory = MemorySaver()
    app = workflow.compile(checkpointer=memory)
    ```

## 上下文管理

Anthropic 支持自动管理模型上下文窗口的 context management 功能，以优化性能和成本。

更详细的说明和配置选项请参见 [Claude documentation](https://platform.claude.com/docs/en/build-with-claude/context-editing)。

### 清除工具使用记录

可以从上下文中清除工具结果，以减少 token 使用，同时保持对话流连续。

### 自动压缩

Claude Opus 4.6 及更高版本支持自动 [server-side compaction](https://platform.claude.com/docs/en/build-with-claude/compaction)。当上下文窗口接近上限时，它会智能压缩对话历史，从而支持更长的对话，而无需手动管理上下文。

<Info>
    **Automatic compaction 要求：**

    - Claude Opus 4.6 或更高版本
    - `langchain-anthropic>=1.3.0`
    - `compact-2026-01-12` beta header
</Info>

```python
from langchain_anthropic import ChatAnthropic

model = ChatAnthropic(
    model="claude-opus-4-8",
    betas=["compact-2026-01-12"], # [!code highlight]
    max_tokens=4096,
    context_management={ # [!code highlight]
        "edits": [ # [!code highlight]
            { # [!code highlight]
                "type": "compact_20260112", # [!code highlight]
                "trigger": {"type": "input_tokens", "value": 50000}, # [!code highlight]
            } # [!code highlight]
        ] # [!code highlight]
    }, # [!code highlight]
)
```

关于 [trigger configuration](https://platform.claude.com/docs/en/build-with-claude/compaction#trigger-configuration) 的细节，请参见 Anthropic 文档。

当触发压缩事件时，`ChatAnthropic` 会返回表示提示状态的 [compaction blocks](https://platform.claude.com/docs/en/build-with-claude/compaction#working-with-compaction-blocks)。在多轮应用中，应将这些 block 保留在后续重新传给模型的消息历史中。

## 结构化输出

<Info>
    结构化输出需要 `langchain-anthropic>=1.1.0`。支持的模型请参见 [Claude docs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)。
</Info>

Anthropic 支持原生 [structured output feature](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)，可以保证响应遵循给定的 schema。

你既可以在单独的模型调用中访问该功能，也可以在 LangChain [agent](/oss/langchain/agents) 中通过指定 [response format](/oss/langchain/structured-output) 来使用。下面给出示例。

<Accordion title="Individual model calls">

使用 [`with_structured_output`](/oss/langchain/models#structured-output) 方法生成结构化响应。指定 `method="json_schema"` 以启用 Anthropic 的原生结构化输出功能；否则默认使用 function calling。

```python
from langchain_anthropic import ChatAnthropic
from pydantic import BaseModel, Field

model = ChatAnthropic(model="claude-sonnet-4-6")

class Movie(BaseModel):
    """A movie with details."""
    title: str = Field(description="The title of the movie")
    year: int = Field(description="The year the movie was released")
    director: str = Field(description="The director of the movie")
    rating: float = Field(description="The movie's rating out of 10")

model_with_structure = model.with_structured_output(Movie, method="json_schema")  # [!code highlight]
response = model_with_structure.invoke("Provide details about the movie Inception")
response
```

```python
Movie(title='Inception', year=2010, director='Christopher Nolan', rating=8.8)
```

</Accordion>

<Accordion title="Agent response format">

通过 [`ProviderStrategy`](/oss/langchain/structured-output) 指定 `response_format`，即可在生成最终响应时启用 Anthropic 的结构化输出功能。

```python
from langchain.agents import create_agent
from langchain.agents.structured_output import ProviderStrategy
from pydantic import BaseModel

class Weather(BaseModel):
    temperature: float
    condition: str

def weather_tool(location: str) -> str:
    """Get the weather at a location."""
    return "Sunny and 75 degrees F."

agent = create_agent(
    model="anthropic:claude-sonnet-4-5",
    tools=[weather_tool],
    response_format=ProviderStrategy(Weather),  # [!code highlight]
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "What's the weather in SF?"}]
})

result["structured_response"]
```

```python
Weather(temperature=75.0, condition='Sunny')
```

</Accordion>

## 内置工具

Anthropic 支持多种内置的客户端和服务端 [tools](/oss/langchain/tools/)。

服务端工具（例如 [web search](#web-search)）会被传给模型，并由 Anthropic 直接执行。客户端工具（例如 [bash tool](#bash-tool)）则需要你在应用中实现回调执行逻辑，并将结果返回给模型。

无论哪种情况，都需要通过在模型实例上使用 @[`bind_tools`][ChatAnthropic.bind_tools] 让聊天模型获得这些工具。

特别需要注意的是，客户端工具要求你自己实现执行逻辑。相关章节里会给出示例。

<Info>
    **Middleware 与 tools**

    对于客户端工具，例如 [bash](#bash-tool)、[text editor](#text-editor)、[memory](#memory-tool)，也可以选择使用 [middleware](/oss/integrations/middleware/anthropic)。它们提供了可用于生产环境的实现，包含内置执行、状态管理和安全策略。

    如果想要开箱即用的方案，用 middleware；如果需要自定义执行逻辑，或想直接使用 @[`bind_tools`][ChatAnthropic.bind_tools]，则使用下方文档中的 tools 方式。
</Info>

<Note>
    **Beta 工具**

    如果将 beta 工具绑定到聊天模型，LangChain 会自动为你加上所需的 beta header。
</Note>

### Bash 工具

Claude 支持一个客户端 [bash tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/bash-tool)，它允许模型在一个持久化 bash session 中执行 shell 命令。这使得系统操作、脚本执行和命令行自动化成为可能。

<Note>
    **重要：你必须自行提供执行环境**

    LangChain 只负责 API 集成，也就是发送和接收工具调用，但 **你需要自己负责**：

    - 搭建沙箱计算环境，例如 Docker、VM 等
    - 实现命令执行和输出捕获
    - 在 agent loop 中将结果回传给 Claude

    实现指导请参见 [Claude bash tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/bash-tool)。
</Note>

<Info>
    **Requirements:**

    - Claude 4 models or Claude Sonnet 3.7
</Info>

<Tabs>
    <Tab title="Anthropic type">
        ```python expandable
        import subprocess

        from anthropic.types.beta import BetaToolBash20250124Param  # [!code highlight]
        from langchain_anthropic import ChatAnthropic
        from langchain.messages import HumanMessage, ToolMessage
        from langchain.tools import tool

        tool_spec = BetaToolBash20250124Param(  # [!code highlight]
            name="bash",  # [!code highlight]
            type="bash_20250124",  # [!code highlight]
        )  # [!code highlight]


        @tool(extras={"provider_tool_definition": tool_spec})  # [!code highlight]
        def bash(*, command: str, restart: bool = False, **kw):
            """Execute a bash command."""
            if restart:
                return "Bash session restarted"
            try:
                result = subprocess.run(
                    command,
                    shell=True,
                    capture_output=True,
                    text=True,
                    timeout=30,
                )
                return result.stdout + result.stderr
            except Exception as e:
                return f"Error: {e}"

        model = ChatAnthropic(model="claude-sonnet-4-6")
        model_with_bash = model.bind_tools([bash]) # [!code highlight]

        # Initial request
        messages = [HumanMessage("List all files in the current directory")]
        response = model_with_bash.invoke(messages)
        print(response.content_blocks)

        # Tool execution loop
        while response.tool_calls:
            # Execute each tool call
            tool_messages = []
            for tool_call in response.tool_calls:
                result = bash.invoke(tool_call)
                tool_messages.append(result)

            # Continue conversation with tool results
            messages = [*messages, response, *tool_messages]
            response = model_with_bash.invoke(messages)
            print(response.content_blocks)
        ```

### 工具搜索

Claude 支持服务端 [tool search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool)，可以动态发现并加载工具。你不需要一次把所有工具定义都塞进上下文窗口，Claude 可以先搜索工具目录，再只加载它真正需要的工具。

这在以下场景中很有用：

- 系统中有 10 个以上工具
- 工具定义占用了大量 token
- 大量工具导致工具选择准确率下降

Tool search 有两种变体：

- **Regex**（`tool_search_tool_regex_20251119`）：Claude 通过构造正则模式来搜索工具
- **BM25**（`tool_search_tool_bm25_20251119`）：Claude 使用自然语言查询来搜索工具

可以通过 `extras` 参数为 LangChain 工具指定 `defer_loading`：

<Tabs>
    <Tab title="Anthropic type">
        ```python expandable
        from anthropic.types.beta import BetaToolSearchToolRegex20251119Param # [!code highlight]
        from langchain_anthropic import ChatAnthropic
        from langchain.tools import tool

        @tool(extras={"defer_loading": True}) # [!code highlight]
        def get_weather(location: str, unit: str = "fahrenheit") -> str:
            """Get the current weather for a location.

            Args:
                location: City name
                unit: Temperature unit (celsius or fahrenheit)
            """
            return f"Weather in {location}: Sunny"

        @tool(extras={"defer_loading": True}) # [!code highlight]
        def search_files(query: str) -> str:
            """Search through files in the workspace.

            Args:
                query: Search query
            """
            return f"Found files matching '{query}'"

        model = ChatAnthropic(model="claude-sonnet-4-6")

        tool_search = BetaToolSearchToolRegex20251119Param( # [!code highlight]
            name="tool_search_tool_regex", # [!code highlight]
            type="tool_search_tool_regex_20251119", # [!code highlight]
        ) # [!code highlight]

        model_with_tools = model.bind_tools([
            tool_search, # [!code highlight]
            get_weather,
            search_files,
        ])
        response = model_with_tools.invoke("What's the weather in San Francisco?")
        ```
    </Tab>

    <Tab title="create_agent">
        ```python expandable

            name="tool_search_tool_regex", # [!code highlight]

        ) # [!code highlight]

                unit: Temperature unit (celsius or fahrenheit)
        ```

**关键点：**

- 带有 `defer_loading: True` 的工具只有在 Claude 通过搜索发现它们时才会真正加载
- 将你最常用的 3 到 5 个工具保持为非延迟加载，可以获得更好的性能
- 两种变体都会搜索工具名称、描述、参数名和参数描述

关于 tool search 的更多细节，包括如何与 MCP server 和客户端实现结合使用，请参见 [Claude documentation](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool)。
