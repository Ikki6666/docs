[聊天模型](/oss/langchain/models)是以一系列 [messages](/oss/langchain/messages) 作为输入，并返回消息作为输出的语言模型 <Tooltip tip="较早的模型不遵循聊天模型接口，而是使用接收字符串输入并返回字符串输出的接口。这些模型通常不会在名称前包含 'Chat'，也不会以 'LLM' 作为后缀。">（相对于传统的纯文本 LLM）</Tooltip>。

## 路由器与代理

路由器与代理让你能够通过单一 API 和凭证访问多个提供方的模型。它们可以简化计费、让你无需更换集成就能切换模型，并提供自动 fallback 等功能。

| Provider | Integration | Description |
|-|-|-|
| [OpenRouter](https://openrouter.ai/) | [`ChatOpenRouter`](/oss/integrations/chat/openrouter) | 统一访问来自 OpenAI、Anthropic、Google、Meta 等提供方的模型 |
| [LiteLLM](https://www.litellm.ai/) | [`ChatLiteLLMRouter`](/oss/integrations/chat/litellm) | 为 OpenAI、Anthropic、Azure、Hugging Face 等提供统一接口，并支持路由与 fallback |

## Chat Completions API

部分模型提供方提供与 OpenAI [Chat Completions API](https://platform.openai.com/docs/api-reference/chat) 兼容的 endpoint。在这种情况下，你可以为 [`ChatOpenAI`](/oss/integrations/chat/openai) 设置自定义 `base_url`，以连接这些 endpoint，并实现基础聊天功能。

<Warning>
    `ChatOpenAI` 仅面向[官方 OpenAI API 规范](https://github.com/openai/openai-openapi)。第三方提供方返回的非标准响应字段（例如 `reasoning_content`、`reasoning`、`reasoning_details`）**不会被提取或保留**。如果你需要访问这些非标准特性，请使用提供方专用的包。

    例如，OpenRouter 就有专门的 LangChain 集成。设置与使用方式请参见 [`ChatOpenRouter` guide](/oss/integrations/chat/openrouter)。
</Warning>

[Snowflake Cortex REST API](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-rest-api) 与 OpenAI 和 Anthropic API 完全兼容。使用 `ChatOpenAI` 或 `ChatAnthropic` 并配合自定义 `base_url`，即可访问在 Snowflake 安全边界内运行的前沿模型。

[Auxen](https://auxen.ai) 为每个客户托管专用的 LLM endpoint，提供与 OpenAI 兼容的 Chat Completions API。使用 `ChatOpenAI` 配合自定义 `base_url` 和按实例分配的 API key。

[DaoXE](https://daoxe.com) 是一个多模型 API 网关，提供与 OpenAI 兼容的 Chat Completions 接口。使用 `ChatOpenAI`，将 `base_url` 设为 `https://daoxe.com/v1`，并使用账户作用域的模型 ID。

[1Claw](https://docs.1claw.xyz) 通过 Shroud TEE 代理路由 LLM 调用，使用 `ChatOpenAI` 或 `ChatAnthropic` 配合自定义 `base_url`，使提供方的 key 和密钥不会出现在 agent 上下文中。

[Apertis](https://docs.apertis.ai) 提供与 OpenAI 兼容的 Chat Completions API。使用 `ChatOpenAI`，将 `base_url` 设为 `https://api.apertis.ai/v1`，并使用你的账户可用的模型 ID。
