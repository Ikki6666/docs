## 概览

`langchain-nvidia-ai-endpoints` 包包含用于聊天模型和 embedding 模型的 LangChain 集成，这些模型由 [NVIDIA AI Foundation Models](https://www.nvidia.com/en-us/ai-data-science/foundation-models/) 驱动，并托管在 [NVIDIA API Catalog](https://build.nvidia.com/) 上。

一个很强的起点是 [Nemotron](https://www.nvidia.com/en-us/ai-data-science/foundation-models/nemotron/)，这是 NVIDIA 专为 agentic AI 打造的开源模型家族。Nemotron 使用混合 Mamba-Transformer mixture-of-experts 架构，在准确率领先的同时，吞吐量最高可达同类模型的 3 倍，并支持最高 1M token 的 context window。模型权重、训练数据和实现配方都基于 NVIDIA Open Model License 公开发布。

NVIDIA AI Foundation models 运行在 NIM microservices 上：这些容器镜像通过 [NVIDIA NGC Catalog](https://catalog.ngc.nvidia.com/) 分发，暴露标准的 OpenAI-compatible API，并通过 TensorRT-LLM 进行优化，以获得最大吞吐量。你既可以通过托管的 [NVIDIA API Catalog](https://build.nvidia.com/) 访问它们，也可以在具备 NVIDIA AI Enterprise 许可的前提下进行本地部署。

本页介绍如何通过 `ChatNVIDIA` 使用 LangChain 与 NVIDIA 模型交互，包括 Nemotron 以及 API Catalog 中的其他模型。

如需了解如何通过该 API 访问 embedding 模型，请参见 [`NVIDIAEmbeddings`](/oss/integrations/embeddings/nvidia_ai_endpoints) 文档。

## 访问 NVIDIA API Catalog

要访问 NVIDIA API Catalog，请按以下步骤操作：

1. 在 [NVIDIA API Catalog](https://build.nvidia.com/) 创建一个免费账号并登录。
2. 点击你的头像，然后点击 **API Keys**。会出现 **API Keys** 页面。
3. 点击 **Generate API Key**。会出现 **Generate API Key** 窗口。
4. 点击 **Generate Key**。你应该会看到 **API Key Granted**，并显示你的 key。
5. 复制并保存这个 key，命名为 `NVIDIA_API_KEY`。
6. 使用以下代码验证你的 key。

```python
import getpass
import os

if os.environ.get("NVIDIA_API_KEY", "").startswith("nvapi-"):
    print("Valid NVIDIA_API_KEY already in environment. Delete to reset")
else:
    nvapi_key = getpass.getpass("NVAPI Key (starts with nvapi-): ")
    assert nvapi_key.startswith(
        "nvapi-"
    ), f"{nvapi_key[:5]}... is not a valid key"
    os.environ["NVIDIA_API_KEY"] = nvapi_key
```

现在你就可以使用该 key 访问 NVIDIA API Catalog 中的 endpoint。

要启用模型调用的自动 tracing，请设置 [LangSmith](/langsmith/observability) API key：

```python
os.environ["LANGSMITH_TRACING"] = "true"
os.environ["LANGSMITH_API_KEY"] = getpass.getpass("Enter your LangSmith API key: ")
```

## 实例化

现在可以访问 NVIDIA API Catalog 中的模型。[Nemotron](https://www.nvidia.com/en-us/ai-data-science/foundation-models/nemotron/) 是 agentic 和 reasoning 工作负载的推荐起点：

```python
from langchain_nvidia_ai_endpoints import ChatNVIDIA

# Nemotron 3 Ultra - frontier reasoning and agentic workflows
llm = ChatNVIDIA(model="nvidia/nemotron-3-ultra-550b-a55b")
```

你也可以通过传入 model ID 来使用 API Catalog 中的任意其他模型：

```python
llm = ChatNVIDIA(model="mistralai/mixtral-8x7b-instruct-v0.1")
```

## 调用

```python
result = llm.invoke("Write a ballad about LangChain.")
print(result.content)
```

## 启用 thinking mode

某些 NVIDIA reasoning 模型支持可配置的 thinking mode。你可以通过在 `invoke` 时传入 `thinking_mode=True`，为单次请求启用 thinking：

```python
from langchain_nvidia_ai_endpoints import ChatNVIDIA

model = ChatNVIDIA(model="nvidia/nemotron-3-nano-30b-a3b")

response = model.invoke("Solve this step by step: 17 * 23", thinking_mode=True)
print(response.content_blocks)
```

如果你希望复用一个默认启用 thinking 的 runnable，可以使用 `with_thinking_mode`：

```python
thinking_model = model.with_thinking_mode(enabled=True)
response = thinking_model.invoke("Solve this step by step: 17 * 23")
```

如果你想列出已知支持 thinking mode 的模型，可以调用 `get_available_models`，并检查 `supports_thinking`。它会查询 NVIDIA 的模型列表 API，然后过滤返回的模型元数据：

```python
thinking_models = [
    model for model in ChatNVIDIA.get_available_models() if model.supports_thinking
]
```

`ChatNVIDIA` 会把 `thinking_mode=True` 转换成所选模型需要的控制方式。有些模型使用请求参数，例如 `chat_template_kwargs={"enable_thinking": True}`。另一些模型则使用基于 prompt 的控制方式，也就是让 LangChain 在 system message 后追加模型专用的 thinking 前缀，或者在没有 system message 时自动创建一个。如果某个模型同时配置了这两种机制，则请求参数优先。

不要在构造 `ChatNVIDIA` 时传入 `thinking_mode=True`。未知的构造参数会变成原始 `model_kwargs`，并被直接合并进 API payload。thinking-mode 的转换逻辑只会在 invocation kwargs 或 bound kwargs 上生效，因此请使用下面这些形式：

```python
response = model.invoke("Solve this step by step: 17 * 23", thinking_mode=True)
```

```python
thinking_model = model.with_thinking_mode(enabled=True)
response = thinking_model.invoke("Solve this step by step: 17 * 23")
```

## 使用 NVIDIA NIM Microservices 自托管

当你准备部署 AI 应用时，可以通过 NVIDIA NIM 自托管模型。更多信息请参见 [NVIDIA NIM Microservices](https://www.nvidia.com/en-us/ai-data-science/products/nim-microservices/)。

下面的代码展示了如何连接本地托管的 NIM Microservices。

```python
from langchain_nvidia_ai_endpoints import ChatNVIDIA, NVIDIAEmbeddings, NVIDIARerank

# Connect to a chat NIM running at localhost:8000, specifying a model
llm = ChatNVIDIA(base_url="http://localhost:8000/v1", model="nvidia/nemotron-3-ultra-550b-a55b")

# Connect to an embedding NIM running at localhost:8080
embedder = NVIDIAEmbeddings(base_url="http://localhost:8080/v1")

# Connect to a reranking NIM running at localhost:2016
ranker = NVIDIARerank(base_url="http://localhost:2016/v1")
```

## 流式、批量与异步

这些模型原生支持流式输出。并且与所有 LangChain LLM 一样，它们提供 batch 方法来处理并发请求，也提供 invoke、stream 和 batch 的异步版本。下面是一些示例。

```python
print(llm.batch(["What's 2*3?", "What's 2*6?"]))
# Or via the async API
# await llm.abatch(["What's 2*3?", "What's 2*6?"])
```

```python
stream = llm.stream_events("How far can a seagull fly in one day?", version="v3")
for token in stream.text:
    # Show the token separations
    print(token, end="|")
```

```python
stream = await llm.astream_events(
    "How long does it take for monarch butterflies to migrate?", version="v3"
)
async for token in stream.text:
    print(token, end="|")
```

## 模型类型

以上这些模型都受到支持，并且都可以通过 `ChatNVIDIA` 访问。

某些模型类型支持独特的提示技术和聊天消息格式。下面我们会介绍几个重要类别。

**如需了解某个具体模型的更多信息，请前往它在 AI Foundation model [列表中的 API 页面](https://catalog.ngc.nvidia.com/orgs/nvidia/teams/ai-foundation/models/codellama-13b/api)。**

### 用于 agentic AI 的 Nemotron 模型

[Nemotron](https://www.nvidia.com/en-us/ai-data-science/foundation-models/nemotron/) 是 NVIDIA 专为 agentic workflow 打造的开源模型家族。关键特点包括：

- **高效率**：混合 Mamba-Transformer MoE 架构，吞吐量最高可达同类 dense 模型的 3 倍
- **长上下文**：原生支持最高 1M token 的 context window
- **Agentic reasoning**：专门训练用于多步规划、工具使用和自主软件工程任务
- **开源**：权重、训练配方和精选数据集均基于 NVIDIA Open Model License 发布


```python
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_nvidia_ai_endpoints import ChatNVIDIA

prompt = ChatPromptTemplate.from_messages(
    [
        ("system", "You are a helpful research assistant. Think step by step."),
        ("user", "{input}"),
    ]
)
chain = prompt | ChatNVIDIA(model="nvidia/nemotron-3-ultra-550b-a55b") | StrOutputParser()

for txt in chain.stream({"input": "What are the key considerations when designing a multi-agent RAG system?"}):
    print(txt, end="")
```

### 通用聊天

像 `meta/llama3-8b-instruct` 和 `mistralai/mixtral-8x22b-instruct-v0.1` 这样的模型，是适合各类 LangChain chat messages 的通用模型。下面是一个示例。

```python
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_nvidia_ai_endpoints import ChatNVIDIA

prompt = ChatPromptTemplate.from_messages(
    [("system", "You are a helpful AI assistant named Fred."), ("user", "{input}")]
)
chain = prompt | ChatNVIDIA(model="nvidia/nemotron-3-ultra-550b-a55b") | StrOutputParser()

for txt in chain.stream({"input": "What's your name?"}):
    print(txt, end="")
```

### 代码生成

这些模型接受与普通聊天模型相同的参数和输入结构，但在代码生成与结构化代码任务上通常表现更好。`meta/codellama-70b` 就是一个例子。

```python
prompt = ChatPromptTemplate.from_messages(

        (
```

NVIDIA 也支持多模态输入，这意味着你可以同时提供图片和文本，让模型进行联合推理。支持多模态输入的一个示例模型是 `nvidia/neva-22b`。

下面是一个使用示例：

```python
import IPython
import requests

image_url = "https://www.nvidia.com/content/dam/en-zz/Solutions/research/ai-playground/nvidia-picasso-3c33-p@2x.jpg"  ## Large Image
image_content = requests.get(image_url).content

IPython.display.Image(image_content)
```

```python
from langchain_nvidia_ai_endpoints import ChatNVIDIA

llm = ChatNVIDIA(model="nvidia/neva-22b")
```

#### 通过 URL 传入图片

```python
from langchain.messages import HumanMessage

llm.invoke(
    [
        HumanMessage(
            content=[
                {"type": "text", "text": "Describe this image:"},
                {"type": "image_url", "image_url": {"url": image_url}},
            ]
        )
    ]
)
```

#### 通过 base64 编码字符串传入图片

当前，为了支持像上面那样较大的图片，客户端还会进行一些额外处理。但对于较小图片（同时也更便于展示底层过程），我们可以像下面这样直接传入：

```python
import IPython
import requests

image_url = "https://picsum.photos/seed/kitten/300/200"
image_content = requests.get(image_url).content

IPython.display.Image(image_content)
```

```python
import base64

from langchain.messages import HumanMessage

## Works for simpler images. For larger images, see actual implementation
b64_string = base64.b64encode(image_content).decode("utf-8")

llm.invoke(
    [
        HumanMessage(
            content=[
                {"type": "text", "text": "Describe this image:"},
                {
                    "type": "image_url",
                    "image_url": {"url": f"data:image/png;base64,{b64_string}"},
                },
            ]
        )
    ]
)
```

#### 直接写在字符串中

NVIDIA API 还独特地支持将 base64 图片以内联 `<img/>` HTML 标签的方式传入。虽然这种方式与其他 LLM 不具备互操作性，但你可以直接按这种方式向模型发出提示。

```python
base64_with_mime_type = f"data:image/png;base64,{b64_string}"
llm.invoke(f'What\'s in this image?\n<img src="{base64_with_mime_type}" />')
```

## 在 `RunnableWithMessageHistory` 中的示例用法

和其他集成一样，`ChatNVIDIA` 完全可以配合 `RunnableWithMessageHistory` 这类聊天工具使用，它相当于 `ConversationChain` 的替代方案。下面展示的是 [LangChain `RunnableWithMessageHistory`](https://reference.langchain.com/python/langchain-core/runnables/history/RunnableWithMessageHistory) 示例，应用于 `mistralai/mixtral-8x22b-instruct-v0.1` 模型。

```python
pip install -qU langchain
```

```python
from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

# store is a dictionary that maps session IDs to their corresponding chat histories.
store = {}  # memory is maintained outside the chain


# A function that returns the chat history for a given session ID.
def get_session_history(session_id: str) -> InMemoryChatMessageHistory:
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]


chat = ChatNVIDIA(
    model="nvidia/nemotron-3-ultra-550b-a55b",
    temperature=0.1,
    max_tokens=100,
    top_p=1.0,
)

#  Define a RunnableConfig object, with a `configurable` key. session_id determines thread
config = {"configurable": {"session_id": "1"}}

conversation = RunnableWithMessageHistory(
    chat,
    get_session_history,
)

conversation.invoke(
    "Hi I'm Srijan Dubey.",  # input or query
    config=config,
)
```

```python
conversation.invoke(
    "I'm doing well! Just having a conversation with an AI.",
    config=config,
)
```

```python
conversation.invoke(
    "Tell me about yourself.",
    config=config,
)
```

## Tool calling

从 v0.2 开始，`ChatNVIDIA` 支持 [`bind_tools`](https://reference.langchain.com/python/langchain-nvidia-ai-endpoints/chat_models/ChatNVIDIA#member-bind_tools-2)。

`ChatNVIDIA` 集成了 [build.nvidia.com](https://build.nvidia.com) 上的多种模型，也支持本地 NIM。并非所有这些模型都针对 tool calling 进行过训练。请确保为你的实验和应用选择确实支持 tool calling 的模型。

你可以通过下面的方式列出已知支持 tool calling 的模型：

```python
tool_models = [
    model for model in ChatNVIDIA.get_available_models() if model.supports_tools
]
tool_models
```

对于支持工具的模型：

```python
from langchain.tools import tool
from pydantic import Field


@tool
def get_current_weather(
    location: str = Field(description="The location to get the weather for."),
):
    """Get the current weather for a location."""
    ...


llm = ChatNVIDIA(model=tool_models[0].id).bind_tools(tools=[get_current_weather])
response = llm.invoke("What is the weather in Boston?")
response.tool_calls
```

更多示例请参见 [How to use chat models to call tools](/oss/langchain/tools)。

## 与 NVIDIA Dynamo 一起使用

[NVIDIA Dynamo](https://developer.nvidia.com/dynamo) 是一个分布式推理服务框架，用于在数据中心规模的多节点环境中部署模型。它通过将推理的不同阶段拆分到不同 GPU 上、智能地将请求路由到合适的 GPU 以避免重复计算，并通过将数据缓存扩展到成本更低的存储层，从而简化并自动化分布式服务的复杂性。

`ChatNVIDIADynamo` 是 `ChatNVIDIA` 的直接替代，它会自动在每次请求中注入 `nvext.agent_hints`。这些 hints 会告诉 Dynamo 部署：

- **`osl`** (output sequence length)：预期输出多少 token，以便调度器规划内存分配
- **`iat`** (inter-arrival time)：请求到达速度，以便路由器预判负载
- **`latency_sensitivity`**：请求对延迟的敏感度，便于交互式调用获得更高优先级路由
- **`priority`**：请求优先级，让后台工作可以给关键路径请求让路

每个请求都会自动生成唯一的 `prefix_id`，使路由器能够跟踪 KV cache affinity。

<Note>
This section assumes you have a running [NVIDIA Dynamo deployment](https://docs.nvidia.com/dynamo/latest/getting-started/quickstart).
</Note>

### 基本用法

将 `ChatNVIDIA` 替换为 `ChatNVIDIADynamo` 后，每次请求都会自动携带路由 hints。所有标准的 `ChatNVIDIA` 参数都仍然支持。

```python
from langchain_nvidia_ai_endpoints import ChatNVIDIA, ChatNVIDIADynamo

BASE_URL = "http://localhost:8099/v1"
MODEL = "your-model-name"

# Standard ChatNVIDIA — no Dynamo hints
llm_standard = ChatNVIDIA(base_url=BASE_URL, model=MODEL)

# ChatNVIDIADynamo — identical interface, automatically injects agent_hints
llm = ChatNVIDIADynamo(base_url=BASE_URL, model=MODEL)

result = llm.invoke("What is KV cache optimization?")
print(result.content)
```

`ChatNVIDIADynamo` 相比 `ChatNVIDIA` 多接受四个参数：

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `osl` | `int` | `512` | Expected output sequence length (tokens) |
| `iat` | `int` | `250` | Expected inter-arrival time (ms) |
| `latency_sensitivity` | `float` | `1.0` | Higher latency sensitivities get priority routing |
| `priority` | `int` | `1` | Lower priority settings receive more scheduling priority |

### 在构造时设置默认值

在创建模型实例时配置 Dynamo hints。当某个模型实例总是承担特定角色时，这种方式很有用，例如高优先级交互式助手，或者低优先级后台摘要器。

```python
# High-priority: short responses, latency-critical
llm_critical = ChatNVIDIADynamo(
    base_url=BASE_URL,
    model=MODEL,
    osl=20,
    priority=0,
    latency_sensitivity=10.0,
)

# Low-priority: long responses, latency-tolerant
llm_background = ChatNVIDIADynamo(
    base_url=BASE_URL,
    model=MODEL,
    osl=512,
    priority=10,
    latency_sensitivity=0,
)
```

### 每次调用时覆盖

Dynamo 参数也可以在每次调用时覆盖。当同一个模型实例要处理不同特征的请求时，这种方式很有用。

```python
result = llm.invoke(
    "Classify this as positive or negative: 'I love this product!'",
    osl=10,
    iat=100,
    latency_sensitivity=1.0,
    priority=10,
)
print(result.content)
```

### 携带 Dynamo hints 的流式输出

Dynamo hints 会包含在初始流式请求中。Dynamo 会在 token 开始流出之前，利用这些信息选择最优 worker。

```python
stream = llm_critical.stream_events("Give a one-sentence summary of GPU computing.", version="v3")
for token in stream.text:
    print(token, end="", flush=True)
```

### 检查 payload

为了调试，你可以通过内部 `_get_payload` 方法检查 `ChatNVIDIADynamo` 发送给 NIM endpoint 的精确 payload。

```python
import json

payload = llm_critical._get_payload(
    inputs=[{"role": "user", "content": "Hello!"}],
    stop=None,
)
print(json.dumps(payload["nvext"], indent=2))
```

这会输出 `nvext.agent_hints` 部分：

```json
{
  "agent_hints": {
    "prefix_id": "langchain-dynamo-a1b2c3d4e5f6",
    "osl": 20,
    "iat": 250,
    "latency_sensitivity": 1.0,
    "priority": 10
  }
}
```
