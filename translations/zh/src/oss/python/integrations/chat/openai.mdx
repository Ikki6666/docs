## 设置

要访问 OpenAI 模型，你需要安装 `langchain-openai` 集成包，并获取一个 [OpenAI Platform](https://platform.openai.com) API key。

### 安装

<CodeGroup>
    ```bash pip
    pip install -U langchain-openai
    ```
    ```bash uv
    uv add langchain-openai
    ```
</CodeGroup>

### 凭证

前往 [OpenAI Platform](https://platform.openai.com/docs/api-reference/authentication) 注册并生成 API key。完成后，请在环境中设置 `OPENAI_API_KEY` 环境变量：

```python
import getpass
import os

if not os.environ.get("OPENAI_API_KEY"):
    os.environ["OPENAI_API_KEY"] = getpass.getpass("Enter your OpenAI API key: ")
```

如果你通过代理或服务模拟器转发请求，也可以通过环境变量设置 base URL，而不是显式传 `base_url`。解析顺序如下（先匹配先使用）：

1. 显式的 `base_url`（或 `openai_api_base`）kwarg
2. `OPENAI_API_BASE`，由 LangChain 在初始化时读取
3. `OPENAI_BASE_URL`，由底层 `openai` SDK client 读取。LangChain 也会检查这个值，以决定是否默认启用 `stream_usage`；如果设置了该变量，默认不会启用，因为很多非 OpenAI endpoint 不支持流式 token usage。

如果你希望为模型调用启用自动 tracing，也可以设置 [LangSmith](/langsmith/observability) API key：

```python
os.environ["LANGSMITH_API_KEY"] = getpass.getpass("Enter your LangSmith API key: ")
os.environ["LANGSMITH_TRACING"] = "true"
```

## 实例化

现在可以实例化模型对象并生成响应：

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="gpt-5-nano",
    # stream_usage=True,
    # temperature=None,
    # max_tokens=None,
    # timeout=None,
    # reasoning_effort="low",
    # max_retries=2,
    # api_key="...",  # If you prefer to pass api key in directly
    # base_url="...",
    # organization="...",
    # other params...
)
```

完整可用参数请参见 @[`ChatOpenAI`] API Reference。

<Note>
    **Token 参数弃用**

    OpenAI 在 2024 年 9 月弃用了 `max_tokens`，改为使用 `max_completion_tokens`。尽管 `max_tokens` 为了向后兼容仍然受支持，但在内部会自动转换为 `max_completion_tokens`。
</Note>

## 流式 usage 元数据

OpenAI 的 Chat Completions API 默认不会流式返回 token usage 统计信息（参见 [OpenAI API reference for stream options](https://platform.openai.com/docs/api-reference/completions/create#completions-create-stream_options)）。

如果你希望在使用 @[`ChatOpenAI`] 或 `AzureChatOpenAI` 流式输出时恢复 token 计数，请在初始化参数或调用时设置 `stream_usage=True`：

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-5.4-mini", stream_usage=True)  # [!code highlight]
```

## 与 Azure OpenAI 一起使用

<Info>
    **Azure OpenAI v1 API 支持**

    从 `langchain-openai>=1.0.1` 开始，`ChatOpenAI` 可以直接与 Azure OpenAI endpoint 上的新 [v1 API](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/api-version-lifecycle?tabs=python#next-generation-api-1) 配合使用。这提供了一种统一方式来使用托管在 OpenAI 或 Azure 上的 OpenAI 模型。

    如果你想使用传统的 Azure 专用实现，仍然请使用 [`AzureChatOpenAI`](/oss/integrations/chat/azure_chat_openai/)。
</Info>

<Accordion title="Using Azure OpenAI v1 API with API Key">

如果要将 `ChatOpenAI` 用于 Azure OpenAI，请将 `base_url` 设置为你的 Azure endpoint，并在末尾追加 `/openai/v1/`：

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="gpt-5-mini",  # Your Azure deployment name
    base_url="https://{your-resource-name}.openai.azure.com/openai/v1/",
    api_key="your-azure-api-key"
)

response = llm.invoke("Hello, how are you?")
print(response.content)
```
</Accordion>

<Accordion title="Using Azure OpenAI with Microsoft Entra ID">

v1 API 原生支持 [Microsoft Entra ID](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/how-to/managed-identity)（原 Azure AD）认证，并带有自动 token 刷新。你可以向 `api_key` 参数传入一个 token provider callable：

```python
from azure.identity import DefaultAzureCredential, get_bearer_token_provider
from langchain_openai import ChatOpenAI

# Create a token provider that handles automatic refresh
token_provider = get_bearer_token_provider(
    DefaultAzureCredential(),
    "https://cognitiveservices.azure.com/.default"
)

llm = ChatOpenAI(
    model="gpt-5-mini",  # Your Azure deployment name
    base_url="https://{your-resource-name}.openai.azure.com/openai/v1/",
    api_key=token_provider  # Callable that handles token refresh
)

# Use the model as normal
messages = [
    ("system", "You are a helpful assistant."),
    ("human", "Translate 'I love programming' to French.")
]
response = llm.invoke(messages)
print(response.content)
```

这个 token provider 是一个 callable，会自动获取并刷新认证 token，因此无需手动管理 token 过期问题。

<Tip>
**安装要求**

要使用 Microsoft Entra ID 认证，请安装 Azure Identity 库：

```bash
pip install azure-identity
```

</Tip>

当你使用异步函数时，也可以向 `api_key` 参数传入一个 token provider callable。此时你必须从 `azure.identity.aio` 导入 DefaultAzureCredential：


```python
from azure.identity.aio import DefaultAzureCredential
from langchain_openai import ChatOpenAI

credential = DefaultAzureCredential()

llm_async = ChatOpenAI(
    model="gpt-5-nano",
    api_key=credential
)

# Use async methods when using async callable
response = await llm_async.ainvoke("Hello!")
```

<Note>
当 `api_key` 使用异步 callable 时，你必须使用异步方法（例如 `ainvoke`、`astream` 等）。同步方法会报错。
</Note>

</Accordion>

## Tool calling

OpenAI 提供了 [tool calling](https://platform.openai.com/docs/guides/function-calling)（这里 “tool calling” 和 “function calling” 这两个术语可互换）API，你可以描述工具及其参数，让模型返回一个 JSON 对象，其中包含要调用的工具和该工具的输入。tool calling 对构建可使用工具的 chain 和 agent 非常有用，也普遍适用于获取更结构化的模型输出。

### 绑定工具

借助 `ChatOpenAI.bind_tools`，我们可以轻松地把 Pydantic 类、dict schema、LangChain 工具，甚至普通函数作为工具传给模型。在底层，它们会被转换为 OpenAI tool schema，形式如下：

```
{
    "name": "...",
    "description": "...",
    "parameters": {...}  # JSONSchema
}
```

并在每次模型调用时一同传入。

```python
from pydantic import BaseModel, Field


class GetWeather(BaseModel):
    """Get the current weather in a given location"""

    location: str = Field(description="The city and state, e.g. San Francisco, CA")


llm_with_tools = llm.bind_tools([GetWeather])
```

```python
ai_msg = llm_with_tools.invoke(
    "what is the weather like in San Francisco",
)
ai_msg
```

```text
AIMessage(content='', additional_kwargs={'refusal': None}, response_metadata={'token_usage': {'completion_tokens': 17, 'prompt_tokens': 68, 'total_tokens': 85}, 'model_name': 'gpt-4o-2024-05-13', 'system_fingerprint': 'fp_3aa7262c27', 'finish_reason': 'tool_calls', 'logprobs': None}, id='run-1617c9b2-dda5-4120-996b-0333ed5992e2-0', tool_calls=[{'name': 'GetWeather', 'args': {'location': 'San Francisco, CA'}, 'id': 'call_o9udf3EVOWiV4Iupktpbpofk', 'type': 'tool_call'}], usage_metadata={'input_tokens': 68, 'output_tokens': 17, 'total_tokens': 85})
```

### 严格模式

<Info>
    **Requires `langchain-openai>=0.1.21`**
</Info>

从 2024 年 8 月 6 日起，OpenAI 在工具调用时支持 `strict` 参数，用于强制模型遵守工具参数 schema。[See more](https://platform.openai.com/docs/guides/function-calling)。

<Note>
    如果 `strict=True`，工具定义本身也会被校验，并且只接受一部分 JSON schema。尤其需要注意的是，schema 不能包含可选参数（即带默认值的参数）。

    关于支持哪些 schema 类型，请阅读[完整文档](https://developers.openai.com/api/docs/guides/structured-outputs#supported-schemas)。
</Note>

```python
llm_with_tools = llm.bind_tools([GetWeather], strict=True)
ai_msg = llm_with_tools.invoke(
    "what is the weather like in San Francisco",
)
ai_msg
```

### 自定义工具

<Info>
**Requires `langchain-openai>=0.3.29`**
</Info>

[Custom tools](https://platform.openai.com/docs/guides/function-calling#custom-tools) 支持任意字符串输入的工具。当你预期字符串参数会很长或很复杂时，这会特别有用。

```python
from langchain_openai import ChatOpenAI, custom_tool
from langchain.agents import create_agent


@custom_tool
def execute_code(code: str) -> str:
    """Execute python code."""
    return "27"


llm = ChatOpenAI(model="gpt-5.5", use_responses_api=True)

agent = create_agent(llm, [execute_code])

input_message = {"role": "user", "content": "Use the tool to calculate 3^3."}
stream = agent.stream_events(
    {"messages": [input_message]},
    version="v3",
)
for snapshot in stream.values:
    snapshot["messages"][-1].pretty_print()
```

<Accordion title="Context-free grammars">

OpenAI 支持为自定义工具输入指定 [context-free grammar](https://platform.openai.com/docs/guides/function-calling#context-free-grammars)，支持 `lark` 或 `regex` 格式。详情请参见 [OpenAI docs](https://platform.openai.com/docs/guides/function-calling#context-free-grammars)。如下面所示，可以通过 `@custom_tool` 的 `format` 参数传入：

```python
from langchain_openai import ChatOpenAI, custom_tool
from langchain.agents import create_agent


grammar = """
start: expr
expr: term (SP ADD SP term)* -> add
| term
term: factor (SP MUL SP factor)* -> mul
| factor
factor: INT
SP: " "
ADD: "+"
MUL: "*"
%import common.INT
"""

format_ = {"type": "grammar", "syntax": "lark", "definition": grammar}


@custom_tool(format=format_)  # [!code highlight]
def do_math(input_string: str) -> str:
    """Do a mathematical operation."""
    return "27"


llm = ChatOpenAI(model="gpt-5.5", use_responses_api=True)

agent = create_agent(llm, [do_math])

input_message = {"role": "user", "content": "Use the tool to calculate 3^3."}
stream = agent.stream_events(
    {"messages": [input_message]},
    version="v3",
)
for snapshot in stream.values:
    snapshot["messages"][-1].pretty_print()
```

## 结构化输出

OpenAI 支持原生的 [structured output feature](https://platform.openai.com/docs/guides/structured-outputs)，可以保证响应遵守给定 schema。

你既可以在单次模型调用中使用这个功能，也可以通过指定 LangChain [agent](/oss/langchain/agents) 的 [response format](/oss/langchain/structured-output) 来使用。示例如下。

<Accordion title="Individual model calls">

使用 [`with_structured_output`](/oss/langchain/models#structured-output) 方法生成结构化模型响应。指定 `method="json_schema"` 可启用 OpenAI 原生结构化输出，否则默认使用 function calling。

```python
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

llm = ChatOpenAI(model="gpt-5.5")

class Movie(BaseModel):
    """A movie with details."""
    title: str = Field(description="The title of the movie")
    year: int = Field(description="The year the movie was released")
    director: str = Field(description="The director of the movie")
    rating: float = Field(description="The movie's rating out of 10")

structured_llm = llm.with_structured_output(Movie, method="json_schema")  # [!code highlight]
response = structured_llm.invoke("Provide details about the movie Inception")
response
```

```python
Movie(title='Inception', year=2010, director='Christopher Nolan', rating=8.8)
```

</Accordion>

<Accordion title="Agent response format">

通过 [`ProviderStrategy`](/oss/langchain/structured-output) 指定 `response_format`，即可在生成最终响应时启用 OpenAI 的结构化输出能力。

```python
from langchain.agents import create_agent
from langchain.agents.structured_output import ProviderStrategy
from pydantic import BaseModel

class Weather(BaseModel):
    temperature: float
    condition: str

def weather_tool(location: str) -> str:
    """Get the weather at a location."""
    return "Sunny and 75 degrees F."

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[weather_tool],
    response_format=ProviderStrategy(Weather),  # [!code highlight]
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "What's the weather in SF?"}]
})

result["structured_response"]
```

```python
Weather(temperature=75.0, condition='Sunny')
```

</Accordion>

### 结合工具调用的结构化输出

OpenAI 的 [structured output](https://platform.openai.com/docs/guides/structured-outputs) 功能可以与 tool calling 同时使用。模型会在“生成工具调用”与“生成符合目标 schema 的响应”之间做选择。示例如下：

```python
from langchain_openai import ChatOpenAI
from pydantic import BaseModel


def get_weather(location: str) -> None:
    """Get weather at a location."""
    return "It's sunny."


class OutputSchema(BaseModel):
    """Schema for response."""

    answer: str
    justification: str


llm = ChatOpenAI(model="gpt-5.5")

structured_llm = llm.bind_tools(
    [get_weather],
    response_format=OutputSchema,
    strict=True,
)

# Response contains tool calls:
tool_call_response = structured_llm.invoke("What is the weather in SF?")

# structured_response.additional_kwargs["parsed"] contains parsed output
structured_response = structured_llm.invoke(
    "What weighs more, a pound of feathers or a pound of gold?"
)
```

## Responses API

<Info>
    **Requires `langchain-openai>=0.3.9`**
</Info>

OpenAI 提供 [Responses](https://platform.openai.com/docs/guides/responses-vs-chat-completions) API，它更适合构建 [agentic](/oss/langchain/agents) 应用。它内置了一整套 [built-in tools](https://platform.openai.com/docs/guides/tools?api-mode=responses)，包括网页搜索和文件搜索。它还支持[会话状态管理](https://platform.openai.com/docs/guides/conversation-state?api-mode=responses)，允许你在不显式传入历史消息的情况下继续同一对话线程，同时也支持返回[推理过程](https://platform.openai.com/docs/guides/reasoning?api-mode=responses)的输出。

如果使用了这些能力，@[`ChatOpenAI`] 会自动路由到 Responses API。你也可以在实例化 @[`ChatOpenAI`] 时显式指定 `use_responses_api=True`。

### 网页搜索

要触发网页搜索，请像传入其他工具一样，向模型传入 `{"type": "web_search"}`。

<Tip>
**你也可以把内置工具作为调用参数传入：**

```python
llm.invoke("...", tools=[{"type": "web_search"}])
```

</Tip>

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-5.4-mini")

tool = {"type": "web_search"}
llm_with_tools = llm.bind_tools([tool])
```

### Tool search

<Info>
Requires `langchain-openai>=1.1.11`
</Info>

OpenAI 支持 [tool search](https://developers.openai.com/api/docs/guides/tools-tool-search/) 功能，允许模型在需要时搜索并将工具加载到上下文中。OpenAI 会把检索到的工具定义注入到当前上下文末尾，以保留其 [cache](#prompt-caching)。

要启用 tool search，请使用 `@tool(extras={"defer_loading": True})` 标记工具，并把 OpenAI 的 search tool 加入可用工具列表。示例如下。

<Accordion title="Server-side tool search">

OpenAI 可以在一次响应中同时完成工具搜索，并返回已加载工具（如果合适，还会直接伴随一个工具调用）：
```python
@tool(extras={"defer_loading": True})  # [!code highlight]
def get_weather(location: str) -> str:
    """Get the current weather for a location."""
    return f"The weather in {location} is sunny and 72°F"

@tool(extras={"defer_loading": True})  # [!code highlight]
def get_recipe(query: str) -> None:
    """Get a recipe for chicken soup."""

model = ChatOpenAI(model="gpt-5.5", use_responses_api=True)

agent = create_agent(
    model=model,
    tools=[
        get_weather,
        get_recipe,
        {"type": "tool_search"}  # [!code highlight]
    ],
)
input_message = {"role": "user", "content": "What's the weather in San Francisco?"}
result = agent.invoke({"messages": [input_message]})

for message in result["messages"]:
    message.pretty_print()
```
``` Result expandable
...
```
</Accordion>

<Accordion title="Client-executed tool search">
如果你想完全掌控底层 tool search 流程，可以在 search tool 定义中指定 `"execution": "client"`。如果模型决定搜索工具，它会在响应中包含一个 `tool_search_call` block。此时你可以再提供一个 `tool_search_output` block，把工具定义传回给模型。

下面的示例演示如何使用 [custom middleware](/oss/langchain/middleware/custom) 来编排这一过程。示例中实现了一个负责搜索工具的 callable，并在 middleware 中加入：
1. 一个 `after_model` hook，用于检查 `tool_search_call` block 并调用该 callable
2. 一个 `wrap_tool_call` hook，用于[运行时工具注册](/oss/langchain/tools#dynamic-tool-selection)

```python
@tool
def get_weather(location: str) -> str:
    """Get the current weather for a location."""
    return f"The weather in {location} is sunny and 72°F"

# Implement a callable that returns a tool definition
def search_tools(goal: str) -> list[dict]:
    """Search for available tools to help answer the question."""
    # Arbitrary logic here
    return [
        {
            "type": "function",
            "defer_loading": True,
            **convert_to_openai_tool(get_weather)["function"],
        }
    ]

tool_search_schema = convert_to_openai_tool(search_tools, strict=True)
tool_search_config: dict = {
    "type": "tool_search",
    "execution": "client",
    "description": tool_search_schema["function"]["description"],
    "parameters": tool_search_schema["function"]["parameters"],
}

# Implement middleware to invoke the callable and register the tool.
class ClientToolSearchMiddleware(AgentMiddleware):
    ...
```
</Accordion>

### Computer use

@[`ChatOpenAI`] 支持 `"computer-use-preview"` 模型，这是一个专门面向内置 computer use 工具的模型。要启用，请像传入其他工具一样，传入一个 [computer use tool](https://platform.openai.com/docs/guides/tools-computer-use)。

当前，computer use 工具的输出存在于消息的 `content` 字段中。若要回复 computer use 工具调用，需要构造一个 @[`ToolMessage`]，并在其 `additional_kwargs` 中加入 `{"type": "computer_call_output"}`。该消息的内容是一个截图。下面给出一个简单示例。

首先，加载两张截图：

```python
import base64


def load_png_as_base64(file_path):
    with open(file_path, "rb") as image_file:
        encoded_string = base64.b64encode(image_file.read())
        return encoded_string.decode("utf-8")


screenshot_1_base64 = load_png_as_base64(
    "/path/to/screenshot_1.png"
)
screenshot_2_base64 = load_png_as_base64(
    "/path/to/screenshot_2.png"
)
```

```python
from langchain_openai import ChatOpenAI

# Initialize model
llm = ChatOpenAI(model="computer-use-preview", truncation="auto")

# Bind computer-use tool
tool = {
    "type": "computer_use_preview",
    "display_width": 1024,
    "display_height": 768,
    "environment": "browser",
}
llm_with_tools = llm.bind_tools([tool])

# Construct input message
input_message = {
    "role": "user",
    "content": [
        {
            "type": "text",
            "text": (
                "Click the red X to close and reveal my Desktop. "
                "Proceed, no confirmation needed."
            ),
        },
        {
            "type": "input_image",
            "image_url": f"data:image/png;base64,{screenshot_1_base64}",
        },
    ],
}

# Invoke model
response = llm_with_tools.invoke(
    [input_message],
    reasoning={
        "generate_summary": "concise",
    },
)
```

响应会在其 `content` 中包含一次 computer-use 工具调用：

```python
response.content
```

```text
[{'id': 'rs_685da051742c81a1bb35ce46a9f3f53406b50b8696b0f590',
  'summary': [{'text': "Clicking red 'X' to show desktop",
    'type': 'summary_text'}],
  'type': 'reasoning'},
 {'id': 'cu_685da054302481a1b2cc43b56e0b381706b50b8696b0f590',
  'action': {'button': 'left', 'type': 'click', 'x': 14, 'y': 38},
  'call_id': 'call_zmQerFBh4PbBE8mQoQHkfkwy',
  'pending_safety_checks': [],
  'status': 'completed',

```

接下来我们构造一个 @[`ToolMessage`]，要求如下：

1. `tool_call_id` 必须与 computer-call 中的 `call_id` 匹配
2. `additional_kwargs` 中必须有 `{"type": "computer_call_output"}`
3. `content` 必须是一个 `image_url` 或 `input_image` 输出块（格式详见 [OpenAI docs](https://platform.openai.com/docs/guides/tools-computer-use#5-repeat)）

```python
from langchain.messages import ToolMessage

tool_call_id = next(
    item["call_id"] for item in response.content if item["type"] == "computer_call"
)

tool_message = ToolMessage(
    content=[
        {
            "type": "input_image",
            "image_url": f"data:image/png;base64,{screenshot_2_base64}",
        }
    ],
    tool_call_id=tool_call_id,
    additional_kwargs={"type": "computer_call_output"},
)
```

然后可以带着消息历史再次调用模型：

```python
messages = [
    input_message,
    response,
    tool_message,
]

response_2 = llm_with_tools.invoke(
    messages,
    reasoning={
        "generate_summary": "concise",
    },
)
```

```python
response_2.text
```

```text
'VS Code has been closed, and the desktop is now visible.'
```

除了传入完整消息序列，我们也可以用 [`previous_response_id`](#passing-previous_response_id)：

```python
previous_response_id = response.response_metadata["id"]

response_2 = llm_with_tools.invoke(
    [tool_message],
    previous_response_id=previous_response_id,
    reasoning={
        "generate_summary": "concise",
    },
)
```

### Apply patch

<Info>
    Requires `langchain-openai>=1.3.0`
</Info>

OpenAI 实现了一个 [apply patch](https://developers.openai.com/api/docs/guides/tools-apply-patch) 工具，让模型能够通过 unified diff 来创建、更新或删除文件。这个工具是客户端执行的：模型提出文件操作，你的应用在本地执行它，并把结果返回给模型，使其可以继续。

要启用它，请像传入其他工具一样传入 `{"type": "apply_patch"}`。不需要定义输入 schema，模型本身知道如何构造 `operation` 对象。

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-5.5")

llm_with_tools = llm.bind_tools([{"type": "apply_patch"}])

response = llm_with_tools.invoke(
    "Create a new file named hello.txt containing the line: hello world"
)
```

模型会返回一个或多个 `apply_patch_call` content block，每个 block 描述一个单独文件操作（`create_file`、`update_file` 或 `delete_file`）：

```python
apply_patch_calls = [
    block
    for block in response.content_blocks
    if block["type"] == "apply_patch_call"
]
```

应用这些操作后，再以同一 `call_id` 返回一个 `apply_patch_call_output` block。成功时把 `status` 设为 `"completed"`；失败时设为 `"failed"` 并附带描述性 `output`，这样模型可以调整并重试。

### 管理会话状态

Responses API 支持[会话状态管理](https://platform.openai.com/docs/guides/conversation-state?api-mode=responses)。

#### 手动管理状态

你可以像其他聊天模型一样，手动管理状态，或者使用 [LangGraph](/oss/langgraph/quickstart) 管理：

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-5.4-mini", use_responses_api=True)

first_query = "Hi, I'm Bob."
messages = [{"role": "user", "content": first_query}]

response = llm.invoke(messages)
print(response.text)
```

#### 传入 `previous_response_id`

当使用 Responses API 时，LangChain 消息会在元数据中包含一个 `"id"` 字段。把该 ID 传入后续调用即可继续同一对话。请注意，从计费角度看，这与手动传入历史消息是[等价的](https://platform.openai.com/docs/guides/conversation-state?api-mode=responses#openai-apis-for-conversation-state)。

```python
second_response = llm.invoke(
    "What is my name?",
    previous_response_id=response.id,
)
print(second_response.text)
```

如果设置 `use_previous_response_id=True`，`ChatOpenAI` 也可以自动使用消息序列中的最后一个响应来填充 `previous_response_id`。

#### 上下文管理

Responses API 支持自动的[服务端上下文压缩](https://developers.openai.com/api/docs/guides/compaction)。当会话达到 token 阈值时，它可以自动缩小上下文，从而更好地支持长时间运行的交互。

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model="gpt-5.5",
    context_management=[
        {"type": "compaction", "compact_threshold": 100_000}
    ],
)
```

启用后，`AIMessage` 响应中可能会出现 `"type": "compaction"` 的内容块。它们应当保留在对话历史中，并按[通常方式](/oss/langchain/short-term-memory)追加到消息序列中。

### 推理输出

某些 OpenAI 模型会单独生成文本内容，用于展示其推理过程。详情请参见 OpenAI 的 [reasoning documentation](https://platform.openai.com/docs/guides/reasoning?api-mode=responses)。

OpenAI 可以返回模型推理过程的摘要（但不会暴露原始推理 token）。要让 @[`ChatOpenAI`] 返回该摘要，请指定 `reasoning` 参数。设置后，@[`ChatOpenAI`] 会自动路由到 Responses API。

```python
from langchain_openai import ChatOpenAI

reasoning = {
    "effort": "medium",
    "summary": "auto",
}

llm = ChatOpenAI(model="gpt-5-nano", reasoning=reasoning)
response = llm.invoke("What is 3^3?")
```

<Tip>
    **故障排查：推理模型返回空响应**

    如果像 `gpt-5-nano` 这样的推理模型返回了空响应，通常是因为 token 限制过于严格。模型会先消耗 token 做内部推理，结果可能没有剩余 token 用于最终输出。

    请确保 `max_tokens` 设为 `None`，或者增大 token 限制，以便同时容纳推理和最终输出。
</Tip>

## 多模态输入（图片、PDF、音频）

OpenAI 提供支持多模态输入的模型。你可以向这些模型传入图片、PDF 或音频。关于如何在 LangChain 中实现，请参见 [multimodal inputs](/oss/langchain/messages#multimodal) 文档。

不同模态的支持模型列表可参见 [OpenAI's documentation](https://platform.openai.com/docs/models)。

对于所有模态，LangChain 同时支持其跨提供方标准格式，以及 OpenAI 原生 content-block 格式。

要向 @[`ChatOpenAI`] 传入多模态数据，请创建一个包含该数据的 [content block](/oss/langchain/messages/)，并将其放入消息中，例如：

```python
message = {
    "role": "user",
    "content": [
        {
            "type": "text",
            "text": "Describe the (image / PDF / audio...)",
        },
        content_block,
    ],
}
```

下面是 content block 的示例。

<Accordion title="Images">

```python URLs
content_block = {

}

# OpenAI Chat Completions format
content_block = {
    "type": "image_url",
    "image_url": {"url": url_string},
}
```

```python In-line base64 data
# LangChain format
content_block = {

content_block = {
    "type": "image_url",

```

```python In-line base64 data
    "input_audio": {"data": base64_string, "format": "wav"},

```

## Predicted output

<Info>
**Requires `langchain-openai>=0.2.6`**
</Info>

某些 OpenAI 模型（例如 `gpt-4o` 与 `gpt-4o-mini` 系列）支持 [Predicted Outputs](https://platform.openai.com/docs/guides/latency-optimization#use-predicted-outputs)，允许你提前传入一部分已知的模型预期输出，从而降低延迟。这在文本或代码编辑场景中特别有用，因为通常只有一小部分输出会发生变化。

示例如下：

```python
code = """
/// <summary>
/// Represents a user with a first name, last name, and username.
/// </summary>
public class User
{
    /// <summary>
    /// Gets or sets the user's first name.
    /// </summary>
    public string FirstName { get; set; }

    /// <summary>
    /// Gets or sets the user's last name.
    /// </summary>
    public string LastName { get; set; }

    /// <summary>
    /// Gets or sets the user's username.
    /// </summary>
    public string Username { get; set; }
}
"""

llm = ChatOpenAI(model="gpt-5.5")
query = (
    "Replace the Username property with an Email property. "
    "Respond only with code, and with no markdown formatting."
)
response = llm.invoke(
    [{"role": "user", "content": query}, {"role": "user", "content": code}],
    prediction={"type": "content", "content": code},
)
```

<Note>
Predictions 会作为额外 token 计费，也就是说你是用更高的使用量与成本，换取更低延迟。
</Note>

## 音频生成（Preview）

<Info>
Requires `langchain-openai>=0.2.3`
</Info>

OpenAI 提供了一项新的 [audio generation feature](https://platform.openai.com/docs/guides/audio?audio-generation-quickstart-example=audio-out)，允许你在 `gpt-4o-audio-preview` 模型上同时使用音频输入和音频输出。

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="gpt-4o-audio-preview",
    temperature=0,
    model_kwargs={
        "modalities": ["text", "audio"],
        "audio": {"voice": "alloy", "format": "wav"},
    },
)

output_message = llm.invoke(
    [
        ("human", "Are you made by OpenAI? Just answer yes or no"),
    ]
)
```

`output_message.additional_kwargs['audio']` 会包含一个类似下面的字典：

```python
{
    'data': '<audio data b64-encoded',
    'expires_at': 1729268602,
    'id': 'audio_67127d6a44348190af62c1530ef0955a',
    'transcript': 'Yes.'
}
```

格式会与你在 `model_kwargs['audio']['format']` 中传入的值一致。

你也可以在 OpenAI `expires_at` 到期前，把这个带有音频数据的消息再次传给模型，作为消息历史的一部分。

<Note>
**输出音频存放在 `AIMessage.additional_kwargs` 的 `audio` 键下，而输入内容块则是在 `HumanMessage.content` 列表中以 `input_audio` 类型和键表示。**

更多信息请参见 OpenAI 的 [audio docs](https://platform.openai.com/docs/guides/audio)。
</Note>

```python
history = [

second_output_message = llm.invoke(history)
```

## Prompt caching

OpenAI 的 [prompt caching](https://platform.openai.com/docs/guides/prompt-caching) 功能会自动缓存超过 1024 token 的 prompt，从而降低成本并改善响应时间。该功能对所有近期模型（`gpt-4o` 及更新版本）默认启用。

### 手动缓存

你可以使用 `prompt_cache_key` 参数来影响 OpenAI 的缓存行为，并优化 cache hit rate：

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-5.5")

messages = [
    {"role": "system", "content": "You are a helpful assistant that translates English to French."},
    {"role": "user", "content": "I love programming."},
]

response = llm.invoke(
    messages,
    prompt_cache_key="translation-assistant-v1"
)
```

<Warning>
    发生 cache hit 的前提是 prompt 前缀必须完全一致
</Warning>

### Cache key 策略

你可以根据应用场景采用不同的 cache key 策略：

```python
# Static cache keys for consistent prompt templates
customer_response = llm.invoke(
    messages,
    prompt_cache_key="customer-support-v1"
)

support_response = llm.invoke(
    messages,
    prompt_cache_key="internal-support-v1"
)

# Dynamic cache keys based on context
user_type = "premium"
cache_key = f"assistant-{user_type}-v1"
response = llm.invoke(messages, prompt_cache_key=cache_key)
```

### 模型级缓存

你也可以通过 `model_kwargs` 在模型级别设置默认 cache key：

```python
llm = ChatOpenAI(
    model="gpt-5.4-mini",
    model_kwargs={"prompt_cache_key": "default-cache-v1"}
)

# Uses default cache key
response1 = llm.invoke(messages)

# Override with specific cache key
response2 = llm.invoke(messages, prompt_cache_key="override-cache-v1")
```

### 使用断点进行显式缓存

<Note>
需要 `langchain-openai>=1.3.5`。在 Chat Completions API 和 [Responses API](/oss/python/integrations/chat/openai#responses-api) 上均受支持。
</Note>

OpenAI 支持 [显式 prompt-cache 断点](https://developers.openai.com/api/docs/guides/prompt-caching#prompt-cache-breakpoints)，允许你把特定的内容块指定为缓存边界。这样你可以精细地控制提示词中哪些部分被缓存，而不必完全依赖自动的前缀缓存。

要把一个内容块标记为缓存断点，请在该块上添加 `"prompt_cache_breakpoint": {"mode": "explicit"}`。显式断点需要 GPT-5.6 或更高版本的模型系列。

### 请求级缓存选项

<Note>
需要 `langchain-openai>=1.3.5`。`prompt_cache_options` 适用于 GPT-5.6 及更高版本的模型系列。
</Note>

你可以通过模型或每次调用上的 `prompt_cache_options` 参数来传入请求级的提示缓存选项：

- **`mode`**：`"implicit"`（默认）或 `"explicit"`。在 `"implicit"` 模式下，OpenAI 会在最新消息上放置一个缓存断点，同时也会使用你提供的任何显式断点。在 `"explicit"` 模式下，只有你的断点会被用于缓存的读取和写入。如果请求没有显式断点，则不会使用提示缓存。
- **`ttl`**：该请求写入的断点的最短缓存存活时间。唯一支持的值是 `"30m"`，这也是默认值。

<OpenaiPromptCacheOptionsPy />

对于 GPT-5.6 系列之前的模型，请改用 `prompt_cache_retention`（`"in_memory"` 或 `"24h"`）。该字段独立于 `prompt_cache_options`，并且在 GPT-5.6 及更高版本的模型系列上已被弃用。

## Flex processing

OpenAI 提供多种 [service tiers](https://platform.openai.com/docs/guides/flex-processing)。其中 “flex” tier 提供更低的请求价格，但代价是响应可能更慢，而且资源未必总是可用。它更适合非关键任务，例如模型测试、数据增强，或可以异步运行的作业。

要使用它，只需在初始化模型时设置 `service_tier="flex"`：

```python
llm = ChatOpenAI(model="o4-mini", service_tier="flex")
```

请注意，这是一个 beta 特性，仅适用于部分模型。更多细节请参见 OpenAI [docs](https://platform.openai.com/docs/guides/flex-processing)。
