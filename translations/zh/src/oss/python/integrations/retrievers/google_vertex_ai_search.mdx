>[Google Vertex AI Search](https://cloud.google.com/enterprise-search)（此前在 `Generative AI App Builder` 中称为 `Enterprise Search`）是 `Google Cloud` 提供的 [Vertex AI](https://cloud.google.com/vertex-ai) 机器学习平台的一部分。
>
>`Vertex AI Search` 让组织能够快速为客户和员工构建由生成式 AI 驱动的搜索引擎。它以多种 `Google Search` 技术为基础，包括语义搜索。语义搜索会利用自然语言处理和机器学习技术推断内容之间的关系，以及用户查询输入背后的意图，因此相比传统基于关键词的搜索技术，能够提供更相关的结果。Vertex AI Search 还受益于 Google 在理解用户搜索方式方面的经验，并会结合内容相关性来排列展示结果。

>`Vertex AI Search` 可以在 `Google Cloud Console` 中使用，也可以通过 API 集成到企业工作流中。

本笔记本演示如何配置 `Vertex AI Search` 并使用 Vertex AI Search [retriever](/oss/langchain/retrieval)。Vertex AI Search retriever 封装了 [Python client library](https://cloud.google.com/generative-ai-app-builder/docs/libraries#client-libraries-install-python)，并利用它访问 [Search Service API](https://cloud.google.com/python/docs/reference/discoveryengine/latest/google.cloud.discoveryengine_v1beta.services.search_service)。

如需查看 `VertexAISearchRetriever` 全部特性与配置项的详细文档，请参阅 [API reference](https://reference.langchain.com/python/langchain-google-community/vertex_ai_search/VertexAISearchRetriever)。

## 设置

### 安装

要使用 Vertex AI Search retriever，需要安装 `langchain-google-community` 和 `google-cloud-discoveryengine` 包。

```python
pip install -qU langchain-google-community google-cloud-discoveryengine
```

### 配置对 Google Cloud 和 Vertex AI Search 的访问

截至 2023 年 8 月，Vertex AI Search 已经普遍可用，无需 allowlist。

在使用 retriever 之前，需要完成以下步骤：

#### 创建搜索引擎并填充非结构化数据存储

- 按照 [Vertex AI Search Getting Started guide](https://cloud.google.com/generative-ai-app-builder/docs/try-enterprise-search) 中的说明，设置 Google Cloud 项目和 Vertex AI Search。
- [使用 Google Cloud Console 创建一个非结构化数据存储](https://cloud.google.com/generative-ai-app-builder/docs/create-engine-es#unstructured-data)
  - 用 `gs://cloud-samples-data/gen-app-builder/search/alphabet-investor-pdfs` Cloud Storage 文件夹中的示例 PDF 文档填充它。
  - 确保选择 `Cloud Storage (without metadata)` 选项。

#### 设置访问 Vertex AI Search API 的凭据

Vertex AI Search retriever 使用的 [Vertex AI Search client libraries](https://cloud.google.com/generative-ai-app-builder/docs/libraries) 提供了以编程方式向 Google Cloud 认证的高级语言支持。  
这些客户端库支持 [Application Default Credentials (ADC)](https://cloud.google.com/docs/authentication/application-default-credentials)；库会在一组预定义位置查找凭据，并使用这些凭据向 API 发起认证请求。  
借助 ADC，你可以在多种环境中为应用提供凭据，例如本地开发或生产环境，而无需修改应用代码。

如果是在 [Google Colab](https://colab.google) 中运行，请使用 `google.colab.google.auth` 进行认证；否则请遵循其中一种[受支持的方法](https://cloud.google.com/docs/authentication/application-default-credentials)，确保 Application Default Credentials 已正确设置。

```python
import sys

if "google.colab" in sys.modules:
    from google.colab import auth as google_auth

    google_auth.authenticate_user()
```

### 配置并使用 Vertex AI Search retriever

Vertex AI Search retriever 实现于 `langchain_google_community.VertexAISearchRetriever` 类中。`get_relevant_documents` 方法会返回一个 `langchain.schema.Document` 列表，其中每个文档的 `page_content` 字段都会填入文档内容。  
根据 Vertex AI Search 中使用的数据类型不同（网站、结构化或非结构化），`page_content` 字段的填充方式如下：

- 使用高级索引的网站：返回与查询匹配的 `extractive answer`。`metadata` 字段会填入提取出这些片段或答案的文档元数据（如果有）。
- 非结构化数据源：返回与查询匹配的 `extractive segment` 或 `extractive answer`。`metadata` 字段会填入提取出这些片段或答案的文档元数据（如果有）。
- 结构化数据源：返回一个字符串化的 json，其中包含从结构化数据源返回的所有字段。`metadata` 字段会填入文档元数据（如果有）。

#### Extractive answers 和 extractive segments

extractive answer 是随每个搜索结果返回的逐字文本，直接从原始文档中提取。它通常显示在网页顶部，为最终用户提供与其查询在上下文上相关的简短答案。extractive answers 可用于网站搜索和非结构化搜索。

extractive segment 也是随每个搜索结果返回的逐字文本。它通常比 extractive answer 更长。extractive segments 可以作为查询答案展示，也可以用于后处理任务，或作为大语言模型生成答案或新文本的输入。extractive segments 可用于非结构化搜索。

如需进一步了解 extractive segments 和 extractive answers，请参阅[产品文档](https://cloud.google.com/generative-ai-app-builder/docs/snippets)。

注意：extractive segments 需要启用 [Enterprise edition](https://cloud.google.com/generative-ai-app-builder/docs/about-advanced-features#enterprise-features) 功能。

在创建 retriever 实例时，你可以指定多个参数，以控制要访问哪个数据存储以及如何处理自然语言查询，其中也包括 extractive answers 和 segments 的相关配置。

#### 必填参数

- `project_id`：你的 Google Cloud Project ID。
- `location_id`：数据存储所在位置。
  - `global`（默认）
  - `us`
  - `eu`

以下两者必须提供其一：

- `search_engine_id`：你想使用的搜索应用 ID。（Blended Search 必填）
- `data_store_id`：你想使用的数据存储 ID。

`project_id`、`search_engine_id` 和 `data_store_id` 可以显式传入 retriever 构造函数，也可以通过环境变量 `PROJECT_ID`、`SEARCH_ENGINE_ID` 和 `DATA_STORE_ID` 提供。

你还可以配置若干可选参数，包括：

- `max_documents`：用于提供 extractive segments 或 extractive answers 的最大文档数。
- `get_extractive_answers`：默认情况下，retriever 配置为返回 extractive segments。
  - 将该字段设为 `True` 可以返回 extractive answers。只有当 `engine_data_type` 设为 `0`（非结构化）时才会使用。
- `max_extractive_answer_count`：每个搜索结果返回的 extractive answer 最大数量。
  - 最多返回 5 个 answer。只有当 `engine_data_type` 设为 `0`（非结构化）时才会使用。
- `max_extractive_segment_count`：每个搜索结果返回的 extractive segment 最大数量。
  - 当前只会返回 1 个 segment。只有当 `engine_data_type` 设为 `0`（非结构化）时才会使用。
- `filter`：根据数据存储中文档关联的元数据，对搜索结果进行过滤的表达式。
- `query_expansion_condition`：用于决定在何种条件下启用 query expansion。
  - `0`：未指定 query expansion 条件。此时服务器行为默认为禁用。
  - `1`：禁用 query expansion。即使 `SearchResponse.total_size` 为零，也只使用精确搜索查询。
  - `2`：由 Search API 构建的自动 query expansion。
- `engine_data_type`：定义 Vertex AI Search 的数据类型。
  - `0`：非结构化数据
  - `1`：结构化数据
  - `2`：网站数据
  - `3`：[Blended search](https://cloud.google.com/generative-ai-app-builder/docs/create-data-store-es#multi-data-stores)

### `GoogleCloudEnterpriseSearchRetriever` 迁移指南

在早期版本中，这个 retriever 的名称是 `GoogleCloudEnterpriseSearchRetriever`。

要迁移到新的 retriever，请进行以下修改：

- 将导入语句从 `from langchain.retrievers import GoogleCloudEnterpriseSearchRetriever` 改为 `from langchain_google_community import VertexAISearchRetriever`。
- 将所有类引用从 `GoogleCloudEnterpriseSearchRetriever` 改为 `VertexAISearchRetriever`。

注意：使用该 retriever 时，如果你想从单次查询中获取自动 tracing，也可以取消下面的注释并设置 [LangSmith](/langsmith/observability) API key：

```python
os.environ["LANGSMITH_API_KEY"] = getpass.getpass("Enter your LangSmith API key: ")
os.environ["LANGSMITH_TRACING"] = "true"
```

## 实例化

### 为**非结构化**数据配置并使用带 extractive segments 的 retriever

```python
from langchain_google_community import (
    VertexAIMultiTurnSearchRetriever,
    VertexAISearchRetriever,
)

PROJECT_ID = "<YOUR PROJECT ID>"  # Set to your Project ID
LOCATION_ID = "<YOUR LOCATION>"  # Set to your data store location
SEARCH_ENGINE_ID = "<YOUR SEARCH APP ID>"  # Set to your search app ID
DATA_STORE_ID = "<YOUR DATA STORE ID>"  # Set to your data store ID
```

```python
retriever = VertexAISearchRetriever(
    project_id=PROJECT_ID,
    location_id=LOCATION_ID,
    data_store_id=DATA_STORE_ID,
    max_documents=3,
)
```

```python
query = "What are Alphabet's Other Bets?"

result = retriever.invoke(query)
for doc in result:
    print(doc)
```

### 为**非结构化**数据配置并使用带 extractive answers 的 retriever

```python
retriever = VertexAISearchRetriever(
    project_id=PROJECT_ID,
    location_id=LOCATION_ID,
    data_store_id=DATA_STORE_ID,
    max_documents=3,
    max_extractive_answer_count=3,
    get_extractive_answers=True,
)

result = retriever.invoke(query)
for doc in result:
    print(doc)
```

### 为**结构化**数据配置并使用 retriever

```python
retriever = VertexAISearchRetriever(
    project_id=PROJECT_ID,
    location_id=LOCATION_ID,
    data_store_id=DATA_STORE_ID,
    max_documents=3,
    engine_data_type=1,
)

result = retriever.invoke(query)
for doc in result:
    print(doc)
```

### 为带高级网站索引的**网站**数据配置并使用 retriever


### 为**blended** 数据配置并使用 retriever

```python
retriever = VertexAISearchRetriever(
    project_id=PROJECT_ID,
    location_id=LOCATION_ID,

    print(doc)
```

### 配置并使用多轮搜索 retriever

[Search with follow-ups](https://cloud.google.com/generative-ai-app-builder/docs/multi-turn-search) 基于生成式 AI 模型，与常规的非结构化数据搜索不同。

```python
retriever = VertexAIMultiTurnSearchRetriever(
    project_id=PROJECT_ID, location_id=LOCATION_ID, data_store_id=DATA_STORE_ID
)

result = retriever.invoke(query)
for doc in result:
    print(doc)
```
