<Update label="Jul 7, 2026" tags={["deepagents"]} rss={{ title: "Jul 7, 2026 - deepagents" }}>
    ## `deepagents` v0.7.0a6

    - **新增 [`delete`](/oss/deepagents/tools#built-in-harness-tools) 文件系统工具**：可删除单个文件，或递归删除目录及其全部内容。对于不支持删除的 backend，该工具会被自动隐藏，不暴露给模型。
    - **`write_file` 现在会覆盖已有文件**：过去如果目标文件已存在，`write_file` 会直接报错。现在它会覆盖现有文件；如果你只想对已有文件做局部修改，请改用 `edit_file`。
    - **[覆盖默认 middleware 实例](/oss/deepagents/customization#override-a-default-middleware-instance)**：如果传入的 `middleware=`，或 subagent 的 `middleware`，其实例 `.name` 与某个默认 middleware 相同，那么现在会原位替换默认 middleware，而不再因重复而报错。
    - **[限制文件系统工具](/oss/deepagents/overview#virtual-filesystem-access)**：`FilesystemMiddleware` 现在支持 `tools` allowlist，用于仅向模型暴露部分内建文件系统工具，这项能力建立在上述 middleware 覆盖行为之上。

</Update>


<Update label="May 12, 2026" tags={["deepagents"]} rss={{ title: "May 12, 2026 - langchain" }}>
    ## `deepagents` v0.6.0

    - **[`CodeInterpreterMiddleware`](/oss/deepagents/interpreters)**：`deepagents` 现在支持通过受限的 QuickJS runtime 进行代码执行和以编程方式调用工具。
    - `stream_events` / `astream_events` 现在支持 `version="v3"`。详见 [event streaming](/oss/deepagents/event-streaming) 指南。
    - **[`DeltaChannel`](/oss/langgraph/pregel#deltachannel) (beta)** ([blog](https://www.langchain.com/blog/delta-channels-evolving-agent-runtime))：Deep Agents 现在使用 `DeltaChannel` 保存消息历史和智能体文件。它不会在每次 checkpoint 时重复序列化完整累计值，而是只存储每一步写入的增量 delta，因此在线程越来越长时仍能保持较小的 checkpoint 体积。
    - **[Harness profiles](/oss/deepagents/profiles)**：你现在可以注册按 provider 或 model 划分的配置包（`HarnessProfile`），在模型被选中时由 `create_deep_agent` 自动应用，包括 system prompt 调整、工具覆盖、middleware 变更和 subagent 默认配置，而无需修改调用端代码。
    - **[`ContextHubBackend`](/oss/deepagents/backends#contexthubbackend)** ([blog](https://www.langchain.com/blog/introducing-context-hub))：新增了一个由 LangSmith Hub 支持的文件系统后端。智能体文件，包括 skills、memories 和其他持久化上下文，会以 Hub commit 的形式存储，让你在无需额外部署 LangGraph store 的情况下获得每次写入的版本历史和 LangSmith 原生持久性。
</Update>

<Update label="May 12, 2026" tags={["langgraph"]} rss={{ title: "May 12, 2026 - langgraph" }}>
    ## `langgraph` v1.2.0

    此版本新增了更细粒度的节点执行控制（超时、错误恢复和优雅关闭）、一种可降低长线程 checkpoint 开销的新 channel 类型，以及以内容块为中心的流式 API（v3），支持按 channel 输出类型化投影。

    - **[`DeltaChannel`](/oss/langgraph/pregel#deltachannel) (beta)**：一种新的 channel 类型，只存储每一步的增量 delta，而不是重复序列化完整累计值。它特别适合会随着时间不断增长的 channel，例如长线程中的消息列表。你可以使用 `snapshot_frequency=K` 每 K 步写入一次完整快照，以控制读取延迟。

    - **[Per-node timeouts](/oss/langgraph/fault-tolerance#timeouts)**：你现在可以在 @[`add_node`] 上传入 `timeout=`，限制单次尝试的运行时长。可通过 @[`TimeoutPolicy`] 设置硬性的 wall-clock 限制（`run_timeout`）、在有进展时会重置的空闲限制（`idle_timeout`），或两者同时设置。超时触发时，LangGraph 会抛出 @[`NodeTimeoutError`]，清除该次尝试的写入，并交由重试策略处理。仅支持 async 节点。

    - **[Node-level error handlers](/oss/langgraph/fault-tolerance#error-handling)**：你现在可以在 @[`add_node`] 上传入 `error_handler=`，在所有重试都耗尽后执行恢复函数。该 handler 会接收类型化的 @[`NodeError`]，并可返回 @[`Command`] 来更新 state 并路由到其他节点，适用于 Saga/补偿类模式。

    - **[Graceful shutdown](/oss/langgraph/fault-tolerance#graceful-shutdown)**：你可以在当前 superstep 完成后，以协作方式停止一个正在运行中的任务，并保存一个可恢复的 checkpoint。创建 @[`RunControl`] 后，可在任意线程调用 `request_drain()`；运行会抛出 `GraphDrained`，之后可以用相同配置继续恢复。

    - **New event streaming API (beta)**：向 `stream_events()` / `astream_events()` 传入 `version="v3"`，即可使用以内容块为中心的协议，获得按 channel 分类的类型化投影（`run.values`、`run.messages`、`run.lifecycle`、`run.subgraphs`），并支持按需启用 updates、custom events、checkpoints、tasks 和 debug 的转换。`run.messages` 会为每次 LLM 调用生成一个 `ChatModelStream`，并提供文本、reasoning、tool calls 和 usage 的类型化子投影。`version="v1"` 和 `version="v2"` 保持不变。

    超时和错误处理器仅支持 Python；重试策略则在 Python 和 TypeScript 中都可继续使用。
</Update>
<Update label="Apr 7, 2026" tags={["deepagents"]} rss={{ title: "Apr 7, 2026 - deepagents" }}>
    ## `deepagents` v0.5.0

    - **[Async subagents](/oss/deepagents/async-subagents)**：Deep Agents 现在可以启动非阻塞后台任务，因此用户在 subagent 并发工作时仍可继续与主智能体交互。该功能需要 [LangSmith Deployment](/langsmith/deployment) 来支持 sub-agents。

    - **多模态支持**：`read_file` 工具现在除了图片，还支持 PDF、音频和视频文件。

    - **后端变更**：我们对 Deep Agents 的 [backend protocol](https://github.com/langchain-ai/deepagents/blob/main/libs/deepagents/deepagents/backends/protocol.py) 做了一些向后兼容的改动：
      - 更新了 [State and Store backends](/oss/deepagents/backends) 中存储的文件格式，以支持二进制文件。
      - 改进了后端向工具传播错误的方式。
      - 现在你可以直接实例化 `StateBackend()` 和 `StoreBackend()`。通过工厂指定（例如 `backend=(lambda rt: StateBackend(rt))`）的方式已被弃用。

    - **Anthropic prompt caching 改进**：我们对 Anthropic 模型的 prompt caching 性能做了若干优化。
</Update>
<Update label="Mar 10, 2026" tags={["langgraph"]} rss={{ title: "Mar 10, 2026 - langgraph" }}>
    ## `langgraph` v1.1.0

    - **Type-safe streaming (`version="v2"`)**：向 `stream()` / `astream()` 传入 `version="v2"`，即可获得统一的 `StreamPart` 输出，每个 chunk 都包含 `type`、`ns` 和 `data` 键。每种 mode 都有对应的 `TypedDict`，并可从 `langgraph.types` 导入。详见 [streaming docs](/oss/langgraph/streaming#stream-output-format-v2)。

    - **Type-safe invoke (`version="v2"`)**：向 `invoke()` / `ainvoke()` 传入 `version="v2"`，即可得到一个带 `.value` 和 `.interrupts` 属性的 `GraphOutput` 对象。详见 [invoke docs](/oss/langgraph/streaming#v2-invoke-format)。

    - **Pydantic 和 dataclass coercion**：在 `version="v2"` 下，`invoke()` 和 `values` 模式的流式输出会自动被转换为你声明的 Pydantic model 或 dataclass 类型。

    - **修复了带 interrupts 和 subgraphs 的 time travel**：replay 现在不会再复用过期的 `RESUME` 值，子图也能正确恢复到父图历史 state 对应的 checkpoint。

    - **完全向后兼容**：`version="v2"` 是可选启用的。`GraphOutput` 也支持已弃用的字典式访问，以帮助你逐步迁移。
</Update>
<Update label="Feb 10, 2026" tags={["deepagents"]} rss={{ title: "Feb 10, 2026 - deepagents" }}>
    ## `deepagents` v0.4.0

    * 为可插拔沙箱新增了集成包：[`langchain-modal`](https://pypi.org/project/langchain-modal/)、[`langchain-daytona`](https://pypi.org/project/langchain-daytona/) 和 [`langchain-runloop`](https://pypi.org/project/langchain-runloop/)。详见 [sandboxes guide](/oss/deepagents/sandboxes) 和示例 [data analysis tutorial](/oss/deepagents/data-analysis)。
    * 对[对话历史摘要](/oss/deepagents/context-engineering#summarization)做了如下调整：
      * 摘要现在通过 `wrap_model_call` 事件在模型节点中执行，因此我们会在图 state 中保留完整消息历史。
      * Token 计数更准确。
      * 如果 chat model 抛出 @[`ContextOverflowError`]（定义于 `langchain-core`），摘要现在也会自动触发。目前 `langchain-anthropic` 和 `langchain-openai` 已支持这一行为。
    * 对于以 `"openai:"` 为前缀的模型字符串，我们现在默认使用 Responses API。
        <Accordion
            title="使用 Responses API 时关闭数据保留"
        >
            ```python
            from langchain.chat_models import init_chat_model

            agent = create_deep_agent(
                model=init_chat_model(
                    "openai:...",
                    use_responses_api=True,
                    store=False,
                    include=["reasoning.encrypted_content"],
                )
            )
            ```
        </Accordion>
</Update>

<Update label="Nov 25, 2025" tags={["langchain"]} rss={{ title: "Nov 25, 2025 - langchain" }}>
    ## `langchain` v1.1.0

    * [Model profiles](/oss/langchain/models#model-profiles)：chat models 现在通过 `.profile` 属性暴露其支持的功能与能力。这些数据来自 [models.dev](https://models.dev)，一个提供模型能力数据的开源项目。
    * [Summarization middleware](/oss/langchain/middleware/built-in#summarization)：已更新为支持基于 model profiles 的灵活触发点，从而实现具备上下文感知的摘要。
    * [Structured output](/oss/langchain/structured-output)：现在可依据 model profiles 自动推断 `ProviderStrategy` 支持（原生 structured output）。
    * [`SystemMessage` for `create_agent`](/oss/langchain/middleware/custom#dynamic-prompt)：`create_agent` 的 `system_prompt` 参数现在支持直接传入 `SystemMessage` 实例，从而支持缓存控制和结构化内容块等高级特性。
    * [Model retry middleware](/oss/langchain/middleware/built-in#model-retry)：新增 middleware，用于通过可配置的指数退避自动重试失败的模型调用。
    * [Content moderation middleware](/oss/integrations/middleware/openai#content-moderation)：为 OpenAI 提供内容审核 middleware，用于检测和处理 agent 交互中的不安全内容，支持检查用户输入、模型输出和工具结果。
</Update>
