LLM 应用往往很难评估，因为它们通常生成的是对话文本，而这类输出往往不存在唯一正确答案。

本指南展示如何使用 [LangSmith UI](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=langsmith-llm-as-judge) 为[离线评估](/langsmith/evaluation-concepts#offline-evaluations)定义一个 [LLM-as-a-judge evaluator](/langsmith/evaluation-concepts#llm-as-judge)。

<Note>
本指南使用 LangSmith UI。你也可以通过 SDK 以编程方式创建 LLM-as-a-judge evaluator。通过这两种方式创建的 evaluator 在 LangSmith UI 中的显示方式相同。请参阅[使用 SDK 管理 evaluators](/langsmith/manage-evaluators-sdk)。

如果想对生产 traces 实时运行评估，请参阅[设置在线评估](/langsmith/online-evaluations-llm-as-judge)。
</Note>

<Tip>
如果 dataset 示例是通过[在 annotation queue 中编写 assertions](/langsmith/assertions)构建出来的，那么 LLM-as-a-judge evaluator 可以读取 `example.outputs["assertions"]`，并根据你的应用输出为每一条 assertion 打分。
</Tip>

## 第 1 步：创建 evaluator

1. 在 [LangSmith UI](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=langsmith-llm-as-judge) 中，从 [Evaluators](/langsmith/evaluators) 页面点击 **+ Evaluator**，或者在 dataset 或 tracing project 内的 **Evaluators** 标签页中点击。
1. 在 **Add Evaluator** 面板中，在 **Create from scratch** 下选择 **LLM-as-a-Judge Evaluator**。也可以选择 **Create from a template**，先从现成 evaluator 开始，再进行编辑。

### Evaluator 模板

在设置评估时，evaluator 模板是一个很有用的起点。在 **Add Evaluator** 面板中选择 **Create from a template**，即可浏览按 Security、Safety、Quality 等类别组织的模板。

你可以在以下场景配置 LLM-as-a-Judge evaluator：

- 从 [Evaluators](/langsmith/evaluators) 页面
- 作为 dataset 的一部分，用于[自动在实验上运行评估](/langsmith/bind-evaluator-to-dataset)
- 在运行[在线评估](/langsmith/online-evaluations-llm-as-judge)时

### 自定义你的 LLM-as-a-judge evaluator

可以为 LLM-as-a-judge evaluator 的 prompt 添加更具体的说明，并配置要将输入、输出、参考输出中的哪些部分传给 evaluator。

## 第 2 步：配置 evaluator

### Prompt

为你的 evaluator 内联创建一个自定义 prompt。

### Model

从提供的选项中选择所需模型。

要使用 decision model 作为 judge，请参阅 [How to define a decision model evaluator](/langsmith/decision-model-evaluator)。

<a id="use-the-openai-flex-service-tier"></a>

#### 使用 OpenAI Flex 服务层级

[OpenAI Flex 服务层级](https://developers.openai.com/api/docs/guides/flex-processing)以较长的响应时间换取较低的模型调用费用。适用于可以等待几分钟再获得评分的 evaluator，例如在线 evaluator 和绑定到 dataset 的 evaluator。

OpenAI GPT-5、GPT-6 系列模型以及 `o3` 和 `o4-mini` 支持 Flex 层级。在 **Prompt & Model** 下点击模型名称，打开 **Model Configuration** 对话框，然后将 **Service Tier** 设为 **Flex**。新建的 OpenAI evaluator 默认使用 **auto** 层级，即 API key 所属 OpenAI 项目的默认层级。只有支持 Flex 的模型才会显示 **Flex** 选项。

Flex 调用遵循以下规则。

- **等待时间**：LangSmith 最多等待每次 Flex 调用 10 分钟以获取评分。
- **调用次数**：Flex 调用超时后，LangSmith 不会重试，避免因响应慢而产生重复费用。该调用中的每个 run 都会收到错误，无法获得评分。
- **批次时限**：LangSmith 每次对一批 runs 应用 evaluator 时都有固定时限。临近时限时，LangSmith 跳过剩余的 Flex 调用并保留已获得的评分。被跳过的调用返回错误 `Skipped: this rule run used up its time on slower OpenAI flex calls`。
- **测试运行**：点击 **Test** 时，LangSmith 最多等待 4 分钟。响应较慢的 Flex 调用可能在测试中超时，但在保存 evaluator 后可以成功。

当[模型定价](/langsmith/cost-tracking#create-a-new-or-modify-an-existing-model-price-entry)中的模型价格条目包含 Flex 费率时，[evaluator 支出上限](/langsmith/evaluator-spend)按 Flex 费率计入这些调用。自定义价格条目若未设置 Flex 费率，则按标准费率计入 Flex 调用。

### 映射变量

使用变量映射来指定从 run 或 example 中将哪些变量传入 evaluator prompt。为了帮助完成变量映射，界面会提供一个示例（或 run）供参考。点击 prompt 中的变量，并使用下拉框将其映射到输入、输出或参考输出中的相应部分。

如果使用 mustache 格式（默认），可以通过双花括号 `{{prompt_var}}` 添加 prompt 变量；如果使用 f-string 格式，则用单花括号 `{prompt_var}`。

你也可以根据需要删除变量。例如，如果正在评估简洁性这类指标，通常不需要参考输出，那么就可以移除该变量。

### 预览

Prompt 预览会展示，在使用右侧显示的参考 run 和 dataset example 进行填充后，最终格式化后的 prompt 长什么样。

### 用 few-shot examples 改进 evaluator

为了让 LLM-as-a-judge evaluator 更贴近人类偏好，LangSmith 允许你为 evaluator 分数收集[人工修正](/langsmith/create-few-shot-evaluators#make-corrections)。启用该选项后，这些修正会被自动插入到 prompt 中，作为 few-shot examples。

了解[如何设置 few-shot examples 并进行修正](/langsmith/create-few-shot-evaluators)。

### Feedback 配置

Feedback 配置就是 LLM-as-a-judge evaluator 用来打分的评分标准。可以把它看作 evaluator 依据的 rubric。分数会以[feedback](/langsmith/observability-concepts#feedback)的形式附加到 run 或 example 上。为 evaluator 定义 feedback 时：

1. **命名 feedback key**：这是查看评估结果时显示的名称。名称应在各个实验中保持唯一。

2. **添加描述**：描述该 feedback 表示什么。

3. **选择 feedback 类型**：

   * **Boolean**：True/false 类型反馈。
   * **Categorical**：从预定义类别中选择。
   * **Continuous**：在指定范围内的数值评分。

在底层实现中，feedback 配置会以[结构化输出](/oss/python/langchain/structured-output)的形式加入到 LLM-as-a-judge prompt 中。Output schema 中的每个顶层 key 都会被当作一条独立 feedback。

## 第 3 步：保存 evaluator

当你完成配置后，保存变更即可。
