## Observability and evaluations

### Tracing

- LangSmith MCP 新增 `query_runs` 工具，接受与 SDK 的 `client.runs.query()` 相同的参数，包括用于成本、token 细分以及完整输入和输出的类型化 `selects`，并支持游标分页。它默认返回 token 计数和美元成本。`fetch_runs` 现在也返回成本和 token 计数，并已弃用，建议改用 `query_runs`。
- 定价页面上的每个 OpenAI 模型现在都能解析成本，包括仅在 "All models" 下列出的模型，例如 GPT-5.6 Luna 和 Terra。此前每日价格同步只读取页面默认显示的模型，因此其余模型的价格保持陈旧。[了解更多](/langsmith/cost-tracking)。
- Vertex AI 通过 Model-as-a-Service 托管的开放模型现在也能解析成本：DeepSeek、Qwen、GLM、Kimi、MiniMax 和 GPT-OSS。[了解更多](/langsmith/cost-tracking)。
- 对于以纯字符串形式发送用户消息的 OpenAI Responses API 调用（通过 `previous_response_id` 或 conversation 链接的调用正是这样发送每个新回合的），Messages 视图现在会显示该用户消息。
- Messages 视图现在请求更小的分页，因此较长的 threads 不再因响应大小错误而失败。
- 当 trace 或 thread 过滤器失败时，LangSmith 会在过滤器下方显示错误，并保持所选 run 详情打开，因此你无需离开页面即可编辑或清除过滤器。
- 创建公开的 trace 或 thread 分享链接现在需要读取 runs（包括其输入和输出）的权限。
- LangSmith Chat 的模型选择器现在提供 Claude Sonnet 5.5。默认模型仍为 Sonnet 5。
- LangSmith Chat 现在在一个回合中可以执行大约四倍的步骤，因此大型自定义应用构建能够完成，而不再以 "Recursion limit of 250 reached" 错误结束。
- 通过 Vertex AI 在 Gemini 3.x 模型上进行 Chat 时，连续调用多个工具的回合现在可以完成。
- LangSmith Chat 构建的应用现在会分页浏览列表（例如 annotation queue items），而不是只显示第一页。
- 按 **Most Recent Run** 对 tracing projects 排序时，runs 引用了 dataset examples 的 projects 现在会按其最新 run 排序，而不再与空 projects 归为一组。

### Datasets and experiments

- 在 Amazon Bedrock 上使用 Claude Opus 5.5 或 Sonnet 5.5 的 LLM-as-a-judge evaluators 不再因不支持的强制 tool choice 而失败。
- 创建 evaluator 时，现在会从模型设置（包括 LangSmith Gateway 预设）中选择默认的 evaluator 模型预设。
- 点击 thread 或 trajectory evaluator 上的 **Test** 时，现在会显示导出和验证失败，而不是看起来毫无反应。Evaluator 测试还会在 evaluator 面板中显示配置错误，例如缺少 endpoint URL。
- 删除 code evaluator 时不再因等待 sandbox snapshot 清理而超时。
- Experiment run 进度现在会在有已记录 runs 时反映它们，而不再只反映已结算的批次。
- **Add to dataset** 现在会保存完整的 source run metadata，你提供的 metadata 会与 run 的 metadata 合并，而不是替换它。
- 当请求更新现有 examples 时，使用 `PUT /v1/platform/datasets/{dataset_id}/examples` 替换 dataset 的 examples 可以再次成功。
- prompt 同时携带旧版和当前输出 schema 的 LLM-as-a-judge evaluators，现在会根据 judge 实际使用的 schema 校验分数，因此分数会保存到正确的 feedback keys 下。

### Feedback

- 在 annotation queue 中打开的 runs 现在会显示与 tracing 中相同的顶栏，因此审核者可以在审核时于 Trajectory 和 Details 视图之间切换。
- Annotation queue 指引现在会在审核侧边面板中保留换行，因此多行和列表样式的指引会按原样显示。
- 从 annotation queue 将 run 添加到 dataset 时，当输出为单条消息时现在会保存你的编辑，并且在无法创建 example 时显示错误。

### Prompts and playground

- GPT-6.1-Sol 现已可用，并默认用于 Playground 中的新 OpenAI prompts 和新的 model configurations。
- Claude Sonnet 5.5 现已在 Anthropic、Amazon Bedrock 和 Vertex AI 的 Playground 和 model configurations 中可用。
- Gemini 3.7 Flash 和 Gemini 3.8 Flash 现已在 Google Gemini 和 Vertex AI 模型选择器中可用。
- LangSmith MCP 的 `get_prompt_by_name` 现在会返回 prompt 模板。新工具允许 agents 推送 prompt 版本、浏览 commits、管理 commit tags、更新或删除 prompts，以及读取和提交 Context Hub 的 agent 和 skill 文件。
- 编辑 Context Hub webhook 时，现在会加载其已保存的自定义 headers，因此保存时不再覆盖它们。
- 加载 model ID 为 application inference profile ARN 的已保存 Bedrock Converse 配置时，现在会保留在 **Extra Parameters** 中设置的 provider。

### Engine

- Engine 用量、支出限制和定价现在以 LangChain Standard Units (LSUs) 显示，每个单价为 $1。美元金额保持不变。[了解更多](/langsmith/engine#manage-engine-costs)。
- Issue validation 现在以 tool call 的形式请求其判断，因此结构化输出响应失败不再中止 run。
- 此前选择了 Skills for Coding Agents 的 Engine projects 现在使用标准 issue 分析，扫描频率取决于其配置的分析级别。
- Engine project boards 不再显示浮动的反馈调查。

## Deployment

- 连接到 LangSmith 原生 MCP 服务器的 agents 可以查找 deployments 和 revisions，并读取构建或运行时日志，可按 revision、时间、搜索文本和严重级别过滤。Deployment 摘要会省略 secrets 和环境配置。
- deployment 的 **Overview** 标签页上的 revision 行会显示 commit 标题，链接到 GitHub 上的 commit，并以你的本地时区显示确切时间。失败的 revision 会显示 "Build failed" 或 "Deploy failed"，完整错误只需点击即可查看。
- Deployment log API 条目现在会说明某行日志来自 API 服务器、queue worker、构建还是平台，由哪个 replica 写入，以及结构化 JSON 日志行的选定字段（例如 run 和 thread ID）。
- Studio 的 thread 侧边栏和 deployment 的 **Threads** 标签页现在只请求其显示的字段，因此此前 threads 超出 Agent Server 响应大小限制的 deployments 也能加载列表。
- 在服务器或构建日志中搜索包含引号或反斜杠的文本时，现在会返回匹配的行，而不是 "Invalid or expired offset" 错误。日志搜索限制为 1,000 个字符。
- 对于托管在 AWS 上的 deployments，其服务器和构建日志在按最新排序时会先列出最近的日志行。
- deployment 的 **Overview** 标签页不再显示 Postgres 磁盘使用量横幅。磁盘使用量仍会在 **Monitoring** 标签页中绘制图表。

## Sandboxes

- LangSmith MCP 可以读取、写入和搜索 sandbox 文件，流式传输长时间运行的 sandbox 命令，在 LangSmith 登录保护下共享 sandbox 端口，并报告 sandbox 用量、organization 用量、audit logs、使用限制、trace 保留设置和 organization members。
- Sandbox 代理规则接受诸如 `"authorization: Bearer account-b"` 之类的 `match_headers` 条目，因此同一主机上的多条规则可以各自用不同的占位符换入自己的凭据，从而服务多个账户。
- 在运行中做快照的保留内存 sandbox，现在会在下一次停止并启动后恢复其全部内存。
- 短暂的存储后端错误不再导致 sandbox 的文件系统在重启前一直返回 I/O 错误。

## Administration

- 在 **Settings** > **OAuth applications** 下注册的 OAuth applications 可以使用一个 access token 同时访问 LangSmith API 和 Remote MCP 服务器，而无需分别授权。
- 通过 LangSmith Managed Tools 的调用现在会以 `invoke_mcp_server` 或 `invoke_mcp_gateway` 的形式出现在 audit logs 中，并包含所使用的 server 或 gateway 以及调用的工具。Audit log 条目还会包含请求的持续时间和 user agent。
- 可以用键盘搜索 organization 和 workspace 设置，在 Mac 上用 Command + 逗号、在 Windows 和 Linux 上用 Ctrl + 逗号打开 **Settings**。
- 在角色预览和角色编辑器中，可以按组、名称或标识符搜索权限。
- 当计费指标变化时，使用量图表和 CSV 导出会保留历史使用量，并隐藏没有使用量的指标。
- 注册和登录重试不再将过期的认证错误带入其返回 URL。

### LLM Gateway

- 使用 workspace 的 `SCALEDOWN_API_KEY` 通过 LLM Gateway 路由 ScaleDown 请求。原生的 compression、extraction、classification、decisions、summarization 和 batch API 保持其请求和响应格式。
- 通过统一 endpoint 调用已保存的 model configuration 时，LLM Gateway 会应用现有的自定义 provider fallback 策略。显式的 model configuration 策略优先。
- LLM Gateway 现在接受输出为文本部分数组的 Responses `function_call_output`。Gemini 和其他需要转换的 providers 此前对这种形式返回 400，导致 LangChain 发送的 MCP 工具结果失败。
- Fallback chain 模型选择器会为自定义 model configurations 显示 **Workspace** 或 **Organization** 徽标。

## Observability and evaluations

### Tracing

- Trajectory 视图现已向所有人开放，支持回合导航、可展开的消息和一致的 trace 详情。
- Tracing quickstart 和引导式 onboarding 现在覆盖 Claude Code、OpenAI Codex、VS Code Copilot 和 Cursor，插件安装和环境设置为你的项目和区域自动生成。[了解更多](/langsmith/trace-claude-code)。
- 无论使用哪个 SDK 进行跟踪，Gemini runs 现在都会报告成本。此前，通过 `google_genai` 以外的客户端跟踪的 Gemini 调用不显示成本。[了解更多](/langsmith/cost-tracking)。
- Traces 现在最多可包含 100,000 个 runs。
- 只要启用了 SmithDB 查询，改版后的 tracing 过滤器即可使用，无需单独的功能开关。
- **Error** 列再次直接在 trace 表格中显示错误描述。
- trace 的 **Tools** 标签页会在 provider 服务器工具（例如 OpenAI `tool_search`）旁边显示 function tools。
- 使用 `DELETE /api/v1/bulk-exports/destinations/{destination_id}` 删除未被任何批量导出使用的导出目标。仍被批量导出引用的目标会被拒绝。
- 自定义模型价格条目现在有 **Clone** 操作，与内置条目一样。
- 超过两分钟的 run 延迟值以分钟显示。
- LangSmith Chat 的模型选择器现在提供 Claude Opus 5.5 和 Gemini 3.8 Flash，并且 Gemini 模型可以完成回合，而不再在第一条消息上失败。
- 现在可以在 LangSmith Chat 面板的任意位置拖放或附加图片。
- LangSmith Chat 会列出 runs 及其输入和输出的预览，并只在需要时才完整打开某个 run，因此大型 projects 不再导致 chats 和自定义应用构建以 "An internal error occurred" 失败。
- LangSmith Chat 会在长回合期间续期其访问权限，因此对 queues、datasets 和 runs 的读取保持可用，而不再以 "Invalid token" 错误结束回合。
- LangSmith Chat 在构建自定义应用时，会将三个或更多连续的探索操作分组。当某个操作失败或需要关注时，分组会自动展开。
- 当 workspace 模型配置指向 Vertex AI 上的 Gemini 时，Chat 在第一个 tool call 之后仍能继续工作。

### Datasets and experiments

- 已完成的 annotation queue items 现在可以从队列的单项视图和批量视图中删除，也可以通过删除 API 删除。
- experiment comparison 和单个 experiment 窗格中的自定义输出渲染器现在会在 `metadata.inputs` 中接收 example 的输入。Reference outputs 以 `type: "reference"` 发送，与文档中的消息格式一致。[了解更多](/langsmith/custom-output-rendering)。
- 在报告支持 trajectory runtime 的每个 data plane 上都可以使用 trajectory evaluators，无需按 workspace 逐步开放。
- 仅当请求将 `include.tool_definitions` 设置为 `true` 时，trajectory API 才会返回每条消息的 tool definitions。规则编辑器的 **Test** 预览现在与实时 trajectory 评估发送给 judge 的内容一致。
- experiment CSV 导出中的 **Include annotator name and comment per row** 现在对每个 workspace 都生效。
- 返回诸如 `output` 之类的占位 JSON 字段的在线 LLM-as-a-judge evaluators，现在会将 feedback 存储在 evaluator 配置的名称下。
- 当请求包含 hub prompt 引用但缺少 `evaluator_version` 时，通过 API 更新在线 evaluator 规则不再失败。
- Thread evaluators 不再提供 **Align Evaluator** 流程或修正 datasets，因为对齐需要 run 级别的 examples。
- 展开字段时，pairwise annotation queues 现在会显示 `true` 和 `false` 输出值。

### Feedback

- 在队列编辑器、审核侧边栏和 CSV 导出中，annotation queue rubric items 现在按添加顺序显示，而不是按字母顺序。
- Feedback 的 extra metadata（包括嵌套 metadata）现在可以通过直接摄取和 multipart 摄取完整往返。
- Feedback 创建中的旧版 `error` 字段已弃用。请通过 `extra.error` 发送 evaluator 失败。旧版字段仍受支持，且在两者同时提供时优先。

### Automations

- Evaluator traces 现在使用 evaluator 的显示名称，而不是通用的 `RunnableSequence` 名称。
- 当 automation 在重试用尽后仍无法获取 runs 时，规则日志会显示所发生的错误，例如超时。

### Engine

- 在 Engine chat 输入框中可以粘贴、拖放或附加最多四张图片，并与消息一起发送。
- Engine 设置现在在 board 的详情区域打开，而不是滑出式窗格，因此设置链接可以共享并重新打开。
- Engine 突出显示跨多个 GitHub 仓库查找和修复 issues 的支持，并提供在设置中管理已连接仓库的快捷方式。
- 描述和提议修复中对其他 Engine issues 的引用会直接链接到对应的 issue。悬停在链接上可查看 issue 标题。
- 连接 GitHub 仓库不再立即为每个打开的代码根 issue 启动修复 run。修复 run 会在你请求时或按 board 的计划启动。
- 将 pull request 与 issue 解除关联的操作现在会生效。Engine 只在 pull request 打开时读取 issue 标记，因此打开时请将标记放在正文中。
- 对使用自定义认证的 deployments 重放 traces 时，Engine boards 可以使用只写的自定义认证 headers。
- Engine 修复分支现在以 `langsmith-engine/` 开头，而不是 `issues-agent/`。在此变更之前已保留修复分支的 issues 保留其 `issues-agent/` 分支。
- 在回合被截断后重试或编辑消息，不再以 "Attempting to delete a message with an ID that doesn't exist" 失败。

### Prompts and playground

- Claude Opus 5.5 现已在 Anthropic、Amazon Bedrock 和 Vertex AI 的 Playground 中可用，并且是这些 providers 新会话的默认模型。
- OpenAI 模型下拉菜单现在会建议 `gpt-6-sol` 和 `gpt-6-luna`。
- Playground 可以从包含 LangChain 消息对象的 traces 渲染可编辑的 prompts，包括多模态内容和没有显式角色的消息。
- Prompt webhook 的自定义 headers 现在会在保存后保留。
- Playground 在流式传输较长响应时不再崩溃。

## Deployment

- **Overview** 标签页在一行中汇总已部署的 revision，包括其来源、时间和日志，并在较新的 rollout 排队、构建或失败时在该行报告。在替换运行中的工作负载后失败的部署会从该行提供回滚选项。
- 生产 deployment 页面会显示 deployment 当前是否正在响应请求，与 revision 状态分开。该徽标也会出现在通过自定义 URL 提供服务的 deployments 上。
- GitHub revisions 会显示 commit 标题，并带有包含分支和短 SHA 的徽标。Deployments API 在每个 revision 上会在 `repo_commit_sha` 旁边返回 `repo_commit_title`。
- 固定到带注解 Git tag 的 deployments 现在会在 `repo_commit_sha` 中记录该 tag 指向的 commit。
- 服务器日志包含 pod 名称被 Kubernetes 缩短的 AWS deployments 的 API 和 worker 日志。
- Studio 会等待 deployment 详情加载，而不是短暂显示连接错误，并在无法加载 deployment 时显示原因。

## Sandboxes

- sandbox 创建时的 `access_delegation` 现在可与 workspace service key 一起使用，因此仅持有 service key 的 deployment 可以为其 sandboxes 授予受限的 LangSmith 访问权限。收窄 key 的角色会收窄 sandbox 的权限，删除 key 会撤销它。
- 通过 sandbox 下载链接共享的每个文件都从其自己的主机提供，并且 `csp_sandbox_flags` 接受 `allow-same-origin`，因此 HTML 页面可以使用 `localStorage` 和 IndexedDB，而其他文件无法读取它们。
- 在没有可用主机时，sandbox 调用会返回 503 并带有 `Retry-After` header，而不是 502，因此在主机维护期间，遇到 503 会重试的客户端可以恢复。
- 从没有 `linux/amd64` 变体的镜像（例如在 Apple Silicon 上构建的仅 arm64 镜像）创建 snapshot 时，现在会立即失败，并给出说明该镜像平台的消息。
- Snapshots 表格以徽标形式显示 tags，并在每个名称下方显示短 snapshot ID。Snapshot 选择器提供每个系统 snapshot 的最新版本。
- Custom Apps 的浏览器编辑功能对启用了 sandbox 支持的符合条件的 workspaces 可用，且 Custom Apps 不再显示 `Beta` 徽标。

## Administration

- 克隆仪表盘现在同时需要 `charts:read` 和 `charts:create` 权限。只能查看图表的角色（例如 Workspace Viewer）不再能克隆仪表盘，而需要保留克隆能力的自定义角色需要 `charts:create`。
- 更改 workspace 范围 service key 的角色，现在需要在该 key 覆盖的每个 workspace 中管理 key 的权限。
- 在 service key 创建表单中，可以预览每个所选角色的基础权限。
- Agent Auth 连接支持加密的只写 `token_request_headers`，用于 OAuth token 交换、刷新和撤销。
- 解析 Agent Auth principals 时，除 `workspaces:manage` 外还接受 `deployments:create` 权限，因此 Workspace Editors 可以使用用户拥有的连接运行 `mda dev`。

### LLM Gateway

- 从可搜索的模型选择器中选择托管模型、providers 或已保存的配置，运行示例请求并复制其代码。[了解更多](/langsmith/llm-gateway)。
- 在 Gateway 请求运行时保持示例代码可见，然后查看响应、提供服务的模型、HTTP 状态、token 用量和 trace。[了解更多](/langsmith/llm-gateway)。
- 当 Gateway 支出策略用尽时，LLM Gateway 不再阻止 Claude Max 和其他由 provider 计费的订阅请求。速率限制、模型访问策略和 guardrails 仍然适用。
- LLM Gateway 会在 Anthropic、Amazon Bedrock 和 Vertex AI 的 Messages 路由（包括流式传输）中保留 Claude 功能 headers 和分类器字段。这使得 Claude Code 的免费服务端 auto mode 检查在模型和平台支持的地方得以启用。
- Vertex AI 模型配置会将 Anthropic Claude 模型路由到 Vertex AI 的原生 Anthropic Messages API，而 Gemini 和开放模型继续使用 OpenAI 兼容的 endpoint。
- LLM Gateway 会在统一 API 请求中省略 temperature，除非目标 OpenAI 模型和推理设置支持它，从而避免较新模型上出现不支持 temperature 的错误。
- 当 `/v1/messages` 请求以 Chat Completions 模型为目标时，Claude Code 在部分回合内容块上发送的 `phase` 标记不再导致 400 错误。该标记会被丢弃并发出警告。
- 当总支出低于一美元时，支出图表 y 轴以美分显示，而不是将每个标签四舍五入为 $0。

## Observability and evaluations

### Datasets and experiments

### Feedback

### Tracing

- 公开共享的 thread 页面不再显示无法成功的分享操作。
- 当两个所选模型都使用其他 provider 时，Insights 不再警告它仅针对 OpenAI 或 Anthropic 优化。

- 仪表盘图表的 feedback key 建议现在包含 run 级别和 thread 级别 feedback 的 keys。

### Engine

- LangSmith Chat 图标和建议问题现在共享一个连续的背景，因此启动器在浅色和深色模式下都呈现为单个胶囊。
- Engine 现在会读取成功 tool 结果的内容，而不仅仅是其状态，因此当调用返回的数据少于其自身结果所声称的，或值到达时被截断时，它会提交 issues。从未以错误形式显现的缺陷不再被忽略。

### Automations

- GET /v2/sandboxes/snapshots 现在使用 page_size 和不透明游标分页，返回 items 和 next_cursor。limit 和 offset 参数以及 snapshots 和 offset 响应字段仍然有效，但已弃用。

### Tracing

- 批量 run ingestion 日志现在会把 run_verbs 作为 run_id 和 verbs 对象的列表输出，而不是以 run UUID 为键的 map，从而避免结构化日志聚合器耗尽动态字段上限。
- 已登录用户查看公共 runs 时，现在会在侧边栏看到其上次所选工作区的导航。未登录的查看者仍可看到公共 run，但没有已登录工作区的导航。
- 获取 runs 或 thread history 的 LangSmith [MCP tools](/langsmith/langsmith-mcp-server) 现在除了项目名外，也接受 `project UUIDs`，让基于 trace URL 的排查更快、更不容易出错。
- OpenTelemetry resource attributes（通过 `OTEL_RESOURCE_ATTRIBUTES` 设置）现在会以 `otel.resource.*` 命名空间显示在 traces 元数据中，因此你可以附加诸如用户 ID 之类的信息，而不必修改 tracer 发出的 spans。
- 原生 OpenTelemetry child spans 在早于 SDK 归属的 parent span 到达时不再被丢弃；它们会被缓冲，并无论到达顺序如何都能正确嵌套。
- 当 ABAC 拒绝 trace 加载时，Thread 页面现在会显示明确的访问控制消息，而不是通用的检索错误。
- Tracing 视图中的所有时间过滤器现在会查询完整的保留期窗口，而不再回退到较短的后端默认值。这样在扩展时间范围时，trace、thread 和 run 的结果保持一致。
- 来自 VS Code Copilot Chat 的 OpenTelemetry traces 现在会按每个用户回合渲染为一条干净的嵌套 trace。辅助的 title/summary 调用和孤立的 tool spans 会被抑制，message 角色会被修正，token 计数会去重，并自动附加标准化的元数据（integration、agent runtime、thread ID、repo/git 信息）。
- Insights 的 cluster run 统计信息（run 数量、延迟、tokens 和 feedback）现在只反映每个 cluster 内的 runs，而不再为每个 cluster 都显示相同的项目级总计。
- LangSmith Chat 现在在搜索文档时会使用 guest token 向 Chat LangChain 进行身份验证，因此在 Chat LangChain 收紧身份验证后，文档问答仍能继续工作。
- 对于包含 middleware guardrails 或 subagent 侧边对话的 traces，Trace Messages 查看器现在会识别出 “主” 对话，因此消息列表只显示主要交互，而不会把 middleware/subagent 分区交错在一起。其正确性已由覆盖 11 个集成（横跨 LangChain、OpenAI Agents SDK、Vercel AI SDK、Claude Agent SDK、deepagents 和原始 provider 封装）的扩展快照测试套件验证。
- 自定义 dashboard 图表现在可以查询 input 和 output cost 的 P50 和 P99，而不会导致 runs analytics 请求失败。
- Thread stats API 现在接受 `filter` 查询参数，让你可以把聚合统计范围限定在匹配某个 LangSmith filter 表达式（例如 start time 或 trace ID）的 traces。
- LangSmith Chat 现在会从 Chat LangChain LangGraph host（`POST /identity/guest`）签发 Managed Deep Agent guest token 用于文档搜索，而不是使用旧版 Chat LangChain 前端的 guest 路由。

### Prompts and playground

- 自托管 [Playground](/langsmith/playground-model-providers) 与 evaluator 的出站模型调用现在会遵循 proxy 环境变量，同时保留对每个请求的 SSRF 校验。

- Playground 和 evaluator 在通过 IAM Trusted Entity 调用 Amazon Bedrock 时，现在会在 AWS 托管的 LangSmith 中扮演客户角色之前先解析出正确的 LangSmith AWS 凭证。这修复了此前在客户角色被扮演之前报 “Failed to assume role” 的失败。
- 通过 forward proxy 路由的出站模型调用，现在会在 proxy CONNECT 隧道中发送原始 hostname，而不是已解析的 IP，因此按域名对隧道目标做白名单的 proxy 不再会拒绝它们。这修复了自托管 Playground 和 evaluator 调用仅能通过此类 proxy 才能访问的内部 OpenAI 兼容 endpoint 的问题。
- Review 一个 prompt commit 时，现在会显示设置在模型上的所有额外参数（例如 verbosity），而不仅是固定的某个子集。

### Feedback

- 向 annotation queue 添加 runs 的 POST 请求现在接受可选的 `extend_trace_retention` 查询参数。当设置为 false 时，短保留期 traces 不会被升级到 extended retention。默认值仍为 true，以保持向后兼容。
- 当客户端提供 session 和 start time 时，feedback 创建现在会从 SmithDB 解析 run metadata，因此仅使用 SmithDB 的部署不再依赖 ClickHouse 来执行 eager feedback 写入。
- `POST /feedback/eager` endpoint 已被弃用，取而代之的是 `POST /feedback`，并计划于 2026-08-10 移除。请将任何直接调用 `/feedback/eager` 的集成更新为使用 `POST /feedback`。

- [Dashboards](/langsmith/dashboards) 图表的 tooltip 和坐标轴现在最多显示 8 位小数（此前为 2 位），因此极小的成本和比率不再被四舍五入为 0。

### Automations

- 打开或关闭在线 evaluator 或 automation 时，现在任何有权编辑 rules 的角色都可以成功保存，而不会再对没有 retention-configuration 权限的成员静默回滚。

### Tracing

- LangSmith 现在会对单个项目和用户执行用户自定义的每月 trace 上限。超过配置上限的新 traces 会被拒绝，而对已接受 traces 的 patch 和 feedback 仍然可以继续流转。
- Tracing 和 evaluation onboarding quickstarts 现在会为自带云数据平面的工作区显示正确的 `LANGSMITH_ENDPOINT`，而不是共享的多租户 endpoint。

- 当项目已有 traces，但当前过滤条件或时间窗口中没有近期 runs 时，项目不再错误显示 onboarding 页面。项目 run-count 检查现在会回看 30 天，而不是之前的 1 小时时间窗。

- 当提交重复的 run create 或 update payload 时，LangSmith 现在会返回更清晰的 409 Conflict 消息。消息会在可能时指出这是重复的 run create 还是 run update 请求。
- 获取 runs 或 thread history 的 LangSmith [MCP tools](/langsmith/langsmith-mcp-server) 现在除了项目名外，也接受 `project UUIDs`，让基于 trace URL 的排查更快、更不容易出错。
