Decision model evaluator 使用 [decision model](/langsmith/online-evaluations-decision-models#decision-models) 作为 judge。你定义的每个问题都会返回一个带类型的答案，LangSmith 会将它记录在自己的 feedback key 下。

本指南介绍如何在 [LangSmith UI](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=langsmith-decision-model-evaluator) 中或[通过 API](#create-the-evaluator-with-the-api) 定义 decision model evaluator。你可以在 dataset 上使用它以[在 experiments 上自动运行 evaluations](/langsmith/bind-evaluator-to-dataset)，也可以在 tracing project 上将其用作 [online evaluator](/langsmith/online-evaluations-decision-models)。要改为使用 LLM 作为 judge，请参阅 [How to define an LLM-as-a-judge evaluator](/langsmith/llm-as-judge)。

<Note>
你可以在 LangSmith UI 中或使用 [LangSmith REST API](#create-the-evaluator-with-the-api) 创建 decision model evaluators。LangSmith SDKs 暂不支持创建它们。
</Note>

<Note>
Decision model evaluators 需要 LangSmith Plus 或 Enterprise [方案](/langsmith/pricing-plans)。这些 evaluators 在 [BYOC](/langsmith/byoc) 部署中不可用。
</Note>

## Step 1. 创建 evaluator

Decision model evaluator 只提供 decision model providers，而 LLM-as-a-judge evaluator 只提供 LLM providers。要在 LLM judge 和 decision model 之间切换，请创建一个新的 evaluator。

要创建 decision model evaluator：

1. 为你的 decision model provider 添加 API key。在 LangSmith 中，前往 **Settings > Integrations > Provider secrets** 并点击 **+ Secret**：
   - 对于 OpenAI，选择 **OpenAI** 并粘贴你的 OpenAI API key。LangSmith 会将其存储为 workspace secret `OPENAI_API_KEY`。
   - 对于 TypeSafe，选择 **TypeSafe** 并粘贴来自你的 TypeSafe 账户的 key。LangSmith 会将其存储为 workspace secret `TYPESAFE_API_KEY`。

   要以其他名称存储 key，请选择 **Custom** 并输入你自己的 secret 名称。更多信息请参阅[添加 provider key](/langsmith/llm-gateway-provider-authentication#add-a-provider-key)。
1. 在 LangSmith UI 中，打开某个 dataset 或 tracing project 的 **Evaluators** 标签页并点击 **+ Evaluator**。
1. 在 **Configure Evaluator** 面板中，在 **Create from scratch** 下选择 **Decision Model Evaluator**。
1. 为你的 evaluator 命名。

## Step 2. 配置 evaluator

Decision model evaluators 支持 OpenAI 和 TypeSafe decision models，采用 bring-your-own-key (BYOK) 方式。你在 evaluator 本身中定义 state 和 questions。Decision model evaluators 不能从 [Prompt Hub](/langsmith/prompt-context-hub#prompts) 加载 prompt，也不能使用自定义 output schema。它们也不支持 [few-shot examples](/langsmith/create-few-shot-evaluators)。要在另一个 dataset 或 tracing project 上复用某个 decision model evaluator，请在 **Configure Evaluator** 面板中选择 **Attach an existing evaluator**。

### Model

在 **Prompt & Model** 下，打开 **Model Configuration** 并选择一个 provider 和 model：

- 对于 OpenAI，选择 **OpenAI** 作为 provider，然后选择一个 decision model。如果你的 key 以 `OPENAI_API_KEY` 之外的名称存储，请在 **API Key Name** 中输入该名称。点击 **Apply**。
- 对于 TypeSafe，选择 **TypeSafe** 作为 provider，然后选择一个 Jev model。如果你的 key 以 `TYPESAFE_API_KEY` 之外的名称存储，请在 **API Key Name** 中输入该名称。点击 **Apply**。
- 对于 OpenAI-Decisions-compatible endpoint 或 TypeSafe-compatible endpoint，选择其保存的配置。请参阅 [Use a compatible endpoint](#use-a-compatible-endpoint)。

<Tip>
如果 trace 过大，超出了 Jev 的上下文限制，请打开 Jev model configuration，并在 **Extra Headers** 下添加值为 `true` 的 `TypeSafe-Danger-Zone-Long-Context` header。该 header 会提高每个请求的上下文限制。关于使用和不使用该 header 时的限制，请参阅 TypeSafe 文档中的 [Long context](https://docs.typesafe.ai/models#long-context)。
</Tip>

受支持的 models 请参阅 [Supported models](/langsmith/online-evaluations-decision-models#supported-models)。

#### 使用 compatible endpoint

Compatible endpoint 将 evaluator 指向任何实现了 [OpenAI Decisions API](https://developers.openai.com/api/docs/guides/decisions) 或 [TypeSafe System One API](https://docs.typesafe.ai) 的服务器。示例包括 OpenRouter 或你自己托管的 decision model。只有在你将其保存为 model configuration 之后，evaluator 才能使用它。关于设置、配置步骤和示例 base URLs，请参阅 [Connect to a compatible decision model provider](/langsmith/compatible-decision-model-provider)。

### State

**State** 是 decision model 评估的上下文。将来自你的 run 或 example 的变量映射到其中：

- 在 dataset 上，映射 input、output 或 reference output。
- 在 tracing project 上，映射 run 或 thread 变量，例如 run 的 inputs 和 outputs。

与 LLM judge 的 prompt 不同，state 不应包含评分指令。请把评分标准放在 questions 中。

Decision models 只评估文本。如果 state 包含多模态内容（例如图像），evaluator run 会失败。

### Questions

Questions 是你的 decision model evaluator 使用的评分标准。每个 question 的名称都会成为被评估的 run 或 thread 上的一个 feedback key。要定义 questions：

1. 在 **Feedback Configuration** 下，为你要评估的每个标准添加一个 question。
1. 为每个 question 输入 **Name**、选择一个 **Type**，并编写 **Instructions**。是或否问题类型在 OpenAI models 和 OpenAI-Decisions-compatible endpoints 中标记为 **Predicate**，在 TypeSafe models 和 TypeSafe-compatible endpoints 中标记为 **Noul**。
1. 为该 question 类型定义 true 和 false 的含义、选项或等级。

要以 JSON 形式编辑 questions，请点击 **Advanced**。

关于每种 question 类型返回什么以及答案如何映射到 feedback，请参阅 [Question types](/langsmith/online-evaluations-decision-models#question-types) 和 [Map answers to feedback keys](/langsmith/online-evaluations-decision-models#map-answers-to-feedback-keys)。

## Step 3. 保存 evaluator

要保存 evaluator，请点击 **Create** 或 **Save**。

在 dataset 上，evaluator 会在每个新 experiment 上运行。在 tracing project 上，它会评估匹配其过滤条件的传入 runs 或 threads。关于过滤条件、采样率和回填，请参阅 [Set up decision model online evaluators](/langsmith/online-evaluations-decision-models)。

## 通过 API 创建 evaluator

要在单个请求中创建 decision model evaluator 并将其挂载到 dataset 或 tracing project，请向 `/api/v1/runs/rules/decision-models` 端点发送 `POST` 请求。该端点支持 Jev、SemIf 和 OpenAI decision models。每个 question 的 key 都会成为一个 feedback key。

发送请求之前，请按 [Step 1](#step-1-create-the-evaluator) 所述，将 provider 的 API key 添加为 workspace secret。

以下请求在 dataset 上创建一个 Jev evaluator。将 `LANGSMITH_API_KEY` 设为你的 LangSmith API key，将 `LANGSMITH_WORKSPACE_ID` 设为包含该 dataset 的 workspace ID，并将 `<your-dataset-id>` 替换为要评估的 dataset ID：

```bash
curl -X POST 'https://api.smith.langchain.com/api/v1/runs/rules/decision-models' \
  -H 'Content-Type: application/json' \
  -H "X-API-Key: $LANGSMITH_API_KEY" \
  -H "X-Tenant-Id: $LANGSMITH_WORKSPACE_ID" \
  -d '{
    "display_name": "answer-quality",
    "dataset_id": "<your-dataset-id>",
    "prompt": [["human", "Question: {{input}}\nAnswer: {{output}}"]],
    "variable_mapping": {"input": "input", "output": "output"},
    "provider": "typesafe",
    "model": "jev-latest",
    "questions": {
      "helpful": {
        "type": "noul",
        "instructions": "Does the answer address the question?",
        "yes": "It answers the question",
        "no": "It does not"
      },
      "tone": {
        "type": "choice",
        "instructions": "What is the tone of the answer?",
        "options": ["formal", "casual"]
      },
      "quality": {
        "type": "score",
        "instructions": "Rate the overall quality of the answer.",
        "levels": ["poor", "ok", "great"]
      }
    }
  }'
```

请求体接受以下字段：

- **`display_name`**：evaluator 名称。必填。
- **`dataset_id`** 或 **`session_id`**：要评估其 experiments 的 dataset，或要评估其 runs 的 tracing project。
- **`prompt`**：decision model 读取的 [state](#state)，以 `[role, template]` 对组成的列表表示。必填。
- **`template_format`**：`mustache`（默认）或 `f-string`。
- **`variable_mapping`**：将每个 prompt 变量映射到 run 或 example 字段，例如 `input` 或 `output`。请映射 prompt 中的每个变量。API 接受不带映射的请求，但在映射所有变量之前，LangSmith UI 无法测试或保存该 evaluator。
- **`questions`**：以 feedback key 为键、按提问顺序排列的 [questions](#questions)。必填。每个 question 都有 `type` 和 `instructions`：
  - **`noul`**：评分从 0 到 1 的是或否问题。可选择同时设置 `yes` 和 `no`，说明每个答案的含义。
  - **`choice`**：2 到 255 个 `options` 之一，以名称列表或名称到说明的映射给出。
  - **`score`**：2 到 10 个 `levels` 之一，从最低开始列出，按位置评分。
- **`provider`**：Jev 和 SemIf 使用 `typesafe`（默认），TypeSafe-compatible endpoint 使用 `typesafe_compatible`，或使用 `openai_decisions`。
- **`model`**：`typesafe` 默认为 `jev-latest`，`openai_decisions` 默认为 `gpt-6-luna`。SemIf 请使用 `semif-qwen3.5-4b`。
- **`base_url`**：直接调用的 model endpoint，而不是通过 LangSmith gateway 调用，使用 workspace 的 `TYPESAFE_API_KEY` 或 `OPENAI_API_KEY` secret。`typesafe_compatible` 必填。
- **`model_headers`**：每次 model 调用时发送的 headers，例如 `TypeSafe-Danger-Zone-Long-Context`。LangSmith 会按原样将它们保存在 evaluator 的 prompt 中，因此不要在其中放置 API key。
- **`timeout_seconds`**：每次 model 调用等待的秒数。仅适用于 `openai_decisions`。
- **`max_retries`**：失败的 model 调用重试次数。仅适用于 `openai_decisions`。

完整 schema（包括采样率、过滤条件和保存的 model configurations），请参阅 API 参考中的 [Create decision model rule](/langsmith/smith-api/run/create-decision-model-rule)。
