发送来自团队 coding agents（例如 Claude Code、Codex 和 Cursor）的 traces，以查看每个 coding agent 的成本。连接 GitHub 或 GitLab，将每个 [thread](/langsmith/threads) 关联到它打开的 pull request，从而查看每个 pull request 背后的支出。当图表显示某个 pull request 或某个用户的支出较为突出时，打开该支出背后的 threads，查看该 coding agent 做了什么。

<Note>
Coding agent 类型处于 [beta](/langsmith/release-stages) 阶段。它需要[基于 agent 的工作区](/langsmith/agent-registry)，该工作区在 LangSmith Cloud 上可用，自托管的 LangSmith 不支持。
</Note>

## 设置

pull request 连接以及 agent Overview 上的 coding 图表仅出现在类型为 Coding 的 agent 上。

### 创建类型为 Coding 的 agent

如果你使用官方 LangSmith 插件将 traces 发送到尚不存在的 agent ID，LangSmith 会创建该 agent 并将其类型设置为 **Coding**。遵循 [Coding agent metadata contract](/langsmith/coding-agent-metadata-contract) 的集成也会获得相同的行为。

如需自行设置类型，请在[创建 agent](/langsmith/create-an-agent) 时将 **Agent type** 设置为 **Coding**。

更改现有 agent 的类型需要具备管理工作区设置的权限。要更改类型，请点击 agent Overview 上的 **Agent settings** <Icon icon="settings"/> 图标，然后选择 **Change agent type**。

### 将 traces 发送到 agent

为团队使用的每个 coding agent 设置 tracing，并将其 traces 发送到类型为 Coding 的 LangSmith agent。每份指南都会说明如何将 traces 发送到该 agent。

你可以将所有 coding agent 的 traces 发送到一个 LangSmith agent。这样就能对每个 coding agent 运行相同的 [evaluators](/langsmith/evaluators)，并按 harness（即 coding agent，例如 Claude Code）进行比较。

| Coding agent | 设置 tracing |
|---|---|
| Claude Code | [安装插件](/langsmith/trace-claude-code#install-the-plugin) |
| OpenAI Codex | [安装插件](/langsmith/trace-with-codex#install-the-plugin) |
| Cursor | [安装插件](/langsmith/trace-with-cursor#install-the-plugin) |
| GitHub Copilot | [配置 tracing](/langsmith/trace-with-vscode-copilot#configure-tracing) |
| Deep Agents Code | [使用 LangSmith 进行 trace](/oss/deepagents/code/quickstart#trace-with-langsmith) |

要跟踪每位工程师的会话，管理员可以使用移动设备管理（MDM）工具安装 Claude Code、Codex 和 Cursor 插件，并锁定 traces 所发往的 agent 和工作区。关于托管文件以及可锁定的设置，请参阅 [Claude Code](/langsmith/trace-claude-code#lock-settings)、[Codex](/langsmith/trace-with-codex#lock-settings) 和 [Cursor](/langsmith/trace-with-cursor#lock-settings) 的锁定设置。

<a id="connect-github-or-gitlab"></a>

### 连接 GitHub 或 GitLab

pull request 跟踪使用与 [LangSmith Engine](/langsmith/engine) 相同的 GitHub 和 GitLab 连接。连接账户需要具备更新该 agent 所有环境的权限。每个 provider 还有各自的要求：

- **GitHub**：首次安装 GitHub App 需要具备在你的 repository 上安装它的权限，你的 GitHub 组织可能还要求管理员批准。如果你已将 repository 连接到 Engine，这些 installation 会显示在连接对话框中，你无需再次授权 GitHub 即可关联它们。
- **GitLab**：由工作区管理员在工作区设置中连接账户。

详情请参阅[将 repository 连接到 Engine](/langsmith/engine-repositories)。

在 BYOC 和自托管 LangSmith 上，GitHub 连接使用管理员为当前 LangSmith 实例注册的 Engine GitHub App。将 GitHub 连接到 coding agent 前，请先设置该 App。详见[为自托管和 BYOC 上的 Engine 配置 GitHub](/langsmith/engine-self-hosted-github)。

在 agent Overview 上，点击 **Track pull requests** 并连接 GitHub 或 GitLab 账户。你可以复用已连接到工作区中另一个 agent 的 installation。

当 GitHub 或 GitLab 报告 pull request 上有活动（例如打开、更新或合并）时，LangSmith 会关联该 pull request。它会关联那些在 Git 元数据中记录了该 pull request 的 repository 和源 branch 的 traces 对应的 threads。在你连接之前已合并的 pull request 不会出现。随着开发者打开和合并 pull request，Time to merge、cost per merged pull request 以及 pull request 卡片会逐步填充数据。

如果某个 pull request 没有显示任何 thread，请检查其 traces 是否记录了 repository 和 branch：

- **GitHub Copilot**：仅在 [Local harness](/langsmith/trace-with-vscode-copilot#choose-your-harness) 上记录，且仅适用于具有 Git remote 的文件夹。
- **Deep Agents Code**：除非你[关闭 Git trace 归属](/oss/deepagents/code/config-file#disable-git-trace-attribution)，否则会记录这些信息。

## 查看 agent Overview

顶部的摘要卡片会将每个指标与上一个周期进行比较：

- **始终显示**：**LLM cost**、**Threads** 和 **Turns / thread**。
- **连接 GitHub 或 GitLab 之前**：**Tokens** 和 **Cost / 1M tokens**。
- **连接之后**：**Cost / merged PR**、**Cache rate** 和 **Time to merge**，其中 **Time to merge** 还会显示 merge rate。它们会取代 **Tokens** 和 **Cost / 1M tokens**。

选择一张卡片，即可将该指标随时间的变化绘制成图表。你可以按 pull request 状态、user、user group、Git user、repo、harness、provider、model 或 metadata key 等维度对图表进行分组。点击某个柱条或类别，可打开其背后 threads 的筛选视图。

在摘要下方，Overview 会显示以下卡片：

- **Work type**：按请求的工作类型划分的 threads：feature、bugfix、refactor、investigation、review 或 off topic。此卡片需要预构建的 Coding Work Type evaluator，并会引导你完成设置。
- **Skill usage**：coding agents 调用了哪些 skills。
- **Cost per PR by state**：open、closed 和 merged pull request 的平均成本。
- **Top PRs by cost**：时间范围内成本最高的 pull request，以及每个 pull request 的状态、作者、threads、turns 和成本。每行都会链接到该 pull request。
- **Cost by conversation length**：按 turns 数量分组的 threads，以及总成本、每个 thread 和每个 turn 的平均成本。

## 示例用法

### 查找成本高昂的 pull request

使用 **Top PRs by cost** 查找成本最高的 pull request。打开某个 pull request 的 threads，查看其背后的 models 和 user。

### 检查更短 thread 的效果

每个新的 turn 都会发送此前的对话，因此长 thread 的每个 turn 成本更高。如果你要求工程师更频繁地开启新 thread，可使用 **Cost by conversation length** 检查长 thread 是否变少。

### 比较 models

当团队切换 models 时，按 model 对成本随时间的变化进行分组，以比较切换前后的支出。在同一时间范围内查看 **Time to merge** 卡片上的 merge rate，了解 pull request 是否仍会被合并。
