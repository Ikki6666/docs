预置完成后，LangChain 会运维你的 data plane，包括升级、扩缩容、监控和安全修补。大多数维护都是非中断性的，不需要你执行任何操作。

## 自动扩缩容

LangChain 会随负载变化对你的 data plane 进行扩缩，因此你无需手动设置容量或调优：

- **无状态 LangSmith 服务**：通过 horizontal pod autoscaler 进行水平扩缩，并由 Karpenter 随 pod 需求变化预置和移除节点容量。
- **数据库**：RDS 和 ElastiCache 的容量设置与扩缩由 LangChain 负责。

## 高可用性

data plane 默认按高可用性预置。部署会横跨你所在 region 的多个可用区，RDS 和 ElastiCache 以 Multi-AZ 模式运行并支持自动故障转移。

<Note>
如果要在没有高可用性的情况下运行 data plane，请联系 LangChain 团队。
</Note>

## 实例规格

data plane 的数据库和 node group 默认按默认实例规格预置。如果要在更小的实例上运行 data plane，请联系 LangChain 团队。

## LangSmith 升级

LangChain 每天都会升级你 data plane 中的 LangSmith 版本。升级以滚动方式进行，逐个副本替换，因此不会出现整个服务停机。

有两个机制确保升级不造成停机：

- **Horizontal pod autoscaling**：LangSmith 服务运行多个副本，副本数由 horizontal pod autoscaler 决定，因此 pod 会一次被替换几个，其余副本继续处理流量。
- **Pod disruption budget**：pod disruption budget 限制一个服务同时不可用的副本数量，因此无论是滚动更新还是节点排空，都不会让服务低于保持可用所需的容量。

## 支持服务的升级

Istio、KEDA 和 ClickHouse operator 等后台服务会按固定节奏升级。这些升级是非侵入式的，预计不会造成服务中断。

## Kubernetes 集群升级

承载你 data plane 的 EKS 集群需要定期升级，以维持安全性、兼容性并获得新功能。LangChain 会主动执行这些升级，赶在 AWS 支持终止日期之前完成，并与你协调升级窗口。

集群升级分为两类：

- **Control plane 升级**：覆盖 Kubernetes API server 以及由 AWS 一并管理的组件。这些升级对你的工作负载是透明的，不会重启 pod。
- **Node group 升级**：以 make-before-break 语义逐个节点滚动。新节点在更新后的版本上预置，pod 迁移到新节点，旧节点在迁移完成后被终止。pod disruption budget 适用于节点排空过程，因此每个服务都保持可用，但在单个 pod 重启时你可能会看到短暂的连接重置。不会丢失数据。

## 维护窗口

任何可能导致停机的维护或升级（例如重启 RDS 或 ElastiCache）都会在计划维护窗口内进行，该窗口由 LangChain 提前与你协调确定。

## 可观测性

你可以在集群中部署可观测性工具（例如 Datadog agent 或 OpenTelemetry collector）以及你自己的安全监控 agent，前提是它们不会干扰 LangSmith 工作负载。

LangSmith 服务发出日志、指标和 traces 的方式与自托管时相同，因此适用相同的配置。参见[将 LangSmith 遥测数据导出到你的可观测性 backend](/langsmith/export-backend)。

## 故障排查

LangChain 团队没有对你数据的长期访问权限，只能管理你 data plane 的基础设施。当故障排查需要访问数据时，有两条路径：

- **由你执行查询**：你自己运行查询，并在与 LangChain 共享之前验证和清理输出。
- **Break-glass 访问（紧急访问）**：你将某位特定工程师加入允许名单来执行该操作。你可以随时撤销该访问权限。

<Note>
如果需要 break-glass 访问，LangChain 团队会主动联系你并提供操作说明。
</Note>

## 审计

- **LangSmith 审计日志**：对 data plane 资源的操作会记录在 data plane 中，并可在你的 data plane endpoint 访问。Control plane 操作（例如创建用户）则在 control plane 中审计。有关如何访问两者，请参阅[审计日志](/langsmith/audit-logs)。
- **EKS 审计日志**：发送到你账户中的 CloudWatch，因此你可以监控执行过的命令。
- **VPC flow logs**：记录在你账户中的 S3 存储桶里。使用 [BYOVPC](/langsmith/byoc-byovpc) 时，VPC flow logs 由你自己配置。

针对这些日志设置告警是你的责任。
