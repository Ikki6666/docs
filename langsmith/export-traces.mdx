推荐使用 [SDK](https://reference.langchain.com/python/langsmith/) 中的 `runs.query` 方法，或 [API](/langsmith/smith-api-ref) 中的 `POST /api/v2/runs/query` 端点，来查询 [runs](/langsmith/observability-concepts#runs)（也就是 LangSmith traces 中的 span 数据）。LangSmith 以一种简单格式存储 traces，该格式定义见 [Run（span）数据格式](/langsmith/run-data-format)。

本页涵盖以下内容：

- [使用 filter 参数](#use-filter-arguments)：通过 SDK 参数进行基于关键字的筛选。
- [使用过滤查询语言](#use-filter-query-language)：使用 LangSmith 过滤语法编写复杂查询。
- [使用子 run 谓词查询 trace trees](#query-trace-trees-with-child-run-predicates)：结合服务端收窄范围与每条 trace 的 runs。
- [速率限制](#rate-limits)：限制与最佳实践。

<Note>
如果你想导出大量 traces，建议使用 [Bulk Data Export](/langsmith/data-export)。它对大数据量处理更稳健，并支持自动重试与分区并行。
</Note>

<Note>
`runs.query` 取代了已弃用的 `list_runs` / `listRuns` 和 `read_run` / `readRun`。LangSmith Cloud 将于 2027 年 1 月 31 日移除这些方法，自托管 LangSmith 将在 v0.19 中移除这些方法。新方法要求 `langsmith>=0.10.15`（Python）或 `langsmith>=0.8.9`（TypeScript），在自托管 LangSmith 上还要求 v0.16 或更高版本。完整的变更列表请参阅[迁移指南](/langsmith/smithdb-sdk-migration-query-runs)。
</Note>

<Note>
要查询某个 agent、某个 experiment 或 evaluators 的 traces，请[查找其 project ID](/langsmith/resolve-an-agent)，并将其作为 project ID 传入。
</Note>

## 使用 filter 参数

对于简单查询，你不必依赖查询语法，可以直接使用 [filter 参数参考](/langsmith/trace-query-syntax#filter-arguments)中列出的 filter 参数。

<Warning>
**前置条件**

运行下面的代码片段之前，请先初始化 client、查找 project ID，并设置时间窗口：

- `runs.query` 接收 project ID，而不是 project 名称。
- 除非传入 `min_start_time`，否则它只回溯 **1 天**。下面的代码片段使用 7 天窗口。单次查询最多可跨越 401 天。
- 除非传入 `selects`（大写字段名，例如 `NAME`、`INPUTS`、`OUTPUTS`），否则它只返回 run 的 `ID`。
- 在 Python 中，`client.runs` 是异步的：请在 `async` 函数内运行代码片段，例如配合 `asyncio.run()`。每次查询都会返回一个异步迭代器，自动为你分页获取结果。
</Warning>

<CodeGroup>

```python Python
from datetime import datetime, timedelta, timezone

from langsmith import Client

client = Client()
project_id = str(client.read_project(project_name="<your_project>").id)
since = datetime.now(timezone.utc) - timedelta(days=7)
```

```typescript TypeScript
import { Client } from "langsmith";

const client = new Client();
const projectId = (await client.readProject({ projectName: "<your_project>" })).id;
const since = new Date(Date.now() - 7 * 24 * 60 * 60 * 1000).toISOString();
```

## 使用过滤查询语言

如果查询更复杂，可以使用过滤查询语言。以下示例覆盖了最常见的模式。完整的运算符和字段参考，包括全部比较器、可筛选字段、取值格式规则以及速查示例表，请参阅 [Trace query syntax: filter query language](/langsmith/trace-query-syntax#filter-query-language)。

### 列出会话 thread 中的所有 root runs

这是获取某个会话 thread 中 runs 的方式。关于如何设置 threads，请参阅[设置 threads 的操作指南](/langsmith/threads)。如需直接列出 threads 及其 traces，请参阅[查询 threads](/langsmith/query-threads)。
Threads 是通过共享 thread ID 进行分组的。LangSmith UI 允许使用以下任一 metadata key：`session_id` 或 `thread_id`。其中 session ID 也叫 tracing project ID。下面的查询会匹配这两者中的任意一种。

<CodeGroup>

```python Python
group_key = "<your_thread_id>"
filter_string = f'and(in(metadata_key, ["session_id","thread_id"]), eq(metadata_value, "{group_key}"))'
thread_runs = client.runs.query(
    project_ids=[project_id],
    min_start_time=since,
    filter=filter_string,
    is_root=True,
)
```

```typescript TypeScript
const groupKey = "<your_thread_id>";
const filterString = `and(in(metadata_key, ["session_id","thread_id"]), eq(metadata_value, "${groupKey}"))`;
const threadRuns = client.runs.query({
  project_ids: [projectId],
  min_start_time: since,
  filter: filterString,
  is_root: true,
});
```

```java Java
String groupKey = "<your_thread_id>";

String filterString = String.format(
    "and(in(metadata_key, [\"session_id\",\"thread_id\"]), eq(metadata_value, \"%s\"))",
    groupKey
);

RunQueryV2Params threadRuns = RunQueryV2Params.builder()
    .addProjectId(projectId)
    .minStartTime(since)
    .filter(filterString)
    .isRoot(true)
    .build();
```

</CodeGroup>

### 检查 metadata 是否存在

如果你想检查某个 metadata 是否存在，可以使用 `eq` 运算符，并可结合 `and` 同时匹配值。这适合在 run 中记录更结构化信息后再进行筛选。

<CodeGroup>

```python Python
# Check for any run with the "user_id" metadata key
client.runs.query(
    project_ids=[project_id],
    min_start_time=since,
    filter="eq(metadata_key, 'user_id')",
)
# Check for runs with user_id=4070f233-f61e-44eb-bff1-da3c163895a3
client.runs.query(
    project_ids=[project_id],
    min_start_time=since,
    filter="and(eq(metadata_key, 'user_id'), eq(metadata_value, '4070f233-f61e-44eb-bff1-da3c163895a3'))",
)
```

```typescript TypeScript
// Check for any run with the "user_id" metadata key
client.runs.query({
  project_ids: [projectId],
  min_start_time: since,
  filter: `eq(metadata_key, 'user_id')`,
});
// Check for runs with user_id=4070f233-f61e-44eb-bff1-da3c163895a3
client.runs.query({
  project_ids: [projectId],
  min_start_time: since,
  filter: `and(eq(metadata_key, 'user_id'), eq(metadata_value, '4070f233-f61e-44eb-bff1-da3c163895a3'))`,
});
```

```java Java
RunQueryV2Params runsWithUserId = RunQueryV2Params.builder()

    .minStartTime(since)
    .filter("eq(metadata_key, 'user_id')")
```

## 使用子 run 谓词查询 trace trees

使用 `trace_filter` 可以匹配 root run 上的字段，使用 `tree_filter` 可以匹配 trace tree 中任意 run 上受支持的可搜索字段。如果你需要针对任意返回的子 run 字段应用谓词，例如嵌套的 `inputs`、`outputs` 或 `extra` 载荷，请按以下步骤进行：

1. 先在服务端使用 `filter`、`trace_filter`、`tree_filter`、`run_type`、metadata 过滤器以及 `ls_run_depth` [system metadata key](/langsmith/ls-metadata-parameters#ls_run_depth) 来收窄候选 root traces。
2. 使用 `traces.list_runs` / `traces.listRuns` 获取每个候选 trace 的 runs。
3. 在本地对那些无法作为服务端过滤字段使用的内容应用你的谓词。

下面这个示例会返回这样的 root traces：其中包含某个工具 run，且该工具 run 的 output 含有特定值。服务端的 `tree_filter` 先把候选范围收窄到包含该工具 run 的 traces，然后本地谓词再检查 `outputs` 载荷。

<CodeGroup>

```python Python
import asyncio
from datetime import datetime, timedelta, timezone

from langsmith import Client


async def main():
    client = Client()
    project_id = str(client.read_project(project_name="<your_project>").id)

    matching_trace_ids = []
    async for candidate in client.runs.query(
        project_ids=[project_id],
        min_start_time=datetime.now(timezone.utc) - timedelta(days=7),
        is_root=True,
        tree_filter='and(eq(run_type, "tool"), eq(name, "<tool_name>"))',
        selects=["TRACE_ID"],
    ):
        response = await client.traces.list_runs(
            str(candidate.trace_id),
            project_id=project_id,
            selects=["NAME", "RUN_TYPE", "OUTPUTS"],
        )
        if any(
            run.run_type == "tool"
            and run.name == "<tool_name>"
            and "<expected_value>" in str(run.outputs or {})
            for run in response.items
        ):
            matching_trace_ids.append(candidate.trace_id)


asyncio.run(main())
```

```typescript TypeScript
import { Client } from "langsmith";

const client = new Client();
const projectId = (await client.readProject({ projectName: "<your_project>" })).id;

const matchingTraceIds: string[] = [];
for await (const candidate of client.runs.query({
  project_ids: [projectId],
  min_start_time: new Date(Date.now() - 7 * 24 * 60 * 60 * 1000).toISOString(),
  is_root: true,
  tree_filter: 'and(eq(run_type, "tool"), eq(name, "<tool_name>"))',
  selects: ["TRACE_ID"],
})) {
  const response = await client.traces.listRuns(candidate.trace_id!, {
    project_id: projectId,
    selects: ["NAME", "RUN_TYPE", "OUTPUTS"],
  });
  const hasMatchingChild = (response.items ?? []).some(
    (run) =>
      run.run_type === "tool" &&
      run.name === "<tool_name>" &&
      JSON.stringify(run.outputs ?? {}).includes("<expected_value>"),
  );
  if (hasMatchingChild) {
    matchingTraceIds.push(candidate.trace_id!);
  }
}
```

### 高级：导出扁平化的 trace 视图，并带上子工具使用情况

下面的 Python 示例展示了如何导出 traces 的扁平化视图，并包含每条 trace 内 agent 使用过的工具信息（来自嵌套 runs）。
这适合用来分析 agents 在多条 traces 中的行为。

这个示例会查询指定天数范围内的所有工具 runs，并按其 trace ID 分组。然后它为每个 root run 拉取相关信息，例如 run 名称、inputs、outputs，并把这些信息与子 run 信息组合在一起。

为了优化查询，该示例：

1. 查询工具 runs 时只选择必要字段，从而减少查询耗时。
2. 按 ID 分批拉取 root runs。root run 的 ID 就是它的 trace ID。

<CodeGroup>

```python Python
import asyncio
from collections import defaultdict
from datetime import datetime, timedelta, timezone

from langsmith import Client


async def main():
    client = Client()
    project_id = str(client.read_project(project_name="my-project").id)
    num_days = 30
    since = datetime.now(timezone.utc) - timedelta(days=num_days)

    # Collect all tools invoked within each trace
    tools_by_trace = defaultdict(set)
    async for run in client.runs.query(
        project_ids=[project_id],
        min_start_time=since,
        run_type="TOOL",
        # We don't need inputs, outputs, and other values that may increase the query time
        selects=["TRACE_ID", "NAME"],
    ):
        tools_by_trace[str(run.trace_id)].add(run.name)

    # Fetch the root runs in batches
    data = []
    trace_ids = list(tools_by_trace)
    trace_batch_size = 50
    for i in range(0, len(trace_ids), trace_batch_size):
        async for root_run in client.runs.query(
            project_ids=[project_id],
            min_start_time=since,
            ids=trace_ids[i : i + trace_batch_size],
            selects=["ID", "NAME", "RUN_TYPE", "INPUTS", "OUTPUTS"],
        ):
            data.append(
                {
                    "run_id": root_run.id,
                    "run_name": root_run.name,
                    "run_type": root_run.run_type,
                    "inputs": root_run.inputs,
                    "outputs": root_run.outputs,
                    "tools_involved": list(tools_by_trace[str(root_run.id)]),
                }
            )
    return data


data = asyncio.run(main())

# (Optional): Convert to a pandas DataFrame
import pandas as pd

df = pd.DataFrame(data)
df.head()
```

### 高级：导出带有反馈的 traces 中的 retriever 输入输出

如果你想基于 retriever 行为来微调 embeddings，或者诊断端到端系统表现，这类查询会很有帮助。
下面的 Python 示例展示了如何导出带有特定反馈分数的 traces 中，retriever 的 inputs 和 outputs。

<CodeGroup>

```python Python
import asyncio
from collections import defaultdict
from datetime import datetime, timedelta, timezone

from langsmith import Client


async def main():
    client = Client()
    project_id = str(client.read_project(project_name="your-project-name").id)
    num_days = 1
    since = datetime.now(timezone.utc) - timedelta(days=num_days)

    # List all retriever runs in traces with "user_score" feedback
    retriever_data = defaultdict(lambda: defaultdict(list))
    async for run in client.runs.query(
        project_ids=[project_id],
        min_start_time=since,
        run_type="RETRIEVER",
        # This time we do want to fetch the inputs and outputs, since they
        # may be adjusted by query expansion steps.
        selects=["TRACE_ID", "INPUTS", "OUTPUTS"],
        trace_filter='eq(feedback_key, "user_score")',
    ):
        for k, v in (run.inputs or {}).items():
            retriever_data[str(run.trace_id)][f"retriever.inputs.{k}"].append(v)
        for k, v in (run.outputs or {}).items():
            retriever_data[str(run.trace_id)][f"retriever.outputs.{k}"].extend(v)

    # Fetch the root runs, with their feedback, in batches
    data = []
    trace_ids = list(retriever_data)
    trace_batch_size = 50
    for i in range(0, len(trace_ids), trace_batch_size):
        async for root_run in client.runs.query(
            project_ids=[project_id],
            min_start_time=since,
            ids=trace_ids[i : i + trace_batch_size],
            selects=["ID", "NAME", "INPUTS", "OUTPUTS", "FEEDBACK_STATS"],
        ):
            feedback = {
                f"feedback.{k}": v.avg
                for k, v in (root_run.feedback_stats or {}).items()
            }
            inputs = {f"inputs.{k}": v for k, v in (root_run.inputs or {}).items()}
            outputs = {f"outputs.{k}": v for k, v in (root_run.outputs or {}).items()}
            data.append(
                {
                    "run_id": root_run.id,
                    "run_name": root_run.name,
                    **inputs,
                    **outputs,
                    **feedback,
                    **retriever_data[str(root_run.id)],
                }
            )
    return data


data = asyncio.run(main())

# (Optional): Convert to a pandas DataFrame
import pandas as pd

df = pd.DataFrame(data)
df.head()
```

## 速率限制

`runs.query`（`POST /api/v2/runs/query`）有独立的速率限制，且高于已弃用的 `POST /runs/query` 端点：在 LangSmith Cloud 中，每个 API key 每 10 秒 300 次请求。超过限制的请求会返回 `429 Too Many Requests`。它不受已弃用端点按租户限制的约束。通用最佳实践请参阅 [Run query 端点速率限制](/langsmith/usage-and-billing#run-query-endpoint)。
