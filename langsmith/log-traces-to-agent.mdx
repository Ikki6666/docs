_Agent addressing_ 指定一条 trace 所属的 [agent](/langsmith/agents) 和 [environment](/langsmith/agent-environments)。你的应用在每次 run 中都发送这两者，LangSmith 会在 trace 到达时记录它们。一条 trace 使用 agent addressing 或 [project addressing](/langsmith/log-traces-to-project) 之一，绝不会同时使用两者。

<Note>
Agent addressing 适用于处于 [beta](/langsmith/release-stages) 阶段的 agent-based workspaces。[`address` 参数](#addressing-arguments)可能在没有通知的情况下更改。Agent addressing 支持于：

- Python SDK，从 `langsmith>=0.14.4` 起
- TypeScript SDK，从 `langsmith>=0.10.8` 起

关于不依赖该 beta 的 tracing 设置，请参阅 [Log traces to a specific project](/langsmith/log-traces-to-project)。
</Note>

## Addressing 变量

两个环境变量承载 agent addressing：

- **`LANGSMITH_AGENT_ID`**：要指定的 agent。值是 agent 的 identifier，浏览器地址栏会携带它，agent 的 Overview 上的 **ID** 字段可以复制它。它在每次 run 中发送。
- **`LANGSMITH_AGENT_ENVIRONMENT`**：该 run 所属的 environment。与 agent 一起必需，取 `local`、`development`、`staging` 或 `production` 之一。使用小写形式，它映射到 UI 中的 Local、Development、Staging 和 Production 标签。没有默认值，因为单独的 agent 或 environment 都无法确定一个目的地。如果只设置了两个变量之一，SDK 会记录一条警告并让该调用不被 trace，而不是替你挑选一个 environment，因此不会有任何内容到达 LangSmith。

`LANGSMITH_AGENT_ID` 接受 identifier，而不是 display name。[Display name 是一个单独的、可编辑的值](/langsmith/agents#identifiers-and-display-names)，不必与 identifier 一致，因此请从 agent 本身读取 identifier，而不是从 agent 的名称推导它。

## Addressing 参数

将 agent 和 environment 一起提供，作为代码中的一个 address，或同时作为两个[环境变量](#addressing-variables)。一个 address 是单个字符串，`lrn:agents/{id}/environments/{environment}`。在 Python 中用 `ls.address.agent("checkout", "production")` 构建，或在 TypeScript 中用 `address.agent("checkout", "production")` 构建，它们会检查两个值并将 environment 小写化，或者直接编写该字符串。

在 Python 中，[`@traceable`](https://reference.langchain.com/python/langsmith/run_helpers/traceable) 和 [`tracing_context`](https://reference.langchain.com/python/langsmith/run_helpers/tracing_context) 都接受 `address`。在 TypeScript 中，[`traceable`](https://reference.langchain.com/javascript/langsmith/traceable) 在其 config 中接受 `address`。代码中的 address 优先于变量。只有当代码中没有指定目的地时，SDK 才读取变量，而且此时两者都需要。

## 示例

用 decorator 为一个函数指定 address：

```python
import langsmith as ls
from langsmith import traceable

@traceable(address=ls.address.agent("checkout", "production"))
def handle_order(order_id: str) -> dict:
    return {"order_id": order_id, "status": "charged"}
```

用 context manager 为一个代码块内 trace 的一切指定 address：

```python
from langsmith import traceable, tracing_context

@traceable
def handle_order(order_id: str) -> dict:
    return {"order_id": order_id, "status": "charged"}

with tracing_context(address="lrn:agents/checkout/environments/production"):
    handle_order("A-1")
```

在 TypeScript 中为一个函数指定 address：

```typescript
import { address } from "langsmith";
import { traceable } from "langsmith/traceable";

const handleOrder = traceable(
  async (orderId: string) => ({ orderId, status: "charged" }),
  { name: "handle_order", address: address.agent("checkout", "production") },
);
```

## 发送你的第一条 agent-addressed trace

<Steps>
  <Step title="Confirm your workspace is enabled">
    如果你的 workspace 是 agent-based 的，agent addressing 已经开启。LangChain 会开启它，你无需更改任何设置。在被 LangChain [转换](/langsmith/migrate-to-agent-based-workspaces#how-a-workspace-moves)的 workspace 中，管理员可以在新体验和经典体验之间切换 UI。该切换只改变 UI 显示的内容，它不会开启 agent addressing。

    要判断你拥有哪种 workspace，请看左上角的控件。在 agent-based workspace 中，它显示你的 workspace 名称。在 project-based workspace 中，它显示 LangSmith logo，并且 agent addressing 是关闭的。要询问访问权限，请[联系我们的销售团队](https://www.langchain.com/contact-sales)。

    如果你的 workspace 未启用，LangSmith ingestion 会拒绝 agent-addressed runs，并且不记录任何内容。
  </Step>
  <Step title="Install the SDK">
    Agent addressing 在 Python 中需要 `langsmith>=0.14.4`，在 TypeScript 中需要 `langsmith@>=0.10.8`：

    <CodeGroup>

    ```bash uv
    uv add "langsmith>=0.14.4"
    ```

    ```bash pip
    pip install -U "langsmith>=0.14.4"
    ```

    ```bash npm
    npm install "langsmith@>=0.10.8"
    ```

    </CodeGroup>
  </Step>
  <Step title="Choose an identifier">
    从一个已有 agent 的 Overview 上的 **ID** 字段复制 identifier，或选择一个新的。如果 workspace 中没有 agent 使用你选择的 identifier，LangSmith 会在你第一次向它发送 trace 时创建该 agent。你不必提前创建 agent。identifier 必须遵循的规则请参阅 [Identifier rules](/langsmith/create-an-agent#identifier-rules)。
  </Step>
  <Step title="Configure the addressing">
    设置两个 addressing [变量](#addressing-variables)，或在代码中传入一个 [address](#addressing-arguments)。如果只设置了一个变量，SDK 会记录一条警告，并且不发送任何内容。

    ```bash
    export LANGSMITH_TRACING=true
    export LANGSMITH_API_KEY=<your-api-key>
    export LANGSMITH_AGENT_ID=checkout
    export LANGSMITH_AGENT_ENVIRONMENT=production
    ```

    前两个是通常的 tracing 前置条件，而不是 agent addressing 的一部分。请使用你在步骤 1 中确认的 workspace 的 [API key](/langsmith/create-account-api-key)。
  </Step>
  <Step title="Run your application">
    运行你的应用，让它至少发送一条 trace。产生 traces 在 Python 中需要 `@traceable` 或 `tracing_context`，在 TypeScript 中需要 `traceable`，如[示例](#examples)所示。
  </Step>
  <Step title="Find the trace">
    在 LangSmith 中，在顶栏选择该 agent，前往 **Tracing**，并将 environment 控件设置为你指定的那一个。trace 会出现在那里。
  </Step>
</Steps>

## Addressing 模式互斥

Agent addressing 和 project addressing 不能组合。发生什么取决于各自在哪里设置：

- **agent 和 project 同时设置**：不允许。如果你设置了 agent 变量，还设置了 `LANGSMITH_PROJECT`、`LANGCHAIN_PROJECT` 或 `LANGCHAIN_SESSION`，这条 trace 就有两个目的地，SDK 不会替你选择。它会在客户端启动时记录一条警告，并且除非代码指定了目的地，否则不会 trace 该调用。如果你在同一次调用中同时将 `address` 和 `project_name` 传给 `@traceable` 或 `tracing_context()`，SDK 会抛出 `LangSmithUserError`，并且不发送任何内容。如果同时带有 address 和 project 的 run 到达了 LangSmith，LangSmith 会拒绝它。
- **在代码中指定 project**：覆盖 agent 变量。将 `project_name` 传给 `@traceable` 或 `tracing_context()` 会把该 run trace 到那个 project 并忽略 agent 变量，不会报错。这就是让一个 [evaluation](/langsmith/evaluation) 使用自己的 project，而 agent 变量在进程的其余部分保持设置的原因。

## 指定一个不存在的 agent

如果一个 identifier 与 workspace 中的任何 agent 都不匹配，LangSmith 会创建该 agent。

该值必须遵循的规则请参阅 [Identifier rules](/langsmith/create-an-agent#identifier-rules)。

以此方式创建的 agent 在其 [Overview](/langsmith/navigate-agents#read-the-agent-overview) 上不会显示 Deployments 部分。

## 当 runs 停止被接受

一个接受 agent-addressed runs 的 workspace 可能会停止接受它们。首先检查你的 API key 是否仍属于该 agent-based workspace，因为 LangSmith 会拒绝使用来自 project-based workspace 的 key 发送的 agent-addressed runs。如果 key 不是问题所在，请通过 [support.langchain.com](https://support.langchain.com) 联系支持团队。
