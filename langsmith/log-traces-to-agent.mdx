将 traces 记录到 agent，就是指定一条 trace 所属的 [agent](/langsmith/agents) 和 [environment](/langsmith/agent-environments)。你的应用在每次 run 中都发送这两者，LangSmith 会在 trace 到达时记录它们。一条 trace 要么发送到 agent，要么发送到 [project](/langsmith/log-traces-to-project)，绝不会同时发送到两者。关于 agents 和 projects 之间的关系，请参阅 [Trace containers](/langsmith/observability-concepts#trace-containers)。

<Note>
将 traces 发送到 agent 目前处于 [beta](/langsmith/release-stages) 阶段，且仅适用于 agent-based workspaces。[接受 agent 的参数](#using-code)可能在没有通知的情况下更改。它支持于：

- Python SDK，从 `langsmith>=0.14.9` 起
- TypeScript SDK，从 `langsmith>=0.10.9` 起
- Go SDK，从 `github.com/langchain-ai/langsmith-go@v0.28.0` 起
- Java SDK，从 `com.langchain.smith:langsmith-java:0.1.0-beta.26` 起

关于不将 traces 发送到 agent 的 tracing 设置，请参阅 [Log traces to a specific project](/langsmith/log-traces-to-project)。
</Note>

## 前置条件

- **一个 agent-based workspace。** [Agent-based workspaces](/langsmith/migrate-to-agent-based-workspaces) 在 [LangSmith Cloud](/langsmith/cloud) 上可用，在[自托管](/langsmith/self-hosted)的 LangSmith 上不可用。在 agent-based workspace 中，将 traces 发送到 agent 已经开启，你无需更改任何设置。要判断你拥有哪种 workspace，请看左上角的控件。在 agent-based workspace 中，它显示你的 workspace 名称。在 project-based workspace 中，它显示 LangSmith logo，并且将 traces 发送到 agent 是关闭的。
- **来自该 workspace 的一个 API key。** 请参阅[创建 API key](/langsmith/create-account-api-key)。
- **SDK。** 将 traces 发送到 agent 在 Python 中需要 `langsmith>=0.14.9`，在 TypeScript 中需要 `langsmith@>=0.10.9`，在 Go 中需要 `github.com/langchain-ai/langsmith-go` v0.28.0 或更高版本，在 Java 中需要 `com.langchain.smith:langsmith-java` 0.1.0-beta.26 或更高版本：

  <CodeGroup>

  ```bash uv
  uv add "langsmith>=0.14.9"
  ```

  ```bash pip
  pip install -U "langsmith>=0.14.9"
  ```

  ```bash npm
  npm install "langsmith@>=0.10.9"
  ```

  ```bash go
  go get github.com/langchain-ai/langsmith-go@v0.28.0
  ```

  ```kotlin Java/Kotlin (Gradle)
  implementation("com.langchain.smith:langsmith-java:0.1.0-beta.26")
  ```

  </CodeGroup>

## 将 traces 发送到 agent

将 agent 和 environment 一起指定，在代码中或通过环境变量。代码中的 agent 优先于变量。只有当代码中没有指定目的地时，SDK 才读取变量，而且此时两者都需要。

- **Agent ID**：agent 的 identifier，浏览器地址栏会携带它，agent 的 Overview 上的 **ID** 字段可以复制它。它不是 display name。[Display name 是一个单独的、可编辑的值](/langsmith/agents#identifiers-and-display-names)，不必与 identifier 一致，因此请从 agent 本身读取 identifier，而不是从 agent 的名称推导它。identifier 必须遵循的规则请参阅 [Identifier rules](/langsmith/create-an-agent#identifier-rules)。如果 workspace 中没有 agent 使用你发送的 identifier，LangSmith 会在你第一次向它发送 trace 时创建该 agent，因此你不必提前创建。以此方式创建 agent 需要 [`projects:create` 权限](/langsmith/organization-workspace-operations#projects)。没有它，LangSmith 会以 `403` 拒绝该 run。已归档的 agent 仍持有其 identifier，因此 LangSmith 会以 `409` 拒绝发送到它的 run，而不是创建一个新的 agent。请将该 agent 的 traces 发送到另一个 identifier。以此方式创建的 agent 的 [Overview](/langsmith/navigate-agents#read-the-agent-overview) 不会显示 deployment 详情。
- **Environment**：该 run 所属的 environment，取 `local`、`development`、`staging` 或 `production` 之一。Environment 名称不区分大小写，它们映射到 UI 中的 Local、Development、Staging 和 Production 标签。没有默认值，因为单独的 agent 或 environment 都无法确定一个目的地。

### 使用环境变量

设置这两个变量：

```bash
export LANGSMITH_TRACING=true
export LANGSMITH_API_KEY=<your-api-key>
export LANGSMITH_AGENT_ID=checkout
export LANGSMITH_AGENT_ENVIRONMENT=production
```

前两个是通常的 tracing 前置条件，而不是指定 agent 的一部分。如果只设置了两个 agent 变量之一，SDK 会记录一条警告。它不会替你挑选一个 environment，而是让代码中未指定目的地的每个调用都不被 trace，因此这些调用不会有任何内容到达 LangSmith。

## 发送你的第一条 trace

运行你的应用，让它至少发送一条 trace。在 LangSmith 中，在顶栏选择该 agent，前往 **Tracing**，并将 environment 控件设置为你发送 trace 所到的那个。trace 会出现在那里。

## 查找 agent 的 project

要查询某个 agent 的 traces，请先[将该 agent 解析为其 project ID](/langsmith/resolve-an-agent)，然后像以前一样使用各个端点，传入该 ID。

## 发送到 agent 或 project，但不能同时

将 traces 发送到 agent 和发送到 project 不能组合。发生什么取决于各自在哪里设置：

- **agent 和 project 同时设置**：不允许。如果你设置了 agent 变量，还设置了 `LANGSMITH_PROJECT`、`LANGCHAIN_PROJECT` 或 `LANGCHAIN_SESSION`，这条 trace 就有两个目的地，SDK 不会替你选择。它会在客户端启动时记录一条警告，并且除非代码指定了目的地，否则不会 trace 该调用。如果你在同一次调用中同时传入 `address` 和 `project_name`，SDK 会抛出错误并且不发送任何内容：Python 中 `@traceable` 或 `tracing_context()` 抛出 `LangSmithUserError`，TypeScript 中 `traceable` 抛出 `Error`。如果同时指定了 agent 和 project 的 run 到达了 LangSmith，LangSmith 会拒绝它。
- **在代码中指定 project**：覆盖 agent 变量。在 Python 中将 `project_name` 传给 `@traceable` 或 `tracing_context()`，或在 TypeScript 中传入 `traceable` 的 config，会把该 run trace 到那个 project 并忽略 agent 变量，不会报错。这就是让一个 [evaluation](/langsmith/evaluation) 使用自己的 project，而 agent 变量在进程的其余部分保持设置的原因。

## 故障排查

如果你的 workspace 不接受发送到 agent 的 runs，LangSmith 会以 `403` 拒绝它们，并附带消息 `agent addressing is not enabled for this workspace`。它会拒绝携带这些 runs 的整个请求，因此该请求中的 runs 都不会被记录。曾经接受此类 runs 的 workspace 也可能停止接受它们。首先检查你的 API key 是否仍属于该 agent-based workspace，因为 LangSmith 会拒绝使用来自 project-based workspace 的 key 发送到 agent 的 runs。如果 key 不是问题所在，请通过 [support.langchain.com](https://support.langchain.com) 联系支持团队。
