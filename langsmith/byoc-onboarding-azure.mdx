<Note>
Azure 上的 BYOC 处于 **[beta](/langsmith/release-stages)** 阶段。要开始使用，请[联系销售团队](https://www.langchain.com/contact-sales)。
</Note>

本页介绍如何在你的 Azure 订阅中创建 LangSmith BYOC data plane。每个 data plane 运行在自己的 resource group 中。Terraform module 仅授予 LangSmith 对该 resource group 的访问权限，随后 LangChain 会在其中创建并运维 data plane。有关设计细节，请参阅 [Azure 上的 BYOC 架构](/langsmith/byoc-architecture-azure)。AWS 相关说明请参阅 [BYOC 入门](/langsmith/byoc-onboarding-aws)。

## 开始之前

你需要以下条件：

- **Azure 上的 LangSmith 组织**：使用位于 [azure.smith.langchain.com](https://azure.smith.langchain.com) 的 Azure 上的 LangSmith control plane。将你的组织 ID 发送给 LangChain 团队以启用 BYOC。
- **一个 Azure 订阅**：建议使用专用订阅，但并非必需。
- **Azure 权限**：在订阅范围内具有 `Owner`，或 `Contributor` 和 `User Access Administrator`，用于应用 Terraform。需要一个能够创建 service principals 的 Microsoft Entra 角色，例如每个租户执行一次的 `Cloud Application Administrator`。这两项权限可由两人分担，如下文的 Terraform 步骤所示。如果你的 `User Access Administrator` 授权阻止了特权角色，请设置 `byo_iam = true` 并自行创建 identities。
- **Terraform**：Terraform 1.11.0 或更高版本。
- **LangSmith 中的组织管理员**：用于创建、更改和删除 data plane。
- **vCPU 配额**：该 region 中至少 6 个可用 vCPU，分别在 **Total Regional vCPUs** 配额和 Dsv6 系列配额中，供三个 `Standard_D2s_v6` 系统节点使用。应用节点使用 v5 或更高版本的 D、E 和 F 系列，因此还需要为这些系列规划配额。参见[节点池](/langsmith/byoc-architecture-azure#compute)。
- **一个 region**：任意 Azure region。要启用新的 region，请联系 LangChain 团队。

## 创建 data plane

<Steps>

<Step title="Copy the external ID">
在 LangSmith 中，转到 **Settings > Data Planes**，然后点击 **Data Planes** 标题旁的复制按钮。不要自行创建该值。LangSmith 使用该 external ID 确认你订阅中的角色分配属于你的组织。
</Step>

<Step title="Grant LangSmith access with Terraform">
在你的订阅中应用 [`langsmith-byoc-access` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/azure/langsmith-byoc-access)。你必须使用此 module。它会创建：

- **LangSmith service principal**，每个租户一次：你的 Entra 租户中 LangSmith 应用（客户端 ID `5b0a74cb-9f37-4797-b557-c15d7be80d3b`）的 identity。LangSmith control plane 在你的租户之外运行，并以该 identity 登录。它没有任何 Microsoft Graph 权限。resource group 中的 managed identities 用于 data plane 内的工作负载。
- **一个 resource group** `langsmith-byoc-<key>`，对应 `data_planes` 中的每个条目。不要在其中放置其他工作负载。
- **每个 resource group 中的一个 Key Vault**，使用 Azure RBAC 且无公共网络访问。LangSmith 将 data plane 的 bootstrap secret 写入其中。
- **每个 resource group 上的两个角色分配**：一个 `langsmith-byoc-<key>-<suffix>` 自定义角色和 `User Access Administrator`。两者都以你的 external ID 作为描述。

```hcl
terraform {
  required_providers {
    azurerm = {
      source  = "hashicorp/azurerm"
      version = ">= 4.42.0, < 5.0.0"
    }
    azuread = {
      source  = "hashicorp/azuread"
      version = "~> 3.0"
    }
  }
}

provider "azurerm" {
  subscription_id = "<subscription-id>"
  features {}

  # The data plane needs these resource providers. LangSmith cannot
  # register them, because its roles stop at the resource group.
  resource_providers_to_register = [
    "Microsoft.Cache",
    "Microsoft.Compute",
    "Microsoft.ContainerRegistry",
    "Microsoft.ContainerService",
    "Microsoft.DBforPostgreSQL",
    "Microsoft.KeyVault",
    "Microsoft.ManagedIdentity",
    "Microsoft.Network",
    "Microsoft.Storage",
  ]
}

provider "azuread" {}

variable "external_id" {
  description = "The external ID from Settings > Data Planes in LangSmith."
  type        = string
}

module "langsmith_byoc_access" {
  source = "github.com/langchain-ai/terraform//modules/byoc/azure/langsmith-byoc-access?ref=main"

  langsmith_app_client_id = "5b0a74cb-9f37-4797-b557-c15d7be80d3b"
  external_id             = var.external_id

  # Set to false if an Entra admin already ran `az ad sp create`.
  # create_service_principal = false

  data_planes = {
    prod = {
      location = "eastus"
    }
  }
}

output "langsmith_byoc_access" {
  value = module.langsmith_byoc_access
}
```

1. 将配置保存为空文件夹中的 `main.tf`。替换订阅 ID 和 region。`data_planes` 的键（`prod`）用于命名 resource group：最多 63 个小写字母、数字和连字符，以字母开头，以字母或数字结尾，且不能有连续的连字符。
1. 如果应用 Terraform 的人无法创建 service principals，请先由 Entra 管理员运行 `az ad sp create --id 5b0a74cb-9f37-4797-b557-c15d7be80d3b`。然后你必须设置 `create_service_principal = false`。此时 Terraform 只会读取该 service principal。
1. 运行：

    ```bash
    az login
    terraform init
    terraform apply -var 'external_id=<external-id>'
    terraform output -json langsmith_byoc_access
    ```

1. 记下 `azure_entra_tenant_id`，以及 `data_planes` 下的 `region` 和 `resource_group_id`。

有关每个角色允许的操作，请参阅[访问与权限](/langsmith/byoc-architecture-azure#access-and-permissions)。有关所有输入，请参阅 [module README](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/azure/langsmith-byoc-access)。
</Step>

<Step title="Create the data plane">
1. 在 [LangSmith on Azure](https://azure.smith.langchain.com) 中，转到 **Settings > Data Planes**，然后点击 **+ Data Plane**。
1. 使用上一步的 Terraform outputs 填写 **Create a data plane** 表单：

    | 字段 | 说明 |
    |-------|-------------|
    | **Name** | 最多 24 个小写字母、数字和连字符。以字母或数字开头和结尾，且不能以 `internal` 开头。例如 `prod`。 |
    | **Azure region** | 选择该 resource group 所在的 region。 |
    | **Microsoft Entra tenant ID** | 使用 `azure_entra_tenant_id` output，格式为 `8-4-4-4-12` 的 UUID。 |
    | **Azure resource group ID** | 使用 `resource_group_id` output，格式为 `/subscriptions/<subscription-id>/resourceGroups/<name>`。每个 resource group 只服务一个 data plane。 |
    | **Use existing managed identities** | 仅当你在该 module 的 `data_planes` 输入中为该 data plane 设置了 `byo_iam = true`，以便 Terraform 创建 identities 及其角色分配时，才选择此项。请在创建 data plane 之前设置 `byo_iam`，因为之后无法更改。请参阅 [Bring your own identities](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/azure/langsmith-byoc-access#bring-your-own-identities-optional)。否则，请保持未选中状态。 |
    | **VNet CIDR Range** | LangSmith 为 data plane 创建的 VNet 的地址范围。请使用从 `/16` 到 `/18`、且不与你的其他网络重叠的私有 RFC 1918 范围。 |
    | **Load balancer access** | 保持默认的 **Private**，仅允许从 data plane VNet 及连接的网络访问。若需要面向互联网的 endpoint，请切换到 **Public**。在 **Private** 模式下，选择 **Private Link**，以便通过你的 VNets 中的私有 endpoint 访问。 |

1. 点击 **Create data plane**。LangSmith 会以 **Data plane requested** 确认。

LangSmith 会先检查 external ID、其权限、Key Vault、region 和 vCPU 配额。如果检查失败，表单会显示错误。参见[排查 data plane 创建问题](#troubleshoot-data-plane-creation)。
</Step>

<Step title="Wait for provisioning">
data plane 会在 **Settings > Data Planes** 中从 `requested` 转到 `provisioning`，再到 `active`。如果它在 3 小时内未变为 active，就会转为 `provisioning_failed`。此时请联系 LangChain 团队。
</Step>

<Step title="Connect to the data plane">
data plane URL 的形式为 `https://<data_plane_id>.azure.langchain-byoc.com`。你可以在 **Settings > Data Planes** 中找到它。

- **内部 load balancer**（`public_load_balancer: false`）：只能从其 VNet 访问 data plane。将你的网络连接到该 VNet，例如通过 peering 或 VPN gateway，并通过其私有 DNS 区域解析 DNS。仅靠 peering 或 VPN 不提供 DNS 解析。
- **Private Link**（仅限内部 load balancer）：无需 peering，即可从你自己的 VNet 访问 data plane。创建 data plane 时，在私有 load balancer 下选择 **Private Link**。来自 data plane 订阅的私有 endpoint 会立即连接。要让你的其他订阅获得自动批准，请让 LangChain 团队添加它们。LangChain 团队会提供 `langsmith-ingress` Private Link Service 的资源 ID。在你的 VNet 中为其创建私有 endpoint。来自其他订阅的请求会等待你在该服务上批准。然后，将私有 DNS 区域 `<data_plane_id>.azure.langchain-byoc.com` 链接到你的 VNet，并为 `@` 和 `*` 添加指向私有 endpoint IP 的 A 记录。
- **公有 load balancer**（`public_load_balancer: true`）：用户和应用通过互联网访问 data plane。

如果 LangSmith UI 无法访问你的 data plane，会提示你切换到可访问的 data plane 上的 workspace。
</Step>

<Step title="Create workspaces">
新 data plane 中会自动创建一个名为 `dp-<data_plane_name>` 的 workspace。在 data plane 可访问之前，它无法被使用。

你可以在该 data plane 中创建更多 workspaces。创建每个 workspace 时，请选择目标 data plane：一个 workspace 恰好属于一个 data plane，而一个 data plane 可以容纳多个 workspaces。

<Warning>
Workspace 在创建后无法移动到另一个 data plane。
</Warning>
</Step>

<Step title="(Optional) Migrate existing data">
如果你是从 LangSmith Cloud 或 [self-hosted](/langsmith/self-hosted) 实例迁移过来，请联系 LangChain 团队安排迁移。仅 AWS 上支持 trace 迁移。

更多信息，请参阅[迁移到 BYOC](/langsmith/byoc-migration)。
</Step>

</Steps>

要将 traces 和 API 请求发送到 data plane，请参阅 [BYOC 使用](/langsmith/byoc-usage)。

<a id="troubleshoot-data-plane-creation"></a>

## 排查 data plane 创建问题

| 错误码 | HTTP 状态 | 原因 | 解决方法 |
|------|-------------|-------|-----|
| `azure_external_id_mismatch` | 403 | 该 resource group 上 LangSmith service principal 的某个角色分配未以你组织的 external ID 作为描述。 | 使用 **Settings > Data Planes** 中的 external ID 应用 Terraform module，然后重试。 |
| `azure_permissions` | 403 | LangSmith service principal 无法访问该 resource group，或缺少必需的权限。解决建议中会列出缺失的操作。 | 确认该 resource group 存在，并且你在应用 Terraform module 时未启用 `reduced_access`，然后重试。 |
| `azure_policy_denied` | 403 | 你订阅中的 Azure Policy 分配拒绝了某个请求。 | 将该 data plane 的 resource group 从该策略中豁免，然后重试。 |
| `azure_resource_group_invalid` | 400 | 该 resource group 不存在、未恰好包含一个 Key Vault，或其 vault 不使用 Azure RBAC。 | 修复该 resource group，然后重试。 |
| `azure_region_unavailable` | 400 | 你的订阅无法使用该 region，或无法在其中创建 AKS 系统节点规格或 PostgreSQL 规格。 | 选择另一个 region，或请 Azure 支持为你的订阅在该 region 中启用该 VM 规格或 PostgreSQL。 |
| `insufficient_azure_quota` | 422 | 该 region 没有足够的可用 vCPU 配额供 AKS 系统节点池使用。 | 申请提高配额，或选择另一个 region。 |
| `azure_resource_group_in_use` | 409 | 另一个 data plane 正在使用该 resource group。 | 为该 data plane 创建新的 resource group。 |
| `data_plane_name_taken` | 409 | 你的组织中已有使用该名称的 data plane。 | 选择另一个名称。 |
| `azure_throttled` | 429 | Azure 正在对你的订阅请求进行限流。 | 等待一分钟后重试。 |
| `azure_unavailable` | 502 或 503 | Azure 返回了服务器错误，或未报告 vCPU 配额。 | 等待一分钟后重试。 |

无效的字段值会返回 HTTP 400，并附带字段名和该值违反的规则。

## 部署后减少权限

data plane 变为 `active` 后，你可以减少其 `langsmith-byoc-<key>-<suffix>` 自定义角色的权限。在 Terraform module 中为该 data plane 设置 `reduced_access = true`，然后运行 `terraform apply`：

```hcl
data_planes = {
  prod = {
    location       = "eastus"
    reduced_access = true
  }
}
```

Terraform 会缩减自定义角色并删除 `User Access Administrator` 分配。Azure 最多需要 5 分钟应用该更改。LangChain 仍可以升级、扩缩容和修复 data plane。它无法删除 data plane、其数据库、存储或网络，也无法创建角色分配。在删除或重新创建 data plane 之前，以及在新增角色分配的升级之前，请将 `reduced_access` 设回 `false`。

## 删除 data plane

<Warning>
在 LangSmith 中删除 data plane 之前，不要将其从 Terraform module 中移除。LangSmith 需要其角色分配来删除 data plane 资源。
</Warning>

1. 如果该 data plane 的 `reduced_access = true`，请将其设为 `false`，运行 `terraform apply`，并等待 5 分钟让 Azure 应用角色更改。
1. 在 **Settings > Data Planes** 中删除该 data plane，或使用 `DELETE /orgs/current/data-planes/<data-plane-id>` API。你可以在 Azure data plane 处于 `provisioning`、`active` 或 `provisioning_failed` 状态时删除它。LangSmith 会先检查它是否仍能访问你的 resource group。
1. 等待 data plane 从 **Settings > Data Planes** 中消失。

LangSmith 会删除 AKS 集群、PostgreSQL、Redis、网络和私有 DNS 区域。它会在你的 resource group 中保留以下内容：

- resource group 和 Key Vault。
- 存放你的 trace 数据和 SmithDB 数据的 Blob 存储账户。

Azure 会在有限时间内保留已删除 PostgreSQL 服务器的备份，在此期间你可以还原它。参见[还原已删除的 Azure Database for PostgreSQL 灵活服务器](https://learn.microsoft.com/azure/postgresql/flexible-server/how-to-restore-dropped-server)。

如果在同一 resource group 中创建同名的新 data plane，它会复用该 Key Vault 和保留的 Blob 存储账户。

当不再需要这些数据时，请先删除 Blob 存储账户。然后从 `data_planes` 中移除该键并运行 `terraform apply`，以删除该 resource group、Key Vault 和角色分配。

## 移除 LangSmith 访问权限

要阻止 LangSmith 更改 data plane，请移除其 resource group 和 AKS 集群上 LangSmith service principal 的角色分配。移除 Terraform module 会移除对该租户中每个 data plane 的访问权限。这些资源仍会保留在你的订阅中，但 LangChain 将无法再升级或修复它们。如果希望 LangSmith 清理资源，请先删除 data plane。
