## 设置

<Accordion title="Which clouds and regions can I deploy to?">
BYOC 在 AWS 上已正式发布（GA），使用美国 control plane。对其他云提供商的支持计划于 2026 年下半年推出。受支持的 AWS regions 请参阅 [Regions and cloud providers](/langsmith/byoc#regions-and-cloud-providers)。
</Accordion>

<Accordion title="Do I need a dedicated AWS account?">
不需要。LangChain 建议使用一个全新的账户，以便计费更清晰，也因为某些权限无法限定到特定资源，但这不是必需的。
</Accordion>

<Accordion title="Can I install BYOC into an existing VPC?">
可以。使用 [自带 VPC（BYOVPC）](/langsmith/byoc-byovpc)时，由你提供 VPC 和子网。你可以使用[参考 Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/byovpc) 创建 VPC，或使用一个满足网络要求的现有 VPC。

要从客户角色中移除 VPC 创建权限，请在 [`langsmith-byoc-role` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role) 中设置 `allow_vpc_creation_permissions = false`，并将你的 VPC ID 包含在 `vpc_ids` 中。
</Accordion>

<Accordion title="Can I deploy multiple data planes in the same VPC?">
不能。目前不支持在同一个 VPC 中部署多个 data plane。请为每个 data plane 使用单独的 VPC。
</Accordion>

<Accordion title="Can I move an existing data plane into my own VPC?">
不能。不支持将现有 data plane 移动到另一个 VPC，也不支持在创建后更改其 VPC 和子网配置。
</Accordion>

<Accordion title="Can I install BYOC into an existing EKS cluster?">
不能，也没有支持它的计划。LangChain 会代表你运维集群，包括升级和打补丁，而专用集群正是让这种管理能够可靠进行的前提。
</Accordion>

<Accordion title="Can I run my own workloads in the LangSmith VPC or cluster?">
可以，只要它们不会干扰 LangSmith 的正常运行。

在 AWS 账户中，请记住授予跨账户角色的某些权限无法按 tag 限定范围，这也是 LangChain 建议使用专用账户的原因。

在 Kubernetes 集群中，不干扰 LangSmith 的被动工作负载是可以的，例如可观测性和安全监控 agents。部署它们时：

- 使用你自己的 node groups 和 tolerations，而不是 LangSmith 所使用的那些。
- 部署到 LangSmith 未使用的 namespace 中。
- 不要编辑 LangChain 预置的资源。

对于由干扰性工作负载导致的停机或问题，LangChain 不承担责任。
</Accordion>

<Accordion title="What value do I set to the external ID for my role?">
External ID 由 LangChain 提供。前往 **Settings > Data Planes**，使用 **Data Planes** 标题旁的复制按钮复制它。在应用 `langsmith-byoc-role` Terraform module 时使用此值。该角色的信任策略必须在 `ExternalId` 条件中使用此值。
</Accordion>

<Accordion title="How long does provisioning take?">
一个 data plane 的端到端预置大约需要 60 到 90 分钟。预置时间可能有变化，因为 AWS 资源预置并不总是稳定一致。
</Accordion>

<Accordion title="What happens if provisioning fails?">
Data plane 会转换为 `Provisioning Failed` 状态。失败通常由跨账户角色缺少权限引起，或是由阻止 LangChain 所需操作的 service control policy（SCP）引起。

请严格按照发布的内容应用 [`langsmith-byoc-role` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role)，不做任何编辑或修改。修改过的 module 是权限缺失的常见来源。

联系 LangChain 团队。权限修正后，预置会自动完成调和。
</Accordion>

<Accordion title="What VPC CIDR range should I use?">
使用 `/18` 到 `/16` 之间的私有 RFC 1918 范围。如果计划使用 VPC peering，请选择一个与你要建立对等连接的 VPC 不重叠的范围。CIDR 范围在预置后无法更改。
</Accordion>

<Accordion title="How do I reach a data plane with a private endpoint?">
Data plane 默认以私有 endpoint 预置，因此你需要私有连接方式，例如 Tailscale、AWS PrivateLink 或 VPC peering。
</Accordion>

<Accordion title="Are my service endpoints exposed to the internet?">
不会。服务默认位于私有 load balancer 之后，只能从你的 VPC 内部或通过你配置的私有连接访问。

Data plane endpoints 可以在预置时设为公共。参见 [Onboarding](/langsmith/byoc-onboarding)。
</Accordion>

<Accordion title="Can I use my own DNS domain?">
不能。Data plane 在标准的 LangChain BYOC 域名下预置。你的 data plane API URL 可以在 **Settings > Data Planes** 下找到。
</Accordion>

<Accordion title="How do I decommission a data plane?">
以 `allow_delete_permissions = true` 重新应用 [`langsmith-byoc-role` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role)，它会授予删除 LangSmith 托管资源所需的权限。

然后在 LangSmith UI 中选择 **Delete Data Plane**。LangChain 会取消预置你账户中的基础设施。
</Accordion>

## 数据与安全

<Accordion title="Does sensitive data ever leave my VPC?">
不会。当用户打开 `aws.smith.langchain.com` 时，浏览器会从 LangChain 的云中获取 LangSmith UI bundle。加载完成后，应用会将每一个针对敏感数据的请求路由到你的 VPC。

参见 [Data traffic](/langsmith/byoc-architecture#data-traffic)。
</Accordion>

<Accordion title="What can the LangChain team do in my account?">
LangChain 只能管理 LangSmith 所创建资源的基础设施，不能做其他任何事情。权限由 `managed_by=langsmith` tag 限定范围，因此该角色无法对账户中无关的资源执行操作。

该角色不持有任何授予数据访问权限的权限。参见 [How least privilege is enforced](/langsmith/byoc-architecture#how-least-privilege-is-enforced)。
</Accordion>

<Accordion title="Can LangChain read my traces or database contents?">
不能。跨账户角色的范围限于基础设施，而非数据。它可以管理存放你数据的资源，但不持有 trace 存储桶上的 `s3:GetObject`，不持有 PostgreSQL 的 `rds-db:connect`，也不持有 Redis 的 `elasticache:Connect`。

访问数据本身需要你显式授权，例如在事件处理期间。参见 [How least privilege is enforced](/langsmith/byoc-architecture#how-least-privilege-is-enforced)。
</Accordion>

<Accordion title="What access do LangChain employees have to my environment and data?">
不存在常态化的数据访问。如果事件处理需要访问你的数据，LangChain 会要求你自行运行查询，或申请 break-glass 访问权限。
</Accordion>

<Accordion title="Does LangSmith support customer-managed encryption keys?">
目前不支持。数据使用云提供商托管密钥进行静态加密。对客户托管加密密钥（CMK）的支持已在计划中。
</Accordion>

<Accordion title="How do I revoke LangChain's access?">
跨账户角色由你在自己的账户中创建并拥有，因此你可以在不牵涉 LangChain 的情况下撤销访问。移除该角色，或移除它与 LangChain 账户之间的信任关系，会阻止 control plane 代入该角色，并停止 data plane 资源的调和。
</Accordion>

<Accordion title="Can I revoke individual permissions granted during provisioning?">
可以，但该角色需要这些权限来持续调和 data plane，并对其进行管理、升级和扩容。移除这些权限可能会破坏这些操作。

如果需要移除特定权限，请先联系 LangChain 团队，以便对变更进行审核。对于未经该审核而移除权限所导致的停机或问题，LangChain 不承担责任。
</Accordion>

<Accordion title="What does LangChain hold in the control plane?">
身份验证、组织和 workspace 配置、计费和使用量元数据、哈希后的 API keys，以及静态前端资源。

Traces、prompts、datasets、evaluators、experiments、insights runs、annotation queues、agent 部署以及 workspace secrets 都存放在你的 data plane 中。
</Accordion>

<Accordion title="What data leaves my account?">
只有运维数据，并且它通过 PrivateLink 而非公共互联网传输：

- **身份验证请求**：Data plane 调用 control plane 来验证请求、验证 API keys，以及解析角色和权限。
- **配置**：从 control plane 加载的组织和 workspace 配置。
- **计费和使用量元数据**。
- **运维遥测数据**。

Traces 等敏感数据不会离开你的账户。它只从 data plane 发送到请求它的最终用户。参见 [Data traffic](/langsmith/byoc-architecture#data-traffic)。
</Accordion>

<Accordion title="Does traffic go over the public internet?">
不会。

- **Control plane 到 data plane**：所有通信都通过 AWS PrivateLink 双向传输。
- **S3**：流量通过 VPC endpoint 传输，并使用 HTTPS 加密。
- **容器镜像**：通过 VPC endpoint 从 LangChain 账户拉取。

参见 [Connectivity](/langsmith/byoc-architecture#connectivity)。
</Accordion>

<Accordion title="Can I restrict outbound network traffic from the data plane?">
可以。

对于 LangChain 托管的 VPC，BYOC 支持通过一个网络防火墙控制 data plane 的出口流量。联系 LangChain 团队以启用它。

启用后，防火墙默认拒绝所有出站流量。然后你配置一个允许列表，列出 data plane 被允许访问的目标：

- **域名**：完全限定域名，例如模型提供商 API endpoint 或公共 Docker registry。
- **CIDR 范围**：IP 范围，例如内部服务或私有子网。

使用 BYOVPC 时，由你管理自己的防火墙和出口控制。你的网络必须继续满足 [BYOVPC 网络要求](/langsmith/byoc-byovpc#meet-the-network-requirements)。
</Accordion>

<Accordion title="Can I use my own private registry?">
目前不能。容器镜像通过 VPC endpoint 从 LangChain 的 AWS 账户拉取。对私有 registry 的支持已在路线图中。
</Accordion>

<Accordion title="How does the control plane reach my Kubernetes API server?">
通过 AWS PrivateLink。管理路径仅暴露你集群的 Kubernetes API server，LangChain 用它来安装和调和 LangSmith 组件。

EKS 集群是私有的：API server endpoint 没有公共访问，worker nodes 没有公共 IP 地址。通过那条连接无法访问你的数据，LangChain 也不会通过公共互联网访问你的环境。参见 [Connectivity](/langsmith/byoc-architecture#connectivity)。
</Accordion>

<Accordion title="Where does the control plane run if my data plane is outside the US?">
无论你将 data plane 放在哪里，control plane 都运行在 `us-east-2`。如果你在美国以外预置一个 data plane，你的敏感应用数据会保留在该 region，而 control plane 元数据仍保留在美国。参见 [Regions and cloud providers](/langsmith/byoc#regions-and-cloud-providers)。
</Accordion>

## Data planes 与 workspaces

<Accordion title="How do organizations, data planes, and workspaces relate?">
Data plane 属于一个组织，而 workspace 恰好属于一个 data plane。使用 data plane 实现数据的物理隔离，使用 workspace 在 data plane 内实现逻辑隔离。参见 [Organizations, data planes, and workspaces](/langsmith/byoc-usage#organizations-data-planes-and-workspaces)。
</Accordion>

<Accordion title="Can I run more than one data plane?">
可以。一个组织可以有多个 data plane，每个都位于自己的 AWS 账户和 region 中。

默认限制是每个组织 5 个 data plane。如果需要部署更多，请联系 LangChain 团队。
</Accordion>

<Accordion title="Can one organization hold both Cloud and BYOC workspaces?">
可以。LangSmith Cloud 上的 workspace 会路由到 LangChain 托管的 backend，而不是 data plane，因此两者可以在同一个组织中并存。这也意味着你可以从 AWS Cloud 试用迁移到 BYOC，同时复用相同的组织、用户、角色和 SSO 配置。
</Accordion>

## 运维

<Accordion title="Who is responsible for what in a BYOC deployment?">
LangChain 运行 control plane，并通过委托的、最小权限的访问管理 data plane 基础设施。你拥有 AWS 账户、网络连接、data plane 中的数据，以及账户内部的安全监控。

平台与基础设施、数据与安全、运维与支持之间的完整划分，请参阅 [BYOC shared responsibility model](/langsmith/byoc-shared-responsibility)。
</Accordion>

<Accordion title="Who upgrades LangSmith, and how often?">
LangChain 每周升级一次你 data plane 中的 LangSmith 版本。升级是滚动进行的，因此不会有整个服务的停机。Istio 和 KEDA 等配套服务会按固定的节奏升级，LangChain 管理所有 EKS 集群升级。

对 release channels 的支持即将推出。参见 [Operations](/langsmith/byoc-operations)。
</Accordion>

<Accordion title="What about Kubernetes upgrades?">
LangChain 负责并主动执行 EKS 升级，先于 AWS 的支持终止日期，并与你协调维护窗口。

Control plane 升级是透明的。Node group 升级以 make-before-break 语义逐个滚动节点，因此当 pods 重启时你可能会看到短暂连接重置，但不会有数据丢失。参见 [Kubernetes cluster upgrades](/langsmith/byoc-operations#kubernetes-cluster-upgrades)。
</Accordion>

<Accordion title="Do upgrades cause downtime?">
不会。服务运行由 horizontal pod autoscaler 决定规模的多个副本，并且 pod disruption budgets 限制了同一时间允许多少副本不可用，因此无论是滚动更新还是节点清空，都不会让服务低于其所需的容量。

可能导致停机的维护（例如 RDS 或 ElastiCache 的重启）会在 LangChain 提前与你协调的维护窗口中进行。
</Accordion>

<Accordion title="Who monitors the data plane?">
LangChain 在预置后运维 data plane，包括针对可用性和错误恢复的监控、扩缩容、升级以及安全补丁。由于部署运行在你自己的账户中，你已经在使用的云控制手段同样适用于它。
</Accordion>

<Accordion title="Can I set up my own observability for LangSmith BYOC?">
可以。只要不干扰 LangSmith 的运行，你可以将 collectors 和 agents 等可观测性工具安装到 EKS 集群中。

LangSmith 服务发出日志、指标和 traces 的方式与 self-hosted 相同，因此同样的配置适用。参见 [Export LangSmith telemetry to your observability backend](/langsmith/export-backend)。
</Accordion>

<Accordion title="How are high availability and disaster recovery handled?">
Data plane 默认按高可用方式预置，跨单个 region 内的多个可用区运行。所有有状态组件都会备份。

Data plane 不会跨 region，因此从整个 region 丢失中恢复依赖这些备份。参见 [High availability](/langsmith/byoc-operations#high-availability)。
</Accordion>

<Accordion title="How are backups handled?">
备份在你自己的账户中运行：

- **RDS**：每天执行备份。
- **ClickHouse**：每天执行备份，并存储在 S3 存储桶中。
- **ElastiCache**：不执行备份，因为数据是临时性的。
</Accordion>

<Accordion title="Does LangChain offer an uptime SLA for BYOC data planes?">
不提供。Data plane 运行在你的 AWS 账户中，因此其可用性取决于你控制的资源，包括账户本身、你为访问 data plane 而配置的私有连接，以及适用于该账户的服务配额和策略。对于并非由 LangChain 单独控制的基础设施，LangChain 不承诺可用性目标。

LangChain 仍会监控 data plane 的可用性和错误恢复，对其进行扩缩容，并应用升级和安全补丁。参见 [Operations](/langsmith/byoc-operations)。
</Accordion>

## 成本

<Accordion title="What do I pay for with BYOC?">
两份独立的账单：

- **基础设施**：Data plane 运行在你自己的 AWS 账户中，因此基础设施由你拥有，并通过你的云提供商账单付费。
- **LangSmith**：由 LangChain 根据你的合同和使用量开具发票。

LangChain 提供与 AWS Marketplace 的集成。
</Accordion>

## 功能与迁移

<Accordion title="Which LangSmith features work on BYOC?">
当前受支持功能的列表请参阅 [Available features](/langsmith/byoc#available-features)。
</Accordion>

<Accordion title="Can I migrate an existing LangSmith instance to BYOC?">
部分可以。用户、角色、datasets、experiments、prompts、annotation queue 配置、automation rules、dashboards 以及 Fleet 资源可以复制过来。Traces 目前不会迁移。参见 [Migrate to BYOC](/langsmith/byoc-migration)。
</Accordion>
