<Info>
本页适用于未运行在离线（air-gapped）模式下，并且已开启运维遥测指标的自托管 LangSmith 实例。
</Info>

当 `config.telemetry.metrics` 设置为 `true`（默认值）时，你的 LangSmith 实例会每分钟通过 OpenTelemetry（OTLP）将运维指标导出到 `https://beacon.langchain.com`。有关运维遥测是什么，以及它与计费遥测和使用量遥测有何区别，请参阅[用于计费与运维遥测的 egress](/langsmith/self-host-egress)。

LangChain 的遥测 collector 只保留本页列出的指标。它会丢弃收到的其他任何指标，因此未出现在本页的指标不会被存储。指标包含计数、大小、时长和状态值。它们不包含 trace 内容、数据库记录或关于你的用户的信息。

## 指标的收集方式

| 来源 | 收集方 | 发送时机 |
| --- | --- | --- |
| LangSmith 服务 | 每个 LangSmith 服务在处理请求和作业时 | 指标开启期间始终发送 |
| PostgreSQL | `queue` 部署，每分钟一次 | 指标开启期间始终发送 |
| Redis | `queue` 部署，每分钟一次 | 指标开启期间始终发送 |
| ClickHouse | `queue` 部署，每分钟一次 | 当 `clickhouse.enabled` 为 `true` 时 |
| SmithDB | `queue` 部署，每分钟一次 | LangSmith v0.18 或更高版本，且 `smithdb.enabled` 为 `true` 时 |
| SmithDB 迁移 | `queue` 部署，每分钟一次 | LangSmith v0.18 或更高版本，且 `smithdb.langsmith.migration.enabled` 为 `true` 时 |

要关闭所有指标，请将 `config.telemetry.metrics` 设置为 `false`。要停止发送单个数据存储（例如 SmithDB）的指标，请参阅[为单个数据存储禁用指标](/langsmith/self-host-egress#disable-metrics-for-one-datastore)。

## 属性

每项指标都带有用于标识发送实例的属性：`env`，以及来自你的许可证的 `customer.id` 和 `customer.name`。collector 会移除其他所有资源属性。

对于各个数据点，collector 仅保留以下属性，并移除其余属性，包括请求路径：

`app_name`、`cmd`、`collector`、`component`、`dbname`、`error_type`、`fault`、`file_type`、`job_kind`、`kind`、`level`、`maxmemory_policy`、`method`、`mode`、`name`、`op`、`outcome`、`pointer_type`、`quantile`、`queue_name`、`reason`、`redis_mode`、`redis_version`、`replica`、`resource_name`、`resource_type`、`result`、`role`、`rule_owner`、`source`、`state`、`status`、`status_code`、`store_type`、`unit_kind`、`value`、`version` 和 `workload_kind`。
