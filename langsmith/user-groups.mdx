用户组是一组组织成员（例如一个团队），你可以将它们作为整体统一管理。你可以授予用户组访问多个工作区的权限，并在每个工作区中为其指定一个角色。属于这些工作区的用户组成员会在其中获得该用户组的角色。用户组构建在[基于角色的访问控制（RBAC）](/langsmith/rbac)和[基于属性的访问控制（ABAC）](/langsmith/abac)之上。

<Note>
用户组适用于使用 [Enterprise 方案](https://www.langchain.com/pricing)的组织，以及[自托管](/langsmith/self-hosted)部署。[联系我们的销售团队](https://www.langchain.com/contact-sales)了解更多信息。
</Note>

## 访问规则

在工作区中，用户的权限是其自身的[工作区角色](/langsmith/rbac#workspace-roles)与所属每个用户组的角色之和。[访问策略](/langsmith/abac)可以来自这些角色，也可以来自用户组本身。匹配的 deny 策略会优先应用并阻止访问，无论角色授予了什么权限。关于评估顺序，请参阅 [ABAC 如何与 RBAC 协同工作](/langsmith/abac#how-abac-works-with-rbac)。

用户组的角色仅适用于属于该工作区的成员。授予用户组访问权限不会把任何人添加到工作区。要授予某个用户组成员访问权限，请[将该用户添加到工作区](/langsmith/set-up-hierarchy#set-up-a-workspace)，或[从身份提供方同步用户组](#sync-user-group-members-from-your-identity-provider)。

## 准备工作

- 确保已为你的组织启用 [RBAC](/langsmith/rbac) 和 [ABAC](/langsmith/abac)。未启用 ABAC 时，用户组访问策略不会生效。
- 对于自托管部署，请参阅下文。

## 为自托管部署启用用户组

<Note>
在[自托管](/langsmith/self-hosted)部署上，用户组需要 LangSmith 0.18 或更高版本。
</Note>

使用以下任一方式启用用户组：

- **为特定组织启用**：针对你的 LangSmith PostgreSQL 数据库运行以下语句，将 `<organization_id>` 替换为从 UI 中组织设置页面复制的 ID：

    ```sql
    UPDATE organizations SET config = config || '{"can_use_teams": true}' WHERE id = '<organization_id>' AND NOT is_personal;
    ```

- **为所有组织启用**：将以下环境变量添加到 `values.yaml` 的 `commonEnv` 中：

    ```yaml
    DEFAULT_ORG_FEATURE_CAN_USE_TEAMS: "true"
    ```

要在 UI 中管理用户组，还需[启用 ABAC](/langsmith/abac#enable-abac-on-a-self-hosted-deployment)。

## 创建用户组

要创建用户组：

1. 进入 Organization **Settings** > **User Groups**。
1. 点击 **Create user group**。
1. 输入 **Name**，并可选输入 **Description**。
1. （可选）添加成员、工作区访问权限和访问策略。请参阅[编辑用户组](#edit-a-user-group)。
1. 点击 **Create user group**。

用户组名称在组织内必须唯一。

## 编辑用户组

要编辑用户组：

1. 进入 Organization **Settings** > **User Groups**，然后点击该用户组。
1. 在 **Members**、**Workspaces** 或 **Access policies** 中进行更改。
1. 点击 **Update user group**。

LangSmith 会一起保存这些更改。如果其中一项保存失败，LangSmith 会保留未保存的更改，以便你重试。

### 成员

点击 **+ Add member** 添加组织成员。要移除成员，请点击其所在行的移除图标。被移除的成员会失去该用户组授予的访问权限。

该部分还会列出用户组的[仅工作区成员](#add-workspace-only-members-and-policies)，并链接到添加他们的工作区。

### 工作区

点击 **+ Grant workspace** 并选择工作区，以授予用户组成员在该工作区中的角色。角色默认为 [Workspace Viewer](/langsmith/rbac#workspace-viewer)。你也可以改为选择任何内置或[自定义工作区角色](/langsmith/rbac#custom-roles)，之后还能在该工作区的行上更改。

要移除访问权限，请点击工作区所在行的移除图标，然后输入工作区名称以确认。移除访问权限还会移除该用户组在该工作区中的仅工作区成员和访问策略。

### 访问策略

点击 **+ Attach policy** 附加[访问策略](/langsmith/abac#access-policy-structure)。在用户组可访问的每个工作区中，用户组的访问策略都会应用于其成员。

要将用户组策略限制在单个工作区，请通过 [API](#manage-user-groups-with-the-api) 附加该策略并设置 `workspace_id`。用户组必须有权访问该工作区，并且你必须是该工作区的成员。用户组对话框会显示此类策略生效的工作区。

## 添加仅工作区成员和策略

在用户组可访问的工作区中，[Workspace Admin](/langsmith/rbac#workspace-admin) 可以为该用户组添加仅针对该工作区的成员和访问策略。这样，工作区管理员无需组织级权限即可管理其工作区中的访问权限。

仅工作区成员不会获得用户组的角色。他们只获得仅工作区访问策略，且仅在该工作区中生效。仅工作区访问策略仅适用于仅工作区成员。

例如，`Support` 用户组在 `Production` 中拥有 [Workspace Editor](/langsmith/rbac#workspace-editor) 角色。`Production` 中的 Workspace Admin 可以仅为该工作区向 `Support` 添加更多用户，并附加一个策略，允许他们读取标记为 `Environment=Development` 的项目。

要添加仅工作区成员或策略：

1. 进入工作区的 **Settings** > **User Groups**。页面会列出每个可访问该工作区的用户组。
1. 点击某个用户组。
1. 添加或移除成员，或者附加或分离访问策略。
1. 点击 **Update user group**。

只能添加属于该工作区的用户。用户组的名称、描述、成员和访问策略会以只读形式显示。

## 删除用户组

要删除用户组，请进入 Organization **Settings** > **User Groups**，点击该用户组所在行的删除图标，然后输入用户组名称以确认。

删除用户组会移除其成员、工作区访问权限和访问策略，包括仅工作区成员和策略。

用户组在工作区中使用的角色无法删除。请先更改用户组的角色或移除其工作区访问权限。

## 从身份提供方同步用户组成员

将用户组关联到身份提供方（IdP）中的群组后，LangSmith 会从该群组设置用户组的成员。同步支持 [SCIM](/langsmith/user-management#set-up-scim-for-your-organization) 和 [SSO Groups Sync](/langsmith/user-management#sso-groups-sync-alternative)。仅工作区成员不会被同步。

要同步用户组：

1. 进入 Organization **Settings** > **User Groups**，然后点击该用户组。
1. 在 **General** 中，在 **IdP group** 中输入群组名称。对于 SCIM，输入 SCIM 群组的名称。对于 SSO Groups Sync，输入 [groups claim](/langsmith/user-management#sso-groups-sync-alternative) 中的值。
1. 选择 **Sync members from the IdP group**。
1. 点击 **Update user group**。

### 同步行为

- **匹配**：当群组名称等于用户组的 IdP 群组时即匹配，忽略首尾空格。匹配区分大小写。每个 IdP 群组只能关联到一个用户组。
- **时机**：SSO Groups Sync 在每次登录时更新用户的成员关系，并且需要启用 **Sync workspace/role assignments**。SCIM 在用户的 SCIM 群组发生变化时更新其成员关系。
- **成员关系**：已同步用户组的成员是该 IdP 群组中的用户。你在 LangSmith 中所做的更改会保持到该用户下次同步。
- **组织角色**：当没有任何 `LS:` 群组设置用户的组织角色时，用户组匹配会设置该角色：

    - 通过 SSO Groups Sync，新用户以 [Organization Viewer](/langsmith/rbac#organization-viewer) 身份加入组织。由 SSO Groups Sync 管理成员关系的用户会被设为 Organization Viewer。其他成员关系（例如来自邀请）会保留其角色。
    - 通过 SCIM，其成员关系不由 SCIM 管理的用户会被设为 [Organization User](/langsmith/rbac#organization-user)，此后由 SCIM 管理该成员关系。这包括拥有更高角色的用户，例如 Organization Admin。

- **工作区成员关系**：同步会将用户添加到用户组可访问的每个工作区。该成员关系没有自己的角色。用户的访问权限来自用户组的角色。在用户下次同步时，如果没有用户组可访问该工作区，LangSmith 会移除该成员关系。
- **登录限制**：启用 **Require matching group to sign in** 后，匹配已同步用户组的群组会被视为匹配群组。对于 SSO Groups Sync，这还需要启用 **Sync workspace/role assignments**。
- **同步已禁用**：用户组会保留其成员，由你继续在 LangSmith 中管理。

## 权限

每项操作所需的最低内置角色：

| 操作 | 最低内置角色 |
|--------|----------------------|
| 查看用户组、成员和访问策略 | [Organization Viewer](/langsmith/rbac#organization-viewer) |
| 创建、重命名或删除用户组 | [Organization Operator](/langsmith/rbac#organization-operator) |
| 添加或移除成员 | Organization Operator |
| 授予、更改或移除工作区访问权限 | Organization Operator |
| 附加或分离访问策略 | Organization Operator |
| 查看仅工作区成员和策略 | [Workspace Viewer](/langsmith/rbac#workspace-viewer) |
| 添加或移除仅工作区成员和策略 | [Workspace Admin](/langsmith/rbac#workspace-admin) |

[自定义角色](/langsmith/rbac#custom-roles)可以包含 `workspaces:user-groups:*` 权限。关于每项操作检查的权限，请参阅[操作参考](/langsmith/organization-workspace-operations#workspace-user-groups)。

## 使用 API 管理用户组

用户组端点位于 `/api/v1/platform/orgs/current/user-groups` 下。[Audit logs](/langsmith/audit-logs#tracked-operations-reference) 会记录对用户组的每次更改。
