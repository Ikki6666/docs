`mda` CLI 用于编译和部署代码优先的 [Managed Deep Agents](/langsmith/python/managed-deep-agents-overview)。

它包含在 `managed-deepagents` Python 包中。




<ManagedDeepAgentsPublicBetaNote />

如果你想走最快的端到端路径，请参见 [quickstart](/langsmith/python/managed-deep-agents-quickstart)。关于工作流指导，请参见 [Identity](/langsmith/python/managed-deep-agents-identity)、[Memory](/langsmith/python/managed-deep-agents-memory)、[Evals](/langsmith/python/managed-deep-agents-evals)、[Custom tools](/langsmith/python/managed-deep-agents-tools)、[Connections](/langsmith/python/managed-deep-agents-connections)、[Custom middleware](/langsmith/python/managed-deep-agents-middleware)、[Sandboxes](/langsmith/python/managed-deep-agents-sandboxes)、[Channels](/langsmith/python/managed-deep-agents-channels)、[Schedules](/langsmith/python/managed-deep-agents-schedules) 和 [Deploy an agent](/langsmith/python/managed-deep-agents-deploy)。

## 安装

`mda init` 会将 `managed-deepagents` 声明为项目依赖，因此请从项目内部运行 `mda` 二进制。

```bash uv
uvx --from managed-deepagents mda init my-agent
cd my-agent
uv sync
uv run mda --version
```

该包提供 agent、identity、schedule 和 sandbox 的编写 API（snake-case 命名），以及 `mda` console script。




## 认证

`mda deploy` 会按以下顺序读取 API keys：

1. `LANGGRAPH_HOST_API_KEY`
2. `LANGSMITH_API_KEY`
3. `LANGCHAIN_API_KEY`

CLI 会先从项目 `.env` 文件读取这些值，再读取进程环境变量。如果在交互式终端中没有找到 key，`mda deploy` 会提示你输入 LangSmith API key，并将其保存到项目 `.env` 文件中。

```text .env
LANGSMITH_API_KEY=<LANGSMITH_API_KEY>
OPENAI_API_KEY=<OPENAI_API_KEY>
```

如果你想使用 organization-scoped key 进行部署，请设置 `LANGSMITH_WORKSPACE_ID`，或在 `mda deploy` 时传入 `--workspace-id`。

LangSmith API key 用于 deploy 鉴权。Agent 在运行时还需要模型 provider 的凭据。你可以把 provider key 放进 `.env`、shell 环境变量，或配置为 LangSmith workspace secret。例如，`openai:gpt-5.5` 需要 `OPENAI_API_KEY`。

`mda deploy` 会把非保留的 `.env` 项，例如 `OPENAI_API_KEY`、MCP tokens 和自定义 tool 凭据，作为托管 deployment secrets 转发。包括 `LANGSMITH_API_KEY`、`LANGGRAPH_HOST_API_KEY`、`LANGCHAIN_API_KEY` 和 `LANGSMITH_WORKSPACE_ID` 在内的保留平台变量，只用于 CLI 认证与 deploy 路由，不会作为用户可管理的 deployment secrets 上传。

## 命令概览

| 命令 | 用途 |
| --- | --- |
| `mda --help` | 显示 CLI 帮助。 |
| `mda --version` | 显示当前安装的 CLI 版本。 |
| `mda init <name>` | 创建 Python Managed Deep Agents 项目脚手架。 |
| `mda build [path]` | 编译项目为托管 LangGraph app，但不部署。 |
| `mda evals …` | 初始化 Harbor workspace，并在 coding agent 中继续编写 eval。 |
| `mda dev [path]` | 编译项目，并在本地 LangGraph dev server 上运行。 |
| `mda connections …` | 管理 tools 和 MCP connectors 的认证。 |
| `mda deploy [path]` | 编译、同步 Context Hub context、上传并部署到 LangSmith。 |
| `mda channels init slack` | 在当前项目中添加 Slack channel 声明。 |
| `mda logs [path]` | 查看已部署 agent 的 Agent Server 日志。 |
| `mda delete [path]` / `mda destroy [path]` | 删除已部署的 agent 及其创建的 LangSmith 资源。 |




## 初始化项目

使用 `mda init` 创建新项目目录：

```bash
uvx --from managed-deepagents mda init my-agent
```




| 参数或 flag | 用途 |
| --- | --- |
| `name` | 必填，项目目录名。如果目标目录已存在，命令会失败。 |
| `--instructions TEXT` | 写入 `instructions.md` 的 system prompt。 |
| `--instructions-file PATH` | 从文件读取 system prompt 写入 `instructions.md`，设为 `-` 时从 stdin 读取。 |
| `--identity` | 添加带用户私有 threads 的托管认证。 |
| `--memory agent\|none` | 可选地写入一个根 memory 声明。如果省略，不会创建 memory 文件，持久 memory 处于关闭状态。 |
| `--model SPEC` | Agent 运行的 model，格式为 `provider:model`。 |
| `--no-sandbox` | 不包含托管 sandbox 声明。 |
| `--channel slack` | 初始化 agent 时写入 Slack channel 声明。可重复使用；`--channels` 是其别名。 |

要在新项目中包含 Slack：

```bash
uvx --from managed-deepagents mda init my-agent --channel slack
```




脚手架语言取决于你运行哪个包，而不是当前目录：PyPI 包总是生成 Python 项目。从 PyPI 安装的 CLI 会拒绝生成 TypeScript 项目。




脚手架会创建：

| 文件 | 说明 |
| --- | --- |
| `agent.py` | 使用 `define_deep_agent(...)` 导出的命名 `agent`。 |
| `instructions.md` | 托管 system prompt。 |
| `pyproject.toml` | 最小语言清单文件。 |
| `README.md` | 本地项目说明。 |
| `.env` | Deploy 鉴权与运行时 secrets。不要提交真实 secrets。 |
| `.gitignore` | 忽略 `.env`、`.env.*`、`.mda/` 和依赖缓存。 |




Eval tasks 是可选的，`mda init` 不会创建。请在项目根目录运行 `mda evals init -i` 来初始化 Harbor workspace，并在 coding agent 中借助 `eval-engineering` skill 继续工作。

## 初始化 Slack channel

在现有 managed deep agent 项目的根目录运行以下命令：

```bash
uv run mda channels init slack
```




该命令会在 `channels/` 目录下创建一个 Slack channel 声明。下一次 `mda deploy` 会配置好 agent 出现在 Slack 中所需的资源。完整流程请参见 [Connect a Managed Deep Agent to Slack](/langsmith/python/managed-deep-agents-channels-slack)。

## 编译项目

使用 `mda build` 编译项目为托管 LangGraph app，但不部署：

```bash
uv run mda build
```




| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--out OUT` | 编译后 app 的输出目录，默认为 `<path>/.mda/build`。该目录在编译前会被清空，因此它必须不存在、为空，或是一个由之前编译写入的目录。 |

## 评估项目

使用 `mda evals init` 初始化 Harbor workspace。通过交互式 handoff，你可以在 coding agent 中借助 `eval-engineering` skill 开发完整的 tasks。

```bash
uv run mda evals init -i
```




| 命令或 flag | 用途 |
| --- | --- |
| `mda evals init` | 在 `evals/harbor-job.json` 缺失时创建它，并在 `.mda/evals/` 下生成 Harbor adapter 和运行时设置。请在项目根目录运行此命令。 |
| `-i`、`--interactive` | 启动检测到的 coding agent 并载入 eval-engineering 提示词，或复制该提示词供其他 agent 使用。 |

这份 handoff 会要求 coding agent 安装 `eval-engineering` skill、检查托管 agent，并在 `evals/<task>/` 下编写完整的 Harbor tasks。其中还包含固定版本的 Harbor 命令，用于加载 MDA job plugin 和 LangSmith plugin。

`mda evals compile` 是一个内部命令，供 Harbor job plugin 使用。该 plugin 会在 Harbor job 启动时运行它，因此你不需要单独编译 eval artifacts。

关于工作流指导，请参见 [Evals](/langsmith/python/managed-deep-agents-evals)。

## 本地开发

使用 `mda dev` 编译项目，并运行本地 LangGraph dev server：

```bash
uv run mda dev
```




| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--port PORT` | 传递端口给 LangGraph dev server。 |
| `--hostname HOSTNAME` | 传递主机名给 LangGraph dev server。 |
| `--no-browser` | 阻止 dev server 启动时在浏览器中打开 Studio。 |
| `--no-reload` | 关闭 dev server 的 hot reload。 |

`mda dev` 会先编译到 `.mda/build`，然后在该目录中启动对应语言的 LangGraph dev server：

| 项目语言 | Dev server 命令 |
| --- | --- |
| Python | `uv run --with langgraph-cli[inmem]>=0.4.30 langgraph dev` |

在运行 `mda dev` 前请先安装 `uv`。CLI 会自动解析本地 LangGraph dev server，因此你不需要自行安装 `langgraph-cli[inmem]`。




如果配置了 sandbox，`mda dev` 会优先尝试配置的 provider。如果缺少 provider 凭据，或 provider 创建失败，它会退回到本地临时目录 sandbox，并打印实际使用的路径。

在本地开发时，`mda dev` 会把项目 `.env` 文件暂存到 `.mda/build/.env`，以便 LangGraph 加载 model provider keys 和其他运行时凭据。

## 管理连接

连接（connection）将一个托管 deep agent 关联到外部服务。凭据保存在 LangSmith workspace 中，因此轮换时无需重新部署，而用户拥有的连接会解析调用该 agent 的人的凭据。Tools 和 MCP connectors 会在运行时通过 `connections.get(...)` 解析连接。

可以用三种模式创建连接：opaque secret（固定 API key）、general OAuth（来自目录中的 BYOT 应用或自定义 endpoint），或 MCP OAuth（从 MCP server URL 发现并注册）。使用 `mda connections` 在当前 workspace 中管理这些凭据。

| 命令 | 用途 |
| --- | --- |
| `mda connections catalog` | 列出带有预配置 OAuth 设置的服务。 |
| `mda connections create <slug>` | 创建 opaque secret、general OAuth 或 MCP OAuth 连接。 |
| `mda connections list` | 列出 workspace 的连接元数据。 |
| `mda connections get <slug>` | 显示一个连接的元数据。 |
| `mda connections delete <slug>` | 删除连接及其存储的内容。 |

`mda connections create` 的第一个参数是一个 slug，即你为连接起的名字，也是代码传给 `connections.get(...)` 的名字。Provider 名称传给 `--oauth`。

OAuth 目录让你无需查找 provider 的 OAuth 设置。当你把目录中列出的服务传给 `--oauth` 时，CLI 会提供其 authorization URL、token URL、token endpoint 认证方式、authorization 参数和默认 scopes，因此你只需提供 client ID 和 client secret。目录并不限制你可以使用哪些 provider：对于其他任何 provider，传入 `--authorize-url` 和 `--token-url`。目录中的名称包括 `github`、`google`、`linear`、`slack`、`atlassian` 和 `notion-api`：

```bash
uv run mda connections catalog
```




为一个自定义 Tavily tool 创建一个 agent 拥有的 API key：

```bash
uv run mda connections create organization-tavily --secret-from-env TAVILY_API_KEY
```




以下 flag 控制连接创建：

| Flag | 用途 |
| --- | --- |
| `--project PATH` | 设置项目目录。默认为当前目录。 |
| `--workspace-id WORKSPACE_ID` | 覆盖 `LANGSMITH_WORKSPACE_ID`。 |
| `--secret-from-env VAR` | 从 shell 或项目 `.env` 读取固定值或 OAuth client secret。 |
| `--secret-from-file PATH` | 从文件读取固定值或 OAuth client secret。 |
| `--oauth SERVICE` | 使用 `mda connections catalog` 中某个服务的预配置设置。 |
| `--grant-type GRANT` | 将 OAuth grant 设为 `authorization_code` 或 `client_credentials`。默认为 `authorization_code`。 |
| `--client-id CLIENT_ID` | 设置 OAuth client ID。 |
| `--auth-method METHOD` | 将 token endpoint 方法设为 `client_secret_basic`、`client_secret_post` 或 `none`。 |
| `--scope SCOPE` | 替换 provider 的默认 scopes。每个 scope 重复一次。 |
| `--allowed-scope SCOPE` | 设置授权流程可以请求的最大 scope。每个 scope 重复一次。 |
| `--authorization-param KEY=VALUE` | 添加一个 OAuth authorization 查询参数。每个参数重复一次。 |
| `--token-param KEY=VALUE` | 向 OAuth token 请求添加一个参数。每个参数重复一次。 |
| `--authorize-url URL` | 设置自定义 OAuth authorization endpoint。需要 `--token-url`。 |
| `--token-url URL` | 设置自定义 OAuth token endpoint。对于 `authorization_code` grant，需要 `--authorize-url`。 |
| `--mcp URL` | 通过从 MCP server URL 发现 OAuth 来创建 MCP OAuth 连接。 |
| `--authorize` | 登录已部署 agent 使用的账户，存储一个 agent 拥有的 OAuth grant。需要 OAuth flag 和项目目录。 |

在不带任何 value flag 也不带 `--oauth` endpoint 的情况下，当 slug 恰好匹配项目中一个用户拥有的 MCP 连接时，`mda connections create <slug>` 会推断为 MCP OAuth。

在 `catalog`、`list` 或 `get` 上使用 `--json` 获得机器可读输出。在 `delete` 上使用 `--yes` 跳过确认提示。

关于凭据所有者、创建模式、调用者身份和运行时示例，请参见[管理连接](/langsmith/python/managed-deep-agents-connections)。

## 部署项目

使用 `mda deploy` 编译并将项目部署到 LangSmith：

```bash
uv run mda deploy
```




| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--name NAME` | Deployment 名称。默认使用 `define_deep_agent` 中的 agent `name`。 |
| `--deployment-type dev\|prod` | 创建 deployment 时使用的类型，默认为 `dev`。 |
| `--workspace-id WORKSPACE_ID` | 要部署到的 Workspace ID，会覆盖 `LANGSMITH_WORKSPACE_ID`。 |
| `--context-strategy overwrite\|keep-hub` | 当 `instructions.md` 或 `skills/` 自上次同步后在 Hub 中发生了变化时，解决 Context Hub 冲突。在非交互式 shell 中必填。参见 [Context Hub](/langsmith/python/managed-deep-agents-context-hub#source-of-truth)。 |
| `--no-wait` | 触发远程构建后立即退出，不轮询 deployment 完成状态。 |




Deploy 会执行以下步骤：

1. 校验项目目录并加载 agent 入口文件。
2. 解析 LangSmith API key 和可选的 workspace ID。
3. 收集非保留的 `.env` 项作为托管 deployment secrets。
4. 验证模型 provider API key 可从 `.env`、shell 环境变量或 LangSmith workspace secrets 中获取。
5. 将 deploy 拥有的 context 同步到 Context Hub。
6. 将项目编译到 `.mda/build`，并提取可选的 `schedules/` 和 `channels/` 声明。
7. 按名称创建或查找 LangSmith 托管 deployment。
8. 归档构建产物、上传并触发远程构建。
9. 除非设置了 `--no-wait`，轮询 revision 直到其达到 `DEPLOYED`。
10. 除非设置了 `--no-wait`，为 schedules 协调受管的 LangSmith cron jobs。
11. 配置已声明的 Slack channel。如果需要 Slack 授权或 workspace 审批，会显示相应操作，并在你完成之后继续。

包含 Slack channel 的项目无法使用 `--no-wait`，因为 Slack 配置需要部署后的 Agent Server URL。完整流程请参见 [Connect a Managed Deep Agent to Slack](/langsmith/python/managed-deep-agents-channels-slack)。

成功后，CLI 会打印 LangSmith deployment dashboard URL。关于 secrets 路由和 deploy 提示，请参见 [Deploy an agent](/langsmith/python/managed-deep-agents-deploy)。

## 查看部署日志

使用 `mda logs` 查看已部署 agent 的 Agent Server 日志：

```bash
uv run mda logs
```




| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--name NAME` | Deployment 名称。默认使用项目中的 agent `name`。 |
| `--lines LINES` | 获取的最近日志行数。默认为 `1000`。 |
| `--level LEVEL` | 只显示达到或超过指定严重级别的条目：`debug`、`info`、`warning`、`error` 或 `critical`。 |
| `--follow` | 持续流式输出新日志。在交互式终端中这是默认行为。 |
| `--no-follow` | 打印最近日志后退出。在输出被管道传递时这是默认行为。 |
| `--workspace-id WORKSPACE_ID` | 读取的 Workspace ID。会覆盖 `LANGSMITH_WORKSPACE_ID`。 |

## 删除 deployment

使用 `mda delete` 删除已部署的 Managed Deep Agent 及其创建的 LangSmith 资源。`mda destroy` 是其别名。

```bash
uv run mda delete
```




| 参数或 flag | 用途 |
| --- | --- |
| `path` | 项目目录，默认为当前目录。 |
| `--name NAME` | Deployment 名称。默认使用 `define_deep_agent` 中的 agent `name`。 |
| `--workspace-id WORKSPACE_ID` | Deployment 所在的 Workspace ID。会覆盖 `LANGSMITH_WORKSPACE_ID`。 |
| `--yes` | 删除时不要求确认。 |




## 故障排查

| 症状 | 原因与修复 |
| --- | --- |
| `project root ... is not a directory` | 请给 `mda dev` 或 `mda deploy` 传入目录路径。 |
| `no agent entry file found` | 请在项目根目录添加 `agent.py`。 |
| `mda dev` 找不到 `uv` | 请安装 `uv`，以便 `mda dev` 解析本地 LangGraph dev server。 |
| `No LangSmith API key found` | 请设置 `LANGSMITH_API_KEY`，或把它写入项目 `.env`。 |
| Deploy 失败并返回 401 或 403 | 请确认该 API key 对应的 workspace 具有部署访问权限。参见 [Pricing plans](/langsmith/pricing-plans)。 |
| Deploy 报缺少模型 provider API key | 请将 `OPENAI_API_KEY` 等 provider key 加入 `.env`、导出到 shell 环境变量，或配置为 LangSmith workspace secret。 |
| Deploy 报 Context Hub 冲突 | `instructions.md` 或 `skills/` 自上次同步后在 Context Hub 中发生了变更，或 repo 在同步期间发生了变更。在交互式终端中，回答覆盖提示。在非交互式 shell 中，使用 `--context-strategy overwrite` 或 `--context-strategy keep-hub` 重新运行。参见 [Context Hub](/langsmith/python/managed-deep-agents-context-hub#source-of-truth)。 |
| Build 超过 200 MB | 请在部署前从项目中移除生成的 artifacts 或大文件。 |
| Deployment 进入 `BUILD_FAILED` 或 `DEPLOY_FAILED` | 请在 LangSmith 中打开打印的 deployment URL，查看 revision logs。 |
