Agent definition 选择 managed deep agent 的模型和核心能力。

<ManagedDeepAgentsPublicBetaNote />

Agent 入口文件位于项目根目录：

```text
my-agent/
  agent.py
```




完整的项目布局请参见 [Project structure](/langsmith/python/managed-deep-agents-project-structure)。

要定义 agent，请使用 `define_deep_agent`：

<CodeGroup>
```python OpenAI
from managed_deepagents import define_deep_agent

agent = define_deep_agent(
    name="research-assistant",
    model="openai:gpt-5.5",
)
```

```python Anthropic
from managed_deepagents import define_deep_agent

agent = define_deep_agent(
    name="research-assistant",
    model="anthropic:claude-sonnet-4-6",
)
```

```python Google Gemini
from managed_deepagents import define_deep_agent

agent = define_deep_agent(
    name="research-assistant",
    model="google_genai:gemini-3.6-flash",
)
```
</CodeGroup>




System prompt、skills、memory、sandbox、identity、channels 和 schedules 通过各自的项目文件配置，而不是通过 agent definition。参见 [Project structure](/langsmith/python/managed-deep-agents-project-structure)。要为每次 run 选择 system prompt、skills、MCP 服务器或 sandbox，请参见 [Select configuration per run](#select-configuration-per-run)。

`define_deep_agent` 不会编译 agent。它返回一个定义，由托管运行时在部署时使用 [create_deep_agent](https://reference.langchain.com/python/deepagents/graph/create_deep_agent) 编译。下面的参数是 [create_deep_agent](https://reference.langchain.com/python/deepagents/graph/create_deep_agent) 的接口去掉运行时拥有的部分。参见 [Relationship to Deep Agents](/langsmith/python/managed-deep-agents-overview#relationship-to-deep-agents)。




## 参数

| 参数 | 作用 |
|---|---|
| `name=` | 必填。传入一个以字母开头、只包含字母、数字、下划线或连字符的静态字符串，例如 `"research-assistant"`。<br /><br /> Managed Deep Agents 将该名称用作 agent 的 graph ID 和默认的 LangSmith deployment 名称，client 调用 deployment 时将它作为 `assistant_id` 传入。你可以用 `mda deploy --name` 覆盖 deployment 名称，而不必修改 agent definition。 |
| `model=` | 设置 agent 使用的 chat model。最简单的方式是 `provider:model` 字符串。将 provider 的 API key 添加到 `.env`，模型才能在本地和 deployment 中工作。<br /><br /> 当你需要在代码中配置模型参数时，改为传入 LangChain chat model 实例。关于模型选项和支持的 provider，请参见 [Models](/oss/python/deepagents/models)。<br /><br /> 要连接 LLM Gateway，请参见 [Use LLM Gateway](#use-llm-gateway)。 |
| `tools=` | 添加 agent 可以调用的 tools。将 tools 放入 `tools` 列表，agent 才能调用应用逻辑或外部服务。<br /><br /> 在本地模块中定义 tools，import 到 agent 入口，并加入定义。参见 [Custom tools](/langsmith/python/managed-deep-agents-tools)。要在不 import 到 agent 入口的情况下添加来自远程 MCP 服务器的 tools，请使用 [MCP connectors](/langsmith/python/managed-deep-agents-mcp-connectors)。 |
| `middleware=` | 添加围绕模型调用、tool 调用和 agent 生命周期的行为。将 middleware 放入 `middleware` 列表。Middleware 按列表顺序运行。参见 [Custom middleware](/langsmith/python/managed-deep-agents-middleware)。 |
| `subagents=` | 为委派任务定义专用 agent。当 agent 需要委派专用或上下文繁重的工作时，传入 subagent 定义。每个 subagent 可以有自己的 prompt、model 和 tools。参见 [Subagents](/oss/python/deepagents/subagents)。 |
| `permissions=` | 控制 filesystem tools 的路径级访问。传入 filesystem 权限规则，控制 agent 内置 filesystem tools 可以读写哪些路径。当项目声明了 [sandbox](/langsmith/python/managed-deep-agents-sandboxes) 时会被清空，因为权限规则会禁用 sandbox 的 `execute` tool。参见 [Permissions](/oss/python/deepagents/permissions)。 |
| `interrupt_on=` | 在选定的 tool 调用之前暂停以等待人工批准。设置 `interrupt_on`，在选定的 tool 调用之前暂停，让人可以在调用运行前批准、编辑或拒绝它。参见 [Human-in-the-loop](/langsmith/python/managed-deep-agents-tools#human-in-the-loop)。 |
| `response_format=` | 当 agent 必须返回符合 schema 的数据而不是不受约束的文本响应时设置。参见 [Structured output](/oss/python/langchain/structured-output)。 |




## 为每次 run 选择配置

要为每次 run 选择 agent 的配置，请导出一个函数作为 `agent`，而不是导出定义。这样一个 deployment 就能适应不同的用户、任务或仓库。该函数是一个 graph factory，与 LangGraph 用来[在运行时重建 graph](/langsmith/graph-rebuild) 的模式相同：它接收 runtime 并返回一个定义。

下面的示例为 run 所处理的仓库选择 instructions 和 skills。它假设项目中有 `skills/python-service/` 和 `skills/typescript-web/`，每个目录各包含一个 [`SKILL.md`](/langsmith/python/managed-deep-agents-skills)。

```python agent.py
from typing import TypedDict

from managed_deepagents import ManagedServerRuntime, define_deep_agent


class AppContext(TypedDict, total=False):
    repository: str


def agent(runtime: ManagedServerRuntime[AppContext]):
    execution = runtime.execution_runtime
    context = execution.context if execution is not None else None
    python_service = context is not None and context.get("repository") == "payments-service"
    return define_deep_agent(
        name="open-swe",
        model="openai:gpt-5.5",
        instructions=(
            "Follow the payments service's API and reliability conventions."
            if python_service
            else "Follow the storefront's frontend and accessibility conventions."
        ),
        skills=["./skills/python-service" if python_service else "./skills/typescript-web"],
        context_schema=AppContext,
    )
```

Factory 可以是同步或异步的。它接收一个 `ManagedServerRuntime`，后者扩展了 LangGraph 原生的 `ServerRuntime`。从 `execution_runtime.context` 读取 run context。在 channel runs 上它是 `None`，而当 Agent Server 为检查目的加载 agent 时 `execution_runtime` 是 `None`。




调用方通过 run 的 `context` 选择配置：

```python
await client.runs.create(
    thread_id,
    "open-swe",
    input={"messages": [{"role": "user", "content": "Run the service test suite."}]},
    context={"repository": "payments-service"},
)
```




Run context 是应用数据，不是经过验证的身份。请在 [tools](/langsmith/python/managed-deep-agents-tools) 中对照 runtime 上经过验证的调用方检查授权。

### 选择托管资源

Factory 还可以选择静态 agent 从项目文件读取的资源。省略某个字段会保留项目的配置。提供值则会为该次 run 替换它：

| 字段 | 省略 | 选择 | 清空 |
|---|---|---|---|
| `instructions` | 使用 `instructions.md`。 | 使用提供的 prompt。 | `""` 移除已编写的 instructions。 |
| `skills` | 暴露所有项目 skills。 | 只暴露选定的 skills。 | `[]` 不暴露任何 skills。 |
| `mcp` | 使用 `mcp` 声明。 | 只使用选定的 MCP 定义。 | `[]` 不暴露任何 MCP tools。 |
| `sandbox` | 使用 `sandbox` 声明。 | 使用提供的 sandbox。 | `None` 禁用 sandbox。 |




静态定义无法设置这些字段。Skill 路径必须以 `skills/<name>` 结尾，并指向项目中的一个 skill。Factory 也可以返回生成的 skill 定义，其名称不得与项目 skill 名称重复。

下面的示例按需启用 docs MCP 服务器，并为一个仓库提供更长的 sandbox 超时时间。它从 [`tools/mcp`](/langsmith/python/managed-deep-agents-mcp-connectors) 和 [`sandbox/`](/langsmith/python/managed-deep-agents-sandboxes) import 声明：

```python agent.py
from typing import TypedDict

from managed_deepagents import ManagedServerRuntime, define_deep_agent, define_sandbox

from sandbox import sandbox
from tools.mcp import mcp


class AppContext(TypedDict, total=False):
    repository: str
    needs_docs: bool


def agent(runtime: ManagedServerRuntime[AppContext]):
    execution = runtime.execution_runtime
    context = execution.context if execution is not None else None
    python_service = context is not None and context.get("repository") == "payments-service"
    needs_docs = context is not None and context.get("needs_docs", False)
    return define_deep_agent(
        name="open-swe",
        model="openai:gpt-5.5",
        mcp=[mcp] if needs_docs else [],
        sandbox=define_sandbox(default_timeout=600) if python_service else sandbox,
        context_schema=AppContext,
    )
```




Memory 不按 run 选择。请在项目的 memory 文件中声明它，并用 `allow` 策略控制每次 run 的访问。参见 [Control access to a layer](/langsmith/python/managed-deep-agents-memory#control-access-to-a-layer)。

### 保持 factory 可重复

Managed Deep Agents 在每次 run 开始时调用 factory，并在 run 恢复或重试时再次调用。Agent Server 也会调用它来读取 schema 和 state。请遵循以下规则：

- **无副作用**：相同的 context 返回相同的定义。不要在 factory 中创建记录、调用外部 API 或修改共享状态。
- **Stable interrupts**：将可能中断 run 的 middleware 保留在每个配置中。当 run 恢复时，引发 interrupt 的 middleware 必须仍然存在。
- **Inline name**：将 `name` 设置为内联字符串。`mda build` 无需调用 factory 即可读取它，并将其用作 graph ID 和默认 deployment 名称。
- **Model dependencies**：为 factory 可能返回的每个模型安装对应的 integration package。构建过程不会检测它们。

要在 run 内的模型调用之间改变行为，请使用 [custom middleware](/langsmith/python/managed-deep-agents-middleware)。

## 使用 LLM Gateway

你可以使用 [LLM Gateway](/langsmith/llm-gateway) 对模型调用应用速率限制、fallback 和其他策略。

在 gateway 模型 ID 前加 `langsmith:` 前缀：

```python
from managed_deepagents import define_deep_agent

agent = define_deep_agent(
    name="my-agent",
    model="langsmith:moonshotai/kimi-k3",
)
```




<Note>
Gateway 模型 ID 在 provider 和模型之间使用斜杠（`langsmith:provider/model-name`）。直接调用 provider 的模型字符串使用冒号（`provider:model-name`）。
</Note>

Gateway 按模型 ID 路由每个请求。`moonshotai/kimi-k3` 是 LangChain 托管的模型，因此不需要 provider secret，并消耗 [Gateway Credits](/langsmith/llm-gateway-credits)。以你的 workspace 已配置的 provider 开头的模型 ID，例如 `anthropic/claude-opus-5`，则使用对应的 [provider secret](/langsmith/llm-gateway-admin-setup#1-add-provider-secrets)，并计入你自己的 provider 账户。

更多信息请参见 [LLM Gateway](/langsmith/llm-gateway)。

要从一开始就搭建使用 Gateway 的项目，请在初始化时传入 `--gateway`：

```bash
mda init my-agent --gateway
```
