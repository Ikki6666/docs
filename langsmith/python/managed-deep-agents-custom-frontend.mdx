自定义 frontend 是你编写的、直接调用 deployment 的任何应用，而不是通过 [channel](/langsmith/python/managed-deep-agents-channels) 或 [LangSmith Studio](/langsmith/python/managed-deep-agents-local-development#start-local-studio) 访问 agent。当 agent 需要嵌入到你控制的产品界面中时，例如支持控制台、内部 dashboard 或面向客户的聊天页面，请使用自定义 frontend。

Managed Deep Agents deployments 运行在 [LangSmith Agent Server](/langsmith/agent-server-overview) 上，因此 frontend 与每个 Agent Server client 使用的 threads、runs 和 streaming endpoints 通信。Agent 侧无需任何改动即可支持 frontend。

## 选择 identity 模式

Frontend 代码在哪里运行，决定了它能使用哪种 [identity](/langsmith/python/managed-deep-agents-identity) 模式。LangSmith API key 授予对整个 workspace 的访问权限，因此绝不能让它进入浏览器。

| Frontend | 凭据存放位置 | Identity 模式 |
| --- | --- | --- |
| 浏览器应用（React、Vue、Svelte、Angular） | 用户的浏览器 | [Supabase](/langsmith/python/managed-deep-agents-identity#configure-identity-with-supabase) |
| 转发浏览器请求的服务器路由或代理 | 你的服务器 | [LangSmith API key](/langsmith/python/managed-deep-agents-identity#configure-identity-with-a-langsmith-api-key) 或 [你自己的 backend](/langsmith/python/managed-deep-agents-identity#configure-identity-with-your-own-backend) |
| Python 应用（Streamlit、Gradio、Dash） | 你的服务器 | LangSmith API key |
| 使用 `mda dev` 进行本地开发 | 无需凭据 | 任意 |

使用 backend identity 时，浏览器永远不会调用 deployment。你的 API 先对用户进行认证，然后使用 ingress secret 调用 deployment。Supabase 和 backend identity 还会为每个已登录用户提供私有的 threads。API key 默认方式不会：所有持有该 key 的调用方共享同一个 thread 空间。

<Warning>
任何持有 LangSmith API key 的人都可以访问该 deployment 以及 workspace 中的其他所有资源。将 key 打进浏览器 JavaScript 会让每个访客都能获取它。当浏览器调用 deployment 时，请使用 Supabase。否则，请将凭据保留在浏览器所调用的服务器路由上。
</Warning>

## 连接到 deployment

Frontend 需要两个值。

**Deployment API URL。** `mda deploy` 打印的是 LangSmith deployment dashboard URL，而不是 API URL。打开该 dashboard，然后在 deployment 详情视图中复制 **API URL**。[`mda dev`](/langsmith/python/managed-deep-agents-local-development) 启动的本地服务器会在 CLI 打印的 URL 上提供相同的路由。

**Assistant ID。** Client 传入 [agent definition](/langsmith/python/managed-deep-agents-agent-definition#parameters) 中 agent 的 `name`，Managed Deep Agents 也将该名称用作 graph ID：

```python agent.py
from managed_deepagents import define_deep_agent

agent = define_deep_agent(
    name="research-assistant",  # [!code highlight]
    model="openai:gpt-6.1-sol",
)
```




Client 以 `assistantId: "research-assistant"` 寻址名为 `research-assistant` 的 agent。重命名 agent 会改变 client 发送的值，因此请把这个名称当作 deployment 公共接口的一部分。

## 构建 web frontend

[LangChain frontend SDKs](/oss/python/langchain/frontend/overview) 将浏览器应用连接到 Agent Server deployment。`useStream` 以响应式值的形式暴露 messages、tool 调用、interrupts 和 thread state：

| Framework | Package | Entry point |
| --- | --- | --- |
| React | `@langchain/react` | `useStream` |
| Vue | `@langchain/vue` | `useStream` |
| Svelte | `@langchain/svelte` | `useStream` |
| Angular | `@langchain/angular` | `injectStream` |

Frontend 是 web 应用，因此无论 agent 是用 Python 还是 TypeScript 编写的，这些示例都是 TypeScript。

将 hook 指向 deployment API URL 和 agent 名称：

```tsx Chat.tsx
import { useStream } from "@langchain/react";
import { useState } from "react";

export function Chat() {
  const [input, setInput] = useState("");
  const stream = useStream({
    apiUrl: import.meta.env.VITE_DEPLOYMENT_API_URL,
    assistantId: "research-assistant",
    defaultHeaders: { Authorization: `Bearer ${accessToken}` },
  });

  return (
    <main>
      {stream.messages.map((message) => (
        <p key={message.id}>{message.text}</p>
      ))}

      <form
        onSubmit={(event) => {
          event.preventDefault();
          stream.submit({ messages: [{ type: "human", content: input }] });
          setInput("");
        }}
      >
        <input value={input} onChange={(event) => setInput(event.target.value)} />
        <button type="submit" disabled={stream.isLoading}>
          Send
        </button>
      </form>
    </main>
  );
}
```

`defaultHeaders` 携带已登录用户从你的 auth flow 获得的 Supabase access token。对于 API key 默认方式，请改为传入 `apiKey`，SDK 会将其作为 `x-api-key` 发送。只应在服务器上运行的代码中这样做。

这些模式无需改动即可应用于 Managed Deep Agents deployment：[tool-call rendering](/oss/python/langchain/frontend/tool-calling)、[generative UI](/oss/python/langchain/frontend/generative-ui-overview)、[human-in-the-loop approval](/oss/python/langchain/frontend/human-in-the-loop)、[queued submissions](/oss/python/langchain/frontend/message-queues) 和 [durable rejoin](/oss/python/langchain/frontend/join-rejoin)。

### 处理授权 interrupt

当 agent 需要一个调用方尚未授权的 [user-owned connection](/langsmith/python/managed-deep-agents-connections) 时，run 会暂停，`stream.interrupt` 会携带 credential gate payload。浏览器 frontend 渲染 consent 链接，并用 `stream.respond` 恢复。关于 payload 的结构和完整示例，请参见 [Handle the authorization interrupt](/langsmith/python/managed-deep-agents-connections#handle-the-authorization-interrupt)。

## 构建 Python frontend

Streamlit、Gradio 和 Dash 都在服务器上渲染，因此 LangSmith API key 不会进入浏览器，API key 默认方式无需额外配置即可使用。三者都使用同一个 [LangGraph SDK](https://reference.langchain.com/python/langgraph-sdk) client，因此下面的连接代码适用于其中任何一个。

将 SDK 与你的应用框架一起安装：

```bash
uv add langgraph-sdk streamlit
```

创建一个 client，然后针对某个 thread 流式执行 run：

```python
from langgraph_sdk import get_sync_client

client = get_sync_client(
    url=DEPLOYMENT_API_URL,
    api_key=LANGSMITH_API_KEY,
)

thread = client.threads.create()

for chunk in client.runs.stream(
    thread["thread_id"],
    "research-assistant",
    input={"messages": [{"role": "user", "content": "Summarize this week's incidents."}]},
    stream_mode="messages",
):
    ...
```

三个细节决定该循环的行为：

- **`api_key`**：设置 `x-api-key` 请求头。如果改为传入 `headers={"x-api-key": ...}`，会引发 `ValueError: Cannot set reserved header 'x-api-key'`。
- **环境回退**：省略 `api_key` 时，client 会依次尝试 `LANGGRAPH_API_KEY`、`LANGSMITH_API_KEY`、`LANGCHAIN_API_KEY`。对于 Supabase 或 backend identity，请显式传入 `api_key=None`，并把 token 放进 `headers`，否则一个遗留的环境变量会附加上第二份凭据。
- **`messages/partial`**：携带到目前为止的完整消息，而不是增量。请在每个事件上替换已渲染的文本，而不是追加，否则输出会自我重复。

### 流式输出到 Streamlit chat

这个应用为每个浏览器会话保留一个 thread，并在每个事件到达时重写 assistant 气泡：

```python app.py
import os

import streamlit as st
from langgraph_sdk import get_sync_client

ASSISTANT_ID = "research-assistant"


@st.cache_resource
def get_agent_client():
    return get_sync_client(
        url=os.environ["DEPLOYMENT_API_URL"],
        api_key=os.environ["LANGSMITH_API_KEY"],
    )


def text_of(message):
    return "".join(
        block.get("text", "")
        for block in message.get("content", [])
        if block.get("type") == "text"
    )


client = get_agent_client()

if "thread_id" not in st.session_state:
    st.session_state.thread_id = client.threads.create()["thread_id"]
    st.session_state.history = []

for role, text in st.session_state.history:
    st.chat_message(role).markdown(text)

if prompt := st.chat_input("Message the agent"):
    st.session_state.history.append(("user", prompt))
    st.chat_message("user").markdown(prompt)

    with st.chat_message("assistant"):
        placeholder = st.empty()
        answer = ""
        for chunk in client.runs.stream(
            st.session_state.thread_id,
            ASSISTANT_ID,
            input={"messages": [{"role": "user", "content": prompt}]},
            stream_mode="messages",
        ):
            if chunk.event != "messages/partial":
                continue
            for message in chunk.data:
                if message.get("type") == "ai":
                    answer = text_of(message)
                    placeholder.markdown(answer)  # [!code highlight]

    st.session_state.history.append(("assistant", answer))
```

高亮的行会在每个事件上替换气泡内容。在那里追加会产生重复文本，因为每个事件都会从头开始重复该消息。

`text_of` 读取的是 content blocks，而不是纯字符串。Agent 消息以带类型的 block 列表形式到达，因此如果 frontend 期望 `message["content"]` 是文本，就渲染不出任何内容。Web SDK 会把每个事件反序列化为一个暴露 `text` 访问器的 message 对象，这就是上面的 React 示例读取 `message.text` 的原因。LangGraph SDK 产出的是普通字典，因此 Python frontend 需要自行提取文本。

Gradio 和 Dash 使用同一个 client 和同一个循环。请用它们的流式原语替代 Streamlit 的 placeholder：为 `gr.ChatInterface` 提供生成器函数，或为 Dash 提供 `dcc.Interval` 回调。
