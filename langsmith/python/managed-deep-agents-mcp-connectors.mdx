将 managed deep agent 连接到远程 [Model Context Protocol (MCP)](/oss/python/deepagents/mcp) 服务器，即可把它们的 tool 添加到 agent。Managed Deep Agents 会创建 MCP client 并加载这些 tool。

大多数远程 MCP 服务器都需要身份验证。一个 [connection](/langsmith/python/managed-deep-agents-connections) 可以提供凭据，而将 connection 声明为 user-owned 可以让每个调用者授权自己的账号。

<ManagedDeepAgentsPublicBetaNote />

在 `tools/mcp.py` 中声明 MCP 服务器：

```text
my-agent/
  agent.py
  tools/
    mcp.py
```




完整的项目布局请参见 [Project structure](/langsmith/python/managed-deep-agents-project-structure)。

如果要在项目中自行实现应用逻辑，请改用 [authored tool](/langsmith/python/managed-deep-agents-tools)。

## 添加 MCP 服务器

当 tool 已经位于某个远程 MCP 服务器上，而你希望 MDA 直接加载它们、无需将其导入 agent 定义时，请使用 MCP 服务器。

<Steps>
  <Step title="声明服务器" id="declare-the-servers">

使用 `define_mcp` 声明一个或多个远程服务器：

```python tools/mcp.py
from managed_deepagents import define_mcp

mcp = define_mcp(
    servers={
        "langchainDocs": {
            "transport": "http",
            "url": "https://docs.langchain.com/mcp",
        },
    },
)
```




该模块必须导出一个模块级 `mcp`。一个项目只有一个 MCP 声明，因此请在其中声明所有服务器。




Managed Deep Agents 支持 Streamable HTTP（`"http"`）和旧版 SSE（`"sse"`）传输方式。不支持 stdio MCP 服务器。请改为通过 HTTP 暴露 stdio 服务器，或者将其操作实现为 [authored tool](/langsmith/python/managed-deep-agents-tools)。

connection 选项请参阅 [Manage connections](/langsmith/python/managed-deep-agents-connections)。

  </Step>
  <Step title="选择 tools（可选）" id="select-tools">

默认情况下，Managed Deep Agents 会暴露每个服务器上的所有 tool。要只暴露选定的 tool，请在该服务器的配置中设置 allowlist：

```python
{
    "transport": "http",
    "url": "https://docs.langchain.com/mcp",
    "include_tools": ["search_docs_by_lang_chain"],
}
```

要暴露除选定 tool 之外的所有 tool，请将 `include_tools` 替换为 `exclude_tools`。




两个选项可以同时使用。denylist 会在 allowlist 之后应用，并且同一个 tool 不能同时出现在两个列表中。

选择使用的是 Managed Deep Agents 为其添加前缀之前的原始 MCP tool 名称。为了避免冲突，tool 名称默认会加上服务器名称前缀。例如，`langchainDocs` 服务器上的 `search_docs_by_lang_chain` tool 会暴露为 `langchainDocs__search_docs_by_lang_chain`。

  </Step>
  <Step title="传入凭据（可选）" id="pass-credentials">

如果 MCP 服务器需要凭据，请在服务器 config 中声明一个 connection，并在 workspace 中创建该 connection。

- **MCP OAuth**：对于声明支持 OAuth 且支持自动 client registration 的服务器，使用 `mda connections create <slug>`（从 MCP 声明推断）或 `mda connections create <slug> --mcp <url>` 创建。你无需提供 client ID 或 secret。
- **Opaque secret 或 general OAuth**：对于静态 API key，或你自己注册的 BYOT OAuth 应用，先创建一个 opaque secret 或 general OAuth connection，然后将服务器的 `connection` 选项设置为 `connections.get(...)`。

创建模式、所有者以及运行时授权请参阅 [Manage connections](/langsmith/python/managed-deep-agents-connections)。

  </Step>
</Steps>

## 配置 MCP 服务器

每个服务器支持以下核心选项：

| 选项 | 说明 |
| --- | --- |
| `transport` | 必填。Streamable HTTP 使用 `http`，旧版 SSE 使用 `sse`。 |
| `url` | 必填。远程 MCP endpoint 的 URL。 |
| `headers` | 发送给服务器的静态 headers。 |
| `include_tools` / `includeTools` | 要暴露的原始 MCP tool 名称。 |
| `exclude_tools` / `excludeTools` | 要隐藏的原始 MCP tool 名称。 |
| `default_tool_timeout` / `defaultToolTimeout` | 每次 tool 调用的超时时间；Python 为秒，TypeScript 为毫秒。 |
| `automatic_sse_fallback` / `automaticSSEFallback` | 对于 HTTP，允许 client 回退到 SSE。 |
| `reconnect` | 对于 SSE，配置重连行为。 |

MCP 定义还接受以下选项：

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `prefix_tool_name_with_server_name` / `prefixToolNameWithServerName` | `true` | 为每个 tool 加上 `{server}__` 前缀。 |
| `throw_on_load_error` / `throwOnLoadError` | `true` | 加载失败时直接报错，而不是以部分 tool 集启动。 |

## Deployment

`mda dev` 和 `mda deploy` 会发现在 `tools/` 下的 MCP 声明，并将其纳入托管配置。该声明不会同步到 Context Hub。

## 何时使用 MCP connectors

| 概念 | 类型 | 如何作用于 agent |
| --- | --- | --- |
| **MCP 服务器** | 托管配置 | 在 `tools/` 下的 MCP 模块中声明；无需导入到 agent 入口 |
| **[MCP endpoint](/langsmith/python/managed-deep-agents-mcp-endpoint)** | Deployment API | 将 agent 暴露为供 MCP client 调用的 tool |
| **[Authored tools](/langsmith/python/managed-deep-agents-tools)** | 应用代码 | 导入并在 agent 定义中传入 |
| **[Channels](/langsmith/python/managed-deep-agents-channels)** | 托管配置 | 接收外部消息以启动 run，并投递响应 |

更多信息请参见 [Project structure](/langsmith/python/managed-deep-agents-project-structure)。
