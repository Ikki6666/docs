<Note>
LangChain Tuned Evaluators 处于 **[beta](/langsmith/release-stages)** 阶段。在正式发布之前，它们的界面和行为可能会发生变化。
</Note>

LangChain Tuned Evaluators 为你的 traces 附加 feedback。每个 evaluator 都使用针对特定评估任务训练的专用 judge。LangChain 负责编写、测试、版本化并维护 prompt 和 judge model，让你可以专注于使用这些 feedback 发现并修复 agent 中的问题。

Perceived Error (Tuned) 检测带有 agent 犯错、误解请求或把交互引向错误方向的证据的对话。当用户似乎察觉到错误时，它返回 `true`，否则返回 `false`。证据可以包括用户纠正、重复请求、拒绝操作、前后矛盾的响应、承认错误、持续误解或未解决的结果。

使用 Perceived Error feedback 可以：

- 发现没有产生系统错误或显式用户评分的失败。
- 筛选出需要调查的对话，并结合原始交互查看 evaluator 的解释。
- 比较被标记的 threads，识别反复出现的失败模式。
- 将有用的 threads 添加到 evaluation datasets，或将模棱两可的案例送去人工审核。
- 针对从已跟踪失败中提取的示例，测试 agent 的变更。

## 了解 LangChain Tuned Evaluators 的工作方式

<Steps>
  <Step title="添加 evaluator">
    将 LangChain Tuned Evaluator 添加到兼容的 tracing project。
  </Step>
  <Step title="识别符合条件的 thread">
    LangSmith 识别出符合 evaluator 要求以及 project 的 filters 和 sampling 配置的 thread。
  </Step>
  <Step title="评估 thread">
    LangChain 管理的专用 judge 评估该符合条件的 thread。
  </Step>
  <Step title="附加 feedback">
    LangSmith 将结果及其解释作为 feedback 附加到该 thread 上。
  </Step>
</Steps>

## 开始之前

添加 Perceived Error (Tuned) 之前：

- 必须由 [organization 管理员](/langsmith/rbac#organization-admin)为 organization 启用 LangChain Tuned Evaluators。
- 源必须是使用 [threads](/langsmith/threads) 的 tracing project。Perceived Error (Tuned) evaluator 不能在单个 runs 上运行。
- Thread traces 必须包含受支持的 [message lists](/langsmith/online-evaluations-multi-turn#prerequisites)。至少要有一条非空的用户消息后面跟着一条非空的助手消息。
- 每个 thread 在 evaluator 运行之前必须至少包含两条 traces。

## 启用 LangChain Tuned Evaluators

启用 LangChain Tuned Evaluators 后，成员可以在整个 organization 的 tracing projects 上附加它们。评估数据使用 LangChain 管理的 API keys 进行处理。

以 organization 管理员身份启用 LangChain Tuned Evaluators：

1. 在 [LangSmith UI](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=langsmith-tuned-evaluators) 中，打开 **Settings**。
1. 选择 **Tuned evaluators**。
1. 开启 **Enable LangChain Tuned evaluators** 并接受条款。

organization 管理员也可以在第一次从 evaluator gallery 保存某个 evaluator 时接受并启用 LangChain Tuned Evaluators。

## 将 LangChain Tuned Evaluator 添加到 project

将 Perceived Error (Tuned) 添加到 tracing project：

1. 打开一个 tracing project，选择 **Evaluators** 标签页。
1. 选择 **+ Evaluator**。
1. 在 **LangChain Tuned** 下，选择 **Perceived Error (Tuned)**。
1. （可选）配置 filters 和 sampling rate。
1. 点击 **Save**。

在创建 evaluator 之前，LangSmith 会检查 project 中最近的 threads，查找包含完整用户到助手交互的受支持 message list。

当 project 为空，或最近的 threads 中没有兼容的消息结构时，LangSmith 会阻止创建。

## 禁用 LangChain Tuned Evaluators

为 organization 禁用 LangChain Tuned Evaluators：

1. 打开 **Settings**，选择 **Tuned evaluators**。
1. 关闭 **Enable LangChain Tuned evaluators**。

禁用该功能会暂停已附加的 LangChain Tuned Evaluators。LangSmith 会保留它们的配置，当 organization 管理员再次启用该功能时，它们会恢复运行。

## 查看使用费用

各个 LangChain Tuned Evaluator 的可用性和定价不同。LangSmith 只对附加了 feedback 的评估 run 收取 LSUs。没有附加 feedback 的跳过和失败的评估尝试不会计费。

与其他 online evaluators 一样，LangChain Tuned Evaluators 会将被评估的 traces 升级到 extended retention。这会增加 trace 存储费用。当前费率请参阅 [LangSmith pricing](/langsmith/pricing-plans)。关于 retention 升级和 trace 费用的详情，请参阅 [data retention auto-upgrades](/langsmith/usage-and-billing#data-retention-auto-upgrades)。

## LangChain Tuned Evaluators 故障排查

### project 为空

向 tracing project 添加一个 thread，然后再次尝试保存 evaluator。该 thread 必须包含受支持的 message lists 以及至少一个完整的用户到助手交互。

### project 不包含有效的 message list

检查 project 中最近的 threads 的 inputs 和 outputs。它们的顶层 `messages` 字段必须包含[受支持格式](/langsmith/online-evaluations-multi-turn#prerequisites)的 message lists，并且至少要有一条用户消息后面跟着一条助手消息。

### evaluator 不产生 feedback

检查以下条件：

- organization 仍然启用了 LangChain Tuned Evaluators。
- 该 thread 至少包含两条 traces。
- project 的 thread 空闲时间已经过去。
- 该 thread 符合 evaluator 的 filters 和 sampling 配置。
- 该 thread 包含采用受支持消息格式的完整用户到助手交互。

要查看 evaluator 活动，打开 tracing project 的 **Evaluators** 标签页，并选择该 evaluator 的 **Logs**。

### 启用该功能没有立即生效

Organization 设置可能需要几秒钟才能传播。如果 LangSmith 报告 managed-evaluator 设置仍在生效中，请等待几秒钟再试。
