这是 [AWS Terraform modules](https://github.com/langchain-ai/terraform/tree/main/modules/aws) 暴露的每个输入变量的完整参考。可在首次填写 `terraform.tfvars` 或调整现有部署时使用。

变量分为两类：

- **非敏感**（region、容量、功能开关）：在 `infra/terraform.tfvars` 中设置。
- **敏感**（license key、密码、加密密钥）：通过 `infra/scripts/setup-env.sh` 加载，该脚本会把它们写入 AWS SSM Parameter Store；再由 External Secrets Operator 同步到集群。

端到端安装请参见[部署指南](/langsmith/self-host-terraform-aws-deploy)。各 module 如何协同工作请参见[架构参考](/langsmith/self-host-terraform-aws-architecture)。

## 核心

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `name_prefix` | — | 是 | 所有资源名称的前缀。最长 15 个字符：小写字母、数字和连字符，以字母开头。格式：`{prefix}-{environment}-{resource}`。 |
| `environment` | `dev` | 否 | 环境标签：`dev`、`staging`、`prod`、`test` 或 `uat`。 |
| `region` | `us-west-2` | 否 | 所有资源所在的 AWS region。 |
| `owner` | `""` | 否 | 负责该部署的团队或个人。作为标签应用。 |
| `cost_center` | `""` | 否 | 成本中心或计费标签。非空时作为标签应用。 |
| `tags` | `{}` | 否 | 应用到所有资源的附加标签。 |

## 网络

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `create_vpc` | `true` | 否 | 创建新的 VPC。设为 `false` 可使用已有的 VPC。 |
| `vpc_id` | `null` | 当 `!create_vpc` 时 | 已有的 VPC ID。 |
| `private_subnets` | `[]` | 当 `!create_vpc` 时 | 已有的私网子网 ID。 |
| `public_subnets` | `[]` | 当 `!create_vpc` 时 | 已有的公网子网 ID。 |
| `vpc_cidr_block` | `null` | 当 `!create_vpc` 时 | 已有的 VPC CIDR block。 |
| `vpc_private_subnets` | `[]` | 否 | 当 `create_vpc = true` 时覆盖私网子网的 CIDR。留空使用 module 默认值。 |
| `vpc_public_subnets` | `[]` | 否 | 当 `create_vpc = true` 时覆盖公网子网的 CIDR。留空使用 module 默认值。 |

## EKS

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `enable_public_eks_cluster` | `true` | 否 | 启用公网 EKS API endpoint。设为 `false` 可获得私有集群，并启用 `create_bastion`，通过 SSM 从 bastion 运行 Terraform 和 Helm。 |
| `eks_public_access_cidrs` | `["0.0.0.0/0"]` | 否 | 允许访问公网 EKS API endpoint 的 CIDR。限制为公司 VPN 出站 CIDR 可收紧访问。 |
| `eks_cluster_version` | `1.33` | 否 | EKS Kubernetes 版本。 |
| `eks_managed_node_group_defaults` | `{ami_type = "AL2023_x86_64_STANDARD"}` | 否 | 应用于所有托管节点组的默认配置。 |
| `eks_managed_node_groups` | 一个 `default` 组：`m5.4xlarge`，最少 3 个 / 最多 10 个 | 否 | 托管节点组定义。省略 `desired_size` 时默认为 `min_size`。 |
| `create_gp3_storage_class` | `true` | 否 | 创建 `gp3` 并将其设为启用卷扩容的默认 `StorageClass`。 |
| `eks_cluster_enabled_log_types` | `["api", "audit", "authenticator", "controllerManager", "scheduler"]` | 否 | 发送到 CloudWatch 的 EKS control plane 日志类型。设为 `[]` 可禁用。 |
| `eks_addons` | `{}` | 否 | EKS 托管 add-on 配置（`coredns`、`kube-proxy`、`vpc-cni` 等）。 |
| `create_langsmith_irsa_role` | `true` | 否 | 为 LangSmith pods 创建 IRSA 角色（S3 访问）。 |

## PostgreSQL (RDS)

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `postgres_source` | `external` | 否 | `external`（带私有访问的 RDS）或 `in-cluster`（通过 Helm 部署）。 |
| `postgres_instance_type` | `db.t3.large` | 否 | RDS 实例规格。 |
| `postgres_storage_gb` | `10` | 否 | 初始 RDS 存储大小（GB）。 |
| `postgres_max_storage_gb` | `100` | 否 | RDS 最大存储大小（GB，自动扩容）。 |
| `postgres_username` | `langsmith` | 否 | RDS 数据库用户名。 |
| `postgres_engine_version` | `16` | 否 | PostgreSQL 引擎版本。PG 14 将于 2026 年 11 月停止支持；新部署推荐使用 16。 |
| `postgres_password` | `""` | 外部时 | RDS 密码。通过 `TF_VAR_postgres_password` 设置，或由 `setup-env.sh` 自动生成并存入 SSM。 |
| `postgres_iam_database_authentication_enabled` | `true` | 否 | 在 RDS 上启用 IAM 数据库认证。 |
| `postgres_iam_database_user` | `null` | 否 | 用于 IAM 认证的数据库用户。必须已存在于 PostgreSQL 中，并执行过 `GRANT rds_iam TO <user>`。 |
| `postgres_deletion_protection` | `true` | 否 | 防止意外删除 RDS。dev/test 环境可设为 `false`。 |
| `postgres_backup_retention_period` | `7` | 否 | 自动 RDS 备份的保留天数。`0` 表示禁用备份。 |

## Redis (ElastiCache)

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `redis_source` | `external` | 否 | `external`（带私有访问的 ElastiCache）或 `in-cluster`（通过 Helm 部署）。 |
| `redis_instance_type` | `cache.m6g.xlarge` | 否 | ElastiCache 节点类型。 |
| `redis_auth_token` | `""` | 外部时 | ElastiCache auth token。由 `setup-env.sh` 自动生成并存入 SSM。通过 `TF_VAR_redis_auth_token` 设置。 |

## S3

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `s3_ttl_enabled` | `true` | 否 | 启用 S3 生命周期规则，使 trace blob 过期。 |
| `s3_ttl_short_days` | `14` | 否 | 短生命周期对象（`ttl_s/` 前缀）的过期天数。 |
| `s3_ttl_long_days` | `400` | 否 | 长生命周期对象（`ttl_l/` 前缀）的过期天数。 |
| `s3_kms_key_arn` | `""` | 否 | 用于 S3 加密的 KMS CMK ARN。留空使用 SSE-S3（AES256）。 |
| `s3_versioning_enabled` | `false` | 否 | 启用 S3 bucket 版本控制。由于保留历史版本，会增加存储成本。 |

## TLS 与 DNS

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `tls_certificate_source` | `acm` | 否 | TLS source：`acm`、`letsencrypt`（经 ALB 解决的 cert-manager HTTP-01 ACME）或 `none`。对于经 Route 53 的 DNS-01 challenge（集群内 gateway），请改用 `create_cert_manager_irsa`；两者互斥。 |
| `acm_certificate_arn` | `""` | 当 `acm` 时 | 已有的 ACM 证书 ARN。 |
| `letsencrypt_email` | `""` | 当 `letsencrypt` 时 | 用于 Let's Encrypt ACME 注册的邮箱。 |
| `langsmith_domain` | `""` | 否 | 自定义域名。设置后（且 `acm_certificate_arn` 为空），会预配 Route 53 hosted zone、ACM 证书和 alias 记录。留空使用 ALB hostname。 |
| `dns_include_wildcard_san` | `false` | 否 | 在 ACM 证书中添加 wildcard SAN（`*.<langsmith_domain>`）。子域名 HTTPS 需要它。 |
| `langsmith_namespace` | `langsmith` | 否 | LangSmith 的 Kubernetes namespace。 |

## Ingress

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `alb_scheme` | `internet-facing` | 否 | ALB scheme：`internet-facing`（公网子网）或 `internal`（私网子网，可通过 VPN、peering 或 PrivateLink 访问）。 |
| `alb_allowed_cidr_blocks` | `["0.0.0.0/0"]` | 否 | 允许通过 HTTP/HTTPS 访问 ALB 的 CIDR。受限访问部署可限制为 VPN 或办公网 CIDR。 |
| `alb_access_logs_enabled` | `false` | 否 | 启用 ALB 访问日志，写入专用的 S3 bucket。 |
| `enable_envoy_gateway` | `false` | 否 | 安装 Envoy Gateway（Kubernetes Gateway API）以替代 ALB Ingress。多 namespace dataplane 部署必需。 |
| `enable_nginx_ingress` | `false` | 否 | 安装 NGINX ingress controller。ALB 通过 `TargetGroupBinding` 转发到 NGINX controller pods。 |
| `enable_istio_gateway` | `false` | 否 | 在节点安全组上开放 15017 端口，供 istiod sidecar-injector webhook 使用。在 EKS 上运行 Istio 时必需。 |
| `istio_nlb_scheme` | `internet-facing` | 否 | Istio ingress gateway NLB 的 scheme：`internet-facing` 或 `internal`。由 setup 向导写入 `tfvars`，但尚未被任何 module 消费；Istio 路径目前使用 ALB `TargetGroupBinding` 后面的 ClusterIP service。 |
| `create_cert_manager_irsa` | `false` | 否 | 为 cert-manager 经 Route 53 的 DNS-01 challenge 创建 IRSA 角色。Istio Gateway 使用 Let's Encrypt 时必需。apply 之后运行 `make tls`。 |
| `cert_manager_hosted_zone_id` | `""` | 当 `create_cert_manager_irsa` 时 | 用于 cert-manager DNS-01 TXT 记录的 Route 53 hosted zone ID。 |

## ClickHouse

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `clickhouse_source` | `in-cluster` | 否 | `in-cluster`（仅限 dev/POC）或 `external`（LangChain Managed ClickHouse，生产环境推荐）。 |

## Bastion（私有集群）

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `create_bastion` | `false` | 否 | 在公网子网中创建一台 EC2 bastion，通过 SSM Session Manager 或 SSH 访问私有集群。 |
| `bastion_instance_type` | `t3.micro` | 否 | bastion 的 EC2 实例类型。 |
| `bastion_key_name` | `null` | 否 | 用于 SSH 的 EC2 key pair。留空则仅使用 SSM Session Manager。 |
| `bastion_enable_ssh` | `false` | 否 | 在 bastion 安全组上开放 22 端口。 |
| `bastion_ssh_allowed_cidrs` | `[]` | 否 | 允许 SSH 访问 bastion 的 CIDR。仅在 `bastion_enable_ssh = true` 时使用。 |
| `bastion_root_volume_size_gb` | `20` | 否 | bastion 根 EBS 卷大小（GB）。 |

## 安全与审计

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `create_cloudtrail` | `false` | 否 | 创建 CloudTrail trail，将 AWS API 调用记录到 S3。如果账号级或组织级 trail 已存在，可跳过。 |
| `cloudtrail_multi_region` | `true` | 否 | 记录所有 region 的 API 调用。 |
| `cloudtrail_log_retention_days` | `365` | 否 | CloudTrail 日志在 S3 中的保留天数。`0` 表示无限期保留。 |
| `create_waf` | `false` | 否 | 为 ALB 挂载 WAFv2 Web ACL（AWS 托管规则：OWASP Top 10、IP 信誉、恶意输入）。成本：基础约 `$8` 到 `$10`/月。 |
| `create_firewall` | `false` | 否 | 部署 AWS Network Firewall，进行基于 FQDN 的出站过滤。需要 `create_vpc = true`。成本：每个 endpoint 约 `$0.395/hr`，另加 `$0.065/GB`。 |
| `firewall_allowed_fqdns` | `["beacon.langchain.com"]` | 否 | 当 `create_firewall = true` 时允许出站的域名。按 TLS SNI 和 HTTP Host 头匹配。其余目的地一律丢弃。 |
| `firewall_subnet_cidr` | `10.0.64.0/21` | 否 | 防火墙子网的 CIDR。必须在 VPC CIDR 内，且不得与公网或私网子网重叠。 |

## 容量与功能开关

`sizing_profile` 和大多数 `enable_*` 开关由 `init-values.sh` 和 `deploy.sh` 读取；Terraform 不会直接处理它们。它们影响脚本生成的 Helm overlay 文件。三个独立开关（`enable_fleet`、`enable_standalone_polly`、`enable_standalone_insights`）是例外：Terraform 会读取它们以创建 database-init Job 和 Kubernetes secret，并对其所需的外部 Postgres 和 Redis 输入执行 plan 时前置条件检查。

| 变量 | 默认值 | 是否必填 | 描述 |
|---|---|---|---|
| `sizing_profile` | `default` | 否 | Helm 容量规格：`production`、`production-large`、`dev`、`minimum` 或 `default`。 |
| `enable_deployments` | `false` | 否 | 启用 LangSmith Deployment（listener、operator、host-backend）。需要 Deployments license entitlement。 |
| `enable_agent_builder` | `false` | 否 | 启用 Agent Builder。需要 `enable_deployments = true` 和 Agent Builder entitlement。 |
| `enable_insights` | `false` | 否 | 启用 Insights（基于 ClickHouse 的分析）。需要 Insights entitlement。 |
| `enable_polly` | `false` | 否 | 启用 Polly（AI 评估与监控）。需要 `enable_deployments = true` 和 Polly entitlement。 |
| `enable_usage_telemetry` | `false` | 否 | 启用扩展的使用量 telemetry 上报。 |
| `enable_fleet` | `false` | 否 | 启用 Fleet 独立部署（chart v0.15+）。需要 `enable_deployments = true` 以及外部 Postgres 和 Redis。 |
| `enable_standalone_polly` | `false` | 否 | 启用 Polly 独立部署（chart v0.15+）。不要求 `enable_deployments`。需要外部 Postgres 和 Redis。 |
| `enable_standalone_insights` | `false` | 否 | 启用 Insights 独立部署（chart v0.15+）。不要求 `enable_deployments`。需要外部 Postgres 和 Redis。 |

## 敏感值（通过 `setup-env.sh` 设置）

source `infra/scripts/setup-env.sh` 会把这些值写入 AWS SSM Parameter Store。External Secrets Operator 将其同步为集群中的 Kubernetes secret。它们不是声明的 Terraform 变量，不应出现在 `terraform.tfvars` 中；只能通过 SSM 设置。

| 变量 | 描述 |
|---|---|
| `langsmith_license_key` | LangSmith enterprise license key。 |
| `langsmith_admin_password` | 初始组织 admin 密码。至少 12 个字符，需包含小写、大写字母和一个符号。 |
| `langsmith_api_key_salt` | 用于哈希 API key 的 salt。首次部署后必须保持稳定。 |
| `langsmith_jwt_secret` | 用于 Basic Auth 会话的 JWT secret。必须保持稳定。 |
| `langsmith_deployments_encryption_key` | LangSmith Deployment 的 Fernet key。绝不能更改。 |
| `langsmith_agent_builder_encryption_key` | Agent Builder 的 Fernet key。绝不能更改。 |
| `langsmith_insights_encryption_key` | Insights 的 Fernet key。绝不能更改。 |
| `langsmith_polly_encryption_key` | Polly 的 Fernet key。绝不能更改。 |
