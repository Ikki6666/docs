BYOC 面向那些希望获得自托管所带来的数据所有权和网络隔离，又不想投入工程时间自行构建和运维完整 LangSmith 平台的组织。data plane 保留在你的 AWS 账户中，LangSmith 基础设施由 LangChain 管理。

## BYOC 提供哪些能力

- **更快实现价值**：你只需预置一个 AWS 账户和所需的角色，其余预置流程由 LangChain 完成。
- **客户拥有的数据**：数据库、对象存储和计算都运行在你拥有的基础设施中。
- **私有网络**：data plane 运行在你的 AWS 账户内，可以私有连接到你的系统，而无需将其公开暴露。
- **与 SaaS 一致的架构**：data plane 使用经过实践检验的架构进行预置。
- **开箱即用的监控**：LangChain 可以看到 data plane 的健康状况和指标，并能够主动识别、调查和修复问题。
- **更少的平台维护**：你的工程团队可以将更多时间用于用 LangSmith 创造价值，将更少时间用于管理 LangSmith 基础设施、升级、扩缩容和运维偏差。
- **自动升级**：你会自动升级到较新版本的 LangSmith。
- **更低的跨环境和跨 region 推广门槛**：可以在多个环境、账户或 region 中运行多个 LangSmith data plane，而无需每次都从头重建架构。

## 比较 BYOC 与自托管

下表比较了两种部署模式：

| 维度 | BYOC | 自托管 |
|-----------|------|-------------|
| **核心价值** | 客户拥有的 data plane，配合托管的 LangSmith 运维模式 | 对完整 LangSmith 部署的最大控制权 |
| **实现价值的时间** | 更快：预置好账户和 role 后，LangChain 会预置受支持的 data plane 架构 | 更长：你需要自行设计、预置、连接、保护并运维整个技术栈 |
| **运维** | LangChain 承担更多产品运维模式、升级路径和可支持的基础设施模式 | 你负责整个技术栈的部署、升级、扩缩容、监控和事件响应 |
| **架构** | 标准化，且接近 LangChain SaaS 生产架构 | 更灵活，但更容易偏离受支持的模式 |
| **最适合** | 需要数据隔离和私有网络，但不想自行运维每个 LangSmith 组件的团队 | 需要完整技术栈所有权、使用不受支持的基础设施模式，或无法使用托管 control plane 的团队 |

## 从自托管迁移到 BYOC

你可以从现有的自托管部署迁移到 BYOC。目前 traces 不会被迁移，但用户、角色、datasets、experiments、prompts、annotation queue 配置、自动化规则和 dashboard 都可以复制过来。

要规划迁移，请[联系销售团队](https://www.langchain.com/contact-sales)。
