<Note>
SmithDB 是自托管 LangSmith 的可选 datastore。ClickHouse 在 LangSmith 0.16 上是必需的，并在 0.17 上仍是默认值。在任何低于 0.17 的版本上，不要禁用 ClickHouse。最低 LangSmith 版本取决于你的云。请参见[云支持](#cloud-support)。
</Note>

SmithDB 是一个为 agent trace 数据构建的列式 datastore：深层嵌套的 spans、多模态内容，以及会保持打开数小时的 spans。它把持久数据保存在 object storage 中，并配有每 pod 磁盘缓存，与现有的 ClickHouse datastore 一起为 LangSmith trace 摄取和查询提供服务。

一些 LangSmith 功能（例如 Trajectory view、trajectory evaluators 和 filter query 语法）需要 SmithDB。请参见 [SmithDB 功能可用性](/langsmith/self-host-smithdb-features)。

## 云支持

你可以在任何受支持的 LangSmith Kubernetes 安装上启用 SmithDB，无论是全新安装还是已在服务流量的安装。[Self-host LangSmith on Kubernetes](/langsmith/kubernetes) 涵盖基础安装；上面的指南涵盖 SmithDB 在其之上添加的所有内容。

这些指南中的示例涵盖 AWS、GCP 和 Azure 上的托管 Kubernetes。它们不涵盖自管理集群。

| 云 | 最低版本 |
|---|---|
| AWS (EKS) | LangSmith 0.16，Helm chart `0.16.14` 或更高 |
| GCP (GKE) | LangSmith 0.16，Helm chart `0.16.14` 或更高 |
| Azure (AKS) | LangSmith 0.17 |

## 组件

启用 SmithDB 会向你的集群添加以下 workloads。其中三个服务会把 trace 数据缓存在网络挂载卷或本地 SSD 上；另外两个服务很小，运行在通用计算上。两个 Job 会运行到完成，而不是作为服务运行。请参见[缓存存储](/langsmith/self-host-smithdb-infrastructure#cache-storage)。

| 组件 | 类型 | 作用 | 磁盘缓存 | 扩缩容 |
| --- | --- | --- | --- | --- |
| Ingestion | Service | 把传入的 traces 写入 object storage | 是 | 水平 |
| Query | Service | 为 LangSmith UI 和 API 提供 trace 读取 | 是 | 水平 |
| Compaction worker | Service | 在后台重组存储的 traces，让查询保持快速 | 是 | 水平 |
| Compaction | Service | 调度由 compaction workers 执行的后台工作 | 否 | 单实例 |
| Cluster manager | Service | 协调其他 SmithDB 服务 | 否 | 单实例 |
| Metastore migration | Job | 在安装期间准备 SmithDB metastore | 否 | 运行一次 |
| Migration | Job | 回填 ClickHouse 历史；仅当你[迁移历史数据](/langsmith/self-host-smithdb-migrate)时运行 | 否 | 并行 |

## 存储要求

自托管 LangSmith 安装使用 PostgreSQL 存储运行数据，使用 Redis 或 Valkey 支撑队列和缓存，以及可选的 blob storage。Traces 和 feedback 存放在 ClickHouse、SmithDB，或在安装运行双路径摄取期间两者同时存放。SmithDB 添加了自己的 metastore、object store 和 cache storage。

在 0.17 上，全新安装可以在没有 ClickHouse 的情况下运行 SmithDB；请参见[不使用 ClickHouse 安装](/langsmith/self-host-smithdb-install#install-without-clickhouse)。从已有安装中退役 ClickHouse 是一个单独的流程；在考虑之前，请通过 [Support Portal](https://support.langchain.com/) 联系 LangChain。

关于同时适用于 ClickHouse 和 SmithDB 的 SDK 方法变更，请参见[迁移到 SmithDB 后端的 SDK 方法](/langsmith/smithdb-sdk-migration)。
