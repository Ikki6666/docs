LangSmith 以两种方式之一组织一个 workspace。_project-based workspace_ 按 [tracing project](/langsmith/observability-concepts#tracing-projects) 分组 traces。_agent-based workspace_ 按 [agent](/langsmith/agents) 分组 traces，并将每个 agent 的 traces 划分到固定的四元素 [environments](/langsmith/agent-environments) 集合中。

Agent-based 组织目前处于 [beta](/langsmith/release-stages) 阶段。本页介绍 agent-based workspace 中有什么不同，以及如果你的 workspace 成为其中之一会发生什么变化。

## 检查你拥有哪一种

左上角的控件会告诉你。在 agent-based workspace 中，它显示你的 workspace 名称，并会打开一个列出你组织中所有 workspaces 的列表。在 project-based workspace 中，它显示 LangSmith logo，并且侧边栏有一个带 application picker 的 **Application** 部分。

## 这次变更的价值

Agents 和 environments 记录了一个 tracing project 无法记录的内容：是哪个应用产生了一条 trace，以及是它的哪个 deployment。随后 LangSmith 可以基于这一上下文采取行动，而不要求你手动过滤，因此一个 alert 可以只监视 production 而对 local runs 保持安静，一个 prebuilt dashboard 可以覆盖每个 environment，而无需你为它命名一个 project。

## 哪些内容会变化

组织的容器会改变，所有以它为范围的内容随之变化：

- **Traces** 改为归入一个 agent 及其某个 environment，而不是归入你命名的 tracing project。不会重新 ingest 或移动任何内容。当一个已有 workspace 转换时，每个 tracing project 会变成一个带 production environment 的 agent，并且该 environment 保留 project 的 ID 和名称。为新 environment 创建的 tracing project 会以 agent identifier、一个连字符和 environment 作为其名称：identifier 为 `checkout` 的 agent，其 staging traces 位于 `checkout-staging` 中。
- **Prebuilt dashboards** 覆盖一个 environment，而不是一个命名的 project。请参阅 [Monitor projects with dashboards](/langsmith/dashboards)。
- **Alerts** 以一个 agent 的某个 environment 为范围。请参阅 [Alerts](/langsmith/alerts)。
- **Evaluators** 附加到某个 environment。请参阅 [Manage evaluators](/langsmith/evaluators)。
- **Datasets** 附加到一个或多个 agents，而不是附加到某个 project，也不附加到任何 environment，因此一个 dataset 可以服务多个 agents。请参阅 [Create and manage datasets in the UI](/langsmith/manage-datasets-in-application)。
- **导航**在顶栏增加一个 agent picker，用于在 agent 列表和单个 agent 的 Overview 之间移动。请参阅 [Navigate agents](/langsmith/navigate-agents)。
- **左上角的控件**变为 workspace 切换器，如 [Check which one you have](#check-which-one-you-have) 中所述。在 project-based workspace 中，如果启用了 Fleet，logo 会打开一个在 LangSmith 和 Fleet 之间移动的菜单；否则，它链接到 LangSmith 主页。在 agent-based workspace 中，如果启用了 Fleet，workspace 列表的末尾会带有一个 Fleet 链接。

不变的内容：你的 traces、datasets、prompts 和 experiments 仍然是相同的记录，已有的 tracing 配置继续工作。请参阅 [Log traces to a specific project](/langsmith/log-traces-to-project)。

## workspace 如何迁移

在 beta 期间，LangChain 会为一个组织启用 agent-based 组织方式，该变更适用于此后在该组织中创建的 workspaces。你无需采取任何操作。

已有的 project-based workspace 不会自动转换。LangChain 可以转换它，转换会按 [What changes](#what-changes) 中所述保留你已有的 tracing projects。

workspace 转换之后，workspace 管理员可以在新体验和经典的 project-based 体验之间切换。前往 **Settings** > **Workspace** > **Configuration** > **Workspace**。该切换适用于 workspace 中的所有人，并且只在 LangChain 已转换的 workspaces 中显示。
