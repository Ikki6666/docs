默认情况下，AWS 托管的密钥会对 [BYOC](/langsmith/byoc) [data plane](/langsmith/byoc-architecture-aws#control-plane-and-data-plane-model) 进行静态加密。你也可以改用你自己的对称 [AWS KMS 密钥](https://docs.aws.amazon.com/kms/latest/developerguide/concepts.html#kms_keys)对其加密，可为所有服务使用一个密钥，也可为每个服务使用单独的密钥：

| 服务 | 密钥加密的内容 |
|---------|-----------------------|
| `s3` | data plane 的 S3 buckets。 |
| `ebs` | 节点卷。 |
| `eks` | EKS 集群中的 Kubernetes Secrets。 |
| `rds` | RDS 存储、RDS 主用户 secrets，以及 Performance Insights 数据。 |
| `elasticache` | 静态的 ElastiCache 数据。 |

## 要求与限制

- 每个服务都是可选的。未设置密钥的服务会保留 AWS 托管加密。
- 密钥必须是 data plane 所在 region 中的对称加密密钥。密钥可以位于 data plane 账户中，也可以位于另一个 AWS 账户中。
- 你在创建 data plane 时设置密钥。无法向现有 data plane 添加密钥。
- 创建后，`ebs`、`eks`、`rds` 和 `elasticache` 密钥无法更改。如需更改 `s3` 密钥，请联系 LangChain 团队。

<Warning>
如果禁用或删除密钥，所有使用该密钥的服务都会停止工作。使用已删除密钥加密的数据无法恢复。
</Warning>

## 准备密钥

在创建 data plane 之前，准备好密钥：

1. 在 [`langsmith-byoc-role` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role#customer-managed-kms-keys) 中，将 `cmk_service_key_arns` 设置为每个服务的 key ARN。要为所有服务使用一个密钥，请为每个服务设置相同的 key ARN。使用 [BYOIAM](/langsmith/byoc-byoiam-aws) 时，也要在 BYOIAM module 中设置。
2. 按照 [module README](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role#customer-managed-kms-keys) 的说明更新密钥策略。`ebs` 密钥策略必须允许 Auto Scaling service-linked role。当 LangSmith 管理 VPC 时，`s3` 密钥策略必须允许 VPC flow log 投递。

位于另一个 AWS 账户中的密钥还需要密钥策略语句，以允许预置角色和每个 BYOIAM 角色。另一个账户中的 `ebs` 密钥还需要为 Auto Scaling service-linked role 提供 grant，该 grant 需从 data plane 账户创建，具体如 [module README](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role#customer-managed-kms-keys) 所述。LangSmith 无法读取另一个账户中密钥的策略，因此在创建 data plane 之前，请确保策略完整。

## 创建 data plane 时设置密钥

在 UI 中，创建 data plane 时在 **Configuration** 下打开 **Encryption keys**。选择 **One key for all services** 或 **A key per service**，然后输入 key ARN。

通过 API 操作时，在[创建 data plane 请求](/langsmith/smith-api/data_planes/create-a-new-data-plane)的请求体中，与其他必需字段一起包含 `customer_managed_keys`。它接受两个字段：

- **`key_arn`**：用于所有服务的一个 key ARN。
- **`service_key_arns`**：一个对象，其键为服务名称，值为 key ARN。

<CodeGroup>

```json One key for all services
{
  "customer_managed_keys": {
    "key_arn": "arn:aws:kms:us-east-1:123456789012:key/mrk-aaaa1111bbbb2222cccc3333dddd4444"
  }
}
```

```json A key per service
{
  "customer_managed_keys": {
    "service_key_arns": {
      "s3": "arn:aws:kms:us-east-1:123456789012:key/mrk-aaaa1111bbbb2222cccc3333dddd4444",
      "ebs": "arn:aws:kms:us-east-1:123456789012:key/mrk-bbbb2222cccc3333dddd4444eeee5555",
      "eks": "arn:aws:kms:us-east-1:123456789012:key/mrk-cccc3333dddd4444eeee5555ffff6666",
      "rds": "arn:aws:kms:us-east-1:123456789012:key/mrk-dddd4444eeee5555ffff666677778888",
      "elasticache": "arn:aws:kms:us-east-1:123456789012:key/mrk-eeee5555ffff66667777888899990000"
    }
  }
}
```

```json A default key with an override
{
  "customer_managed_keys": {
    "key_arn": "arn:aws:kms:us-east-1:123456789012:key/mrk-aaaa1111bbbb2222cccc3333dddd4444",
    "service_key_arns": {
      "rds": "arn:aws:kms:us-east-1:123456789012:key/mrk-dddd4444eeee5555ffff666677778888"
    }
  }
}
```

</CodeGroup>

设置 `key_arn`、`service_key_arns`，或两者都设置。`service_key_arns` 中的密钥会覆盖其对应服务的 `key_arn`。如果不设置 `key_arn`，`service_key_arns` 未列出的服务会保留 AWS 托管加密。

## LangSmith 如何验证密钥

在创建 data plane 之前，LangSmith 会检查每个密钥：

- 密钥存在且已启用。
- 密钥是对称加密密钥。
- 预置角色可以使用该密钥。

对于 data plane 账户中的密钥，LangSmith 还会检查两个密钥策略：

- `ebs` 密钥策略允许 Auto Scaling service-linked role。
- 当 LangSmith 管理 VPC 时，`s3` 密钥策略允许 VPC flow log 投递。

LangSmith 不检查另一个账户中密钥的策略。
