---
title: 自带密钥（CMK）
sidebarTitle: 自带密钥（CMK）
description: 在 AWS 上使用你自己的 AWS KMS 密钥加密新的 LangSmith BYOC data plane，可为所有服务使用一个密钥，也可为每个服务使用单独的密钥。
icon: "key"
---

默认情况下，AWS 托管的密钥会对 data plane 进行静态加密。你也可以改用你自己的对称 [AWS KMS 密钥](https://docs.aws.amazon.com/kms/latest/developerguide/concepts.html#kms_keys)，在创建 data plane 时设置：

| 服务 | 密钥加密的内容 |
|---------|-----------------------|
| `s3` | data plane 的 S3 buckets。 |
| `ebs` | 节点卷。 |
| `eks` | EKS 集群中的 Kubernetes Secrets。 |
| `rds` | RDS 存储、RDS 主用户 secrets，以及 Performance Insights 数据。 |
| `elasticache` | 静态的 ElastiCache 数据。 |

<Note>
一个密钥可以为所有服务加密。在 UI 中，选择 **One key for all services**。在 Terraform 中，为 `cmk_service_key_arns` 里的每个服务设置相同的 key ARN。你也可以为每个服务使用单独的密钥。
</Note>

每个服务都是可选的：未设置密钥的服务会保留 AWS 托管加密。密钥必须位于 data plane 所在的 region。密钥可以位于 data plane 账户中，也可以位于另一个 AWS 账户中。

无法向现有 data plane 添加密钥。创建后，`ebs`、`eks`、`rds` 和 `elasticache` 密钥无法更改。如需更改 `s3` 密钥，请联系 LangChain 团队。

设置密钥的步骤：

1. 在 [`langsmith-byoc-role` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role#customer-managed-kms-keys) 的 `cmk_service_key_arns` 中为每个服务设置一个 key ARN。使用 [BYOIAM](/langsmith/byoc-byoiam-aws) 时，也要在 BYOIAM module 中设置。
2. 按照 [module README](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role#customer-managed-kms-keys) 的说明更新密钥策略。`ebs` 密钥策略必须允许 Auto Scaling service-linked role。当 LangSmith 管理 VPC 时，`s3` 密钥策略必须允许 VPC flow log 投递。
3. 创建 data plane 时，在 **Configuration** 下打开 **Encryption keys**，然后输入 key ARN。通过 API 操作时，为每个服务设置 `customer_managed_keys.key_arn`，或按服务设置 `customer_managed_keys.service_key_arns`。

在创建 data plane 之前，LangSmith 会检查每个密钥是否存在且已启用，并检查预置角色是否可以使用该密钥。对于 data plane 账户中的密钥，LangSmith 还会检查 `ebs` 和 `s3` 密钥策略是否允许这些主体。

位于另一个 AWS 账户中的密钥还需要密钥策略语句，以允许预置角色和每个 BYOIAM 角色。另一个账户中的 `ebs` 密钥还需要为 Auto Scaling service-linked role 提供 grant，该 grant 需从 data plane 账户创建，具体如 [module README](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role#customer-managed-kms-keys) 所述。LangSmith 无法读取另一个账户中密钥的策略，因此在创建 data plane 之前，请确保策略完整。

<Warning>
如果禁用或删除密钥，所有使用该密钥的服务都会停止工作。使用已删除密钥加密的数据无法恢复。
</Warning>
