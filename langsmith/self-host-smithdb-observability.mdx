SmithDB 组件会暴露应用指标，并可以把 logs 和 traces 导出到你已有的 observability 栈。请在部署 SmithDB 服务之后、调优容量或迁移历史数据之前完成此项设置。它提供用于验证那些变更和排查故障的信号。

## Metrics

每个 SmithDB 组件会在其 HTTP 端口上的固定 `/metrics` 路径暴露应用指标。通过为每个组件添加抓取注解，配置你的监控栈来发现 pods：

<Accordion title="Sample Prometheus configuration">

```yaml
smithdb:
  query:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "8060"
  ingestion:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "8050"
  compaction:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "8070"
  compactionWorker:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "9000"
  clusterManager:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "8090"
  migration:
    job:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "9040"
```

在 LangSmith 0.16 上，在 `smithdb.migration.deployment.annotations` 下设置 migration 注解。

使用 `smithdb.topology: unified` 时，只需为 unified pod 添加注解，并只抓取端口 `8060`：

```yaml
smithdb:
  unified:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "8060"
```

</Accordion>

这些是 Prometheus 风格的注解。有自己发现格式的 provider（例如 Datadog）需要把该格式应用到相同的端口和路径。

关于关注哪些指标以及如何解读，请参见[必备 SmithDB 指标](/langsmith/self-host-smithdb-metrics)。

### 直方图和导出集

收集直方图时请一并收集其 buckets。如果没有 buckets，就无法计算百分位数，例如 p95 查询延迟。

Helm chart 会把每个 SmithDB 组件设置为导出 `critical` 指标集。该指标集包含[推荐告警](/langsmith/self-host-smithdb-alerts)所使用的所有 SmithDB 指标。要导出所有指标，请在 `smithdb.commonEnv` 中或某个组件的 `extraEnv` 中设置 `SMITHDB_<COMPONENT>__METRICS__MODE=all`。不要在两处同时设置同一个变量，否则 chart 将无法渲染。

### LangSmith 摄取指标

LangSmith 摄取管道会把所有 run 发送到 SmithDB，而 SmithDB 的问题通常首先在这里显现。请将这些指标与 SmithDB 指标一起收集：

| 服务 | 端口 | 指标 |
|---|---|---|
| Platform backend | `1986` | `langsmith_asynq_ingestion_queue_pending`, `langsmith_asynq_ingestion_queue_retry`, `langsmith_asynq_ingestion_queue_archived`, `langsmith_asynq_queue_latency_seconds` |
| Ingest queue | `1989` | `langsmith_ingestion_e2e_latency_seconds`, `langsmith_ingestion_api_to_worker_latency_seconds`, `langsmith_ingestion_worker_to_store_latency_seconds`, `langsmith_ingest_task_failures_total` |

这两个服务都在 `/metrics` 暴露这些指标。其他 LangSmith 服务请参见[导出 LangSmith telemetry](/langsmith/export-backend)。

[仪表板采集示例](/langsmith/self-host-observability-dashboards#smithdb)并未采集所有这些指标。请将缺失的指标添加到你的采集配置中。

### 基础设施指标

使用你已有的基础设施监控来监控 PostgreSQL metastore、Redis、Kubernetes 和云服务。对于托管 Redis 和 PostgreSQL，请使用你的云提供商提供的指标。

## Logs 和 traces

SmithDB 使用[将 LangSmith telemetry 导出到你的 observability backend](/langsmith/export-backend) 中描述的 chart 级 OpenTelemetry tracing 配置，但有一点不同：SmithDB 只通过 OTLP gRPC 导出。把 `config.observability.tracing.exporter` 设置为 `grpc`。使用 `http` 时，SmithDB 导出保持禁用，SmithDB logs 仍然只输出到 console。chart 会自动把 SmithDB pod 和 container 名称添加为 OpenTelemetry resource attributes。

要自定义 SmithDB log 过滤，通过 `smithdb.commonEnv` 为所有 SmithDB workloads 设置 `RUST_LOG`：

```yaml
smithdb:
  commonEnv:
    - name: RUST_LOG
      value: "warn,smithdb_query=debug,vortex=warn"
```

确认 collector 可以从 LangSmith namespace 访问，应用 chart，然后确认 telemetry 到达。设置或调优 collector 请参见[为 LangSmith telemetry 配置你的 collector](/langsmith/langsmith-collector)。
