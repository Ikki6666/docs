Managed Deep Agents 将 deploy 拥有的 instructions 和 skills，以及可选的持久 memory，存储在 [LangSmith Context Hub](/langsmith/use-the-context-hub) 中。这种划分让你无需重建应用代码即可更改 agent 的行为，同时项目仍然是持久 instruction 和 skill 更新的事实来源。

<ManagedDeepAgentsPublicBetaNote />

## Context Hub 中存放什么

| 内容 | 项目中的来源 | 是否在 `mda deploy` 时同步 | Agent 是否可写 |
| --- | --- | --- | --- |
| System prompt | [`instructions.md`](/langsmith/javascript/managed-deep-agents-instructions) | 是 | 否 |
| Skills | [`skills/`](/langsmith/javascript/managed-deep-agents-skills) | 是 | 否 |
| 持久 memory | 可选的 [`memory`](/langsmith/javascript/managed-deep-agents-memory) 声明 | 启用目录树；不会覆盖已有 memory | 是，位于 `/memories/agent/` 下 |

Tools、middleware、MCP connectors、channels、schedules、sandboxes 和 agent definition 随编译后的 deployment 一起发布。它们不会同步到 Context Hub。

关于托管运行时字段的所有权，请参见 [Agent definition](/langsmith/javascript/managed-deep-agents-agent-definition)。

## 事实来源

项目和 Context Hub 都保存着 `instructions.md` 和 `skills/` 的副本。哪份副本生效取决于你在哪里进行持久更改，以及你如何在部署时解决冲突。

- **项目文件**：把项目中的 `instructions.md` 和 `skills/` 视为持久更改的事实来源。每次 `mda deploy` 都会把它们同步到 agent 的 Context Hub repo。
- **Context Hub 编辑**：当你需要一个无需代码重新部署即可生效的快速更改时，在 Context Hub 中编辑文件。这些 Hub 编辑会一直生效，直到后来的部署覆盖它们，或者当冲突提示出现时你选择保留 Hub 副本。
- **持久 memory**：`/memories/agent/` 下的 memory 归 agent 所有。部署会启用该目录树，但不会覆盖已存储的内容。

## 部署如何同步 context

`mda deploy` 在部署管线中同步 deploy 拥有的 context：

- **Instructions 和 skills**：每次部署都会根据项目文件更新 agent 的 Context Hub repo。后续部署会再次同步项目副本。对于 skills，部署还会删除本地已不存在的已部署 skill 文件。
- **持久 memory**：启用 memory 时，deployment 会在 `/memories/agent/` 挂载一个 Context Hub 目录树。部署不会覆盖已存储的内容。
- **冲突**：如果自上次 `mda deploy` 以来 `instructions.md` 或 `skills/` 在 Context Hub 中发生了变化，CLI 会在同步前停下，询问是否用项目副本覆盖 Context Hub 副本。默认答案保留 Context Hub 版本并跳过同步该部分。在非交互式 shell 中没有提示。部署会以错误退出，你必须用 `--context-strategy overwrite` 或 `--context-strategy keep-hub` 重新运行。单独重新运行 `mda deploy` 会再次报告同样的冲突。
- **并发编辑**：如果 repo 在同步过程中发生变化，部署会以 commit 冲突失败。请重新运行 `mda deploy`。

交互式冲突提示：

```text
◇  Checked Context Hub context
│
▲  Context Hub instructions.md changed since the last MDA sync.
│
◆  Overwrite Hub-edited instructions.md with the local version?
│  ○ Yes / ● No
└
```

非交互式冲突（CI 或重定向输出）：

```text
└  Context Hub instructions.md and skills/ changed since the last MDA sync. Re-run with --context-strategy overwrite or --context-strategy keep-hub.
```

| 策略 | 效果 |
| --- | --- |
| `overwrite` | 用项目副本替换 Hub 中被编辑的 `instructions.md` 或 `skills/`，然后继续部署。 |
| `keep-hub` | 保留 Context Hub 版本，跳过同步该部分，并继续部署。 |

完整的部署步骤列表和 flags 请参见 [CLI reference](/langsmith/javascript/managed-deep-agents-cli#deploy-projects)。关于 secrets 路由和部署选项，请参见 [Deploy an agent](/langsmith/javascript/managed-deep-agents-deploy)。

## 在 LangSmith 中编辑 context

成功部署后：

1. 在 LangSmith 中打开该 deployment。
1. 使用 Details 侧边栏链接打开存放该 deployment 的 instructions、skills 和 memories 的 Context Hub repo。当 context 不再生效时，归档的 repo 会被标注。
1. 当你需要一个无需代码重新部署即可生效的快速更改时，在 Context Hub 中编辑文件。

对于持久更改，请编辑项目副本并重新部署。关于部署如何处理 Hub 编辑，请参见 [Source of truth](#source-of-truth)。

关于浏览 commits、晋升环境，以及 Managed Deep Agents 之外的 Context Hub 概念，请参见 [Use the Context Hub](/langsmith/use-the-context-hub) 和 [Context engineering concepts](/langsmith/context-engineering-concepts)。

## 本地开发

`mda dev` 会为 instructions、skills 和 memory 创建一个本地 Context Hub mock。本地 Studio 会话不会创建或更新 deployment 的托管 Context Hub repo。

更多信息请参见 [Develop locally with LangSmith Studio](/langsmith/javascript/managed-deep-agents-local-development)。
