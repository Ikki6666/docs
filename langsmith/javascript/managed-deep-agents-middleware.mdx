Middleware 会在模型调用、tool calls 和 agent 生命周期周围添加行为。与 [custom tools](/langsmith/javascript/managed-deep-agents-tools) 一样，MDA 不会自动发现 middleware。你需要导入它，并将其传给 agent 定义。

<ManagedDeepAgentsPublicBetaNote />

把自定义 middleware 放在 `middleware/` 目录下，将其导入 agent 入口文件，并传给 agent 定义：



```text
my-agent/
  agent.ts
  middleware/
    audit.ts
```


完整的项目布局请参见 [Project structure](/langsmith/javascript/managed-deep-agents-project-structure)。

托管运行时仍负责 `backend`、`store`、`checkpointer`、`memory`、`skills` 和 system prompt。Middleware 应聚焦于模型调用、工具调用和生命周期 hooks 周围的 agent 行为。

## 添加 middleware

使用 middleware 来脱敏 PII、强制调用上限、重试失败、在模型之间回退、动态选择模型，或记录和检查 tool calls。

<Steps>
  <Step title="使用预构建 middleware" id="use-prebuilt-middleware">

你可以直接在 agent 定义中使用 LangChain [预构建 middleware](/oss/javascript/langchain/middleware/built-in)：



```ts agent.ts
import { defineDeepAgent } from "managed-deepagents";
import { modelCallLimitMiddleware, piiMiddleware } from "langchain";

export const agent = defineDeepAgent({
  name: "support-agent",
  model: "openai:gpt-5.5",
  middleware: [
    piiMiddleware("email", { strategy: "redact", applyToInput: true }),
    modelCallLimitMiddleware({ runLimit: 50 }),
  ],
});
```


  </Step>
  <Step title="定义自定义 middleware（可选）" id="define-custom-middleware">

如果需要更高级的选项，可以在本地模块中定义 [custom middleware](/oss/javascript/langchain/middleware/custom)。



```ts middleware/audit.ts
import { createMiddleware } from "langchain";

export const logToolCalls = createMiddleware({
  name: "LogToolCalls",
  wrapToolCall: async (request, handler) => {
    console.log(`Calling tool: ${request.toolCall.name}`);
    const result = await handler(request);
    console.log(`Finished tool: ${request.toolCall.name}`);
    return result;
  },
});
```


把 middleware 导入项目根目录下的 agent 入口文件，并放进 `middleware` 列表中：



```ts agent.ts
import { defineDeepAgent } from "managed-deepagents";

import { logToolCalls } from "./middleware/audit";

export const agent = defineDeepAgent({
  name: "support-agent",
  model: "openai:gpt-5.5",
  middleware: [logToolCalls],
});
```




你的 middleware imports 行为应与普通本地 TypeScript 项目保持一致。


  </Step>
</Steps>

## 使用运行时 context

Middleware 可以通过标准 LangChain 运行时 API 读取每次 run 的 context。你可以用 context 传递 user IDs、organization IDs、feature flags、request metadata，或那些默认不应进入模型 prompt 的 credentials。

示例请参见 [Custom middleware](/oss/javascript/langchain/middleware/custom)。

Managed Deep Agents 添加的 caller、channel 和 sandbox 字段请参见 [Runtime](/langsmith/javascript/managed-deep-agents-runtime)。

要在 middleware hook 中读写 thread sandbox 中的文件，请使用 `runtime.backend`。参见 [Read and write sandbox files from code](/langsmith/javascript/managed-deep-agents-sandboxes#read-and-write-sandbox-files-from-code)。

## 部署

`mda dev` 和 `mda deploy` 会把项目文件（包括 `middleware/` 目录下的模块）复制到编译后的 build 中。Middleware 不会同步到 Context Hub，而是随 agent 代码一起发布。

## 何时使用 middleware

| Concept | Kind | How it reaches the agent |
| --- | --- | --- |
| **Middleware** | 应用代码 | 导入并传给 agent 定义 |
| **[Custom tools](/langsmith/javascript/managed-deep-agents-tools)** | 应用代码 | 导入并传给 agent 定义 |
| **[Instructions](/langsmith/javascript/managed-deep-agents-instructions)** | 托管 context | 常驻 system prompt |

更多信息请参见 [Project structure](/langsmith/javascript/managed-deep-agents-project-structure)。
