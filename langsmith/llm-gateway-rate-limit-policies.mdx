速率限制策略限制 subject 在一个较短的滚动时间窗口内通过 [LLM Gateway](/langsmith/llm-gateway) 消耗的**请求数**或**token 数**。gateway 会实时强制执行该限制，并阻止任何会把 subject 推过上限的请求，返回带有 `Retry-After` header 的 `429` 响应：

```
API Error: 429 request blocked by gateway policies: Dev Team Rate Limit
Retry-After: 42
```

`Retry-After` 的值是距当前窗口重置的秒数。client 应该遵守这个 header，在重试之前先退避。

速率限制策略和 [spend cap policies](/langsmith/llm-gateway-spend-policies) 互补，可以同时启用—spend caps 用于成本控制，rate limits 用于吞吐量和流量控制。

## 策略维度

速率限制策略会在每个入站请求上评估。你可以把策略设为 default（对所有用户、[工作区](/langsmith/administration-overview#workspaces)或 [API keys](/langsmith/create-account-api-key) 施加统一的速率限制），也可以设为 granular policy（对单个 subject 或一组 subject 的单独限制）。

| Subject | 限制什么 | 示例 |
| --- | --- | --- |
| **User** | 来自单个用户或一组用户的请求或 token（从 API key 的身份解析而来） | "任何单个开发者每分钟最多发送 100 个请求" |
| **Workspace** | 单个工作区或一组工作区内的请求或 token | "R&D 工作区每小时不能超过 1,000,000 tokens" |
| **API key** | 来自单个 API key 或一组 API keys 的请求或 token | "客服 agent keys 共享每分钟 200 个请求的限制" |

### 默认策略与细粒度策略

速率限制策略有两种模式：

1. **默认策略**自动应用于某个 subject 维度的每个成员。例如："这个工作区中的每个用户都获得每分钟 100 个请求的默认上限。"无需为每个人创建策略。
2. **细粒度策略**针对一个命名的 subject，并仅为该 subject 覆盖默认值。例如："值班工程师获得每分钟 500 个请求。"编辑默认策略会更新仍然应用它的所有人。

### 独立执行

每个 subject 都被单独跟踪和限制。一个用户达到自己的限额不会影响其他用户。

## 限制

一条速率限制策略可以同时强制执行**多个限制**。例如，一条策略可以同时执行*每分钟 100 个请求*和*每小时 1,000,000 tokens*。

每个限制有三个字段：

| 字段 | 允许的值 |
| --- | --- |
| **Metric** | `requests` 或 `tokens`（provider 报告的总 tokens） |
| **Window** | `minute` 或 `hour` |
| **Value** | 正整数（上限） |

规则：

- 每条策略至少需要一个限制。
- 一条策略中不能有两个 metric 和 window 组合相同的限制。

## 创建速率限制策略

<Warning>
创建和管理策略需要 `organization:manage` 权限。完整的权限说明请参见 [Traces、Engine 与访问控制](/langsmith/llm-gateway-access)。
</Warning>

1. 前往 **LLM Gateway**。
1. 点击 **Create policy**。
1. 选择 **Rate limit** 作为策略类型。
1. 选择 subject 范围（user、workspace 或 API key）。
1. 添加一个或多个限制，每个限制包含 metric、window 和 value。
1. 保存。

策略会立即生效。

速率限制策略还可以携带一个针对自定义请求 header 的条件，使来自单个 subject 的流量按 header 值拆分为独立的限额。用它在一个 API key 下为你的每个终端客户提供自己的吞吐量配额。更多信息请参见 [Per-customer policies](/langsmith/llm-gateway-header-policies)。
