---
title: Preview builds
description: 为 pull requests 创建临时 preview deployments，以便在合并之前测试 Agent Server 的变更。
---

Preview builds 为 pull requests 创建临时的 **preview deployments**。使用 preview deployment 可以在将 Agent Server 变更合并到运行 parent deployment 的分支之前，先在隔离环境中测试它们。

当 pull request 触发 preview build 时，LangSmith 会将源分支上的最新 commit 构建为 preview deployment 的第一个 revision。之后对该分支的每个 commit 都会触发一个新的 revision。

<Note>
Preview builds 目前处于 public beta 阶段，仅适用于通过 GitHub integration 创建的 deployments 的 LangSmith Cloud。
</Note>

## 启用 preview builds

要启用 preview builds：

1. 在 **Deployments** 视图中，选择一个 deployment。
1. 在右上角，选择齿轮图标（**Deployment Settings**）。
1. 滚动到 **Preview Builds** 部分。
1. 选择 **Enable preview builds**。
1. 选择一种触发模式：
   - **Every PR**：针对 deployment 分支的任何 pull request 都会触发 preview build。
   - **Label only**：仅当 pull request 带有配置的 label 时才触发 preview build。
1. 配置 preview 限制：
   - **Idle TTL**：preview deployment 在其最新 revision 之后可以保持不活动状态多久，超过该时长 LangSmith 会将其删除。
   - **Max concurrent previews**：可以为 parent deployment 并发运行的 preview deployments 的最大数量。
1. 选择 **Save**。

## 管理 secrets

LangSmith 创建 preview deployment 时，它会继承 parent deployment 的 secrets。你可以在 preview deployment 上覆盖这些继承的 secrets。

对 parent deployment 的 secrets 所做的变更不会传播到已有的 preview deployments。

## 删除 preview deployments

当 preview deployment 的 idle TTL 过期时，LangSmith 会将其删除。你也可以随时手动删除它。

删除 parent deployment 会删除它的所有 preview deployments。
