模型访问策略定义哪些 providers 和模型被允许通过 [LLM Gateway](/langsmith/llm-gateway)。gateway 会阻止策略未包含的 providers 或模型的请求，并返回 `403` 响应。如果没有适用的策略，所有 providers 和模型都可用。

## 策略配置

模型访问策略列出一个或多个 providers，每个 provider 带有一种访问模式：

- **All models**：该 provider 提供的每个模型都被允许。
- **Selected models**：只允许你指定的模型。至少需要一个模型。

<Note>
模型访问策略尚不支持自定义模型 providers。当模型访问策略适用于某个请求时，gateway 会阻止 `/providers/{configName}` 和 `/models/{configName}` 路由。
</Note>

## 范围与覆盖

模型访问策略被限定在一个 subject 层级：

| 层级 | 适用于 |
| --- | --- |
| Organization | 组织中的所有用户和工作区 |
| Workspace | 一个工作区中的所有用户 |
| User | 单个用户 |
| API key | 单个 API key |

### 策略覆盖

策略覆盖（policy overrides）让你可以给更具体的 subject 授予与更宽泛默认不同的访问权限。一个常见场景是：让某个 API key 访问组织中其他人不可用的某个高级模型。

当请求在多个层级匹配到策略时，只有最具体的层级适用，顺序为 API key、user、workspace、organization。更具体的策略会完全替换更宽泛的策略。例如，如果组织策略允许 OpenAI 和 Anthropic，而某个 API key 策略只允许 OpenAI 和 Gemini，那么使用该 key 的请求只能访问 OpenAI 和 Gemini。如果同一层级有多条策略匹配，模型必须被所有策略允许才可以访问。

## 创建模型访问策略

<Warning>
创建和管理策略需要 `organization:manage` 权限。完整的权限说明请参见 [Traces、Engine 与访问控制](/langsmith/llm-gateway-access)。
</Warning>

1. 前往 **LLM Gateway** 并选择 **Model Access**。
1. 点击 **Create model access**。
1. 输入 **Policy name**。
1. 在 **Applies to** 下选择范围（organization、workspace、user 或 API key）。
1. 配置 **Allowed providers and models**。
1. 保存。

策略会立即生效。
