</Note>

Bring Your Own Cloud（BYOC）让你可以在自己的云环境中部署 LangSmith 服务并存储数据，同时由 LangChain 负责基础设施的运维、扩缩容和升级。BYOC 适合需要对数据拥有完全主权，但又不想承担基础设施预置和管理开销的组织。

BYOC 采用责任分离模型：control plane 运行在 LangChain 的云中，data plane 则完全运行在你自己的云环境中。有关 LangChain 管理什么与你管理什么的详细信息，请参阅 [BYOC 共享责任模型](/langsmith/byoc-shared-responsibility)。

## 快速开始

要部署 LangSmith BYOC，请[联系销售团队](https://www.langchain.com/contact-sales)。在 LangChain 团队为你的组织启用 BYOC 后，请按照 [AWS](/langsmith/byoc-onboarding-aws)、[GCP](/langsmith/byoc-onboarding-gcp) 或 [Azure](/langsmith/byoc-onboarding-azure) 的入门指南创建你的第一个 data plane。

## Region 与云服务商

BYOC 已在 AWS 上正式发布（GA）。GCP 和 Azure 上的 BYOC 目前处于 [beta](/langsmith/release-stages) 阶段。

### AWS

你可以在以下任意 AWS region 中部署 LangSmith BYOC：

| 地区 | AWS region |
|------|-------------|
| **美国** | `us-east-1`, `us-east-2`, `us-west-1`, `us-west-2` |
| **加拿大** | `ca-central-1` |
| **欧洲** | `eu-central-1`, `eu-west-1`, `eu-west-2`, `eu-west-3`, `eu-north-1` |
| **亚太** | `ap-south-1`, `ap-northeast-1`, `ap-northeast-2`, `ap-northeast-3`, `ap-southeast-1`, `ap-southeast-2` |

无论你将 AWS data plane 放在哪个位置，AWS control plane 都运行在 `us-east-2`，即 [aws.smith.langchain.com](https://aws.smith.langchain.com)。如果你在美国以外预置 data plane，你的敏感应用数据会保留在该 region，而 control plane 元数据则保留在美国：

| Control plane（美国） | Data plane（你的 region） |
|--------------------|--------------------------|
| 用户、角色、计费、组织配置、SSO 配置、API keys | traces、experiments、datasets、insights runs、annotation queues、workspace secrets，以及所有其他敏感应用数据 |

### GCP

GCP 上的 BYOC 可以在任意 GCP region 中运行。如果你需要的 region 尚未启用，请联系 LangChain 团队添加。

GCP control plane 运行在 `us-central1`，位于 [smith.langchain.com](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=langsmith-byoc) 的 LangSmith 美国 region。control plane 元数据与 data plane 应用数据的分离方式相同。有关设置，请参阅 [GCP 上的 BYOC 入门指南](/langsmith/byoc-onboarding-gcp)。有关 LangSmith 在你的项目中部署的内容，请参阅 [GCP 上的 BYOC 架构](/langsmith/byoc-architecture-gcp)。

### Azure

Azure 上的 BYOC 可以在任意 Azure region 中运行。如果你需要的 region 尚未启用，请联系 LangChain 团队添加。

Azure control plane 运行在 `centralus`，位于 [azure.smith.langchain.com](https://azure.smith.langchain.com)。control plane 元数据与 data plane 应用数据的分离方式相同。有关设置，请参阅 [Azure 上的 BYOC 入门指南](/langsmith/byoc-onboarding-azure)。有关 LangSmith 在你的订阅中部署的内容，请参阅 [Azure 上的 BYOC 架构](/langsmith/byoc-architecture-azure)。

## 可用功能

以下功能在 AWS 上受支持。有关 GCP 和 Azure beta 阶段的功能可用性，请在部署前与 LangChain 团队确认你的需求：

- **[可观测性](/langsmith/observability)**：tracing、projects、dashboard 和告警。
- **[评估](/langsmith/evaluation)**：datasets、experiments、evaluators 和 annotation queues。
- **[Insights](/langsmith/insights)**：自动分析 traces，以发现使用模式、常见的 agent 行为和失败模式。
- **[LangSmith Chat](/langsmith/chat)**：在你的 workspace 内分析 traces、threads、prompts 和评估结果。
- **[Prompt engineering](/langsmith/prompt-context-hub#prompts)**：prompts 和 prompt commits。
- **[LangSmith Agent Server](/langsmith/deployment)**：LangSmith Agent Server control plane 运行在你的 data plane 集群内部，因此 agent 管理层和你的 agents 都运行在你的私有网络中。
- **[Sandboxes](/langsmith/sandboxes)**：通过 CLI 和 SDK 的使用方式与 Cloud 完全相同，只是需要指向你的 data plane endpoint。
- **[LLM Gateway](/langsmith/llm-gateway)**：用一个 LangSmith API key 调用多家提供商的模型，并集中执行支出、速率限制和数据保护策略。
- **[LLM auth proxy](/langsmith/llm-auth-proxy-self-hosted)**：为模型调用强制执行你自己的身份验证流程，使提供商凭证永远不会暴露给最终用户。
- **[LangSmith MCP](/langsmith/langsmith-remote-mcp)**：将兼容 MCP 的客户端连接到 LangSmith 以查询数据。
- **[Fleet](/langsmith/fleet/index)**：基于模板、连接器和 channel 构建并运行无代码 agents。
- **[SmithDB](/langsmith/smithdb-sdk-migration)**：专为 trace 数据构建的可观测性 backend，在你的云环境中持久化到 AWS 上的 S3、GCP 上的 Cloud Storage 或 Azure 上的 Blob Storage。在 2026 年 10 月 21 日或之后创建的 data planes 仅运行 SmithDB。ClickHouse 已弃用，支持将于 LangSmith v0.19 结束。
- **[Engine](/langsmith/engine)**：自动检测、诊断并解决生产 traces 中反复出现的问题。在 BYOC 上，Engine 在你自己的模型提供商上运行其模型，并且由你在 LangSmith UI 中配置 GitHub App 和 Slack app。请参阅 [Engine on BYOC](/langsmith/engine-self-hosted#engine-on-byoc)。
- **[Managed Deep Agents](/langsmith/python/managed-deep-agents-overview)**：使用连接器、channel 和调度构建并运行 deep agents。

<Note>
在 BYOC 上请使用 Managed Deep Agents CLI 和 SDK v0.10 或更高版本。要开始使用，请遵循 [Managed Deep Agents 快速入门](/langsmith/python/managed-deep-agents-quickstart)。
</Note>

## 前提条件

在 LangChain 预置 AWS 上的 data plane 之前，你需要：

- **一个 AWS 上的 LangSmith 组织**：在 [aws.smith.langchain.com](https://aws.smith.langchain.com) 创建一个组织，然后将你的组织 ID 发送给 LangChain 团队以启用 BYOC。
- **一个 AWS 账户**：LangChain 建议使用专用于 LangSmith BYOC 的全新账户，但这不是必需的。
- **一个受支持的 region**：从上面列出的 AWS region 中选择一个。
- **一个 IAM role 和 external ID**：external ID 由 LangChain 提供。使用 **Settings > Data Planes** 标题旁边的按钮复制它，然后使用该值应用 [`langsmith-byoc-role` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role)，以创建 LangChain 为预置和管理你的 data plane 而承担的 role。你必须使用此 module。

有关 GCP，请参阅 [GCP 上的 BYOC 入门指南中的前提条件](/langsmith/byoc-onboarding-gcp#before-you-start)。

有关 Azure，请参阅 [Azure 上的 BYOC 入门指南中的前提条件](/langsmith/byoc-onboarding-azure#before-you-start)。
