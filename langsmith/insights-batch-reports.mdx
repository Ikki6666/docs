批量 Insights 报告会分析某一时间范围内的 trace 样本，并将其归入类别和子类别，从而呈现使用模式、常见智能体行为和失败模式。你可以运行一次报告，也可以按计划运行。

在查询 ClickHouse 而非 [SmithDB](/langsmith/self-host-smithdb) 的自托管 LangSmith 安装中，Insights 以批量报告的方式运行。LangSmith Cloud 以及使用 SmithDB 的自托管安装则运行[持续型 Insights](/langsmith/insights)，会在新 trace 到达时对其进行分类。

针对单个[智能体环境](/langsmith/agent-environments)运行报告，即可只分析生产流量，而不一并分析本地 run。

<Note>
Insights 适用于 LangSmith Plus 和 Enterprise [套餐](/langsmith/pricing-plans)。
</Note>

## 前提条件

- 已在工作区中为 Insights 设置好[模型配置](/langsmith/model-configurations)。
- 具备创建规则的[权限](/langsmith/organization-workspace-operations#projects)，这是生成报告所必需的；并具备查看智能体环境的权限，这是查看现有报告所必需的。

## 生成第一份 Insights 报告

<Tabs>
  <Tab title="UI" icon="layout-dashboard">

1. 在[智能体切换器](/langsmith/navigate-agents)中选择你的智能体，前往 **Tracing**，然后选择环境。报告只针对一个环境运行，而不是整个智能体。
1. 点击右上角的 **+ New**，然后点击 **New Insights Report**。
1. 输入任务名称。
1. 如果尚未配置，请在工作区设置中为 Insights [配置模型](/langsmith/model-configurations)。
1. 回答引导问题，让 Insights 报告聚焦于你想了解的智能体信息，然后点击 **Run job**。

<Tip>切换到 Manual 模式，即可[手动配置任务](#configure-a-job)。</Tip>

这会启动一项后台 Insights 报告。报告最多可能需要 30 分钟才能完成。

  </Tab>
  <Tab title="SDK" icon="code">

你可以使用 [Python SDK](/langsmith/smith-python-sdk) 对存储在 LangSmith 之外的数据生成 Insights 报告。这样，你可以分析来自生产系统、日志或其他来源的聊天历史。

调用 `generate_insights()` 时，SDK 会：

1. 将聊天历史作为 trace 上传到 LangSmith。
1. 基于这些已上传的 trace 生成一份 Insights 报告。
1. 返回一个指向 [LangSmith UI](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=langsmith-insights-batch-reports) 中结果的链接。

<CodeGroup>

```python Python
import os
from langsmith import Client

client = Client()

chat_histories = [
    [
        {"role": "user", "content": "how are you"},
        {"role": "assistant", "content": "good!"},
    ],
    [
        {"role": "user", "content": "do you like art"},
        {"role": "assistant", "content": "only Tarkovsky"},
    ],
]

report = client.generate_insights(
    chat_histories=chat_histories,
    name="Customer Support Topics - March 2024",
    instructions="What are the main topics and questions users are asking about?",
    openai_api_key=os.environ["OPENAI_API_KEY"],  # optional if already set as workspace secret
)

# client.poll_insights(report=report)
```
</CodeGroup>

  </Tab>
  <Tab title="CLI" icon="terminal-2">

[LangSmith CLI](/langsmith/langsmith-cli) 会根据一个 JSON 文件创建报告，该文件使用[手动配置](#manual-configuration)中的字段：

```bash
langsmith insights create --project "<environment-tracer-session-name>" --config insights.json --wait
```

将 `<environment-tracer-session-name>` 替换为报告所分析智能体环境的 [`tracer_session_name`](/langsmith/create-an-agent#use-an-environment-project)。

关于文件格式，以及运行、列出和更新已保存配置的命令，请参阅 [管理 insights](/langsmith/langsmith-cli#manage-insights)。

  </Tab>
</Tabs>

<Note>
    对 1,000 个 thread 生成 Insights 时，使用 OpenAI 模型的成本通常为 \$1.00-\$2.00，使用当前 Anthropic 模型时通常为 \$3.00-\$4.00。成本会随采样的 thread 数量和每个 thread 的大小而变化。
</Note>

## 了解结果

任务完成后，你可以前往 **Insights** 标签页，其中会显示一个 Insights 报告表格。每份报告都包含针对该环境中特定 trace 样本生成的分析结果。

点击任务，即可查看按一组自动生成的类别整理好的 trace。

你可以逐层查看类别和子类别，以查看底层 trace、feedback 和 run 统计信息。

### 执行摘要

每份报告开头都会先给出执行摘要，概述在 trace 中发现的最重要模式。摘要包括：

- 关键发现，并用百分比表示每种模式出现的频率。
- 可点击的引用（例如 #1、#2、#3），指向智能体认为与你的问题特别相关的 trace。

### 顶层类别

你的 trace 会被自动归入顶层类别，这些类别代表数据中最宽泛的模式。

分布条会显示每种模式出现的频率，让你可以轻松发现哪些行为出现得比预期更多或更少。

每个类别都有简短描述，并展示其中 trace 的聚合指标，包括：

- 典型的 trace 统计信息（例如错误率、延迟、成本）
- 来自 evaluator 的 feedback 分数
- 作为任务一部分提取的[属性](#attributes)

### 子类别

点击任意类别，即可查看按子类别拆分的明细，从而更细致地理解该类 trace 中的交互模式。

### 单条 trace

你可以点击进入 trace 表格，查看分配给每个类别或子类别的 trace。然后，你可以点开任意 trace，查看完整的对话详情。

## 配置任务 {#configure-a-job}

你既可以使用自动生成流程创建 Insights 报告，也可以通过手动配置创建。

### 自动生成配置

1. 打开 **New Insights**，并确保 **Auto** 开关已启用。
2. 回答关于智能体用途、你想了解的内容以及 trace 组织方式的自然语言问题。Insights 会把你的回答转换为配置草稿（任务名称、摘要提示词、属性和采样默认值）。
3. 选择 provider，然后点击 **Generate config** 预览，或点击 **Run job** 立即启动。

#### 提供有用的上下文

为获得最佳结果，请为每个提示词写一到两句话，为 Insights 提供所需的上下文：你想了解什么、哪些信号或字段最重要，以及哪些信息你已经知道没有帮助。你越清楚地说明智能体做什么、其 trace 如何组织，Insights 就越能按符合你理解数据方式的逻辑对示例进行分组。

#### 描述 trace

说明数据是如何组织的：这些是单次 run 还是多轮对话？哪些输入和输出包含关键信息？这有助于 Insights 生成聚焦重点的摘要提示词和属性。如有需要，你也可以直接指定[摘要提示词](#summary-prompt)部分中的变量。

### 选择模型

Insights 使用两个模型：

- **Thinking model**：执行聚类步骤（能力更强，成本更高）。
- **Summarization model**：生成每条 trace 的摘要（速度更快，成本更低）。

这两个模型都从你在工作区中配置的 provider 中选择。当你在[模型配置](/langsmith/model-configurations)中为 Insights 启用了特定模型时，可以分别选择这些模型。如果未配置单独模型，则选择 provider（OpenAI 或 Anthropic），Insights 会使用该 provider 的默认模型。

为获得最佳效果，请为这两个角色使用同一 provider 的模型。

### 手动配置 {#manual-configuration}

手动配置可让你获得更多控制权，例如预先定义希望数据归入的类别，或仅针对符合特定 feedback 分数和筛选条件的 trace。

#### 选择 trace

- **Sample size**：要分析的 trace 最大数量（上限为 1,000）。
- **Time range**：从这个时间范围内采样 trace。
- **Filters**：额外的 trace 筛选条件。调整筛选条件时，面板会显示有多少条 trace 符合你的条件。

#### 类别

默认情况下，顶层类别会根据底层 trace 自下而上自动生成。

在某些情况下，你事先就知道自己关注哪些具体类别，并希望任务将 trace 归入这些预定义类别。

配置中的 **Categories** 部分允许你列出希望使用的顶层类别名称和描述，以此实现该目标。

子类别仍会由算法在预定义的顶层类别内自动生成。

任务完成后，发现的顶层类别会自动保存回配置，但前提是配置此前未定义任何类别。这意味着后续定时运行会复用这些类别，以保持一致性。

#### 摘要提示词 {#summary-prompt}

任务的第一步是为每条 trace 生成一份简短摘要。然后，这些摘要会被分类。

在摘要中提取正确的信息，对于获得有用的类别至关重要。

你可以编辑用于生成这些摘要的提示词。编辑提示词时需要考虑以下两点：

- 摘要指令：任何未出现在 trace 摘要中的信息都不会影响生成的类别，因此请明确说明每条 trace 中哪些信息重要、需要提取。
- Trace 内容：使用 mustache 格式指定每条 trace 的哪些部分会传递给摘要器。包含大量输入和输出的大型 trace 可能成本高昂且噪声较多。将提示词缩减到只包含 trace 中最相关的部分，可以改善结果。

你必须使用以下至少一个模板变量，指定要将每条 trace 的哪些部分发送给摘要器：

| 变量 | 说明 | 示例 |
| --- | --- | --- |
| `run.inputs` | 最近一次 root run 的输入 | `{{run.inputs}}` |
| `run.outputs` | 最近一次 root run 的输出 | `{{run.outputs}}` |
| `run.error` | 如果 run 失败，则为错误字符串 | `{{run.error}}` |
| `run.feedback` | 所有 feedback 分数，以 JSON blob 表示 | `{{run.feedback}}` |
| `run.feedback.<key>` | 按 key 指定的某个 feedback 分数 | `{{run.feedback.correctness}}` |
| `all_thread_messages` | thread 的完整消息历史（仅适用于包含 [threads](/langsmith/threads) 的环境） | `{{all_thread_messages}}` |

你可以使用点号表示法访问嵌套字段。例如，`{{run.inputs.foo.bar}}` 只包含最后一次 run 输入中 `foo` 内的 `bar` 字段。

<Note>
对于包含 [threads](/langsmith/threads) 的环境，Insights 会分析完整对话。`run.*` 变量只会使用每个 thread 中最近一次 root run。使用 `all_thread_messages` 可访问完整对话历史。
</Note>

#### 属性 {#attributes}

除了摘要之外，你还可以定义要从每条 trace 中提取的额外字符串、数值和布尔属性。
这些属性会影响分类步骤：属性值相似的 trace 往往会被归入同一类别。
你还可以查看每个类别中这些属性的聚合结果。

例如，你可能希望从每条 trace 中提取 `user_satisfied: boolean` 属性，以引导算法划分正向和负向用户体验的类别，并查看每个类别的平均用户满意度。

#### 筛选属性

你可以在布尔属性上使用 `filter_by` 参数，在生成 Insights 之前预先筛选 trace。启用后，只有该属性评估为 `true` 的 trace 才会纳入分析。

当你想将 Insights 报告聚焦到特定的 trace 子集时，这会很有用。例如，只分析错误、只检查英语对话，或只包含符合特定质量标准的 trace。

**工作原理：**
- 创建 Insights 配置时，为任意布尔属性添加 `"filter_by": true`。
- 在摘要生成期间，LLM 会根据属性描述评估每条 trace。
- 在生成 Insights 之前，属性为 `false` 或缺失的 trace 会被排除。

## 定时运行 Insights 报告

将 Insights 报告设置为按固定周期自动运行。创建或编辑配置时，使用 **Schedule** 部分选择：

- **Daily**：每天 8:00 UTC 运行。
- **Weekly on Monday**：每周一 8:00 UTC 运行。
- **Custom**：输入你自己的 cron 表达式（UTC）。

每次定时运行都会使用已保存的配置生成一份新报告。时间范围会动态计算。例如，“last 24 hours”始终会在执行时分析最近的 24 小时窗口。

## 保存配置

你可以选择使用 **Save as** 按钮保存配置，以便将来复用。
已保存的配置让你可以比较一段时间内的 Insights 报告，以识别用户和智能体行为的变化。

创建新的 Insights 报告时，可以从面板左上角的下拉菜单中选择之前保存的配置。
