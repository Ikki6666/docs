标准的 LLM Gateway API 支持三种请求和响应格式。选择你的应用已经在使用的格式，然后通过同一个 endpoint 调用 bring-your-own-key 或 Gateway Credits 模型。

## 比较 API 格式

| API 格式 | Base URL | Prompt endpoint | 兼容的 client |
| --- | --- | --- | --- |
| OpenAI Chat Completions | `https://gateway.smith.langchain.com/v1` | `POST /chat/completions` | OpenAI 兼容的 Chat Completions client |
| Anthropic Messages | `https://gateway.smith.langchain.com` | `POST /v1/messages` | Anthropic Messages client |
| OpenAI Responses | `https://gateway.smith.langchain.com/v1` | `POST /responses` | OpenAI 兼容的 Responses client |

所有格式都使用工作区范围的 LangSmith API key 进行认证。把它作为 provider API key 或 `Authorization: Bearer` token 传入。

这些 base URL 适用于 LangSmith Cloud 上的 US gateway。关于其他区域、BYOC data planes 和自托管安装，请参见[检查可用性](/langsmith/llm-gateway-how-it-works#check-availability)。

对于 bring-your-own-key 模型，把 `model` 设置为 `<provider>/<model>`，例如 `openai/gpt-5.4-mini`、`anthropic/claude-opus-5` 或 `azure/<deployment-name>`。对于 Gateway Credits 模型，传入受支持的模型名称，例如 `moonshotai/kimi-k3`。

## 使用 Chat Completions

把 OpenAI 兼容的 client 指向 `https://gateway.smith.langchain.com/v1`。完整的请求和响应 schema 请参见 [OpenAI Chat Completions API](https://platform.openai.com/docs/api-reference/chat)。

<CodeGroup>

```bash cURL
curl https://gateway.smith.langchain.com/v1/chat/completions \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-opus-5","messages":[{"role":"user","content":"Hello!"}]}'
```

```python Python
import os

from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.smith.langchain.com/v1",
    api_key=os.environ["LANGSMITH_API_KEY"],
)
response = client.chat.completions.create(
    model="anthropic/claude-opus-5",
    messages=[{"role": "user", "content": "Hello!"}],
)
```

```typescript TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.smith.langchain.com/v1",
  apiKey: process.env.LANGSMITH_API_KEY,
});
const response = await client.chat.completions.create({
  model: "anthropic/claude-opus-5",
  messages: [{ role: "user", content: "Hello!" }],
});
```

</CodeGroup>

## 使用 Messages

把 Anthropic client 指向 `https://gateway.smith.langchain.com`。完整的请求和响应 schema 请参见 [Anthropic Messages API](https://docs.anthropic.com/en/api/messages)。

<CodeGroup>

```bash cURL
curl https://gateway.smith.langchain.com/v1/messages \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"openai/gpt-5.4-mini","max_tokens":1024,"messages":[{"role":"user","content":"Hello!"}]}'
```

```python Python
import os

import anthropic

client = anthropic.Anthropic(
    base_url="https://gateway.smith.langchain.com",
    api_key=os.environ["LANGSMITH_API_KEY"],
)
message = client.messages.create(
    model="openai/gpt-5.4-mini",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello!"}],
)
```

```typescript TypeScript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  baseURL: "https://gateway.smith.langchain.com",
  apiKey: process.env.LANGSMITH_API_KEY,
});
const message = await client.messages.create({
  model: "openai/gpt-5.4-mini",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Hello!" }],
});
```

</CodeGroup>

## 使用 Responses

把 OpenAI 兼容的 client 指向 `https://gateway.smith.langchain.com/v1`。完整的请求和响应 schema 请参见 [OpenAI Responses API](https://platform.openai.com/docs/api-reference/responses)。

<CodeGroup>

```bash cURL
curl https://gateway.smith.langchain.com/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-opus-5","input":"Hello!"}'
```

```python Python
import os

from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.smith.langchain.com/v1",
    api_key=os.environ["LANGSMITH_API_KEY"],
)
response = client.responses.create(
    model="anthropic/claude-opus-5",
    input="Hello!",
)
```

```typescript TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.smith.langchain.com/v1",
  apiKey: process.env.LANGSMITH_API_KEY,
});
const response = await client.responses.create({
  model: "anthropic/claude-opus-5",
  input: "Hello!",
});
```

</CodeGroup>

## 启用 prompt caching

OpenAI 模型（Chat Completions 和 Responses）会自动支持隐式 prompt caching，无需额外参数。

Anthropic 模型和一些较旧的 OpenAI 模型需要显式开启 prompt caching。通过任意标准 gateway endpoint 调用这些模型时，请在请求体中传入 provider 专属的字段。

<Note>
显式 caching 支持是一项临时措施，gateway 级别的 caching policy 仍在开发中。以下字段会被透传给上游 provider。
</Note>

### Anthropic 模型

传入带有 `ttl` 值的 `prompt_cache_options`：

<CodeGroup>

```bash cURL
curl https://gateway.smith.langchain.com/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "anthropic/claude-opus-5",
      "input": "Hello!",
      "prompt_cache_options": {"ttl": "30m"}
    }'
```

```python Python
import os

from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.smith.langchain.com/v1",
    api_key=os.environ["LANGSMITH_API_KEY"],
)
response = client.responses.create(
    model="anthropic/claude-opus-5",
    input="Hello!",
    extra_body={"prompt_cache_options": {"ttl": "30m"}},
)
```

```typescript TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.smith.langchain.com/v1",
  apiKey: process.env.LANGSMITH_API_KEY,
});
const response = await client.responses.create({
  model: "anthropic/claude-opus-5",
  input: "Hello!",
  // @ts-ignore — provider-specific field
  prompt_cache_options: { ttl: "30m" },
});
```

</CodeGroup>

同一个字段也适用于 Chat Completions endpoint：

```bash cURL
curl https://gateway.smith.langchain.com/v1/chat/completions \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "anthropic/claude-opus-5",
      "messages": [{"role": "user", "content": "Hello!"}],
      "prompt_cache_options": {"ttl": "30m"}
    }'
```

### 较旧的 OpenAI 模型

一些较旧的 OpenAI 模型支持通过 `prompt_cache_retention` 进行显式缓存控制。对大多数模型，把它设置为 `"in_memory"`。对于 `gpt-5.5`，请使用 `"24h"`：

```bash cURL (most older models)
curl https://gateway.smith.langchain.com/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "openai/gpt-5.4-mini",
      "input": "Hello!",
      "prompt_cache_retention": "in_memory"
    }'
```

```bash cURL (gpt-5.5 specifically)
curl https://gateway.smith.langchain.com/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "openai/gpt-5.5",
      "input": "Hello!",
      "prompt_cache_retention": "24h"
    }'
```

完整的 `prompt_cache_retention` 文档请参见 [OpenAI prompt caching 指南](https://developers.openai.com/api/docs/guides/prompt-caching#prompt-cache-retention)。

## 理解转换行为

endpoint 决定你的应用发送和接收的格式，model ID 决定上游 provider。

- 当 provider 原生支持所选格式时，gateway 会保留该格式。
- 否则，gateway 会把请求转换为 provider 支持的格式，并把响应转换回来，包括流式响应。
- 转换可能会拒绝无法在目标 provider 格式中表达的字段。当需要 provider 原生行为时，请使用 [Direct model access](/langsmith/llm-gateway-direct-model-access)。

无论使用哪种格式，每个请求都会解析相同的 Provider Secrets、策略和 tracing 配置。

## 列出模型

调用 `GET /v1/models` 可以列出工作区所配置 providers 提供的模型，以及 [Gateway Credits](/langsmith/llm-gateway-credits) 提供的模型。gateway 会返回一个 OpenAI 兼容的列表：

```bash
curl https://gateway.smith.langchain.com/v1/models \
    -H "Authorization: Bearer $LANGSMITH_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    {"id": "openai/gpt-5.4-mini", "object": "model"},
    {"id": "fireworks/accounts/fireworks/models/glm-5p2", "object": "model"},
    {"id": "anthropic/claude-opus-5", "object": "model"},
    {"id": "moonshotai/kimi-k3", "object": "model"}
  ]
}
```

bring-your-own-key 模型 ID 使用 `<provider>/<model>` 形式。托管模型使用响应中显示的 slug。发起调用时，请按原样传入任一 ID。未配置 secret 的 bring-your-own-key provider 会被省略；托管模型不需要 provider secret。

## 处理错误

| 状态或现象 | 含义 |
| --- | --- |
| `400 Bad Request` | 请求格式错误、model ID 不可用或格式不正确，或请求无法被转换。 |
| `401 Unauthorized` | LangSmith API key 缺失或无效。 |
| `403 Forbidden` | 该 key 没有所需的 gateway 权限。 |
| `429 Too Many Requests` | 达到了 gateway 速率限制或上游 provider 的速率限制。 |
| `GET /v1/models` 中没有出现带 provider 前缀的模型 | provider 可能未配置，或者没有返回模型目录。 |

针对具体配置的解决方法，请参见 [Quickstart](/langsmith/llm-gateway-quickstart)。
