---
title: 从 traces 中脱敏 secrets
description: 使用 SDK anonymizer，防止 API keys、tokens 和其他 secrets 出现在 LangSmith traces 中。
---

当你的应用会处理 API keys、tokens 或其他凭据时，如果这些值出现在 inputs 或 outputs 中，它们就可能进入 LangSmith traces。你可以使用 LangSmith SDK 内置的 anonymizer，在数据发送到后端之前先对这些 secrets 做脱敏。

<Note>
本页讲的是如何通过 SDK 从 trace 数据中脱敏 secrets（API keys、tokens、credentials）。如果你要脱敏的是电子邮箱、姓名、社会安全号等 personally identifiable information（PII），请参见 [Prevent logging of sensitive data in traces](/langsmith/mask-inputs-outputs)。如果你要在 LLM Gateway 这一层对 secrets 做脱敏，请参见 [数据策略](/langsmith/llm-gateway-data-policy)。

适用于 [Claude Code](/langsmith/trace-claude-code#secret-redaction)、[OpenAI Codex](/langsmith/trace-with-codex#secret-redaction) 和 [Cursor](/langsmith/trace-with-cursor#secret-redaction) 的 coding agent tracing 插件默认会应用下方的预设。这些工具不需要 SDK 代码。
</Note>

## 使用内置 secret 预设

SDK 内置了一套针对常见凭据格式的精选规则集。把 `create_secret_anonymizer` 传给 [Client](https://reference.langchain.com/python/langsmith/client/Client) 构造函数，它会在 run inputs、outputs、errors 和 metadata 上传之前，对检测到的 secrets 做脱敏。当你想覆盖已知的 key 格式而不想自己编写 pattern 时，可以使用它。

<Info>
`create_secret_anonymizer` / `createSecretAnonymizer` 函数要求：

- Python SDK：0.9.0 或更高版本
- TypeScript SDK：0.7.11 或更高版本
</Info>

<CodeGroup>

```python Python
from langsmith import Client
from langsmith.anonymizer import create_secret_anonymizer

client = Client(anonymizer=create_secret_anonymizer())
```

```typescript TypeScript
import { Client } from "langsmith";
import { createSecretAnonymizer } from "langsmith/anonymizer";

const client = new Client({ anonymizer: createSecretAnonymizer() });
```

</CodeGroup>

每个匹配项都会被替换为 `[SECRET_DETECTED]`。预设最多遍历 24 层嵌套，而不是 `create_anonymizer` 使用的 10 层，因为被跟踪的 payload 嵌套很深。可以用 `max_depth` 覆盖它。

Python 和 TypeScript 的预设持有相同的规则，因此由其中一个脱敏的 trace 与由另一个脱敏的 trace 一致。

### 预设中的规则

Provider 规则锚定到已知的 key 前缀。Contextual 规则只有在一个敏感名称与一次赋值配对时才会触发，这样普通代码、UUID 和内容哈希都保持不变。

| Category | Detected formats |
| --- | --- |
| Anthropic | `sk-ant-` |
| OpenAI | `sk-proj-`、`sk-svcacct-`、`sk-admin-` 以及旧版 `sk-` keys |
| LangSmith | `lsv2_pt_`、`lsv2_sk_`、`ls__` |
| GitHub | `ghp_`、`gho_`、`ghu_`、`ghs_`、`ghr_` 以及 `github_pat_` |
| GitLab | `glpat-` |
| AWS | 以 `AKIA`、`ASIA`、`ABIA`、`ACCA` 或 `A3T` 为前缀的 Access key IDs |
| Google | `AIza` API keys 和 `ya29.` OAuth access tokens |
| Slack | `xoxb-`、`xoxa-`、`xoxp-`、`xoxr-`、`xoxs-`、`xapp-` 以及 `hooks.slack.com` webhook URLs |
| Stripe | `sk_live_`、`sk_test_`、`rk_live_`、`rk_test_` |
| npm | `npm_` |
| PyPI | `pypi-AgEIcHlwaS` 上传 tokens |
| SendGrid | `SG.` |
| JSON Web Tokens | 以 `eyJ` 开头的 `header.payload.signature` 三段式 |
| Private keys | RSA、EC、OpenSSH、DSA 和 PGP keys 的 PEM 块 |
| Named assignments | `API_KEY`、`SECRET`、`TOKEN`、`PASSWORD`、`PASSWD`、`PRIVATE_KEY`、`ACCESS_KEY`、`AUTH_TOKEN` 或 `CLIENT_SECRET`，后跟 `=` 或 `:` 以及六个或以上字符的值 |
| Credential headers | `Authorization`、`X-Api-Key` 和 `X-Auth-Token`，以及单独的 `Bearer <token>` |
| URL credentials | `scheme://user:password@host` 中的密码 |

名称规则要求存在组件边界，因此 `TOKEN` 会匹配 `api_token` 和 `mytoken`，但不会匹配 `tokenizer` 或 `tokens`。Header 和 `Bearer` 规则会保留 header 名称和 scheme 词，只对随后的凭据做脱敏。

### 向预设添加自己的规则

传入 `extra_rules` 可以追加预设不认识的凭据的 pattern，例如内部 key 格式。Extra rules 在内置规则之后运行。

<CodeGroup>

```python Python
import re

from langsmith import Client
from langsmith.anonymizer import create_secret_anonymizer

anonymizer = create_secret_anonymizer(
    extra_rules=[
        {"pattern": re.compile(r"ACME-[A-Z0-9]{16}"), "replace": "[REDACTED_ACME_KEY]"},
    ]
)

client = Client(anonymizer=anonymizer)
```

```typescript TypeScript
import { Client } from "langsmith";
import { createSecretAnonymizer } from "langsmith/anonymizer";

const anonymizer = createSecretAnonymizer({
  extraRules: [
    { pattern: /ACME-[A-Z0-9]{16}/g, replace: "[REDACTED_ACME_KEY]" },
  ],
});

const client = new Client({ anonymizer });
```

</CodeGroup>

没有 `replace` 值的规则会回退到 `[redacted]`，而不是 `[SECRET_DETECTED]`。如果你想在 trace 中区分两者，请设置 `replace`。

### 预设的局限

该预设更看重精确性而非穷尽式覆盖，这带来了一些值得提前规划的影响：

- **未识别的格式会进入 LangSmith**：不匹配任何规则的凭据，包括没有周围上下文的随机高熵字符串，会按原样上传。
- **只有四个字段会被脱敏**：anonymizer 覆盖 `inputs`、`outputs`、`error` 和 `extra.metadata`。Run 名称、tags 和 attachments 会按原样上传。
- **脱敏不是访问控制**：脱敏后的 trace 仍然包含构建它的 prompts、文件内容和 tool results。请限制谁可以读取该 tracing project。如果想省略内容而不是擦除它，请参见 [Prevent logging of sensitive data in traces](/langsmith/mask-inputs-outputs)。

## 编写自定义 pattern

<Info>
`create_anonymizer` / `createAnonymizer` 函数要求：

- Python SDK：0.1.81 或更高版本
- TypeScript SDK：0.1.33 或更高版本
</Info>

当预设不适用时，`create_anonymizer` 会接收一组 regex pattern 和 replacement string，并且只应用这些。把生成的 anonymizer 传给 [Client](https://reference.langchain.com/python/langsmith/client/Client) 构造函数后，它会在所有 run inputs 和 outputs 发送到 LangSmith 之前自动应用。

下面的示例会脱敏几种常见的 secret 格式，包括 OpenAI API keys、通用 bearer tokens，以及以 `sk-` 开头的 keys：

<CodeGroup>

```python Python
from langsmith.anonymizer import create_anonymizer
from langsmith import Client, traceable

# Redact common secret patterns
anonymizer = create_anonymizer([
    # OpenAI-style keys: sk-... or sk-proj-...
    {"pattern": r"sk-[A-Za-z0-9\-_]{20,}", "replace": "<REDACTED_API_KEY>"},
    # Generic bearer tokens
    {"pattern": r"Bearer\s+[A-Za-z0-9\-_\.]{20,}", "replace": "Bearer <REDACTED_TOKEN>"},
    # Anthropic keys
    {"pattern": r"sk-ant-[A-Za-z0-9\-_]{20,}", "replace": "<REDACTED_API_KEY>"},
    # Generic high-entropy strings that look like secrets (40+ hex chars)
    {"pattern": r"\b[0-9a-fA-F]{40,}\b", "replace": "<REDACTED_TOKEN>"},
])

client = Client(anonymizer=anonymizer)

@traceable(client=client)
def call_external_api(api_key: str, prompt: str) -> str:
    # The api_key value will be redacted in the trace
    return f"Response to: {prompt}"

call_external_api(
    api_key="sk-proj-AbCdEfGhIjKlMnOpQrStUvWxYz1234567890",
    prompt="What is LangSmith?",
)
```

```typescript TypeScript
import { createAnonymizer } from "langsmith/anonymizer";
import { traceable } from "langsmith/traceable";
import { Client } from "langsmith";

// Redact common secret patterns
const anonymizer = createAnonymizer([
    // OpenAI-style keys: sk-... or sk-proj-...
    { pattern: /sk-[A-Za-z0-9\-_]{20,}/g, replace: "<REDACTED_API_KEY>" },
    // Generic bearer tokens
    { pattern: /Bearer\s+[A-Za-z0-9\-_.]{20,}/g, replace: "Bearer <REDACTED_TOKEN>" },
    // Anthropic keys
    { pattern: /sk-ant-[A-Za-z0-9\-_]{20,}/g, replace: "<REDACTED_API_KEY>" },
    // Generic high-entropy strings that look like secrets (40+ hex chars)
    { pattern: /\b[0-9a-fA-F]{40,}\b/g, replace: "<REDACTED_TOKEN>" },
]);

const client = new Client({ anonymizer });

const callExternalApi = traceable(
    async (apiKey: string, prompt: string): Promise<string> => {
        // The apiKey value will be redacted in the trace
        return `Response to: ${prompt}`;
    },
    { client }
);

await callExternalApi(
    "sk-proj-AbCdEfGhIjKlMnOpQrStUvWxYz1234567890",
    "What is LangSmith?"
);
```

</CodeGroup>

anonymizer 会先把 inputs 和 outputs 序列化成 JSON，对每个 regex pattern 依次应用，再在发送到 LangSmith 前反序列化回来。默认情况下，它最多向下遍历 10 层嵌套结构。如需修改这个深度，可以传入 `max_depth` 参数：

```python
anonymizer = create_anonymizer(
    [{"pattern": r"sk-[A-Za-z0-9\-_]{20,}", "replace": "<REDACTED_API_KEY>"}],
    max_depth=5,
)
```

## 使用自定义函数

如果你的脱敏逻辑更复杂，可以传入一个函数，而不是一组 patterns。这个函数接收一个字符串，并返回脱敏后的字符串：

<CodeGroup>

```python Python
import re
from langsmith.anonymizer import create_anonymizer
from langsmith import Client

# Example: redact any value that follows a known key name in JSON-like payloads
SECRET_KEYS = {"api_key", "apiKey", "token", "secret", "password", "credential"}

def redact_secret_values(text: str) -> str:
    for key in SECRET_KEYS:
        # Match patterns like: "api_key": "some-value"
        pattern = rf'("{key}"\s*:\s*)"[^"]*"'
        text = re.sub(pattern, r'\1"<REDACTED>"', text)
    return text

anonymizer = create_anonymizer(redact_secret_values)
client = Client(anonymizer=anonymizer)
```

```typescript TypeScript
import { createAnonymizer } from "langsmith/anonymizer";
import { Client } from "langsmith";

const SECRET_KEYS = new Set(["api_key", "apiKey", "token", "secret", "password", "credential"]);

function redactSecretValues(text: string): string {
    for (const key of SECRET_KEYS) {
        // Match patterns like: "api_key": "some-value"
        const pattern = new RegExp(`("${key}"\\s*:\\s*)"[^"]*"`, "g");
        text = text.replace(pattern, '$1"<REDACTED>"');
    }
    return text;
}

const anonymizer = createAnonymizer(redactSecretValues);
const client = new Client({ anonymizer });
```

</CodeGroup>

## 与 LANGSMITH_HIDE_INPUTS 配合使用

如果你的场景要求彻底屏蔽全部 inputs，例如为了满足 zero-retention 合规要求，可以改用 `LANGSMITH_HIDE_INPUTS=true`。当 `LANGSMITH_HIDE_INPUTS` 或 `LANGSMITH_HIDE_OUTPUTS` 被设为 `true` 时，anonymizer 会被跳过。

更多选项，包括隐藏全部 inputs 和 outputs、隐藏 metadata、函数级 processors，以及第三方 PII 库，请参见 [Prevent logging of sensitive data in traces](/langsmith/mask-inputs-outputs)。
